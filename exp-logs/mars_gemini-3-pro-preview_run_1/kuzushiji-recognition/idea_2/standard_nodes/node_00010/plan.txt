The issue is caused by **Intermediate Tensor Explosion** in the loss function due to the high-cardinality output (4,782 classes). With a batch size of 4, a single dense tensor consumes ~4.67 GiB. The `ModifiedFocalLoss` allocates multiple such tensors simultaneously (e.g., `neg_weights`, `log(1-pred)`, `pow(pred)`), causing the GPU to run out of memory (Cite debug_lesson_2).

To fix this, I will:
1.  **Reduce Batch Size**: Lower `BATCH_SIZE` in `library/config.py` from 4 to 2. This directly reduces the size of the dense tensors by 50%, bringing the memory requirement within the GPU's capacity (Cite debug_lesson_1).
2.  **Optimize Loss Calculation**: Modify `library/loss.py` to calculate the negative loss term using in-place operations (`*=`). This prevents the creation of multiple concurrent intermediate tensors, significantly reducing peak memory usage during the loss computation (Cite debug_lesson_2).
