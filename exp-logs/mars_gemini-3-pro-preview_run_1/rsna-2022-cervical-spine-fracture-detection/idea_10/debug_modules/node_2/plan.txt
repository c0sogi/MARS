The issue stems from `library/data.py` initializing a global logger at import time using `get_logger("data")`. This function immediately creates a `FileHandler` that opens a log file within the `working/idea_10/logs` directory. Consequently, when `runfile.py` attempts to delete the `working` directory using `shutil.rmtree`, the operation fails with `OSError: [Errno 39] Directory not empty` because the Python process itself holds an open file handle inside that directory.

To fix this, I will:
1.  Refactor `library/data.py` to use `logging.getLogger("data")` instead of `get_logger("data")`. This retrieves the logger instance without attaching handlers (and thus without opening files) at import time.
2.  Update `runfile.py` to import `get_logger` and call `get_logger("data")` explicitly *after* the directory cleanup and `Config.setup()` have completed. This ensures the log file is created in the newly established directory structure.
