### Implementation Strategy

1.  **Configuration Override**: To ensure the script runs quickly (within minutes) and uses minimal resources, I will dynamically modify the `Config` class attributes. I will set the working directory to a demo-specific folder, reduce the number of epochs to 1, limit the training/validation samples to a small batch, and define a simplified model architecture (shallower depth, fewer channels, smaller patch size).
2.  **Data Preparation**: I will create a subset of the test metadata containing only a single image. This allows the `generate_submission` function to run and verify the full inference pipeline without processing the entire test set, which would be time-consuming.
3.  **Component Verification**:
    *   **Utils**: Verify `calculate_rmse` against manual calculation.
    *   **Dataset**: Instantiate dataloaders and verify batch shapes and data types.
    *   **Model**: Instantiate the `UNet` model and verify the output shape of a forward pass.
    *   **Training**: Execute `train_all_models` to train the simplified model for one epoch and verify that the model checkpoint is saved.
    *   **Inference**: Run `generate_submission` using the trained model and the subset test metadata. Verify the existence and format of the submission file.
4.  **Assertions**: Throughout the script, `assert` statements will be used to enforce expected behaviors (e.g., correct tensor shapes, file existence, loss reduction).
