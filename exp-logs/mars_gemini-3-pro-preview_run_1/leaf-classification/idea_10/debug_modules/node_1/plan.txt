The issue is that in `DEBUG_MODE`, the dataset loading function naively slices the first N rows of the training and validation sets. In a high-cardinality dataset (99 classes), this random slicing creates disjoint sets of classes between training and validation. Consequently, the model is trained on one set of classes, but evaluated on a validation set containing unseen classes, causing `sklearn.metrics.log_loss` to fail.

To fix this, I will modify `library/dataset.py` to implement a class-aware filtering strategy for debug mode (Cite debug_lesson_1). Instead of just slicing rows, the code will first identify a common subset of species present in both training and validation sets, filter both datasets to these species, and then apply the size limit. This ensures that the validation set strictly contains a subset of the classes seen during training.
