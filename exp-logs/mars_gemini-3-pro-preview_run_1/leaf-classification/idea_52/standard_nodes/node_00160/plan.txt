Implementation strategy:

1.  **Environment Setup**: Import necessary modules and set random seeds using `library.utils.set_seed` to ensure reproducibility.
2.  **Data Pipeline**: Utilize the `DataManager` class from `library.data` to orchestrate the loading and processing of data. This class handles:
    *   Loading metadata for train, validation, and test sets.
    *   Extracting features, including the novel **Integral-Morphological** features (e.g., Mean Thickness) and standard tabular features.
    *   Preprocessing using the **High-Precision Pipeline** (Yeo-Johnson transformation followed by Standard Scaling) via `library.preprocessing`.
    *   Caching results to `working/` to optimize runtime.
3.  **Model Training**: Initialize the `OASLinearDiscriminant` from `library.model`. This model implements the **OAS-LDA backbone** with `float64` precision. Fit the model on the preprocessed training data.
4.  **Validation & Metric**:
    *   Generate probability predictions on the validation set.
    *   Compute the **Multi-class Log Loss** using `library.utils.custom_log_loss`, which strictly applies the required rescaling and clipping ($10^{-15}$).
    *   Print the validation metric in the specified format `Final Validation Metric: <value>`.
5.  **Failure Analysis**:
    *   Calculate the error magnitude for each validation sample (negative log-likelihood of the true class).
    *   Compute the Pearson correlation between this error magnitude and each input feature to identify which features correlate with model failure.
    *   Print the top 5 correlated features.
6.  **Submission**:
    *   Compare the validation metric against the strict threshold (`3.3382359570696616e-14`).
    *   If the metric is lower than the threshold, generate predictions for the test set.
    *   Format the submission DataFrame (ID column + class probability columns) and save it to `./submission/submission.csv`.
