Implementation Strategy
The implementation follows a streamlined pipeline designed for speed and reproducibility. First, we initialize the `Config` to set random seeds and prepare directories. We explicitly detect the available device (GPU/CPU) to adhere to runtime requirements, though the underlying `sklearn`-based LDA model will execute on the CPU. We then load the preprocessed data using `load_data(load_cached_data=True)` to minimize overhead.

The core modeling phase involves training the `TaxonomyEnsemble`, which fits both a Global LDA and a Hierarchical (Genus-specific) LDA. We validate this ensemble on the hold-out validation set, calculating the Multi-class Log Loss.

For failure analysis, we compute the sample-wise log loss (negative log-likelihood) and perform a vectorized correlation analysis against all input features. This identifies which features are most strongly associated with prediction errors. Finally, we enforce the strict conditional submission logic: the test set predictions are generated and saved to `submission.csv` if and only if the validation log loss is below the specified threshold of `1.4705545687989736e-08`.
