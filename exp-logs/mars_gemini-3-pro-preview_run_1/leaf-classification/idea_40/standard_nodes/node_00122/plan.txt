The `ValueError: Input X contains NaN` is caused by a mathematical error in `library/features.py` where `cv2.fitEllipse` returns axes that are not guaranteed to be sorted by size. When the returned "width" is smaller than the "height", treating it as the `major_axis` leads to a negative value inside the square root calculation for eccentricity, producing NaNs. Additionally, the caching mechanism needs to be updated to invalidate previous corrupt feature files.

I will fix this by:
1.  Updating `library/config.py` to define a `FEATURE_VERSION` constant.
2.  Updating `library/utils.py` to include `FEATURE_VERSION` in the configuration hash (Cite debug_lesson_2), forcing a cache refresh.
3.  Updating `library/features.py` to explicitly sort the axes from `cv2.fitEllipse` and clamp the axis ratio to prevent numerical instability.
