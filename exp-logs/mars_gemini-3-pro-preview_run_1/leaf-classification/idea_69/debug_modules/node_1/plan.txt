The previous implementation naively sliced the first `max_samples` rows of the training and validation datasets for debugging. Because the dataset has high cardinality (99 classes), the training subset contained only a specific set of classes, while the validation subset happened to include a class (`'Populus_Adenopoda'`) not present in that training slice. This caused the `LabelEncoder`, which was fitted only on the training subset, to crash when encountering the unseen label in the validation set.

The fix addresses this by ensuring schema consistency between the training and validation subsets in debug mode. Instead of simple slicing, we first filter the datasets to a pool of the most frequent classes to ensure data density. We then slice the training set to the requested limit and strictly filter the validation set to include *only* the classes present in the resulting training subset. This guarantees that `y_val` is always a subset of `y_train` (Cite debug_lesson_1).
