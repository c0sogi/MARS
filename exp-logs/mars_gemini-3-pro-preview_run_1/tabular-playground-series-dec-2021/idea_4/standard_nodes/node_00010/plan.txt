Implementation strategy:
1.  **Configuration & Setup**: Import necessary libraries and the provided library modules. Override the `MODEL_PARAMS` in `library.config` to slightly reduce `n_estimators` (from 3000 to 2000) to ensure the "fast baseline" requirement is met while maintaining high capacity for the ensemble.
2.  **Data Loading**: Use `load_dataset(load_cached_data=True)` to efficiently load the training, validation, and test sets. Crucially, we will reserve the `val_df` returned by this function as a strict **Hold-Out Set** for the final evaluation and failure analysis, ensuring no leakage during the training phases.
3.  **Stage 1 (Teacher)**: Execute the `run_cross_validation` function on the `train_df`. This performs a stratified 5-fold cross-validation, training 5 independent XGBoost models. We aggregate their predictions on the test set to form the baseline probabilities.
4.  **Pseudo-Labeling**: Use `create_augmented_train` to identify high-confidence test samples (probability > 0.99) and assign them pseudo-labels. We extract these samples into a separate `pseudo_df`.
5.  **Stage 2 (Student)**: Execute `run_cross_validation` again on the `train_df`, but this time passing the `pseudo_df`. The pipeline is designed to augment *only* the training portion of each fold with the pseudo-labeled data, preserving the integrity of the internal validation folds. This produces a refined ensemble of 5 models.
6.  **Final Validation**: Perform inference using the Stage 2 ensemble on the reserved Hold-Out Set (`val_df`). Calculate the multi-class classification accuracy and print it in the required format: `Final Validation Metric: <value>`.
7.  **Failure Analysis**: Compare the model's predictions on the hold-out set with the true labels to generate an error vector. Compute the correlation between this error vector and each input feature to identify which features are most associated with model failure. Print the top correlated features.
8.  **Submission**: Check if the final validation metric exceeds the threshold (0.96147...). If successful, generate the submission file using the Stage 2 ensemble; otherwise, skip generation.
