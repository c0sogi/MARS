Based on the provided dataset analysis and model architectures, I propose the following baseline approach. This solution prioritizes speed, simplicity, and robustness by leveraging the Gradient Boosting paradigm (Model 1) with hardware acceleration.

### Model
We will implement a **Gradient Boosting Decision Tree (GBDT)** architecture using the **XGBoost** framework. The model functions as an ensemble of weak prediction models (regression trees), where new trees are trained sequentially to correct the residual errors of the previous ones.
*   **Architecture**: The model will consist of a series of decision trees.
*   **Acceleration**: To handle the large dataset (3.6M samples) efficiently within the time limit, we will utilize the `gpu_hist` tree method. This algorithm constructs histograms of feature values on the GPU (NVIDIA A100) to speed up the split finding process, significantly reducing training time compared to CPU-based exact methods.
*   **Configuration**: We will use a standard configuration with `multi:softmax` objective for multi-class classification.

### Data
The dataset is already clean, numerical, and free of missing values, allowing for a streamlined pipeline:
1.  **Loading**: We will load the processed training and validation subsets from the metadata CSV files (`./metadata/train.csv` and `./metadata/val.csv`).
2.  **Target Encoding**: The target variable `Cover_Type` contains non-contiguous integers (1, 2, 3, 4, 6, 7). We will use a `LabelEncoder` to map these to a 0-indexed range (0-5) required by the model.
3.  **Feature Handling**: Since decision trees are invariant to monotonic transformations, we will not apply feature scaling or normalization. The numerical features will be passed directly to the model.

### Training
The training procedure focuses on establishing a strong baseline with minimal tuning:
1.  **Optimization**: The model will be trained to minimize the `multi:softmax` loss.
2.  **Validation & Early Stopping**: We will train for a maximum number of boosting rounds (e.g., 1000-3000) but implement early stopping. By monitoring the classification error (`merror`) on the validation set, training will halt if performance does not improve for a set number of rounds. This prevents overfitting and saves compute time.
3.  **Class Imbalance**: Given the goal is overall accuracy and the dataset is imbalanced, we will initially train without heavy class re-weighting to maximize the correct predictions on the dominant classes (which make up >90% of the data).

### Evaluation
1.  **Inference**: We will load the test set (`./metadata/test.csv`) and use the trained model to predict the class index for each sample.
2.  **Post-processing**: The predicted indices (0-5) will be inverse-transformed back to the original `Cover_Type` labels using the fitted `LabelEncoder`.
3.  **Submission**: The final predictions will be formatted into a CSV file with `Id` and `Cover_Type` columns, matching the sample submission format.
