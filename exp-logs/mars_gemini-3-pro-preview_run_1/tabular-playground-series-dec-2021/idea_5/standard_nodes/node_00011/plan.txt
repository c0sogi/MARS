The implementation strategy follows the "Full-Scale Homogeneous Ensemble" approach outlined in the idea, ensuring strict adherence to the validation requirements and resource constraints.

1.  **Setup & Configuration**: The script initializes the environment by setting random seeds for reproducibility and suppressing unnecessary warnings. It imports the necessary configurations and utility functions from the provided `library` modules (`config`, `data_processor`, `ensemble_trainer`, `inference_utils`).

2.  **Data Loading**: To strictly comply with the requirement of validating on the hold-out set without data leakage, the script manually loads the pre-split datasets from the `./metadata` directory:
    *   `metadata/train.csv` (80% of data) is used for training the ensemble.
    *   `metadata/val.csv` (20% of data) is used exclusively for the final validation metric.
    *   `input/test.csv` is used for generating submission predictions.

3.  **Feature Engineering**: The `engineer_features` function from `library.data_processor` is applied to all three datasets (train, val, test). This injects the physics-informed geometric features (e.g., Euclidean distance to hydrology, relative elevation) that are crucial for this task.

4.  **Ensemble Training**: The script invokes `train_ensemble` to train 5 independent XGBoost models on the training set using Stratified 5-Fold Cross-Validation. The models utilize the GPU (`device='cuda'`) and histogram-based learning (`tree_method='hist'`) for high-speed execution, ensuring the process completes well within the time limit.

5.  **Validation & Metrics**:
    *   Inference is performed on the hold-out validation set using `soft_vote_predict` (averaging probabilities from all 5 models).
    *   The overall accuracy is computed and printed as `Final Validation Metric`.

6.  **Failure Analysis**: The script calculates the correlation between the model's error vector (binary: 1 for error, 0 for correct) and the input features on the validation set. The top 5 features most correlated with prediction errors are printed to identify systematic weaknesses.

7.  **Submission**: The script checks if the validation accuracy exceeds the specified threshold (`0.9614708333333334`). If successful, it generates predictions for the test set and saves them to `./submission/submission.csv` using `export_submission`.
