Implementation strategy:

1.  **Setup & Configuration Patching**: 
    -   Import the provided library modules.
    -   Create a temporary directory structure in `./working` to hold a small subset of the data (1000 rows) and cache files. This ensures the demo runs quickly (seconds instead of hours) and doesn't interfere with the main dataset or cache.
    -   Monkey-patch the `Config` class attributes to point to these new temporary paths and reduce hyperparameters (e.g., `epochs=1`, `num_boost_round=2`, `N_FOLDS=2`).

2.  **Data Preparation**:
    -   Load the first 1000 rows from the original metadata files (`train.csv`, `val.csv`, `test.csv`).
    -   Save these subsets to the temporary input directory defined in the patched `Config`.

3.  **Component Verification**:
    -   **DataFactory**: Call `load_and_engineer_data` to verify it correctly loads the subset and generates the expected engineered features (e.g., `Euclidean_Distance_To_Hydrology`).
    -   **TabularResNet**: Instantiate the model with dimensions matching the processed data. Perform a forward pass with a dummy tensor to verify the architecture and output shape.
    -   **Trainers**: Briefly run `train_xgboost_model` and `train_neural_network` using the subsampled data to ensure the training loops execute without errors.

4.  **Integration Test (EnsembleRunner)**:
    -   Instantiate `EnsembleRunner`.
    -   Execute `run_kfold_stacking`. This orchestrates the entire pipeline: loading data, K-Fold CV for XGBoost and ResNet, meta-learner training, and submission generation.
    -   Verify that the submission file is created and follows the correct format.

5.  **Cleanup**:
    -   The script is self-contained and handles all temporary file creation within `./working`.
