The `ValueError` in XGBoost (`Expected: [0 1 2 3 4], got [0 1 2 4 5]`) is caused by the stratified subsampling logic used when `Config.DEBUG_SAMPLES` is set to 2000. The dataset contains an extremely rare class (Class 4, mapped to 3) with only ~0.01% prevalence. Standard stratification rounds the expected count of this class in a 2000-sample subset to zero, causing it to be dropped. This results in non-contiguous target labels, which violates XGBoost's requirement for classes to be zero-indexed and contiguous (Cite debug_lesson_6). To fix this, I will replace the `train_test_split` logic in `library/features.py` with a custom "forced inclusion" sampling strategy that explicitly selects at least one example from every unique class before filling the remaining quota with random samples.
