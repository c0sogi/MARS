To solve the task more effectively, I propose a **Heterogeneous Ensemble Strategy** enhanced by **Physics-Informed Feature Engineering**. This approach evolves the solution from a single-model optimization problem to a system that leverages structural diversity (different tree-growing algorithms) and domain-specific input transformations to capture complex spatial dependencies.

### Model
The architecture will consist of a **Weighted Soft-Voting Ensemble** of two distinct Gradient Boosting frameworks:
1.  **XGBoost (Level-wise):** This component retains the successful high-capacity configuration (`max_depth=10`, `eta=0.05`) validated in previous experiments. We explicitly avoid aggressive fine-tuning (e.g., `eta=0.01`) to prevent inefficient convergence. Cite `solution_lesson_node_00004`.
2.  **LightGBM (Leaf-wise):** We introduce LightGBM as a structural innovation. Its leaf-wise tree growth strategy (splitting the leaf with max delta loss) creates trees with different structures compared to XGBoost's level-wise approach, providing error diversity that is crucial for effective ensembling.

### Data
We will move beyond raw features to a **Feature Engineering Paradigm** that creates explicit interaction terms, helping axis-aligned trees capture diagonal decision boundaries.
1.  **Interaction Features:** Generate new features based on the physical relationships in the data (e.g., `Euclidean_Distance_To_Hydrology` = $\sqrt{\text{Horizontal}^2 + \text{Vertical}^2}$, and `Hydrology_Elevation` = `Elevation` - `Vertical_Distance_To_Hydrology`).
2.  **Processing:**
    - Load the **full training dataset** (2.8M rows) and the **full validation set** (720k rows). We will strictly avoid subsampling the training data to ensure the models maximize their capacity. Cite `solution_lesson_node_00002`.
    - Apply the feature transformations consistently across Train, Validation, and Test sets.
    - Validate all improvements against the full validation set to ensure metrics are reliable proxies for test performance. Cite `solution_lesson_node_00001`.

### Training
The training procedure focuses on efficiency and automated regularization:
1.  **Hardware Acceleration:** Both models will be trained using **GPU-accelerated histogram algorithms** (`tree_method='hist'`/`device='cuda'` for XGBoost; `device='gpu'` for LightGBM) to handle the 3.6M+ total samples within the time limit.
2.  **Convergence Control:** We will set a high iteration budget (e.g., 5000) but rely entirely on **Early Stopping** (patience=50) to halt training. This decouples the iteration limit from hyperparameter tuning. Cite `solution_lesson_node_00003`.
3.  **Optimization:** Both models will use a moderate learning rate (~0.05) to balance training speed with generalization, avoiding the diminishing returns of extremely low learning rates. Cite `solution_lesson_node_00004`.

### Evaluation
1.  **Inference:** Generate class probability vectors (soft predictions) for the test set using both the trained XGBoost and LightGBM models.
2.  **Ensembling:** Compute the weighted average of the probability vectors (e.g., 0.5 * XGB + 0.5 * LGBM, or weighted by validation accuracy).
3.  **Submission:** Apply `argmax` to the averaged probabilities to determine the final class labels and map them back to the original `Cover_Type` values.
