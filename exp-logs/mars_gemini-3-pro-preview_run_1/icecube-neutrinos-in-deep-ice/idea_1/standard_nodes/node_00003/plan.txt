The failure is caused by an architectural mismatch between the `DataLoader`'s random sampling (`shuffle=True`) and the dataset's storage format (large Parquet shards). Randomly accessing events scattered across many large files causes "cache thrashing," where worker processes constantly load, decompress, and discard multi-gigabyte files for single samples, leading to massive memory spikes and the observed `ArrowMemoryError`.

To fix this, I will implement a `FilesystemAwareSampler` (Cite debug_lesson_1) that aligns the data sampling with the storage shards. This sampler will:
1.  Group event indices by their `batch_id` (file).
2.  Shuffle the order of batches (files) for global randomness.
3.  Shuffle events within each batch for local randomness.
4.  Yield all indices from one batch before moving to the next.

I will also sort the validation and test metadata by `batch_id` to ensure sequential file access during evaluation, preventing memory issues there as well.

class FilesystemAwareSampler(Sampler):
    """
    Sampler that yields indices grouped by batch_id (file) to minimize disk I/O and memory usage.
    It shuffles the order of batches (files) and shuffles events within each batch.
    Cite debug_lesson_1: Align Data Sampling with Storage Shards.
    """

    def __init__(self, metadata, batch_col="batch_id"):
        self.groups = metadata.groupby(batch_col).indices
        self.batch_keys = list(self.groups.keys())

    def __iter__(self):
        # Shuffle the order of files (batches)
        batch_order = torch.randperm(len(self.batch_keys)).tolist()
        final_indices = []
        for i in batch_order:
            key = self.batch_keys[i]
            indices = self.groups[key]
            # Shuffle indices within the file
            indices_t = torch.tensor(indices)
            perm = torch.randperm(len(indices))
            final_indices.extend(indices_t[perm].tolist())
        return iter(final_indices)

    def __len__(self):
        return sum(len(v) for v in self.groups.values())
