The issue is caused by inefficient data sampling in `DEBUG` mode where random events are selected from the entire dataset. This forces the data loader workers to load and decompress nearly every large Parquet batch file to retrieve just a few samples, leading to massive memory consumption and OOM errors (Cite debug_lesson_1). The fix involves modifying the sampling logic to select all events from a few contiguous batches instead of a random subset, ensuring only a minimal number of files are loaded. Additionally, explicit garbage collection is added to the dataset iterator to free memory immediately after processing each file.
