The previous implementation encountered an `ArrowMemoryError` (Out of Memory) because the data loading strategy was too aggressive with memory usage. Specifically, using 8 worker processes (`NUM_WORKERS=8`), each maintaining a cache of 10 large batch files (`cache_size=10`), resulted in excessive RAM consumption that exceeded the available 220 GB. To fix this, I will reduce the number of workers to 4 and decrease the per-worker cache size to 2, significantly lowering the concurrent memory footprint. I will also explicitly specify the `pyarrow` engine for reading parquet files to ensure consistent behavior.

    NUM_WORKERS = 8

    NUM_WORKERS = 4
