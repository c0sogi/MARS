The implementation strategy involves the following steps:

1.  **Configuration Setup**: Import the `Config` class and modify its class-level attributes to optimize for a quick demonstration. This includes reducing the number of epochs, batch size, graph size (`MAX_PULSES`), and model complexity (`NUM_LAYERS`, `HIDDEN_DIM`). We also redirect the working directory to a demo-specific path.
2.  **Utility Verification**: Demonstrate and verify the correctness of coordinate conversion functions (`azimuth_zenith_to_vector`, `vector_to_azimuth_zenith`) and the metric function (`angular_dist_score`) using assertions with known geometric values.
3.  **Data Pipeline Demonstration**:
    *   Load the training metadata to identify a valid `batch_id`.
    *   Instantiate the `IceCubeGraphDataset` for a single batch.
    *   Create a `DataLoader` and extract a small subset of data (2 batches) into a list. This avoids iterating through the entire massive dataset during the demo while still testing the data loading and processing logic.
    *   Verify the structure and shapes of the yielded `Data` objects (features, targets, event IDs).
4.  **Model and Engine Execution**:
    *   Instantiate the `IceCubeDGCN` model and move it to the configured device.
    *   Initialize the `Engine` with the model and an optimizer.
    *   Execute the `engine.fit` method using the limited data subset as both training and validation sets. This demonstrates the training loop, loss calculation, and backpropagation without consuming excessive time.
5.  **Inference Demonstration**:
    *   Simulate the inference process by running `engine.predict` on the same limited subset (mimicking test data).
    *   Verify that the submission file is generated correctly and contains the required columns.
