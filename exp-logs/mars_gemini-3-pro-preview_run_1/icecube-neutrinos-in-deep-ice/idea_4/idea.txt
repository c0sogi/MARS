# Baseline Approach: Dynamic Graph Convolutional Network (DGCN)

## Model
I propose a **Dynamic Graph Convolutional Network (DGCN)**. This architecture represents a structural evolution from the 1D-CNN (Idea 1) and Hybrid GRU (Idea 3) approaches. Instead of forcing the spatially sparse, irregular neutrino events into a fixed temporal sequence or a flattened tabular summary, this model treats the event as a **geometric point cloud**.

*   **Input Representation**: The event is represented as a graph where nodes are active pulses. Each node has features $(x, y, z, t, \log(q))$.
*   **Dynamic Edge Convolution (EdgeConv)**: The core backbone consists of stacked `EdgeConv` layers (from `torch_geometric`). Unlike static graph convolutions, EdgeConv dynamically constructs a k-nearest neighbor (k-NN) graph in the *feature space* at each layer. This allows the model to learn latent relationships between pulses that are not just spatially adjacent but semantically related (e.g., correlating early trigger pulses with late-stage high-charge pulses along the particle track).
*   **Global Aggregation**: After several message-passing layers, a global pooling operation (concatenation of Global Max and Global Mean pooling) aggregates the node features into a single graph-level embedding.
*   **Prediction Head**: A Multi-Layer Perceptron (MLP) maps the graph embedding to a 3D direction vector $(v_x, v_y, v_z)$.

## Data
*   **Preprocessing**:
    *   **Filtering**: Remove `auxiliary` pulses to focus on high-quality signal data.
    *   **Sampling**: To manage memory and compute, sample a fixed number of pulses (e.g., $N=256$) per event. Priority is given to high-charge pulses and the earliest pulses in time, as these carry the most information about the neutrino's origin.
    *   **Normalization**: Standardize coordinates $(x, y, z)$ and time $t$. Log-transform charge $q$.
*   **Robust Caching**: Graph construction (finding k-NN) is computationally expensive. To enable rapid iteration, processed graph data objects will be cached to disk. **Crucially, the cache filename will be generated by hashing the full configuration dictionary** (including parameters like $N_{pulses}$, $k_{neighbors}$, feature scaling method, and dataset split). This ensures that any modification to the preprocessing logic automatically invalidates the cache and triggers re-computation, preventing the model from training on stale or mismatched data. *   **Target Transformation**: Convert `azimuth` and `zenith` to a unit direction vector $(x_{gt}, y_{gt}, z_{gt})$.

## Training
*   **Loss Function**: **Cosine Similarity Loss** ($1 - \cos(\theta)$). This directly optimizes the angular alignment between the predicted vector and the ground truth, which is the competition metric.
*   **Optimizer**: **AdamW** with a **OneCycleLR** scheduler. The OneCycle policy helps the model escape local minima early in training and converge to a stable solution.
*   **Strategy**: Train on the full training set using the validation set for model selection. The dynamic graph structure allows the model to leverage the full 3D geometry of the detector, which is lost in 1D sequence models.

## Evaluation
*   **Inference**:
    1.  Load test batches and process them into graph data objects using the same sampling and normalization logic as training.
    2.  Pass graphs through the trained DGCN to predict 3D vectors.
*   **Post-processing**:
    1.  Normalize the output vector to unit length: $\hat{v} = v_{pred} / ||v_{pred}||$.
    2.  Convert to spherical coordinates:
        *   `zenith` = $\arccos(\hat{v}_z)$
        *   `azimuth` = $\arctan2(\hat{v}_y, \hat{v}_x)$ (mapped to $[0, 2\pi)$).
*   **Submission**: Format the predictions into the required CSV format.
