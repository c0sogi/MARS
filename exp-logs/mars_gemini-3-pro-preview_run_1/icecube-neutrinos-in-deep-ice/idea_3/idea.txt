# Baseline Approach: Hybrid Recurrent-Dense Network

## Model
I propose a **Hybrid Recurrent-Dense Network** that integrates the strengths of raw sequential data processing with physics-informed feature engineering. This structural innovation fuses a deep learning sequence model with a tabular feature extractor, creating a "Wide and Deep" architecture that captures both fine-grained temporal causality and global event statistics.

*   **Sequence Branch (Deep)**: This branch processes the event as a time-ordered sequence of pulses to capture the wavefront evolution.
    *   **Input**: A tensor of shape $(B, L, 5)$, representing $B$ events, $L$ selected pulses, and 5 features per pulse ($x, y, z, \text{time}, \text{charge}$).
    *   **Architecture**: A **Bidirectional GRU (Gated Recurrent Unit)**. Unlike the 1D-CNN from Idea 1, the GRU is explicitly designed to model long-term dependencies and sequential ordering, making it highly effective for tracking the particle's path through the detector over time.
*   **Feature Branch (Wide)**: This branch processes a vector of aggregated global statistics.
    *   **Input**: A vector of shape $(B, F)$ containing engineered features.
    *   **Architecture**: A Multi-Layer Perceptron (MLP) with residual connections. This explicitly preserves the physics-based aggregation strategy from Idea 2 (e.g., centroids, quantiles), ensuring the model has direct access to robust summary statistics that might be hard to learn solely from a truncated sequence.
*   **Fusion Head**: The final hidden state of the GRU is concatenated with the output embedding of the Feature Branch. This combined vector is passed through a final regression MLP to predict the 3D direction vector $(v_x, v_y, v_z)$.

## Data
*   **Preprocessing**:
    *   **Filtering**: Remove pulses where `auxiliary` is `True`.
    *   **Sequence Generation**: Sort pulses by `time`. Select the first $L=196$ pulses to capture the critical "first arrival" photons and the early track development. Pad with zeros if an event has fewer than $L$ pulses. Standardize inputs $(x, y, z, t)$ and log-transform `charge`.
    *   **Feature Generation**: Compute the global features identified in Idea 2: charge-weighted centroids ($x_c, y_c, z_c$), time quantiles (10th, 50th), and total charge.
*   **Robust Caching**: To enable efficient iteration without re-computing these expensive transformations, processed tensors will be saved to disk. Crucially, the cache filename will be generated by hashing the full preprocessing configuration (e.g., sequence length $L$, feature list, normalization method, and dataset version). This ensures that any change in parameters automatically invalidates the cache, preventing the model from training on stale or mismatched data. Cite {solution_lesson_node_00008}

## Training
*   **Loss Function**: **Cosine Similarity Loss**. Defined as $1 - \frac{y_{pred} \cdot y_{true}}{||y_{pred}|| ||y_{true}||}$. This directly optimizes the angular alignment of the direction vector, which is the core metric.
*   **Optimizer**: **AdamW** with a **OneCycleLR** scheduler. This provides a warm-up phase to stabilize the recurrent weights followed by a cosine annealing decay for convergence.
*   **Strategy**: Train on the full training set (using the validation set for early stopping). The hybrid nature allows the model to lean on the robust engineered features early in training while the GRU learns the subtle sequential patterns.

## Evaluation
*   **Inference**: Process test batches to generate the sequence and feature inputs, then pass them through the trained hybrid model.
*   **Post-processing**:
    1.  Normalize the predicted 3D vector to unit length.
    2.  Convert the unit vector to spherical coordinates:
        *   `zenith` = $\arccos(z)$
        *   `azimuth` = $\arctan2(y, x)$ (mapped to $[0, 2\pi)$).
*   **Submission**: Save the resulting angles to the submission CSV.
