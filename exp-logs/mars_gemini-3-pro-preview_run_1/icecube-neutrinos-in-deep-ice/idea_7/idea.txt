# Solution Proposal: Hierarchical Spatiotemporal Graph Network (HSGN)

## Model
I propose a **Hierarchical Spatiotemporal Graph Network (HSGN)**. This architecture represents a structural evolution from the "flat" Dynamic Graph Convolutional Network (Idea 4) and the Graph Transformer (Idea 6). While those models successfully leveraged Geometric Deep Learning (Cite {solution_lesson_node_00011}), they processed all selected pulses at a single resolution. This can be inefficient for neutrino events, which exhibit structures at multiple scales: local dense clusters of photons (cascades) and long-range linear dependencies (tracks).

*   **Input**: A point cloud of $N$ selected pulses with features $(x, y, z, t, \log(q))$.
*   **Hierarchical Backbone**: The model employs a stack of **Set Abstraction Modules** (inspired by PointNet++), which iteratively downsample the point cloud to capture multi-scale features:
    *   **Sampling**: At each level, a subset of points (centroids) is selected using **Farthest Point Sampling (FPS)**. This ensures the receptive fields cover the entire spatiotemporal volume of the event.
    *   **Grouping**: Neighboring points are grouped around each centroid. Crucially, the distance metric for grouping is a **4D Spatiotemporal Distance** ($d^2 = \Delta x^2 + \Delta y^2 + \Delta z^2 + \alpha \Delta t^2$), ensuring that grouped pulses are causally related.
    *   **Feature Extraction**: A local Graph Neural Network (e.g., EdgeConv) processes each local group to generate a feature vector for the centroid.
*   **Global Aggregation**: After the final hierarchical layer reduces the event to a small set of high-level "super-points" (representing track segments or shower centers), a global pooling operation (concatenation of Max and Mean) aggregates them into a single event embedding.
*   **Prediction Head**: An MLP maps the global embedding to a 3D direction vector $(v_x, v_y, v_z)$.

## Data
*   **Stratified Causal-Signal Sampling**: To maintain the high information density identified in Idea 6, we will retain the multi-tier sampling strategy:
    1.  **Causal Set**: The first $K$ pulses sorted by time (capturing the vertex).
    2.  **Signal Set**: The top $M$ pulses sorted by charge (capturing the track body).
    3.  **Context Set**: Random sampling from the remainder.
    This preserves the "arrow of time" and spatial trajectory required for vector reconstruction (Cite {solution_lesson_node_00011}).
*   **Robust Caching**: We will implement a strict caching mechanism where the cache filename is generated by hashing the **entire configuration dictionary** (including sampling hyperparameters, feature scaling, and model architecture versions). This explicitly prevents the "silent failure" of training on stale or mismatched data observed in previous iterations (Cite {solution_lesson_node_00008}).
*   **Normalization**: Coordinates $(x, y, z)$ and time $t$ will be standardized; charge $q$ will be log-transformed.

## Training
*   **Loss Function**: **Cosine Similarity Loss** ($1 - \text{cosine\_similarity}$). This directly optimizes the angular alignment between the predicted and ground truth vectors.
*   **Optimizer**: **AdamW** with a **OneCycleLR** scheduler to manage convergence stability.
*   **Augmentation**:
    *   **Point Dropout**: Randomly drop a small percentage of pulses from the input point cloud during training. This forces the model to learn robust global features rather than over-relying on specific sensor hits.
    *   **Time Jittering**: Add small random offsets to the global event time and individual pulse times to prevent overfitting to specific quantization artifacts.

## Evaluation
*   **Inference**:
    1.  Load test batches and apply the **Stratified Causal-Signal Sampling**.
    2.  Pass the processed point clouds through the trained HSGN.
    3.  Normalize the output vector to unit length.
    4.  Convert the unit vector to spherical coordinates (`azimuth`, `zenith`) for the final submission.
