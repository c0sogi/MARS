The issue stems from a mismatch between the memory layout of the node features and the index map used to retrieve them. The `nodes` array is constructed from the `structures` DataFrame, which is explicitly sorted by `molecule_name`. However, the `index_df` (which maps molecules to slices of the `nodes` array) is constructed using `meta_df["molecule_name"].unique()`, which preserves the arbitrary appearance order of molecules in the metadata. This misalignment causes the `MoleculeDataset` to retrieve node features for the wrong molecule, leading to edge indices that are out of bounds for the retrieved graph slice, triggering the `CUDA error: device-side assert triggered`. Additionally, molecules present in metadata but missing from structures create "ghost" entries with 0 nodes, further corrupting the index alignment.

To fix this, I will modify `library/graph_utils.py` to define `target_molecules` based on the sorted `structures` DataFrame rather than the raw metadata. This ensures that the order of molecules in the index map matches the physical layout of the node feature array and eliminates ghost molecules by intersecting the requested targets with the available structure data (Cite debug_lesson_4).
