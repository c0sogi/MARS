To establish a robust and efficient baseline for predicting scalar coupling constants, I propose a **Single-Model Gradient Boosting** approach using **Minimal Geometric Features**. This solution prioritizes speed and simplicity by avoiding the complex feature engineering of Model 1 (e.g., angles, dihedrals) and the computational overhead of deep learning architectures (Models 2-5).

### Model
The core of the solution is a single **XGBoost Regressor** (Extreme Gradient Boosting) trained on all coupling types simultaneously.
*   **Architecture:** A decision-tree-based ensemble using gradient boosting. Unlike Model 1, which suggests separate models for each coupling type and extensive hand-crafted features, this baseline will use a **single global model** to learn shared representations across coupling types (e.g., the physics of distance decay).
*   **Key Components:**
    *   **Tree Booster:** Uses `gbtree` for non-linear relationship modeling.
    *   **Categorical Handling:** Uses native or one-hot encoding for atom and coupling types to allow the trees to split effectively on chemical environments.

### Data
The data processing pipeline focuses on extracting the most critical physical signal—interatomic distance—without expensive geometric computations.
1.  **Structure Merging:** Load `structures.csv` and merge the Cartesian coordinates (`x`, `y`, `z`) for both `atom_index_0` and `atom_index_1` into the train/test datasets.
2.  **Feature Engineering:**
    *   **Distance:** Calculate the Euclidean distance ($d$) between the atom pair.
    *   **Physics-Informed Transformations:** Create inverse distance features ($1/d$, $1/d^2$, $1/d^3$) to help the tree model approximate physical force/potential laws (Coulombic/Van der Waals interactions).
    *   **Type Encoding:** Label encode the `type` column (e.g., `1JHC`, `2JHH`) and the atomic elements (e.g., `C`, `H`) of the pair.
    *   **Basic Context:** Include the total number of atoms in the molecule as a proxy for molecular size/complexity.
3.  **Sanitization:** Ensure no leakage of "future" data (like Mulliken charges or dipole moments) is used, relying strictly on the molecular structure provided in `structures.csv`.

### Training
The training procedure is designed for efficiency and robustness.
*   **Split:** Use the pre-generated `metadata/train.csv` for training and `metadata/val.csv` for validation. This ensures the model is evaluated on unseen molecules, mirroring the test condition.
*   **Objective Function:** Train using **Mean Absolute Error (MAE)** (`reg:absoluteerror`), which aligns closely with the competition metric (Log MAE).
*   **Optimization:** Use early stopping based on the validation score to prevent overfitting.
*   **Hyperparameters:** Use standard baseline settings (e.g., `max_depth=6-9`, `learning_rate=0.1`) to establish a performance floor without extensive tuning.

### Evaluation
1.  **Prediction:** Generate scalar coupling constant predictions for the samples in `metadata/test.csv`.
2.  **Metric Calculation:** During validation, compute the Log Mean Absolute Error per coupling type and average them to estimate the leaderboard score.
3.  **Submission:** Format the test predictions into the required `id,scalar_coupling_constant` CSV format for submission.
