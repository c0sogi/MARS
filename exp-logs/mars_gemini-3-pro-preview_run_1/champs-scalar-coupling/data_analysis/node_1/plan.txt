The issue is caused by a column name collision during the second `merge` operation. The first merge introduces a column named `atom_index` (from `structures_map`) into the dataframe. During the second merge, the `suffixes=("_0", "_1")` argument instructs pandas to rename overlapping columns, attempting to rename the existing `atom_index` to `atom_index_0`. However, `atom_index_0` already exists in the dataframe (from the original `df_train`), causing a `MergeError`. The fix is to drop the redundant `atom_index` column immediately after each merge, preventing the collision.
