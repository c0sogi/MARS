# Proposed Strategy: Uniform-Capacity Curated-Physics Composite Network

This strategy resolves the conflicts identified in previous iterations regarding **Model Capacity** (Lesson 85), **Residual Stability** (Lesson 64), and **Physics Fidelity** (Lesson 76). It rejects the "Graduated Capacity" (bottleneck-to-wide) approach which caused instability (Cite solution_lesson_node_00085) in favor of a **Uniform-Width Backbone** that maintains a constant, high-capacity state space. It combines this with **Curated Context Injection** and **Strict Identity Residuals** to maximize gradient flow and physical accuracy.

### Model
The architecture is a **Uniform-Capacity Curated-Physics Composite Network**. It maintains a fixed model dimension ($D_{model}=512$) from the stem through the final layer to ensure consistent representational capacity and stable optimization.

*   **Stem (Mixed Multi-Scale Initialization):** The input sequence is processed by a **Multi-Scale 1D Convolutional Block** (Inception-style) with kernel sizes of `[3, 5, 7]`. Crucially, the concatenated output is immediately processed by a **Linear Projection (Dense Layer)** to mix the multi-scale features into a unified representation of dimension **512** (Cite solution_lesson_node_00084). This acts as a "Bottleneck Initialization" to filter high-frequency noise before entering the recurrent backbone (Cite solution_lesson_node_00073).
*   **Backbone (Uniform Composite Blocks):** The core consists of a stack of **4 Composite Blocks**. Unlike previous "Graduated" attempts, every block operates strictly at $D_{model}=512$.
    1.  **Curated Context Injection:** The input to the recurrent layer is formed by concatenating the block input $x$ ($D=512$) with a **Curated Context Vector**. This vector contains **only** Static Attributes ($R, C$) and **Derived Physics Interactions** ($R \cdot u_{in}$, $Volume / C$). We explicitly inject these terms to relieve the network of learning arithmetic multiplication (Cite solution_lesson_node_00076), while strictly excluding raw dynamic noise like lags to preserve the temporal hierarchy (Cite solution_lesson_node_00066).
    2.  **Aligned Bi-LSTM:** A Bidirectional LSTM processes the concatenated input. We set the hidden dimension to **256 per direction**, resulting in a natural output dimension of **512**. This matches the block input $x$ exactly, preventing the information bottleneck observed when compressing Bi-LSTMs (Cite solution_lesson_node_00055).
    3.  **Strict Identity Residual 1:** The residual connection is applied as $y = x + \text{Dropout}(\text{LSTM}(\dots))$. Since dimensions match perfectly (512 -> 512), we use a **Strict Identity Mapping** (no linear weights) on the skip connection. This creates a pristine gradient highway (Cite solution_lesson_node_00064).
    4.  **Pointwise Channel Mixing (FFN):** The output $y$ is passed through a **Pointwise Feed-Forward Network** (`Linear -> GELU -> Linear`) with an expansion factor of **2x** (1024 units). We explicitly avoid 4x expansion to maintain stability without normalization (Cite solution_lesson_node_00052).
    5.  **Strict Identity Residual 2:** A second identity residual is applied: $z = y + \text{Dropout}(\text{FFN}(y))$. We strictly **exclude Layer Normalization** to preserve the absolute pressure magnitude required for regression (Cite solution_lesson_node_00044).
*   **Deep Supervision:** An **Auxiliary Regression Head** is attached to the output of the **2nd Block**. This provides a gradient short-circuit to accelerate convergence and enforce feature quality in early layers (Cite solution_lesson_node_00039).
*   **Head:** A linear layer projects the output of the 4th Block to the final `pressure`.

### Data
The data pipeline is strictly engineered for **Physics Fidelity** and **Control Segregation**.

*   **Physics-Fidelity Feature Engineering:**
    *   **Correct Integration:** Calculate `volume` as the cumulative sum of flow scaled by the time delta: $\sum (u_{in} \cdot \Delta t)$ (Cite solution_lesson_node_00031).
    *   **Soft Physics Integration:** Include interaction terms (`u_in * R`, `volume / C`) as input features to the Stem. We avoid "Hard" additive residuals at the output to prevent unit-mismatch biases (Cite solution_lesson_node_00011).
    *   **Rich Dynamics:** Include Lags (1-4), First Differences, and Second Differences of `u_in` to capture system inertia (Cite solution_lesson_node_00022).
*   **Control Segregation:** Explicitly segregate the `u_out` control flag. It must **not** be scaled or normalized, preserving its binary (0/1) nature for exact loss masking (Cite solution_lesson_node_00058). All other continuous features are scaled using `RobustScaler`.
*   **Robust Caching:** Generate cache filenames using a hash of the configuration to prevent stale data artifacts.

### Training
*   **Loss Function:** Weighted **Masked L1 Loss** ($L_{total} = L_{final} + 0.3 \cdot L_{aux}$). The mask is calculated as `1 - u_out` using the unscaled binary flag (Cite solution_lesson_node_00001).
*   **Optimizer:** **AdamW** with a **OneCycleLR** scheduler.
*   **Strict Gradient Clipping:** We enforce a gradient clipping threshold of **1.0**. This is a mandatory prerequisite for the convergence of the LSTM backbone (Cite solution_lesson_node_00059).
*   **Extended Optimization Horizon:** Train for **35 epochs**. This allows the OneCycleLR scheduler to fully anneal the learning rate, which is critical for solving the cumulative (elastic) dynamics of the system (Cite solution_lesson_node_00028, Cite solution_lesson_node_00057).
*   **Update Budget:** Maintain a batch size of **512** to ensure a sufficient number of gradient updates (Cite solution_lesson_node_00019).
*   **Dropout Placement:** Dropout is applied strictly to the residual branch *before* addition (Cite solution_lesson_node_00024).

### Evaluation
*   **Inference:** The test set is processed through the identical hashed caching and Physics-Fidelity feature pipeline.
*   **Prediction:** Predictions are generated using only the **Final Head** (Block 4 output). The auxiliary head is discarded during inference. The output is flattened and mapped to the `id` column for submission.
