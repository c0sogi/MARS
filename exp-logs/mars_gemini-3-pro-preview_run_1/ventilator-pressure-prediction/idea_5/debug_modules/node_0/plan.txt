### Implementation Strategy

1.  **Environment Setup & Optimization**: To ensure the code runs quickly (within seconds) while exercising the full pipeline, we will create "mini" datasets. We will read a small number of breaths (rows) from the provided metadata files and save them to the `./working` directory.
2.  **Configuration Patching**: We will dynamically modify the attributes of the `library.config` module at runtime. We will point the data paths to our mini datasets, reduce the number of epochs to 1, and set a small batch size. This allows us to use the provided library functions without modification while processing only a fraction of the data.
3.  **Component Demonstration & Verification**:
    *   **Utils**: Verify random seeding and device detection.
    *   **Features**: Manually verify the logic of `add_physics_features` and `encode_categoricals` using a small pandas DataFrame to ensure physics calculations (e.g., `flow_interaction`) are correct.
    *   **Data Pipeline**: Call `data.get_data_loaders` to trigger the caching and loading mechanism. We will assert that the resulting DataLoaders yield batches of the expected shape.
    *   **Model Architecture**: Instantiate `PhysicsResidualModel`. Perform a forward pass with dummy tensors to verify input/output tensor shapes match the sequence length and batch size.
    *   **Loss Function**: Test `MaskedL1Loss` with manually crafted prediction and target tensors to confirm that errors during the expiratory phase (`u_out=1`) are correctly ignored (masked out).
    *   **Training Loop**: Execute `train.train_epoch` and `train.validate_epoch` using the mini-dataloaders. This proves the integration of the model, optimizer, scheduler, and loss function works without crashing.
    *   **Inference**: Run the prediction logic to generate a submission file for the mini test set.
