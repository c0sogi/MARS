# Proposed Strategy: Learnable Physics-Residual Multi-Scale CNN-LSTM

This strategy synthesizes the superior feature extraction of the Multi-Scale CNN (Idea 5), the robust sequential modeling of LSTMs (Idea 1/2), and a novel "Learnable Residual" structure to correctly integrate physical laws without the scaling errors observed in previous attempts.

### Model
I propose a **Learnable Physics-Residual Multi-Scale CNN-LSTM**. This architecture is designed to decouple the linear physical baseline from the complex non-linear dynamics, allowing the network to learn unit conversions explicitly.

*   **Input & Embeddings:** The model accepts time-series control inputs and static lung attributes. Crucially, `R` and `C` are passed through **Learnable Embedding Layers** rather than being treated as continuous scalars. This allows the model to learn distributed representations for these discrete settings, capturing non-linearities better than simple scaling (refining the approach in Idea 5).
*   **Branch 1: Deep Temporal Residual (The "Correction"):**
    *   **Multi-Scale Stem:** The input sequence passes through a **Multi-Scale 1D Convolutional Block** (Inception-style) with kernel sizes of `[3, 5, 7]`. This extracts both fine-grained noise and smoothed trends simultaneously (Cite solution_lesson_node_00015).
    *   **Backbone:** The features are processed by a stack of **Bidirectional LSTM** layers. We retain LSTMs over Transformers due to their superior inductive bias for this specific sequence length and data scale (Cite solution_lesson_node_00008).
    *   **Projection:** A dense layer projects the LSTM output to a scalar prediction sequence $\Delta P$.
*   **Branch 2: Learnable Physics Adapter (The "Baseline"):**
    *   In parallel, the physics-based interaction features (specifically `u_in * R` and `cumulative_volume / C`) are passed into a shallow **Linear Adapter Network** (a single dense layer with no activation).
    *   Unlike the "Hard" integration in Idea 4 which failed due to unit mismatches (Cite solution_lesson_node_00011), this layer explicitly learns the scaling coefficients (weights) required to convert these proxy units into pressure units (cmH2O).
*   **Fusion:** The final output is the element-wise sum of the LSTM prediction and the Physics Adapter prediction: $P_{final} = \text{LSTM}(x) + \text{Adapter}(x_{phys})$. This structural change forces the LSTM to focus solely on the difficult, non-linear residuals while the linear path handles the bulk pressure magnitude.

### Data
The data pipeline is engineered for physical fidelity and reproducibility.

*   **Equation-Driven Feature Engineering:** We generate features derived from the Equation of Motion:
    *   `cumulative_volume`: The time-integral of `u_in`.
    *   `flow_interaction`: `u_in * R`.
    *   `volume_interaction`: `cumulative_volume / C`.
    *   These features are provided to both the CNN stem (concatenated) and the Physics Adapter (exclusively) (Cite solution_lesson_node_00005).
*   **Robust Caching:** To prevent stale data issues, all cache filenames are generated using a **configuration hash** that includes the feature list and preprocessing parameters. This ensures any change to the engineering logic triggers a fresh dataset generation (Cite solution_lesson_node_00002).
*   **Preprocessing:** Continuous features are scaled using `RobustScaler`. Data is reshaped to `(N_breaths, 80, N_features)`.

### Training
*   **Loss Function:** We utilize the **Masked L1 Loss**. The error is calculated for the entire sequence but multiplied by `(1 - u_out)` before averaging. This strictly focuses the gradient updates on the inspiratory phase, preventing the model from wasting capacity on the irrelevant expiratory phase (Cite solution_lesson_node_00001).
*   **Optimization:** We use the **AdamW** optimizer with a **OneCycleLR** scheduler.
*   **Update Budget Management:** We will use a batch size of **512** but explicitly set the training duration to **20 epochs**. This ensures we maintain a sufficient number of total gradient updates to allow convergence, avoiding the underfitting observed when batch size was increased without scaling epochs (Cite solution_lesson_node_00019).

### Evaluation
*   **Inference:** The test data is processed through the identical hashed caching and feature engineering pipeline.
*   **Prediction:** The model generates the `pressure` sequence for each breath. These sequences are flattened and mapped to the `id` column in the submission format.
