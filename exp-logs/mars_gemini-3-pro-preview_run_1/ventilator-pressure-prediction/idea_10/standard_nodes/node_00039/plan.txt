The issue is that the `RobustScaler` in the preprocessing pipeline indiscriminately scales all features, including the binary control input `u_out`. Since `u_out` has a median of 1 (expiratory phase is more frequent), scaling shifts the values from `{0, 1}` to `{-1, 0}`. This breaks the downstream logic in the loss function and validation script, which rely on `u_out == 0` to identify the inspiratory phase. As a result, the model is evaluated on the expiratory phase (where the scaled value is 0), leading to an incorrect metric. The fix is to manually override the scaler parameters for `u_out` in `library/features.py` to ensure it remains unscaled (center=0, scale=1).
