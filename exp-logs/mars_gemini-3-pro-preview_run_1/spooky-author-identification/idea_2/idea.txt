# Idea 2: Neural-Linear Ensemble with Sparse Stylometry

### Model
I propose a **Neural-Linear Ensemble** that fuses the strengths of deep contextual representations with the robust stylometric signals identified in the previous attempt. The architecture consists of two parallel branches:
1.  **The Contextual Branch (Deep):** A pre-trained Transformer model (specifically `roberta-base` or similar) with a classification head. This component addresses the weakness identified in the previous solution where short sentences lacked sufficient signal; the Transformer's self-attention mechanism leverages pre-trained linguistic knowledge to infer authorship even from brief, semantically sparse inputs.
2.  **The Stylometric Branch (Wide):** A Logistic Regression classifier operating on **Hybrid TF-IDF features (Word N-grams 1-3 + Character N-grams 3-5)**. This explicitly preserves the successful feature engineering strategy that captures morphological "fingerprints" Cite {solution_lesson_node_00001}.

The final predictions will be generated via a **Weighted Soft Voting** mechanism, combining the probability distributions from both branches.

### Data
Preprocessing will diverge for the two branches:
- **For the Contextual Branch:** Raw text will be tokenized using the Transformer's specific sub-word tokenizer (e.g., Byte-Pair Encoding), preserving casing and punctuation as they are critical for author identification.
- **For the Stylometric Branch:** Text will be vectorized into TF-IDF matrices for both word and character n-grams. Crucially, strictly adhering to the lessons learned, these matrices will be **maintained in their sparse format (CSR/CSC)** throughout the entire pipeline. We will strictly avoid densifying these matrices to prevent the memory overhead and excessive runtime observed previously Cite {solution_lesson_node_00001}.

### Training
The training process will be decoupled to maximize efficiency:
1.  **Contextual Training:** The Transformer will be fine-tuned on the GPU using the **Multi-class Logarithmic Loss**. We will employ standard techniques such as AdamW optimization, a linear learning rate decay, and early stopping based on validation loss.
2.  **Stylometric Training:** The Logistic Regression model will be trained on the CPU using a solver optimized for sparse data (e.g., `saga` or `lbfgs` with sparse support). This ensures the linear baseline trains in seconds rather than minutes Cite {solution_lesson_node_00001}.
3.  **Ensemble Weighting:** Weights for the soft vote (e.g., $0.6 \times P_{trans} + 0.4 \times P_{linear}$) will be determined by minimizing log loss on the validation set.

### Evaluation
For evaluation, the test text will be processed through both pipelines independently. The Transformer will output a probability distribution based on context, while the Linear model will output a distribution based on n-gram frequency. These probabilities will be linearly combined using the optimized weights, and the result will be clipped (as per the metric definition) before generating the submission file.
