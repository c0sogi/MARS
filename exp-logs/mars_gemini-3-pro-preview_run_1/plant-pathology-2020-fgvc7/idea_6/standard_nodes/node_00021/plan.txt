The issue in the previous implementation was **data leakage**: the `run_training` function in `library/train.py` merged the training metadata with the validation metadata before performing cross-validation. This caused the hold-out validation set (used later in `runfile.py` for final scoring) to be included in the training data for the models, leading to an invalid and inflated evaluation metric.

To fix this, I will modify `library/train.py` to load only the training metadata (`Config.TRAIN_METADATA_PATH`) for the cross-validation process. This ensures the validation set remains completely unseen by the models during training, preserving the integrity of the final evaluation.
