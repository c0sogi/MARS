To establish a robust and highly efficient baseline for the taxi fare prediction task, I propose a **Spatial-Temporal Gradient Boosting Machine**. This approach synthesizes the efficiency of the Gradient Boosting architecture (Model 1) with domain-specific feature engineering to handle the spatial and temporal nature of the data without requiring complex deep learning structures.

# Model
The core model will be a **LightGBM (Light Gradient Boosting Machine) Regressor**. This architecture is chosen for its exceptional training speed and low memory usage on large datasets (55M rows) compared to traditional random forests or neural networks.
- **Architecture**: The model consists of an ensemble of decision trees trained sequentially, where each new tree corrects the errors (residuals) of the previous ones.
- **Key Components**:
    - **Leaf-wise Growth**: The trees will use a leaf-wise growth strategy to minimize loss more rapidly than level-wise growth.
    - **Histogram-based Learning**: Continuous features will be binned into histograms to speed up split finding and reduce memory footprint.
    - **Regression Head**: The final output will be a single continuous value representing the predicted fare amount.

# Data
Efficient data processing is critical given the dataset size.
1.  **Cleaning**:
    - **Filtering**: Remove rows with invalid coordinates (e.g., latitude outside -90 to 90, longitude outside -180 to 180, or coordinates at 0,0).
    - **Target Cleaning**: Remove rows with negative or zero `fare_amount`, and extreme outliers (e.g., fares > $500) to stabilize training.
    - **Passenger Count**: Filter out rides with 0 or excessive passenger counts (e.g., > 10).
2.  **Feature Engineering**:
    - **Geospatial Features**: Since the model cannot inherently understand "distance" from raw coordinates easily, we will explicitly calculate the **Haversine distance** (great-circle distance) between pickup and dropoff points. We will also compute the **Manhattan distance** and the absolute differences in latitude and longitude.
    - **Temporal Features**: The `pickup_datetime` timestamp will be decomposed into numerical components: **Hour**, **Day of Week**, **Month**, and **Year**. The "Year" feature is particularly important to capture the inflation or base rate changes over time.
    - **Coordinate Features**: Raw pickup and dropoff latitude/longitude values will be retained as features, allowing the tree to learn location-specific surcharges (e.g., airport fees).

# Training
The training procedure prioritizes speed while ensuring convergence.
- **Loss Function**: The model will be trained to minimize **Root Mean Squared Error (RMSE)**, aligning directly with the competition metric.
- **Optimizer**: The native LightGBM optimization algorithm (gradient descent on leaf values) will be used.
- **Strategy**:
    - **Train/Validation Split**: We will use the pre-generated stratified validation set (`val.parquet`) to monitor performance.
    - **Early Stopping**: Training will halt if the validation RMSE does not improve for a set number of rounds (e.g., 50) to prevent overfitting and save time.
    - **Hyperparameters**: We will use a relatively high learning rate (e.g., 0.1) with a moderate number of trees for the baseline, ensuring the run completes quickly.

# Evaluation
- **Inference**: The test set (`test.parquet`) will undergo the exact same cleaning (where applicable) and feature engineering pipeline as the training set.
- **Prediction**: The trained LightGBM model will predict the `fare_amount` for each row in the test set.
- **Submission**: The resulting predictions will be paired with their corresponding `key` and saved to a CSV file in the required format.
