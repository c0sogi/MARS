The implementation strategy follows a structured pipeline designed to be robust, reproducible, and efficient within the provided time constraints.

1.  **Setup & Configuration**: We initialize the environment by setting random seeds for reproducibility using `library.utils.seed_everything` and verifying the configuration from `library.config`.
2.  **Training**: We execute the training pipeline via `library.train.train_model`. We utilize the full training dataset and the default 20 epochs specified in the configuration. Given the dataset size (~2000 samples) and the efficiency of the BiLSTM model on a GPU, this will complete quickly (typically under 5 minutes) while ensuring the model converges sufficiently to meet performance targets.
3.  **Validation & Metric Calculation**:
    *   We load the best saved model and the validation dataloader.
    *   We perform a dedicated inference pass on the validation set to retrieve raw predictions and ground truth targets.
    *   We calculate the **Final Validation Metric** (MCRMSE) using the `library.utils.mcrmse_loss` function, which correctly handles the column-wise averaging and sequence slicing (first 68 positions). This metric is printed with full precision.
4.  **Failure Analysis**:
    *   We compute the error magnitude for each validation sample individually.
    *   We load the validation metadata (from `val.parquet`) to access auxiliary features like `signal_to_noise` and sequence content (counts of A, G, C, U).
    *   We calculate and print the Pearson correlation between the sample errors and these features to identify systematic weaknesses (e.g., if the model struggles with noisy samples or specific nucleotide distributions).
5.  **Submission**:
    *   We compare the calculated validation metric against the strict threshold of `0.6176461577`.
    *   If the model's performance is superior (lower metric), we trigger `library.train.generate_submission_file` to produce the final `submission.csv` for the test set.
