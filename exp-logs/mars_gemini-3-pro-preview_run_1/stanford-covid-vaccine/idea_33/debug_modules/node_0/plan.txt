Implementation Strategy:
1.  **Configuration**: Subclass the provided `Config` to create a `DemoConfig`. This allows us to override hyperparameters (reduce epochs, batch size, model size) and set a specific working directory (`./working/demo_run`) to ensure the demo runs quickly and doesn't interfere with other potential runs.
2.  **Unit Verification**: Implement standalone functions to verify the core components:
    *   `test_dataset_loading`: Loads a small subset of the training data using `get_dataset` with `num_samples` and asserts correct shapes and keys.
    *   `test_model_forward`: Instantiates the `RNAModel` with the demo config and runs a dummy batch to verify the forward pass and output dimensions.
    *   `test_metric_logic`: Validates the `mcrmse_loss` function against a manual calculation to ensure metric correctness.
    *   `test_submission_formatting`: Verifies that `format_submission` produces a DataFrame with the correct schema and row count.
3.  **Integration Pipeline**:
    *   Execute `run_training` using the `DemoConfig` and a small number of samples (`num_samples=32`) to quickly generate a trained model file.
    *   Execute `run_inference` to generate predictions on the test set (240 samples) and save the submission file.
    *   Assert that the output files (`best_model.pth`, `submission.csv`) are created and valid.
4.  **Execution**: Wrap the verification and pipeline steps in the `__main__` block, ensuring a clean working directory at the start.
