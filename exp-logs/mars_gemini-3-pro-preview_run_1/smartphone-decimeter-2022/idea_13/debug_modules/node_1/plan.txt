The issue is caused by a timestamp precision mismatch between the aggregated GNSS features and the ground truth (GT) data. The GNSS timestamps are rounded to the nearest second (1Hz alignment) during preprocessing, while the GT timestamps retain millisecond precision. This results in an empty intersection when merging on `UnixTimeMillis`, causing the pipeline to fail with a "No data processed" error.

To fix this:
1.  **In `_process_drive`**: I will round the ground truth `UnixTimeMillis` to the nearest second before merging with the GNSS features. This ensures the keys match (Cite `debug_lesson_4`).
2.  **In `process_data`**: For the test set (where GT is not available), I will implement a mapping strategy. I will round the requested exact timestamps from the submission file to match the feature timestamps for filtering, and then restore the exact timestamps in the final dataframe to ensure the submission format is correct.
