Based on the lessons learned, I propose a **Multiscale 1D U-Net with Cartesian Residuals**. This strategy evolves the previous TCN-based approaches by adopting an Encoder-Decoder architecture to explicitly model errors at different temporal scales (e.g., slow atmospheric drift vs. sudden multipath spikes) and transforms the regression target into a physically consistent metric space.

### Model
**Architecture: 1D U-Net**
Instead of a flat stack of dilated convolutions (TCN), the backbone will be a **1D U-Net**.
*   **Encoder:** A series of convolutional blocks followed by pooling operations. This downsampling path increases the receptive field and extracts high-level, low-frequency features, allowing the model to identify long-term biases or drifts in the signal (e.g., entering a dense urban area).
*   **Decoder:** A series of upsampling layers that restore the temporal resolution.
*   **Skip Connections:** Critical for this task, skip connections concatenate high-frequency features from the Encoder directly to the Decoder. This preserves local signal details (e.g., a momentary drop in `Cn0DbHz`), enabling the model to make sharp corrections for sudden noise spikes while maintaining the global bias correction learned by the bottleneck.
*   **Capacity Control:** The network depth and channel width will be kept moderate to prevent overfitting to specific drive fingerprints, adhering to the findings on overparameterization (Cite solution_lesson_node_00002).

### Data
**Preprocessing Pipeline**
1.  **Temporal Alignment:** Raw GNSS logs and ground truth timestamps will be aligned by **rounding to the nearest second (1Hz quantization)** rather than exact matching, ensuring valid sensor data is not discarded due to clock jitter (Cite solution_lesson_node_00016).
2.  **Feature Aggregation:** Instead of complex set-based architectures, raw satellite data will be aggregated per timestamp using robust statistics (mean, max, count) of signal quality metrics (`Cn0DbHz`, `SvElevationDegrees`) and solution metadata (`SatCount`, `RawPseudorangeUncertaintyMeters`) (Cite solution_lesson_node_00014, solution_lesson_node_00006).
3.  **Translation Invariance:** Absolute geospatial coordinates (`Latitude`, `Longitude`) will be strictly excluded from the input features to prevent the model from memorizing training trajectories (Cite solution_lesson_node_00003).
4.  **Target Transformation (Innovation):** The regression target will be transformed from Degrees (Latitude/Longitude) to **Meters (North/East)** relative to the WLS baseline. This normalizes the output space, making the loss function physically consistent regardless of the drive's latitude, and simplifies the learning task for the network.

### Training
*   **Loss Function:** **Mean Absolute Error (MAE)** will be used to regress the North/East residuals. MAE is preferred for its robustness to the heavy-tailed error distributions common in urban GNSS data (Cite solution_lesson_node_00001).
*   **Optimizer:** AdamW with weight decay will be used to regularize the model.
*   **Validation Strategy:** A `GroupShuffleSplit` based on `drive_id` will be employed to ensure the model is evaluated on entirely unseen trips, preventing data leakage and ensuring realistic performance estimates.

### Evaluation
1.  **Inference:** The model will predict the residual vector $(\Delta North, \Delta East)$ in meters for each timestamp in the test set.
2.  **Reconstruction:** These Cartesian residuals will be converted back into angular offsets ($\Delta Lat, \Delta Lon$) using the WGS84 ellipsoid parameters and added to the provided WLS baseline coordinates.
3.  **Submission:** The final corrected coordinates will be formatted into the required CSV structure.
