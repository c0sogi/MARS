The issue is that the `UnixTimeMillis` timestamps in the ground truth metadata (and sample submission) have millisecond precision (e.g., `...432`), while the aggregated GNSS data has timestamps rounded to the nearest second (e.g., `...000`). An inner join on `UnixTimeMillis` fails to find matches, resulting in an empty dataset.

To fix this, I will modify `library/data_processing.py` to create a temporary `UnixTimeMillis_rounded` column in the metadata by rounding the original timestamps to the nearest second. I will then rename the GNSS data's timestamp column to match this new key and perform the merge on `UnixTimeMillis_rounded`. This ensures correct alignment of features and targets while preserving the original `UnixTimeMillis` column in the resulting DataFrame, which is required for the submission file.
