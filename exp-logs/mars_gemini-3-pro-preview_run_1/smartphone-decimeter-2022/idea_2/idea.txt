Based on the accumulated lessons, I propose a **Multi-Modal Sensor Fusion TCN**. This strategy evolves the previous "Residual Learning" approach by structurally integrating Inertial Measurement Unit (IMU) data to provide a "dead reckoning" context. This allows the model to differentiate between genuine movement and GNSS noise spikes (e.g., a sudden jump in GNSS position unsupported by accelerometer data).

### Model
**Architecture Design**
The core backbone remains a **Temporal Convolutional Network (TCN)** to process time-series windows, as this has proven effective and efficient. However, the input layer is restructured to accept a multi-modal feature vector.
*   **Inputs:** A windowed sequence (e.g., 128 time steps) of feature vectors. Each time step contains:
    1.  **GNSS Signal Quality:** `Cn0DbHz` (mean), `SvElevationDegrees` (mean), and `WlsAlt`. These translation-invariant features describe the geometric and signal environment (Cite solution_lesson_node_00003).
    2.  **Solution Metadata:** `SatCount` and `RawPseudorangeUncertaintyMeters` to quantify the baseline's reliability (Cite solution_lesson_node_00006).
    3.  **IMU Dynamics (New):** Aggregated accelerometer magnitude and gyroscope yaw rate. These provide independent evidence of motion.
    4.  **Baseline Dynamics (New):** The first-order difference (velocity) of the WLS baseline. This allows the model to compare the *implied* movement of the GNSS baseline against the *measured* movement from the IMU.
*   **Outputs:** The model predicts the 2D residual vector $(\Delta Lat, \Delta Lon)$ to correct the WLS baseline (Cite solution_lesson_node_00001).
*   **Capacity Constraint:** The network depth and width will be kept constrained (e.g., 32-64 channels per layer) to prevent overfitting to specific drive trajectories (Cite solution_lesson_node_00002).

### Data
**Preprocessing Pipeline**
1.  **GNSS Aggregation:** Group raw satellite measurements by timestamp. Calculate the mean signal strength (`Cn0DbHz`) and elevation (`SvElevationDegrees`), and the count of satellites (`SatCount`).
2.  **IMU Processing:** Load `device_imu.csv`. Calculate the Euclidean norm of the accelerometer vectors ($a = \sqrt{x^2+y^2+z^2}$) to get total acceleration magnitude.
3.  **Sensor Alignment:** Resample the high-frequency IMU data to match the 1Hz GNSS timestamps. Use statistical aggregation (mean and standard deviation) for each 1-second bin to capture both the motion intensity and the vibration/noise level.
4.  **Feature Engineering:** Calculate the step-to-step velocity of the WLS baseline coordinates.
5.  **Target Generation:** Calculate the target residuals: $Target = GroundTruth - Baseline_{WLS}$.
6.  **Windowing:** Create sliding windows of the aligned, multi-modal feature matrix.
7.  **Exclusion:** Explicitly drop absolute `Latitude` and `Longitude` from the input features to ensure translation invariance (Cite solution_lesson_node_00003).

### Training
*   **Loss Function:** Use **Mean Absolute Error (MAE)**. This is robust to the heavy tails of GNSS error distributions (outliers).
*   **Optimizer:** AdamW with a standard learning rate (e.g., 1e-3) and weight decay.
*   **Validation Strategy:** Use `GroupShuffleSplit` based on `drive_id` to ensure the model is evaluated on entirely unseen trips, preventing leakage.

### Evaluation
*   **Inference:** For each timestamp in the test set, generate the multi-modal feature window and feed it to the trained TCN.
*   **Reconstruction:** Add the predicted residuals $(\Delta Lat, \Delta Lon)$ to the provided WLS baseline coordinates to obtain the final predicted Latitude and Longitude.
*   **Post-Processing:** Ensure the output format matches the submission requirements (tripId, UnixTimeMillis, LatitudeDegrees, LongitudeDegrees).
