The previous implementation failed due to two primary data preprocessing issues identified in the error analysis:

1.  **Data Loss (Timestamp Mismatch):** The `PreProcessor` rounded `utcTimeMillis` from GNSS logs to the nearest second, assuming alignment with ground truth timestamps. However, ground truth timestamps are exact (e.g., ending in `432`ms). This mismatch caused the merge between features and ground truth to fail for most drives, resulting in an empty or very small training dataset (only 9 batches).
2.  **NaN Loss (Missing Baseline):** The pipeline did not filter out samples where the Weighted Least Squares (WLS) baseline position was missing (`NaN`). These `NaN` values propagated into the regression targets (`target_east`, `target_north`). When the model encountered these `NaN` targets, the loss function returned `NaN`, corrupting the training process immediately.

To fix these issues, I will modify `library/preprocessing.py` to:
1.  **Use Exact Timestamps:** Remove the rounding logic in `_compute_features` and use the exact `utcTimeMillis` (converted to `int64`) as the `UnixTimeMillis` key. This ensures correct alignment with the ground truth data.
2.  **Sanitize Targets:** In `_process_drive`, explicitly drop rows where the calculated targets (`target_east`, `target_north`) are `NaN`. This prevents invalid data from reaching the model, applying the lesson learned about sanitizing regression targets (Cite debug_lesson_7).
