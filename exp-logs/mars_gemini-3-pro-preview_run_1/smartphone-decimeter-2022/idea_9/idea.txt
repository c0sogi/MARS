Based on the accumulated lessons, I propose the **Hybrid 1D ResUNet-GRU with Distributional Signal Embeddings**.

This strategy introduces two structural innovations:
1.  **Distributional Feature Engineering:** It evolves the "Simple Aggregation" (Cite solution_lesson_node_00014) and "Boundary Aggregation" (Cite solution_lesson_node_00020) by representing the satellite constellation state as **histograms** (distributional embeddings) rather than just scalar statistics. This allows the model to distinguish complex signal environments (e.g., bimodal signal strengths indicating mixed line-of-sight and multipath signals) that simple means or minimums might obscure.
2.  **Hybrid Backbone:** It integrates a **Bi-directional GRU** at the bottleneck of the **1D U-Net** (Cite solution_lesson_node_00018). While the U-Net handles local signal denoising efficiently, the RNN component explicitly models the continuous temporal state evolution (e.g., clock drift or atmospheric bias accumulation) across the entire drive, addressing the long-term dependency limitations of pure CNNs.

### Model
**Architecture: 1D Residual U-Net with RNN Bottleneck**
*   **Input:** A sequence of feature vectors representing the entire drive (Batch Size, Features, Time Steps).
*   **Encoder:** A stack of **1D Residual Blocks** (ResNet style) followed by Max Pooling layers. This progressively downsamples the temporal resolution to extract robust, high-level features from the noisy sensor data.
*   **Bottleneck (Hybrid Innovation):** The compressed feature sequence is fed into a **Bi-directional GRU (Gated Recurrent Unit)**. This layer processes the sequence forward and backward to capture global context and long-term dependencies (drifts) that persist throughout the drive.
*   **Decoder:** A stack of upsampling layers and 1D Residual Blocks.
*   **Skip Connections:** Features from the Encoder are concatenated with the Decoder inputs (Cite solution_lesson_node_00018) to preserve high-frequency local signal details (e.g., sudden signal drops) essential for precise localization.
*   **Output Head:** A final 1D Convolution projects the features to a 2D output: the Cartesian residuals $(\Delta North, \Delta East)$ for each timestamp.

### Data
**Preprocessing Pipeline**
1.  **Temporal Quantization:** Align raw GNSS logs and ground truth by rounding timestamps to the nearest second (1Hz). This prevents data loss caused by exact matching failures due to clock jitter (Cite solution_lesson_node_00016).
2.  **Distributional Feature Extraction (Innovation):** For each timestamp, construct a rich representation of the satellite signals:
    *   **Histograms:** Bin `Cn0DbHz` (Signal Strength) and `SvElevationDegrees` into fixed ranges (e.g., 5-10 bins). Count the number of satellites falling into each bin. This creates a "fingerprint" of the signal quality distribution.
    *   **Boundary Statistics:** Explicitly calculate the **Minimum** and **Maximum** values for `Cn0DbHz` and `SvElevationDegrees` (Cite solution_lesson_node_00020). The minimum elevation is a critical indicator of multipath risk.
    *   **Metadata:** Include `SatCount` and aggregated `RawPseudorangeUncertaintyMeters` to quantify baseline reliability (Cite solution_lesson_node_00006).
3.  **Translation Invariance:** Strictly exclude absolute `Latitude` and `Longitude` coordinates from the input features to ensure the model learns error dynamics rather than memorizing training maps (Cite solution_lesson_node_00003).
4.  **Target Transformation:** Convert regression targets from Degrees (Lat/Lon) to **Meters (East-North)** relative to the WLS baseline. This ensures the loss function operates in a physically consistent metric space (Cite solution_lesson_node_00018).

### Training
*   **Loss Function:** **Mean Absolute Error (MAE)**. This is selected for its robustness to the heavy-tailed outlier distributions inherent in urban GNSS data (Cite solution_lesson_node_00001).
*   **Optimizer:** AdamW with weight decay is used to prevent overfitting, particularly in the recurrent layers.
*   **Validation Strategy:** Use `GroupShuffleSplit` grouped by `drive_id`. This ensures the model is validated on entirely unseen drives, preventing data leakage and providing realistic performance estimates.

### Evaluation
1.  **Inference:** The preprocessed feature sequence for a full test drive is fed into the model. The model outputs the sequence of Cartesian residuals $(\Delta North, \Delta East)$.
2.  **Reconstruction:** These Cartesian offsets are converted back into angular offsets $(\Delta Lat, \Delta Lon)$ using local WGS84 approximations.
3.  **Correction:** The predicted offsets are added to the baseline WLS coordinates provided in the test set to generate the final submission coordinates.
