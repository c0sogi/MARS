To resolve the `NaN` loss error caused by missing or invalid target values, I will update the `process_drive` function in `library/features.py`. The fix involves four key changes:
1.  **Robust Aggregation:** Change the WLS baseline aggregation from `.first()` to `.mean()` to prevent `NaN` values from propagating if the first row of a group is missing data (Cite debug_lesson_6).
2.  **Timestamp Alignment:** Round the `UnixTimeMillis` in the metadata to the nearest second before merging with the GNSS data. This ensures the join keys match, preventing the loss of baseline coordinates (Cite debug_lesson_4).
3.  **Strict Filtering:** Drop rows where the WLS baseline is missing immediately after the merge (Cite debug_lesson_25) and filter out computed targets that are `NaN`, `Inf`, or physically impossible (> 1,000 km) (Cite debug_lesson_11).
4.  **Remove Invalid Imputation:** Remove the `fillna(0)` call for WLS coordinates, as filling missing baselines with zero places them at the Earth's center, causing massive target errors.
