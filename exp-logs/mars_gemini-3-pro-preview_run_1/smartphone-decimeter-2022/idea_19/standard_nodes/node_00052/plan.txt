The `IntCastingNaNError` is caused by the presence of `NaN` or infinite values in the `SvAzimuthDegrees` column of the GNSS data, which fails when pandas attempts to cast the calculated bin indices to integers. To fix this, I will implement a sanitization step that filters out rows with non-finite azimuth values before performing the binning operation. If filtering removes all data for a drive, the function will return `None` to gracefully skip it. This approach ensures that only valid sensor data enters the feature construction pipeline (Cite debug_lesson_2).
