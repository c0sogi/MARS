To address the `ZeroDivisionError` and the underlying data loading issue causing the validation set to be empty, I will implement the following changes:

1.  **Fix Cache Collision in `library/utils.py`**: The `process_target_residuals` function currently saves processed targets to a fixed filename (`target_residuals.parquet`). This causes the validation data loader to load the training residuals (cached during training data loading) instead of computing its own. Since training and validation drives are disjoint, merging training residuals with validation metadata results in an empty dataset. I will modify the function to append a hash of the `drive_id`s to the cache filename, ensuring unique cache files for different data splits (Cite debug_lesson_3).
2.  **Handle Empty Datasets in `library/trainer.py`**: I will add guard clauses in `train_epoch` and `validate` to check if `total_samples` is zero before performing division. This prevents the `ZeroDivisionError` and returns appropriate fallback values (`NaN` loss, infinite metric) if the dataset is empty.
