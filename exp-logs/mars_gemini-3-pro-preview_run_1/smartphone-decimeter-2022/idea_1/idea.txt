Model 1 (GBDT) relies on statistical aggregates of a window, while Model 2 (LSTM) uses recurrent connections for temporal dependencies. A **1D Convolutional Neural Network (1D-CNN)** offers a distinct, lightweight, and highly efficient baseline. It processes the raw temporal sequence of baseline positions directly (unlike Model 1's aggregates) and leverages parallelizable convolution operations (unlike Model 2's sequential processing) to learn local smoothing patterns and error corrections.

### Model
The proposed architecture is a **Temporal Convolutional Denoising Network**.
*   **Input**: The model accepts a fixed-length time-series window of "Baseline States" derived from the raw GNSS log. Each time step in the window contains a vector comprising the WLS (Weighted Least Squares) estimated Latitude and Longitude, along with aggregated signal quality indicators (specifically, the average Carrier-to-Noise density `Cn0DbHz` and average Satellite Elevation `SvElevationDegrees` for that epoch).
*   **Architecture**: The core consists of a stack of 3 to 4 standard **1D Convolutional layers**. These layers use small kernels (e.g., size 3 or 5) to capture local temporal dynamics and trends in the movement and noise. Non-linear activations (ReLU) are applied between layers.
*   **Output**: The network terminates with a fully connected layer that projects the learned features into a 2D correction vector $(\Delta Lat, \Delta Lon)$ corresponding to the central timestamp of the input window.
*   **Mechanism**: The model effectively learns a non-linear smoothing filter. By observing the trajectory context and signal quality, it determines how much to adjust the current WLS position to approximate the ground truth.

### Data
1.  **Aggregation**: The raw `device_gnss.csv` contains multiple rows per timestamp (one per satellite). Preprocessing first aggregates this to one row per timestamp by:
    *   Extracting the baseline WLS position (`WlsPositionXEcefMeters` converted to Latitude/Longitude).
    *   Computing the mean `Cn0DbHz` and `SvElevationDegrees` of all satellites visible at that timestamp.
2.  **Alignment**: The aggregated GNSS data is merged with `ground_truth.csv` based on `UnixTimeMillis`.
3.  **Target Generation**: The regression target is defined as the residual: $Target = GroundTruth - Baseline_{WLS}$.
4.  **Windowing**: The continuous time-series data for each drive is sliced into overlapping sliding windows (e.g., 64 time steps) to form the input tensors.
5.  **Normalization**: Input features (Lat, Lon, CN0, Elevation) are standardized (z-score normalization) to ensure stable training.

### Training
*   **Loss Function**: **Mean Absolute Error (MAE)** is used instead of MSE. MAE is less sensitive to the extreme outliers often present in GNSS data (e.g., due to "urban canyon" multipath effects), leading to a more robust baseline model.
*   **Optimizer**: The Adam optimizer is used with a standard learning rate (e.g., 1e-3).
*   **Strategy**: Training is performed using a standard batch-based approach. To prevent overfitting to specific drive patterns, an early stopping mechanism monitors the loss on a hold-out validation set (split by `drive_id`).

### Evaluation
1.  **Preprocessing**: The test set `device_gnss.csv` files are aggregated and windowed using the exact same pipeline as the training data.
2.  **Inference**: The trained 1D-CNN predicts the residual corrections $(\Delta Lat, \Delta Lon)$ for each timestamp in the test set.
3.  **Reconstruction**: The final predicted coordinates are obtained by adding the predicted corrections back to the baseline WLS positions: $Prediction = Baseline_{WLS} + PredictedResidual$.
4.  **Submission**: The resulting Latitude and Longitude values are formatted into the required submission CSV.
