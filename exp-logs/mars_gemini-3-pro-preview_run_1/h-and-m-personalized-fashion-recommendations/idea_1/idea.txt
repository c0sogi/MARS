Based on the task requirements and the provided dataset, I propose a highly efficient baseline solution that prioritizes speed and simplicity while establishing a strong performance benchmark.

# Model
I propose a **Time-Decayed Trend & Repurchase Cascade**. This model simplifies the collaborative filtering and ranking concepts (found in Model Architectures 1 and 2) into a lightweight, heuristic-based approach. It operates on the hypothesis that future purchases are driven by two primary factors: a user's recent personal history (repurchase/habit) and the aggregate market momentum (trend).

The architecture consists of two non-parametric scoring components:
1.  **Global Trend Scorer**: Calculates a relevance score for every `article_id` based on its sales velocity across the entire population. To account for fast-moving fashion cycles, transactions are weighted by a time-decay factor (e.g., inverse time since purchase), ensuring recent bestsellers rank higher than older ones.
2.  **Personal History Scorer**: Retrieves the specific items a user has purchased in the past. These are ranked by recency, assuming that items bought recently are more likely to be relevant (e.g., rebuying basics or completing an outfit) than items bought months ago.

The final prediction is generated via a **Cascade Strategy**: For each user, the model first fills prediction slots with their top-ranked personal history items. If the user has fewer than 12 history items (or has no history), the remaining slots are filled with the top-ranked items from the Global Trend Scorer.

# Data
1.  **Temporal Filtering**: To maximize relevance and reduce noise, the training data (`transactions_train.csv`) will be filtered to include only the last $N$ weeks (e.g., 4 to 8 weeks) of transactions. This ensures the model focuses on the current season.
2.  **Date Processing**: The `t_dat` column will be converted to datetime objects to calculate the "days elapsed" between the transaction date and the end of the training period.
3.  **ID Encoding**: `customer_id` and `article_id` will be mapped to integer indices to minimize memory usage during aggregation, though the final output will be mapped back to the original string format.
4.  **Exclusion**: Image and text data will be excluded to maintain high throughput and low latency, adhering to the strict efficiency philosophy.

# Training
Since this is a heuristic-based model, "training" consists of efficient memory-based aggregations rather than gradient descent:
1.  **Trend Index Construction**: Group the filtered transactions by `article_id`. Calculate the sum of decay weights (e.g., $1 / (\text{days\_elapsed} + \alpha)$) for each article. Sort all articles by this score to create a master `Trend_List`.
2.  **History Index Construction**: Group the filtered transactions by `customer_id`. For each user, create a list of purchased `article_id`s, sorted by purchase date (descending).
3.  **Hyperparameter Tuning**: Use the validation set (the last 7 days of the training data) to select the optimal window size $N$ (weeks of data to use) and the decay constant $\alpha$.

# Evaluation
The inference process for the test set is a fast look-up and fill operation:
1.  Identify the list of `customer_id`s from `sample_submission.csv`.
2.  For each customer:
    *   **Step A (History)**: Retrieve the user's sorted purchase history from the History Index. Deduplicate items while preserving order.
    *   **Step B (Fill)**: Append items from the global `Trend_List` to the user's list.
    *   **Step C (Truncate)**: Keep only the top 12 unique items.
3.  Format the predictions into a space-separated string of article IDs and save to the submission file.
