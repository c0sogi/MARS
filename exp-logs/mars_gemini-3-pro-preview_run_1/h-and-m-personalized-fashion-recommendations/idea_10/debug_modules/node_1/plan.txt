The issue causing the `TypeError` is that the `setup_demo_data` function creates the training dataset by taking the last 50,000 rows (`.tail(50000)`) of the full training file. Since the data is time-sorted, this selects only the most recent transactions. When `DataFactory` subsequently attempts to split this data into a "historical" training set and a "recent" validation set (using a T-7 days cutoff), the training portion becomes empty because the sample lacks any data prior to that cutoff. This empty DataFrame leads to `NaT` values during memory optimization, causing the crash.

To fix this, I will modify the sampling strategy to select a random subset of **customers** and retain their full transaction history, rather than slicing by row index. This ensures the sampled dataset spans the entire timeline, allowing for a valid temporal split between training and validation periods. Cite debug_lesson_3.
