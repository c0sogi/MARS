The implementation strategy involves the following steps:

1.  **Configuration & Setup**: Import the necessary modules and override the `Config` class attributes. We will redirect the `WORKING_DIR` and `SUBMISSION_DIR` to a temporary demo folder to avoid conflicts. Crucially, we will reduce the temporal window sizes (e.g., `WINDOW_STRUCTURE_DAYS`) and `TOP_K_NEIGHBORS` to ensure the heavy matrix computations complete almost instantly for demonstration purposes. We also manually update dependent file paths in `Config` since they are evaluated at import time.
2.  **Data Processing**: Call `data_utils.load_processed_data` to convert the raw CSVs into optimized Parquet files and integer mappings. We will assert the validity of the resulting DataFrames. We will also demonstrate `get_temporal_view` to verify it correctly slices data by date.
3.  **Component Demos**:
    *   **IdMapper**: Instantiate and fit the mapper, then verify that transforming a user ID to an index and back returns the original ID.
    *   **SparseEngine**: Use the engine to build a User-Item interaction matrix from a small slice of data and compute a similarity matrix, asserting the output shapes and sparsity.
4.  **Full Pipeline Execution**: Instantiate `IGDCRecommender`, run `fit()` (which uses the cached data), and `predict()` to generate a submission file.
5.  **Metric Evaluation**: Use `metrics.calculate_map12` to score the generated submission against the validation set, ensuring the evaluation logic functions correctly.
