The error `AssertionError: Mappings should not be empty` arises because the training set becomes empty after the time-based split. This is caused by the naive row slicing (`nrows=50000`) in `setup_demo_environment`, which extracts a dataset spanning only a single day. Since the validation logic reserves the last 7 days, the entire 1-day sample is assigned to validation, leaving zero records for training.

To fix this, I will replace the row slicing with **entity-based sampling** (Cite debug_lesson_3). I will load the full training metadata, randomly select a subset of 2,000 customers, and retain their complete transaction history. This ensures the sampled dataset preserves the full temporal structure (2018–2020), allowing the time-split logic to correctly populate both training and validation sets.
