Based on the comprehensive analysis of the "Lessons Learned" and the evolution of previous ideas, I propose the **Multi-Scale Stratified Graph Cascade (MSG-Cascade)**.

This solution introduces a structural innovation by resolving the fundamental conflict between **Recency** (Lesson 00007) and **Long-Tail Density** (Lesson 00012) through a **Multi-Scale Graph Architecture**. Instead of forcing a single trade-off with one historical window or one decay rate, we construct two distinct Collaborative Filtering graphs—a "Fast" graph to capture high-velocity trends and a "Slow" graph to capture stable style affinities—and integrate them into a strict priority cascade.

# Model
The architecture is a **Four-Stage Stratified Retrieval System** implemented via vectorized sparse linear algebra. It generates a single unified score vector $R_u$ for each user $u$. The innovation lies in the **Multi-Scale Stratification**, which maps signal sources to disjoint numerical ranges to enforce a strict priority hierarchy: **Habit > Fast Trends > Stable Style > Global Fallback**.

1.  **Stratum 1: Habitual Repurchase (The "Priors" Layer)**
    *   **Logic:** Users are overwhelmingly likely to rebuy items they purchased recently. Cite {solution_lesson_node_00002}.
    *   **Mechanism:** Retrieve the user's history vector $U_{hist}$. Apply strict temporal decay ($1 / \text{days\_elapsed}$).
    *   **Stratification:** Scores are shifted to the range $[3000, \infty)$. This ensures explicit history *always* outranks inferred similarity, strictly adhering to the "Cascade > Ensemble" principle. Cite {solution_lesson_node_00016}.

2.  **Stratum 2: Fast-Decay Collaborative Filtering (The "Trend" Layer)**
    *   **Purpose:** Captures immediate, high-velocity market trends and viral combinations (e.g., "What are people buying *this week* with this item?").
    *   **Matrix Construction:** We construct a **Fast Interaction Matrix** $X_{fast}$ using an **Aggressive Decay** function (e.g., half-life of ~1 week) over a medium window (e.g., 8 weeks).
    *   **Normalization:** $X_{fast}$ is Row-Normalized (User) and IDF-Weighted. Cite {solution_lesson_node_00004}, {solution_lesson_node_00011}.
    *   **Inference:** $R_{fast} = U_{fast} \times S_{fast}$, where $S_{fast} = X_{fast}^T X_{fast}$. The query vector $U_{fast}$ uses the same aggressive decay.
    *   **Stratification:** Scores are normalized and scaled to the range $[2000, 3000)$. This ensures that if a strong recent trend signal exists, it outranks older stable correlations.

3.  **Stratum 3: Slow-Decay Collaborative Filtering (The "Style" Layer)**
    *   **Purpose:** Captures latent, long-term style compatibilities (e.g., "This specific belt goes with these jeans") that are stable over time but sparse in any single week. This addresses the "Long Tail" benefit identified in Lesson 00012.
    *   **Matrix Construction:** We construct a **Slow Interaction Matrix** $X_{slow}$ using a **Gentle Decay** function (e.g., half-life of ~8 weeks) over a long window (e.g., 24 weeks).
    *   **Active Inventory Filter:** To prevent the "Concept Drift" issue (recommending obsolete/out-of-stock items) identified in Lesson 00007, we explicitly **mask the columns** of $S_{slow}$. We retain only those items that appeared in the transactions of the most recent training week ("Active Inventory").
    *   **Inference:** $R_{slow} = U_{slow} \times S_{slow}$.
    *   **Stratification:** Scores are normalized and scaled to the range $[1000, 2000)$.

4.  **Stratum 4: Global Trend (The "Fallback" Layer)**
    *   **Logic:** Time-decayed sales velocity for cold-start users.
    *   **Stratification:** Scores are scaled to $[0, 1000)$.

**Final Aggregation:**
$$ R_{total} = R_{rep} + R_{fast} + R_{slow} + R_{trend} $$
Sorting $R_{total}$ is mathematically equivalent to the heuristic cascade: Sort(Repurchase) $\rightarrow$ Sort(Fast CF) $\rightarrow$ Sort(Slow CF) $\rightarrow$ Sort(Trend).

# Data
1.  **Temporal Windowing:**
    *   We utilize a **24-week** historical window for training. This maximizes the density for the "Slow" graph while the "Fast" graph naturally focuses on the recent tail.
2.  **Validation Strategy:**
    *   **Time-Based Split:** Train on Weeks $T-24$ to $T-1$, Validate on Week $T$. This ensures the model has access to the user history required for Strata 1, 2, and 3. Cite {solution_lesson_node_00026}.
3.  **Preprocessing:**
    *   **Decay Pre-computation:** Calculate two separate weight columns for transactions: `weight_fast` ($e^{-\lambda_{fast} t}$) and `weight_slow` ($e^{-\lambda_{slow} t}$).
    *   **Active Item Identification:** Identify the set of unique `article_id`s sold in Week $T-1$ to create the inventory mask.
4.  **Precision:**
    *   Use **float32** for all matrix accumulators. Cite {solution_lesson_node_00010}.

# Training
Since this is a memory-based heuristic model, "training" is the efficient construction of the sparse matrices:
1.  **Fast Graph:** Construct sparse $X_{fast}$ using `weight_fast`. Apply L2 Row Normalization and IDF. Compute $S_{fast} = X_{fast}^T X_{fast}$ (pruned to top-100 neighbors).
2.  **Slow Graph:** Construct sparse $X_{slow}$ using `weight_slow`. Apply L2 Row Normalization and IDF. Compute $S_{slow} = X_{slow}^T X_{slow}$.
3.  **Inventory Masking:** Zero out columns in $S_{slow}$ that do not correspond to "Active Items".

# Evaluation
1.  **Vectorized Inference:**
    *   Generate predictions using **Vectorized Sparse Matrix Multiplication** for both scales ($R_{fast} = U_{fast} \times S_{fast}$ and $R_{slow} = U_{slow} \times S_{slow}$). Cite {solution_lesson_node_00012}.
2.  **Retrieval Strategy:**
    *   Employ the **Mask-and-Partition** technique: Densify the score vector, mask history items (unless Repurchase score overrides), and use `np.argpartition` to select top 12 items in linear time. Cite {solution_lesson_node_00013}.
