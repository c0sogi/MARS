### Implementation Strategy

1.  **Environment Setup**: Import necessary libraries and suppress warnings/logs to keep the output clean. Set a fixed random seed for reproducibility.
2.  **Configuration Override**: Modify the global `Config` class attributes to enable `debug` mode. This ensures the pipeline uses a tiny subset of data (subsampled in `get_dataloaders`), runs for only 1 epoch, and uses a dedicated working directory for this demonstration to avoid overwriting existing work.
3.  **Component Verification (Unit Testing)**:
    *   **Feature Engineering**: Manually instantiate `FeatureEngineer`, process a small dummy DataFrame, and verify the output shape and values (e.g., character differences).
    *   **Data Loading**: Call `get_dataloaders` and fetch a single batch. Verify the presence of all required keys (`input_ids_a`, `scalar_features`, `labels`) and check tensor shapes.
    *   **Model Architecture**: Instantiate the `SiameseDeberta` model. Perform a forward pass with the fetched batch and verify that the output logits have the correct shape `(batch_size, 3)`.
4.  **Pipeline Execution (Integration Testing)**:
    *   **Training**: Execute `run_training()`. This will run the training loop on the debug subset. Verify that the model checkpoint (`best_model.pth`) is created.
    *   **Inference**: Execute `generate_predictions()`. Verify that the submission file is generated and adheres to the required format (columns and row count).
5.  **Final Validation**: Load the generated submission file and assert its structure matches the requirements.
