To establish a robust and efficient baseline, I propose a **Keypoint-based Object Detection** approach (conceptually similar to CenterNet). This method treats objects not as boxes to be matched to anchors (like YOLO or R-CNN), but as single points (center points) on a heatmap. This eliminates the need for complex anchor box hyperparameter tuning and non-maximum suppression (NMS) during post-processing, prioritizing simplicity and speed.

### Model
The architecture is designed as a fully convolutional network that predicts object centers and their properties directly from a high-resolution feature map.

*   **Backbone:** Use a lightweight, pre-trained **ResNet-18** as the feature extractor. This provides a good balance between inference speed and feature representation capability without the computational heaviness of larger backbones.
*   **Neck (Upsampling):** Unlike multi-scale architectures (FPN/PANet used in Model 1 and 2), this baseline will use a simple series of **Transposed Convolution (Deconvolution)** layers to upsample the low-resolution features from the backbone. The goal is to produce a single high-resolution feature map (e.g., stride 4 relative to the input image).
*   **Heads:** Three parallel convolutional branches emerge from the high-resolution map:
    1.  **Heatmap Head:** A standard convolution layer outputting $C$ channels (where $C=14$, corresponding to the disease classes). Each pixel represents the probability of that pixel being the center of an object.
    2.  **Size Head:** Outputs 2 channels representing the width and height of the bounding box at the center location.
    3.  **Offset Head:** Outputs 2 channels to predict the local discretization error (offsets) caused by the downsampling stride, ensuring precise box localization.

### Data
Preprocessing will focus on converting medical formats to standard tensor inputs and generating heatmap targets.

*   **DICOM Preprocessing:** 
    *   Read DICOM files and apply **Percentile Normalization** (e.g., clipping pixel intensities to the 1st and 99th percentiles) to handle the high dynamic range and varying intensity scales of X-rays.
    *   Normalize values to the 0-1 range and resize images to a fixed square resolution (e.g., 512x512) to ensure consistent batch processing.
*   **Target Generation:**
    *   For each ground truth bounding box, calculate the center point $(cx, cy)$.
    *   Splat a 2D **Gaussian kernel** onto the ground truth heatmap at the calculated center. The radius of the Gaussian should be adaptive based on the size of the object (larger objects get larger blobs).
    *   The Size and Offset targets are simply the raw width/height and sub-pixel offsets at the center coordinates.
*   **Augmentation:** Apply only minimal augmentations such as horizontal flipping to maintain training speed and stability.

### Training
The training process treats the task as a combination of pixel-wise classification and regression.

*   **Loss Functions:**
    *   **Heatmap:** Use a **Pixel-wise Focal Loss**. This effectively handles the extreme class imbalance (most pixels are background) by down-weighting easy negatives (background) and focusing on the sparse positive peaks (disease centers).
    *   **Size and Offset:** Use **L1 Loss** or Smooth L1 Loss, applied only at the ground truth center locations.
*   **Optimization:** Use the **Adam** optimizer, which converges faster than SGD for this type of heatmap regression task.
*   **Strategy:** Train for a moderate number of epochs (e.g., 15-20) with a standard learning rate schedule (warmup followed by cosine decay or step decay).

### Evaluation
Inference is straightforward and deterministic, avoiding complex box matching or suppression algorithms.

1.  **Heatmap Prediction:** Pass the test image through the network to generate the 14-channel heatmap, size map, and offset map.
2.  **Peak Extraction:** Instead of NMS, perform a simple **3x3 Max Pooling** operation on the heatmap. Pixels that remain unchanged after pooling are local maxima (peaks).
3.  **Thresholding:** Select peaks with a confidence score above a set threshold (e.g., 0.2).
4.  **Box Reconstruction:** For each selected peak:
    *   Retrieve the class ID from the channel index.
    *   Retrieve width and height from the Size map at that coordinate.
    *   Adjust the center coordinates using the Offset map.
    *   Calculate `xmin, ymin, xmax, ymax` from the center and size.
5.  **"No Finding" Logic:**
    *   Collect all predicted boxes for the image.
    *   If the list of predictions is empty (no peaks above threshold), generate the required "No finding" string: `14 1.0 0 0 1 1`.
    *   Otherwise, format the detected objects into the submission string.
