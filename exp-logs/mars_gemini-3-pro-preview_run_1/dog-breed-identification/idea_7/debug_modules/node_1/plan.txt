The `IndexError` during validation is caused by a synchronization issue in the `load_data` function within `library/dataset.py`. Specifically, the code appends the processed image to the `images` list *before* attempting to resolve and append the corresponding label. When the validation subset contains breeds not present in the training subset (a scenario typical of small debug datasets, as noted in **Cite debug_lesson_1**), the label lookup raises a `KeyError`. This error is caught by the `except` block, preventing the label from being appended, but the image remains in the list. This leaves the `images` list longer than the `labels` list, causing the `IndexError` when the `DataLoader` attempts to access a label index that doesn't exist.

The fix involves making the list updates transactional: for the training and validation sets, we must successfully retrieve the label *before* appending either the image or the label to their respective lists. This ensures that the dataset remains consistent even if some samples fail processing or lookup.
