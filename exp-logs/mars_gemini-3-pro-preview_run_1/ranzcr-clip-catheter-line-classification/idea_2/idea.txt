# Solution: High-Fidelity EfficientNet-B4 with GeM Pooling

### Model
We will upgrade the architecture to **EfficientNet-B4**, a significantly deeper and wider network than the previously used B0 variant. This decision aligns with the finding that server-side hardware (A100) allows for prioritizing accuracy-optimized architectures over latency-constrained ones **Cite solution_lesson_node_00002**.
- **Dynamic Instantiation:** To prevent configuration errors where the model architecture does not match the intended experiment, the model will be instantiated dynamically using a factory pattern (e.g., `getattr(models, config.model_name)`) rather than hardcoding the class **Cite solution_lesson_node_00003**.
- **Pooling Layer:** Instead of standard Global Average Pooling, we will implement **Generalized Mean (GeM) Pooling**. GeM pooling is a learnable pooling operation that can focus on salient features (like thin catheter lines) more effectively than simple averaging, which tends to wash out small details in the large background of a chest x-ray.
- **Head:** The output of the GeM layer will be fed into a linear classification layer with 11 outputs.

### Data
To address the challenge of detecting thin tubes and lines, we will fundamentally alter the preprocessing pipeline to support **High-Resolution Input**.
- **Resolution:** Input images will be resized to **768x768** pixels (up from 512x512). This 2.25x increase in pixel count is crucial for resolving fine-grained features like catheter tips which may be blurred at lower resolutions.
- **Channels:** Single-channel X-rays will be converted to 3-channel RGB to utilize pre-trained ImageNet weights.
- **Augmentation:** We will introduce **CoarseDropout** (randomly masking out rectangular regions) to the augmentation pipeline. This encourages the larger model to learn distributed feature representations and prevents reliance on any single visual cue, acting as a regularization technique for the increased model capacity.

### Training
The training strategy focuses on stability and handling class imbalance without unnecessary complexity.
- **Loss Function:** We will continue to use **BCEWithLogitsLoss** with the `pos_weight` argument set to the inverse class frequency (`negative_count / positive_count`). This ensures that the model receives sufficient signal from rare classes like "ETT - Abnormal" **Cite solution_lesson_node_00001**.
- **Optimizer:** We will use the **AdamW** optimizer to decouple weight decay from gradient updates, providing better regularization for the larger B4 backbone.
- **Learning Rate Strategy:** We will employ a **Constant Learning Rate** (e.g., 1e-4) for the duration of the training (approx. 10-12 epochs). We will explicitly avoid aggressive decay schedules like Cosine Annealing in this short-epoch regime to ensure the optimizer maintains sufficient step sizes to converge to a robust minimum **Cite solution_lesson_node_00006**.

### Evaluation
- **Inference:** Test images will be resized to the same **768x768** resolution as the training set.
- **TTA:** We will perform inference on the original image and a horizontally flipped version (Test Time Augmentation), averaging the probabilities to further boost stability and performance.
