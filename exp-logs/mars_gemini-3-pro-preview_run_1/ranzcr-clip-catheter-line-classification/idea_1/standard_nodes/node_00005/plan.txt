The issue arises because the `CatheterModel` class assumes the backbone's classifier has the structure of an EfficientNet (where `classifier[1]` is the `Linear` layer), but the configuration is set to `mobilenet_v3_large`. In `mobilenet_v3_large`, the `classifier` is a `Sequential` block where the layer at index 1 is a `Hardswish` activation, which does not have an `in_features` attribute. The `Linear` layer containing the input feature size for the classifier block in MobileNetV3 is located at index 0.

To fix this, I will modify `library/model.py` to check if the first layer of the classifier (`classifier[0]`) is an instance of `nn.Linear`. If it is (as in MobileNetV3), we extract `in_features` from there; otherwise, we fall back to index 1 (as in EfficientNet). This ensures the code works for the configured model while maintaining compatibility with the architecture described in the comments.
