The issue is that the `swa_model` (an instance of `torch.optim.swa_utils.AveragedModel`) wraps the underlying model in a `.module` attribute. When `swa_model.state_dict()` is called, all keys are prefixed with `module.` (e.g., `module.backbone.conv1.weight`). The `runfile.py` script attempts to load this checkpoint into a standard `IcebergResNet18GeM` instance, which expects keys without the prefix (e.g., `backbone.conv1.weight`), causing a `RuntimeError` due to missing/unexpected keys.

To fix this, I will modify `library/training.py` to save the state dictionary of the underlying model (`swa_model.module.state_dict()`) instead of the wrapper. This ensures the checkpoint keys match the original model architecture. This applies `debug_lesson_8`.
