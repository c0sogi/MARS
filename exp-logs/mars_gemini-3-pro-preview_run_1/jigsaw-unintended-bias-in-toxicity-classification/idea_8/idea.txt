# Proposed Solution: DeBERTa-v3-Large with Adversarial Robustness and Hybrid Ranking

### Model
**Architecture:**
We upgrade the backbone from the base model to **DeBERTa-v3-Large**. The empirical success of the DeBERTa architecture in disentangling content from context (Lesson 00007) suggests that scaling to the "Large" variant (approx. 300M parameters) will provide the necessary capacity to resolve the finer semantic distinctions between neutral identity mentions and toxicity.

**Structural Innovation (Triangulated Multi-Task Heads):**
We retain the Multi-Task Learning (MTL) framework to prevent the model from learning identity as a proxy for toxicity. The encoder feeds into three distinct classification heads:
1.  **Primary Toxicity Head:** A linear layer predicting the main `target`.
2.  **Auxiliary Identity Head:** A multi-label head predicting the presence of identity attributes. **Cite solution_lesson_node_00004**.
3.  **Auxiliary Identity Attack Head:** A head predicting the `identity_attack` subtype. This creates a "semantic triangulation" signal, forcing the model to differentiate between a mere identity mention (Aux Head 1 active) and an actual attack (Aux Head 2 active).

### Data
**Preprocessing:**
The text is tokenized using the DeBERTa-v3-Large tokenizer with dynamic padding to maximize throughput.

**Stratified Weighted Sampling:**
We utilize a **Weighted Random Sampler** for batch construction. This sampler is configured to significantly oversample the "Bias Trap" subgroups (Non-Toxic + Identity Mention, Toxic + Identity Mention). This ensures that every mini-batch contains a dense mixture of these difficult examples, which is a strict prerequisite for the pairwise ranking loss to function effectively. **Cite solution_lesson_node_00007**.

**Bias-Centric Sample Weights:**
We generate a sample weight vector where examples belonging to the "Bias Trap" subgroups are assigned a significantly higher weight (e.g., 5.0) compared to standard examples (1.0). This weight vector is passed to the pointwise loss function. **Cite solution_lesson_node_00002**.

### Training
**Loss Function:**
We employ a composite loss function: $L_{total} = L_{BCE} + \lambda_{rank} L_{Rank} + \lambda_{aux} L_{Aux}$.
1.  **Weighted Pointwise Loss ($L_{BCE}$):** We apply Binary Cross-Entropy on the soft toxicity targets, multiplied by the **Bias-Centric Sample Weights**. This forces the model to prioritize minimizing absolute error on the specific subgroups that historically degrade the metric. **Cite solution_lesson_node_00002**.
2.  **Pairwise Margin Ranking Loss ($L_{Rank}$):** We mine hard pairs $(x_{pos}, x_{neg})$ within each batch (where $x_{pos}$ is Toxic/No-Identity and $x_{neg}$ is Non-Toxic/Identity) and penalize the model if it ranks the non-toxic identity example higher than the toxic background example. This directly optimizes the rank-based nature of the competition metric. **Cite solution_lesson_node_00007**.
3.  **Auxiliary Loss ($L_{Aux}$):** Standard BCE on the auxiliary heads to enforce semantic disentanglement. **Cite solution_lesson_node_00004**.

**Structural Innovation: Adversarial Weight Perturbation (AWP):**
To address the "unintended bias" that arises from overfitting to specific identity tokens, we introduce **AWP** into the training loop.
*   **Mechanism:** After the standard forward and backward pass, AWP calculates an adversarial perturbation $\delta$ that maximizes the loss (ascending the loss surface) and adds it to the model weights. A second forward/backward pass is then performed to minimize the loss at this perturbed state.
*   **Benefit:** This forces the model to find a "flat minimum" in the loss landscape. A flat minimum implies that small perturbations (like the presence of a specific identity word in a different context) do not drastically change the output, thereby improving the model's robustness and generalization on the bias metrics.

### Evaluation
**Inference:**
The test data is processed through the fine-tuned DeBERTa-v3-Large backbone. We extract predictions **only from the Primary Toxicity Head** for the final submission. The auxiliary heads and ranking logic are training-time constraints used solely to shape the encoder's representation.
