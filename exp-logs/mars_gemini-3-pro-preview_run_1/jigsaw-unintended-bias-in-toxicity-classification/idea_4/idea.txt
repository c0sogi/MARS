# Proposed Solution: Multi-Task Transformer with Auxiliary Identity Prediction

This strategy introduces a structural evolution by adopting a **Multi-Task Learning (MTL)** framework. While the previous Transformer idea (Idea 3) introduced semantic understanding, this approach explicitly forces the model to disentangle "identity concepts" from "toxicity concepts" by training it to recognize both simultaneously. This directly addresses the root cause of bias (conflating identity with toxicity) while retaining the proven weighting strategy.

### Model
**Architecture:**
The backbone is a pre-trained Transformer encoder (e.g., RoBERTa or DeBERTa) which provides deep contextual embeddings, addressing the limitation of linear models in distinguishing between slur usage and neutral identity mentions.
**Structural Innovation (Multi-Task Heads):**
Instead of a single output layer, the model features two distinct classification heads sharing the same encoder:
1.  **Primary Toxicity Head:** A linear layer predicting the main `target` (toxicity).
2.  **Auxiliary Identity Head:** A separate linear layer (or set of layers) predicting the presence of the specific identity attributes (e.g., `male`, `female`, `muslim`, `black`).
By sharing the encoder, the model is forced to learn a representation that encodes identity information (to satisfy the auxiliary head) separate from toxicity information (to satisfy the main head), reducing the likelihood of the model using identity merely as a proxy for toxicity.

### Data
**Preprocessing:**
1.  **Tokenization:** Process `comment_text` using the backbone's specific tokenizer (e.g., BPE), truncating to a fixed length (e.g., 256 tokens).
2.  **Target Generation:** Prepare two sets of targets for each sample: the scalar `target` for toxicity and a vector of identity attributes for the auxiliary head.
3.  **Bias-Centric Weight Generation:** We explicitly preserve the successful weighting strategy from the linear baseline. We calculate a sample weight vector where examples belonging to the "bias trap" subgroups—specifically **Non-Toxic examples mentioning an identity** and **Toxic examples mentioning an identity**—are assigned significantly higher weights (e.g., 5.0) compared to standard examples. Cite solution_lesson_node_00002.

### Training
**Procedure:**
1.  **Objective Function:** The loss is a weighted sum of two components: $L_{total} = L_{toxicity} + \lambda L_{identity}$.
    *   **Toxicity Loss ($L_{toxicity}$):** We use **Weighted Binary Cross-Entropy** on the soft toxicity targets. Crucially, this loss component is multiplied by the pre-calculated bias-centric sample weights. This ensures the primary optimization task remains focused on the difficult subgroups identified in the evaluation metric. Cite solution_lesson_node_00002.
    *   **Identity Loss ($L_{identity}$):** We use standard Binary Cross-Entropy for the auxiliary identity targets to supervise the learning of identity features.
2.  **Optimization:** Use the AdamW optimizer. The auxiliary loss is typically weighted lower ($\lambda \approx 0.1 - 0.5$) to ensure the model prioritizes the main competition metric while still benefiting from the representation learning.

### Evaluation
**Inference:**
For the final submission, we perform inference using only the **Primary Toxicity Head**. The auxiliary head is discarded after training, as its purpose was solely to regularize the encoder and improve the quality of the embeddings during the learning process. The output probabilities are saved directly to the submission file.
