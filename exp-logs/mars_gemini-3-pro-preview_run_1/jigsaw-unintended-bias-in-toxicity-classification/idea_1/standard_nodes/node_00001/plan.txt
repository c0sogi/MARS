The implementation strategy follows the provided library structure to create a robust baseline for toxicity classification with bias mitigation.

1.  **Setup & Data Loading**: We initialize the environment with a fixed seed for reproducibility. We use the `data_loader` module to load the training, validation, and test sets. This module automatically handles the "Bias-Corrective Resampling" (duplicating rows with identity mentions) to ensure the model focuses on difficult subgroups.
2.  **Feature Extraction**: We use the `FeatureExtractor` to transform the raw text into a high-dimensional sparse matrix using TF-IDF. This combines word n-grams (semantic meaning) and character n-grams (morphological patterns), which is crucial for handling obfuscated toxic terms.
3.  **Model Training**: We instantiate the `RidgeRegressor` (Linear Regression with L2 regularization). We train it on the resampled training data. Ridge regression is chosen for its speed and ability to handle sparse data effectively while optimizing for the continuous toxicity score.
4.  **Validation & Metrics**: We evaluate the model on the hold-out validation set. We compute the specific competition metric (Weighted ROC-AUC) which combines overall performance with bias-specific metrics (Subgroup AUC, BPSN, BNSP). We print the "Final Validation Metric" as required.
5.  **Failure Analysis**: We perform a post-hoc analysis on the validation predictions. We calculate the absolute error for each example and correlate this error with metadata features (identity mentions and text length) to identify which subgroups or text types are causing the most confusion for the model.
6.  **Submission**: Finally, we generate predictions for the test set and save the submission file in the specified format.
