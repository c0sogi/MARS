### Implementation Strategy

1.  **Configuration Override**: To ensure the demonstration runs quickly (under 1 hour) and fits within memory constraints while debugging, we will override the default `Config` parameters. We will switch the model to `prajjwal1/bert-tiny` (a very small, fast Transformer), reduce batch sizes, set `DEBUG=True` to use a tiny subset of data, and enable AWP from epoch 0.
2.  **Data Pipeline Verification**: We will initialize the data loaders using `library.data.get_dataloaders` and verify that the returned batches contain the expected keys (`ids`, `mask`, `target`, `aux_targets`, `weight`) and correct tensor shapes.
3.  **Model Initialization**: We will instantiate the `DebertaV3MultiTask` model (using the tiny backbone) and verify it can perform a forward pass on a batch of data, producing logits for toxicity, identities, and attack types.
4.  **Loss Function Check**: We will instantiate `HybridLoss` and calculate the loss on the model outputs to ensure the composite loss (BCE + Ranking + Aux) is computed correctly and allows backpropagation.
5.  **Training Loop Execution**: We will run `train_one_epoch` from `library.engine` to demonstrate the full training cycle, including gradient scaling and AWP integration.
6.  **Validation and Metrics**: We will run the `validate` function to generate predictions on the validation set and compute the competition metric. We will also perform a manual sanity check on the `calculate_final_score` function using synthetic data to ensure it handles edge cases correctly.
7.  **Inference**: We will execute the `inference` function to generate a submission file and verify the output format matches the requirements.
