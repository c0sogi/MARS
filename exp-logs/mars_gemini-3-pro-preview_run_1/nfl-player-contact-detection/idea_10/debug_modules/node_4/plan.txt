The `pyarrow.lib.ArrowTypeError` is caused by the inclusion of non-numeric columns (specifically `datetime_p2`, which contains mixed string and integer values) in the feature matrix `X`. This occurs because the feature selection logic inadvertently includes timestamp and categorical columns (like `datetime_p1`, `datetime_p2`, `team_p1`) based on suffix matching, and the subsequent `X.fillna(0)` operation fills missing values in these object-type columns with the integer `0`. This creates a mixed-type column that Parquet cannot serialize.

The fix involves two steps in `library/feature_engineering.py`:
1.  Activate the previously unused `exclude` list to filter the `feature_cols`.
2.  Explicitly restrict the feature matrix `X` to numeric columns only using `.select_dtypes(include=[np.number])` before applying imputation. This prevents object columns from being included and corrupted with integer fill values (Cite debug_lesson_11).
