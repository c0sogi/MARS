The implementation strategy follows the "Ego-Centric Spatial Grid Mining Ensemble" (ECS-ME) architecture while adhering to the constraints of a fast baseline execution.

1.  **Configuration & Setup**: I will import the provided library modules and override the default `Config` parameters. Specifically, I will reduce the number of estimators (trees) for both LightGBM and XGBoost to 100 and limit tree depth/leaves. This ensures the training completes quickly (well within the 2-hour limit) while still validating the pipeline's logic. I will also disable verbose logging to keep the output clean.
2.  **Pipeline Orchestration**: I will instantiate the `Pipeline` class and execute the three training phases manually (`run_scout_phase`, `run_mining_phase`, `run_expert_phase`). This manual control allows me to pass `load_cached_data=True` explicitly and manage the flow for the subsequent analysis steps.
3.  **Validation & Metric Reporting**: After training, I will retrieve the validation dataset and use the ensemble to find the optimal decision threshold. I will explicitly calculate and print the `Final Validation Metric` (MCC) to satisfy the strict output requirement.
4.  **Failure Analysis**: I will compute the absolute error of the model's predictions on the validation set and calculate the Pearson correlation between these errors and the input features. The top correlated features will be printed to identify sources of systematic error.
5.  **Conditional Submission**: Finally, I will check if the validation MCC exceeds the threshold of 0.6782. If satisfied, I will trigger the inference pipeline to generate and save `submission.csv`; otherwise, I will skip this step to save resources.
