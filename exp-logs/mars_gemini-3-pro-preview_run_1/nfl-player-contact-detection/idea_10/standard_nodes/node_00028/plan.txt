The issue is that the validation dataset is being filtered ("gated") to remove player pairs separated by more than 3.0 yards, similar to the training set. While this is a valid optimization for training (to focus on hard examples), it invalidates the validation metric because the validation set must represent the full data distribution (including "easy negatives") to be comparable to the test set and the final evaluation metric.

To fix this, I will:
1.  Modify `library/feature_engineering.py` to restrict the geometric gating logic solely to the training mode (`mode == "train"`), ensuring the validation set retains all pairs.
2.  Modify `library/data_manager.py` to rename the validation cache file from `val_features_gated.parquet` to `val_features_full.parquet`. This ensures that the pipeline does not load the previously cached (incomplete) validation data and correctly identifies the new dataset as the full, ungated version.
