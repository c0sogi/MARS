# Strategy: Ego-Centric Spatial Grid Mining Ensemble (ECS-ME)

Building on the success of the **Geometrically-Gated Full-Context Mining Ensemble** (Idea 9), I propose a structural evolution in the **Feature Engineering Paradigm**.

While previous solutions correctly identified the importance of **Spatial Context** (Cite solution_lesson_node_00023), they relied on scalar summaries (e.g., `neighbor_count`, `cluster_speed`) which discard critical directional information. A player being tackled from behind (blind spot) is physically distinct from a frontal collision, yet scalar density treats these identical.

This solution introduces **Ego-Centric Spatial Grids**: a vectorized representation of the local environment aligned to the player's orientation. By combining this high-fidelity context with **Geometric Gating** (Cite solution_lesson_node_00026) and **Hard-Negative Mining** (Cite solution_lesson_node_00021), we maximize information density without exceeding the computational budget.

### 1. Model
The architecture remains a **Unified Heterogeneous Ensemble** designed for maximum capacity and stability.

*   **Unified Backbone:** A single modeling framework predicts both Player-Player and Player-Ground contacts using an `is_ground` categorical indicator. This prevents the fragmentation of the dataset and leverages the shared non-contact majority class to stabilize the decision boundary (Cite solution_lesson_node_00007).
*   **Heterogeneous Components:** The ensemble consists of **LightGBM** (Leaf-wise) and **XGBoost** (Level-wise) models.
*   **High-Capacity Configuration:** Both models are configured with deep trees (e.g., `num_leaves=256`, `max_depth=10`) to exploit the rich feature space of the new spatial grids (Cite solution_lesson_node_00003).

### 2. Data
The pipeline employs **Geometric Gating** to enable the computation of computationally expensive **Ego-Centric Grids** for the entire candidate pool.

*   **Stage 0: Geometric Gating (The Sieve)**
    *   **Filter:** For the full training set (~3.4M rows), calculate instantaneous Euclidean distance.
    *   **Logic:** Discard Player-Player pairs with `Distance > 3.0` yards. Keep **ALL** Player-Ground pairs.
    *   *Rationale:* This eliminates trivial non-contacts (Cite solution_lesson_node_00026), reducing the dataset to ~600k rows and freeing up the computational budget for complex feature engineering.

*   **Stage 1: Ego-Centric Grid Feature Engineering**
    *   **Innovation:** For every survivor row, construct a **3x3 Spatial Grid** (e.g., 1-yard bins) centered on Player 1 and aligned to their **Orientation**.
    *   **Binning:** Map neighboring players into these bins based on their relative position.
    *   **Features:** Flatten the grid into a feature vector (e.g., `grid_front_center_count`, `grid_back_left_speed`).
    *   *Benefit:* This captures **Directional Density** (e.g., "Is the pile-up in front or behind?"), strictly preserving **Translation Invariance** (Cite solution_lesson_node_00024) while providing far richer context than simple counts (Cite solution_lesson_node_00023).

*   **Stage 2: Kinematic & Physics Features**
    *   **Temporal Flattening:** Generate +/- 10 step (1.0s) flattened windows for relative kinematics (Cite solution_lesson_node_00001).
    *   **Physics Derivatives:** Compute **Jerk** and **Angular Jerk** to explicitly detect impact impulses, critical for Ground contact detection (Cite solution_lesson_node_00012).

*   **Caching:** Enforce **parameter-aware caching** to prevent implicit hazards (Cite solution_lesson_node_00002).

### 3. Training
The training process executes a **High-Fidelity Mining Curriculum** to ensure the model learns from the hardest examples.

*   **Phase 1: Scout Training**
    *   Construct a balanced dataset from the **Gated Survivors** (All Positives + Equal Random Negatives).
    *   Train a **Scout LightGBM** using the **Full Feature Set** (Grids + Windows).
    *   *Crucial Correction:* Unlike previous tiered attempts, the Scout sees the *exact same* high-fidelity features as the Expert, preventing the "Semantic Gap" failure (Cite solution_lesson_node_00022).

*   **Phase 2: Full-Context Mining**
    *   Run Scout inference on the **Entire Gated Survivor Pool** (~600k rows).
    *   Select **Hard Negatives**: Instances where $P(Contact) > 0.05$ but Ground Truth is 0.
    *   *Rationale:* This leverages the scale-dependent efficacy of mining (Cite solution_lesson_node_00021) to find the most confusing "near-misses" and "dense cluster" non-contacts.

*   **Phase 3: Expert Training**
    *   Construct the **Expert Dataset**: All Positives + All Mined Hard Negatives + Small Buffer of Random Gated Negatives.
    *   Train the **Expert Ensemble** (LGBM + XGB) on this high-information-density dataset.
    *   **Imbalance Handling:** Use `is_unbalance=True` (LGBM) and `scale_pos_weight` (XGB) to manage the remaining difficulty-based imbalance (Cite solution_lesson_node_00011).

### 4. Evaluation
1.  **Preprocessing:** Generate the **Full Feature Set** (Ego-Centric Grids + Windows) for the **Entire Test Set**. (The test set is small enough that Geometric Gating is unnecessary for inference speed).
2.  **Inference:** Run the **Expert Ensemble** on the test features.
3.  **Ensembling:** Compute the unweighted average of the probability outputs.
4.  **Thresholding:** Apply the decision threshold optimized on the validation set (maximizing MCC) to generate the final submission.
