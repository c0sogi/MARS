The issue is that the validation set was being subjected to the "Relaxed Quadratic Gating" filter, which removes "easy negative" examples (players > 3 yards apart). While this is a valid optimization for training data to improve balance and speed, applying it to the validation set distorts the data distribution, removing a large number of True Negatives. This results in an invalid Matthews Correlation Coefficient (MCC) because the metric is calculated on a subset of the data rather than the full hold-out set (Cite debug_lesson_3).

To fix this, I will modify `library/feature_engineering.py` to restrict the gating logic strictly to the `train` split. I will also update the cache filename generation logic to distinguish between "gated" (train) and "full" (val/test) datasets. This change in filename serves a dual purpose: it correctly reflects the content and ensures that the pipeline does not load the previously cached, corrupted (gated) validation data, forcing a regeneration of the full validation set (Cite debug_lesson_5).
