# Strategy: Topologically-Enriched Unified Ensemble

This strategy synthesizes the efficiency of windowed kinematics with a structural evolution in feature engineering—moving from local "density" counts to global **Topological Context** via Graph Theory—while enforcing strict data discipline to maximize information density.

### 1. Model
The core architecture is a **Unified Heterogeneous Ensemble** comprising two high-capacity Gradient Boosting models (**LightGBM** and **XGBoost**).

*   **Unified Architecture:** Both models will be trained to predict all contact types (Player-Player and Player-Ground) within a single framework. We explicitly reject the "Split-Stream" approach (Cite solution_lesson_node_00007), as fragmenting the dataset destroys the model's ability to learn from the shared non-contact majority class. Instead, we rely on the `is_ground` categorical feature to allow the trees to learn type-specific decision paths.
*   **High-Capacity Configuration:** To prevent "Early Convergence" (Cite solution_lesson_node_00003), both models will be configured with deep trees (e.g., `num_leaves=256` for LightGBM, `max_depth=10` for XGBoost). This ensures the ensemble has sufficient complexity to model the subtle boundaries of "near-miss" events without underfitting.

### 2. Data
The data pipeline introduces a **Topological Feature Paradigm** while strictly adhering to caching and volume best practices.

*   **Parameter-Aware Caching:** To prevent "Implicit Caching Hazards" (Cite solution_lesson_node_00002), the feature generation routine will generate cache filenames that include a hash of the feature configuration (e.g., `train_feats_topo_v1_{hash}.parquet`). This guarantees that the new topological features are computed and not silently skipped.
*   **Feature Engineering:**
    *   **Temporal Flattening (Retention):** We retain the **Flattened Window** (+/- 10 steps) as the primary representation (Cite solution_lesson_node_00001), as it is the most efficient way to expose temporal trends to GBDTs.
    *   **Physics Derivatives (Retention):** We retain **Jerk** (derivative of acceleration) and **Angular Jerk** (Cite solution_lesson_node_00012) to explicitly model the "impact impulses" characteristic of Ground contacts, compensating for the lack of Z-coordinate data.
    *   **Topological Context (Innovation):** We replace simple "Spatial Density" counts with **Graph-Theoretic Metrics**. For each timestep, we construct a spatial graph where nodes are players and edges exist between neighbors (< 2 yards). We then compute:
        *   **Eigenvector Centrality:** Identifies if a player is in the "center of action" (connected to other highly connected players), distinguishing a pile-up from a simple line.
        *   **Local Clustering Coefficient:** Measures how connected a player's neighbors are to each other, a strong proxy for "being inside a pile."
        *   **Edge Betweenness:** For the target pair, measures if they act as a "bridge" between clusters.
*   **Dataset Volume:** We will use the **Full Training Dataset** (~3.4 million rows). We explicitly reject downsampling (Cite solution_lesson_node_00011), as the full distribution of "hard negatives" (near misses) is critical for precision. The computational cost of the new topological features is offset by the efficiency of the GBDT training.

### 3. Training
*   **Objective:** Binary Log-Loss.
*   **Imbalance Handling:** We will use internal rebalancing parameters (`is_unbalance=True` for LightGBM, `scale_pos_weight` for XGBoost). This allows the models to train on the full, imbalanced distribution (Cite solution_lesson_node_00011) while penalizing false negatives, avoiding the information loss associated with undersampling.
*   **Validation:** We maintain the `game_play` based split to ensure zero leakage.

### 4. Evaluation
1.  **Inference:** Generate predictions using both the LightGBM and XGBoost models on the test set, utilizing the cached topological feature pipeline.
2.  **Ensembling:** Compute the unweighted average of the probability outputs. This leverages the diversity of the two boosting implementations (leaf-wise vs. level-wise growth) to improve generalization.
3.  **Thresholding:** Apply a threshold optimized on the validation set (maximizing MCC) to the averaged probabilities to generate the final binary submission.
