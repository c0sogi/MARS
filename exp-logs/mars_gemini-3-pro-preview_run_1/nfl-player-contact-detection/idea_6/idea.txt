Based on the comprehensive analysis of the previous experiments and lessons learned, I propose the **Iterative Hard-Negative Mining Ensemble (IHNME)**. This strategy introduces a structural evolution in the training pipeline to resolve the conflict between "Data Volume" (Lesson 00018) and "Information Density" (Lesson 00011), while retaining the highly effective feature engineering discovered in Lesson 00012.

### 1. Model
The core architecture will be a **Unified Heterogeneous Ensemble** consisting of **LightGBM** and **XGBoost** models.

*   **Unified Architecture:** We will train a single model for all contact types, using the `is_ground` categorical feature to distinguish between Player-Player and Player-Ground interactions. This retains the stability benefits of the shared non-contact majority class (Cite solution_lesson_node_00007).
*   **High-Capacity Configuration:** Both models will use deep trees (e.g., `num_leaves=256`, `max_depth=10`) to prevent early convergence and maximize the capture of complex interaction boundaries (Cite solution_lesson_node_00003).
*   **Structural Innovation (The Cascade):** Unlike previous iterations that used a single training stage, this solution employs a **Two-Stage Cascade**. A lightweight "Scout" model is used to filter the massive dataset, and the heavy "Expert" Ensemble is trained on a curated curriculum.

### 2. Data
The feature engineering pipeline preserves the successful kinematic features while introducing a dynamic data selection process.

*   **Feature Engineering:**
    *   **Flattened Temporal Window:** We retain the +/- 10 step (1.0s) flattened window as the primary representation, as it is computationally efficient and effective (Cite solution_lesson_node_00001).
    *   **Physics Derivatives:** We retain **Jerk** (derivative of acceleration) and **Angular Jerk** to explicitly model the "impact impulses" of ground contacts (Cite solution_lesson_node_00012).
    *   **Contextual Density:** We retain **Spatial Density** (neighbor counts) (Cite solution_lesson_node_00012) but reject topological graph features (Cite solution_lesson_node_00015).
    *   **New: Cluster Kinematics:** We extend the density feature by calculating the *average velocity and acceleration* of the local neighbor cluster. This allows the model to distinguish between a "static pileup" (high density, low cluster speed) and "running in a pack" (high density, high cluster speed).
*   **Caching:** We enforce **parameter-aware caching** (hashing feature configs into filenames) to prevent implicit caching hazards (Cite solution_lesson_node_00002).
*   **Dynamic Dataset Construction:**
    *   **Scout Dataset:** All Positives + 5x Random Negatives.
    *   **Expert Dataset:** All Positives + **All Hard Negatives** (mined from Stage 1) + 1x Random Negatives.
    *   *Rationale:* This explicitly addresses the conflict between Lesson 00011 (need hard negatives for precision) and Lesson 00018 (blind scaling causes collapse). We discard the "easy" negatives that drown the loss function, keeping only the informative examples.

### 3. Training
The training procedure implements the **Iterative Hard-Negative Mining** strategy:

1.  **Phase 1 (Scout Training):** Train a single, lightweight LightGBM model on the **Scout Dataset**. This model is optimized for speed and recall.
2.  **Phase 2 (Mining):** Use the Scout model to run inference on the **Full Training Dataset** (~3.4M rows). Identify **Hard Negatives**: samples where the ground truth is `0` but the Scout predicted a probability $> 0.05$ (or a similar low threshold). These are the "near misses" and "confusing" non-contacts.
3.  **Phase 3 (Expert Training):** Construct the **Expert Dataset** by combining all positive samples with the mined Hard Negatives and a small buffer of random negatives. Train the full **Heterogeneous Ensemble (LGBM + XGB)** on this high-information-density dataset.
    *   **Objective:** Binary Log-Loss.
    *   **Imbalance Handling:** Use `is_unbalance=True` (LGBM) and `scale_pos_weight` (XGB) to handle the remaining imbalance (Cite solution_lesson_node_00011).

### 4. Evaluation
1.  **Inference:** Generate features for the test set using the cached pipeline.
2.  **Ensemble Prediction:** Run inference using the **Expert Ensemble** (Phase 3 models). Compute the unweighted average of the probability outputs.
3.  **Thresholding:** Optimize the decision threshold on the validation set (maximizing MCC) and apply it to the test predictions. By training on hard negatives, the Expert model is expected to have a much sharper decision boundary, allowing for higher precision at the optimal threshold.
