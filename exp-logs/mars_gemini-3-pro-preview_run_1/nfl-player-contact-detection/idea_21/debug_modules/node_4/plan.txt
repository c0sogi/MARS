The issue is that the `best_iteration` attribute in XGBoost (and potentially LightGBM) is only defined when early stopping is used during training. Since the Scout models are trained on the full training subset without a validation set, early stopping is disabled, and accessing `best_iteration` raises an `AttributeError`. To fix this, I will modify the `predict` methods in `library/model_factory.py` to check for the existence of `best_iteration` using `hasattr` before using it to define the iteration range. If the attribute is missing, the model will predict using all trees (Cite debug_lesson_27). I will also apply this safe access pattern to the logging in `LGBMExpert.fit` for consistency.
