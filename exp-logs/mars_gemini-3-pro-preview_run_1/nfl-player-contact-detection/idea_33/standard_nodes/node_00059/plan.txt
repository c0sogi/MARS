The issue is that the **Relaxed Quadratic Gating** filter, which removes "easy negative" examples (player pairs far apart), is being applied to the validation set. This violates the requirement that validation metrics must be calculated on the full, unaltered distribution of the test set (Cite debug_lesson_3). Because the gating removes True Negatives, the Matthews Correlation Coefficient (MCC) is calculated on a biased subset, resulting in an invalid metric.

To fix this, I will modify the `FeatureEngine` to allow disabling the gating step. I will update `_generate_features` to accept an `apply_gating` flag. Then, I will update `process_val` to pass `apply_gating=False` and change the validation cache filename to `features_val_ungated.parquet` to ensure the corrupted (gated) cache is ignored and the full validation set is regenerated (Cite debug_lesson_5). `process_train` and `process_test` will continue to use gating for efficiency.
