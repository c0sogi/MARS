Based on the comprehensive analysis of the "Lessons Learned" and the trajectory of previous experiments, I propose the **Decoupled-Entity Interaction-Basis Anchored-Mining Ensemble (DEIB-AME)**.

This strategy introduces a **Structural Evolution** in Feature Engineering. It moves beyond "Relative Kinematics" (which collapse the system into a single difference vector) to **Decoupled Entity-Specific Projections** within an **Interaction-Aligned Basis**. This allows the model to explicitly learn the momentum balance and "aggressor" dynamics (e.g., active tackler vs. passive bracing) while maintaining strict geometric invariance. This is synthesized with the robust **Anchored Diversity Mining** pipeline to ensure stability and precision.

### 1. Model
The architecture employs a **Unified Heterogeneous Tri-Ensemble** designed to maximize algorithmic diversity and decision boundary resolution.

*   **Unified Backbone:** We utilize a single modeling framework for both Player-Player and Player-Ground contacts. We explicitly retain the **Sentinel Value Strategy** (Cite solution_lesson_node_00035), setting the `distance` feature for Ground interactions to `-1.0`. This allows the tree-based models to isolate distinct modalities via root-level splits while leveraging the shared non-contact majority class for stability (Cite solution_lesson_node_00007).
*   **Tri-Model Expert Tier:** The final predictor consists of three distinct Gradient Boosting implementations:
    1.  **LightGBM:** Leaf-wise growth (Best for dense numerical data).
    2.  **XGBoost:** Level-wise growth (Best for approximate splits).
    3.  **CatBoost:** Symmetric/Oblivious trees (Best for native categorical handling and reducing overfitting).
    *   *Rationale:* Adding CatBoost introduces a third structural bias, maximizing the ensemble's ability to resolve the "Hard Negatives" mined by the Scouts (Cite solution_lesson_node_00039).
*   **High-Capacity Configuration:** All models are configured with deep trees (e.g., `num_leaves=256`, `max_depth=10`) to maximize information density (Cite solution_lesson_node_00003).

### 2. Data
The data pipeline implements **Relaxed Quadratic Gating** and **Decoupled Interaction-Basis Feature Engineering** to capture high-fidelity momentum physics without losing directional context or support vectors.

*   **Stage 0: Relaxed Quadratic Reachability Gating**
    *   **Logic:** Model relative distance as a quadratic function: $d(t) = d_0 + v_{rel}t + 0.5 a_{rel}t^2$. Solve for $\min(d(t))$ in the window.
    *   **Filter:** Keep pairs where $\min(d(t)) < 3.0$ yards.
    *   *Rationale:* This captures high-acceleration events (like dives) (Cite solution_lesson_node_00039) while retaining the "buffer zone" of near-misses required to define the decision boundary, preventing the Support Vector Fallacy (Cite solution_lesson_node_00042).

*   **Stage 1: Decoupled Interaction-Basis Feature Engineering (Structural Innovation)**
    *   **Modality-Adaptive Basis Definition:**
        *   **Case A (Player-Player):** Define Basis $\hat{u}$ as the **Collision Axis** (Unit vector from Player 2 to Player 1).
        *   **Case B (Player-Ground):** Define Basis $\hat{u}$ as the **Motion Axis** (Unit vector of Player 1's velocity).
        *   *Rationale:* Ensures the basis aligns with the physical mechanism of interaction (Geometry vs. Trajectory) (Cite solution_lesson_node_00057).
    *   **Decoupled Vector Decomposition:** Instead of calculating relative differences ($v_1 - v_2$), project the **Individual Motion Vectors** of *both* entities onto the basis.
        *   **P1 Features:** $v_1 \cdot \hat{u}$ (Longitudinal), $v_1 \cdot \hat{u}_\perp$ (Transverse), $a_1 \cdot \hat{u}$, $j_1 \cdot \hat{u}$ (Jerk).
        *   **P2 Features:** $v_2 \cdot \hat{u}$, $v_2 \cdot \hat{u}_\perp$, $a_2 \cdot \hat{u}$, $j_2 \cdot \hat{u}$.
        *   *Rationale:* By decoupling the entities, the model can learn **Momentum Balance** ($m_1 v_1 + m_2 v_2$) and distinguish between "Head-on Collision" (both closing) and "Rear-end Collision" (one chasing). Relative features lose this absolute intensity information.
    *   **Explicit Time-Domain Lags:** Retain the projected values as explicit lags over the window ($t \in [-10, +10]$).
        *   *Rationale:* Allows GBDTs to split on specific temporal sequences (e.g., "P1 accelerates at t-5 AND P2 stops at t-1") without the information loss of spectral abstraction (Cite solution_lesson_node_00054).
    *   **Invariance:** Strictly exclude absolute coordinates (Cite solution_lesson_node_00024).

*   **Caching:** Enforce **parameter-aware caching** (Cite solution_lesson_node_00002).

### 3. Training
The training process executes a **Tri-Scout Anchored Mining Curriculum** using a strict **Binary Classification Objective**.

*   **Phase 1: Tri-Scout Training**
    *   Construct a balanced dataset from the **Relaxed Gated Survivors**.
    *   Train **Scout A (LGBM)**, **Scout B (XGB)**, and **Scout C (CatBoost)** using the **Full Decoupled Feature Set**.
    *   *Constraint:* Scouts must see the exact same features as the Expert to prevent "Semantic Gaps" (Cite solution_lesson_node_00022).

*   **Phase 2: Diversity Mining**
    *   Run Scouts on the **Entire Gated Survivor Pool**.
    *   Select **Hard Negatives**: Instances where $P(Contact) > 0.05$ from **any** Scout (Union) (Cite solution_lesson_node_00021).

*   **Phase 3: Anchored Expert Training (Binary Objective)**
    *   **Dataset Construction:** Create the Expert Dataset using three components:
        1.  **All Positives**.
        2.  **Mined Hard Negatives** (The Union).
        3.  **Random Easy Negatives (Anchors):** A random sample of the Gated Survivors that were *not* mined as hard negatives.
        *   *Rationale:* The random anchors preserve the global decision boundary, preventing the model from overfitting exclusively to the edge cases (Cite solution_lesson_node_00048).
    *   **Objective:** Train using standard **Binary LogLoss** (Targets: 0 or 1).
        *   *Rationale:* We explicitly reject Temporal Label Smoothing. For sharp event detection, soft targets degrade precision by blurring the temporal boundary (Cite solution_lesson_node_00056).
    *   **Imbalance Handling:** Use internal rebalancing parameters (`is_unbalance`, `scale_pos_weight`) (Cite solution_lesson_node_00011).

### 4. Evaluation
1.  **Feature Generation:** Generate the **Full Decoupled Interaction-Basis Feature Set** for the **Entire Test Set**.
2.  **Inference:** Run the **Tri-Model Expert Ensemble** on the test features.
3.  **Ensembling:** Compute the unweighted average of the probability outputs from the three models.
4.  **Thresholding:** Apply the decision threshold optimized on the validation set (maximizing MCC) to generate the final submission.
