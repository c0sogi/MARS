The issue stems from `Config.VERBOSE_EVAL` being set to `-1` in `runfile.py` to silence training output. While LightGBM tolerates this value, XGBoost's `xgb.train` function uses this integer as a logging period and asserts that it must be strictly positive (`period > 0`), causing an `AssertionError`. To fix this, I will modify `library/models.py` within the `XGBWrapper.fit` method to check if `Config.VERBOSE_EVAL` is less than or equal to 0. If so, I will explicitly set the `verbose_eval` argument for XGBoost to `False`, which correctly disables logging without triggering the invalid period assertion.
