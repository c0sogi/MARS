# Strategy: Context-Enriched Heterogeneous Ensemble

Building on the successes and failures of previous iterations, I propose a solution that combines the efficiency of windowed features with a structural expansion of the feature space to include "Context," and robustifies the modeling approach using a heterogeneous ensemble. This strategy directly addresses the "Ground Contact" detection failure (Lesson 00001) and the "Split-Stream" failure (Lesson 00007) while maximizing data utility (Lesson 00011).

### 1. Model
The architecture will be a **Heterogeneous Ensemble** consisting of two high-capacity Gradient Boosting models: **LightGBM** and **XGBoost**.

*   **Unified Architecture:** Both models will be trained as **Unified Classifiers** that predict both Player-Player and Player-Ground contacts simultaneously. We explicitly reject the "Split-Stream" approach (Cite Lesson 00007), as fragmenting the dataset destroyed the model's ability to learn from the shared non-contact majority class. Instead, we rely on the categorical `is_ground` feature to allow the trees to learn type-specific decision paths within a single robust framework.
*   **High Capacity:** We will configure both models with **High-Capacity Hyperparameters** (e.g., `num_leaves=256` for LightGBM, `max_depth=10` for XGBoost). This addresses the "Early Convergence" issue (Cite Lesson 00003) by ensuring the models have sufficient complexity to absorb the massive dataset and model the subtle boundaries of "near-miss" events.

### 2. Data
The data pipeline will undergo a **Structural Evolution** to incorporate environmental context and physics-based derivatives, managed by a strict caching protocol.

*   **Parameter-Aware Caching:** To prevent the "Implicit Caching Hazards" (Cite Lesson 00002), the feature generation function will generate a cache filename that includes a hash of the feature configuration (e.g., `train_features_context_v1_{hash}.parquet`). This ensures that the new context features are guaranteed to be computed.
*   **Feature Engineering:**
    *   **Temporal Flattening:** We retain the **Flattened Window** approach (+/- 10 steps, 21 total) as the core representation (Cite Lesson 00001), as it proved highly efficient.
    *   **New: Spatial Density Context:** We will introduce a new feature set representing the **Local Player Density**. For each timestep, we will pre-compute the count of *other* players (not in the current pair) within a 1.5-yard radius of Player 1 and Player 2. This provides critical context: a sudden stop in isolation suggests Ground contact, while a sudden stop in a cluster suggests unlisted Player contact.
    *   **New: Impact Physics:** We will calculate **Jerk** (derivative of acceleration) and **Angular Jerk** (derivative of orientation change) over the window. These high-frequency signals are specific proxies for the "impact impulse" of hitting the ground, directly addressing the lack of Z-coordinate data.
*   **Dataset Composition:** We will use the **Full Training Dataset** (~3.4 million rows) without downsampling. We explicitly reject the "Balance over Volume" approach (Cite Lesson 00011), as the full distribution of "hard negatives" (near misses) is essential for precision.

### 3. Training
The training procedure focuses on handling the extreme imbalance without data loss.

*   **Objective:** Binary Log-Loss.
*   **Imbalance Handling:** We will utilize internal rebalancing parameters—`is_unbalance=True` for LightGBM and `scale_pos_weight` (calculated as `neg/pos` ratio) for XGBoost. This allows the models to train on the full, imbalanced distribution (Cite Lesson 00011) while penalizing false negatives appropriately.
*   **Validation:** We will maintain the strict `game_play` based split to prevent leakage.

### 4. Evaluation
1.  **Inference:** Generate predictions using both the LightGBM and XGBoost models on the test set.
2.  **Ensembling:** Compute the unweighted average of the probability outputs from both models. This reduces variance and typically improves generalization over a single model.
3.  **Thresholding:** Apply a threshold optimized on the validation set (maximizing MCC) to the averaged probabilities to generate the final binary submission.
