The issue is caused by the creation of a mixed-type column (`nfl_player_id_2`) in the `FeatureEngine._compute_dynamic_features` method. Specifically, the code temporarily casts this column to `int` for Player-Player interactions to facilitate merging with tracking data, while Player-Ground interactions retain the string value "G". When these subsets are concatenated back together, the column contains both integers and strings. This violates strict schema requirements for Parquet serialization, causing `pyarrow` to crash when it attempts to infer a single data type (Cite debug_lesson_16).

The fix is to explicitly cast the `nfl_player_id_2` column back to `str` immediately after concatenating the subsets in `_compute_dynamic_features`. This ensures the column is homogeneous before it is passed to downstream processes and eventually saved to Parquet.
