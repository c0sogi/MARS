The issue is a schema inconsistency when generating synthetic tracking data for "Ground" (Player 2) interactions. The code indiscriminately initializes all Player 2 tracking columns (including non-numeric ones like `datetime` and `position`) to the float value `0.0`. When these rows are concatenated with Player-Player interactions (where those columns are strings), it creates mixed-type columns that cause PyArrow to crash during Parquet serialization. To fix this, we must check the data type of the source column and assign a string sentinel (e.g., "ground") for non-numeric features, ensuring type homogeneity Cite debug_lesson_16.
