The `KeyError: 'step_lag'` arises because the `merge_lag` function deletes the `step_lag` column immediately after merging Player 1's tracking data, despite it being required as a join key for the subsequent Player 2 merge. This premature deletion violates the requirement to track schema changes across sequential transformations (Cite debug_lesson_24). The fix involves removing `step_lag` from the exclusion list of the first `.drop()` call, ensuring it persists until the second merge is complete, where it is already scheduled for removal.
