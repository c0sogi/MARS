Here is the implementation strategy and the complete `runfile.py` script.

### Implementation Strategy

1.  **Configuration Override**: To ensure the solution runs quickly as a baseline, we will dynamically modify the `library.config` parameters. We will reduce `NUM_ESTIMATORS` to 100 and enable GPU acceleration for LightGBM, XGBoost, and CatBoost by patching the configuration dictionaries.
2.  **Data Loading & Subsampling**: We will use the `CurriculumTrainer`'s loader to fetch cached datasets. To strictly adhere to the time limit, we will subsample the training data to 100,000 instances while preserving the full validation set for accurate metric calculation.
3.  **Step-by-Step Training**: Instead of calling the monolithic `trainer.run()`, we will execute the pipeline phases (Scout Training, Hard Negative Mining, Expert Training) sequentially. This allows us to intervene between steps if necessary and ensures we have access to the models for specific evaluation tasks.
4.  **Validation & Metric Reporting**: We will manually perform inference on the validation set using the trained expert ensemble. We will optimize the decision threshold to maximize the Matthews Correlation Coefficient (MCC) and print the result in the required format: `Final Validation Metric: <value>`.
5.  **Failure Analysis**: We will calculate the absolute error of the model's probability predictions against the ground truth on the validation set. We will then compute the Pearson correlation between this error signal and the input features to identify which features are most correlated with model failure.
6.  **Conditional Submission**: We will check if the optimized validation MCC exceeds the threshold of 0.6865. If it does, we will trigger the `predict_test` method to generate the submission file; otherwise, we skip this step.
