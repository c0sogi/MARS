The implementation strategy involves a split-stream approach where distinct models handle player-player interactions and player-ground impacts, orchestrated by a central pipeline.

1.  **Configuration & Setup**: Initialize the environment and override default configuration parameters (reducing epochs and boosting rounds) to ensure the code runs within the "fast baseline" time constraints while maintaining reproducibility via fixed seeds.
2.  **Data Loading & Preprocessing**: Utilize the `DataPipeline` to load and split data into two streams:
    *   **Stream A (Interaction)**: Tabular data for player-player pairs. We will subsample the training set to ~200,000 rows to speed up the LightGBM training.
    *   **Stream B (Impact)**: Tensor data (N, Channels, Time) for player-ground events. We use the full set of ground contacts but limit training epochs.
3.  **Model Training**:
    *   Train the **InteractionGBM** (LightGBM) on Stream A data.
    *   Train the **ImpactTrainer** (1D-ResNet) on Stream B data, utilizing the GPU.
4.  **Validation & Evaluation**:
    *   Generate predictions for both streams on the validation set.
    *   Combine predictions and calculate the global Matthews Correlation Coefficient (MCC).
    *   Print the metric in the exact required format.
5.  **Failure Analysis**:
    *   Compute prediction errors (residuals) on the validation set.
    *   Calculate correlations between errors and input features (specifically for Stream A) to identify weak points (e.g., high speed differences or specific orientations).
6.  **Submission**:
    *   Check if the validation MCC exceeds the threshold (0.5979...).
    *   If successful, process the test set through both streams, merge predictions, align with `sample_submission.csv`, and save the result.
