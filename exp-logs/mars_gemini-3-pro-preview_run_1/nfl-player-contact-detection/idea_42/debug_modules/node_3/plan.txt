The issue is that the feature engineering pipeline applies a distance-based gating mechanism (`GATING_THRESHOLD = 3.0`) which discards player pairs that are far apart. While this is efficient for training, it causes the inference pipeline to produce a submission file that is missing rows for these "easy negative" cases. The submission file must contain a prediction for every `contact_id` in the test set.

To fix this, I will:
1.  Modify `DataLoader` in `library/data_loader.py` to expose a method `load_raw_test_metadata` that loads the complete, unfiltered test metadata.
2.  Update `InferencePipeline` in `library/inference_pipeline.py` to merge the predictions from the gated subset back into the full list of `contact_id`s. Missing values (which correspond to pairs filtered out by gating) will be filled with `0` (No Contact). This ensures the final output preserves all entity identifiers required by the submission format (Cite debug_lesson_31).
