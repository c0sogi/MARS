The issue is that the validation dataset was being filtered (gated) using a distance threshold of 3.0 yards, similar to the training set. This removal of "easy negatives" from the validation set distorted the class distribution, leading to an invalid Matthews Correlation Coefficient (MCC) calculation that did not reflect performance on the full distribution. To fix this, I will modify the feature generation logic to allow disabling gating. Specifically, I will update `_process_chunk` and `_generate_features_impl` to accept an `apply_gating` flag. I will then update `generate_val_features` to pass `apply_gating=False` and change the cache filename to `features_val_ungated.parquet` to force the regeneration of the validation data (Cite debug_lesson_3, Cite debug_lesson_5). Training and test feature generation will continue to use gating for efficiency.
