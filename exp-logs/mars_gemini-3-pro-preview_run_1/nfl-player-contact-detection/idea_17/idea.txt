Based on the comprehensive analysis of the "Lessons Learned" and the trajectory of "Previous Ideas," I propose the **Kinematically-Projected Mining Ensemble (KP-ME)**.

This strategy introduces a **Structural Evolution** in the *Candidate Generation* (Gating) and *Mining* phases. It addresses a critical latent flaw in the previous best approach (Idea 9): **Static Geometric Gating** (`Distance < 3.0y`) inadvertently discards high-velocity collisions where players are distant at $t=0$ but converge rapidly within the temporal window. By replacing static gating with **Kinematic Reachability Gating** and deploying a **Dual-Scout Diversity Mining** pipeline, we maximize the recall of "Hard Negatives" without diluting the Expert model with environmental noise.

### 1. Model
The architecture employs a **Unified Heterogeneous Ensemble** designed for maximum capacity and stability.

*   **Unified Backbone:** We utilize a single modeling framework for both Player-Player and Player-Ground contacts. We explicitly use a **Sentinel Value Strategy** (Cite solution_lesson_node_00035), setting the `distance` feature for Ground interactions to `-1.0` (a distinct, non-physical value). This allows the tree-based models to isolate Ground interactions into separate branches via a root-level split, preserving the stability of the shared non-contact majority class (Cite solution_lesson_node_00007).
*   **Heterogeneous Components:** The final predictor consists of two distinct Gradient Boosting models: **LightGBM** (Leaf-wise growth) and **XGBoost** (Level-wise growth).
*   **High-Capacity Configuration:** Both models will be configured with deep trees (e.g., `num_leaves=256`, `max_depth=10`) to maximize information density (Cite solution_lesson_node_00003).

### 2. Data
The data pipeline implements **Kinematic Reachability Gating** to enable the computation of high-fidelity physics features for the entire *plausible* search space without the risk of "High-Speed Misses."

*   **Stage 0: Kinematic Reachability Gating (The Sieve)**
    *   **Input:** The full training dataset (~3.4 million rows).
    *   **Logic:** Instead of a static distance threshold (Cite solution_lesson_node_00026), we compute the **Projected Minimum Distance**:
        *   For Player-Player: Keep if `Distance_t0 < 3.0` **OR** `(Distance_t0 / Closing_Speed_t0) < 1.0` (i.e., Time-To-Collision < 1.0s).
        *   For Player-Ground: Keep **ALL** rows (Ground physics are subtle and cannot be safely filtered by simple position).
    *   *Rationale:* This ensures that high-velocity impacts (where players are > 3 yards apart at the start of the window) are retained for the Expert, fixing the blind spot of Idea 9.

*   **Stage 1: Primary Interaction Physics Feature Engineering**
    *   **Flattened Temporal Windows:** Retain +/- 10 step (1.0s) windows for relative position, speed, and acceleration (Cite solution_lesson_node_00001).
    *   **Physics Derivatives:** Retain **Jerk** and **Angular Jerk** to explicitly detect impact impulses for Ground contact (Cite solution_lesson_node_00012).
    *   **Interaction Primitives (New):** Explicitly compute non-linear interaction terms for the **Primary Pair Only** (Cite solution_lesson_node_00036):
        *   **Time-To-Collision (TTC):** `Distance / Closing_Speed`.
        *   **Kinetic Energy Proxy:** `Relative_Speed^2`.
    *   **Invariance:** Strictly exclude absolute coordinates (Cite solution_lesson_node_00024).
    *   **Context Exclusion:** Strictly exclude 3rd-party/environmental context features to prevent signal dilution (Cite solution_lesson_node_00036).

*   **Caching:** Enforce **parameter-aware caching** to prevent implicit hazards (Cite solution_lesson_node_00002).

### 3. Training
The training process executes a **Dual-Scout Diversity Mining Curriculum** to ensure the model learns from the hardest examples across different algorithmic biases.

*   **Phase 1: Dual-Scout Training**
    *   Construct a balanced dataset from the **Gated Survivors** (All Positives + Equal Random Negatives).
    *   Train **Scout A (LightGBM)** and **Scout B (XGBoost)** on this set using the **Full Feature Set**.
    *   *Constraint:* The Scouts must see the exact same high-fidelity features as the Expert to prevent the "Semantic Gap" failure (Cite solution_lesson_node_00022).

*   **Phase 2: Diversity Mining**
    *   Run *both* Scouts on the **Entire Gated Survivor Pool**.
    *   Select **Hard Negatives**: Instances where $P(Contact) > 0.05$ from **either** Scout (Union).
    *   *Rationale:* LightGBM (gradient-based) and XGBoost (level-wise) have different error profiles. Mining the union of their mistakes maximizes the capture of edge cases (Cite solution_lesson_node_00021).

*   **Phase 3: Expert Training**
    *   Construct the **Expert Dataset**: All Positives + The Union of Mined Hard Negatives + Small Buffer of Random Gated Negatives.
    *   Train the **Expert Ensemble** (LGBM + XGB) on this high-information-density dataset.
    *   **Imbalance Handling:** Use `is_unbalance=True` (LGBM) and `scale_pos_weight` (XGB) to manage the remaining difficulty-based imbalance (Cite solution_lesson_node_00011).

### 4. Evaluation
1.  **Feature Generation:** Generate the **Full Feature Set** for the **Entire Test Set**. (The test set is small enough that Gating is unnecessary for inference speed).
2.  **Inference:** Run the **Expert Ensemble** on the test features.
3.  **Ensembling:** Compute the unweighted average of the probability outputs.
4.  **Thresholding:** Apply the decision threshold optimized on the validation set (maximizing MCC) to generate the final submission.
