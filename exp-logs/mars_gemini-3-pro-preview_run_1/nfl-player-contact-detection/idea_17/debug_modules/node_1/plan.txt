The error `pyarrow.lib.ArrowInvalid` occurs because the `nfl_player_id_2` column contains mixed data types (integers for player-player contacts and the string "G" for player-ground contacts) when passed to `to_parquet`. While Pandas handles this mixed content using the `object` dtype, Parquet requires strict, homogeneous column types (Cite debug_lesson_16). The PyArrow engine infers the column as `int64` based on the numeric values but crashes when it encounters "G".

To resolve this, I will modify `library/feature_engineering.py` to explicitly cast the `nfl_player_id_2` column back to string within the player-player processing block. This ensures that when the player-player and player-ground dataframes are concatenated, the resulting column is uniformly string-typed, satisfying Parquet's serialization requirements.
