# Strategy: Polar-Gated Kinematic Mining Ensemble (PG-KME)

Building on the success of **Geometric Gating** (Cite solution_lesson_node_00026) and **Hard-Negative Mining** (Cite solution_lesson_node_00021), I propose a structural evolution in feature engineering: **Ego-Centric Polar Interaction Descriptors**.

This strategy addresses the limitations of "Scalar Density" (Cite solution_lesson_node_00023) and "Absolute Coordinates" (Cite solution_lesson_node_00024) by mapping the local environment into a rotation-invariant, biologically plausible polar grid. This allows the model to physically distinguish between "running in a pack" (tangential flow) and "converging for a tackle" (radial flow) within a computationally efficient, gated pipeline.

### 1. Model
The architecture employs a **Unified Heterogeneous Ensemble** designed for maximum capacity and stability.

*   **Unified Backbone:** We utilize a single modeling framework for both Player-Player and Player-Ground contacts, utilizing an `is_ground` categorical feature. This leverages the shared non-contact majority class to stabilize the decision boundary (Cite solution_lesson_node_00007).
*   **Heterogeneous Components:** The predictor consists of two distinct Gradient Boosting models: **LightGBM** (Leaf-wise) and **XGBoost** (Level-wise).
*   **High-Capacity Configuration:** Both models will be configured with deep trees (e.g., `num_leaves=256`, `max_depth=10`) to maximize information density (Cite solution_lesson_node_00003).

### 2. Data
The data pipeline implements **Geometric Gating** to enable the computation of the new **Polar Interaction Features** for the entire candidate pool without semantic gaps.

*   **Stage 0: Geometric Gating (The Sieve)**
    *   **Filter:** For the full training set (~3.4M rows), calculate instantaneous Euclidean distance.
    *   **Logic:** Discard Player-Player pairs with `Distance > 2.5` yards. Keep **ALL** Player-Ground pairs.
    *   *Rationale:* This eliminates trivial non-contacts (Cite solution_lesson_node_00026), reducing the dataset to ~600k rows while preserving all potential "Hard Negatives".

*   **Stage 1: Ego-Centric Polar Feature Engineering (Innovation)**
    *   **Base Kinematics:** Retain **Flattened Temporal Windows** (+/- 10 steps) and **Physics Derivatives** (Jerk) (Cite solution_lesson_node_00001, solution_lesson_node_00012).
    *   **Polar Interaction Grids:** For every survivor row, construct a local coordinate system aligned with the target player's orientation.
        *   **Binning:** Divide the space into **Polar Bins** (e.g., 4 angular sectors: Front, Back, Left, Right × 2 radial bands: 0-1y, 1-2y).
        *   **Aggregation:** For each bin, compute:
            *   **Occupancy:** Count of neighbors.
            *   **Radial Flux:** Average relative velocity projected onto the radius (Negative = Converging).
            *   **Tangential Flux:** Average relative velocity perpendicular to the radius (Positive = Orbiting/Running alongside).
        *   *Rationale:* This explicitly encodes the *structure* of the crowd (e.g., "Impact coming from the blindside") while maintaining strict **Translation Invariance** (Cite solution_lesson_node_00024). It resolves the ambiguity of scalar density counts (Cite solution_lesson_node_00023).

*   **Caching:** Enforce **parameter-aware caching** to prevent implicit hazards (Cite solution_lesson_node_00002).

### 3. Training
The training process executes a **Full-Fidelity Mining Curriculum** to ensure the model learns from the hardest examples.

*   **Phase 1: Scout Training**
    *   Construct a balanced dataset from the **Gated Survivors** (All Positives + Equal Random Negatives).
    *   Train a **Scout LightGBM** using the **Full Feature Set** (Polar + Windows).
    *   *Constraint:* The Scout must see the exact same high-fidelity features as the Expert to prevent the "Semantic Gap" failure (Cite solution_lesson_node_00022).

*   **Phase 2: Full-Scale Mining**
    *   Run Scout inference on the **Entire Gated Survivor Pool** (~600k rows).
    *   Select **Hard Negatives**: Instances where $P(Contact) > 0.05$ but Ground Truth is 0.
    *   *Rationale:* This leverages the scale-dependent efficacy of mining (Cite solution_lesson_node_00021) to find edge cases.

*   **Phase 3: Expert Training**
    *   Construct the **Expert Dataset**: All Positives + All Mined Hard Negatives + Small Buffer of Random Gated Negatives.
    *   Train the **Expert Ensemble** (LGBM + XGB) on this high-information-density dataset.
    *   **Imbalance Handling:** Use `is_unbalance=True` (LGBM) and `scale_pos_weight` (XGB) (Cite solution_lesson_node_00011).

### 4. Evaluation
1.  **Feature Generation:** Generate the **Full Feature Set** (Polar + Windows) for the **Entire Test Set**. (Test set size allows full computation without gating).
2.  **Inference:** Run the **Expert Ensemble** on the test features.
3.  **Ensembling:** Compute the unweighted average of the probability outputs.
4.  **Thresholding:** Apply the decision threshold optimized on the validation set (maximizing MCC) to generate the final submission.
