### Implementation Strategy

1.  **Configuration Override**: We will modify the imported `KADM_CONFIG` dictionary to enable `debug` mode and reduce training iterations (`num_boost_round`). This ensures the pipeline runs on a small sample of data (200 rows) and trains quickly (10 rounds) to meet the time constraints. We will also redirect output paths to a specific `./working/demo_run` directory to keep the environment clean.
2.  **Pipeline Initialization**: We will explicitly pass the modified configuration dictionary to the `TrainingCurriculum` class. This ensures that all internal components (DataLoader, FeatureEngine, ModelZoo) use the optimized settings.
3.  **Execution**:
    *   **Training**: We will execute the `curriculum.run()` method. This triggers the full workflow: feature engineering with caching, hard negative mining using Scout models, training the Expert Dual-Ensemble (LGBM + XGB), and optimizing the decision threshold.
    *   **Inference**: We will call `generate_submission()` using the trained ensemble and optimized threshold to produce predictions on the test set (sampled in debug mode).
4.  **Verification**: We will use assertions to verify:
    *   The existence of trained model artifacts (`expert_lgbm.joblib`, `expert_xgb.joblib`).
    *   The existence of the optimized threshold file.
    *   The creation and validity of the `submission.csv` file (checking for correct columns and non-empty content).
