### Implementation Strategy

1.  **Configuration Override**: To ensure the demonstration runs quickly within the time limit, we will first modify the global `Config` class attributes. We will reduce the number of estimators (trees) for LightGBM, XGBoost, and CatBoost to a minimal value (10) and reduce early stopping rounds.
2.  **Data Loading & Feature Engineering**: We will utilize the `DataLoader` class to load a small sample of the training data. We will verify that the `FeatureEngineer` correctly computes physics-based features (e.g., `distance`, `v_radial`) and handles the "Ground" sentinel values.
3.  **Model Validation**: We will instantiate individual models (`LGBMModel`, `XGBModel`, `CatBoostModel`) and the `EnsemblePredictor`. We will train them on the small data sample, verify that predictions are valid probabilities (0 to 1), and check the save/load functionality.
4.  **Full Pipeline Execution**: We will instantiate the `Trainer` class and execute the full `run_training_pipeline` with a constrained `sample_size`. This will verify the integration of the Scout/Expert architecture, Hard Negative Mining, Temporal Smoothing, and Threshold Optimization.
5.  **Submission Verification**: Finally, we will assert that the `submission.csv` file is generated correctly and adheres to the expected format.
