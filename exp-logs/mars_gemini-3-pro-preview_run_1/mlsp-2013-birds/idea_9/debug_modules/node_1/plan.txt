The issue is that the data processing logic implicitly infers the number of classes by matching all columns starting with "species_", which incorrectly picks up an artifact column (`species_19`) generated during metadata creation, resulting in 20 classes instead of the expected 19. This causes a shape mismatch between the data loader and the model configuration.

To fix this, I will modify `library/data.py` to explicitly select the label columns based on the `NUM_CLASSES` defined in the configuration, ensuring only the valid 19 species columns are loaded. This aligns with the principle of prioritizing explicit schema definitions over implicit pattern matching (Cite debug_lesson_1).
