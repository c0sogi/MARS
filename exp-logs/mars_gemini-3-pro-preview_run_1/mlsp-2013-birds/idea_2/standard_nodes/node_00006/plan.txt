The issue is that `sklearn.metrics.roc_auc_score` with `average='macro'` returns `nan` instead of raising a `ValueError` when the validation set lacks positive samples for certain classes. This behavior bypasses the existing fallback logic, which is designed to handle such sparsity by calculating AUC per column. Consequently, the validation metric remains `nan`, preventing model checkpoints and resulting in a failed submission. The fix is to explicitly check if the calculated score is `nan` inside the `try` block and raise a `ValueError` if so, forcing the execution of the robust fallback calculation.
