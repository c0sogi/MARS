The issue is that `roc_auc_score(..., average='macro')` returns `NaN` when the validation set contains "degenerate" classes (classes with only one label value, e.g., all zeros), which inevitably happens when training on a tiny debug subset (32 samples). This `NaN` value causes the `val_auc > best_auc` comparison to fail (evaluating to False), preventing the "best model" checkpoint from ever being saved. The fix involves manually iterating through each class in the `validate` function, checking for the presence of both positive and negative labels, and computing the mean AUC manually, substituting 0.5 for degenerate classes (Cite debug_lesson_5).
