The issue is that the SWA models are saved using `AveragedModel`, which wraps the underlying model in a `module` attribute and adds a buffer named `n_averaged`. When loading these checkpoints into a standard `BirdModel` for inference, the keys mismatch (e.g., `module.backbone.conv1...` vs `backbone.conv1...`) and the `n_averaged` key is unexpected, causing a `RuntimeError`.

To fix this, I will implement a `sanitize_state_dict` helper function in `library/pipeline.py` that strips the `module.` prefix and removes the `n_averaged` key from the loaded state dictionary before loading it into the model. This solution directly applies the guidance from **debug_lesson_9**. I will then update both the `generate_pseudo_labels` and `run_pipeline` functions to use this sanitizer when loading checkpoints.
