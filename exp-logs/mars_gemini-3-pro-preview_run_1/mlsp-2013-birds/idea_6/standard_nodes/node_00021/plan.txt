The issue is that `roc_auc_score` returns `nan` instead of raising a `ValueError` when a specific class has only one unique label in the ground truth (e.g., all zeros), causing the fallback loop to collect `nan` values and the final mean to be `nan`. This prevents the model from saving checkpoints because `nan` is not greater than the best score, leading to a `FileNotFoundError` later (Cite debug_lesson_2). The fix involves explicitly checking if the per-class AUC score is `nan` within the fallback loop and treating it as a neutral value (0.5), ensuring a valid numerical metric is always returned.
