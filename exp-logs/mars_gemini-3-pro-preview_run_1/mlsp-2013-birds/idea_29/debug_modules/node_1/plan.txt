The issue is that the `_load_cache_data` function in `library/data.py` uses implicit pattern matching (`startswith("species_")`) to identify label columns. The dataset metadata contains 20 label columns (`species_0` through `species_19`)—likely due to an artifact in the `species_list.txt` file—while the model configuration `Config.NUM_CLASSES` expects only 19. This results in a shape mismatch during data loading (loading 20 classes instead of 19).

To fix this, I will modify `library/data.py` to explicitly select the label columns based on `Config.NUM_CLASSES` (i.e., `species_0` to `species_18`). This ensures the data loader adheres strictly to the defined architecture and ignores any extraneous columns, applying the principle from **debug_lesson_1**.
