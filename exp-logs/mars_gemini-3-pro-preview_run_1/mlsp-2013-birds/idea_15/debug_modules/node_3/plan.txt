The issue is that the `load_checkpoint` function in `library/utils.py` uses a brittle heuristic to detect if a model is wrapped (e.g., by `DataParallel` or `AveragedModel`). It checks only the **first key** of the state dictionary. In the case of SWA (Stochastic Weight Averaging) checkpoints, the first key is often `n_averaged`, which does not start with `module.`. Consequently, the function fails to unwrap the parameters (e.g., `module.conv1.weight`), causing a `RuntimeError` due to key mismatches when loading into a standard ResNet.

To fix this, I will modify `library/utils.py` to check if **any** key starts with `module.`, making the detection robust to the order of keys. I will also update the unwrapping loop to explicitly filter for keys starting with `module.`, thereby discarding auxiliary buffers like `n_averaged` that are not part of the base model architecture. This aligns with **Cite {debug_lesson_9}**.
