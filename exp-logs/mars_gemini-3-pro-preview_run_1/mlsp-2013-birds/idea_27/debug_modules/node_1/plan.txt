The issue is that the validation AUC calculation returns `NaN` when running on the small demo dataset because some bird species (classes) lack positive or negative examples in the tiny validation subset. Standard `roc_auc_score(average='macro')` fails or returns `NaN` in these "degenerate" cases, causing the `val_auc > best_auc` check to fail (since `NaN > 0` is False), preventing the best model checkpoint from being saved.

To fix this, I will modify `Trainer.validate` in `library/training.py` to manually iterate through each class. I will explicitly check if a class has both positive and negative samples before calculating its AUC, and then compute the mean of only the valid class AUCs. This robustly handles degenerate data subsets typically found in debug or demo runs, ensuring a valid numeric score is returned so the checkpointing logic works. Cite {debug_lesson_5}.
