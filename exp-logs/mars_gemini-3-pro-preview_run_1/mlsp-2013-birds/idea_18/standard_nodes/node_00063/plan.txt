The `RuntimeError` during checkpoint loading occurs because the SWA model (`AveragedModel`) is saved including its wrapper structure. This results in keys prefixed with `module.` and the inclusion of the `n_averaged` buffer. When `load_checkpoint` attempts to load this into the base `ResNet` model, the brittle prefix-stripping logic fails (likely due to key ordering or the presence of `n_averaged`), causing a key mismatch.

To fix this, I will modify `library/core.py` to save the **inner model's** state dictionary (`self.swa_model.module.state_dict()`) instead of the wrapper's state dictionary. This ensures the checkpoint contains clean keys (e.g., `conv1.weight`) that match the base model's architecture, resolving the compatibility issue. This solution directly follows the recommendation in Cite {debug_lesson_11}.
