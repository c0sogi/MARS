The issue stems from a discrepancy in the class vocabulary between the training and inference phases when running in debug mode. During training (`debug=True`), the code subsets the data to 50 classes but explicitly skips saving the label map (`classes.npy`) to avoid polluting the cache. Consequently, during inference (`debug=True`), the data loader fails to find the cached map and falls back to loading the full dataset, resulting in a vocabulary of 64,500 classes. This causes a size mismatch when attempting to load the 50-class model weights.

To fix this, I will modify `library/dataset.py` to:
1.  Update `get_label_map` to use a separate cache file (`classes_debug.npy`) when `debug=True` and allow saving/loading this file. This ensures the debug vocabulary is persisted without affecting the main cache.
2.  Update `get_test_dataloader` to look for this debug-specific cache file when `debug=True`.
3.  Update the fallback logic in `get_test_dataloader` to replicate the debug subsetting logic if the cache is missing, ensuring referential integrity (Cite debug_lesson_1).
