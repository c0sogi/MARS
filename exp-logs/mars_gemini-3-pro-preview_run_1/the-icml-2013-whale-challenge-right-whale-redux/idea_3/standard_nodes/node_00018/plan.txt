The issue is that the training pipeline is loading stale, cached data from a previous debug run (likely a small subset) instead of processing the full dataset. This caused the model to train on a tiny fraction of the data, resulting in anomalously fast epoch times and invalid validation metrics. To fix this, I will modify `runfile.py` to set `load_cached_data=False` in the `run_training` call. This forces the `process_and_cache_data` function in `library/dataset.py` to bypass the existing cache, re-process all audio files from the metadata, and overwrite the cache with the complete dataset.
