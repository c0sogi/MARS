The implementation strategy involves a step-by-step verification of the provided library components, ensuring they function correctly and interact as expected.

1.  **Environment Setup**: Initialize the random seed using `library.utils.seed_everything` to ensure reproducibility.
2.  **Data Pipeline Verification**:
    *   Utilize `library.data.get_dataloaders` with `debug=True` to load a small subset of the data.
    *   Iterate through the `train_loader` to fetch a single batch.
    *   Assert the presence and correct shape of all expected keys in the batch dictionary (`axial`, `coronal`, `tabular`, `target`, `dt`, `baseline_fvc`). This confirms the `CTDataset` and `TabularPreprocessor` are working correctly.
3.  **Model Architecture Verification**:
    *   Instantiate the `SLHDAN` model from `library.model`.
    *   Perform a forward pass using the fetched data batch.
    *   Verify that the model outputs (`alpha`, `sigma_base`, `sigma_growth`) have the expected dimensions matching the batch size.
    *   Test the custom loss function `criterion` to ensure it computes a valid scalar loss without errors.
4.  **Metric Logic Verification**:
    *   Manually test `library.utils.laplace_log_likelihood_metric` with known dummy values (e.g., perfect prediction vs. poor prediction) to confirm the metric calculation logic aligns with the task description.
5.  **Full Training Pipeline Execution**:
    *   Execute `library.train.run_training` with `debug=True` and `epochs=1`. This runs the entire workflow: training loop, validation, checkpoint saving, and inference.
    *   This step implicitly verifies the optimizer, scheduler, and training loop logic in `train_one_epoch` and `validate`.
6.  **Submission Verification**:
    *   After the pipeline finishes, check for the existence of the submission file at `Config.SUBMISSION_PATH`.
    *   Load the submission file and verify it contains the required columns (`Patient_Week`, `FVC`, `Confidence`) and the correct number of rows corresponding to the debug test set.
