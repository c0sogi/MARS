The following strategy outlines the implementation of the demonstration script:

1.  **Configuration & Setup**: We will first modify the global `Config` class attributes to adapt the training parameters for a quick demonstration. This includes reducing the number of epochs to 2, the batch size to 4, and the debug sample size to 16. This ensures the script runs within seconds while still exercising all code paths.
2.  **Data Pipeline Verification**: We will instantiate the data loaders using `get_dataloaders` in debug mode. We will fetch a single batch to verify that the shapes of the images (Axial and Coronal views), tabular features, and targets are correct and adhere to the expected dimensions.
3.  **Model Instantiation & Forward Pass**: We will initialize the `ASADAN` model and move it to the appropriate device (GPU/CPU). We will perform a forward pass using the batch fetched in the previous step to confirm that the model produces predictions (`FVC` and `Confidence`) without errors and that the outputs satisfy basic constraints (e.g., positive confidence).
4.  **Training Simulation**: We will execute the `run_training` function from the library. This function encapsulates the training loop, validation, and checkpointing. By running it in debug mode with our reduced configuration, we verify the entire training pipeline.
5.  **Inference & Submission Generation**: Post-training, we will load the saved best model checkpoint. We will manually iterate over the test set (aligned with the debug subset), generate predictions, and construct a submission DataFrame. Finally, we will save this to a CSV file, mimicking the actual submission process.
