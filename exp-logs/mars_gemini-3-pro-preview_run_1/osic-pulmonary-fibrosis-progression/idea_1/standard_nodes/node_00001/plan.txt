The implementation strategy follows a standard deep learning pipeline orchestration tailored to the specific constraints of the task.

1.  **Setup & Configuration**: We initialize the environment by setting random seeds for reproducibility and detecting the available computation device (GPU/CPU). We utilize the provided `Config` class to manage paths and hyperparameters.
2.  **Data Loading**: We use the `get_dataloaders` function from the library. We ensure `load_cached_data=True` (default in Config) is utilized to leverage the pre-computed MIP images, significantly speeding up data loading.
3.  **Model Initialization**: The `MIPLinearDecayNet` is instantiated and moved to the GPU. This model combines a ResNet18 backbone for image analysis with an MLP for tabular data to predict the slope of decline and confidence.
4.  **Training**: We employ the `Trainer` class to handle the training loop. To satisfy the "fast baseline" requirement, we limit training to 10 epochs with early stopping. This ensures the code completes well within the time limit while still learning a meaningful baseline.
5.  **Validation & Metric**: After training, we reload the best model checkpoint. We compute the final validation loss using the `LaplaceLogLikelihoodLoss`. Since the competition metric is the negative of this loss, we invert the sign and print it as `Final Validation Metric`.
6.  **Failure Analysis**: We perform a dedicated inference pass on the validation set to calculate absolute errors for each sample. We then compute and print the correlation between these errors and input features (Age, Baseline FVC, Weeks, etc.) to identify sources of systematic error.
7.  **Submission**: Finally, we use the `Trainer.predict` method to generate predictions for the test set. This method handles the logic of extrapolating the FVC based on the predicted slope and the specific week required for the submission file, saving the result to `./submission/submission.csv`.
