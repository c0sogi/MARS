The issue is that recent versions of PyTorch (2.6+) default `torch.load` to `weights_only=True`, which restricts unpickling to a safe allowlist of types. The checkpoint file generated by the training loop includes a validation score stored as a NumPy scalar (`numpy.float64`), which is not in this default allowlist, causing a `_pickle.UnpicklingError`. To resolve this, I will explicitly set `weights_only=False` in the `torch.load` call within `library/utils.py`, opting out of the restricted mode to permit loading the custom metadata stored alongside the model weights.
