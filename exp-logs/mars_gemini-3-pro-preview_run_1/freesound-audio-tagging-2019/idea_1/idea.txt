To establish a reliable performance baseline, I propose a **Shallow VGG-Style Convolutional Neural Network (CNN)**. This approach prioritizes architectural simplicity and computational efficiency, serving as a fundamental deep learning benchmark to evaluate if more complex architectures (like EfficientNet, Transformers, or RNNs) are actually necessary.

### Model
The architecture is a straightforward 2D CNN designed to process audio spectrograms as images.
*   **Backbone:** The network consists of **four convolutional blocks**. Each block comprises a standard 2D Convolutional layer (kernel size 3x3) to extract local spectral-temporal features, followed by Batch Normalization for training stability, a ReLU activation function, and a 2D Max Pooling layer (2x2) to reduce spatial dimensions and computational load.
*   **Feature Aggregation:** Unlike the Global Average Pooling used in Model 1 and Model 5, this model employs **Global Max Pooling** after the final convolutional block. Max pooling is particularly effective for weakly labeled audio data (where a sound event may occur only briefly within a longer clip) as it captures the strongest activation for each feature map regardless of the event's duration.
*   **Classification Head:** The aggregated feature vector is fed directly into a single fully connected (dense) layer with 80 output units. A Sigmoid activation function is applied to generate independent probabilities for each class.

### Data
*   **Preprocessing:** All audio clips will be converted to mono and resampled to a standard sample rate (e.g., 32 kHz) to reduce input size while retaining high-frequency information.
*   **Feature Extraction:** We will compute Log-Mel Spectrograms for each clip. Key parameters will include a window size of roughly 25-30ms, a hop length of 10ms, and 64 Mel filter banks. This creates a 2D representation (Time x Frequency).
*   **Input Formatting:** To enable efficient batch training, inputs will be standardized to a fixed length (e.g., 5 seconds). Clips shorter than this duration will be padded with zeros (silence), and clips longer than this will be randomly cropped during training or truncated.

### Training
*   **Loss Function:** We will use **Binary Cross-Entropy (BCE) Loss** (specifically `BCEWithLogitsLoss` for numerical stability). This treats the task as 80 independent binary classification problems, which is appropriate for multi-label data.
*   **Optimizer:** The **Adam** optimizer will be used with default parameters and a standard learning rate (e.g., 1e-3), as it requires minimal tuning compared to SGD.
*   **Procedure:** The model will be trained for a fixed number of epochs (e.g., 20-30) using the combined training set (Curated + Noisy). We will monitor the validation loss on the curated validation set to implement early stopping if the loss fails to improve for several consecutive epochs.

### Evaluation
*   **Inference:** For the test set, audio files will be processed into Log-Mel Spectrograms using the same parameters as training.
*   **Prediction:** To handle variable lengths in the test set without information loss, we will either process the full-length spectrogram (since Global Max Pooling handles variable dimensions) or center-crop/pad to the training size. The model will output raw logits, which are converted to probabilities [0, 1] via the Sigmoid function.
*   **Submission:** The resulting probability vectors for the 80 classes will be associated with their respective filenames and saved to the submission CSV format.
