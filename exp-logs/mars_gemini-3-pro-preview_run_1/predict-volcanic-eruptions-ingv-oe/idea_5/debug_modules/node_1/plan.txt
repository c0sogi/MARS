The `ValueError: Input contains NaN` during validation indicates that the Vision model is producing invalid predictions, likely due to corrupted input data (spectrograms containing `-inf` from log-of-zero operations on silent sensors) or numerical instability in the network. To fix this, I will implement a multi-layered defense:
1.  **Sanitize Inputs**: In `library/data_processing.py`, I will apply `np.nan_to_num` to the generated spectrograms to replace `-inf` (silence) and `NaN` values with safe constants before they enter the model (Cite debug_lesson_1).
2.  **Invalidate Cache**: I will update `library/config.py` to modify the `SPECTROGRAM_PARAMS` hash, ensuring the pipeline regenerates the spectrograms instead of loading the corrupted cached files.
3.  **Sanitize Outputs**: In `library/train_vision.py`, I will sanitize the validation predictions using `np.nan_to_num` before calculating the MAE metric to prevent the evaluation loop from crashing on transient instabilities (Cite debug_lesson_5).
