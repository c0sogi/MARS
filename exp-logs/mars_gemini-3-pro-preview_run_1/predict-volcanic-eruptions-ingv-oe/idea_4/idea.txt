Based on the comprehensive analysis of the previous experiments and the distilled lessons, I propose a **Hybrid Spectrogram-Feature Stacked Ensemble**. This strategy structurally evolves the failed Idea 3 by replacing the raw 1D-ResNet with a 2D Spectrogram-based Vision model, strictly implementing target scaling, and upgrading the ensemble mechanism.

# Model
The solution utilizes a **Heterogeneous Stacking Ensemble** composed of two orthogonal modeling branches:

1.  **Branch A: Expert Feature Gradient Boosting (LightGBM)**
    *   This branch retains the highly successful tabular approach but ensures robustness via strict caching and explicit coding.
    *   **Input:** A dense vector of engineered statistics per segment.
    *   **Architecture:** A LightGBM Regressor optimized for tabular data.

2.  **Branch B: Time-Frequency Vision Model (2D-CNN)**
    *   **Structural Innovation (Spectrograms):** Instead of processing raw 1D waveforms (which failed in Idea 3) or collapsing time completely (Idea 1), this branch transforms the sensor data into **Log-Mel Spectrograms**. This 2D representation captures the *evolution* of frequency content over time (e.g., pre-eruptive harmonic tremors) in an image format.
    *   **Architecture:** An **EfficientNet-B0** (or similar 2D CNN) modified to accept 10 input channels (one per sensor). This leverages powerful pre-trained vision biases to detect complex texture patterns in the seismic frequency maps.

3.  **Meta-Learner:**
    *   Instead of a simple unweighted average, a **Ridge Regression (Linear)** meta-model will be trained on the Out-of-Fold (OOF) predictions from Branch A and Branch B to optimally weigh the contributions of each model (Cite Lesson ID: solution_lesson_node_00012).

# Data
The data pipeline is divided to serve the specific needs of each branch, underpinned by a unified caching layer.

1.  **Robust Caching:**
    *   All feature extraction and spectrogram generation will use **Configuration Hashing** in filenames to prevent the loading of stale data (Cite Lesson ID: solution_lesson_node_00002).

2.  **Branch A Preprocessing (Expert Features):**
    *   **Explicit Extraction:** Features will be calculated using explicit function calls to avoid silent failures (Cite Lesson ID: solution_lesson_node_00005).
    *   **Global Statistics:** Compute Mean, Std, Skew, Kurtosis, and Quantiles (e.g., Max, 99%) over the entire segment. We explicitly avoid aggregating local window statistics to preserve sparse event magnitudes (Cite Lesson ID: solution_lesson_node_00004).
    *   **Spectral & Structural:** Calculate FFT statistics (Mean, Std, Dominant Freq), **Raw Zero-Crossing Rate** (to utilize amplitude gating, Cite Lesson ID: solution_lesson_node_00007), and Total Variation (Cite Lesson ID: solution_lesson_node_00006).
    *   **Wavelets:** Compute Energy and Entropy of Discrete Wavelet Transform (DWT) coefficients (retained from the successful component of Idea 3).

3.  **Branch B Preprocessing (Spectrograms):**
    *   **Transformation:** Convert the 10 normalized sensor arrays into Log-Mel Spectrograms using `torchaudio`. Stack these into a `(10, Frequency_Bins, Time_Steps)` tensor.
    *   **Target Scaling (Crucial):** Apply **Log-Scaling** (`np.log1p`) or **Robust Scaling** to the `time_to_eruption` target variable. This reduces the target magnitude from $\sim10^7$ to a small range (e.g., 0-20), preventing the gradient explosion/convergence failure observed in the previous neural network attempt (Cite Lesson ID: solution_lesson_node_00009).

# Training
Both branches will utilize a **5-Fold Cross-Validation** scheme.

1.  **Branch A (LightGBM):**
    *   Train with MAE objective and early stopping based on validation performance.

2.  **Branch B (2D-CNN):**
    *   **Loss Function:** Mean Absolute Error (MAE) calculated on the **scaled target**.
    *   **Optimizer:** AdamW with a Cosine Annealing Learning Rate scheduler to ensure stable convergence.
    *   **Augmentation:** Apply mild time/frequency masking (SpecAugment) to prevent overfitting on the small dataset.

3.  **Stacking:**
    *   Collect OOF predictions from A and B (inverse-transforming B's predictions first).
    *   Train the Ridge Regressor on these OOF predictions against the ground truth to learn the optimal blending weights.

# Evaluation
1.  **Inference:** Process test data to generate both the Expert Feature Matrix and the Spectrogram Tensor.
2.  **Prediction:**
    *   Generate predictions from LightGBM (Branch A).
    *   Generate predictions from 2D-CNN (Branch B) and apply the **inverse target transformation** (e.g., `np.expm1`) to return to the original scale.
3.  **Submission:** Feed both prediction vectors into the trained Ridge Meta-Learner to produce the final `time_to_eruption` estimates.
