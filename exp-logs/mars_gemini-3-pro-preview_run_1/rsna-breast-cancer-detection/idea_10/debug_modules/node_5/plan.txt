The issue is a "Zombie Tensor" problem where GPU memory from a previous execution is not being released because the Python interpreter (specifically the exception handling mechanism) holds references to the stack frame of the crashed function. The current cleanup logic at the start of `run_demo` is insufficient because it cannot access the local variables of the *previous* `run_demo` call that are trapped in the traceback held by the external runner.

To fix this, I will apply `debug_lesson_21` ("Wrap GPU Allocations in Try-Finally Blocks to Prevent Zombie Stack Frames") to `runfile.py`. I will wrap the entire execution logic of `run_demo` in a `try...finally` block. Inside the `finally` block, I will explicitly delete the local variables (like `model`, `train_loader`, etc.) and call `gc.collect()` and `torch.cuda.empty_cache()`. This ensures that even if the script crashes, the references to the GPU tensors are severed *before* the exception propagates up to the interpreter, preventing the creation of new zombie stack frames and allowing the memory to be reclaimed.
