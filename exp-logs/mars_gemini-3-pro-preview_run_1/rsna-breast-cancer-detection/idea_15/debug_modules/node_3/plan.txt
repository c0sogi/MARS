The previous implementation of `load_image` failed because it relied on `cv2.imread` (which often lacks DICOM support) and a brittle manual byte-search fallback, leading to a `FileNotFoundError` when it couldn't decode a file. To fix this, I will implement a robust, cascading loading strategy in `library/dataset.py`. This strategy includes:
1.  **Adding Optional Imports**: Importing `pydicom` (the standard for DICOM) and `tensorflow` (for its robust image decoders) inside `try-except` blocks, ensuring `tensorflow` is configured to not consume GPU memory (Cite debug_lesson_13).
2.  **Cascading Fallbacks**: The `load_image` function will sequentially try loading via `.npy` cache, `pydicom`, `cv2`, and manual byte extraction (Cite debug_lesson_8).
3.  **Graceful Failure**: Instead of raising an exception and crashing the pipeline when a file is corrupt or unsupported, the function will log a warning and return a black image (zeros), allowing the training loop to proceed (Cite debug_lesson_8).

    """
    Loads an image from the given path using multiple fallbacks.
    Priority: .npy -> pydicom -> cv2 -> manual decode -> tensorflow -> black image.
    """
    # 0. Check for pre-processed .npy file (Cite debug_lesson_4)
    npy_path = path.replace(".dcm", ".npy")
    if os.path.exists(npy_path):
        try:
            return np.load(npy_path)
        except Exception:
            pass

    if not os.path.exists(path):
        # Return black image if file is genuinely missing to avoid crashing
        logger.warning(f"File not found: {path}. Returning black image.")
        return np.zeros(Config.IMG_SIZE, dtype=np.uint8)
