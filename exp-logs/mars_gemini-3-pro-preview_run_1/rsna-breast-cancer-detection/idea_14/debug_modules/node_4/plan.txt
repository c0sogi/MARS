The error `torch.AcceleratorError: CUDA error: out of memory` occurs immediately during model initialization, indicating that the GPU memory is saturated by "zombie" resources from previous executions in the persistent environment. As detailed in **debug_lesson_18** and **debug_lesson_15**, simply restarting the script is insufficient because exception tracebacks (`sys.last_traceback`) and global variables retain references to old tensors, preventing garbage collection. To fix this, I will modify `runfile.py` to import `gc` and implement a `cleanup_gpu_resources` function that explicitly clears system tracebacks, deletes global PyTorch objects (Models, Tensors, Optimizers), and invokes garbage collection before the demo starts.

def cleanup_gpu_resources():
    print("Cleaning up GPU resources...")
    
    # 1. Clear System Tracebacks (Cite debug_lesson_18)
    # These hold references to stack frames from previous crashes, keeping local variables alive.
    if hasattr(sys, 'last_traceback'):
        del sys.last_traceback
    if hasattr(sys, 'last_value'):
        del sys.last_value
    if hasattr(sys, 'last_type'):
        del sys.last_type
        
    # 2. Clear Global PyTorch Objects (Cite debug_lesson_15)
    # Iterate over globals and delete any Tensors, Modules, or Optimizers.
    for name, obj in list(globals().items()):
        if isinstance(obj, (torch.nn.Module, torch.Tensor, torch.optim.Optimizer)):
            try:
                del globals()[name]
            except KeyError:
                pass
            
    # 3. Force Garbage Collection and Cache Clearing
    gc.collect()
    torch.cuda.empty_cache()
    print("GPU cleanup complete.")


def run_demo():
