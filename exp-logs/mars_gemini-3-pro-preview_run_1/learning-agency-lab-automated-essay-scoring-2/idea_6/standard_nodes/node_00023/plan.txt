The issue is that the Adversarial Weight Perturbation (AWP) logic, which calls `scaler.unscale_(optimizer)`, is executed at every mini-batch step, while the optimizer update (`scaler.step(optimizer)`) only happens every `gradient_accumulation_steps` (8 in this case). PyTorch's `GradScaler` throws a `RuntimeError` if `unscale_` is called multiple times between updates.

To fix this, I will move the entire AWP execution block inside the gradient accumulation conditional check (`if (step + 1) % Config.gradient_accumulation_steps == 0:`). This ensures that gradient unscaling and the adversarial attack only occur immediately before the optimizer step, synchronizing the unscaling operations with the updates as per `debug_lesson_6`.
