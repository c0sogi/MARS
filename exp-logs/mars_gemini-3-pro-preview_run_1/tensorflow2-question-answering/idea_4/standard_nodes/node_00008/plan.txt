The implementation strategy involves a sequential execution pipeline designed to meet the constraints of a fast baseline while satisfying the rigorous evaluation requirements.

1.  **Configuration & Setup**: The script starts by importing necessary modules and overriding `Config` parameters. We set `EPOCHS=1` and `DEBUG=True` (with a small `DEBUG_SIZE`) to ensure the training phase completes quickly. We explicitly clean up any existing cached data in the working directory to prevent stale data usage.
2.  **Training**: We generate data loaders under the `DEBUG=True` setting. This creates a small training set. The model is initialized and trained for one epoch.
3.  **Validation**: To evaluate on the *entire* hold-out validation set as required, we switch `Config.DEBUG = False`. We delete the cached validation data (which was small from the previous step) and regenerate the data loaders. This forces the processing of the full validation set. We then run the trained model in evaluation mode on this full set, calculating the Micro F1 score based on Long Answer predictions (as the primary classification task) and printing it in the specific format required.
4.  **Failure Analysis**: Using the validation results, we compute the absolute error for each sample. We extract input features (Question Length and Candidate Length) and calculate their Pearson correlation with the error magnitude to identify performance bottlenecks.
5.  **Submission**: With `Config.DEBUG` still False, the test data loader covers the entire test set. We run the inference pipeline to generate predictions and format them into the required CSV submission file.
