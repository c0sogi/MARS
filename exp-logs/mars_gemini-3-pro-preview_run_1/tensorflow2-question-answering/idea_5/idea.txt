### **Model: Question-Conditioned Bi-Directional GRU (QC-BiGRU)**

This approach utilizes **Recurrent Neural Networks (RNNs)**, a foundational architecture distinct from the Tree-based (Idea 1), Convolutional (Idea 2), Averaging (Idea 3), and Attention-based (Idea 4) approaches previously suggested. It prioritizes sequential understanding with a lightweight conditioning mechanism.

*   **Model Design:**
    *   **Question Aggregation:** The variable-length Question sequence is encoded into a single fixed-size dense vector using a simple aggregation operation (e.g., Max Pooling over pre-trained word embeddings).
    *   **Conditioned Sequential Encoding:** The Candidate text is processed by a **Bi-Directional Gated Recurrent Unit (Bi-GRU)**. Unlike standard RNNs that process inputs in isolation, this model concatenates the static **Question Vector** with the **Candidate Token Embedding** at *every* time step. This "conditioning" forces the RNN to process the text specifically through the lens of the question, filtering for relevance dynamically as it traverses the sequence.
    *   **Long Answer Classifier:** The final hidden states from both the forward and backward GRU passes are concatenated to form a global representation of the candidate. This vector is passed through a dense layer with sigmoid activation to predict the probability that the candidate is the correct answer.
    *   **Short Answer Tagger:** The full sequence of hidden states (one per token) is passed to a shared linear layer that outputs two logits for every token: the probability of being the **Start** of an answer and the probability of being the **End**.

### **Data**

*   **Preprocessing:**
    *   **Flattening:** The dataset is flattened so that each sample represents a single `(Question, Candidate)` pair.
    *   **Tokenization & Embedding:** Text is whitespace-tokenized and mapped to fixed, pre-trained word embeddings (e.g., GloVe) to avoid the cost of learning embeddings from scratch.
    *   **Truncation:** Candidate sequences are truncated to a fixed length (e.g., 256 tokens). This is critical for RNNs to prevent the computational bottleneck of processing extremely long sequences.
*   **Labeling:**
    *   **Long Answer:** A binary label (`1` or `0`).
    *   **Short Answer:** Two integer labels representing the indices of the start and end tokens. If no short answer exists, these are set to a specialized "ignore" index.

### **Training**

*   **Multi-Task Optimization:** The model is trained to minimize a combined loss function: **Binary Cross-Entropy** for the Long Answer classification and **Sparse Categorical Cross-Entropy** for the Short Answer span prediction.
*   **Class Balancing:** Given the sparsity of correct answers, **Negative Subsampling** is applied. The training set retains all positive candidates and a random sample (e.g., 20%) of negative candidates to ensure the model converges quickly.
*   **Optimizer:** The Adam optimizer is used with a standard learning rate.

### **Evaluation**

1.  **Inference:** Feed all test set candidates into the QC-BiGRU to generate Long Answer probabilities and Short Answer span logits.
2.  **Long Answer Selection:** For each example ID, identify the candidate with the highest Long Answer probability. If this probability is below a tuned threshold $\tau_{long}$, predict `NULL`.
3.  **Short Answer Extraction:** If a Long Answer is selected, calculate the score for all possible valid spans (where `Start Index` $\le$ `End Index`) by summing the corresponding start and end logits.
4.  **Final Prediction:** Select the span with the highest score. If this score exceeds a secondary threshold $\tau_{short}$, output the Short Answer indices (and YES/NO if the span corresponds to those tokens); otherwise, output only the Long Answer.
