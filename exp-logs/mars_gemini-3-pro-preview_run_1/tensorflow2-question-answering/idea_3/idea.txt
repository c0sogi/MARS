Based on the provided Model Architectures and the constraints for a high-efficiency baseline, here is the proposed solution.

### **Model: Deep Averaging Network with Token-Query Projection (DAN-TQP)**

This approach prioritizes speed by discarding the sequence-dependent operations of RNNs (Model 3) and the local feature extraction of CNNs (Model 2). Instead, it relies on **Global Average Pooling** to capture semantic composition for ranking and **Direct Token-Query Similarity** for extraction.

*   **Long Answer Ranker (Deep Averaging Network):**
    *   **Architecture:** A lightweight neural network that processes the Question and Candidate Text as "bags of words."
    *   **Encoding:** Input tokens are mapped to trainable word embeddings. The model computes the **mean (average) vector** across the sequence dimension for both the Question and the Candidate. This compresses variable-length text into two fixed-size dense vectors ($Q_{avg}$ and $C_{avg}$) instantly, without iterating through the sequence.
    *   **Interaction:** The relationship between the two is captured by constructing a feature vector consisting of the concatenation $[Q_{avg}; C_{avg}]$ and their element-wise product $Q_{avg} \odot C_{avg}$.
    *   **Classification:** This interaction vector is fed into a shallow Multi-Layer Perceptron (MLP) with ReLU activation to output a single probability score indicating if the candidate is the correct Long Answer.

*   **Short Answer Extractor (Token-Query Projection):**
    *   **Architecture:** A per-token classification layer that operates only on the candidate selected by the Ranker.
    *   **Mechanism:** Instead of processing the candidate text as a sequence, this module evaluates each token in isolation relative to the question. For every token embedding $T_i$ in the candidate, we concatenate it with the Question Mean Vector $Q_{avg}$.
    *   **Prediction:** This combined vector $[T_i; Q_{avg}]$ is passed through a shared Linear Layer that outputs logits for three classes: `Start Token`, `End Token`, or `Neither`. This effectively asks, "Is this specific word the start/end of the answer to this specific question topic?"

### **Data**

*   **Preprocessing:**
    *   **Tokenization & Vocabulary:** Use a simple whitespace tokenizer. Map tokens to a pre-initialized embedding matrix (e.g., GloVe) to jumpstart semantic understanding.
    *   **Flattening:** Flatten the dataset so each sample is a `(Question, Candidate)` pair.
    *   **Labeling:** Assign binary labels (`1`/`0`) for the Long Answer task. For the Short Answer task, map the ground truth start/end byte offsets to token indices within the candidate.
*   **Subsampling:** Apply aggressive negative subsampling (e.g., keeping only 10-20% of negative candidates) to balance the training distribution and reduce epoch time.

### **Training**

*   **Strategy:** Train the Long Answer Ranker and Short Answer Extractor simultaneously in a multi-task learning setup, or sequentially (Ranker first, then Extractor).
*   **Loss Functions:**
    *   **Ranker:** Use **Binary Cross-Entropy Loss** to optimize the identification of the correct Long Answer.
    *   **Extractor:** Use **Sparse Categorical Cross-Entropy Loss** applied to the per-token predictions (Start/End/Neither) for positive samples only.
*   **Optimization:** Use the Adam optimizer with a learning rate scheduler that decays upon plateauing validation loss.

### **Evaluation**

1.  **Inference:** For each sample in the test set, generate embeddings and compute $Q_{avg}$ and $C_{avg}$.
2.  **Ranking:** Pass the vectors through the **DAN MLP** to score all candidates. Select the candidate with the highest probability.
3.  **Long Answer Decision:** If the top score is below a threshold $\tau_{long}$, predict `NULL`. Otherwise, predict the candidate as the Long Answer.
4.  **Short Answer Extraction:** If a Long Answer is predicted, pass its token embeddings and $Q_{avg}$ through the **Token-Query Projection** layer.
5.  **Span Selection:** Identify the valid span (where `index(Start) < index(End)`) that maximizes the sum of the Start and End logits. If the confidence of this span is below a threshold $\tau_{short}$, predict a Long Answer only; otherwise, predict the Short Answer span.
