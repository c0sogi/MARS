Based on the provided model architectures and the requirement for a highly efficient baseline, here is the proposed solution.

### **Model: Context-Aware Lexical Gradient Boosting (CA-LGB)**

The architecture synthesizes the **ranking capability of Model 4 (GBDT)** with a simplified **contextual awareness conceptually derived from Model 3 (Bi-LSTM)**, but implemented via tabular features rather than recurrent neural networks to maintain high speed.

*   **Long Answer Classifier:** A **LightGBM** binary classifier is used to score each `long_answer_candidate` provided in the dataset. Unlike a standard ranker that treats candidates in isolation, this model incorporates **contextual features** (scores of neighboring candidates) to mimic the sequential understanding of neural models without the computational cost.
*   **Short Answer Extractor:** A deterministic **N-gram Overlap Heuristic** is used instead of a learned secondary model. This module scans the text of the predicted Long Answer to identify the sentence with the highest lexical overlap with the question, or assigns a YES/NO label if specific boolean indicators (e.g., "did", "was") are present in the question and answer text.

### **Data**

*   **Structure Flattening:** The hierarchical data (one document $\to$ many candidates) is flattened into a tabular format where each row represents a single `(Question, Candidate)` pair.
*   **Feature Engineering:**
    *   **Lexical Features:** Compute **TF-IDF Cosine Similarity**, **BM25 scores**, and **Jaccard Similarity** between the Question and the Candidate text.
    *   **Structural Features:** Extract metadata such as the candidate's HTML tag type (e.g., `<P>`, `<Table>`), span length, and normalized byte offset (position in document).
    *   **Contextual Features:** To capture local context, include the TF-IDF/BM25 scores of the **preceding** and **succeeding** candidates as features for the current candidate. This helps the model identify clusters of relevant information.
*   **Labeling:** For training, candidates are labeled `1` if they significantly overlap with the ground truth annotation bytes, and `0` otherwise.

### **Training**

*   **Class Balancing:** Since the vast majority of candidates are not answers, the training set is constructed using **Negative Subsampling**. All positive examples are kept, while negative examples are randomly sampled (e.g., at a 1:10 ratio) to reduce dataset size and training time.
*   **Optimization:** The LightGBM model is trained using **Binary Log-Loss** to output a probability score for each candidate.
*   **Validation:** A validation set grouped by `document_url` is used for **Early Stopping** to determine the optimal number of boosting rounds and to tune the decision threshold for the "No Answer" class.

### **Evaluation**

*   **Inference Pipeline:**
    1.  **Feature Generation:** Generate the lexical, structural, and contextual features for all candidates in the test set.
    2.  **Scoring:** Use the trained LightGBM model to predict the probability of each candidate being the Long Answer.
    3.  **Thresholding:** If the maximum probability for a document's candidates is below a tuned threshold $\tau$, predict `NULL` (No Answer). Otherwise, select the candidate with the highest probability as the **Long Answer**.
    4.  **Extraction:** Run the N-gram Overlap Heuristic on the selected Long Answer text to determine the **Short Answer** span (or YES/NO label).
    5.  **Formatting:** Convert the selected indices and text into the required submission format.
