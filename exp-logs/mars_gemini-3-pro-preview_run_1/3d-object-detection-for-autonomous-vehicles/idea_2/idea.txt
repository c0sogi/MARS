Based on the accumulated lessons, I propose a structural evolution of the baseline model: **DLA-34 (Deep Layer Aggregation) with Iterative Feature Fusion**.

This solution addresses the primary bottleneck identified in the lessons: the conflict between the need for a lightweight architecture to handle sparse data (Lesson 00003) and the need for high-resolution spatial features to achieve precise regression (Lesson 00004, Lesson 00007).

### Model
**Architecture: DLA-34 with Iterative Deep Aggregation**
Instead of the standard ResNet-18 Encoder-Decoder used previously, we will adopt **DLA-34** as the backbone.
*   **Structural Innovation:** Unlike ResNet, which aggregates features only at the end of blocks, DLA uses a tree-structured aggregation to fuse information across layers iteratively. This allows the network to preserve spatial resolution and low-level geometric cues (critical for the sparse BEV inputs) much better than a linear ResNet-34, while having a parameter count closer to the efficient ResNet-18 (Cite Lesson 00003).
*   **Feature Fusion:** We will implement **Iterative Deep Aggregation (IDA)** in the upsampling path. Instead of a simple sequence of upsampling layers, IDA aggregates features from the backbone's lower stages directly into the upsampling path. This ensures that the final feature map contains both the semantic strength of deep layers and the spatial precision of shallow layers, directly addressing the need for high-resolution refinement (Cite Lesson 00004) without the inefficient "upsample-process-downsample" sandwich structure (Cite Lesson 00008).
*   **Geometric Constraints:** The model's `forward` method will include an explicit interpolation step at the very end to ensure the output tensors exactly match the target grid size (e.g., 250x250), regardless of the backbone's natural stride. This encapsulates the geometric contract within the model (Cite Lesson 00015) and avoids the aliasing issues of resizing intermediate features (Cite Lesson 00013).

### Data
**Preprocessing: Robust BEV Rasterization**
*   **Input Representation:** We retain the **Rasterized BEV** approach (Max Height, Intensity, Density) as it is the proven efficient baseline for this task (Cite Lesson 00001).
*   **Pipeline Integrity:** The data loader will strictly enforce a "Load-Process-Convert" sequence. Geometric augmentations (flips, rotations) will be applied to the NumPy arrays *before* they are converted to PyTorch tensors to ensure alignment between images and bounding box targets (Cite Lesson 00005).
*   **Reproducibility:** We will implement a `worker_init_fn` in the DataLoader to uniquely seed the random number generator of each worker process, ensuring that multi-process data loading is deterministic and experimental results are reproducible (Cite Lesson 00010).

### Training
**Strategy: Precision-Focused Optimization**
*   **Loss Function:** We will use a multi-task loss where the weights for regression heads (dimensions, depth/Z, rotation) are set to **1.0**, equal to the heatmap classification weight. This forces the optimizer to prioritize geometric exactness, which is crucial for maximizing 3D IoU (Cite Lesson 00007).
*   **Schedule:** The training will run for a minimum of **25 epochs** using a OneCycle learning rate scheduler. This extended duration is necessary to allow the regression heads (which converge slower than classification) to fully optimize (Cite Lesson 00009).
*   **Early Stopping:** We will set the Early Stopping patience to **5 epochs** (or 20% of the total duration). This "loose" patience prevents the training from terminating prematurely during temporary loss plateaus, allowing the model to escape local minima in the noisy regression landscape (Cite Lesson 00014).

### Evaluation
**Inference: Standard CenterNet Decoding**
*   The evaluation process remains consistent with the baseline. We will generate heatmaps and regression maps, extract local peaks from the heatmap as object centers, and retrieve the corresponding 3D parameters from the regression maps.
*   Because the model now internally handles output resizing (Cite Lesson 00015), the inference script can decode the outputs directly without manual interpolation, reducing the risk of coordinate mismatch.
