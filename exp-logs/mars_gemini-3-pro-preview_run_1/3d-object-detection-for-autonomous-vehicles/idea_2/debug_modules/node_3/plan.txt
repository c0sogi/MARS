The issue is caused by the `BEVDataset` loading stale cached `.npy` files that were generated with a previous configuration (250x250 resolution) instead of the current configuration (256x256). The loader blindly trusts the cache existence without verifying if the data dimensions match the current requirements. To fix this, we will modify the `_get_bev_map` method in `library/dataset.py` to check the shape of the loaded array against the expected dimensions derived from `Config`. If there is a mismatch, the cache is ignored, and the data is recomputed. This applies the principle of invalidating caches when configurations change (Cite debug_lesson_3).
