The following strategy outlines the implementation of the metadata generation script:

1.  **Setup and Data Loading**:
    -   Define paths for input data (`./input`) and output metadata (`./metadata`).
    -   Load `train.csv` to identify training samples and their object annotations.
    -   Load `sample_submission.csv` to identify test samples.

2.  **File Path Mapping**:
    -   Parse `sample_data.json` from both `train_data` and `test_data` directories.
    -   Map each `sample_token` to its corresponding sensor files (Lidar and Camera).
    -   Construct full relative file paths (e.g., `./input/train_images/...`) based on the file extensions and the directory structure provided in the task description.

3.  **Annotation Aggregation**:
    -   Group the `train.csv` data by `Id` (sample token).
    -   Aggregate all bounding box annotations for each sample into a list of dictionaries (JSON format).

4.  **Dataset Splitting**:
    -   Load `sample.json` to map each `sample_token` to its `scene_token`.
    -   Perform a **Group Shuffle Split** on the training data using `scene_token` as the group. This ensures that frames from the same scene do not leak between training and validation sets.
    -   Split the data into 80% training and 20% validation using a fixed random state (42).

5.  **Metadata Generation**:
    -   Create `train.csv`, `val.csv`, and `test.csv` in the `./metadata` directory.
    -   Each file will contain the `sample_token`, `scene_token`, `lidar_path`, `image_paths` (list of camera images), and `annotations` (for train/val).

6.  **Validation**:
    -   Print summary statistics (sample counts).
    -   Verify that there is no overlap of `scene_token` between the training and validation sets.
    -   Randomly sample 1000 file paths from the generated metadata and verify their existence on the disk. Raise an error if the missing file ratio exceeds 0.5.
