The `AssertionError` in `runfile.py` occurs because the global depth normalization logic in `library/dataset.py` naively concatenates train, validation, and test depths. Since the test set metadata lacks depth information (resulting in `NaN` values), the calculation `all_depths.min()` returns `NaN`. This `NaN` value propagates during normalization `(train_depths - min) / denom`, causing all depth values in the training set to become `NaN`. The assertion `np.all(depth_channel == depth_channel[0, 0])` subsequently fails because `NaN == NaN` evaluates to `False` in Python.

To resolve this, I will modify `library/dataset.py` to check for `NaN` values in the depth data. If found, I will calculate the mean of the valid entries and impute this mean into the missing values for all splits before proceeding with min/max normalization. This ensures that the inputs to the model are valid numerical tensors, preventing the assertion failure and adhering to data validity contracts (Cite debug_lesson_6).
