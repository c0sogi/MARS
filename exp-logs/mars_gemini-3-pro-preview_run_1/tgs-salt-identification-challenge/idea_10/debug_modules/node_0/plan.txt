### Implementation Strategy

1.  **Setup and Configuration**: Initialize the environment by setting a fixed random seed for reproducibility. Define paths for a temporary working directory (`./working/demo_execution`) to store cache, checkpoints, and submission files, ensuring isolation from other runs.

2.  **Utility Verification**: Demonstrate the `rle_encode` and `rle_decode` functions from `library.utils` using a synthetic binary mask. Verify that encoding and subsequent decoding restores the original mask. Additionally, test the `do_kaggle_metric` function with synthetic ground truth and prediction arrays to confirm it calculates the mean Average Precision correctly.

3.  **Dataset and DataLoader Demonstration**: Use `library.dataset.get_loaders` with `debug=True` to quickly load a small subset of the training data. Verify the structure of the batches (image shape `[B, 2, 128, 128]` and mask shape `[B, 1, 128, 128]`) and ensure data types are correct (PyTorch tensors).

4.  **Model Architecture Verification**: Instantiate the `ClassificationGatedResUNet` from `library.model`. Pass a batch of data from the data loader through the model. Assert that the output is a dictionary containing the expected keys (`logits`, `cls`, `aux_32`, `aux_64`) and that the output tensors have the correct dimensions.

5.  **Loss Function Verification**: Initialize the `CompoundLoss` from `library.loss`. Calculate the loss using the model's output and the ground truth masks. Assert that the resulting loss is a valid scalar tensor.

6.  **Training Loop Demonstration**: Initialize the `Trainer` class from `library.train` with minimal hyperparameters (1 epoch, small batch size) and the debug flag enabled. Execute the `fit()` method to run a short training cycle. Verify that the training completes without error and that a model checkpoint (`best_model.pth`) is saved to the specified directory.

7.  **Inference and Submission Demonstration**: Call `predict_and_submit` from `library.inference` using the trained checkpoint. Verify that the function processes the test set (using the cached data) and generates a `submission.csv` file in the output directory. Check that the submission file contains the expected columns (`id`, `rle_mask`).
