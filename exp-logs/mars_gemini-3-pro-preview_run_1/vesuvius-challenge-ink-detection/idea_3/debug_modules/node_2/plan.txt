To address the `torch.OutOfMemoryError` caused by the high memory footprint of the 3D volumetric model, I will implement the following fixes:

1.  **Reduce Batch Size**: In `runfile.py`, I will decrease `Config.BATCH_SIZE` from 2 to 1. This directly halves the memory required for storing activations during the forward pass.
2.  **Clear Memory**: In `runfile.py`, I will explicitly delete the large tensors and model instance used during the verification steps (`dummy_input`, `output`, `model`) and call `torch.cuda.empty_cache()` before the training loop begins. This ensures that fragmented memory from the verification phase is released (Cite debug_lesson_1).
3.  **Enable Mixed Precision**: In `library/engine.py`, I will modify the `train_one_epoch` function to use `torch.amp.autocast` and `torch.amp.GradScaler`. This reduces the memory usage of activations by using 16-bit precision where appropriate.

def train_one_epoch(model, dataloader, criterion, optimizer, device):
    """
    Performs one epoch of training.
    """
    model.train()
    running_loss = 0.0
    num_batches = 0
    scaler = torch.amp.GradScaler('cuda')

    for batch in dataloader:
        images = batch["image"].to(device)
        masks = batch["mask"].to(device)

        # Zero the parameter gradients
        optimizer.zero_grad()

        # Forward pass
        with torch.amp.autocast('cuda'):
            outputs = model(images)
            loss = criterion(outputs, masks)

        # Backward pass and optimize
        scaler.scale(loss).backward()
        scaler.step(optimizer)
        scaler.update()

        running_loss += loss.item()
        num_batches += 1

    avg_loss = running_loss / num_batches if num_batches > 0 else 0.0
    return avg_loss
