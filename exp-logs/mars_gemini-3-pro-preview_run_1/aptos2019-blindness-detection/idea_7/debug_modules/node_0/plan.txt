The following strategy outlines the implementation of the demonstration script:

1.  **Setup and Configuration**: Initialize the environment by setting random seeds for reproducibility and suppressing unnecessary warnings to keep the output clean.
2.  **Component Verification (Unit Tests)**:
    *   **Metric**: Validate the `compute_score` function (Quadratic Weighted Kappa) using synthetic ground truth and prediction vectors to ensure it returns expected values (e.g., 1.0 for perfect agreement).
    *   **Dataset**: Instantiate the `RetinopathyDataset` using the pre-generated metadata. Retrieve a single sample to verify image tensor dimensions and the correctness of the ordinal target encoding (converting integer labels to binary vectors).
    *   **Data Loaders**: Use `get_dataloaders` to create training and validation loaders. Fetch a single batch to confirm batch dimensions and data types.
    *   **Model**: Instantiate the `RetinopathyModel`. Perform a forward pass with a dummy input tensor to verify that the architecture (Backbone + GeM Pooling + Head) produces the correct output shape `(Batch_Size, 4)`.
3.  **End-to-End Execution (Integration Test)**:
    *   Execute the `run_training` function from the engine.
    *   Use reduced parameters (1 epoch, smaller image size, small batch size) to ensure the training and inference pipeline completes quickly (well within the 1-hour limit) while still exercising all code paths including backpropagation, validation, checkpoint saving, and TTA inference.
4.  **Output Validation**:
    *   After the run, verify that the expected output files (`best_model.pth` and `submission.csv`) exist in the working directory.
    *   Load the generated `submission.csv` to ensure it adheres to the required format (`id_code`, `diagnosis`) and value range.
