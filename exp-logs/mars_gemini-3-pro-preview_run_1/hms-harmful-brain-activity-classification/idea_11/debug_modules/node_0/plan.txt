### Implementation Strategy

1.  **Configuration Override**: We will modify the `Config` class attributes directly to adapt the execution for a quick demonstration. This includes enabling `DEBUG` mode to use a small subset of data, reducing `EPOCHS` to 1, setting a small `BATCH_SIZE`, and disabling multiprocessing (`NUM_WORKERS = 0`) to avoid overhead.
2.  **Data Pipeline Verification**: We will instantiate the `BrainDataset` and `DataLoader` manually to verify that data loading, preprocessing (EEG downsampling, Spectrogram resizing), and batching work correctly. We will assert the shapes of the output tensors.
3.  **Model Logic Verification**: We will instantiate the `BidirectionalFusionNet`, pass a batch of dummy data (matching the shapes verified in the previous step) through it, and assert that the output logits have the expected shape `(Batch, Num_Classes)`.
4.  **Metric Verification**: We will test the `kl_divergence_score` function with known probability distributions to ensure it calculates the metric correctly.
5.  **Full Integration Test**: We will execute the `train_model` function from the library. This function orchestrates the entire pipeline (training, validation, and submission generation). Since we modified the `Config` globally, this will run a fast "dry run" of the training loop.
6.  **Output Verification**: Finally, we will check if the submission file was generated successfully.
