The issue stems from the `InceptionBlock1D` implementation, which calculates the number of filters per branch using integer division (`out_channels // num_branches`). When the requested `out_channels` (e.g., 64) is not perfectly divisible by the number of branches (5), the actual total output channels (e.g., 60) differ from the requested amount. The `Siamese1DEncoder` currently hardcodes the input channels for subsequent blocks based on the requested `base_filters` rather than the actual output dimensions of the previous block, causing a shape mismatch. The fix involves dynamically chaining the blocks by using the `final_channels` attribute of the preceding block to define the `in_channels` of the next block.
