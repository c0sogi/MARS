The implementation strategy follows the requirements to establish a fast but robust baseline using the Tri-View Hierarchical Fusion Network.

1.  **Configuration Override**: We dynamically update the `Config` class to optimize for the available A100 GPU and time constraints. We increase the `BATCH_SIZE` to 64 to maximize GPU utilization and set `EPOCHS` to 2. This ensures the model sees the entire dataset twice, which, combined with the OneCycleLR scheduler, is sufficient for a competitive baseline within the 2-hour limit.
2.  **Training**: We invoke the `train` function with `debug=False` to use the full training dataset (approx. 80k samples) and `load_cached_data=True` to speed up data loading.
3.  **Validation & Metric Calculation**: After training, we load the saved best checkpoint. We iterate through the full validation set using a dedicated `DataLoader` to collect predictions and targets. We then compute the Kullback-Leibler Divergence on the entire set to report the `Final Validation Metric` with high precision.
4.  **Failure Analysis**: We calculate the KL divergence for each individual sample in the validation set. We then merge these error values with the validation metadata to calculate Pearson correlations between the model's error and temporal metadata features (EEG and Spectrogram offsets), identifying potential biases.
5.  **Conditional Submission**: We compare the final validation metric against the strict threshold of `0.7327804565429688`. If the model performs better (lower score), we trigger the `inference` module to generate predictions on the test set and save the `submission.csv`.
