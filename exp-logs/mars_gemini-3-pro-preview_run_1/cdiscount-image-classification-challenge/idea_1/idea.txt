To establish a robust and efficient baseline for this product categorization task, I propose a **Multi-View ResNet-18 with Max-Pooling Aggregation**. This approach prioritizes high throughput and architectural simplicity, avoiding the computational overhead of attention mechanisms or heavy transformer models while effectively handling the variable number of images per product.

### Model
The architecture is designed as a **Siamese Convolutional Neural Network** using a shared **ResNet-18** backbone.
*   **Backbone:** A standard ResNet-18 (pre-trained on ImageNet) serves as the feature extractor. It is lightweight and significantly faster than larger variants like ResNet-50 or EfficientNet, making it ideal for a time-constrained baseline.
*   **Input Processing:** For a given product with $N$ images (where $1 \le N \le 4$), each image is passed independently through the shared backbone to produce a feature vector of size 512.
*   **Aggregation:** Instead of the Mean-Pooling suggested in Model 1 or the Attention mechanism in Model 3, this model uses **Global Max-Pooling** across the $N$ image vectors. Max-pooling is computationally negligible and operates on the hypothesis that the most discriminative feature for classification (e.g., a logo, a specific texture, or text) may appear clearly in only one of the provided images. By taking the maximum activation for each feature dimension, the model captures the strongest signal present in any of the views.
*   **Classifier:** The aggregated 512-dimensional vector is fed into a single fully connected layer (linear projection) that outputs the logits for the 5,270 categories.

### Data
*   **Preprocessing:** The raw BSON data will be decoded, and images will be converted to RGB tensors. Since the images are already 180x180, no resizing is required. Pixel values will be normalized using standard ImageNet mean and standard deviation.
*   **Augmentation:** To maintain speed, data augmentation will be minimal, consisting only of random horizontal flips during training.
*   **Batching Strategy:** To handle the variable number of images efficiently on the GPU, the data loader will flatten the batch. For a batch of $B$ products, the loader will produce a tensor of $\sum N_i$ images and a corresponding index vector mapping each image back to its product ID. The backbone processes the flattened image batch in parallel, and the max-pooling operation uses the index vector to aggregate results, avoiding the need for padding or fixed-size tensor constraints.

### Training
*   **Loss Function:** Standard **Cross-Entropy Loss** will be used.
*   **Optimizer:** The **Adam** optimizer will be employed for its ability to converge quickly without extensive hyperparameter tuning.
*   **Scheduler:** A **OneCycleLR** learning rate scheduler will be used. This technique allows for super-convergence, enabling the model to reach a competitive accuracy in fewer epochs compared to constant or stepped learning rates.
*   **Precision:** Mixed-precision training (FP16) will be utilized to reduce memory usage and increase training speed on the A100 GPU.

### Evaluation
*   **Inference:** The test set will be processed using the same pipeline: images for each product are extracted, normalized, and passed through the backbone. The feature vectors are max-pooled, and the category with the highest logit value is selected as the prediction.
*   **Submission:** The resulting product IDs and predicted category IDs will be written to a CSV file in the required format.
