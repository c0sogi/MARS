To establish a robust and efficient baseline, I propose a **Bidirectional GRU with Concatenated Pooling** architecture. This approach synthesizes the sequential modeling strengths of RNNs (like Model 3) with the efficient feature aggregation of pooling (like Model 2), while stripping away the computational overhead of attention mechanisms or heavy transformers. It is designed to be significantly faster than LSTM-based models and more context-aware than simple linear baselines.

### Model
The architecture consists of the following streamlined layers:
1.  **Embedding Layer**: The input integer sequences are fed into a trainable embedding layer initialized with pre-trained word vectors (e.g., GloVe or FastText). This allows the model to leverage semantic relationships immediately.
2.  **Spatial Dropout**: A Spatial Dropout layer is applied to the embeddings. Unlike standard dropout, this drops entire feature maps (embedding dimensions) across the sequence, effectively preventing the model from over-relying on specific embedding dimensions and improving generalization.
3.  **Bidirectional GRU**: The core layer is a Bidirectional Gated Recurrent Unit (GRU). GRUs are computationally more efficient than LSTMs (fewer gates) but still capture long-range dependencies. The bidirectional nature ensures the model considers context from both the start and end of the comment.
4.  **Concatenated Pooling**: Instead of a complex attention mechanism, the model employs a dual pooling strategy. We compute both **Global Average Pooling** (to capture the general sentiment/topic of the comment) and **Global Max Pooling** (to extract the strongest signal of toxicity, such as a single slur). These two vectors are concatenated to form a comprehensive sentence representation.
5.  **Classification Head**: The concatenated vector is passed through a fully connected (Dense) layer with ReLU activation and Dropout, followed by a final output Dense layer with 6 units and sigmoid activation to predict the probability for each toxicity class.

### Data
1.  **Tokenization & Cleaning**: The text will be converted to lowercase. A tokenizer will be fitted on the training corpus to convert words to integers, keeping the top $N$ (e.g., 100,000) most frequent words.
2.  **Sequence Padding**: Comments will be padded or truncated to a fixed length (e.g., 200 tokens). This length is sufficient to capture the majority of toxic content while keeping memory usage low.
3.  **Embedding Matrix**: A weight matrix will be constructed mapping the tokenizer's vocabulary to pre-trained word vectors. Words not found in the pre-trained set will be initialized with random normal values.

### Training
1.  **Loss Function**: Binary Cross-Entropy (BCE) will be used as the loss function, treating the problem as 6 independent binary classification tasks.
2.  **Optimizer**: The Adam optimizer will be employed for its adaptive learning rate capabilities, ensuring fast convergence.
3.  **Routine**: The model will be trained for a small number of epochs (e.g., 3-5) with a batch size optimized for the A100 GPU (e.g., 128 or 256).
4.  **Regularization**: Early stopping monitoring the validation ROC AUC will be used to halt training if performance degrades, ensuring the best version of the model is retained.

### Evaluation
1.  **Inference**: The trained model will process the test set using the same tokenization and padding logic as the training set.
2.  **Prediction**: The model will output 6 probabilities for each comment in the test set.
3.  **Submission**: These probabilities will be formatted into a CSV file with the required header and column order (`id, toxic, severe_toxic, obscene, threat, insult, identity_hate`) for submission.
