To resolve the `torch.OutOfMemoryError` caused by the large batch size relative to the available VRAM, I will implement **Gradient Accumulation** (Cite debug_lesson_5). This technique decouples the physical micro-batch size (which must fit in VRAM) from the effective training batch size (which determines convergence behavior).

The changes involve:
1.  **`library/engine.py`**: Modifying `train_mlm` and `train_fn` to accept a `gradient_accumulation_steps` parameter. The loss will be scaled by this factor, and the optimizer/scheduler steps (including AWP) will only execute once every `gradient_accumulation_steps` batches.
2.  **`runfile.py`**: Configuring a safe `MICRO_BATCH_SIZE` of 8 and calculating the necessary `ACCUM_STEPS` to maintain the target batch size of 32. The `Config.train_batch_size` will be updated to the micro-batch size, and the `total_steps` for the schedulers will be adjusted to account for the reduced number of updates.

        outputs = model(input_ids, attention_mask)
        main_logits = outputs["main_logits"]
        aux_logits = outputs["aux_logits"]

        # --- Loss Calculation ---

        # Deep Supervision Logic
        if Config.use_deep_supervision:

            loss = loss_main + Config.aux_loss_weight * loss_aux
