The previous implementation caused a `RuntimeError` because it used `-1e9` as a masking constant for padding tokens. In Mixed Precision training (FP16), this value exceeds the minimum representable limit of `float16` (approximately -65,504), causing an overflow when PyTorch attempts to cast it. To fix this, I will replace `-1e9` with `-1e4` (negative ten thousand), which is sufficiently small to ensure the Softmax function outputs zero for masked tokens while remaining safely within the bounds of `float16` Cite debug_lesson_8.
