The issue is that the code uses a hardcoded constant `-1e9` to mask padding tokens in the attention mechanism and max pooling operations. When running with Automatic Mixed Precision (AMP), tensors are cast to `float16`, which has a minimum value of approximately -65,504. Since `-1e9` is far smaller than this limit, attempting to assign it to a `float16` tensor causes an overflow error (Cite debug_lesson_1). To fix this, I will replace `-1e9` with `-1e4` (i.e., -10,000), which is small enough to function as negative infinity for Softmax and Max Pooling purposes but fits safely within the `float16` range.
