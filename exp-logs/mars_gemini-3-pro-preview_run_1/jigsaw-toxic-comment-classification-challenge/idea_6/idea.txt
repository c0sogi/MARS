# Context-Aware DeBERTa-v3-Base with Dynamic Layer Aggregation

## Model
I propose a structural evolution that synthesizes the architectural strengths of **DeBERTa-v3** with a **Dynamic Layer Aggregation** mechanism, optimized for the specific lexical challenges of toxicity detection.

1.  **Backbone (Structural Optimization):** We will utilize **DeBERTa-v3-base** as the core feature extractor.
    *   **Why DeBERTa?** Transformers significantly outperform RNNs in this domain due to pre-trained semantic knowledge (Cite solution_lesson_node_00007). DeBERTa-v3 improves on RoBERTa by using disentangled attention, which is critical for understanding the context of toxic words.
    *   **Why Base?** We explicitly choose the "Base" variant over "Large". Previous experiments demonstrated that while "Large" models are theoretically more powerful, they force data subsampling to meet time constraints, leading to inferior performance compared to a "Base" model trained on the full dataset (Cite solution_lesson_node_00014). The "Base" model allows us to utilize 100% of the training data within the 24-hour limit.

2.  **Dynamic Layer Aggregation (Structural Innovation):** Instead of relying solely on the final hidden state, we will implement a **learnable weighted sum of the last 4 encoder layers**.
    *   **Rationale:** Toxicity detection often relies on specific vocabulary (slang, profanity) captured in lower layers, while semantic context resides in higher layers. Lesson 00009 showed that dampening lower layers (via LLRD) hurts performance because those layers need to adapt. By aggregating the last 4 layers, we provide the classification head with direct access to these critical lexical features alongside the high-level semantics, without the optimization penalties of LLRD (Cite solution_lesson_node_00009).

3.  **Hybrid Pooling Head (Strategic Retention):** We will apply the proven hybrid pooling strategy to the aggregated representation:
    *   **Global Max Pooling:** To extract the strongest local signal (e.g., a specific slur) regardless of its position (Cite solution_lesson_node_00001).
    *   **Linear Attention Pooling:** To compute a context-aware weighted average, prioritizing relevant tokens while filtering noise (Cite solution_lesson_node_00002). We will use simple **Linear Attention** ($w^T h_t$) to avoid the convergence issues of complex additive attention (Cite solution_lesson_node_00003).
    *   These two vectors will be concatenated.

4.  **Multi-Sample Dropout:** The concatenated vector will pass through 5 parallel dropout masks. The outputs will be fed to a shared dense layer, and the logits will be averaged. This acts as an internal ensemble to smooth the loss landscape.

## Data
1.  **Tokenization:** We will use the **DeBERTa-v3 Tokenizer** (SentencePiece). This is critical as it preserves punctuation and special characters (e.g., "!!", "f**k") as distinct tokens, which are high-signal features for toxicity that are lost with standard alphanumeric cleaning (Cite solution_lesson_node_00004).
2.  **Preprocessing:** We will use the **Full Training Dataset**. Input sequences will be padded/truncated to a fixed length (e.g., 300 tokens), which balances context retention with memory efficiency.

## Training
1.  **Optimization Strategy:** We will use the **AdamW** optimizer with a **Uniform Learning Rate** across all layers. We will explicitly **reject Layer-wise Learning Rate Decay (LLRD)**. Since we are using Layer Aggregation to access lower-level features, we must allow those layers to update at the full learning rate to adapt to the specific toxic vocabulary of the dataset (Cite solution_lesson_node_00009).
2.  **Scheduling:** We will employ a **OneCycleLR** scheduler with a training duration of **4 to 5 epochs**. This ensures the learning rate decay is gradual, avoiding the performance degradation and premature convergence associated with compressed schedules (Cite solution_lesson_node_00006).
3.  **Loss Function:** Binary Cross-Entropy (BCE) with Logits, computed on the averaged logits from the Multi-Sample Dropout.

## Evaluation
The evaluation pipeline remains consistent. Test set comments will be tokenized using the DeBERTa-v3 tokenizer. For each comment, the model will output the probability for each of the six toxicity classes (averaged across the Multi-Sample Dropout heads). These probabilities will be formatted into the required submission CSV.
