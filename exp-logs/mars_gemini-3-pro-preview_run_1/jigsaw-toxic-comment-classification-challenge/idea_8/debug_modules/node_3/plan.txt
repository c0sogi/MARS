The issue is that `sklearn.model_selection.KFold` requires `n_splits` to be at least 2 to create a train/validation split, but `runfile.py` sets `Config.n_folds = 1`. While the intention was to execute only a single fold for the demo, this configuration parameter initializes the K-Fold splitter itself, which mathematically requires multiple partitions. The fix is to set `Config.n_folds` to a valid integer (e.g., 5) in `runfile.py`. The demo logic already manually restricts execution to just `fold = 0`, so increasing the split count defines a valid cross-validation scheme without forcing the code to run all folds.
