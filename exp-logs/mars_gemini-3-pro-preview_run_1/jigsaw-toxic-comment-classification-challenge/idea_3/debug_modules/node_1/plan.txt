The `RuntimeError: value cannot be converted to type at::Half without overflow` occurs because the hardcoded value `-1e9` (negative one billion) is outside the range of IEEE 754 half-precision floating-point numbers (FP16), which has a minimum finite value of approximately -65,504. When mixed-precision training (`autocast`) is enabled, PyTorch attempts to cast this scalar to FP16, causing the overflow.

To fix this, I will replace `-1e9` with `-1e4` (-10,000) in `library/model.py`. This value is safely within the FP16 range while remaining small enough to effectively serve as negative infinity for Softmax and Max Pooling operations.

Additionally, I will apply the guidance from `debug_lesson_1` to `library/engine.py`. I will add a check to slice the `test_meta` DataFrame when `config.debug` is enabled, ensuring that the submission file generation does not fail due to a length mismatch between the predicted probabilities (subset) and the metadata IDs (full set).
