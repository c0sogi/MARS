This implementation strategy focuses on demonstrating the complete pipeline—from data loading to submission generation—while strictly adhering to the time and resource constraints.

### Strategy Outline

1.  **Configuration for Speed**: We will modify the `Config` class attributes at runtime to enable `DEBUG` mode. This limits the dataset to 2,000 samples. We will also reduce `MAX_LEN` to 64 and `EPOCHS` to 1 to ensure the script completes execution within a few minutes.
2.  **Data Loading**: We will utilize `get_dataloaders` and `get_test_dataloader` from `library.dataset`. We explicitly set `load_cached_data=False` to force the preprocessing logic to run on the reduced debug dataset, ensuring that the shapes of our data match our assertions.
3.  **Model Instantiation & Verification**: We will initialize the `ToxicityRoBERTa` model and perform a dummy forward pass with a single batch from the training loader. We will assert that the output logits have the correct shape `(batch_size, num_labels)`.
4.  **Training Loop**: We will execute the `run_training` function from `library.engine`. This handles the training epoch, validation, and model saving. We will verify that the model weights are saved to the expected location.
5.  **Inference & Submission**: We will load the best saved model and generate predictions on the test set using `predict`. Finally, we will align these predictions with the corresponding IDs (accounting for the debug slicing) and generate a valid `submission.csv`.
