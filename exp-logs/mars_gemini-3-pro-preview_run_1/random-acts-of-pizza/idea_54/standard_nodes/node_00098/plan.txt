The implementation strategy follows the Hybrid Ensemble architecture described in the idea.

1.  **Initialization**: We set the random seed for reproducibility and define necessary paths using the provided config.
2.  **Data Loading**: We use `load_dataset` to retrieve the training, validation, and test dataframes, leveraging caching where possible.
3.  **Feature Engineering**: We utilize the `FeatureProcessor` class to generate two distinct feature sets:
    *   **Stream A (RF)**: A concatenation of TF-IDF vectors, scaled metadata, binary community flags, and explicit interaction terms.
    *   **Stream B (MLP)**: A structured dictionary separating Semantic embeddings (SBERT + Consistency), Reliability metrics (Metadata), and Community signals (Flags) for the topology-aware network.
4.  **Model Training**:
    *   **Random Forest**: Trained on the Stream A features.
    *   **Topology-Aware MLP**: Trained on the Stream B features using the custom `PizzaDataset` and `TopologyAwareMLP` class, with early stopping based on validation AUC.
5.  **Ensemble & Evaluation**: We compute the simple weighted average of the probability predictions from both models. We calculate the final AUC on the validation set.
6.  **Failure Analysis**: We compute the absolute error of the ensemble predictions on the validation set and correlate these errors with key numerical metadata features to identify systematic weaknesses.
7.  **Submission**: If the validation AUC exceeds the specified threshold, we generate the `submission.csv` file using the test set predictions.
