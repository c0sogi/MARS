The issue is caused by the early binding of the `SUBMISSION_PATH` variable in `library/trainer.py`. Because `SUBMISSION_PATH` is imported directly using `from library.config import ...`, it retains the value it had at import time (the default path). When `runfile.py` subsequently updates `config.SUBMISSION_PATH` to point to the demo directory, `trainer.py` remains unaware of this change and saves the file to the original location.

To fix this, I will modify `library/trainer.py` to import the entire `config` module instead of the specific `SUBMISSION_PATH` variable. I will then update the `run_training_pipeline` function to access `config.SUBMISSION_PATH` dynamically at runtime. This ensures the function uses the most current path value, resolving the `AssertionError` (Cite debug_lesson_3).
