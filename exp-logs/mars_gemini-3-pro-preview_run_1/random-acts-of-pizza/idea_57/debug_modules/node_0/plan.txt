Implementation Strategy:
1.  **Configuration & Setup**: Initialize the environment and set random seeds using the provided `utils` module. We will override the `CACHE_DIR` in the `config` module to a temporary demo directory. This ensures that the feature engineering pipeline runs on our specific data subset rather than loading potentially pre-existing full-dataset caches, and prevents overwriting any production caches.
2.  **Data Loading**: Use `data_loader.load_dataset` to retrieve the training, validation, and test DataFrames.
3.  **Data Subsampling**: To ensure the demonstration runs quickly (optimizing for speed as requested), we will slice the DataFrames to a small subset (e.g., 50 samples each). This allows us to verify the entire pipeline logic (SBERT encoding, TF-IDF, model training) without waiting for extensive computation.
4.  **Feature Engineering**: Instantiate the `FeatureEngineer` class and run `process_data` on the subsets. This demonstrates the generation of both Stream A (Random Forest) and Stream B (MLP) feature sets.
5.  **Stream A (Random Forest)**:
    *   Train the RF model using `model_rf.train_rf_model` with reduced estimators (e.g., 10) for speed.
    *   Generate predictions on the test set.
    *   Validate that predictions are within the [0, 1] range.
6.  **Stream B (MLP)**:
    *   Train the MLP model using `model_mlp.train_mlp_model`. We will pass a custom `params` dictionary to limit the number of epochs to 2, ensuring a quick training loop.
    *   Generate predictions on the test set.
    *   Validate output shapes and value ranges.
7.  **Ensemble & Submission**:
    *   Compute a weighted average of the RF and MLP predictions.
    *   Construct a submission DataFrame.
    *   Use `utils.verify_submission_format` to confirm the output meets the competition requirements.
8.  **Cleanup**: Save the resulting submission to the designated output path.
