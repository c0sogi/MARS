The pipeline is suffering from data leakage because features ending in `_at_retrieval` (e.g., `number_of_upvotes_of_request_at_retrieval`) are included in the training set. These features represent future information collected at the time of dataset creation, which is unavailable for prediction in a real-world scenario (and zeroed out in the test set). To fix this, I will update `get_tabular_features` in `library/config.py` to explicitly filter out any column ending with `_at_retrieval`. Furthermore, I will modify `runfile.py` to set `load_cached_data=False` when calling `process_data`. This forces the pipeline to ignore the existing cache (which contains the leaked features) and recompute the dataset from scratch, ensuring the new feature selection logic is applied.
