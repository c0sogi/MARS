Here is the implementation strategy and the complete `runfile.py` script.

### Implementation Strategy

1.  **Initialization**: Set random seeds for reproducibility using the provided `utils` module.
2.  **Feature Engineering**: Instantiate and run the `FeaturePipeline` from `library.feature_engineering`. This handles data loading, cleaning, text embedding (SBERT), topic modeling (K-Means), and metadata engineering. It returns processed dictionaries for train, validation, and test sets containing features for both Stream A (RF) and Stream B (MLP).
3.  **Stream A (Random Forest) Training**:
    - Initialize `StreamARandomForest` from `library.models`.
    - Train the model using the sparse TF-IDF and dense metadata features from the training set.
    - Generate probability predictions for the validation set.
4.  **Stream B (Context-Gated MLP) Training**:
    - Initialize `MLPTrainer` from `library.models`.
    - Train the neural network using the multi-modal dictionary (Request Embeddings, History Tensor, Metadata). The trainer handles the PyTorch `DataLoader` creation and training loop with early stopping.
    - Generate probability predictions for the validation set.
5.  **Ensemble & Evaluation**:
    - Compute the final validation predictions using a simple weighted average (0.5/0.5) of Stream A and Stream B outputs.
    - Calculate the Area Under the ROC Curve (AUC) using `utils.compute_score`.
    - **Crucial**: Print the `Final Validation Metric` in the required format.
6.  **Failure Analysis**:
    - Calculate the absolute prediction error for each validation sample.
    - Compute the Pearson correlation between this error and the numerical metadata features (from Stream B's normalized input) to identify which features correlate with model failure.
    - Print the top correlations.
7.  **Submission Generation**:
    - Check if the validation AUC exceeds the threshold (0.6959737721862433).
    - If successful, generate predictions for the test set using both trained models.
    - Combine predictions, format the output dataframe with `request_id` and `requester_received_pizza`, and save to `./submission/submission.csv`.
