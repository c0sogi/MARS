The issue is caused by the pipeline loading stale cache files containing a small debug subset (50 samples) instead of the full dataset (2302 samples), despite `config.DEBUG` being set to `False`. This happens because the data loading functions check for the existence of cache files but fail to verify if the cached data matches the current run configuration (e.g., dataset size). This leads to training on insufficient data and subsequent validation errors due to dimension mismatches.

To fix this, I will implement cache validation logic in `library/data_loader.py`, `library/feature_engineering.py`, `library/model_rf.py`, and `library/model_mlp.py`. Specifically, I will check if the loaded cache dimensions match the expected full dataset size (or the current dataframe size) when `DEBUG` is `False`. If a mismatch is detected (indicating a stale debug cache), the system will invalidate the cache and reload/reprocess the data from scratch. This applies the principle from `debug_lesson_1`: "Invalidate Stale Caches When Changing Data Configuration."
