Based on the lessons learned, I propose the **Contextualized Anchor-Attention Network (CAAN)**. This solution retains the highly effective anchor-based classification and soft-ranking strategies but introduces a structural innovation to capture the *sequential flow* of the notebook, which was previously ignored by treating code anchors as an unordered bag of keys.

### Model
The architecture evolves from a static matching network to a sequence-aware attention mechanism.

1.  **Frozen Backbone:** We utilize the `sentence-transformers/all-MiniLM-L6-v2` model to generate fixed, pre-computed embeddings for all code and markdown cells. This ensures high throughput and respects the computational budget.
2.  **Symmetric Projection Towers:** We employ two separate, learnable MLP projection heads (one for Code, one for Markdown) to map the 384-dimensional backbone embeddings into a shared **512-dimensional latent space**. This symmetric design is critical for aligning the heterogeneous modalities **Cite solution_lesson_node_00003**. We maintain the 512-dimensional width to ensure sufficient capacity for geometric alignment **Cite solution_lesson_node_00004**.
3.  **Contextual Anchor Encoder (Structural Innovation):**
    *   Instead of using the projected code embeddings directly as static keys, we feed the **ordered sequence of Code embeddings** (for a given notebook) into a lightweight **Transformer Encoder** (e.g., 2 layers, 4 heads).
    *   We append a learnable "End-of-Notebook" token to the end of this sequence and add **Sinusoidal Positional Encodings**.
    *   **Purpose:** This allows the code anchors to attend to each other. The model can now distinguish between semantically identical code cells (e.g., `plt.show()`) based on their position in the execution flow (e.g., distinguishing a plot in the EDA section from a plot in the Evaluation section).
4.  **Attention Classification Head:**
    *   The projected Markdown embeddings (Queries) compute dot-product attention scores against the **Contextualized Code embeddings** (Keys) output by the Transformer Encoder.
    *   A Softmax is applied to produce a probability distribution over the possible positions (the code anchors).

### Data
1.  **Preprocessing:** We perform a one-time pass over the entire dataset using the frozen backbone to generate and cache embeddings for all cells.
2.  **Input Construction:** For each training step, the input consists of:
    *   A batch of shuffled Markdown embeddings (Queries).
    *   The corresponding ordered sequence of Code embeddings (Anchors).
3.  **Labeling:** Each markdown cell is assigned a target class label corresponding to the 0-based index of the code cell that immediately follows it (or the index of the "End-of-Notebook" token). We do **not** generate pairwise labels, relying instead on the global anchor structure **Cite solution_lesson_node_00008**.

### Training
1.  **Objective Function:** We use standard **Cross-Entropy Loss**.
2.  **Optimization:** We use the Adam optimizer with a **constant learning rate of 1e-3**. We explicitly **exclude warmup schedules and label smoothing**, as these were found to hinder convergence when training adapters on frozen features **Cite solution_lesson_node_00006**.
3.  **Batching:** We use a batch size of **64 notebooks**. This ensures a high frequency of gradient updates, which is vital for training the projection heads and the new encoder effectively **Cite solution_lesson_node_00004**.

### Evaluation
1.  **Inference:** For a test notebook, we generate the probability distribution for each markdown cell across the contextualized code anchors.
2.  **Soft Ranking:** We compute the **Expected Index** ($ \sum_{i} P_i \times i $) for each markdown cell. This maps the discrete classification outputs to a continuous ranking score, effectively handling local ordering ambiguities without explicit pairwise refinement **Cite solution_lesson_node_00008**.
3.  **Ordering:** The final `cell_order` is produced by sorting the markdown cells based on their Expected Index values and interleaving them into the fixed code sequence.
