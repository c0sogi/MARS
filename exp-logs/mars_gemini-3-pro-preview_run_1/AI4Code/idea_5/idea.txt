Based on the comprehensive analysis of the accumulated lessons, I propose the **Dual-Context Anchor Network (DC-AN)** powered by a **Similarity-Tuned MPNet Backbone**.

This solution synthesizes the structural success of the *Contextualized Anchor-Attention Network* (Idea 3) with the theoretical advancements of *Dual-Context* modeling (Idea 4), while correcting the critical backbone and data-scaling mistakes that caused Idea 4 to fail.

# Model

The architecture is a symmetric, dual-stream network designed to align a set of permutation-invariant markdown queries against a sequence of fixed code anchors.

1.  **Backbone Upgrade (`all-mpnet-base-v2`):**
    *   We replace the lightweight `MiniLM` (used in Idea 3) and the generic `CodeBERT` (used in Idea 4) with **`sentence-transformers/all-mpnet-base-v2`**.
    *   **Rationale:** Lesson 00017 established that similarity-tuned backbones are essential for dot-product ranking tasks, explaining why CodeBERT failed. However, Lesson 00020 highlighted that data coverage is paramount. MPNet represents the optimal "Pareto frontier": it is significantly more powerful than MiniLM (SOTA for semantic search) but, unlike CodeBERT, is pre-tuned for similarity and efficient enough to process the **full dataset** within the 24-hour limit (unlike the generative LLMs).
    *   **Mechanism:** The backbone is **frozen** to allow pre-computation and aggressive adapter training **Cite solution_lesson_node_00006**.

2.  **Symmetric Projection Towers:**
    *   We employ two distinct MLP projection heads to map the 768-dimensional MPNet embeddings of Code and Markdown cells into a shared **512-dimensional latent space**.
    *   **Rationale:** This symmetric design is retained to geometrically align the heterogeneous manifolds of code and text **Cite solution_lesson_node_00003**.

3.  **Code Branch (Sequential Anchor Context):**
    *   The ordered sequence of projected Code embeddings is processed by a **Transformer Encoder with Sinusoidal Positional Encodings**.
    *   **Rationale:** This creates a "Contextualized Skeleton" of the notebook, allowing the model to distinguish identical code snippets based on their execution flow **Cite solution_lesson_node_00013**.

4.  **Markdown Branch (Set-Aware Query Context - Structural Innovation):**
    *   We introduce a **Permutation-Invariant Set Transformer** (a Transformer Encoder *without* positional embeddings) to process the bag of shuffled Markdown embeddings.
    *   **Rationale:** Previous successful iterations (Idea 3) treated Markdown cells as independent queries. By allowing Markdown cells to attend to each other via a Set Transformer, the model generates "Contextualized Queries." A cell containing "Model Evaluation" can now adjust its representation based on the presence (or absence) of a "Data Loading" cell in the same set, resolving ambiguities that the Code skeleton alone cannot address. This fixes the flaw in Idea 4 (which attempted this but failed due to data starvation) by pairing it with a feasible backbone.

5.  **Interaction Head:**
    *   We compute the dot-product attention between the **Contextualized Markdown Set** (Queries) and the **Contextualized Code Sequence** (Keys).
    *   A Softmax over the code positions produces the placement probabilities.

# Data

1.  **Full Dataset Pre-computation:**
    *   We will run the frozen `all-mpnet-base-v2` model over the **entire training dataset (~140k notebooks)** to extract and cache embeddings.
    *   **Rationale:** Lesson 00014 and Lesson 00020 proved that maximizing data volume is the primary driver of performance. Pre-computing embeddings allows us to train on the full dataset without the runtime bottleneck of re-encoding text every epoch.

2.  **Input Construction:**
    *   **Anchors:** Loaded as an ordered sequence of cached Code embeddings.
    *   **Queries:** Loaded as a shuffled set of cached Markdown embeddings.
    *   **Labels:** The target index of the code cell immediately following the markdown cell (or the "End-of-Notebook" token).

# Training

1.  **Objective Function:**
    *   **Cross-Entropy Loss** applied to the classification logits. We explicitly **exclude label smoothing** **Cite solution_lesson_node_00006**.

2.  **Optimization:**
    *   **Optimizer:** AdamW.
    *   **Learning Rate:** Constant **1e-3**. We explicitly **disable warmup schedules**, as they hinder the rapid convergence of adapters on frozen features **Cite solution_lesson_node_00006**.
    *   **Batch Size:** **64 notebooks**. This ensures a high frequency of gradient updates to effectively train the projection heads and context transformers **Cite solution_lesson_node_00004**.

# Evaluation

1.  **Inference:**
    *   For each test notebook, the model outputs a probability distribution for each markdown cell over the contextualized code anchors.
2.  **Soft Ranking:**
    *   We compute the **Expected Index** ($ \sum_{i} P_i \times i $) for each markdown cell.
    *   **Rationale:** This continuous ranking score implicitly handles local ordering ambiguities better than explicit pairwise refinement **Cite solution_lesson_node_00008**.
3.  **Ordering:**
    *   The final `cell_order` is produced by sorting the markdown cells based on their Expected Index values and interleaving them into the fixed code sequence.
