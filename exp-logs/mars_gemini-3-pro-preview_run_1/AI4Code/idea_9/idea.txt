Based on the accumulated lessons, I propose the **Corrected Dual-Context Anchor Network (DC-AN)**.

This solution represents the structural evolution from "Contextualized Anchors" (Idea 3) to **"Dual-Context Alignment"**. It retains the successful anchor-based classification framework but addresses the critical limitation where markdown cells were treated as independent queries. By introducing a permutation-invariant Set Transformer for the markdown branch, the model can resolve ambiguities (e.g., ordering "Introduction" vs. "Conclusion") by attending to the global content of the notebook. Crucially, this proposal integrates the stronger `MPNet` backbone while explicitly correcting the implementation flaw (EOS token handling) that caused the failure of Idea 6.

# Model

The architecture is a symmetric, dual-stream network designed to align a set of contextualized markdown queries against a sequence of contextualized code anchors.

1.  **Backbone (`all-mpnet-base-v2`):**
    *   We utilize **`sentence-transformers/all-mpnet-base-v2`** as the frozen feature extractor.
    *   **Rationale:** This backbone is pre-tuned for semantic similarity, which is essential for dot-product ranking tasks **Cite solution_lesson_node_00017**. It offers a superior trade-off between performance and speed compared to the generic `CodeBERT` (which failed due to misalignment) and the lightweight `MiniLM` (used in the current baseline).

2.  **Symmetric Projection Towers:**
    *   We employ two distinct MLP projection heads to map the 768-dimensional MPNet embeddings of Code and Markdown cells into a shared **512-dimensional latent space**.
    *   **Rationale:** This symmetric design is retained to geometrically align the heterogeneous manifolds of code and text **Cite solution_lesson_node_00003**.

3.  **Code Branch (Sequential Anchor Context):**
    *   The ordered sequence of projected Code embeddings is processed by a **Transformer Encoder with Sinusoidal Positional Encodings**.
    *   **Rationale:** This generates a "Contextualized Skeleton" of the notebook, allowing the model to distinguish identical code snippets based on their execution flow **Cite solution_lesson_node_00013**.

4.  **Markdown Branch (Set-Aware Query Context):**
    *   We introduce a **Permutation-Invariant Set Transformer** (a Transformer Encoder *without* positional embeddings) to process the bag of shuffled Markdown embeddings.
    *   **Rationale:** This allows each markdown cell to attend to all other markdown cells in the notebook (e.g., "I am one of 3 text cells"). This creates "Contextualized Queries" that are aware of the global notebook content, addressing the density-related errors observed in previous iterations **Cite solution_lesson_node_00002**.

5.  **EOS Token Correction (Critical Fix):**
    *   We append a learnable "End-of-Notebook" (EOS) token to the Code sequence.
    *   **Correction:** Unlike the failed Idea 6, which concatenated the EOS token to the end of the padded batch, we will **dynamically insert the EOS token** at the index corresponding to the sequence length (`batch_indices, valid_lens`) for each sample.
    *   **Rationale:** This prevents the model from calculating loss on masked padding positions (which leads to `inf` loss) and ensures the EOS token correctly interacts with the valid code sequence **Cite solution_lesson_node_00022**.

6.  **Interaction Head:**
    *   We compute Cross-Attention where the **Contextualized Markdown Set** serves as Queries and the **Contextualized Code Sequence** serves as Keys/Values. A Softmax over the code positions produces the placement probabilities.

# Data

1.  **Full Dataset Pre-computation:**
    *   We will run the frozen `all-mpnet-base-v2` model over the **entire training dataset (~140k notebooks)** to extract and cache embeddings.
    *   **Rationale:** Maximizing data volume is the primary driver of performance **Cite solution_lesson_node_00014**. Pre-computing allows us to train on the full dataset without the runtime bottleneck of re-encoding text every epoch **Cite solution_lesson_node_00020**.

2.  **Input Construction:**
    *   **Anchors:** Loaded as an ordered sequence of cached Code embeddings.
    *   **Queries:** Loaded as a shuffled set of cached Markdown embeddings.
    *   **Labels:** The target index of the code cell immediately following the markdown cell.

# Training

1.  **Objective Function:**
    *   **Cross-Entropy Loss** applied to the classification logits. We explicitly **exclude label smoothing** to avoid diluting the ranking signal **Cite solution_lesson_node_00006**.

2.  **Optimization:**
    *   **Optimizer:** AdamW.
    *   **Learning Rate:** Constant **1e-3**. We explicitly **disable warmup schedules**, as they hinder the rapid convergence of adapters on frozen features **Cite solution_lesson_node_00006**.
    *   **Batch Size:** **64 notebooks**. This ensures a high frequency of gradient updates to effectively train the projection heads and context transformers **Cite solution_lesson_node_00004**.

# Evaluation

1.  **Inference:**
    *   For each test notebook, the model outputs a probability distribution for each markdown cell over the contextualized code anchors.

2.  **Soft Ranking:**
    *   We compute the **Expected Index** ($ \sum_{i} P_i \times i $) for each markdown cell.
    *   **Rationale:** This continuous ranking score implicitly handles local ordering ambiguities better than explicit pairwise refinement **Cite solution_lesson_node_00008**.

3.  **Ordering:**
    *   The final `cell_order` is produced by sorting the markdown cells based on their Expected Index values and interleaving them into the fixed code sequence.
