Based on the lessons learned, I propose the **Temporal Ash-Net**, a strategy that evolves the successful custom baseline by integrating **temporal context** directly into the model structure. This approach shifts the paradigm from single-frame segmentation to multi-frame spatiotemporal analysis, leveraging the sequential nature of the dataset to distinguish moving contrails from static ground features, while strictly adhering to the architectural and training constraints that yielded the best results.

# Model
**Architecture: Temporal Custom U-Net**
I propose a **multi-frame U-Net** trained from scratch.
*   **Structural Innovation (Temporal Stacking):** Instead of processing a single frame, the model will accept a **9-channel input tensor**. This tensor consists of the "Ash" color composites for three consecutive time steps: the frame before the labeled event ($t-1$), the labeled frame ($t$), and the frame after ($t+1$). This allows the network's convolutional filters to learn temporal features (motion, persistence, and dissipation) in the channel dimension, providing a critical discriminator between static linear features (like roads or ridges) and moving contrails.
*   **Backbone:** We will use a **custom, lightweight encoder** with 4 stages, initialized with random weights. We explicitly reject pretrained backbones (like ResNet or HRNet) to avoid the domain gap issues and convergence failures observed with ImageNet weights. Cite solution_lesson_node_00021
*   **Downsampling Strategy:** The encoder will have a maximum downsampling factor of **16x** (bottleneck resolution of 16x16). We will avoid standard 32x downsampling to preserve the spatial signal of thin, single-pixel contrail features. Cite solution_lesson_node_00015

# Data
**Preprocessing: Temporal Ash Composite**
We will construct the input by stacking physics-informed composites across time.
*   **Ash Composite Construction:** For frames $t-1$, $t$, and $t+1$ (indices 3, 4, and 5), generate the 3-channel Ash composite:
    *   Red: Band 15 $-$ Band 14 (Optical Depth)
    *   Green: Band 14 $-$ Band 11 (Particle Phase)
    *   Blue: Band 14 (Temperature)
    Cite solution_lesson_node_00001
*   **Normalization:** Apply **Wide Normalization Bounds** (e.g., Red channel: -6.7 to 2.6) derived from the dataset statistics. We will explicitly avoid tight, heuristic clipping to preserve signal tails. Cite solution_lesson_node_00016
*   **Augmentation:** We will employ **only discrete geometric transformations** (Horizontal Flip, Vertical Flip, Random 90-degree Rotation). We will strictly exclude interpolation-based transforms (scaling, shifting, shearing) to prevent the destruction of high-frequency contrail details. Cite solution_lesson_node_00012

# Training
**Strategy: Metric-Driven Imbalance Correction**
The training loop is designed to stabilize gradients for the sparse target class while ensuring full convergence.
*   **Loss Function:** A weighted sum of **Balanced Focal Loss** and **Dice Loss**.
    *   **Configuration:** Set Focal Loss $\alpha=0.5$ to ensure the minority class is not down-weighted. Cite solution_lesson_node_00010
    *   **Weighting:** Prioritize pixel-wise stability by assigning a higher weight to Focal Loss (e.g., 0.75) compared to Dice Loss (0.25). Cite solution_lesson_node_00006
*   **Scheduler:** Use `ReduceLROnPlateau` monitoring the **Validation Dice Score** (not Loss). This ensures learning rate decay is triggered only when segmentation quality stagnates, enabling a proper refinement phase. Cite solution_lesson_node_00018
*   **Duration:** Train for 30+ epochs to allow the scheduler to fully decay the learning rate and fine-tune the weights.

# Evaluation
**Inference Process**
1.  **Input Generation:** For each test record, generate the 9-channel Temporal Ash stack (Frames 3, 4, 5) using the **Wide Normalization** constants.
2.  **Prediction:** Pass the tensor through the Temporal Ash-Net.
3.  **Thresholding:** Apply a sigmoid activation and a fixed threshold (0.5) to generate the binary mask.
4.  **Formatting:** Encode the masks using Run-Length Encoding (RLE) for submission.
