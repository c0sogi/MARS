Based on the task requirements and the provided model architectures, I propose the following baseline approach. This solution prioritizes simplicity and distinctness by utilizing a **Generative** paradigm, contrasting with the Extractive, Retrieval, and Sequence Labeling approaches listed previously.

### Model
We will implement a **Generative Encoder-Decoder Transformer** architecture (specifically utilizing the `google/mt5-small` backbone). Unlike Model 1 (which uses an Encoder-only architecture to predict start/end indices), this model treats Question Answering as a Sequence-to-Sequence (Seq2Seq) translation task.
*   **Encoder:** Processes the concatenated input sequence of the Question and Context to create a dense contextual representation.
*   **Decoder:** Autoregressively generates the answer text token-by-token.
This architecture naturally handles the multilingual nature of the dataset (Hindi and Tamil) via its pre-trained shared vocabulary and avoids the complex index-mapping logic required for extractive models in non-Latin scripts.

### Data
1.  **Input Formatting:** For each sample, construct a single input string using a standardized template: `"question: <question_text> context: <context_text>"`.
2.  **Target Formatting:** The target sequence is simply the raw `answer_text`.
3.  **Tokenization:** Use the pre-trained SentencePiece tokenizer associated with mT5. The inputs are padded/truncated to a fixed maximum length (e.g., 512 tokens), and targets are padded to the maximum answer length.
4.  **Splitting:** Use the metadata-generated split (train/val) which ensures no context leakage between sets.

### Training
*   **Procedure:** Fine-tune the model using standard **Teacher Forcing**, where the model predicts the next token given the ground truth history.
*   **Loss Function:** Minimize the **Cross-Entropy Loss** between the predicted token logits and the actual target tokens.
*   **Optimization:** Use the AdamW optimizer with a linear learning rate decay schedule. Given the small dataset size (~800 samples), we will use a small batch size and early stopping based on validation loss to prevent overfitting.

### Evaluation
1.  **Generation:** For the test set, use the model to generate a candidate answer string using **Greedy Decoding** (selecting the most probable token at each step) for maximum inference speed.
2.  **Constraint Satisfaction (Post-Processing):** The submission format requires the answer to be a strictly quoted substring of the context. Generative models may produce slight variations (e.g., normalizing punctuation). To address this:
    *   Take the generated text string.
    *   Perform a **Sliding Window Search** over the original `context` text.
    *   Select the window (substring) that maximizes the Jaccard similarity with the generated text.
    *   Return this exact substring as the final prediction.
