Based on the lessons learned and the task requirements, I propose a structural evolution from the previous Generative (Seq2Seq) approach to a **Retriever-Reader Extractive** approach using a robust Encoder-only backbone. This strategy addresses the critical failures regarding context length, "Gold Window" bias, and inference aggregation.

# Model
I propose replacing the `mt5` generative backbone with **`xlm-roberta-base`**, an Encoder-only Transformer pre-trained on 100 languages.
- **Architecture**: The model will utilize a standard Question Answering head (linear layers) on top of the encoder's hidden states to predict the **start** and **end** token indices of the answer span.
- **Rationale**: Unlike the generative approach, an extractive model produces unnormalized logit scores for every possible span. This provides a natural "confidence" metric, which is essential for comparing predictions across multiple sliding windows during inference. The `xlm-roberta` backbone is specifically optimized for cross-lingual representation, making it suitable for the Hindi and Tamil dataset.

# Data
**Preprocessing**:
1.  **Tokenization**: Use the `xlm-roberta` tokenizer. Concatenate the Question and Context. Crucially, utilize the `return_overflowing_tokens=True` and `return_offsets_mapping=True` parameters to automatically handle long documents by creating multiple overlapping token-based windows (Cite Lesson 00005).
2.  **Training Set Construction (Mixed-Sample)**:
    - Instead of creating a single "Gold Window" per document, we will generate **all possible sliding windows** for the training data.
    - **Positive Samples**: Windows that fully contain the answer span. The targets will be the specific start/end token indices.
    - **Negative Samples**: Windows that do not contain the answer. The target for these will be the `<s>` (CLS) token (index 0).
    - **Balancing**: To address the "Gold Window" bias (Cite Lesson 00006) without creating an overwhelming class imbalance, we will retain all Positive Samples and randomly downsample the Negative Samples (e.g., keeping a 1:2 positive-to-negative ratio). This forces the model to learn to discriminate between relevant and irrelevant contexts.

# Training
- **Procedure**: Train the model to minimize the Cross-Entropy Loss for both the start and end vectors.
- **Optimization**: Use the AdamW optimizer with a linear learning rate decay.
- **Step Count**: By converting each document into multiple windows (positives + negatives), the effective dataset size will increase significantly. We will train for sufficient epochs to ensure the model absorbs this larger, harder dataset, avoiding the underfitting observed when augmentation was applied without a budget increase (Cite Lesson 00007).

# Evaluation
- **Inference Strategy**:
    1.  **Exhaustive Sliding Windows**: Preprocess the test set using the same strided window approach (e.g., stride 128, window size 384) to generate overlapping chunks covering the entire text. Run the model on **every** chunk (Cite Lesson 00004).
    2.  **Score Aggregation**: For each window, the model will output a "best span" and a corresponding confidence score (sum of start and end logits).
    3.  **Global Selection**: Discard predictions pointing to the `<s>` token (No Answer). Compare the confidence scores of the non-null predictions across all windows for a given document ID. Select the span with the **highest global score**.
    4.  **Reconstruction**: Use the offset mapping to extract the exact substring from the original context, ensuring the prediction is a valid quote.
