Based on the comprehensive analysis of the accumulated lessons and the failure modes of previous iterations, I propose the following optimized strategy. This solution structurally evolves the approach into a **Robust Adversarial Seed Ensemble**, specifically designed to resolve the conflict between the need for high model capacity (`xlm-roberta-large`) and the severe constraints of data scarcity (~800 samples) and high variance.

# Model
**Architecture: Adversarial Multi-Task XLM-R Large**
*   **Backbone:** We will utilize **`xlm-roberta-large`**. Previous experiments confirmed that in low-data regimes, this massive generalist model significantly outperforms region-specific models like MuRIL due to superior cross-lingual transfer capabilities (Cite solution_lesson_node_00024).
*   **Multi-Task Heads:** The model will employ two distinct heads to explicitly model answer presence (Cite solution_lesson_node_00030):
    1.  **Span Head:** A linear layer predicting `start_logits` and `end_logits` for the answer boundaries.
    2.  **Relevance Head:** A binary classification head applied to the `[CLS]` token embedding to predict whether the window contains the answer.
*   **Structural Innovation (Corrected Adversarial Wrapper):** We will wrap the entire model with **Fast Gradient Method (FGM)**. Crucially, we will implement **Loss Normalization** during the adversarial pass. Previous attempts failed because gradients were accumulated without scaling, effectively doubling the step size and destabilizing training (Cite solution_lesson_node_00039). By averaging the clean and adversarial losses, we will smooth the optimization landscape and reduce the high run-to-run variance inherent in small datasets (Cite solution_lesson_node_00013).

# Data
**Preprocessing & Sampling:**
1.  **Token-Based Windowing:** We will use the `xlm-roberta-large` tokenizer with `return_overflowing_tokens=True` and `return_offsets_mapping=True`. This ensures precise, token-aligned splitting of long documents without heuristic truncation (Cite solution_lesson_node_00005).
2.  **Random Negative Sampling:** We will generate all possible sliding windows. We will retain 100% of "Positive" windows and randomly downsample "Negative" windows to maintain a strict **2:1 Negative-to-Positive ratio**. We will explicitly avoid "Hard Negative Mining" as it was proven to degrade performance in this low-resource regime (Cite solution_lesson_node_00038, solution_lesson_node_00021).
3.  **Full Dataset Merging:** We will concatenate the provided `train.csv` and `val.csv` metadata files into a single training set. With only ~800 total samples, withholding data for cross-validation starves the model; we must utilize 100% of the available signal (Cite solution_lesson_node_00027).
4.  **Deterministic Caching:** The processed features (including the specific random selection of negatives) will be saved to disk with explicit type sanitization (converting Numpy arrays to Lists). This locks in the data distribution, ensuring reproducibility and preventing serialization artifacts (Cite solution_lesson_node_00010, solution_lesson_node_00014).

# Training
**Procedure: Converged Full-Data Seed Ensemble**
*   **Ensemble Strategy:** We will train **3 independent models** on the full merged dataset, each initialized with a different random seed. We prioritize the **full convergence** of a few strong models over a larger ensemble of under-trained models (Cite solution_lesson_node_00040).
*   **Optimization Strategy:**
    *   **Differential Learning Rates (DLR):** We will apply a low learning rate (`1e-5`) to the backbone and a higher rate (`5e-5`) to the heads (Cite solution_lesson_node_00031). We will avoid aggressive Layer-Wise Decay (LLRD) as it starves the lower layers of necessary adaptation (Cite solution_lesson_node_00044).
    *   **Explicit Parameter Grouping:** We will define parameter groups using **explicit module references** (e.g., `model.backbone.parameters()`) rather than string matching to prevent grouping errors (Cite solution_lesson_node_00033).
    *   **Global Weight Decay:** We will apply weight decay to **ALL** parameters, including biases and LayerNorms. In this extreme low-data regime, global decay is necessary to dampen the capacity of the Large model and prevent memorization (Cite solution_lesson_node_00036).
    *   **Loss Weighting:** We will strictly down-weight the auxiliary relevance loss: $L = L_{span} + 0.5 \times L_{relevance}$ (Cite solution_lesson_node_00035).
    *   **Extended Duration:** We will train each seed for **8 to 10 epochs**. The combination of DLR and Adversarial Training increases optimization difficulty, requiring a longer schedule to ensure full convergence (Cite solution_lesson_node_00034, solution_lesson_node_00032).
    *   **Small Batch Regularization:** We will use a batch size of **4** to introduce gradient noise (Cite solution_lesson_node_00011).

# Evaluation
**Inference Pipeline:**
1.  **Exhaustive Sliding Windows:** The test set will be processed into overlapping token-based windows. We will run inference on **every** chunk without heuristic filtering (Cite solution_lesson_node_00004).
2.  **Ensemble Aggregation:** For each window, we will compute the `start`, `end`, and `relevance` logits from all 3 converged seed models and **average them**. This reduces the stochastic noise inherent in any single training run.
3.  **Gated Scoring:** We will calculate the final confidence score using the averaged logits:
    $$ \text{Score} = (\text{Start\_Logit} + \text{End\_Logit}) + \text{Relevance\_Logit} $$
    This uses the Relevance Head to suppress high-confidence span predictions that appear in contextually irrelevant windows (Cite solution_lesson_node_00030).
4.  **Reconstruction:** We will select the span with the maximum Gated Score across all windows for a given document ID and map it back to the original text using the offset mapping.
