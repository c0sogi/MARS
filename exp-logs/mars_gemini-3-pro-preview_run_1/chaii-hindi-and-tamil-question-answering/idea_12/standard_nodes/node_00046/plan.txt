The strategy involves a straightforward execution of the provided library components to establish a robust baseline. We will instantiate the `Config` with a moderate epoch count (3) to balance convergence speed with performance on the small dataset. The data loading pipeline will be manually orchestrated to strictly separate the training set (`metadata/train.csv`) and the hold-out validation set (`metadata/val.csv`), bypassing the default merging behavior to enable rigorous evaluation.

The workflow proceeds as follows:
1.  **Training**: We process the training metadata into features and train the `XLMRobertaForQA` model using the ensemble of seeds defined in the configuration. The training utilizes the provided adversarial training (FGM) and differential learning rates.
2.  **Validation**: We process the validation metadata using the test-time sliding window approach (`prepare_test_features`). We then run the full inference pipeline (`predict_and_aggregate` and `post_processing`) to generate answer strings.
3.  **Evaluation**: We compute the word-level Jaccard score against the ground truth. This metric determines whether we proceed to submission.
4.  **Failure Analysis**: We calculate the Pearson correlation between the error magnitude ($1 - \text{Jaccard}$) and input properties (context and question length) to diagnose performance bottlenecks.
5.  **Submission**: If the validation score exceeds the threshold, we repeat the inference process on the test set and generate the `submission.csv`.
