Based on the comprehensive history of experiments and the specific lessons learned, I propose the following optimized strategy. This solution structurally evolves the approach by correcting the implementation of **Adversarial Training** (specifically addressing the gradient accumulation error) and integrating it into a **Full-Data Seed Ensemble** with **Layer-Wise Learning Rate Decay**. This design targets the critical balance between model capacity (`xlm-roberta-large`) and the regularization required for this extreme low-data regime (~800 samples).

# Model
**Architecture: Adversarial Multi-Task XLM-R Large Ensemble**
*   **Backbone:** We will utilize **`xlm-roberta-large`**. Previous lessons confirmed that in low-data regimes, this massive generalist model significantly outperforms region-specific models like MuRIL due to superior cross-lingual transfer capabilities (Cite solution_lesson_node_00024).
*   **Multi-Task Heads:** Each model in the ensemble will employ two distinct heads to explicitly model answer presence (Cite solution_lesson_node_00030):
    1.  **Span Head:** A linear layer predicting `start_logits` and `end_logits` for the answer boundaries (Cite solution_lesson_node_00008).
    2.  **Relevance Head:** A binary classification head applied to the `[CLS]` token embedding to predict whether the window contains the answer.
*   **Structural Innovation (Corrected Adversarial Wrapper):** We will wrap the model with **Fast Gradient Method (FGM)**. Crucially, we will implement **Loss Normalization** during the adversarial pass. Previous attempts failed because gradients were accumulated without scaling, effectively doubling the learning rate and destabilizing training (Cite solution_lesson_node_00039). By averaging the clean and adversarial losses, we will smooth the loss landscape and reduce run-to-run variance (Cite solution_lesson_node_00013).

# Data
**Preprocessing & Sampling:**
1.  **Token-Based Windowing:** Use the `xlm-roberta-large` tokenizer with `return_overflowing_tokens=True` and `return_offsets_mapping=True` to ensure precise splitting of long documents without heuristic truncation (Cite solution_lesson_node_00005).
2.  **Random Negative Sampling:** Generate all sliding windows. Retain 100% of "Positive" windows and randomly downsample "Negative" windows to maintain a strict **2:1 Negative-to-Positive ratio**. We will explicitly avoid "Hard Negative Mining" as it was proven to degrade performance in this low-resource regime (Cite solution_lesson_node_00038, solution_lesson_node_00021).
3.  **Full Dataset Merging:** Concatenate the provided `train.csv` and `val.csv` metadata files into a single training set. We will not use cross-validation splits, as withholding data starves the model (Cite solution_lesson_node_00027).
4.  **Deterministic Caching:** Save the processed features (including the specific random selection of negatives) to disk with explicit type sanitization (converting Numpy arrays to Lists) to ensure reproducibility (Cite solution_lesson_node_00010, solution_lesson_node_00014).

# Training
**Procedure: Full-Data Seed Ensemble with Layer-Wise Decay**
*   **Ensemble Strategy:** We will train **3 to 5 independent models** on the full merged dataset, each initialized with a different random seed. We prioritize full convergence of each model over the number of ensemble members (Cite solution_lesson_node_00040).
*   **Optimization Strategy:**
    *   **Layer-Wise Learning Rate Decay (LLRD):** Instead of a simple 2-group DLR, we will implement LLRD. We will assign exponentially decreasing learning rates to the lower layers of the backbone (e.g., decay factor 0.9 per layer). This provides a smoother transition from the frozen embeddings to the highly plastic task heads, preserving multilingual features better than simple grouping (Evolution of solution_lesson_node_00031).
    *   **Global Weight Decay:** Apply weight decay to **ALL** parameters, including biases and LayerNorms. This is strictly necessary to prevent overfitting in this low-data regime (Cite solution_lesson_node_00036).
    *   **Loss Weighting:** Strictly down-weight the auxiliary relevance loss: $L = L_{span} + 0.5 \times L_{relevance}$ (Cite solution_lesson_node_00035).
    *   **Extended Duration:** Train for **8 to 10 epochs**. The combination of LLRD and Adversarial Training increases optimization difficulty, requiring a longer schedule to ensure full convergence (Cite solution_lesson_node_00034, solution_lesson_node_00032).
    *   **Small Batch Regularization:** Use a batch size of **4** to introduce gradient noise (Cite solution_lesson_node_00011).

# Evaluation
**Inference Pipeline:**
1.  **Exhaustive Sliding Windows:** Process the test set into overlapping token-based windows and run inference on **every** chunk (Cite solution_lesson_node_00004).
2.  **Ensemble Aggregation:** For each window, average the `start`, `end`, and `relevance` logits across all converged seed models.
3.  **Gated Scoring:** Calculate the final confidence score using the averaged logits:
    $$ \text{Score} = (\text{Start\_Logit} + \text{End\_Logit}) + \text{Relevance\_Logit} $$
    This uses the Relevance Head to suppress high-confidence span predictions that appear in contextually irrelevant windows (Cite solution_lesson_node_00030).
4.  **Reconstruction:** Select the span with the maximum Gated Score and map it back to the original text using the offset mapping.
