The issue lies in `library/model_arch.py` where `get_model` attempts to load the model configuration using `AutoConfig.from_pretrained(checkpoint_path)`. When `checkpoint_path` points to a PyTorch binary file (`.pth` containing a state dictionary), the `transformers` library fails to parse it as a JSON configuration file, raising an `OSError`.

To fix this, I will modify `get_model` to:
1.  Always load the configuration and initialize the model architecture from the base `Config.MODEL_CHECKPOINT`.
2.  Explicitly check if `checkpoint_path` is a file (indicating a state dictionary saved via `torch.save`).
3.  If it is a file, use `torch.load` to retrieve the weights and `model.load_state_dict` to apply them, bypassing the `transformers` configuration loading for the checkpoint file.

This ensures the model architecture is correctly initialized before loading the learned weights.
