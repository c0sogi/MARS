### Implementation Strategy

1.  **Environment Setup**: We will import the necessary modules and the provided library classes (`Config`, `QADataset`, `QAModel`, etc.). We will set the random seed for reproducibility.
2.  **Data Subsetting**: To ensure the demonstration runs quickly (within minutes), we will create small subsets (e.g., 20 samples) of the training, validation, and test datasets. We will save these subsets to the `./working` directory.
3.  **Configuration Override**: We will modify the `Config` class attributes and instance variables to point to these new subset files. Crucially, we will modify `Config.test_data_path` at the class level because `library.model.post_process_predictions` accesses this static attribute directly. We will also reduce `epochs` to 1 and `n_folds` to 2.
4.  **Data Processing**: We will use `load_and_process_data` to tokenize and prepare features. We will verify the output DataFrames contain the expected columns.
5.  **Model Initialization**: We will instantiate the `QAModel` and verify its structure.
6.  **Training Loop**: We will run the `train_loop` function from `library.engine` for one epoch to demonstrate the training process.
7.  **Inference & Submission**: We will use `generate_submission` to predict answers for the test subset.
8.  **Validation**: We will assert that the submission file is created, follows the correct format, and contains predictions for the test IDs. We will also demonstrate the metric calculation using `library.utils`.
