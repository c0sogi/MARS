Based on the comprehensive analysis of previous experiments and the specific lessons learned, I propose the following optimized strategy. This solution structurally evolves the approach by correcting the implementation of **Adversarial Training** (which previously failed due to insufficient training duration) and integrating it into a **Full-Data Seed Ensemble** with **Global Regularization**. This design specifically targets the critical tension between the need for high model capacity (`xlm-roberta-large`) and the overfitting risks inherent in the extremely small dataset (~800 samples).

# Model
**Architecture: Adversarial Multi-Task XLM-R Large**
*   **Backbone:** We will utilize **`xlm-roberta-large`**. Previous lessons confirmed that in low-data regimes, this massive generalist model significantly outperforms region-specific models like MuRIL due to superior cross-lingual transfer capabilities (Cite solution_lesson_node_00024).
*   **Multi-Task Heads:** The model will employ two distinct heads to explicitly model answer presence (Cite solution_lesson_node_00030):
    1.  **Span Head:** A linear layer predicting `start_logits` and `end_logits` for the answer boundaries (Cite solution_lesson_node_00008).
    2.  **Relevance Head:** A binary classification head applied to the `[CLS]` token embedding to predict whether the window contains the answer.
*   **Structural Innovation (Adversarial Wrapper):** We will wrap the model with **Fast Gradient Method (FGM)**. By injecting small perturbations into the input embeddings during the forward pass, we smooth the loss landscape. This acts as a powerful structural regularizer, directly addressing the high run-to-run variance and overfitting tendencies observed in small-sample fine-tuning (Cite solution_lesson_node_00013).

# Data
**Preprocessing & Sampling:**
1.  **Token-Based Windowing:** Use the `xlm-roberta-large` tokenizer with `return_overflowing_tokens=True` and `return_offsets_mapping=True`. This ensures precise splitting of long documents based on the model's actual token capacity, avoiding heuristic truncation errors (Cite solution_lesson_node_00005).
2.  **Hard Negative Mining:** We will refine the negative sampling strategy. Instead of purely random sampling, we will explicitly prioritize **"Boundary Negatives"**—windows that are adjacent to the answer span or share high token overlap with the question but do not contain the answer. We will fill the remainder with random negatives to maintain the proven **2:1 Negative-to-Positive ratio** (Cite solution_lesson_node_00021).
3.  **Full Dataset Merging:** We will concatenate the provided `train.csv` and `val.csv` metadata files into a single training set. With only ~800 total samples, withholding data for validation starves the model; we will rely on the ensemble strategy for robustness (Cite solution_lesson_node_00027).
4.  **Deterministic Caching:** The processed features (including the specific selection of negatives) will be saved to disk with explicit type sanitization (converting Numpy arrays to Lists). This locks in the data distribution, ensuring reproducibility (Cite solution_lesson_node_00014, solution_lesson_node_00010).

# Training
**Procedure: Full-Data Seed Ensemble with Extended Adversarial Schedule**
*   **Ensemble Strategy:** We will train **5 independent models** on the full merged dataset, each initialized with a different random seed. This utilizes 100% of the data for learning while statistically smoothing predictions during inference (Cite solution_lesson_node_00027).
*   **Optimization Strategy:**
    *   **Differential Learning Rates (DLR):** Apply a low learning rate (`1e-5`) to the backbone and a higher rate (`5e-5`) to the heads (Cite solution_lesson_node_00031). Use **explicit module references** for grouping to avoid string-matching errors (Cite solution_lesson_node_00033).
    *   **Global Weight Decay:** Crucially, we will apply weight decay to **ALL** parameters, including biases and LayerNorms. In this extreme low-resource regime, global decay is necessary to dampen the capacity of the Large model and prevent memorization (Cite solution_lesson_node_00036).
    *   **Small Batch Regularization:** Use a batch size of **4** to introduce gradient noise (Cite solution_lesson_node_00011).
    *   **Extended Duration:** We will train for **8 to 10 epochs**. Previous attempts at Adversarial Training failed because the schedule was shortened; FGM increases the optimization difficulty, and combined with DLR, the backbone requires significantly more steps to converge (Cite solution_lesson_node_00034, solution_lesson_node_00032).
    *   **Loss Weighting:** We will strictly down-weight the auxiliary loss: $L = L_{span} + 0.5 \times L_{relevance}$ (Cite solution_lesson_node_00035).

# Evaluation
**Inference Pipeline:**
1.  **Exhaustive Sliding Windows:** Process the test set into overlapping token-based windows and run inference on **every** chunk (Cite solution_lesson_node_00004).
2.  **Ensemble Aggregation:** For each window, average the `start`, `end`, and `relevance` logits across all 5 seed models.
3.  **Gated Scoring:** Calculate the final confidence score using the averaged logits:
    $$ \text{Score} = (\text{Start\_Logit} + \text{End\_Logit}) + \text{Relevance\_Logit} $$
    This uses the Relevance Head to suppress high-confidence span predictions that appear in contextually irrelevant windows (Cite solution_lesson_node_00030).
4.  **Reconstruction:** Select the span with the maximum Gated Score and map it back to the original text using the offset mapping.
