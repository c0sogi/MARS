The issue is that the training loop initializes `best_acc` to `0.0`, and in the demo run, the validation accuracy for the first epoch is also `0.0`. Consequently, the condition `if val_acc > best_acc` evaluates to `False`, causing the code to skip saving the model checkpoint. This results in the inference step loading a stale `best_model.pth` file from a previous run with a different architecture, triggering a `RuntimeError`. To fix this, I will initialize `best_acc` to `-1.0` so that the model is saved at least once during the first epoch, ensuring the checkpoint on disk matches the current model architecture. This addresses the issue of stale artifacts persisting across runs (Cite debug_lesson_3).
