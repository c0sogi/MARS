The strategy for generating the metadata is as follows:

1.  **Setup and Initialization**: Define the input directories (`./input/train/audio`, `./input/test/audio`) and the output directory (`./metadata`). Define the set of target labels (`yes`, `no`, `up`, `down`, `left`, `right`, `on`, `off`, `stop`, `go`).
2.  **Training Data Collection**:
    *   Iterate through all subdirectories in the training audio folder.
    *   **Label Assignment**:
        *   If the folder name is `_background_noise_`, assign the label `silence`.
        *   If the folder name is in the target list, assign the folder name as the label.
        *   Otherwise (e.g., `bed`, `bird`), assign the label `unknown`.
    *   **Subject ID Extraction**: Parse the filename (e.g., `00176480_nohash_0.wav`) to extract the subject ID (first segment before `_`). For background noise files which do not follow this pattern, assign a placeholder ID.
    *   Store the relative file path, label, and subject ID.
3.  **Test Data Collection**:
    *   Iterate through the test audio folder.
    *   Store the relative file path and a placeholder label (`unknown`).
4.  **Data Splitting (Train/Validation)**:
    *   **Group Sampling**: To prevent data leakage, use `GroupShuffleSplit` on the non-noise data, using the extracted `subject_id` as the group. This ensures that all clips from a specific speaker end up in either the training or validation set, but not both. Use a fixed 80:20 split ratio and `random_state=42`.
    *   **Noise Handling**: Since background noise files are few and do not have subject IDs, split them using a simple random split (or assign to train if too few) to maintain the 80:20 ratio as best as possible.
    *   Combine the split regular data and split noise data to form the final training and validation sets.
5.  **Output Generation**: Save the resulting datasets to `train.csv`, `val.csv`, and `test.csv` in the `./metadata` directory.
6.  **Validation**:
    *   Print summary statistics (counts, label distributions).
    *   Verify file existence for a random sample of paths.
    *   **Leakage Check**: Programmatically assert that the set of subject IDs in the training set and validation set are disjoint (intersection is empty).
