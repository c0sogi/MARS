Implementation strategy:
1.  **Configuration & Setup**: Import the provided configuration objects. Override `TRAIN_CONFIG.epochs` to 15 and `TRAIN_CONFIG.swa_start_epoch` to 10 to satisfy the "fast baseline" requirement while preserving the SWA strategy. Set random seeds for reproducibility.
2.  **Data Loading**: Use `get_dataloaders` with `load_cached_data=True` to efficiently load the training, validation, and test sets.
3.  **Training**: Instantiate the `Trainer` class. Pass `test_loader=None` initially to prevent automatic submission generation during the `fit()` call, allowing for conditional submission based on the validation threshold. Execute `trainer.fit()` to train the model and perform SWA.
4.  **Validation & Metric Calculation**:
    *   Load the trained SWA model (`trainer.swa_model`).
    *   Iterate over the validation set.
    *   Perform inference to get fine-grained predictions.
    *   Map both predicted and ground-truth labels to the 12 competition classes (using `LABEL_CONFIG.map_to_submission_label`).
    *   Calculate the **Multiclass Accuracy** on these 12 classes as the final validation metric.
5.  **Failure Analysis**:
    *   During the validation loop, compute input signal features: **RMS** (Root Mean Square amplitude) as a proxy for signal volume/energy.
    *   Calculate **Error Magnitude** ($1.0 - P(\text{True Class})$) based on the fine-grained probabilities.
    *   Compute and print the Pearson correlation between Error Magnitude and RMS to identify if volume affects performance.
6.  **Submission**: Compare the calculated validation metric against the strict threshold (`0.9872909698996656`). If the metric exceeds the threshold, assign the test loader to the trainer and call `generate_submission()`.
