The `IndexError` in `library/data.py` occurs because `np.unique` is used to count atoms per crystal based on `batch_indices`. Since crystals with zero atoms do not appear in `batch_indices`, they are omitted from the counts, causing the `self.atom_starts` array to be shorter than the total number of samples. When the `DataLoader` tries to access an index corresponding to a sample near the end of the dataset, it goes out of bounds.

To fix this, I will calculate atom counts using `np.bincount` with `minlength` set to the total number of samples (derived from `self.global_inputs`). This ensures that empty crystals are correctly recorded as having 0 atoms, keeping the indexing aligned. This solution applies the lesson "Handle Empty Graphs by Anchoring Batch Size to Graph-Level Features" (Cite debug_lesson_2).
