The issue is that `Config.MODEL_PATH` is initialized when the `Config` class is imported, based on the original `WORKING_DIR`. When `runfile.py` updates `Config.WORKING_DIR` to a temporary demo directory, `Config.MODEL_PATH` is not automatically updated and continues to point to the non-existent original directory, causing `torch.save` to fail. To fix this, I will explicitly update `Config.MODEL_PATH` in `runfile.py` immediately after modifying `Config.WORKING_DIR`, ensuring state consistency (Cite debug_lesson_6).
