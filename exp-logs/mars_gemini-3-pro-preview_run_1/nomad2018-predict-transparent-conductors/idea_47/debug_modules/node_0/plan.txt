The implementation strategy involves creating a self-contained Python script that imports and utilizes the provided library modules (`utils`, `features`, `data`, `model`, `train`).

1.  **Setup and Imports**: Import necessary standard libraries (`os`, `numpy`, `pandas`, `torch`) and the provided library modules. Set random seeds for reproducibility.
2.  **Utils Demo**: Verify `calculate_cell_volume` and `calculate_angular_distortion` with known values. Verify `get_pbc_distances` using a simple cubic lattice to ensure neighbor finding works under periodic boundary conditions.
3.  **Features and Data Demo**:
    *   Create a small "dummy" metadata set in `./working/dummy_meta` by subsetting the provided `./metadata/train.csv` and `./metadata/test.csv`. This avoids processing the entire dataset and speeds up execution.
    *   Demonstrate `parse_xyz` on a real file from the input directory.
    *   Demonstrate `extract_atomic_features` and `extract_global_features` to show feature generation logic.
    *   Instantiate `MaterialDataset` with the dummy metadata. This triggers the processing pipeline (caching, scaling) on a small subset.
    *   Use `DataLoader` with `SparseCollate` to show how variable-sized crystal graphs are batched.
4.  **Model Demo**:
    *   Instantiate the `CEADSModel` with dimensions matching the data.
    *   Perform a forward pass with a batch from the data loader to verify tensor shapes and connectivity.
5.  **Training Demo**:
    *   Manually run a training loop for one epoch using `train_one_epoch` and `validate` functions from `library.model` (or `library.train` if applicable, but direct function calls allow using the dummy loaders).
    *   Simulate the submission generation process using the dummy test set and the trained model, saving the output to `./working/demo_submission.csv`.

This approach ensures all components are exercised and verified within the time and resource constraints, without modifying the read-only input or provided library files.
