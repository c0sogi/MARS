The issue is caused by missing values (NaNs) in the metadata CSV files, specifically in the `data_path` and `audio_path` columns. When `pandas` reads these CSVs, missing entries are converted to floating-point `NaN` values. The `load_and_process_sample` function then attempts to pass these `NaN` values directly to `os.path.join`, which raises a `TypeError` because it expects string arguments.

To fix this, I will:
1.  **Sanitize Inputs in `load_and_process_sample`**: Explicitly check if `data_path` and `audio_path` are valid strings before attempting to construct file paths. If they are not (e.g., `NaN`), handle them gracefully (e.g., treat as missing files) to prevent the crash.
2.  **Filter Metadata in `GestureDataset` and `get_dataloaders`**: Pre-emptively remove rows from the DataFrame where the essential `data_path` is missing. This ensures that the dataset only contains valid samples and prevents `NaN`s from propagating to the processing logic or statistics computation.

These changes directly address the `TypeError` by enforcing type safety and data integrity as recommended in **debug_lesson_5** ("Sanitize Metadata Inputs Before File Operations").
