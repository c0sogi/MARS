The `zipfile.BadZipFile` error is caused by passing a lazy-loading `numpy.lib.npyio.NpzFile` object (returned by `np.load`) to multiple `DataLoader` worker processes. This object holds an open file handle, and when pickled and accessed concurrently by workers, it leads to race conditions and file pointer corruption. To fix this, I will modify `library/data_loader.py` to explicitly materialize the statistics into a standard Python dictionary and close the file handle immediately upon loading. This ensures that `self.stats` contains safe, in-memory arrays that can be serialized without issues. Cite debug_lesson_12.
