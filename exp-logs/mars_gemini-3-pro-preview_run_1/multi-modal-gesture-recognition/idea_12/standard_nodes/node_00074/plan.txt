The `zipfile.BadZipFile` error occurs because `np.load` returns a lazy-loading `NpzFile` object that maintains an open file handle. When this object is serialized and sent to multiple `DataLoader` worker processes, concurrent access leads to file pointer corruption. To resolve this, I will modify `_get_global_stats` in `library/data_loader.py` to explicitly materialize the data into a standard Python dictionary and close the file handle immediately using a context manager. I will also update the computation path to return the in-memory dictionary directly instead of reloading it from disk. Cite debug_lesson_12.
