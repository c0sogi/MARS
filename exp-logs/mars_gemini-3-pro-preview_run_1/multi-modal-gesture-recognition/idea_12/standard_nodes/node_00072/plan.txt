The `zipfile.BadZipFile` error occurs because `np.load` returns a lazy-loading `NpzFile` object that maintains an open file handle. When this object is assigned to `self.stats` in the dataset and subsequently pickled/shared across multiple `DataLoader` worker processes, concurrent access to the same file descriptor corrupts the read state, leading to the crash. To fix this, I will modify `_get_global_stats` in `library/data_loader.py` to explicitly materialize the `.npz` content into a standard Python dictionary and close the file handle immediately, ensuring thread-safe access in workers.
