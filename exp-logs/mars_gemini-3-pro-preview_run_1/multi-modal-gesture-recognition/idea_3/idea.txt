Based on the comprehensive analysis of previous experiments and the derived lessons, I propose the **Multi-Scale Decoupled Inception-GRU (MS-DIG)**. This solution introduces a structural innovation in the feature extraction phase to handle the variable temporal dynamics of gestures while rigorously adhering to the successful regularization and optimization strategies identified in the lessons.

# Model

The architecture is a **Multi-Stream Hybrid Network** that evolves the previous simple projection stems into **Temporal Inception Blocks**.

1.  **Decoupled Input Stems:**
    The model processes Skeleton and Audio data in two completely independent streams to prevent gradient dominance and allow modality-specific feature learning Cite solution_lesson_node_00021.
    *   **Skeleton Stream:**
        *   **Input:** Normalized Joint Coordinates (relative to Hip Center).
        *   **Normalization:** Global Z-score Normalization (Zero Mean, Unit Variance) applied to the raw input to handle scale differences without physical unit scaling Cite solution_lesson_node_00016.
        *   **Structural Innovation (Temporal Inception Block):** Instead of a single convolution, the input is projected into three parallel **1D Convolutional branches** with varying kernel sizes (e.g., $k=3$, $k=7$, $k=11$).
            *   $k=3$: Captures rapid, high-frequency movements (jitter/fast transitions).
            *   $k=7$: Captures standard gesture dynamics.
            *   $k=11$: Captures longer-term context and smooths static poses.
        *   **Aggregation:** The outputs of these branches are concatenated and passed through a `Linear -> ReLU -> Dropout` sequence. This allows the model to learn features at multiple temporal resolutions simultaneously. The dropout used is **Standard Element-wise Dropout**, not Spatial Dropout, to preserve temporal continuity Cite solution_lesson_node_00024.
    *   **Audio Stream:**
        *   Follows an identical **Inception-based** structure tailored for MFCCs, allowing the model to capture both short phoneme-like sounds and longer prosodic cues.

2.  **Fusion & Backbone:**
    *   **Fusion:** The outputs from both stems are concatenated and immediately normalized via **Layer Normalization**. This stabilizes the merging of the two distinct feature distributions Cite solution_lesson_node_00011.
    *   **Recurrent Core:** A **Bidirectional GRU** processes the fused sequence. The hidden dimension is strictly limited (e.g., 256 units) to act as a structural regularizer against overfitting on this small dataset Cite solution_lesson_node_00023.

# Data

1.  **Preprocessing:**
    *   **Skeleton:** Calculate relative coordinates (`Joint - HipCenter`) to ensure user-position invariance Cite solution_lesson_node_00005.
    *   **Audio:** Extract MFCCs synchronized to the video frame rate (20 fps).
    *   **Normalization:** Compute global statistics (Mean/Std) on the training set for both modalities and apply them to all inputs Cite solution_lesson_node_00021.

2.  **Augmentation:**
    *   **Random Channel Masking:** Randomly zero out ~10% of feature channels for the entire sequence duration with 50% probability. This forces the model to learn robust representations from redundant signals Cite solution_lesson_node_00013.
    *   **Additive Gaussian Noise:** Inject noise into the skeleton coordinates to prevent overfitting to specific spatial configurations Cite solution_lesson_node_00007.

# Training

1.  **Loss Function:**
    *   Use **Frame-wise Cross Entropy Loss**.
    *   Apply **Label Smoothing (0.1)** to handle boundary ambiguity between gestures and the null class Cite solution_lesson_node_00011.
    *   Set the **Background Class Weight to 0.5**. This balances the need to suppress the dominant background class without causing excessive insertion errors (hallucinations) Cite solution_lesson_node_00011.

2.  **Optimization Strategy:**
    *   **Metric-Aware Checkpointing:** Do not rely on Validation Loss for model selection. At the end of every training epoch, run the full inference pipeline (decoding) on the validation set and compute the **Levenshtein Error Rate**. Save the checkpoint that minimizes this specific metric. This addresses the disconnect between the frame-wise proxy loss and the sequence-level target metric Cite solution_lesson_node_00025.

# Evaluation

1.  **Inference:**
    *   Pass the test sequences through the trained MS-DIG model to obtain frame-wise probabilities.
    *   Apply a **Median Filter** (window size ~5-7) to smooth the predictions and remove single-frame glitches Cite solution_lesson_node_00005.
    *   **Decoding:** Use **Run-Length Encoding (RLE)** to collapse the smoothed frames into a sequence of gesture IDs. Filter out the background class and any segments shorter than a minimal threshold (e.g., 5 frames) to produce the final ordered list.
