### Implementation Strategy

1.  **Environment Setup**: Initialize random seeds using the provided `seed_everything` utility to ensure reproducibility. Define a dedicated working directory (`./working/demo_run`) for this demonstration to avoid conflicts with existing files.
2.  **Data Subsetting**: To ensure the script runs quickly as requested, load the existing metadata files (`train.csv`, `val.csv`, `test.csv`), sample a small subset of rows (e.g., 5 samples each), and save these as temporary metadata files. This drastically reduces the time required for feature extraction during the dataset initialization.
3.  **Data Loading**: Instantiate the `GestureDataset` class using the temporary metadata files. Wrap these datasets in PyTorch `DataLoader`s using the provided `collate_fn` to handle variable-length sequences.
4.  **Model Initialization**: Instantiate the `GestureGRU` model. Perform a dummy forward pass with a single batch from the data loader to verify input/output tensor shapes (Features: `[Batch, Time, Dim]`, Logits: `[Batch, Time, Classes]`).
5.  **Training Loop**: Configure an optimizer (AdamW) and instantiate the `Trainer` class. Execute the `fit` method for a minimal number of epochs (e.g., 2) to demonstrate the training process and checkpoint saving mechanism.
6.  **Inference**: Instantiate the `Predictor` class using the checkpoint generated in the training step. Run inference on the subsetted test dataset and generate a submission file.
7.  **Validation**:
    *   Assert that the checkpoint file exists.
    *   Assert that the submission file exists and contains the expected number of rows.
    *   Manually verify utility functions (`calculate_levenshtein_distance`, `rle_collapse`) with known inputs to ensure logic correctness.
