The issue is that `numpy.load` returns a lazy-loading `NpzFile` object that maintains an open file handle. When this object is stored in `self.stats` and the dataset is serialized for multiprocessing (via `DataLoader` with `num_workers > 0`), the open file handle is shared across worker processes, leading to race conditions and the `zipfile.BadZipFile` error. To fix this, we must eagerly materialize the data into a standard Python dictionary using a context manager, ensuring the file handle is closed immediately after loading (Cite {debug_lesson_15}).
