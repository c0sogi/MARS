The issue is caused by `torch.load` defaulting to `weights_only=True` in the installed PyTorch version, which restricts unpickling to a safe subset of types. Since the checkpoint dictionary contains a NumPy scalar (the `val_metric`), the loader rejects it as unsafe. The fix is to explicitly set `weights_only=False` in the `torch.load` call in `runfile.py` to allow deserialization of the full checkpoint content, matching the behavior used elsewhere in the codebase.
