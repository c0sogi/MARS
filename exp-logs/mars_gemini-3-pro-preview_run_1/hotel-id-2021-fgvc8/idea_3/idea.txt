Based on the lessons learned from the previous experiments, I propose a **Curriculum-Based EfficientNet Retrieval System**. This approach upgrades the backbone for better feature extraction, introduces a specialized pooling mechanism for retrieval, and strictly adheres to the training dynamics identified in the lessons to prevent convergence failure and overfitting.

### Model
*   **Backbone**: Replace the lightweight MobileNetV3 with **EfficientNet-B0**. While MobileNet is fast, the hotel recognition task involves fine-grained architectural details that require the superior feature extraction capabilities of the EfficientNet family. This fits the "moderately heavier" allowance while remaining efficient on the A100 GPU.
*   **Neck (Structural Innovation)**: Replace the standard Global Average Pooling (GAP) with **Generalized Mean Pooling (GeM)**. Unlike GAP, which treats all pixels equally (averaging out distinctive features with background noise), GeM is a learnable pooling layer that focuses on salient regions (similar to Max Pooling) while retaining some context. This is critical for identifying hotels where specific landmarks or facade details are more important than the sky or street.
*   **Head**: Retain the **ArcFace (Additive Angular Margin)** head. This component is essential for learning a discriminative metric space where intra-class variance is minimized, which is crucial for the high-cardinality (7,700+ classes) nature of this dataset.

### Data
*   **Preprocessing**: Images will be resized and center-cropped to **224x224** to match the EfficientNet input requirements.
*   **Augmentation**: Apply **TrivialAugment** or a moderate **RandAugment** policy. Since the dataset has a long tail, stronger augmentation is necessary to prevent the heavier EfficientNet backbone from memorizing rare samples.
*   **Batching**: Strictly utilize a **Small Batch Size (e.g., 64)**. As observed previously, larger batch sizes reduce the stochastic gradient noise that acts as an implicit regularizer, leading to overfitting on long-tail classes. We will prioritize the regularization benefits of small batches over the throughput benefits of large batches Cite {solution_lesson_node_00004}.

### Training
The training procedure will follow a strict **Two-Stage Curriculum** to manage the stability-plasticity trade-off:

1.  **Stage 1: Softmax Warmup (Plasticity Preservation)**
    *   **Objective**: Train using standard **CrossEntropy Loss** (ArcFace margin $m=0$).
    *   **Duration**: Train for a very short duration (e.g., **1 epoch**).
    *   **Rationale**: We must initialize the weights to a reasonable state to prevent the "Cold-Start Convergence Failure" inherent in margin-based losses Cite {solution_lesson_node_00001}. However, we will explicitly terminate this stage *before* the model converges or achieves high accuracy. This ensures the embeddings remain "plastic" and capable of being reshaped by the metric learning objective in the next stage Cite {solution_lesson_node_00003}.

2.  **Stage 2: Metric Fine-Tuning**
    *   **Objective**: Switch to **ArcFace Loss** (margin $m=0.5$, scale $s=30$).
    *   **Optimizer**: Use **AdamW** with a cosine decay learning rate schedule.
    *   **Rationale**: Once the feature space is roughly organized, the margin penalty is applied to enforce tight clustering.

### Evaluation
*   **Inference**: Pass test images through the EfficientNet backbone and GeM pooling layer to generate normalized embeddings.
*   **Prediction**: Calculate the **Cosine Similarity** between the test image embedding and the learned ArcFace class centers (weights of the final layer).
*   **Ranking**: Select the top 5 class IDs with the highest similarity scores. This method is computationally efficient as it avoids the need for a KNN search against the entire training set, using the class centers as robust proxies.
