2.  **Training Orchestration**: Instead of using the `Trainer.fit()` method (which unconditionally generates a submission), I will implement a custom training loop using `Trainer.train_epoch()` and `Trainer.validate()`. This allows precise control over the workflow and checkpointing.
3.  **Validation Metric (Levenshtein)**: I will implement a custom evaluation pass on the validation set. This involves:
    *   Running inference to get the predicted word and position.
    *   Reconstructing the predicted sentence and the ground-truth sentence.
    *   Calculating the Levenshtein distance between them using `nltk.metrics.edit_distance`.
    *   Computing the mean distance as the final metric.
4.  **Failure Analysis**: During the validation pass, I will collect metadata (sentence lengths, gap positions) and the corresponding error (Levenshtein distance). I will then compute and print the Pearson correlation between the error and these features to identify failure modes.
5.  **Conditional Submission**: I will check if the calculated Final Validation Metric is strictly lower than 7.70033. If satisfied, I will call `trainer.generate_submission()` to produce the `submission.csv` file.
