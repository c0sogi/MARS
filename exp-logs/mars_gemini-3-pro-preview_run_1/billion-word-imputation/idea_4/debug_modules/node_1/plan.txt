The issue stems from the fact that Python evaluates default argument values at function definition time (when the module is imported), not at call time. Although `runfile.py` updates the `Config` attributes to point to the demo directories, the `get_vocab` and `generate_submission` functions in the imported modules retain the original `Config` values that were captured when they were defined. As a result, `get_vocab` processes the full training set instead of the small demo set, and `generate_submission` saves to the wrong location, causing the subsequent assertion to fail. To fix this, we must explicitly pass the updated configuration values as arguments when calling these functions in `runfile.py`, overriding the stale defaults.
