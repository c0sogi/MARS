The implementation strategy involves orchestrating the training and evaluation pipeline using the provided library components while adhering to the specific constraints of the task.

1.  **Setup and Data Loading**: The script initializes the environment by setting seeds and suppressing warnings. It loads the training metadata first to check the dataset size; if the dataset is large (>50,000 samples), it reduces the number of epochs to ensure the "Fast Baseline" runtime constraint is met. It then utilizes `get_dataloaders` with `load_cached_data=True` to efficiently load the preprocessed data.
2.  **Model Initialization and Training**: The `TripleBranchDistilRoBERTa` model is instantiated and moved to the GPU. The optimizer is configured with differential learning rates (higher for the head, lower for the backbone) and parameter grouping (excluding bias/LayerNorm from weight decay). The training loop implements the specific schedule: freezing the backbone in the first epoch for head warmup, then unfreezing it for fine-tuning. The best model state (based on validation Spearman correlation) is saved.
3.  **Validation and Failure Analysis**: After training, the best model is reloaded. Inference is performed on the full validation set to compute the `Final Validation Metric`. A failure analysis follows, where the Mean Absolute Error (MAE) of the predictions is correlated with input text lengths (title, body, answer) to identify systematic errors.
4.  **Conditional Submission**: The script checks if the final validation metric exceeds the threshold `0.40802662717842303`. If satisfied, it runs inference on the test set, formats the predictions with `qa_id` and target columns, and saves the result to `submission.csv`.
