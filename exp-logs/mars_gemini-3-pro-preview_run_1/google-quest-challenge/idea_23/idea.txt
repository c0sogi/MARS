Based on the comprehensive analysis of the "Lessons Learned" and the trajectory of previous experiments, I propose the following optimized strategy.

# Model
I propose a **Shared-Bottom Partitioned-Pooling RoBERTa Dual-Encoder**.

This architecture represents a structural synthesis of the three most effective concepts identified in the lessons: **Partitioned Pooling** for hierarchical text handling (**Cite solution_lesson_node_00101**), **Shared-Bottom/Split-Top Encoders** to balance alignment with specialization (**Cite solution_lesson_node_00080**, **Cite solution_lesson_node_00076**), and **Residual Fusion** to preserve geometric signals (**Cite solution_lesson_node_00100**).

*   **Backbone Architecture:** Utilize **`roberta-base`** (12 layers).
    *   *Rationale:* This backbone provides the necessary capacity to model complex hierarchical dependencies in the Question text, outperforming distilled variants (**Cite solution_lesson_node_00077**).
*   **Shared-Bottom Split-Top Structure (Structural Innovation):**
    *   **Layers 0-9 (Shared):** The first 10 layers are shared between the Question and Answer branches. This anchors the representations in a unified metric space, guaranteeing the validity of downstream geometric interactions and preventing "Alignment Drift" (**Cite solution_lesson_node_00080**).
    *   **Layers 10-11 (Independent):** The top 2 layers are split into independent branches. This allows the model to learn specialized high-level semantic features for the disjoint target sets (Question Quality vs. Answer Relevance) without gradient interference (**Cite solution_lesson_node_00076**).
*   **Partitioned-Pooling:**
    *   **Question Branch:** Apply **Partitioned Pooling** to the output of the Question-Specific Layer 11. Use the tokenizer's special tokens to generate masks for the **Title** and **Body** segments. Extract $u_{title}$ (Intent) and $u_{body}$ (Context) separately (**Cite solution_lesson_node_00101**).
    *   **Answer Branch:** Apply Global Mean Pooling to the output of the Answer-Specific Layer 11 to extract $v_{answer}$.
*   **Granular Interaction Fusion:**
    *   Compute explicit geometric interactions (Element-wise Product and Absolute Difference) on the partitioned vectors (**Cite solution_lesson_node_00007**):
        1.  **Intent Matching:** $I_{intent} = [u_{title} \odot v_{answer}, |u_{title} - v_{answer}|]$.
        2.  **Context Matching:** $I_{context} = [u_{body} \odot v_{answer}, |u_{body} - v_{answer}|]$.
    *   Concatenate: $F = [u_{title}, u_{body}, v_{answer}, I_{intent}, I_{context}, \text{Max\_Pools}]$.
    *   Apply **Layer Normalization** to $F$ (**Cite solution_lesson_node_00009**).
*   **Residual Interaction Head:**
    *   Utilize the **Residual Projection Block**.
    *   Architecture: $Output = \text{Linear}(\text{Concat}(F, \text{Dropout}(\text{ReLU}(\text{Linear}(F)))))$.
    *   This preserves the raw granular signals via a skip connection while enabling non-linear feature mixing (**Cite solution_lesson_node_00027**, **Cite solution_lesson_node_00100**).
    *   **Monolithic Output:** Predict all 30 targets simultaneously (**Cite solution_lesson_node_00016**).

# Data
*   **Preprocessing:**
    *   **Question Stream:** Use `tokenizer(question_title, question_body)`. This leverages the tokenizer's native separator insertion (`[CLS] Title [SEP] Body [SEP]`) to preserve the semantic boundary (**Cite solution_lesson_node_00070**).
    *   **Answer Stream:** Use `tokenizer(answer)`. Do not inject the Title here to avoid redundancy and truncation (**Cite solution_lesson_node_00063**).
    *   **Metadata:** Exclude categorical metadata to prevent shortcut learning (**Cite solution_lesson_node_00039**, **Cite solution_lesson_node_00049**).
*   **Tokenization:** Use the `roberta-base` tokenizer.
*   **Dynamic Padding:** Pad sequences to the longest length in the batch to optimize throughput (**Cite solution_lesson_node_00018**).

# Training
*   **Phantom Scheduling (Strategic Retention):**
    *   **Configuration:** Initialize the Learning Rate Scheduler with a total duration of **7 epochs**.
    *   **Execution:** Explicitly terminate training after **3 epochs**.
    *   *Rationale:* `roberta-base` peaks at Epoch 3 on this dataset (**Cite solution_lesson_node_00077**). "Phantom Scheduling" ensures the decay profile remains optimal for fine-tuning, avoiding the underfitting caused by compressing the schedule (**Cite solution_lesson_node_00078**).
*   **Gradient Accumulation:** Set physical batch size to **8** and accumulate gradients (steps=2) to achieve an **effective batch size of 16**, ensuring stability without exceeding GPU memory (**Cite solution_lesson_node_00022**).
*   **Differential Learning Rates:** Apply a high learning rate (`1e-3`) to the Head and a low learning rate (`2e-5`) to the Backbone (Shared + Split layers) (**Cite solution_lesson_node_00015**).
*   **Head Warmup:** Freeze the entire backbone (Shared + Split) for the first epoch. Train only the head (**Cite solution_lesson_node_00050**).
*   **Continuous Schedule:** Do not reset the optimizer after warmup; allow momentum to carry over (**Cite solution_lesson_node_00019**).
*   **Loss Function:** Binary Cross Entropy (BCE) with Logits Loss.

# Evaluation
*   **Inference:** Pass the test set through the model, applying the partitioned pooling logic to the Question branch.
*   **Prediction:** Apply Sigmoid activation to the 30 output logits.
*   **Validation:** Monitor Mean Column-wise Spearman's Correlation, expecting peak performance at Epoch 3.
