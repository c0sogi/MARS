This implementation strategy focuses on demonstrating the complete pipeline provided by the library files while ensuring rapid execution and correctness verification.

1.  **Configuration Override**: We will dynamically modify the `Config` class attributes to set up a "demo" environment. This includes reducing the maximum sequence length (`MAX_LEN`) to 32, batch sizes to 4/8, and setting epochs to 1. This ensures the code runs in seconds rather than hours. We also redirect the `WORKING_DIR` to a unique path to avoid conflicts with existing caches.
2.  **Metric Verification**: We will explicitly test the `compute_spearmanr` function with synthetic data (perfectly correlated and inversely correlated vectors) to assert that the metric calculation logic functions as expected.
3.  **Component Testing**: Before running the full engine, we will instantiate the `QuestDataset` and `SymmetricDualEncoder` separately. We will fetch a single batch and pass it through the model to verify input/output shapes (ensuring the model outputs 30 probabilities per sample).
4.  **Full Pipeline Execution**: We will utilize the `run_training(debug=True)` function from `library.engine`. This function orchestrates data loading (using a small subset due to `debug=True`), model initialization, training, evaluation, and submission generation.
5.  **Output Verification**: Finally, we will verify that the submission file is created and follows the expected format.
