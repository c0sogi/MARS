The issue is a mismatch between the model architecture and the data pipeline. The `QuestModel` is currently defined as a Dual Encoder (Siamese) network expecting separate inputs for questions and answers (`input_ids_q`, `input_ids_a`, etc.), but the data pipeline (`process_text_data`) and training engine (`train_fn`) are set up for a Single Encoder architecture that concatenates the question and answer into one sequence with partition masks. Additionally, the `runfile.py` contains a manual inference loop that incorrectly attempts to unpack Dual Encoder keys from the dataloader, which will cause a `KeyError` or `TypeError` later in the execution (Cite debug_lesson_4).

To fix this:
1.  Update `library/model.py` to change the `forward` method signature to accept `input_ids`, `attention_mask`, `question_mask`, and `answer_mask`. The implementation will run the backbone once on the concatenated input and use the masks to pool the question and answer representations separately.
2.  Update `runfile.py` to align the manual failure analysis loop with the actual keys provided by the `val_loader` (`input_ids`, `question_mask`, etc.) and the corrected model signature.
