Based on the comprehensive analysis of the "Lessons Learned" and the trajectory of previous experiments, I propose the following optimized strategy.

# Model
I propose a **Hybrid-Depth Asymmetric Dual-Encoder**.

This architecture introduces a **Structural Innovation** by assigning different model capacities to the two branches of the Siamese network. It synthesizes the performance benefits of the deeper `roberta-base` backbone (**Cite solution_lesson_node_00077**) with the efficiency and regularization benefits of the `distilroberta-base` backbone (**Cite solution_lesson_node_00023**), tailored to the specific information density of the inputs.

*   **Asymmetric Backbone Architecture:**
    *   **Question Branch:** Utilize **`roberta-base`** (12 layers, ~125M params).
        *   *Rationale:* The Question input contains complex hierarchical structures (Title vs. Body) and determines the ground truth for 21 of the 30 target labels. Previous experiments proved that `roberta-base` captures these dependencies better than distilled models, particularly for longer sequences (**Cite solution_lesson_node_00077**).
    *   **Answer Branch:** Utilize **`distilroberta-base`** (6 layers, ~82M params).
        *   *Rationale:* The Answer input is structurally simpler (single text block) and primarily informs only 9 relational targets. Using a distilled model here reduces the parameter space, mitigating the rapid overfitting observed with the full 2x `roberta-base` setup (**Cite solution_lesson_node_00077**) and freeing up GPU memory to maintain a healthy batch size (**Cite solution_lesson_node_00022**).
    *   *Compatibility:* Both models share the same hidden dimension ($H=768$), allowing for seamless fusion without projection artifacts.
*   **Independent Encoders:** Maintain the "Asymmetric" design where weights are **not** shared between the branches. This isolates the optimization objectives for the disjoint label sets (Question-centric vs. Answer-centric), preventing gradient interference (**Cite solution_lesson_node_00076**).
*   **Masked Hybrid Pooling:** Apply **Masked Global Average and Max Pooling** to the final hidden state of both branches (**Cite solution_lesson_node_00003**).
*   **Interaction-Aware Fusion:**
    *   Compute explicit interactions (Element-wise Product and Absolute Difference) *only* on the **Average Pooled** vectors (**Cite solution_lesson_node_00007**).
    *   Construct the Fused Vector $F = [u_{avg}, u_{max}, v_{avg}, v_{max}, u_{avg} \odot v_{avg}, |u_{avg} - v_{avg}|]$.
    *   Apply **Layer Normalization** to $F$ (**Cite solution_lesson_node_00009**).
*   **Residual Interaction Head:**
    *   Utilize the **Residual Projection Block** identified as the optimal head design (**Cite solution_lesson_node_00076**).
    *   Architecture: $Output = \text{Linear}(\text{Concat}(F, \text{Dropout}(\text{ReLU}(\text{Linear}(F)))))$.
    *   This preserves raw interaction signals while allowing for non-linear feature mixing (**Cite solution_lesson_node_00027**).
    *   **Monolithic Output:** Predict all 30 targets simultaneously to leverage inter-label correlations (**Cite solution_lesson_node_00016**).

# Data
*   **Preprocessing:**
    *   **Question Stream:** Use the tokenizer's native pairing function: `tokenizer(question_title, question_body)`. This inserts special separators (`[CLS] Title [SEP] Body [SEP]`) to explicitly preserve the semantic boundary between intent and context (**Cite solution_lesson_node_00070**).
    *   **Answer Stream:** Use `tokenizer(answer)`. Do not inject the Title here, as it causes redundant truncation (**Cite solution_lesson_node_00063**).
    *   **Metadata:** Exclude categorical metadata to prevent shortcut learning (**Cite solution_lesson_node_00039**, **Cite solution_lesson_node_00049**).
*   **Tokenization:** Use the `roberta-base` tokenizer (which is compatible with `distilroberta`).
*   **Dynamic Padding:** Pad sequences to the longest length in the batch to optimize throughput (**Cite solution_lesson_node_00018**).

# Training
*   **Phantom Scheduling (Strategic Retention):**
    *   **Configuration:** Initialize the Learning Rate Scheduler with a total duration of **7 epochs**.
    *   **Execution:** Explicitly terminate training after **3 epochs**.
    *   *Rationale:* Previous experiments showed that `roberta-base` peaks at Epoch 3 and then overfits (**Cite solution_lesson_node_00077**). However, simply configuring the scheduler for 3 epochs compresses the decay curve, causing underfitting (**Cite solution_lesson_node_00078**). "Phantom Scheduling" preserves the gentle decay profile required for optimal fine-tuning while respecting the early stopping point.
*   **Gradient Accumulation:** Set the physical batch size to fit in memory (e.g., 8) and accumulate gradients to achieve an **effective batch size of 16**. This ensures gradient stability without "starving" the batch (**Cite solution_lesson_node_00022**).
*   **Differential Learning Rates:** Apply a high learning rate (`1e-3`) to the Head and a low learning rate (`2e-5`) to both Backbones (**Cite solution_lesson_node_00015**).
*   **Head Warmup:** Freeze both backbones for the first epoch. Train only the head to align random weights before unfreezing (**Cite solution_lesson_node_00050**).
*   **Continuous Schedule:** Do not reset the optimizer or scheduler after the warmup epoch; allow momentum to carry over (**Cite solution_lesson_node_00019**).
*   **Loss Function:** Binary Cross Entropy (BCE) with Logits Loss.

# Evaluation
*   **Inference:** Pass the test set through the hybrid model.
*   **Prediction:** Apply Sigmoid activation to the 30 output logits.
*   **Validation:** Monitor Mean Column-wise Spearman's Correlation. Accept the model if it exceeds the previous best (`~0.4113`) plus a small noise margin, expecting the peak at Epoch 3 (**Cite solution_lesson_node_00077**).
