Based on the comprehensive analysis of previous experiments and the accumulated "Lessons," I propose the following optimized strategy.

# Model
I propose a **Text-Augmented DistilRoBERTa Dual-Encoder with Gated Feature Fusion**. This architecture synthesizes the robust efficiency of the `distilroberta` backbone with a novel feature engineering paradigm (Textual Metadata Injection) and an advanced non-linear fusion mechanism to resolve the limitations of previous simple concatenation strategies.

*   **Backbone Architecture:** Utilize **`distilroberta-base`**.
    *   *Rationale:* This backbone (82M params) strikes the optimal balance between capacity and trainability for this specific dataset size (~4,400 samples). It avoids the "Starved Batch" instability observed with `deberta-v3-base` (**Cite solution_lesson_node_00022**) and provides significantly higher representational capacity than the smaller `deberta-v3-small`, which suffered from information bottlenecks (**Cite solution_lesson_node_00045**, **Cite solution_lesson_node_00023**).
*   **Dual-Branch Structure:** Maintain the Siamese design, processing the "Question" and "Answer" streams independently. This ensures the model accommodates the full length of both inputs without the truncation issues of Single-Encoders (**Cite solution_lesson_node_00032**) and prevents context leakage that degrades intrinsic question labels (**Cite solution_lesson_node_00030**).
*   **Textual Metadata Injection (Structural Innovation):** Instead of learning separate embedding layers for `category` and `host` (which failed due to overfitting/noise, **Cite solution_lesson_node_00039**), inject this metadata directly into the text stream.
    *   Prefix the Question input with natural language markers: `"Category: [category]. Host: [host]. [Title]..."`.
    *   *Benefit:* This leverages the pre-trained backbone's existing semantic knowledge to interpret domain indicators (e.g., "StackOverflow" implies technical/code context) without introducing new, randomly initialized parameters that require extensive training.
*   **Masked Hybrid Pooling:** Apply **Masked Global Average and Max Pooling** to the final hidden state of both branches (**Cite solution_lesson_node_00003**).
*   **Interaction-Aware Fusion:**
    1.  Compute explicit interactions (Element-wise Product and Absolute Difference) *only* on the **Average Pooled** vectors to capture semantic alignment (**Cite solution_lesson_node_00007**).
    2.  Concatenate the components: $[u_{avg}, u_{max}, v_{avg}, v_{max}, u_{avg} \odot v_{avg}, |u_{avg} - v_{avg}|]$.
    3.  Apply **Layer Normalization** to the fused vector (**Cite solution_lesson_node_00009**).
*   **Gated Fusion Head (Structural Innovation):** Replace the standard MLP with a **Gated Residual Network**.
    *   *Mechanism:* The fused vector $x$ is passed through a gating branch ($\sigma(W_g x + b_g)$) and a feature branch ($\text{GELU}(W_f x + b_f)$). The output is computed as $x + \text{Dropout}(\text{Gate} \odot \text{Feature})$.
    *   *Benefit:* This addresses the need for a non-linear head (**Cite solution_lesson_node_00027**) while explicitly allowing the model to suppress irrelevant interaction features (e.g., ignoring "answer relevance" signals when predicting "question well-written" targets), effectively emulating the benefits of decoupled heads without losing the inter-label correlations of a monolithic head (**Cite solution_lesson_node_00016**).

# Data
*   **Preprocessing:**
    *   **Question Branch:** Construct the string: `f"Category: {category}. Host: {host}. {question_title} {question_body}"`.
    *   **Answer Branch:** Use `answer`.
*   **Tokenization:** Use the `distilroberta-base` tokenizer.
*   **Dynamic Padding:** Pad sequences to the longest length in the batch to optimize training speed (**Cite solution_lesson_node_00018**).

# Training
*   **Differential Learning Rates:** Apply a high learning rate (`1e-3`) to the Gated Fusion Head and a low learning rate (`2e-5`) to the backbone. This ensures the complex head learns effective projections without destabilizing the pre-trained features (**Cite solution_lesson_node_00015**).
*   **Parameter Grouping:** Explicitly exclude `bias` and `LayerNorm` parameters from weight decay in the AdamW optimizer to prevent underfitting (**Cite solution_lesson_node_00018**).
*   **Batch Size:** Use a batch size of **16**. The `distilroberta` backbone fits comfortably in memory at this size, ensuring stable gradient estimation and better generalization than larger batches (**Cite solution_lesson_node_00012**).
*   **Schedule:** Train for **5 epochs** using a continuous linear decay schedule with warmup. Do not reset the optimizer after the initial warmup; allow momentum to carry over (**Cite solution_lesson_node_00019**, **Cite solution_lesson_node_00011**).
*   **Regularization:** Use standard Dropout ($p=0.1$) within the head. Avoid aggressive Multi-Sample Dropout ($p=0.5$) which induces convergence latency in short training windows (**Cite solution_lesson_node_00042**).
*   **Loss Function:** Binary Cross Entropy (BCE) with Logits Loss on the monolithic 30-target output.

# Evaluation
*   **Inference:** Pass the test data (Text + Metadata Prefixes) through the model.
*   **Prediction:** Apply Sigmoid activation to the 30 output logits.
*   **Validation:** Monitor Mean Column-wise Spearman's Correlation. Accept the model if it exceeds the previous best (`~0.408`) plus a small noise margin (**Cite solution_lesson_node_00010**).
