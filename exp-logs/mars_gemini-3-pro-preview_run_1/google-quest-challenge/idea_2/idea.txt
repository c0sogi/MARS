Based on the lessons learned from the Deep Averaging Network (DAN) experiments, I propose a structural evolution that transitions from static word embeddings to **contextualized representations** while rigorously preserving the architectural optimizations identified in previous trials.

# Model
I propose a **Contextual Dual-Encoder with Hybrid Pooling and Explicit Interactions**.

*   **Backbone Architecture:** Replace the static embedding layer of the previous DAN with a lightweight pre-trained **Transformer** (e.g., `distilroberta-base` or `all-MiniLM-L6-v2`). This introduces a fundamental structural change: instead of averaging context-agnostic word vectors, the model aggregates dynamic, context-aware token embeddings, allowing it to capture nuances like "well-written" or "sarcasm" that Bag-of-Words models miss.
*   **Dual-Branch Strategy:** Retain the **Dual-Branch** design, processing the "Question" (Title + Body) and "Answer" text streams independently through the Transformer. This ensures that the distinct semantic properties of questions (intent) and answers (solution quality) are preserved before fusion. Cite Lesson 00001.
*   **Hybrid Pooling Mechanism:** Apply **Masked Dual-Pooling** to the sequence of hidden states output by the Transformer. For both the Question and Answer branches, compute:
    1.  **Masked Global Average Pooling:** To capture the overall semantic "gist".
    2.  **Global Max Pooling:** To capture salient features and discriminative keywords.
    *Note: This replaces the standard `[CLS]` token usage often found in Transformers, leveraging the lesson that dual-pooling provides a richer signal for regression tasks.* Cite Lesson 00003.
*   **Interaction-Aware Fusion:** Construct the input to the final Multi-Layer Perceptron (MLP) by concatenating the pooled vectors with specific interaction terms. Crucially, apply **Explicit Interaction Heuristics** (Element-wise Product and Absolute Difference) *only* to the **Average Pooled** representations. The Max Pooled vectors should be concatenated as raw features but excluded from interaction calculations to avoid introducing noise. Cite Lesson 00004, Cite Lesson 00007.

# Data
*   **Tokenization:** Use the specific tokenizer associated with the chosen pre-trained Transformer backbone.
*   **Input Formatting:** Concatenate `question_title` and `question_body` into a single sequence for the Question branch, and use `answer` for the Answer branch.
*   **Masking:** Generate binary attention masks to ensure that padding tokens are strictly excluded from the Average Pooling calculation, preventing signal dilution. Cite Lesson 00003.
*   **Truncation:** Set a maximum sequence length (e.g., 512 tokens) to optimize GPU memory usage while retaining the majority of the content.

# Training
*   **Loss Function:** Use **Binary Cross Entropy (BCE) with Logits Loss** to optimize the 30 continuous target probabilities.
*   **Optimizer:** Utilize **AdamW** with weight decay to prevent overfitting the high-dimensional Transformer parameters.
*   **Strategy:** Implement a **Gradual Unfreezing** strategy.
    1.  **Warmup:** Train only the custom pooling layers and the MLP head for the first epoch while keeping the Transformer backbone frozen.
    2.  **Fine-tuning:** Unfreeze the backbone and train the entire model with a lower learning rate (e.g., 2e-5) and a linear decay schedule.
*   **Regularization:** Apply dropout within the MLP head and standard Transformer dropout.

# Evaluation
*   **Inference:** Pass the tokenized test set through the fine-tuned Dual-Encoder.
*   **Prediction:** The model will output logits for 30 classes; apply a **Sigmoid** activation to map these to the [0, 1] probability range required for submission.
*   **Metric:** Monitor the Mean Column-wise Spearman's correlation on the validation set to select the best checkpoint.
