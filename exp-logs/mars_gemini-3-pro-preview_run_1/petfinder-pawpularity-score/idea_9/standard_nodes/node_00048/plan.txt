The issue is a broken data contract: the `PetDataset` class was modified to stop yielding the `local_view` key (to prioritize expert tuning), but the downstream consumers—`FeatureExtractor` and `StackingEngine`—were not updated to reflect this change. This causes a `KeyError: 'local_view'` in `FeatureExtractor` and would cause `FileNotFoundError` or logic errors in `StackingEngine` if it tried to load non-existent local features.

To fix this, I will:
1.  Update `library/feature_extraction.py` to remove all logic related to processing, storing, and saving `local_view` features (Cite debug_lesson_8).
2.  Update `library/stacking_engine.py` to stop loading `local` view features in `load_data` and remove `local` view configurations from the expert definitions in `train_level0`.
3.  Enhance the cache validation in `StackingEngine.train_level0` to check the number of experts (columns in the OOF matrix). This ensures that if a stale cache exists (with 18 experts from the previous 2-view configuration), it is invalidated and recomputed for the new 9-expert (1-view) configuration (Cite debug_lesson_5).
