The issue is that the `PetDataset` class in `library/data_loader.py` was modified to stop producing the `local_view` output (returning a dictionary without that key), but the downstream consumers—specifically `FeatureExtractor` and `StackingEngine`—were not updated to reflect this interface change. The `FeatureExtractor` crashes with a `KeyError` when attempting to access `batch["local_view"]`.

To fix this, I will remove all references to the "local" view in the feature extraction and stacking logic. This ensures the pipeline aligns with the current data provider interface (Cite debug_lesson_2). Specifically:
1.  In `library/feature_extraction.py`, I will remove the code that defines local feature paths, extracts local features from the batch, and saves them to disk.
2.  In `library/stacking_engine.py`, I will update the data loading and expert configuration loops to only process the "global" view, preventing the engine from looking for non-existent local features.
