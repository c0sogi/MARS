The issue stems from the cache validation logic in `library/feature_extraction.py`, which checks the length of a shared `ids.npy` file rather than the backbone-specific feature files. Because `ids.npy` is overwritten by each backbone sequentially, it can reflect the correct dataset size (from a successfully processed backbone like CLIP) while the feature file for a subsequent backbone (like ConvNeXt) remains stale and incorrect (e.g., from a debug run). To fix this, I will modify the validation step to check the dimensions of the backbone-specific global feature file (`file_map["global"]`). This ensures that the actual artifact being loaded matches the current runtime configuration (Cite debug_lesson_5).
