Based on the comprehensive analysis of the previous experiments and the derived lessons, I propose the following optimized strategy. This solution implements a **Progressive Resolution Ensemble** of **DenseNet121** models. This approach leverages the proven efficacy of the DenseNet architecture for this specific dataset while addressing the variance inherent in few-shot learning through ensembling and optimizing feature extraction through a multi-stage resolution curriculum.

# Model
I propose an **Ensemble of DenseNet121 models**, each equipped with a **Projected ArcFace Head**.

*   **Backbone:** **DenseNet121**.
    *   *Rationale:* Previous experiments confirmed that the dense connectivity of this architecture significantly outperforms modern isotropic designs (like ConvNeXt) and deeper variants (like DenseNet169) in this high-cardinality, few-shot regime. It strikes the optimal balance between capacity and inductive bias for feature reuse **Cite solution_lesson_node_00016, solution_lesson_node_00020**.
*   **Pooling:** **Global Average Pooling (GAP)**.
    *   *Rationale:* We retain GAP and explicitly reject specialized pooling layers like GeM, which were shown to overfit to background artifacts in this dataset **Cite solution_lesson_node_00010**.
*   **Neck:** **Projection Head**.
    *   *Structure:* `Batch Normalization` $\to$ `Dropout` $\to$ `Linear (Features $\to$ 512)` $\to$ `Batch Normalization`.
    *   *Rationale:* This learnable bottleneck is critical for adapting the semantic features of the pre-trained backbone to the geometric constraints of the ArcFace loss, preventing the underfitting observed when it was omitted **Cite solution_lesson_node_00015**.
*   **Head:** **ArcFace (Additive Angular Margin)**.
    *   *Rationale:* This loss function enforces intra-class compactness, which is superior to Cross-Entropy for distinguishing between thousands of subtly different whale identities **Cite solution_lesson_node_00012**.
*   **Ensemble Structure:** The final model will consist of **3 to 5 independently trained instances** of the architecture described above. Each instance will be initialized with a different random seed to capture diverse feature representations.

# Data
*   **Splitting Strategy:** Strictly maintain the **Singleton-Inclusive Split**. All classes with only 1 sample must be included in the training set to prevent zero-shot validation errors **Cite solution_lesson_node_00002**.
*   **Augmentation:**
    *   **Geometric:** Apply **Conservative** Affine transformations (Rotation $\pm 20^\circ$, Scale 0.9-1.1) and Horizontal Flips. Aggressive distortions are avoided to preserve feature integrity **Cite solution_lesson_node_00014**.
    *   **Photometric:** Apply Brightness and Contrast adjustments only. Explicitly **exclude** Saturation and Hue jitter, as chromatic noise degrades performance in this domain **Cite solution_lesson_node_00004**.
*   **Resolution Strategy:** Implement **Progressive Resizing** (detailed in Training).
    *   *Rationale:* This addresses the trade-off where 224x224 loses detail **Cite solution_lesson_node_00005** while 448x448 induces overfitting **Cite solution_lesson_node_00007**.

# Training
I propose a **Multi-Stage Progressive Training Pipeline** for each model in the ensemble:

1.  **Stage 1 (Coarse Tuning):** Train the model on images resized to **256x256**.
    *   *Objective:* Allow the model to learn robust global features and converge quickly without overfitting to high-frequency noise.
    *   *Duration:* ~8-10 Epochs.
2.  **Stage 2 (Fine Tuning):** Fine-tune the model on images resized to **320x320**.
    *   *Objective:* Refine the decision boundaries using the optimal resolution identified in previous lessons **Cite solution_lesson_node_00008**.
    *   *Duration:* ~4-6 Epochs with a reduced learning rate.
3.  **Optimization:**
    *   **Loss:** **ArcFace Loss**.
    *   **Regularization:** Explicitly **disable** Label Smoothing to maintain sharp gradient signals for singleton classes **Cite solution_lesson_node_00013**.
    *   **Optimizer:** **AdamW**.
    *   **Scheduler:** **Cosine Annealing** (restarted or continued for Stage 2).

# Evaluation
*   **Protocol:** Implement **Test-Time Augmentation (TTA)** using Horizontal Flips for **both** the validation loop and final inference.
    *   *Rationale:* Consistency between validation and inference is crucial for accurate model selection **Cite solution_lesson_node_00011**.
*   **Ensemble Inference:**
    *   For each test image, generate embeddings (or logits) from all models in the ensemble using both the original and horizontally flipped versions.
    *   Average the resulting feature vectors/logits.
    *   Compute the cosine similarity against the class centers (if using embeddings) or apply Softmax (if using logits).
    *   Select the top 5 `Id`s for the submission.
