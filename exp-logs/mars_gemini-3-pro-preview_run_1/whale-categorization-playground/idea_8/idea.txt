Based on the comprehensive analysis of the previous experiments and the derived lessons, I propose the following optimized strategy. This solution implements a **Homogeneous Ensemble of DenseNet121 Models** with **Projected ArcFace Heads**. This approach leverages the proven architectural superiority of DenseNet121 for this specific dataset while addressing the high variance and overfitting risks inherent in few-shot/singleton classification through ensembling and strict regularization.

# Model
I propose an **Ensemble of 5 independent DenseNet121 models**.
*   **Backbone:** **DenseNet121**.
    *   *Rationale:* Previous experiments confirmed that the dense connectivity of this architecture significantly outperforms modern isotropic designs (like ConvNeXt) and deeper variants (like DenseNet169) in this high-cardinality, few-shot regime. It strikes the optimal balance between capacity and inductive bias for feature reuse **Cite solution_lesson_node_00016, solution_lesson_node_00020**.
*   **Pooling:** **Global Average Pooling (GAP)**.
    *   *Rationale:* We retain GAP and explicitly reject specialized pooling layers like GeM, which were shown to overfit to background artifacts in this dataset **Cite solution_lesson_node_00010**.
*   **Neck (Structural Retention):** **Projection Head**.
    *   *Structure:* A learnable bottleneck layer (Linear $\to$ Batch Normalization) inserted between the pooling layer and the ArcFace head.
    *   *Rationale:* This layer is critical for adapting the semantic features of the pre-trained backbone to the geometric constraints of the ArcFace loss, preventing the underfitting observed when it was omitted **Cite solution_lesson_node_00015**.
*   **Head:** **ArcFace (Additive Angular Margin)**.
    *   *Rationale:* This loss function enforces intra-class compactness, which is superior to Cross-Entropy for distinguishing between thousands of subtly different whale identities **Cite solution_lesson_node_00012**.

# Data
*   **Splitting Strategy:** Strictly maintain the **Singleton-Inclusive Split**. All classes with only 1 sample must be included in the training set to prevent zero-shot validation errors **Cite solution_lesson_node_00002**.
*   **Resolution:** Standardize input size to **320x320** (Constant).
    *   *Rationale:* This resolution offers the optimal trade-off. We explicitly reject **Progressive Resizing** (starting small) as it destroys critical details early in training **Cite solution_lesson_node_00023**. We also reject 448x448 as it induces overfitting **Cite solution_lesson_node_00007**.
*   **Augmentation:**
    *   **Geometric:** Apply **Conservative** Affine transformations (Rotation $\pm 20^\circ$, Scale 0.9-1.1) and Horizontal Flips. Aggressive distortions are avoided to preserve feature integrity **Cite solution_lesson_node_00014**.
    *   **Photometric:** Apply Brightness and Contrast adjustments only. Explicitly **exclude** Saturation and Hue jitter, as chromatic noise degrades performance in this domain **Cite solution_lesson_node_00004**.

# Training
*   **Ensemble Strategy:** Train **5 separate instances** of the model described above. Each instance will be initialized with a different random seed to capture diverse feature representations and settle in different local minima, mitigating the variance caused by singleton classes.
*   **Loss Function:** **ArcFace Loss**.
*   **Regularization:** **Enable Label Smoothing (0.1)**.
    *   *Rationale:* Unlike Idea 4 which failed by removing it, we must retain Label Smoothing. It acts as a vital regularizer for singleton classes, preventing the model from overfitting to the specific artifacts of the single training example **Cite solution_lesson_node_00024**.
*   **Optimizer:** **AdamW** for effective weight decay.
*   **Scheduler:** **Cosine Annealing** learning rate scheduler to ensure smooth convergence **Cite solution_lesson_node_00003**.

# Evaluation
*   **Protocol:** Implement **Test-Time Augmentation (TTA)** using Horizontal Flips for **both** the validation loop and final inference.
    *   *Rationale:* Consistency between validation and inference is crucial for accurate model selection **Cite solution_lesson_node_00011**.
*   **Prediction:**
    1.  For each test image, generate the embedding/logits from **all 5 models** in the ensemble using both original and flipped versions.
    2.  Average the outputs across all models and TTA views.
    3.  Select the top 5 `Id`s based on the averaged scores.
