The previous implementation suffered from **Data Leakage**, causing an invalid validation metric (~1.0). The `StackingTrainer` merged the hold-out validation set with the training set to perform Cross-Validation. Consequently, the "Out-Of-Fold" (OOF) predictions used to train the meta-learner included predictions for the validation set. Evaluating the meta-learner on this same validation set violated the independence assumption.

To fix this, I will strictly isolate the validation set, treating it as a pure hold-out set.
1.  **`library/config.py`**: Add cache keys for validation data to support separate loading.
2.  **`library/stacking.py`**:
    *   Modify `load_all_data` to load validation data into separate arrays (`self.val_imgs`, etc.) without merging it into the training set.
    *   Update `get_base_model_predictions` and `_train_single_fold` to generate predictions for this hold-out validation set using the models trained on the training folds. These predictions will be saved to `val_predictions.parquet`.
3.  **`runfile.py`**: Update the validation analysis to load predictions from `val_predictions.parquet` instead of extracting them from the OOF set.
