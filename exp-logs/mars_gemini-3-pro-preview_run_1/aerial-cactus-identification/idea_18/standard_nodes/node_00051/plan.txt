The `InvalidMetricValueError` with a perfect AUC of 1.0 is caused by **data leakage**. The `load_all_data` method in `library/stacking.py` merges the validation set into the training set to perform Cross-Validation, but the pipeline subsequently uses that same validation set as a "hold-out" set for final evaluation. Since the models encounter the validation samples during training (within the CV folds), the final evaluation metric is artificially inflated and invalid.

To fix this, I will modify `library/stacking.py` to:
1.  Remove the code block that concatenates the validation data (`val_imgs`, etc.) into the training data (`self.train_imgs`, etc.) in `load_all_data`. This ensures strict isolation between the training set used for CV and the hold-out validation set.
2.  Update the log message to reflect that validation data is kept separate.
3.  Force `load_cached_data=False` in the `run` method to prevent loading previously cached predictions that were generated using the leaked data.

These changes apply **Debug Lesson 11: Enforce Strict Isolation Between Training and Hold-Out Validation Sets**.
