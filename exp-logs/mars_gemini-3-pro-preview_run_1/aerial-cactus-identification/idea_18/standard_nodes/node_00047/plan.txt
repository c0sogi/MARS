The `RuntimeError` occurs because the directory structure for saving checkpoints (`./working/idea_18/checkpoints`) is not created before the `torch.save` call is executed. Although `Config.setup_directories` exists, it is not invoked in the execution flow, and the `StackingTrainer` only creates the root working directory. To resolve this robustly, I will implement "just-in-time" directory creation within the `save_checkpoint` function in `library/utils.py`. This ensures that the parent directory for any given checkpoint path is guaranteed to exist immediately before the write operation, preventing the error regardless of initialization order.
