The following script demonstrates the usage of the provided library components to solve the cactus classification task.

**Implementation Strategy:**

1.  **Configuration Override**: We first modify the global `Config` class to set up a "Demo Mode". This involves changing the working directory to avoid conflicts, reducing the number of epochs to 1, reducing the number of cross-validation folds to 2, and selecting a single model architecture ("RepVGG_Spatial") instead of the full ensemble. This ensures the script runs quickly (under a few minutes).

2.  **Component Verification (Unit Testing)**:
    *   **Dataset**: We manually instantiate the `CactusDataset` with a small set of random data to verify that the `__getitem__` method correctly returns the image tensors, labels, and meta-features (FiLM normalization and MTL log targets) with the expected shapes and types.
    *   **Model**: We instantiate the `CactusModel` and perform a forward pass with the dummy data. We assert that the output contains both classification logits and auxiliary regression predictions (MTL) and that their shapes match the batch size.

3.  **Pipeline Execution (Integration Testing)**:
    *   We utilize the high-level `StackingTrainer` class to orchestrate the pipeline.
    *   **Data Loading**: We call `load_all_data()` to load the real images and metadata.
    *   **Data Truncation**: To strictly adhere to the time limit and "Optimize for Speed" requirement, we manually truncate the loaded arrays within the trainer instance to 200 samples. This allows us to verify the entire training, validation, and stacking logic without waiting for the full dataset to process.
    *   **Training & Inference**: We execute the core methods: `get_base_model_predictions` (Level 0 training), `train_meta_learner` (Level 1 stacking), and `generate_submission`.
    *   **Validation**: Finally, we check that the submission file and intermediate artifacts (OOF predictions) are successfully created.
