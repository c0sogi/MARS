The issue is a `torch.OutOfMemoryError` caused by the persistence of GPU memory allocations from the first training stage (`train_tagger`) into the second stage (`train_seq2seq`). Despite Python's garbage collection, internal PyTorch references (like those in DataLoaders or tracebacks) often prevent CUDA memory from being released within the same process.

To fix this, I will isolate each training stage in its own operating system process using `multiprocessing`. This ensures that when the first training process terminates, the OS forcibly reclaims all associated GPU resources, providing a clean memory state for the second model. I will define wrapper functions in `runfile.py` to ensure the configuration overrides are correctly applied in the child processes.
