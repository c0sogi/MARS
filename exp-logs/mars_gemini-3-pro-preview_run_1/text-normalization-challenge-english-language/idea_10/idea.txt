Based on the accumulated lessons and the analysis of previous iterations, I propose the **Quad-Hybrid Bi-LSTM Tagger with Explicit Features and Transformer Fallback**.

This solution represents a structural evolution of the "Multi-Granularity" approach (Idea 9) by integrating **Explicit Morphological Features** to guarantee the detection of rare entity patterns (addressing Lesson 00009) and solidifying the **Transformer-Based Fallback** (addressing Lesson 00027).

### Model
The architecture follows the decoupled "Classify-Retrieve-Generate" paradigm **Cite {solution_lesson_node_00005}**, splitting the task into semantic classification and conditional normalization.

1.  **Stage 1: Quad-Hybrid Bi-LSTM Tagger (Classification)**
    *   **Structural Innovation (Input):** To maximize **Input Fidelity** **Cite {solution_lesson_node_00009}** and ensure robust handling of rare classes, we employ a **Quad-Hybrid Input Representation**:
        1.  **Word Embeddings:** A trainable embedding layer with a maximized vocabulary size to capture high-level semantics.
        2.  **Character-Level CNN:** A 1D-CNN processing character sequences to extract learned morphological features (e.g., suffixes, capitalization).
        3.  **Subword (BPE) Embeddings:** We introduce **Byte-Pair Encoding (BPE)** embeddings (mean-pooled for the token). Unlike word embeddings which map rare words to `<UNK>`, BPE captures meaningful semantic units (e.g., "micro", "biology") for OOV terms, ensuring the model has a valid representation for *every* token.
        4.  **Explicit Morphological Features:** A dense vector of binary flags derived from **Regex Matching** (e.g., `is_digit`, `is_date_format`, `has_currency_symbol`, `is_capitalized`). This "Wide and Deep" approach forces the model to attend to specific lexical cues that define rare classes, preventing the "majority class bias" where the model ignores subtle signals **Cite {solution_lesson_node_00009}**.
    *   **Backbone:** The concatenated representation is fed into a **Bi-directional LSTM (Bi-LSTM)**. This recurrent architecture is retained as it converges significantly faster and captures local dependencies more effectively than raw Transformers for this specific tagging task **Cite {solution_lesson_node_00012}**.
    *   **Head:** A standard **Softmax Classification Head**. We explicitly reject the Conditional Random Field (CRF) layer, as lessons prove it hinders convergence for this locally-determinable task **Cite {solution_lesson_node_00028}**.

2.  **Stage 2: Hybrid Normalization Strategy**
    *   **Primary (Deterministic Memory):** A **Knowledge Base (KB)** maps `(raw_token, predicted_class)` pairs to their normalized text. This handles the vast majority of cases (93%+) with 100% precision **Cite {solution_lesson_node_00005}**.
    *   **Secondary (Neural Fallback):** For Out-of-Vocabulary (OOV) tokens, we employ a **Character-Level Transformer Seq2Seq Model**.
        *   **Architecture:** A Transformer Encoder-Decoder. Transformers are structurally superior to LSTMs for generating long, coherent character sequences (e.g., spelling out complex numbers) **Cite {solution_lesson_node_00027}**.
        *   **Conditioning:** The model is conditioned on the **Class Embedding** predicted by the Tagger, ensuring the generation follows the correct semantic rules (e.g., treating "2025" as a date vs. a cardinal).

### Data
1.  **Knowledge Base Construction:** We will construct the KB using the **entire training dataset** (not just the training split). Performance is strictly bounded by memory coverage, so maximizing the number of stored keys is critical **Cite {solution_lesson_node_00007}**.
2.  **Tagger Data:** The Tagger is trained on the full dataset. We will train a BPE tokenizer on the corpus to generate the subword inputs and pre-calculate the Regex feature vectors for all tokens.
3.  **Fallback Data:** We will create a specialized dataset by filtering the training data to include only token pairs where `before != after`. This focuses the Transformer on learning non-trivial transformations rather than identity mappings **Cite {solution_lesson_node_00027}**.

### Training
1.  **Tagger Training:**
    *   **Loss Function:** Cross-Entropy Loss with **Square-Root Smoothed Class Weights** ($\sqrt{N/N_c}$). This penalizes errors on rare classes (like `MONEY`) without the gradient instability caused by raw inverse frequency weights **Cite {solution_lesson_node_00013}**.
    *   **Optimizer:** We will use the **Adam** optimizer paired with a **ReduceLROnPlateau** scheduler. This dynamic schedule is essential for allowing the LSTM to escape local minima and converge to a better generalization point than static rates **Cite {solution_lesson_node_00011}**.
2.  **Fallback Training:** The Transformer Seq2Seq will be trained using standard Cross-Entropy Loss with Teacher Forcing on the filtered "changed" dataset.

### Evaluation
1.  **Inference Pipeline:**
    *   **Step 1 (Tagging):** Pass the test sentence through the **Quad-Hybrid Bi-LSTM** to obtain the predicted class for each token.
    *   **Step 2 (Retrieval):** For each token, query the **Knowledge Base** using `(token, predicted_class)`. If a match is found, return the stored value.
    *   **Step 3 (Generation):** If the pair is missing from the KB (OOV) and the class is not `PLAIN`, pass the token and its class to the **Transformer Fallback Model** to generate the normalized text. This ensures robust handling of the "long tail" of unseen entities **Cite {solution_lesson_node_00027}**.
