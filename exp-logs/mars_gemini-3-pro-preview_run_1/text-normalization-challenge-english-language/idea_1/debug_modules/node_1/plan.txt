The issue stems from Python's behavior regarding default argument evaluation. The `BiLSTMTagger` class defines default values for its `__init__` parameters (like `embedding_dim`) using `Config` attributes. These defaults are evaluated once when the module is first imported. In `runfile.py`, the `Config` attributes are modified at runtime *after* the import, but the class defaults remain set to the original values. Consequently, when `InferencePipeline` instantiates the model without explicit arguments, it uses the original (larger) architecture instead of the modified (smaller) one used during training, causing a shape mismatch when loading the checkpoint.

To fix this, I will modify `library/inference.py` to explicitly pass the model configuration parameters from `Config` when instantiating `BiLSTMTagger`. This ensures the model is built using the current runtime configuration values.
