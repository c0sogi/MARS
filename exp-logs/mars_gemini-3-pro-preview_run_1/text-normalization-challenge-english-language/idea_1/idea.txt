To establish a robust and efficient baseline for the text normalization task, I propose the **Bi-directional LSTM Tagger with Memorization-Based Normalization**.

This approach treats the problem primarily as a **Sequence Labeling** (Tagging) task rather than a text generation task. By leveraging the strong correlation between a token's class (e.g., DATE, MONEY) and its normalized form, we can achieve high accuracy with a lightweight architecture that avoids the computational cost of autoregressive Transformers (Model 1) or the complexity of handcrafted feature engineering (Model 2).

### Model
The architecture consists of two distinct stages: a **Neural Tagger** and a **Deterministic Lookup Decoder**.

1.  **Neural Tagger (Bi-LSTM):**
    *   **Embeddings:** A trainable word embedding layer converts raw input tokens into dense vectors. This allows the model to learn semantic similarities between tokens.
    *   **Context Encoder:** A single-layer Bi-directional Long Short-Term Memory (Bi-LSTM) network processes the sequence of token embeddings. This captures the necessary left and right context to disambiguate tokens (e.g., distinguishing "2005" as a *DATE* in "in 2005" vs. a *CARDINAL* in "2005 apples").
    *   **Classification Head:** A simple linear layer followed by a Softmax activation projects the LSTM output to a probability distribution over the predefined classes (e.g., PLAIN, PUNCT, DATE, CARDINAL).

2.  **Memorization-Based Decoder:**
    *   Instead of generating text character-by-character, this component utilizes a **Knowledge Base (Hash Map)** constructed from the training data.
    *   The map keys are tuples of `(raw_token, predicted_class)` and the values are the most frequent `after` strings observed during training.

### Data
1.  **Preprocessing:**
    *   **Vocabulary Construction:** Build a vocabulary of the most frequent tokens in the `before` column of the training set. Assign a special `<UNK>` token for rare words.
    *   **Label Encoding:** Map the unique values in the `class` column (e.g., "PLAIN", "DATE") to integer IDs.
    *   **Knowledge Base Creation:** Iterate through the entire training set to build a dictionary `{(raw_token, class): normalized_text}`. For conflicts (same token/class mapping to different outputs), store the most frequent normalization.

2.  **Sequence Generation:**
    *   Group the training data by `sentence_id` to form sequences.
    *   Pad sequences to a fixed length (e.g., 128 tokens) to allow for efficient batch processing on the GPU.

### Training
*   **Objective:** Train the Bi-LSTM Tagger to minimize the **Cross-Entropy Loss** between the predicted class probabilities and the true class labels provided in the training set.
*   **Optimization:** Use the **Adam** optimizer with a standard learning rate (e.g., 0.001).
*   **Strategy:** Since 93% of tokens are "PLAIN", use **Class Weights** in the loss function to penalize errors on rare but important classes (like DATE or MONEY) more heavily, preventing the model from trivially predicting "PLAIN" for everything.

### Evaluation
1.  **Inference:**
    *   Feed the test sentences into the trained Bi-LSTM Tagger to obtain the predicted `class` for each token.
2.  **Normalization (Lookup):**
    *   For each test token, query the Knowledge Base using the pair `(token_text, predicted_class)`.
    *   **Hit:** If the pair exists in the map, output the stored normalized text.
    *   **Miss (OOV):** If the pair is not found (e.g., a new number or date not seen in training), apply a simple **fallback heuristic**:
        *   If the predicted class is `PLAIN` or `PUNCT`, copy the input text.
        *   If the predicted class is `DATE`, `CARDINAL`, etc., apply a basic regex transformation (or simply copy if implementation speed is prioritized, relying on the fact that most complex patterns are repeated).
