Based on the comprehensive analysis of the accumulated lessons, I propose the **Prior-Informed Multi-Feature Bi-LSTM with Inductive-Bias-Aligned Fallback**.

This solution represents a structural synthesis that combines the advanced "Wide and Deep" feature engineering strategies (attempted in Idea 11) with the robust, inductive-bias-aligned architecture (proven in Idea 5 and Idea 12). It explicitly corrects the failure of Idea 11 by rejecting the Transformer-based fallback in favor of an LSTM, while retaining the powerful Global Prior and Regex features to maximize input fidelity.

### Model
The architecture follows the decoupled "Classify-Retrieve-Generate" paradigm **Cite {solution_lesson_node_00005}**, optimized for maximum input fidelity and generative stability.

1.  **Stage 1: Prior-Informed Multi-Feature Tagger (Classification)**
    *   **Structural Innovation (Input):** To definitively address the "Input Fidelity" bottleneck **Cite {solution_lesson_node_00009}** and the "Needle-in-a-haystack" difficulty of detecting rare classes, we employ a **Penta-Hybrid Input Representation**:
        1.  **Word Embeddings:** A trainable embedding layer with a maximized vocabulary size (100k+) to capture high-level semantics and minimize `<UNK>` tokens.
        2.  **Subword (BPE) Embeddings:** We include Byte-Pair Encoding embeddings (mean-pooled) to capture semantic stems for rare words (e.g., "bio", "graphy"), ensuring valid semantic representations for OOV terms.
        3.  **Character-Level CNN:** A 1D-CNN processing character sequences to extract learned morphological features (e.g., suffixes, capitalization).
        4.  **Explicit Morphological Features:** A dense vector of binary flags derived from **Regex Matching** (e.g., `is_digit`, `is_date_format`, `has_currency_symbol`). This forces the model to attend to specific lexical cues that define rare classes.
        5.  **Global Prior Features:** A probability vector representing the empirical class distribution of the token in the training corpus (e.g., `P(DATE|'May') = 0.95`). This explicitly bridges the gap between the deterministic memory and the statistical classifier, providing a strong signal for ambiguous tokens.
    *   **Backbone:** This rich feature set is concatenated and fed into a **Bi-directional LSTM (Bi-LSTM)**. We explicitly retain this recurrent architecture as it converges significantly faster and captures local dependencies more effectively than Transformers for this specific tagging task **Cite {solution_lesson_node_00012}**.
    *   **Head:** A standard **Softmax Classification Head**. We explicitly reject the Conditional Random Field (CRF) layer, as lessons prove it hinders convergence for this locally-determinable task **Cite {solution_lesson_node_00028}**.

2.  **Stage 2: Hybrid Normalization Strategy**
    *   **Primary (Deterministic Memory):** A **Knowledge Base (KB)** maps `(raw_token, predicted_class)` pairs to their normalized text. This handles the vast majority of cases with 100% precision **Cite {solution_lesson_node_00007}**.
    *   **Secondary (Neural Fallback):** For Out-of-Vocabulary (OOV) tokens, we employ a **Character-Level LSTM Seq2Seq Model with Attention**.
        *   **Strategic Retention:** We revert to the **LSTM-based** fallback, explicitly rejecting the Transformer fallback. As identified in **Cite {solution_lesson_node_00037}**, LSTMs outperform Transformers on character-level transduction tasks with rigid formatting rules (like dates and numbers) due to their inherent sequential inductive bias.
        *   **Conditioning:** The model is conditioned on the **Class Embedding** predicted by the Tagger.

### Data
1.  **Knowledge Base & Prior Construction:**
    *   Use the **entire training dataset** to build the KB `(token, class) -> normalization` map to maximize coverage **Cite {solution_lesson_node_00007}**.
    *   Compute the **Global Prior Vectors** by aggregating class counts for every unique token in the full training set.
2.  **Tagger Data:**
    *   Train a BPE tokenizer on the corpus to generate subword inputs.
    *   Pre-calculate Regex flags and Global Prior vectors for all tokens.
3.  **Fallback Data:**
    *   Filter the training data to include only token pairs where `before != after`. This focuses the generative model on non-trivial transformations **Cite {solution_lesson_node_00027}**.

### Training
1.  **Tagger Training:**
    *   **Loss Function:** Cross-Entropy Loss with **Square-Root Smoothed Class Weights** ($\sqrt{N/N_c}$). This penalizes errors on rare classes without the gradient instability caused by raw inverse frequency weights **Cite {solution_lesson_node_00013}**.
    *   **Optimizer:** **Adam** optimizer paired with a **ReduceLROnPlateau** scheduler. This dynamic schedule is critical for allowing the LSTM to escape local minima **Cite {solution_lesson_node_00011}**.
    *   **Regularization:** Apply **Feature Dropout** specifically to the Global Prior and Regex vectors during training. This prevents the model from over-relying on these "shortcuts" and forces it to learn robust context-based disambiguation for OOV tokens.
2.  **Fallback Training:**
    *   Train the LSTM Seq2Seq using standard Cross-Entropy Loss with Teacher Forcing on the filtered "changed" dataset.

### Evaluation
1.  **Inference Pipeline:**
    *   **Step 1 (Feature Extraction):** Generate Word, BPE, Char-CNN, Regex, and Global Prior features for the test sentence. (Note: Test tokens will have zero vectors for Global Priors if they were not seen in training).
    *   **Step 2 (Tagging):** Pass features through the **Prior-Informed Bi-LSTM** to predict the class for each token.
    *   **Step 3 (Retrieval):** Query the **Knowledge Base** using `(token, predicted_class)`. If a match is found, return the stored value.
    *   **Step 4 (Generation):** If the pair is missing from the KB (OOV) and the class is not `PLAIN`, pass the token and its class to the **LSTM Seq2Seq Fallback Model** to generate the normalized text. This ensures robust handling of unseen entities while leveraging the superior sequential modeling of LSTMs **Cite {solution_lesson_node_00037}**.
