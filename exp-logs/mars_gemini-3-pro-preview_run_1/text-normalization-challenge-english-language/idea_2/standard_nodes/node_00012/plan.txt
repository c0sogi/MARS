The strategy for the implementation is as follows:

1.  **Configuration & Setup**: Initialize the random seeds and device. Override the default `Config` to ensure the "fast baseline" requirement is met while retaining high performance. Specifically, we will set `Config.NUM_EPOCHS` to 2 and use the full dataset (`Config.DEBUG = False`) to maximize the coverage of the Knowledge Base and the generalization of the Transformer model.
2.  **Data Loading**: Use `get_dataloaders` with `load_cached_data=True` to efficiently load the pre-processed Parquet files (train, val, test splits, vocabularies, and knowledge base).
3.  **Training**: Execute `train_model` to train the Transformer Tagger. This function handles the training loop, loss calculation (with class weights), and saves the best model based on validation loss.
4.  **Validation**: Load the best model weights. Perform a custom validation loop to calculate the exact text normalization accuracy (string match). This involves:
    *   Iterating through the validation dataloader.
    *   Predicting token classes.
    *   Normalizing tokens using the `Normalizer` (which combines the deterministic Knowledge Base and the predicted class).
    *   Comparing the normalized text against the ground truth `after` column derived directly from the validation dataframe.
5.  **Failure Analysis**: During the validation loop, collect data on errors and token lengths. Calculate the Point-Biserial correlation between the error presence (0 for correct, 1 for incorrect) and the token length to identify if length is a systematic factor in failures.
6.  **Submission**: Compare the calculated validation metric against the threshold (0.9861543320467205). If the metric is higher, call `generate_submission` to produce the `submission.csv` file for the test set.
