Based on the accumulated lessons, I propose the **Context-Aware Transformer Tagger with Deterministic Knowledge Retrieval**.

### Model
This solution introduces a structural innovation by replacing the recurrent Bi-LSTM backbone with a **Transformer Encoder**, while explicitly retaining the successful "Classify-and-Lookup" paradigm established in previous iterations **Cite {solution_lesson_node_00005}**.

1.  **Embedding Layer:** The model begins with a trainable word embedding layer. To maintain high input fidelity as identified in **Cite {solution_lesson_node_00009}**, we will use a large vocabulary size to minimize `<UNK>` tokens.
2.  **Transformer Encoder Backbone:** Instead of processing tokens sequentially like an LSTM, we will employ a stack of **Transformer Encoder layers** (Multi-Head Self-Attention + Feed-Forward Networks). This architecture allows the model to attend to the entire sentence context simultaneously, enabling superior disambiguation of tokens (e.g., distinguishing "St." as "Saint" or "Street") based on long-range dependencies that LSTMs often struggle to capture. Since Transformers are permutation-invariant, **Positional Encodings** will be added to the embeddings to retain sequence order information.
3.  **Classification Head:** The output of the Transformer is fed into a linear classification layer to predict the semantic category (e.g., `DATE`, `CARDINAL`, `PLAIN`) for each token.
4.  **Deterministic Decoder (Knowledge Base):** We retain the deterministic lookup table. The final output is generated by querying a hash map with the tuple `(raw_token, predicted_class)`.

### Data
1.  **Knowledge Base Construction:** We will construct the Knowledge Base (KB) using the **entire training dataset**, not just the subset used for training the neural model. This maximizes the coverage of the deterministic memory, addressing the bottleneck identified in **Cite {solution_lesson_node_00007}**.
2.  **Preprocessing:** Data will be batched by sentence. We will use a fixed sequence length (padding/truncating) suitable for the Transformer (e.g., 128 or 256 tokens).

### Training
1.  **Loss Function:** We will employ **Class-Weighted Cross-Entropy Loss**. Weights will be inversely proportional to class frequency (or square-root smoothed) to force the model to focus on rare but critical classes like `MONEY` or `TIME`, preventing the "majority class bias" noted in **Cite {solution_lesson_node_00009}**.
2.  **Optimizer & Schedule:** We will use the **AdamW** optimizer paired with a **dynamic learning rate scheduler** (e.g., Linear Warmup followed by Cosine Decay or ReduceLROnPlateau). This adheres to the finding that dynamic schedules outperform static conservative rates for convergence and generalization **Cite {solution_lesson_node_00011}**.

### Evaluation
1.  **Inference:** The Transformer Tagger predicts the class for every token in the test set.
2.  **Normalization:**
    *   **Primary:** Query the Knowledge Base with `(token, predicted_class)`. If found, return the stored value.
    *   **Fallback:** If the pair is missing (OOV), apply a heuristic: copy the text if the class is `PLAIN`/`PUNCT`, or apply basic regex transformations for numeric classes.
