Implementation strategy:
1.  **Configuration**: Import the `Config` class and override settings for a fast baseline execution. We will enable `DEBUG` mode with a subset of 100,000 sentences and reduce the number of epochs (3 for Tagger, 5 for Seq2Seq) to ensure the script completes within the time limit while still providing a meaningful signal.
2.  **Setup**: Initialize the environment, set random seeds, and prepare directories using `Config.setup()`.
3.  **Training**:
    *   Train the **Bi-LSTM-CRF Tagger** using `train_tagger`. This model identifies the type of each token.
    *   Train the **Transformer Seq2Seq** model using `train_seq2seq`. This model handles the normalization of complex tokens (OOV).
    *   We utilize `load_cached=True` which, combined with the new working directory for this idea, will trigger the initial data processing and caching for the debug subset.
4.  **Validation**:
    *   Implement a custom validation pipeline `run_validation` that mimics the inference logic: Tagger $\rightarrow$ Knowledge Base Lookup $\rightarrow$ Seq2Seq Fallback.
    *   Evaluate this pipeline on the hold-out validation set (`val_grouped`).
    *   Compute the exact string match accuracy.
    *   Print the required metric string: `Final Validation Metric: <value>`.
5.  **Failure Analysis**:
    *   During validation, collect error statistics including token length and error status.
    *   Compute and print the correlation between token length and error occurrence to identify if longer tokens are more prone to errors.
    *   Analyze error distribution by class.
6.  **Submission**:
    *   Check if the validation accuracy exceeds the strict threshold of `0.9949142925818993`.
    *   If successful, instantiate the `NormalizationPipeline` to generate predictions for the test set and save them to `./submission/submission.csv`.
