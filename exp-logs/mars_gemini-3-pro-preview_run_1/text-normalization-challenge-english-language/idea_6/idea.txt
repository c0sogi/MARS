Based on the accumulated lessons and the analysis of previous iterations, I propose the **Bi-LSTM-CRF Tagger with Transformer-Based Neural Fallback**. This solution introduces structural innovations in both the classification (tagging) and generation (fallback) stages while strictly adhering to the architectural choices proven to work in this specific domain.

# Model
The system operates on a decoupled "Classify-Retrieve-Generate" paradigm **Cite {solution_lesson_node_00005}**, enhanced with global sequence modeling and a modern generative architecture.

1.  **Stage 1: Context-Aware Tagger (Bi-LSTM-CRF)**
    *   **Input Representation:** We retain the hybrid input strategy to ensure high fidelity **Cite {solution_lesson_node_00009}**.
        *   **Word Embeddings:** A trainable embedding layer with a maximized vocabulary size to minimize `<UNK>` tokens.
        *   **Character Features:** A 1D-CNN processes the character sequence of each token to capture morphological signals (e.g., suffixes, capitalization, digit patterns).
        *   These features are concatenated and fed into the backbone.
    *   **Backbone:** We employ a **Bi-directional LSTM (Bi-LSTM)**. As established, this recurrent architecture converges faster and captures local dependencies more effectively than raw Transformers for this specific tagging task **Cite {solution_lesson_node_00012}**.
    *   **Structural Innovation (Head):** We replace the simple linear classification head with a **Conditional Random Field (CRF)** layer. While previous models predicted token classes independently, a CRF models the *joint probability* of the entire label sequence. This enforces global consistency, ensuring that the predicted sequence of classes (e.g., `MONEY` tokens usually appearing together) follows valid transition rules, thereby improving disambiguation in complex sentences.

2.  **Stage 2: Hybrid Normalization Strategy**
    *   **Primary (Deterministic Memory):** A **Knowledge Base (KB)** maps `(raw_token, predicted_class)` pairs to their normalized text. This handles the vast majority of cases with 100% precision.
    *   **Secondary (Neural Fallback):** For Out-of-Vocabulary (OOV) tokens, we employ a **Character-Level Transformer Seq2Seq Model**.
        *   **Structural Innovation:** We replace the LSTM-based fallback with a **Transformer Encoder-Decoder**. Transformers are superior at handling long-range dependencies in character-level generation (e.g., spelling out long numbers or complex chemical formulas) and are more robust to vanishing gradients during generation. This model is conditioned on the class predicted by the Tagger (e.g., Input: `<DATE> 2025` $\to$ Output: `twenty twenty-five`).

# Data
1.  **Knowledge Base Construction:** We will construct the KB using the **entire training dataset**. Performance is bounded by memory coverage, so maximizing the number of stored keys is critical **Cite {solution_lesson_node_00007}**.
2.  **Tagger Data:** The Tagger is trained on the full dataset. We will use a large vocabulary size for the word embeddings to maintain input fidelity **Cite {solution_lesson_node_00009}**.
3.  **Fallback Data:** We will create a filtered dataset containing only token pairs where `before != after`. This focuses the Transformer on learning non-trivial transformations (e.g., Dates, Numbers) rather than identity mappings **Cite {solution_lesson_node_00027}**.

# Training
1.  **Tagger Training:**
    *   **Loss Function:** We will use **Class-Weighted Negative Log-Likelihood (NLL)** for the CRF. The emission scores will be weighted using **Square-Root Smoothing** ($\sqrt{N/N_c}$) to penalize errors on rare classes without causing gradient instability **Cite {solution_lesson_node_00013}**.
    *   **Optimizer:** We will use the **Adam** optimizer paired with a **ReduceLROnPlateau** scheduler. This dynamic schedule is essential for allowing the LSTM to converge to a deeper minimum compared to static rates **Cite {solution_lesson_node_00011}**.
2.  **Fallback Training:** The Transformer Seq2Seq will be trained using standard Cross-Entropy Loss with Teacher Forcing on the filtered dataset.

# Evaluation
1.  **Inference Pipeline:**
    *   **Step 1 (Tagging):** Pass the test sentence through the **Bi-LSTM-CRF** to obtain the optimal sequence of predicted classes (Viterbi Decoding).
    *   **Step 2 (Retrieval):** For each token, query the **Knowledge Base** using `(token, predicted_class)`. If a match is found, return the stored value.
    *   **Step 3 (Generation):** If the pair is missing from the KB (OOV) and the class is not `PLAIN`, pass the token and its class to the **Transformer Fallback Model** to generate the normalized text. This ensures robust handling of the "long tail" of unseen entities **Cite {solution_lesson_node_00027}**.
