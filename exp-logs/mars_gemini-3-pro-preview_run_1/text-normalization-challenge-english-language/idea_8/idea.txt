Based on the comprehensive analysis of previous experiments and the derived lessons, I propose the **Bi-LSTM Tagger with Transformer-Based Neural Fallback**.

This solution synthesizes the robust classification capabilities of the Bi-LSTM (proven superior to Transformers for this specific tagging task) with the advanced generative capabilities of a Transformer for the fallback mechanism (improving upon the LSTM fallback). It explicitly corrects the architectural flaw of using CRFs for local classification.

### Model
The architecture operates on a decoupled "Classify-Retrieve-Generate" pipeline **Cite {solution_lesson_node_00005}**:

1.  **Stage 1: Morphologically-Aware Bi-LSTM Tagger**
    *   **Input Representation:** To maximize input fidelity **Cite {solution_lesson_node_00009}**, we employ a hybrid embedding strategy.
        *   **Word Embeddings:** A trainable embedding layer with a maximized vocabulary size to minimize `<UNK>` tokens.
        *   **Character Features:** A **1D-CNN** processes the character sequence of each token to extract morphological signals (e.g., digit patterns, suffixes).
        *   These two representations are concatenated to form the input vector.
    *   **Backbone:** We utilize a **Bi-directional LSTM (Bi-LSTM)**. Lessons have proven that this recurrent architecture converges significantly faster and achieves higher accuracy than raw Transformers for this specific tagging task **Cite {solution_lesson_node_00012}**.
    *   **Classification Head:** We employ a standard **Softmax** layer. We explicitly reject the Conditional Random Field (CRF) used in previous failed iterations, as the token classes in this task are locally determinable and CRFs introduce unnecessary optimization complexity **Cite {solution_lesson_node_00028}**.

2.  **Stage 2: Hybrid Normalization Strategy**
    *   **Primary (Deterministic Memory):** A **Knowledge Base (KB)** maps `(raw_token, predicted_class)` pairs to their normalized text. This handles the vast majority of cases (93%+) with 100% precision.
    *   **Secondary (Neural Fallback):** For Out-of-Vocabulary (OOV) tokens, we employ a **Character-Level Transformer Seq2Seq Model**.
        *   **Structural Innovation:** We replace the LSTM-based fallback (from Idea 5) with a **Transformer Encoder-Decoder**. While the Bi-LSTM is superior for tagging, the Transformer is structurally superior for *generation*, particularly for handling long-range dependencies in character sequences (e.g., spelling out complex numbers). This model is conditioned on the class predicted by the Tagger **Cite {solution_lesson_node_00027}**.

### Data
1.  **Knowledge Base Construction:** We will construct the KB using the **entire training dataset**. Performance is strictly bounded by memory coverage, so maximizing the number of stored keys is critical **Cite {solution_lesson_node_00007}**.
2.  **Tagger Data:** The Tagger is trained on the full dataset. We will use a large vocabulary size for the word embeddings to maintain input fidelity **Cite {solution_lesson_node_00009}**.
3.  **Fallback Data:** We will create a specialized dataset by filtering the training data to include only token pairs where `before != after`. This focuses the Transformer on learning non-trivial transformations rather than identity mappings **Cite {solution_lesson_node_00027}**.

### Training
1.  **Tagger Training:**
    *   **Loss Function:** We will use Cross-Entropy Loss with **Square-Root Smoothed Class Weights** ($\sqrt{N/N_c}$). This penalizes errors on rare classes (like `MONEY`) to prevent majority class bias, but avoids the gradient instability caused by raw inverse frequency weights **Cite {solution_lesson_node_00013}**.
    *   **Optimizer:** We will use the **Adam** optimizer paired with a **ReduceLROnPlateau** scheduler. This dynamic schedule is essential for allowing the LSTM to escape local minima and converge to a better generalization point than static rates **Cite {solution_lesson_node_00011}**.
2.  **Fallback Training:** The Transformer Seq2Seq will be trained using standard Cross-Entropy Loss with Teacher Forcing on the filtered "changed" dataset.

### Evaluation
1.  **Inference Pipeline:**
    *   **Step 1 (Tagging):** Pass the test sentence through the **Bi-LSTM Tagger** to obtain the predicted class for each token.
    *   **Step 2 (Retrieval):** For each token, query the **Knowledge Base** using `(token, predicted_class)`. If a match is found, return the stored value.
    *   **Step 3 (Generation):** If the pair is missing from the KB (OOV) and the class is not `PLAIN`, pass the token and its class to the **Transformer Fallback Model** to generate the normalized text. This ensures robust handling of the "long tail" of unseen entities **Cite {solution_lesson_node_00027}**.
