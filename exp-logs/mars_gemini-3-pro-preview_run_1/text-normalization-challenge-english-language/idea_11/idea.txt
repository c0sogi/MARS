Based on the comprehensive analysis of the "Lessons" and "Previous Ideas," I propose the **Prior-Augmented Multi-Granularity Bi-LSTM with Transformer Fallback**.

This solution introduces a structural innovation in the **Input Representation** of the Tagger by integrating **Global Prior Features** (empirical class probabilities). This explicitly bridges the gap between the deterministic memory (Knowledge Base) and the statistical classifier, while strictly adhering to the architectural choices (Bi-LSTM Backbone, Transformer Fallback) proven to be optimal in previous experiments.

### Model
The architecture follows the decoupled "Classify-Retrieve-Generate" paradigm **Cite {solution_lesson_node_00005}**, enhanced with a "Wide and Deep" input strategy.

1.  **Stage 1: Prior-Augmented Tagger (Classification)**
    *   **Structural Innovation (Input):** To maximize **Input Fidelity** **Cite {solution_lesson_node_00009}** and resolve ambiguity, we employ a **Penta-Hybrid Input Representation**:
        1.  **Word Embeddings:** Large vocabulary (100k+) to capture high-level semantics.
        2.  **Subword (BPE) Embeddings:** To capture semantic stems for rare words (e.g., "bio", "graphy").
        3.  **Character-Level CNN:** A 1D-CNN to extract local morphological features (e.g., suffixes, capitalization).
        4.  **Explicit Morphological Features:** Binary flags derived from Regex (e.g., `is_digit`, `is_currency`) to guide the model on OOV tokens.
        5.  **Global Prior Features (New):** A dense probability vector representing the empirical class distribution of the token in the training corpus (e.g., `[P(PLAIN)=0.1, P(DATE)=0.9, ...]`). This explicitly informs the model of the token's historical usage. For Out-of-Vocabulary (OOV) tokens, this is a zero vector. This allows the model to rely on strong priors for known tokens and switch to morphological/contextual signals for OOVs.
    *   **Backbone:** The concatenated features are processed by a **Bi-directional LSTM (Bi-LSTM)**. This architecture is retained as it converges significantly faster and captures local dependencies better than raw Transformers for this specific tagging task **Cite {solution_lesson_node_00012}**.
    *   **Head:** A standard **Softmax Classification Head**. We explicitly reject the CRF layer, as lessons prove it hinders convergence for this locally-determinable task **Cite {solution_lesson_node_00028}**.

2.  **Stage 2: Hybrid Normalization Strategy**
    *   **Primary (Deterministic Memory):** A **Knowledge Base (KB)** maps `(raw_token, predicted_class)` pairs to their normalized text. This handles the vast majority of cases with 100% precision **Cite {solution_lesson_node_00005}**.
    *   **Secondary (Neural Fallback):** For OOV tokens (where KB lookup fails), we employ a **Character-Level Transformer Seq2Seq Model**.
        *   **Architecture:** A Transformer Encoder-Decoder, chosen for its superior ability to generate coherent long sequences (e.g., complex numbers) compared to LSTMs **Cite {solution_lesson_node_00027}**.
        *   **Conditioning:** The model is conditioned on the **Class Embedding** predicted by the Tagger, ensuring the generation adheres to the semantic rules of the predicted category.

### Data
1.  **Knowledge Base & Prior Construction:**
    *   Use the **entire training dataset** to build the KB `(token, class) -> normalization` map to maximize coverage **Cite {solution_lesson_node_00007}**.
    *   Compute the **Global Prior Vectors** by aggregating class counts for every unique token in the full training set and normalizing them to probabilities.
2.  **Tagger Data:**
    *   Train a BPE tokenizer on the corpus.
    *   Pre-calculate Regex flags and Global Prior vectors for all tokens.
3.  **Fallback Data:**
    *   Filter the training data to include only token pairs where `before != after`. This focuses the generative model on non-trivial transformations **Cite {solution_lesson_node_00027}**.

### Training
1.  **Tagger Training:**
    *   **Loss Function:** Cross-Entropy Loss with **Square-Root Smoothed Class Weights** ($\sqrt{N/N_c}$). This penalizes errors on rare classes without the gradient instability caused by raw inverse frequency weights **Cite {solution_lesson_node_00013}**.
    *   **Optimizer:** **Adam** optimizer paired with a **ReduceLROnPlateau** scheduler. This dynamic schedule is critical for allowing the LSTM to escape local minima **Cite {solution_lesson_node_00011}**.
    *   **Regularization Strategy:** Apply **Feature Dropout** specifically to the Global Prior vector (randomly zeroing it out with $p=0.2$). This prevents the model from over-relying on the priors and forces it to learn robust morphological and contextual features for handling OOV tokens effectively.
2.  **Fallback Training:**
    *   Train the Transformer Seq2Seq using standard Cross-Entropy Loss with Teacher Forcing on the filtered "changed" dataset.

### Evaluation
1.  **Inference Pipeline:**
    *   **Step 1 (Feature Extraction):** Generate Word, BPE, Char-CNN, Regex, and Global Prior features for the test sentence. (Note: Test tokens will have zero vectors for Global Priors if they were not seen in training).
    *   **Step 2 (Tagging):** Pass features through the **Prior-Augmented Bi-LSTM** to predict the class for each token.
    *   **Step 3 (Retrieval):** Query the **Knowledge Base** using `(token, predicted_class)`. If a match is found, return the stored value.
    *   **Step 4 (Generation):** If the pair is missing from the KB (OOV) and the class is not `PLAIN`, pass the token and its class to the **Transformer Fallback Model** to generate the normalized text. This ensures robust handling of the "long tail" **Cite {solution_lesson_node_00027}**.
