The issue stems from the incorrect usage of `torch.cuda.amp.autocast`. The code calls `amp.autocast("cuda")`, but unlike the generic `torch.autocast` context manager introduced in later PyTorch versions, `torch.cuda.amp.autocast` does not accept a device type argument; its first argument is `enabled` (a boolean). Passing `"cuda"` assigns a string to `enabled`, causing the `TypeError`. The fix is to remove the `"cuda"` argument, allowing `enabled` to default to `True`.
