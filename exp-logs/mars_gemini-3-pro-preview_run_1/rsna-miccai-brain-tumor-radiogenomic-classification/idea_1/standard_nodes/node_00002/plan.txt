The issue stems from the `MGMTDataset` class loading stale cache files (`.npy`) that do not match the current metadata size (e.g., loading 4 cached samples when the metadata expects 59 or 105). This mismatch results in training and validation on a tiny, unrepresentative subset of data, causing the model to overfit and the ROC AUC calculation to fail (returning `nan`) because the validation subset likely contains only a single class.

To fix this, I will:
1.  Update `library/dataset.py` to verify that the number of loaded cached images matches the number of rows in the metadata. If there is a mismatch, the cache will be ignored and the data reprocessed.
2.  Update `runfile.py` to disable loading from cache (`load_cached_data=False`) during the initial training and submission generation steps to ensure fresh, correct data is processed. I will also add robustness to the AUC calculation block.
