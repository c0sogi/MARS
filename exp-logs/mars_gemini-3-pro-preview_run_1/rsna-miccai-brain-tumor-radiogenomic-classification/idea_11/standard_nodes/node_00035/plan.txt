The following implementation strategy outlines the execution flow of the `runfile.py` script:

1.  **Configuration**: We override `Config.NUM_EPOCHS` to 10 to ensures the training completes quickly while allowing sufficient time for the model to converge on this dataset. We ensure `Config.DEBUG` is `False` to utilize the full training and validation sets for reliable metric calculation.
2.  **Training**: We invoke `library.train.run_training`. This function manages the entire training loop, including data loading (with caching), forward/backward passes, validation monitoring, and saving the model checkpoint with the highest validation AUC to `Config.MODEL_SAVE_PATH`.
3.  **Validation**: After training, we reload the best model checkpoint. We perform inference on the hold-out validation set using the validation DataLoader. Since the model operates on independent slices (3 per subject), we aggregate these predictions by calculating the mean probability per subject ID. We then compute the final ROC AUC score.
4.  **Failure Analysis**: We calculate the absolute error for each subject in the validation set. To identify systematic error patterns, we extract a metadata feature—the number of T2w slices (representing scan depth/volume)—and compute its Pearson correlation with the model's prediction error.
5.  **Submission**: We compare the final validation AUC against the required threshold (0.6705454545454544). If the model's performance exceeds this benchmark, we call `library.inference.predict_and_submit` to generate the final `submission.csv` for the test set.
