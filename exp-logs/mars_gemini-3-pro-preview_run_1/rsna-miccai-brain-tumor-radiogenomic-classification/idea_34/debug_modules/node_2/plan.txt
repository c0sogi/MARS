The issue stems from the validation AUC metric evaluating to `nan` (Not a Number) during the training loop on the small demonstration dataset, coupled with an initialization of `best_auc` to `0.0`. In Python, comparisons involving `nan` (e.g., `nan > 0.0`) always evaluate to `False`, causing the model saving logic to be skipped entirely. This results in the `best_model.pth` file never being created, leading to a `FileNotFoundError` (or `AssertionError` in the script) during the inference phase.

To fix this, I will:
1.  **Initialize the metric tracker to negative infinity** (`-float('inf')`) instead of `0.0`. This ensures that any valid numerical score (even 0.0) will trigger the initial model save (Cite debug_lesson_5).
2.  **Sanitize the metric before control flow** by checking if `val_auc` is `nan` and replacing it with a fallback value of `0.5`. This prevents the comparison logic from failing silently due to undefined metrics (Cite debug_lesson_1).
