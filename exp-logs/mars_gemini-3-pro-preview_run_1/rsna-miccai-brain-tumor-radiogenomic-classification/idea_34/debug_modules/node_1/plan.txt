The issue is that the validation AUC is returning `nan` (likely due to the small dataset size in the demo run having only one class), which causes the model checkpoint saving condition `if val_auc > self.best_auc` to fail silently because comparisons with `nan` are always False. Additionally, the `best_auc` tracker is initialized to `0.0`, which prevents saving if the first valid metric is also `0.0` (or if it remains `nan`).

To fix this:
1.  **Sanitize Metrics:** Explicitly check for `nan` values in the AUC calculation within `train_one_epoch` and `validate` and replace them with a fallback value (0.5). This ensures the control flow in the training loop receives valid numbers (Cite debug_lesson_1).
2.  **Initialize Tracker Correctly:** Initialize `self.best_auc` to `-float('inf')` instead of `0.0` to ensure that any valid numeric score (even 0.0 or 0.5) triggers the initial model save (Cite debug_lesson_5).
