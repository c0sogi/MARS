# 2.5D Siamese Multi-Slice Network with Feature Max-Pooling

This solution introduces a **Siamese Network** architecture designed to overcome the "Middle Slice Fallacy" (Cite solution_lesson_node_00002) without incurring the computational instability of full 3D sequence modeling (Cite solution_lesson_node_00008) or the label noise of stochastic sampling (Cite solution_lesson_node_00015).

### Model
The architecture utilizes a **Siamese** design with a shared weight backbone to process multiple deterministic views of the brain volume simultaneously.
*   **Backbone:** A standard **EfficientNet-B0** (pretrained on ImageNet) serves as the shared feature extractor.
*   **Input:** The network accepts $K=3$ distinct inputs per subject. Each input is a 3-channel composite image corresponding to a specific depth percentage of the brain volume (e.g., 45%, 50%, and 55%).
*   **Feature Extraction:** Each of the $K$ inputs is passed through the shared backbone independently, resulting in $K$ feature vectors (after Global Average Pooling).
*   **Aggregation (Innovation):** Instead of attention mechanisms (which failed in Idea 2) or averaging (which dilutes the signal), we employ **Element-wise Max-Pooling** across the $K$ feature vectors.
    *   *Logic:* This operation assumes that if the tumor signature exists in *any* of the selected slices, its corresponding features will have high activation. Max-pooling preserves this strong signal while suppressing the "noise" from adjacent slices that may miss the tumor, effectively acting as a "Feature-Level Maximum Intensity Projection" without the texture destruction of pixel-level MIP (Cite solution_lesson_node_00003).
*   **Head:** The aggregated feature vector is passed to a single fully connected layer with a sigmoid activation to predict `MGMT_value`.

### Data
The data pipeline moves from a single heuristic point to a **Deterministic Strided Sampling** strategy.
1.  **Slice Selection:** For each subject and each modality (FLAIR, T1wCE, T2w), we calculate the slice indices corresponding to **45%, 50%, and 55%** of the total file count. This ensures we capture the central volume (where the brain resides) while accounting for slight anatomical offsets that a single "50%" slice might miss (Cite solution_lesson_node_00002).
2.  **Input Construction:** We construct 3 composite images.
    *   Image A: [FLAIR@45%, T1wCE@45%, T2w@45%]
    *   Image B: [FLAIR@50%, T1wCE@50%, T2w@50%]
    *   Image C: [FLAIR@55%, T1wCE@55%, T2w@55%]
    *   *Note:* We map modalities by percentage depth rather than absolute index to handle varying slice counts across sequences.
3.  **Preprocessing:**
    *   **Precision:** Load and process all images as **float32**. We explicitly avoid casting to `uint8` to preserve the high dynamic range of the MRI sensors (Cite solution_lesson_node_00016).
    *   **Normalization:** Apply **Instance-level Min-Max Scaling** to the $[0, 1]$ range. We strictly avoid ImageNet normalization (mean/std subtraction) as it distorts the histogram of grayscale medical data (Cite solution_lesson_node_00017).

### Training
*   **Loss Function:** Binary Cross-Entropy (BCE) with Logits.
*   **Optimizer:** AdamW with a learning rate of $1e-4$.
*   **Regularization:** To combat the overfitting inherent in small datasets:
    *   **Weight Decay:** Set to **$1e-2$** (aggressive) rather than the default $1e-4$ (Cite solution_lesson_node_00010).
    *   **Dropout:** Enforce a dropout rate of **0.3** in the backbone.
*   **Augmentation:** Apply **Elastic Transformations** and **Grid Distortions** independently to each of the 3 inputs. Non-rigid augmentations are critical for learning robust features from limited medical data (Cite solution_lesson_node_00010).

### Evaluation
*   **Inference:** For each test subject, deterministically generate the same 3 inputs (45%, 50%, 55%).
*   **Prediction:** Pass the triplet through the Siamese network. The model internally aggregates the features and outputs a single probability. This avoids the need for post-hoc ensembling of random slices (which failed in Idea 4) by learning the aggregation logic end-to-end.
