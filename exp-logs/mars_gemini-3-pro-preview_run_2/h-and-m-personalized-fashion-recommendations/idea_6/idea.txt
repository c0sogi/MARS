Based on the progression of experiments and the "Lessons" provided, I propose a **Hybrid Graph-Enhanced Retrieval & Interaction-Aware Ranking** strategy. This approach structurally evolves the previous "Latent Behavioral Embeddings" (Idea 4) by replacing the context-limited Item2Vec model with **Graph Convolutional Networks (LightGCN)**. This addresses the "Recall Gap" by capturing high-order collaborative signals (transitive relationships) that simple co-occurrence misses, while strictly adhering to the "Bag-of-Nodes" aggregation preference identified in Lesson 00027.

# Model

The architecture is a **Two-Stage Pipeline** designed to maximize Recall through diverse retrieval strategies (Graph, Structure, Habit) and maximize Precision through interaction-aware ranking.

**Stage 1: Multi-Source Candidate Retrieval (The "Recall" Layer)**
We will generate a union of candidates from four distinct sources:

1.  **Source A: Graph Collaborative Filtering (High-Order Structure) [Structural Innovation]:**
    *   **Concept:** Previous iterations used Item2Vec (Idea 4), which only captures "items in the same basket." It fails to capture transitive relationships (e.g., User A buys X & Y; User B buys Y & Z $\rightarrow$ X and Z are related).
    *   **Mechanism:** We will implement **LightGCN** (using `torch_geometric`).
        *   **Graph Construction:** Build a Bipartite Graph between Users and Items based on purchase history.
        *   **Propagation:** Perform graph convolution (neighbor aggregation) to refine User and Item embeddings. This explicitly models the collaborative signal: a user is represented by the aggregation of items they bought, and items by the users who bought them.
    *   **Retrieval:** For each user, compute the dot product between their learned LightGCN User Embedding and all Item Embeddings to retrieve the top $K$ candidates. This aligns with **Cite solution_lesson_node_00027** by using an aggregation-based representation rather than a brittle sequential one.

2.  **Source B: Linear-Decay Item-Item Co-occurrence (Local Structure):**
    *   **Mechanism:** Construct a sparse similarity matrix based on immediate co-occurrence.
    *   **Configuration:** Apply **Linear Time Decay** ($w = 1/t$) to historical transactions (**Cite solution_lesson_node_00011**).
    *   **Metric:** Use **raw, unnormalized scores** to preserve popularity magnitude (**Cite solution_lesson_node_00006**).

3.  **Source C: Repurchase History (Habit):**
    *   Explicitly retrieve items the user has purchased before, ranked by frequency and recency.

4.  **Source D: Recent Popularity (Trend):**
    *   A fallback list of top-selling items from the most recent week.

**Stage 2: Interaction-Aware Ranking (The "Precision" Layer)**
We will use a **LightGBM** ranker optimized for listwise performance (**Cite solution_lesson_node_00019**), utilizing a high-capacity configuration (**Cite solution_lesson_node_00022**).

*   **Behavioral Features:** Raw scores from Source B (Co-occurrence), Source C (Repurchase), and the **Dot Product Score** from Source A (LightGCN).
*   **Affinity Features:** We will retain the **User-Item Affinity Features** (e.g., "User's historical purchase rate in Candidate's Department"), as these have been proven to dominate static metadata (**Cite solution_lesson_node_00017**).
*   **Contextual Feature:** We will compute the **Last-Item Graph Similarity**. Instead of just using the user's aggregate vector, we will calculate the Cosine Similarity between the *Candidate Item's LightGCN Embedding* and the *LightGCN Embedding of the User's most recent purchase*. This recovers the sequential signal lost during aggregation (**Cite solution_lesson_node_00021**).
*   **Trend Features:** **Sales Velocity** (slope of daily sales) to capture trend direction.

# Data

1.  **Validation Strategy:**
    *   Strictly employ a **Time-based Split**, using the last 7 days of the training data as the Validation Set (**Cite solution_lesson_node_00003**).

2.  **Preprocessing:**
    *   **Co-occurrence Window:** Restrict the training data for Source B to the **most recent 4 weeks** to minimize noise (**Cite solution_lesson_node_00005**).
    *   **Graph Window:** For Source A (LightGCN), use a longer history (e.g., 12 weeks). Unlike co-occurrence counts, the graph structure benefits from more edges to establish connectivity between disparate user groups, and the GCN's aggregation mechanism naturally handles older noise better than raw counts.
    *   **Caching:** Ensure all intermediate files are cached with **Configuration-Aware Filenames** (**Cite solution_lesson_node_00016**).

# Training

1.  **Phase 1: Graph Representation Learning:**
    *   Construct the User-Item Bipartite Graph from the 12-week window.
    *   Train LightGCN using **BPR (Bayesian Personalized Ranking) Loss**.
    *   **Crucial:** Use robust negative sampling (e.g., 1 positive : 10 negatives) to ensure the embeddings discriminate well, addressing the data efficiency issues seen in **Cite solution_lesson_node_00029**.

2.  **Phase 2: Retrieval Construction:**
    *   Build the Linear-Decay Co-occurrence Matrix (Source B).
    *   Perform Approximate Nearest Neighbor (ANN) search using the LightGCN User/Item Embeddings (Source A).
    *   Generate the union of candidates for Validation Users.

3.  **Phase 3: Ranker Optimization:**
    *   Construct the dataset with Behavioral, Affinity, Graph, and Trend features.
    *   Train LightGBM using the **`lambdarank`** objective (**Cite solution_lesson_node_00019**).
    *   Use **High Model Capacity** (e.g., `num_leaves=128`, `learning_rate=0.03`) to ensure the tree can learn complex boundaries in the dense embedding space (**Cite solution_lesson_node_00022**).

# Evaluation

1.  **Inference Retraining:**
    *   Shift the time windows forward to include the validation week.
    *   Re-train LightGCN and Re-build the Co-occurrence Matrix on this freshest data (**Cite solution_lesson_node_00005**).
2.  **Prediction:**
    *   Generate candidates for all test `customer_id`s.
    *   Compute features (including the new LightGCN Scores and Last-Item Graph Similarity).
    *   Score with LightGBM, sort by score, and select the top 12 items.
