The `KeyError` occurs because the `prepare_graph_data` function returns an `item_map` that maps **Article IDs (strings) to Indices (integers)**, but the `CandidateGenerator` and `FeatureEngineer` classes expect the inverse mapping (**Indices to Article IDs**) to decode model outputs and look up embeddings. This mismatch causes the code to fail when it attempts to look up an integer index in a dictionary keyed by strings. I will fix this by creating an inverted dictionary (`item_idx_to_id`) in `runfile.py` immediately after graph training and passing this inverted map to the retrieval and feature engineering components.
