Based on the provided lessons and previous iterations, I propose a **Hybrid Multi-Source Retrieval & Interaction-Aware Ranking** strategy. This approach structurally evolves the previous "Retrieve and Rank" idea by diversifying the candidate generation sources (improving Recall) and transforming static metadata into dynamic user-item interaction features (improving Precision).

# Model

The architecture is a two-stage pipeline designed to maximize the utility of behavioral signals while forcing the integration of content metadata through explicit feature interaction.

**Stage 1: Hybrid Candidate Retrieval (The "Recall" Layer)**
Instead of relying on a single Item-Item model, we will employ a **Multi-Source Retrieval Strategy** to generate a union of candidates. This addresses different user behaviors (discovery vs. habit).
1.  **Source A: Linear-Decay Item-Item Co-occurrence:**
    *   We will construct a similarity matrix based on user history.
    *   **Configuration:** We will apply a **Linear Time Decay** ($w = 1/t$) to historical transactions. This preserves signal density better than aggressive polynomial decay, allowing the model to learn stable structural relationships (Cite Lesson 00011).
    *   **Scoring:** We will output **raw, unnormalized co-occurrence scores**. We explicitly reject Cosine Normalization to preserve the magnitude of popularity signals, which are predictive in this domain (Cite Lesson 00006).
2.  **Source B: Repurchase History:**
    *   We will explicitly retrieve the items a user has purchased most frequently/recently within the training window. This captures the "habitual" purchase signal that pure Item-Item CF might miss if the item doesn't co-occur strongly with *other* items.
3.  **Source C: Decayed Popularity:**
    *   A fallback list of the top-selling items from the most recent week to ensure coverage for cold-start users.

**Stage 2: Interaction-Aware Ranking (The "Precision" Layer)**
We will use a **LightGBM** ranker. However, we will fundamentally change the feature engineering paradigm.
*   **Problem:** Previous iterations showed that raw metadata (e.g., "Item is Red") was ignored by the model in favor of behavioral signals (Cite Lesson 00012).
*   **Solution:** We will replace static metadata features with **User-Item Affinity Features**.
    *   **User Profiling:** For every metadata attribute (e.g., `department_no`, `colour_group_code`), we will compute a user preference vector based on their history (e.g., "User A buys 80% from Dept X").
    *   **Interaction Features:** The ranker will receive features representing the *match* between the user's profile and the candidate item (e.g., `User_Dept_Preference_Score` for the candidate's department). This forces the ranker to evaluate metadata *contextually* rather than statically.

# Data

1.  **Validation Strategy:**
    *   We will strictly enforce a **Time-based Split**, using the last 7 days of the training data as the Validation Set. This ensures the model has access to historical context for validation users, avoiding the artificial cold-start failure of random splits (Cite Lesson 00003).

2.  **Preprocessing:**
    *   **Time Window:** We will restrict the training data for the Retrieval Stage to the **most recent 4 weeks**. This reduces noise from obsolete fashion trends and improves computational efficiency (Cite Lesson 00005).
    *   **Candidate Construction:** For the training set of the Ranker, we will generate candidates for the Validation Users using the Retrieval models trained on the *pre-validation* 4-week window.
    *   **Labeling:** Positive samples are items actually bought in the validation week. Negative samples are items retrieved by the Hybrid model but *not* bought (Hard Negatives).

# Training

1.  **Retrieval Pre-computation:**
    *   Compute the Co-occurrence Matrix (Linear Decay) and User History lists.
    *   Generate a candidate pool (e.g., Top 60 from Co-occurrence + Top 20 from Repurchase + Top 12 Popularity) for every user in the Validation Set.

2.  **Feature Engineering:**
    *   Compute **Behavioral Features:** `cooccurrence_score` (raw), `repurchase_count`, `popularity_rank`.
    *   Compute **Interaction Features:** Calculate the dot product or ratio between the User's historical distribution of attributes (Department, Color, Garment Group) and the Candidate Item's attributes.

3.  **Ranker Optimization:**
    *   Train LightGBM using the `lambdarank` objective (optimizing for ranking quality) or `binary_logloss`.
    *   Apply Early Stopping based on the Validation MAP@12.

# Evaluation

1.  **Inference Retraining:**
    *   Shift the 4-week window forward to include the validation week (Cite Lesson 00005). Re-calculate the Co-occurrence Matrix and Popularity lists on this freshest data.
    *   Re-calculate User Profiles for the Interaction Features using the full history.

2.  **Prediction:**
    *   Generate the union of candidates for all test customers.
    *   Compute features and score with the trained LightGBM model.
    *   Select the top 12 items per user.
