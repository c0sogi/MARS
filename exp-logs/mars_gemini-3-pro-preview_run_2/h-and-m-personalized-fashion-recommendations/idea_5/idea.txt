Based on the progression of experiments and the "Lessons" provided, I propose a **Hybrid Sequential-Structural Retrieval & Interaction-Aware Ranking** strategy. This approach structurally evolves the previous "Latent Behavioral Embeddings" (Idea 4) by replacing static user representations (Item2Vec averaging) with **Dynamic Sequential Encoding (Transformer)**. This directly addresses the "Aggregation destroys sequence" issue identified in Lesson 00021 while retaining the highly effective co-occurrence and affinity feature engineering protocols.

# Model

The architecture is a **Two-Stage Pipeline** that combines the robustness of structural graph signals with the temporal precision of deep sequential learning.

**Stage 1: Multi-Source Candidate Retrieval (The "Recall" Layer)**
We will generate a union of candidates from four distinct sources to cover Structure, Sequence, Habit, and Trend:

1.  **Source A: Linear-Decay Item-Item Co-occurrence (Structure):**
    *   **Mechanism:** Construct a sparse similarity matrix based on user purchase history.
    *   **Configuration:** Apply **Linear Time Decay** ($w = 1/t$) to historical transactions (Cite solution_lesson_node_00011).
    *   **Metric:** Use **raw, unnormalized scores** to preserve the magnitude of popularity signals, which are highly predictive (Cite solution_lesson_node_00006).

2.  **Source B: Sequential Deep Retrieval (Sequence) [Structural Innovation]:**
    *   **Concept:** Previous iterations used Item2Vec, which averages item vectors to represent a user. This "bag-of-items" approach fails to capture the order of purchases (Cite solution_lesson_node_00021).
    *   **Mechanism:** We will implement a lightweight **Transformer-based Sequential Encoder** (inspired by SASRec).
        *   **Input:** The sequence of `article_id`s purchased by a user, ordered by time.
        *   **Architecture:** A Transformer Encoder (e.g., 2 layers, 128-dim embeddings, Multi-Head Attention) that outputs a dense **User State Vector** based on the entire sequence context.
    *   **Retrieval:** For each user, we compute the dot product between their dynamic User State Vector and all Item Embeddings, retrieving the top $K$ items. This allows the model to recommend items that naturally follow the *current* state of the user's interest, rather than their average historical interest.

3.  **Source C: Repurchase History (Habit):**
    *   Explicitly retrieve items the user has purchased before, ranked by frequency and recency.

4.  **Source D: Recent Popularity (Trend):**
    *   A fallback list of top-selling items from the most recent week.

**Stage 2: Interaction-Aware Ranking (The "Precision" Layer)**
We will use a **LightGBM** ranker optimized for listwise performance (Cite solution_lesson_node_00019), using a high-capacity configuration (Cite solution_lesson_node_00022).

*   **Behavioral Features:** Raw scores from Source A (Co-occurrence), Source C (Repurchase), and the **Logits** from Source B (Sequential Model).
*   **Affinity Features:** We will retain the **User-Item Affinity Features** (e.g., "User's historical purchase rate in Candidate's Department"), as these have been proven to dominate static metadata (Cite solution_lesson_node_00017).
*   **Trend Features:** **Sales Velocity** (slope of daily sales) to capture trend direction (Cite solution_lesson_node_00019).
*   **Contextual Feature:** We will compute the **Last-Item Similarity** using the embeddings learned by the Sequential Model, providing a specific signal for immediate compatibility (Cite solution_lesson_node_00021).

# Data

1.  **Validation Strategy:**
    *   Strictly employ a **Time-based Split**, using the last 7 days of the training data as the Validation Set (Cite solution_lesson_node_00003).

2.  **Preprocessing:**
    *   **Co-occurrence Window:** Restrict the training data for Source A to the **most recent 4 weeks** to minimize noise (Cite solution_lesson_node_00005).
    *   **Sequential Window:** For Source B (Transformer), use a longer history (e.g., 12 weeks) to allow the model to learn long-term transition patterns and item semantics.
    *   **Caching:** Ensure all intermediate files are cached with **Configuration-Aware Filenames** (hashing parameters into the name) to prevent stale data loading (Cite solution_lesson_node_00016).

# Training

1.  **Phase 1: Sequential Representation Learning:**
    *   Train the Transformer model on user sequences using a **Next-Item Prediction** objective (Causal Language Modeling).
    *   Extract Item Embeddings and User State Vectors.

2.  **Phase 2: Retrieval Construction:**
    *   Build the Linear-Decay Co-occurrence Matrix (Source A).
    *   Perform Approximate Nearest Neighbor (ANN) search using the User State Vectors from Phase 1 (Source B).
    *   Generate the union of candidates for Validation Users.

3.  **Phase 3: Ranker Optimization:**
    *   Construct the dataset with Behavioral, Affinity, and Trend features.
    *   Train LightGBM using the **`lambdarank`** objective to optimize MAP@12 directly (Cite solution_lesson_node_00019).
    *   Use **High Model Capacity** (e.g., `num_leaves=128`, `learning_rate=0.03`) to ensure the tree can learn complex boundaries in the dense embedding space (Cite solution_lesson_node_00022).

# Evaluation

1.  **Inference Retraining:**
    *   Shift the time windows forward to include the validation week.
    *   Re-train the Sequential Model and Re-build the Co-occurrence Matrix on this freshest data (Cite solution_lesson_node_00005).
2.  **Prediction:**
    *   Generate candidates for all test `customer_id`s.
    *   Compute features (including the new Sequential Logits).
    *   Score with LightGBM, sort by score, and select the top 12 items.
