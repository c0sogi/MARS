Based on the analysis of the task and the lessons learned from previous iterations, I propose a **Two-Stage Retrieve-and-Rank Pipeline**. This approach structurally evolves the solution from a single-stage heuristic (which lacks the capacity to learn complex feature interactions) to a hybrid system that combines the efficiency of collaborative filtering with the precision of supervised learning.

# Model

The architecture consists of two distinct stages:

1.  **Stage 1: Candidate Retrieval (The "Recall" Layer)**
    *   **Goal:** Efficiently reduce the search space from ~100,000 items to a manageable set of candidates (e.g., Top 50-100) per user.
    *   **Mechanism:** We will retain the **Time-Weighted Item-Item Co-occurrence** model from the previous ideas, as it effectively captures the "frequently bought together" signal.
    *   **Key Configuration:** Based on **Cite solution_lesson_node_00006**, this stage will utilize **high-decay recency weighting** and output **raw, unnormalized co-occurrence scores**. We explicitly avoid cosine normalization to preserve the magnitude of popularity signals, which are predictive in this domain.
    *   **Augmentation:** To address cold-start users (who have no history to trigger co-occurrence), we will augment the candidate set with a "Global Popularity" list derived from the most recent week of data.

2.  **Stage 2: Ranking (The "Precision" Layer)**
    *   **Goal:** Re-order the retrieved candidates to maximize MAP@12 by learning specific user-item preferences.
    *   **Mechanism:** A Gradient Boosted Decision Tree (LightGBM) trained as a binary classifier (or ranker).
    *   **Input:** User-Item pairs generated by Stage 1.
    *   **Features:**
        *   **Signal Features:** The raw score from the Stage 1 retrieval model (Cite solution_lesson_node_00006).
        *   **User Metadata:** Age, Club Member Status (from `customers.csv`).
        *   **Item Metadata:** Product Type, Graphical Appearance, Colour Group, Perceived Colour (from `articles.csv`).
        *   **Content-Based Features (New):** To utilize the provided image dataset, we will extract visual embeddings (using a pre-trained ResNet from `torchvision`) for all items. We will compute a "Visual Similarity" score between the candidate item and the average embedding of the user's recent purchases. This adds a content-driven signal that is robust to cold-start items.

# Data

1.  **Validation Strategy:**
    *   We will strictly employ a **Time-based Split** (Cite solution_lesson_node_00003).
    *   **Validation Set:** Transactions from the final 7 days of the training data.
    *   **Training Set (for Stage 1):** Transactions from the 4 weeks *immediately preceding* the validation week (Cite solution_lesson_node_00005). Using a longer history is avoided to minimize noise from obsolete trends.

2.  **Dataset Construction for Ranker:**
    *   **Positive Samples:** Items actually purchased by users in the Validation Set.
    *   **Negative Samples:** Items retrieved by Stage 1 for those same users that were *not* purchased. This "hard negative" mining ensures the Ranker learns to discriminate between "generally popular" items and "personally relevant" items.

# Training

1.  **Retrieval Pre-computation:**
    *   Construct the Co-occurrence Matrix using the 4-week training window.
    *   Generate candidate lists for all users present in the Validation Set.

2.  **Feature Engineering:**
    *   For every (User, Candidate) pair, compute the metadata, interaction, and visual features.
    *   Label the pairs (1 if bought, 0 otherwise).

3.  **Ranker Training:**
    *   Train the LightGBM model on this labeled dataset.
    *   Objective: `binary_logloss` (or `lambdarank` if computationally feasible).
    *   Use Early Stopping based on the validation metric to prevent overfitting.

# Evaluation

1.  **Inference Preparation:**
    *   Shift the time window forward: Retrain the Stage 1 Co-occurrence Matrix using the *most recent* 4 weeks of data (including the week previously used for validation) to capture the latest trends (Cite solution_lesson_node_00005).
2.  **Candidate Generation:**
    *   Generate candidates for all `customer_id`s in the `sample_submission.csv`.
3.  **Scoring & Submission:**
    *   Compute features for these test candidates.
    *   Use the trained Ranker to predict probabilities.
    *   Sort candidates by probability descending and select the top 12 unique items per user.
    *   Format and save to `submission.csv`.
