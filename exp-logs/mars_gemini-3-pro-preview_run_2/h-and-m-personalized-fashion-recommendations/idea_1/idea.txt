Based on the provided dataset analysis and model architectures, I propose the following baseline approach. This solution prioritizes efficiency and robustness, avoiding the data merging issues observed in the EDA (where metadata joins failed) by relying primarily on transaction history.

### Model
I propose a **Time-Weighted Item-Item Co-occurrence** model, conceptually based on **Model Architecture 1**.
*   **Core Concept:** The model rests on the assumption that items frequently purchased together by the same users are similar. If a user recently bought Item A, and Item A is often bought with Item B by other users, then Item B is a strong candidate for recommendation.
*   **Time Decay:** To account for the fast-moving nature of fashion trends, the model applies a time-decay function. Co-occurrences and user history are weighted such that recent interactions contribute significantly more to the similarity score than older ones.
*   **Components:**
    1.  **Similarity Matrix:** A sparse matrix where entry $(i, j)$ represents the weighted frequency of users purchasing both item $i$ and item $j$.
    2.  **Popularity Fallback:** A simple "Trending Now" heuristic to fill prediction slots when a user has insufficient history or similarity matches.

### Data
1.  **Source:** We will use `transactions_train.csv` exclusively for the core logic, ignoring `articles.csv` and `customers.csv` to avoid the join failures observed in the EDA.
2.  **Filtering:** To maximize efficiency and relevance, we will filter the training data to include only transactions from the last 4 weeks. This reduces the memory footprint and focuses on current fashion trends.
3.  **Encoding:** `customer_id` and `article_id` strings will be label-encoded to integers to minimize memory usage and speed up matrix operations.
4.  **Grouping:** Data will be grouped by `customer_id` to create lists of purchased items per user, which serves as the input for the co-occurrence calculation.

### Training
This approach uses a heuristic calculation rather than gradient-based optimization:
1.  **Weight Calculation:** For every transaction, assign a weight $w_t$ based on the date, where $w_t$ decreases as the date gets further from the test period (e.g., linear or exponential decay).
2.  **Matrix Construction:** Iterate through the grouped user histories. For each user, generate pairs of items $(i, j)$ purchased by that user. Add the sum of their transaction weights to the Similarity Matrix at position $(i, j)$.
3.  **Normalization:** Normalize the rows of the matrix to prevents highly popular items from dominating all recommendations purely due to volume.
4.  **Global Popularity:** Separately, calculate the top 12 most popular items in the last week of data to serve as the fallback list.

### Evaluation
1.  **History Lookup:** For each `customer_id` in the test set, retrieve their purchase history from the training period.
2.  **Candidate Scoring:**
    *   Identify the items the user purchased most recently.
    *   Query the Similarity Matrix to find items most similar to these recent purchases.
    *   Sum the similarity scores for each candidate item.
3.  **Ranking & Filling:**
    *   Rank the candidates by their aggregated score.
    *   Select the top $K$ unique items (up to 12).
    *   If fewer than 12 items are found (cold-start users or sparse history), fill the remaining slots with the pre-calculated Global Popularity list.
4.  **Formatting:** Decode the integer IDs back to the original string `article_id` format and save the submission.
