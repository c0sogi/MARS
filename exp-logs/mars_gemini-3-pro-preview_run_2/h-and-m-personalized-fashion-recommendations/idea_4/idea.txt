Based on the progression of experiments and the specific lessons learned, I propose a **Hybrid Multi-Source Retrieval with Latent Behavioral Embeddings** strategy. This approach structurally evolves the previous "Retrieve & Rank" solutions by introducing **Representation Learning (Item2Vec)** to capture latent behavioral similarities that simple co-occurrence counting misses, while strictly adhering to the successful data splitting and feature engineering protocols identified in the lessons.

# Model

The architecture is a **Two-Stage Pipeline** designed to maximize Recall through diverse retrieval strategies and maximize Precision through interaction-aware ranking.

**Stage 1: Multi-Source Candidate Retrieval (The "Recall" Layer)**
We will generate a union of candidates from four distinct sources to cover different aspects of user behavior (Structure, Semantics, Habit, and Trend):
1.  **Source A: Linear-Decay Item-Item Co-occurrence (Structure):**
    *   We will construct a sparse similarity matrix based on user purchase history.
    *   **Configuration:** Apply **Linear Time Decay** ($w = 1/t$) to historical transactions (Cite solution_lesson_node_00011).
    *   **Metric:** Use **raw, unnormalized scores**. We explicitly reject Cosine Normalization to preserve the magnitude of popularity signals, which are highly predictive (Cite solution_lesson_node_00006).
2.  **Source B: Latent Behavioral Embeddings (Semantics) [New]:**
    *   **Concept:** Pure co-occurrence fails to capture transitive relationships (e.g., Item A and Item C are similar because both are bought with Item B, even if never bought together).
    *   **Mechanism:** We will train a **Word2Vec (Skip-gram)** model on user purchase sequences, treating item IDs as "words" and user histories as "sentences".
    *   **Retrieval:** For each user, we calculate a **User Vector** (average of their recent item vectors) and retrieve the top $K$ items with the highest **Cosine Similarity** in the embedding space. This introduces a "Vector Space" retrieval mechanism alongside the "Graph Space" mechanism.
3.  **Source C: Repurchase History (Habit):**
    *   Explicitly retrieve items the user has purchased before, ranked by frequency and recency.
4.  **Source D: Recent Popularity (Trend):**
    *   A fallback list of top-selling items from the most recent week.

**Stage 2: Interaction-Aware Ranking (The "Precision" Layer)**
We will use a **LightGBM** ranker (Cite solution_lesson_node_00008) with an enhanced feature set that combines explicit counts with latent affinities.
*   **Behavioral Features:** Raw scores from Source A (Co-occurrence), Source B (Embedding Similarity), and Source C (Repurchase counts).
*   **Affinity Features:** We will retain the **User-Item Affinity Features** (e.g., "User's purchase rate in Candidate's Department"), as these have been proven to dominate static metadata (Cite solution_lesson_node_00017).
*   **Trend Features:** We will calculate the **Sales Velocity** (slope of daily sales count) for each candidate item over the last 7 days to help the model distinguish between "fading" and "rising" trends.

# Data

1.  **Validation Strategy:**
    *   We will strictly employ a **Time-based Split**, using the last 7 days of the training data as the Validation Set (Cite solution_lesson_node_00003).
2.  **Preprocessing:**
    *   **Co-occurrence Window:** Restrict the training data for the Co-occurrence matrix to the **most recent 4 weeks** to minimize noise (Cite solution_lesson_node_00005).
    *   **Embedding Window:** Use a slightly longer window (e.g., 10 weeks) for training the Item2Vec model. Unlike raw counts, embeddings require more context to converge and are less sensitive to immediate trend shifts, allowing us to learn robust semantic representations.
    *   **Caching:** We will implement **Configuration-Aware Caching**. All intermediate files (candidates, features) will include a hash of their configuration parameters in the filename to prevent the "Parameter-Blind Caching" failure (Cite solution_lesson_node_00016).

# Training

1.  **Representation Learning:**
    *   Train the Item2Vec model on the 10-week sequence data.
2.  **Retrieval Construction:**
    *   Build the Linear-Decay Co-occurrence Matrix on the 4-week window.
    *   Generate the union of candidates (Sources A+B+C+D) for the Validation Users.
3.  **Feature Engineering:**
    *   Compute Behavioral Features (Co-occurrence Score, Embedding Cosine Similarity).
    *   Compute Affinity Features (User Profile vs. Item Attribute).
    *   Label data: 1 if bought in Validation week, 0 otherwise.
4.  **Ranker Optimization:**
    *   Train LightGBM using the `lambdarank` objective.
    *   Apply Early Stopping based on Validation MAP@12.

# Evaluation

1.  **Inference Retraining:**
    *   Shift the time windows forward to include the validation week.
    *   Re-train the Item2Vec model and Re-build the Co-occurrence Matrix on this freshest data (Cite solution_lesson_node_00005).
2.  **Prediction:**
    *   Generate candidates for all test `customer_id`s.
    *   Compute features (including the new Embedding Similarity and Sales Velocity).
    *   Score with LightGBM and select the top 12 items.
