The `AssertionError: Model checkpoint not saved` occurs because the `Trainer.fit` method initializes `best_f1` to `0.0` and uses a strict inequality (`val_f1 > best_f1`) to decide whether to save a checkpoint. In the demo run, the model achieves a Validation F1 score of `0.0` (common for initialized models on small debug datasets). Since `0.0 > 0.0` evaluates to `False`, the checkpoint is never saved, causing the subsequent file existence check to fail.

To fix this, I will initialize `best_f1` to `-1.0` in `library/trainer.py`. This ensures that an F1 score of `0.0` in the first epoch is treated as an improvement, triggering the save mechanism while preserving the correct early stopping logic for subsequent epochs. This adjustment ensures the pipeline handles the low metric values typical of debug/small data scenarios (Cite {debug_lesson_3}).
