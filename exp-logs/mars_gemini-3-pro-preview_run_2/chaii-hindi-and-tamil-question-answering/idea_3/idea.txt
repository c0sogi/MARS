Based on the lessons learned from the previous experiments, I propose a **Robust Cross-Validated MuRIL Ensemble**.

This strategy addresses the high variance observed in small datasets (Cite solution_lesson_node_00008) and corrects the specific failure mode of the previous attempt where a stronger model was undertrained (Cite solution_lesson_node_00009). By combining a language-specific backbone with a rigorous training regimen, we aim to maximize representational power without sacrificing convergence.

# Model
I propose replacing the generic, lightweight `distilbert-base-multilingual-cased` with **`google/muril-base-cased` (MuRIL)**.
- **Architecture:** MuRIL is a BERT-base architecture (12 layers) specifically pre-trained on 17 Indian languages, including Hindi and Tamil, using both masked language modeling and translation language modeling. This provides a significantly stronger inductive bias for the target languages compared to the distilled multilingual baseline.
- **Ensemble:** Instead of a single model, the solution will consist of **$K$ independent models** (where $K=3$ or $5$), each acting as a voter in an ensemble.
- **Head:** Each backbone will utilize a standard linear Question Answering head to project token embeddings into start and end logits.

# Data
- **Preprocessing (Sliding Windows):** Given the extreme length of the context passages, we will strictly retain the **sliding window strategy with overlap** (e.g., stride=128, window=384). This ensures that answer spans located deep in the text or across boundaries are successfully captured (Cite solution_lesson_node_00001).
- **Splitting Strategy:** We will employ **Group K-Fold Cross-Validation**, grouping by `context`. This ensures that all questions derived from the same paragraph remain in the same fold, preventing data leakage while allowing us to utilize the entire dataset for training across the ensemble members.

# Training
- **Training Duration:** A critical correction from previous attempts is to ensure sufficient convergence time. We will train each fold for **3 to 5 epochs**. We will not reduce the epoch count to compensate for the larger model size, as previous experiments demonstrated that undertraining a heavy model leads to catastrophic failure (Cite solution_lesson_node_00009). The available A100 compute is sufficient to handle this increased load.
- **Optimization:** We will use the **AdamW** optimizer combined with a **linear learning rate scheduler with warmup**. This is mandatory to stabilize the fine-tuning of the randomly initialized head and prevent the "oscillation" observed with constant learning rates (Cite solution_lesson_node_00003).
- **Precision:** Mixed Precision (FP16) will be used to accelerate training and reduce memory overhead.

# Evaluation
- **Ensemble Inference:** During the test phase, each sliding window input will be processed by all $K$ trained models. We will **average the start and end logits** across the ensemble before decoding. This statistical averaging is essential to mitigate the high variance and noise inherent in training on small datasets (Cite solution_lesson_node_00008).
- **Span Selection:** The aggregated logits will be used to identify the optimal answer span by maximizing the sum of start and end scores.
- **Regression Gate:** We will maintain the conditional submission logic. The final submission will only be generated if the cross-validated metric of the current run exceeds the best historical performance, protecting the leaderboard score from stochastic regression (Cite solution_lesson_node_00002).
