The issue stems from the fact that `Config.SUBMISSION_CSV` is initialized at the module level in `library/config.py` using the default `WORKING_DIR` ("./working/idea_3"). When `runfile.py` dynamically changes `Config.WORKING_DIR` to "./working/demo_run" for the debug session, `Config.SUBMISSION_CSV` retains the old path pointing to the non-existent "idea_3" directory, causing an `OSError` when saving the submission. The fix is to explicitly update `Config.SUBMISSION_CSV` in `runfile.py` immediately after modifying `Config.WORKING_DIR` so that it points to the correct location.
