Based on the accumulated lessons and the failure modes of previous attempts, I propose a **Correctly Configured MuRIL Cross-Validation Ensemble**.

This strategy represents a structural evolution from the single DistilBERT baseline to a robust, language-specific ensemble. It specifically targets the "dead code" and "undertraining" issues that caused previous attempts at using stronger backbones to fail.

# Model
We will transition the backbone from the lightweight `distilbert-base-multilingual-cased` to **`google/muril-base-cased` (MuRIL)**.
*   **Architecture:** MuRIL is a 12-layer BERT-based model pre-trained on Indian languages with a specific focus on transliteration and language proximity, offering a far superior inductive bias for Hindi and Tamil than the generic multilingual DistilBERT.
*   **Structural Correction (Segment Embeddings):** A critical innovation over previous failed attempts is the explicit inclusion of **Segment Embeddings**. Unlike DistilBERT, MuRIL (being a BERT architecture) strictly requires `token_type_ids` to distinguish between the "Question" and "Context" segments of the input. We will configure the model and tokenizer to generate and consume these IDs (0 for Question, 1 for Context), correcting the architecture mismatch that previously led to model failure (Cite solution_lesson_node_00018).
*   **Head:** We will use a standard linear classification head to project the hidden states into start and end logits.

# Data
*   **Preprocessing (Sliding Windows):** We will strictly retain the **sliding window strategy with overlap** (e.g., stride=128, window=384) to handle context passages that exceed the model's maximum sequence length. This ensures answer spans located deep in the text are preserved (Cite solution_lesson_node_00001).
*   **Splitting Strategy:** To address the high variance and instability observed when training on this small dataset (Cite solution_lesson_node_00008), we will implement **Group K-Fold Cross-Validation** (with $K=3$). Data will be grouped by the `context` column to prevent leakage between folds. This allows us to utilize the entire dataset for training across the ensemble while maintaining rigorous validation.

# Training
*   **Training Duration:** We will train each of the $K$ folds for **3 to 4 epochs**. We will explicitly avoid the mistake of reducing the epoch count to compensate for the larger model size, as heavier models like MuRIL require sufficient steps to converge, and undertraining leads to catastrophic performance drops (Cite solution_lesson_node_00009).
*   **Optimization:** We will employ the **AdamW** optimizer combined with a **linear learning rate scheduler with warmup**. This is mandatory to stabilize the fine-tuning of the randomly initialized head and prevent the optimization difficulties observed with constant learning rates (Cite solution_lesson_node_00003).
*   **Precision:** We will utilize Mixed Precision (FP16) to manage the memory footprint of the larger MuRIL model on the A100 GPU.

# Evaluation
*   **Ensemble Inference:** During the test phase, the input data (and its sliding windows) will be processed by all $K$ independent models generated by the cross-validation. We will **average the start and end logits** across the ensemble members. This statistical averaging is required to mitigate the stochastic noise inherent in single-model predictions on small data (Cite solution_lesson_node_00020).
*   **Span Selection:** The aggregated logits will be processed to select the optimal answer span by maximizing the sum of start and end scores across all valid windows for a given question.
*   **Regression Gate:** We will maintain the conditional submission logic. The final submission file will only be generated if the cross-validated metric of the current run exceeds the best historical performance, protecting the leaderboard score from regression (Cite solution_lesson_node_00002).
