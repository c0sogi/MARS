Based on the accumulated lessons, I propose a **Multi-Task XLM-RoBERTa Large Ensemble**.

This strategy synthesizes the superior multilingual performance of the XLM-R backbone (Cite solution_lesson_node_00028) with a structural innovation designed to resolve the conflict between the high noise of sliding windows (Cite solution_lesson_node_00023) and the performance degradation caused by removing that noise (Cite solution_lesson_node_00025).

# Model
I propose upgrading the backbone to **`xlm-roberta-large`** and implementing a **Multi-Task Prediction Head**.
*   **Backbone:** We will scale up from the `base` model to `xlm-roberta-large`. The 24-hour compute budget with an A100 GPU is more than sufficient to accommodate this larger model, ensuring we maximize representational power for the complex Hindi and Tamil scripts (Cite solution_lesson_node_00028). Crucially, XLM-R does not use `token_type_ids`, avoiding the architectural mismatch that caused previous failures with MuRIL (Cite solution_lesson_node_00018).
*   **Multi-Task Heads (Structural Innovation):** To address the signal-to-noise ratio in sliding windows without discarding data, we will attach two distinct heads to the backbone:
    1.  **QA Head:** A standard linear layer to predict `start_logits` and `end_logits` for span extraction.
    2.  **Answerability Head:** A binary classification layer on the `<s>` (CLS) token embedding to predict whether the current window contains the answer ($1$) or is irrelevant ($0$).
    This structure allows the model to learn to "soft-filter" irrelevant text passages dynamically, resolving the trade-off where removing negatives hurt performance (Cite solution_lesson_node_00025) but keeping them overwhelmed the model (Cite solution_lesson_node_00023).

# Data
*   **Preprocessing:** We will apply a **sliding window strategy with overlap** (stride=128, window=384) to handle the long context passages (Cite solution_lesson_node_00001).
*   **Negative Retention:** We will **retain all generated windows**, including those without answers. We explicitly reject aggressive negative downsampling, as previous experiments proved this removes essential context and degrades performance (Cite solution_lesson_node_00025). The new Answerability Head will handle the resulting class imbalance.
*   **Splitting:** We will employ **Group K-Fold Cross-Validation** (K=3), grouping by `context`. This ensures no leakage while allowing the ensemble to learn from the full dataset, mitigating the high variance observed in small-data training (Cite solution_lesson_node_00008).

# Training
*   **Objective:** The model will be optimized on a joint loss function: $L = L_{Span} + \lambda L_{Answerability}$, where $L_{Span}$ is Cross-Entropy for token positions and $L_{Answerability}$ is Binary Cross-Entropy for the window classification.
*   **Optimization:** We will use the **AdamW** optimizer with a **linear learning rate scheduler with warmup**. This is mandatory to stabilize the fine-tuning of the new heads and prevent optimization issues (Cite solution_lesson_node_00003).
*   **Duration:** We will train each fold for **3 to 5 epochs**. We will strictly avoid undertraining the large model, as insufficient epochs lead to failure (Cite solution_lesson_node_00009).
*   **Precision:** Mixed Precision (FP16) will be used to manage the memory footprint of the Large model.

# Evaluation
*   **Weighted Inference:** During testing, we will generate predictions using all $K$ ensemble models. For each window, the final score of a candidate span will be calculated as: $\text{Score} = (\text{StartLogit} + \text{EndLogit}) \times \sigma(\text{AnswerabilityLogit})$. This effectively suppresses high-confidence spans found in irrelevant windows.
*   **Ensembling:** We will **average these weighted scores** across the ensemble members before selecting the best span. This aggregation mitigates stochastic noise (Cite solution_lesson_node_00020).
*   **Regression Gate:** The submission will only be generated if the cross-validated metric exceeds the best historical performance (Cite solution_lesson_node_00002).
