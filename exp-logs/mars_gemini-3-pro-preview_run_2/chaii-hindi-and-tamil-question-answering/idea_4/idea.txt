Based on the accumulated lessons and previous experiments, I propose a **Segment-Aware MuRIL Ensemble**. This strategy evolves the previous ideas by aligning the model architecture with the correct input features (addressing the "dead code" issue) and implementing a robust training regimen to handle the small dataset size and high variance.

# Model
We will transition from the distilled multilingual model to **`google/muril-base-cased` (MuRIL)**.
- **Backbone:** MuRIL is a 12-layer BERT-based model pre-trained specifically on Indian languages (including Hindi and Tamil). This offers a stronger inductive bias for the target languages than the generic `distilbert-base-multilingual-cased`.
- **Feature Alignment (Structural Innovation):** Unlike the DistilBERT baseline, MuRIL supports and benefits from **Segment Embeddings**. We will explicitly generate and feed `token_type_ids` to the model (0 for Question tokens, 1 for Context tokens). This allows the model to structurally distinguish between the query and the passage, correcting the feature-architecture mismatch observed in previous attempts (Cite solution_lesson_node_00016).
- **Head:** A standard linear QA head will be used to predict start and end logits.

# Data
- **Preprocessing (Sliding Windows):** We will retain the **sliding window strategy with overlap** (e.g., stride=128, window=384) to handle the long context passages. This ensures that answers located deep in the text are captured (Cite solution_lesson_node_00001).
- **Splitting Strategy:** To mitigate the high variance inherent in small datasets (Cite solution_lesson_node_00008), we will implement **Group K-Fold Cross-Validation** (with $K=3$ or $5$). Data will be grouped by `context` to prevent leakage. This allows us to use the entire dataset for training across the ensemble while maintaining rigorous validation.

# Training
- **Training Duration:** We will train each fold for **4 to 5 epochs**. We will strictly avoid reducing the epoch count, as previous experiments demonstrated that heavier models like MuRIL require more steps to converge than lightweight models, and undertraining leads to failure (Cite solution_lesson_node_00009).
- **Optimization:** We will use the **AdamW** optimizer with a **linear learning rate scheduler with warmup**. This is essential to stabilize the fine-tuning of the randomly initialized head and prevent optimization difficulties (Cite solution_lesson_node_00003).
- **Precision:** Mixed Precision (FP16) will be used to manage the memory footprint of the larger MuRIL model on the A100 GPU.

# Evaluation
- **Ensemble Inference:** During the test phase, input windows will be processed by all $K$ models in the cross-validation ensemble. We will **average the start and end logits** across the folds before decoding. This statistical averaging reduces the noise and variance associated with single-seed training runs (Cite solution_lesson_node_00008).
- **Regression Gate:** The submission generation will be wrapped in a conditional check. The final submission will only be created if the cross-validated Jaccard score of the current ensemble exceeds the best historical performance, preventing regression due to stochasticity (Cite solution_lesson_node_00002).
