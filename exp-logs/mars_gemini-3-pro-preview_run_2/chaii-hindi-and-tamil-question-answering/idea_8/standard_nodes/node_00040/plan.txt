The implementation strategy follows the robust pipeline design outlined in the "Idea" section. 

1.  **Training**: We define a `run_training` function that iterates through the 3 random seeds specified in the configuration. For each seed, it initializes the `CustomXLMRoberta` model (with weighted layer pooling and multi-task heads), prepares the training data using the sliding window approach, and trains for 2 epochs. We utilize the `train_fn` from the library, which handles gradient accumulation and adversarial training (FGM). The best model state for each seed is saved to the working directory.

2.  **Validation**: The `run_validation` function evaluates the ensemble. It loads the hold-out validation set from `./metadata/val.csv`. Crucially, it manages the feature cache to prevent collisions between validation and test data. It runs inference using all 3 trained models, averages their logits, and extracts the best answer spans. It then computes the Word-level Jaccard score, prints the `Final Validation Metric`, and performs failure analysis by calculating the correlation between error magnitude and input text lengths.

3.  **Submission**: The `main` function orchestrates the flow. If the validation metric exceeds the threshold of `0.5907916666666666`, it invokes the `inference_fn` from the library to generate predictions on the test set. Finally, it ensures the submission file is placed in the required `./submission/submission.csv` path.
