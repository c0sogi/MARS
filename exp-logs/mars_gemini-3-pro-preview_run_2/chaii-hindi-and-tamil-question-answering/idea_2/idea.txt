To address the challenges of high variance on a small dataset and the linguistic complexity of Hindi and Tamil, I propose a structural evolution from a single lightweight model to a **Cross-Validated Ensemble of Language-Specific Transformers**. This strategy prioritizes stability and representational power over raw speed, utilizing the available A100 GPU to deploy a more robust architecture.

# Model
I propose replacing the generic `distilbert-base-multilingual-cased` with **`google/muril-base-cased` (MuRIL)**.
- **Architecture:** MuRIL (Multilingual Representations for Indian Languages) is a 12-layer BERT-based model pre-trained specifically on Indian text corpora with a focus on transliteration and language proximity. This provides a stronger inductive bias for Hindi and Tamil compared to the distilled multilingual baseline.
- **Ensemble Structure:** Instead of a single model instance, the solution will consist of **$K$ independent model checkpoints** (where $K=5$), each trained on a different subset of the data.
- **Head:** Each backbone will retain the standard Question Answering head (linear projection to start/end logits).

# Data
- **Preprocessing:** We will retain the **sliding window strategy with overlap** to handle the extremely long context passages (mean ~11k characters). Inputs will be chunked with a stride (e.g., 128 tokens) to ensure answer spans are not lost at truncation boundaries (Cite solution_lesson_node_00001).
- **Splitting:** To address the instability inherent in small datasets (Cite solution_lesson_node_00008), we will implement **Group K-Fold Cross-Validation**. The training data will be split into $K$ folds, grouped by `context` to prevent data leakage (ensuring questions about the same paragraph remain in the same fold). This replaces the single fixed train/validation split.

# Training
- **Procedure:** We will execute a training loop that trains $K$ separate models. For each fold $i$:
    - Train on $K-1$ folds and validate on the $i$-th fold.
    - This ensures that every data point is used for both training and validation across the ensemble, maximizing the utility of the small dataset.
- **Optimization:** We will employ the **AdamW** optimizer with a **linear learning rate scheduler with warmup**. This is strictly retained to ensure stable convergence of the classification head before fine-tuning the backbone (Cite solution_lesson_node_00003).
- **Precision:** Mixed Precision (FP16) will be used to maintain reasonable training times despite the heavier model architecture.

# Evaluation
- **Inference Strategy (Ensembling):** During the test phase, each input sample (and its sliding windows) will be processed by all $K$ trained models. We will compute the **average of the start and end logits** across the ensemble members before applying the decoding logic. This statistical averaging mitigates the high variance observed in single-seed runs (Cite solution_lesson_node_00008).
- **Span Selection:** The aggregated logits will be used to select the best answer span using the established `start_logit + end_logit` maximization logic.
- **Regression Gate:** The submission generation will be wrapped in a conditional check. We will calculate the average validation Jaccard score across all folds. The submission file will only be generated if this cross-validated metric exceeds the previous best score, preventing regression due to stochastic noise (Cite solution_lesson_node_00002).
