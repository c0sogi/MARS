To address the task of Question Answering in Hindi and Tamil with a focus on efficiency and simplicity, I propose a **Distilled Multilingual Transformer** baseline. This approach leverages the conceptual foundation of the Transformer architecture (as seen in Model 1) but replaces the computationally heavy base model with a lightweight, distilled variant to satisfy the requirement for speed and low resource usage.

# Model
The core of the proposed architecture is **`distilbert-base-multilingual-cased`**.
- **Backbone:** Unlike the 12-layer `muril-base-cased` (Model 1), this model utilizes a 6-layer Transformer encoder. It is trained using knowledge distillation, retaining 97% of the performance of multilingual BERT while being 40% smaller and 60% faster. This directly addresses the "highly efficient" constraint.
- **Head:** A simple linear classification layer is attached to the hidden states of the last transformer layer. This head projects the embedding of each token into two logits: one for the `start_position` and one for the `end_position` of the answer span.
- **Input:** The model accepts a concatenated sequence of `[CLS] Question [SEP] Context [SEP]`.

# Data
Given the significant length of the context passages (mean ~1600 words) relative to the model's maximum input size (usually 512 tokens), a **sliding window** strategy is essential during preprocessing.
- **Tokenization:** Inputs will be tokenized using the DistilBERT tokenizer.
- **Sliding Window:** Contexts longer than the maximum sequence length (e.g., 384 tokens) will be split into multiple overlapping chunks (windows). A stride (e.g., 128 tokens) will be used to ensure that answers appearing at the boundaries of windows are captured correctly in at least one chunk.
- **Label Mapping:** For training, the character-level `answer_start` and `answer_text` will be mapped to token-level start and end indices within the appropriate window. Windows that do not contain the answer will be labeled with the `[CLS]` token position or ignored, depending on the specific implementation strategy (e.g., training only on positive windows or downsampling negatives).

# Training
- **Objective:** The model will be trained to minimize the **Cross-Entropy Loss** for the start and end token predictions.
- **Optimization:** We will use the **AdamW** optimizer with a linear learning rate decay.
- **Efficiency:** To further enhance speed, **Mixed Precision (FP16)** training will be utilized on the A100 GPU. This reduces memory usage and speeds up tensor operations without significant loss in accuracy.
- **Strategy:** We will fine-tune the entire model (backbone + head) for a small number of epochs (e.g., 2-3) to prevent overfitting, given the distilled nature of the model.

# Evaluation
- **Inference:** During testing, the text context will be chunked into sliding windows as done in preprocessing. The model will output start and end logits for every window.
- **Aggregation:** We will select the span with the highest combined `start_logit + end_logit` score across all windows for a given question-context pair.
- **Post-processing:** The predicted token span will be decoded back into a string. Basic cleanup (handling subword tokens like `##`) will be applied to format the final prediction string.
