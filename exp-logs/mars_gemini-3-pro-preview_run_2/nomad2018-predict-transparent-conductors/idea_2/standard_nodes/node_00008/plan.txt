The implementation strategy follows a structured pipeline to ensure robustness and compliance with the requirements.

1.  **Setup & Data Loading**: We initialize the environment with a fixed random seed for reproducibility. We use the provided `get_dataloaders` function with `load_cached_data=True` to efficiently load the preprocessed graph data.
2.  **Model Initialization**: The `EUGAT` model is instantiated and moved to the appropriate device (GPU if available). The optimizer (AdamW) and scheduler (ReduceLROnPlateau) are set up according to the configuration.
3.  **Training Loop**: A custom training loop is implemented instead of using the library's `run_training` to have granular control over the validation and submission logic. The loop iterates for a maximum of `Config.NUM_EPOCHS`, utilizing `train_one_epoch` for training and `evaluate` for validation. We track the best validation RMSLE (Root Mean Squared Logarithmic Error) and save the model checkpoint whenever an improvement is observed. Early stopping is applied if performance stagnates.
4.  **Final Assessment**: After training, the best model is re-loaded. We run a final evaluation on the full validation set to compute the `Final Validation Metric` (Mean RMSLE) and print it exactly as requested.
5.  **Failure Analysis**: We perform inference on the validation set to compute sample-wise errors (Mean Squared Log Error). These errors are then correlated with the numerical features from the validation metadata (e.g., lattice parameters, atom counts) to identify potential sources of model failure.
6.  **Conditional Submission**: Finally, we check if the `Final Validation Metric` is strictly lower than the specified threshold (0.053007537912991315). If the condition is met, we generate predictions for the test set, apply the inverse transformation to return to the original scale, clamp values to be non-negative, and save the results to `submission.csv`.
