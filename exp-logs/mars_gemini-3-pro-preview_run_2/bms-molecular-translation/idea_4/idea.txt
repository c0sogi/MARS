Idea 4: **Spatial Attention-Guided Recurrent Network**

To establish a highly efficient baseline that balances structural understanding with computational speed, I propose an architecture that integrates a lightweight Convolutional Neural Network (CNN) with an Attention-based Recurrent Decoder.

This approach is strictly distinct from the previous ideas:
-   Unlike **Idea 1 (CRNN+CTC)**, it utilizes a 2D attention mechanism rather than collapsing the image into a 1D sequence, allowing it to handle complex cyclic structures more naturally.
-   Unlike **Idea 2 (Global Context)**, it preserves spatial feature maps and uses attention to focus on specific atoms during generation, rather than compressing the entire image into a single global vector.
-   Unlike **Idea 3 (Transformer)**, it uses a Recurrent Neural Network (GRU) instead of a Transformer decoder, significantly reducing memory usage and training complexity for a baseline implementation.

### Model
The architecture is designed as a "Show, Attend, and Tell" system optimized for efficiency:
1.  **Lightweight Encoder:** The backbone is **MobileNetV3-Small**, pre-trained on ImageNet. The final global average pooling and classification layers are removed to retain the raw spatial feature maps ($H \times W \times C$). A 1x1 convolution layer is added to reduce the channel dimension (e.g., to 256), creating a compact "Feature Grid" that represents the visual content of the molecule while minimizing downstream computational cost.
2.  **Bahdanau Attention:** An Additive Attention module serves as the interface between the encoder and decoder. At each time step, it calculates a weighted sum of the Encoder's feature grid (the "Context Vector") based on the Decoder's previous hidden state. This allows the model to dynamically "look" at the specific atom or bond it is currently transcribing.
3.  **GRU Decoder:** A single-layer **Gated Recurrent Unit (GRU)** acts as the sequence generator. The GRU is chosen over LSTM for its simpler architecture (fewer gates), which translates to faster training and inference. At each step, the GRU takes the embedding of the previously generated character and the dynamic Context Vector to predict the next character in the InChI string.

### Data
*   **Image Preprocessing:** Images are converted to grayscale (1 channel) to reduce data volume. They are resized to a fixed square resolution (e.g., $320 \times 320$) that balances inference speed with the spatial resolution required to read small atomic subscripts. Pixel values are normalized to $[0, 1]$.
*   **Text Preprocessing:** The InChI labels are tokenized at the character level. The vocabulary consists of all unique characters in the training set plus `<SOS>` (Start), `<EOS>` (End), and `<PAD>` (Padding) tokens.
*   **Batching:** Data is batched with fixed-length padding for efficient GPU processing.

### Training
*   **Loss Function:** The model is trained using **Cross-Entropy Loss**, computed between the predicted character probability distribution and the ground truth character at each time step.
*   **Optimization:** The **Adam** optimizer is used with a standard learning rate (e.g., 1e-4).
*   **Training Strategy:** **Teacher Forcing** is employed, where the model is fed the actual ground truth character from the previous step during training. This stabilizes the recurrent network and speeds up convergence compared to free-running generation. Gradient clipping is applied to prevent exploding gradients.

### Evaluation
*   **Prediction:** During inference, the test image is encoded once. The decoder is initialized, and the generation loop begins with the `<SOS>` token.
*   **Decoding:** A **Greedy Decoding** strategy is used. At each step, the character with the highest softmax probability is selected and fed as the input for the next step.
*   **Termination:** The process repeats until the `<EOS>` token is generated or a maximum sequence length (e.g., 400) is reached. The resulting tokens are concatenated to form the final InChI string.
