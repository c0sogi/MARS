Implementation strategy:
1.  **Environment Setup**: Import necessary modules from the provided library files (`library.config`, `library.dataset`, `library.model`, `library.engine`, `library.utils`, `library.tokenizer`) and standard libraries.
2.  **Configuration Override**: Modify `Config` attributes at runtime to create a "fast baseline" configuration suitable for the 2-hour limit. This involves setting `EPOCHS` to 5, enabling `DEBUG` mode, and setting `DEBUG_SAMPLE_SIZE` to 100,000 samples to train on a representative subset. Batch size is increased to 64 to utilize the A100 GPU efficiently.
3.  **Training**: Execute the training pipeline using `library.engine.fit()`. This function handles the training loop, validation per epoch, and saves the best model checkpoint based on Levenshtein distance.
4.  **Full Validation**:
    *   Disable `DEBUG` mode to ensure the subsequent validation and testing phases use the complete datasets.
    *   Load the best saved model.
    *   Iterate through the entire validation dataset using a `DataLoader`.
    *   Compute predictions and calculate the Levenshtein distance for every sample.
    *   Print the `Final Validation Metric` with full precision.
5.  **Failure Analysis**:
    *   Calculate the Pearson correlation between the prediction error (Levenshtein distance) and the target string length for the entire validation set.
    *   Perform a targeted analysis on a random subset (1,000 samples) of the validation data to calculate correlations between the error and input image features (width, height, aspect ratio). This avoids the high I/O cost of reading dimensions for all 380k+ validation images.
6.  **Submission**: Call `library.engine.predict_and_submit()`, which loads the best model, generates predictions for the full test set, and saves the `submission.csv` file.
