The issue is that the `get_features` function in `library/feature_extractor.py` blindly loads cached feature files if they exist, without verifying that the cache contains the correct number of samples for the current dataset. This caused the pipeline to load a stale, incomplete cache (likely from a debug run with only ~16 samples) instead of processing the full dataset (196k samples), leading to immediate overfitting and an invalid validation metric.

To fix this, I will modify `library/feature_extractor.py` to explicitly check if the number of rows in the loaded cached features matches the size of the current dataset (`len(dataloader.dataset)`). If there is a mismatch, the code will log a warning and proceed to re-compute the features instead of returning the stale cache. This implements the "Robustness Fix" suggested in the error analysis.
