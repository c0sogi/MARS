### Proposed Baseline: Kernel-Pooling Interaction Network

This approach introduces a **Kernel-Based Neural Ranking** architecture. It differs from previous ideas by abandoning the "learnable feature extraction" paradigm (CNNs, RNNs, or MLPs applied to text) for the ranking task. Instead, it employs fixed **Radial Basis Function (RBF) Kernels** to perform "soft counting" of word matches at various similarity levels (e.g., exact matches, synonyms, loose associations). This design is inspired by efficient Information Retrieval models, offering high speed and interpretability without the computational cost of deep encoders.

#### **Model**
*   **Embedding Layer:** The model uses pre-trained static word embeddings (e.g., GloVe) to convert tokens into dense vectors. These are frozen to ensure maximum efficiency.
*   **Interaction Matrix:** For a given Question and Long Answer Candidate pair, the model computes a similarity matrix containing the cosine similarity between every question word and every candidate word.
*   **Ranking Module (Kernel Pooling):**
    *   The model applies a set of **$K$ fixed RBF Kernels** to the interaction matrix. Each kernel is defined by a mean and variance, focusing on a specific similarity range (e.g., one kernel counts exact matches $\approx 1.0$, another counts synonyms $\approx 0.7$).
    *   For each question word, the kernel outputs are summed across the candidate text. This generates a **Soft-Match Histogram** vector for every question word, representing how frequently and how strongly that word appears in the candidate.
    *   These vectors are aggregated (log-sum) and passed through a linear layer to produce the **Long Answer Score**.
*   **Span Prediction Module (Depthwise Separable Encoder):**
    *   To predict the short answer, the model constructs a candidate-centric representation. It concatenates each candidate word embedding with its **Maximum Similarity** score to any question word.
    *   This sequence is processed by a stack of **Depthwise Separable 1D Convolutions**. This operation is computationally cheaper than standard convolutions but effectively captures the local context required to identify answer boundaries.
    *   The output is fed to two linear heads to predict **Start** and **End** token probabilities.
*   **Yes/No Head:** The aggregated features from the Ranking Module are passed through a small classifier to predict `YES`, `NO`, or `NONE`.

#### **Data**
*   **Preprocessing:**
    *   **Tokenization:** Text is split using a fast whitespace tokenizer.
    *   **Padding:** Question and candidate sequences are padded/truncated to fixed lengths (e.g., 20 and 300 tokens) to facilitate efficient matrix operations.
    *   **Vocabulary:** Tokens are mapped to indices in the pre-trained embedding matrix.
*   **Labeling:**
    *   **Long Answer:** Binary label (`1` if the candidate matches the annotation, `0` otherwise).
    *   **Short Answer:** Start and End indices relative to the candidate text.
    *   **Yes/No:** Categorical labels.

#### **Training**
*   **Strategy:** The model is trained using a **Multi-Task Learning** objective, optimizing the ranking, span extraction, and Yes/No classification simultaneously.
*   **Sampling:** **Random Negative Sampling** is used to balance the dataset. Each training batch consists of positive question-candidate pairs and a fixed ratio of negative pairs sampled from the same document.
*   **Loss Function:** A weighted sum of three loss components is minimized:
    *   **Binary Cross-Entropy** for the long answer ranking score.
    *   **Sparse Categorical Cross-Entropy** for the start and end span indices.
    *   **Categorical Cross-Entropy** for the Yes/No classification.
*   **Optimizer:** The Adam optimizer is used with a standard learning rate.

#### **Evaluation**
1.  **Inference:** For a test document, the model processes the question paired with every available long answer candidate.
2.  **Long Answer Selection:** The candidate with the highest ranking score is selected. If this score is below a tuned **confidence threshold**, the prediction defaults to `BLANK`.
3.  **Short Answer Extraction:** If a long answer is selected, the span is determined by the indices with the highest logits from the Start and End heads.
4.  **Yes/No Prediction:** The final label is assigned based on the class with the highest probability from the Yes/No Head.
