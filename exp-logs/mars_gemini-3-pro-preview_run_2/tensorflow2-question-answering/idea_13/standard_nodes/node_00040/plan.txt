The implementation strategy for the `runfile.py` script is as follows:

1.  **Configuration and Setup**: Initialize the `Config` class, modifying parameters for a "fast baseline" execution (e.g., reducing `NUM_EPOCHS` to 1). Set random seeds for reproducibility using `torch`, `numpy`, and `random`.
2.  **Data Preparation**:
    *   Initialize `VocabManager` and build/load the vocabulary and embedding matrix from the cache.
    *   Use `get_data_loaders` to create PyTorch DataLoaders for training, validation, and testing. This function handles feature generation via `WindowProcessor` and splitting via metadata.
3.  **Model Initialization**: Instantiate the `WindowMaxPoolingNetwork` using the pre-trained embedding matrix and configuration settings. Move the model to the appropriate device (GPU/CPU).
4.  **Training**: Initialize the `Solver` class and execute the `train` method using the training and validation loaders. This handles the training loop, loss calculation, and backpropagation.
5.  **Validation and Metric Computation**:
    *   Implement a custom evaluation function `evaluate_model` to calculate the Micro F1 score on the validation set.
    *   Iterate through the validation loader in evaluation mode (`torch.no_grad()`).
    *   Aggregate window-level scores by `example_id` to determine the best candidate and span for each question.
    *   Compare predictions against ground truth labels derived from the dataset batches (reconstructing global spans from window-relative labels).
    *   Compute the global Micro F1 score based on exact matches for both long and short answers.
6.  **Failure Analysis**:
    *   Calculate the error magnitude (1.0 - F1 score) for each validation example.
    *   Extract features such as question length (from input IDs).
    *   Compute and print the Pearson correlation between the error and these features to identify failure modes.
7.  **Inference and Submission**:
    *   Use the `solver.inference` method to generate predictions for the test set.
    *   This method handles the aggregation of window scores, thresholding, and formatting of the output string (`start:end` or `YES`/`NO`).
    *   The final submission file is saved to `./submission/submission.csv` as required.
