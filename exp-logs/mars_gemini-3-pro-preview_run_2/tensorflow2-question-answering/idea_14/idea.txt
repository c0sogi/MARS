Based on the analysis of the previous ideas and the provided model architectures, here is a proposal for a highly efficient baseline approach.

### **Proposed Baseline: Context-Query Concatenated Recurrent Network (CQC-RNN)**

This approach introduces a **Conditional Sequential** architecture. It distinguishes itself from the Siamese approaches (Ideas 1, 3, 4, 10) by fusing the question and candidate information *before* the main encoding layers, and from the Single-Stream approaches (Idea 9) by using a vector-to-sequence concatenation strategy processed by Recurrent Neural Networks (GRUs). This design effectively conditions the sequential reading of the candidate text on the global semantic summary of the question, capturing dependencies that pointwise models (Idea 7) miss, while remaining lighter than full attention mechanisms.

#### **Model**
*   **Embedding Layer:** The model utilizes pre-trained static word embeddings (e.g., GloVe) to convert tokens into dense vectors. These are frozen to ensure low memory usage and fast training.
*   **Question Compression:** The variable-length question sequence is aggregated into a single fixed-size **Context Vector** using **Mean Pooling**. This provides a lightweight global summary of the question's intent.
*   **Context Fusion:** The Question Context Vector is replicated (broadcasted) and concatenated with the embedding of *every* token in the Long Answer Candidate. This results in a sequence of inputs where each candidate word is explicitly paired with the global question context.
*   **Conditional Encoder:** A **Bi-Directional Gated Recurrent Unit (Bi-GRU)** processes the fused sequence. The Bi-GRU is computationally more efficient than an LSTM but still captures the sequential context of the candidate text (e.g., "born in" suggests a date follows) conditioned on the question vector attached to each step.
*   **Ranking Head:** An **Attention-Weighted Pooling** layer aggregates the sequence of GRU hidden states into a single document vector. Unlike Max or Mean pooling, this allows the model to learn to weigh specific keywords (like entities or verbs) more heavily when forming the final representation. This vector is passed to a binary classifier to predict the **Long Answer Score**.
*   **Span Prediction Heads:** The full sequence of GRU hidden states (preserving the candidate length) is fed into two parallel linear layers to predict the **Start Token** and **End Token** probabilities for the short answer.
*   **Yes/No Head:** The document vector from the pooling layer is passed to a small classifier to predict `YES`, `NO`, or `NONE`.

#### **Data**
*   **Preprocessing:**
    *   **Tokenization:** Input text is tokenized using a fast whitespace splitter.
    *   **Padding:** Long answer candidates are padded or truncated to a fixed length (e.g., 300 tokens) to allow for efficient batch processing in the RNN. Question tokens are simply averaged, so fixed padding for questions is not strictly required for the encoder, but may be used for batching.
    *   **Vocabulary:** Tokens are mapped to indices corresponding to the pre-trained embedding matrix.
*   **Labeling:**
    *   **Long Answer:** Binary label (`1` if the candidate matches the ground truth, `0` otherwise).
    *   **Short Answer:** Start and End indices relative to the candidate text. If no short answer exists, indices point to a reserved "null" position.
    *   **Yes/No:** One-hot encoded categorical labels.

#### **Training**
*   **Strategy:** The model is trained using a **Multi-Task Learning** objective, optimizing the ranking, span extraction, and Yes/No classification heads simultaneously.
*   **Sampling:** **Random Negative Sampling** is employed to handle the class imbalance. Each training batch consists of positive question-candidate pairs and a fixed ratio of randomly selected negative pairs from the same document.
*   **Loss Function:** A weighted sum of three loss components is minimized:
    *   **Binary Cross-Entropy** for the long answer ranking.
    *   **Sparse Categorical Cross-Entropy** for the start and end span indices.
    *   **Categorical Cross-Entropy** for the Yes/No classification.
*   **Optimizer:** The Adam optimizer is used with a standard learning rate schedule.

#### **Evaluation**
1.  **Inference:** For a test document, the model processes the question paired with every available long answer candidate.
2.  **Long Answer Selection:** The candidate with the highest ranking score is identified. If this score is below a calibrated **confidence threshold**, the prediction defaults to `BLANK`.
3.  **Short Answer Extraction:** If a long answer is selected, the span is determined by the indices with the highest logits from the Start and End heads.
4.  **Yes/No Prediction:** The final label is assigned based on the class with the highest probability from the Yes/No Head.
