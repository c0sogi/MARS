The issue is that the validation dataset is being filtered using negative sampling, a technique intended only for training to balance classes. This discards a large portion of "negative" (unanswerable) candidates, creating a skewed data distribution during validation that does not reflect the true test distribution. Consequently, the validation metrics are artificially inflated and invalid.

To fix this, I will modify `library/data.py` to decouple the label extraction logic (controlled by `is_train`) from the negative example filtering. I will introduce a `filter_negatives` flag to the `NQDataset` class. This allows the validation set to be initialized with `is_train=True` (to extract labels for loss calculation) but `filter_negatives=False` (to retain all candidates), ensuring a statistically valid evaluation on the full dataset (Cite debug_lesson_11).
