### Proposed Baseline: Modulated Feature-Selection Network

This approach introduces a **Feature-wise Linear Modulation (FiLM)** architecture. It distinguishes itself from previous ideas by using a "mid-level fusion" strategy. Unlike Siamese models (Ideas 1, 3, 4, 10) that compare vectors at the very end, or Single-Stream models (Ideas 7, 9) that concatenate inputs at the very beginning, this model processes the candidate text independently but uses the question representation to dynamically "scale and shift" the internal feature maps of the candidate encoder. This effectively allows the question to "highlight" specific types of information (e.g., dates, entities) within the candidate text before the final classification.

#### **Model**
*   **Embedding Layer:** The model utilizes pre-trained static word embeddings (e.g., GloVe) to convert tokens into dense vectors. These are frozen to ensure maximum training efficiency.
*   **Question Encoder:** The question text is processed by a simple **1D Convolutional Neural Network (CNN)** followed by **Global Max Pooling**. This produces a single fixed-size context vector representing the semantic intent of the question (e.g., asking for a time, a person, or a reason).
*   **Candidate Encoder:** The long answer candidate is processed by a separate **1D CNN** to generate a sequence of feature maps (preserving the sequence length).
*   **Modulation Mechanism (FiLM):**
    *   The Question context vector is projected via two separate linear layers to generate a **Scale Vector ($\gamma$)** and a **Shift Vector ($\beta$)**.
    *   These vectors are applied to the Candidate feature maps via element-wise multiplication and addition: `Output = (Candidate_Features * \gamma) + \beta`.
    *   This operation dynamically amplifies feature channels relevant to the question (e.g., boosting the "temporal" feature channel if the question starts with "When") while suppressing irrelevant ones.
*   **Ranking Head:** The modulated candidate features are aggregated using **Global Max Pooling** and passed to a binary classifier to predict the **Long Answer Score**.
*   **Span Prediction Heads:** The modulated candidate sequence (which retains token-level information) is fed into two parallel lightweight Convolutional layers to predict the **Start Token** and **End Token** probabilities.
*   **Yes/No Head:** The pooled modulated vector is passed to a classifier to predict `YES`, `NO`, or `NONE`.

#### **Data**
*   **Preprocessing:**
    *   **Tokenization:** Input text is tokenized using a fast whitespace splitter.
    *   **Padding:** Question sequences are padded to a short fixed length (e.g., 20 tokens), and long answer candidates are padded/truncated to a moderate fixed length (e.g., 300 tokens) to ensure consistent tensor shapes for the CNNs.
    *   **Vocabulary:** Tokens are mapped to indices corresponding to the pre-trained embedding matrix.
*   **Labeling:**
    *   **Long Answer:** Binary label (`1` if the candidate matches the ground truth, `0` otherwise).
    *   **Short Answer:** Start and End indices relative to the candidate text. If no short answer exists, indices point to a reserved "no answer" token.
    *   **Yes/No:** One-hot encoded categorical labels.

#### **Training**
*   **Strategy:** The model is trained using a **Multi-Task Learning** objective, optimizing the ranking, span extraction, and Yes/No classification heads simultaneously.
*   **Sampling:** **Random Negative Sampling** is employed to handle the class imbalance. Each training batch consists of positive question-candidate pairs and a fixed ratio of randomly selected negative pairs from the same document.
*   **Loss Function:** A weighted sum of three loss components is minimized:
    *   **Binary Cross-Entropy** for the long answer ranking.
    *   **Sparse Categorical Cross-Entropy** for the start and end span indices.
    *   **Categorical Cross-Entropy** for the Yes/No classification.
*   **Optimizer:** The Adam optimizer is used with a standard learning rate schedule.

#### **Evaluation**
1.  **Inference:** For a test document, the model processes the question paired with every available long answer candidate.
2.  **Long Answer Selection:** The candidate with the highest ranking score is identified. If this score is below a calibrated **confidence threshold**, the prediction defaults to `BLANK`.
3.  **Short Answer Extraction:** If a long answer is selected, the span is determined by the indices with the highest logits from the Start and End heads.
4.  **Yes/No Prediction:** The final label is assigned based on the class with the highest probability from the Yes/No Head.
