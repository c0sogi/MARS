### Model
The proposed solution is a **Feature-Based Gradient Boosting Ranker**. This approach moves away from learned dense embeddings (as seen in previous neural ideas) and instead relies on explicit, handcrafted statistical features to quantify the relevance of a text span.

*   **Feature Extractor:** The core of the model is a deterministic module that maps a pair of inputs—the Question and a Long Answer Candidate—to a dense vector of numerical features. These features capture lexical overlap, statistical relevance, and structural information. Key features include:
    *   **BM25 Score:** A probabilistic information retrieval function that ranks the candidate based on the appearance of question terms, adjusting for document length and term frequency saturation.
    *   **TF-IDF Cosine Similarity:** The angle between the sparse term-frequency vectors of the question and the candidate.
    *   **Lexical Overlap:** Simple counts and ratios of shared tokens (unigrams and bigrams) between the question and the candidate.
    *   **Positional Encoding:** The relative index of the candidate within the document (e.g., the first paragraph is often more relevant than the last).
    *   **Length Statistics:** The token count of the candidate, helping to distinguish between substantive paragraphs and short headers or captions.
*   **Scoring Model:** A **LightGBM** (Light Gradient Boosting Machine) classifier takes the feature vector as input and outputs a probability score indicating the likelihood that the candidate answers the question. LightGBM is chosen for its high training speed, low memory usage, and ability to handle non-linear feature interactions via decision trees.
*   **Short Answer Module:** Instead of a sliding window, this model employs a **Sentence Selection Heuristic**. The predicted long answer text is segmented into individual sentences. Each sentence is scored based on its **Jaccard Similarity** (intersection over union of unique tokens) with the question. The sentence with the highest overlap is selected as the short answer span.

### Data
*   **Preprocessing:**
    *   The corpus is tokenized using a simple whitespace and punctuation splitter.
    *   Stop words are removed, and tokens are stemmed (reduced to root form) to maximize lexical matching potential.
    *   A global Inverse Document Frequency (IDF) dictionary is computed from the training set to support TF-IDF and BM25 calculations.
*   **Feature Generation:**
    *   The raw `document_text` is split into candidates using the provided `long_answer_candidates` indices.
    *   For every candidate in a document, the feature extractor computes the numerical vector described above.
*   **Labeling:**
    *   Candidates matching the ground truth `long_answer_index` are labeled as positive (`1`).
    *   All other candidates in the document are labeled as negative (`0`).

### Training
*   **Strategy:** The problem is formulated as a pointwise binary classification task. The model learns to distinguish between "correct" and "incorrect" candidates based solely on their feature profiles.
*   **Sampling:** To handle class imbalance (one correct answer vs. many candidates), the training data is subsampled. For every positive instance, a fixed number of negative instances (e.g., 5) are randomly sampled from the same document.
*   **Objective:** The model is trained to minimize **Binary Log Loss** (Logarithmic Loss).
*   **Optimization:** The training utilizes LightGBM's standard gradient boosting algorithm with early stopping based on validation loss to prevent overfitting.

### Evaluation
*   **Long Answer Prediction:**
    1.  For a given test example, features are generated for *all* available long answer candidates.
    2.  The trained LightGBM model predicts a score for each candidate.
    3.  The candidate with the maximum score is identified.
    4.  If the maximum score exceeds a calibrated **confidence threshold**, that candidate is predicted as the long answer; otherwise, a `BLANK` is predicted.
*   **Short Answer Prediction:**
    1.  If a long answer is successfully predicted, the text is split into sentences.
    2.  The Jaccard Similarity between each sentence and the question is calculated.
    3.  The sentence with the highest similarity is chosen as the short answer.
    4.  If the similarity score is below a secondary threshold (indicating no sentence strongly matches the question words), the short answer is predicted as `BLANK`.
*   **Yes/No Prediction:**
    *   The system checks the first token of the predicted short answer. If it explicitly matches "Yes" or "No" (case-insensitive), the corresponding label is assigned; otherwise, the label is `NONE`.
