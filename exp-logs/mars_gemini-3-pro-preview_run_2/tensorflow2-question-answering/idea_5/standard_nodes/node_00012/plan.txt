The issue is that the `runfile.py` script enables `DEBUG_SAMPLE_SIZE = 2000` but initializes the data processor and datasets with `load_cached_data=True`. This causes the system to load stale cache files (e.g., `cached_train.parquet`) generated from a previous run (likely with a different sample size or split), while the metadata is sliced to the top 2000 entries of the current run. Consequently, the dataloader iterates through indices present in the sliced metadata that do not exist in the stale cache, resulting in an `IndexError`. The fix is to explicitly set `load_cached_data=False` in `runfile.py` to force the regeneration of the vocabulary, embeddings, and dataset caches so they match the current `DEBUG_SAMPLE_SIZE` configuration.
