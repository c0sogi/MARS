The `IndexError: tuple index out of range` is caused by an incorrect calculation of the number of convolution layers (`num_convs`) in the `Res2NeXtBlock` class within `library/model.py`. When `stride > 1`, the code sets `num_convs` to `scale`, but the `forward` method handles the first split (`spx[0]`) separately using a pooling layer and iterates over the remaining splits using the convolutions. This results in the loop trying to access `spx[scale]`, which is out of bounds. The fix is to ensure `num_convs` is always `scale - 1`, matching the number of remaining splits that require convolution processing.
