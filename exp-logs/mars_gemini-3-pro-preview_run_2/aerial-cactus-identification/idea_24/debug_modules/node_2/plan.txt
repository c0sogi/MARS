The issue is caused by stale cache files in the `working/demo_execution` directory. The existing cache files correspond to a previous run with 50 samples, but the current `runfile.py` configuration generates a mini-test set with only 20 samples. This discrepancy causes the model to generate 50 predictions instead of the expected 20, triggering the `AssertionError`.

To fix this, I will modify `runfile.py` to explicitly clear the `demo_execution` directory before creating the new mini-datasets. This ensures that the `CactusDataset` cannot find stale cache files and is forced to regenerate the data from the correct 20-sample metadata.
