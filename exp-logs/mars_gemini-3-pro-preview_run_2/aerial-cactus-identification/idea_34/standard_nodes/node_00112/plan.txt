The strategy is to optimize the solution for efficiency while maintaining the saturated performance (AUC ~1.0). I will significantly reduce the model's capacity and complexity based on the lessons learned. Specifically, I will scale down the channel widths from `[96, 192, 384]` to `[32, 64, 128]` (Cite {solution_lesson_node_00019}, {solution_lesson_node_00049}), remove the Squeeze-and-Excitation blocks (Cite {solution_lesson_node_00013}), and switch from grouped convolutions (RepNeXt) to standard dense convolutions (RepVGG) by setting `GROUPS=1` to improve memory access patterns. I will also reduce the number of epochs to 15, as the previous model converged quickly. The model class will be renamed to `CactusRepVGG` to reflect these architectural changes.

    - 3 Stages with channels [96, 192, 384].
    - Multi-Scale Aggregation (Stage 2 + Stage 3).
    """

        super(UltraWideSERepNeXt, self).__init__()

        self.stage_channels = Config.STAGE_CHANNELS  # [96, 192, 384]
        self.groups = Config.GROUPS

        # --- Stem ---
        # 3 -> 96. Stride 1. Groups=1 (since 3 < 32).
        self.stem = RepNeXtBlock(
            3, self.stage_channels[0], stride=1, groups=1, use_se=Config.USE_SE
        )

        # --- Stage 1 ---
        # 96 -> 96. Stride 1. Groups=32.
        stage1_blocks = []
        for _ in range(num_blocks[0]):
            stage1_blocks.append(
                RepNeXtBlock(
                    self.stage_channels[0],
                    self.stage_channels[0],
                    stride=1,
                    groups=self.groups,
                    use_se=Config.USE_SE,
                )
            )

        # 96 -> 192. First block stride 2 (Downsample). Groups=32.
        stage2_blocks = []

        stage2_blocks.append(

                self.stage_channels[1],
                stride=2,
                groups=self.groups,
                use_se=Config.USE_SE,
            )
        )

        for _ in range(num_blocks[1] - 1):
