The `RuntimeError` is caused by using `-1e9` as a masking value while training with Automatic Mixed Precision (AMP). In AMP, operations are often cast to `float16`, which has a minimum value of approximately -65,504. The constant `-1e9` is far below this limit, causing an overflow when PyTorch attempts to cast it to `float16`. To fix this, I will change the masking value to `-1e4`, which is well within the `float16` range but still sufficiently negative to ensure the softmax probability is effectively zero (Cite debug_lesson_2).
