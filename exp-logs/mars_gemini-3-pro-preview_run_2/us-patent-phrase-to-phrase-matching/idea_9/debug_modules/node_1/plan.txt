The `RuntimeError: value cannot be converted to type at::Half without overflow` occurs because the code uses `-1e9` for masking in `AttentionPooling`. When running with Automatic Mixed Precision (AMP), operations are performed in `float16`, which has a range of roughly $\pm 65,504$. The value `-1e9` exceeds this range, causing an overflow (Cite debug_lesson_2). I will replace `-1e9` with `-1e4`, which fits within `float16` limits while remaining small enough to effectively zero out probabilities after Softmax. Additionally, I will configure gradient checkpointing with `use_reentrant=False` to prevent potential runtime errors during the backward pass associated with the legacy reentrant implementation (Cite debug_lesson_1).
