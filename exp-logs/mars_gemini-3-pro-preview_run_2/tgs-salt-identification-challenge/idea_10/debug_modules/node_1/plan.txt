The execution failure is caused by PyTorch 2.6+ defaulting `torch.load` to `weights_only=True`, which restricts unpickling to a safe allowlist. The checkpoint contains a numpy scalar (the validation score) that is not in this default allowlist, triggering an `UnpicklingError`.

To fix this, I will:
1.  **Update `runfile.py`**: Explicitly set `weights_only=False` in `torch.load` to allow loading the trusted checkpoint generated by the script.
2.  **Update `library/utils.py`**: Cast the `score` to a standard Python `float` in `save_checkpoint` before saving. This addresses the root cause by ensuring future checkpoints contain only standard types compatible with the secure `weights_only=True` default.
3.  **Update `library/losses.py`**: Convert docstrings containing LaTeX escape sequences (like `\infty`) to raw strings (`r"""`) to resolve the `SyntaxWarning: invalid escape sequence`.
