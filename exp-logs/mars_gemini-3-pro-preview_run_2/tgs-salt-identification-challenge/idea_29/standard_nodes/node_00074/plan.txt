Implementation strategy:
1.  **Environment Setup**: Import necessary modules and the provided library components (`config`, `pipeline`, `models`, `dataset`, `utils`, `training`). Set random seeds for reproducibility.
2.  **Configuration Override**: Dynamically adjust the number of epochs in `Config` to 20 per stage. This ensures the pipeline runs as a "fast baseline" (well within the 2-hour limit given the small dataset size) while still allowing sufficient convergence for the ResNet34 backbone.
3.  **Pipeline Execution**:
    *   **Stage 1**: Train the Privileged Teacher (Image + Depth) using `run_stage1_teacher`.
    *   **Stage 2**: Train the Multi-Task Student Ensemble (Image Only) via `run_stage2_student_ensemble`, distilling knowledge from the Teacher.
    *   **Stage 3**: Execute `run_stage3_self_training` to generate pseudo-labels for the test set and retrain the final student model.
4.  **Validation & Analysis**:
    *   Load the best model (from Stage 3, falling back to Stage 2 if necessary).
    *   Perform inference on the hold-out validation set.
    *   Calculate the **Final Validation Metric** (mAP over IoU thresholds) using the best binarization threshold found during training.
    *   Perform **Failure Analysis** by calculating the IoU for each validation image and computing the Pearson correlation between the error (1 - IoU) and the depth feature.
5.  **Submission Handling**: Check if the validation metric exceeds the threshold of 0.7985. If it does, ensure the submission file exists (generating it if necessary). If not, delete any existing submission file to comply with the requirements.
