The issue is caused by **data leakage** in Stage 3 of the pipeline. The function `run_stage3_self_training` concatenates the training and validation datasets (`t_imgs` and `v_imgs`) to form the labeled training set (`labeled_imgs`), but then evaluates the model's performance using the same validation set (`v_imgs`). This causes the model to train on its evaluation data, leading to inflated metrics and the `InvalidMetricValueError`. To fix this, I will modify the code to exclude the validation data from the labeled training set in Stage 3, ensuring the model is trained only on the training split (plus pseudo-labeled test data) and evaluated on the unseen validation split.
