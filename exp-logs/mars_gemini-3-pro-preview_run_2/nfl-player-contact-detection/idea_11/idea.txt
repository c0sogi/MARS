Based on the accumulated lessons, I propose the **Entity-Centric Gated Residual Network (EC-GRN)**. This solution synthesizes the robust "Wide Format" data representation of the baseline MLP with a deeper, gated residual architecture. It explicitly corrects the pipeline ordering failure that doomed previous deep networks (Cite solution_lesson_node_00045) and integrates the strict physical imputation rules required for Ground contacts.

# Proposed Solution: Entity-Centric Gated Residual Network (EC-GRN)

### Model
The architecture is a **Deep Gated Multi-Layer Perceptron** designed to handle the high dimensionality of "Wide Format" tabular data while managing signal-to-noise ratios via gating.

1.  **Wide-Input Layer:** The model accepts a single flattened vector representing the entire temporal window (e.g., $11 \text{ timesteps} \times N \text{ features}$). This strictly preserves the temporal alignment that was lost in Global Pooling architectures (Cite solution_lesson_node_00011) and avoids the optimization difficulties of Attention mechanisms (Cite solution_lesson_node_00042).
2.  **Gated Residual Backbone:** Instead of simple dense layers or standard ResNet blocks, the backbone consists of **Gated Residual Blocks**.
    *   **Structure:** Each block contains a primary dense path and a parallel "Gating" path (Sigmoid activation). The output is computed as $Output = Activation(Dense(Input)) \odot Gating(Input) + Input$.
    *   **Purpose:** The gating mechanism allows the network to dynamically suppress irrelevant features (e.g., noisy tracking data at the edges of the window $t-5$) while amplifying the signal from the center frame ($t=0$). This adds the non-linear capacity of a Deep Network without the "vanishing gradient" or "feature dilution" problems observed in previous deep attempts.
3.  **Unified Head:** The output is a single Sigmoid neuron trained on all interaction types, avoiding the data starvation issues of "Dual Head" architectures (Cite solution_lesson_node_00023).

### Data
The data pipeline is fundamentally restructured to strictly follow the **"Entity-First"** paradigm, correcting the O(N²) scaling and alignment failures of previous attempts.

1.  **Entity-Level Windowing (Structural Correction):** We generate all temporal features (lags, windows) on the `player_tracking` dataframe **before** merging it with `train_labels`. This ensures that temporal consistency relies on the robust source sensor data rather than the fragile interaction label set (Cite solution_lesson_node_00045).
2.  **Hybrid Ground Imputation:** We enforce strict physical separation for Ground interactions:
    *   **Position:** Impute Ground coordinates ($x, y$) as the Player's coordinates. This forces `distance` to **0**, maintaining the geometric invariant "Contact implies Proximity" (Cite solution_lesson_node_00024).
    *   **Kinematics:** Impute Ground velocity and acceleration as **0**. This preserves the "Relative Motion" signal (e.g., Closing Speed) required to detect impact, correcting the failure where copying player velocity zeroed out the impact signal (Cite solution_lesson_node_00034).
3.  **Explicit Relative Kinematics:** We explicitly engineer **Relative Speed**, **Relative Acceleration**, and **Closing Speed** for every step in the window. We prioritize these physics-based features over raw coordinates (Cite solution_lesson_node_00033).
    *   **Logarithmic Distance:** Apply `np.log1p(distance)` to expand feature resolution near the contact boundary (Cite solution_lesson_node_00005).
    *   **Clamped Closing Speed:** Use `max(distance, 1e-6)` in the denominator to ensure numerical stability (Cite solution_lesson_node_00007).
4.  **Normalization:** Apply **StandardScaler** to the final feature vector. This is mandatory to ensure the binary `is_ground` flag is not drowned out by unscaled kinematic magnitudes (Cite solution_lesson_node_00037).

### Training
The training strategy is optimized for stability and calibration on the full dataset.

1.  **Loss Function:** Use **Focal Loss** (e.g., $\alpha=0.75, \gamma=2.0$). This provides better probability calibration than static weighting for the extreme class imbalance, preventing the model from becoming trivially overconfident (Cite solution_lesson_node_00003, solution_lesson_node_00008).
2.  **Full Dataset:** Train on the **entire training set** (3.4M rows). The efficient "Wide Format" architecture allows this within the compute budget, avoiding the performance degradation associated with subsampling (Cite solution_lesson_node_00023).
3.  **Optimizer:** Use **AdamW** with a standard learning rate and **Early Stopping** monitoring the Validation MCC.

### Evaluation
The evaluation pipeline includes a mandatory calibration step.

1.  **Threshold Optimization:** Post-training, perform a grid search on the **validation set** to find the decision threshold $T$ that maximizes the Matthews Correlation Coefficient (MCC). This is necessary to align the decision boundary with the probability distribution output by the Focal Loss (Cite solution_lesson_node_00002).
2.  **Inference:** Apply the optimized threshold $T$ to the test set predictions to generate the final binary submission.
