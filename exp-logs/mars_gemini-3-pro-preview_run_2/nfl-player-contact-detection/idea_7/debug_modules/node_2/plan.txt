The issue stems from `runfile.py` attempting to modify `Config` behavior by patching class attributes at runtime. Since `Config` is a dataclass, its `__init__` method uses default values defined at class creation time, ignoring subsequent class attribute modifications when instantiating new objects (like inside `load_and_process_data`). To fix this, I will implement dependency injection in `load_and_process_data` to accept an optional `config` instance, allowing the caller to explicitly define execution parameters. This aligns with the principle of decoupling configuration from execution logic (Cite debug_lesson_4). I will then update `runfile.py` to instantiate a specific `Config` object with the desired debug settings and pass it to the processing and training functions.
