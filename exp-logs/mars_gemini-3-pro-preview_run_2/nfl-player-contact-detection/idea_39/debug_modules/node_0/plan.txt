### Implementation Strategy

1.  **Configuration Setup**: We first override the default paths in `Config` to point to a specific `./working/demo_execution` directory. This ensures we don't overwrite existing experiment data and allows us to verify file creation in a controlled environment. We also set `Config.EPOCHS` to 1 and `Config.BATCH_SIZE` to a small value to ensure the demonstration runs quickly.
2.  **Data Processing Verification**: We utilize `get_data(load_cached_data=False, debug=True)` to trigger the full data ingestion pipeline (loading metadata, merging tracking/helmet data, feature engineering, and scaling) on a small subset of the data. We assert that the resulting datasets are not empty and that feature dimensions are consistent.
3.  **Model Architecture Verification**: We instantiate the `WDPIRVModel` with the dynamically determined input dimension. We perform a forward pass with a dummy tensor to confirm the network architecture produces the correct output shape `(batch_size, 1)` and that the `FocalLoss` computes a valid gradient.
4.  **Full Pipeline Execution**: We execute `run_training_pipeline(debug=True, ...)` to simulate an end-to-end run. This tests the integration of data loaders, the training loop, validation logic, model checkpointing, and submission generation. We verify that the submission file is created.
5.  **Inference Tools Verification**: We demonstrate the `optimize_threshold` function using synthetic data to ensure it correctly identifies a threshold maximizing the MCC metric. Finally, we verify the `predict_and_submit` utility.
