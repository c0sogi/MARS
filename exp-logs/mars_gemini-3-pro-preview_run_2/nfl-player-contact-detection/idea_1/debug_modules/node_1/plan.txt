The issue is that the intermediate column `nfl_player_id_2_num`, created to handle merging player tracking data (converting "G" to NaN), is not excluded from the final feature set. Consequently, it is treated as a numerical feature, introducing `NaN` values into the feature matrix for ground contact rows, which causes the assertion failure during validation. To fix this, I will add `nfl_player_id_2_num` to the `exclude_cols` list in `library/feature_engineering.py` so it is ignored during feature selection and normalization.
