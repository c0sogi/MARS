# Baseline Approach: Kinematic Multi-Layer Perceptron (K-MLP)

### Model
The proposed model is a **Kinematic Multi-Layer Perceptron (K-MLP)**. This architecture is designed to be a lightweight, purely tabular deep learning baseline that operates solely on player tracking data, bypassing the computational overhead of video processing.

Unlike the 1D CNN (Model 2) which scans for temporal patterns using convolutions, or the GBM (Model 1) which uses decision trees, the K-MLP treats the contact detection problem as a direct non-linear mapping of the instantaneous kinematic state to a probability score. The network consists of an input layer that accepts a flattened vector of engineered features, followed by a sequence of fully connected (Dense) layers. Each dense layer is preceded by Batch Normalization to stabilize learning given the varying scales of physical units (e.g., speed vs. coordinates) and followed by a ReLU activation and Dropout for regularization. The final layer is a single neuron with a Sigmoid activation to output the contact probability.

### Data
To maximize efficiency, we will use **only** the player tracking data (`[train/test]_player_tracking.csv`) and the provided labels.

1.  **Pairwise Feature Engineering**: For every `contact_id` (Player A vs. Player B), we construct a feature vector at the target timestep $t$.
    *   **Player-Player**: Calculate Euclidean distance, relative speed ($|v_A - v_B|$), relative acceleration, and the difference in orientation/direction.
    *   **Player-Ground**: If Player B is 'G' (Ground), set relative distance to 0 and relative velocity/acceleration equal to Player A's absolute values. Include a binary flag `is_ground`.
2.  **Temporal Windowing**: To capture momentum and impact mechanics without complex sequence modeling, we extract these features for a small window around the target step (e.g., $t-5$ to $t+5$). These timesteps are concatenated into a single flat feature vector (e.g., 11 timesteps $\times$ $N$ features).
3.  **Normalization**: Apply standard scaling (Z-score normalization) to all continuous input features to ensure efficient convergence of the MLP.
4.  **Imputation**: Fill any missing tracking data (e.g., due to sensor occlusion) with the mean value of that feature from the training set.

### Training
The training process prioritizes stability and handling the severe class imbalance (1:72).

*   **Loss Function**: Use **Weighted Binary Cross-Entropy Loss**. We will assign a higher weight to the positive class (contact) inversely proportional to its frequency in the training data to prevent the model from trivially predicting "no contact."
*   **Optimizer**: Use **AdamW** with a standard learning rate (e.g., 1e-3) and weight decay to prevent overfitting on the noisy tracking data.
*   **Strategy**: Train for a fixed number of epochs (e.g., 20) with **Early Stopping** monitoring the validation loss. A `ReduceLROnPlateau` scheduler will be used to refine the weights once learning stagnates.
*   **Batch Size**: Use a large batch size (e.g., 1024 or 2048) to fully utilize the GPU and speed up the training on the millions of tabular rows.

### Evaluation
Prediction on the test set follows a streamlined pipeline:

1.  **Preprocessing**: Load the test tracking data and generate the same windowed, flattened feature vectors for every `contact_id` in `sample_submission.csv`.
2.  **Inference**: Run the preprocessed batch through the trained K-MLP to obtain raw probability scores (0 to 1).
3.  **Thresholding**: Instead of a default 0.5 threshold, determine the optimal decision threshold $T$ by maximizing the **Matthews Correlation Coefficient (MCC)** on the validation set.
4.  **Submission**: Apply threshold $T$ to the test probabilities to generate binary predictions (0 or 1) and save to the submission file.
