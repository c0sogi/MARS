The issue stems from the `create_demo_data` function in `runfile.py` reading only the first 500 rows of the metadata. Since a single game play contains thousands of rows, this sample likely captures only a fraction of one play. Consequently, the 80/20 split logic (`int(1 * 0.8)`) results in an empty training set (0 samples). When `pd.read_csv` loads this empty dataset, it defaults the `step` column to `object` type. The pipeline then crashes in `library/data_processing.py` when attempting to call `.round()` on this non-numeric column.

To fix this:
1.  **In `runfile.py`**: Modify the data loading to read the full metadata file (which fits in memory) and explicitly sample 2 unique game plays. This ensures that both training and validation sets are populated.
2.  **In `library/data_processing.py`**: Explicitly cast the `step` column to integer immediately after loading. This enforces the correct schema and prevents type errors even if the dataframe is empty or types are inferred incorrectly (Cite debug_lesson_17).
