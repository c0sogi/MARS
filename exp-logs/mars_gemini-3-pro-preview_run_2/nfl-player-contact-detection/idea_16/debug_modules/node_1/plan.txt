The `KeyError: 'x_position_1_lag-5'` occurs because the code incorrectly anticipates the column naming schema resulting from the Pandas merge operation. The `_load_tracking_data` method creates columns like `x_position_lag-5`. When these are merged with suffixes `_1` and `_2` (or renamed via map), Pandas appends the suffix to the end of the existing name, producing `x_position_lag-5_1`. However, the feature engineering logic attempts to access them as `x_position_1_lag-5`. This misalignment between the merge output and the access pattern is a direct instance of **Cite debug_lesson_3** (Explicitly Define Suffixes to Prevent Implicit Column Renaming / Mismatched Expectations). The fix involves updating the string formatting in `_compute_features` and `_process_split` to match the actual `{feature}_lag{k}_{player_id}` structure.
