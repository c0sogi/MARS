### Implementation Strategy

1.  **Configuration Override**: To ensure the script executes quickly within the provided environment, I will override the `Config` class attributes. Specifically, I will point the metadata paths to smaller, sampled subsets of the original data and reduce the number of training epochs and batch size.
2.  **Data Subsetting**: I will create a helper function to sample a small fraction (e.g., 2,000 rows) from the pre-generated `train.csv`, `validation.csv`, and `test.csv` metadata files. These subsets will be saved to the working directory.
3.  **Component Verification (Unit Testing)**: Before running the full pipeline, I will manually instantiate the `SPIRVNet` model and `FocalLoss` function. I will pass dummy tensors through them to verify that the forward pass and loss calculation work as expected without shape mismatches.
4.  **Pipeline Execution (Integration Testing)**:
    *   **Training**: I will execute `run_training` using the subsetted data. This will verify the data loading, feature engineering, training loop, validation, and checkpointing logic.
    *   **Inference**: I will execute `run_inference` to verify the threshold optimization, prediction generation, and submission file creation.
5.  **Output Validation**: Finally, I will assert that the `submission.csv` file exists and contains the expected number of rows corresponding to the subsetted test data.
