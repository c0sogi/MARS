Based on the comprehensive analysis of the accumulated lessons, I propose the **Stochastic Pyramidal Invariant Residual-Visual Network (SPIRV-Net)**.

This solution represents the convergence of the most successful architectural patterns identified in the failure analysis: **Pyramidal Feature Compression** (Cite solution_lesson_node_00096), **Strict Physical Invariance** (Cite solution_lesson_node_00092), and **Residual-Visual Fusion** (Cite solution_lesson_node_00071).

The core structural innovation is the introduction of **Stochastic Input Regularization** (Gaussian Noise Injection) directly applied to the kinematic manifold. This addresses the "Memorization" failure mode (Cite solution_lesson_node_00092) by forcing the model to learn robust physical decision boundaries (e.g., "decreasing distance implies contact") rather than overfitting to precise but noisy sensor values, effectively smoothing the decision surface.

# Model
The architecture is a **Dual-Stream Network** designed to fuse a robust, invariant kinematic signal with a noisy visual proxy via an additive residual connection.

1.  **Kinematic Stream (Stochastic Pyramidal Backbone):**
    *   **Input:** A **flattened wide feature vector** of player tracking data (Window $t-5$ to $t+5$). This preserves the superior temporal alignment of the wide format (Cite solution_lesson_node_00015).
    *   **Stochastic Regularization Layer (Structural Innovation):** During training *only*, a Gaussian Noise layer adds $\mathcal{N}(0, \sigma)$ to the continuous kinematic features. This acts as a continuous data augmentation strategy, preventing the deep backbone from memorizing high-frequency sensor noise.
    *   **Strict Invariance:** We explicitly **exclude** categorical entity embeddings (`team`, `position`). The model relies solely on relative kinematics, preventing the learning of non-generalizable priors (Cite solution_lesson_node_00092).
    *   **Pyramidal Architecture:** We employ an **Interleaved Pyramidal Backbone** (Cite solution_lesson_node_00096) to force hierarchical abstraction.
        *   *Structure:* `Input` $\to$ `Project(512)` $\to$ `ResBlock` $\to$ `Project(256)` $\to$ `ResBlock` $\to$ `Project(128)` $\to$ `ResBlock`.
        *   *ResBlock:* `Linear` $\to$ `BatchNorm` $\to$ `ReLU` $\to$ `Dropout` $\to$ `Linear` $\to$ `Add`.
    *   **Unified Input:** All kinematic features (geometry, motion, dynamics) are fed into the single input layer to allow immediate learning of coupled interactions (Cite solution_lesson_node_00093).
    *   **Output:** A single scalar logit ($L_{kin}$).

2.  **Visual Stream (Shallow Correction):**
    *   **Input:** A **flattened wide feature vector** of helmet bounding box metrics, derived using a **Max-Pooling Selection Strategy** (Cite solution_lesson_node_00074).
    *   **Backbone:** A **Shallow MLP**. This prevents overfitting to the noisy visual proxy while capturing simple geometric rules (Cite solution_lesson_node_00071).
    *   **Output:** A single scalar logit ($L_{vis}$).

3.  **Residual Fusion:**
    *   **Operation:** $Logit_{final} = L_{kin} + \lambda \cdot L_{vis}$.
    *   **Rationale:** We use a simple additive residual rather than gating, as gating mechanisms have been shown to suppress signal in this domain (Cite solution_lesson_node_00098).
    *   **Logits-Only:** The final layer outputs raw logits, strictly adhering to the requirement for numerically stable loss functions (Cite solution_lesson_node_00048).

# Data
The data pipeline synthesizes the "Entity-First" tracking approach with strict physical constraints and ground imputation rules.

1.  **Entity-First Feature Generation:** Generate lags and windowed features on the `player_tracking` dataframe **before** merging it with `train_labels`. This prevents O(N²) scaling errors (Cite solution_lesson_node_00045).
2.  **Explicit Numerical Stability:**
    *   **Clamping:** Explicitly clamp derived kinematic features (e.g., `closing_speed`) to fixed physical ranges (e.g., `[-50, 50]`) during engineering to prevent gradient instability (Cite solution_lesson_node_00081).
    *   **Angular Continuity:** Use the **Shortest Arc** method (e.g., `min(|a-b|, 360-|a-b|)`) for relative angles (Cite solution_lesson_node_00076).
    *   **Resolution Enhancement:** Apply `np.log1p(distance)` (Cite solution_lesson_node_00005) and `clamped_closing_speed` (Cite solution_lesson_node_00007).
3.  **Hybrid Ground Imputation:**
    *   **Kinematics:** Impute Ground Position = Player Position (Distance=0) and Ground Velocity = 0. This preserves the "Relative Motion" signal (Cite solution_lesson_node_00034).
    *   **Visuals:** For Ground interactions, set `Visual_IoU` to 0 but retain the **Player's Helmet Box Top** features to capture the "falling" visual signature (Cite solution_lesson_node_00071).
4.  **Visual Feature Selection (Max-Pooling):** Apply a **Max-Pooling Strategy** per timestamp to select the single "best" view (largest box area) for each player. This creates a dense, consistent visual feature vector (Cite solution_lesson_node_00074).
5.  **Normalization:** Apply **StandardScaler** to the final fused vector (Cite solution_lesson_node_00037).

# Training
The training strategy is optimized for stability and calibration on the full dataset.

1.  **Loss Function:** Use **Focal Loss** implemented via `BCEWithLogitsLoss`. Crucially, set `alpha=0.25` and `gamma=2.0`. This ensures the loss properly balances the suppression of easy negatives with the regularization of noisy labels (Cite solution_lesson_node_00077).
2.  **Full Dataset:** Train on the **entire training set** (3.4M rows). The efficient tabular architecture allows this within the compute budget (Cite solution_lesson_node_00023).
3.  **Batch Size:** Use a large batch size (e.g., **8192**) to maximize the stability of Batch Normalization statistics within the Pyramidal backbone (Cite solution_lesson_node_00096).
4.  **Optimizer:** Use **AdamW** with **Early Stopping** monitoring the Validation MCC.

# Evaluation
The evaluation pipeline includes a mandatory calibration step.

1.  **Threshold Optimization:** Post-training, perform a grid search on the **validation set** to find the decision threshold $T$ that maximizes the Matthews Correlation Coefficient (MCC). This aligns the decision boundary with the probability distribution (Cite solution_lesson_node_00002).
2.  **Inference:** Apply the optimized threshold $T$ to the test set predictions to generate the final binary submission.
