The issue is caused by the implicit inclusion of string identifier columns (`nfl_player_id_1`, `nfl_player_id_2`) in the list of features to be lagged (`base_feats`). When these columns are shifted, `NaN` values are introduced at the boundaries. Subsequently, `fillna(0)` replaces these `NaN`s with the integer `0`, resulting in columns containing mixed types (strings and integers). This causes `pyarrow` to fail during schema inference when saving to Parquet.

To fix this, I will modify `library/features.py` to explicitly exclude these ID columns from the `base_feats` list in the `create_wide_input` method. This ensures only numeric features are lagged and padded, preventing type conflicts. Cite debug_lesson_1
