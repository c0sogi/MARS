Based on the comprehensive analysis of the previous attempts and lessons learned, I propose the **Kinematic Center-Attention Network (K-CAN)**. This solution introduces a temporal attention mechanism designed to strictly enforce the "Center Focus" required for this task, addressing the alignment failures of previous CNNs while retaining the robust feature engineering of the baseline MLP.

# Proposed Solution: Kinematic Center-Attention Network (K-CAN)

### Model
The architecture is a **Time-Resolved Attention Network** that replaces the flat dense layers of the MLP and the translation-invariant filters of the CNN with a dynamic aggregation mechanism centered on the target frame.

1.  **Input Reshaping:** The model accepts the **Wide Format** feature vector (Cite solution_lesson_node_00015) and reshapes it into a temporal tensor of shape $(Batch, Window\_Size, Features)$.
2.  **Feature Embedding:** A shared Linear Layer (Time-Distributed MLP) projects the features of each time step into a higher-dimensional latent space, creating a sequence of embeddings $E = \{e_{-5}, ..., e_0, ..., e_{+5}\}$.
3.  **Center-Query Attention (Structural Innovation):** Instead of Global Pooling (which destroys alignment, Cite solution_lesson_node_00011) or Flattening (which creates fixed temporal weights), we employ a **Multi-Head Attention** block defined as:
    *   **Query ($Q$):** Derived *exclusively* from the center frame embedding ($e_0$). This forces the model to ask: "Given the state at $t=0$, what context is relevant?"
    *   **Keys ($K$) & Values ($V$):** Derived from the entire window sequence $E$.
    *   **Operation:** $Attention(Q, K, V) = \text{Softmax}(\frac{QK^T}{\sqrt{d_k}})V$. This produces a single context vector that is a weighted sum of the window, where the weights are dynamically determined by the event at $t=0$.
4.  **Explicit Skip Connection:** The output of the Attention block is concatenated with the **raw explicit kinematic features** of the center frame. This ensures the instantaneous physics (Distance, Speed at $t=0$) are preserved with high fidelity (Cite solution_lesson_node_00011, solution_lesson_node_00033).
5.  **Unified Classification Head:** The concatenated vector feeds into a Dense network. We use a single head for all contact types, relying on the geometric consistency of the input data to handle "Ground" vs. "Player" distinctions (Cite solution_lesson_node_00023).

### Data
The data pipeline synthesizes the most effective feature engineering techniques while strictly adhering to the normalization and imputation requirements identified in failure analyses.

1.  **Wide-Window Construction:** Construct the temporal window (e.g., $t-5$ to $t+5$) using **vectorized `shift()` operations** to create a single wide row per sample (Cite solution_lesson_node_00015).
2.  **Hybrid Ground Imputation:** For "Ground" interactions, we enforce strict physical invariants (Cite solution_lesson_node_00034):
    *   **Position:** Impute Ground coordinates ($x, y$) as the Player's coordinates. This forces `distance` to **0**, aligning with the "Proximity" manifold.
    *   **Kinematics:** Impute Ground velocity and acceleration as **0**. This preserves the "Relative Motion" signal (e.g., Closing Speed) required to detect impact.
3.  **Explicit Relative Kinematics:** Pre-calculate **Relative Speed**, **Relative Acceleration**, and **Closing Speed** for every step in the window. We rely on these explicit physics features rather than asking the model to infer them from raw coordinates (Cite solution_lesson_node_00033).
    *   **Logarithmic Distance:** Apply `np.log1p(distance)` (Cite solution_lesson_node_00005).
    *   **Clamped Closing Speed:** Use `max(distance, 1e-6)` in the denominator (Cite solution_lesson_node_00007).
4.  **Input Normalization:** Apply **StandardScaler** to the final feature set. This is critical to ensure the binary `is_ground` flag is not drowned out by unscaled continuous variables (Cite solution_lesson_node_00037).

### Training
The training strategy prioritizes stability and calibration on the full dataset.

1.  **Loss Function:** Use **Focal Loss** (e.g., $\alpha=0.75, \gamma=2.0$). This provides better stability and probability calibration than static weighting for this specific imbalance, preventing the model from becoming trivially overconfident (Cite solution_lesson_node_00003, solution_lesson_node_00023).
2.  **Full Dataset:** Train on the **entire training set** (3.4M rows). The efficient architecture allows this within the compute budget (Cite solution_lesson_node_00023).
3.  **Optimizer:** Use **AdamW** with a standard learning rate and Early Stopping monitoring the Validation MCC.

### Evaluation
1.  **Threshold Optimization:** Post-training, perform a grid search on the **validation set** to find the decision threshold $T$ that maximizes the Matthews Correlation Coefficient (MCC). This is mandatory to correct for any residual probability shift induced by the Focal Loss (Cite solution_lesson_node_00002).
2.  **Inference:** Apply the optimized threshold $T$ to the test set predictions to generate the final binary submission.
