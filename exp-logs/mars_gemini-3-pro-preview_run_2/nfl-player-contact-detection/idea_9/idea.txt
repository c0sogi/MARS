Based on the comprehensive analysis of previous attempts and the specific lessons learned, I propose the **Wide-Input Residual Kinematic Network (WIRK-Net)**. This solution represents a structural evolution from the simple "Kinematic MLP" baseline to a **Deep Residual Architecture**. It explicitly rejects the "Sequence Modeling" paradigm (CNNs/Attention) which failed due to alignment and complexity issues, and instead doubles down on the "Wide Format" paradigm by increasing the model's capacity to learn complex feature interactions via depth.

# Proposed Solution: Wide-Input Residual Kinematic Network (WIRK-Net)

### Model
The architecture is a **Deep Residual Multi-Layer Perceptron** designed for high-dimensional tabular data.

1.  **Wide-Input Layer:** The model accepts a single flattened vector representing the entire temporal window (e.g., $11 \text{ timesteps} \times N \text{ features}$). This preserves the "Wide Format" which was proven superior to sequence-based inputs for this specific task (Cite solution_lesson_node_00015, solution_lesson_node_00042).
2.  **Categorical Embeddings:** Unlike previous iterations which ignored player roles, we introduce **Entity Embeddings** for categorical features (e.g., Player Position: 'WR', 'CB'). These embeddings are concatenated with the continuous kinematic features to provide context (e.g., a QB is less likely to tackle than a LB).
3.  **Residual Backbone:** The core innovation is replacing the shallow dense layers of the baseline with a stack of **Dense Residual Blocks**. Each block consists of: `Linear -> BatchNorm -> ReLU -> Dropout -> Linear -> Add (Skip Connection)`.
    *   **Why:** The baseline MLP (Idea 1) performed well but was likely capacity-constrained. Deep Residual networks allow for learning highly complex, non-linear interactions between features (e.g., "High Speed" + "Low Angle" + "Ground Proximity") without suffering from vanishing gradients, while retaining the strict alignment of the MLP.
4.  **Unified Head:** The output is a single Sigmoid neuron. We reject "Dual Head" architectures as they cause data starvation for the "Ground" class (Cite solution_lesson_node_00023).

### Data
The data pipeline synthesizes the "Wide Format" strategy with strict physical imputation rules to correct the "Ground" representation failures.

1.  **Vectorized Wide-Windowing:** Construct the temporal window (e.g., $t-5$ to $t+5$) using **vectorized `shift()` operations** to create a single wide row per sample. This avoids the brittle vertical expansion pipeline (Cite solution_lesson_node_00015).
2.  **Hybrid Ground Imputation:** We implement the strict physical separation of position and kinematics for Ground interactions (Cite solution_lesson_node_00034):
    *   **Position:** Impute Ground coordinates ($x, y$) as the Player's coordinates. This forces `distance` to **0**, maintaining the geometric invariant "Contact implies Proximity" (Cite solution_lesson_node_00024).
    *   **Kinematics:** Impute Ground velocity and acceleration as **0**. This preserves the "Relative Motion" signal (e.g., Closing Speed) required to detect impact, correcting the failure where copying player velocity zeroed out the impact signal.
3.  **Explicit Relative Kinematics:** We explicitly engineer **Relative Speed**, **Relative Acceleration**, and **Closing Speed** for every step in the window. We prioritize these physics-based non-linear features over raw coordinates (Cite solution_lesson_node_00033).
    *   **Logarithmic Distance:** Apply `np.log1p(distance)` to expand feature resolution near the contact boundary (Cite solution_lesson_node_00005).
    *   **Clamped Closing Speed:** Use `max(distance, 1e-6)` in the denominator to ensure numerical stability (Cite solution_lesson_node_00007).
4.  **Input Normalization:** Apply **StandardScaler** to the final continuous feature set. This is mandatory to ensure the binary `is_ground` flag and embeddings are not drowned out by unscaled kinematic magnitudes (Cite solution_lesson_node_00037).

### Training
The training strategy is optimized for stability and calibration on the full dataset.

1.  **Loss Function:** Use **Focal Loss** (e.g., $\alpha=0.75, \gamma=2.0$). This provides better probability calibration than static weighting for the 1:72 class imbalance, preventing the model from becoming trivially overconfident (Cite solution_lesson_node_00003).
2.  **Full Dataset:** Train on the **entire training set** (3.4M rows). The efficient tabular architecture allows this within the compute budget, avoiding the performance degradation associated with subsampling (Cite solution_lesson_node_00023).
3.  **Optimizer:** Use **AdamW** with a standard learning rate and **Early Stopping** monitoring the Validation MCC.

### Evaluation
The evaluation pipeline includes a mandatory calibration step.

1.  **Threshold Optimization:** Post-training, perform a grid search on the **validation set** to find the decision threshold $T$ that maximizes the Matthews Correlation Coefficient (MCC). This is necessary to align the decision boundary with the probability distribution output by the Focal Loss (Cite solution_lesson_node_00002).
2.  **Inference:** Apply the optimized threshold $T$ to the test set predictions to generate the final binary submission.
