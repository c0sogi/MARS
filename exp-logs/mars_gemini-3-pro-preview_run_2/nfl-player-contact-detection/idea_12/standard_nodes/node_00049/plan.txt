The implementation strategy follows the "Entity-Centric Physics-Informed Residual Network (EC-PIRN)" design. The script orchestrates the pipeline by leveraging the provided library modules for configuration, data processing, model definition, and training/evaluation.

To ensure a **fast baseline execution** within the time limits:
1.  **Configuration Override**: We dynamically adjust `Config.NUM_EPOCHS` to a lower value (5) and subsample the training data (random 500k samples) to speed up the training loop while maintaining statistical significance.
2.  **Data Loading**: We utilize `DataProcessor` with `load_cached_data=True` to avoid redundant feature engineering.
3.  **Training**: We initialize the `Trainer` and fit the model on the subsampled training set, using the full validation set for early stopping and threshold optimization.
4.  **Evaluation**: We compute the final MCC on the hold-out validation set and print it in the required format.
5.  **Failure Analysis**: We analyze the correlation between prediction errors and input features (kinematics, geometry) on the validation set to identify weak points.
6.  **Submission**: We conditionally generate the submission file if the validation MCC exceeds the specified threshold (0.62458462731896), ensuring efficient inference using the GPU.
