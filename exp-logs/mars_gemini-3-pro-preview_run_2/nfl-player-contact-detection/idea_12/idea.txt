Based on the accumulated lessons, I propose the **Entity-Centric Physics-Informed Residual Network (EC-PIRN)**. This solution represents a structural evolution that synthesizes the robust "Wide Format" representation of the baseline with a Deep Residual architecture. It explicitly corrects the pipeline ordering failure (O(N²) scaling/alignment) and the activation-loss mismatch that prevented previous deep networks from outperforming the shallow baseline.

# Proposed Solution: Entity-Centric Physics-Informed Residual Network (EC-PIRN)

### Model
The architecture is a **Deep Residual Multi-Layer Perceptron** designed to leverage the high capacity of deep networks while strictly preserving the temporal alignment of the "Wide Format" input.

1.  **Wide-Input Backbone:** The model accepts a single **flattened wide feature vector** representing the window $t-5$ to $t+5$. This preserves the strict temporal alignment that was lost in Global Pooling architectures (Cite solution_lesson_node_00011) and avoids the optimization difficulties of Attention mechanisms (Cite solution_lesson_node_00042).
2.  **Residual Blocks:** The core innovation is replacing the shallow dense layers with a stack of **Dense Residual Blocks** (e.g., `Linear -> BatchNorm -> ReLU -> Dropout -> Linear -> Add`).
    *   **Rationale:** Previous deep attempts failed due to pipeline/loss errors, not depth itself. By using residual connections, we allow the model to learn complex non-linear interactions (e.g., "High Speed" + "Low Angle" + "Ground Proximity") without vanishing gradients, surpassing the capacity of the baseline K-MLP.
3.  **Unified Linear Output:** The final layer is a single Linear unit **without an activation function**. This outputs raw logits, strictly adhering to the requirement for numerically stable loss functions (Cite solution_lesson_node_00048). We reject "Dual Head" architectures to prevent data starvation (Cite solution_lesson_node_00023).

### Data
The data pipeline is fundamentally restructured to follow the **"Entity-First"** paradigm, decoupling temporal processing from interaction logic.

1.  **Entity-Level Feature Generation:** We generate all temporal features (lags, windows, derivatives) on the `player_tracking` dataframe **before** merging it with `train_labels`. This ensures temporal consistency relies on the robust source sensor data rather than the fragile interaction label set, correcting the alignment failures of previous attempts (Cite solution_lesson_node_00045).
2.  **Hybrid Ground Imputation:** We enforce strict physical separation for Ground interactions during the merge step:
    *   **Position:** Impute Ground coordinates ($x, y$) as the Player's coordinates. This forces `distance` to **0**, maintaining the geometric invariant "Contact implies Proximity" (Cite solution_lesson_node_00024).
    *   **Kinematics:** Impute Ground velocity and acceleration as **0**. This preserves the "Relative Motion" signal (e.g., Closing Speed) required to detect impact, correcting the failure where copying player velocity zeroed out the impact signal (Cite solution_lesson_node_00034).
3.  **Explicit Relative Physics:** After merging the windowed entity data, we explicitly calculate **Relative Speed**, **Relative Acceleration**, and **Closing Speed** for every step in the window. We prioritize these physics-based features over raw coordinates (Cite solution_lesson_node_00033).
    *   **Logarithmic Distance:** Apply `np.log1p(distance)` to expand resolution near the contact boundary (Cite solution_lesson_node_00005).
    *   **Clamped Closing Speed:** Use `max(distance, 1e-6)` in the denominator for numerical stability (Cite solution_lesson_node_00007).
4.  **Normalization:** Apply **StandardScaler** to the final feature vector. This is mandatory to ensure the binary `is_ground` flag is not drowned out by unscaled kinematic magnitudes (Cite solution_lesson_node_00037).

### Training
The training strategy is optimized for stability and calibration on the full dataset.

1.  **Loss Function:** Use **Focal Loss** implemented with `BCEWithLogitsLoss` (passing raw logits). This provides better probability calibration than static weighting for the extreme class imbalance (Cite solution_lesson_node_00003) and avoids the "Logits vs Probabilities" bug (Cite solution_lesson_node_00048).
2.  **Full Dataset:** Train on the **entire training set** (3.4M rows). The efficient "Wide Format" architecture allows this within the compute budget, avoiding the performance degradation associated with subsampling (Cite solution_lesson_node_00023).
3.  **Optimizer:** Use **AdamW** with a standard learning rate and **Early Stopping** monitoring the Validation MCC.

### Evaluation
The evaluation pipeline includes a mandatory calibration step.

1.  **Threshold Optimization:** Post-training, perform a grid search on the **validation set** to find the decision threshold $T$ that maximizes the Matthews Correlation Coefficient (MCC). This is necessary to align the decision boundary with the probability distribution output by the Focal Loss (Cite solution_lesson_node_00002).
2.  **Inference:** Apply the optimized threshold $T$ to the test set predictions to generate the final binary submission.
