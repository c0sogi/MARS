Based on the accumulated lessons, specifically the success of "Residual-Visual Correction" (Idea 18) and the insight that "Data Resolution" is the primary bottleneck (Cite solution_lesson_node_00059), I propose the **Stereoscopic Residual-Visual Network (SRV-Net)**.

This solution represents a structural evolution from "Aggregated Visual Fusion" (Idea 17/18) to **"Stereoscopic Disparity Modeling"**. Instead of compressing visual data into a single summary statistic (e.g., `Max(IoU)`), this architecture explicitly models the **disagreement (parallax)** between the Sideline and Endzone camera views. This allows the network to distinguish true contact (visible in both views) from visual occlusion (visible in one, gap in the other), effectively increasing the resolution of the visual proxy without expensive video processing.

# Model
The architecture is a **Dual-Stream Network** with a specialized Stereoscopic branch, fused via a residual connection.

1.  **Kinematic Stream (Primary Backbone):**
    *   **Input:** A **flattened wide feature vector** of player tracking data ($t-5$ to $t+5$). This preserves the strict temporal alignment proven superior to sequence models (Cite solution_lesson_node_00015, solution_lesson_node_00042).
    *   **Architecture:** A **Deep Residual MLP** (Linear $\to$ BatchNorm $\to$ ReLU $\to$ Dropout $\to$ Linear $\to$ Add). This provides the capacity to learn complex non-linear physics (Cite solution_lesson_node_00059) while remaining optimization-friendly.
    *   **Output:** A single scalar logit representing the "Kinematic Probability".

2.  **Stereoscopic Visual Stream (Correction Branch):**
    *   **Input:** A **Multi-View Feature Vector**. Instead of aggregating helmet metrics, we feed view-specific features: `[Sideline_IoU, Sideline_BoxTop, Endzone_IoU, Endzone_BoxTop, ...]`.
    *   **Architecture:** A **Comparator MLP**. This network is designed to learn logical disparity rules. For example:
        *   *Rule 1 (Confirmation):* If `Sideline_IoU > 0` AND `Endzone_IoU > 0` $\to$ High Correction.
        *   *Rule 2 (Occlusion):* If `Sideline_IoU > 0` BUT `Endzone_IoU == 0` $\to$ Low/Negative Correction.
        *   *Rule 3 (Ground):* If `Sideline_BoxTop` drops AND `Endzone_BoxTop` drops $\to$ High Ground Probability.
    *   **Output:** A single scalar logit representing the "Stereoscopic Correction".

3.  **Residual Fusion:**
    *   **Operation:** $Logit_{final} = Logit_{kinematic} + \lambda \cdot Logit_{visual}$.
    *   **Rationale:** This maintains the hierarchy where robust kinematics drive the baseline, and visuals act as an orthogonal "sanity check" (Cite solution_lesson_node_00070, solution_lesson_node_00071).
    *   **Logits-Only:** The final output is raw logits, correcting the activation-loss mismatch (Cite solution_lesson_node_00048).

# Data
The data pipeline is structurally expanded to support **Multi-View Alignment** while retaining the robust "Entity-First" tracking processing.

1.  **Stereoscopic Feature Engineering:**
    *   **Pivoting:** Process `baseline_helmets.csv` to create a wide-format representation where every timestamp has separate columns for `Sideline` and `Endzone` metrics. Handle missing views (e.g., only one camera available) by imputing with a specialized value (-1) and adding binary `view_available` flags.
    *   **View-Specific Metrics:** Calculate **IoU** and **Centroid Distance** independently for Sideline and Endzone views.
    *   **Windowing:** Apply vectorized windowing to these stereoscopic features to capture the temporal trajectory of the disparity (e.g., "views converging vs. diverging").

2.  **Entity-First Tracking Pipeline:** Generate temporal features on the tracking data **before** merging to prevent O(N²) scaling errors (Cite solution_lesson_node_00045).

3.  **Hybrid Ground Imputation:**
    *   **Kinematics:** Impute Ground Position = Player Position (Distance=0) and Ground Velocity = 0 to preserve relative motion signals (Cite solution_lesson_node_00034, solution_lesson_node_00024).
    *   **Visuals:** For Ground interactions, set `IoU` to 0. Crucially, retain the **Player's Helmet Box Top** features for both views. This allows the Stereoscopic stream to detect the specific visual signature of a player falling (box lowering in both perspectives) (Cite solution_lesson_node_00018 context).

4.  **Explicit Relative Physics:** Retain `np.log1p(distance)` (Cite solution_lesson_node_00005) and `clamped_closing_speed` (Cite solution_lesson_node_00007).

5.  **Normalization:** Apply **StandardScaler** to the final fused vector (Cite solution_lesson_node_00037).

# Training
The training strategy is optimized for stability and calibration on the full dataset.

1.  **Loss Function:** Use **Focal Loss** implemented via `BCEWithLogitsLoss` (taking raw logits). This ensures calibration for the 1:72 class imbalance (Cite solution_lesson_node_00003) and avoids activation mismatches (Cite solution_lesson_node_00048).
2.  **Full Dataset:** Train on the **entire training set** (3.4M rows). The efficient tabular architecture allows this within the compute budget (Cite solution_lesson_node_00023).
3.  **Optimizer:** Use **AdamW** with **Early Stopping** monitoring the Validation MCC.

# Evaluation
The evaluation pipeline includes a mandatory calibration step.

1.  **Threshold Optimization:** Post-training, perform a grid search on the **validation set** to find the decision threshold $T$ that maximizes the Matthews Correlation Coefficient (MCC). This aligns the decision boundary with the probability distribution (Cite solution_lesson_node_00002).
2.  **Inference:** Apply the optimized threshold $T$ to the test set predictions to generate the final binary submission.
