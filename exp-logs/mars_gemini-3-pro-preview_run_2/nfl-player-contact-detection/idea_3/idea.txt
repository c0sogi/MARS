# Proposed Solution: Time-Resolved Gated Convolutional Network (TR-GCN)

### Model
The proposed architecture is a **Time-Resolved Gated Convolutional Network (TR-GCN)**. This design synthesizes the temporal feature extraction capabilities of a CNN with the strict positional alignment of the baseline MLP, while explicitly addressing the distinct physics of ground vs. player contacts.

1.  **Temporal Encoder (No Pooling):** The model accepts a time-series window of tracking data (e.g., $11 \text{ frames} \times N \text{ features}$). It processes this input using a stack of **1D Convolutional Layers** with `padding='same'`. Crucially, we **remove all Global Pooling layers**. This allows the network to learn local temporal patterns (like "whiplash" or sudden deceleration) while preserving the absolute temporal position of features, ensuring the model can distinguish the center frame (target) from surrounding context (Cite Lesson 11).
2.  **Flattening:** The output of the convolutional stack is **flattened** into a single vector. This retains the temporal structure (e.g., "Feature X at time $t-1$") for the dense layers, unlike global pooling which aggregates features invariantly.
3.  **Gated Dual-Head Output:** The dense section splits into two parallel "heads":
    *   **Player Head:** Specialized in detecting collisions between two moving bodies.
    *   **Ground Head:** Specialized in detecting impacts with the ground (e.g., sudden stops without a second player).
    *   **Gating Mechanism:** The final prediction is a deterministic combination based on the `is_ground` feature: $P_{final} = P_{ground} \times I_{ground} + P_{player} \times (1 - I_{ground})$. This forces the model to use the correct physical logic for each interaction type.

### Data
The data pipeline builds on the windowed tracking approach but incorporates specific refinements for numerical stability and feature resolution.

1.  **Centered Windowing:** Extract tracking data for a window centered on the target step (e.g., $t-5$ to $t+5$), creating a $(Batch, 11, Features)$ tensor.
2.  **Feature Engineering:**
    *   **Logarithmic Distance:** Transform the distance feature using `np.log1p(distance)`. This expands the numerical variance near zero, giving the model high resolution at the exact moment of contact (Cite Lesson 5).
    *   **Clamped Closing Speed:** Calculate the closing speed (rate of change of distance). When normalizing or dividing by distance, use a **clamped denominator** (e.g., `max(distance, 1e-6)`) instead of additive smoothing to prevents numerical instability and gradient noise at the singularity where distance $\approx$ 0 (Cite Lesson 7).
    *   **Raw Kinematics:** Include raw speed, acceleration, and orientation, allowing the 1D-CNN layers to learn higher-order kinematic derivatives (jerk) directly.

### Training
The training strategy is designed to handle the extreme class imbalance without uncalibrating the model's capacity to learn rare events.

1.  **Loss Function:** Use **Weighted Binary Cross-Entropy Loss** with a positive class weight approximating the inverse frequency (~72). We explicitly select this over Focal Loss, as previous empirical results demonstrated that static weighting outperforms Focal Loss for this specific dataset's imbalance ratio (Cite Lesson 8).
2.  **Optimization:** Train using **AdamW** with a standard learning rate. Implement **Early Stopping** monitoring the validation MCC (not Loss) to prevent overfitting to the majority class.

### Evaluation
The evaluation pipeline includes a mandatory calibration step to address the probability shift caused by the weighted loss.

1.  **Inference:** Pass the test set windows through the trained TR-GCN to obtain raw probability scores.
2.  **Threshold Optimization:** Do not use a default 0.5 threshold. Perform a grid search on the **validation set** to find the decision threshold $T$ that maximizes the Matthews Correlation Coefficient (MCC). This corrects for the probability distribution shift induced by the heavy positive class weights (Cite Lesson 2).
3.  **Submission:** Apply the optimized threshold $T$ to the test probabilities to generate the final binary submission.
