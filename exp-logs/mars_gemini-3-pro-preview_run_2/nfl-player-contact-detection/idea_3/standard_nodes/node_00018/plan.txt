The runtime error is caused by the `DataProcessor` loading stale cached data from `working/idea_3/` which contains 3D tensors (`[N, 11, 18]`) generated for a previous TR-GCN model. The current `KinematicMLP` architecture and `DataProcessor` logic expect flattened 2D "Wide Format" inputs. The `runfile.py` script incorrectly infers the input dimension as 11 (the time dimension of the stale data) instead of the flattened feature size, causing a matrix multiplication failure in the first linear layer. To fix this, I will update `CACHE_DIR` in `library/config.py` to a new location. This effectively invalidates the cache, forcing the `DataProcessor` to regenerate the data in the correct 2D format required by the current runtime configuration (Cite debug_lesson_1).
