Implementation Strategy
The implementation strategy focuses on demonstrating the complete machine learning pipeline provided by the library files while ensuring the execution is fast and verifiable.

1.  **Configuration Patching**: We will modify the `Config` class attributes at runtime. This allows us to enable `DEBUG` mode (using a tiny subset of data), reduce `EPOCHS` to 1, set `N_FOLDS` to 2, and limit `MODEL_ARCHS` to a single lightweight model (`convnext_tiny`). We will also redirect all file outputs (cache, checkpoints, submission) to a temporary `./working/demo_execution` directory to avoid cluttering the main workspace.
2.  **Component Verification**: Before running the full pipeline, we will explicitly instantiate and verify individual components:
    *   **Data Loading**: Verify `get_dataloaders` yields batches with correct shapes and normalization.
    *   **Model Architecture**: Verify `get_model` creates a valid PyTorch model that accepts input tensors.
    *   **Utilities**: Test `Mixup` to ensure it returns mixed inputs and labels, and test `ModelEMA` to confirm it updates shadow weights.
3.  **Full Pipeline Execution**:
    *   Execute `run_training()`: This will run the training loop using the patched configuration, training the model on the debug subset and saving checkpoints.
    *   Execute `run_inference()`: This will load the checkpoints generated in the previous step and produce a submission file.
4.  **Result Validation**: Finally, we will verify that the submission CSV exists and contains the expected columns and row counts.
