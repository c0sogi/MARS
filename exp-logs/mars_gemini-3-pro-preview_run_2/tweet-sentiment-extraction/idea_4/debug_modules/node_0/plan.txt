To demonstrate the usage of the provided library files for the Tweet Sentiment Extraction task, I will implement a script that systematically verifies each component.

### Strategy

1.  **Configuration Override**: I will monkey-patch the `Config` class in `library.config` to enable `DEBUG` mode, reduce `EPOCHS` to 1, set a small `DEBUG_SAMPLE_SIZE`, and redirect output paths to `./working/demo`. This ensures the code runs quickly and does not interfere with existing production files.
2.  **Utility Verification**: I will validate the helper functions in `library.utils` (specifically `jaccard` and `get_selected_text`) using assertions with known inputs.
3.  **Data Pipeline Verification**: I will use `library.dataset.get_loaders` to generate training and validation DataLoaders. I will inspect a single batch to ensure the shapes of `input_ids`, `attention_mask`, and target tensors (`start_tokens`, `end_tokens`) are correct.
4.  **Model Architecture Verification**: I will instantiate the `TweetModel` from `library.model`, pass the batch from the previous step through it, and assert that the output logits have the expected dimensions `(batch_size, sequence_length)`.
5.  **Training Loop Execution**: I will run `library.train.run_fold(0)` for a single fold. This demonstrates the integration of the engine, loss calculation, and optimizer. I will verify that a model artifact is saved.
6.  **Inference Execution**: I will run `library.inference.predict(debug=True)` to generate predictions on the test set. I will verify the existence and format of the resulting `submission.csv`.
