The implementation strategy is as follows:

1.  **Setup & Configuration**: Define a `run_demo` function that overrides the default `Config` parameters. This involves pointing the data paths to temporary files and reducing computational parameters (1 epoch, small batch size, limited folds) to ensure the script runs quickly.
2.  **Data Preparation**: Create tiny subsets of the provided metadata (train, validation, and test) and save them to the working directory. This ensures the data processing pipeline runs almost instantly while still exercising the full logic.
3.  **Component Verification**: Systematically instantiate and verify the core components:
    *   **Data Pipeline**: Call `process_data` and `get_loaders` to verify they return correctly shaped tensors and dictionaries.
    *   **Model**: Instantiate `TweetModel`, move it to the GPU, and perform a dummy forward pass to check output shapes.
    *   **Loss**: Verify that `LabelSmoothingLoss` and `DistillationLoss` produce valid scalar outputs given dummy inputs.
4.  **Execution Loop**: Run a complete (but minimal) training epoch using `train_fn`, followed by an evaluation using `eval_fn`. Simulate the distillation stage (Stage 2) by creating a mock soft-label cache and running `train_fn` again.
5.  **Inference**: Save the trained model state and run `predict_test` to generate a submission file, asserting that the output file exists and has the correct format.
