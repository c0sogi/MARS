Based on the lessons learned from the Bi-Directional GRU experiment, I propose upgrading the architecture to a **Transformer-based Conditional Span Extraction** model (specifically using a pre-trained backbone like RoBERTa). This addresses the critical lack of semantic understanding observed in the recurrent model while preserving the effective span-prediction formulation.

### Model
- **Backbone Architecture**: Replace the scratch-trained Bi-GRU with a **pre-trained Transformer encoder** (e.g., RoBERTa-base). The Transformer's self-attention mechanism allows for significantly deeper semantic modeling, which is necessary to distinguish complex positive/negative phrases that the GRU failed to capture.
- **Input Representation**: Instead of concatenating a sentiment vector to every word embedding, the input will be formatted as a single sequence: `[CLS] <Sentiment> [SEP] <Tweet Text> [SEP]`. This allows the model to utilize its self-attention layers to dynamically condition the text representation on the sentiment token across all layers.
- **Prediction Head**: Retain the **Pointer Network (Span Prediction)** structure. `Cite solution_lesson_node_00001`. The model will output two vectors of logits corresponding to the sequence length—one for the start index and one for the end index—derived from the final hidden states of the Transformer. This enforces the structural constraint that the output must be a contiguous span.

### Data
- **Tokenization & Offsets**: Use the pre-trained Byte-Level BPE tokenizer associated with the backbone. Crucially, generate **offset mappings** for each token. This maps every sub-word token back to its character start and end positions in the original string, enabling precise extraction that respects the original whitespace and punctuation required by the Jaccard metric.
- **Label Alignment**: Convert the character-level start and end positions of the `selected_text` into token-level indices. If the `selected_text` does not align perfectly with token boundaries, select the span of tokens that maximally overlaps with the target characters.

### Training
- **Objective Function**: Minimize the sum of Cross-Entropy losses for the start and end token positions.
- **Optimization**: Use the AdamW optimizer with a learning rate scheduler that includes a warmup phase followed by linear decay. This is essential for fine-tuning pre-trained Transformers to prevent catastrophic forgetting of the pre-trained weights.
- **Regularization**: Apply dropout within the Transformer layers and the prediction head to mitigate overfitting, particularly given the relatively small size of the dataset compared to the model capacity.

### Evaluation
- **Inference Strategy**: Compute the start and end probability distributions for the test set. Select the pair of indices `(start, end)` that maximizes the sum of log-probabilities `P(start) + P(end)`, subject to `start <= end`.
- **Reconstruction**: Use the **offset mappings** (generated during preprocessing) to map the predicted token indices back to the original text string. This ensures the final output preserves the exact formatting of the raw tweet, which is critical for the word-level Jaccard score. `Cite solution_lesson_node_00001`.
