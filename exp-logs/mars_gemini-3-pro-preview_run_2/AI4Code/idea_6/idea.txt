Based on the "Lessons" learned, particularly the failure of the dense Transformer to improve upon the linear baseline (Cite solution_lesson_node_00010) and the proven efficiency of the Anchor-Based Ridge Regression (Cite solution_lesson_node_00001), I propose a **Stacked Hybrid Linear-Tree Ranking** strategy.

This solution structurally evolves the approach by transitioning from a single-stage linear regressor to a **Two-Stage Stacked Pipeline**. It retains the robust "lexical signposting" of the Ridge model (Exploitation) while introducing a Gradient Boosting Machine (Innovation) to capture non-linear interactions and notebook-level context (via Latent Semantic Analysis) that the linear model cannot perceive.

# Model
The architecture consists of two cascaded regression levels:

1.  **Level 1: Sparse Lexical Regressor (The "Signpost" Model)**
    *   **Architecture:** A **Ridge Regression** model.
    *   **Role:** This component is preserved exactly from the best-performing lessons. It acts as a high-bias, low-variance extractor of "signpost" features (e.g., mapping "Introduction" directly to rank 0.0).
    *   **Input:** Sparse TF-IDF vectors of the markdown text.

2.  **Level 2: Context-Aware Gradient Booster (The "Refinement" Model)**
    *   **Architecture:** A **LightGBM Regressor** (or XGBoost).
    *   **Role:** This model corrects the linear predictions by learning non-linear dependencies between the markdown content, the notebook's global code context, and the notebook's structure.
    *   **Input Features:**
        *   **Ridge Prediction:** The output rank from Level 1 (the strongest feature).
        *   **Markdown Semantics (LSA):** The TF-IDF vectors from Level 1 projected down to ~128 dimensions using **Truncated SVD**. This provides a dense, tabular representation of the markdown topic (e.g., "Data Loading" vs. "Visualization") without using neural embeddings (Cite solution_lesson_node_00010).
        *   **Code Context (LSA):** A separate TF-IDF + SVD pipeline applied to the *aggregated code cells* of the notebook. This provides a vector representing the notebook's technical domain (e.g., "PyTorch" vs. "Pandas"), allowing the tree to adjust ranks based on context (e.g., "Training" might appear later in a complex DL notebook than in a simple ML script).
        *   **Structural Metadata:** Notebook length (total cells), Markdown/Code ratio, and character counts.

# Data
**Preprocessing for Training:**
1.  **Target Generation:** Calculate the **Normalized Rank** $y \in [0, 1]$ for all markdown cells in the **Full Training Dataset** (Cite solution_lesson_node_00001, solution_lesson_node_00002).
2.  **Feature Engineering (Level 1):**
    *   Fit a **TF-IDF Vectorizer** on the full markdown corpus.
    *   **Configuration:** Use **Bigrams** (`ngram_range=(1, 2)`), **Logarithmic TF** (`sublinear_tf=True`), **Vocabulary=60,000**, and **No Accent Stripping** (Cite solution_lesson_node_00004, solution_lesson_node_00005).
3.  **Feature Engineering (Level 2):**
    *   **Markdown LSA:** Fit `TruncatedSVD` (n_components=128) on the Level 1 TF-IDF matrix.
    *   **Code LSA:** Aggregate all code text per notebook. Fit a separate TF-IDF (Vocab=5000) + SVD (n_components=32) pipeline to generate "Code Context" vectors.
    *   **Metadata:** Compute character lengths and notebook-level statistics.

**Preprocessing for Evaluation:**
1.  Process test data through the exact same TF-IDF -> SVD pipelines.
2.  Extract the sequence of **Code Cell IDs** for each test notebook to serve as the structural skeleton.

# Training
1.  **Level 1 (Cross-Validation):**
    *   Train the Ridge Regressor using **K-Fold Cross-Validation** (e.g., K=5) on the full training set.
    *   Generate **Out-Of-Fold (OOF)** predictions for every training sample. These OOF predictions serve as the unbiased input feature for Level 2.
    *   Retrain the Ridge Regressor on the *entire* training set for use during inference.
2.  **Level 2 (Stacking):**
    *   Construct the Level 2 dataset using the OOF Ridge predictions, LSA features, and metadata.
    *   Train the **LightGBM Regressor** to predict the Normalized Rank, minimizing **Mean Absolute Error (MAE)** or **RMSE**.
    *   **Strategy:** Use early stopping with a validation split to prevent overfitting.

# Evaluation
1.  **Pipeline Inference:**
    *   Pass test markdown cells through the Level 1 Ridge model to get initial rank predictions.
    *   Pass these predictions, along with the test set's SVD and metadata features, into the Level 2 LightGBM model to generate the **Final Predicted Rank**.
2.  **Anchor-Based Sorting:**
    *   Assign fixed, equidistant ranks ($0.0, \dots, 1.0$) to the notebook's ordered code cells (Cite solution_lesson_node_00001).
    *   Combine the code cells (fixed ranks) and markdown cells (Level 2 predicted ranks) into a single list.
    *   Sort the list by rank to produce the final `cell_order`.
