2.  **Training Pipeline**: We will initialize the `RankingPipeline` and execute `run_train()`. This handles data loading, feature engineering, and training both the Stage 1 (Ridge) and Stage 2 (LightGBM) models, saving them to disk.
3.  **Validation & Metric**: To meet the specific output requirement, we will manually reload the validation data and trained models. We will generate predictions, reconstruct the ground truth cell orders, and calculate the Kendall Tau metric. The result will be printed in the exact format: `Final Validation Metric: <value>`.
4.  **Failure Analysis**: We will compute the absolute error between the predicted rank and the ground truth rank for the validation set. We will then correlate this error with the generated features (e.g., lexical and latent similarity scores) to identify which features are most associated with prediction errors.
5.  **Submission**: We will compare the calculated validation metric against the threshold (0.7959051868218839). If the metric is higher, we will disable `DEBUG` mode and trigger `pipeline.run_inference(load_cached_data=False)`. Passing `False` for cached data ensures that the full test set is processed from raw files, preventing the use of any partial cache created during a debug run.
