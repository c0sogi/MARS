Based on the comprehensive analysis of the "Lessons" learned—specifically the necessity of **Decoupling Retrieval Spaces** (Cite solution_lesson_node_00035), the superiority of **Neighborhood Smoothing** (Cite solution_lesson_node_00015), the critical need for **Explicit Similarity Scores** (Cite solution_lesson_node_00034), and the efficiency of **Linear Baselines** on the **Full Dataset** (Cite solution_lesson_node_00002, solution_lesson_node_00010)—I propose a **Stacked Hybrid Ranking with Decoupled Dual-View Neighborhood Aggregation**.

This solution structurally evolves the "Stacked Hybrid" architecture (Idea 25) by formally addressing the "Data Starvation" failure mode identified in Lesson 00035. It ensures the decoupled retrieval strategy is applied to the full dataset and refines the aggregation logic to strictly adhere to the "Instance-Based" and "Explicit Score" lessons.

# Model

The architecture is a **Two-Stage Stacked Regression Pipeline** that arbitrates between global structural priors ("Signposts") and local alignment cues ("Anchors") derived from two independent vector spaces.

1.  **Stage 1: Sparse Lexical Regressor (The "Signpost" Model)**
    *   **Component:** A **Ridge Regression** model.
    *   **Role:** Explicitly preserved from the lessons to serve as the robust, high-bias baseline. It maps explicit "signpost" keywords (e.g., "Introduction", "Submission") directly to normalized ranks using high-dimensional sparse features (Cite solution_lesson_node_00010).
    *   **Input:** High-dimensional **TF-IDF** vectors (Unigrams + Bigrams).

2.  **Stage 2: Decoupled Dual-View Gradient Booster (The "Refinement" Model)**
    *   **Component:** A **LightGBM Regressor**.
    *   **Role:** Refines the linear prediction by integrating non-linear interactions and **Decoupled Neighborhood Aggregation**. It consumes signals from two independent retrieval views to distinguish between "Exact Matches" and "Conceptual Matches."
    *   **Input Features:**
        *   **Ridge Prediction:** The output from Stage 1 (Cite solution_lesson_node_00011).
        *   **View A: Lexical Neighborhood (Precision):** Derived from **Sparse TF-IDF** similarity. Captures exact keyword matches (e.g., `plt.plot` $\leftrightarrow$ "plot").
            *   **Instance Features:** The **Rank** and **Similarity Score** of the **1st Nearest Neighbor**. This acts as a high-confidence gate for exact matches (Cite solution_lesson_node_00034).
            *   **Smoothed Features:** The **Weighted Mean Rank** (weighted by similarity) and **Standard Deviation** of the **Top-K** (e.g., K=10) neighbors. This provides robustness against spurious keyword overlaps (Cite solution_lesson_node_00015).
        *   **View B: Latent Neighborhood (Recall):** Derived from **Truncated SVD** similarity. Captures conceptual alignment (e.g., `StandardScaler` $\leftrightarrow$ "Preprocessing") efficiently on the full dataset (Cite solution_lesson_node_00013, solution_lesson_node_00035).
            *   **Instance Features:** Rank and Similarity of the 1st neighbor in SVD space.
            *   **Smoothed Features:** Weighted Mean Rank and Standard Deviation of the Top-K neighbors in SVD space.
        *   **Interaction Features:** Explicit deltas to guide arbitration (e.g., $|Rank_{Ridge} - Rank_{Lexical\_Mean}|$ and $|Rank_{Lexical\_Mean} - Rank_{Latent\_Mean}|$).
        *   **Metadata:** Notebook length, markdown ratio, and raw LSA vectors.

# Data

**Preprocessing for Training:**
1.  **Full Dataset:** Utilize the entire training corpus (~140k notebooks). **Do not subsample**; the linear and SVD components are scalable enough to handle this volume (Cite solution_lesson_node_00002).
2.  **Target Generation:** Calculate the **Normalized Rank** $y \in [0, 1]$ for all markdown cells relative to the fixed code cell skeleton (Cite solution_lesson_node_00001).
3.  **Global Vectorization:**
    *   Fit a **TF-IDF Vectorizer** on the full markdown corpus.
    *   **Configuration:** Vocabulary=60,000, N-gram range=(1, 2), Sublinear TF=True, and **No Accent Stripping** (Cite solution_lesson_node_00004, solution_lesson_node_00005).
4.  **Latent Space Construction:**
    *   Fit **Truncated SVD** (e.g., 128 components) on the TF-IDF matrix.
    *   **Project Code Cells:** Transform the notebook's code cells into this same SVD space by projecting their TF-IDF vectors (Cite solution_lesson_node_00013).
5.  **Decoupled Neighbor Extraction:**
    *   **Lexical View:** Compute sparse cosine similarity between each markdown cell and all code cells in its notebook. Retrieve Top-10 neighbors. Extract Instance (Top-1) and Smoothed (Top-10 Weighted Mean/Std) features.
    *   **Latent View:** Compute dense cosine similarity in SVD space. Retrieve Top-10 neighbors. Extract Instance and Smoothed features.

**Preprocessing for Evaluation:**
1.  Apply the fitted TF-IDF and SVD pipelines to the test data.
2.  Extract the fixed sequence of **Code Cell IDs** for each test notebook.
3.  Compute the Decoupled Dual-View Neighborhood Features relative to the test notebook's code skeleton.

# Training

1.  **Stage 1 (Cross-Validation):**
    *   Train the Ridge Regressor using **5-Fold Cross-Validation** on the full dataset.
    *   Generate **Out-Of-Fold (OOF)** predictions for the entire training set to serve as unbiased features for Stage 2 (Cite solution_lesson_node_00011).
    *   Retrain Ridge on the full dataset for final inference.
2.  **Stage 2 (Stacking):**
    *   Construct the Stage 2 dataset combining: OOF Ridge Predictions, Lexical Neighborhood Features, Latent Neighborhood Features, Interaction Features, and Metadata.
    *   Train the **LightGBM Regressor** to predict Normalized Rank, minimizing **Mean Absolute Error (MAE)**.
    *   **Strategy:** Use early stopping with a validation split. The explicit similarity scores allow the tree to learn gating logic (e.g., "Trust Lexical Rank only if Similarity > 0.5").

# Evaluation

1.  **Pipeline Inference:**
    *   Generate Stage 1 predictions (Ridge).
    *   Generate Stage 2 features (Decoupled Neighborhoods).
    *   Predict Final Rank using the LightGBM model.
2.  **Anchor-Based Sorting:**
    *   Assign fixed, equidistant ranks ($0.0, \dots, 1.0$) to the ordered code cells (Cite solution_lesson_node_00001).
    *   Combine the code cells (fixed ranks) and markdown cells (predicted ranks) into a single list.
    *   Sort the list by rank to produce the final `cell_order`.
