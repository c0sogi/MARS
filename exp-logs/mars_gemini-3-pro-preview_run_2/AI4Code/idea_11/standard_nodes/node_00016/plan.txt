The implementation strategy follows the "Stacked Hybrid Ranking" architecture defined in the provided library files. The script orchestrates the pipeline by manually executing the steps typically found in `training_pipeline.py` to retain access to intermediate variables (predictions, features) required for the mandatory failure analysis and metric reporting.

1.  **Setup & Data Loading**: The script initializes the environment and loads the training and validation features using `feature_engine.generate_features`. This handles TF-IDF vectorization, SVD projection, and neighborhood feature extraction.
2.  **Stage 1 (Ridge) Training**: It calls `training_pipeline.run_stage1_cv` to generate Out-Of-Fold (OOF) predictions for the training set and trains the Ridge model on the full training corpus.
3.  **Stage 2 (LightGBM) Training**: It constructs the stacking dataset. For the validation set, it generates Stage 1 predictions using the trained Ridge model. It then trains the LightGBM model to refine the rankings.
4.  **Validation & Metric**: It generates final predictions on the validation set, reconstructs the cell orders (merging predicted markdown ranks with fixed code ranks), and computes the Kendall Tau correlation using the provided ground truth metadata.
5.  **Failure Analysis**: It calculates the absolute error of the model's rank predictions on the validation set and computes Pearson correlations between this error and input features (e.g., `lex_max_sim`, `n_code_cells`) to identify systematic weaknesses.
6.  **Submission**: If the validation metric exceeds the specified threshold, it triggers `inference_pipeline.run_inference_pipeline` to generate the final `submission.csv` for the test set.
