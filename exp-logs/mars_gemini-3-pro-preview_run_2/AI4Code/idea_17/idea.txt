Based on the "Lessons" learned—specifically the power of **Anchor-Based Regression** (Cite solution_lesson_node_00001), the necessity of **Neighborhood Smoothing** (Cite solution_lesson_node_00015), and the scalability of **Latent Semantic Analysis** (Cite solution_lesson_node_00013)—I propose a **Stacked Hybrid Ranking with Functional Landmark Triangulation**.

This solution structurally evolves the "Stacked Hybrid" architecture by overcoming the "blindness" of previous anchoring methods. Previous iterations (Idea 12, Idea 15) calculated the distance to the "nearest" code cell, ignoring *what* that code cell actually did. This meant a markdown cell describing "Model Training" could be incorrectly anchored to a lexically similar but functionally irrelevant "Data Loading" cell. The proposed solution introduces **Functional Landmarks**: it uses unsupervised clustering to categorize code cells into functional types (e.g., Imports, EDA, Modeling) and then "triangulates" the position of each markdown cell relative to the nearest anchor of *each* type.

# Model

The architecture is a **Two-Stage Stacked Regression Pipeline** that combines a robust linear baseline with a structure-aware non-linear refiner.

1.  **Stage 1: Sparse Lexical Regressor (The "Signpost" Model)**
    *   **Component:** A **Ridge Regression** model.
    *   **Role:** Explicitly preserved from the lessons to serve as the high-bias baseline. It maps explicit "signpost" keywords (e.g., "Introduction", "Submission") directly to normalized ranks using high-dimensional sparse features (Cite solution_lesson_node_00010).
    *   **Input:** High-dimensional **TF-IDF** vectors (Unigrams + Bigrams).

2.  **Stage 2: Landmark-Aware Gradient Booster (The "Refinement" Model)**
    *   **Component:** A **LightGBM Regressor**.
    *   **Role:** Refines the linear prediction by learning non-linear interactions and **Functional Landmark Triangulation**. Instead of a single "nearest neighbor" feature, it sees a vector of distances to specific notebook functions.
    *   **Input Features:**
        *   **Ridge Prediction:** The output from Stage 1 (Cite solution_lesson_node_00011).
        *   **Landmark Anchor Features (Innovation):** We define $K$ global "Functional Code Types" (e.g., Imports, Visualization, Modeling) using clustering. For each markdown cell, we identify the **nearest code cell of Type $k$** within the notebook. We extract the **Rank** and **Similarity** of these $K$ specific landmarks. This allows the model to learn rules like "If text contains 'plot', align with the nearest Type-2 (Visualization) anchor, even if a Type-0 (Import) anchor is lexically closer."
        *   **Smoothed Neighborhood Features:** The **Mean Rank** of the **Top-N** code cells (regardless of type) with the highest TF-IDF similarity. This preserves the robustness of the "Lexical Overlap" signal (Cite solution_lesson_node_00015, solution_lesson_node_00018).
        *   **Metadata:** LSA vectors of the markdown text and notebook statistics.

# Data

**Preprocessing for Training:**
1.  **Target Generation:** Calculate the **Normalized Rank** $y \in [0, 1]$ for all markdown cells in the **Full Training Dataset** relative to the fixed code cell skeleton (Cite solution_lesson_node_00001, solution_lesson_node_00002).
2.  **Global Vectorization:**
    *   Fit a **TF-IDF Vectorizer** on the full markdown corpus.
    *   **Configuration:** Vocabulary=60,000, N-gram range=(1, 2), Sublinear TF=True, and **No Accent Stripping** (Cite solution_lesson_node_00004, solution_lesson_node_00005).
3.  **Functional Code Clustering (The Core):**
    *   Fit a separate **TF-IDF + Truncated SVD** pipeline on the aggregated **Code Cells** of the training set (Cite solution_lesson_node_00013).
    *   Apply **Mini-Batch K-Means** (e.g., $K=5$) to these code SVD vectors to identify global "Functional Types" (e.g., Cluster 0: Imports/Setup, Cluster 1: Plots, Cluster 2: Sklearn/Model, etc.).
4.  **Feature Extraction:**
    *   **Landmarks:** For each notebook, assign every code cell to a Cluster ID. For each markdown cell, calculate the cosine similarity to all code cells. For each Cluster ID $k \in [0..4]$, find the code cell with the maximum similarity. Store its **Rank** and **Similarity Score**. If a notebook lacks a specific cluster (e.g., no plots), use a sentinel value (NaN).
    *   **Neighborhood:** Compute the Mean Rank of the Top-5 code cells with the highest TF-IDF similarity (Cite solution_lesson_node_00015).

**Preprocessing for Evaluation:**
1.  Apply TF-IDF and SVD pipelines to test data.
2.  Assign Cluster IDs to test code cells using the trained K-Means model.
3.  Compute Landmark and Neighborhood features relative to the test notebook's code skeleton.

# Training

1.  **Stage 1 (Cross-Validation):**
    *   Train the Ridge Regressor using **5-Fold Cross-Validation** on the full dataset.
    *   Generate **Out-Of-Fold (OOF)** predictions for the entire training set to serve as unbiased features for Stage 2 (Cite solution_lesson_node_00011).
    *   Retrain Ridge on the full dataset for inference.
2.  **Stage 2 (Stacking):**
    *   Construct the Stage 2 dataset combining: OOF Ridge Predictions, Landmark Anchor Features ($K \times 2$ features), Smoothed Neighborhood Features, and Metadata.
    *   Train **LightGBM** to predict Normalized Rank, minimizing **Mean Absolute Error (MAE)**.
    *   **Strategy:** Use early stopping with a validation split. The tree will learn to weight specific landmarks based on the markdown content (e.g., trusting the "Visualization" landmark when the text vector implies plotting).

# Evaluation

1.  **Pipeline Inference:**
    *   Generate Stage 1 predictions (Ridge).
    *   Generate Stage 2 features (Landmark Triangulation).
    *   Predict Final Rank using LightGBM.
2.  **Anchor-Based Sorting:**
    *   Assign fixed, equidistant ranks ($0.0, \dots, 1.0$) to the ordered code cells (Cite solution_lesson_node_00001).
    *   Combine the code cells (fixed ranks) and markdown cells (predicted ranks) into a single list.
    *   Sort the list by rank to produce the final `cell_order`.
