Based on the lessons learned, specifically the effectiveness of the granular backoff hierarchy for common tokens (Cite solution_lesson_node_00006) and the failure of lookup tables for high-cardinality semiotic classes like Money and Decimals (Cite solution_lesson_node_00002), I propose a **Hybrid Retrieve-and-Generate System**.

This system delegates the "head" of the distribution (standard words, punctuation) to an efficient memory-based model and the "tail" (numbers, complex symbols) to a generative neural network.

# Model
The solution consists of two distinct components managed by a **Rule-Based Router**:

1.  **Component A: Enhanced HFBB (The Memory Module)**
    *   This component handles the vast majority of tokens (PLAIN, PUNCT).
    *   It utilizes the **5-level backoff hierarchy** proven successful in previous iterations: **Trigram $\rightarrow$ Bigram (Prev) $\rightarrow$ Bigram (Next) $\rightarrow$ Unigram $\rightarrow$ Identity**. Cite {solution_lesson_node_00006}.
    *   This ensures near-instant inference and high precision for seen vocabulary.

2.  **Component B: Context-Aware Character-Level Transformer (The Generative Module)**
    *   This component addresses the "infinite cardinality" problem (Cite {solution_lesson_node_00002}) where lookup tables fail (e.g., unseen monetary values like "$3,451.29").
    *   **Architecture:** A lightweight Sequence-to-Sequence (Seq2Seq) Transformer operating at the **character level**.
    *   **Input:** A windowed sequence containing the target token and its immediate context: `[Prev_Word] <SEP> [Target_Token] <SEP> [Next_Word]`. The context is crucial for disambiguating ambiguous inputs (e.g., "2" becoming "two" vs. "second").
    *   **Output:** The normalized character sequence.

3.  **Routing Logic:**
    *   The router inspects the raw input token.
    *   **Condition:** If the token contains any decimal digits (0-9), it is routed to **Component B** (Transformer).
    *   **Default:** All other tokens are routed to **Component A** (HFBB). This effectively isolates the "hard" numeric normalization tasks while preserving the high accuracy of the baseline for text.

# Data
1.  **HFBB Preparation:**
    *   Process the entire training corpus to build the Trigram, Bigram, and Unigram frequency maps as per the standard HFBB procedure.

2.  **Seq2Seq Preparation:**
    *   **Filtering:** Create a specialized training subset consisting *only* of tokens that contain digits. This focuses the neural network's capacity on the problem domain it will actually serve (semiotic classes).
    *   **Tokenization:** Use a **Character-Level Tokenizer**. Since the task involves transliteration and number expansion, subword tokenizers (like BPE) are often suboptimal. Character-level processing allows the model to learn precise mappings (e.g., "1" $\rightarrow$ "o-n-e").
    *   **Context Windowing:** For each sample, extract the preceding and succeeding tokens from the sentence to form the source sequence.

# Training
1.  **HFBB:** No training required; constructed via single-pass statistical aggregation (Maximum Likelihood Estimation).
2.  **Seq2Seq Model:**
    *   **Objective:** Minimize Cross-Entropy Loss on the target character sequence.
    *   **Optimizer:** Use AdamW with a learning rate scheduler (e.g., linear warmup and decay) to ensure stable convergence.
    *   **Strategy:** Train from scratch on the filtered "digit-heavy" dataset. Given the 24-hour limit and GPU availability, a model with ~4-6 layers and hidden dimension of 256-512 is feasible and sufficient for this complexity.

# Evaluation
1.  **Inference Pipeline:**
    *   Iterate through the test set.
    *   For each token, apply the **Routing Logic** (check for digits).
    *   If **Digits Present**: Pass the context-windowed string to the Seq2Seq model and generate the prediction using **Beam Search** (width ~3-5) to maximize output quality.
    *   **Else**: Query the HFBB hierarchy (Trigram $\to$ Bigrams $\to$ Unigram $\to$ Identity).
2.  **Submission:** Combine the outputs from both streams into the final CSV format.
