The implementation strategy for the `runfile.py` script is as follows:

1.  **Configuration Override**: To ensure the pipeline serves as a "fast baseline" and completes within the 2-hour limit, we modify the global `Config` object. We reduce `EPOCHS` to 5 and `N_FOLDS` to 3. This speeds up both the Jackknife residual generation (data preparation) and the Transformer training loop.
2.  **Pipeline Execution**:
    *   **Training**: We call `train_transformer(load_cached_data=True)`. This function orchestrates the `DataFactory` to generate the curriculum-enriched dataset (mixing residuals and anchors) and trains the `CharToSubwordTransformer`.
    *   **Memory Model Setup**: We explicitly load the full training metadata and fit the `HFBB` (Hierarchical Frequency Back-off) model. This ensures the Tier 1 memory component is populated with the complete dataset for inference, not just the folds used during training.
    *   **Inference Engine**: We instantiate `CascadeInference`, which loads both the trained HFBB model and the best Transformer checkpoint.
3.  **Validation**: We load the hold-out validation set (`val.csv`) and run the full inference pipeline. We compute the exact string match accuracy and print it in the required format (`Final Validation Metric: <value>`).
4.  **Failure Analysis**: We analyze the validation results by calculating the correlation between prediction errors and input token length. We also group errors by token `class` to identify which types of text (e.g., DATE, MONEY) are causing the most failures.
5.  **Submission**: We compare the calculated validation accuracy against the strict threshold (`0.9784022349361615`). If the model performs sufficiently well, we generate predictions for the test set and save them to `submission.csv`.
