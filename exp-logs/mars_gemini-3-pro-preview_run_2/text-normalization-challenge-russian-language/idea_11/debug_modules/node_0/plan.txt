Implementation Strategy:
1.  **Environment Setup**: We will begin by importing the necessary modules and setting up a dedicated working directory (`./working/demo_execution`) to store temporary artifacts, ensuring we don't interfere with existing caches.
2.  **Data Subsetting**: To meet the speed requirement, we will create "mini" versions of the training, validation, and test datasets (e.g., 500 rows each) derived from the provided metadata. We will then redirect the `Config` paths to these mini files.
3.  **Configuration Override**: We will dynamically modify the `Config` class attributes to reduce model complexity (e.g., smaller embedding dimensions, fewer layers) and training duration (1 epoch, small batch size). This ensures the code runs quickly on the CPU/GPU.
4.  **Component Demonstration**:
    *   **Tokenization**: We will build character and BPE tokenizers from scratch using the mini dataset and verify their vocabulary sizes.
    *   **HFBB (Tier 1)**: We will instantiate the statistical back-off model, build its stats from the mini dataset, and verify its query logic with a specific test case.
    *   **Transformer (Tier 2)**: We will initialize the custom Transformer architecture, verify the output shape of a forward pass, and run a full training cycle using the `train_model` function.
    *   **Inference**: We will use the `InferenceEngine` to generate predictions for the mini test set, utilizing the trained model and HFBB logic, and verify the submission file format.
5.  **Validation**: Throughout the script, we will use `assert` statements to validate data shapes, file existence, and logical correctness of the outputs.
