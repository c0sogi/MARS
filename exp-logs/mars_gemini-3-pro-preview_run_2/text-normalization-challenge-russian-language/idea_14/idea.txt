Based on the comprehensive failure analysis and the synthesis of all provided lessons, I propose the **Robust Soft-Residual Hybrid Cascade**.

This strategy introduces a **Soft-Residual Learning Paradigm** to resolve the fundamental conflict between "training on failures" (which causes distribution mismatch, **Cite {solution_lesson_node_00013}**) and "training on all data" (which is inefficient and lacks focus). It combines this with a **Heterogeneous Granularity** architecture and a **Strict-Priority Routing** logic to ensure stability.

# Model

The solution employs a **Two-Tier Cascade** architecture that routes tokens based on **Contextual Specificity** and **Statistical Confidence**.

1.  **Tier 1: Confidence-Aware Granular Memory (HFBB)**
    *   **Structure:** A 4-level statistical backoff hierarchy: **Trigram $\rightarrow$ Bigram (Prev) $\rightarrow$ Bigram (Next) $\rightarrow$ Unigram**.
    *   **Innovation (Confidence Gating):** The **Unigram** layer explicitly stores a **Confidence Score** ($P(\text{Mode}) = \frac{\text{Count}(\text{Mode})}{\text{Total Count}}$).
    *   **Role:** This tier acts as a high-precision filter. It resolves all context-dependent matches (**Cite {solution_lesson_node_00006}**) and "stable" context-free tokens (e.g., "2012", Confidence $\approx$ 1.0). It flags "ambiguous" tokens (e.g., "2", Confidence < 0.9) for the neural network, strictly adhering to the "Exhaust Lookup" principle (**Cite {solution_lesson_node_00010}**).

2.  **Tier 2: Heterogeneous Granularity Transformer**
    *   **Architecture:** A Sequence-to-Sequence Transformer designed to match the linguistic requirements of the task:
        *   **Encoder (Character-Level):** The input is tokenized at the character level. This is strictly necessary to parse the internal structure of infinite-cardinality classes like Money and Decimals (**Cite {solution_lesson_node_00002}**).
        *   **Decoder (Subword-Level):** The output is generated using a **BPE (Byte Pair Encoding)** tokenizer trained on the target text. This ensures the model generates valid Russian morphemes and words.
    *   **Input Representation (Context Anchoring):** The input sequence explicitly delimits the target token within a wide context window ($\pm 2$ words) using special tags: `[Prev_Context] <SEP> <START> [Target_Chars] <END> <SEP> [Next_Context]`. This guides the attention mechanism to focus on the token to be normalized while attending to the surrounding gender/case cues.

# Data

The core innovation is the **Soft-Residual Density-Maximized Pipeline**, which solves the "Curriculum vs. Mismatch" trade-off.

1.  **Pipeline Safety (Solving Lesson 00031):**
    *   **Hash-Based Invalidation:** All intermediate artifacts (vocabularies, HFBB tables, processed tensors) will be saved in directories named after the **hash of their configuration and source data size**. This guarantees that the model never trains on stale "debug" artifacts.

2.  **HFBB Construction:**
    *   Computed on the **Full Training Corpus** (7M+ tokens) to maximize coverage.

3.  **Transformer Dataset (Density-Maximized Semiotics):**
    *   **Domain Filtering:** Extract **ALL** tokens from the training set that belong to semiotic classes (containing digits `\d` or Latin `[a-zA-Z]`). We do *not* filter out the "easy" examples (Anchors). This ensures the model has sufficient data density to generalize (**Cite {solution_lesson_node_00026}**).
    *   **Class Balancing:** Aggressively upsample rare, high-error classes (`MONEY`, `DECIMAL`, `TELEPHONE`) to match the frequency of the dominant class (`DATE`) (**Cite {solution_lesson_node_00002}**).

# Training

1.  **Strategy: Soft-Residual Weighting (Structural Innovation):**
    *   Instead of hard-filtering the dataset into "Residuals" (which destroys the curriculum, **Cite {solution_lesson_node_00014}**) or treating all data equally (which wastes capacity on easy tokens), we assign a **Sample Weight** to each training instance based on the Tier 1 model's performance:
        *   **Anchors (Easy):** If Tier 1 correctly predicts the token with High Confidence, set `Weight = 0.1`. This maintains the "grammar" of normalization (e.g., "1" $\to$ "one") without dominating the gradients.
        *   **Residuals (Hard):** If Tier 1 fails (incorrect prediction) or is Low Confidence, set `Weight = 1.0`.
    *   **Effect:** This focuses the neural network's capacity on the "long tail" of edge cases (**Cite {solution_lesson_node_00013}**) while preserving the fundamental rules learned from simple examples.

2.  **Optimization:**
    *   **Objective:** Minimize Weighted Cross-Entropy Loss on the target BPE sequence.
    *   **Optimizer:** `AdamW` with a linear warmup and cosine decay scheduler.
    *   **Regularization:** Dropout (0.1) and Label Smoothing (0.1).

# Evaluation

The inference pipeline employs a **Confidence-Gated Routing Logic**:

1.  **Step 1 (Context Match):** Query HFBB Trigram $\rightarrow$ Bigram(Prev) $\rightarrow$ Bigram(Next).
    *   If a match is found, **Return Prediction** immediately (**Cite {solution_lesson_node_00006}**).
2.  **Step 2 (Confidence Check):** Query HFBB Unigram.
    *   If Match Found **AND** `Confidence > Threshold` (e.g., 0.99): **Return Prediction**. (Stable tokens are handled by memory, **Cite {solution_lesson_node_00010}**).
    *   If Match Found **AND** `Confidence <= Threshold`: **Route to Tier 2**. (Ambiguous tokens are routed to the Neural Net).
3.  **Step 3 (OOV/Fallback):**
    *   If the token is Semiotic (contains `\d` or `[a-zA-Z]`): **Route to Tier 2**.
    *   Else: **Identity Fallback**.
