The issue is that the `_batch_greedy_decode` method in `library/pipeline.py` uses `Config.MAX_SEQ_LEN` as a default argument. Python evaluates default arguments at import time, so the method captures the initial configuration value (128) rather than the value updated at runtime (32) by the demo script. This causes the decoding loop to attempt generating sequences longer than the model's positional encoding buffer (which was initialized with the runtime value of 32), resulting in a tensor size mismatch. To fix this, I will change the default argument to `None` and assign `Config.MAX_SEQ_LEN` inside the function body, ensuring the current runtime configuration is used.
