# Strategy: Strict-Priority Hybrid Cascade with Class-Balanced Neural Fallback

This approach refines the "Hybrid" concept by strictly enforcing the hierarchy of memorization over generation (addressing **Lesson 00010**) and optimizing the neural component to specifically target the "long tail" of rare semiotic classes (addressing **Lesson 00002**).

### Model
The architecture is a **Strict-Priority Cascade** of two distinct inference engines. The system processes each token through a sequence of gates, stopping as soon as a confident match is found.

1.  **Tier 1: Granular HFBB (The Memory Engine)**
    *   This component utilizes the optimized **4-level backoff hierarchy**: **Trigram $\rightarrow$ Bigram (Prev) $\rightarrow$ Bigram (Next) $\rightarrow$ Unigram**.
    *   **Innovation:** Crucially, unlike previous hybrid attempts, the **Unigram** layer is included in this high-priority tier. This ensures that any token seen in the training set—even in isolation—is handled by the memory model. This directly resolves the regression observed in **Cite {solution_lesson_node_00010}**, where routing known simple tokens (e.g., "2") to a neural network caused unnecessary inference errors.
    *   **Structure:** Hash maps storing `context_tuple -> normalized_text`.

2.  **Tier 2: Regex-Gated Transformer (The Generative Engine)**
    *   **Gate:** This engine is invoked *only* if Tier 1 fails (returns no match) **AND** the token satisfies a "Semiotic Regex" (contains a digit `\d` OR a Latin character `[a-zA-Z]`). This expands the scope beyond just numbers to include transliteration tasks (e.g., "Julius"), which HFBB might miss if OOV.
    *   **Architecture:** A character-level Sequence-to-Sequence Transformer (e.g., a lightweight Encoder-Decoder trained from scratch).
    *   **Input:** A context-windowed character sequence: `[Prev_Word] <SEP> [Target_Token] <SEP> [Next_Word]`.
    *   **Role:** To generate normalizations for **unseen** (OOV) complex tokens, such as rare monetary amounts, dates, or foreign names.

3.  **Tier 3: Identity Fallback**
    *   If both Tier 1 and Tier 2 are bypassed/fail, the system returns the original token (Identity).

### Data
1.  **HFBB Construction:**
    *   Use the full training corpus to populate the Trigram, Bigram, and Unigram frequency maps.
    *   Apply **Group Shuffle Split** to ensure validation integrity.

2.  **Transformer Data Preparation (Curriculum Learning):**
    *   **Filtering:** Construct a training dataset consisting *only* of tokens where `class` is **NOT** `PLAIN` or `PUNCT`. This focuses the model exclusively on the semiotic classes (Date, Cardinal, Money, Letters, etc.).
    *   **Class Balancing (Upsampling):** **Cite {solution_lesson_node_00002}** identified that classes like `MONEY`, `DECIMAL`, and `TELEPHONE` have high error rates but low frequency. To address this, **upsample** these rare classes in the Transformer training set to match the frequency of the `DATE` class. This forces the model to learn the complex grammar of these rare entities rather than ignoring them.
    *   **Tokenization:** Use a custom **Character-Level Tokenizer** derived from this filtered subset to handle the expansion of digits and symbols precisely.

### Training
1.  **HFBB:**
    *   Single-pass Maximum Likelihood Estimation (frequency counting and mode selection).

2.  **Transformer:**
    *   **Objective:** Minimize Cross-Entropy Loss on the target character sequence.
    *   **Optimization:** Train from scratch using `AdamW` with a linear warmup and cosine decay scheduler.
    *   **Regularization:** Use high dropout (0.2) to prevent overfitting, as the model effectively sees a "distilled" version of the dataset.

### Evaluation
1.  **Inference Pipeline:**
    *   For each token in the test set:
        1.  **Query Tier 1 (HFBB):** Check Trigram $\to$ Bigram(P) $\to$ Bigram(N) $\to$ Unigram. If a match is found, return it immediately (**Cite {solution_lesson_node_00006}**).
        2.  **Check Gate:** If no match, check if `token` contains `\d` or `[a-zA-Z]`.
        3.  **Query Tier 2 (Transformer):** If Gate is True, run the Transformer on the context window and return the generated string.
        4.  **Fallback:** Otherwise, return the original token.
2.  **Submission:** Format the outputs into the required CSV structure.
