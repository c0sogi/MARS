To optimize the performance of the text normalization model, I will extend the **Hierarchical Frequency-Based Backoff (HFBB)** model by introducing intermediate **Bigram** layers. The current solution jumps directly from a specific Trigram context `(prev, curr, next)` to a generic Unigram context `(curr)`. This creates a gap where the model fails to normalize tokens that appear in slightly different trigram contexts but share a strong local dependency (e.g., a number influenced by the preceding preposition or the following noun).

By adding `(prev, curr)` and `(curr, next)` lookup layers, we create a smoother backoff hierarchy: **Trigram $\to$ Bigram (Prev) $\to$ Bigram (Next) $\to$ Unigram $\to$ Identity**. This strategy directly applies the lesson that a robust hierarchical lookup cache is the most effective "Day 0" baseline for high-cardinality text normalization tasks (Cite {solution_lesson_node_00002}). This modification is expected to improve accuracy on the "tail" of the distribution without significantly increasing runtime.

I will modify `library/model.py` to implement these additional layers in the `HFBBModel` class.
