This balances the need for a "fast baseline" with the requirement to achieve a high F1 score (>0.808), ensuring the model converges sufficiently within the 2-hour time limit.
2.  **Data Loading**: We will load the training and validation metadata from the `./metadata` directory. We will instantiate `KuzushijiDataset` with the appropriate transforms (photometric augmentation for training, standard normalization for validation) and wrap them in PyTorch `DataLoader`s with `pin_memory=True` for efficient GPU transfer.
3.  **Model Initialization**: We will construct the Faster R-CNN model using `library.model.get_model()`, which is pre-configured with a ResNet-50 backbone and adapted for the high-cardinality classification task (4782 classes). The model will be moved to the detected GPU device.
4.  **Training**: We will execute the training pipeline using `library.engine.train_eval_loop`. This handles the epoch iteration, gradient updates, and validation monitoring, saving the best model checkpoint to `./working/idea_4/best_model.pth`.
5.  **Validation & Metrics**: After training, we will reload the best model checkpoint. We will compute the global F1 score on the validation set using `library.engine.evaluate` and print it in the strict format `Final Validation Metric: <value>`.
6.  **Failure Analysis**: We will perform a granular analysis by iterating through the validation set in inference mode. We will calculate the F1 score for each image individually and compute the Pearson correlation between the error magnitude (`1 - F1`) and image metadata (Width, Height, Character Count) to identify systematic weaknesses.
7.  **Submission**: We will check if the final validation F1 score exceeds the strict threshold of `0.8082640433856375`. If successful, we will generate predictions for the test set using `library.engine.inference` and save the formatted submission file to `./submission/submission.csv`.
