Based on the extensive failure analysis and lessons learned from previous iterations, I propose the following optimized strategy.

### Model
**Architecture: Cascade R-CNN with ResNet-50-FPN**
I propose a structural shift from the standard Faster R-CNN to a **Cascade R-CNN** architecture, while explicitly retaining the lighter **ResNet-50** backbone.
*   **Cascade Head (Structural Innovation):** Standard Faster R-CNN uses a single detection head with a fixed IoU threshold (0.5), which struggles to separate dense, touching cursive characters, often merging them or failing to localize the center precisely. Cascade R-CNN introduces a multi-stage architecture with increasing IoU thresholds (e.g., 0.5, 0.6, 0.7). This progressively refines the bounding boxes, ensuring that the final predictions are tightly aligned with the character ink, directly addressing the separation issues identified in early segmentation attempts **Cite solution_lesson_node_00001**.
*   **Backbone Selection (Strategic Retention):** We explicitly reject the ResNet-101 backbone proposed in "Idea 2". Empirical evidence demonstrated that the deeper network caused convergence issues and lower recall for this specific task, as the visual features (strokes) are geometric rather than semantic. We revert to **ResNet-50**, which offers the optimal balance of capacity and convergence speed **Cite solution_lesson_node_00026**.
*   **Configuration:** The model will be initialized using a dedicated configuration object to inject parameters directly into the constructor, preventing the "silent default" errors observed previously **Cite solution_lesson_node_00015**, **Cite solution_lesson_node_00023**.

### Data
**Preprocessing & Augmentation**
1.  **Resolution Scaling:** Input images will be resized to `min_size=1024` and `max_size=2048`. This high-resolution input is non-negotiable for resolving small characters **Cite solution_lesson_node_00005**.
2.  **Geometric Sanitization:** Ground truth bounding boxes will be explicitly clipped to the image boundaries during loading. This prevents the model from attempting to regress to coordinates outside the visible frame, which was found to destabilize training on edge cases **Cite solution_lesson_node_00027**.
3.  **Label Encoding:** Class labels will be offset by `+1` (1-3848) to strictly reserve index `0` for the background, preventing the silent suppression of the first character class **Cite solution_lesson_node_00022**.
4.  **Photometric Augmentation:** We will apply `ColorJitter` (brightness, contrast, saturation) to the training pipeline. This forces the model to learn shape-invariant features, which is critical given the varying paper backgrounds **Cite solution_lesson_node_00020**.

### Training
**Procedure & Optimization**
1.  **Hyperparameters:** We will use a **Batch Size of 4** and a **Learning Rate of 0.005**. This strictly adheres to the Linear Scaling Rule ($0.02 \times 4/16$) required for SGD convergence with small batches **Cite solution_lesson_node_00012**.
2.  **Schedule:** The training duration will be extended to **15 epochs**, with learning rate decays delayed to epochs 10 and 13. This extended schedule is necessary to allow the model to converge despite the difficulty added by the photometric augmentation **Cite solution_lesson_node_00007**, **Cite solution_lesson_node_00020**.

### Evaluation
**Inference Pipeline**
1.  **RPN Uncapping:** The Region Proposal Network will be configured to keep **2,000 post-NMS proposals** (up from the default 1,000). This ensures that on pages with ~600 characters, valid candidates are not discarded before reaching the classifier **Cite solution_lesson_node_00016**.
2.  **Detection Cap:** The maximum detections per image will be set to **1,200**, overriding the library default of 100 to match the dataset's density **Cite solution_lesson_node_00008**.
3.  **Thresholding:** The final confidence threshold will be set to **0.35**. This lower threshold prioritizes Recall, recovering borderline characters in dense clusters **Cite solution_lesson_node_00013**.
4.  **Coordinate Restoration:** We will explicitly calculate the scale factors used during the resizing step (preprocessing) and apply the inverse transformation to the predicted bounding boxes. This ensures the submitted coordinates match the original image resolution, not the resized model input **Cite solution_lesson_node_00025**.
