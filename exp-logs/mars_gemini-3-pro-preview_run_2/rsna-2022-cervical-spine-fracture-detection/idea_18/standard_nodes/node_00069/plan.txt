The previous implementation failed with a `CUDA out of memory` error because the effective batch size (Batch Size × Sequence Length) passed to the 2D backbone was too large for the GPU memory. Specifically, processing `4 * 96 = 384` high-resolution images (`384x384`) simultaneously in the EfficientNet-B4 backbone exceeded the 40GB VRAM limit (Cite `debug_lesson_1`). Additionally, passing gradient checkpointing arguments directly to the factory function is unreliable (Cite `debug_lesson_5`).

To fix this, I will:
1.  **Reduce Memory Footprint:** In `library/config.py`, reduce `batch_size` to 1 and `image_size` to `(256, 256)`. This drastically lowers the memory requirement per forward pass.
2.  **Maintain Effective Batch Size:** Increase `accum_iter` to 16 so the optimization step still sees an effective batch of 16 samples.
3.  **Enable Gradient Checkpointing Correctly:** In `library/model.py`, explicitly call `set_grad_checkpointing(True)` on the backbone instance after creation, ensuring it is applied correctly (Cite `debug_lesson_5`).
4.  **Safe Inference:** In `runfile.py`, set the inference batch size to 2 instead of 16 to prevent OOM during the prediction phase.
