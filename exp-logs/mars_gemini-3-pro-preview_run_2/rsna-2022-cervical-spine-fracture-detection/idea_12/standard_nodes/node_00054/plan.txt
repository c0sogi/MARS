The error analysis indicates that the `OutOfMemoryError` is caused by an excessive **effective batch size** (Cite debug_lesson_1). The `TimeDistributed` wrapper collapses the batch and sequence dimensions, resulting in the EfficientNet-B4 backbone attempting to process `Batch_Size (2) * Seq_Len (96) = 192` high-resolution images simultaneously. This saturates the GPU memory with intermediate activations required for backpropagation.

To resolve this, I will implement two targeted fixes in `library/model.py`:

1.  **Enable Gradient Checkpointing**: I will call `set_grad_checkpointing(True)` on the backbone. This significantly reduces memory usage by discarding intermediate activations during the forward pass and recomputing them during the backward pass, allowing the model to handle the large effective batch size (Cite debug_lesson_1, debug_lesson_5).
2.  **Freeze Batch Normalization**: Processing highly correlated slices from the same patient in a large batch causes Batch Normalization layers to calculate near-zero variance, leading to numerical instability (NaNs) during validation (Cite debug_lesson_12). I will override the `train()` method in `MultiLevelEfficientNet` to forcibly keep all `BatchNorm2d` layers in `eval` mode, ensuring they use robust pretrained statistics instead of corrupted batch statistics.
