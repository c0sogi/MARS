The `torch.OutOfMemoryError` is caused by an excessively large effective batch size ($2 \times 96 \times 384 \times 384$) overloading the GPU memory during the backbone's forward pass. Additionally, reducing the batch size to 1 to fix the memory issue introduces a risk of training instability due to correlated samples (all 96 slices from the same patient) corrupting Batch Normalization statistics.

To resolve this, I will:
1.  **Reduce Memory Usage**: In `library/config.py`, decrease `IMAGE_SIZE` to `(256, 256)` and `BATCH_SIZE` to `1`, while increasing `GRAD_ACCUMULATION_STEPS` to maintain the effective batch size (Cite Debug Lesson 1).
2.  **Enable Gradient Checkpointing**: In `library/model.py`, enable gradient checkpointing on the backbone to reduce activation memory (Cite Debug Lesson 11).
3.  **Freeze Batch Normalization**: In `library/model.py`, override the `train()` method to force BN layers into `eval()` mode, preventing statistical collapse from correlated samples in the single-patient batches (Cite Debug Lesson 12).
4.  **Reload Modules**: In `runfile.py`, explicitly reload the library modules to ensure these changes are active in the persistent environment (Cite Debug Lesson 4).
