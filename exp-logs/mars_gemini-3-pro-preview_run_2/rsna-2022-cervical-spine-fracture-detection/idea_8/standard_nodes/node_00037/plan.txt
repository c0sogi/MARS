The `torch.OutOfMemoryError` is caused by the model attempting to process an excessive number of high-resolution image slices simultaneously. The effective batch size for the 2D backbone is calculated as `Batch_Size * Sequence_Length`, which resulted in $2 \times 96 = 192$ images of $384 \times 384$ resolution, exceeding the GPU memory capacity (Cite debug_lesson_1).

To resolve this, I will:
1.  Modify `library/config.py` to reduce `BATCH_SIZE` to 1, `SEQ_LEN` to 48, and `IMAGE_SIZE` to (256, 256). I will also increase `ACCUMULATION_STEPS` to 16 to compensate for the smaller batch size.
2.  Modify `library/model.py` to enable gradient checkpointing on the backbone. This reduces memory usage by trading compute for memory during backpropagation. I will call `set_grad_checkpointing(True)` on the model instance instead of passing it to the factory function, ensuring compatibility (Cite debug_lesson_5).
