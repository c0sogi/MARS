The issue is caused by implicit type promotion in the `load_dicom_and_process` function within `library/utils.py`. When the `float32` pixel array is multiplied by `RescaleSlope` or added to `RescaleIntercept` (which `pydicom` often reads as standard Python 64-bit floats), NumPy promotes the entire array to `float64` to preserve precision. Subsequent operations like windowing and resizing maintain this `float64` type, causing the assertion failure in `runfile.py` which expects `float32`. The fix is to explicitly cast the processed image array back to `np.float32` before returning it.
