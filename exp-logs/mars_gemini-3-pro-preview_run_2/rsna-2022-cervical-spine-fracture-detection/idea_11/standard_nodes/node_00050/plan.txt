The `RuntimeError` during model loading is caused by the pipeline loading a **stale checkpoint** (`best_model.pth`) from a previous run (likely a debug run with `SEQ_LEN=32`) instead of the current run (`SEQ_LEN=96`). This happens because the current training run produced `NaN` validation losses (likely due to mixed-precision instability in the validation loop), preventing the "save best model" condition from ever triggering. Consequently, the script attempted to load the old, incompatible file, causing a shape mismatch.

To fix this, I will:
1.  **Purge Stale Artifacts (Cite debug_lesson_11):** Delete `Config.MODEL_PATH` at the start of `runfile.py` to ensure the pipeline never loads a ghost configuration.
2.  **Stabilize Validation:** Remove `autocast` (mixed precision) from the `validate` method in `library/trainer.py`. Running validation in FP32 avoids the numerical instability that led to `NaN` losses.
3.  **Ensure Model Availability:** Update `library/trainer.py` to save the final model as a fallback if no "best" model was saved (e.g., if validation metrics remain poor or `NaN`), ensuring `runfile.py` always has a valid checkpoint to load.
