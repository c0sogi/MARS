The issue is that the `load_data` function in `library/data.py` concatenates the training and validation datasets into a single dataframe, which is then used for cross-validation. This causes data leakage because the hold-out validation set (`metadata/val.csv`), which is intended for the final assessment, gets mixed into the training folds. Consequently, the models are trained on data they are later evaluated on, invalidating the final metric.

To fix this, I will:
1.  Modify `load_data` in `library/data.py` to process and return the training, validation, and test datasets separately, without concatenation. I will also ensure the scaler is fit only on the training data to prevent feature leakage.
2.  Update `library/inference.py` to handle the three return values from `load_data`.
3.  Update `runfile.py` to use the separated training data for cross-validation and the dedicated validation dataframe for the final assessment, removing the logic that attempted to filter it back out of the combined dataset.
