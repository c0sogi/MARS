Based on the lessons learned, particularly the failure of **Idea 6** due to incomplete rule sets (Cite {solution_lesson_node_00014}) and the success of **Idea 4** in classification, I propose a **Hybrid "Route-and-Refine" Architecture**. This approach bridges the gap between rigid rule-based systems and flexible generative models.

# Idea 7: Hybrid Router-Generator Network with Class-Conditional Execution

This strategy addresses the core bottleneck: while we can accurately classify tokens (Idea 4), writing deterministic rules for complex, unstructured classes like `ADDRESS`, `TELEPHONE`, or `ELECTRONIC` is brittle and error-prone. Instead of forcing a "Rules-Only" (Idea 4) or "Generative-Only" (Idea 1) approach, we dynamically route tokens to the optimal processing mechanism.

### Model
**Architecture**: The system consists of two distinct components operating in a pipeline:
1.  **The Router (Contextual Classifier)**:
    *   **Backbone**: A Transformer Encoder (e.g., `roberta-base`) acting as a sequence labeler.
    *   **Role**: It predicts the semantic `class` (e.g., `DATE`, `PLAIN`, `ADDRESS`) for each token using full sentence context. This strictly preserves the "Decouple classification from generation" principle (Cite {solution_lesson_node_00006}) to resolve ambiguities.
2.  **The Refiners (Dual-Path Normalization)**:
    *   **Path A: Deterministic Rule Engine**: For "Structured Classes" (`PLAIN`, `PUNCT`, `CARDINAL`, `ORDINAL`, `DIGIT`, `LETTERS`, `MONEY`), we utilize a registry of deterministic Python functions. These classes follow strict grammatical rules where hallucination is unacceptable, and logic is easy to implement.
    *   **Path B: Specialist Generator**: For "Unstructured/Complex Classes" (`ADDRESS`, `TELEPHONE`, `TIME`, `ELECTRONIC`, `VERBATIM`, `MEASURE`), we route the tokens to a small, character-aware Sequence-to-Sequence model (e.g., **ByT5-small**).
    *   **Why**: This avoids the "Incomplete Operator Set" failure (Cite {solution_lesson_node_00014}) by allowing a neural network to learn the messy, non-algorithmic patterns of addresses and times from the data, rather than relying on hand-coded regex.

### Data
**Preprocessing**:
1.  **Router Dataset**: We employ the **Strategic Sampling** from Idea 5. We retain 100% of sentences with non-`PLAIN` tokens and a hard-negative subset of `PLAIN` sentences (those with digits/caps). This ensures the Router focuses on the decision boundary.
2.  **Generator Dataset**: We construct a specific dataset for the Seq2Seq model containing *only* the tokens belonging to the "Unstructured/Complex Classes".
    *   **Input**: A string combining the predicted class tag and the raw token (e.g., `[TIME] 12:00`). This allows the generator to use the Router's explicit disambiguation signal.
    *   **Target**: The ground-truth `after` text.
    *   **Benefit**: This dataset will be small (a fraction of the total), allowing for rapid training of the generator despite it being a Seq2Seq model.

### Training
**Procedure**:
1.  **Stage 1: Train Router**: Fine-tune the RoBERTa model on the Router Dataset using Cross-Entropy Loss to predict the 15 semantic classes.
2.  **Stage 2: Train Generator**: Train the ByT5 model on the Generator Dataset using standard Seq2Seq loss (Teacher Forcing).
    *   *Note*: Since we use the provided ground-truth labels for the Router and ground-truth text for the Generator, we avoid the "Inverse Label Engineering" trap (Cite {solution_lesson_node_00014}) entirely. We are not deriving labels; we are simply routing based on them.

### Evaluation
**Inference**:
1.  **Classify**: Pass the test sentences through the **Router** to obtain the predicted class for every token.
2.  **Route & Execute**:
    *   **If Class $\in$ Structured Set** (e.g., `CARDINAL`): Pass the raw token to the corresponding Python function (e.g., `number_to_words`).
    *   **If Class $\in$ Unstructured Set** (e.g., `TIME`): Pass the string `[CLASS] raw_token` to the **Generator** (ByT5) and decode the result greedily.
    *   **If Class $\in$ Copy Set** (`PLAIN`, `PUNCT`): Copy the raw text directly.
3.  **Combine**: Merge the outputs into the final submission format. This ensures that 99% of the data (Plain + Numbers) is handled with the speed and safety of code, while the difficult 1% is handled by the flexible neural network.
