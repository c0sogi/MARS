# Idea 5: Transformer-CRF Sequence Labeling with Strategic Hard-Negative Sampling

This approach evolves the **Contextual Transformer Classification (Idea 4)** by introducing a **Conditional Random Field (CRF)** layer to model label dependencies and a **Strategic Sampling** mechanism to efficiently handle the class imbalance. It strictly adheres to the **Hybrid Classification-Rule Pipeline** paradigm established in **Lesson 00006**.

### Model
**Architecture**: The model is designed as a Sequence Labeler rather than a simple Token Classifier.
*   **Backbone (Context Encoder)**: A pre-trained Transformer (e.g., `roberta-base` or `bert-base-uncased`) processes the input at the sentence level. This provides deep, bidirectional contextual embeddings for every token, resolving ambiguities that simple features (Idea 2) or local windows (Idea 3) miss.
*   **Structural Innovation: CRF Layer**: Instead of using a simple Softmax classifier which predicts each token's class independently, we place a **Conditional Random Field (CRF)** layer on top of the Transformer's output.
    *   **Why**: Semiotic classes often exhibit sequential dependencies (e.g., a `MONEY` currency symbol is almost always followed by `MONEY` digits; "Jan" as `DATE` implies the following "12" is likely `DATE`). The CRF models the conditional probability of the entire label sequence, $P(\mathbf{y}|\mathbf{x})$, enforcing global consistency and correcting isolated misclassifications.
*   **Generator (Deterministic Rules)**: We strictly retain the "Decouple classification from generation" strategy. The model's output is purely a sequence of class labels (e.g., `DATE`, `CARDINAL`). These labels are passed to a registry of deterministic Python functions to generate the final text (Cite {solution_lesson_node_00006}).

### Data
**Preprocessing & Strategic Sampling**:
*   **Problem**: The dataset is 93% `PLAIN`. Random downsampling (Idea 1, 2) risks losing "hard" `PLAIN` examples (e.g., years that should be read as numbers, or "US" as a word vs "U.S." as letters).
*   **Strategy**: We implement **Hard-Negative Mining** via heuristics:
    1.  **Keep 100%** of sentences containing at least one non-`PLAIN` token.
    2.  **Filter `PLAIN` Sentences**: For sentences that are 100% `PLAIN`, we do *not* discard them randomly. We apply a set of "Ambiguity Regexes" (checking for digits, capitalization, punctuation).
        *   If a `PLAIN` sentence contains "suspicious" tokens (e.g., "Chapter 5", "The 1990s"), we **keep it** as a Hard Negative.
        *   If a `PLAIN` sentence is trivial (pure lowercase text), we downsample it aggressively (e.g., keep 1%).
*   **Alignment**: We map the Transformer's sub-word tokens to the dataset's word-level labels. If a word is split into multiple sub-words, the label is assigned to the first sub-word, and subsequent sub-words are masked (ignored) in the loss calculation.

### Training
**Procedure**:
*   **Objective**: Minimize the **Negative Log-Likelihood (NLL)** of the ground-truth label sequence according to the CRF layer. This optimizes both the emission scores (from the Transformer) and the transition scores (between classes).
*   **Optimization**: Use `AdamW` with a linear learning rate scheduler.
*   **Efficiency**: By filtering out "trivial" `PLAIN` sentences, we reduce the training volume significantly (similar to the efficiency gains in Idea 3) while focusing the model's capacity entirely on the decision boundary between "Normalizable" and "Looks-Normalizable-But-Isn't".

### Evaluation
**Inference**:
1.  **Predict**: Pass test sentences through the Transformer-CRF model. Use **Viterbi Decoding** to find the most likely sequence of class labels for the sentence.
2.  **Execute**: Iterate through the tokens and their predicted labels:
    *   If Class is `PLAIN` / `PUNCT`: Copy `before` text.
    *   If Class is `DATE`: Apply `date_to_text(token)`.
    *   If Class is `CARDINAL`: Apply `number_to_words(token)`.
    *   (And so on for all classes).
3.  **Fallback**: If a rule function fails (e.g., regex mismatch), default to a safe fallback (e.g., character-by-character spelling) to prevent crashes.
