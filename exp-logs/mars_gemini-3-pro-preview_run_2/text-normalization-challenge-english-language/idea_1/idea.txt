Based on the task requirements and the provided dataset analysis, I propose the following highly efficient baseline approach. This approach is strictly distinct from the provided examples, focusing on a generative character-level solution rather than classification-plus-rules (Models 1 & 3), heavy transformers (Model 2), retrieval (Model 4), or convolutional networks (Model 5).

### Model
**Architecture**: Character-Level Sequence-to-Sequence (Seq2Seq) with Attention.
**Design**:
*   **Encoder**: A Bidirectional LSTM (Long Short-Term Memory) network that processes the input text character-by-character. The input consists of the target token to be normalized, flanked by its immediate left and right context tokens (e.g., `prev_word [target_word] next_word`) to capture necessary grammatical cues (like distinguishing "St." as "Street" vs. "Saint").
*   **Decoder**: A Unidirectional LSTM that generates the normalized text character-by-character.
*   **Attention Mechanism**: A standard Bahdanau (additive) attention layer is applied between the decoder and encoder states. This allows the model to align specific parts of the output (e.g., "fifteen") with relevant parts of the input (e.g., "15") dynamically, which is crucial for non-sequential normalizations like dates (e.g., "2023" -> "twenty twenty-three").
*   **Why this is a baseline**: Unlike the ByT5 transformer (Model 2), this architecture has significantly fewer parameters and lower latency. Unlike Models 1 and 3, it is fully end-to-end and does not require maintaining a complex codebase of manual regex rules or Python formatting functions.

### Data
**Preprocessing**:
1.  **Tokenization**: Decompose all source and target text into characters. Create a vocabulary of unique characters found in the training set (including a special `<UNK>` token and padding).
2.  **Context Windowing**: For every token in the dataset, construct an input string that concatenates the previous token, the current token, and the next token, separated by special delimiters (e.g., `|`).
3.  **Balancing**: The dataset is heavily imbalanced (93% of tokens are `PLAIN` and do not change). To prevent the model from converging to a trivial "copy" identity function:
    *   Keep 100% of samples where `before != after`.
    *   Randomly downsample the `PLAIN` / `PUNCT` samples (where `before == after`) to make up only ~20-30% of the training data. This forces the model to learn the complex transformations (dates, numbers) while still retaining the ability to copy text when needed.

### Training
**Procedure**:
*   **Loss Function**: Standard Cross-Entropy Loss calculated on the predicted character sequence against the ground truth normalized text.
*   **Optimizer**: Adam optimizer with default parameters.
*   **Teacher Forcing**: Use Teacher Forcing (feeding the actual ground-truth previous character as input to the decoder) during training to accelerate convergence and stabilize the learning of long sequences (like writing out long numbers).
*   **Strategy**: Train for a fixed number of epochs (e.g., 3-5) or until validation loss plateaus. Given the efficiency of LSTMs, this should fit comfortably within the compute budget.

### Evaluation
**Inference**:
*   **Greedy Decoding**: For each test sample, feed the context-augmented token into the encoder. The decoder generates the output character-by-character by selecting the token with the highest probability at each step until an `<EOS>` (End of Sequence) token is produced.
*   **Post-Processing**: Detokenize the character list back into a string to form the final prediction. No complex beam search is required for this baseline, prioritizing speed.
