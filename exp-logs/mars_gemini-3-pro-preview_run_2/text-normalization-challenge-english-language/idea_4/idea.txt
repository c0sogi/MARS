# Idea 4: Contextual Transformer Classification with Deterministic Normalization

This strategy proposes a **Hybrid Deep Learning Pipeline** that treats Text Normalization primarily as a sequence labeling problem rather than a text generation problem. It directly addresses the scalability bottleneck identified in the previous k-NN approach while maintaining the high precision of rule-based formatting.

### Model
**Architecture**: The solution utilizes a **Transformer-based Token Classifier** (e.g., BERT or RoBERTa) coupled with a **Deterministic Rule Engine**.
*   **Contextual Disambiguator (The Transformer)**: Instead of using a generative Seq2Seq model (which can hallucinate numbers) or a simple k-NN (which scales poorly), we employ a pre-trained Transformer encoder. A classification head is attached to the encoder to predict the semiotic `class` (e.g., `DATE`, `CARDINAL`, `MONEY`, `PLAIN`) for each input token. This leverages the Transformer's superior attention mechanism to resolve ambiguous contexts (e.g., distinguishing "2/3" as a date vs. a fraction) efficiently.
*   **Rule-Based Normalizer (The Engine)**: We explicitly retain the strategy of decoupling classification from generation Cite {solution_lesson_node_00006}. Once the Transformer predicts the class, the raw token is passed to a specific, deterministic Python function designed for that class (e.g., a function that reliably converts "1998" to "nineteen ninety-eight" if the class is `DATE`, or "one thousand nine hundred ninety-eight" if `CARDINAL`). This ensures 100% fidelity in converting values, preventing the model from altering the underlying information.

### Data
**Preprocessing**:
1.  **Context Preservation**: Unlike the k-NN approach which treated tokens in isolation or with limited windows, we process data at the **sentence level**. This allows the Transformer to utilize the full sentence context for disambiguation.
2.  **Strategic Subsampling**: The dataset is heavily imbalanced (93% `PLAIN`). We will construct a training set that retains 100% of sentences containing at least one "non-plain" token (e.g., numbers, symbols) and downsample the purely `PLAIN` sentences to ~5-10%. This focuses the model's capacity on the difficult disambiguation tasks while maintaining enough "copy" examples to learn the `PLAIN` class.
3.  **Alignment**: We will utilize tokenizer mapping (e.g., `return_offsets_mapping` or `word_ids`) to ensure the sub-word tokens generated by the Transformer align correctly with the word-level labels provided in the dataset.

### Training
**Procedure**:
*   **Objective**: We treat this as a standard **Token Classification** (Named Entity Recognition style) task. The model is trained to minimize Cross-Entropy Loss between the predicted class logits and the ground-truth `class` labels.
*   **Optimization**: We will fine-tune the pre-trained Transformer using the AdamW optimizer with a linear learning rate decay.
*   **Scalability**: Unlike the k-NN approach which required storing millions of vectors, the Transformer's parameters are fixed. This allows us to train on a much larger portion of the dataset (millions of tokens) compared to the limited 50k samples used previously, significantly improving generalization without sacrificing inference speed.

### Evaluation
**Inference**:
1.  **Class Prediction**: Feed the test sentences into the fine-tuned Transformer to obtain the predicted `class` for every token.
2.  **Deterministic Execution**: Iterate through the tokens and their predicted classes:
    *   If the class is `PLAIN` or `PUNCT`, copy the raw text.
    *   If the class is a special entity (e.g., `MONEY`), pass the raw text to the corresponding formatting function (e.g., `normalize_money()`) to generate the `after` string.
3.  **Submission**: Concatenate the results to match the submission format.
