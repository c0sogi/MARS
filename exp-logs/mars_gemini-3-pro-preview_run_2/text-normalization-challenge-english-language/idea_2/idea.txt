Based on the provided task description and dataset analysis, here is a proposal for a highly efficient baseline approach.

### Model
**Architecture**: Feature-Based Classification with Memory-Augmented Normalization.
**Design**:
*   **Classifier (XGBoost)**: Instead of a deep neural network, this approach uses a Gradient Boosted Decision Tree (GBDT) model. Its role is strictly to predict the **semiotic class** of a token (e.g., `PLAIN`, `DATE`, `CARDINAL`, `MONEY`) based on its local context and orthography.
*   **Normalizer (Lookup Table)**: A probabilistic dictionary is constructed from the training data. This acts as a memory bank that maps a pair of `(raw_token, predicted_class)` to the most frequent `normalized_text` observed during training.
*   **Fallback Mechanism**: If a token and its predicted class are not found in the dictionary (an "out-of-vocabulary" scenario), the model defaults to a **Copy** operation (returning the raw text). This exploits the dataset statistic that 93% of tokens are `PLAIN` and do not change, and even many "changeable" tokens (like specific years or prices) repeat frequently.
*   **Why this is a baseline**: This approach is computationally cheaper than the Seq2Seq LSTM (Idea 1) and simpler than Transformers. It establishes a performance floor based on effective classification and memorization, without requiring complex text generation logic.

### Data
**Preprocessing**:
1.  **Feature Engineering**: Convert each token into a dense feature vector suitable for XGBoost.
    *   **Character N-grams**: Extract unigrams, bigrams, and trigrams of the target token (TF-IDF or count-based) to capture subword patterns (e.g., "$", "th", "19").
    *   **Orthography**: Boolean flags such as `is_digit`, `is_upper`, `is_title`, `has_punctuation`.
    *   **Context**: Include the identity (hashed) and casing features of the immediate left and right neighbor tokens to resolve ambiguities (e.g., distinguishing "St." as "Street" vs. "Saint").
2.  **Dictionary Construction**: Iterate through the entire training corpus to build a hash map.
    *   Key: `(raw_token, class)`
    *   Value: The most frequent `after` string associated with that key.
3.  **Balancing**: Downsample the `PLAIN` class in the training data (e.g., keep only 5-10% of `PLAIN` samples) to prevent the classifier from ignoring minority classes like `DATE` or `MONEY`.

### Training
**Procedure**:
*   **Algorithm**: Train the XGBoost classifier on the engineered features to predict the `class` label.
*   **Loss Function**: Multi-class Log Loss (Softmax).
*   **Optimization**: Use a validation set to perform early stopping, optimizing the number of boosting rounds and tree depth to balance speed and accuracy.
*   **Note**: The dictionary is "trained" simply by populating it with counts from the training set, requiring no gradient descent.

### Evaluation
**Inference**:
1.  **Predict Class**: For each token in the test set, generate features and predict the semiotic class using the trained XGBoost model.
2.  **Lookup**: Query the memory dictionary with the `(raw_token, predicted_class)` pair.
3.  **Output**:
    *   If the pair exists in the dictionary, output the stored normalized text.
    *   If the pair is missing (unseen token), output the original `raw_token` (Copy).
