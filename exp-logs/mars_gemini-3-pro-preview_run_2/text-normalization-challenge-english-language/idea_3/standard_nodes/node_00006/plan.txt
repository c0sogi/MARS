The strategy for this implementation is to create a fast, robust baseline using the provided k-Nearest Neighbors (k-NN) architecture. We will leverage the pre-implemented library functions for feature extraction (TF-IDF + SVD), data loading, and normalization logic.

1.  **Setup & Data Loading**: We will initialize the environment with a fixed seed and load the training features using `load_or_create_train_features`. To ensure the script completes well within the time limit, we will downsample the training data to 50,000 samples before training the k-NN index.
2.  **Model Training**: We will use `load_or_train_index` to build the k-NN classifier on the downsampled training set. This classifier predicts the semiotic class (e.g., DATE, CARDINAL) of each token.
3.  **Validation**: We will load the validation set, transform it into embedding vectors, and predict the classes. Crucially, we will then map these predicted classes to the actual normalized text strings using the `NormalizationRegistry` and compare them against the ground truth to compute the exact string-match accuracy.
4.  **Failure Analysis**: We will calculate the correlation between prediction errors and the length of the input tokens to identify if longer tokens are more prone to errors.
5.  **Submission**: Finally, we will process the test set, generate normalized strings for each token, and save the results in the required `id,after` CSV format.
