### Idea 11: 2.5D Ghost U-Net

#### Model
I propose a **2.5D Ghost U-Net** architecture. This design targets the "redundancy" in feature maps found in standard CNNs. Unlike Idea 1 (MobileNet/Inverted Residuals) or Idea 10 (ShuffleNet/Group Convolutions), this model relies on **Ghost Modules** to generate more features from fewer parameters using cheap linear operations.

*   **Ghost Module:** The fundamental building block. In a standard convolution, many feature maps are similar (redundant). The Ghost Module generates a small number of "intrinsic" feature maps using a standard convolution, and then applies a series of cheap linear operations (depthwise convolutions) to these intrinsic maps to generate "ghost" features. These are concatenated to form the full output, significantly reducing computational cost (FLOPs) and parameter count.
*   **Encoder (Backbone):** The model utilizes a **GhostNet** backbone pre-trained on ImageNet. This encoder provides a highly efficient feature extraction path that is distinct from the MobileNet or EfficientNet backbones used in other ideas.
*   **Decoder:** Crucially, unlike Idea 1 which uses a standard heavy decoder, this model employs a **Ghost Decoder**. The upsampled features are processed using Ghost Modules rather than standard convolutions. This ensures that the efficiency gains are maintained throughout the entire network, not just the encoder.
*   **Input:** The model processes **2.5D inputs** (3 channels: Slice $i-1$, Slice $i$, Slice $i+1$) to incorporate volumetric context.

#### Data
The data preparation strategy focuses on standardizing the input to maximize the stability of the lightweight Ghost modules.

1.  **2.5D Stack Generation:** For every target slice, we construct a 3-channel image consisting of the target slice flanked by its immediate superior ($i-1$) and inferior ($i+1$) neighbors. Replicate padding is used for the start and end of scans.
2.  **Min-Max Normalization:** We apply min-max normalization to each 3-channel stack, scaling pixel intensities to the range $[0, 1]$. This prevents intensity outliers from destabilizing the lightweight feature maps.
3.  **Resizing:** All input images are resized to a fixed resolution of **256x256** pixels. This resolution balances spatial detail with the receptive field requirements of the Ghost modules.
4.  **Balanced Sampling:** The training set is constructed using all positive slices (containing masks) and a random subsample (e.g., 50%) of negative slices (background) to maintain training efficiency.

#### Training
The training pipeline is designed for fast convergence and generalization.

*   **Loss Function:** We employ a composite **BCE + Dice Loss**. Binary Cross Entropy provides smooth gradient descent for pixel classification, while Dice Loss directly optimizes the overlap metric.
*   **Optimizer:** **AdamW** is used to optimize the model weights. The decoupled weight decay is particularly beneficial for GhostNet to prevent overfitting in the intrinsic feature maps.
*   **Scheduler:** A **Cosine Annealing** learning rate scheduler is implemented to gradually reduce the learning rate, allowing the model to fine-tune the linear operations in the Ghost modules.
*   **Augmentation:** Only lightweight, non-destructive augmentations are applied: Random Horizontal Flips and Vertical Flips.

#### Evaluation
The evaluation process includes specific post-processing to minimize the Hausdorff distance error.

1.  **Inference:** The model generates probability maps for every slice in the test set using the 2.5D input format.
2.  **Thresholding:** A fixed threshold (0.5) is applied to binarize the predictions.
3.  **3D Connected Component Analysis:** To optimize the **3D Hausdorff distance**, the predicted 2D masks are stacked into 3D volumes for each case. We identify 3D connected components for each class and **retain only the largest connected component**, discarding smaller floating artifacts (noise) that would otherwise severely penalize the Hausdorff metric.
4.  **Submission:** The refined masks are converted to Run-Length Encoding (RLE) for the final submission.
