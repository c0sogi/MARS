Based on the lessons learned from the previous experiments, specifically the success of 2.5D inputs and the critical failures associated with resolution downsampling and cascaded architectures, I propose **Idea 14: 2.5D High-Resolution Network (HRNet) with Physical Space Normalization**.

### Model
I propose replacing the U-Net encoder-decoder structure with a **2.5D High-Resolution Network (HRNet-W32)**.
*   **Structural Innovation:** Unlike U-Net (Idea 1, 11) or FPN (Idea 7), which downsample the input to a low-resolution bottleneck to capture semantics and then attempt to recover spatial details, HRNet maintains high-resolution representations throughout the entire forward pass. It connects multi-resolution feature streams in parallel and repeatedly exchanges information between them. This architecture is structurally optimized to prevent the "detail loss" identified in **Lesson 30**, ensuring that fine boundaries of the intestines are preserved without needing a separate "Fine" model.
*   **Single-Stage Robustness:** By using a high-capacity, high-resolution architecture, we adhere to the single-stage design philosophy to avoid the "Recall Bottleneck" observed in the Coarse-to-Fine cascade (**Cite solution_lesson_node_00031**).
*   **Input:** The model accepts **2.5D inputs** (3 channels: Slice $i-1$, Slice $i$, Slice $i+1$) to encode volumetric context directly into the channel dimension (**Cite solution_lesson_node_00030**).

### Data
The data strategy shifts from "fixed image dimensions" to "fixed physical resolution" to standardize anatomical features.
1.  **2.5D Channel Stacking:** For every slice, we construct the 3-channel input stack using the target slice and its neighbors. (**Cite solution_lesson_node_00030**).
2.  **Physical Space Resampling:** Instead of resizing all images to fixed dimensions (e.g., 256x256)—which causes variable compression of anatomical structures depending on the scan's field of view—we resample all 2.5D stacks to a **fixed physical pixel spacing** (e.g., $1.5 \text{mm} \times 1.5 \text{mm}$). This ensures that a specific organ structure (like the small bowel) always appears at a consistent scale to the network, regardless of the original scanner resolution.
3.  **Random Cropping (Training):** Since resampling results in variable image sizes, we extract **Random Crops** of a fixed size (e.g., **320x320**) from the resampled images for training. This allows the model to train on high-fidelity data without memory overflows, directly addressing the resolution bottleneck (**Cite solution_lesson_node_00030**).
4.  **Augmentation:** We apply spatial augmentations (Rotations, Flips) and Elastic Deformations to the crops to encourage shape generalization.

### Training
*   **Loss Function:** We employ a sum of **Binary Cross Entropy (BCE) and Tversky Loss**. The Tversky Loss is configured with $\beta > \alpha$ (e.g., $\alpha=0.3, \beta=0.7$) to penalize false negatives more heavily, ensuring high recall for the small and disconnected bowel segments.
*   **Optimizer:** **AdamW** is used for its efficient handling of weight decay.
*   **Scheduler:** A **Cosine Annealing** scheduler is implemented to gradually reduce the learning rate.

### Evaluation
The inference process adapts to the variable sizes produced by physical resampling.
1.  **Resampling:** The test image (2.5D stack) is resampled to the target physical spacing ($1.5 \text{mm}$).
2.  **Sliding Window Inference:** We slide a window (e.g., 320x320) with overlap across the resampled image. The model predicts probabilities for each window, which are blended (using Gaussian weighting) to reconstruct the full segmentation map.
3.  **Inverse Resampling:** The predicted mask is resampled (using Nearest Neighbor interpolation) back to the original image dimensions to match the submission format.
4.  **3D Post-Processing:** We stack the 2D predictions into a 3D volume and retain only the **Largest Connected Component** for each class to optimize the Hausdorff distance.
