The issue is that the `HRNetSegmentation` model assumes the backbone's feature maps start at stride 4 (1/4 resolution), as indicated by the hardcoded 4x upsampling at the end of the `forward` method (`scale_factor=4`). However, `timm.create_model` with `hrnet_w32` and `features_only=True` returns the stem output (stride 2) as the first feature map (index 0) by default. This causes the model to align all features to stride 2 (H/2, W/2) and then upsample by 4, resulting in an output resolution of 2H x 2W (e.g., 640x640 for a 320x320 input), triggering the assertion error.

To fix this, we need to explicitly instruct `timm` to return features corresponding to strides 4, 8, 16, and 32 by setting `out_indices=(1, 2, 3, 4)`. This skips the stride-2 stem (index 0) and aligns the feature hierarchy with the model's upsampling logic.
