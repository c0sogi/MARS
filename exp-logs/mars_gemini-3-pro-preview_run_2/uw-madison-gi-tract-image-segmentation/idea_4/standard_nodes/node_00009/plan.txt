The `InvalidSubmissionError` is caused by inconsistent spatial dimensions among the predicted masks within a single 3D volume (Case/Day). The grading system expects all slices in a volume to have the same shape to stack them into a 3D array, but the original code resized each slice individually to its specific original dimensions (`orig_dims.get(s)`). If a case has varying slice dimensions or if image loading fails for some slices (defaulting to config size), the resulting RLEs produce masks of different shapes, causing the stacking operation to fail (Cite debug_lesson_4).

To fix this, I will modify `_process_volume_inference` in `library/model.py` to enforce a single target resolution for the entire volume. I will determine the dimensions of the first successfully loaded slice and use those dimensions as the canonical shape for all predictions in that group. This ensures that the generated RLEs decode to a homogeneous set of arrays that can be successfully stacked by the evaluation system (Cite debug_lesson_2).
