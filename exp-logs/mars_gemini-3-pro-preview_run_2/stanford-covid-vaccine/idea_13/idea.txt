Based on the lessons learned from previous iterations, I propose the **Bridged Dense-Refined Hybrid Network**. This strategy synthesizes the robust feature extraction of the "Dense-Context" backbone (Idea 8) with a novel, physically-motivated "Stacking Refinement" branch. This addresses the failure of serial/staged architectures (Idea 12, 13) by preserving the full multi-scale history while explicitly modeling base-pair stacking interactions.

# Model

The architecture is a **Parallel Hybrid Network** that processes sequence context and structural physics in two coordinated branches before global aggregation.

1.  **Input Representation (Parsimonious One-Hot):**
    *   We utilize **One-Hot Encoding** for `sequence`, `structure`, and `predicted_loop_type` (Cite solution_lesson_node_00010).
    *   We strictly **exclude** static "Partner Base Identity" or "Partner Triplets" from the input. As established in **Lesson 00031** and **Lesson 00023**, dynamic gathering of learned features is superior to static injection, and high-dimensional sparse inputs degrade optimization.

2.  **Backbone (Dense Dilated TCN):**
    *   **Architecture:** A stack of **Single-Layer Dilated Residual Blocks** (Cite solution_lesson_node_00011) utilizing **Dense Connections** (concatenating outputs of all prior blocks).
    *   **Configuration:** We employ exponentially increasing dilation rates ($d=1, 2, \dots, 32$) to ensure global receptive field coverage (Cite solution_lesson_node_00002).
    *   **Capacity:** We strictly set the **Growth Rate / Channel Width** to **64** (Cite solution_lesson_node_00037) and apply **Dropout (0.1)** (Cite solution_lesson_node_00038) to ensure robust feature extraction without overfitting.
    *   **Output:** This produces a high-dimensional tensor $H_{dense}$ containing multi-scale features (Cite solution_lesson_node_00047).

3.  **Parallel Stacking Refinement Branch (The Innovation):**
    *   **Latent Pair Construction:** We compress $H_{dense}$ via a 1x1 convolution and perform the **Latent Structural Gather** (Cite solution_lesson_node_00031). For every position $i$, we gather the features of its partner $j$ and concatenate them to $i$, forming a "Pair State" representation.
    *   **Stacking Module:** Instead of passing this directly to the RNN (as in Idea 8) or resetting the whole network (as in Idea 12), we process the "Pair State" with a **Short Convolutional Block** (e.g., 2 layers, Kernel 3, Dilation 1).
    *   **Physics:** This module explicitly models **Base-Pair Stacking**. By convolving over the sequence of "Pair States", the network learns the energetic interaction between the base pair at $i$ and the base pair at $i+1$.
    *   **Output:** This produces a refined tensor $H_{stack}$ encoding physical stability.

4.  **Bridged Fusion & Global Aggregation:**
    *   **Bridge Connection:** We concatenate the original backbone output $H_{dense}$ with the refined stacking features $H_{stack}$. This adheres to **Lesson 00047**, ensuring the RNN has access to the full multi-scale history (preserved by the bridge) *augmented* by the explicit stacking physics, rather than replacing it.
    *   **BiGRU Head:** The fused representation is processed by a **Bidirectional GRU** (Cite solution_lesson_node_00003).
    *   **Constraint:** The hidden size is set to `input_dim // 2` (Cite solution_lesson_node_00004).

5.  **Output:**
    *   Linear projection to the 5 target variables.

# Data

1.  **Preprocessing & Cache Safety:**
    *   **Explicit Cache Invalidation:** We will force the data loader to use a new, unique cache key (e.g., `train_data_bridged_v1.npz`) to ensure the input features are generated correctly and not loaded from a stale cache (Cite solution_lesson_node_00032).
    *   **Feature Generation:** Generate One-Hot encodings and the **Partner Index Map** (required for the Latent Gather).
    *   **Target Parsing:** Parse stringified targets in `train.csv` to numerical arrays.

2.  **Loaders:**
    *   Yield the Parsimonious Input Tensor, Partner Index Map, and Target Tensor.

# Training

1.  **Loss Function (Masked Optimization):**
    *   Use **MCRMSE** (Mean Columnwise Root Mean Squared Error).
    *   **Strategy:** Calculate loss **only on the three scored columns** (`reactivity`, `deg_Mg_pH10`, `deg_Mg_50C`).
    *   **Rationale:** We strictly adhere to **Lesson 00016**, masking out auxiliary targets (`deg_pH10`, `deg_50C`) to prevent negative transfer and align the optimization objective directly with the competition metric.

2.  **Optimizer:**
    *   Use **AdamW** with a learning rate of 1e-3 and a `ReduceLROnPlateau` scheduler.
    *   Use **Standard Convolutions** throughout (Cite solution_lesson_node_00018).
