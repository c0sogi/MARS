Based on the comprehensive analysis of the provided lessons and the progression of previous ideas, I propose the **Positional Partner-Aware Separable Hybrid Network**. This strategy optimizes the successful "Partner-Aware" baseline by incorporating explicit spatial constraints and reducing architectural redundancy to prevent overfitting.

# Model

1.  **Input Representation (Spatially Augmented Features):**
    *   **Standard & Partner Features:** We retain the **One-Hot Encoding** for `sequence`, `structure`, and `predicted_loop_type` (Cite Lesson 00010), as well as the **Partner Base Identity** feature (Cite Lesson 00015), which explicitly injects the identity of paired bases.
    *   **Innovation (Spatial Encodings):** We introduce two new feature channels to address the physical constraints of RNA degradation:
        *   **Relative Pair Distance:** For paired bases $(i, j)$, we add a normalized scalar feature $|i - j| / L$. This explicitly informs the model about the size of the structural motif (e.g., a small hairpin vs. a long-range interaction), which correlates with stability.
        *   **Absolute Positional Encoding:** We inject sinusoidal positional encodings (similar to Transformers) to the input. RNA degradation often exhibits "end effects" (fraying at 5' and 3' ends), and explicit position information helps the translation-invariant CNN model these biases.

2.  **Backbone (Depthwise Separable Dilated TCN):**
    *   To address the risk of **Over-Parameterization** observed when widening the model (Cite Lesson 00017), we replace standard convolutions with **Depthwise Separable Convolutions** within the dilated residual blocks.
    *   **Mechanism:** Each block performs a spatial convolution (depthwise, per channel) followed by a pointwise convolution (1x1, mixing channels). This drastically reduces the parameter count (from $C^2K$ to $CK + C^2$), acting as a structural regularizer while preserving the large receptive field and resolution of the **Dilated TCN** (Cite Lesson 00002).
    *   **Configuration:** We utilize **Single-Layer Blocks** (Cite Lesson 00011) with exponentially increasing dilation rates ($d=1, 2, \dots, 32$).

3.  **Global Aggregation (Multi-Scale BiGRU):**
    *   We retain the **Multi-Scale Fusion** strategy (concatenating outputs from all dilation levels) to capture both local motifs and global context.
    *   This fused representation is passed to a **Bidirectional GRU (BiGRU)** (Cite Lesson 00003) with `hidden_size = input_dim // 2` (Cite Lesson 00004) to efficiently model the global sequence state.

# Data

1.  **Preprocessing:**
    *   **Feature Generation:**
        *   Generate One-Hot encodings for `sequence`, `structure`, and `predicted_loop_type`.
        *   Generate **Partner Features**: Identify pairs $(i, j)$ from `structure`. Assign the one-hot vector of base $j$ to position $i$.
        *   Generate **Distance Feature**: Assign $|i-j|/107$ to position $i$ if paired, else 0.
        *   Generate **Positional Encoding**: Compute sine/cosine embeddings for indices $0 \dots 106$.
    *   **Concatenation:** Combine all features into a single input tensor of shape $(107, C_{total})$.
    *   **Target Parsing:** Parse stringified targets in `train.csv` to numerical arrays.

2.  **Loaders:**
    *   Yield the spatially augmented input tensors and the 5-column target vectors.

# Training

1.  **Loss Function (Masked Optimization):**
    *   Use **MCRMSE** (Mean Columnwise Root Mean Squared Error).
    *   **Strategy:** Calculate loss **only on the three scored columns** (`reactivity`, `deg_Mg_pH10`, `deg_Mg_50C`).
    *   **Rationale:** As established in **Lesson 00016**, when using a highly capable architecture (like one with Partner Features), including auxiliary tasks (`deg_pH10`, `deg_50C`) can introduce negative transfer and degrade performance on the primary metric. We align the objective strictly with the evaluation criteria.
    *   Apply masking to score only the first 68 positions (`seq_scored`).

2.  **Optimizer:**
    *   Use **AdamW** with a learning rate of 1e-3 and a `ReduceLROnPlateau` scheduler.

# Evaluation

1.  **Inference:**
    *   Apply the full preprocessing pipeline (One-Hot + Partner + Distance + Position) to `test.csv`.
    *   Predict all 107 positions for the scored targets.
2.  **Submission:**
    *   Flatten predictions to the `id_seqpos` format, ensuring correct column mapping.
