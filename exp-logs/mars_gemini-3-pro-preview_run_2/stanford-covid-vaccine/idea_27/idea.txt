Based on the comprehensive analysis of the provided lessons and the progression of previous ideas, I propose the **Projected Latent-Interaction Dense Network**.

This strategy optimizes the state-of-the-art "Dense-Context" architecture (Idea 8) by implementing a **High-Fidelity Linear Interaction** mechanism. It resolves the "Information Bottleneck" of Idea 8 (which compressed features too aggressively to 32 channels) and the "Noise/Distortion" failures of subsequent ideas (which used raw features, non-linearities, or asymmetry) by establishing a **Symmetric, Linear, Moderate-Dimensionality** latent space. This allows the model to exchange rich structural messages without overfitting or distorting the feature manifold.

# Model

1.  **Input Representation (Partner-Aware):**
    *   **Standard Features:** We utilize **One-Hot Encoding** for `sequence`, `structure`, and `predicted_loop_type` (Cite solution_lesson_node_00010).
    *   **Explicit Partner Identity:** We **retain** the explicit injection of the **Partner Base Identity** (one-hot vector of the paired base) at the input level. As established in **Lesson 00052**, removing this input cripples the encoder's ability to form basic chemical representations, regardless of downstream complexity.

2.  **Backbone (Dense Dilated TCN):**
    *   **Architecture:** A stack of **Single-Layer Dilated Residual Blocks** (Cite solution_lesson_node_00011) utilizing **Dense Connections** (concatenating outputs of all prior blocks). This preserves the full multi-scale history required for complex interaction modeling (Cite solution_lesson_node_00047).
    *   **Configuration:** We employ exponentially increasing dilation rates ($d=1, 2, 4, 8, 16, 32$) to ensure global receptive field coverage (Cite solution_lesson_node_00002).
    *   **Capacity & Regularization:** We strictly set the **Growth Rate / Channel Width** to **64** to avoid capacity bottlenecks (Cite solution_lesson_node_00037) and apply **Dropout (0.1)** within every block to prevent overfitting (Cite solution_lesson_node_00038).
    *   **Convolution Type:** We use **Standard Convolutions** throughout (Cite solution_lesson_node_00018).
    *   **Output:** This produces a high-dimensional tensor $H_{dense}$ (approx. 384 channels).

3.  **Innovation: High-Fidelity Linear Interaction Layer:**
    *   **Linear Projection:** We project the dense history $H_{dense}$ to a **Latent Dimension of 128** using a simple **1x1 Convolution**.
        *   *Rationale:* This dimension (128) is significantly larger than Idea 8 (32), preserving more signal (addressing the bottleneck), but compressed relative to Idea 16 (384), filtering noise (Cite solution_lesson_node_00062). Crucially, it uses a **Linear** projection, avoiding the distortion caused by Non-Linear bottlenecks (Cite solution_lesson_node_00076).
    *   **Symmetric Gather:** For every position $i$, we gather the 128-dimensional latent vector of its paired partner $j$ (Cite solution_lesson_node_00031). We maintain **Symmetry** by ensuring the local and partner vectors have equal dimensionality (Cite solution_lesson_node_00073).
    *   **Null-Masking:** We explicitly apply a **Zero-Mask** to the gathered features for unpaired bases, ensuring orthogonal representation for missing links (Cite solution_lesson_node_00071).
    *   **Fusion:** We concatenate the local latent vector (128 dim) with the gathered partner vector (128 dim). We use simple **Concatenation** (Cite solution_lesson_node_00066) to avoid imposing rigid arithmetic biases (Cite solution_lesson_node_00067).

4.  **Global Aggregation (BiGRU):**
    *   The fused features (256 dim) are processed by a **Bidirectional GRU** to capture global constraints (Cite solution_lesson_node_00003).
    *   **Constraint:** Hidden size is set to `input_dim // 2` (128) to ensure the output dimension matches the input, preventing parameter bloat (Cite solution_lesson_node_00004).

5.  **Output Head:**
    *   Linear projection to the 5 target variables.

# Training

1.  **Loss Function (Masked Optimization):**
    *   Use **MCRMSE** (Mean Columnwise Root Mean Squared Error).
    *   **Strategy:** Calculate loss **only on the three scored columns** (`reactivity`, `deg_Mg_pH10`, `deg_Mg_50C`).
    *   **Rationale:** We strictly adhere to **Lesson 00016**, masking out auxiliary targets (`deg_pH10`, `deg_50C`) to prevent negative transfer and align the optimization objective directly with the competition metric.

2.  **Optimizer:**
    *   Use **AdamW** with a learning rate of 1e-3 and a `ReduceLROnPlateau` scheduler.
