Based on the comprehensive analysis of the provided lessons and the progression of previous ideas, I propose the **Stabilized Recurrent Dense-Context Network (SR-DCN)**.

This strategy synthesizes the robust, state-of-the-art "Dense-Context" backbone (proven in Idea 8) with a **Stabilized Recycling** mechanism. It directly addresses the failure of "Naive Recycling" (Lesson 00078) by implementing **Gradient Detachment** and **Auxiliary Supervision**. Furthermore, it optimizes the Latent Interaction layer to strictly adhere to the constraints of "Parsimony" (Lesson 00023), "Linearity" (Lesson 00076), and "Symmetry" (Lesson 00073).

# Model

1.  **Input Representation (Recurrent & Partner-Aware):**
    *   **Static Features:** We utilize **One-Hot Encoding** for `sequence`, `structure`, and `predicted_loop_type` (Cite solution_lesson_node_00010).
    *   **Explicit Partner Identity:** We **retain** the explicit injection of the **Partner Base Identity** (one-hot vector of the paired base). As established in **Lesson 00052**, this provides the necessary chemical context for the encoder to generate meaningful local features.
    *   **Dynamic Recycling Channels:** We augment the input with **5 additional channels** corresponding to the model's predictions for the target variables (`reactivity`, `deg_*`).
        *   In **Pass 1**, these are initialized to zero.
        *   In **Pass 2**, these contain the *detached* predictions from Pass 1.

2.  **Backbone (Dense Dilated TCN):**
    *   **Architecture:** A stack of **Single-Layer Dilated Residual Blocks** (Cite solution_lesson_node_00011) utilizing **Dense Connections** (concatenating outputs of all prior blocks). This preserves the full multi-scale history required for complex interaction modeling (Cite solution_lesson_node_00047).
    *   **Configuration:** We employ exponentially increasing dilation rates ($d=1, 2, 4, 8, 16, 32$) to ensure global receptive field coverage (Cite solution_lesson_node_00002).
    *   **Capacity & Regularization:** We strictly set the **Growth Rate / Channel Width** to **64** to avoid capacity bottlenecks (Cite solution_lesson_node_00037) and apply **Dropout (0.1)** within every block to prevent overfitting (Cite solution_lesson_node_00038).
    *   **Convolution Type:** We use **Standard Convolutions** throughout (Cite solution_lesson_node_00018).

3.  **Latent Structural Interaction (Optimized):**
    *   **Linear Projection:** We project the high-dimensional dense history (~384 channels) to a **Latent Dimension of 64** using a **Linear 1x1 Convolution**.
        *   *Rationale:* We choose 64 to match the backbone's growth rate, balancing the "High Fidelity" needs (Cite solution_lesson_node_00062) with "Parsimony" (Cite solution_lesson_node_00023), avoiding the information bottleneck of 32 dim and the noise of 128+ dim. We strictly use a **Linear** projection to avoid distorting the feature manifold (Cite solution_lesson_node_00076) and apply it to the unified history (Cite solution_lesson_node_00070).
    *   **Symmetric Gather:** For every position $i$, we gather the 64-dimensional latent vector of its paired partner $j$ (Cite solution_lesson_node_00031). We avoid gathering neighbors, as the backbone already encodes local context (Cite solution_lesson_node_00058).
    *   **Null-Masking:** We explicitly apply a **Zero-Mask** to the gathered features for unpaired bases, ensuring orthogonal representation for missing links (Cite solution_lesson_node_00071).
    *   **Fusion:** We concatenate the local latent vector (64 dim) with the gathered partner vector (64 dim). We use simple **Concatenation** (Cite solution_lesson_node_00066) to maintain symmetry (Cite solution_lesson_node_00073).

4.  **Global Aggregation (BiGRU):**
    *   The fused features (128 dim) are processed by a **Bidirectional GRU** to capture global constraints (Cite solution_lesson_node_00003).
    *   **Constraint:** Hidden size is set to `input_dim // 2` (64) to ensure the output dimension matches the input (Cite solution_lesson_node_00004).
    *   **Placement:** The fused features are fed directly to the RNN, avoiding post-fusion local layers (Cite solution_lesson_node_00077).

5.  **Output Head:**
    *   Linear projection to the 5 target variables.

# Data

1.  **Preprocessing & Cache Safety:**
    *   **Explicit Cache Invalidation:** We will force the data loader to use a new, unique cache key (e.g., `train_data_sr_dcn_v1.npz`) to ensure the input features (specifically Partner Identity) are generated correctly and not loaded from a stale cache (Cite solution_lesson_node_00032).
    *   **Feature Generation:** Generate One-Hot encodings, Partner Identity, and Partner Index Map.
    *   **Target Parsing:** Parse stringified targets in `train.csv` to numerical arrays.

2.  **Loaders:**
    *   Yield the Augmented Input Tensor, Partner Index Map, and Target Tensor. Recycling inputs are handled dynamically in the training loop.

# Training

1.  **Stabilized Recurrent Loop:**
    *   For each batch, perform a **Two-Stage Forward Pass**:
        1.  **Pass 1 (Cold Start):** Feed inputs with zeroed recycling channels. Output $\hat{Y}_1$.
        2.  **Gradient Detachment:** Create a detached copy: $R = \hat{Y}_1.detach()$. This breaks the computation graph, preventing the "noisy feedback loop" failure identified in **Lesson 00078**.
        3.  **Pass 2 (Refinement):** Feed inputs with $R$ as the recycling channels. Output $\hat{Y}_2$.

2.  **Loss Function (Masked & Multi-Stage):**
    *   **Primary Loss:** MCRMSE on $\hat{Y}_2$ (Refined Prediction), calculated **only on the three scored columns** (`reactivity`, `deg_Mg_pH10`, `deg_Mg_50C`) (Cite solution_lesson_node_00016).
    *   **Auxiliary Loss:** MCRMSE on $\hat{Y}_1$ (Initial Prediction).
    *   **Total Loss:** $L_{total} = L(\hat{Y}_2) + 0.5 \times L(\hat{Y}_1)$.
    *   **Rationale:** The auxiliary loss ensures the model learns to generate a competent "hint" in the first pass, stabilizing the input distribution for the second pass.

3.  **Optimizer:**
    *   Use **AdamW** with a learning rate of 1e-3 and a `ReduceLROnPlateau` scheduler.

# Evaluation

1.  **Inference Strategy:**
    *   Initialize recycling channels to zero.
    *   Run **Pass 1** to generate initial predictions.
    *   Run **Pass 2** using Pass 1 outputs as input.
    *   Use **Pass 2** outputs as the final submission predictions.

2.  **Metric Calculation:**
    *   Implement the **Correct Global RMSE** calculation. Accumulate SSE and counts across the entire validation set before computing the square root, avoiding the statistical bias of batch-averaging (Cite solution_lesson_node_00020).
