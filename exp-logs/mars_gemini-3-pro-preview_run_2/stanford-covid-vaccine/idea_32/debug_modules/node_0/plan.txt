The implementation strategy involves the following steps:

1.  **Setup and Imports**: Import necessary libraries and the provided modules (`Config`, `utils`, `loss`, `model`, `data`, `train`).
2.  **Unit Testing**: Implement standalone verification functions for critical components:
    *   `mcrmse_metric`: Verify calculation correctness using simple numpy arrays.
    *   `MCRMSELoss`: Verify the PyTorch loss module correctly handles scored vs. unscored columns.
    *   `NRDCN`: Verify the model architecture by running a forward pass with dummy tensors and checking output shapes.
3.  **Data Subset Creation**: Create a helper function to generate small subsets (e.g., 22 rows) of the training, validation, and test metadata CSVs. This ensures the demonstration runs quickly.
4.  **Configuration Patching**: Modify the `Config` class attributes at runtime to:
    *   Point to the newly created subset CSVs.
    *   Redirect output and cache files to a temporary working directory (`./working/demo_execution`).
    *   Reduce hyperparameters (Batch Size = 4, Epochs = 1, Workers = 0) to optimize for speed.
5.  **Pipeline Execution**: Call `train_model()`, which orchestrates data preprocessing, loading, model training, validation, and inference.
6.  **Validation**: Assert that the submission file is generated and contains the expected number of rows based on the subset size.
