The issue is a **Stale State Cache** problem where the existing cached data file (`train_demo.npz`) lacks the `'masks'` key required for the training dataset. The current implementation of `preprocess_data` permissively sets `masks` to `None` if the key is missing, which bypasses the recomputation logic but subsequently causes a `KeyError` in the consumer code (`runfile.py`) that strictly expects the mask to exist.

To fix this, I will modify `library/data.py` to enforce strict schema validation when loading cached data for training sets (`is_test=False`). Instead of using conditional retrieval (`if "masks" in data`), I will access the keys directly. This ensures that if the required keys are missing, a `KeyError` is raised within the `try` block, which is then caught by the `except` block, triggering the necessary recomputation of the data.
