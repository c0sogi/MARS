Based on the comprehensive analysis of the provided lessons and the progression of previous ideas, I propose the **Asymmetric Dense-Context Hybrid Network**.

This strategy synthesizes the state-of-the-art performance of the "Dense-Context" backbone (Idea 8) with a novel **Asymmetric Latent Fusion** mechanism. This addresses the trade-off between the information bottleneck of Idea 8 (which compressed local history too aggressively) and the noise propagation of Idea 16 (which gathered full-scale features), while strictly adhering to the data engineering and regularization constraints identified in the lessons.

### Model

1.  **Input Representation (Partner-Aware):**
    *   **Standard Features:** We utilize **One-Hot Encoding** for `sequence`, `structure`, and `predicted_loop_type` (Cite solution_lesson_node_00010).
    *   **Explicit Partner Identity:** We **retain** the explicit injection of the **Partner Base Identity** (one-hot vector of the paired base) at the input level. As established in **Lesson 00052**, removing this input cripples the encoder's ability to form basic chemical representations, correcting the flaw of Idea 14.

2.  **Backbone (Dense Dilated TCN):**
    *   **Architecture:** A stack of **Single-Layer Dilated Residual Blocks** (Cite solution_lesson_node_00011) utilizing **Dense Connections** (concatenating outputs of all prior blocks). This preserves the full multi-scale history required for complex interaction modeling (Cite solution_lesson_node_00047).
    *   **Configuration:** We employ exponentially increasing dilation rates ($d=1, 2, \dots, 32$) to ensure global receptive field coverage (Cite solution_lesson_node_00002).
    *   **Capacity & Regularization:** We strictly set the **Growth Rate / Channel Width** to **64** to avoid capacity bottlenecks (Cite solution_lesson_node_00037) and apply **Dropout (0.1)** within every block to prevent overfitting (Cite solution_lesson_node_00038).
    *   **Convolution Type:** We use **Standard Convolutions** throughout (Cite solution_lesson_node_00018).
    *   **Output:** This produces a high-dimensional tensor $H_{dense}$ (e.g., 384 channels) containing the full multi-scale history.

3.  **Innovation: Asymmetric Latent Fusion Module:**
    *   **Concept:** Previous attempts failed by either compressing the local context too much (Idea 8) or gathering too much noisy data (Idea 16). We propose a dual-stream approach that decouples **Local Fidelity** from **Structural Context**.
    *   **Stream 1 (Local Projection):** We project the full backbone output $H_{dense}$ to a moderate dimension $H_{local}$ (e.g., 128 channels) using a **Non-Linear Bottleneck** (1x1 Conv $\to$ BN $\to$ ReLU). This preserves the high-resolution local sequence history required by the RNN.
    *   **Stream 2 (Structural Message):** We project $H_{dense}$ to a compact dimension $M$ (e.g., 64 channels) using a separate bottleneck. We then perform the **Latent Gather** (Cite solution_lesson_node_00031) to retrieve the message $M_{partner}$ from the paired base. This adheres to **Lesson 00062** by compressing the non-local info to prevent noise.
    *   **Fusion:** We concatenate $[H_{local}, M_{partner}]$. This provides the aggregator with a balanced representation: rich local details + summarized structural constraints, utilizing simple concatenation (Cite solution_lesson_node_00066).

4.  **Global Aggregation (BiGRU):**
    *   The fused features are processed by a **Bidirectional GRU** to capture global constraints (Cite solution_lesson_node_00003).
    *   **Constraint:** Hidden size is strictly set to `input_dim // 2` to ensure the output dimension matches the input, preventing parameter bloat (Cite solution_lesson_node_00004).

5.  **Output Head:**
    *   Linear projection to the 5 target variables.

### Data

1.  **Preprocessing & Cache Safety:**
    *   **Explicit Cache Invalidation:** We will force the data loader to use a new, unique cache key (e.g., `train_data_asymmetric_dense_v1.npz`) to ensure the input features (specifically Partner Identity) are generated correctly and not loaded from a stale cache (Cite solution_lesson_node_00032).
    *   **Feature Generation:**
        *   Generate One-Hot encodings for Seq, Struct, Loop.
        *   **Partner Identity (Input):** Generate the one-hot vector for the paired base.
        *   **Partner Index Map (Latent):** Generate the index array for the gather operation.
    *   **Target Parsing:** Parse stringified targets in `train.csv` to numerical arrays.

2.  **Loaders:**
    *   Yield the Augmented Input Tensor, the Partner Index Map, and the Target Tensor.

### Training

1.  **Loss Function (Masked Optimization):**
    *   Use **MCRMSE** (Mean Columnwise Root Mean Squared Error).
    *   **Strategy:** Calculate loss **only on the three scored columns** (`reactivity`, `deg_Mg_pH10`, `deg_Mg_50C`).
    *   **Rationale:** We strictly adhere to **Lesson 00016**, masking out auxiliary targets (`deg_pH10`, `deg_50C`) to prevent negative transfer and align the optimization objective directly with the competition metric.

2.  **Optimizer:**
    *   Use **AdamW** with a learning rate of 1e-3 and a `ReduceLROnPlateau` scheduler.
