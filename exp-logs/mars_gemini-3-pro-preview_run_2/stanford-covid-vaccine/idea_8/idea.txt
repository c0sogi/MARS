Based on the progression of insights from the provided lessons, I propose the **Dense-Context Partner-Aware Hybrid Network**. This strategy evolves the successful "Partner-Aware" baseline (Idea 4) by replacing the simple multi-scale fusion with a **Dense Connectivity** pattern and refining the structural interaction to be context-aware yet parsimonious.

# Model

1.  **Input Representation (Partner-Augmented):**
    *   **Standard Features:** We retain **One-Hot Encoding** for `sequence`, `structure`, and `predicted_loop_type` as learnable embeddings proved inferior for small vocabularies (Cite solution_lesson_node_00010).
    *   **Partner Base Identity:** We explicitly include the **Partner Base Identity** feature (concatenating the one-hot vector of the paired base). This has been proven to "teleport" critical distal information effectively (Cite solution_lesson_node_00015).

2.  **Backbone (Dense Dilated TCN):**
    *   **Architecture:** We employ a stack of **Single-Layer Dilated Residual Blocks** (Cite solution_lesson_node_00011) with exponentially increasing dilation rates ($d=1, 2, \dots, 32$) to ensure global receptive field coverage (Cite solution_lesson_node_00002).
    *   **Structural Innovation (Dense Connectivity):** Instead of standard residual connections ($x + f(x)$) or a final concatenation of all layers (Idea 4), we implement **Dense Connections**. The input to block $k$ is the concatenation of the outputs of *all* preceding blocks $0 \dots k-1$.
    *   **Rationale:** This ensures that every layer has direct access to both local (low dilation) and global (high dilation) features, maximizing information flow and feature reuse while maintaining a compact parameter budget (Cite solution_lesson_node_00017).

3.  **Latent Structural Interaction:**
    *   **Compression:** The high-dimensional output of the Dense backbone is projected down to a lower dimension (e.g., 32 channels) using a **1x1 Convolution**.
    *   **Context Gathering:** We introduce a **Latent Partner Gather** step. For every position $i$, we gather the compressed feature vector of its paired partner $j$ and concatenate it to position $i$.
    *   **Refinement:** This allows the model to see the *latent context* of the partner (e.g., "partner is in a stable stem") rather than just its identity, providing a richer signal than the input-level feature alone. By compressing first, we adhere to the lesson of **Parsimony**, avoiding the high sparsity/dimensionality issues of "Partner Triplets" (Cite solution_lesson_node_00023).

4.  **Global Aggregation (BiGRU):**
    *   The structurally augmented features are processed by a **Bidirectional GRU (BiGRU)** to capture global sequence state (Cite solution_lesson_node_00003).
    *   **Constraint:** The hidden size is strictly set to `input_dim // 2` to ensure the output dimension matches the input, preventing overfitting (Cite solution_lesson_node_00004).

5.  **Output Head:**
    *   A final linear projection maps the BiGRU output to the 5 target variables.

# Data

1.  **Preprocessing:**
    *   **Encodings:** Generate One-Hot encodings for sequence, structure, and loop type.
    *   **Partner Mapping:** Parse the `structure` string to create:
        *   **Partner Identity:** One-hot vector of the paired base (for Input).
        *   **Partner Index Map:** Array of indices mapping position $i$ to partner $j$ (for Latent Gather).
    *   **Target Parsing:** Parse stringified targets in `train.csv` to numerical arrays.

2.  **Loaders:**
    *   Data loaders will yield the Input Tensor (One-Hot + Partner ID), the Partner Index Map, and the Target Tensor.

# Training

1.  **Loss Function (Masked Optimization):**
    *   Use **MCRMSE** (Mean Columnwise Root Mean Squared Error).
    *   **Strategy:** Calculate loss **only on the three scored columns** (`reactivity`, `deg_Mg_pH10`, `deg_Mg_50C`).
    *   **Rationale:** We strictly adhere to **Lesson 00016**, masking out the auxiliary targets (`deg_pH10`, `deg_50C`) to prevent negative transfer and align the optimization objective directly with the competition metric.

2.  **Optimizer:**
    *   Use **AdamW** with a learning rate of 1e-3 and a `ReduceLROnPlateau` scheduler.
    *   Use **Standard Convolutions** throughout, avoiding Depthwise Separable convolutions to preserve joint spatial-channel modeling (Cite solution_lesson_node_00018).

# Evaluation

1.  **Metric Calculation:**
    *   Implement the **Correct Global RMSE** calculation by accumulating the Sum of Squared Errors (SSE) and counts across all batches, computing the square root only at the end of the epoch (Cite solution_lesson_node_00020).

2.  **Inference:**
