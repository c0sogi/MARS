The issue is that the current metric calculations (`MaskedMCRMSELoss` and `GlobalRMSETracker`) compute the error over the entire sequence length (107 positions), including the zero-padded tail where no ground truth exists. According to the task description, only the first 68 positions (`seq_scored`) are valid for scoring. Including the padded regions dilutes the error metric, leading to incorrect validation scores.

To fix this, I will modify `library/utils.py` to explicitly slice the predictions and targets to the first `Config.SEQ_SCORED` positions along the sequence dimension before calculating the Mean Columnwise Root Mean Squared Error (MCRMSE). This ensures the metric reflects performance only on the valid data points.
