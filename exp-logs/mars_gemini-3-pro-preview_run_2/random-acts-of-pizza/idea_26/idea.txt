Based on the comprehensive failure analysis and the synthesis of lessons learned—specifically the trade-off between **Semantic Resolution** and **Dimensionality** (Cite solution_lesson_node_00017), the proven superiority of **Linear Probes** on properly scaled data (Cite solution_lesson_node_00005, Cite solution_lesson_node_00015), and the effectiveness of **Ensembling** (Cite solution_lesson_node_00027)—I propose the **Dual-Backbone Consensus Ensemble (DBCE)**.

This strategy structurally evolves the solution by moving from a **Single-Backbone** approach (relying solely on `MiniLM`) to a **Multi-Resolution Consensus** approach. It leverages the complementary strengths of a compact, validated backbone (`MiniLM`) and a semantically richer, larger backbone (`MPNet`) that is structurally adapted (via PCA) to fit the small-data constraints. This resolves the "Curse of Dimensionality" that caused previous MPNet attempts to fail, without discarding its superior semantic understanding.

# Model
The architecture is a **Soft-Voting Ensemble** of two distinct **Bagged Logistic Regression** pipelines, each operating on a different semantic view of the data.

1.  **Branch A: The Baseline Expert (Compact Semantics)**
    *   **Backbone:** `sentence-transformers/all-MiniLM-L6-v2` (384 dimensions).
    *   **Rationale:** We strictly retain this component as it has consistently provided the highest single-model performance (Cite solution_lesson_node_00017). It serves as the stable, low-variance anchor.
    *   **Classifier:** **Bagged Logistic Regression**.

2.  **Branch B: The Deep Expert (Projected Semantics)**
    *   **Backbone:** `sentence-transformers/all-mpnet-base-v2` (768 dimensions).
    *   **Projection:** **Principal Component Analysis (PCA)** reducing dimensions to **200**.
    *   **Rationale:** MPNet captures deeper semantic nuances than MiniLM but failed previously due to dimensionality (Cite solution_lesson_node_00017). By projecting it to a lower dimension (smaller than MiniLM) via unsupervised PCA, we extract the "principal semantic variance" while strictly controlling the feature-to-sample ratio. This avoids the noise of raw 768d vectors and the overfitting of supervised projection (PLS) (Cite solution_lesson_node_00054).
    *   **Classifier:** **Bagged Logistic Regression**.

3.  **Consensus Mechanism:**
    *   **Soft Voting:** The final prediction is the unweighted average of the probabilities from Branch A and Branch B.

# Data
1.  **Text Preprocessing (Both Branches):**
    *   Concatenate `request_title` and `request_text_edit_aware` to preserve critical context (Cite solution_lesson_node_00025).
    *   **Pre-computation:** Generate raw embeddings for both `MiniLM` and `MPNet` **outside** the cross-validation loop to ensure efficiency (Cite solution_lesson_node_00031).

2.  **Branch A Processing:**
    *   Apply **L2 Normalization** to the raw 384d `MiniLM` embeddings (Cite solution_lesson_node_00015).

3.  **Branch B Processing:**
    *   Apply **PCA (n_components=200)** to the raw 768d `MPNet` embeddings.
    *   **Crucial Step:** Apply **L2 Normalization** *after* PCA. This ensures the projected features lie on the hypersphere, strictly aligning their magnitude for the linear solver (Cite solution_lesson_node_00015).

4.  **Metadata Preprocessing (Both Branches):**
    *   Explicitly include `unix_timestamp_of_request` (Cite solution_lesson_node_00033).
    *   Apply **QuantileTransformer (output_distribution='normal')** (RankGauss) to all numerical metadata. This neutralizes outliers and aligns the distribution with the normalized embeddings (Cite solution_lesson_node_00019, Cite solution_lesson_node_00006).
    *   **Fusion:** Concatenate the processed text and metadata features (Early Fusion) (Cite solution_lesson_node_00020).

# Training
1.  **Stratified Cross-Validation:**
    *   Use 5-Fold Stratified CV.
    *   **Encapsulation:** Fit the PCA (Branch B) and QuantileTransformer (Both) **inside** the cross-validation loop to prevent statistical leakage (Cite solution_lesson_node_00047).

2.  **Hyperparameter Tuning (Per Branch):**
    *   Perform Grid Search within each fold for the Logistic Regression base learner.
    *   **Regularization `C`:** Search the **High-Regularization Regime** (e.g., `1e-4` to `10.0`). **Cap Max C at 10.0** to prevent overfitting (Cite solution_lesson_node_00012, Cite solution_lesson_node_00022).
    *   **Class Weights:** Search `['balanced', None]` (Cite solution_lesson_node_00028).
    *   **Penalty:** Strictly use **L2 (Ridge)** (Cite solution_lesson_node_00044).

3.  **Ensemble Construction:**
    *   Train a Bagged Ensemble (`n_estimators=20`) for each branch on each fold using the optimal parameters.

# Evaluation
1.  **Inference:**
    *   Generate raw embeddings for the test set using both backbones.
    *   **Branch A:** L2 Normalize -> Concatenate with RankGauss-scaled Metadata -> Predict (using 5 fold-models).
    *   **Branch B:** Project using training fold's PCA -> L2 Normalize -> Concatenate with RankGauss-scaled Metadata -> Predict (using 5 fold-models).
2.  **Prediction:**
    *   Average the probability outputs from all 10 estimators (5 folds $\times$ 2 branches). This **CV-Bagging** strategy maximizes stability and generalization (Cite solution_lesson_node_00027).
