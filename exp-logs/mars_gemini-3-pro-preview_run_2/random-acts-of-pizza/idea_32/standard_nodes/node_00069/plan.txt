The issue is a clear case of data leakage where the hold-out validation set (`val.csv`) was merged with the training set (`train.csv`) prior to the cross-validation loop. This meant that the models were trained on data they were later evaluated on in the independent validation step, resulting in an invalid and inflated performance metric.

To fix this, I will modify `library/pipeline.py` to strictly isolate the training process. The `run_cv` method will be updated to load only the training data (`train.csv`). The logic that loads and concatenates the validation data will be removed. This ensures that the models generated during cross-validation have never seen the hold-out validation samples, making the subsequent evaluation in `runfile.py` a valid out-of-sample test.
