The issue is caused by the way `DEBUG_SAMPLE_SIZE` is imported in `library/data_loader.py`. By using `from library.config import DEBUG_SAMPLE_SIZE`, the variable is bound to its initial value (`500`) at import time. When `runfile.py` subsequently modifies `config.DEBUG_SAMPLE_SIZE` to `50`, `data_loader.py` retains the stale reference to the original value, causing the data loader to sample 500 rows instead of the expected 50, which triggers the `AssertionError`.

To fix this, I will modify `library/data_loader.py` to import the `library.config` module itself rather than the specific variable. I will then access `config.DEBUG_SAMPLE_SIZE` dynamically within the functions. This ensures that the code retrieves the current runtime value of the configuration variable, reflecting the changes made by `runfile.py`. This solution applies the principle of avoiding stale references to mutable global state (Cite debug_lesson_11).
