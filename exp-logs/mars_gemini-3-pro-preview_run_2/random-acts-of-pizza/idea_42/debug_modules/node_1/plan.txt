The issue is caused by the immediate initialization of global loggers in the `library` modules (`data_loader`, `trainer`, etc.) when they are imported at the top level of `runfile.py`. These loggers open file handles in the `working/idea_42` directory. When `runfile.py` subsequently attempts to delete this directory using `shutil.rmtree`, the operation fails with `OSError: [Errno 39] Directory not empty` because the operating system (specifically on NFS) maintains locks or `.nfs` artifacts for the open files.

To fix this, I will move the import statements for the affected modules inside the `main()` function, placing them strictly *after* the directory cleanup logic. This ensures that the old directory is removed before any new log files are created or locked by the library modules.
