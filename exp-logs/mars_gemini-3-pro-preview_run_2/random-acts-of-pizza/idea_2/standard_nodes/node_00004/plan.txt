The implementation strategy follows the pipeline defined in the provided library files.

1.  **Setup & Data Loading**: We initialize the environment by setting the random seed and loading the preprocessed data (Train, Validation, Test) using `library.data_loader`. This leverages the caching mechanism to save time.
2.  **Feature Engineering**: We instantiate the `HybridFeaturePipeline`. This class handles the heavy lifting: it uses the GPU-accelerated `SentenceTransformer` to convert text fields into dense 384-dimensional embeddings and applies standard scaling to the numerical metadata.
3.  **Model Tuning**: We use the `Trainer` class to perform Stratified K-Fold Cross-Validation on the training set. This identifies the optimal inverse regularization strength (`C`) for the Logistic Regression model, balancing bias and variance.
4.  **Validation & Assessment**:
    *   Before the final full training, we explicitly train a model on the training split using the best `C` and evaluate it on the hold-out validation split.
    *   We compute and print the **Final Validation Metric (AUC)**.
    *   **Failure Analysis**: We calculate the absolute prediction errors on the validation set and compute the Pearson correlation between these errors and the numerical input features. This identifies which features (e.g., account age, karma) are most associated with model failure.
5.  **Submission**: If the validation AUC exceeds the specified threshold (0.6219...), we instruct the `Trainer` to retrain the model on the combined Train + Validation set (to maximize data utility) and generate the prediction CSV for the test set.
