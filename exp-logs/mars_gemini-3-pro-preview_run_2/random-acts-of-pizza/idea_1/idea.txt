# Baseline Approach: Random Forest with Feature Hashing

### Model
The proposed model is a **Random Forest Classifier**, an ensemble learning method that constructs a multitude of decision trees at training time. Unlike the boosting approach in Model 1 (XGBoost) or the linear approach in Model 3, Random Forest relies on **Bagging (Bootstrap Aggregating)** to reduce variance and resist overfitting. The architecture processes a hybrid input vector consisting of raw tabular metadata and text features encoded via the **Hashing Trick**. This design avoids the computational cost of SVD (Model 1) and the memory overhead of maintaining a large vocabulary for TF-IDF (Model 3), while being significantly more lightweight than Transformer-based methods (Models 2 and 5).

### Data
1.  **Text Processing (Hashing Trick):**
    *   Concatenate the `request_title` and `request_text_edit_aware` fields into a single string for each sample.
    *   Apply a **Hashing Vectorizer** to this text. This method applies a hash function to tokenized words to map them directly to indices in a fixed-size feature vector (e.g., 100 dimensions). This is stateless and requires no vocabulary storage, making it faster and more memory-efficient than TF-IDF.
2.  **Tabular Processing:**
    *   Select key numerical features such as `requester_account_age_in_days_at_request`, `requester_upvotes_minus_downvotes_at_request`, and `requester_number_of_posts_at_request`.
    *   Handle missing values using simple **Median Imputation**.
    *   Since decision trees are invariant to feature scaling, no normalization or standardization is required.
3.  **Feature Integration:**
    *   Concatenate the fixed-width hashed text vector and the imputed tabular features into a single feature matrix for training.

### Training
*   **Procedure:** Initialize the Random Forest with a moderate number of estimators (e.g., 100 trees).
*   **Criterion:** Use Gini Impurity or Entropy to measure the quality of splits.
*   **Optimization:** The training process involves recursive partitioning of the data. Unlike gradient-based methods (Models 1, 2, 3, 4), this does not require a learning rate scheduler or backpropagation. The parallel nature of Random Forest allows it to utilize multiple CPU cores efficiently during fitting.

### Evaluation
*   **Inference:** For each request in the test set, preprocess the text and tabular data using the same Hashing Vectorizer and Imputer instances fitted (or defined) during training.
*   **Prediction:** Pass the processed features through the forest. Aggregating the vote counts from all trees (calculating the mean predicted class probability) will yield the final real-valued probability score required for the ROC AUC metric.
