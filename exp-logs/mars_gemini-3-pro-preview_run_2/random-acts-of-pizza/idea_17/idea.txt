Idea 17:
# Strategy: Asymmetric Multi-View Bagged Linear Ensemble (AMBLE)

Based on the synthesis of lessons learned—specifically the proven superiority of **Early Fusion** with **Compact Dense Embeddings** (Cite solution_lesson_node_00020, Cite solution_lesson_node_00017), the failure of sparse/high-dimensional auxiliary features (Cite solution_lesson_node_00029), and the critical need for **Robust Scaling** (Cite solution_lesson_node_00019)—I propose the **Asymmetric Multi-View Bagged Linear Ensemble (AMBLE)**.

This strategy structurally evolves the solution by introducing **Asymmetric Feature Compression**. We retain the high-resolution semantic signal from the request text (384d) while introducing a new, highly compressed dense view of the **User's Subreddit History** (16d). This allows us to capture the "User Persona" (homophily signal) identified as missing in previous iterations, without triggering the curse of dimensionality or sparse noise that caused Ideas 10 and 11 to fail.

# Model
The architecture is a **Bagged Ensemble of Logistic Regression Classifiers** operating on a fused, multi-resolution feature space.

1.  **Backbone (Frozen):** `sentence-transformers/all-MiniLM-L6-v2`.
    *   **Rationale:** We strictly retain the compact 384d model. Larger models (MPNet) failed due to dimensionality (Cite solution_lesson_node_00017), and fine-tuning failed due to data scarcity (Cite solution_lesson_node_00014).
2.  **Asymmetric Views:**
    *   **Primary View (Request):** Full 384d resolution. Captures the nuance of the specific request.
    *   **Secondary View (User History):** Compressed 16d resolution via PCA. Captures broad user interests (e.g., "Gamer", "Altruist") without overwhelming the primary signal.
3.  **Classifier:** **BaggingClassifier** wrapping **Logistic Regression**.
    *   **Rationale:** We preserve the high-bias linear core (Cite solution_lesson_node_00005) and use Bagging to reduce variance (Cite solution_lesson_node_00022).

# Data
We construct three distinct feature views and fuse them via concatenation (Early Fusion):

1.  **View 1: Semantic Request Content (384 dims)**
    *   **Input:** Concatenation of `request_title` and `request_text_edit_aware` (Cite solution_lesson_node_00025).
    *   **Processing:** Encode with `all-MiniLM-L6-v2`.
    *   **Normalization:** Apply **L2 Normalization** to project onto the hypersphere (Cite solution_lesson_node_00015).

2.  **View 2: Compressed User Persona (16 dims)**
    *   **Input:** Join the list `requester_subreddits_at_request` into a single space-separated string (e.g., "AskReddit gaming pics").
    *   **Processing:** Encode with `all-MiniLM-L6-v2` to get a 384d "History Vector".
    *   **Compression:** Apply **Principal Component Analysis (PCA)** to reduce this to **16 dimensions**.
    *   **Normalization:** Apply **L2 Normalization** *after* PCA.
    *   **Rationale:** This replaces the failed sparse TF-IDF approaches (Cite solution_lesson_node_00029). 16 dimensions are sufficient to distinguish broad user clusters without adding noise.

3.  **View 3: Robust Metadata (~10 dims)**
    *   **Features:** All numerical metadata, **explicitly including** `unix_timestamp_of_request` (Cite solution_lesson_node_00033).
    *   **Scaling:** Apply **QuantileTransformer (output_distribution='normal')** (RankGauss). This neutralizes outliers and aligns the scale with the normalized embeddings (Cite solution_lesson_node_00019).
    *   **No Manual Scaling:** We rely on RankGauss and do not apply manual multipliers (Cite solution_lesson_node_00035).

# Training
1.  **Pipeline Efficiency:**
    *   Pre-compute raw SBERT embeddings for both Request and User History **outside** the CV loop (Cite solution_lesson_node_00031).
2.  **Stratified Cross-Validation:**
    *   Use 5-Fold Stratified CV.
    *   **Inside Loop Processing:** Fit the PCA (for User View) and QuantileTransformer (for Metadata) on the **training fold only** to prevent leakage.
    *   **Hyperparameter Tuning:** Perform Grid Search within each fold for:
        *   **Regularization `C`:** Search **High-Regularization Regime** (`1e-4` to `10.0`). **Cap Max C at 10.0** (Cite solution_lesson_node_00022).
        *   **Class Weights:** Search `['balanced', None]` (Cite solution_lesson_node_00028).
3.  **Ensemble Strategy:**
    *   Train a Bagged Ensemble (`n_estimators=20`) on each fold.

# Evaluation
1.  **Inference:**
    *   Generate raw embeddings for Request and User History.
    *   Apply the training fold's PCA to the User History embeddings and L2 normalize.
    *   L2 normalize the Request embeddings.
    *   Apply the training fold's QuantileTransformer to Metadata.
    *   Concatenate and pass to the fold's model.
2.  **Prediction:**
    *   **Average the probability outputs** from all 5 fold-ensembles (CV-Bagging) (Cite solution_lesson_node_00027).
