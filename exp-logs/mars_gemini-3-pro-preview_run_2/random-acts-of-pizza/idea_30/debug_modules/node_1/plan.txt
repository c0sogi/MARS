The error occurs because the default PCA component count (50) exceeds the number of training samples available during the nested cross-validation of the debug run (approximately 17 samples). This violates the mathematical constraint for standard PCA (`n_components <= n_samples`). To fix this, we must explicitly reduce `Config.AUX_PCA_COMPONENTS` in the demonstration script (`runfile.py`) to a value compatible with the small debug dataset size (e.g., 10). This aligns with the practice of exposing and adjusting statistical hyperparameters for small-scale testing (Cite debug_lesson_8).
