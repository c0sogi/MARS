The error is caused by a column name collision during the merge operation in `library/dataset.py`. Both the metadata file (`train_metadata.csv`) and the raw data file (`train.csv`) contain a `target` column. When these are merged using pandas, the default behavior creates `target_x` and `target_y` columns instead of a single `target` column, causing a `KeyError` when the code subsequently tries to access `train_merged["target"]`.

To fix this, I will modify `library/dataset.py` to drop the `target` column from the raw training dataframe (`df_train_raw`) immediately after loading it. This ensures that the `target` column from the metadata (which is the source of truth for the stratified split) is preserved without conflict during the merge.
