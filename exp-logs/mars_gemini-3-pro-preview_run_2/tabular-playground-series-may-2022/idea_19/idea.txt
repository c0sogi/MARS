Based on the comprehensive empirical analysis and the derived lessons, I propose the implementation of a **Normalized-Fusion Hybrid ResFunnel Network**.

This strategy represents a structural evolution of the "Hybrid Attention-ResFunnel" (Idea 9) and "Pre-Activation ResFunnel" (Idea 17). It synthesizes the superior sequence modeling of the **Transformer** (Cite Lesson 29) with the robust classification of the **Pre-Activation GLU Backbone** (Cite Lesson 54). The core innovation is **Normalized Fusion**: explicitly applying Batch Normalization to the flattened Transformer embeddings *before* concatenation with the continuous features. This aligns the statistics of the LayerNorm-bounded sequence representation with the Z-scored continuous signal, ensuring balanced gradient flow into the deep backbone (Cite Lesson 49, Lesson 35).

# Model

The architecture is a dual-stream network that fuses a normalized categorical representation with raw continuous signals into a deep, compressive residual backbone.

1.  **Stream 1: Categorical Sequence (Transformer)**
    *   **Input**: The `f_27` feature is decomposed into 10 distinct character tokens (Cite Lesson 1).
    *   **Embedding**: Tokens are passed through a shared embedding layer (dimension 32).
    *   **Positional Encoding**: **Learnable Positional Embeddings** are added to the token vectors to explicitly encode sequence order (Cite Lesson 30).
    *   **Encoder**: The sequence is processed by a **Standard Transformer Encoder** (2 layers, 4 heads).
        *   **Configuration**: Use standard Feed-Forward Networks and Layer Normalization. Avoid complex variants like Conformer or Gated FFNs (Cite Lesson 46, Lesson 55).
        *   **Regularization**: Apply **Low Dropout (0.1)** to preserve gradient flow in the attention mechanism (Cite Lesson 48).
    *   **Output Processing (Innovation)**: The output sequence is flattened and immediately passed through a **Batch Normalization (1D)** layer. This re-centers and scales the sequence embeddings to match the distribution characteristics of the continuous stream before fusion.

2.  **Stream 2: Continuous Preservation**
    *   **Input**: The 30 numerical features are standardized (Z-score).
    *   **Preservation**: Features are maintained in their raw, normalized form. No early projection is applied to avoid signal dilution (Cite Lesson 38).

3.  **Fusion Layer**
    *   **Concatenation**: The **Normalized Flattened Transformer Output** and the **Raw Continuous Features** are concatenated.
    *   **Projection**: The fused vector is projected to the initial backbone width (512).

4.  **Backbone: Deep Pre-Activation ResFunnel**
    *   **Structure**: The backbone is organized into 3 **Stages** with progressively decreasing widths (512 $\to$ 256 $\to$ 128) to enforce feature compression (Cite Lesson 15).
    *   **Depth**: Each stage consists of **3 stacked blocks** (9 total non-linear blocks) to leverage the depth capability enabled by residual connections (Cite Lesson 17).
    *   **Blocks**: Use **Pre-Activation Direct GLU Residual Blocks**.
        *   **Topology**: $x_{out} = x + \text{Dropout}(\text{GLU}(\text{Linear}(\text{BatchNorm}(x))))$.
        *   **Rationale**: Pre-Activation stabilizes gating (Cite Lesson 54). Direct GLU is efficient (Cite Lesson 51). Batch Normalization is strictly preferred for the backbone (Cite Lesson 49).
    *   **Regularization**: Apply **High Dropout (0.35)** within the backbone blocks to prevent memorization (Cite Lesson 16, Lesson 48).
    *   **Downsampling**: Transitions between stages use **Projected Residual Connections** to strictly preserve gradient flow (Cite Lesson 24).

5.  **Output Head**
    *   The final stage output (width 128) is passed through a **Simple Linear Layer** (128 $\to$ 1) with Sigmoid activation. No additional Dropout or BN is applied in the head (Cite Lesson 60).

# Data

1.  **Decomposition**: The string feature `f_27` is strictly split into 10 integer-encoded columns.
2.  **Normalization**: Continuous features (`f_00` - `f_30`) are Z-score normalized.
3.  **Splitting**: Use the metadata-defined stratified validation split.
4.  **Volume**: Use the full training dataset; do not subsample (Cite Lesson 58).

# Training

1.  **Optimizer**: Use **AdamW** with a high weight decay of `1e-2` (Cite Lesson 8).
2.  **Optimization Granularity**:
    *   **Batch Size**: Use a reduced batch size of **1024** to improve generalization via gradient noise (Cite Lesson 44).
    *   **Scheduler**: Use an **Aggressive Step Learning Rate Scheduler** (decay by factor 0.1 every 10 epochs). This is critical for high-precision convergence (Cite Lesson 33).
3.  **Duration**: Train for **35+ epochs**. This ensures the model fully utilizes the final, lowest learning rate stage (Cite Lesson 45).
4.  **Metric**: Monitor **Validation AUC** for checkpointing, decoupling it from the loss function (Cite Lesson 3).
