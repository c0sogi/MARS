The implementation strategy involves the following steps:

1.  **Configuration Override**: We first modify `Config.SUBMISSION_PATH` to ensure the output file is saved to `./submission/submission.csv` as required by the task, and create the necessary directory.
2.  **Training**: We execute the `run_training` function with `debug=False`. This utilizes the full dataset and the default 40 epochs defined in `Config`. This is crucial because the required validation threshold (0.9972+) is extremely high, necessitating a fully converged model rather than a quick approximation.
3.  **Validation & Metrics**: After training, we reload the best model checkpoint. We then perform a dedicated inference pass on the validation set using a GPU-optimized loop (evaluation mode, no gradients) to compute the final AUC score. This score is printed in the exact format required.
4.  **Failure Analysis**: We calculate the absolute prediction error (`|y_true - y_pred|`) for the validation set. We then compute the Pearson correlation between this error and the continuous input features to identify which variables are most associated with model failure.
5.  **Submission**: We compare the computed validation AUC against the strict threshold. If the condition is met, we call the `predict` function to generate the submission file for the test set.
