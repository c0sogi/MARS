The current implementation of the final validation step in `runfile.py` suffers from data leakage (resubstitution error). The meta-learner is trained on the validation set predictions (Round 2 OOFs) and then immediately used to predict on that same validation set to calculate the final AUC. This results in an invalid, optimistic metric because the model "sees" the labels during training.

To fix this, I will update `runfile.py` to capture the return value of `train_meta_learner` and use the Out-Of-Fold (OOF) predictions it generates via internal Cross-Validation (`meta_results["oof_preds"]`). This ensures that the validation metric is calculated on predictions made by models that did not see the corresponding labels during training, adhering to proper validation protocols (Cite debug_lesson_12, Cite debug_lesson_16).
