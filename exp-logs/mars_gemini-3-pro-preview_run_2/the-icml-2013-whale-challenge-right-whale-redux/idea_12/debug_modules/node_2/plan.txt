The `AssertionError: AUC score out of bounds!` occurs because `best_auc` remains at its initialized value of `-1.0` throughout the training loop. This happens because `roc_auc_score` returns `nan` when passed 2D arrays of shape `(N, 1)` (created by `unsqueeze(1)` in `eval_fn`) if the validation set contains only one class (which is the case in the small demo subset). When `roc_auc_score` receives 2D inputs, it defaults to multi-label classification behavior and returns `nan` for single-class labels instead of raising a `ValueError`.

To fix this, I will modify `calculate_roc_auc` in `library/utils.py` to explicitly flatten `y_true` and `y_pred` into 1D arrays using `np.ravel()`. This ensures `roc_auc_score` treats the inputs as binary classification targets. Consequently, if only one class is present, it will raise a `ValueError`, which is already correctly caught by the existing `try...except` block to return `0.5`, allowing `best_auc` to update correctly.
