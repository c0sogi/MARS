# Proposed Strategy: ConvNeXt-Tiny with GeM Pooling and High-Resolution Spectrograms

This strategy proposes a structural evolution by transitioning to a modern **ConvNeXt** architecture equipped with **Generalized Mean (GeM) Pooling**. This approach addresses the transient nature of whale calls more effectively than standard pooling and corrects the signal processing flaws identified in previous attempts.

### Model
We will adopt **ConvNeXt-Tiny** as the backbone, replacing the previous ResNet and EfficientNet architectures.
- **Backbone Architecture**: ConvNeXt modernizes the standard ResNet design with "Inverted Bottleneck" blocks, larger kernel sizes (7x7), and Layer Normalization. The larger receptive field of the 7x7 kernels is particularly advantageous for capturing the longer-range temporal dependencies of whale calls compared to the 3x3 kernels in ResNet-18.
- **Input Adaptation**: The first convolutional projection layer of the pretrained ConvNeXt (designed for 3-channel RGB images) will be modified to accept 1-channel audio spectrograms. The weights for this new kernel will be initialized by averaging the weights of the original RGB channels **Cite solution_lesson_node_00001**.
- **Pooling Layer (Structural Innovation)**: We will replace the standard Global Average Pooling (GAP) with **Generalized Mean (GeM) Pooling**. Whale calls are short, transient events within the 2-second clips. Standard GAP tends to dilute the strong signal of a call with the surrounding noise. GeM pooling (a learnable interpolation between Max and Average pooling) allows the model to focus on the high-activation "peaks" corresponding to the call, making it structurally superior for detecting short events in noisy environments.

### Data
The data pipeline focuses on generating high-fidelity time-frequency representations to avoid the resolution issues encountered in previous iterations.
- **Preprocessing**: Audio clips will be converted to **Log-Mel Spectrograms**.
- **Signal Processing Correction**: We will explicitly set the FFT window size (`n_fft`) to **1024** and the hop length to a corresponding appropriate value (e.g., 512), while generating **128 Mel bands**. This ensures that the number of unique FFT bins (513) significantly exceeds the number of Mel bands (128), providing a dense and accurate spectral representation and preventing the aliasing/sparsity issues that degraded performance in previous attempts **Cite solution_lesson_node_00008**.
- **Augmentation**: We will apply **SpecAugment** (Time and Frequency Masking) during training. This forces the model to learn distributed features robust to signal interruptions and noise, rather than memorizing specific artifacts **Cite solution_lesson_node_00003**.

### Training
The training process is optimized for stability and handling class imbalance.
- **Sampling**: A **WeightedRandomSampler** will be used to oversample the minority class (whale calls), ensuring each batch contains an approximately equal number of positive and negative samples.
- **Batch Size**: We will maximize the batch size to **128** (or the limit of GPU memory). This is critical to stabilize the variance introduced by the WeightedRandomSampler and ensures that normalization layers receive robust statistics during training **Cite solution_lesson_node_00004**.
- **Optimizer & Loss**: The model will be trained using **Binary Cross Entropy with Logits Loss** and the **AdamW** optimizer with a Cosine Annealing learning rate scheduler.

### Evaluation
- **Inference**: Test set recordings will be processed into Log-Mel Spectrograms using the exact same high-resolution parameters (`n_fft=1024`, `n_mels=128`).
- **Prediction**: The trained ConvNeXt-Tiny model will perform a forward pass. The GeM pooling layer will automatically highlight the most salient features (the call) for the final classification. The output probability will be saved to the submission file.
