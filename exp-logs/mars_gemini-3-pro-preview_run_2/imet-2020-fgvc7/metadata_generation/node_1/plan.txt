The issue is that the current implementation uses `sklearn.model_selection.train_test_split`, which performs a simple random split. In multi-label classification tasks, especially those with many rare classes (long-tail distribution), random splitting fails to ensure that all labels and label combinations are representatively distributed across the training and validation sets. To fix this, we will implement **iterative stratification** using `skmultilearn.model_selection.iterative_train_test_split`. This method iteratively attempts to balance the distribution of each label in the split. We will also update the verification step to be tolerant of minor discrepancies, acknowledging that iterative stratification is a best-effort approach for complex multi-label data.
