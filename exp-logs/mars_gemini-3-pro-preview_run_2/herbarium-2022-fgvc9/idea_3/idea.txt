Based on the analysis of the dataset and the lessons learned from previous attempts, I propose the following **Hierarchical Metric Learning Strategy**.

### Model: Hierarchical Metric Learning Network
To address the failure of frozen features in fine-grained classification (Cite solution_lesson_node_00001) and the challenge of distinguishing 15,501 visually similar species, I propose a **Hierarchical Metric Learning Network**.

*   **Backbone**: Utilize an **EfficientNet-B4** initialized with ImageNet weights. Crucially, this backbone will be **fully unfrozen** and fine-tuned to allow the model to learn the subtle, species-specific features (e.g., leaf venation, trichomes) that generic pre-trained weights cannot capture (Cite solution_lesson_node_00001).
*   **Structural Innovation (Metric Learning Head)**: Instead of a standard linear classification head for the species level, implement an **ArcFace (Additive Angular Margin)** head.
    *   Standard Cross-Entropy optimizes for separability but does not enforce intra-class compactness, which is critical when classes are extremely fine-grained.
    *   ArcFace projects the learned features onto a hypersphere and enforces an additive angular margin penalty. This explicitly maximizes the angular distance between the 15,501 species centers, creating a more discriminative latent space than standard softmax.
*   **Taxonomic Regularization**: Retain the hierarchical structure from "Idea 2" by adding two auxiliary classification heads for **Family** and **Genus**.
    *   These heads will use standard Cross-Entropy loss.
    *   They act as "phylogenetic guides," ensuring that the backbone learns features that respect the biological hierarchy (e.g., grouping all *Asteraceae* together) before distinguishing the species within them.

### Data: Taxonomy-Aware Square-Root Sampling
To handle the extreme class imbalance (3 to 50+ images per class) without causing the model to overfit on the rarest classes (a risk with pure inverse-frequency sampling).

*   **Preprocessing**: Resize images to **380x380** (EfficientNet-B4 resolution) and normalize using ImageNet statistics.
*   **Sampling Strategy**: Implement a **Square-Root Class Sampler**.
    *   The sampling probability for a class $c$ will be proportional to $\sqrt{1/N_c}$, where $N_c$ is the number of images in that class.
    *   This provides a middle ground between uniform sampling (which ignores minority classes) and inverse-frequency sampling (which over-repeats minority classes), ensuring rare species are seen frequently enough to learn but not memorized.
*   **Augmentation**: Apply **RandAugment** and **CoarseDropout** to prevent overfitting, which is critical given the extensive parameter space of the un-frozen backbone.

### Training: High-Volume Gradient Update Schedule
This strategy explicitly addresses the convergence issues observed when scaling batch sizes (Cite solution_lesson_node_00008).

*   **Loss Function**: A multi-task loss combining the metric learning loss and taxonomic classification losses:
    $$L_{total} = L_{ArcFace}(\text{Species}) + \lambda_1 L_{CE}(\text{Genus}) + \lambda_2 L_{CE}(\text{Family})$$
*   **Optimizer**: AdamW with a Cosine Annealing learning rate schedule.
*   **Update Budget**:
    *   Maximize hardware throughput by using a **Batch Size of 128 or 256** (depending on VRAM usage with B4).
    *   **Critically**, to compensate for the large batch size, the training duration will be extended to **30-40 epochs**.
    *   This ensures the model performs **>80,000 gradient updates**, which is necessary for the optimizer to converge on the long-tail distribution of 15,501 classes (Cite solution_lesson_node_00008). Shortening the training time simply to save compute will result in underfitting on rare classes.

### Evaluation
*   **Inference**: Pass test images through the backbone to obtain the feature embedding.
*   **Prediction**: Calculate the **Cosine Similarity** between the image embedding and the learned ArcFace class centers (weights of the Species head). The class with the highest similarity score is the prediction.
*   **TTA**: Perform 3-view Test Time Augmentation (center crop + horizontal flip) if the runtime budget permits, averaging the cosine similarity scores before ranking.
