The issue is a data leakage problem in `library/data.py` where the validation dataset (`validation.csv`) is merged with the training dataset (`train.csv`) before K-Fold splitting. This causes the validation data to be included in the training set for most folds, leading to an invalid and overly optimistic evaluation metric. To fix this, I will modify `get_dataloaders` in `library/data.py` to only use `train.csv` for generating the K-Fold splits. Additionally, I will modify `library/train.py` to remove the check that skips training if model checkpoints exist, ensuring that the models are retrained with the corrected, leakage-free data splits.
