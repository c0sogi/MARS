Based on the accumulated empirical evidence, I propose the **Capacity-Scaled Transformer with Multi-Sample Dropout**. This strategy synthesizes the superior linguistic understanding of pre-trained Transformers (Lesson 12) with the efficient training pipelines (Lessons 6, 7) and robust regularization techniques (Lesson 2) developed in previous experiments. It introduces **Multi-Sample Dropout** as a structural innovation to further smooth the decision boundary and minimize variance in bias metrics.

### Model
We will implement a **Multi-Task RoBERTa-Large** architecture designed for maximum capacity and generalization.

*   **Backbone:** We will upgrade the feature extractor to **RoBERTa-Large**. Lesson 4 demonstrated that **Capacity Scaling** is critical when disentangling complex confounders (identities) from targets (toxicity). The "Large" variant provides the necessary depth and width to model these distinct concepts without underfitting, while Lesson 12 proved that pre-trained Transformers outperform RNNs even on smaller data subsets.
*   **Regularization:** We will apply **Spatial Dropout** to the sequence of hidden states output by the backbone. This forces the model to learn distributed representations rather than relying on specific embedding channels (Cite solution_lesson_node_00002).
*   **Aggregation:** We will utilize **Attention Pooling** instead of the `[CLS]` token. This allows the model to dynamically weight tokens based on context, which Lesson 2 showed is superior for nuance than static pooling (Cite solution_lesson_node_00002).
*   **Structural Innovation (Multi-Sample Dropout):** We will replace the standard classification head with a **Multi-Sample Dropout** block. Instead of a single dropout mask followed by a linear layer, we will generate $M$ (e.g., 5) different dropout masks in parallel. Each masked feature vector is passed through the *same* shared weights for the Toxicity and Identity heads, and the resulting predictions are averaged. This technique effectively creates an ensemble within a single model, significantly improving generalization and reducing the variance of the bias metrics.
*   **Multi-Task Heads:** The network will output two distinct signals: a primary **Toxicity** score and auxiliary **Identity** scores (Cite solution_lesson_node_00001).

### Data
We will leverage the **Full Dataset** using the efficiency optimizations proven in previous lessons to make training the "Large" model feasible.

*   **Preprocessing:** Text will be tokenized using the RoBERTa-Large BPE tokenizer and pre-padded to a fixed length (e.g., 512) into contiguous `int32` arrays.
*   **Device-Side Trimming:** We will employ the **"Pad-then-Trim"** strategy. We load fixed-length batches to the GPU and dynamically slice them to the maximum non-padding length of that specific batch before the forward pass. This avoids CPU bottlenecks and maximizes GPU throughput (Cite solution_lesson_node_00007).

### Training
The training strategy focuses on balancing bias mitigation with primary task performance.

*   **Loss Function:** We will use a **Balanced Multi-Task Loss**. The total loss will be $L_{total} = L_{toxicity} + \lambda L_{identity}$. We will set $\lambda = 0.5$. Lesson 15 warned that if the auxiliary weight dominates the primary weight (e.g., ratio > 1.0), the model overfits to identities and degrades overall performance. A balanced weight allows the identity task to guide feature learning without hijacking the gradients (Cite solution_lesson_node_00015).
*   **Optimization:** We will use the **AdamW** optimizer with **OneCycleLR** scheduling. This schedule allows for super-convergence, enabling the heavy RoBERTa-Large model to fit the data efficiently within the runtime limits (Cite solution_lesson_node_00006).
*   **Layer-Wise Learning Rate Decay:** We will apply lower learning rates to the earlier layers of the Transformer and higher rates to the head. This preserves the pre-trained linguistic knowledge while allowing the new heads to adapt quickly (reinforcing the benefits seen in Lesson 12).

### Evaluation
*   **Inference:** The test set will be processed using the same **Device-Side Trimming** pipeline to minimize inference time.
*   **Prediction:** We will generate predictions using solely the **Toxicity Head** (averaged across the Multi-Sample Dropout masks), discarding the auxiliary Identity outputs.
