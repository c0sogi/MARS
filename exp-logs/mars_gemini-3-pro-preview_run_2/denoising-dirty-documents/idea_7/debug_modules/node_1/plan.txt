The issue stems from the `_load_and_cache_data` method in `library/dataset.py` unconditionally adding a channel dimension to loaded images using `np.expand_dims`. When loading cached `.npy` files that might already possess a channel dimension (shape `(H, W, 1)`), this operation creates a 4D array (shape `(H, W, 1, 1)`). The Albumentations library, used subsequently for transformations, strictly requires images in HW or HWC format (2D or 3D) and raises a `ValueError` when encountering 4D input.

To fix this, I will modify `library/dataset.py` to check the number of dimensions (`ndim`) of the loaded images. The channel dimension will only be added if the image is 2D (shape `(H, W)`), ensuring the data remains in the correct HWC format regardless of whether it was loaded from a flat grayscale source or a pre-processed cache.
