# Proposed Strategy: Cross-Validation Ensemble with Multi-Sample Dropout

## Model
To address the rapid overfitting and high variance observed when training high-capacity models on this small dataset, I propose a structural evolution from a single-model architecture to a **Cross-Validation Ensemble** utilizing a **Multi-Sample Dropout** mechanism.

- **Backbone**: We will retain the **DeBERTa-v3-base** architecture, as it has proven to provide superior semantic representations compared to RoBERTa and DistilRoBERTa (Cite solution_lesson_node_00009).
- **Pooling**: We will continue to use **Mean Pooling** of the last hidden state rather than the `[CLS]` token, as this aggregates signal across the entire sequence (Cite solution_lesson_node_00009).
- **Classification Head (Innovation)**: Instead of a standard single Dropout-Linear head, we will implement **Multi-Sample Dropout**. This technique duplicates the dropout layer multiple times (e.g., 5 branches) with different random masks. The outputs of these dropout layers are passed through the same shared linear layer, and the final prediction is the average of these branches. This effectively creates an internal ensemble within the network, accelerating convergence and providing stronger regularization against the overfitting tendencies noted in previous experiments (Cite solution_lesson_node_00007).

## Data
- **Preprocessing**: We will maintain the unicode un-escaping and quote removal to ensure clean text input.
- **Tokenization**: We will use the DeBERTa-v3 tokenizer with a maximum sequence length of 128.
- **Splitting Strategy (Innovation)**: Instead of a single fixed train/validation split, we will implement **Stratified K-Fold Cross-Validation** (e.g., K=5). This ensures that every sample in the training set is used for both training and validation across different folds, maximizing the utility of the limited data (~3,000 samples) and mitigating the risk of a noisy validation set guiding the model astray.

## Training
- **Pipeline**: The training loop will run $K$ times, producing $K$ distinct model checkpoints.
- **Optimization**: We will use the **AdamW** optimizer with a linear warmup and cosine decay schedule.
- **Layer-wise Learning Rate Decay (LLRD)**: To further control the "catastrophic forgetting" of pre-trained features (Cite solution_lesson_node_00005), we will apply lower learning rates to the initial layers of the transformer and higher rates to the top layers and classification head.
- **Checkpointing**: Within each fold, we will save the model weights using **`copy.deepcopy(model.state_dict())`** (Cite solution_lesson_node_00004) whenever the **Validation AUC** improves. We will explicitly ignore Validation Loss for early stopping decisions, as previous lessons demonstrated that loss often diverges while ranking performance (AUC) continues to improve (Cite solution_lesson_node_00006).

## Evaluation
- **Inference**: For the test set, we will generate predictions using **all $K$ trained models**.
- **Ensembling**: The final submission score for each test sample will be the **arithmetic mean** of the probability outputs from the $K$ models. This averaging process is crucial for reducing the variance of the predictions and smoothing out the noise inherent in fine-tuning large models on small datasets.
