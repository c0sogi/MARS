### Implementation Strategy

1.  **Configuration Override**: We will override the default `Config` parameters to create a "Fast Baseline". Specifically, we will reduce the number of epochs to 10 and enable debugging mode with a larger sample size (5000) for the training set to ensure the process completes within the 2-hour limit while still learning effectively.
2.  **Data Loading**: We will instantiate the `ContrailDataset` for both training and validation. The training set will use the subsampled (debug) mode, while the validation set will use the **full** dataset (`debug=False`) to ensure the final metric is valid. We apply the provided augmentations via `get_transforms`.
3.  **Model Training**: We will initialize the `AttentionGatedConvNeXtUNet` and train it using the `train_model` engine. We use `AdamW` optimizer, `CosineAnnealingLR` scheduler, and the `HybridBCEDiceLoss`.
4.  **Validation & Metric**: After training, we load the best checkpoint and evaluate it on the full validation set. We print the `Final Validation Metric` in the required format.
5.  **Failure Analysis**: We implement a function `analyze_failures` that iterates through the validation set, calculates sample-wise error magnitudes (1 - Dice), and computes Pearson correlations with metadata features (Hour of Day, Location, Ground Truth Area) to identify systematic errors.
6.  **Submission**: We compare the final validation metric against the threshold (0.5910660985501295). If the model performs sufficiently well, we call `run_inference` to generate the submission file using Test-Time Augmentation (TTA).
