The implementation strategy is as follows:

1.  **Configuration Override**: To adhere to the "fast baseline" requirement, I will dynamically modify the `Config` class attributes before execution. I will limit the number of training epochs to 5 and the number of training samples to 5,000. This ensures the pipeline completes well within the time limit while still learning from a representative subset of data.
2.  **Training**: I will invoke the `run_training` function from `library.train`. This handles dataset loading, model initialization (MobileNetV3 U-Net), and the training loop with BCE+Dice loss. It automatically saves the best model based on validation Dice score.
3.  **Validation & Failure Analysis**:
    *   I will load the best saved model and the validation dataset.
    *   I will run a custom inference loop on the validation set to compute the **Global Dice Coefficient** (the official metric).
    *   Simultaneously, I will record the error magnitude ($1 - \text{Dice}$) for each individual sample.
    *   I will merge these error scores with the validation metadata (timestamp, geospatial coordinates) and calculate the Pearson correlation coefficient to identify if specific conditions (e.g., time of day, location) correlate with model failure.
4.  **Submission**: I will call `generate_submission` from `library.predict` to generate masks for the test set and save them in the required Run-Length Encoding format to `submission.csv`.
