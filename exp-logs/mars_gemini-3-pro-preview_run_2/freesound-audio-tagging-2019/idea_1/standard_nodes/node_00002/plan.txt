The issue is caused by the `get_dataloaders` function loading the test dataset from a static metadata file (`metadata/test.csv`) or a cached parquet file, which reflects only the public test set available during development. In the grading environment, `sample_submission.csv` is updated to include the full test set. Because the code ignores this runtime file, the generated submission has the wrong number of rows, causing the `InvalidSubmissionError`.

To fix this, I will modify `library/dataset.py` to always load the test dataframe dynamically from `input/sample_submission.csv` at runtime, constructing the file paths on the fly. This ensures the submission matches the files expected by the grading system. I will retain the caching mechanism for the training and validation sets as they are static.
