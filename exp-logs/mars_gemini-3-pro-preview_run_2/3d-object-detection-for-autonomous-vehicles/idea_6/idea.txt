# Solution Proposal: Multi-Sweep Pillar-UNet with CenterHead

## Model
I propose a **Multi-Sweep Pillar-UNet**, a high-performance evolution of the "Pillar-Based CenterPoint" (Idea 5). This architecture introduces two structural innovations: the integration of temporal LiDAR sweeps to densify the input and the use of a U-Net backbone to resolve the spatial precision limitations of standard downsampling CNNs.

1.  **Pillar Feature Encoder (with Scatter)**:
    *   The model accepts a point cloud that combines the current frame with previous temporal sweeps (densified input).
    *   Points are discretized into a 2D grid of vertical columns ("pillars").
    *   Instead of a simple linear layer, we utilize `torch_scatter` (available in the environment) to efficiently compute permutation-invariant features (mean, max, and center-offset) for all points within a pillar. This creates a high-fidelity $(C, H, W)$ pseudo-image in the Bird's Eye View (BEV) space (Cite `solution_lesson_node_00005`).
2.  **U-Net Backbone**:
    *   Unlike the generic 2D CNN proposed in Idea 5, this solution employs a **U-Net (Encoder-Decoder)** architecture.
    *   **Encoder**: A ResNet-like top-down path downsamples the BEV feature map to extract semantic context (crucial for identifying large objects like buses).
    *   **Decoder**: A bottom-up path upsamples the features and fuses them with high-resolution maps from the encoder via skip connections. This recovers the fine-grained spatial details lost during downsampling, ensuring precise localization of small objects (pedestrians) on the BEV grid.
3.  **Center-Based Detection Head**:
    *   The head operates on the high-resolution output of the U-Net. It predicts a class-specific **Heatmap** (where peaks denote object centers) and dense **Regression Maps** for 3D attributes (z-coordinate, dimensions, rotation, and height).

## Data
The data pipeline is upgraded to leverage temporal context and correct the validation logic flaws identified in previous attempts.

1.  **Multi-Sweep Accumulation**:
    *   Using the linked list structure in `sample_data.json` (`prev` tokens), load the LiDAR point clouds from the current timestamp and the preceding $N$ sweeps (e.g., previous 2 frames).
    *   Transform the points from previous sweeps into the current **Ego-Vehicle Coordinate Frame** using the `ego_pose` and `calibrated_sensor` data. This significantly increases point density, improving detection of distant or occluded objects.
2.  **Refined Dataset Logic**:
    *   Implement the dataset class with two decoupled control flags: `enable_augmentation` and `has_targets` (Cite `solution_lesson_node_00004`).
    *   **Training**: `enable_augmentation=True`, `has_targets=True`. Applies random flipping, global rotation, and scaling to the point cloud.
    *   **Validation**: `enable_augmentation=False`, `has_targets=True`. This ensures the validation set generates valid ground truth heatmaps for loss calculation without applying random noise, enabling accurate model checkpointing.
3.  **Target Generation**:
    *   Project 3D ground truth boxes into the BEV grid.
    *   Generate Gaussian heatmaps centered at the projection point.
    *   Create regression masks for box parameters, active only at the center indices.

## Training
The training strategy optimizes for both classification (heatmap) and regression accuracy.

*   **Loss Function**:
    *   **Heatmap**: Penalty-Reduced Focal Loss. This handles the extreme class imbalance of the BEV grid (mostly background).
    *   **Regression**: L1 Loss. Applied to the predictions for box dimensions, height, and rotation (encoded as $\sin \theta, \cos \theta$), masked to only penalize errors at ground truth object centers.
*   **Optimizer**: **AdamW** with a **OneCycleLR** scheduler. This provides a rapid warmup to a high learning rate followed by a cosine decay, ensuring convergence within the 24-hour runtime limit.

## Evaluation
The evaluation pipeline converts the dense heatmap predictions into the required sparse 3D bounding box submission.

1.  **Inference**:
    *   Process the test sample (accumulated with its previous sweeps) through the network to obtain the heatmap and regression maps.
2.  **Peak Extraction**:
    *   Apply a $3 \times 3$ max-pooling operation on the heatmap to suppress non-peak noise.
    *   Select the top $K$ local maxima (peaks) whose scores exceed a confidence threshold.
3.  **Decoding & Transformation**:
    *   Extract the regression values (z, dimensions, rotation) at the peak indices.
    *   Combine these with the BEV grid coordinates $(x, y)$ of the peaks.
    *   Transform the resulting bounding boxes from the **Sensor Frame** back to the **Global World Frame** using the inverse ego-pose matrices.
4.  **Submission**: Format the global boxes into the prediction string, ensuring high-confidence boxes are listed first.
