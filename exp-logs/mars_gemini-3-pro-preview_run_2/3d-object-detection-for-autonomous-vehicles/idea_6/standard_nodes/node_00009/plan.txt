The issue is that the `PillarUNet3D` model returns a tuple `(preds, loss, stats)` when ground truth targets are present in the batch (which is true for the validation set), whereas the code in `runfile.py` assumes it always returns a dictionary. This causes a `TypeError` when `decode_predictions` attempts to access dictionary keys on the returned tuple. The fix is to explicitly check if the model output is a tuple and unpack it to extract the predictions dictionary `preds[0]` before proceeding with decoding.

```diff
runfile.py
<<<<<<< SEARCH
            # Predict
            preds = model(batch)
            decoded_batch = decode_predictions(preds, Config)
=======
            # Predict
            preds = model(batch)
            if isinstance(preds, tuple):
                preds = preds[0]
            decoded_batch = decode_predictions(preds, Config)
```
