The `ValueError` occurs because `XGBClassifier` expects class labels to be contiguous integers starting from 0 (e.g., `[0, 1, 2]`), but the debug dataset produces sparse global class IDs (e.g., `[0, 2, 9]`). This mismatch causes the internal validation in XGBoost's scikit-learn wrapper to fail.

To fix this, I will:
1.  **Update `library/model.py`**: Introduce a `LabelEncoder` to map sparse global class IDs to contiguous local IDs before training (`fit`) and map predictions back to global IDs during inference (`predict`). I will also ensure validation data in `fit` is filtered to only contain classes present in the training set to prevent encoding errors (Cite `debug_lesson_1`).
2.  **Update `library/train.py`**: Inverse-transform the raw classifier predictions (which will now be local encoded IDs) back to global IDs before calculating evaluation metrics, ensuring the accuracy score compares consistent labels.
