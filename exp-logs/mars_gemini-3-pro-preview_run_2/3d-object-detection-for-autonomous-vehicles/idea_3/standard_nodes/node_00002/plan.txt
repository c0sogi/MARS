The issue stems from the `CalibrationLookup` class failing to populate the calibration cache because it filters `sample_data` using a `channel` column (expecting "LIDAR_TOP") that relies on a mapping from `calibrated_sensor.json`. In the absence of explicit channel names in the source tables (often found in `sensor.json` which isn't loaded), the mapping fails or produces UUIDs, causing the filter to exclude all LiDAR data. Consequently, `get_calibration` returns `None`, leading to a crash. Similarly, `LidarDataset` fails to load point clouds because it strictly looks for the "LIDAR_TOP" key in `file_paths`, which likely contains UUID keys instead.

To fix this, I will update `library/dataset.py` to:
1.  Modify `CalibrationLookup._build_lookup` to identify LiDAR entries by checking if the `filename` ends with `.bin`, which is a robust, data-driven heuristic independent of channel naming metadata.
2.  Modify `LidarDataset.__getitem__` to include a fallback mechanism that searches `file_paths` values for any file ending in `.bin` if the "LIDAR_TOP" key is missing.
