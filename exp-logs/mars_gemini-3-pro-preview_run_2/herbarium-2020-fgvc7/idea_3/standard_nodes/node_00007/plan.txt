The `CUDA out of memory` error confirms that the current configuration (EfficientNet-B4, 380x380 resolution, Batch Size 32) exceeds the available GPU memory (approx. 15.77 GiB). Heavy backbones like EfficientNet-B4 generate large activation maps, causing memory usage to spike. To resolve this, I will reduce the `BATCH_SIZE` from 32 to 16. This reduction will decrease the memory required for storing activations during the forward and backward passes, allowing the model to train without exhausting VRAM. This approach follows the guidance to aggressively downscale batch sizes for heavy backbones when encountering OOM errors (Cite debug_lesson_3).
