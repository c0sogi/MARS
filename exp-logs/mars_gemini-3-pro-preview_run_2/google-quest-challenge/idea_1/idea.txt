# Proposed Baseline Approach: Dual-Stream Averaged Embedding Network (Dual-AveNet)

## Model
The proposed architecture is a lightweight, Siamese-style neural network that processes Question and Answer contexts independently to capture their distinct semantic properties before fusing them for prediction. This approach avoids the computational cost of Transformers or Recurrent networks while outperforming linear baselines by learning dense representations.

1.  **Dual-Input Streams**: The model defines two separate input pipelines: one for the **Question** (concatenating `question_title` and `question_body`) and one for the **Answer**.
2.  **Shared Embedding Layer**: Both streams utilize a shared, trainable embedding layer. This layer maps token indices to dense vectors and is initialized with pre-trained static embeddings (e.g., GloVe or FastText) to accelerate convergence.
3.  **Global Average Pooling**: Instead of complex convolution or recurrence, the model applies Global Average Pooling across the sequence dimension. This computes the "semantic centroid" of the Question and the Answer, resulting in two fixed-length vectors.
4.  **Interaction Layer**: To model the relationship between the question and the answer (critical for targets like `answer_relevance`), the model computes interaction features. It concatenates:
    *   The pooled Question vector.
    *   The pooled Answer vector.
    *   The element-wise **absolute difference** between them (measuring distance).
    *   The element-wise **product** of them (measuring alignment).
5.  **MLP Head**: The fused feature vector is fed into a simple Multi-Layer Perceptron (MLP) consisting of two dense layers with ReLU activation, Batch Normalization, and Dropout. The final output layer has 30 units with a **Sigmoid** activation to constrain predictions to the `[0,1]` range.

## Data
1.  **Text Preprocessing**:
    *   Combine `question_title` and `question_body` into a single string.
    *   Lowercase all text and perform basic cleaning (removing rare special characters).
    *   Tokenize by splitting on whitespace.
2.  **Vocabulary Building**:
    *   Construct a vocabulary from the training corpus, retaining the top $N$ (e.g., 20,000) most frequent tokens to minimize memory usage.
    *   Reserve indices for padding and unknown tokens.
3.  **Vectorization**:
    *   Convert text sequences into integer arrays based on the vocabulary.
    *   Pad or truncate sequences to a fixed length (e.g., 300 tokens) to enable efficient batch processing on the GPU.

## Training
1.  **Loss Function**: Utilize **Binary Cross Entropy (BCE)** loss. Although the targets are continuous, they are bounded in `[0,1]`. BCE is often more numerically stable and effective for probability-like regression tasks than Mean Squared Error.
2.  **Optimizer**: Employ the **Adam** optimizer with a default learning rate (e.g., 0.001).
3.  **Training Strategy**:
    *   Use a batch size of 64 or 128 to maximize GPU throughput.
    *   Implement **Early Stopping** based on validation loss to prevent overfitting.
    *   Because the model relies on simple pooling, it will train extremely quickly (likely within minutes), leaving ample time for hyperparameter tuning if needed.

## Evaluation
1.  **Inference Pipeline**: Apply the same preprocessing and vectorization steps to the test data (`test.csv`).
2.  **Prediction**: Pass the vectorized test batches through the trained model to obtain a `(num_samples, 30)` matrix of probabilities.
3.  **Formatting**: Construct the submission DataFrame by combining the `qa_id` column from the test set with the 30 predicted columns (using the header from `sample_submission.csv`) and save to CSV.
