The implementation strategy involves the following steps:

1.  **Setup and Imports**: Import necessary libraries and the provided modules from the `library` package (`utils`, `feature_pipeline`, `ensemble_manager`). Set random seeds for reproducibility.
2.  **Validation Data Loading**: Manually load the `train.csv` and `val.csv` metadata files. Unlike the final pipeline which merges them, we keep them separate to perform a strict hold-out validation.
3.  **Feature Processing**: Instantiate the `FeatureProcessor` (which handles Scaling and PCA). Fit it strictly on the training split and transform both the training and validation splits. This prevents data leakage.
4.  **Model Training**: Instantiate the `HybridEnsemble` (Logistic Regression + LDA + GPC). Train it on the processed training data.
5.  **Validation Inference**: Generate probability predictions on the validation set. Apply the required clipping (`1e-15` to `1-1e-15`) and normalization.
6.  **Metric Calculation**: Compute the Multi-class Log Loss on the validation set and print it in the specified format.
7.  **Failure Analysis**: Calculate the cross-entropy error for each validation sample. Compute the Pearson correlation between this error signal and each of the 192 input features. Report the features most strongly correlated with high error (positive correlation) and low error (negative correlation).
8.  **Conditional Submission**: Check if the validation metric is below the threshold (`0.010187299388940634`). If successful, execute the `run_pipeline` function from `library.ensemble_manager`. This function handles the full training (Train + Val), inference on Test, and saving the submission file to `./submission/submission.csv`.
