The issue is caused by the aggressive subsampling in `DEBUG_MODE` (50 samples for 99 classes), which results in many classes having only 1 sample (singletons). The `QuadraticDiscriminantAnalysis` (QDA) model requires at least 2 samples per class to estimate the covariance matrix, leading to the `ValueError: y has only 1 sample in class 9`.

To fix this, I will modify `runfile.py` to:
1.  Increase `DEBUG_SAMPLE_SIZE` from 50 to 150 to increase the probability of capturing multiple samples per class while keeping the demo fast.
2.  Update the assertion that checks the training set size.
3.  Implement a filtering step before model training that removes classes with fewer than 2 samples from `y_train` and `X_train_views`. This ensures that QDA only receives valid classes (Cite debug_lesson_2).
