### Implementation Strategy

1.  **Configuration Optimization**: We will modify the `library.config` module at runtime to speed up the demonstration. Specifically, we will reduce the number of LDA shrinkage candidates to a single value and limit the interaction components. We will keep `MAX_TRAIN_SAMPLES` as `None` to ensure all classes are present in the training set, preventing LabelEncoder errors during validation (since the dataset is small, ~700 rows, this is still very fast).
2.  **Data Loading**: We will use `library.data_factory.load_dataset` to load the training, validation, and test sets. We will verify the integrity of the loaded data (shapes, keys) using assertions.
3.  **Feature Extraction Verification**: We will explicitly check that the "morphometric" features (extracted from images via `library.features`) are correctly merged into the dataset.
4.  **Expert Lifecycle**: We will generate the library of experts using `library.model_lib.generate_expert_library`. We will then iterate through these experts, training them on the training set and generating probabilities for the validation and test sets.
5.  **Ensemble Selection**: We will use `library.ensemble_selector.GreedySelector` to find the optimal combination of experts based on the validation log loss. We will verify that the selector actually selects experts and produces valid weights.
6.  **Submission**: Finally, we will generate predictions for the test set using the optimized ensemble and save the results in the required submission format.
