The issue originates in `runfile.py` where the training dataset is aggressively subsampled to 200 instances for the demonstration. With 99 distinct classes, this random subset fails to capture enough samples for every class to support the 2-fold cross-validation used by `LogisticRegressionCV`. Consequently, during cross-validation, the validation fold contains classes that were not present in the training fold (or vice versa), causing the `log_loss` scorer to crash with a dimension mismatch (`ValueError: y_true and y_prob contain different number of classes`).

To fix this, I will remove the subsampling step in `runfile.py` and train on the full dataset. Since the dataset is relatively small (~900 samples) and the hyperparameters have already been optimized for speed (reduced iterations and grid size), training on the full set is computationally feasible for the demo and ensures that all classes are adequately represented for cross-validation (Cite debug_lesson_2).
