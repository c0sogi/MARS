The `ZeroDivisionError` is caused by the `OneCycleLR` scheduler configuration in the demo run. In `library/train.py`, `pct_start` is calculated as `Config.WARMUP_EPOCHS / Config.NUM_EPOCHS`. In `runfile.py`, `Config.NUM_EPOCHS` is set to 1, while `Config.WARMUP_EPOCHS` remains at its default value of 1. This results in `pct_start = 1.0`, meaning the learning rate increases for the entire duration of training, leaving 0 steps for the annealing phase. The scheduler's internal calculation divides by the number of annealing steps, causing the crash. I will fix this in `runfile.py` by setting `Config.WARMUP_EPOCHS` to `0.1` during the configuration override, ensuring `pct_start` is less than 1.0.
