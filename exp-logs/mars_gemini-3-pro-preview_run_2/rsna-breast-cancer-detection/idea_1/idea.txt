Based on the task description and the strict environment constraints (specifically the absence of `pydicom`), I propose the following baseline approach. This solution prioritizes robustness and efficiency, using a lightweight hybrid architecture and a custom data loading strategy to handle the specific file format challenges without standard DICOM libraries.

### Model
**Architecture:** **Hybrid EfficientNet-B0 with Metadata Fusion**
The model consists of two parallel branches that fuse information from the image and the patient's clinical data:
1.  **Image Branch:** Utilizes an **EfficientNet-B0** backbone (via the `timm` library), initialized with ImageNet weights. This specific variant is selected for its optimal balance of parameter efficiency and feature extraction capability. The network extracts a high-dimensional feature vector from the mammogram, which is reduced to a compact embedding using Global Average Pooling (GAP).
2.  **Tabular Branch:** A lightweight Multi-Layer Perceptron (MLP) processes the metadata. Categorical features (`site_id`, `laterality`, `view`, `machine_id`, `implant`) are one-hot encoded, and numerical features (`age`) are normalized.
3.  **Fusion Head:** The image embedding and tabular vector are concatenated. This combined representation passes through a final fully connected layer with a Sigmoid activation to predict the probability of cancer.

**Aggregation Strategy:**
Since the task requires one prediction per breast (`prediction_id`) but provides multiple views (images) per breast, the model predicts a probability for every individual image. The final submission score for a `prediction_id` is derived by taking the **maximum** probability across all associated images (i.e., if any view looks suspicious, the breast is flagged).

### Data
**DICOM Handling (Constraint Workaround):**
Given that `pydicom` is not installed but `opencv-python` is available, and noting that images are often JPEG 2000 compressed, I will implement a **Byte-Level Image Extractor**:
1.  **Read Raw Bytes:** Read the `.dcm` file as a binary stream.
2.  **Signature Detection:** Scan the byte stream for standard Start-Of-Image (SOI) markers for JPEG (`FF D8`) or JPEG 2000 (`00 00 00 0C 6A 50`).
3.  **Extraction & Decoding:** Extract the payload from the SOI marker to the end of the file and decode it directly from memory using `cv2.imdecode`. This bypasses the need for DICOM header parsing libraries.

**Preprocessing:**
-   **Resizing:** Images are resized to **512x512** pixels. This resolution is sufficient to capture significant masses while keeping training time low.
-   **Normalization:** Pixel intensities are scaled to the [0, 1] range.
-   **Tabular:** Missing values are imputed (mean for age, mode for others) to ensure the MLP receives complete vectors.

### Training
**Procedure:**
-   **Loss Function:** **BCEWithLogitsLoss** with a `pos_weight` parameter set to approximately 50. This explicitly handles the severe class imbalance (~2% positive cases) by penalizing false negatives more heavily.
-   **Optimizer:** **AdamW** is used for its decoupled weight decay, promoting better generalization.
-   **Scheduler:** A **OneCycleLR** scheduler is employed to warm up the learning rate and then decay it, allowing for super-convergence in a minimal number of epochs (e.g., 3-5 epochs).
-   **Validation:** The provided `val.csv` metadata (stratified by patient) is used to monitor the Probabilistic F1 (pF1) score and trigger early stopping.

### Evaluation
**Inference Pipeline:**
1.  Load the `test.csv` metadata.
2.  Iterate through each row, loading the corresponding image using the Byte-Level Extractor.
3.  Preprocess and pass through the trained model to get a cancer probability.
4.  Group results by `prediction_id` and aggregate using the `max` operation.
5.  Format the output to match `sample_submission.csv` and save.
