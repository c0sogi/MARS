The issue is that `roc_auc_score` returns `nan` (rather than raising an exception) when the target vector contains only one class, which happens during the small-scale demo execution. This `nan` value causes the model checkpoint condition (`val_auc > best_val_auc`) to evaluate to `False`, preventing the model from being saved and causing a subsequent `FileNotFoundError`. I will fix this by modifying `library/train.py` to explicitly flatten the target arrays and check if they contain at least two unique classes before calculating the AUC. If only one class is present, the AUC will default to 0.5. This addresses **Debug Lesson 1** (Guard Metric Calculations Against Single-Class Data Subsets) and ensures the fix is applied to both the training and validation functions (**Debug Lesson 2**).
