The issue is that `roc_auc_score` returns `nan` (instead of raising a `ValueError`) when the validation set contains only one class, which occurred during the demo run with a small dataset. Because `nan > -1.0` evaluates to `False`, the model checkpointing logic assumed "no improvement" and never saved the model file, causing the subsequent `FileNotFoundError`.

To fix this, I will modify `library/train.py` to explicitly flatten the target and prediction arrays and check for the presence of at least two unique classes before calculating AUC. If only one class is present, it will default to 0.5. This ensures a valid numeric metric is always returned, allowing the training loop to save the model. Cite debug_lesson_1.
