The issue is that the small validation set used in the demo run contains only a single class, causing `roc_auc_score` to return `nan` (undefined) instead of raising a `ValueError`. Because `nan > 0.0` is false, the model checkpoint is never saved. The inference step then attempts to load a stale `best_model.pth` from a previous run, leading to a `RuntimeError` due to mismatched model architectures.

To fix this, I will modify `train_one_epoch` and `validate` in `library/model.py` to explicitly check if the targets contain at least two unique classes before calculating AUC (Cite debug_lesson_1). I will also flatten the targets and predictions to ensure they are treated as 1D arrays, preventing potential multi-label interpretation issues.
