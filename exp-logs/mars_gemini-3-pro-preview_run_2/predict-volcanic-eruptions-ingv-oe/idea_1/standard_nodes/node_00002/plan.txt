To optimize the model's performance, I will implement **target scaling**. The previous failure analysis showed that the model predicted a constant value close to zero because the target variable (`time_to_eruption`) has a magnitude of ~2.27e7, while the network weights are initialized near zero. Following **Lesson solution_lesson_node_00001**, I will standardize the targets (subtract mean, divide by std) during training and inverse-transform the predictions during inference.

Here is the implementation strategy:
1.  **Update `library/config.py`**: Define file paths for saving/loading the target scaler statistics (`target_mean.npy`, `target_std.npy`).
2.  **Modify `library/data_loader.py`**: Calculate the mean and standard deviation of the training targets. Scale both training and validation targets using these statistics before creating DataLoaders. Save the statistics to disk.
3.  **Modify `library/inference.py`**: Load the saved target statistics and apply the inverse transformation to the model's predictions to restore the original scale.
4.  **Modify `library/runfile.py`**:
    *   Inverse-transform the validation predictions and targets before calculating the final MAE to ensure the metric is reported in the correct unit (time to eruption).
    *   Add the conditional logic to only generate the submission file if the validation MAE improves upon the baseline (22,692,780.0).

I will also slightly increase the `BATCH_SIZE` to 64 to improve training stability and speed.
