Based on the dataset analysis and the provided model architectures, I propose a **Feature-Based Deep Regression Network (MLP)**. This approach synthesizes the robust *feature engineering philosophy* of Model 1 with the *gradient-based learning components* (Dense layers) found in Models 3, 4, and 5. It offers a highly efficient, deterministic baseline that is distinct from the tree-based and raw-signal deep learning approaches previously suggested.

### Model
The architecture is a **Multi-Layer Perceptron (MLP)** designed to map a compact vector of statistical summaries to the time to eruption.
*   **Input Layer**: A flat vector representing aggregated statistics for all 10 sensors.
*   **Hidden Layers**: A sequence of fully connected (Dense) layers (e.g., sizes 256, 128, 64). Each dense layer is followed by **Batch Normalization** to stabilize learning, a **ReLU** activation function for non-linearity, and **Dropout** to prevent overfitting on the relatively small dataset (approx. 4,000 samples).
*   **Output Layer**: A single linear neuron that predicts the scalar `time_to_eruption`.

### Data
The data processing pipeline focuses on reducing the high-dimensional raw signals (60,001 time steps) into a rich, low-dimensional feature set.
1.  **Feature Extraction**: For each segment (file), iterate through all 10 sensor channels and compute the following statistics:
    *   **Central Tendency & Dispersion**: Mean, Standard Deviation (highly correlated with target per EDA), Min, Max.
    *   **Distribution Shape**: Skewness, Kurtosis.
    *   **Quantiles**: 5th, 25th, 50th (Median), 75th, and 95th percentiles to capture signal range nuances.
    *   **Metadata Features**: Explicitly count the number of `NaN` values per sensor, as the EDA demonstrated a correlation (0.17) between missing data counts and the target.
2.  **Imputation**: During feature calculation, standard statistics (mean, std, etc.) will be computed by ignoring `NaN` values.
3.  **Normalization**: Apply **Standard Scaling** (Z-score normalization) to the resulting feature matrix. This is critical for the MLP to converge efficiently. The scaler will be fit on the training set and applied to both validation and test sets.

### Training
*   **Loss Function**: Use **Mean Absolute Error (MAE)** (L1 Loss) directly, as this matches the competition metric and is robust to outliers in the target variable.
*   **Optimizer**: Use **Adam** or **AdamW** with a standard learning rate (e.g., 1e-3) and weight decay for regularization.
*   **Procedure**: Train for a fixed number of epochs (e.g., 50-100) with **Early Stopping** based on validation MAE. Use a batch size of 32 or 64.
*   **Scheduler**: Implement a learning rate scheduler (e.g., `ReduceLROnPlateau`) to lower the learning rate when validation loss stagnates.

### Evaluation
1.  **Inference**: Load the test set metadata and iterate through the test files.
2.  **Processing**: Apply the exact same feature extraction pipeline used for training.
3.  **Prediction**: Normalize the test features using the scaler fitted on the training data and pass them through the trained MLP.
4.  **Submission**: Collect the `segment_id` and predicted `time_to_eruption` into the required CSV format.
