The previous solution used low-resolution spectrograms (64 bins) and simple log-scaling, which limited the CNN's ability to resolve fine seismic textures. Additionally, it treated missing data (NaNs) implicitly via zero-filling, losing valuable information about sensor reliability.

My strategy involves:
1.  **Increasing Spectral Resolution**: Updating `config.py` to increase `N_MELS` from 64 to 128. This provides the ResNet backbone with higher-fidelity "images" of the seismic signals.
2.  **Improving Signal Scaling**: Modifying `feature_engineering.py` to replace the raw log transform with `AmplitudeToDB` (Decibel scaling). This standardizes the dynamic range (e.g., top 80dB), making the model more robust to varying noise floors (Cite `solution_lesson_node_00013`).
3.  **Explicit NaN Features**: Updating `feature_engineering.py` to calculate and include `nan_count` per sensor as a statistical feature before zero-filling. This allows the MLP branch to learn directly from the quality of the sensor stream (Cite `solution_lesson_node_00013`).
4.  **Updating Execution**: Changing the working directory to ensure fresh feature computation and updating the submission threshold in `runfile.py`.
