# Model
I propose a **Dual-Backbone Gradient Boosting Ensemble** utilizing **Stratified K-Fold Cross-Validation**.
*   **Architecture:** The solution will consist of two distinct gradient boosting implementations: **LightGBM** and **XGBoost**. While both are tree-based, they utilize different split-finding algorithms and regularization schemes, providing necessary algorithmic diversity to capture different signal patterns.
*   **Ensemble Strategy:** Instead of a complex stacking layer that requires a separate meta-training set, I will use a **Weighted Blending** approach. The final prediction will be a linear combination of the probability vectors from both models, with weights optimized on the Out-Of-Fold (OOF) predictions.

# Data
*   **Full Dataset Utilization:** We will utilize the **entire training dataset (~2.8M rows)** for training. We will strictly avoid downsampling, as previous experiments demonstrated that data volume is the primary driver of performance and reducing it for architectural complexity leads to regression (Cite Lesson 00004).
*   **Targeted Feature Engineering:** We will generate **Interaction Features** specifically targeting the "weak sub-domains" identified in prior failure analysis. We will create multiplicative interactions between the binary `Wilderness_Area` columns and key continuous features (e.g., `Elevation`, `Horizontal_Distance_To_Hydrology`). This forces the trees to explicitly model the conditional distributions within these specific geographic areas, addressing the high error correlation found in these regions (Cite Lesson 00001).
*   **Preprocessing:** We will treat all features, including the integer-encoded binary columns, as **numerical**. We will explicitly pass an empty list for categorical features to the LightGBM constructor to prevent suboptimal default binning behavior (Cite Lesson 00011).

# Training
*   **Stratified K-Fold Cross-Validation (K=5):** Instead of a single train/validation split, we will train both the LightGBM and XGBoost models on 5 stratified folds. This ensures that every data point is used for both training and validation (via OOF predictions), reducing variance and maximizing signal extraction.
*   **GPU Acceleration:** We will leverage the available NVIDIA A100 GPU for both libraries (using `device='cuda'` for LightGBM and `tree_method='gpu_hist'` for XGBoost) to ensure that training on the full 2.8M row dataset completes well within the time limit.
*   **Optimization:** Both models will minimize **Multi-class Logarithmic Loss**. We will use early stopping based on the validation fold's log-loss to prevent overfitting.

# Evaluation
*   **Inference:** For the test set, predictions will be generated by averaging the probabilities from all 10 trained models (5 folds $\times$ 2 architectures).
*   **Champion-Challenger Gate:** Before generating the submission file, the system will compare the aggregate OOF accuracy of this new ensemble against the hardcoded accuracy of the previous best solution. The submission will only be generated if the new approach demonstrates a quantifiable improvement, safeguarding against regression due to variance (Cite Lesson 00002).
