The issue is caused by the default security setting `weights_only=True` in `torch.load` (introduced in newer PyTorch versions like 2.6), which prevents the unpickling of NumPy scalars (specifically `best_map` in the checkpoint dictionary). The execution traceback confirms this `UnpicklingError` occurs during inference when loading the model. To fix this, we need to explicitly set `weights_only=False` in the `torch.load` calls, as the checkpoints are locally generated and trusted. I will apply this fix to `library/inference.py` where the error occurred, and proactively to `library/train.py` to prevent the same error during multi-stage training.
