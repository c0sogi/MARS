Based on the accumulated lessons and the available computational budget, I propose a **Dual-Backbone Ensemble Strategy**. The previous best solution utilized a single EfficientNet-B4 model which converged in just ~15 minutes (Cite solution_lesson_node_00035), leaving a massive surplus of compute time within the 24-hour limit. We will leverage this by training two distinct high-capacity architectures and ensembling their predictions to improve robustness, while integrating Test-Time Augmentation (TTA) to further refine the retrieval quality.

# Model
**Architecture: Dual-Backbone Ensemble**
Instead of relying on a single feature extractor, we will train two separate metric learning models and ensemble their similarity scores.
1.  **Model A (Baseline):** **EfficientNet-B4**. We retain this backbone as it has proven effective when trained with gradient checkpointing (Cite solution_lesson_node_00035).
2.  **Model B (Structural Innovation):** **EfficientNet-V2-M**. We introduce the V2 architecture (via `timm`) as the second component. EfficientNet-V2 utilizes Fused-MBConv layers and a modified scaling strategy, providing a structurally diverse feature representation compared to the standard MBConv layers in B4. This diversity is critical for effective ensembling.

**Components for Both Models:**
*   **Pooling:** **Generalized Mean (GeM) Pooling**. We will replace the default pooling layers in both backbones with GeM to focus on fine-grained salient features (e.g., scars) while suppressing background noise (Cite solution_lesson_node_00020).
*   **Head:** **ArcFace (Additive Angular Margin Loss)**. Both models will project features into a 512-d embedding space optimized with ArcFace, which is superior to pairwise losses for high-cardinality datasets (Cite solution_lesson_node_00008).

# Data
**Preprocessing & Curation**
*   **Progressive Resolution:** We will employ the **Progressive Resizing** strategy for both models. Training will commence with **256x256** images to learn structural features rapidly, followed by a fine-tuning phase at **384x384** to resolve minute details (Cite solution_lesson_node_00035).
*   **Filtering:** The training set will strictly **exclude** the `new_whale` class. We will train only on verified identities to prevent embedding collapse (Cite solution_lesson_node_00005).
*   **Caching:** We will use unique, parameterized cache filenames for each model and resolution (e.g., `cache_b4_384.npy`, `cache_v2m_384.npy`) to prevent data collisions (Cite solution_lesson_node_00001).

# Training
**Procedure & Strategy**
*   **Gradient Checkpointing:** We will enable **Gradient Checkpointing** on both backbones. This is essential to fit the heavier V2-M and B4 models into GPU memory at 384px resolution without sacrificing batch size (Cite solution_lesson_node_00035).
*   **Batch Size:** We will maintain a **Batch Size of 32**. We will not drop below this threshold, as previous experiments demonstrated that smaller batches (e.g., 16) destabilize Batch Normalization and degrade performance (Cite solution_lesson_node_00022).
*   **Loss Hyperparameters:** We will set the ArcFace scaling factor **$s=30.0$**. We will explicitly avoid high scaling factors (e.g., 64.0), which were shown to hinder convergence on this specific dataset size (Cite solution_lesson_node_00038).
*   **Validation:** We will validate using a **Deterministic, Known-Only Gallery** (Cite solution_lesson_node_00024, solution_lesson_node_00019). Checkpointing will be based on the MAP@5 score, not training loss (Cite solution_lesson_node_00021).

# Evaluation
**Inference: Ensemble with Test-Time Augmentation (TTA)**
We will implement a robust inference pipeline that aggregates signals from both models and multiple views.
1.  **Cache Invalidation:** We will explicitly force the re-computation of all embeddings to ensure no stale weights are used (Cite solution_lesson_node_00003).
2.  **Test-Time Augmentation (TTA):** For every query and gallery image, we will compute embeddings for the **original** and **horizontally flipped** versions. The final embedding for an image will be the average of these two views. This exploits the bilateral symmetry of the flukes to reduce pose-related noise.
3.  **Score Fusion:** We will calculate the Cosine Similarity matrix for Model A ($S_A$) and Model B ($S_B$) separately. The final similarity matrix will be the average: $S_{final} = 0.5 \cdot S_A + 0.5 \cdot S_B$.
4.  **Open-Set Rejection:** We will apply **Distance Thresholding** to $S_{final}$.
    *   Calculate the distance to the nearest neighbor in the **Known-Only** Gallery (Cite solution_lesson_node_00018).
    *   If the similarity is below the calibrated threshold, predict `new_whale`.
    *   We will **strictly avoid k-Reciprocal Re-ranking**, as it has been proven to degrade performance on this sparse dataset (Cite solution_lesson_node_00033).
