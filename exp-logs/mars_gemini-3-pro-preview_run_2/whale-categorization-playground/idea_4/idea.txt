Based on the comprehensive analysis of the previous experiments and the specific lessons learned, I propose the following optimized strategy. This solution synthesizes the need for high model capacity, stable architectures, and a corrected open-set inference pipeline.

# Model
**Architecture:**
I propose utilizing an **EfficientNet-B4** backbone.
*   **Rationale:** We observed a "Capacity-Resolution Swap" where model depth (EfficientNet-B3) outperformed higher resolution (EfficientNet-B2 @ 384px) (Cite solution_lesson_node_00013). However, we also learned that fine details are critical (Cite solution_lesson_node_00009). With the available A100 GPU, we can afford to scale up both dimensions. EfficientNet-B4 offers a significant capacity increase over the B3 used in the current best solution, while remaining structurally stable compared to the ConvNeXt architecture that failed to converge (Cite solution_lesson_node_00017).
*   **Pooling:** We will retain **Generalized Mean (GeM) Pooling** to focus on salient features and suppress background noise, which is superior to Global Average Pooling for fine-grained tasks (Cite solution_lesson_node_00020).
*   **Head:** We will use the **ArcFace** head. This classification-based margin loss is proven to converge faster and generalize better than pairwise losses for this high-cardinality dataset (Cite solution_lesson_node_00008).

# Data
**Preprocessing:**
*   **Resolution:** We will standardize input images to **384x384**. This higher resolution is necessary to resolve minute scarring details (Cite solution_lesson_node_00009) and is computationally feasible with the EfficientNet-B4 backbone on the provided hardware.
*   **Filtering:** The training set will strictly **exclude** the `new_whale` class. We will train only on verified identities to prevent embedding collapse (Cite solution_lesson_node_00005).
*   **Caching:** We will use parameterized cache filenames (e.g., `train_enc_b4_384.npy`) to ensure data coherency (Cite solution_lesson_node_00001).

# Training
**Strategy:**
*   **Loss Function:** ArcFace Loss on known identities.
*   **Batch Size:** We will use a decoupled, moderate batch size (e.g., 16 or 20). As learned, proxy-based methods like ArcFace do not require large batches for negative mining, allowing us to fit the heavier B4 model into memory (Cite solution_lesson_node_00010).
*   **Validation:** We will perform validation at the end of every epoch using a **Known-Only Gallery**. The `new_whale` class will be excluded from the reference set, and the metric will be calculated by applying the inference-time thresholding logic. This ensures the validation score correlates with the open-set test objectives (Cite solution_lesson_node_00019).
*   **Checkpointing:** Due to the stochastic variance observed in long-tail metric learning, we will save checkpoints based strictly on the validation MAP@5 score, not training loss or epoch number (Cite solution_lesson_node_00021).

# Evaluation
**Inference Pipeline:**
I propose a **Split-Inference Pipeline** that corrects the flawed re-ranking approach from Idea 3.
1.  **Cache Invalidation:** Explicitly force re-computation of embeddings to avoid stale data (Cite solution_lesson_node_00003).
2.  **Gallery Construction:** The reference gallery will contain **only known whales**. We will not include `new_whale` images in the retrieval set, as they do not form a coherent cluster (Cite solution_lesson_node_00018).
3.  **Step 1: Retrieval:** Compute Cosine Similarity between test queries and the Known Gallery.
4.  **Step 2: Manifold Re-ranking (Structural Innovation):** Apply **k-Reciprocal Encoding Re-ranking** *only* to the retrieved known candidates. By restricting re-ranking to the set of known identities, we leverage the manifold structure to disambiguate hard positives (e.g., different angles of the same whale) without the noise of the "unknown" class that caused previous failures (Cite solution_lesson_node_00018).
5.  **Step 3: Open-Set Rejection:** Check the similarity score of the top re-ranked candidate.
    *   If `Score < Threshold`: Predict `new_whale` as the primary label, followed by the top 4 known matches.
    *   Else: Predict the top 5 known matches.
