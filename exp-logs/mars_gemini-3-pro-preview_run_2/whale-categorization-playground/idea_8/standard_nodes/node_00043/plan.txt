The implementation strategy follows the High-Fidelity Dual-Ensemble Strategy described in the task, adapted to run within the time limit while maximizing performance.

1.  **Configuration & Setup**: We initialize the environment and override the default epoch counts in `CFG` to fit the "fast baseline" requirement (reducing to ~5 epochs per model total) while maintaining the progressive resizing strategy (256px -> 384px).
2.  **Data Processing**: We load the pre-processed metadata and cache using `process_data`.
3.  **Training Orchestration**: We define a `train_model_pipeline` function that handles the two-phase training for a specific architecture:
    *   **Phase 1 (Warm-up)**: Train at 256x256 resolution.
    *   **Phase 2 (Fine-tuning)**: Train at 384x384 resolution with Gradient Checkpointing enabled.
    *   We save the best checkpoint based on validation MAP@5.
4.  **Dual-Model Execution**: We sequentially train **Model A** (EfficientNet-B5) and **Model B** (EfficientNet-V2-M).
5.  **Ensemble Validation**:
    *   We extract embeddings for the Validation set (Query) and Training set (Gallery) using both trained models.
    *   We compute the cosine similarity matrices for both models and fuse them (average).
    *   We calculate the final **MAP@5** on the validation set.
6.  **Failure Analysis**: We analyze the validation results by correlating the prediction error (1 - MAP) with the model's confidence (max similarity score) and the class frequency in the training set, providing insights into systematic errors.
7.  **Submission**: If the validation MAP@5 exceeds the specified threshold (0.846985), we generate the submission file for the test set using the full ensemble logic.
