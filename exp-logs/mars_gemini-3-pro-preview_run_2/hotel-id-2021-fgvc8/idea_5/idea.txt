# Idea 5: ConvNeXt-Based Metric Learning with Class-Balanced Sampling and Database Augmentation

### Model
To overcome the limitations of previous CNN backbones and further enhance feature discriminability, I propose a structural evolution to a **ConvNeXt** architecture.
*   **Backbone**: Adopt **ConvNeXt-Base** initialized with ImageNet-21k weights. ConvNeXt modernizes the standard ResNet design with "Transformer-style" blocks (e.g., larger kernel sizes, layer normalization, and isotropic stages). This architecture is structurally superior for fine-grained retrieval as it combines the local feature capture of CNNs (crucial for hotel textures/patterns) with the global receptive field of Transformers, without the complexity of self-attention heads.
*   **Pooling**: Retain the **Generalized Mean (GeM) Pooling** layer to efficiently aggregate spatial features while focusing on salient regions (Cite Idea 2).
*   **Head**: Utilize the **Sub-Center ArcFace** head ($K=3$). This component is explicitly retained to handle the multi-modal nature of hotel classes (e.g., bedrooms vs. facades) which caused single-center models to fail (Cite Lesson 00011).

### Data
*   **Resolution**: Set input resolution to **384 $\times$ 384** pixels. This balances the need for high-fidelity detail (Cite Lesson 00011) with the memory constraints of the heavier ConvNeXt backbone.
*   **Preprocessing**: Normalize images using ImageNet mean and standard deviation.
*   **Augmentation**: Apply the established strong augmentation pipeline (Albumentations: HorizontalFlip, ColorJitter, CoarseDropout) to prevent overfitting and force structural learning.

### Training
*   **Sampling Strategy (Structural Innovation)**: Replace standard random shuffling with **Class-Balanced (P-K) Sampling**. In each batch, randomly sample $P$ distinct hotel classes, and for each class, sample exactly $K$ images (e.g., $P=8, K=4$ for Batch Size 32). This ensures that every batch contains valid "positive" pairs for every sample, providing the Sub-Center loss with the necessary intra-class signal to compact the clusters effectively. Standard sampling often yields batches with singletons, rendering the margin-based objective ineffective for those samples.
*   **Loss Function**: Use **Sub-Center ArcFace Loss** without Label Smoothing. Label smoothing is explicitly excluded as it was proven to destroy the gradient signal required for margin-based convergence (Cite Lesson 00009).
*   **Optimizer & Schedule**: Use **AdamW** with a Cosine Annealing scheduler.
*   **Duration**: Train for **15 epochs**. As identified, margin-based objectives require extended training to converge compared to classification tasks (Cite Lesson 00013).

### Evaluation
*   **Inference Mechanism**: Adhere to the **Train-with-Proxy, Infer-with-Instances** paradigm. Discard the Sub-Center head and use the backbone to generate embeddings for the full training set (Gallery) and test set (Query) (Cite Lesson 00015).
*   **Database Augmentation (DBA) (Structural Innovation)**: Before querying, perform **Database Augmentation** on the Gallery. For every image in the Gallery, find its nearest $N$ neighbors within the Gallery itself and replace its embedding with a weighted average of itself and these neighbors. This reduces the noise of individual training samples (e.g., occlusions, bad lighting) and creates more robust "prototypes" for retrieval.
*   **Query Expansion (QE)**: Apply **Average Query Expansion** to the test queries (as explored in Idea 4) to further refine the search vector.
*   **Ranking**: Perform Cosine Similarity search between the refined Query vectors and the augmented Gallery vectors to generate the final predictions.
