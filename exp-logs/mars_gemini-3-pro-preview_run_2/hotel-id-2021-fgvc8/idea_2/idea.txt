# Idea 2: Deep Metric Learning with ArcFace and Retrieval-Based Inference

### Model
To address the limitations of standard classification on this high-cardinality, long-tail dataset, I propose shifting from a parametric classification model to a **Deep Metric Learning** architecture.
*   **Backbone**: Upgrade the backbone from ResNet-18 to **ResNet-50** (initialized with ImageNet weights). This provides a deeper feature extractor capable of capturing more subtle visual details required to distinguish between 7,770 hotels.
*   **Embedding Head**: Replace the classification head with a projection head designed for metric learning. This consists of a **Generalized Mean Pooling (GeM)** layer (to capture domain-specific features better than standard Average Pooling), followed by a Linear layer, Batch Normalization, and PReLU.
*   **L2 Normalization**: The final output of the network will be a 512-dimensional embedding vector, strictly **L2-normalized**. This constrains the features to a hypersphere, which is a prerequisite for cosine-similarity-based loss functions.
*   **Training Head (ArcFace)**: During training only, an **ArcFace (Additive Angular Margin)** head is attached. This layer maintains a set of learnable "center vectors" (one for each of the 7,770 classes). It computes the cosine similarity between the image embedding and these centers, adds an angular margin penalty ($m$) to the ground-truth class, and scales the logits ($s$) before passing them to the Cross-Entropy loss. This explicitly optimizes the embedding space for intra-class compactness and inter-class separability, directly addressing the "structural inefficiency" of standard Softmax identified in the previous attempt (Cite solution_lesson_node_00001).

### Data
*   **Preprocessing**: Images will be resized to $256 \times 256$ and center-cropped to $224 \times 224$, retaining the standard normalization from the previous idea.
*   **Augmentation**: To prevent overfitting and encourage the model to learn robust invariant features, I will introduce a stronger augmentation pipeline using `albumentations`. This will include **HorizontalFlip**, **ColorJitter** (brightness/contrast), and **CoarseDropout** (simulating occlusions). This is critical for metric learning to force the model to focus on structural identity rather than superficial pixel statistics.
*   **Sampling**: We will utilize the existing stratified metadata split but ensure the data loader yields batches that maximize class diversity per step.

### Training
*   **Loss Function**: The primary objective is the **ArcFace Loss**. By enforcing an angular margin, the model is forced to learn more discriminative features even for "tail" classes with few samples, preventing the "head" class bias observed in the baseline (Cite solution_lesson_node_00001).
*   **Optimizer**: Use **AdamW** with a higher weight decay ($1e-2$) to regularize the larger ResNet-50 backbone.
*   **Scheduler**: Implement a **Cosine Embedding** learning rate schedule with a linear warmup period to stabilize the initial training of the uninitialized ArcFace centers.

### Evaluation
Inference will be fundamentally changed from a classification task to a **Retrieval Task**:
1.  **Gallery Generation**: Pass the entire **Training Set** through the trained backbone to generate a "Gallery" of embeddings (shape: $N_{train} \times 512$).
2.  **Query Generation**: Pass the **Test Set** (or Validation Set) through the backbone to generate "Query" embeddings.
3.  **Similarity Search**: Calculate the Cosine Similarity matrix between all Query vectors and the Gallery vectors.
4.  **Ranking**: For each test image, retrieve the top $K$ (e.g., 100) most similar images from the training set.
5.  **Voting**: Aggregate the retrieved results by `hotel_id`. The score for a candidate hotel is the sum of the cosine similarities of its retrieved images.
6.  **Prediction**: The top 5 scoring hotels are returned as the prediction. This leverages the visual similarity to known examples rather than relying on a fixed decision boundary.
