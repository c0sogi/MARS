### Implementation Strategy

1.  **Configuration Override**: To ensure the script runs quickly and within the resource limits, we will monkey-patch the `Config` class. We will switch the backbone to a lightweight `resnet18`, reduce the number of epochs to 1, set a small batch size, and point the data paths to a generated "mini" dataset.
2.  **Data Subsetting**: We will load the original metadata and create a tiny subset containing only a few classes (e.g., 5 classes) and a small number of images. This subset will be saved to the working directory and used for the demonstration.
3.  **Component Verification (Unit Testing)**:
    *   **Dataset**: Verify that `HotelDataset` loads images correctly and applies transforms, producing tensors of the expected shape.
    *   **Model**: Verify that `HotelIdModel` (using `resnet18`) can be instantiated and performs a forward pass producing embeddings of the correct dimension.
    *   **Loss**: Verify that `SubCenterArcFaceLoss` computes a scalar loss value given dummy embeddings and labels.
    *   **Metric**: Verify `mean_average_precision` with a manual example to ensure correctness.
4.  **Training Pipeline Execution**: We will run the `train_model` function from the `engine` module using the mini-dataset. This serves as an integration test for the training loop, optimizer, and scheduler.
5.  **Inference Pipeline Execution**: We will run the `run_inference` function to demonstrate feature extraction, database augmentation (DBA), query expansion (QE), and submission generation.
6.  **Cleanup**: Temporary files created in the working directory will be left for inspection (as per standard practice in such environments) but the script will handle file path management robustly.
