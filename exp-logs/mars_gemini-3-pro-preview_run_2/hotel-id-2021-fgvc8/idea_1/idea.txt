To establish a robust and efficient baseline, I propose a **Parametric Multi-Class Classification** approach. This method differs fundamentally from the provided retrieval-based architectures (Models 1, 3, 4, 5) and the contrastive learning approach (Model 2) by treating the problem as a standard closed-set classification task rather than a similarity search or metric learning problem. Instead of comparing query images against a gallery of training embeddings during inference, this model encodes the visual identity of all 7,770 hotels directly into the weights of the final classification layer.

### Model
The architecture is designed for low latency and minimal complexity:
*   **Backbone**: Use a **ResNet-18** pre-trained on ImageNet. This is significantly lighter than the architectures in the provided examples (e.g., EfficientNet, Swin, ResNet-34) while still providing strong feature extraction capabilities.
*   **Head**: Remove the original fully connected layer and replace it with a single **Linear (Dense) layer** that maps the 512-dimensional output of the Global Average Pooling layer directly to the **7,770 hotel classes**.
*   **Mechanism**: Unlike the "Previous Ideas" which rely on generating embeddings and performing Nearest Neighbor search (ArcFace, NetVLAD, DINOv2), this model outputs class logits directly. This reduces inference complexity from $O(N)$ (searching the training set) to $O(1)$ (constant time matrix multiplication).

### Data
Preprocessing focuses on standardizing inputs for the pre-trained backbone:
*   **Label Encoding**: Map the 7,770 unique `hotel_id` strings to integer indices ($0$ to $7769$) to serve as target labels.
*   **Image Resizing**: Resize all images to $256 \times 256$ pixels.
*   **Cropping**: Apply a Center Crop of $224 \times 224$ pixels to focus on the central subject and remove edge artifacts.
*   **Normalization**: Normalize pixel values using standard ImageNet mean and standard deviation to align with the pre-trained weights.
*   **Augmentation**: Limit augmentation to horizontal flipping during training to maintain high throughput.

### Training
The training procedure prioritizes convergence speed and stability:
*   **Loss Function**: Use **Categorical Cross-Entropy Loss** with **Label Smoothing** (e.g., $\epsilon=0.1$). Label smoothing is crucial here to prevent the model from becoming over-confident on the many "singleton" classes (hotels with only 1-2 images) and helps regularize the high-dimensional output space.
*   **Optimizer**: Use **Adam** with a standard learning rate (e.g., $1e-3$) and a learning rate scheduler (ReduceLROnPlateau) to decay the rate when validation loss stagnates.
*   **Strategy**: Fine-tune the entire network (backbone + head) to allow the feature extractors to adapt to the specific domain of hotel rooms/facades, which differs from the object-centric ImageNet data.

### Evaluation
Inference is performed purely via the parametric weights, requiring no reference to the training data at test time:
1.  **Forward Pass**: Pass the test image through the network to obtain a vector of 7,770 logits.
2.  **Ranking**: Sort the logits in descending order.
3.  **Selection**: Select the indices of the top 5 highest logits.
4.  **Decoding**: Map these indices back to their original `hotel_id` strings using the inverse of the Label Encoder created during preprocessing.
5.  **Submission**: Format these 5 IDs as a space-delimited string for the submission file.
