# Proposed Strategy: Domain-Adapted Heterogeneous Ensemble (TAPT)

I propose a **Multi-Stage Training Pipeline** that introduces **Task-Adaptive Pretraining (TAPT)** to the heterogeneous ensemble. While previous iterations relied on off-the-shelf pre-trained weights, this strategy explicitly adapts the transformer backbones to the specific linguistic distribution of the "Wikipedia Talk" domain (e.g., slang, toxicity, and obfuscation) via unsupervised learning before supervised fine-tuning. This structural innovation bridges the gap between the generic pre-training of the backbones and the noisy nature of the target dataset.

### Model
The solution utilizes a **Tri-Branch Heterogeneous Ensemble** designed to maximize architectural diversity [Cite solution_lesson_node_00007].
1.  **Branch A: Domain-Adapted DeBERTa-v3 (Structural Innovation)**
    *   **Backbone:** `microsoft/deberta-v3-base`.
    *   **Adaptation:** The weights are initialized not from the public hub, but from a checkpoint generated by running Masked Language Modeling (MLM) on the competition dataset (see Training).
    *   **Head:** A **Multi-Sample Dropout** classification head to accelerate convergence and smooth the loss landscape [Cite solution_lesson_node_00009].
2.  **Branch B: Domain-Adapted RoBERTa (Structural Innovation)**
    *   **Backbone:** `roberta-base`.
    *   **Adaptation:** Similarly, this backbone is pre-trained on the domain corpus to capture context-specific semantics distinct from DeBERTa's disentangled attention mechanism.
    *   **Head:** Multi-Sample Dropout.
3.  **Branch C: Linear Baseline (Retention)**
    *   **Architecture:** A One-Vs-Rest Logistic Regression ensemble.
    *   **Features:** Concatenated **Word N-grams (1-2)** and **Character N-grams (2-6)**. This branch is explicitly retained to handle "out-of-vocabulary" noise and character-level obfuscations that subword tokenizers might misinterpret [Cite solution_lesson_node_00001, solution_lesson_node_00006].

### Data
1.  **Corpus Generation (for TAPT):** Concatenate the text from `train.csv` and `test.csv` (ignoring labels) to create a large, unsupervised domain corpus. This allows the model to learn from the 153k test samples during the pre-training phase.
2.  **Feature Caching:** For Branch C, continue to compute TF-IDF sparse matrices once and cache them to disk to eliminate redundant processing overhead [Cite solution_lesson_node_00005].
3.  **Tokenization:** Use a sequence length of **200 tokens** for the Transformer branches. This is increased from 128 to capture toxic signals that appear late in longer comments [Cite solution_lesson_node_00008].

### Training
The training process is restructured into a two-phase pipeline:

**Phase 1: Task-Adaptive Pretraining (TAPT)**
*   **Objective:** Masked Language Modeling (MLM).
*   **Procedure:** Train both the DeBERTa-v3 and RoBERTa backbones on the combined domain corpus for 3-5 epochs. This updates the embeddings to understand dataset-specific vocabulary (e.g., "sockpuppet", creative insults) before any classification labels are seen.

**Phase 2: Supervised Fine-Tuning**
*   **Strategy:** Fine-tune the domain-adapted backbones on the labeled data.
*   **Optimization:**
    *   **Layer-wise Learning Rate Decay (LLRD):** Apply multiplicative decay to learning rates, keeping lower layers stable (preserving general knowledge) while allowing the top layers to adapt aggressively [Cite solution_lesson_node_00009].
    *   **Scheduler:** Use a **Cosine Schedule with Warmup** to ensure better convergence compared to linear decay [Cite solution_lesson_node_00008].
    *   **Duration:** Train for **3 epochs**. A single epoch is insufficient for the optimizer to fully resolve decision boundaries, even with gradient accumulation [Cite solution_lesson_node_00011].
    *   **Loss:** Binary Cross-Entropy with Logits.

### Evaluation
1.  **Inference:** Generate probability predictions for the test set using all three branches: TAPT-DeBERTa, TAPT-RoBERTa, and the Linear model.
2.  **Optimized Blending:** Instead of using fixed weights, perform a **validation-driven scalar minimization** (using `scipy.optimize` or a grid search) to determine the optimal blending weights ($w_1, w_2, w_3$) that maximize ROC AUC on the validation set. This ensures the linear baseline's contribution is mathematically calibrated to complement the enhanced deep learning branches [Cite solution_lesson_node_00007].
