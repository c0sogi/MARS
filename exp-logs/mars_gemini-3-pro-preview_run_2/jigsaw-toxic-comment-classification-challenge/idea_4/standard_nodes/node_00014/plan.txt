The issue is that the script relies on `os.path.exists(directory)` to determine if the Task-Adaptive Pretraining (TAPT) step has been completed. This is unreliable because a previous failed run may have created the directory without successfully saving the model weights, leading to an `OSError` when the code later attempts to load the missing `pytorch_model.bin`. To fix this, I will update the conditions to check for the existence of the specific artifact (`pytorch_model.bin`) inside the directory instead of the directory itself. This ensures the pipeline only skips the step if the necessary files are actually present (Cite debug_lesson_2).
