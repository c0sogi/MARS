### Implementation Strategy

1.  **Configuration Patching**: To satisfy the "Optimize for Speed" requirement without modifying the source files, the script dynamically patches the `library.config` module at runtime. This includes:
    *   Redirecting `WORKING_DIR` to a temporary demo directory to avoid overwriting existing work.
    *   Reducing cross-validation folds (`cv`) and iteration limits (`max_iter`) for the classifiers to ensure rapid execution.
    *   Setting `NUM_WORKERS` to 0 to avoid multiprocessing overhead on the small debug dataset.

2.  **Data Loading Verification**: The script uses the `debug=True` flag provided in `data_loader.get_dataloaders`. This limits the dataset to 100 samples. We verify the integrity of the data loader by checking batch keys (`global`, `standard`, `local`, `id`) and tensor shapes.

3.  **Feature Extraction**: We utilize `feature_engine.extract_features` to generate embeddings for the debug train, validation, and test sets. We assert that the output dimensions match the expected concatenated embedding size (ConvNeXt-Large 1536 * 3 views = 4608).

4.  **Hybrid Model Training**: We instantiate the `HybridEnsemble` class.
    *   **Fit**: Train both the Linear (Logistic Regression) and Non-Linear (Histogram Gradient Boosting) heads on the training embeddings.
    *   **Optimize**: Run the weight optimization process on the validation set and verify that the resulting weights are within valid bounds [0, 1].

5.  **Submission Generation**: We generate predictions for the test set and use `hybrid_model.generate_submission` to create the CSV. We validate the output file's format, ensuring it contains the correct columns (id + 120 breeds) and the correct number of rows.
