Based on the analysis of the previous attempts and the specific lessons learned, I propose a **High-Fidelity Heterogeneous Ensemble** strategy. This approach addresses the failures of previous ensembling attempts by enforcing strict weight provenance and utilizing a Late Fusion architecture.

# Model
- **Dual-Architecture Backbone**: We will construct a prediction pipeline consisting of two distinct, high-capacity architectures to capture diverse feature representations:
    1.  **ConvNeXt-Large**: A pure Convolutional Neural Network (CNN) that excels at capturing local textures and patterns. This retains the high-performance component from the current best solution.
    2.  **Swin Transformer V2-Base**: A Hierarchical Vision Transformer that utilizes shifted windows to capture long-range global dependencies. This provides a complementary "attention-based" view of the data compared to the CNN.
- **Weight Provenance**: Crucially, both backbones will be initialized using **`torchvision` "New Recipe" weights** (e.g., `IMAGENET1K_V1` or `V2`). We will strictly avoid mixing weight sources (like `timm` vs. `torchvision`) to ensure we do not compromise the base estimator quality, addressing the specific failure mode observed where inferior weights degraded ensemble performance (Cite solution_lesson_node_00011).
- **Independent Classifiers**: Instead of concatenating embeddings (Early Fusion), which failed previously due to feature space mismatches (Cite solution_lesson_node_00009), we will attach a separate **Logistic Regression** head to each frozen backbone. This maintains the efficiency and calibration benefits of Linear Probing (Cite solution_lesson_node_00002).

# Data
- **Model-Specific Preprocessing**: We will create two separate data pipelines. Each pipeline will utilize the exact preprocessing transforms (resize resolution, interpolation method, crop size, and normalization mean/std) associated with its specific `torchvision` model weights. This ensures the input distribution for each backbone perfectly matches its pre-training conditions (Cite solution_lesson_node_00005).
- **Deterministic Pipeline**: No random augmentations will be applied during the training of the Logistic Regression heads to ensure stability and speed.

# Training
- **Feature Extraction with TTA**: We will iterate through the dataset once for each backbone. For every image, we will generate the original view and a horizontally flipped view. We will extract embeddings for both views and **average them** to create a single, robust feature vector for that image (Cite solution_lesson_node_00006).
- **Parallel Optimization**: The two Logistic Regression classifiers will be trained independently on their respective cached embeddings (ConvNeXt embeddings -> LogReg A; SwinV2 embeddings -> LogReg B). This isolates the optimization problems, allowing each linear head to converge optimally for its specific feature manifold.

# Evaluation
- **Late Fusion Inference**:
    1.  Generate probabilities for the test set using Pipeline A (ConvNeXt -> LogReg A).
    2.  Generate probabilities for the test set using Pipeline B (SwinV2 -> LogReg B).
    3.  **Average the probability vectors** from both pipelines to produce the final prediction. This "Prediction Ensembling" strategy is preferred over feature concatenation for heterogeneous architectures (Cite solution_lesson_node_00009).
