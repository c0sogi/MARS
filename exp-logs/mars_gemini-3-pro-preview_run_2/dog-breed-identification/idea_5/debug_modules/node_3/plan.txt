The issue is a shape mismatch caused by the `debug=True` mode, where the training subset (100 samples) contains fewer classes (58) than the total defined classes (120). The Logistic Regression model only outputs probabilities for the classes it has seen, resulting in a probability matrix of shape `(N, 58)` instead of `(N, 120)`. This triggers the `AssertionError` in `runfile.py` and would cause dimension mismatch errors in downstream ensemble logic.

To fix this, I will modify `library/classifier.py`:
1.  Update `train_logreg` to detect if the model output has fewer columns than `config.NUM_CLASSES`. If so, it will create a full-sized probability matrix (filled with zeros) and map the model's predictions to the correct columns based on `clf.classes_`. This ensures the output always matches the expected schema (Cite debug_lesson_2).
2.  Update `optimize_ensemble_weights` to handle cases where the input probability matrices are full-sized (120 columns) but the evaluation is restricted to a subset of classes (defined by `labels`). It will slice the probability matrices to match the provided `labels` before calculating log loss, preventing dimension mismatch errors during optimization.
