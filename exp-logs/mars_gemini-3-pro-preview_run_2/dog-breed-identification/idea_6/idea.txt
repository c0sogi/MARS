Based on the comprehensive analysis of the "Lessons Learned," I propose the **Dual-Stream Multi-View Heterogeneous Ensemble** strategy. This approach synthesizes the highly successful "Multi-View Early Fusion" data strategy (Lesson 00019) with a "Heterogeneous Backbone" architectural strategy, while rigorously addressing the integration failures observed in previous ensemble attempts (Lessons 00009, 00011, 00012, 00021).

# Model
We will construct a prediction system composed of two independent, high-capacity processing streams. This design leverages the complementary strengths of Convolutional Neural Networks (local texture) and Vision Transformers (global context) without mixing their feature spaces.

1.  **Stream A (CNN):** The **`ConvNeXt-Large`** architecture initialized with **`torchvision` "New Recipe" weights** (`IMAGENET1K_V1`). This retains the proven performance of the current best solution (Cite solution_lesson_node_00006, solution_lesson_node_00011).
2.  **Stream B (Transformer):** The **`ViT-H-14` (Huge)** architecture initialized with **SWAG weights** (`IMAGENET1K_SWAG_E2E_V1`). The selection of SWAG (Supervised Weakly from AGgregated hashtags) weights addresses the "weak base learner" failure of previous attempts by providing a transformer backbone that is competitive with, or superior to, ConvNeXt (Cite solution_lesson_node_00011).
3.  **Classifiers:** Each stream will terminate in its own independent **Logistic Regression** head. We will strictly avoid sharing heads or concatenating embeddings between streams (Early Fusion) to prevent feature space mismatch (Cite solution_lesson_node_00009).

# Data
We will implement a **Multi-View Data Pipeline** for *each* stream, ensuring that both architectures benefit from the geometric diversity that boosted the single-model baseline.

1.  **View Generation:** For every image, we will generate three geometric views (Cite solution_lesson_node_00016):
    *   **Standard:** Resize and Center Crop (Balance).
    *   **Global:** Resize "Squish" (Shape/Context).
    *   **Local:** Large Resize and Center Crop (Texture/Detail).
2.  **Stream-Specific Preprocessing:** Stream A and Stream B will use independent preprocessing transforms (resolution, interpolation, mean/std) that perfectly match their respective pre-training recipes (Cite solution_lesson_node_00005).
3.  **Feature-Level TTA:** We will apply horizontal flipping to all views and average the embeddings of the original and flipped versions to stabilize the features (Cite solution_lesson_node_00006).

# Training
The training process combines **Early Fusion** (for homogeneous data views) and **Parallel Linear Probing** (for heterogeneous architectures).

1.  **Intra-Stream Early Fusion:**
    *   For Stream A, we will **concatenate** the embeddings from the Standard, Global, and Local views into a single feature vector. We will **not** apply L2 normalization, preserving magnitude signal (Cite solution_lesson_node_00015, solution_lesson_node_00019).
    *   For Stream B, we will similarly concatenate its three view embeddings.
2.  **Parallel Optimization with Tuning:**
    *   We will train a `LogisticRegressionCV` classifier on Stream A's concatenated features.
    *   We will train a separate `LogisticRegressionCV` classifier on Stream B's concatenated features.
    *   Using Cross-Validation to automatically tune the regularization parameter `C` is critical to ensure both models reach their potential, avoiding the underfitting observed when using fixed hyperparameters (Cite solution_lesson_node_00021).
3.  **Ensemble Weight Optimization:** We will learn optimal scalar weights $(w_A, w_B)$ on the validation set to minimize the combined Log Loss. This protects against performance degradation if one stream unexpectedly underperforms (Cite solution_lesson_node_00012).

# Evaluation
1.  **Weighted Late Fusion:**
    *   Generate probability predictions $P_A$ using the fully trained Stream A pipeline.
    *   Generate probability predictions $P_B$ using the fully trained Stream B pipeline.
    *   Compute the final prediction as the weighted average: $P_{final} = w_A \cdot P_A + w_B \cdot P_B$ (Cite solution_lesson_node_00009).
2.  **Cache Management:** We will ensure all cached embeddings are stored in directories with unique signatures (e.g., `convnext_large_v1` vs `vit_huge_swag`) to prevent the cache invalidation failures observed previously (Cite solution_lesson_node_00018).
