The execution failure is caused by a security feature in PyTorch 2.6+ where `torch.load` defaults to `weights_only=True`, preventing the unpickling of NumPy scalars (like the validation score) stored in the checkpoint. To resolve this, I will modify `library/utils.py` to explicitly cast the score to a Python float before saving (preventing the issue in future checkpoints) and disable the `weights_only` restriction when loading to support existing checkpoints containing NumPy types.
