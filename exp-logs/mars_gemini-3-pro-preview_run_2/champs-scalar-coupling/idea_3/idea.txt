# Optimized Strategy: Directional Message Passing with Spherical Basis Functions

### Model
I propose a **Directional Message Passing Neural Network (DMPNN)** architecture, conceptually similar to DimeNet, which explicitly models molecular geometry through both distances and bond angles.

*   **Directional Embeddings:** Unlike the previous SchNet-based approach which updated atom features, this model will learn embeddings for **directed edges** (messages from atom $j$ to atom $i$). This allows the network to distinguish the geometric environment of an atom from different incoming directions, addressing the limitation where scalar distance features were found to be angle-blind (Cite `solution_lesson_node_00002`).
*   **Geometric Basis Expansion:**
    *   **Radial Basis Functions (RBF):** Inter-atomic distances will be expanded into high-dimensional vectors using Gaussian RBFs. This retains the successful strategy of decoupling spatial information to learn distinct interaction filters for different distance bands (Cite `solution_lesson_node_00004`).
    *   **Angular Basis Functions:** To explicitly capture angular dependencies, the model will define interactions based on triplets of atoms $(k, j, i)$. The angle $\angle kji$ will be expanded using **Spherical Bessel Functions** (or 2D Circular Basis functions). These angular features will modulate the aggregation of messages from preceding edges ($k \to j$) to the current edge ($j \to i$).
*   **Non-Linear Update Blocks:** The core interaction block will aggregate the angular-weighted messages and process them through a deep Multi-Layer Perceptron (MLP) with non-linear activations (e.g., Swish or Shifted Softplus) before updating the edge embedding. This strictly adheres to the finding that reducing update functions to linear projections creates information bottlenecks (Cite `solution_lesson_node_00006`).
*   **Deterministic Readout:** The final prediction for a coupling pair will be generated by a specialized output block that concatenates the learned representations of the two interacting atoms (and their connecting edge features). This regression head will be fully deterministic, omitting Dropout layers to prevent stochastic noise from degrading the precision of the physical predictions (Cite `solution_lesson_node_00007`).

### Data
*   **Graph Construction:** Molecules will be converted into graphs using a spatial cutoff (e.g., 5.0 Å) to define neighbors.
*   **Triplet Indexing:** A pre-processing step will generate an index of all valid triplets $(k, j, i)$ within the graph. This is necessary to facilitate the directional message passing where edge $j \to i$ receives information from all edges $k \to j$.
*   **Basis Pre-computation:** To optimize training throughput, the RBF expansions for distances and the Angular Basis expansions for triplets will be pre-computed and stored as fixed tensors, rather than computed on-the-fly.
*   **Target Normalization:** The target `scalar_coupling_constant` will be standardized (zero mean, unit variance) per coupling type to aid convergence.

### Training
*   **Loss Function:** The model will be trained using **Mean Absolute Error (MAE)**.
*   **Optimizer:** An **AdamW** optimizer will be used with a warm-up period followed by a cosine decay schedule. This helps navigate the complex loss landscape associated with high-dimensional geometric features.
*   **Regularization:** Regularization will be achieved through weight decay and the inherent geometric constraints of the architecture, strictly avoiding Dropout (Cite `solution_lesson_node_00007`).

### Evaluation
*   **Inference Pipeline:** The evaluation process will iterate through the `test_metadata.csv` and load the corresponding raw `.xyz` files directly to construct the graphs. This ensures that all test molecules are correctly processed, avoiding the missing data issues encountered with aggregated CSVs in previous attempts.
*   **Inverse Transformation:** Predictions will be generated in the normalized space and then inversely transformed (using the training set's mean and standard deviation) to produce the final `scalar_coupling_constant` values.
