The issue stems from `scipy.special.jn_zeros` only accepting integer orders, causing a `ValueError` when calculating roots for spherical Bessel functions which correspond to half-integer orders of standard Bessel functions. To fix this, I will implement a robust numerical root-finding approach using `scipy.special.spherical_jn` and `scipy.optimize.brentq`. Instead of relying on asymptotic heuristics which can fail for small $n$ (Cite debug_lesson_7), I will use an incremental scanning strategy to identify intervals where the function sign changes, ensuring reliable bracketing for the solver.

        # Precompute roots of Spherical Bessel functions
        # Roots of j_l(z) are roots of J_{l+0.5}(z)
        # We compute them numerically using scanning + Brent's method
        roots = []
        for l in range(num_spherical):
            l_roots = []

            # Scanning parameters
            # Roots are roughly pi apart. A step of 0.1 is safe.
            step = 0.1
            x = step

            # Robust scanning for roots
            while len(l_roots) < num_radial:
                y1 = spherical_jn(l, x)
                y2 = spherical_jn(l, x + step)

                if y1 * y2 < 0:
                    # Sign change detected, root is in [x, x+step]
                    r = brentq(lambda z: spherical_jn(l, z), x, x + step)
                    l_roots.append(r)
                elif y1 == 0:
                    # Exact zero found (unlikely with float, but possible)
                    l_roots.append(x)

                x += step

                # Safety break (roots are approx n*pi)
                if x > (num_radial + l + 10) * np.pi:

                    break
