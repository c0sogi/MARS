The implementation strategy involves the following steps:

1.  **Configuration Override**: Modify the `Config` class attributes to adapt the pipeline for a "fast baseline" run. This includes setting a `DEBUG_SAMPLE_SIZE` (e.g., 5000 molecules) to limit dataset size and reducing `NUM_EPOCHS` to ensure the script completes quickly. We also update the `SUBMISSION_PATH` to match the specific requirement (`./submission/submission.csv`).
2.  **Initialization**: Set random seeds for reproducibility. Initialize the `Engine` which encapsulates the model, optimizer, and training logic.
3.  **Training & Submission**: Execute `engine.run()`. This method performs the training loop with validation-based early stopping and automatically generates the submission file using the best saved model.
4.  **Validation & Failure Analysis**:
    *   After the engine run, reload the best model and the validation data loader.
    *   Perform a full inference pass on the validation set to calculate the `Final Validation Metric` (Log MAE) exactly as required.
    *   Extract prediction errors and input features (specifically the inter-atomic distance and coupling type).
    *   Compute and print the correlation between the absolute error and these features to identify failure modes (e.g., does the model fail more on distant atoms?).
5.  **Output**: Print the final metric and failure analysis results to standard output.
