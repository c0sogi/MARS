The issue is that the `run_training` function in `library/train.py` constructs its datasets directly from the full processed data arrays, ignoring the `config.DEBUG` flag and `config.DEBUG_SIZE` setting. This causes the pipeline to process the entire dataset and generate a full-size submission file (321 rows) instead of the expected debug size (50 rows), leading to an assertion failure in the demo script. This behavior aligns with **Cite debug_lesson_10**, where the code behaves as if using original configuration values despite runtime overrides because the logic to handle the override is missing.

To fix this, I will modify `run_training` to explicitly check `config.DEBUG` and slice the training, validation, and test arrays (as well as the test metadata DataFrame) to `config.DEBUG_SIZE` before processing proceeds.
