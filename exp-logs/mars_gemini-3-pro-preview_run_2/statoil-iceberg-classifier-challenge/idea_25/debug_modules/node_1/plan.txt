The issue is caused by the data augmentation operations (`np.rot90` and `np.fliplr`) in `IcebergDataset.__getitem__`, which return NumPy array views with negative strides. PyTorch's `torch.from_numpy()` cannot handle arrays with negative strides without an explicit copy to reorder the memory. To fix this, I will invoke `.copy()` on the image array immediately before converting it to a tensor, ensuring the data is contiguous and has positive strides (Cite debug_lesson_7).
