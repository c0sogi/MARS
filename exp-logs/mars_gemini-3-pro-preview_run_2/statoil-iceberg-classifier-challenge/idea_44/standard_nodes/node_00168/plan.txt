The implementation strategy follows a structured pipeline designed to meet the task requirements efficiently while ensuring robustness through ensemble learning.

1.  **Initialization**: We begin by setting random seeds using `library.utils` to ensure the entire run is reproducible.
2.  **Model Training**: We invoke `library.train.run_training()` to execute the 5-Fold Cross-Validation. This function handles the training loop, including data loading, optimization, and saving the best model checkpoints for each fold to the working directory. We use the full dataset (`debug_size=None`) to maximize performance given the small dataset size.
3.  **Validation Assessment**:
    *   We load the specific hold-out validation metadata from `metadata/val.csv` as required.
    *   We retrieve the preprocessed training data from the cache generated during the training phase.
    *   We filter this data to isolate exactly those samples present in the hold-out set.
    *   We perform inference on this hold-out set using all 5 trained models (Ensemble). The predictions are averaged to produce a robust probability estimate.
    *   We calculate and print the **Final Validation Metric** (Log Loss).
4.  **Failure Analysis**: We compute the absolute error for each validation sample and calculate the Pearson correlation between this error and key input features (Incidence Angle, Band 1 Mean, Band 2 Mean). This helps identify if specific physical conditions (e.g., viewing angle or signal brightness) correlate with model failure.
5.  **Submission Generation**: We compare the validation metric against the strict threshold (`0.1477...`). If the model performs sufficiently well, we proceed to load the test set, generate ensemble predictions using the 5 models, and save the final `submission.csv` in the required format.
