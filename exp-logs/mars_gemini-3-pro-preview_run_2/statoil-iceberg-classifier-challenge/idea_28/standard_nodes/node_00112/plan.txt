The issue is that the training pipeline currently uses the entire dataset from `train.json` for cross-validation, ignoring the `metadata/train.csv` split which defines the actual training subset. This causes the hold-out validation samples (defined in `metadata/val.csv`) to leak into the training folds, rendering the final validation metric invalid because the models are evaluated on data they have already seen.

To fix this, I will modify `library/data.py` to filter the loaded data in `get_dataloaders`, ensuring only IDs present in `metadata/train.csv` are used for training and cross-validation splitting. I will also update `runfile.py` to apply the same filtering logic when reconstructing the folds to calculate scaling statistics for the hold-out validation phase. This ensures the hold-out set remains completely unseen (Cite debug_lesson_7).
