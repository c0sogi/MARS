Based on the comprehensive analysis of the previous experiments and the accumulated lessons, I propose the **Sky-State Transformer for Anchor-Free Trajectory Refinement**.

This solution synthesizes the need for geometric context (Lesson 00013) with the requirement to avoid spatial overfitting (Lesson 00017) and global pooling (Lesson 00032). It introduces a structural innovation by using a **Transformer** backbone to dynamically weigh temporal neighbors via self-attention, conditioned on a novel **Sky-State** embedding that captures environmental biases without memorizing geospatial coordinates.

### Model
**Architecture: Dual-Stream Transformer with Center-Focus**
The model is designed as a sequence-to-vector regression network that refines the position at a specific timestamp by analyzing its temporal neighborhood and environmental context.

1.  **Trajectory Stream (Transformer Backbone):**
    *   **Input:** A sliding time-series window of size $N$ (e.g., 15 epochs). Each timestep contains a feature vector of **Window-Relative Coordinates** (meters), **Dynamics** (Velocity/Deltas), and **Signal Metrics** (Cn0, Uncertainty).
    *   **Encoder:** A stack of **Transformer Encoder Layers** (e.g., 2-4 layers). The **Self-Attention** mechanism allows the model to dynamically attend to "clean" epochs within the window to correct the noisy center epoch, effectively learning a non-linear, content-aware smoothing filter.
    *   **Center Extraction:** Crucially, instead of Global Average Pooling (which destroys temporal alignment **Cite solution_lesson_node_00032**), the output vector corresponding specifically to the **center timestamp** (index $N//2$) is extracted. This preserves the exact feature state of the target moment while enriching it with attended context from neighbors.

2.  **Sky-State Context Stream (MLP):**
    *   **Input:** A vector of aggregated **Satellite Geometry Statistics** for the entire window (e.g., Mean/Std of Satellite Elevation and Azimuth, Mean Signal Strength).
    *   **Purpose:** This stream creates an embedding of the "Environmental State" (e.g., distinguishing "Open Sky" from "Deep Urban Canyon" based on low satellite elevation). This allows the model to apply state-dependent bias corrections **Cite solution_lesson_node_00011** without using absolute Latitude/Longitude, thereby strictly preventing the spatial overfitting observed in previous iterations **Cite solution_lesson_node_00017**.

3.  **Fusion Head:**
    *   The **Center Token** from the Trajectory Stream and the **Sky-State Embedding** are concatenated.
    *   A Multi-Layer Perceptron (MLP) projects this fused vector to a 2D output: the residual correction ($\Delta$East, $\Delta$North) in meters.

### Data
**Preprocessing Pipeline:**
1.  **Target Transformation:** Calculate ground truth residuals in a local metric frame (Meters). The target variable is the difference between the Ground Truth and the WLS Baseline **Cite solution_lesson_node_00001**.
2.  **Sequence Feature Engineering:**
    *   **Windowing:** Generate sliding windows of a short, fixed length (e.g., 15 seconds) to capture local motion without overfitting to long-term trajectory signatures **Cite solution_lesson_node_00010**.
    *   **Relative Centering:** For each window, subtract the WLS Latitude/Longitude/Altitude of the *center* timestamp from all steps.
    *   **Simple Scaling:** Convert these relative differences to meters using **Simple Element-wise Scaling** (e.g., $\Delta Lat^\circ \times 111,320$). This preserves the geometric shape of the path **Cite solution_lesson_node_00013** while ensuring translation invariance and avoiding the numerical instability of complex projections **Cite solution_lesson_node_00020**.
    *   **Dynamics:** Explicitly include first-order differences (velocity) for Latitude, Longitude, and **Altitude**. Vertical dynamics are retained as a critical orthogonal signal for detecting GNSS anomalies **Cite solution_lesson_node_00005**, **Cite solution_lesson_node_00006**.
3.  **Filtering:** Strictly filter the training data to include only windows where the center timestamp has valid Ground Truth. **Do not use interpolation** to fill gaps in the baseline, as this creates artificial error signals **Cite solution_lesson_node_00035**.
4.  **Normalization:** Apply Standard Scaling (Z-score) to all input features.

### Training
*   **Loss Function:** **Mean Absolute Error (MAE)**. This L1 loss is selected for its robustness to the extreme outliers (multipath effects) inherent in urban GNSS data.
*   **Optimizer:** **AdamW** optimizer with a `ReduceLROnPlateau` learning rate scheduler to ensure stable convergence.
*   **Regularization:** Apply Dropout within the Transformer and MLP layers to prevent overfitting.

### Evaluation
**Inference Process:**
1.  **Preprocessing:** Apply the same windowing, relative-centering, simple scaling, and sky-context aggregation steps to the test data.
2.  **Prediction:** Feed the processed windows into the model to predict the metric residuals ($\Delta$East, $\Delta$North).
3.  **Reconstruction:** Convert the predicted metric residuals back to decimal degrees using the local approximation factors derived from the test sample's latitude. Add these corrections to the baseline WLS Latitude/Longitude to generate the final submission coordinates.
