Based on the comprehensive analysis of previous experiments and the accumulated lessons, I propose the **Local-Attention Transformer (LAT)**. This solution addresses the limitations of previous architectures by leveraging the self-attention mechanism to effectively filter noise from the trajectory sequence while strictly adhering to translation invariance to ensure generalization.

### Model
**Architecture: Local-Attention Transformer (LAT)**
The model is a sequence-to-vector regression network that processes a sliding window of sensor data to predict the correction for the center timestamp.

1.  **Input Embedding:**
    *   The input is a sequence of length $N$ (e.g., 11 epochs).
    *   Each timestep is projected into a high-dimensional embedding space using a Linear layer.
    *   **Positional Encodings** are added to retain the temporal order of the sequence.

2.  **Transformer Encoder Backbone:**
    *   A stack of **Transformer Encoder layers** (e.g., 2-3 layers).
    *   **Mechanism:** The **Self-Attention** mechanism allows the model to dynamically weigh the importance of every timestep in the window based on its signal quality and geometric consistency. Unlike CNNs (fixed kernels) or LSTMs (sequential bias), the Transformer can directly attend to "clean" epochs within the window to correct the noisy center epoch.

3.  **Prediction Head:**
    *   The representation of the **center token** (or a global average of the sequence) is passed through a Multi-Layer Perceptron (MLP).
    *   **Output:** A 2D vector representing the residual correction ($\Delta$East, $\Delta$North) in meters.

### Data
**Preprocessing:**
1.  **Target Transformation:** Calculate the ground truth residuals in a local metric frame (Meters). The target is the difference between Ground Truth and the WLS Baseline. **Cite solution_lesson_node_00001**.
2.  **Feature Engineering:**
    *   **Relative Position Sequence:** To preserve geometric context (**Cite solution_lesson_node_00013**) while preventing spatial overfitting (**Cite solution_lesson_node_00017**), the input sequence will contain positions **relative to the window center**.
    *   **Robust Scaling:** Instead of complex ECEF/ENU transformations which caused instability, use **Simple Element-wise Scaling** to convert these relative degrees to approximate meters (e.g., $\Delta Lat^\circ \times 111,320$). **Cite solution_lesson_node_00020**.
    *   **Dynamics:** Explicitly include the first-order differences (velocity) for Latitude, Longitude, and **Altitude**. Vertical dynamics are a critical feature for detecting anomalies. **Cite solution_lesson_node_00005**, **Cite solution_lesson_node_00006**.
    *   **Signal Metrics:** Include Cn0, Uncertainty, and Satellite Count for each timestep.
3.  **Windowing:** Use a short sliding window (e.g., 11 seconds) to prevent overfitting to long-term trajectory signatures. **Cite solution_lesson_node_00010**.
4.  **Normalization:** Apply Standard Scaling (Z-score) to all input features.

### Training
*   **Loss Function:** **Mean Absolute Error (MAE)**. This L1 loss is robust to the extreme outliers typical of urban GNSS data.
*   **Optimizer:** **AdamW** with a learning rate scheduler (e.g., `ReduceLROnPlateau`) to ensure convergence.
*   **Regularization:** Apply Dropout within the Transformer and MLP layers.

### Evaluation
**Inference Process:**
1.  **Preprocessing:** Apply the same windowing and relative-centering transformation to the test data.
2.  **Prediction:** Feed the test windows into the LAT model to predict the metric residuals ($\Delta$East, $\Delta$North).
3.  **Reconstruction:** Convert the predicted metric residuals back to decimal degrees using local approximation factors. Add these corrections to the baseline WLS position to generate the final submission coordinates.
