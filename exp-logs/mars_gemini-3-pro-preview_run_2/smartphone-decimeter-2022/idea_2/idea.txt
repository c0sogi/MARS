Based on the lessons learned from the Windowed MLP experiments, I propose a structural evolution to a **Sequence-Aware Residual Regressor** using a **Bidirectional LSTM (Bi-LSTM)** backbone. This approach addresses the MLP's inability to effectively capture temporal dependencies within the window and incorporates the critical findings regarding feature engineering and target scaling.

### Model
**Design:**
The architecture shifts from a flattened Feed-Forward Network to a sequential **Bidirectional LSTM** network. This allows the model to process the sliding window as a time-series sequence, preserving the temporal order and dependencies of the sensor readings surrounding the target timestamp.

*   **Input Layer:** Accepts a sequence of shape $(L, F)$, where $L$ is the window length (e.g., 30 seconds) and $F$ is the number of features.
*   **Backbone:** A stack of **Bidirectional LSTM** layers. The bidirectional nature allows the model to utilize context from both the past (history of movement) and the future (trajectory look-ahead) to refine the estimate at the center timestamp.
*   **Attention / Pooling:** An **Attention Mechanism** or Global Average Pooling layer is applied to the LSTM outputs to dynamically weigh the importance of different time steps within the window (e.g., focusing on epochs with higher signal quality) before aggregating them.
*   **Output Head:** A dense projection layer that outputs the 2D residual correction ($\Delta$East, $\Delta$North) in **meters**.

### Data
**Preprocessing:**
1.  **Coordinate Transformation (Target Scaling):** Instead of predicting residuals in degrees, which led to scaling issues, convert both the Ground Truth and the baseline WLS coordinates into a local metric coordinate system (e.g., ENU - East, North, Up) centered at the window's middle timestamp. The target variable becomes the difference in meters between the Ground Truth and the WLS baseline. **Cite solution_lesson_node_00001**.
2.  **Feature Engineering:**
    *   **Trajectory Dynamics:** Explicitly calculate and include the first-order differences (velocities) of the baseline WLS position: `DeltaLat`, `DeltaLon`. **Cite solution_lesson_node_00005**.
    *   **Vertical Dynamics:** Include the rate of change of Altitude (`DeltaAlt`) as an input feature. Although the task is 2D, vertical anomalies are strong indicators of signal error. **Cite solution_lesson_node_00006**.
    *   **Signal Metrics:** Include standard signal quality indicators (Cn0, Uncertainty, Satellite Count).
3.  **Normalization:** Apply Standard Scaling (Z-score) to all input features.

### Training
**Procedure:**
*   **Loss Function:** Use **Mean Absolute Error (MAE)** (L1 Loss). This is robust to the extreme outliers common in GNSS data (urban canyons) and aligns with the competition's percentile-based metric.
*   **Optimizer:** Use **AdamW** with a learning rate scheduler (e.g., Cosine Annealing or ReduceLROnPlateau) to ensure convergence.
*   **Windowing:** Create sliding windows of length $L$ centered on each target timestamp. Ensure data from different drives is not mixed within a single window.

### Evaluation
**Inference:**
1.  **Preprocessing:** Apply the same coordinate transformation and feature engineering (including Delta features) to the test data.
2.  **Prediction:** Pass the sliding windows of test data through the trained Bi-LSTM to predict the metric residuals ($\Delta$Meters).
3.  **Reconstruction:** Convert the predicted metric residuals back to decimal degrees (using the local approximation that 1 meter $\approx 1/111320$ degrees latitude, and adjusted for longitude based on latitude) and add them to the baseline WLS Latitude/Longitude to generate the final submission coordinates.
