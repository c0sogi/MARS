The issue is that the `create_windows` function in `library/data_loader.py` implements a strict sliding window strategy that discards data points at the beginning and end of each trip segment where a full window cannot be centered. Specifically, for a window size of 15, it drops the first 7 and last 7 points of every continuous segment. Since the submission format requires a prediction for every timestamp listed in the test metadata, this data dropping causes a mismatch between the number of predictions and the expected number of rows (e.g., 86 vs 100).

To fix this, I will modify `create_windows` to pad the feature arrays (`wls_pos`, `sig_metrics`, `sky_data`) with edge values before generating windows. This allows the sliding window to be centered on every timestamp in the segment, ensuring that the function produces an output for every input row.
