Based on the analysis of previous experiments and the accumulated lessons, I propose the **Sky-Contextualized Sequence-to-Point CNN**.

This solution represents a structural evolution of the successful Windowed MLP (Idea 1) and the failed CNN attempts (Ideas 3, 4, 5, 9). It integrates the feature extraction capabilities of convolutions with the robust "center-focused" regression of the MLP, while introducing a new environmental context stream to correct biases without spatial overfitting.

### Model
**Architecture: Dual-Input Sequence-to-Point Network**
The model utilizes a hybrid architecture that processes temporal motion data and static environmental context separately before fusion.

1.  **Trajectory Stream (1D-CNN):**
    *   **Input:** A sliding time-series window of size $N$ (e.g., 15 epochs). Features include **Window-Relative Coordinates** (meters), **Dynamics** (Velocity/Deltas), and **Signal Metrics** (Cn0, Uncertainty).
    *   **Backbone:** A shallow stack of **Residual 1D Convolutional Layers** (2-3 layers). These layers act as learnable smoothing filters, identifying kinematic patterns (e.g., consistent motion vs. jitter) from the sequence **Cite solution_lesson_node_00013**.
    *   **Temporal Preservation:** Crucially, **Global Average Pooling is removed**. The output of the CNN is **flattened**. This preserves the specific feature representation of the *center* timestamp and its relationship to neighbors, addressing the loss of temporal alignment that caused previous sequence models to fail **Cite solution_lesson_node_00032**.

2.  **Sky Context Stream (MLP):**
    *   **Input:** A vector of aggregated **Satellite Geometry Statistics** for the window (Mean Satellite Elevation, Azimuth Spread, and Signal Strength variance).
    *   **Purpose:** This stream provides a proxy for the environmental state (e.g., "Urban Canyon" vs. "Open Sky") based on the physical configuration of satellites. This allows the model to apply state-dependent bias corrections **Cite solution_lesson_node_00011** without using absolute geospatial coordinates, thereby strictly preventing the spatial overfitting observed in previous iterations **Cite solution_lesson_node_00017**.

3.  **Fusion Head:**
    *   The flattened trajectory features and the sky context embedding are concatenated.
    *   A Multi-Layer Perceptron (MLP) projects this fused vector to a 2D output: the residual correction ($\Delta$East, $\Delta$North) in meters.

### Data
**Preprocessing Pipeline:**
1.  **Target Transformation:** Calculate ground truth residuals in a local metric frame (ENU - East, North, Up). The target is the difference in **meters** between the Ground Truth and the WLS baseline. **Cite solution_lesson_node_00001**.
2.  **Sequence Feature Engineering:**
    *   **Relative Centering:** For each window, subtract the WLS Latitude/Longitude/Altitude of the *center* timestamp from all steps.
    *   **Simple Scaling:** Convert these relative differences to meters using simple element-wise scaling (e.g., $\Delta Lat^\circ \times 111,320$). This avoids the numerical instability of complex ECEF/ENU projections on noisy data **Cite solution_lesson_node_00020**.
    *   **Dynamics:** Explicitly include first-order differences (velocities) for Latitude, Longitude, and **Altitude**. Vertical dynamics serve as a critical orthogonal signal for detecting GNSS anomalies **Cite solution_lesson_node_00005**, **Cite solution_lesson_node_00006**.
3.  **Windowing:** Use a short sliding window (e.g., 15 seconds) to capture local motion context without overfitting to long-term trajectory signatures **Cite solution_lesson_node_00010**.
4.  **Normalization:** Apply Standard Scaling (Z-score) to all inputs.

### Training
*   **Loss Function:** **Mean Absolute Error (MAE)**. This L1 loss is selected for its robustness to the extreme outliers (multipath effects) inherent in the dataset.
*   **Optimizer:** **AdamW** optimizer with a `ReduceLROnPlateau` learning rate scheduler to ensure stable convergence.
*   **Regularization:** Apply Batch Normalization within the CNN blocks and Dropout in the Fusion MLP to prevent co-adaptation.

### Evaluation
**Inference Process:**
1.  **Preprocessing:** Apply the same windowing, relative-centering, simple scaling, and sky-context aggregation steps to the test data.
2.  **Prediction:** Feed the processed windows into the model to predict the metric residuals ($\Delta$East, $\Delta$North).
3.  **Reconstruction:** Convert the predicted metric residuals back to decimal degrees using the local approximation factors derived from the test sample's latitude. Add these corrections to the baseline WLS Latitude/Longitude to generate the final submission.
