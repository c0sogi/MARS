The issue is that the training pipeline encounters `NaN` values in the loss function immediately, which prevents the validation loss comparison (`val_loss < best_val_loss`) from ever evaluating to `True`. Consequently, the model checkpoint is never saved, leading to a `FileNotFoundError` when the inference step tries to load it. The root cause is that while feature columns are sanitized for missing values, the ground truth target columns (`LatitudeDegrees`, `LongitudeDegrees`, `AltitudeMeters`) are not checked. Missing values in these targets propagate through the coordinate conversion functions and into the loss calculation.

To fix this, I will modify `library/model.py` to explicitly drop rows where either the features or the target columns contain `NaN` values during the training and validation phases. This ensures that the model receives valid inputs and targets, preventing `NaN` loss and allowing the training loop to save the best model.
