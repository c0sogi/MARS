Implementation Strategy:
1.  **Utils Demonstration**: Import and verify coordinate conversion functions (`WGS84_to_ECEF`, `ECEF_to_WGS84`) and distance calculation (`haversine_distance`) using known values to ensure correctness.
2.  **Data Loading & Processing**: Utilize `get_dataloaders` to process the raw data. This function internally calls `process_data`, which reads the metadata files, loads the corresponding GNSS/IMU CSVs, computes derived features, applies sliding windows, and caches the result. We will set `load_cached_data=False` initially to demonstrate the full pipeline, then use the cache for inference.
3.  **Model Initialization**: Instantiate the `DSTResNet` model with dimensions matching the processed data (6 dynamic features, 2 static features). Perform a dummy forward pass to verify tensor shape compatibility.
4.  **Training Loop**: Initialize the `Trainer` class with the model, optimizer, and loss function. Execute a single epoch of training to demonstrate the fitting process and checkpoint saving mechanism.
5.  **Inference & Submission**: Use the `generate_submission` function to load the trained checkpoint, run inference on the test set (loading from the cache generated in step 2), reconstruct latitude/longitude from the predicted residuals, and save the final CSV.
