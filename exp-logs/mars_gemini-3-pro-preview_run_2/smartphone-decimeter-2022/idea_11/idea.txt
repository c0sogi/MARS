Based on the accumulated lessons and the analysis of previous experiments, I propose the **IMU-Enhanced Local-Trajectory CNN**.

This solution addresses the limitations of previous attempts by integrating a new data modality (IMU) to provide location-invariant motion context, while strictly adhering to the architectural constraints identified in the lessons (e.g., avoiding global pooling, using relative coordinates).

### Model
**Architecture: Residual 1D-CNN with Multi-Modal Fusion**
The model is a sequence-to-vector regression network designed to refine the trajectory at a specific timestamp by analyzing the local motion and signal context.

1.  **Input Sequence:** A sliding window of size $N$ (e.g., 11 epochs, representing $\pm 5$ seconds). Each timestep contains a concatenated feature vector of GNSS and IMU data.
2.  **Convolutional Backbone:** A stack of **Residual 1D Convolutional Blocks** (Conv1D $\to$ BatchNorm $\to$ ReLU).
    *   The convolutional filters act as learnable smoothing kernels, extracting local kinematic patterns (e.g., acceleration, braking, turning) and signal quality trends from the sequence **Cite solution_lesson_node_00013**.
3.  **Temporal Preservation Head:**
    *   Instead of Global Average Pooling (which destroys the temporal alignment required for point estimation **Cite solution_lesson_node_00032**), the output of the CNN is **flattened** (or the feature vector corresponding to the *center* index is extracted).
    *   This preserves the specific context of the target timestamp while retaining the processed neighborhood information.
4.  **Prediction Head:** A Multi-Layer Perceptron (MLP) projects the flattened features to a 2D output vector: the residual correction ($\Delta$East, $\Delta$North) in meters.

### Data
**Preprocessing Pipeline:**
1.  **Target Transformation:** Calculate ground truth residuals in **meters** relative to the WLS baseline. This ensures the target magnitude is compatible with network initialization **Cite solution_lesson_node_00001**.
2.  **IMU Integration (Structural Innovation):**
    *   The raw IMU data (Accelerometer and Gyroscope) is sampled at a much higher frequency than GNSS.
    *   **Aggregation:** For each GNSS epoch $t$, aggregate the IMU readings within the interval $[t-0.5s, t+0.5s]$. Calculate summary statistics: Mean and Standard Deviation of the total acceleration magnitude and rotation rate.
    *   **Purpose:** IMU data provides a robust, location-invariant signal of physical motion that helps the model distinguish between true movement and GNSS signal noise (e.g., a stationary device with jumping GNSS coordinates will have near-zero IMU acceleration).
3.  **Sequence Feature Engineering:**
    *   **Window-Relative Coordinates:** For each window, subtract the WLS Latitude/Longitude of the *center* timestamp from all steps. Convert these differences to meters using **Simple Element-wise Scaling** (e.g., $\Delta Lat^\circ \times 111,320$). This preserves the geometric "shape" of the path **Cite solution_lesson_node_00013** while ensuring translation invariance to prevent spatial overfitting **Cite solution_lesson_node_00017**.
    *   **Dynamics:** Explicitly include first-order differences (velocity) for Latitude, Longitude, and **Altitude**. Vertical dynamics are retained as a critical orthogonal signal for detecting GNSS anomalies **Cite solution_lesson_node_00005**, **Cite solution_lesson_node_00006**.
    *   **Sky Context:** Include aggregated Satellite Geometry statistics (Mean Elevation, Azimuth Spread) per epoch. This serves as a proxy for environmental state (e.g., urban canyon detection) without using absolute coordinates **Cite solution_lesson_node_00011**.
4.  **Windowing:** Use a short sliding window (e.g., 11 seconds) to prevent overfitting to long-term trajectory signatures **Cite solution_lesson_node_00010**.
5.  **Normalization:** Apply Standard Scaling to all inputs.

### Training
*   **Loss Function:** **Mean Absolute Error (MAE)**. This L1 loss is selected for its robustness to the extreme outliers (multipath effects) inherent in the dataset.
*   **Optimizer:** **AdamW** optimizer with a `ReduceLROnPlateau` scheduler to ensure stable convergence.
*   **Regularization:** Apply Batch Normalization within the CNN blocks and Dropout in the final MLP layers.

### Evaluation
**Inference Process:**
1.  **Preprocessing:** Apply the same IMU aggregation, windowing, relative-centering, and scaling steps to the test data.
2.  **Prediction:** Feed the processed windows into the model to predict the metric residuals ($\Delta$East, $\Delta$North).
3.  **Reconstruction:** Convert the predicted metric residuals back to decimal degrees using the local approximation factors derived from the test sample's latitude. Add these corrections to the baseline WLS Latitude/Longitude to generate the final submission.
