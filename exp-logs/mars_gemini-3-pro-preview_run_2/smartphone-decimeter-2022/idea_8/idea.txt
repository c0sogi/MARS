Based on the comprehensive analysis of previous experiments and the accumulated lessons, I propose the **Short-Window Relative-State Bi-GRU**. This solution addresses the limitations of previous architectures by combining the geometric context preservation of sequence models with the stability and generalization benefits of relative coordinate systems, while avoiding the overfitting associated with long-term dependencies.

# Model
**Architecture: Bidirectional GRU with Temporal Attention**
The model is designed as a sequence-to-vector regression network that processes a short time-series window of sensor data to predict the location correction for the center timestamp.

1.  **Input Sequence:** A sliding window of size $N$ (e.g., 15 epochs). Each timestep consists of relative spatial features, dynamics, and signal metrics.
2.  **Recurrent Backbone:** A stack of **Bidirectional Gated Recurrent Unit (Bi-GRU)** layers. The Bi-GRU is chosen over Transformers for its superior sample efficiency on moderate-sized datasets and its inductive bias towards sequential continuity, which aligns with physical motion.
3.  **Temporal Attention Mechanism:** Instead of simple pooling, an attention layer computes a weighted sum of the GRU hidden states. This allows the model to dynamically prioritize "clean" epochs within the window (e.g., those with high signal strength and consistent dynamics) while suppressing noisy epochs when estimating the position at the window's center.
4.  **Prediction Head:** A Multi-Layer Perceptron (MLP) projects the attention-aggregated context vector to a 2D output: the residual correction in local metric units ($\Delta$East, $\Delta$North).

# Data
**Preprocessing Pipeline:**
1.  **Target Transformation:** Calculate the ground truth residuals in a local metric frame (Meters). The target variable is the difference between the Ground Truth and the WLS Baseline **Cite solution_lesson_node_00001**.
2.  **Feature Engineering:**
    *   **Windowing:** Generate sliding windows of a short, fixed length (e.g., 15 seconds). This duration is sufficient to capture local motion context but short enough to prevent the model from overfitting to unique, long-term trajectory signatures found in the training set **Cite solution_lesson_node_00010**.
    *   **Relative Position Sequence:** To preserve the geometric "shape" of the trajectory **Cite solution_lesson_node_00013** while ensuring translation invariance (preventing spatial overfitting) **Cite solution_lesson_node_00017**, the input sequence will contain positions **relative to the window center** (i.e., $Pos_t - Pos_{center}$).
    *   **Robust Scaling:** Perform the degree-to-meter conversion for these relative coordinates using **Simple Element-wise Scaling** (e.g., $\Delta Lat^\circ \times 111,320$) rather than complex ECEF/ENU projections. This avoids the numerical instability and artifact generation observed with rigorous projection methods on noisy data **Cite solution_lesson_node_00020**.
    *   **Dynamics:** Explicitly include the first-order differences (velocity) for Latitude, Longitude, and **Altitude**. The inclusion of vertical dynamics provides a critical orthogonal signal for detecting GNSS anomalies **Cite solution_lesson_node_00005**, **Cite solution_lesson_node_00006**.
    *   **Signal Metrics:** Include standardized Cn0, Uncertainty, and Satellite Count for each timestep.
3.  **Normalization:** Apply Standard Scaling (Z-score) to all input features.

# Training
*   **Loss Function:** **Mean Absolute Error (MAE)**. This L1 loss is selected for its robustness to the extreme outliers (multipath effects) inherent in urban GNSS data.
*   **Optimizer:** **AdamW** optimizer with a `ReduceLROnPlateau` learning rate scheduler to ensure stable convergence and fine-tuning.
*   **Regularization:** Apply Dropout within the GRU and MLP layers to prevent overfitting.

# Evaluation
**Inference Process:**
1.  **Preprocessing:** Apply the same windowing, relative-centering, and simple scaling transformations to the test data.
2.  **Prediction:** Feed the processed test windows into the Bi-GRU model to predict the metric residuals ($\Delta$East, $\Delta$North).
3.  **Reconstruction:** Convert the predicted metric residuals back to decimal degrees using the same local approximation factors used in preprocessing. Add these corrections to the baseline WLS Latitude/Longitude to generate the final submission coordinates.
