Based on the analysis of the previous experiments and the accumulated lessons, I propose the **Relative-Centric Windowed MLP with Sky-State Injection**.

This solution represents a strategic evolution of the Current Best Solution (Windowed MLP). It retains the successful MLP backbone (which effectively captures position-specific correlations in short windows) but fundamentally restructures the **Input Representation** to address the spatial overfitting and scaling issues identified in subsequent experiments. It replaces absolute geospatial coordinates with a translation-invariant local map, augmented by a satellite geometry stream to correct environmental biases.

### Model
**Architecture: Dual-Input Flattened MLP**
The model is a regression network that processes a fixed-size temporal window to predict the position correction for the center timestamp.

1.  **Trajectory Input Block:**
    *   **Input:** A sliding window of size $N$ (e.g., 15 epochs).
    *   **Features:** Instead of absolute Latitude/Longitude, the input consists of **Window-Relative Coordinates** (meters relative to the center epoch), **Kinematics** (Velocity/Acceleration, including Vertical), and **Signal Metrics** (Cn0, Uncertainty).
    *   **Processing:** This window is **flattened** into a single vector. Unlike CNNs or RNNs which share weights across time, the flattened MLP assigns unique weights to each timestep relative to the center. This preserves the precise temporal alignment required for point estimation **Cite solution_lesson_node_00032** and allows the model to learn specific rules (e.g., "if the immediate past is high-confidence, trust it more").

2.  **Sky-State Context Block:**
    *   **Input:** A vector of aggregated **Satellite Geometry Statistics** for the window (Mean/Std of Satellite Elevation and Azimuth, Signal Strength distribution).
    *   **Purpose:** This injects environmental context (e.g., "Low elevation satellites imply urban canyon") to enable state-dependent bias correction **Cite solution_lesson_node_00011**. By using satellite geometry instead of absolute coordinates, the model avoids memorizing specific map locations, ensuring generalization **Cite solution_lesson_node_00017**.

3.  **Fusion & Prediction:**
    *   The flattened trajectory vector and the sky-state vector are concatenated.
    *   A series of Dense layers with Batch Normalization and ReLU activations projects this representation to a 2D output: the residual correction ($\Delta$East, $\Delta$North) in meters.

### Data
**Preprocessing Pipeline:**
1.  **Target Transformation:** Calculate ground truth residuals in a local metric frame (Meters). The target is the difference between Ground Truth and the WLS Baseline. This ensures the target magnitude matches network initialization **Cite solution_lesson_node_00001**.
2.  **Feature Engineering:**
    *   **Relative Centering:** For each window, subtract the WLS Latitude/Longitude/Altitude of the *center* timestamp from all steps in the window.
    *   **Simple Scaling:** Convert these relative differences to meters using simple element-wise scaling (e.g., $\Delta Lat^\circ \times 111,320$). This preserves the geometric shape of the trajectory **Cite solution_lesson_node_00013** while avoiding the numerical instability of complex ECEF/ENU projections **Cite solution_lesson_node_00020**.
    *   **Vertical Dynamics:** Explicitly include the rate of change of Altitude. Vertical anomalies are a critical orthogonal signal for detecting GNSS errors **Cite solution_lesson_node_00006**.
3.  **Windowing:** Use a short sliding window (e.g., 5-15 seconds) to capture local motion without overfitting to long-term trajectory signatures **Cite solution_lesson_node_00010**.
4.  **Filtering:** Train only on windows where the center timestamp has valid ground truth. **Do not use interpolation** to fill gaps, as this creates artificial error signals **Cite solution_lesson_node_00035**.
5.  **Normalization:** Apply Standard Scaling (Z-score) to all inputs.

### Training
*   **Loss Function:** **Mean Absolute Error (MAE)**. This L1 loss is robust to the extreme outliers (multipath effects) inherent in urban GNSS data.
*   **Optimizer:** **AdamW** optimizer with a `ReduceLROnPlateau` learning rate scheduler.
*   **Strategy:** Train on the **full dataset**. As observed in previous experiments, simpler models trained on all data outperform complex models (like Transformers) trained on subsamples **Cite solution_lesson_node_00040**.
*   **Cache Safety:** Use configuration hashing for data caching to prevent training on stale features **Cite solution_lesson_node_00037**.

### Evaluation
**Inference Process:**
1.  **Preprocessing:** Apply the same windowing, relative-centering, simple scaling, and sky-context aggregation steps to the test data.
2.  **Prediction:** Feed the processed windows into the MLP to predict the metric residuals ($\Delta$East, $\Delta$North).
3.  **Reconstruction:** Convert the predicted metric residuals back to decimal degrees using local approximation factors derived from the test sample's latitude. Add these corrections to the baseline WLS Latitude/Longitude to generate the final submission.
