Based on the comprehensive analysis of previous experiments and the accumulated lessons, I propose the **Ego-Centric Multi-Modal MLP (ECM-MLP)**.

This solution represents a strategic evolution of the successful Windowed MLP (Idea 1). It retains the efficient, center-focused MLP backbone (Lesson 00032, 00040) but fundamentally restructures the **Input Representation** to address the critical weaknesses of spatial overfitting (Lesson 00017) and lack of environmental awareness (Lesson 00011). It achieves this by shifting to a translation-invariant "Ego-Centric" coordinate system, augmented by satellite geometry and inertial motion context.

### Model
**Architecture: Flattened Multi-Modal Fusion Network**
The model is a regression network that processes a fixed-size temporal window to predict the position correction for the window's *center* timestamp. Unlike dual-stream CNNs which failed due to pooling layers destroying temporal alignment, this model flattens the temporal dimension to preserve the specific relationship between each neighbor and the target center.

1.  **Trajectory Block:**
    *   **Input:** A sliding window of size $N$ (e.g., 15 epochs).
    *   **Features:** **Window-Relative Coordinates** (meters relative to the center epoch), **Kinematics** (Velocity/Acceleration, including Vertical), and **Signal Metrics** (Cn0, Uncertainty).
    *   **Processing:** Flattened into a single vector. This allows the MLP to learn specific temporal filters (e.g., "if $t-1$ is high quality, weight it heavily") without the weight-sharing constraints of a CNN.

2.  **Environmental Context Block:**
    *   **Input:** Aggregated **Satellite Geometry Statistics** for the window (Mean/Std of Satellite Elevation and Azimuth).
    *   **Purpose:** Proxies the environmental state (e.g., "Urban Canyon" vs. "Open Sky") to enable state-dependent bias correction **Cite solution_lesson_node_00011** without using absolute geospatial coordinates, strictly preventing spatial overfitting **Cite solution_lesson_node_00017**.

3.  **Inertial Context Block:**
    *   **Input:** Aggregated **IMU Statistics** (Mean/Std of Acceleration Magnitude and Gyroscope) synchronized to the GNSS epochs.
    *   **Purpose:** Provides a robust, location-invariant signal of physical motion intensity. This helps the model distinguish between true movement and GNSS signal drift (e.g., stationary device with jumping coordinates) using a shallow fusion approach **Cite solution_lesson_node_00033**.

4.  **Prediction Head:**
    *   All feature blocks are concatenated.
    *   A Deep Dense Network (e.g., 4 layers, 512 units) with Batch Normalization and ReLU activations projects the fused state to a 2D output: the residual correction ($\Delta$East, $\Delta$North) in meters.

### Data
**Preprocessing Pipeline:**
1.  **Target Transformation:** Calculate ground truth residuals in a local metric frame (Meters). The target is the difference between Ground Truth and the WLS Baseline **Cite solution_lesson_node_00001**.
2.  **Feature Engineering:**
    *   **Relative Centering:** For each window, subtract the WLS Latitude/Longitude/Altitude of the *center* timestamp from all steps.
    *   **Simple Scaling:** Convert these relative differences to meters using simple element-wise scaling (e.g., $\Delta Lat^\circ \times 111,320$). This preserves the geometric shape **Cite solution_lesson_node_00013** while avoiding the numerical instability of complex ECEF/ENU projections **Cite solution_lesson_node_00020**.
    *   **Dynamics:** Explicitly include first-order differences (velocities) for Latitude, Longitude, and **Altitude**. Vertical dynamics are a critical orthogonal signal for detecting anomalies **Cite solution_lesson_node_00005**, **Cite solution_lesson_node_00006**.
    *   **IMU Aggregation:** Resample high-frequency IMU data to GNSS epochs by calculating the mean and standard deviation of magnitudes within $\pm 0.5s$ of each epoch.
3.  **Windowing:** Use a short sliding window (e.g., 15 seconds) to capture local motion without overfitting to long-term trajectory signatures **Cite solution_lesson_node_00010**.
4.  **Filtering:** Train only on windows where the center timestamp has valid ground truth. **Do not use interpolation** to fill gaps, as this creates artificial error signals **Cite solution_lesson_node_00035**.
5.  **Normalization:** Apply Standard Scaling (Z-score) to all inputs.

### Training
*   **Loss Function:** **Mean Absolute Error (MAE)**. This L1 loss is robust to the extreme outliers (multipath effects) inherent in urban GNSS data.
*   **Optimizer:** **AdamW** optimizer with a `ReduceLROnPlateau` learning rate scheduler.
*   **Strategy:** Train on the **full dataset**. Simpler models trained on all available data outperform complex models trained on subsets **Cite solution_lesson_node_00040**.
*   **Cache Safety:** Use configuration hashing for data caching to prevent training on stale features **Cite solution_lesson_node_00037**.

### Evaluation
**Inference Process:**
1.  **Preprocessing:** Apply the same windowing, relative-centering, simple scaling, and multi-modal aggregation steps to the test data.
2.  **Prediction:** Feed the processed windows into the ECM-MLP to predict the metric residuals ($\Delta$East, $\Delta$North).
3.  **Reconstruction:** Convert the predicted metric residuals back to decimal degrees using local approximation factors derived from the test sample's latitude. Add these corrections to the baseline WLS Latitude/Longitude to generate the final submission.
