Based on the analysis of the provided lessons and the evolution of previous experiments, I propose a **Disjoint Background-Foreground Gradient Boosting** strategy. This approach structurally resolves the conflict between the need for massive data to capture "Heavy Tail" outliers and the gradient instability caused by training on that data, while explicitly addressing the "Hard Integration" risks identified in Lesson 00055.

# Model
I will utilize the **XGBoost Regressor** as the backbone, leveraging its proven superiority for spatial tabular tasks **Cite {solution_lesson_node_00030}**.
*   **Structural Innovation (Disjoint Knowledge Decoupling):** Instead of using complex K-Fold encoding or Vectorized Subtraction on a single dataset, I will explicitly partition the massive 55M dataset into two disjoint sets: a **Background Knowledge Base (45M rows)** and a **Foreground Training Set (5M rows)**.
    *   **Rationale:** This allows us to apply **Differential Data Hygiene**. We can rigorously sanitize the "Background" to create stable, high-quality statistical priors (The "Wisdom"), while leaving the "Foreground" relatively raw to allow the model to learn how to handle real-world noise and valid outliers using the L2 loss **Cite {solution_lesson_node_00018}**. This avoids the leakage risks of K-Fold encoding and the instability of training on the full dataset **Cite {solution_lesson_node_00017}**.

# Data
The data pipeline employs a **Multi-View Target Encoding** strategy derived from the disjoint split.

**1. Background Knowledge Base (The "Prior")**
*   **Source:** 45 Million rows (disjoint from training).
*   **Strict Hygiene:** Apply **Strict Physics-Consistent Filtering**. Remove rows where `Fare < $2.50`, `Fare > $200`, or `Fare_Per_Km > $10`. This ensures the statistical priors represent the "True" expected price, free from the "garbage" outliers that corrupted previous attempts **Cite {solution_lesson_node_00017}**.
*   **Multi-View Encoding:** Compute aggregate statistics (Mean Fare, Mean Fare-Per-Km) for multiple spatial resolutions:
    *   **Fine-Grained Route:** `(Pickup_Geohash7, Dropoff_Geohash7)` (~150m resolution) to capture micro-pricing **Cite {solution_lesson_node_00045}**.
    *   **Coarse-Grained Route:** `(Pickup_Geohash6, Dropoff_Geohash6)` (~1km resolution) to capture neighborhood trends.
    *   **Temporal-Spatial:** `(Pickup_Geohash6, Hour)` to capture time-of-day surcharges.

**2. Foreground Training Set (The "Learner")**
*   **Source:** 5 Million rows (disjoint from Background).
*   **Loose Hygiene:** Apply **Minimal Filtering**. Retain valid high-fare outliers (e.g., up to $1000) if they are physically consistent (e.g., long distance). This preserves the "Heavy Tail" signal required for the RMSE metric **Cite {solution_lesson_node_00018}**.
*   **Feature Enrichment:**
    *   **Soft Integration:** Join the statistics from the Background Knowledge Base to the Foreground set. If a route is missing in the Background, fallback to the Coarse view or a global average. These are added as **Input Features**, not Base Margins, allowing the tree to ignore them if they are noisy **Cite {solution_lesson_node_00055}**.
    *   **Inductive Bias:** explicit physical features (Haversine, Manhattan, Bearing, Rotated Coordinates) to ensure generalization **Cite {solution_lesson_node_00046}**.

# Training
1.  **Objective Function:** Use **`reg:squarederror`** (Standard L2 Loss).
    *   **Rationale:** Because the training set is a stable subsample and the input features provide robust, clean priors (from the Background), the optimization landscape is stable. We can safely use L2 loss to minimize the specific RMSE metric, avoiding the underperformance of robust losses like Huber **Cite {solution_lesson_node_00037}**.
2.  **Target:** Train on the **raw `fare_amount`**. Do not log-transform, as this biases the RMSE **Cite {solution_lesson_node_00025}**.

# Evaluation
1.  **Inference:**
    *   Map the test set coordinates to the Geohash keys used in the **Background Knowledge Base**.
    *   Retrieve the pre-computed Multi-View Encodings (Fine, Coarse, Rate).
    *   Generate predictions using the XGBoost model.
2.  **Post-Processing:** Apply a minimum fare floor ($2.50) and clamp predictions to be non-negative. Ensure test coordinates are clamped to the NYC bounding box **Cite {solution_lesson_node_00003}**.
