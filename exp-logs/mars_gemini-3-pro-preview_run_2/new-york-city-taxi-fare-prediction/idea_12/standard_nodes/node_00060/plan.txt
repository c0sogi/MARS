The issue is that the production run (`debug=False`) is silently loading stale, subsampled data cached during a previous debug run (`debug=True`) because both configurations share the same working directory (`./working/idea_12`). This results in the model training on a tiny fraction of the data (100k rows instead of 5M+), leading to poor performance and an invalid validation metric. To fix this, I will modify `library/config.py` to append a suffix to the working directory based on the `debug` flag (e.g., `_debug` vs `_full`). This ensures that full-scale runs use a separate cache location, forcing the pipeline to regenerate the complete dataset instead of loading invalid artifacts. Cite debug_lesson_1.
