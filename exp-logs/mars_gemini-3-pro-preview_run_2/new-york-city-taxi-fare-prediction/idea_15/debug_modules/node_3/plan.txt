The XGBoost training failed because the feature engineering process generated infinite values (`inf`), likely due to division by zero during the "Rest of World" subtraction logic (when `rest_cnt` is 0) or when calculating rates for short trips. XGBoost cannot handle `inf` values natively in the DMatrix constructor.

To fix this, I will modify `library/feature_factory.py`:
1.  **Sanitize Subtraction Logic:** In `transform_learner`, explicitly set the calculated mean fare or rate to `NaN` whenever the "Rest of World" count (`rest_cnt`) is less than or equal to zero. This prevents `inf` generation and invalid negative counts (leakage).
2.  **Global Sanitization:** In `_apply_fallbacks`, replace all `np.inf` and `-np.inf` values with `np.nan` before applying the imputation cascade. This ensures that any infinite values (e.g., from rate calculations) are treated as missing data and filled with valid fallbacks (Cite debug_lesson_3).
3.  **Final Cleanup:** Add a final check after calculating `temporal_fare` to ensure no new `inf` values were introduced by multiplication.
