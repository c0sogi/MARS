# Idea: Log-Space Gradient Boosting with Spatial Clustering

Based on the analysis of previous failures, I propose a solution that fundamentally alters the regression target space and feature representation to resolve the conflict between training stability and outlier prediction.

### Model
I propose using **XGBoost** with a **Log-Link formulation**.
*   **Architecture**: A Gradient Boosted Decision Tree (GBDT) regressor.
*   **Structural Innovation**: Instead of predicting the raw `fare_amount` directly (which spans orders of magnitude and causes gradient instability), the model will predict the **log-transformed fare**. This changes the optimization landscape from minimizing squared dollar error (highly sensitive to outliers) to minimizing squared percentage error (robust to scale).
*   **Spatial Abstraction**: Introduce **K-Means Clustering** layers to the input. By mapping raw float coordinates to discrete "Cluster IDs" (e.g., "JFK Airport Area", "Times Square"), the tree model can explicitly learn region-to-region pricing rules (like flat rates) that are difficult to approximate with simple coordinate splits.

### Data
The data pipeline will be engineered to handle the "Heavy Tail" distribution identified in Lesson 00018 without the instability noted in Lesson 00017.

1.  **Coordinate Sanitization (Input Clamping)**:
    *   Strictly clamp all pickup and dropoff coordinates in the Training, Validation, and Test sets to the NYC bounding box (e.g., Lat 40-42, Lon -75 to -72). This prevents the linear extrapolation of massive distances from corrupt GPS data, which was the root cause of the baseline failure **Cite {solution_lesson_node_00003}**.

2.  **Target Transformation (Log-Space)**:
    *   Apply the transformation $y_{new} = \log(1 + y_{raw})$ to the `fare_amount` in the training set.
    *   **Rationale**: The raw target variable contains extreme outliers (up to $93k) that destabilized the L2 loss function when training on the full dataset **Cite {solution_lesson_node_00017}**. However, removing these outliers causes the model to fail on valid high-fare test cases **Cite {solution_lesson_node_00018}**. The log transform compresses the range $[0, 90000]$ to roughly $[0, 11.5]$, preventing gradient explosion while retaining the *relative* information needed to predict high fares.

3.  **Feature Engineering**:
    *   **Spatial Clusters**: Train a Mini-Batch K-Means algorithm (e.g., $K=100$) on the training coordinates to assign a `pickup_cluster` and `dropoff_cluster` ID to every row.
    *   **Physics Features**: Retain Haversine distance, Manhattan distance, and Bearing.

### Training
1.  **Dataset Scale**: Train on the **Full Dataset** (or the largest feasible subset, e.g., 40M rows). The log-transformation makes the loss function robust enough to handle the noise of the full dataset without the divergence observed in previous attempts **Cite {solution_lesson_node_00017}**.
2.  **Objective**: Minimize RMSE on the log-transformed target.
3.  **Hardware Acceleration**: Use `tree_method='gpu_hist'` to efficiently process the large dataset and cluster features on the A100 GPU.

### Evaluation
1.  **Inference**: Generate predictions $\hat{y}_{log}$ using the trained model on the sanitized test features.
2.  **Inverse Transformation**: Convert predictions back to the original dollar scale using the exponential function: $\hat{y}_{final} = \exp(\hat{y}_{log}) - 1$.
3.  **Post-Processing**: Apply a minimum fare floor (e.g., $2.50).
