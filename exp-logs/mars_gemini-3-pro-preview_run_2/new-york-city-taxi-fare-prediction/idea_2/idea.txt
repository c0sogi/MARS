# Idea 2: Gradient Boosting with Robust Coordinate Sanitization

### Model
I propose replacing the linear architecture with a **Gradient Boosted Decision Tree (GBDT)** model, specifically using the **XGBoost** framework.

*   **Architecture:** The model will consist of an ensemble of decision trees trained sequentially to correct the errors of previous trees.
*   **Rationale:** The previous linear model failed because it extrapolated massive fare predictions from outlier coordinates in the validation set ($y = wx$). By contrast, tree-based models partition the feature space into "leaves" and predict the average value within that leaf. This structural characteristic naturally bounds predictions and prevents the indefinite extrapolation of outliers observed in the linear baseline Cite {solution_lesson_node_00003}.
*   **Complexity:** While computationally heavier than linear regression, the provided NVIDIA A100 GPU allows for efficient training of GBDT models on large datasets using GPU-accelerated histogram algorithms.

### Data
The data pipeline will be upgraded to strictly enforce the "Input Clamping" strategy identified as missing in the previous lesson.

1.  **Coordinate Sanitization (Crucial Step):**
    *   Define a strict bounding box for the NYC area based on the training data statistics (e.g., Lat: 40-42, Lon: -75 to -72).
    *   Apply a **clipping operation** to the coordinates in the **Training, Validation, and Test sets**. Any coordinate falling outside this box will be clamped to the boundary. This directly mitigates the risk of generating massive distance values from corrupt GPS data, which destroyed the RMSE in the previous attempt Cite {solution_lesson_node_00003}.
2.  **Feature Engineering:**
    *   **Retained Features:** Continue to calculate **Haversine** and **Manhattan** distances, as these are the strongest physical signals.
    *   **New Features:** Add **bearing/direction** (angle of travel) and **distance to major hubs** (JFK, LGA, EWR, Times Square). These features allow the tree model to learn non-linear pricing dynamics specific to certain routes (e.g., fixed airport fares) which the linear model could not easily capture.
    *   **Temporal Features:** Extract Hour, Day of Week, and Year.

### Training
1.  **Algorithm:** Use XGBoost with the `tree_method='gpu_hist'` parameter to leverage the available A100 GPU. This is essential for processing the 55M row dataset within the time limit.
2.  **Objective:** Minimize Root Mean Squared Error (RMSE).
3.  **Strategy:**
    *   Use a hold-out validation set (20%) to monitor performance.
    *   Implement **Early Stopping**: Stop training if the validation RMSE does not improve for a set number of rounds. This prevents overfitting to the noise in the training data.

### Evaluation
1.  **Inference:** Generate predictions on the sanitized test set.
2.  **Post-Processing:**
    *   Apply a lower bound to the predictions (e.g., $2.50 minimum fare) to handle rare cases where the model might predict unrealistically low values.
    *   The tree-based structure ensures that even if a test sample has strange features (after sanitization), the prediction will remain within the range of valid fares seen during training, avoiding the catastrophic error spikes seen in the linear model Cite {solution_lesson_node_00003}.
