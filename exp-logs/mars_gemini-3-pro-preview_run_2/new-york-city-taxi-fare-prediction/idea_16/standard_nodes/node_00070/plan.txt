The previous implementation failed because the validation set contains rows with missing coordinates (`NaN`), causing the Haversine distance calculation to return `NaN`. This propagated through the waterfall logic, resulting in `NaN` values in the `margin` column (used as `base_margin` for XGBoost), which ultimately caused the model predictions to be `NaN` and the RMSE calculation to crash. Additionally, `encode_geohash` produced runtime warnings when casting `NaN` coordinates to integers.

To fix this, I will:
1.  **Sanitize Geohashing Inputs**: Update `library/utils.py` to replace `NaN` coordinates with `0.0` before processing. This prevents runtime warnings and ensures valid (dummy) hashes are generated.
2.  **Impute Missing Margins**: Update `library/margin_logic.py` to fill `NaN` values in the computed margins with the global mean fare. This ensures the `base_margin` passed to the model is always finite, even for rows with missing data (Cite `debug_lesson_11`).
