Based on the analysis of the provided lessons and the failure modes of previous experiments, I propose a **Global-Knowledge-Augmented Gradient Boosting** strategy. This approach decouples the extraction of high-density statistical information (from the full dataset) from the gradient learning process (on a stable subsample), resolving the conflict between "instability at scale" and "loss of information in subsampling."

# Model
I will utilize the **XGBoost Regressor** as the backbone architecture, leveraging its proven superiority over Deep Learning for this low-dimensional spatial task **Cite {solution_lesson_node_00030}**.
*   **Structural Innovation (Global-Local Decoupling):** The model will not be trained on the full 55M dataset directly (which causes gradient instability). Instead, it will be trained on a stable subsample, but it will be augmented with **Global Statistical Features** derived from the entire 55M dataset. This allows the model to access the "wisdom of the crowd" (e.g., fixed rates for specific routes) without being exposed to the noise that destabilizes the loss function.

# Data
The data pipeline is divided into a **Global Feature Extraction Stage** and a **Local Training Stage**.

1.  **Stage 1: Global Route Encoding (The "Knowledge" Layer)**
    *   **Discretization:** Using the **entire 55M row dataset**, discretize the `pickup` and `dropoff` coordinates into spatial grid buckets (Geohashes or high-resolution bins) **Cite {solution_lesson_node_00038}**.
    *   **K-Fold Target Encoding:** Calculate the **Mean Fare** for every unique `(Pickup_Bin, Dropoff_Bin)` route. To prevent data leakage, perform this using a K-Fold strategy (e.g., 5 folds): for rows in Fold 1, the "Route Avg Fare" feature is calculated using data from Folds 2-5.
    *   **Significance:** This explicitly encodes complex pricing dynamics (like airport flat rates or tolls) that simple distance metrics miss, significantly improving performance even with smaller training sets **Cite {solution_lesson_node_00038}**.

2.  **Stage 2: Training Set Construction (The "Learning" Layer)**
    *   **Subsampling:** Select a random subsample of approximately **5 million rows** for the actual model training. This avoids the gradient explosion and convergence failure observed when training on the full 55M dataset **Cite {solution_lesson_node_00017}**.
    *   **Input Sanitization:** Strictly clamp all pickup and dropoff coordinates in this subsample (and the test set) to the valid NYC bounding box. This prevents the linear extrapolation of massive distances from corrupt GPS data **Cite {solution_lesson_node_00003}**.
    *   **Target Preservation:** Use the **raw `fare_amount`** as the target. Do **not** truncate high fares (e.g., >$500) and do **not** log-transform the target. Truncation destroys the model's ability to predict valid outliers **Cite {solution_lesson_node_00018}**, and log-transformation biases the RMSE metric **Cite {solution_lesson_node_00025}**.

# Training
1.  **Objective Function:** Use **`reg:squarederror`** (Standard L2 Loss).
    *   **Rationale:** Because we are training on a stable subsample (where extreme outliers are less dominant) and the input features now include robust "Expected Fare" priors, we can safely use the loss function that aligns perfectly with the evaluation metric (RMSE). We avoid robust losses like Huber, which were shown to underperform on this specific metric because they ignore the heavy tail **Cite {solution_lesson_node_00037}**.
2.  **Feature Set:** The model will be trained on:
    *   **Global Route Avg Fare** (from Stage 1).
    *   **Geometric Features:** Haversine distance, Manhattan distance, and Rotated Coordinates (to capture the street grid).
    *   **Temporal Features:** Hour, Day, Year.

# Evaluation
1.  **Global Lookup:** For the test set, generate the `Route_Avg_Fare` feature using the statistics computed from the **entire 55M row training set** (no folding required for inference). If a test route was never seen in the full history, fallback to a global distance-based estimate.
2.  **Prediction:** Generate predictions using the XGBoost model.
3.  **Post-Processing:** Apply a minimum fare floor (e.g., $2.50) to ensure physical validity.
