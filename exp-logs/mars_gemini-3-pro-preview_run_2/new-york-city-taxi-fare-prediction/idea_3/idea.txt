Based on the lessons learned from the previous experiments, I propose an **Ensemble of Subsampled XGBoost Regressors** (Bagging). This strategy addresses the stability issues of training on the full dataset while avoiding the pitfalls of blind data truncation.

# Model
I propose replacing the single monolithic model with a **Bagging Ensemble**. The architecture will consist of $K$ independent **XGBoost Regressors** (e.g., $K=5$ to $10$).
*   **Rationale:** Lesson 00017 demonstrated that a single model trained on the full 44M row dataset was unstable and performed worse (RMSE 23.25) than a model trained on just 5M rows (RMSE 4.28). This was due to the accumulation of gradients from extreme outliers in the massive dataset. By breaking the problem into an ensemble of models trained on smaller subsamples, we replicate the stability of the successful "small data" experiment (Cite {solution_lesson_node_00017}) while effectively utilizing the entire dataset through aggregation.
*   **Backbone:** Each estimator in the ensemble will be a Gradient Boosted Decision Tree using the GPU-accelerated `hist` tree method.

# Data
The data pipeline will be refined to handle outliers intelligently, resolving the conflict between "outliers cause instability" and "removing outliers destroys RMSE".

1.  **Input Sanitization (Clamping):**
    *   Apply strict bounding box clamping (e.g., Lat 40-42, Lon -75 to -72) to the **pickup and dropoff coordinates** in the Training, Validation, and Test sets. This prevents the generation of massive distance features from corrupt GPS data, which was the root cause of the linear model's failure (Cite {solution_lesson_node_00003}).

2.  **Target Sanitization (Physics-Consistency Filtering):**
    *   Instead of blindly truncating the target distribution (e.g., removing all fares > $500), which caused the model to underpredict valid high-fare rides in the validation set (Cite {solution_lesson_node_00018}), I will implement **Consistency Filtering**.
    *   Calculate a `fare_per_unit_distance` metric. Remove rows only if they are **inconsistent** (e.g., High Fare > $100 AND Distance < 1km). This removes the "garbage" noise that destabilizes the L2 loss (Cite {solution_lesson_node_00017}) while preserving legitimate long-distance/high-fare samples needed to predict the "tail" of the distribution (Cite {solution_lesson_node_00018}).

3.  **Feature Engineering:**
    *   **Distance Metrics:** Haversine and Manhattan distances.
    *   **Rotated Coordinates:** Create features representing a 45-degree rotation of the coordinate system (e.g., `lat + lon`, `lat - lon`). This allows the decision trees (which make axis-aligned cuts) to better approximate distances on the diagonal NYC street grid.

# Training
1.  **Subsampling Strategy:**
    *   Randomly partition the training data (or sample with replacement) into $K$ subsets, each containing approximately 5-10 million rows.
    *   Train one XGBoost model on each subset. This ensures each model converges stably (as seen in Idea 2) without being overwhelmed by the cumulative noise of 55M rows.

2.  **Loss Function:**
    *   Use **Squared Error (RMSE)**. Since the "garbage" outliers have been removed via Consistency Filtering, the standard L2 loss will focus on fitting the valid data distribution without diverging.

# Evaluation
1.  **Inference:**
    *   Generate predictions for the test set using all $K$ models in the ensemble.
2.  **Aggregation:**
    *   Compute the **mean** of the predictions. This averaging process will further smooth out variance and improve generalization compared to any single model.
3.  **Post-Processing:**
    *   Apply a minimum fare floor (e.g., $2.50) to the final averaged prediction.
