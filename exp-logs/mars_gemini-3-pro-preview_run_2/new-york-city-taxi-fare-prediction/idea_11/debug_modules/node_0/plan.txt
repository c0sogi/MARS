The following implementation demonstrates the usage of the provided library modules for the NYC Taxi Fare Prediction task.

### Strategy Outline
1.  **Configuration Override**: To ensure the demonstration runs quickly (seconds instead of hours), we override the default `Config` paths and hyperparameters. We direct the pipeline to use a temporary working directory and significantly reduce the number of boosting rounds and data subsample sizes.
2.  **Mock Data Generation**: Instead of loading the full 55 million row dataset, we create small, synthetic training and validation datasets (based on the provided test set structure) in the `./working` directory. We then point the `Config` input paths to these small files. This validates the data loading logic without the memory/time overhead of the full dataset.
3.  **Component Verification**: We systematically instantiate and verify each component of the pipeline:
    *   **Utils**: Verify distance calculations and coordinate clamping.
    *   **DataFactory**: Verify data loading and physics-based filtering.
    *   **KnowledgeBase**: Verify the generation of hierarchical statistical priors (Fine/Coarse grids).
    *   **FeatureEngineer**: Verify the calculation of base margins and residuals.
    *   **ModelTrainer**: Execute a full training cycle and generate a submission file using the `ResidualXGBRegressor`.
4.  **Assertions**: Logic checks are embedded throughout to ensure the pipeline functions as expected (e.g., checking that residuals are calculated correctly).
