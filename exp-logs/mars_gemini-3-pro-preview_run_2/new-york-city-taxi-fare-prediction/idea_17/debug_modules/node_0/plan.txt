### Implementation Strategy

1.  **Configuration Patching for Speed**:
    *   The default configuration points to the full 44M+ row dataset and uses 5,000 boosting rounds. To ensure the script completes quickly (within minutes), we will create a small subset (10,000 rows) of the training data in the `./working` directory.
    *   We will dynamically modify the `library.config` module variables (`TRAIN_DATA_PATH`, `TRAIN_SAMPLE_SIZE`, `XGB_PARAMS`) to point to this small dataset and reduce the training iterations to 10.

2.  **Spatial Operations Verification**:
    *   We will create a synthetic DataFrame with known coordinates (including some out-of-bounds values) to verify the `clamp_coordinates`, `haversine_distance`, and `get_spatial_grid_id` functions from `library.spatial_ops`.

3.  **Pipeline Execution**:
    *   We will instantiate the `PipelineProcessor` from `library.feature_builder`.
    *   We will execute `process_data(load_cached_data=False)` to force the pipeline to run from scratch using our patched small dataset.
    *   We will validate the resulting DataFrames (`train`, `val`, `test`) to ensure feature engineering (e.g., `dist_haversine`, `route_mean_fare`) was applied correctly.

4.  **Model Training and Prediction**:
    *   We will instantiate the `XGBTrainer` from `library.model_trainer`.
    *   We will train the model on the processed data.
    *   We will generate predictions for the test set and verify that the output values are valid (e.g., non-negative, above the minimum fare).

5.  **Submission Generation**:
    *   We will use the trainer to generate the `submission.csv` file and verify its format against the requirements.
