To establish a reliable performance baseline for the NYC Taxi Fare Prediction task, I propose a **Physics-Informed Linear Regression** approach. This solution prioritizes interpretability, speed, and resource efficiency by relying on domain-specific feature engineering rather than complex model architectures.

### Model
The architecture is a **Regularized Linear Regression** model (specifically Ridge Regression). Instead of relying on the model to learn spatial relationships from raw coordinates (which linear models struggle with), we explicitly encode the physical determinants of a taxi fare—distance and time—into the input features.
*   **Architecture**: A single dense layer mapping engineered features to the target `fare_amount`.
*   **Equation**: $y = \sum (w_i \cdot x_i) + b$, where $x_i$ represents calculated distances, time attributes, and location flags.

### Data
Preprocessing and feature engineering are the critical components of this baseline to ensure the linear model receives meaningful signals.
1.  **Cleaning**:
    *   Filter the training data to remove anomalies: rows with coordinates outside the valid NYC bounding box (based on EDA ranges), negative fare amounts, and passenger counts of zero.
    *   Drop rows with missing values (NaNs) to maintain data integrity.
2.  **Feature Engineering**:
    *   **Distance Metrics**: Calculate the **Haversine distance** (great-circle distance) and **Manhattan distance** (sum of absolute latitude/longitude differences) between pickup and dropoff points. These serve as direct proxies for the "distance traveled," which is the primary driver of cost.
    *   **Temporal Features**: Extract **Year** (to capture inflation and base rate changes) and **Hour of Day** (to capture traffic density and night surcharges).
    *   **Airport Flags**: Create binary indicators (0/1) for pickups or dropoffs occurring within fixed bounding boxes of major airports (JFK, LaGuardia, Newark), as these routes often have fixed-rate fares distinct from the standard distance metering.
3.  **Normalization**: Apply Z-score standardization (subtract mean, divide by standard deviation) to all input features. This is essential for linear regression to ensure that features with larger magnitudes (like Year) do not disproportionately influence the gradients.

### Training
1.  **Algorithm**: Use **Stochastic Gradient Descent (SGD)** with a regression objective. SGD is highly efficient for large-scale datasets (55M rows) as it updates weights iteratively without requiring the entire dataset to be loaded into memory simultaneously.
2.  **Loss Function**: **Mean Squared Error (MSE)** combined with **L2 Regularization (Ridge)**. The regularization term penalizes large weights, preventing the model from overfitting to outliers or noise in the GPS data.
3.  **Optimization**: Train for a fixed number of epochs (e.g., 1-5) with a learning rate scheduler (e.g., `invscaling`) to converge quickly.

### Evaluation
1.  **Inference**: Apply the same feature engineering and normalization pipeline to the `test.csv` data.
2.  **Prediction**: Compute the weighted sum of the processed test features using the learned model parameters.
3.  **Post-Processing**: Enforce a lower bound on predictions (e.g., `max(prediction, 2.50)`) to ensure no predicted fare is below the minimum base rate or negative.
