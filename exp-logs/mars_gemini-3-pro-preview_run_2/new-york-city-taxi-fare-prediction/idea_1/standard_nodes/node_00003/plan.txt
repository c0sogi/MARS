The previous implementation failed because the validation dataset contains missing values (NaNs) in the dropoff coordinates, which resulted in NaN values in the engineered features (distances). The `SGDRegressor` model does not support NaNs, causing the crash. Additionally, the system attempted to load a corrupted cache file (`X_val.npy`) from a previous run instead of recomputing the features, which would have persisted the error even after a code fix.

To resolve this, I will:
1.  Update `library/config.py` to change the `CACHE_DIR` to `idea_1_v2`. This deterministically invalidates the old cache and forces the pipeline to re-process the data from scratch. Cite debug_lesson_1.
2.  Update `library/feature_engineering.py` in the `transform` method to impute missing values in the raw feature matrix (`X_raw`) using the feature means from the training set (stored in `self.scaler.mean_`). This ensures that rows with missing coordinates are filled with the average values before scaling, preventing NaNs from reaching the model.
