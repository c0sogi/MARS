The issue is a mismatch between the feature configuration and the feature engineering implementation. The `library/dataset.py` script intentionally restricts lag features to 1st and 2nd order (`u_in_diff1`, `u_in_diff2`) to avoid noise amplification, as documented in the code comments. However, `library/config.py` still lists `u_in_diff3` and `u_in_diff4` in `CONTINUOUS_FEATURES`, causing a `KeyError` when the preprocessor attempts to access these non-existent columns for scaling.

To fix this, I will update `library/config.py` to remove `u_in_diff3` and `u_in_diff4` from the `CONTINUOUS_FEATURES` list. This ensures the configuration is synchronized with the actual features generated by the pipeline (Cite debug_lesson_2).
