The following strategy outlines the implementation of the demonstration script:

1.  **Configuration Setup**: We will import the `Config` class and override specific parameters (e.g., `WORKING_DIR`, `EPOCHS`, `DEBUG`) to ensure the script runs quickly and in isolation. Crucially, we will update dependent file paths (like cache paths) that were initialized at import time to reflect the new working directory.
2.  **Data Loading Demonstration**: We will utilize `get_dataloaders` with the debug flag enabled. We will assert the correctness of the batch shapes (Batch Size, Sequence Length, Feature Dimensions) and data types for training, validation, and test sets.
3.  **Model Initialization and Forward Pass**: We will instantiate the `DGC_BiLSTM` model and perform a forward pass with a single batch of data. We will verify that the output shape matches the expected `(Batch Size, Sequence Length)` structure.
4.  **Loss Function Verification**: We will instantiate the `WeightedL1Loss` class and calculate the loss for the sample batch. We will perform a manual calculation check to ensure the inspiratory/expiratory weighting logic is applied correctly.
5.  **Training Loop Simulation**: Instead of running the full `run_training` pipeline which might be too heavy, we will manually execute `train_one_epoch` and `validate` for a single epoch. This demonstrates how the training components interact while keeping runtime minimal.
6.  **Inference**: We will run the model on the test loader to demonstrate how to generate predictions.
