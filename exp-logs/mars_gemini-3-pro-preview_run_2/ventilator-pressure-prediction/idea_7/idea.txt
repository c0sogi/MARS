# Model: Deep Projected-Injection BiLSTM (DPI-BiLSTM)

I propose a **Unified Deep Recurrent Architecture** that specifically solves the "Signal Dilution" problem identified in previous unified attempts while avoiding the limitations of branched architectures.

*   **Latent Input Projection (Structural Innovation):**
    *   Instead of feeding raw features directly into the LSTM or concatenating low-dimensional raw features to deep layers (which leads to signal dilution, Cite solution_lesson_node_00028), the model will first pass the input sequence through a **Non-Linear Projection Block** (a Dense layer followed by activation).
    *   This projects the $\approx 15$ raw features into a high-dimensional latent space (e.g., 512 dimensions), creating a rich "Context Signal" that carries significant statistical weight.
*   **Deep Recurrent Backbone with Projected Injection:**
    *   The core will consist of **4 to 6 layers of Bidirectional LSTMs**.
    *   We will implement **Latent Input Injection**: The high-dimensional "Context Signal" generated above will be concatenated to the input of **every** LSTM layer in the stack (Cite solution_lesson_node_00021). This ensures that even the deepest layers have direct, high-fidelity access to the physical control signals (Flow, Resistance, Compliance) required to solve the differential equations, without the signal being "washed out" by recurrent state transitions.
    *   This unified approach allows the model to learn complex non-linear cross-terms between "instantaneous" and "cumulative" dynamics, which branched/dual-stream architectures fail to capture (Cite solution_lesson_node_00025).
*   **Stabilization:**
    *   We will apply **Layer Normalization** after every recurrent block to stabilize the hidden state dynamics and enable deeper training (Cite solution_lesson_node_00023).
    *   We explicitly reject CNN stems (Cite solution_lesson_node_00017) and Transformer blocks (Cite solution_lesson_node_00012) to maximize training throughput.

# Data: Physics-Fidelity Feature Engineering

We will strictly adhere to the feature engineering protocols that preserve the continuous nature of the physical signals, ensuring the "Context Signal" contains all necessary components for the Equation of Motion.

*   **Integral Features:** Explicitly generate `u_in_cumsum` to represent Air Volume, relieving the LSTM of the linear integration task (Cite solution_lesson_node_00003).
*   **Interaction Features:** Explicitly calculate the physical interaction terms `R * u_in` (Resistive Pressure) and `u_in_cumsum / C` (Elastic Pressure) (Cite solution_lesson_node_00004).
*   **Derivative Features:** Augment the input with **Lag features** and **Finite Differences** (1st and 2nd derivatives of `u_in`) to provide explicit velocity and acceleration data (Cite solution_lesson_node_00008).
*   **Signal Preservation:** Treat Lung Resistance (`R`) and Compliance (`C`) strictly as **continuous numerical features**. We will **not** use embeddings, preserving the ordinal magnitude information required for the physics calculations (Cite solution_lesson_node_00018).
*   **Normalization:** All inputs will be scaled using RobustScaler.

# Training: Long-Tail Convergence Protocol

*   **Loss Function:** We will use a **Weighted L1 Loss**, assigning a weight of **1.0** to the inspiratory phase and **0.1** to the expiratory phase. This focuses capacity on the metric while maintaining the temporal context required for stable hidden states (Cite solution_lesson_node_00021).
*   **Optimizer:** We will use **AdamW** with a **Cosine Annealing** scheduler.
*   **Extended Duration:** We will set the training duration to **150+ epochs**.
    *   Previous experiments showed that deep recurrent models on this physical task exhibit "long-tail convergence," where significant error reduction (e.g., ~24%) occurs *after* epoch 50 (Cite solution_lesson_node_00029).
    *   By utilizing the high-throughput LSTM architecture (avoiding CNN/Attention overhead), we can fit this extended training regimen within the compute budget (Cite solution_lesson_node_00005).
