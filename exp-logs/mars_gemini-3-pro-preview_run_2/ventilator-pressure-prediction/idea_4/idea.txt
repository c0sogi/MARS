# Model: Deep Residual Bidirectional LSTM (Res-BiLSTM)

I propose a **Deep Residual Bidirectional LSTM** architecture. This design directly addresses the need for increased model capacity (Cite Lesson 00005) while strictly adhering to the findings that pure recurrent architectures outperform hybrids for this specific physical task (Cite Lesson 00012) and that signal fidelity is paramount (Cite Lesson 00018).

*   **Input Projection:** The input sequence will pass through a single Linear layer to project the engineered feature set into a high-dimensional latent space (e.g., 512 or 1024 units).
*   **Deep Recurrent Backbone:** The core will consist of **4 to 6 layers of Bidirectional LSTMs**.
    *   **Innovation (Dense Residual Connections):** Unlike the standard stacked LSTM used in previous baselines, we will implement **Dense Residual Connections**. The input to layer $N$ will be the concatenation of the output of layer $N-1$ and the original input projection.
    *   **Rationale:** Lesson 00018 highlighted that deep feature extractors (like CNNs) distort the precise numerical magnitudes required for physics-based regression. By concatenating the original input at every layer, we ensure that the raw physical signals (Flow, Resistance, Compliance) are available to the deepest layers of the network. This combats the vanishing gradient problem and allows us to train a much deeper network than the previous 2-layer baseline without losing the "Equation of Motion" inductive bias.
*   **Regression Head:** A final fully connected layer will map the LSTM outputs to the scalar pressure prediction.
*   **Exclusion of Complex Blocks:** We explicitly reject Transformer blocks (Cite Lesson 00012) and CNN stems (Cite Lesson 00017) to maximize training throughput, ensuring we can reach convergence within the compute budget.

# Data: Physics-Informed Feature Engineering

We will rigorously apply the feature engineering protocols proven to be effective, while correcting the data representation errors from Idea 3.

*   **Physics-Based Integration:** We will explicitly generate the `u_in_cumsum` feature to represent cumulative air volume (Cite Lesson 00003).
*   **Equation of Motion Interactions:** We will calculate and include the interaction terms `R * u_in` (resistive pressure) and `u_in_cumsum / C` (elastic pressure) (Cite Lesson 00004).
*   **Explicit Dynamics:** We will augment the input with **Lag features** (previous 1-4 time steps) and **Finite Difference features** (1st and 2nd derivatives of `u_in`) (Cite Lesson 00008).
*   **Correction on Constants:** We will treat Lung Resistance (`R`) and Compliance (`C`) strictly as **continuous numerical features**. We will **not** use categorical embeddings, as Lesson 00018 demonstrated that embeddings destroy the ordinal/ratio information necessary for the model to learn the mathematical relationships between these physical constants and pressure.
*   **Normalization:** All features will be scaled using RobustScaler to handle outliers in the control input.

# Training: Extended Convergence Protocol

*   **Loss Function:** We will minimize the **Mean Absolute Error (L1 Loss)** computed over the **entire breath sequence**. Although the metric only scores the inspiratory phase, we retain the full-sequence training to force the model to learn the complete inflation/deflation dynamics, which stabilizes the hidden states (Cite Lesson 00003).
*   **Optimizer:** We will use **AdamW** with a **Cosine Annealing** scheduler.
*   **Throughput & Duration:** By utilizing the lightweight Res-BiLSTM architecture (avoiding the computational overhead of Attention/Convolution), we will maximize the epochs-per-second throughput (Cite Lesson 00017). This allows us to extend the training duration to **50+ epochs** within the 24-hour limit, ensuring the deep model fully converges (Cite Lesson 00005).

# Evaluation

*   **Inference:** The model will predict the pressure sequences for the test set in batches, utilizing `test_metadata.csv`.
*   **Post-Processing:** The output sequences will be flattened and mapped to the `id` column for submission.
*   **Validation:** We will monitor the MAE on the validation set, specifically analyzing the performance on high-Resistance breaths, as these were identified as the primary source of error (Cite Lesson 00003).
