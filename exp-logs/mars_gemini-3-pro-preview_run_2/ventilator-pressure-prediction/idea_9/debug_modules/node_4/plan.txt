The issue lies in the `__init__` method of the `SC_GI_BiLSTM` class in `library/model.py`. When initializing the model without explicit arguments (as done during inference), the `bidirectional` argument defaults to `None`. The code incorrectly uses this raw `None` value to calculate `self.num_directions`, resulting in a unidirectional model (1 direction) even when `self.bidirectional` correctly resolves to `True` from the configuration. This causes a shape mismatch when loading weights from a bidirectional model checkpoint. To fix this, I will update the code to use the resolved `self.bidirectional` attribute for the calculation, ensuring the model structure matches the configuration. Cite debug_lesson_5.
