This strategy outlines the implementation of the `runfile.py` orchestration script. The script is designed to serve as a fast baseline by optimizing training parameters while ensuring rigorous validation and failure analysis.

1.  **Configuration & Setup**: The script starts by importing necessary modules and the provided library components. It overrides default `Config` parameters to `EPOCHS=10` and `BATCH_SIZE=512` to ensure the training completes quickly (within ~30 minutes on an A100) while still converging sufficiently. It sets the random seed for reproducibility.
2.  **Data Preparation**: It calls `prepare_datasets` to load or generate the feature-engineered data. To strictly adhere to the "fast baseline" constraint, it subsets the training data to 50% of the breaths using `torch.utils.data.Subset`. Crucially, it retains the **full** validation set to ensure the final metric is directly comparable to the required threshold.
3.  **Training Loop**: The script initializes the `GIDBiLSTM` model, `WeightedL1Loss`, `AdamW` optimizer, and `CosineAnnealingLR` scheduler. It runs a training loop for 10 epochs, monitoring the validation MAE and saving the best model checkpoint.
4.  **Validation & Failure Analysis**: After training, the best model is reloaded. The script computes the final MAE on the entire validation set. It then performs failure analysis by calculating the absolute error for each inspiratory time step and computing the Pearson correlation between this error and every input feature. This identifies which physical conditions (e.g., high `u_in`, specific `R`/`C` values) are associated with higher model error.
5.  **Submission**: Finally, the script compares the `Final Validation Metric` against the threshold `0.19242813024255964`. If the model's performance is better (lower) than the threshold, it generates predictions for the test set, formats them according to `test_metadata.csv`, and saves the `submission.csv`.
