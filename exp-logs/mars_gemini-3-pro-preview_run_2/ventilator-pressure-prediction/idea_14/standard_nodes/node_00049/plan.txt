The implementation strategy follows a streamlined pipeline designed to balance the constraints of a "Fast Baseline" (2-hour limit) with the need for high model performance to meet the strict submission threshold.

1.  **Configuration Overrides**: We first override the default `Config` parameters. We set `EPOCHS` and `T_MAX` to 30, which allows the model to converge sufficiently on the powerful A100 GPU (approx. 212 steps per epoch) without exceeding the runtime limit. We explicitly disable `DEBUG` mode to ensure the model trains on the full dataset for maximum accuracy.
2.  **Data Loading**: We utilize the `get_data_loaders` function with `load_cached_data=True`. This leverages the pre-processed Parquet files in the working directory, significantly reducing startup time.
3.  **Training**: We instantiate the `Trainer` class and run the `fit` method. This handles the entire training loop, including loss calculation (Weighted L1), backpropagation, scheduler stepping (Cosine Annealing), and saving the best model checkpoint based on validation MAE.
4.  **Validation & Failure Analysis**:
    *   We reload the best model checkpoint to ensure we evaluate the optimal state.
    *   We run a custom inference loop on the validation set to collect predictions, targets, and input features.
    *   We filter for the inspiratory phase (`u_out == 0`) and calculate the `Final Validation Metric` (MAE).
    *   We compute the absolute error for each prediction and calculate its Pearson correlation with every input feature to identify error drivers.
5.  **Conditional Submission**: We compare the calculated validation MAE against the strict threshold (`0.1619843989610672`). If the model passes, we invoke `generate_submission` to create the final `submission.csv`; otherwise, we skip this step to adhere to the requirements.
