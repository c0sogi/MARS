### Implementation Strategy

1.  **Configuration Override**: To ensure the demonstration runs quickly and fits within the "demo" scope, I will override specific `Config` class attributes at runtime. This includes enabling `DEBUG` mode (to use data subsets), reducing `EPOCHS` to 1, disabling `SWA`, and switching the model architecture to a lightweight `resnet18` to minimize compute time.
2.  **Utility Verification**: I will demonstrate and verify the core utility functions (`calculate_roc_auc`, `rank_normalize`, `reconstruct_probabilities`) using synthetic numpy arrays to ensure mathematical correctness.
3.  **Component Testing**:
    *   **Dataset**: I will load the dataframes using `get_dataframes`, instantiate the `AppleDataset`, and verify that the `DataLoader` yields batches of the correct shape and type.
    *   **Model**: I will instantiate the `AppleDiseaseModel` with the lightweight architecture and perform a dummy forward pass to confirm the output dimensions match `[Batch Size, Num Classes]`.
4.  **Pipeline Execution**:
    *   **Training**: I will execute `run_training()`. This will use the overridden configuration to train the lightweight model for one epoch on a small subset of data and save the checkpoint.
    *   **Inference**: I will execute `run_inference()`. This will load the checkpoint saved in the previous step, perform inference on the test set (also a subset due to `DEBUG` mode), and generate the submission file.
5.  **Final Validation**: I will check for the existence of the submission file and verify its dimensions and content format.
