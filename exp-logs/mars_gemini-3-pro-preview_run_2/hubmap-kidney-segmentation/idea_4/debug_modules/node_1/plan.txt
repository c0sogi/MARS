The `RuntimeError` occurs because the `MultiTaskLoss` class slices the target tensor (`targets[:, 0, :, :]`) to isolate the primary task channel. This slicing operation returns a non-contiguous view of the original tensor. When this non-contiguous tensor is passed to `DiceLoss`, the `.view(-1)` method fails because it strictly requires contiguous memory layout.

To fix this, I will replace `.view(-1)` with `.reshape(-1)` in `library/loss.py`. The `.reshape()` method is robust to memory layout: it returns a view if the tensor is contiguous or creates a copy if it is not, effectively resolving the stride incompatibility caused by the slicing.
