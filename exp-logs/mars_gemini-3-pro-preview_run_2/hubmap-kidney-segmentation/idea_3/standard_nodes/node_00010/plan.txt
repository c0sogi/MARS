The implementation strategy follows the end-to-end machine learning lifecycle adapted for a fast baseline execution.

1.  **Configuration & Setup**: We import the provided `Config` class and override the training parameters (`EPOCHS`, `WARMUP_EPOCHS`, `EARLY_STOPPING_PATIENCE`) to ensure the pipeline completes rapidly (within minutes) while still verifying the learning capability. Random seeds are set for reproducibility.
2.  **Training**: We invoke the `run_training()` function from the provided library. This function handles the initialization of the `AttentionUNetResNet34` model, the `BCEDiceLoss`, and the data loaders (using cached tiles if available). It executes the training loop with cosine annealing and saves the best model based on validation Dice score.
3.  **Validation & Metrics**: We implement a custom validation routine `run_validation_and_analysis`. Unlike the training loop which validates on image tiles, this routine performs inference on the **full-resolution validation images** using a sliding window approach with Gaussian smoothing. It applies the anatomical mask post-processing filter to strictly constrain predictions to the renal cortex. It calculates the Dice coefficient for each image and computes the global mean Dice score, printing it in the required format: `Final Validation Metric: <value>`.
4.  **Failure Analysis**: Within the validation routine, we calculate the prediction error (`1 - Dice`) for each image. We then compute the Pearson correlation coefficient between this error and various metadata features (e.g., `age`, `bmi`, `percent_cortex`) to identify potential biases or failure modes.
5.  **Submission**: Finally, the script checks if the `Final Validation Metric` exceeds the threshold of `0.8873`. If successful, it calls `generate_submission()`, which processes the test set, generates RLE-encoded masks, and saves the `submission.csv` file.
