The `ZeroDivisionError` is caused by the training `DataLoader` configuration in `library/data.py`. Specifically, `drop_last=True` is used, which discards the last batch if it's smaller than the batch size. In the test execution (`runfile.py`), `max_train_samples` is set to 4 while `batch_size` defaults to 8. This results in the only available batch being dropped, creating an empty `DataLoader` (`len(loader) == 0`). Consequently, the division `running_loss / len(loader)` in `library/train.py` fails.

To fix this, I will:
1.  Modify `library/data.py` to dynamically set `drop_last` to `False` if the dataset size is smaller than the batch size, ensuring at least one batch is generated during testing/debugging.
2.  Update `library/train.py` to handle the case where `len(loader)` is 0 (e.g., empty dataset) to prevent the crash.
