Based on the empirical history and lessons learned, I propose the **Wide-Context SegFormer (MiT-B4) with Learnable Z-Compression**.

This strategy introduces a structural innovation to decouple the volumetric input depth from the pretrained backbone's channel constraints. By employing a **Learnable Channel Compressor** with a specific **Identity Initialization**, we can ingest a wider Z-volume (5 overlapping slabs) to capture wandering ink strokes, while strictly preserving the transfer learning benefits of the 3-channel baseline.

### Model
**Architecture:** I propose upgrading the backbone to the **SegFormer MiT-B4** (Mix Transformer B4).
*   **Backbone:** The **MiT-B4** encoder (~64M parameters) offers significantly higher capacity and a larger receptive field than the MiT-B2/B3 used in previous iterations. This allows the model to model more complex, long-range spatial dependencies in the ink strokes (Cite Lesson 00024).
*   **Structural Innovation (Input Adapter):** To address the "Signal Dilution" risk of modifying the backbone (Cite Lesson 00025) while overcoming the limited Z-view of the 3-channel input (Cite Lesson 00026), I propose prepending a **Learnable Channel Compressor** to the network.
    *   This is a lightweight `Conv2d(5, 3, kernel_size=1)` layer.
    *   It accepts a **5-channel** input tensor (representing a wider volumetric range) and projects it to the **3-channel** format required by the pretrained SegFormer.
*   **Identity Initialization (Crucial):** To prevent the "Random Initialization" failure (Cite Lesson 00024) and preserve the proven efficacy of the 3-channel overlapping baseline (Cite Lesson 00029), the adapter weights will be manually initialized to perform an **Identity Mapping** for the central 3 channels.
    *   Weights for Input Channels 2, 3, and 4 will be set to map directly to Output Channels 1, 2, and 3 respectively.
    *   Weights for the new "outer" Input Channels 1 and 5 will be initialized to zero.
    *   *Rationale:* This ensures that at Epoch 0, the model is mathematically equivalent to the successful "Idea 7/8" baseline. During training, the model will gradually learn to incorporate information from the outer slabs (Channels 1 & 5) only if they provide useful signal, effectively expanding its Z-context without destabilizing convergence.

### Data
**Preprocessing:**
*   **Wide-Context Overlapping Stratified Projection:** We will expand the input representation from 3 to **5 Overlapping Thick Slabs** to cover a wider depth range (approx. slices 14-50) and capture ink strokes that deviate significantly from the mean surface.
    *   **Channel 1:** MIP of slices **14-26** (12 slices).
    *   **Channel 2:** MIP of slices **20-32** (12 slices).
    *   **Channel 3:** MIP of slices **26-38** (12 slices).
    *   **Channel 4:** MIP of slices **32-44** (12 slices).
    *   **Channel 5:** MIP of slices **38-50** (12 slices).
    *   *Rationale:* We retain the "Thick Slab" (12 slices) and "Overlap" (50%) principles to preserve signal continuity (Cite Lesson 00026, 00029), but expand the field of view to handle Z-axis outliers.
*   **Normalization:** Pixel values normalized to [0, 1] using dataset statistics.

**Augmentation:**
*   **Volumetric Z-Jitter:** During training, we will randomly shift the start index of the 5-slab window by $\pm N$ slices (Cite Idea 8). This forces the model to learn features invariant to absolute depth.
*   **Geometric Only:** Random horizontal/vertical flips and 90-degree rotations.
*   **Intensity Constraints:** Explicitly **exclude** brightness/contrast augmentations to preserve physical radiodensity semantics (Cite Lesson 00006).

### Training
*   **Loss Function:** **BCE + Dice Loss**. We avoid Tversky Loss as it previously failed to improve the F0.5 score (Cite Lesson 00031).
*   **Optimizer:** **AdamW** with `ReduceLROnPlateau`.
*   **Validation Gating:** The execution script will implement a strict logic gate. The submission file will **only** be generated if the current model's best validation F0.5 score exceeds the previous best baseline (approx 0.598). This prevents inferior stochastic runs from overwriting the best result (Cite Lesson 00004).

### Evaluation
*   **Defensive Inference:** The inference pipeline will explicitly check the input tensor shape to ensure it matches `(Batch, 5, H, W)` before processing (Cite Lesson 00005).
*   **Test Time Augmentation (TTA):** We will average predictions from the original input and its geometric transformations (flips/rotations).
*   **Fixed Window:** During inference, we use the standard centered slice ranges (14-50) without jitter.
