The issue stems from incorrect normalization of the ground truth labels in `library/data.py`. The labels are loaded as 8-bit integers (0-255) but are cast directly to float without scaling, causing the metric calculation to use values like 255.0 instead of 1.0, resulting in impossible F-scores (>1.0). To fix this, I will modify the dataset class to threshold labels into binary values (0.0 or 1.0). Additionally, I will lower the validation thresholds in `library/config.py` and `runfile.py` to 0.0. This ensures that the newly trained (valid) models overwrite the previous invalid checkpoints and that a submission file is generated for verification regardless of the initial score, as recommended in **debug_lesson_6** (Cite debug_lesson_6).
