Based on the comprehensive empirical history and lessons learned, I propose the **SegFormer MiT-B3 with Volumetric Z-Jitter**.

This strategy evolves the most successful architecture (SegFormer, Idea 7) by scaling up the backbone to **MiT-B3** and introducing a domain-specific **Volumetric Z-Jitter** augmentation. This addresses the "Signal Dilution" and "Depth Variance" issues by forcing the model to learn robust features invariant to the precise depth location of the ink, while strictly adhering to the 3-channel constraint required for effective transfer learning.

# Model
**Architecture:** I propose upgrading the backbone to the **SegFormer MiT-B3** (Mix Transformer B3).
*   **Backbone:** The **MiT-B3** encoder offers a larger receptive field and higher parameter count (~45M) compared to the MiT-B2 (~25M) used in Idea 7. Given that the Transformer architecture successfully captured global context where CNNs failed (Cite Lesson 00024), scaling up the capacity of this specific architecture allows for more granular distinction between ink strokes and papyrus fibers without the instability observed in deep CNNs (Cite Lesson 00014).
*   **Input Interface:** We strictly maintain the **3-channel input interface**. This ensures we can utilize **ImageNet-pretrained weights** without modification, avoiding the catastrophic failure of random initialization (Cite Lesson 00024) or the feature destruction caused by channel expansion (Cite Lesson 00025).
*   **Decoder:** The standard MLP decoder aggregates multi-scale features from the B3 encoder to predict the binary mask.

# Data
**Preprocessing:**
*   **Overlapping Stratified Depth Projection:** We retain the highly effective "Overlapping Thick Slab" strategy (Cite Lesson 00029). We define a central Z-volume and split it into three **overlapping, thick Maximum Intensity Projections (MIPs)**.
    *   **Channel 1 (Top):** MIP of slices **20-32** (12 slices).
    *   **Channel 2 (Middle):** MIP of slices **26-38** (12 slices).
    *   **Channel 3 (Bottom):** MIP of slices **32-44** (12 slices).
    *   *Rationale:* This 50% overlap ensures that ink strokes at the boundaries of one slab are fully captured in the center of the adjacent slab, preserving morphological continuity (Cite Lesson 00029). We use MIP to preserve the sparse high-intensity ink signal (Cite Lesson 00015).
*   **Normalization:** Pixel values are normalized to [0, 1] using dataset statistics.

**Augmentation:**
*   **Structural Innovation: Volumetric Z-Jitter:** I introduce a new augmentation strategy called **Z-Jitter**. During training, instead of always extracting the fixed ranges defined above (starting at slice 20), we randomly shift the start index of the entire block by $\pm N$ slices (e.g., randomly selecting a start index between 18 and 22).
    *   *Rationale:* Ink depth varies naturally across the scroll fragments. By jittering the Z-window, we simulate these depth variations, forcing the model to become invariant to the absolute Z-position of the ink and focus on the relative structural cues within the overlapping channels.
*   **Geometric Only:** Random horizontal/vertical flips and 90-degree rotations.
*   **Intensity Constraints:** We explicitly **exclude** brightness, contrast, and gamma augmentations. The model relies on physical radiodensity to distinguish ink, and intensity perturbations destroy this signal (Cite Lesson 00006).

# Training
*   **Initialization:** Load **ImageNet-pretrained weights** for the MiT-B3 model (Cite Lesson 00024).
*   **Loss Function:** Use **BCE + Dice Loss**. We reject Tversky Loss as previous experiments showed it failed to improve the F0.5 score compared to the standard balanced Dice Loss (Cite Lesson 00031).
*   **Validation Gating:** The execution script will implement a strict logic gate. The submission file will **only** be generated if the current model's best validation F0.5 score exceeds the previous best baseline (0.588). This prevents inferior stochastic runs from overwriting the best result (Cite Lesson 00004).
*   **Optimizer:** AdamW optimizer with a `ReduceLROnPlateau` scheduler.

# Evaluation
*   **Defensive Inference:** The inference pipeline will explicitly check the input tensor shape to ensure it matches `(Batch, 3, H, W)` before processing, preventing runtime errors (Cite Lesson 00005).
*   **Test Time Augmentation (TTA):** We will average predictions from the original input and its geometric transformations (flips/rotations) to smooth out prediction noise.
*   **Fixed Z-Window:** During inference, we disable Z-Jitter and use the standard, centered slice ranges (20-32, 26-38, 32-44) to ensure consistent predictions.
