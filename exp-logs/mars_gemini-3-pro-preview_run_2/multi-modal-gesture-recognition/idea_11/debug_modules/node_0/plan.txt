Implementation Strategy:
1.  **Environment Preparation**: Create a temporary working directory (`./working/demo_task`) to store artifacts (metadata subsets, cache, checkpoints) without modifying the original read-only input or metadata.
2.  **Data Subsetting**: Load the original metadata CSVs (`train.csv`, `val.csv`, `test.csv`), select a small subset of rows (e.g., 20 training, 10 validation, 5 test samples), and save these subsets to the temporary directory. This ensures the demonstration runs quickly by processing only a fraction of the data.
3.  **Configuration Override**: Dynamically modify the `Config` class attributes to point to the temporary metadata and output directories. Reduce `NUM_EPOCHS` to 2 and `BATCH_SIZE` to 4 to minimize runtime.
4.  **Utility Verification**: Explicitly test the `levenshtein_distance` and `decode_predictions` functions with hardcoded examples to ensure logic correctness.
5.  **Model Verification**: Instantiate the `NMD_CRCN` model, pass a dummy tensor with the expected shape `(Batch, Time, Features)`, and assert that the output shapes for all stages are correct `(Batch, Time, NumClasses)`.
6.  **Training & Inference Pipeline**: Initialize the `Trainer` class. Execute `fit()` to train on the subset and `predict()` to generate predictions for the test subset.
7.  **Result Validation**: Verify that the checkpoint file and submission CSV are generated and that the submission file follows the expected format.
