1.  **Setup and Configuration**: Initialize the environment by creating a temporary working directory for the demo. Import necessary libraries and the provided modules (`library.config`, `library.utils`, `library.data_loader`, `library.model`, `library.trainer`, `library.inference`).
2.  **Data Subsetting**: To ensure the script runs quickly (within the time limit) and tests the data processing logic, create "mini" versions of the training, validation, and test metadata files containing only a few samples (e.g., 4 samples each). Save these to the working directory.
3.  **Monkey-Patching**: Dynamically override the file paths and hyperparameters in the imported `library.config`, `library.data_loader`, and `library.trainer` modules. This redirects the code to use the mini datasets and reduces the number of training epochs to 2, ensuring a fast runtime without modifying the original library files.
4.  **Utility Verification**: Validate the `levenshtein_score` function with known inputs to ensure metric calculation correctness.
5.  **Data Loading Verification**: Instantiate the `GestureDataset` and `DataLoader` using the mini metadata. Verify that the data is processed correctly (shapes of tensors, data types) and that the caching mechanism works (first run processes, second run loads).
6.  **Model Verification**: Instantiate the `HybridGestureNet`. Pass a batch of data through it to confirm the forward pass works and outputs tensors of the expected shape.
7.  **Training Loop Demonstration**: Initialize the `Trainer` with the model and dataloaders. Run `trainer.fit()` for the reduced number of epochs. Verify that the training completes and a "best model" checkpoint is saved.
8.  **Inference Demonstration**: Execute `generate_submission()`. Verify that it successfully loads the trained model, processes the test set, and generates a submission file in the correct format.
9.  **Assertions**: Throughout the script, use `assert` statements to strictly validate shapes, file existence, and logic correctness.
