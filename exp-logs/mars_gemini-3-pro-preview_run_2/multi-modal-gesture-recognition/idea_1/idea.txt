# Baseline Approach: Bi-directional LSTM for Frame-wise Classification

### Model
We will implement a **Bi-directional Long Short-Term Memory (Bi-LSTM)** network. This architecture serves as a robust baseline for sequence modeling tasks, distinct from the graph-based (ST-GCN), convolutional (MS-TCN), and attention-based (Transformer) architectures previously listed.
*   **Input Layer:** The model accepts a frame-wise feature vector formed by concatenating skeletal data and audio features.
*   **Recurrent Layers:** Two stacked Bi-LSTM layers process the sequence. The bi-directional nature allows the model to capture context from both the past (start of a gesture) and the future (end of a gesture) to make a prediction for the current frame.
*   **Output Layer:** A fully connected layer maps the hidden states of the LSTM to 21 output logits (20 gesture classes + 1 "background/null" class) for each frame.
*   **Activation:** A Softmax activation produces the probability distribution over classes for each time step.

### Data
To ensure efficiency and low latency, we will prioritize the lightweight Skeleton and Audio modalities over the heavy RGB and Depth video data.
*   **Skeleton Preprocessing:**
    *   **Normalization:** To ensure user independence, joint coordinates will be normalized relative to the "HipCenter" or "Spine" joint. This makes the features invariant to the user's absolute position in the room.
    *   **Feature Selection:** We will utilize the 3D coordinates ($x, y, z$) of the upper-body joints (hands, elbows, shoulders, head, spine) as these are most relevant for the target gestures.
    *   **Dynamics:** We will compute the first derivatives (velocity) of these coordinates to capture the motion dynamics.
*   **Audio Preprocessing:**
    *   We will extract Mel-frequency cepstral coefficients (MFCCs) from the audio stream. These features will be upsampled or aligned to match the video frame rate (approx. 10-20 fps) and concatenated with the skeleton features.
*   **Label Generation:**
    *   The provided training annotations (Start Frame, End Frame, Label Name) will be converted into a dense, frame-by-frame target vector. Frames falling within a gesture's interval are assigned that gesture's ID (1-20), while frames outside any annotation are assigned the background class ID (0).

### Training
*   **Loss Function:** We will use **Cross-Entropy Loss** applied to each frame's prediction. To address the imbalance between the frequent background class and the sparse gesture classes, we will apply class weighting (assigning higher weights to gesture classes).
*   **Optimizer:** The model will be trained using the **Adam** optimizer with a standard learning rate (e.g., 1e-3).
*   **Procedure:** Training will be performed on fixed-length sequences or batches of padded sequences. We will use the validation set to monitor the frame-level accuracy and stop training when performance plateaus to prevent overfitting.

### Evaluation
*   **Inference:** For each test sequence, the model will output a probability distribution for every frame.
*   **Decoding:** We will employ a **Greedy Decoding** strategy:
    1.  Select the class with the highest probability (argmax) for each frame.
    2.  **Collapse Repeats:** Merge consecutive identical labels (e.g., `[0, 2, 2, 2, 0]` becomes `[0, 2, 0]`).
    3.  **Filter Background:** Remove the background class labels (e.g., `[0, 2, 0]` becomes `[2]`).
*   **Output:** The resulting ordered list of gesture IDs will be formatted as the final prediction string (e.g., `SessionID,2`).
