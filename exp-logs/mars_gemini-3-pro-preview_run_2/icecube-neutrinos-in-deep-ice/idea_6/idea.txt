Based on the previous attempts and the critical insight from **Cite solution_lesson_node_00011**, I propose a **Hybrid Graph-Context Network**. This approach moves beyond the limitations of 1D projections (Idea 3) and independent point processing (Idea 2) by modeling the neutrino event as a connected graph of sensors. Crucially, it safeguards against the loss of global orientation context—the specific failure mode of Idea 4—by explicitly injecting validated second-order moments into the architecture.

# Model
The architecture consists of two parallel streams that fuse at the final stage:

1.  **Dynamic Graph Stream (Local Direction):**
    *   **Concept:** Instead of treating pulses as a sequence or a static cloud, this stream treats them as nodes in a graph. The core operation is **Edge Convolution** (e.g., from DGCNN), which calculates features based on the relationship between a node and its neighbors (vectors $\vec{x}_j - \vec{x}_i$). This explicitly allows the network to learn local directional vectors (track segments) directly from the 3D data.
    *   **Architecture:**
        *   **Input:** A node feature matrix of shape $(Batch, N, Features)$, where $N$ is the number of selected pulses. Features include spatial coordinates, time, and charge.
        *   **Dynamic Graph Construction:** At each layer, a k-Nearest Neighbors (k-NN) graph is constructed dynamically in the feature space. This groups pulses that are spatiotemporally related.
        *   **EdgeConv Blocks:** A series of layers that compute edge features and aggregate them (e.g., using `max` pooling) to update node representations.
        *   **Global Pooling:** A final Global Max Pooling layer aggregates the learned local track segments into a graph-level feature vector.

2.  **Global Context Stream (Global Orientation):**
    *   **Concept:** To address the failure identified in **Cite solution_lesson_node_00011**, this stream explicitly provides the model with the "principal axis" of the event.
    *   **Input:** A flat vector containing the **Charge-Weighted Covariance Matrix** (6 components: variances and covariances) and the **Center of Gravity**.
    *   **Architecture:** A lightweight Multi-Layer Perceptron (MLP) that projects these statistical moments into a latent embedding. This guarantees the model has access to the macroscopic shape (elongation and orientation) of the event, preventing the collapse to the mean seen in previous tabular attempts.

3.  **Fusion Head:**
    *   The output vectors from the Graph Stream and the Global Context Stream are concatenated.
    *   A final regression MLP maps this fused representation to the unnormalized 3D direction vector $(n_x, n_y, n_z)$.

# Data
1.  **Graph Data Preparation:**
    *   **Pulse Selection:** Select a fixed number of pulses (e.g., $N=128$) per event, prioritizing those with the highest `charge`.
    *   **Feature Engineering:** For each pulse, use normalized $x, y, z, time, charge, auxiliary$.
    *   **Tensor Construction:** Create a dense tensor of nodes. The adjacency (edges) will be computed on-the-fly by the model (k-NN), so no pre-computed adjacency matrix is required.

2.  **Context Data Preparation:**
    *   **Aggregation:** Compute statistics using **all** pulses in the event (not just the selected $N$) to ensure statistical robustness.
    *   **Moment Calculation:** Calculate the charge-weighted Center of Gravity (1st moment) and the charge-weighted Covariance Matrix (2nd moment).
    *   **Validation:** Explicitly check that the covariance terms are non-zero during the pipeline execution to prevent the silent failure mode described in **Cite solution_lesson_node_00011**.

# Training
*   **Loss Function:** **Cosine Similarity Loss**.
    *   $Loss = 1 - \text{CosineSimilarity}(\vec{v}_{pred}, \vec{v}_{true})$.
    *   This metric aligns perfectly with the competition goal and is robust to the magnitude of the predicted vector.
*   **Optimizer:** **AdamW** with a standard learning rate (e.g., 1e-3) and weight decay to prevent overfitting on the graph weights.
*   **Scheduler:** **OneCycleLR**, which warms up the learning rate and then decays it. This is particularly effective for training GNNs to convergence quickly.

# Evaluation
1.  **Inference:** Iterate through the test set batches.
2.  **Processing:**
    *   For the Graph Stream: Select top pulses and normalize.
    *   For the Context Stream: Compute global moments from the full event.
3.  **Prediction:** Pass both inputs to the model to obtain the raw 3D vector.
4.  **Post-Processing:**
    *   Normalize the output vector to unit length.
    *   Convert to spherical coordinates (`azimuth`, `zenith`).
    *   Format and save to CSV.
