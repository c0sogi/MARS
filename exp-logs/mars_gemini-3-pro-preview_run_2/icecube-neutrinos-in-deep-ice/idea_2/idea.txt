### Model: Geometric Pulse Aggregator (GPA)

This approach utilizes the **PointNet** (Model 3) architecture but simplifies it significantly to create a lightweight, permutation-invariant baseline. Unlike the Temporal Recurrent Regressor (Idea 1), which treats the event as a time-ordered sequence, this model treats the event as a geometric "cloud" of pulses. This aligns well with the physical nature of the detector, where the spatial distribution of triggered sensors is just as critical as the timing.

*   **Input Layer:** Accepts a tensor of shape $(Batch, N, Features)$, where $N$ is a fixed number of pulses (e.g., 128). The features are `[x, y, z, time, charge, auxiliary]`.
*   **Point-wise Feature Extraction:** A **Shared Multi-Layer Perceptron (MLP)** is applied independently to each of the $N$ pulses.
    *   It consists of two linear layers (e.g., 64 $\to$ 128 channels) with ReLU activations.
    *   This step lifts the low-level pulse data into a higher-dimensional latent feature space, learning local signal characteristics.
    *   *Simplification:* The complex "T-Net" (alignment network) found in the original PointNet is removed to reduce computational overhead and training time.
*   **Symmetric Aggregation:** A **Global Max Pooling** operation is applied across the $N$ points.
    *   This extracts the most prominent features (e.g., the earliest timestamp or the location of the highest charge) from the entire set.
    *   Crucially, this operation renders the model **permutation invariant**, meaning the input pulses do not need to be sorted, simplifying the data pipeline.
*   **Prediction Head:** The aggregated global feature vector is passed through a final MLP (e.g., 128 $\to$ 64 $\to$ 3) to regress the normalized 3D direction vector $(n_x, n_y, n_z)$.

### Data Preprocessing

*   **Pulse Selection:** Select a fixed subset of $N=128$ pulses per event to ensure uniform input size.
    *   **Strategy:** Select the pulses with the highest `charge`. This prioritizes the strongest signals which are most correlated with the neutrino's core interaction path.
*   **Formatting:** Unlike Idea 1, **no sorting is required**. The pulses can be in any order due to the symmetric aggregation layer.
*   **Normalization:**
    *   **Coordinates & Time:** Apply Standard Scaling (zero mean, unit variance) to `x`, `y`, `z`, and `time` based on global dataset statistics.
    *   **Charge:** Apply a logarithmic transformation ($\log(1 + charge)$) to compress the dynamic range of the signal.
    *   **Padding:** Events with fewer than $N$ pulses are padded with zeros (masked during pooling if necessary, or simply treated as zero-signal points).

### Training Procedure

*   **Loss Function:** **Cosine Similarity Loss**.
    *   $Loss = 1 - \frac{\hat{v} \cdot v_{true}}{||\hat{v}|| \cdot ||v_{true}||}$
    *   This directly optimizes the alignment between the predicted and true direction vectors, which is the geometric equivalent of minimizing the angular error.
*   **Optimizer:** **Adam** optimizer with a default learning rate (e.g., 1e-3).
*   **Regularization:** Minimal regularization (e.g., small weight decay) is used. The simplicity of the model (shared weights) naturally acts as a regularizer against overfitting.

### Evaluation

*   **Inference:** Process the test set batches using the `test_metadata`. For each event, load the pulses, apply the selection/normalization, and feed the tensor to the model.
*   **Vector to Angle Conversion:**
    1.  The model outputs a 3D vector $\vec{v} = (n_x, n_y, n_z)$.
    2.  Normalize this vector to unit length: $\hat{u} = \frac{\vec{v}}{||\vec{v}||}$.
    3.  Convert the unit vector to spherical coordinates:
        *   `zenith` = $\arccos(z)$ (clipping $z$ to $[-1, 1]$ for stability).
        *   `azimuth` = $\arctan2(y, x)$ (output in range $[0, 2\pi]$).
*   **Submission:** Format the resulting `event_id`, `azimuth`, and `zenith` into the required CSV format.
