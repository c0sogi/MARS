The issue causing the `TimeoutError` is the **eager geometry mapping** applied to the entire batch dataframe upon loading. In the `IceCubeDataset.__getitem__` method, the code currently maps sensor coordinates (`x`, `y`, `z`) to all ~33 million rows in a batch file, even though only a tiny fraction (less than 200 rows) is needed for a single event. This massive read amplification saturates the CPU and causes the timeout (Cite debug_lesson_1).

To fix this, I will move the geometry mapping logic from the batch loading block to the event extraction block. By applying the mapping only to the sliced dataframe containing the pulses for the specific requested event, the computational cost becomes negligible. I will apply this fix to both `library/data_loader.py` and `library/model.py` where the `IceCubeDataset` class is defined.
