The issue identified is an **eager preloading strategy** in the `IceCubeDataset` class that loads all referenced batch files into memory during initialization. When `max_samples=100` is used with shuffled metadata, the dataset attempts to load up to 100 full Parquet files (approx. 17GB) just to access 100 events, causing a `TimeoutError`. This corresponds to **Cite debug_lesson_1**.

The fix involves switching to a **lazy loading** strategy where batch files are loaded into the cache only when an event from that batch is requested in `__getitem__`. This ensures that only the necessary files are loaded, preventing the massive I/O overhead during initialization.

Here are the changes for `library/data_loader.py` and `library/model.py`.
