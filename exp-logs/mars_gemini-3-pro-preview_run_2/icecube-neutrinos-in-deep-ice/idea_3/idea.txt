### Idea 3: Temporal Convolutional Baseline (TCB)

This approach adapts the **1D ResNet** (Model 4) concept but strips away the complex residual connections and deep layering to form a streamlined **1D Convolutional Neural Network (CNN)**. Unlike the Recurrent Regressor (Idea 1), which processes pulses sequentially and is limited by loop overhead, this model processes the entire pulse sequence in parallel using sliding convolutional kernels. Unlike the Geometric Pulse Aggregator (Idea 2), it explicitly leverages the temporal ordering of the data to detect local wavefront patterns (e.g., light propagating from sensor A to sensor B).

#### Model
The architecture treats the event as a multi-channel time-series signal.
*   **Input Layer:** A tensor of shape $(Batch, Channels, Length)$, where $Length$ is fixed (e.g., 128) and $Channels$ corresponds to the pulse features `[x, y, z, charge, auxiliary]`.
*   **Feature Extractor (Encoder):** A stack of 3 to 4 **Convolutional Blocks**.
    *   Each block consists of a **1D Convolution** (kernel size 3) to capture local temporal dependencies, followed by **Batch Normalization** for stability, a **ReLU** activation, and **1D Max Pooling** (stride 2).
    *   This hierarchical structure progressively reduces the temporal resolution while increasing the receptive field, allowing the model to aggregate local signal triggers into global event features.
*   **Global Aggregation:** A **Global Average Pooling** layer condenses the remaining temporal sequence into a single, compact feature vector. This ensures the model can handle the fixed input size robustly regardless of where the signal is concentrated.
*   **Prediction Head:** A single Fully Connected (Linear) layer maps the global feature vector directly to the 3D direction vector $(n_x, n_y, n_z)$.

#### Data
*   **Pulse Selection:** Select a fixed window of $L=128$ pulses per event.
    *   **Strategy:** Prioritize pulses with the highest `charge` to capture the most significant signal components.
*   **Sorting:** Sort the selected pulses strictly by **time**. This is mandatory for the 1D CNN to correctly interpret the input as a temporal waveform rather than a random set of points.
*   **Normalization:**
    *   **Spatial/Temporal:** Apply Standard Scaling (Z-score) to `x`, `y`, `z`, and `time` using training set statistics.
    *   **Charge:** Apply a Log-transformation ($\log(1 + x)$) to compress the dynamic range.
*   **Tensor Construction:** The `time` feature is treated as a channel value, not an index, allowing the convolution kernels to learn relationships between the timestamp and the spatial coordinates.

#### Training
*   **Loss Function:** **Cosine Similarity Loss**.
    *   Objective: $Loss = 1 - \text{CosineSimilarity}(\hat{v}, v_{true})$.
    *   This loss function is computationally efficient and orientation-invariant, directly optimizing the angular alignment.
*   **Optimizer:** **Adam** optimizer with a standard learning rate (e.g., 1e-3).
*   **Efficiency:** By utilizing 1D convolutions, the model takes full advantage of the NVIDIA A100's parallel compute capabilities, offering significantly faster training times than recurrent architectures.

#### Evaluation
*   **Inference:** Iterate through test batches using `test_metadata`. For each event, load, select, sort, and normalize the pulses exactly as done during training.
*   **Post-Processing:**
    1.  **Normalize:** The model outputs a raw 3D vector. Normalize it to a unit vector: $\hat{u} = \frac{\vec{v}}{||\vec{v}||}$.
    2.  **Convert:** Transform the unit vector $\hat{u} = (x, y, z)$ into spherical coordinates:
        *   `zenith` = $\arccos(z)$
        *   `azimuth` = $\arctan2(y, x)$
    3.  **Submit:** Save the `event_id`, `azimuth`, and `zenith` to the final CSV submission file.
