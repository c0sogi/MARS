Based on the task description and the provided model architectures, here is a proposal for a highly efficient baseline approach that remains distinct from the previous deep learning ideas.

### **Model: Gradient Boosting Vector Regressor (GBVR)**

This approach adopts the **Gradient Boosting Decision Tree** (Model 2) foundation. Unlike the previous ideas (RNN, PointNet, CNN) which learn features directly from raw pulse tensors, this model relies on explicit statistical feature engineering to compress each event into a compact tabular vector. This method is often computationally superior for tabular-like physics data and provides a robust baseline without the overhead of deep learning training loops.

*   **Architecture:** The solution employs an ensemble of decision trees (e.g., LightGBM) using Gradient-based One-Side Sampling (GOSS).
*   **Multi-Output Strategy:** Since the target is a 3D direction, the system consists of **three independent regressors**, one for each component of the normalized direction vector: $\hat{n}_x$, $\hat{n}_y$, and $\hat{n}_z$.
*   **Input:** A flat, fixed-length vector of engineered features per event.
*   **Output:** The three scalar predictions are combined to form the estimated direction vector.

### **Data Preprocessing**

*   **Aggregation:** Instead of selecting a fixed window of pulses, process **all** pulses in an event to generate summary statistics. This avoids information loss from truncation.
*   **Feature Engineering:** Construct a feature vector for each event containing:
    *   **Signal Magnitude:** Total charge (sum) and pulse count (log-transformed).
    *   **Spatial Center:** The charge-weighted center of gravity (CoG) for coordinates $x, y, z$.
        *   Example: $CoG_x = \frac{\sum (x_i \cdot q_i)}{\sum q_i}$
    *   **Signal Spread:** The weighted standard deviation of pulse positions along each axis, indicating the "width" of the event.
    *   **Temporal Evolution:** Key percentiles of the pulse times (e.g., 10th, 50th, 90th percentiles) relative to the first pulse, capturing the wavefront's arrival speed.
    *   **Shape Descriptors (PCA):** Calculate the covariance matrix of the pulse coordinates $(x, y, z)$ weighted by charge. Flatten the unique elements of this $3 \times 3$ matrix (variances and covariances) into features. These values explicitly encode the orientation of the particle track (linear vs. spherical).
*   **Formatting:** The resulting dataset is a standard tabular matrix $(N_{events}, N_{features})$, requiring no padding or sorting.

### **Training Procedure**

*   **Loss Function:** **Mean Squared Error (MSE)**.
    *   Each of the three regressors is trained to minimize the squared difference between the predicted vector component and the true vector component (derived from the ground truth azimuth/zenith).
    *   Minimizing component-wise MSE is a strong proxy for maximizing Cosine Similarity.
*   **Optimizer:** The native gradient descent algorithm within the boosting framework (e.g., LightGBM's default).
*   **Strategy:**
    *   Train the three models ($\text{Model}_X, \text{Model}_Y, \text{Model}_Z$) in parallel or sequentially.
    *   Use **Early Stopping** based on a validation set to prevent overfitting, monitoring the validation MSE.

### **Evaluation**

*   **Inference:** Iterate through the test set batches. For each event, compute the same engineered features used in training.
*   **Prediction:** Query the three trained models to obtain the raw vector components $[\hat{x}, \hat{y}, \hat{z}]$.
*   **Post-Processing:**
    1.  **Normalization:** Normalize the resulting vector to unit length: $\vec{u} = \frac{[\hat{x}, \hat{y}, \hat{z}]}{\sqrt{\hat{x}^2 + \hat{y}^2 + \hat{z}^2}}$.
    2.  **Conversion:** Transform the unit vector $\vec{u}$ into the required spherical coordinates:
        *   `zenith` = $\arccos(u_z)$
        *   `azimuth` = $\arctan2(u_y, u_x)$
    3.  **Submission:** Save the event ID and the calculated angles to the submission file.
