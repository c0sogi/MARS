Based on the task description and the provided model architectures, here is a proposal for a highly efficient baseline approach.

### **Model: Temporal Recurrent Regressor (TRR)**

This architecture synthesizes the sequential data handling of the 1D ResNet (Model 4) and Transformer (Model 5) but replaces their heavy backbones with a lightweight Recurrent Neural Network. This design leverages the physical intuition that a neutrino event is a time-evolving wavefront of light detected by sensors.

*   **Input Layer:** Accepts a fixed-length sequence of pulses, shaped as $(Batch, Length, Features)$. The features for each pulse are `[x, y, z, time, charge, auxiliary]`.
*   **Feature Projection (Stem):** A single 1D Convolutional layer (kernel size 1) projects the raw input features into a latent dimension (e.g., 64 channels). This acts as a learnable embedding for the sensor data.
*   **Sequential Backbone:** A **Bi-Directional Gated Recurrent Unit (GRU)** with 2 layers.
    *   Unlike the Transformer (Model 5), the GRU has linear complexity with respect to sequence length, making it faster and less memory-intensive.
    *   Unlike the 1D ResNet (Model 4), the Bi-Directional nature explicitly captures the temporal context both forwards and backwards, effectively modeling the causality of the photon propagation.
*   **Aggregation:** The final hidden states from both the forward and backward passes are concatenated to form a global event descriptor.
*   **Prediction Head:** A lightweight Multi-Layer Perceptron (MLP) (e.g., 2 layers with ReLU activation) maps the global descriptor to a 3-dimensional output vector $(n_x, n_y, n_z)$ representing the neutrino's direction.

### **Data Preprocessing**

*   **Pulse Selection:** To handle the variable number of pulses (tens to thousands) efficiently, select a fixed window of $L=128$ pulses per event.
    *   Selection Strategy: Prioritize non-auxiliary pulses with the highest `charge` values to focus on the strongest signal components.
*   **Sorting:** Sort the selected pulses strictly by `time`. This is critical for the GRU to correctly interpret the sequence as a temporal evolution.
*   **Normalization:**
    *   **Spatial/Temporal:** Apply Standard Scaling (Z-score normalization) to `x`, `y`, `z`, and `time` using statistics derived from the training sample.
    *   **Charge:** Apply a Log-transformation ($\log(1 + x)$) to the `charge` feature to compress its heavy-tailed distribution.
*   **Tensor Construction:** Pad events with fewer than 128 pulses with zeros. The final input tensor will have the shape $(Batch\_Size, 128, 6)$.

### **Training Procedure**

*   **Loss Function:** **Cosine Similarity Loss**. Since the objective is to minimize the angular error, the model should maximize the cosine of the angle between the predicted vector $\hat{v}$ and the true vector $v$.
    *   $Loss = 1 - \text{CosineSimilarity}(\hat{v}, v_{true})$
    *   This is numerically stable and directly optimizes the competition metric.
*   **Optimizer:** Use the **AdamW** optimizer for stable convergence, with a standard learning rate (e.g., 1e-3).
*   **Scheduler:** Implement a `ReduceLROnPlateau` scheduler to decay the learning rate when validation loss stagnates, ensuring precise fine-tuning.

### **Evaluation**

*   **Inference:** Iterate through the test set batches using the `test_metadata` to locate files. Load and preprocess pulses exactly as in training (selection, sorting, normalization).
*   **Vector Normalization:** The model predicts a raw 3D vector. Normalize this vector to unit length: $\hat{u} = \frac{(n_x, n_y, n_z)}{\sqrt{n_x^2 + n_y^2 + n_z^2}}$.
*   **Coordinate Conversion:** Convert the normalized unit vector $\hat{u} = (x, y, z)$ into the required spherical coordinates:
    *   `zenith` = $\arccos(z)$
    *   `azimuth` = $\arctan2(y, x)$ (using `numpy.arctan2` to handle quadrants correctly).
    *   Ensure results are within $[0, \pi]$ for zenith and $[0, 2\pi]$ for azimuth.
