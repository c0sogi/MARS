The execution failure was caused by memory thrashing and fragmentation during the validation phase. The validation dataset is highly sparse (50,000 events sampled from ~600 files), resulting in ~83 events per file. With the original `BATCH_SIZE=1024`, a single batch required loading ~12 different Parquet files. This exceeded the `cache_limit=4`, forcing the `DataLoader` workers to constantly load, decompress, and discard large files (thrashing). Combined with `NUM_WORKERS=4`, this high-churn behavior across multiple processes overwhelmed the memory allocator (Cite debug_lesson_4 and Cite debug_lesson_3).

To fix this, I will:
1.  **Reduce `NUM_WORKERS` to 2** in `library/config.py` to minimize memory overhead from process replication (Cite debug_lesson_3).
2.  **Reduce `BATCH_SIZE` to 512** in `library/config.py` to reduce the number of files spanned by a single batch.
3.  **Increase `cache_limit` to 8** for the validation dataset in `runfile.py`. With a batch size of 512 and ~83 events/file, a batch spans ~6 files. A limit of 8 ensures the working set fits in memory, preventing thrashing (Cite debug_lesson_4).
