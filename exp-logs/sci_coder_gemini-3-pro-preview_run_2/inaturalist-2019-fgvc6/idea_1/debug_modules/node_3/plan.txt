The `KeyError: np.int64(538)` occurs because the label mapping (`cat_to_idx`) is currently constructed **after** the training dataset is subsampled for debugging. When `Config.DEBUG_SAMPLE_SIZE` is small (e.g., 50), the subsampled training set contains only a subset of the 1010 categories. However, the validation set (also subsampled independently) may contain categories not present in the subsampled training set (in this case, category ID 538). When the validation loader attempts to map this category ID to a class index, the lookup fails.

To fix this, I will modify `library/dataset.py` to construct the label mappings using the **full** training dataframe **before** applying any debugging subsampling. This ensures that `cat_to_idx` always contains all 1010 valid categories, preventing `KeyError` during validation regardless of which samples are selected for debugging.
