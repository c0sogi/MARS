The issue arises from a data type mismatch in `library/engine.py` during the validation loop. When using `torch.cuda.amp.autocast()`, the model produces embeddings in `float16` (Half) precision to optimize performance on the GPU. However, the class proxy weights (`weights`) used for calculating cosine similarity are derived outside the autocast context and remain in `float32` (Float). PyTorch's `torch.matmul` requires both inputs to have the same data type, causing the `RuntimeError`.

To fix this, I will explicitly cast the embeddings to `float32` before normalization and matrix multiplication in the `valid_one_epoch` function. This ensures type compatibility and improves the numerical precision of the validation metric calculation.
