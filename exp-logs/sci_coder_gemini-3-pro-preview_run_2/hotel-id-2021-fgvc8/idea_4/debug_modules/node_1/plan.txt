The issue is caused by the persistence of a stale `best_model.pth` file in the working directory from a previous run with a different model architecture. In the current execution, the validation MAP@5 score remained at 0.0 (likely due to the limited debug steps), which did not exceed the initial `best_map` of 0.0. Consequently, the `train_loop` never saved a new checkpoint. However, the code unconditionally checks `if os.path.exists(best_model_path):` at the end of training and attempts to load it. This caused the script to load the incompatible stale file, triggering a `RuntimeError` due to key mismatches (e.g., "neck" vs "bn1").

To fix this, I will introduce a flag `saved_any_model` in `library/engine.py` to track if the current training loop has actually saved a checkpoint. The model loading logic at the end of the function will be updated to check this flag, ensuring that we only load a checkpoint if it was generated during the current session.
