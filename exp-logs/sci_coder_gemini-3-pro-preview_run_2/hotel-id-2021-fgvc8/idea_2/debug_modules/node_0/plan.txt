The implementation strategy is as follows:

1.  **Setup & Configuration**: Initialize the environment, set random seeds for reproducibility, and define a temporary working directory (`./working/demo_run`) to store intermediate files.
2.  **Data Subsampling**: To ensure the script executes quickly (optimizing for speed), read the provided metadata files (`train_metadata.csv`, `val_metadata.csv`, `test_metadata.csv`) and create tiny subsets (e.g., 32 training samples, 16 validation/test samples). Save these mini-metadata files to the working directory.
3.  **Config Patching**: Dynamically modify the attributes of the `Config` class from `library.config`. This includes pointing file paths to the new mini-datasets, reducing the batch size, switching to a lighter backbone (`resnet18`), disabling pretraining (to avoid network dependencies), and updating the number of classes to match the subset.
4.  **Component Verification**:
    *   **Dataset**: Instantiate `HotelDataset` with the mini-training set and verify that it yields tensors of the correct shape.
    *   **Model**: Instantiate `HotelRecognitionModel`, perform a forward pass with dummy data to check embedding generation (inference mode) and logit generation (training mode).
5.  **Pipeline Execution**:
    *   **Training**: Call `run_training` from `library.train`. This will train the model for 1 epoch on the mini-dataset and save a checkpoint.
    *   **Inference**: Call `run_inference` from `library.inference`. This will load the saved checkpoint, generate embeddings for the gallery (train) and query (test) sets, and produce a submission file.
6.  **Final Validation**: Check that the submission file exists and adheres to the required format (columns and row counts).
