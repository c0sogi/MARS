# Proposed Solution: Conditioned Kinematic Residual Network (CK-ResNet)

### Model
The proposed architecture is a **Conditioned Kinematic Residual Network (CK-ResNet)**. This design evolves the successful Kinematic MLP baseline by introducing **Feature-wise Linear Modulation (FiLM)** to explicitly handle the distinct physics of "Player-Player" vs. "Player-Ground" interactions without fragmenting the training data.

1.  **Wide-Input Backbone:** The model accepts a **flattened wide feature vector** (representing the temporal window $t-5$ to $t+5$). This input is processed by a stack of **Residual Dense Blocks** (Linear $\to$ BatchNorm $\to$ ReLU $\to$ Linear $\to$ Add). This residual structure allows for a deeper network to capture complex kinematic dependencies without vanishing gradients, offering more capacity than the simple MLP used previously.
2.  **FiLM Conditioning (Structural Innovation):** Instead of using separate "Heads" (which failed due to data starvation, Cite solution_lesson_node_00023), we use a unified backbone that is dynamically modulated by the interaction type. A lightweight auxiliary network takes the binary `is_ground` feature and outputs scale ($\gamma$) and shift ($\beta$) vectors. These parameters modulate the activations of the main residual blocks via affine transformation: $h_{out} = \gamma \cdot h_{in} + \beta$. This allows the network to adapt its internal "physics engine" for ground impacts (vertical drops, sudden stops) versus player collisions (momentum transfer) while still sharing the majority of weights and training on the full dataset.
3.  **Center-Frame Skip Connection:** To prevent temporal dilution, the raw features corresponding to the **center frame ($t=0$)** are concatenated directly to the output of the final residual block before the classification layer. This ensures the model retains high-fidelity access to the instantaneous state (Cite solution_lesson_node_00011).

### Data
The data pipeline synthesizes the robust "Wide Format" approach with strict geometric consistency to fix the "Ground" representation.

1.  **Geometric Consistency:** For "Ground" interactions, we explicitly impute the second entity's position and velocity to match the first player's. This forces the `distance` to be **0** and relative velocity to be **0**, geometrically aligning the "Ground" class with the "Proximity" manifold used for player contacts (Cite solution_lesson_node_00024).
2.  **Vectorized Lag Construction:** We construct the temporal window using **vectorized `shift()` operations** to create a single wide row per sample. We explicitly reject vertical expansion to avoid alignment failures (Cite solution_lesson_node_00015).
3.  **High-Resolution Feature Engineering:**
    *   **Logarithmic Distance:** Apply `np.log1p(distance)` to expand feature resolution near the contact boundary (Cite solution_lesson_node_00005).
    *   **Clamped Closing Speed:** Calculate closing speed using a **clamped denominator** (`max(distance, 1e-6)`) to ensure numerical stability at the singularity (Cite solution_lesson_node_00007).

### Training
The training strategy is designed to maximize stability and calibration on the full dataset.

1.  **Loss Function:** Use **Focal Loss** (with $\alpha=0.75, \gamma=2.0$). This dynamically down-weights easy negatives, providing better probability calibration and stability than static class weighting for this specific imbalance ratio (Cite solution_lesson_node_00003, solution_lesson_node_00008).
2.  **Full Dataset:** We will train on the **entire training set** (3.4M rows). The efficient "Wide Input" architecture and unified backbone allow this within the compute budget, preventing the performance degradation associated with subsampling (Cite solution_lesson_node_00023).
3.  **Optimizer:** Use **AdamW** with a standard learning rate and Early Stopping monitoring the Validation MCC.

### Evaluation
The evaluation pipeline includes a mandatory calibration step.

1.  **Threshold Optimization:** Post-training, we will perform a grid search on the **validation set** to find the decision threshold $T$ that maximizes the Matthews Correlation Coefficient (MCC). This is necessary to align the decision boundary with the probability distribution output by the Focal Loss (Cite solution_lesson_node_00002).
2.  **Inference:** The optimized threshold $T$ is applied to the test set predictions to generate the final binary submission.
