Since the demo dataset is generated via random sampling, it inevitably includes labels corresponding to these edge timestamps. When the tracking data for these steps is dropped, the subsequent inner merge in `_process_split` removes the associated labels, resulting in fewer training samples than expected.

To resolve this, I will modify `library/data_processing.py` to replace `dropna()` with an imputation strategy. I will use forward and backward filling (`ffill` and `bfill`) grouped by `game_play` and `nfl_player_id`. This ensures that the edge timestamps are filled with the nearest valid values from the same player's track, preserving the rows required by the random sample without bleeding data across different plays. A final `fillna(0)` will be added to handle any remaining edge cases (e.g., tracks shorter than the window).
