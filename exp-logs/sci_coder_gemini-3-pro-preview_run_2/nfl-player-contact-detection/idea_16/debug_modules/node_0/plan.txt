Implementation Strategy:
1.  **Setup Environment**: Initialize random seeds and define a working directory for the demo to ensure isolation and reproducibility.
2.  **Patch Configuration**: Dynamically modify the `Config` class attributes to point to the demo working directory and reduce training parameters (e.g., fewer epochs, smaller batch size) for speed. Crucially, update dependent configuration variables like `INPUT_DIM` if necessary (though we will keep `WINDOW_SIZE` default to avoid complexity).
3.  **Create Data Subsets**: Read the provided metadata files (`train.csv`, `validation.csv`, `test.csv`) and sample a small fraction of rows (e.g., 2000 training samples) to create lightweight versions. Save these to the demo directory and update `Config` paths to point to them. This ensures the full data loading pipeline is exercised without the overhead of the full dataset.
4.  **Data Processing**: Instantiate `DataProcessor` and invoke `get_train_val_datasets`. Verify that the returned feature matrices (`X_train`, `X_val`) and targets (`y_train`, `y_val`) have the correct shapes and data types.
5.  **Model & Dataset Verification**:
    *   Create `ContactDataset` and `DataLoader` instances.
    *   Instantiate the `DCN` model.
    *   Perform a dummy forward pass with a single batch to verify the model architecture and output shape (should be `[batch_size, 1]`).
6.  **Training Loop**: Execute `train_model`. Since we patched `Config.NUM_EPOCHS` to a small number (e.g., 2), this will run quickly. Verify that the model file and threshold file are saved.
7.  **Inference**: Run `get_test_dataset` using the `DataProcessor` and the subsetted test metadata. Generate predictions using the trained model and formatted `submission.csv`.
8.  **Final Validation**: Check that the submission file exists and follows the required format.
