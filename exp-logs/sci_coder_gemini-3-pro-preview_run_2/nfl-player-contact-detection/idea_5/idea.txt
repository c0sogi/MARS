# Proposed Solution: Center-Focused Temporal Convolutional Network (CF-TCN)

### Model
The proposed architecture is a **Center-Focused Temporal Convolutional Network (CF-TCN)**. This design evolves the baseline MLP by incorporating temporal feature extraction (CNN) while strictly preserving the positional importance of the target frame, addressing the "Global Pooling" failure observed in previous attempts.

1.  **Wide-Input Reshaping:** The model accepts a **flattened wide feature vector** (e.g., size $11 \times N_{features}$) constructed via vectorized lags. Inside the model, this is reshaped into a tensor of shape $(Batch, Channels, Window\_Size)$. This leverages the robust "Wide Format" data pipeline (Cite solution_lesson_node_00015).
2.  **Temporal Encoder (No Pooling):** The tensor passes through a stack of **Residual 1D Convolutional Layers**. These layers learn non-linear temporal patterns (e.g., "whiplash" or rapid deceleration) that a simple MLP cannot easily capture. Crucially, **no Global Pooling** is applied (Cite solution_lesson_node_00011), and the output is flattened. This preserves the temporal structure, ensuring the model knows *when* features occurred relative to the center frame.
3.  **Center-Skip Connection:** To enforce the primacy of the specific moment being predicted ($t=0$), the raw input features corresponding to the **center frame** are extracted and concatenated directly with the flattened output of the Convolutional Encoder. This "Short-Circuit" ensures that the instantaneous kinematic state (Distance, Speed at $t=0$) is never diluted by the temporal aggregation.
4.  **Unified Head:** The concatenated vector feeds into a Dense classification head. We explicitly reject the "Dual Head" gating architecture, as previous lessons showed it starved the "Ground" head of data. Instead, we rely on a unified network to learn shared physics (Cite solution_lesson_node_00023).

### Data
The data pipeline synthesizes the most effective feature engineering techniques while correcting the critical "Ground" representation error.

1.  **Geometric Consistency for Ground:** When the second entity is "Ground" (Player 2 = 'G'), we impute the second player's position ($x, y$) and speed to be **identical to Player 1's**. This forces the calculated `distance` to be **0**, geometrically aligning "Ground Contact" with the "Proximity" manifold used for Player-Player contact (Cite solution_lesson_node_00024).
2.  **Vectorized Lag Construction:** We construct the temporal window (e.g., $t-5$ to $t+5$) using **vectorized `shift()` operations**. This avoids the brittle vertical expansion pipeline (Cite solution_lesson_node_00015).
3.  **High-Resolution Features:**
    *   **Logarithmic Distance:** Apply `np.log1p(distance)` to expand feature resolution near the contact boundary (Cite solution_lesson_node_00005).
    *   **Clamped Closing Speed:** Calculate closing speed using a **clamped denominator** (`max(distance, 1e-6)`) to ensure numerical stability at the singularity (Cite solution_lesson_node_00007).

### Training
The training strategy prioritizes stability and calibration on the full dataset.

1.  **Loss Function:** Use **Focal Loss** (e.g., $\alpha=0.75, \gamma=2.0$). Previous lessons demonstrated that while static weighting offers raw power, it severely uncalibrates the model (Cite solution_lesson_node_00002). Focal Loss provides better stability and a more natural decision boundary (Cite solution_lesson_node_00003), which is critical when training on the full dataset without subsampling (Cite solution_lesson_node_00023).
2.  **Full Dataset:** We will train on the **entire training set** (3.4M rows). The efficient "Wide Input" architecture allows this within the compute budget, avoiding the performance degradation caused by subsampling (Cite solution_lesson_node_00023).
3.  **Regularization:** Use **Early Stopping** monitoring the Validation MCC.

### Evaluation
1.  **Threshold Optimization:** Post-training, we will perform a grid search on the **validation set** to find the decision threshold $T$ that maximizes the Matthews Correlation Coefficient (MCC). This remains a necessary step to fine-tune the decision boundary, even with the improved calibration of Focal Loss (Cite solution_lesson_node_00002).
2.  **Inference:** The optimized threshold is applied to the test set predictions to generate the final submission.
