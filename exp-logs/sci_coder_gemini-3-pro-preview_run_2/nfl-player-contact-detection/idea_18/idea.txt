Based on the accumulated lessons and the success of multi-modal integration in the most recent attempt, I propose the **Residual-Visual Corrected Kinematic Network (RVC-Net)**.

This solution represents a structural evolution from "Early Fusion" (concatenating all features into one vector, used in Idea 17) to **"Residual Late Fusion"**. It acknowledges the empirical reality that kinematic tracking data is the primary, high-precision signal (Cite solution_lesson_node_00059), while visual helmet data acts as an orthogonal "sanity check" (Cite solution_lesson_node_00070). By structuring the network to learn the visual signal as an additive correction to the kinematic baseline, we prevent noisy or missing visual data from destabilizing the robust physics learning.

# Model
The architecture is a **Dual-Stream Network** that fuses modalities via a residual connection at the logit level.

1.  **Kinematic Stream (Primary Backbone):**
    *   **Input:** A **flattened wide feature vector** of player tracking data (Window $t-5$ to $t+5$). This preserves the strict temporal alignment proven superior to sequence models (Cite solution_lesson_node_00015, solution_lesson_node_00042).
    *   **Architecture:** A **Deep Residual MLP** (Linear $\to$ BatchNorm $\to$ ReLU $\to$ Dropout $\to$ Linear $\to$ Add). This provides the capacity to learn complex non-linear physics (e.g., "High Speed" + "Low Angle" = Contact) (Cite solution_lesson_node_00059).
    *   **Output:** A single scalar logit representing the "Kinematic Probability".

2.  **Visual Stream (Correction Branch):**
    *   **Input:** A **flattened wide feature vector** of helmet bounding box metrics (Window $t-5$ to $t+5$).
    *   **Architecture:** A **Shallow MLP**. Since visual data is sparser and serves as a proxy (Cite solution_lesson_node_00070), a shallower network prevents overfitting to noise while capturing simple geometric rules (e.g., "IoU is zero $\to$ Reduce Probability").
    *   **Output:** A single scalar logit representing the "Visual Correction".

3.  **Residual Fusion:**
    *   **Operation:** $Logit_{final} = Logit_{kinematic} + \lambda \cdot Logit_{visual}$.
    *   **Rationale:** This additive structure enforces a hierarchy: the model defaults to the robust kinematic prediction and uses the visual stream only to nudge the decision boundary (e.g., penalizing false positives where sensors show proximity but video shows a gap).
    *   **Logits-Only:** The final output is raw logits, correcting the activation-loss mismatch failure (Cite solution_lesson_node_00048).

# Data
The data pipeline synthesizes the "Entity-First" tracking approach with a "Windowed Visual" expansion.

1.  **Entity-First Feature Generation:**
    *   **Tracking:** Generate lags and windows for tracking data **before** merging pairs to prevent O(N²) scaling errors (Cite solution_lesson_node_00045).
    *   **Visuals:** Map `baseline_helmets.csv` to tracking timestamps. Calculate **Helmet IoU** and **Centroid Pixel Distance** for every step. Crucially, apply **Vectorized Windowing** to these visual features (e.g., `Visual_IoU_Lag_-1`, `Visual_IoU_Lag_0`) to capture the *trajectory* of visual overlap, not just the instantaneous state.

2.  **Hybrid Ground Imputation:**
    *   **Kinematics:** Impute Ground Position = Player Position (Distance=0) and Ground Velocity = 0. This preserves the "Relative Motion" signal (Cite solution_lesson_node_00034, solution_lesson_node_00024).
    *   **Visuals:** For Ground interactions, set `Visual_IoU` to 0. Retain the **Player's Helmet Box Features** (e.g., `box_top`). This allows the Visual Stream to learn that a "low box top" (player near bottom of frame/ground) increases contact probability.

3.  **Explicit Relative Physics:**
    *   Calculate `np.log1p(distance)` (Cite solution_lesson_node_00005) and `clamped_closing_speed` (Cite solution_lesson_node_00007) to maximize resolution near the contact boundary.
    *   Use explicit relative kinematics (Relative Speed/Acceleration) rather than raw coordinates (Cite solution_lesson_node_00033).

4.  **Normalization:** Apply **StandardScaler** to both kinematic and visual inputs to ensure the binary flags and pixel coordinates are on the same scale as physical speeds (Cite solution_lesson_node_00037).

# Training
The training procedure focuses on stability and calibration.

1.  **Loss Function:** Use **Focal Loss** implemented via `BCEWithLogitsLoss` (taking raw logits). This ensures calibration for the 1:72 class imbalance (Cite solution_lesson_node_00003) and avoids the "Logits vs Probabilities" bug (Cite solution_lesson_node_00048).
2.  **Full Dataset:** Train on the **entire training set** (3.4M rows). The efficient tabular architecture allows this within the compute budget (Cite solution_lesson_node_00023).
3.  **Optimizer:** Use **AdamW** with **Early Stopping** monitoring the Validation MCC.

# Evaluation
1.  **Threshold Optimization:** Post-training, perform a grid search on the **validation set** to find the decision threshold $T$ that maximizes the Matthews Correlation Coefficient (MCC). This is mandatory to align the decision boundary with the probability distribution (Cite solution_lesson_node_00002).
2.  **Inference:** Apply the optimized threshold $T$ to the test set predictions to generate the final binary submission.
