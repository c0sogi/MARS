The `pyarrow.lib.ArrowInvalid` error occurs because the global `df.fillna(0)` operation fills `NaN` values in categorical columns (like `position_2` and `team_2`) with the integer `0`. Since these columns already contain strings (e.g., "WR", "CB"), this creates a mixed-type column (integers and strings). When `to_parquet` attempts to infer the column schema, it detects the integers and enforces an `int64` type, causing a crash when it subsequently encounters a string.

To fix this, I will explicitly fill the categorical columns (`position_1`, `team_1`, `position_2`, `team_2`) with a string placeholder "Unknown" *before* applying the global numeric imputation. This ensures these columns remain strictly string-typed, preventing schema drift and mixed-type errors during serialization.
