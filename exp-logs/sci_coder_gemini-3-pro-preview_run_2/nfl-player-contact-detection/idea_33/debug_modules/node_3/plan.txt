The `ArrowInvalid` error occurs because the `nfl_player_id_2` column in the final DataFrame contains mixed data types: integers (from player-to-player contacts) and strings (the 'G' identifier for ground contacts). While Pandas handles mixed types in `object` columns, the Parquet serialization format requires strictly homogenous column types. When `to_parquet` attempts to infer the schema, it encounters a conflict between the integer IDs and the string "G", causing the crash (Cite debug_lesson_14).

To fix this, I will explicitly cast the `nfl_player_id_2` column to `str` in the `build_features` function immediately after concatenating the player and ground DataFrames. This ensures the column is uniformly typed as string, satisfying Parquet's requirements.
