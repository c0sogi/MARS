Based on the accumulated lessons, specifically the insight that architectural complexity cannot overcome data resolution limits (Cite solution_lesson_node_00059), I propose the **Multi-Modal Wide-Input Network (MM-WIN)**.

This solution represents a structural evolution from "Uni-Modal Architectural Engineering" (trying to make better models for tracking data) to **"Multi-Modal Feature Fusion"**. It integrates the provided **Baseline Helmet Detection** data (Visual Modality) with the **Player Tracking** data (Kinematic Modality). By fusing these orthogonal signal sources—sensor-based kinematics and pixel-based geometry—we address the resolution bottleneck of tracking data without incurring the computational cost of raw video processing.

# Model
The architecture is a **Deep Residual Multi-Layer Perceptron** designed to fuse heterogeneous tabular data sources.

1.  **Wide-Input Backbone:** The model accepts a single **flattened wide feature vector** representing the temporal window (e.g., $t-5$ to $t+5$). This preserves the strict temporal alignment found superior to sequence models (Cite solution_lesson_node_00015, solution_lesson_node_00042).
2.  **Multi-Modal Input:** The input vector is the concatenation of:
    *   **Kinematic Features:** Explicit relative physics from tracking data.
    *   **Visual Features:** Geometric properties derived from the `baseline_helmets.csv` bounding boxes (e.g., Box IoU, Centroid Distance, Aspect Ratio).
3.  **Residual Blocks:** A stack of **Dense Residual Blocks** (Linear $\to$ BatchNorm $\to$ ReLU $\to$ Dropout $\to$ Linear $\to$ Add) processes the fused input. This provides the capacity to learn non-linear correlations between modalities (e.g., "High Closing Speed" + "Low Helmet Height" = Tackle) (Cite solution_lesson_node_00059).
4.  **Logits-Only Output:** The final layer is a single Linear unit **without an activation function**. This outputs raw logits to ensure compatibility with numerically stable loss functions, correcting the "Logits vs. Probabilities" failure (Cite solution_lesson_node_00048).

# Data
The data pipeline is structurally expanded to support **Multi-Modal Alignment** while retaining the robust "Entity-First" tracking processing.

1.  **Visual Feature Engineering (New Modality):**
    *   **Alignment:** Map `baseline_helmets.csv` (indexed by `frame`) to `player_tracking.csv` (indexed by `step`) using the `video_metadata.csv` (syncing `start_time` and `snap_time`).
    *   **Box Metrics:** For every player at every step, aggregate helmet box statistics (Centroid X/Y, Area, Aspect Ratio). If multiple views (Sideline/Endzone) are available, take the average or max.
    *   **Imputation:** Create a binary `helmet_found` flag. Impute missing box statistics with -1.
2.  **Entity-First Tracking Pipeline:** Generate temporal features (lags, windows) on the tracking data **before** merging. This prevents O(N²) scaling errors (Cite solution_lesson_node_00045).
3.  **Hybrid Ground Imputation:**
    *   **Tracking:** Impute Ground Position = Player Position (Distance=0) and Ground Velocity = 0 (Cite solution_lesson_node_00024, solution_lesson_node_00034).
    *   **Visual:** For Ground interactions, set `Visual_IoU` to 0. Crucially, retain the **Player's Helmet Box Features** (e.g., `box_top`, `aspect_ratio`). A player contacting the ground often exhibits a specific visual profile (low `top` coordinate, compressed aspect ratio) which this feature captures.
4.  **Explicit Relative Features:**
    *   **Kinematic:** `np.log1p(distance)` (Cite solution_lesson_node_00005), `clamped_closing_speed` (Cite solution_lesson_node_00007), and explicit relative acceleration (Cite solution_lesson_node_00033).
    *   **Visual:** Calculate `Visual_IoU` (Intersection over Union) and `Visual_Pixel_Distance` for the player pair.
5.  **Normalization:** Apply **StandardScaler** to the final fused feature vector (Cite solution_lesson_node_00037).

# Training
The training strategy is optimized for stability and calibration on the full dataset.

1.  **Loss Function:** Use **Focal Loss** implemented via `BCEWithLogitsLoss` (taking raw logits). This ensures calibration for the class imbalance (Cite solution_lesson_node_00003) and avoids activation mismatches (Cite solution_lesson_node_00048).
2.  **Full Dataset:** Train on the **entire training set** (3.4M rows). The efficient tabular architecture allows this within the compute budget (Cite solution_lesson_node_00023).
3.  **Optimizer:** Use **AdamW** with **Early Stopping** monitoring the Validation MCC.

# Evaluation
The evaluation pipeline includes a mandatory calibration step.

1.  **Threshold Optimization:** Post-training, perform a grid search on the **validation set** to find the decision threshold $T$ that maximizes the Matthews Correlation Coefficient (MCC). This aligns the decision boundary with the probability distribution (Cite solution_lesson_node_00002).
2.  **Inference:** Apply the optimized threshold $T$ to the test set predictions to generate the final binary submission.
