The issue stems from a column name collision during the second merge operation. Both the existing DataFrame (`merged`) and the incoming tracking DataFrame (renamed with suffix `_2`) contain a column named `nfl_player_id_2`. Since `nfl_player_id_2` is not used as the join key on the left side (which uses `nfl_player_id_2_num`), pandas automatically renames the colliding columns with default suffixes (e.g., `_x`, `_y`). This causes a `KeyError` later when the code tries to access `nfl_player_id_2` by its original name. The fix is to explicitly provide `suffixes=("", "_tracking")` to the `merge` method, ensuring the columns in the left DataFrame preserve their original names.
