Based on the analysis of previous attempts and the specific lessons learned, I propose the **Explicitly-Featurized Wide Residual Network (EF-WideResNet)**. This solution represents a structural evolution that combines the robust feature engineering of the baseline with the high capacity of deep residual networks, while explicitly rejecting the sequence-modeling architectures (CNNs/Attention) that failed due to alignment and complexity issues.

# Proposed Solution: Explicitly-Featurized Wide Residual Network (EF-WideResNet)

### Model
The architecture is a **Deep Residual Multi-Layer Perceptron** designed specifically for high-dimensional, explicitly engineered tabular data.

1.  **Wide-Input Architecture:** The model accepts a single **flattened wide feature vector** representing the entire temporal window (e.g., $11 \text{ timesteps} \times N \text{ features}$). This preserves the "Wide Format" which was proven superior to sequence-based inputs (CNNs/Attention) for this specific task, as it maintains strict temporal alignment without the overhead or blurring of pooling layers (Cite solution_lesson_node_00015, solution_lesson_node_00042, solution_lesson_node_00011).
2.  **Explicit Feature Backbone:** Unlike previous deep learning attempts (like CK-ResNet) that failed because they relied on raw coordinates to infer physics (Cite solution_lesson_node_00033), this model is fed **explicitly engineered relative kinematics** (Relative Speed, Closing Speed, etc.).
3.  **Residual Depth:** The core structural innovation is replacing the shallow dense layers of the baseline MLP with a stack of **Dense Residual Blocks** (Linear $\to$ BatchNorm $\to$ ReLU $\to$ Dropout $\to$ Linear $\to$ Add).
    *   **Rationale:** While the baseline MLP performed well, it was capacity-constrained. By adding depth via residual connections, the model can learn highly complex, non-linear interactions (e.g., "High Speed" + "Low Angle" + "Ground Proximity") without suffering from vanishing gradients, while retaining the successful tabular alignment of the MLP.
4.  **Entity Embeddings:** Categorical features (e.g., Player Position) are passed through embedding layers and concatenated with the continuous kinematic features, providing context (e.g., differentiating QB behavior from LB behavior) that modifies the physical probability.

### Data
The data pipeline synthesizes the "Wide Format" strategy with strict physical imputation rules to correct the "Ground" representation failures.

1.  **Vectorized Wide-Windowing:** We construct the temporal window (e.g., $t-5$ to $t+5$) using **vectorized `shift()` operations** to create a single wide row per sample. We explicitly reject vertical expansion strategies to avoid the alignment failures and NaN generation observed in previous attempts (Cite solution_lesson_node_00015).
2.  **Hybrid Ground Imputation:** We implement a strict separation of positional and kinematic imputation for Ground interactions (Cite solution_lesson_node_00034):
    *   **Position:** Impute Ground coordinates ($x, y$) as the Player's coordinates. This forces `distance` to **0**, maintaining the geometric invariant "Contact implies Proximity" (Cite solution_lesson_node_00024).
    *   **Kinematics:** Impute Ground velocity and acceleration as **0**. This preserves the "Relative Motion" signal (e.g., Closing Speed) required to detect impact, correcting the failure where copying player velocity zeroed out the impact signal.
3.  **Explicit Relative Kinematics:** We explicitly engineer **Relative Speed**, **Relative Acceleration**, and **Closing Speed** for every step in the window. We prioritize these physics-based non-linear features over raw coordinates (Cite solution_lesson_node_00033).
    *   **Logarithmic Distance:** Apply `np.log1p(distance)` to expand feature resolution near the contact boundary (Cite solution_lesson_node_00005).
    *   **Clamped Closing Speed:** Use `max(distance, 1e-6)` in the denominator to ensure numerical stability at the singularity (Cite solution_lesson_node_00007).
    *   **Avoid Linear Redundancy:** We will not include simple finite differences (like $x_t - x_{t-1}$) as features, as the first dense layer can infer these, focusing instead on non-linear transformations (Cite solution_lesson_node_00006).
4.  **Input Normalization:** Apply **StandardScaler** to the final continuous feature set. This is mandatory to ensure the binary `is_ground` flag and embeddings are not drowned out by unscaled kinematic magnitudes (Cite solution_lesson_node_00037).

### Training
The training strategy is optimized for stability and calibration on the full dataset.

1.  **Loss Function:** Use **Focal Loss** (e.g., $\alpha=0.75, \gamma=2.0$). This provides better probability calibration and stability than static weighting for the extreme class imbalance, preventing the model from becoming trivially overconfident (Cite solution_lesson_node_00003).
2.  **Full Dataset:** Train on the **entire training set** (3.4M rows). The efficient tabular architecture allows this within the compute budget, avoiding the performance degradation associated with subsampling (Cite solution_lesson_node_00023).
3.  **Optimizer:** Use **AdamW** with a standard learning rate and **Early Stopping** monitoring the Validation MCC.

### Evaluation
The evaluation pipeline includes a mandatory calibration step.

1.  **Threshold Optimization:** Post-training, perform a grid search on the **validation set** to find the decision threshold $T$ that maximizes the Matthews Correlation Coefficient (MCC). This is necessary to align the decision boundary with the probability distribution output by the Focal Loss (Cite solution_lesson_node_00002).
2.  **Inference:** Apply the optimized threshold $T$ to the test set predictions to generate the final binary submission.
