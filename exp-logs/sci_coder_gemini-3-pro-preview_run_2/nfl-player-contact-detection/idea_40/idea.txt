Based on the comprehensive analysis of the accumulated lessons, I propose the **Linear-Residual Pyramidal Invariant Network (LRP-Net)**.

This solution represents a structural synthesis of the most robust architectural patterns identified in the failure analysis. It explicitly addresses the "Signal Dominance" vs. "Complexity Penalty" trade-off (Cite solution_lesson_node_00059, solution_lesson_node_00075) by implementing a **Wide-and-Deep** topology at the logit level. This ensures that the dominant linear physical signals (e.g., proximity) are captured by a direct linear highway and never diluted by network depth, while a parallel **Pyramidal Backbone** (Cite solution_lesson_node_00096) captures complex non-linear dynamics. This is augmented by **Strict Physical Invariance** (Cite solution_lesson_node_00092), **Input Noise Injection**, and **Residual-Visual Fusion** (Cite solution_lesson_node_00071).

# Model
The architecture is a **Triple-Stream Network** designed to fuse a linear physics baseline, a deep temporal backbone, and a visual correction branch.

1.  **Input Layer & Preprocessing:**
    *   **Input:** A **flattened wide feature vector** of player tracking data (Window $t-5$ to $t+5$).
    *   **Input Clamping:** A fixed, non-trainable layer immediately clamps all continuous features to a physical range (e.g., `[-50, 50]`). This prevents outliers in derivative features from destabilizing gradients (Cite solution_lesson_node_00081).
    *   **Stochastic Noise Injection:** During training *only*, add Gaussian Noise $\mathcal{N}(0, \sigma)$ to the kinematic features. This forces the model to learn robust physical manifolds rather than memorizing sensor noise (Cite solution_lesson_node_00092).

2.  **Stream 1: Wide Kinematic Path (Linear Highway):**
    *   **Architecture:** A single **Linear Layer** connecting the clamped input directly to the output logit ($L_{linear}$).
    *   **Rationale:** Explicit physics features (e.g., `log_distance`, `closing_speed`) are highly predictive on their own. This path guarantees that the gradient for these dominant signals is never vanished or diluted by the deep network, establishing a robust "Linear Physics" baseline (Cite solution_lesson_node_00075).

3.  **Stream 2: Deep Kinematic Path (Pyramidal Invariant Backbone):**
    *   **Strict Invariance:** We explicitly **exclude** categorical entity embeddings. The model relies solely on relative kinematics to prevent memorization of non-generalizable priors (Cite solution_lesson_node_00092).
    *   **Pyramidal Architecture:** An **Interleaved Pyramidal Backbone** (Cite solution_lesson_node_00096) forces hierarchical abstraction.
        *   *Structure:* `Input` $\to$ `Project(512)` $\to$ `ResBlock` $\to$ `Project(256)` $\to$ `ResBlock` $\to$ `Project(128)` $\to$ `ResBlock` $\to$ `Linear` $\to$ $L_{deep}$.
    *   **Unified Input:** All kinematic features are fed into this stream to allow immediate learning of coupled interactions (Cite solution_lesson_node_00093).

4.  **Stream 3: Visual Path (Shallow Correction):**
    *   **Input:** A **flattened wide feature vector** of helmet bounding box metrics, derived using a **Max-Pooling Selection Strategy** (Cite solution_lesson_node_00074).
    *   **Backbone:** A **Shallow MLP**. This prevents overfitting to the noisy visual proxy while capturing simple geometric rules (Cite solution_lesson_node_00071).
    *   **Output:** A single scalar logit ($L_{vis}$).

5.  **Fusion:**
    *   **Operation:** $Logit_{final} = L_{linear} + L_{deep} + \lambda \cdot L_{vis}$.
    *   **Logits-Only:** The final layer outputs raw logits, strictly adhering to the requirement for numerically stable loss functions (Cite solution_lesson_node_00048).

# Data
The data pipeline synthesizes the "Entity-First" tracking approach with strict physical constraints.

1.  **Entity-First Feature Generation:** Generate lags and windowed features on the `player_tracking` dataframe **before** merging it with `train_labels`. This prevents O(N²) scaling errors (Cite solution_lesson_node_00045).
2.  **Explicit Numerical Stability:**
    *   **Clamping:** Explicitly clamp derived kinematic features (e.g., `closing_speed`) to fixed physical ranges during engineering (Cite solution_lesson_node_00081).
    *   **Angular Continuity:** Use the **Shortest Arc** method (e.g., `min(|a-b|, 360-|a-b|)`) for relative angles (Cite solution_lesson_node_00076).
    *   **Resolution Enhancement:** Apply `np.log1p(distance)` (Cite solution_lesson_node_00005) and `clamped_closing_speed` (Cite solution_lesson_node_00007).
3.  **Hybrid Ground Imputation:**
    *   **Kinematics:** Impute Ground Position = Player Position (Distance=0) and Ground Velocity = 0. This preserves the "Relative Motion" signal (Cite solution_lesson_node_00034).
    *   **Visuals:** For Ground interactions, set `Visual_IoU` to 0 but retain the **Player's Helmet Box Top** features (Cite solution_lesson_node_00071).
4.  **Visual Feature Selection (Max-Pooling):** Apply a **Max-Pooling Strategy** per timestamp to select the single "best" view (largest box area) for each player. This creates a dense, consistent visual feature vector (Cite solution_lesson_node_00074).
5.  **Normalization:** Apply **StandardScaler** to the final fused vector (Cite solution_lesson_node_00037).

# Training
The training strategy is optimized for stability and calibration on the full dataset.

1.  **Loss Function:** Use **Focal Loss** implemented via `BCEWithLogitsLoss`. Crucially, set `alpha=0.25` and `gamma=2.0`. This ensures the loss properly balances the suppression of easy negatives with the regularization of noisy labels (Cite solution_lesson_node_00077).
2.  **Full Dataset:** Train on the **entire training set** (3.4M rows). The efficient tabular architecture allows this within the compute budget (Cite solution_lesson_node_00023).
3.  **Batch Size:** Use a large batch size (e.g., **8192**) to maximize the stability of Batch Normalization statistics within the Pyramidal backbone (Cite solution_lesson_node_00096).
4.  **Optimizer:** Use **AdamW** with **Early Stopping** monitoring the Validation MCC.

# Evaluation
The evaluation pipeline includes a mandatory calibration step.

1.  **Threshold Optimization:** Post-training, perform a grid search on the **validation set** to find the decision threshold $T$ that maximizes the Matthews Correlation Coefficient (MCC). This aligns the decision boundary with the probability distribution (Cite solution_lesson_node_00002).
2.  **Inference:** Apply the optimized threshold $T$ to the test set predictions to generate the final binary submission.
