The execution crash "REPL child process died unexpectedly" immediately after starting the training loop indicates that the system's shared memory (`/dev/shm`) was exhausted by the PyTorch `DataLoader` worker processes. In containerized environments, the default shared memory limit is often insufficient for multiple workers handling large image batches. To resolve this, I will set `NUM_WORKERS = 0` in `library/config.py`. This forces data loading to occur in the main process, bypassing the shared memory mechanism entirely and preventing the crash.
