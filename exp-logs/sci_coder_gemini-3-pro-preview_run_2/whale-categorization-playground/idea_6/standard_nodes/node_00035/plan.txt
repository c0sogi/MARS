The issue is that the validation process in `runfile.py` performs a "closed-set" evaluation by filtering out `new_whale` samples (`filter_new_whale=True`), whereas the task is an "open-set" problem where the model must distinguish between known whales and new individuals. This mismatch leads to an invalid metric because the validation set does not represent the test distribution. Additionally, the validation loop uses a simple top-k retrieval without the confidence thresholding logic used in inference, failing to predict `new_whale` when the model is uncertain.

To fix this, I will:
1.  Initialize the validation `WhaleDataset` in `runfile.py` with `filter_new_whale=False` to include all validation samples.
2.  Update the validation loop to implement the open-set logic: check if the top prediction's confidence score exceeds `Config.CONFIDENCE_THRESHOLD`. If it does, predict the ID followed by `new_whale` (sentinel `-1`); otherwise, predict `new_whale` first. This aligns the validation architecture with the inference strategy (Cite debug_lesson_5) and correctly handles the sentinel value for unknown classes (Cite debug_lesson_3).
