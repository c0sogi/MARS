To solve the Humpback Whale Identification challenge, I propose a structural evolution from the previous pairwise Siamese approach to a **Classification-based Metric Learning** framework utilizing **ArcFace (Additive Angular Margin Loss)**. This approach scales better to thousands of classes and leverages the specific lessons learned regarding data curation and validation.

### Model
*   **Backbone Architecture**: Replace the ResNet-18 with an **EfficientNet-B0**. This provides a stronger feature extractor ("moderately heavier" as permitted) while maintaining computational efficiency suitable for the 24-hour limit.
*   **Embedding Head**: The classification layer of the backbone will be replaced with a **Generalized Mean Pooling (GEM)** layer followed by a Batch Normalization layer and a fully connected layer to project features into a 512-dimensional embedding space.
*   **Metric Learning Head (ArcFace)**: Instead of the previous Siamese distance output, the model will output class logits using an **ArcFace** head. This component learns a center vector for each distinct whale ID and enforces a margin in the angular space, promoting high intra-class compactness and inter-class discrepancy. This structural shift eliminates the need for complex pair mining.

### Data
*   **Preprocessing**: Images will be resized to 256x256 and normalized.
*   **Cache Management**: To prevent the "Silent Empty Dataset" bug, all dataset instantiations will use parameterized cache filenames (e.g., `cache_train.npy`, `cache_val.npy`) rather than hardcoded defaults (Cite solution_lesson_node_00001).
*   **Training Set Curation**: The training data loader will strictly filter out the `new_whale` class. The model will only train on images with verified, specific identities. This prevents the embedding space from collapsing by trying to cluster visually distinct "unknown" whales into a single point (Cite solution_lesson_node_00005).
*   **Reference Database Curation**: For the inference phase, the reference database (gallery) will include **all** training images, including those labeled `new_whale`. This ensures the retrieval system can rely on density estimation to identify new whales, rather than relying solely on distance thresholds (Cite solution_lesson_node_00006).

### Training
*   **Loss Function**: The model will be optimized using **ArcFace Loss** on the known identities.
*   **Validation Strategy**: We will discard the loss-based validation metric entirely. Instead, at the end of each epoch, we will perform a K-Nearest Neighbors (KNN) search on the validation set to calculate the **MAP@5** score. This ensures model selection is driven by its actual retrieval performance rather than a proxy loss, which is critical for sparse datasets (Cite solution_lesson_node_00002).
*   **Optimization**: We will use the AdamW optimizer with a cosine annealing learning rate scheduler.

### Evaluation
*   **Inference Pipeline**:
    1.  **Cache Invalidation**: The inference script will explicitly force the re-computation of embeddings (setting `load_cache=False`) to ensure predictions reflect the final trained model state, preventing the use of stale data (Cite solution_lesson_node_00003).
    2.  **Embedding Generation**: Compute embeddings for the entire Training set (Gallery) and the Test set (Query).
    3.  **KNN Retrieval**: For each test image, find the nearest neighbors in the Gallery.
    4.  **Prediction Logic**: Predict the `Id` of the nearest neighbors. If the neighbors are `new_whale` or the distance exceeds a calibrated threshold, the prediction will default to `new_whale`.
