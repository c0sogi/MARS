Based on the comprehensive analysis of the previous experiments and lessons learned, I propose the following optimized strategy. This approach introduces a structural shift in the backbone architecture and the inference pipeline while retaining the successful metric learning components from the previous iterations.

# Model
**Architecture:**
I propose replacing the EfficientNet backbone with a **ConvNeXt-Tiny** architecture.
*   **Rationale:** While the "Capacity-Resolution Swap" indicated that model depth is crucial (Cite solution_lesson_node_00013), ConvNeXt modernizes the standard CNN by incorporating design choices from Vision Transformers (e.g., larger kernel sizes, fewer activation functions). This provides a stronger inductive bias for feature extraction than EfficientNet, offering higher capacity without the quadratic complexity of full self-attention.
*   **Pooling:** We will retain the **Generalized Mean Pooling (GeM)** layer, which has proven effective for fine-grained retrieval tasks.
*   **Head:** We will maintain the **ArcFace (Additive Angular Margin Loss)** head. This classification-based margin loss is mathematically superior to pairwise losses for high-cardinality datasets (Cite solution_lesson_node_00008).

# Data
**Preprocessing:**
*   **Resolution:** We will standardize input images to **384x384**. Although Lesson 13 favored capacity over resolution under strict constraints, Lesson 9 highlighted that fine-grained ID tasks require sufficient spatial resolution to resolve minute details like scars (Cite solution_lesson_node_00009). With the powerful A100 GPU available, we can afford both the higher capacity of ConvNeXt and the higher resolution of 384px.
*   **Augmentation:** We will apply **CoarseDropout (Cutout)** to force the model to learn distributed features rather than relying on specific keypoints (Cite solution_lesson_node_00009).
*   **Caching:** All dataset instantiations will use parameterized cache filenames (e.g., `cache_train_384.npy`) to prevent the "Silent Empty Dataset" bug (Cite solution_lesson_node_00001).
*   **Filtering:** The training set will strictly **exclude** the `new_whale` class to prevent embedding collapse (Cite solution_lesson_node_00005).

# Training
**Strategy:**
*   **Loss Function:** We will optimize the model using **ArcFace Loss** on the known identities.
*   **Batch Size:** We will use a moderate batch size (e.g., 24 or 32). As discovered, proxy-based methods like ArcFace do not require large batches for negative mining, allowing us to fit the larger 384px images into GPU memory (Cite solution_lesson_node_00010).
*   **Validation:** We will ignore the training loss for model selection. Instead, we will compute the **MAP@5** score on the validation set at the end of every epoch using a K-Nearest Neighbors search (Cite solution_lesson_node_00002).

# Evaluation
**Inference Pipeline:**
*   **Structural Innovation: k-Reciprocal Re-ranking.**
    Instead of relying solely on Euclidean/Cosine distance, we will implement **k-Reciprocal Encoding Re-ranking** during the inference phase. This technique refines the distance between a query and a gallery image by considering the similarity of their k-nearest neighbor sets (Jaccard distance). This exploits the manifold structure of the data, helping to disambiguate hard positives that might be far in Euclidean space but share common neighbors.
*   **Gallery Construction:** The reference database (Gallery) will include **all** training images, including those labeled `new_whale`. This allows the retrieval system to predict "unknown" based on density estimation in the embedding space (Cite solution_lesson_node_00006).
*   **Cache Management:** The inference script will explicitly invalidate or ignore previous embedding caches to ensure predictions are generated using the latest trained model weights (Cite solution_lesson_node_00003).
