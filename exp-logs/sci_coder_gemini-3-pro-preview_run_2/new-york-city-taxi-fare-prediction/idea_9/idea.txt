Based on the lessons learned, I propose a **Global-Prior Augmented Gradient Boosting** strategy. This approach structurally decouples "Knowledge Aggregation" (utilizing the full 55M dataset for feature engineering) from "Model Learning" (training on a stable subsample). It leverages the **Vectorized Subtraction** technique to efficiently inject high-resolution global pricing priors into a stable training set, resolving the conflict between the need for massive data to predict outliers and the gradient instability of training on that data.

# Model
I will use the **XGBoost Regressor** as the backbone, leveraging its proven superiority over Deep Learning for this low-dimensional spatial task **Cite {solution_lesson_node_00030}**.
*   **Structural Innovation (Background-Augmented Encoding):** The model will be trained on a subsample, but its features will be derived from the entire 55M dataset. By treating the full dataset as a "Background Knowledge Base," the model gains the ability to predict rare and high-fare routes (which require massive data to see) without being exposed to the gradient instability of the full dataset during the optimization phase.

# Data
The data pipeline utilizes **Vectorized Subtraction** to efficiently process the 55M row dataset.

1.  **Input Sanitization (Clamping):**
    *   Strictly clamp all pickup and dropoff coordinates in the Training (55M), Validation, and Test sets to the NYC bounding box. This prevents the linear extrapolation of massive distances from corrupt GPS data **Cite {solution_lesson_node_00003}**.

2.  **High-Resolution Spatial Discretization:**
    *   Round all coordinates to **3 decimal places** (approx. 110m resolution). This fine-grained grid captures micro-location pricing factors (e.g., specific hotels or corners) which significantly improved RMSE in previous experiments **Cite {solution_lesson_node_00045}**.

3.  **Feature Engineering (Global-Prior Injection):**
    *   **Global Statistics:** Compute the `Sum` and `Count` of `fare_amount` for every unique `(Pickup_Grid, Dropoff_Grid)` route on the **entire 55M dataset**.
    *   **Training Subsample:** Select a stable random subsample of **5 million rows** for the actual model training **Cite {solution_lesson_node_00017}**.
    *   **Background-Augmented K-Fold Encoding:** Partition the 5M training set into $K$ folds. For each fold, calculate the `Route_Avg_Fare` feature using the **Vectorized Subtraction Method**:
        $$ \text{Feature} = \frac{\text{Global}_{\text{sum}} - \text{Fold}_{\text{sum}}}{\text{Global}_{\text{count}} - \text{Fold}_{\text{count}}} $$
        This effectively uses roughly $55M - \frac{5M}{K}$ rows to estimate the price for each training sample, maximizing information density without data leakage **Cite {solution_lesson_node_00045}**.

4.  **Target Preservation:**
    *   Use the **raw `fare_amount`** as the target. Do **not** truncate outliers (e.g., >$500) and do **not** log-transform. Truncation destroys the ability to predict valid high-fare rides **Cite {solution_lesson_node_00018}**, and log-transformation biases the RMSE metric **Cite {solution_lesson_node_00025}**.

# Training
1.  **Objective Function:** Use **`reg:squarederror`** (Standard L2 Loss).
    *   **Rationale:** Since we are training on a stable subsample (where extreme outliers are statistically less dominant) and providing the model with robust "Global Prior" features, we can safely use the loss function that aligns perfectly with the RMSE metric. We avoid robust losses like Huber, which were shown to underperform because they ignore the heavy tail **Cite {solution_lesson_node_00037}**.
2.  **Dataset:** Train exclusively on the **5 million row subsample**. This avoids the gradient explosions observed when training on the full 55M dataset **Cite {solution_lesson_node_00017}**.

# Evaluation
1.  **Inference Features:**
    *   For the test set, generate the `Route_Avg_Fare` feature using the **Global Statistics** from the full 55M dataset directly (no subtraction needed, as test data is not in the training set).
2.  **Prediction:** Generate predictions using the XGBoost model.
3.  **Post-Processing:** Apply a minimum fare floor ($2.50) and ensure coordinate clamping is applied to the test inputs **Cite {solution_lesson_node_00003}**.
