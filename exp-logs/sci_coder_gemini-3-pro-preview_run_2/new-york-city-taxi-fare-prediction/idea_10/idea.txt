Based on the comprehensive analysis of the provided lessons, I propose a **Residual-Learning Gradient Boosting** strategy with **Physics-Consistent Data Cleaning**. This approach synthesizes the stability of subsampled training, the information density of global target encoding, and the structural advantages of residual learning to resolve the conflict between outlier prediction and gradient stability.

# Model
I propose using an **XGBoost Regressor** configured to learn the **residual** of the fare rather than the absolute value.
*   **Structural Innovation (Base Margin Injection):** Instead of using the "Global Route Average" merely as a feature, I will set it as the **`base_margin`** (initial prediction) of the XGBoost model.
    *   **Rationale:** Gradient Boosted Trees are poor at approximating linear identity functions (e.g., $y \approx x$). By setting the high-resolution historical average as the baseline, the model only needs to learn the *deviation* (residual) caused by temporal factors (traffic, time of day) or specific route conditions. This reduces the variance of the target variable significantly, stabilizing the gradients for the L2 loss function while retaining the "Heavy Tail" magnitude information from the global priors.
*   **Backbone:** XGBoost with `tree_method='gpu_hist'` for efficiency **Cite {solution_lesson_node_00030}**.

# Data
The data pipeline employs a **Two-Stage Global-Local Architecture** to maximize signal while enforcing physical consistency.

**Stage 1: Global Knowledge Base (The "Prior")**
1.  **Physics-Consistent Filtering:** Process the entire 55M dataset. Instead of blindly truncating high fares (which destroys valid signal **Cite {solution_lesson_node_00018}**), apply a **Consistency Filter**:
    *   Remove rows where `Fare_Amount > $500` **AND** `Fare_Per_Km > Threshold` (e.g., >$50/km).
    *   This removes "garbage" outliers (e.g., $93k for a 1km ride) that destabilize L2 loss **Cite {solution_lesson_node_00017}**, while preserving valid long-distance high fares (e.g., $300 for 100km) needed for the test set.
2.  **High-Resolution Discretization:** Round coordinates to 3 decimal places (~100m resolution) to capture micro-location pricing (e.g., hotels, corners) **Cite {solution_lesson_node_00045}**.
3.  **Global Aggregation:** Compute the `Sum` and `Count` of `fare_amount` for every unique `(Pickup_Grid, Dropoff_Grid)` route on the filtered 55M dataset.

**Stage 2: Training Set Construction (The "Learner")**
1.  **Subsampling:** Select a stable subsample of **5 million rows** for training. This prevents the gradient explosion associated with the full 55M dataset **Cite {solution_lesson_node_00017}**.
2.  **Vectorized Subtraction Encoding:** For the training subsample, compute the `Route_Avg_Fare` by subtracting the subsample's own statistics from the Global Aggregation using the **Vectorized Subtraction Method**:
    $$ \text{Prior} = \frac{\text{Global}_{\text{sum}} - \text{Batch}_{\text{sum}}}{\text{Global}_{\text{count}} - \text{Batch}_{\text{count}}} $$
    This provides a strictly out-of-fold, high-cardinality prior without data leakage **Cite {solution_lesson_node_00045}**.
3.  **Input Clamping:** Strictly clamp all spatial coordinates to the NYC bounding box to prevent linear extrapolation of distance features **Cite {solution_lesson_node_00003}**.
4.  **Feature Engineering:**
    *   **Inductive Bias Features:** Retain Haversine distance, Manhattan distance, and Rotated Coordinates. **Cite {solution_lesson_node_00046}** demonstrated that removing these in favor of pure memorization causes failure.
    *   **Prior Feature:** Include the `Route_Avg_Fare` as an input feature as well.

# Training
1.  **Objective Function:** Use **`reg:squarederror`** (L2 Loss).
    *   **Rationale:** With "garbage" outliers removed via Physics Filtering and the magnitude handled by the `base_margin`, the residuals will be well-behaved. We avoid robust losses (Huber) because they fail to optimize the specific RMSE metric for the heavy tail **Cite {solution_lesson_node_00037}**.
2.  **Base Margin:** Pass the `Route_Avg_Fare` (calculated via Vectorized Subtraction) as the `base_margin` to the XGBoost `fit` method.
3.  **Target:** Train on the raw `fare_amount`. Do not log-transform, as this biases RMSE **Cite {solution_lesson_node_00025}**.

# Evaluation
1.  **Inference:**
    *   For the test set, look up the `Route_Avg_Fare` from the **Global Knowledge Base** (Stage 1). Use a distance-based fallback ($Distance \times Global\_Per\_Km$) for unseen routes.
    *   Set this value as the `base_margin` for prediction.
2.  **Prediction:** The model predicts the residual, which is added to the base margin to produce the final fare.
3.  **Post-Processing:** Apply a minimum fare floor ($2.50) and clamp predictions to be non-negative.
