Based on the analysis of the provided lessons and the evolution of previous experiments, I propose a **Multi-Scale Interaction Gradient Boosting** strategy with **Dual-Hygiene Data Processing**. This approach structurally synthesizes the superior information density of "Interaction" features (Lesson 00062), the robustness of "Soft Integration" (Lesson 00055), and the efficiency of "Vectorized K-Fold Encoding" (Lesson 00045), while resolving the conflict between clean priors and heavy-tail prediction via a novel Dual-Hygiene pipeline.

# Model
I will utilize the **XGBoost Regressor** as the backbone, leveraging its proven superiority for spatial tabular tasks **Cite {solution_lesson_node_00030}**.

*   **Structural Innovation (Multi-Scale Interaction Features):** Instead of relying on a single "Route Average" or failing with "Marginal" (Pickup/Dropoff independent) encodings **Cite {solution_lesson_node_00062}**, I will provide the model with a **Pyramid of Interaction Priors**. I will generate K-Fold Target Encodings for the **Route** (Pickup $\leftrightarrow$ Dropoff pair) at three distinct spatial resolutions:
    1.  **Micro-Interaction:** `(Geohash7_Pickup, Geohash7_Dropoff)` (~150m resolution). Captures specific building-to-building pricing.
    2.  **Meso-Interaction:** `(Geohash6_Pickup, Geohash6_Dropoff)` (~1km resolution). Captures neighborhood-to-neighborhood trends.
    3.  **Macro-Interaction:** `(Geohash5_Pickup, Geohash5_Dropoff)` (~5km resolution). Captures district-to-district baselines.
    These will be fed as **Input Features** (Soft Integration). This allows the tree model to dynamically learn which resolution to trust: relying on the Micro-Interaction for dense urban routes and naturally shifting weight to Meso/Macro features for sparse regions, avoiding the brittleness of hardcoded fallbacks **Cite {solution_lesson_node_00055}**.

# Data
The data pipeline employs a **Dual-Hygiene Strategy** to resolve the conflict between "Robust Priors" and "Heavy-Tail Prediction".

1.  **Dual-Hygiene Preprocessing:**
    *   **For Statistics Generation (The "Wisdom"):** Use the **Full 55M Dataset**. Apply **Strict Filtering**: Remove outliers (e.g., Fare > $200, Fare/Km > $10). This ensures the calculated Interaction Priors represent the "true" typical price, free from the "garbage" noise that corrupted previous attempts **Cite {solution_lesson_node_00017}**.
    *   **For Model Training (The "Learner"):** Use a stable **Subsample (5M rows)**. Apply **Loose Filtering**: Remove only physically impossible records (e.g., $100 for 0km), but **retain valid high-fare outliers** (e.g., long trips > $500). This preserves the "Heavy Tail" signal required to minimize the RMSE metric **Cite {solution_lesson_node_00018}**.

2.  **Vectorized K-Fold Encoding:**
    *   Apply **K-Fold Target Encoding** to the training subsample.
    *   Use the **Vectorized Subtraction Method** (Global Stats - Fold Stats) to efficiently compute the Multi-Scale Interaction features. This allows us to leverage the full depth of the 55M dataset to estimate priors for the 5M training rows without data leakage **Cite {solution_lesson_node_00045}** and without the inefficiency of Disjoint splitting **Cite {solution_lesson_node_00060}**.

3.  **Inductive Bias Preservation:**
    *   Retain explicit geometric features (Haversine, Manhattan, Rotated Coordinates). This ensures the model has a generalized physics rule to fall back on when all interaction priors are unseen, preventing memorization failure **Cite {solution_lesson_node_00046}**.
    *   Strictly clamp all input coordinates to the NYC bounding box **Cite {solution_lesson_node_00003}**.

# Training
1.  **Objective Function:** Use **`reg:squarederror`** (Standard L2 Loss).
    *   **Rationale:** We are training on a stable subsample with robust, clean Multi-Scale Priors as features. The optimization landscape is stable enough to use L2 loss, which aligns perfectly with the RMSE metric. We avoid robust losses (Huber) as they fail to prioritize the high-fare outliers we explicitly retained in the training target **Cite {solution_lesson_node_00037}**.
2.  **Target:** Train on the **raw `fare_amount`**. Do not log-transform, as this biases the RMSE **Cite {solution_lesson_node_00025}**.

# Evaluation
1.  **Inference:**
    *   Map the test set coordinates to the Geohash keys (Levels 5, 6, 7).
    *   Retrieve the Multi-Scale Interaction Priors using the **Strict Global Statistics** derived from the full 55M dataset (no subtraction needed).
2.  **Prediction:** Generate predictions using the XGBoost model.
3.  **Post-Processing:** Apply a minimum fare floor ($2.50) and ensure coordinate clamping is applied to test inputs **Cite {solution_lesson_node_00003}**.
