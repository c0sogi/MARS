The following strategy outlines the implementation of the solution:

1.  **Imports**: We will import the necessary standard libraries (`os`, `numpy`, `pandas`, `xgboost`) and the provided library modules (`config`, `data_factory`, `feature_pipeline`, `model_engine`).
2.  **Runtime Optimization**: To ensure the script executes within the time limit and serves as a quick demonstration:
    *   We will patch `library.data_factory.LEARNER_SUBSET_SIZE` to `50,000` (down from 5 million). This significantly speeds up the OOF fingerprinting and model training steps.
    *   We will patch `library.config.XGB_PARAMS` to reduce `n_estimators` to `100` and increase `learning_rate` to `0.1`.
    *   We will patch `library.model_engine.EARLY_STOPPING_ROUNDS` to `10`.
3.  **Feature Pipeline Execution**: We will call `library.feature_pipeline.build_features` with `load_cached_data=False`. This forces the system to execute the full logic: loading the Wisdom Set (full training data), computing global statistical fingerprints, subsampling the Learner Set, and generating OOF features. This demonstrates the core "Dual-Hygiene" and "Fingerprinting" logic provided in the library.
4.  **Validation**: We will assert that the generated feature sets (`X_train`, `X_test`, etc.) have the correct shapes, contain expected engineered features (e.g., `dist_haversine`, `L5_mean`), and that the subset size matches our patched configuration.
5.  **Model Training**: We will train the XGBoost model using `library.model_engine.train_regressor` and verify the returned object is a fitted regressor.
6.  **Prediction & Submission**: We will generate predictions using `library.model_engine.predict_fare` (which applies the $2.50 floor) and create a submission file using `library.model_engine.generate_submission`. We will verify the file's existence and format.
