Based on the analysis of previous experiments and the provided lessons, I propose a **Retrieval-Augmented Gradient Boosting** strategy. This approach fundamentally shifts the feature engineering paradigm from simple coordinate geometry to **Spatially-Smoothed Target Encoding**, allowing the model to "retrieve" historical pricing patterns for specific routes. This resolves the conflict between the need to predict high-fare outliers (Lesson 00018) and the instability they cause during training (Lesson 00017).

# Model
I propose using a **Gradient Boosted Decision Tree (XGBoost)** as the backbone, leveraging its superior performance on spatial tabular data **Cite {solution_lesson_node_00030}**.
*   **Structural Innovation (Spatial Target Encoding):** Instead of forcing the tree to learn complex pricing rules solely from raw latitude/longitude splits, I will introduce **Target-Encoded Features**. The spatial domain will be discretized into **Geohashes** (e.g., precision 6). For every route (defined as a `Pickup_Geohash` $\to$ `Dropoff_Geohash` pair), the model will be fed the **historical average fare** from the training set. This allows the model to explicitly "memorize" fixed-rate routes (e.g., Manhattan to JFK) and high-fare patterns that distance features fail to capture, effectively bridging the gap between the "head" and "tail" of the fare distribution.

# Data
The data pipeline is designed to maximize signal retention while ensuring training stability.
1.  **Input Sanitization (Clamping):** Strictly clamp all pickup and dropoff coordinates in the Training, Validation, and Test sets to the NYC bounding box. This prevents the generation of massive distance values from corrupt GPS data, which was the root cause of the baseline failure **Cite {solution_lesson_node_00003}**.
2.  **Target Preservation:** Do **not** truncate the target variable (e.g., removing fares > $500) and do **not** log-transform it. Truncation destroys the ability to predict valid high-fare rides **Cite {solution_lesson_node_00018}**, and log-transformation introduces a systematic under-prediction bias when optimizing for RMSE **Cite {solution_lesson_node_00025}**.
3.  **Feature Engineering:**
    *   **Smoothed Target Encoding:** Calculate the mean `fare_amount` for each `(Pickup_Geohash, Dropoff_Geohash)` pair. To prevent overfitting (data leakage), use **K-Fold Mean Encoding** (calculating the mean for a fold using only data from other folds) and **Smoothing** (blending the route average with the global average based on the number of samples).
    *   **Physical Features:** Retain Haversine distance, Manhattan distance, and Bearing.

# Training
1.  **Objective Function:** Use **Pseudo-Huber Loss** (or Huber Loss).
    *   **Rationale:** Lesson 00017 demonstrated that the standard L2 (RMSE) loss is unstable on the full dataset due to extreme outliers ($93k fares) causing gradient explosions **Cite {solution_lesson_node_00017}**. Pseudo-Huber loss acts as a robust middle ground: it is quadratic for small errors (optimizing the mean, unlike L1/Median) but linear for large errors (preventing outliers from dominating the gradient). This allows us to train on the full dataset without the divergence observed in previous attempts.
2.  **Dataset Scale:** Train on the **Full Dataset** (or the largest feasible subset, e.g., 20M+ rows). The combination of Target Encoding (which explains the variance of high fares) and Huber Loss (which dampens the noise) makes this feasible.

# Evaluation
1.  **Inference:**
    *   Map the test set coordinates to Geohashes.
    *   Retrieve the learned smoothed target encodings. For routes in the test set that were never seen in the training set, fallback to a robust estimate (e.g., `Distance * Global_Cost_Per_Mile`).
2.  **Prediction:** Generate predictions using the XGBoost model and apply a minimum fare floor (e.g., $2.50).
