Implementation Strategy:
1.  **Setup and Configuration**: Import necessary libraries and the provided modules from the `library` package. Set random seeds for reproducibility and suppress warnings to keep the output clean.
2.  **Data Mocking**: Create a small subset of the training and validation data (10,000 rows each) from the provided metadata files. Save these to the `./working` directory. This ensures the demonstration runs quickly and adheres to the "Optimize for Speed" requirement.
3.  **Library Configuration Patching**: Modify the `XGB_PARAMS` dictionary in `library.config` in-place to use fewer estimators and a shallower depth. This ensures the model training step is nearly instantaneous while still exercising the code paths.
4.  **Component Verification (Unit Testing)**:
    *   **Utils**: Verify `haversine_distance` and `filter_within_bbox` with assertions on known inputs.
    *   **Local Features**: Instantiate `LocalFeatureGenerator`, process a sample DataFrame, and verify that expected columns (e.g., `dist_haversine`, `hour`) are created.
    *   **Global Features**: Instantiate `SpatialTargetEncoder`, fit/transform a small sample, and verify that target encoding logic works (e.g., `route_avg_fare` is generated).
5.  **Pipeline Integration**:
    *   Instantiate `DataManager`. Override its `train_path` and `val_path` attributes to point to the mocked small datasets.
    *   Call `load_and_prepare_data` with `load_cached_data=False` to force fresh feature generation on the small dataset.
    *   Verify the shapes of the resulting feature matrices (`X_train`, `X_val`, `X_test`).
6.  **Model Training and Prediction**:
    *   Instantiate `FarePredictor`.
    *   Train the model on the prepared small dataset.
    *   Generate predictions on the test set.
    *   Verify that predictions respect the minimum fare floor logic.
7.  **Output**: Print confirmation messages for each step to demonstrate successful execution.
