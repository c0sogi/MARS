# Proposed Strategy: Fine-Tuned Siamese Dual-Encoder

### Model
To address the limitations of frozen embeddings while avoiding the input truncation issues of cross-encoders, I propose a **Fine-Tuned Siamese Dual-Encoder**.

*   **Backbone:** The model will utilize a lightweight pre-trained Transformer (e.g., `all-MiniLM-L6-v2` or `deberta-v3-xsmall`) as a shared feature extractor. Unlike the baseline, this backbone will be **fully fine-tuned** to learn quality-specific features rather than generic semantic similarity (Cite solution_lesson_node_00001).
*   **Input Architecture:** Instead of encoding the Prompt, Response A, and Response B as three separate vectors (which loses the context of how well a response answers a specific prompt), or concatenating all three into one sequence (which leads to truncation), the model will process data in two parallel passes (Cite solution_lesson_node_00002):
    1.  **Pass A:** `[CLS] Prompt [SEP] Response A`
    2.  **Pass B:** `[CLS] Prompt [SEP] Response B`
    This structure ensures that the interaction between the prompt and the response is captured via the transformer's self-attention layers, while the independent passes ensure that neither response is truncated due to the length of the other.
*   **Classification Head:** The `[CLS]` embeddings from Pass A ($u$) and Pass B ($v$) will be combined into a single feature vector using concatenation and interaction terms: $[u; v; |u - v|; u * v]$. This vector will be fed into a classifier to predict the probability of Winner A, Winner B, or Tie.

### Data
*   **Preprocessing:** Text cleaning will be applied to prompts and responses.
*   **Tokenization:** The data will be tokenized into pairs: `(Prompt, Response A)` and `(Prompt, Response B)`. The maximum sequence length will be set to 512 (or the model's maximum) to accommodate the combined length of a prompt and a single response, ensuring minimal information loss compared to the cross-encoder approach (Cite solution_lesson_node_00002).
*   **Batching:** Data will be batched such that the two passes for a given ID are processed effectively, either by doubling the batch size (stacking A and B) or processing them as paired inputs.

### Training
*   **Optimization Strategy:** The entire model (backbone + head) will be trained end-to-end. Crucially, to prevent the catastrophic divergence observed in previous attempts, the learning rate will be set to **2e-5** with a linear warmup and cosine decay, rather than the aggressive `1e-3` used previously (Cite solution_lesson_node_00004).
*   **Loss Function:** Cross-Entropy Loss will be minimized.
*   **Regularization:** Weight decay and dropout will be employed to prevent overfitting given the increased model capacity compared to the frozen baseline.

### Evaluation
*   **Inference:** For each test instance, the `(Prompt, Response A)` and `(Prompt, Response B)` pairs will be tokenized and passed through the fine-tuned backbone.
*   **Prediction:** The resulting embeddings will be aggregated in the classification head to generate the final probability distribution.
