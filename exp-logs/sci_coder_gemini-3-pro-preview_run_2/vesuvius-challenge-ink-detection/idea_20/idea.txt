Based on the comprehensive empirical analysis and the synthesis of the "Lessons Learned," I propose the **Translation-Invariant SegFormer (MiT-B2) with Discrete Multi-View Training**.

This strategy resolves the critical conflict identified in the project history: the need to detect "wandering" ink strokes that vary in depth (requiring flexible scanning) versus the need for high Signal-to-Noise Ratio (SNR) during training (requiring strict constraints). It introduces a **Discrete Multi-View Training Protocol**—a structural innovation in the data pipeline—to force the model to learn Z-translation invariance without the label noise that caused previous augmentation attempts to fail.

### Model
**Architecture:** I propose the **SegFormer MiT-B2** with the standard **MLP Decoder**.
*   **Backbone:** We will utilize the **MiT-B2** encoder (~25M parameters).
    *   *Rationale:* Previous experiments confirmed that scaling up to MiT-B3 or MiT-B4 in this low-data regime (~400 samples) causes the model to overfit to intensity artifacts, degrading the F0.5 score (Cite Lesson 00040). The B2 backbone provides the optimal balance of receptive field and regularization.
*   **Decoder:** We strictly retain the standard **All-MLP Decoder**.
    *   *Rationale:* Experiments demonstrated that U-Net decoders with direct skip connections propagate high-frequency substrate noise (papyrus fibers) to the output, reducing precision (Cite Lesson 00043). The MLP decoder's bottleneck forces the model to learn robust semantic features.
*   **Input Interface:** We maintain the **3-channel input interface** to utilize **ImageNet-pretrained weights** without modification. This avoids the convergence failures associated with random initialization (Cite Lesson 00024) or channel expansion (Cite Lesson 00025).

### Data
**Preprocessing (Training):**
*   **Overlapping Stratified Depth Projection:** We employ the "Overlapping Thick Slab" strategy (Cite Lesson 00029) to generate high-SNR inputs. We define a slab thickness of 12 slices with 50% overlap.
*   **Structural Innovation: Discrete Multi-View Training Protocol:** Instead of training on a single fixed Z-window (which biases the model to expect ink only in the center channel) or using random Z-jitter (which introduces label noise, Cite Lesson 00035), we define **three discrete, valid depth views** for training. These views are mathematically guaranteed to contain the central ink volume (Slice 32) while varying its channel position:
    1.  **View A (High):** Slices **16–40**. (Ink appears lower, primarily in Channel 2/3).
    2.  **View B (Center):** Slices **20–44**. (Ink appears centered, primarily in Channel 2).
    3.  **View C (Low):** Slices **24–48**. (Ink appears higher, primarily in Channel 1/2).
    *   *Mechanism:* During training, for each image, we randomly sample one of these three views. This forces the model to recognize ink regardless of which channel it occupies, enabling robust inference scanning without the "Signal Dilution" of wide-context inputs (Cite Lesson 00034).
*   **Normalization:** Pixel values are normalized to [0, 1] using dataset statistics.

**Augmentation:**
*   **Geometric Only:** Random horizontal/vertical flips and 90-degree rotations.
*   **Exclusion of Intensity Augmentation:** We explicitly **exclude** brightness/contrast augmentations to preserve physical radiodensity semantics (Cite Lesson 00006).

### Training
*   **Micro-Dataset Optimization Protocol:**
    *   **Batch Size:** We strictly set the batch size to **8**. This maximizes the number of gradient updates per epoch (approx. 50 steps), preventing the underfitting observed with larger batches (e.g., 16) on this small dataset (Cite Lesson 00044).
    *   **Learning Rate:** We use a **Conservative Learning Rate** of `6e-5` with the **AdamW** optimizer. Aggressive rates (e.g., `2e-4`) caused divergence in previous Transformer experiments (Cite Lesson 00037).
*   **Loss Function:** **BCE + Dice Loss**. We utilize the balanced Dice Loss, as weighted variants (Tversky) failed to improve the F0.5 metric (Cite Lesson 00031).
*   **Validation Gating:** The submission file will **only** be generated if the current model's best validation F0.5 score exceeds the previous best baseline (approx. 0.598), ensuring only superior models are submitted (Cite Lesson 00004).

### Evaluation
**Inference Strategy: Multi-View Ensemble Scanning**
We leverage the model's learned translation invariance to capture wandering ink strokes at test time.
1.  **Scanning:** For each test fragment, we generate the same three input tensors used in training (View A, View B, View C).
2.  **Inference:** The trained MiT-B2 model predicts a probability map for each view.
3.  **Max-Fusion:** We compute the **Maximum Probability Projection** across the three predictions per pixel.
    *   *Rationale:* Since the model is explicitly trained to be invariant to the ink's channel position, it will output high confidence in *at least one* view where the ink is best focused. Max-fusion effectively aggregates these confident detections (Cite Lesson 00042).
4.  **Defensive Inference:** Explicitly check input tensor shapes `(Batch, 3, H, W)` before batching to prevent runtime errors (Cite Lesson 00005).
5.  **Test Time Augmentation (TTA):** We average predictions from geometric flips within each view before the final fusion.
