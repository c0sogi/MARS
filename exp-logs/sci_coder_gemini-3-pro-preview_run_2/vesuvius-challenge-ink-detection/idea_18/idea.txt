Based on the comprehensive empirical history and the synthesis of "Lessons Learned," I propose the **Multi-View Robust SegFormer (MiT-B2)**.

This strategy introduces a structural evolution to the "Decoupled Z-Scanning" concept (Idea 17). It addresses the critical flaw of previous scanning attempts—**Channel Variance**—where a model trained only on centered data failed to recognize ink when it appeared in different depth channels during inference scanning. By implementing a **Discrete Multi-View Training Protocol**, we force the model to learn Z-translation invariance, enabling it to robustly detect "wandering ink" strokes across the depth volume without diluting the signal or introducing label noise.

### Model
**Architecture:** I propose the **SegFormer MiT-B2** with the standard **MLP Decoder**.
*   **Backbone:** We utilize the **MiT-B2** encoder (~25M parameters).
    *   *Rationale:* Previous experiments demonstrated that scaling up to MiT-B3 or MiT-B4 in this low-data regime (~400 samples) causes overfitting to intensity artifacts (Cite Lesson 00040). The B2 backbone offers the optimal balance of capacity and regularization.
*   **Decoder:** We strictly retain the standard **All-MLP Decoder**.
    *   *Rationale:* Experiments showed that U-Net decoders with direct skip connections propagate high-frequency substrate noise, degrading precision (Cite Lesson 00043). The MLP decoder's bottleneck forces the model to learn robust semantic features.
*   **Input Interface:** We maintain the **3-channel input interface** to utilize **ImageNet-pretrained weights** without modification, ensuring stable convergence (Cite Lesson 00024, 00025).

### Data
**Preprocessing (Training):**
*   **Overlapping Stratified Depth Projection:** We employ the "Overlapping Thick Slab" strategy (Cite Lesson 00029) to generate high-SNR inputs. We define a slab thickness of 12 slices with 50% overlap.
*   **Structural Innovation: Discrete Multi-View Sampling:** Instead of training on a single fixed Z-window (e.g., 20-44), we define **three valid depth views** that guarantee the inclusion of the central ink volume (Slice 32) while varying its channel position:
    1.  **View A (High):** Slices **16–40**. (Ink appears lower in the frame).
    2.  **View B (Center):** Slices **20–44**. (Ink appears centered).
    3.  **View C (Low):** Slices **24–48**. (Ink appears higher in the frame).
    *   *Rationale:* By randomly sampling one of these views for each training example, we force the model to recognize ink regardless of which channel (Top, Mid, Bottom) it occupies. This solves the "Channel Variance" problem that undermined previous scanning approaches, while avoiding the "Signal Dilution" of wide-context inputs (Cite Lesson 00034).
*   **Normalization:** Pixel values are normalized to [0, 1] using dataset statistics.

**Augmentation:**
*   **Geometric Only:** Random horizontal/vertical flips and 90-degree rotations.
*   **Exclusion of Intensity Augmentation:** We explicitly **exclude** brightness/contrast augmentations to preserve physical radiodensity semantics (Cite Lesson 00006).

### Training
*   **Optimization Protocol:**
    *   **Batch Size:** We strictly set the batch size to **8**. This maximizes the number of gradient updates per epoch, preventing the underfitting observed with larger batches on this micro-dataset (Cite Lesson 00044).
    *   **Learning Rate:** We use a **Conservative Learning Rate** of `6e-5` with the **AdamW** optimizer. Aggressive rates (e.g., `2e-4`) caused divergence in previous Transformer experiments (Cite Lesson 00037).
*   **Loss Function:** **BCE + Dice Loss**. We utilize the balanced Dice Loss, as weighted variants (Tversky) failed to improve the F0.5 metric (Cite Lesson 00031).
*   **Validation Gating:** The submission file will **only** be generated if the current model's best validation F0.5 score exceeds the previous best baseline (approx. 0.598), ensuring only superior models are submitted (Cite Lesson 00004).

### Evaluation
**Inference Strategy: Multi-View Ensemble Scanning**
We leverage the model's multi-view robustness to capture wandering ink strokes at test time.
1.  **Scanning:** For each test fragment, we generate the same three input tensors used in training (View A, View B, View C).
2.  **Inference:** The trained MiT-B2 model predicts a probability map for each view.
3.  **Max-Fusion:** We compute the **Maximum Probability Projection** across the three predictions per pixel.
    *   *Rationale:* Since the model is explicitly trained to be invariant to the ink's channel position, it will output high confidence in *at least one* view where the ink is best focused. Max-fusion effectively aggregates these confident detections (Cite Lesson 00042).
4.  **Defensive Inference:** Explicitly check input tensor shapes `(Batch, 3, H, W)` before batching to prevent runtime errors (Cite Lesson 00005).
5.  **Test Time Augmentation (TTA):** We average predictions from geometric flips within each view before the final fusion.
