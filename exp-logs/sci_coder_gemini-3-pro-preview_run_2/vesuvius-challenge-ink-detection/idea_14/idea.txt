Based on the comprehensive empirical history and lessons learned, I propose the **Siamese Multi-View SegFormer (Siamese-MVS)**.

This strategy introduces a structural innovation—a **Siamese Network Topology**—to resolve the core conflict identified in Lessons 00034 and 00035: the trade-off between capturing "wandering" ink strokes (which requires a wide depth range) and maintaining high Signal-to-Noise Ratio (SNR) (which requires narrow, focused data). By processing multiple depth views in parallel through a shared encoder and fusing them in feature space, this model explicitly learns to identify ink regardless of its specific Z-position, without diluting the input signal or introducing label noise.

### Model
**Architecture:** I propose a **Siamese SegFormer** network.
*   **Backbone (Shared Encoder):** We will utilize the **SegFormer MiT-B2** encoder. We strictly retain the B2 architecture (approx. 25M parameters) rather than scaling up to B3 or B4, as previous experiments demonstrated that larger models in this low-data regime (~400 samples) tend to overfit to intensity artifacts and degrade performance (Cite Lesson 00040).
*   **Siamese Topology:** Instead of a single input stream, the model is designed to accept **three parallel input streams**, each representing a different Z-depth "view" of the same surface patch (e.g., Upper, Center, Lower).
    *   These three inputs are processed by the **same shared encoder instance** (weights are tied). This ensures that the model learns a consistent feature representation for "ink" regardless of which depth view it appears in.
    *   Crucially, this maintains the standard **3-channel input interface** for the encoder, allowing us to initialize with **ImageNet-pretrained weights** and avoiding the failure modes associated with modifying the input layer (Cite Lesson 00025).
*   **Feature Fusion:** The multi-scale feature maps produced by the encoder for the three views are aggregated using **Element-wise Max Pooling**. This operation acts as a "Feature-Space MIP," selecting the strongest ink signal from the three views while suppressing noise from the empty views.
*   **Decoder:** A standard MLP decoder receives the fused feature maps to predict the final binary segmentation mask.

### Data
**Preprocessing:**
*   **Base Representation (Overlapping Thick Slabs):** We retain the highly effective "Overlapping Thick Slab" projection method (Cite Lesson 00029). Each input view is a 3-channel image where:
    *   Channel 1: MIP of slices $N$ to $N+12$.
    *   Channel 2: MIP of slices $N+6$ to $N+18$.
    *   Channel 3: MIP of slices $N+12$ to $N+24$.
*   **Multi-View Generation:** For every training sample, we generate **three distinct 3-channel input tensors**, corresponding to shifted windows along the Z-axis:
    1.  **View 1 (High):** Start index $N=16$ (Covers slices 16–40).
    2.  **View 2 (Center):** Start index $N=20$ (Covers slices 20–44).
    3.  **View 3 (Low):** Start index $N=24$ (Covers slices 24–48).
    *   *Rationale:* This covers a wide total depth (16–48) to capture wandering ink, but each individual view remains "narrow" and high-contrast. This avoids the "Signal Dilution" caused by cramming too many slices into one input (Cite Lesson 00034).
*   **Normalization:** Pixel values are normalized to [0, 1] using dataset statistics.

**Augmentation:**
*   **Geometric Only:** We apply random horizontal/vertical flips and 90-degree rotations.
*   **Intensity Constraints:** We explicitly **exclude** brightness, contrast, and gamma augmentations to preserve the physical radiodensity semantics required for ink detection (Cite Lesson 00006).
*   **Exclusion of Z-Jitter:** We exclude random Z-jitter. Since the Siamese network sees the full relevant volume via the three views, random shifting is unnecessary and would only introduce label noise (Cite Lesson 00035).

### Training
*   **Loss Function:** We use a composite **BCE + Dice Loss**. We reject weighted variants like Tversky Loss, as they failed to outperform the balanced baseline in previous trials (Cite Lesson 00031).
*   **Optimizer:** **AdamW** optimizer with a `ReduceLROnPlateau` scheduler. We will use a **conservative learning rate** (e.g., `6e-5`) to ensure stability, avoiding the divergence observed with aggressive tuning on larger models (Cite Lesson 00037).
*   **Validation Gating:** The execution script will implement a strict logic gate. The submission file will **only** be generated if the current model's best validation F0.5 score exceeds the previous best baseline (approx. 0.598). (Cite Lesson 00004).

### Evaluation
*   **Siamese Inference:** During inference, we generate the same three views (High, Center, Low) for each test fragment and feed them into the Siamese model. The model internally fuses the features and outputs a single probability map.
*   **Defensive Inference:** The pipeline will explicitly check that the input tensors have the correct shapes before batching to prevent runtime errors (Cite Lesson 00005).
*   **Test Time Augmentation (TTA):** We will average predictions from the original input and its geometric transformations (flips/rotations) to further maximize the F0.5 score.
