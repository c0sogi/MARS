Implementation Strategy:
1.  **Configuration Setup**: Override default `Config` parameters to create a lightweight execution environment. Set `EPOCHS` to 1, `BATCH_SIZE` to 2, and define a custom `WORKING_DIR` to isolate outputs.
2.  **Utility Verification**: Test the `rle_encoding` and `fbeta_score` functions with known inputs to ensure they function correctly.
3.  **Dataset Instantiation**: Load the provided training metadata. Filter it to a very small subset (e.g., 4 samples) to minimize I/O overhead when loading 3D volumes. Instantiate `InkDataset` and verify the shape and data types of the yielded batches.
4.  **Model Initialization**: Instantiate the `SpecialistModel`. Pass a batch of data through it to confirm the forward pass works and produces outputs of the expected shape `(B, 1, H, W)`.
5.  **Training Loop Simulation**: Execute `train_specialist` using the subset dataloaders. This verifies the training loop, loss calculation, and metric reporting. We force the validation threshold low to ensure the checkpointing logic is exercised.
6.  **Inference Component Test**: Instead of running the full inference pipeline (which processes large test volumes), demonstrate the core inference functions (`predict_slab`, `fuse_predictions`) using the trained model and the validation dataset. Verify that probability maps are generated and correctly fused.
7.  **Assertions**: Throughout the script, use `assert` statements to validate shapes, types, and logic flow.
