The `AssertionError` arises because `GroupShuffleSplit` partitions the data based on the number of groups (locations), not the number of samples (images). Since the number of images varies significantly across locations, selecting 20% of the locations resulted in only ~11% of the total images, failing the validation check which requires the split to be between 19% and 21% of samples.

To fix this, I will replace the `GroupShuffleSplit` implementation with a custom greedy splitting logic. This logic will:
1.  Shuffle the unique locations (groups).
2.  Iteratively add locations to the validation set.
3.  Stop when the accumulated number of images is closest to the target validation size (20% of total samples).

This ensures the validation set size is correct in terms of samples while maintaining the strict group separation required to prevent data leakage. The existing code already correctly handles schema normalization as per `debug_lesson_1` (lines 32-37), so no changes are needed for column naming.
