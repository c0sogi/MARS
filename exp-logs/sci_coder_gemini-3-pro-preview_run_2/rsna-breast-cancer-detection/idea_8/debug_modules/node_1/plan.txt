To address the `RuntimeError` caused by loading a stale, incompatible model checkpoint and the underlying training instability (NaN losses), I will implement the following targeted fixes:

1.  **Clean Stale Artifacts (`runfile.py`):** Explicitly remove the `best_model.pth` file if it exists before training starts. This ensures that the inference step cannot load a leftover checkpoint from a previous experiment with a mismatched architecture (e.g., 1-channel vs. 3-channel).
2.  **Improve Training Stability (`runfile.py`):** Increase `BATCH_SIZE` from 4 to 8 and reduce `LEARNING_RATE` to `1e-4`. The original batch size of 4 is too small for stable Batch Normalization statistics, contributing to NaN losses when combined with random initialization (`pretrained=False`).
3.  **Robust Checkpointing (`library/trainer.py`):** Modify the saving logic to ensure a model checkpoint is saved at least once (e.g., after the first epoch), even if the validation loss is NaN or does not improve. This guarantees that the inference phase always finds a valid, architecture-compatible model file to load, preventing the crash.
