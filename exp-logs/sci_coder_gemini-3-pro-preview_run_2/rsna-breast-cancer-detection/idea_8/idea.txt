Based on the accumulated lessons from previous experiments, I propose the **High-Resolution Multi-Task Network with Stable Focal Optimization**.

This strategy addresses the critical failure modes of previous attempts: it avoids the feature collapse of frozen embeddings, the calibration drift of balanced sampling, and the numerical instability of high-weight Mixed Precision training. It introduces a structural evolution by scaling the input resolution to 1024x1024 (essential for microcalcification detection) while maintaining computational feasibility through Gradient Accumulation and efficient architecture.

### Model
**Architecture: Fine-Tuned EfficientNetV2-Small with Auxiliary Heads**
1.  **Visual Backbone:** The model utilizes an **EfficientNetV2-Small** backbone. Crucially, this will be **completely unfrozen and fine-tuned** end-to-end to adapt to the specific grayscale texture statistics of mammography (Cite {solution_lesson_node_00002}). The V2 variant is selected for its memory efficiency, allowing for higher resolution inputs than previous B-series iterations.
2.  **Pooling & Fusion:** Feature maps are aggregated using **Generalized Mean Pooling (GeM)**, which focuses on high-activation regions (lesions) more effectively than standard average pooling. This visual embedding is concatenated with a normalized metadata vector (Age, Implant, View, Machine ID) processed by a parallel MLP.
3.  **Multi-Task Heads:** The network branches into three outputs to leverage all training signals and improve feature robustness:
    *   **Primary Head:** Binary classification for `cancer`.
    *   **Auxiliary Head 1:** Regression for `BIRADS` scores.
    *   **Auxiliary Head 2:** Classification for `density`.

### Data
1.  **Single-Instance Learning (SIL):** The pipeline strictly follows the SIL paradigm where patient-level labels are broadcast to every image. This **dense supervision** is retained as it outperforms the sparse supervision of Multi-Instance Learning in this domain (Cite {solution_lesson_node_00005}).
2.  **Resolution Upgrade:** Input images will be resized to **1024x1024**. This is a significant structural shift from the 512px/640px used previously, designed to capture subtle microcalcifications that are lost at lower resolutions.
3.  **Ingestion:** The robust **Byte-Level Image Extractor** (using `cv2.imdecode` on binary streams) is used to handle DICOM files without `pydicom`.

### Training
1.  **Objective: FP32 Focal Loss:**
    *   To address the class imbalance without the numerical instability observed in Idea 5, the model will use **Focal Loss** instead of `BCEWithLogitsLoss`. Focal Loss dynamically down-weights easy negatives, eliminating the need for large scalar `pos_weight` values that cause `NaN` divergence in Mixed Precision training (Cite {solution_lesson_node_00008}).
    *   **Stability Enforcer:** The loss calculation will be explicitly wrapped in a `float32` context manager to ensure numerical precision during the gradient computation step.
2.  **Sampling: Natural Distribution:**
    *   The training will use a **Standard Random Sampler** rather than a Weighted Random Sampler. This ensures the model learns the true prior probability of cancer (~2%), preserving **probability calibration** which is critical for the Probabilistic F1 metric (Cite {solution_lesson_node_00010}).
3.  **Optimization:**
    *   **Gradient Accumulation:** To accommodate the memory-intensive 1024x1024 resolution on a single GPU, gradients will be accumulated over multiple micro-batches before an optimizer step.
    *   **Optimizer:** AdamW with a OneCycleLR scheduler.

### Evaluation
1.  **Inference:** The model iterates through the test set. Auxiliary heads are ignored, and only the probability from the **Primary Cancer Head** is extracted.
2.  **Test Time Augmentation (TTA):** To further boost robustness, predictions will be averaged across horizontal flips of the input image.
3.  **Aggregation:** Predictions are grouped by `prediction_id`. The final submission score is the **maximum** probability across all images (views) associated with that ID (Cite {solution_lesson_node_00005}).
