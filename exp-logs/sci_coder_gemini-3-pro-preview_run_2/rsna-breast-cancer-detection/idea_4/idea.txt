Based on the failure of the frozen embedding approach (Idea 2) and the insights from **Lesson 00002**, I propose a structural evolution that shifts from Single-Instance learning to **Multi-Instance Learning (MIL)**, while strictly adhering to the requirement for end-to-end fine-tuning.

# Idea 4: Multi-View Attention Network (MVAN) with End-to-End Fine-Tuning

### Model
The core innovation is treating the "breast" (a set of views) as the fundamental unit of analysis rather than the individual "image." This allows the model to synthesize information across complementary views (e.g., CC and MLO) to improve detection confidence, rather than relying on a naive "max" aggregation.

1.  **Instance Encoder (Backbone):** An **EfficientNet-B2** initialized with ImageNet weights. Crucially, this backbone will be **completely unfrozen and fine-tuned** end-to-end. This directly addresses **Cite {solution_lesson_node_00002}**, ensuring the feature extractor adapts to the specific grayscale texture statistics of mammograms (e.g., microcalcifications) which frozen ImageNet weights fail to capture.
2.  **View Aggregation (MIL Head):** Instead of simple pooling, the feature vectors from all views of a single breast (grouped by `patient_id` and `laterality`) are passed to a **Gated Attention Mechanism**. This layer learns to assign importance weights to each view, allowing the model to focus on the view with the clearest lesion while ignoring non-informative views, producing a single distinct "Breast Embedding."
3.  **Metadata Fusion:** The learned Breast Embedding is concatenated with the processed clinical metadata (Age, Implant, Machine ID, etc.) from the tabular branch.
4.  **Classifier:** A final fully connected layer outputs the probability of cancer for the breast.

### Data
1.  **Grouped Ingestion:** The data pipeline will be restructured to load **bags of images**. For each unique `patient_id` + `laterality` combination (representing one breast), all available images are loaded simultaneously.
2.  **Byte-Level Extraction (Retained):** The robust byte-level image decoding strategy (scanning for JPEG/JPEG2000 headers and using `cv2.imdecode`) is retained to handle the DICOM files without `pydicom`.
3.  **High-Resolution Input:** Images will be resized to **640x640** (or higher). This higher resolution is essential to preserve the subtle texture anomalies that were lost at the 224x224 resolution used in the failed experiment **Cite {solution_lesson_node_00002}**.
4.  **Augmentation:** Strong instance-level augmentation (random affine transforms, flips) will be applied to each view independently to prevent the fine-tuning backbone from overfitting.

### Training
1.  **Procedure:** The model is trained end-to-end. The input batch consists of "bags" of images (e.g., Batch Size = 8 breasts, where each breast has 1-4 images).
2.  **Loss Function:** **BCEWithLogitsLoss** is applied to the breast-level prediction. A high `pos_weight` (e.g., 20-50) is used to counter the class imbalance.
3.  **Regularization:** To further stabilize the fine-tuning of the CNN backbone on this smaller medical dataset, **Stochastic Depth (DropPath)** and heavy weight decay (AdamW) will be employed.

### Evaluation
1.  **Inference:** The test set is grouped by `prediction_id`. For each ID, all associated images are loaded, processed by the backbone, aggregated via the Attention mechanism, and fused with metadata to produce a single probability.
2.  **Submission:** This single probability is assigned to the `prediction_id`, naturally handling the requirement without arbitrary post-processing rules like "max" or "mean."
