Based on the accumulated lessons and the analysis of previous experiments, I propose the **RoBERTa-Large with Bias-Centric Sample Weighting and Stability Enhancements**.

This strategy represents a structural evolution that addresses the limitations of previous approaches: it leverages the superior capacity of "Large" Transformers (validated in Lesson 12) while solving the optimization conflict between primary and auxiliary tasks (Lesson 15) and correcting the numerical instability issues (Lesson 18) that caused previous high-capacity attempts to fail.

### Model
We will construct a **Multi-Task RoBERTa-Large** architecture designed for maximum capacity and robust generalization.

*   **Backbone:** We will upgrade the feature extractor to **RoBERTa-Large**. Lesson 12 proved that pre-trained Transformers significantly outperform RNNs, and Lesson 4 demonstrated that **Capacity Scaling** is critical when disentangling complex confounders (identities) from targets (toxicity). The "Large" variant provides the necessary depth to model these distinct concepts without underfitting (Cite solution_lesson_node_00012, solution_lesson_node_00004).
*   **Aggregation:** We will replace the standard `[CLS]` token classification with **Attention Pooling**. This allows the model to dynamically weight tokens (e.g., emphasizing the context around an identity term rather than the term itself), which Lesson 2 showed is superior to static pooling for capturing nuance (Cite solution_lesson_node_00002).
*   **Regularization:** We will apply **Spatial Dropout** to the sequence of hidden states before pooling to force distributed feature learning (Cite solution_lesson_node_00002). Additionally, we will implement **Multi-Sample Dropout** (passing the pooled features through multiple dropout masks and averaging the outputs) to further smooth the decision boundary and reduce variance.
*   **Multi-Task Heads:** We retain the auxiliary **Identity Head** to explicitly supervise the learning of identity features, ensuring they are not conflated with toxicity (Cite solution_lesson_node_00001).

### Data
We will process the **Full Dataset** using the efficiency optimizations required to train the "Large" model within the 24-hour limit.

*   **Preprocessing:** Text will be tokenized using the RoBERTa-Large tokenizer and pre-padded to a fixed length (e.g., 512) into contiguous `int32` arrays.
*   **Device-Side Trimming:** We will strictly employ the **"Pad-then-Trim"** strategy. Fixed-length batches are loaded to the GPU and dynamically sliced to the maximum non-padding length of that specific batch before the forward pass. This maximizes GPU throughput and avoids the CPU bottlenecks associated with custom collation (Cite solution_lesson_node_00007).

### Training
The training procedure introduces a structural shift in how bias is mitigated to resolve the conflict identified in Lesson 15.

*   **Loss Function (Structural Innovation):** Instead of relying on an aggressive auxiliary weight ($\lambda > 1.0$) which risks overpowering the primary task (Cite solution_lesson_node_00015), we will shift the bias mitigation burden to the primary loss via **Identity-Based Sample Weighting**.
    *   $L_{total} = L_{BCE}(\text{Tox}, \text{weight}=w_{sample}) + \lambda_{aux} L_{BCE}(\text{Ident})$
    *   **Sample Weighting:** We will assign a higher weight (e.g., 5.0) to any training example that mentions an identity. This forces the primary head to focus on the "hard" BPSN/BNSP examples directly, allowing us to keep $\lambda_{aux}$ moderate (e.g., 0.4) to serve only as a feature regularizer.
*   **Optimizer:** We will use **AdamW** with **OneCycleLR** scheduling to achieve super-convergence, enabling the heavy model to fit the data efficiently (Cite solution_lesson_node_00006).
*   **Stochastic Weight Averaging (SWA):** Towards the end of training, we will employ SWA to average the weights of several checkpoints. This stabilizes the model in a flat region of the loss landscape, which is crucial for minimizing the variance of the sensitive generalized mean metric ($p=-5$).

### Evaluation
*   **Inference:** The test set will be processed using the same **Device-Side Trimming** pipeline.
*   **Metric Stability:** When calculating the Generalized Mean of Bias AUCs ($p=-5$) for internal validation, we will **clip the predictions** to a safe range (e.g., `[1e-6, 1-1e-6]`). This prevents the divide-by-zero errors and numerical explosions that caused the failure of previous high-capacity attempts (Cite solution_lesson_node_00018).
*   **Prediction:** We will generate predictions using solely the **Toxicity Head** of the final SWA-averaged model.
