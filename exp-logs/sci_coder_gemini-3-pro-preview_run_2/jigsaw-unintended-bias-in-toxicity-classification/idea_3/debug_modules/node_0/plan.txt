Implementation Strategy:
1.  **Environment Setup**: Import necessary libraries and the provided modules from the `library` package. Set a fixed random seed for reproducibility.
2.  **Configuration Override**: Modify the `Config` class attributes to optimize for a quick demonstration. This includes setting `EPOCHS` to 1, reducing batch sizes, and defining a temporary working directory (`./working/demo_run`) to avoid clutter.
3.  **Data Subsampling**: To ensure the script runs within the time limit, create "mini" versions of the metadata files (e.g., 100 training samples, 20 validation/test samples) by reading the top rows of the original metadata and saving them to the working directory. Update the `Config` paths to point to these mini-files. This forces the data loading pipeline to process only a tiny fraction of the data.
4.  **Component Verification**:
    *   **Data Pipeline**: Call `get_dataloaders` and fetch a single batch to verify that the data is loaded, tokenized, and collated correctly (checking shapes and keys).
    *   **Model & Loss**: Instantiate the `MultiTaskRoberta` model and `AggressiveMultiTaskLoss`. Perform a forward pass with the fetched batch on the CPU to verify output shapes and ensure the loss function calculates a valid scalar without errors.
5.  **Training Execution**: Initialize the `Engine` class and run the full training loop (`run_training`) using the subsampled dataloaders. This will demonstrate the training, validation, model saving, and inference processes.
6.  **Submission Verification**: Check that the submission file is generated in the expected location and contains the correct number of rows corresponding to the mini test set.
