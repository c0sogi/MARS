Based on the accumulated lessons and previous experiments, I propose the **Identity-Weighted RoBERTa-Large with Stochastic Weight Averaging (SWA)**.

This strategy structurally evolves the solution by shifting the burden of bias mitigation from "Aggressive Auxiliary Loss" (which risks overpowering the primary task, Cite solution_lesson_node_00015) to **Identity-Based Sample Weighting** within the primary task itself. Furthermore, it introduces **Stochastic Weight Averaging (SWA)** to stabilize the optimization trajectory, addressing the high variance inherent in the generalized mean metric ($p=-5$).

### Model
We will implement a **Multi-Task RoBERTa-Large** architecture designed for maximum capacity and robust generalization.
*   **Backbone:** We will upgrade the feature extractor to **RoBERTa-Large**. Lesson 12 proved that pre-trained Transformers outperform RNNs even on data subsets, and Lesson 4 demonstrated that **Capacity Scaling** is essential when disentangling complex confounders like identity mentions from toxicity (Cite solution_lesson_node_00012, solution_lesson_node_00004).
*   **Aggregation:** We will use **Attention Pooling** on the sequence of hidden states. This allows the model to dynamically weight tokens (e.g., focusing on the context around an identity term), which Lesson 2 showed is superior to static pooling for capturing nuance (Cite solution_lesson_node_00002).
*   **Regularization:** We will apply **Spatial Dropout** to the hidden states (Cite solution_lesson_node_00002) and utilize **Multi-Task Heads** (Toxicity + Identity) to enforce feature disentanglement (Cite solution_lesson_node_00001).
*   **Weight Averaging (Structural Innovation):** Instead of using the weights from a single "best" epoch, the final model will be constructed using **Stochastic Weight Averaging (SWA)**. We will average the model weights from multiple checkpoints near the end of training. This creates a model centered in the flat region of the loss landscape, significantly improving generalization on the sensitive bias metrics.

### Data
We will process the **Full Dataset** using efficiency optimizations to accommodate the larger backbone.
*   **Preprocessing:** Text will be tokenized using the RoBERTa-Large tokenizer and pre-padded to a fixed length (e.g., 512) into contiguous `int32` arrays.
*   **Device-Side Trimming:** We will employ the **"Pad-then-Trim"** strategy. Fixed-length batches are loaded to the GPU and dynamically sliced to the maximum non-padding length of that specific batch before the forward pass. This maximizes GPU throughput and eliminates CPU bottlenecks (Cite solution_lesson_node_00007).
*   **Identity-Based Sample Weighting:** To address the "Risk of Dominant Auxiliary Losses" (Cite solution_lesson_node_00015), we will not rely solely on a high $\lambda$ for the identity head. Instead, we will pre-calculate a **Sample Weight** for every training example. Examples that mention any identity (where `identity_sum > 0`) will be assigned a higher weight (e.g., 5.0) in the primary toxicity loss function. This forces the model to prioritize the "hard" examples (BPSN/BNSP quadrants) directly in the main task, without distorting the feature space with excessive auxiliary gradients.

### Training
*   **Loss Function:** The total loss will be:
    $$L = L_{BCE}(\text{tox}_{pred}, \text{tox}_{true}, \text{weight}=w_{sample}) + \lambda L_{BCE}(\text{ident}_{pred}, \text{ident}_{true})$$
    We will use a balanced $\lambda$ (e.g., 0.5) to let the auxiliary task guide representation learning without dominating it (Cite solution_lesson_node_00015), while the $w_{sample}$ ensures the primary head focuses on bias mitigation.
*   **Optimizer:** We will use **AdamW** with **OneCycleLR** scheduling to achieve super-convergence within the runtime limits (Cite solution_lesson_node_00006).
*   **SWA Schedule:** We will run the OneCycle schedule for the majority of the training, then switch to a constant, low learning rate for a few final epochs to collect SWA checkpoints.

### Evaluation
*   **Inference:** The test set will be processed using the same **Device-Side Trimming** pipeline.
*   **Prediction:** We will generate predictions using the **Toxicity Head** of the SWA-averaged model. The auxiliary Identity Head is used only during training.
