Based on the task requirements and the provided dataset analysis, here is a proposal for a highly efficient baseline approach.

### Model
**Architecture: Cascade Segmentation-Classification Pipeline**
This approach decouples the problem into two distinct, manageable stages: finding the "ink" (localization) and reading the "ink" (classification). This separation simplifies the learning process for the high-cardinality classification task (3,800+ classes).

1.  **Stage 1: Binary Segmentation Network (Localizer)**
    *   **Design:** A lightweight **U-Net** architecture utilizing a computationally efficient backbone (e.g., MobileNetV2 or ResNet-18).
    *   **Function:** This network performs binary semantic segmentation. It takes the full page (or large tiles) as input and outputs a probability map indicating whether each pixel belongs to a "valid character" or "background".
    *   **Rationale:** By training only on the ground truth bounding boxes, this model learns to detect the main text while suppressing background noise, illustrations, and the unlabelled "annotation" characters (which are visually distinct and smaller).

2.  **Stage 2: Patch Classifier (Recognizer)**
    *   **Design:** A standard **ResNet-18** Convolutional Neural Network.
    *   **Function:** This network acts as a dedicated image classifier. It accepts cropped image patches identified by Stage 1 and outputs a probability distribution over the 3,848 character classes using a standard Softmax layer.
    *   **Rationale:** Using a standard CNN for classification is more stable and easier to converge than training a dense detection head (like YOLO) for such a massive number of classes from scratch.

### Data
1.  **Stage 1 Preprocessing (Mask Generation):**
    *   Convert the training bounding boxes into binary masks. Create a blank image (zeros) of the same size as the source. Fill the rectangles defined by the ground truth bounding boxes with ones.
    *   Resize the images and masks to a fixed resolution (e.g., 512x512 or 1024x1024) suitable for the U-Net, or prepare a tiling strategy for high-resolution training.

2.  **Stage 2 Preprocessing (Crop Generation):**
    *   Extract individual character crops from the training images using the ground truth bounding boxes.
    *   Resize all crops to a fixed square dimension (e.g., 64x64 pixels), padding with white or edge values to preserve the aspect ratio, as character shape is crucial.
    *   Normalize pixel values (0-1) using the dataset statistics calculated in the analysis (Mean: ~0.7, Std: ~0.2).

### Training
1.  **Training Stage 1 (Localizer):**
    *   **Loss Function:** Use a combination of **Binary Cross-Entropy (BCE)** and **Dice Loss**. BCE handles pixel-wise accuracy, while Dice Loss ensures the model focuses on the intersection of the predicted and ground truth shapes, helping with the foreground-background imbalance.
    *   **Optimizer:** AdamW with a standard learning rate scheduler (e.g., Cosine Annealing).

2.  **Training Stage 2 (Recognizer):**
    *   **Loss Function:** **Categorical Cross-Entropy Loss**.
    *   **Strategy for Imbalance:** Address the extreme class imbalance (ratio ~15,000) by using a **Weighted Random Sampler** in the dataloader. This ensures that rare characters are seen frequently enough for the model to learn them, preventing bias towards common characters like 'no' (の) or 'ni' (に).

### Evaluation
1.  **Inference Pipeline:**
    *   **Step 1:** Pass the test image through the Stage 1 U-Net to generate a binary probability map.
    *   **Step 2:** Threshold the map (e.g., >0.5) to create a binary mask. Apply **Connected Component Analysis (CCA)** to find independent blobs of ink. Filter out extremely small blobs (noise) based on area.
    *   **Step 3:** For each connected component, calculate its bounding box and center point.
    *   **Step 4:** Extract the crop corresponding to the bounding box from the original test image. Resize it to the input size of the Stage 2 Classifier (64x64).
    *   **Step 5:** Pass the batch of crops through the Stage 2 Classifier to obtain the predicted Unicode labels.
2.  **Submission Generation:**
    *   Combine the center coordinates derived from Stage 1 with the labels predicted by Stage 2 to format the submission string (`Label X Y`) for each image.
