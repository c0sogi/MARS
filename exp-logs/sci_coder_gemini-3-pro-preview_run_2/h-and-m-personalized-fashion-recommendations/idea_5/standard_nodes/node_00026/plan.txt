The issue is that the `preprocess_sequences` function, decorated with `@utils.cache_result`, loads the cached dataset tensors directly onto the GPU (CUDA) because `library/utils.py` uses `map_location=config.DEVICE` (which is "cuda"). However, the `DataLoader` in `library/sequential_encoder.py` uses multiple worker processes (`num_workers=12`). Standard multiprocessing cannot share CUDA tensors between processes, causing a `CUDA error: initialization error` when workers attempt to access the GPU-resident data.

To fix this, I will modify `library/utils.py` to explicitly load cached `.pt` files to the CPU (`map_location="cpu"`). This ensures that the source tensors remain in CPU memory, allowing the multi-process `DataLoader` to function correctly. The tensors will then be moved to the GPU within the training loop as intended. This aligns with **debug_lesson_6** ("Keep Source Tensors on CPU for Multi-Process DataLoaders").
