The optimization strategy focuses on enhancing the Ranking Stage of the pipeline, leveraging the available compute time to improve the model's ability to discriminate between relevant and irrelevant items within the candidate set.

1.  **Objective Function Upgrade (Cite Lesson 00008)**: The Ranker is transitioned from a binary classification task (`objective='binary'`, optimizing AUC) to a Learning-to-Rank task (`objective='lambdarank'`, optimizing MAP@12). This aligns the loss function directly with the competition metric, ensuring the model prioritizes the correct ordering of the top 12 items rather than just their individual probability of being purchased.
2.  **Training Data Scale**: The training sample size is quadrupled from 50,000 to 200,000 users. Since the previous pipeline completed in ~11 minutes (well under the 4-hour limit), increasing the data volume allows the model to learn more robust patterns across diverse user segments without risking a timeout.
3.  **Candidate Expansion**: The number of co-occurrence candidates (`TOP_K_COOC`) is increased from 60 to 100. This improves recall by allowing the retrieval stage to pass a larger pool of potential items to the ranker, which can then filter them effectively using the more sophisticated objective function.
4.  **Hyperparameter Tuning**: LightGBM parameters are adjusted (`num_leaves=80`, `learning_rate=0.03`, `n_estimators=3000`) to support the increased data volume and complexity of the ranking task.
