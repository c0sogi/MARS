The implementation strategy involves the following steps:

1.  **Setup and Data Loading**: Define input and output directories. Load the `transactions_train.csv` and `sample_submission.csv` using Pandas. The transactions file serves as the source for training and validation data, while the sample submission defines the test set customers.
2.  **Group Sampling Split**: Identify unique `customer_id`s from the transaction data. Adhering to the requirements, shuffle these customers with `RANDOM_STATE = 42` and split them into an 80% training set and a 20% validation set. This ensures that all transactions for a specific customer reside in only one of the sets, preventing data leakage at the user level (Group Split).
3.  **Metadata Generation**:
    *   For the **Train** and **Validation** sets: Filter the original transactions based on the split customer lists. Generate a relative `image_path` for each transaction by formatting the `article_id` (padding to 10 digits, extracting the first 3 digits for the subfolder). Save these datasets as Parquet files in the `./metadata` directory.
    *   For the **Test** set: Use the `sample_submission.csv` data. Since the test set targets future predictions, it does not have associated ground-truth image paths for the target period in the input. Save this as a Parquet file.
4.  **Verification and Validation**:
    *   **Load**: Immediately reload the generated metadata files.
    *   **Stats**: Print summary statistics (row counts, unique customers).
    *   **Split Check**: Assert that the intersection of customer IDs between train and validation sets is empty, confirming a successful group split.
    *   **Path Check**: For the training and validation metadata (which contain image paths), randomly sample 1000 paths. Verify their existence in the `./input` directory. If the missing ratio exceeds 0.5, raise an error.
