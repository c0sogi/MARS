The issue is a data structure mismatch: `prepare_graph_data` returns an `item_map` mapping **Article ID (String) → Graph Index (Integer)**, but `CandidateGenerator` and `FeatureEngineer` expect the reverse mapping (**Graph Index (Integer) → Article ID (String)**) to resolve integer indices returned by the model back to string IDs. This causes a `KeyError` when the code attempts to look up an integer index in a dictionary keyed by strings.

I will fix this in `runfile.py` by explicitly inverting the `item_map` dictionaries (`i_map_local` and `i_map`) before passing them to the `CandidateGenerator` and `FeatureEngineer` instances during both the training and validation/testing phases. Cite debug_lesson_1.
