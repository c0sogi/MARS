The execution failure `torch.AcceleratorError: CUDA error: device-side assert triggered` is caused by an index-out-of-bounds error in the loss function. The dataset contains `category_id`s that are non-contiguous or 1-based (up to 15,505), but the model expects contiguous class indices in the range `[0, 15500]` (since `NUM_CLASSES=15501`). When the model receives a label $\ge$ 15501, the GPU kernel asserts failure (Cite debug_lesson_2).

To fix this, I will:
1.  Modify `library/dataset.py` to implement a `get_label_mappings` function that creates a mapping from the original `category_id`s (found in `train.csv`) to contiguous indices `0..N-1`.
2.  Update `PlantDataset` to apply this mapping to the `label` column during initialization, ensuring the model always receives valid indices.
3.  Update `library/prototype_manager.py` to use the inverse mapping during submission generation, converting the model's predicted indices back to the original `category_id` format required by the competition.
