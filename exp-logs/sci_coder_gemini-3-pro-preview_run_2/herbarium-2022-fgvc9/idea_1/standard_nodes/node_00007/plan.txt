The issue is a mismatch between the model's output dimension (hardcoded as 15501) and the dataset's label indices (which go up to 15505 and are non-contiguous). This causes a `device-side assert triggered` (index out-of-bounds) during loss calculation (Cite debug_lesson_2). To fix this, I will implement a dynamic label mapping system that converts raw `category_id`s to a contiguous range `[0, num_classes-1]` and initialize the model with the correct dynamic class count (Cite debug_lesson_3).
