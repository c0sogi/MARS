Implementation strategy:
1.  **Setup & Imports**: Import necessary libraries and the provided modules (`Config`, `Trainer`, `DataLoader`, `TextEncoder`, `TabularProcessor`). Set random seeds for reproducibility.
2.  **Training**: Instantiate the `Trainer` and call `train_and_submit(load_cached_data=True)`. This executes the 5-fold cross-validation pipeline (training on the merged Train+Validation set) and generates the initial submission file.
3.  **Validation (OOF Reconstruction)**:
    *   Since the `Trainer` merges the training and validation sets, naively evaluating on the validation set using the ensemble would result in data leakage.
    *   To calculate a valid metric on the hold-out validation set (`df_val`), I will reconstruct the Out-Of-Fold (OOF) predictions.
    *   I will replicate the `StratifiedKFold` split used in the `Trainer`.
    *   For each fold, I will identify which samples from the original `df_val` fell into the validation split.
    *   I will load the specific model trained for that fold and generate predictions *only* for those validation samples.
    *   This ensures that the metric is computed on samples the model did not see during training.
4.  **Metric Calculation**: Compute the Area Under the ROC Curve (AUC) on the reconstructed OOF predictions for `df_val`. Print this as the "Final Validation Metric".
5.  **Failure Analysis**:
    *   Calculate the absolute error (`|y_true - y_pred|`) for each validation sample.
    *   Compute the Pearson correlation between this error and the numerical features.
    *   Print the features most strongly correlated with high error to identify failure modes.
6.  **Submission Logic**:
    *   Compare the calculated validation AUC against the threshold (`0.7141749705260098`).
    *   If the AUC is less than or equal to the threshold, delete the `submission.csv` file generated by the `Trainer`.
