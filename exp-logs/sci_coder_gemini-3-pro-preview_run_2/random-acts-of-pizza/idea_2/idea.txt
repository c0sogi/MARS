Based on the lessons learned from the previous Random Forest approach—specifically the massive overfitting caused by hash collisions (Cite Lesson 1) and the model's tendency to memorize noise in small datasets (Cite Lesson 3)—I propose a structural shift to a **Hybrid Semantic-Linear Model**.

This approach abandons the non-linear tree-based architecture in favor of a high-bias, low-variance linear classifier, and replaces the "hashing trick" with pre-trained semantic embeddings to capture the true meaning of the text rather than random token overlaps.

# Model
The architecture consists of two parallel feature extraction branches feeding into a single linear output layer:
1.  **Text Branch (Semantic Embeddings):** Instead of using a Hashing Vectorizer which caused feature collisions and noise memorization (Cite Lesson 1, Lesson 2), we will use a **Pre-trained Sentence Transformer** (e.g., `sentence-transformers/all-MiniLM-L6-v2`) to encode the `request_title` and `request_text` into a fixed-size dense vector (e.g., 384 dimensions). This leverages the available GPU to capture semantic nuances (politeness, urgency, narrative structure) that bag-of-words methods miss.
2.  **Tabular Branch:** We will retain the numerical metadata features (e.g., account age, karma) but apply **Standard Scaling** (Z-score normalization). This is crucial because, unlike the previous decision trees, the proposed linear model is sensitive to feature magnitude.
3.  **Classifier (Linear Baseline):** The concatenated features (Text Embeddings + Scaled Tabular Data) will be passed to a **Logistic Regression** classifier with L2 regularization. This replaces the Random Forest to explicitly enforce a simpler decision boundary, preventing the "perfect memorization" (Train AUC 1.0) observed in the previous iteration (Cite Lesson 3).

# Data
1.  **Text Preprocessing:** Concatenate `request_title` and `request_text_edit_aware`. Truncate text to the maximum sequence length of the Transformer model to ensure efficient processing.
2.  **Embedding Generation:** Process the text data in batches using the Sentence Transformer on the NVIDIA A100 GPU. This transforms the sparse, high-dimensional text space into a dense, semantic feature space, avoiding the sparsity pitfalls identified in the failure analysis (Cite Lesson 2).
3.  **Tabular Preprocessing:**
    *   Impute missing values with the median.
    *   Apply `StandardScaler` to all numeric features to ensure they contribute equally to the Logistic Regression objective function alongside the normalized embeddings.

# Training
*   **Algorithm:** Train a Logistic Regression model using the L-BFGS or Liblinear solver.
*   **Regularization Tuning:** Perform **K-Fold Cross-Validation** (e.g., 5-fold) to strictly tune the inverse regularization strength parameter (`C`). This is the primary mechanism to control model complexity and bridge the generalization gap seen in the previous solution (Cite Lesson 3).
*   **Class Weighting:** Apply `class_weight='balanced'` to handle the 3:1 class imbalance identified in the data analysis.

# Evaluation
*   **Inference:** For each test sample, generate text embeddings using the same pre-trained Transformer and scale tabular features using the statistics (mean/std) derived from the training set.
*   **Prediction:** Output the probability of the positive class (pizza received).
*   **Validation:** Monitor the gap between Training AUC and Validation AUC. A smaller gap (e.g., < 0.05) will confirm that the structural changes have successfully mitigated the overfitting issues (Cite Lesson 3).
