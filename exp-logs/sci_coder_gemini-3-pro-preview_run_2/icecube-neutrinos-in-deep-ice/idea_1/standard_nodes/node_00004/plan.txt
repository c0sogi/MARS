The `ArrowMemoryError` is caused by cache thrashing in the `IceCubeDataset` when used with a `DataLoader` that has `shuffle=True`. The dataset caches large decompressed Parquet files (approx. 1.5GB each in RAM) keyed by `batch_id`. When the data is shuffled globally, the access pattern becomes random across hundreds of batch files, causing the cache hit rate to drop to near zero. This forces the worker processes to constantly load, parse, and discard massive DataFrames, leading to high memory churn and fragmentation that eventually exhausts the available RAM (Cite debug_lesson_2).

To fix this, I will modify `runfile.py` to:
1.  **Cluster the training data by `batch_id`**: Instead of a global random shuffle, I will organize the `train_meta` DataFrame such that all events from the same batch are contiguous.
2.  **Implement Block Shuffling**: To preserve training stochasticity, I will shuffle the order of the batches and shuffle the events *within* each batch.
3.  **Disable `shuffle=True` in the DataLoader**: This ensures the worker processes access the data in the sorted, batch-clustered order, maximizing cache hits (loading each file once and processing all its events) and stabilizing memory usage.
