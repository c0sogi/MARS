To address the Steganography Detection task, I propose an **Optimized Residual-V2 Network (ResV2-GeM)**. This strategy synthesizes the structural strengths of previous iterations while correcting the architectural and procedural flaws identified in the lessons.

### Model
The architecture is designed to maximize the Signal-to-Noise Ratio (SNR) of steganographic artifacts while leveraging modern, high-capacity feature extractors.
*   **SRM Residual Stem:** The network input will be processed by a fixed, non-trainable layer of 30 high-pass filters derived from the Spatial Rich Model (SRM). This effectively suppresses semantic image content and isolates the noise residuals where steganographic signals reside. Cite {solution_lesson_node_00001}.
*   **Learnable Input Projection:** Instead of replacing the backbone's stem (which breaks transfer learning), I will insert a trainable 2D convolution layer (kernel size 3x3) to project the 30-channel residual maps down to the 3 channels expected by the backbone. This ensures the pretrained weights of the backbone can be utilized immediately without a "cold start." Cite {solution_lesson_node_00010}.
*   **Backbone (EfficientNetV2-Small):** I will utilize **EfficientNetV2-Small** as the primary feature extractor. This model offers a higher parameter count and better feature representation capabilities than the previously used EfficientNet-B0, addressing the need for capacity in low-SNR tasks. Its Fused-MBConv architecture ensures it remains computationally efficient on the A100 GPU. Cite {solution_lesson_node_00002}.
*   **GeM Pooling Head:** I will replace the standard Global Average Pooling (GAP) with **Generalized Mean (GeM) Pooling**. Since steganographic payloads are often localized based on texture complexity, GeM pooling (with a trainable parameter $p$) allows the network to focus on high-activation regions (anomalies) rather than diluting the signal by averaging it with the benign background.

### Data
*   **Unique Content Sampling:** The data loader will employ a "Unique Content" strategy. For every epoch, the loader will iterate through each unique Image ID and randomly select exactly **one** variant (either the Cover or one of the three Stego versions). This maximizes the diversity of underlying image content seen by the model per compute unit, avoiding the inefficiency of processing redundant paired variants. Cite {solution_lesson_node_00009}.
*   **Preprocessing:** Images will be loaded at their native 512x512 resolution and normalized to the [0, 1] range.
*   **Augmentation:** "D4" augmentations (random 90-degree rotations, horizontal and vertical flips) will be applied during training to enforce rotational invariance.

### Training
*   **Extended Convergence Schedule:** The training duration will be set to **30 epochs**. This prolonged exposure is critical for the model to distinguish subtle high-frequency noise patterns from the noise floor, a process that requires significantly more iterations than standard object recognition. Cite {solution_lesson_node_00005}.
*   **Dynamic Scheduling:** The optimizer will use a **Cosine Annealing** scheduler. The `T_max` parameter will be explicitly linked to the total number of epochs (30) to ensure the learning rate decays precisely to its minimum by the end of training, avoiding the static configuration mismatches seen previously. Cite {solution_lesson_node_00004}.
*   **Loss Function:** Binary Cross Entropy with Logits Loss will be used as the objective.

### Evaluation
*   **5-View Test Time Augmentation (TTA):** Inference will be performed using a 5-view strategy: predictions will be generated for the original image, horizontal flip, vertical flip, 90-degree rotation, and 270-degree rotation. The final probability will be the average of these five predictions, leveraging the model's geometric robustness to boost the Weighted AUC. Cite {solution_lesson_node_00005}.
*   **Metric-Based Checkpointing:** The model will be evaluated on the validation set using the custom **Weighted AUC** metric (weighting the 0.0-0.4 TPR region 2x). The best-performing checkpoint according to this specific metric will be saved for the final submission.
