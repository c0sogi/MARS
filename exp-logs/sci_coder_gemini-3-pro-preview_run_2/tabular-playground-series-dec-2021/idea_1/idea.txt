To establish a reliable and efficient baseline for this tabular classification task, I propose a solution based on **Model 1**, utilizing a Histogram-based Gradient Boosting architecture. This approach is chosen for its superior speed on large datasets (millions of rows) and its ability to handle raw tabular features effectively without complex preprocessing.

### Model
The architecture is a **Histogram-based Gradient Boosting Decision Tree (GBDT)**.
*   **Core Mechanism**: The model functions as an ensemble of weak prediction models (decision trees). It builds trees sequentially, where each new tree attempts to correct the errors (residuals) of the preceding ensemble.
*   **Efficiency Optimization**: Unlike traditional GBDTs that sort all feature values to find split points, this model discretizes continuous input features into integer-mapped histograms (bins). This reduces the complexity of split finding, significantly accelerating training on large datasets like this one.
*   **Structure**: The trees will utilize a leaf-wise (best-first) growth strategy, which tends to achieve lower loss faster than level-wise growth, further prioritizing efficiency.

### Data
*   **Loading**: The solution will utilize the pre-generated `train.parquet` and `val.parquet` files from the metadata directory to leverage faster I/O compared to CSVs.
*   **Preprocessing**:
    *   **Feature Selection**: The `Id` column will be dropped as it carries no predictive signal.
    *   **Feature Engineering**: No explicit scaling, normalization, or encoding is required. The model natively handles the continuous features (e.g., `Elevation`, `Horizontal_Distance`) and the binary features (e.g., `Soil_Type`, `Wilderness_Area`) present in the dataset.
    *   **Class Handling**: The target `Cover_Type` will be encoded into zero-indexed integers for training (0-5) and mapped back to the original class labels (1, 2, 3, 4, 6, 7) for prediction.

### Training
*   **Objective Function**: The model will minimize **Multi-class Logarithmic Loss (Cross-Entropy)**, which is appropriate for the probabilistic classification of the 6 distinct cover types.
*   **Optimization**: Training will proceed via gradient descent in function space.
*   **Strategy**:
    *   **Early Stopping**: To ensure the "speed" requirement is met and to prevent overfitting, the training process will monitor the accuracy on the validation set. Training will halt automatically if the validation score does not improve for a set number of rounds.
    *   **Hyperparameters**: We will use lightweight default hyperparameters (e.g., a limited learning rate and moderate tree depth) to establish a true baseline without expensive grid searching.

### Evaluation
*   **Inference**: The trained model will predict class probabilities for the test set loaded from `test.parquet`.
*   **Prediction**: The final class prediction will be determined by the `argmax` of the probability distribution (the class with the highest confidence).
*   **Submission**: The predicted integer indices will be mapped back to the original `Cover_Type` values and combined with the test `Id`s to generate the final `submission.csv` file.
