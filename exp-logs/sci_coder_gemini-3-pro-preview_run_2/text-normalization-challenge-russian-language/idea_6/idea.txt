Based on the comprehensive failure analysis and lessons learned, I propose the **Residual-Optimized Hybrid Cascade**.

This strategy fundamentally corrects the **training-inference distribution mismatch** identified in **Cite {solution_lesson_node_00013}**. Instead of training the neural network on the "easy" distribution (which the memory model already solves) and testing it on the "hard" distribution (unseen residuals), we will explicitly construct a training set of "cache misses" to force the neural network to specialize in generalization.

# Model

The solution employs a strictly prioritized three-tier cascade:

1.  **Tier 1: Granular Memory Engine (HFBB)**
    *   **Role:** The primary solver for all "seen" vocabulary and context patterns.
    *   **Architecture:** A 4-level statistical backoff hierarchy: **Trigram $\rightarrow$ Bigram (Prev) $\rightarrow$ Bigram (Next) $\rightarrow$ Unigram**.
    *   **Design Choice:** By including the **Unigram** layer here, we ensure that frequent semiotic tokens (e.g., "2" $\rightarrow$ "два") are resolved by memory, preventing the inference errors observed when routing simple cases to neural networks **Cite {solution_lesson_node_00010}**. The intermediate Bigram layers ensure high precision for context-dependent tokens **Cite {solution_lesson_node_00006}**.

2.  **Tier 2: Residual Transformer (Generative Fallback)**
    *   **Role:** A specialized solver for the "long tail" of infinite-cardinality classes (Money, Decimals, complex Dates) that are **unseen** in the training set **Cite {solution_lesson_node_00002}**.
    *   **Architecture:** A **Character-to-Subword** Transformer.
        *   **Input:** Character-level tokenization of the target and its surrounding context window (`Prev_Word <SEP> Target_Chars <SEP> Next_Word`). This preserves precise digit information.
        *   **Output:** Subword (BPE) tokenization of the normalized text. This ensures the output adheres to valid Russian morphology.

3.  **Tier 3: Identity Fallback**
    *   **Role:** The default for OOV tokens that are not semiotic (e.g., rare proper nouns), preserving the high baseline accuracy for PLAIN/PUNCT classes.

# Data

The critical innovation lies in the **Data Preparation** phase, specifically the construction of the neural training set:

1.  **Standard HFBB Data:**
    *   The full training set is used to populate the Tier 1 hash maps (Trigram/Bigram/Unigram) for the final inference model.

2.  **Residual Dataset Generation (Jackknifing):**
    *   To address **Cite {solution_lesson_node_00013}**, we must simulate "inference time" conditions during training.
    *   Perform **K-Fold Cross-Validation** (e.g., K=5) on the training data.
    *   For each fold:
        1.  Train a temporary HFBB model on the other $K-1$ folds.
        2.  Run inference on the current fold.
        3.  Collect the **Residuals**: tokens where the HFBB prediction is incorrect (or falls back to Identity when it shouldn't).
    *   **Result:** A dataset consisting exclusively of tokens that *cannot* be solved by memorization (e.g., unique monetary amounts, rare dates). This effectively filters out the "easy" examples (like "2012" or "Chapter 1") that dominated previous training sets.

3.  **Semiotic Filtering:**
    *   Filter the Residual Dataset to include only tokens belonging to semiotic classes (containing digits `\d` or Latin `[a-zA-Z]`). This focuses the Transformer's capacity on learning the *rules* of number expansion rather than memorizing noise.

# Training

1.  **Tier 1 (HFBB):**
    *   Constructed via single-pass Maximum Likelihood Estimation on the full dataset.

2.  **Tier 2 (Transformer):**
    *   **Dataset:** Train *only* on the **Residual Dataset** generated above.
    *   **Effect:** The model learns to handle the specific distribution of "hard" cases it will face in the wild, rather than overfitting to frequent tokens it will never see (because Tier 1 catches them).
    *   **Objective:** Minimize Cross-Entropy Loss on the target BPE sequence.

# Evaluation

1.  **Inference Pipeline:**
    *   For each token in the test set:
        1.  **Query Tier 1:** Check Trigram $\rightarrow$ Bigram(P) $\rightarrow$ Bigram(N) $\rightarrow$ Unigram. If a match is found, return it immediately **Cite {solution_lesson_node_00010}**.
        2.  **Gate:** If no match, check if the token is semiotic (contains `\d` or `[a-zA-Z]`).
        3.  **Query Tier 2:** If semiotic, run the Residual Transformer on the context window.
        4.  **Fallback:** Otherwise, return the original token (Identity).
2.  **Submission:** Format the predictions into the required CSV structure.
