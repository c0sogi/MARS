Based on the task description and dataset analysis, I propose the following highly efficient baseline approach.

# Baseline Approach: Hierarchical Frequency-Based Backoff (HFBB)

### Model
The proposed model is a **non-parametric statistical model** that utilizes a hierarchical memory structure to map input tokens to their normalized forms. It synthesizes the "context-awareness" of sequence models (like Model 4 and 5) and the "memorization" capability of lookup tables (the core of Model 3's dispatcher) into a lightweight, interpretable architecture.

The architecture consists of three cascaded layers of retrieval:
1.  **Contextual Trigram Layer**: A hash map storing the mapping `(w_{i-1}, w_i, w_{i+1}) \rightarrow y_i`. This layer captures context-dependent normalizations (e.g., disambiguating "2" as "two" vs. "second" based on surrounding words).
2.  **Unigram Layer**: A hash map storing the mapping `w_i \rightarrow y_i`. This layer handles the vast majority of tokens that have a consistent normalization regardless of context (e.g., "dollar" $\rightarrow$ "dollar").
3.  **Identity Fallback**: A deterministic rule `f(w_i) = w_i`. This layer acts as the default for Out-Of-Vocabulary (OOV) tokens, relying on the observation that 87.5% of tokens (PLAIN, PUNCT) remain unchanged.

### Data
1.  **Preprocessing**:
    *   **Training Data**: Load the training set and group tokens by `sentence_id` to reconstruct the sequence order. Pad the beginning and end of each sentence with special `<BOS>` and `<EOS>` tokens to handle boundary conditions.
    *   **Test Data**: Apply the same grouping and padding procedure to prepare the input sequences for inference.
2.  **Feature Extraction**:
    *   Generate **Trigrams** `(prev, curr, next)` and **Unigrams** `(curr)` for every token in the dataset.
    *   The `class` column is ignored for this baseline to reduce complexity, as the direct mapping `before` $\rightarrow$ `after` implicitly captures the class transformation rules.

### Training
The "training" process is a single-pass statistical aggregation (Maximum Likelihood Estimation):
1.  **Aggregation**: Iterate through the training corpus and count the occurrences of each target `after` string for every unique Unigram and Trigram key.
2.  **Selection**: For each unique key in both the Trigram and Unigram maps, select the `after` string with the highest frequency (Mode).
    *   *Optimization*: To ensure memory efficiency, Trigrams that appear only once (hapax legomena) can be pruned if they do not contradict the Unigram prediction, though with 220GB RAM, full retention is feasible.

### Evaluation
1.  **Inference**: For each token in the test set:
    *   Construct its query tuple `(prev, curr, next)`.
    *   **Step 1**: Query the **Contextual Trigram Layer**. If a match is found, return the stored value.
    *   **Step 2**: If no match, query the **Unigram Layer** with `(curr)`. If a match is found, return the stored value.
    *   **Step 3**: If no match, return the original `curr` token (Identity).
2.  **Submission**: Reformat the predictions into the required `id,after` CSV format, ensuring the order matches the `ru_sample_submission.csv`.
