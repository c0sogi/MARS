Based on the progression of experiments and the synthesis of the provided lessons, I propose the **Density-Maximized Confidence-Gated Hybrid Cascade**.

This strategy resolves the critical conflict between **Lesson 00013** (Distribution Mismatch), **Lesson 00014** (Curriculum Gap), and **Lesson 00026** (Data Density). It combines the high-precision memorization of the statistical baseline with a neural network that is specifically engineered—via data construction—to master the "long tail" of semiotic normalization without losing the fundamental grammar of numbers.

# Model
The architecture is a **Strict-Priority Two-Tier Cascade** that routes tokens based on context specificity and statistical confidence.

1.  **Tier 1: Confidence-Aware Granular Memory (HFBB)**
    *   **Structure:** This tier implements the optimized **4-level backoff hierarchy**: **Trigram $\rightarrow$ Bigram (Prev) $\rightarrow$ Bigram (Next) $\rightarrow$ Unigram**. This structure preserves the gains from **Cite {solution_lesson_node_00006}**.
    *   **Innovation (Confidence Gating):** The **Unigram** layer is augmented to store a **Confidence Score** ($P(\text{Mode})$). This allows the system to distinguish between "stable" context-free tokens (e.g., "2012", which is almost always a date) and "ambiguous" tokens (e.g., "2", which changes based on gender/case).
    *   **Role:** This tier acts as a high-precision filter, resolving ~98% of queries instantly. It ensures that simple, frequent tokens are never routed to the neural network, preventing the inference regressions observed in **Cite {solution_lesson_node_00010}**.

2.  **Tier 2: Heterogeneous Granularity Transformer**
    *   **Architecture:** A Sequence-to-Sequence Transformer designed with **Heterogeneous Granularity** to match the linguistic requirements of the task:
        *   **Encoder (Character-Level):** The input is tokenized at the character level. This is strictly necessary to parse the internal structure of infinite-cardinality classes like Money and Decimals, which subword tokenizers often mangle **Cite {solution_lesson_node_00002}**.
        *   **Decoder (Subword-Level):** The output is generated using a BPE tokenizer trained on the target text. This ensures the model generates valid Russian morphemes and words, avoiding character-level spelling errors.
    *   **Context Window:** The input includes a wide context window ($\pm 2$ words): `Prev_2 Prev_1 <SEP> Target_Chars <SEP> Next_1 Next_2`. This extended context provides the necessary signals (e.g., noun gender) for the model to resolve the ambiguities that caused Tier 1 to have low confidence.

# Data
The core innovation is the **Density-Maximized Class-Balanced Data Construction**, which solves the "Curriculum vs. Mismatch" trade-off.

1.  **HFBB Construction:**
    *   Compute frequency maps and confidence scores using the **Full Training Corpus**.

2.  **Transformer Dataset Construction:**
    *   **Domain Filtering (Solving Lesson 00026):** Extract **ALL** tokens from the training set that belong to semiotic classes (containing digits `\d` or Latin `[a-zA-Z]`). We explicitly do **not** use a "debug" subset or a "residual-only" subset. By using the full semiotic corpus (millions of tokens), we ensure the model has sufficient data density to generalize.
    *   **Curriculum Retention (Solving Lesson 00014):** By including "easy" semiotic tokens (Anchors) alongside the hard ones, we ensure the model learns the fundamental grammar of normalization (e.g., "1" $\to$ "one").
    *   **Aggressive Class Balancing (Solving Lesson 00013):** To prevent the model from overfitting to the "easy" anchors (creating a distribution mismatch), we apply **Inverse Frequency Sampling**. We aggressively upsample rare, high-error classes (`MONEY`, `DECIMAL`, `TELEPHONE`) to match the frequency of the dominant class (`DATE`). This forces the model to prioritize the "long tail" rules that Tier 1 cannot handle.

# Training
1.  **Tier 1 (HFBB):**
    *   Single-pass Maximum Likelihood Estimation.

2.  **Tier 2 (Transformer):**
    *   **Objective:** Minimize Cross-Entropy Loss on the target BPE sequence.
    *   **Strategy:** Train from scratch on the **Density-Maximized Class-Balanced** dataset.
    *   **Regularization:** Apply **Label Smoothing (0.1)** and **Dropout (0.1)**. This prevents the model from memorizing the specific values in the training set (which Tier 1 already covers) and encourages it to learn the *generative rules* of number expansion.

# Evaluation
The inference pipeline employs a **Confidence-Gated Routing Logic** to strictly enforce the "Exhaust Lookup" principle **Cite {solution_lesson_node_00010}**:

1.  **Step 1 (Context Match):** Query HFBB Trigram $\rightarrow$ Bigram(Prev) $\rightarrow$ Bigram(Next).
    *   If a match is found, **Return Prediction** immediately. (These are specific, high-precision context hits).
2.  **Step 2 (Confidence Check):** Query HFBB Unigram.
    *   If Match Found **AND** `Confidence > Threshold` (e.g., 0.99): **Return Prediction**. (Stable tokens are handled by memory).
    *   If Match Found **AND** `Confidence <= Threshold`: **Route to Tier 2**. (Ambiguous tokens are routed to the Neural Net to use extended context).
3.  **Step 3 (OOV/Fallback):**
    *   If the token is Semiotic (contains `\d` or `[a-zA-Z]`): **Route to Tier 2**. (Unseen numbers/money).
    *   Else: **Identity Fallback**. (Unknown proper nouns/punctuation).
