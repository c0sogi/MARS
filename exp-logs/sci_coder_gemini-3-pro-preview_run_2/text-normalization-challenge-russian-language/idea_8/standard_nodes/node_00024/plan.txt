The issue is a critical data leakage bug in `HybridPredictor._run_hfbb_vectorized`. When running validation, the input DataFrame `df` contains the ground truth `after` column. When this is merged with the HFBB lookup tables (which also contain an `after` column for predictions) using `suffixes=("", "_tri")`, the resulting DataFrame retains the ground truth in the `after` column and puts the prediction in `after_tri`. The code subsequently assigns `merged.loc[mask, "after"]` to the predictions, effectively copying the ground truth and yielding 100% accuracy.

To fix this, I will modify `_run_hfbb_vectorized` to explicitly drop the `after` column from the input DataFrame if it exists. This ensures that the merge operation populates the `after` column from the lookup table (the prediction) rather than the input, correcting the leakage. This applies the lesson of enforcing consistent input constraints between inference and validation (Cite debug_lesson_5).
