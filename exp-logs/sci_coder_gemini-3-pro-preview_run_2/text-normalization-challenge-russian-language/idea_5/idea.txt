# Strategy: Strict-Priority Hybrid Cascade with Heterogeneous Granularity

This strategy introduces a **Heterogeneous Granularity** architecture. It acknowledges that different sub-tasks require different levels of token abstraction: "Memory" works best at the word level, "Number Parsing" works best at the character level, and "Language Generation" works best at the subword level.

### Model

The system is designed as a strict two-stage cascade that prioritizes deterministic retrieval over stochastic generation.

1.  **Tier 1: The Granular Memory Engine (Word-Level)**
    *   **Function:** This component acts as the primary gatekeeper, resolving all "seen" tokens using a high-precision lookup hierarchy.
    *   **Structure:** It implements the optimized **4-level backoff hierarchy**: **Trigram $\rightarrow$ Bigram (Prev) $\rightarrow$ Bigram (Next) $\rightarrow$ Unigram**.
    *   **Retention:** By including the **Unigram** layer in this high-priority tier, we explicitly adhere to **Cite {solution_lesson_node_00010}**, ensuring that simple, frequent semiotic tokens (e.g., "2" $\rightarrow$ "два") are resolved by memory rather than risking neural inference errors.
    *   **Granularity:** This tier operates strictly at the **Word/Token level**, preserving the successful approach of **Cite {solution_lesson_node_00006}**.

2.  **Tier 2: The Heterogeneous Transformer (Char-to-Subword)**
    *   **Function:** This component is a generative fallback reserved exclusively for **unseen** semiotic tokens (the "long tail" identified in **Cite {solution_lesson_node_00002}**).
    *   **Innovation (Heterogeneous Architecture):** Unlike previous character-level approaches, this model uses different granularities for input and output to match the linguistic nature of the task:
        *   **Encoder (Character-Level):** The input (e.g., "$3,415.20") is tokenized by **characters**. This is crucial for parsing the precise sequence of digits and symbols without the information loss caused by standard subword tokenizers on numbers.
        *   **Decoder (Subword-Level):** The output is generated using a **BPE (Byte Pair Encoding)** tokenizer trained on the Russian target text. This ensures the model generates valid Russian morphemes and words, reducing "spelling errors" common in pure char-to-char models.
    *   **Input Context:** `[Prev_Word] <SEP> [Target_Token_Chars] <SEP> [Next_Word]`.

3.  **Routing Logic:**
    *   The system queries Tier 1. If a match is found, it is returned immediately.
    *   If Tier 1 fails (OOV), the system checks if the token is "semiotic" (contains digits or Latin characters).
    *   If semiotic, it dispatches to Tier 2 (Transformer).
    *   Otherwise, it falls back to Identity.

### Data

1.  **HFBB Construction:**
    *   Process the full training corpus to populate the Trigram, Bigram, and Unigram hash maps.
    *   Use **Group Shuffle Split** to ensure validation integrity.

2.  **Neural Data Preparation:**
    *   **Filtering:** Construct a training subset containing *only* tokens belonging to semiotic classes (e.g., `DATE`, `CARDINAL`, `MONEY`, `LETTERS`). This isolates the "tail" problem.
    *   **Class-Balanced Upsampling:** As identified in **Cite {solution_lesson_node_00002}**, classes like `MONEY` and `DECIMAL` have high error rates but low frequency. We will **upsample** these rare classes in the neural training set to match the frequency of the dominant `DATE` class, forcing the model to learn their specific grammars.
    *   **Target Tokenizer Training:** Train a **SentencePiece BPE model** (vocab size ~8000) exclusively on the `after` column of the training data. This creates a specialized vocabulary for normalized Russian text.

### Training

1.  **Tier 1 (HFBB):**
    *   Single-pass Maximum Likelihood Estimation (frequency counting and mode selection).

2.  **Tier 2 (Transformer):**
    *   **Architecture:** A lightweight Encoder-Decoder (e.g., ~4 layers, 256 hidden dim).
    *   **Objective:** Minimize Cross-Entropy Loss on the target BPE sequence.
    *   **Optimization:** Use `AdamW` with a "OneCycle" learning rate scheduler to ensure rapid convergence.
    *   **Regularization:** Apply Label Smoothing (0.1) to prevent the model from becoming over-confident on the specific numbers in the training set, encouraging it to learn the *rules* of conversion rather than memorizing values.

### Evaluation

1.  **Inference Pipeline:**
    *   Iterate through the test set tokens.
    *   **Step 1:** Query the HFBB hierarchy (Trigram $\to$ Bigram_P $\to$ Bigram_N $\to$ Unigram). If hit, return result. **Cite {solution_lesson_node_00006}**.
    *   **Step 2:** If miss, check `if has_digit(token) or has_latin(token)`.
    *   **Step 3:** If true, tokenize input as chars, run Transformer inference, decode BPE output to string.
    *   **Step 4:** Else, return original token (Identity).
2.  **Submission:** Format predictions into the required CSV structure.
