The implementation strategy follows the standard machine learning pipeline using the provided library modules. 

1.  **Setup & Data Loading**: We initialize the environment by setting random seeds for reproducibility. We then load the training, validation, and test datasets using the `load_datasets` function from `library.data_loader`, enabling caching to speed up subsequent runs.
2.  **Feature Extraction**: We utilize the `FeatureExtractor` from `library.features` to transform the raw text data into numerical features. This combines Word N-grams and Character N-grams into a sparse TF-IDF matrix, capturing both semantic meaning and morphological patterns (like misspellings) essential for toxicity detection.
3.  **Model Training**: We instantiate the `ToxicityClassifier` from `library.model`, which wraps a One-Vs-Rest Logistic Regression approach. We train the model on the training features and labels. The `train` method internally evaluates the model on the validation set, but we will also perform explicit prediction for failure analysis.
4.  **Validation & Failure Analysis**: 
    *   We report the **Final Validation Metric** (Mean Column-wise ROC AUC).
    *   We perform a failure analysis by calculating the correlation between the model's prediction error (Mean Absolute Error across labels) and input text properties (Character Length and Word Count). This helps identify if the model struggles with longer or shorter comments.
5.  **Submission**: Finally, we generate predictions for the test set using the trained model and save them to the specified submission path using the `generate_submission` method.
