The `AssertionError` in `runfile.py` confirms that the target variable `y` is being flattened into a 1D tensor (size 8) instead of a 2D batch tensor (4x2). This occurs because PyTorch Geometric's batching process concatenates attributes along the first dimension. If the individual `Data` objects contain 1D tensors (e.g., shape `(2,)`), the resulting batch is a single long 1D tensor. To achieve a batched shape of `(B, F)`, the individual attributes must be 2D tensors of shape `(1, F)`.

I will modify `library/data.py` to ensure that `global_features` and `y` are always treated as 2D tensors with a leading dimension of 1.
1.  **`_process_data`**: Unsqueeze `global_features` and `y` to have shape `(1, F)` upon creation.
2.  **`_save_to_cache`**: Use `np.concatenate` instead of `np.stack` for these attributes to store them as `(N, F)` arrays (flattening the list of `(1, F)` arrays correctly).
3.  **`_load_from_cache`**: Explicitly `unsqueeze(0)` the sliced arrays to restore the `(1, F)` shape for each graph.
4.  **`get`**: When applying scalers, assign the 2D scaled result directly back to the data object without indexing `[0]`, preserving the `(1, F)` shape.

This ensures that when `DataLoader` collates the graphs, it concatenates these `(1, F)` tensors into a `(B, F)` tensor, matching the model's expected input and the assertion check. (Cite debug_lesson_8)
