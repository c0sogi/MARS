The `AttributeError: 'GlobalStorage' object has no attribute 'id'` occurs because the `Data` objects loaded from the cached NPZ files do not contain the `id` attribute, which is required in `runfile.py` to map predictions to material IDs. The caching functions (`save_graphs_to_npz` and `load_graphs_from_npz`) in `library/data.py` were not saving or loading this attribute.

I will update `library/data.py` to:
1.  Modify `save_graphs_to_npz` to extract and save the `id` attribute from the list of `Data` objects.
2.  Modify `load_graphs_from_npz` to load the `id` array from the NPZ file and restore it to the `Data` objects.

This change will cause a `KeyError` when loading existing cache files (which lack the 'id' key), which is handled by the `CrystalDataset` class by regenerating the cache, thus resolving the issue.
