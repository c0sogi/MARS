### Model
The proposed solution is a **Crystal Graph Convolutional Neural Network (CGCNN)**. This architecture is designed to be significantly more lightweight than the ALIGNN approach (Model 3) by operating solely on the atomic bond graph and ignoring the computationally expensive line graph (bond angle) updates.

*   **Graph Representation**: The material is represented as a multigraph where atoms are nodes and chemical bonds are edges. Unlike Model 3, this model considers only pairwise interactions.
*   **Node Embeddings**: Atoms are initialized with learnable embedding vectors corresponding to their atomic type (Al, Ga, In, O).
*   **Edge Embeddings**: Edges are represented by expanding the interatomic distances using a filter of radial basis functions (Gaussian), creating a continuous representation of spatial proximity.
*   **Convolution Layers**: The core of the model consists of a stack of graph convolution layers. In each layer, a node's feature vector is updated by aggregating messages from its neighbors. The message is computed using a gated activation mechanism (element-wise product of a sigmoid and a softplus activation) applied to the concatenation of node and edge features. This allows the model to learn local chemical environments efficiently.
*   **Global Pooling & Output**: After the convolutional layers, a global pooling operation (mean or sum) aggregates all node features into a single vector representing the crystal. This vector is passed through a simple Multi-Layer Perceptron (MLP) to simultaneously predict the two scalar targets: formation energy and bandgap energy.

### Data
*   **Graph Construction**: For each entry in the training and test sets, the `geometry.xyz` file is parsed to extract atomic coordinates and lattice vectors. A neighbor list is constructed for each atom using a fixed cutoff radius (e.g., 5 Å), respecting the periodic boundary conditions defined by the lattice.
*   **Feature Encoding**:
    *   **Nodes**: Map atomic species (Al, Ga, In, O) to integer indices [0, 1, 2, 3] to lookup embeddings.
    *   **Edges**: Calculate Euclidean distances between connected nodes and expand them using a fixed set of Gaussian centers and widths.
*   **Normalization**: The target variables (`formation_energy_ev_natom` and `bandgap_energy_ev`) are normalized (e.g., standard scaling) during training to ensure balanced gradient updates, as their magnitudes may differ.

### Training
*   **Loss Function**: The model is trained to minimize the Mean Squared Error (MSE) between the predicted and actual normalized target values.
*   **Optimizer**: Use the Adam optimizer with a standard learning rate (e.g., 0.001) and weight decay for regularization.
*   **Procedure**: Train for a fixed number of epochs. Implement a learning rate scheduler (e.g., ReduceLROnPlateau) to decrease the learning rate if the validation loss stops improving, ensuring convergence to a stable minimum. The batch size is kept moderate (e.g., 64) to maintain training stability while fitting within memory constraints.

### Evaluation
*   **Inference**: The test set geometries are processed into graphs using the same cutoff and encoding logic as the training set.
*   **Prediction**: The trained model performs a forward pass on the test graphs.
*   **Inverse Normalization**: The model outputs are inverse-transformed using the statistics (mean, std) computed from the training targets to produce the final values in eV.
*   **Submission**: The predicted formation energy and bandgap energy for each test ID are formatted into the required CSV submission structure.
