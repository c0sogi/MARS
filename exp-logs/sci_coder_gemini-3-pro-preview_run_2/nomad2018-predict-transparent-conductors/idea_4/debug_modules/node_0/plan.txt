### Implementation Strategy

1.  **Configuration Override**: We will modify the class attributes of `library.config.Config` at runtime to set up a "demo" mode. This involves reducing the number of epochs, batch size, embedding dimensions, and RBF bins to ensure the script runs quickly (within minutes) while still verifying the logic. We will also redirect the `CACHE_DIR` and `METADATA_DIR` to the writable `./working` directory.
2.  **Data Preparation**: We will create a small subset of the provided metadata files (top 20 rows of train, val, and test) and save them to the new temporary metadata directory. This allows the data loading functions to process real geometry files from the read-only `./input` directory without processing the entire dataset.
3.  **Component Verification**:
    *   **Utils**: We will instantiate `GaussianRBF` and `Standardizer` to verify their shapes and transformation logic (e.g., inverse transform reconstruction). We will also test `compute_rmsle`.
    *   **Data**: We will call `get_dataloaders` to trigger the graph construction pipeline on our subset. We will verify the structure of the generated PyTorch Geometric `Data` objects (node features, edge indices, line graph attributes).
    *   **Model**: We will instantiate the `AngleAwareGNN` with the reduced dimensions and perform a forward pass on a single batch to verify output shapes.
    *   **Training**: We will instantiate the `Trainer` and run a complete training loop for 2 epochs on the subset data. We will verify that the loss decreases (or runs without error), checkpoints are saved, and predictions can be generated.
