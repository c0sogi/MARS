The error arises because `ase.io.read` infers the file format from the `.xyz` extension, defaulting to the standard XYZ parser. However, the provided geometry files contain FHI-aims formatted data (indicated by comments and lattice vectors), causing the parser to fail on the header. To fix this, I will explicitly specify `format='aims'` in the `read` calls within `library/data.py` and `runfile.py`, forcing ASE to use the correct parser regardless of the file extension.
