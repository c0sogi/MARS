The attribute `self.node_dim` is reserved by the parent `MessagePassing` class to indicate the dimension of the node features (defaulting to -2 or 0), but the code overwrites it with the embedding dimension (64). This causes the `propagate` method to attempt accessing a non-existent dimension in the input tensor. To fix this, I will rename `self.node_dim` to `self.emb_dim` in `CGCNNConv.__init__`, ensuring it doesn't interfere with the internal logic of `MessagePassing`.
