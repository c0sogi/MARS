Based on the accumulated insights, particularly the dominance of model capacity and depth over specialized interaction layers (Lesson 6, Lesson 2) and the necessity of robust normalization and regularization (Lesson 7, Lesson 8), I propose the implementation of a **Deep Residual MLP (ResMLP)**.

This architecture represents a structural evolution from the "Deep MLP" used previously. While the Deep MLP improved performance by increasing depth, plain feed-forward networks suffer from optimization difficulties (vanishing gradients) as they grow deeper. By introducing residual skip connections, we can safely increase the network depth significantly beyond the previous 3-layer limit, maximizing the representational capacity that was proven to be the primary driver of performance.

# Model
The architecture is a deep, residual feed-forward network designed to scale capacity effectively.

1.  **Input Processing**:
    *   **Categorical**: The `f_27` feature is decomposed into 10 character tokens (Cite Lesson 1). These are passed through a shared embedding layer (dimension 32) and flattened.
    *   **Continuous**: The 30 numerical features are standardized.
    *   **Projection**: The flattened embeddings and continuous features are concatenated and passed through a linear projection layer to map them to a uniform hidden dimension $d$ (e.g., 512).

2.  **Residual Backbone**:
    *   Instead of a simple stack of dense layers, the core of the network consists of a series of **Dense Residual Blocks** (e.g., 6 blocks).
    *   **Block Structure**: Each block implements the transformation $x_{l+1} = \text{Activation}(x_l + \mathcal{F}(x_l))$, where $\mathcal{F}$ is a sub-network consisting of `Linear -> Batch Normalization -> Activation -> Dropout -> Linear -> Batch Normalization -> Dropout`.
    *   **Rationale**: This structure retains the critical Batch Normalization (Cite Lesson 7) and Dropout components but allows gradients to flow through the skip connections, enabling the model to learn highly complex non-linearities without the optimization instability associated with deep plain MLPs (Cite Lesson 2, Lesson 6).

3.  **Output Head**:
    *   The output of the final residual block is passed through a final Linear layer with a Sigmoid activation to produce the probability.

# Data
1.  **Decomposition**: The string feature `f_27` is split into 10 distinct integer-encoded columns (Cite Lesson 1).
2.  **Normalization**: Continuous features are Z-score normalized to ensure scale consistency with the embeddings.
3.  **Splitting**: Use the stratified validation split provided in the metadata to maintain class distribution.

# Training
1.  **Optimizer**: Use **AdamW** with a high weight decay of `1e-2`. This aggressive regularization is strictly necessary to prevent the high-capacity residual network from overfitting (Cite Lesson 8).
2.  **Scheduler**: Use a constant learning rate or a simple step decay. Avoid complex schedulers like Cosine Annealing, which have been shown to induce overfitting in this specific domain (Cite Lesson 5).
3.  **Convergence Strategy**: Train for an extended duration (e.g., 30+ epochs). Continue training even if the Binary Cross-Entropy loss plateaus, as long as the Validation AUC continues to improve, to fully refine the ranking of difficult examples (Cite Lesson 3).

# Evaluation
1.  **Inference**: Iterate through the test set using the trained ResMLP. The model will process the decomposed tokens and continuous features to generate probability scores.
2.  **Submission**: Save the raw probability outputs directly to the submission file.
