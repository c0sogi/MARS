Implementation Strategy
1.  **Environment Setup**: Import necessary libraries and append the current directory to the system path to ensure the provided `library` modules are accessible.
2.  **Configuration Override**: Modify the `Config` class attributes at runtime to point to a dedicated working directory (`./working/demo_execution`). This ensures the demo runs in isolation and updates output paths (processed data, model checkpoint, submission) accordingly.
3.  **Component Verification**: Implement unit tests with assertions for key model components (`GatedGLU`, `GatedTransformerBlock`, `ResFunnelBlock`) and the full `GatedTransformerResFunnelHybrid` model to ensure they accept inputs and produce outputs of correct shapes.
4.  **Data Pipeline Verification**: Invoke `get_dataloaders` with `load_cached_data=False` to trigger the raw data processing logic. Verify the resulting DataLoaders produce batches with the expected structure and dimensions.
5.  **Training Execution**: Execute the `run_training` function with a reduced number of epochs (1) and a large batch size (2048) to demonstrate the full training loop quickly while utilizing the pre-verified data cache.
6.  **Submission Validation**: Check for the existence of the generated submission file, validate its dimensions (100,000 rows), column names, and ensure the IDs match the test metadata.
