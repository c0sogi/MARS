Based on the comprehensive history of experiments and the derived empirical lessons, I propose the implementation of an **Interface-Normalized Hybrid SwiGLU Network**.

This strategy represents a structural synthesis that optimizes the **Feature Fusion Interface**. It integrates the highly successful **Post-Norm Transformer** configuration (Cite solution_lesson_node_00095) and **Unit-Variance Initialization** (Cite solution_lesson_node_00114) with a targeted architectural correction: **Branch-Specific Layer Normalization**. By normalizing the high-variance output of the Post-Norm Transformer *before* concatenation, we align the statistical distributions of the categorical and continuous streams (Cite solution_lesson_node_00069) without the destructive interference of Batch Normalization on the fused vector (Cite solution_lesson_node_00074) or the optimization instability of learnable scalars (Cite solution_lesson_node_00118).

# Model

The architecture is a dual-stream network that fuses a statistically aligned categorical sequence with a raw continuous stream into a deep, SwiGLU-based residual funnel.

1.  **Stream 1: Categorical Sequence (Stabilized Post-Norm Transformer)**
    *   **Input**: The `f_27` feature is decomposed into 10 distinct character tokens.
    *   **Embedding**: Tokens are passed through a shared embedding layer (dimension 32).
        *   **Initialization**: Explicitly initialize with **Unit Variance** (`std=1.0`) to ensure robust signal propagation in the Post-Norm architecture (Cite solution_lesson_node_00114).
    *   **Positional Encoding**: **Learnable Absolute Positional Embeddings** are added.
        *   **Initialization**: Explicitly initialize with **Low Variance Random Noise** (`std=0.02`) to break symmetry without introducing high-magnitude noise (Cite solution_lesson_node_00081).
    *   **Encoder**: The sequence is processed by a **Standard Transformer Encoder** (2 layers, 4 heads).
        *   **Configuration**: Use **Post-Normalization** (`norm_first=False`) to maximize representational capacity for this shallow encoder (Cite solution_lesson_node_00095).
        *   **Activation**: Explicitly set `activation="gelu"` (Cite solution_lesson_node_00068).
        *   **Regularization**: Apply **Low Dropout (0.1)** (Cite solution_lesson_node_00048).
    *   **Structural Innovation: Interface Normalization**:
        *   The output sequence is flattened and immediately passed through a **LayerNorm** layer.
        *   **Rationale**: The Post-Norm Transformer output has unbounded variance that grows with depth, creating a distribution mismatch with the Z-scored continuous features. This layer strictly aligns the categorical signal's statistics to $\sim N(0,1)$ *before* fusion, ensuring the Linear Stem receives a balanced multi-modal signal (Cite solution_lesson_node_00069).

2.  **Stream 2: Continuous Preservation**
    *   **Input**: The 30 numerical features are standardized.
    *   **Preservation**: Features are maintained in their **raw, normalized form**. No early projection or independent processing stems are used (Cite solution_lesson_node_00105, solution_lesson_node_00038).

3.  **Fusion Layer: The Linear Stem**
    *   **Concatenation**: The **Normalized Transformer Output** and the **Raw Continuous Features** are concatenated.
    *   **Linear Stem**: The concatenated vector is passed through a **Linear Projection Layer** to map to the backbone width (512) (Cite solution_lesson_node_00073).

4.  **Backbone: SwiGLU ResFunnel**
    *   **Topology**: The backbone is organized into 3 stages (512 $\to$ 256 $\to$ 128) (Cite solution_lesson_node_00084).
    *   **Sustained Depth**: Each stage consists of **3 stacked Residual Blocks** (Cite solution_lesson_node_00070).
    *   **Blocks**: Use **Pre-LayerNorm Direct SwiGLU Residual Blocks**.
        *   **Structure**: $x_{out} = x + \text{DropPath}(\text{Dropout}(\text{SwiGLU}(\text{Linear}(\text{LayerNorm}(x)))))$.
        *   **Normalization**: Use **LayerNorm** (Cite solution_lesson_node_00087).
        *   **Activation**: **SwiGLU** (Swish-Gated Linear Unit) (Cite solution_lesson_node_00090).
    *   **Transitions**: Use **Pre-Norm Transitions** (`LayerNorm -> Linear`) between stages (Cite solution_lesson_node_00088).
    *   **Regularization**: Linear **Stochastic Depth** schedule (0.0 to 0.2) (Cite solution_lesson_node_00086) + **Dropout (0.35)**.

5.  **Output Head**
    *   **Minimalist Design**: Single `Linear` layer with Sigmoid activation (Cite solution_lesson_node_00060).

# Data

1.  **Decomposition**: The string feature `f_27` is strictly split into 10 integer-encoded columns.
2.  **Normalization**: Continuous features (`f_00` - `f_30`) are Z-score normalized (StandardScaler).
3.  **Splitting**: Use the metadata-defined stratified validation split.
4.  **Volume**: Use the **Full Training Dataset** (640,000 samples) (Cite solution_lesson_node_00058).

# Training

1.  **Optimizer**: Use **AdamW**.
2.  **Strict Decoupled Weight Decay**:
    *   **Group 1 (Decay 1e-2)**: Weights of Linear layers, Embeddings, and Attention projections.
    *   **Group 2 (Decay 0.0)**: Biases, **LayerNorm parameters**, and **Positional Embeddings**. Explicitly filter by name (e.g., `pos_embed`) to prevent permutation-invariance failure (Cite solution_lesson_node_00098).
3.  **Initialization**:
    *   **SwiGLU Blocks**: Use **Kaiming (He) Uniform** (Cite solution_lesson_node_00090).
    *   **Transformer**: Use **Xavier (Glorot)** (Cite solution_lesson_node_00082).
4.  **Optimization Granularity**:
    *   **Batch Size**: 1024 (Cite solution_lesson_node_00044).
    *   **Scheduler**: Aggressive Step Decay (factor 0.1 every 10 epochs) (Cite solution_lesson_node_00033).
5.  **Duration**: Train for **40 epochs** (Cite solution_lesson_node_00045).
6.  **Metric**: Monitor **Validation AUC** (Cite solution_lesson_node_00003).

# Evaluation

1.  **Inference**: Iterate through the test set using the trained Interface-Normalized Hybrid SwiGLU Network.
2.  **Prediction**: Generate predictions using the single output head.
3.  **Submission**: The raw probability outputs are saved directly to the submission file.
