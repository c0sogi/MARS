# Solution Strategy

Based on the accumulated empirical evidence and the derived lessons, I propose the implementation of a **Dual-View Post-Norm SwiGLU-ResFunnel Network**.

This strategy represents a structural synthesis that re-integrates the **"Dual-View" Categorical Encoding** (conceptually validated in early successful iterations like Idea 13) with the modern, highly optimized **SwiGLU-ResFunnel** backbone (Cite solution_lesson_node_00090). It explicitly addresses the potential information bottleneck in the Transformer encoder by providing the backbone with a "Linear Shortcut" to the raw character embeddings. This ensures the model retains high-fidelity, position-specific character identity signals (Local View) while simultaneously leveraging the Transformer for complex inter-character dependencies (Contextual View), all stabilized by the proven Post-Norm and Decoupled Weight Decay configurations.

# Model

The architecture is a multi-stream network that fuses a dual-view categorical representation with a raw continuous stream into a deep, SwiGLU-based residual funnel.

1.  **Stream 1: Categorical Sequence (Dual-View)**
    *   **Input**: The `f_27` feature is decomposed into 10 distinct character tokens.
    *   **Shared Embedding**: Tokens are passed through a shared embedding layer (dimension 32).
    *   **Positional Encoding**: **Learnable Absolute Positional Embeddings** are added.
        *   **Initialization**: Explicitly initialize with **Low Variance Random Noise** ($\mathcal{N}(0, 0.02)$) to break symmetry without introducing high-magnitude noise (Cite solution_lesson_node_00081).
    *   **View A: Contextual (Transformer)**: The sequence is processed by a **Standard Transformer Encoder** (2 layers, 4 heads).
        *   **Configuration**: Use **Post-Normalization** (`norm_first=False`) to maximize capacity for this shallow encoder (Cite solution_lesson_node_00095).
        *   **Activation**: Explicitly set `activation="gelu"` (Cite solution_lesson_node_00068).
        *   **Regularization**: Apply **Low Dropout (0.1)** (Cite solution_lesson_node_00048).
        *   **Output**: Flattened vector (Dim: $10 \times 32 = 320$).
    *   **View B: Local (Residual Shortcut)**: The raw output of the embedding layer (with positional embeddings added) is **flattened directly**, bypassing the Transformer.
        *   **Rationale**: This acts as a "ResNet-style" skip connection over the Transformer, ensuring the backbone has direct access to the raw "Bag-of-Characters" signal, preventing over-smoothing by the attention mechanism.
        *   **Output**: Flattened vector (Dim: $10 \times 32 = 320$).

2.  **Stream 2: Continuous Preservation**
    *   **Input**: The 30 numerical features are standardized.
    *   **Preservation**: Features are maintained in their **raw, normalized form** (Cite solution_lesson_node_00038).

3.  **Fusion Layer: The Linear Stem**
    *   **Concatenation**: Concatenate **View A**, **View B**, and **Raw Continuous Features**. Total Dim: $320 + 320 + 30 = 670$.
    *   **No Normalization**: Do **not** apply normalization immediately after concatenation (Cite solution_lesson_node_00074).
    *   **Linear Stem**: The concatenated vector is passed through a **Linear Projection Layer** to map to the backbone width (512) (Cite solution_lesson_node_00073).

4.  **Backbone: LayerNorm SwiGLU ResFunnel**
    *   **Topology**: The backbone is organized into 3 stages (512 $\to$ 256 $\to$ 128) (Cite solution_lesson_node_00084).
    *   **Sustained Depth**: Each stage consists of **3 stacked Residual Blocks** (Cite solution_lesson_node_00070).
    *   **Blocks**: Use **Pre-LayerNorm Direct SwiGLU Residual Blocks**.
        *   **Structure**: $x_{out} = x + \text{DropPath}(\text{Dropout}(\text{SwiGLU}(\text{Linear}(\text{LayerNorm}(x)))))$.
        *   **Normalization**: Use **LayerNorm** (Cite solution_lesson_node_00087).
        *   **Activation**: **SwiGLU** (Swish-Gated Linear Unit) (Cite solution_lesson_node_00090).
    *   **Transitions**: Use **Pre-Norm Transitions** (`LayerNorm -> Linear`) between stages (Cite solution_lesson_node_00088).
    *   **Regularization**: Linear **Stochastic Depth** schedule (0.0 to 0.2) (Cite solution_lesson_node_00086) + **Dropout (0.35)**.

5.  **Output Head**
    *   **Minimalist Design**: Single `Linear` layer with Sigmoid activation. Avoid Multi-Sample Dropout as it degrades performance in high-precision regimes (Cite solution_lesson_node_00111, solution_lesson_node_00060).

# Data

1.  **Decomposition**: The string feature `f_27` is strictly split into 10 integer-encoded columns.
2.  **Normalization**: Continuous features (`f_00` - `f_30`) are Z-score normalized (StandardScaler).
3.  **Splitting**: Use the metadata-defined stratified validation split.
4.  **Volume**: Use the **Full Training Dataset** (640,000 samples) (Cite solution_lesson_node_00058).

# Training

1.  **Optimizer**: Use **AdamW**.
2.  **Strict Decoupled Weight Decay**:
    *   **Group 1 (Decay 1e-2)**: Weights of Linear layers, Embeddings, and Attention projections.
    *   **Group 2 (Decay 0.0)**: Biases, **LayerNorm parameters**, and **Positional Embeddings**. Explicitly filter by name (e.g., `pos_embed`) to prevent the permutation-invariance failure (Cite solution_lesson_node_00098).
3.  **Initialization**:
    *   **SwiGLU Blocks**: Use **Kaiming (He) Uniform** (Cite solution_lesson_node_00090).
    *   **Transformer**: Use **Xavier (Glorot)** (Cite solution_lesson_node_00082).
4.  **Optimization Granularity**:
    *   **Batch Size**: 1024 (Cite solution_lesson_node_00044).
    *   **Scheduler**: Aggressive Step Decay (factor 0.1 every 10 epochs) (Cite solution_lesson_node_00033).
5.  **Duration**: Train for **40 epochs** (Cite solution_lesson_node_00045).
6.  **Metric**: Monitor **Validation AUC** (Cite solution_lesson_node_00003).

# Evaluation

1.  **Inference**: Iterate through the test set using the trained Dual-View Post-Norm SwiGLU-ResFunnel.
2.  **Prediction**: Generate predictions using the single output head.
3.  **Submission**: The raw probability outputs are saved directly to the submission file.
