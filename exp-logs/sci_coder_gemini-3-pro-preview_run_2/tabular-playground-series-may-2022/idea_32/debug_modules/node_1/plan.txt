The error `KeyError: 'target'` occurs because both the metadata file (`train_metadata.csv`) and the raw data file (`train.csv`) contain a `target` column. When these DataFrames are merged on `id` without handling the duplicate column, Pandas renames them to `target_x` and `target_y` to avoid collision (Cite debug_lesson_1). Consequently, the code fails later when it attempts to access the column named `target`.

Additionally, the traceback indicates that the training pipeline in `library/network.py` is triggered immediately upon import by `runfile.py`. This happens before `runfile.py` can apply the "Demo" configuration (e.g., enabling Debug mode), causing the script to attempt a full training run instead of the intended quick verification.

To fix these issues:
1.  In `library/dataset.py`, I will explicitly drop the `target` column from the raw training data before merging it with the metadata. This ensures the merged DataFrame retains the authoritative `target` column from the metadata.
2.  In `library/network.py`, I will wrap the `run()` call in an `if __name__ == "__main__":` block to prevent it from executing automatically during import.
