### Implementation Strategy

1.  **Configuration Override**: I will modify the global `Config` class attributes at runtime to use a lightweight model (`prajjwal1/bert-tiny`) and reduce the number of epochs, batch size, and data volume. This ensures the demonstration runs in seconds rather than hours.
2.  **Utility Verification**: I will demonstrate and verify the `clean_text` and `get_score` functions from `library.utils` with assertions.
3.  **Data Pipeline Demonstration**:
    *   I will load a small subset (20 rows) of the training data to simulate a quick run.
    *   I will use `library.dataset.load_dataset_dataframe` and `InsultDataset` to demonstrate data loading, cleaning, and tokenization.
    *   I will verify the output shapes of the `DataLoader`.
4.  **Model & AWP Demonstration**:
    *   I will instantiate the `InsultModel` with the tiny backbone.
    *   I will perform a forward pass to verify tensor shapes.
    *   I will initialize the `AWP` (Adversarial Weight Perturbation) class, perform an attack, and assert that weights have actually been perturbed and then restored.
5.  **Training Loop Simulation**:
    *   Instead of running the full K-Fold cross-validation (which is time-consuming), I will manually execute `train_one_epoch` and `valid_one_epoch` from `library.trainer` using the small dataset.
    *   I will save the resulting model weights to the working directory, mimicking the format expected by the inference pipeline.
6.  **Inference Pipeline Demonstration**:
    *   I will generate a small dummy test set.
    *   I will call `library.inference.predict_fn` to generate predictions using the saved model, verifying the output submission file exists and has the correct format.
