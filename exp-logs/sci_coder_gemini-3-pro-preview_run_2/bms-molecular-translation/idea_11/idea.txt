Based on the lessons learned, specifically the resolution mismatch identified in **Lesson solution_lesson_node_00012** and the superior flexibility of autoregressive modeling identified in **Lesson solution_lesson_node_00015**, I propose the **Anisotropic ResNet-Transformer with 2D Spatial-Awareness**.

This strategy addresses the critical failure mode where the encoder's output resolution was insufficient to represent the dense character sequences of InChI strings ($T < L$). By decoupling the vertical and horizontal downsampling rates, we ensure the model retains the necessary horizontal granularity to distinguish individual atoms while aggregating vertical context.

### Model
The architecture is an Encoder-Decoder network designed to handle high-aspect-ratio chemical images:

1.  **Anisotropic Visual Encoder:**
    *   **Backbone:** A **ResNet-50** is used as the feature extractor (upgraded from ResNet-18/34 in previous ideas for better feature discrimination).
    *   **Strided Modification:** To satisfy the capacity constraint ($T \ge L$) identified in **solution_lesson_node_00012**, the downsampling operations in the latter stages (Layer 3 and Layer 4) are modified. Instead of standard $2 \times 2$ strides, we employ **anisotropic strides** of $(2, 1)$. This compresses the height (capturing global structure) while preserving the width (retaining character-level resolution).
    *   **Result:** For an input image of size $(H, W)$, the output feature map has dimensions roughly $(H/32, W/4)$. This ensures that even for dense molecules, the horizontal feature resolution is sufficient to separate adjacent characters.
2.  **2D Positional Encoding:**
    *   The resulting 2D feature map is flattened into a sequence of vectors. Crucially, learnable **2D Positional Embeddings** (summing row and column embeddings) are added to the feature vectors before they enter the decoder. This explicitly informs the Transformer of the spatial relationships (e.g., "above", "below") which are vital for interpreting chemical bonds and stereochemistry.
3.  **Transformer Decoder:**
    *   A standard multi-layer Transformer Decoder is used. It employs **Cross-Attention** to attend to the resolution-preserved encoder features and **Masked Self-Attention** to generate the InChI string autoregressively. This architecture is chosen over pure CTC to decouple the output length from the input grid, as recommended in **solution_lesson_node_00015**.

### Data
1.  **Input-Adaptive Preprocessing:**
    *   **Fixed-Height Resizing:** Images are resized to a fixed height (e.g., 320 pixels) while maintaining their original aspect ratio. This ensures a consistent vertical scale for atoms across the dataset, regardless of molecule length.
    *   **Dynamic Width Padding:** Instead of resizing to a fixed square (which distorts aspect ratios), images are padded horizontally to the nearest multiple of the backbone's stride (e.g., 32 pixels). This preserves the "density" of the visual information.
    *   **Grayscale:** Images are converted to 1-channel grayscale to reduce computational overhead.
2.  **Tokenization:**
    *   The InChI strings are tokenized at the character level.
    *   Special tokens `<SOS>`, `<EOS>`, and `<PAD>` are added to the vocabulary.

### Training
1.  **Loss Function:** The model is trained using **Cross-Entropy Loss** with **Teacher Forcing**. The decoder receives the ground-truth tokens from the previous step to predict the current token.
2.  **Optimization:** An **AdamW** optimizer is used with a **One-Cycle Learning Rate Scheduler**. This schedule warms up the learning rate to stabilize the training of the Transformer components and then decays it for fine-tuning.
3.  **Regularization:** To prevent overfitting on the training set structure, **Image Augmentation** (light rotation, noise, and erosion/dilation) is applied to simulate the variability in line thickness and scan quality found in the test set.

### Evaluation
1.  **Inference:** Test images are preprocessed using the same fixed-height strategy. The encoder generates the 2D-aware feature memory bank.
2.  **Decoding:** The prediction is generated using **Beam Search** (e.g., beam width 3-5). This explores multiple probable sequences simultaneously, offering a significant improvement over greedy decoding for ensuring syntactically valid InChI strings (e.g., matching parentheses).
