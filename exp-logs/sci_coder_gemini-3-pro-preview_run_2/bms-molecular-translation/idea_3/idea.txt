To solve the task of predicting InChI strings from chemical images, I propose a **CNN-Transformer Hybrid Network**.

This approach establishes a modern baseline by synthesizing the robust feature extraction of Convolutional Neural Networks (CNNs) with the parallel processing capabilities of Transformers. It is strictly distinct from the previous ideas: unlike Idea 1, it does not rely on CTC loss or treat the image as a single horizontal sequence; unlike Idea 2, it retains spatial feature maps rather than compressing the image into a global vector, utilizing attention mechanisms to focus on fine-grained molecular details.

### Model
The architecture is designed as a streamlined Encoder-Decoder network:
1.  **Visual Encoder:** A lightweight, pre-trained CNN backbone (e.g., **ResNet-18**) serves as the feature extractor. The final pooling and fully connected layers are removed to preserve the spatial structure of the feature maps ($H \times W \times D$). These maps are flattened into a sequence of $L$ visual vectors ($L = H \times W$) and projected to the dimension required by the decoder.
2.  **Positional Encoding:** Learnable 1D positional embeddings are added to the sequence of visual vectors. This step is crucial to inject spatial context (relative positions of atoms and bonds) into the permutation-invariant Transformer architecture.
3.  **Transformer Decoder:** The decoder consists of a shallow stack (e.g., 2 to 3 layers) of Transformer blocks. Each block contains:
    *   **Masked Self-Attention:** To model the dependencies within the generating InChI text sequence.
    *   **Cross-Attention:** To dynamically attend to specific visual vectors from the encoder, allowing the model to focus on relevant image regions (e.g., specific functional groups) while generating the corresponding text.
    *   **Feed-Forward Networks:** For token-wise processing.
4.  **Prediction Head:** A final linear layer projects the decoder's output to the size of the character vocabulary to predict the next token probability.

### Data
*   **Image Preprocessing:** Images are resized to a fixed square resolution (e.g., 256x256 pixels) to allow for efficient batching. Pixel values are normalized to the range [0, 1] or standardized using ImageNet statistics. No heavy augmentations are applied to maintain baseline simplicity.
*   **Text Preprocessing:** The InChI strings are tokenized at the character level. The vocabulary is built from all unique characters in the training set, plus special control tokens: `<SOS>` (Start of Sequence), `<EOS>` (End of Sequence), and `<PAD>` (Padding). Target sequences are padded to a fixed maximum length.

### Training
*   **Loss Function:** The model is trained using **Cross-Entropy Loss**, calculating the discrepancy between the predicted token probabilities and the ground truth characters at each position.
*   **Optimization:** An **AdamW** optimizer is used, often with a learning rate scheduler that includes a warmup phase followed by cosine decay, which is standard for stabilizing Transformer training.
*   **Training Strategy:** Unlike RNNs, the Transformer architecture allows for **parallelized training** using causal masking. This means the model can process all tokens in the target sequence simultaneously during the forward pass (Teacher Forcing), significantly speeding up the training process compared to sequential RNN baselines.

### Evaluation
*   **Prediction:** During inference, the test image is encoded once. The decoding process is autoregressive: it begins with the `<SOS>` token.
*   **Decoding:** A **Greedy Decoding** strategy is employed for efficiency. At each step, the model predicts the token with the highest probability, and this token is appended to the input sequence for the next step.
*   **Termination:** The generation loop continues until the `<EOS>` token is predicted or a maximum sequence length is reached. The generated tokens are then concatenated to form the final InChI string.
