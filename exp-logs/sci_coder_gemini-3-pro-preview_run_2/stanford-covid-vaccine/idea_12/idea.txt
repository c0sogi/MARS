Based on the comprehensive analysis of the provided lessons and the progression of previous ideas, I propose the **Stacking-Aware Dense-Refined Hybrid Network**. This strategy synthesizes the breakthrough performance of "Latent Structural Gathering" with the high-capacity feature extraction of "Dense Connectivity," while explicitly architecting the network to model base-pair stacking thermodynamics through a "Cascaded" design.

# Model

The architecture is a **Two-Stage Dense-Dilated Hybrid** designed to sequentially resolve local motifs, structural pairings, and stacking interactions.

1.  **Input Representation (Parsimonious One-Hot):**
    *   We utilize **One-Hot Encoding** for `sequence`, `structure`, and `predicted_loop_type` (Cite solution_lesson_node_00010).
    *   We strictly **exclude** static "Partner Base Identity" or "Partner Triplets" from the input. As established in **Lesson 00031** and **Lesson 00023**, dynamic gathering of learned features is superior to static injection, and high-dimensional sparse inputs degrade optimization.

2.  **Stage 1 Backbone (Local Motif Extraction):**
    *   **Architecture:** A stack of **Single-Layer Dilated Residual Blocks** (Cite solution_lesson_node_00011) utilizing **Dense Connections** (concatenating outputs of all prior blocks).
    *   **Configuration:** We employ exponentially increasing dilation rates ($d=1, 2, \dots, 32$) to capture global sequence context (Cite solution_lesson_node_00002).
    *   **Capacity:** We strictly set the **Growth Rate / Channel Width** to **64**. This addresses the bottleneck failure observed in **Lesson 00037**, ensuring the model has sufficient vocabulary to encode diverse chemical motifs.
    *   **Regularization:** We apply **Dropout (0.1)** within every block. This is mandatory to prevent the overfitting observed in **Lesson 00038** when using dense connectivity on this dataset.
    *   **Convolution Type:** We use **Standard Convolutions** throughout, avoiding Separable convolutions (Cite solution_lesson_node_00018).

3.  **Inter-Stage Latent Refinement (The Pair-State):**
    *   **Compression:** The high-dimensional output of Stage 1 is compressed via a **1x1 Convolution** to a compact dimension (e.g., 64) to enforce parsimony.
    *   **Dynamic Gather:** For every position $i$, we use the structure map to "gather" the compressed feature vector of its paired partner $j$ and concatenate it to the feature vector of $i$. This creates a **"Pair-State" Representation** that encodes the learned context of the interaction (Cite solution_lesson_node_00031).

4.  **Stage 2 Backbone (Stacking Interaction Solver):**
    *   **Structural Innovation (Dilation Reset):** We process the fused "Pair-State" features with a second stack of Dense Dilated Blocks. Crucially, we **reset the dilation schedule** starting from $d=1, 2, 4 \dots$.
    *   **Rationale:** RNA stability is governed by **Stacking Interactions**—the energy between a base pair $(i, j)$ and its immediate neighbors $(i \pm 1, j \mp 1)$. By resetting dilation to 1, the initial layers of Stage 2 explicitly convolve over adjacent "Pair-States", allowing the model to learn these stacking energies from the rich, pre-processed features. This solves the physics targeted by "Partner Triplets" (Idea 6) using robust learned representations instead of sparse inputs.

5.  **Global Aggregation (BiGRU):**
    *   The Stage 2 output is processed by a **Bidirectional GRU** to capture global constraints (Cite solution_lesson_node_00003).
    *   **Constraint:** Hidden size is set to `input_dim // 2` to ensure the output dimension matches the input (Cite solution_lesson_node_00004).

6.  **Output Head:**
    *   Linear projection to the 5 target variables.

1.  **Loss Function (Masked Optimization):**
    *   Use **MCRMSE** (Mean Columnwise Root Mean Squared Error).
    *   **Strategy:** Calculate loss **only on the three scored columns** (`reactivity`, `deg_Mg_pH10`, `deg_Mg_50C`).
    *   **Rationale:** We strictly adhere to **Lesson 00016**, masking out auxiliary targets (`deg_pH10`, `deg_50C`) to prevent negative transfer and align the optimization objective directly with the competition metric.

2.  **Optimizer:**
