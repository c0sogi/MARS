The issue is caused by the presence of stale cache files (`.npz`) in the working directory that contain the full dataset from a previous execution or environment setup. When `run_pipeline_demo` runs, the data loading logic detects these existing files and loads them instead of processing the newly created subset CSVs, leading to a mismatch between the expected subset size (22 samples) and the actual loaded data (full test set). This is a classic instance of a stale state crash where the persistence layer masks configuration changes (Cite debug_lesson_9).

To fix this, I will modify `runfile.py` to explicitly delete any existing cache files at the start of the `run_pipeline_demo` function. This ensures that the data processing pipeline is forced to regenerate the cache using the correct subset CSVs.
