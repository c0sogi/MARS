Based on the progression of insights derived from the provided lessons, I propose the **Latent Structure-Refined Hybrid Network**. This strategy evolves the successful "Partner-Aware" baseline by extending the utilization of structural information from the input stage to the latent feature space, allowing the model to validate interactions using learned context while maintaining architectural efficiency.

# Model

1.  **Input Representation (Partner-Augmented):**
    *   **One-Hot Encoding:** We retain the robust One-Hot encoding for `sequence`, `structure`, and `predicted_loop_type` as the primary input representation (Cite solution_lesson_node_00010).
    *   **Partner Base Identity:** We explicitly include the **Partner Base Identity** feature, where the one-hot vector of a paired base is concatenated to the current position's input. This has been proven to significantly improve performance by "teleporting" distal information (Cite solution_lesson_node_00015).

2.  **Backbone (Multi-Scale Dilated TCN):**
    *   The core feature extractor remains a stack of **Single-Layer Dilated Residual Blocks** (Cite solution_lesson_node_00011). We employ **Standard Convolutions** rather than separable ones to preserve the joint modeling of channel and spatial correlations required for chemical motifs (Cite solution_lesson_node_00018).
    *   **Multi-Scale Fusion:** We retain the strategy of concatenating the outputs of all dilated layers to form a dense, multi-resolution feature map that captures both local motifs and broader context.

3.  **Structural Innovation (Latent Structural Refinement):**
    *   **Concept:** While the "Partner Base Identity" at the input level tells the model *who* the partner is, it lacks context about the partner's state (e.g., is the partner part of a stable stem or a frayed end?).
    *   **Mechanism:** I introduce a **Latent Structural Refinement Module** inserted between the TCN backbone and the BiGRU.
        *   For every position $i$ in the sequence, the module uses the known secondary structure to "gather" the **Multi-Scale Feature Vector** of its paired partner $j$. (If unpaired, a zero vector is used).
        *   These gathered partner features are concatenated with the local features at position $i$.
        *   A **1x1 Convolution** then projects this fused representation back to the original feature dimension.
    *   **Rationale:** This effectively performs a single, highly efficient message-passing step using learned, high-level features. It allows the model to verify the stability of base pairs based on their contextualized representations without the noise propagation or computational overhead of a full Graph Neural Network (addressing solution_lesson_node_00007) and without the sparsity issues of "Partner Triplet" inputs (addressing solution_lesson_node_00023).

4.  **Global Aggregation (BiGRU):**
    *   The structurally refined features are processed by a **Bidirectional GRU (BiGRU)** to capture global sequence state (Cite solution_lesson_node_00003).
    *   **Constraint:** The hidden size is strictly set to `input_dim // 2` to ensure the output dimension matches the input, preventing over-parameterization (Cite solution_lesson_node_00004).

5.  **Output Head:**
    *   A final linear layer maps the BiGRU output to the 5 target variables.

# Data

1.  **Preprocessing:**
    *   **Encodings:** Generate One-Hot encodings for sequence, structure, and loop type.
    *   **Partner Indices:** Parse the `structure` string to create two auxiliary arrays:
        *   **Partner Identity:** The one-hot vector of the paired base (for Input).
        *   **Partner Index Map:** An integer array where index $i$ contains the index $j$ of its partner (or a sentinel value like -1 if unpaired). This is used for the **Latent Structural Refinement** gather operation.
    *   **Target Parsing:** Parse stringified targets in `train.csv` to numerical arrays.

2.  **Loaders:**
    *   Data loaders must yield the Input Tensor (One-Hot + Partner ID), the Partner Index Map, and the Target Tensor.

# Training

1.  **Loss Function (Masked Optimization):**
    *   Use **MCRMSE** (Mean Columnwise Root Mean Squared Error).
    *   **Strategy:** Calculate loss **only on the three scored columns** (`reactivity`, `deg_Mg_pH10`, `deg_Mg_50C`).
    *   **Rationale:** We strictly adhere to **Lesson 00016** and **Lesson 00006**, masking out the auxiliary targets (`deg_pH10`, `deg_50C`) to prevent negative transfer and align the optimization objective directly with the competition metric.

2.  **Optimizer:**
    *   Use **AdamW** with a learning rate of 1e-3 and a `ReduceLROnPlateau` scheduler.
    *   Maintain a moderate model width (e.g., 128 channels) to avoid the overfitting risks associated with wider models (Cite solution_lesson_node_00017).

# Evaluation

1.  **Metric Calculation:**
    *   Implement the **Correct Global RMSE** calculation by accumulating the Sum of Squared Errors (SSE) and counts across all batches, computing the square root only at the end of the epoch (Cite solution_lesson_node_00020).

2.  **Inference:**
    *   Process `test.csv` to generate inputs and Partner Index Maps.
    *   Generate predictions for all 107 positions.
    *   Flatten outputs to the `id_seqpos` format for submission.
