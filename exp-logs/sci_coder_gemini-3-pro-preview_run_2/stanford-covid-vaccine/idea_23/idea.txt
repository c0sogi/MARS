Based on the comprehensive analysis of the provided lessons and the progression of previous ideas, I propose the **Asymmetric Bottleneck Dense-Context Network**.

This strategy synthesizes the robust performance of the "Dense-Context" backbone (Idea 8) with a novel **Asymmetric Latent Interaction** mechanism. It resolves the trade-off between the "information smashing" of aggressive compression (Idea 8) and the "noise propagation" of full-scale gathering (Idea 16) by decoupling the fidelity of local representations from the compression required for distant message passing.

# Model

1.  **Input Representation (Partner-Aware):**
    *   **Standard Features:** We utilize **One-Hot Encoding** for `sequence`, `structure`, and `predicted_loop_type` (Cite solution_lesson_node_00010).
    *   **Explicit Partner Identity:** We **retain** the explicit injection of the **Partner Base Identity** (one-hot vector of the paired base) at the input level. As established in **Lesson 00052**, removing this input cripples the encoder's ability to form basic chemical representations, regardless of downstream complexity.

2.  **Backbone (Dense Dilated TCN):**
    *   **Architecture:** A stack of **Single-Layer Dilated Residual Blocks** (Cite solution_lesson_node_00011) utilizing **Dense Connections** (concatenating outputs of all prior blocks). This preserves the full multi-scale history required for complex interaction modeling (Cite solution_lesson_node_00047).
    *   **Configuration:** We employ exponentially increasing dilation rates ($d=1, 2, 4, 8, 16, 32$) to ensure global receptive field coverage (Cite solution_lesson_node_00002).
    *   **Capacity & Regularization:** We strictly set the **Growth Rate / Channel Width** to **64** to avoid capacity bottlenecks (Cite solution_lesson_node_00037) and apply **Dropout (0.1)** within every block to prevent overfitting (Cite solution_lesson_node_00038).
    *   **Convolution Type:** We use **Standard Convolutions** throughout (Cite solution_lesson_node_00018).
    *   **Output:** This produces a high-dimensional tensor $H_{dense}$ (e.g., ~384 channels) containing the concatenated multi-scale history.

3.  **Innovation: Asymmetric Latent Interaction:**
    *   **Concept:** Previous iterations failed by either compressing the local context too much (losing detail) or gathering too much distant data (adding noise). We treat these two information streams asymmetrically.
    *   **Stream 1 (High-Fidelity Local):** We project $H_{dense}$ to a **High-Dimensional Local Vector** $L$ (e.g., 96 channels) using a 1x1 convolution. This preserves the rich local details required by the RNN.
    *   **Stream 2 (Compressed Message):** We project $H_{dense}$ to a **Compact Message Vector** $M$ (e.g., 32 channels) using a separate 1x1 convolution. This adheres to **Lesson 00062**, compressing the representation to filter noise before the gather operation.
    *   **Zero-Masked Gather:** For every position $i$, we gather the compressed message $M$ from its paired partner $j$. Crucially, we use **Zero-Masking** for unpaired bases (Cite solution_lesson_node_00071) to provide a distinct orthogonal signal, avoiding the noise amplification of self-referencing.
    *   **Fusion:** We concatenate the high-fidelity local features with the compressed partner message: $[L_i, M_{partner}]$. We use simple concatenation (Cite solution_lesson_node_00066) to avoid imposing rigid arithmetic biases (Cite solution_lesson_node_00067).

4.  **Global Aggregation (BiGRU):**
    *   The fused features (Total 128 channels) are processed by a **Bidirectional GRU** to capture global constraints (Cite solution_lesson_node_00003).
    *   **Constraint:** Hidden size is set to `input_dim // 2` (64) to ensure the output dimension matches the input, preventing parameter bloat (Cite solution_lesson_node_00004).

5.  **Output Head:**
    *   Linear projection to the 5 target variables.

# Training

1.  **Loss Function (Masked Optimization):**
    *   Use **MCRMSE** (Mean Columnwise Root Mean Squared Error).
    *   **Strategy:** Calculate loss **only on the three scored columns** (`reactivity`, `deg_Mg_pH10`, `deg_Mg_50C`).
    *   **Rationale:** We strictly adhere to **Lesson 00016**, masking out auxiliary targets (`deg_pH10`, `deg_50C`) to prevent negative transfer and align the optimization objective directly with the competition metric.

2.  **Optimizer:**
    *   Use **AdamW** with a learning rate of 1e-3 and a `ReduceLROnPlateau` scheduler.
