### Implementation Strategy

1.  **Environment Setup**: Import necessary libraries and the provided `library` modules. Suppress warnings for clean output.
2.  **Data Subsetting**: Create a temporary directory (`./working/demo_metadata`) and save small subsets (e.g., 20 samples) of the provided metadata CSVs (`train.csv`, `val.csv`, `test.csv`). This ensures the demonstration runs quickly.
3.  **Configuration Override**: Modify the `library.config.Config` class attributes to point to these new subset files and a temporary working directory (`./working/demo_execution`). This isolates the demo from the main workflow and forces the data processing pipeline to handle the new subsets.
4.  **Component Verification (Unit Tests)**:
    *   **Data Loading**: Initialize `get_loaders` and verify that the returned DataLoaders yield batches with the expected shapes for inputs, partner indices, and targets.
    *   **Model Logic**: Instantiate `ScalePartitionedDenseNet`. Perform a forward pass with a batch from the loader and assert that the output shape matches `(Batch, SeqLen, 5)`.
    *   **Loss Logic**: Instantiate `MaskedMCRMSELoss`. Compute the loss on the model output and verify it returns a valid scalar.
    *   **Metric Logic**: Instantiate `GlobalMetricTracker`. Simulate a batch update and verify the computation logic.
5.  **Full Pipeline Execution**: Call `library.train.run_training` with a small number of epochs (2) and a small batch size (4). This tests the end-to-end flow: training loop, validation, checkpointing, inference, and submission generation.
6.  **Output Validation**: Verify that the `submission.csv` file is generated and contains the correct number of rows corresponding to the test subset.
