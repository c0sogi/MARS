Based on the comprehensive analysis of the provided lessons and the progression of previous ideas, I propose the **Dense-Stacking Hybrid Network**. This strategy synthesizes the state-of-the-art performance of the "Dense-Context" architecture (Idea 8) with the physics-aware "Neighbor Stacking" concept attempted in Idea 14, while strictly correcting the critical data engineering flaw that caused Idea 14 to fail.

# Model

The architecture is a **Dense Dilated TCN** augmented with a **Dual-Context Interaction Mechanism** (Input-Level Identity + Latent-Level Stacking).

1.  **Input Representation (Dual-Context):**
    *   **Standard Features:** We utilize **One-Hot Encoding** for `sequence`, `structure`, and `predicted_loop_type` (Cite solution_lesson_node_00010).
    *   **Explicit Partner Identity:** We **retain** the explicit injection of the **Partner Base Identity** (one-hot vector of the paired base) at the input level. As established in **Lesson 00052**, removing this input cripples the encoder's ability to form basic chemical representations, regardless of downstream complexity. This corrects the fatal flaw of Idea 14.

2.  **Backbone (Dense Dilated TCN):**
    *   **Architecture:** A stack of **Single-Layer Dilated Residual Blocks** (Cite solution_lesson_node_00011) utilizing **Dense Connections** (concatenating outputs of all prior blocks). This preserves the full multi-scale history required for complex interaction modeling (Cite solution_lesson_node_00047).
    *   **Configuration:** We employ exponentially increasing dilation rates ($d=1, 2, \dots, 32$) to ensure global receptive field coverage (Cite solution_lesson_node_00002).
    *   **Capacity & Regularization:** We strictly set the **Growth Rate / Channel Width** to **64** to avoid capacity bottlenecks (Cite solution_lesson_node_00037) and apply **Dropout (0.1)** within every block to prevent overfitting (Cite solution_lesson_node_00038).
    *   **Convolution Type:** We use **Standard Convolutions** throughout (Cite solution_lesson_node_00018).

3.  **Innovation: Latent Neighbor-Stacking Interaction:**
    *   **Concept:** While the Input Partner Identity tells the model *who* the partner is, it does not describe the *thermodynamic environment* of the pair. RNA stability is governed by **Stacking Interactions**—the energetic coupling between a base pair $(i, j)$ and its neighbors $(i \pm 1, j \mp 1)$.
    *   **Mechanism:**
        *   **Compression:** The high-dimensional output of the Dense backbone is compressed via a 1x1 convolution.
        *   **Multi-Point Gather:** For every position $i$ paired with $j$, we gather the compressed learned features from **three** indices: the partner $j$, the **5' neighbor** $j-1$, and the **3' neighbor** $j+1$ (Cite solution_lesson_node_00031).
        *   **Fusion:** We concatenate the local features of $i$ with the gathered features of $j, j-1, \text{and } j+1$.
    *   **Rationale:** This combines the best of Idea 8 and Idea 14. We use the **Input Partner Identity** to drive robust local encoding, and the **Latent Neighbor Gather** to explicitly model the stacking physics using rich, context-aware features. This avoids the sparsity of input triplets (Cite solution_lesson_node_00023) while capturing the geometry Idea 8 missed.

4.  **Global Aggregation (BiGRU):**
    *   The stacking-augmented features are processed by a **Bidirectional GRU** to capture global constraints (Cite solution_lesson_node_00003).
    *   **Constraint:** Hidden size is set to `input_dim // 2` to ensure the output dimension matches the input (Cite solution_lesson_node_00004).

5.  **Output Head:**
    *   Linear projection to the 5 target variables.

# Training

1.  **Loss Function (Masked Optimization):**
    *   Use **MCRMSE** (Mean Columnwise Root Mean Squared Error).
    *   **Strategy:** Calculate loss **only on the three scored columns** (`reactivity`, `deg_Mg_pH10`, `deg_Mg_50C`).
    *   **Rationale:** We strictly adhere to **Lesson 00016**, masking out auxiliary targets (`deg_pH10`, `deg_50C`) to prevent negative transfer and align the optimization objective directly with the competition metric.

2.  **Optimizer:**
    *   Use **AdamW** with a learning rate of 1e-3 and a `ReduceLROnPlateau` scheduler.
