Based on the comprehensive analysis of the provided lessons and the progression of previous ideas, I propose the **Dense Latent-Neighbor Hybrid Network**. This strategy optimizes the state-of-the-art "Dense-Context" architecture (Idea 8) by refining the structural interaction mechanism. It replaces the simple "Partner Gather" with a **Latent Neighbor-Stacking Gather**, explicitly modeling the thermodynamics of base-pair stacking using dense, learned representations rather than sparse inputs or staged architectures.

# Model

1.  **Input Representation (Parsimonious One-Hot):**
    *   We utilize **One-Hot Encoding** for `sequence`, `structure`, and `predicted_loop_type` (Cite solution_lesson_node_00010).
    *   We strictly **exclude** static "Partner Base Identity" or "Partner Triplets" from the input. As established in **Lesson 00031** and **Lesson 00023**, dynamic gathering of learned features is superior to static injection, and high-dimensional sparse inputs degrade optimization.

2.  **Backbone (Dense Dilated TCN):**
    *   **Architecture:** A stack of **Single-Layer Dilated Residual Blocks** (Cite solution_lesson_node_00011) utilizing **Dense Connections** (concatenating outputs of all prior blocks).
    *   **Configuration:** We employ exponentially increasing dilation rates ($d=1, 2, \dots, 32$) to ensure global receptive field coverage (Cite solution_lesson_node_00002).
    *   **Capacity:** We strictly set the **Growth Rate / Channel Width** to **64**. This addresses the bottleneck failure observed in **Lesson 00037**, ensuring the model has sufficient vocabulary to encode diverse chemical motifs.
    *   **Regularization:** We apply **Dropout (0.1)** within every block. This is mandatory to prevent the overfitting observed in **Lesson 00038** when using dense connectivity.
    *   **Convolution Type:** We use **Standard Convolutions** throughout (Cite solution_lesson_node_00018).

3.  **Innovation: Latent Neighbor-Stacking Interaction:**
    *   **Concept:** RNA helix stability is determined by **Stacking Interactions**—the energetic coupling between a base pair $(i, j)$ and its neighbors $(i \pm 1, j \mp 1)$. While the CNN backbone captures $i$'s neighbors ($i \pm 1$), a simple partner gather only captures $j$, missing $j$'s context.
    *   **Mechanism:**
        *   **Compression:** The high-dimensional output of the Dense backbone is compressed via a 1x1 convolution to a compact dimension (e.g., 64).
        *   **Multi-Point Gather:** For every position $i$ paired with $j$, we gather the compressed features from **three** indices: the partner $j$, the **5' neighbor** $j-1$, and the **3' neighbor** $j+1$.
        *   **Fusion:** We concatenate the local features of $i$ with the gathered features of $j, j-1, \text{and } j+1$.
    *   **Rationale:** This explicitly reconstructs the **Stacking Geometry** in the latent space. Unlike Idea 6 (which used sparse "Partner Triplets" at the input and failed per **Lesson 00023**), this approach uses rich, **dense learned features**. Unlike Idea 12/13 (which used staged/bridged architectures and failed per **Lesson 00047**), this preserves the full dense history while injecting the necessary physics.

4.  **Global Aggregation (BiGRU):**
    *   The stacking-augmented features are processed by a **Bidirectional GRU** to capture global constraints (Cite solution_lesson_node_00003).
    *   **Constraint:** Hidden size is set to `input_dim // 2` to ensure the output dimension matches the input (Cite solution_lesson_node_00004).

5.  **Output Head:**
    *   Linear projection to the 5 target variables.

    *   **Rationale:** We strictly adhere to **Lesson 00016**, masking out auxiliary targets (`deg_pH10`, `deg_50C`) to prevent negative transfer and align the optimization objective directly with the competition metric.
