Based on the lessons learned, specifically the importance of **Decoupled Block Micro-Architecture** (Lesson 00111), **Dense Connectivity** (Lesson 00047), and **Lightweight Feedback** (Lesson 00103), I propose the **Decoupled Dense-Feedback Recurrent Network (DDF-RN)**.

This strategy optimizes the "Topology-Informed" architecture (Idea 43) by structurally upgrading the feedback encoder. While Idea 43 used a Residual TCN for feedback, **Lesson 00047** proves that Dense connectivity is superior for capturing multi-scale dependencies. Previous attempts at Dense Feedback (Idea 38, 42) failed due to excessive capacity (Lesson 00103) or improper block structure (Lesson 00111). The **DDF-RN** resolves this by implementing a **Lightweight Dense Feedback Encoder** utilizing **Decoupled Spatial/Channel Blocks**, ensuring high feature reuse and robustness without parameter bloat.

# Model

1.  **Input Representation (Static & Partner-Aware):**
    *   **Features:** One-Hot Encoding for `sequence`, `structure`, and `predicted_loop_type` (Cite solution_lesson_node_00010).
    *   **Explicit Partner Identity:** We **retain** the explicit injection of the **Partner Base Identity** (one-hot vector of the paired base) at the input level (Cite solution_lesson_node_00052).
    *   **Static Tensor:** The input remains static; we do not augment it with recycling channels to avoid re-running the heavy main backbone (Cite solution_lesson_node_00090).

2.  **Main Backbone (Static Dense Dilated TCN):**
    *   **Architecture:** A stack of **Single-Layer Dilated Blocks** utilizing **Dense Connections** (concatenating outputs of all prior blocks) (Cite solution_lesson_node_00047).
    *   **Micro-Architecture:** We strictly enforce the **Decoupled Block Structure** (Cite solution_lesson_node_00111): `Norm -> ReLU -> Dilated Conv (k=3) -> Norm -> ReLU -> Pointwise Conv (k=1)`. This separates spatial aggregation from channel mixing.
    *   **Configuration:** Exponentially increasing dilation rates ($d=1, 2, 4, 8, 16, 32$) (Cite solution_lesson_node_00002).
    *   **Capacity:** Growth Rate **64**, **Dropout 0.1** (Cite solution_lesson_node_00037, solution_lesson_node_00038).
    *   **Latent Projection:** The output is projected to **Latent Dim 64** ($Z$) via a **Linear 1x1 Convolution** (Cite solution_lesson_node_00062, solution_lesson_node_00076).

3.  **Decoupled Dense Feedback Module (Structural Innovation):**
    *   **Inputs:** Recycled predictions $\hat{Y}_{k-1}$ (masked to zero out unscored targets, Cite solution_lesson_node_00016) concatenated with **Raw Topology Features** (Structure/Loop one-hots).
    *   **Architecture:** A **Lightweight Dense TCN**.
        *   *Structure:* Uses **Dense Connections** to maximize signal propagation from the noisy feedback (Cite solution_lesson_node_00047).
        *   *Blocks:* Uses the same **Decoupled Block Structure** (Dilated $\to$ Pointwise) to ensure robustness (Cite solution_lesson_node_00111).
        *   *Constraint:* **Low Growth Rate (e.g., 12)**. This ensures the feedback loop remains low-capacity relative to the backbone, preventing it from dominating the signal or overfitting to noise (Cite solution_lesson_node_00103).
    *   **Output:** Feedback Embeddings $E_{fb}$ (32 channels).

4.  **Interaction & Aggregation:**
    *   **Augmented Gather:** For every position $i$ paired with $j$:
        *   **Self Vector:** Concatenate $[Z_i, E_{fb, i}]$.
        *   **Partner Vector:** Gather $[Z_j, E_{fb, j}]$ (Cite solution_lesson_node_00031). This propagates the dynamic feedback through structural connections (Cite solution_lesson_node_00105).
    *   **Null-Masking:** Apply **Zero-Mask** to gathered vectors for unpaired bases (Cite solution_lesson_node_00071).
    *   **Fusion:** Concatenate Self and Partner vectors (Cite solution_lesson_node_00066).
    *   **Global Aggregation:** Process with a **Bidirectional GRU** (Cite solution_lesson_node_00003) feeding directly from the fusion layer (Cite solution_lesson_node_00077).
    *   **Output:** Linear projection to targets.

# Data

1.  **Preprocessing:**
    *   **Explicit Cache Invalidation:** Use a new cache key (e.g., `train_data_ddf_rn_v1.npz`) to ensure input features (especially Partner Identity) are generated correctly (Cite solution_lesson_node_00032).
    *   **Feature Generation:** Generate One-Hot encodings, Partner Identity, and Partner Index Map.
    *   **Target Parsing:** Parse stringified targets to numerical arrays.

2.  **Loaders:**
    *   Yield Augmented Input, Partner Index Map, and Targets.

# Training

1.  **Iterative Refinement Loop:**
    *   **Step 1 (Static):** Compute $Z$ from static inputs once.
    *   **Step 2 (Recycling):** Initialize $\hat{Y}_0 = 0$.
    *   **Pass 1:**
        *   Compute $E_{fb, 0}$ from $\hat{Y}_0$ using the **Decoupled Dense Feedback Module**.
        *   Run Interaction + RNN using $Z$ and $E_{fb, 0}$. Output $\hat{Y}_1$.
    *   **Pass 2:**
        *   Detach Gradients: $R = \hat{Y}_1.detach()$ (Cite solution_lesson_node_00078).
        *   Compute $E_{fb, 1}$ from $R$ using the **Decoupled Dense Feedback Module**.
        *   Run Interaction + RNN using $Z$ and $E_{fb, 1}$. Output $\hat{Y}_2$.

2.  **Loss Function:**
    *   $L_{total} = \text{MCRMSE}(\hat{Y}_2) + 0.5 \times \text{MCRMSE}(\hat{Y}_1)$.
    *   **Strict Masking:** Calculate loss **only on the three scored columns** (`reactivity`, `deg_Mg_pH10`, `deg_Mg_50C`) and **only on valid sequence positions** (0-67) to prevent metric inflation (Cite solution_lesson_node_00016, solution_lesson_node_00109).

3.  **Optimizer:**
    *   **AdamW** (lr=1e-3) with `ReduceLROnPlateau`.

# Evaluation

1.  **Inference:**
    *   Compute Backbone features $Z$ once.
    *   Run Pass 1 (Zero Feedback) $\to \hat{Y}_1$.
    *   Run Pass 2 (Feedback = Masked $\hat{Y}_1$) $\to \hat{Y}_2$.
    *   Submit $\hat{Y}_2$.

2.  **Metric:**
    *   Use **Correct Global RMSE**. Accumulate SSE and counts across the entire validation set before computing the square root to avoid batch-averaging bias (Cite solution_lesson_node_00020).
