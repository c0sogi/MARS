Based on the progression of insights from the provided lessons, I propose the **Staged Interactive Dense Network**. This strategy structurally evolves the "Latent-Refined" paradigm by interleaving the structural interaction within the convolutional backbone. This allows the model to explicitly learn higher-order physical interactions (like base-pair stacking) in the latent space, addressing the limitations of input-level "Partner Triplets" while maintaining the efficiency of the "Latent Gather" mechanism.

# Model

1.  **Input Representation (Parsimonious Encoding):**
    *   **One-Hot Encoding:** We utilize **One-Hot Encoding** for `sequence`, `structure`, and `predicted_loop_type` (Cite solution_lesson_node_00010).
    *   **Removal of Static Partner Identity:** We explicitly **remove** the static "Partner Base Identity" feature from the input. As established in **Lesson 00031**, the dynamic gathering of learned features is superior to static injection. Furthermore, removing this redundant input reduces dimensionality and adheres to the principle of parsimony (Cite solution_lesson_node_00023).

2.  **Backbone (Staged Dense Dilated TCN):**
    *   We split the feature extraction into two distinct stages to enable **Recursive Contextualization**:
    *   **Stage 1 (Local Context):** A stack of **Single-Layer Dilated Residual Blocks** (Cite solution_lesson_node_00011) with **Dense Connections** (concatenating outputs of all prior blocks). This stage learns local sequence and structure motifs. We ensure a robust channel width (e.g., 64 filters) to avoid the capacity bottleneck observed in Idea 9 (Cite solution_lesson_node_00037).
    *   **Inter-Stage Latent Interaction:** We insert the **Latent Structural Refinement** module here. For every position $i$, we gather the Stage 1 output vector of its paired partner $j$ and concatenate it to $i$.
        *   *Innovation:* By placing this *between* convolutional stages, we allow the subsequent layers to process the **"Pair State"**.
    *   **Stage 2 (Stacking/Pair Context):** A second stack of Dense Dilated Residual Blocks processes the fused features.
        *   *Rationale:* Since the input to this stage contains information about the partner, the convolutions here can detect interactions between *neighboring pairs* (e.g., the stacking energy between base pair $i-j$ and base pair $(i+1)-(j-1)$). This effectively reconstructs the physics targeted by "Partner Triplets" (Idea 6) but does so using dense, learned representations rather than sparse, static inputs (addressing solution_lesson_node_00023).
    *   **Regularization:** We strictly apply **Dropout** (e.g., 0.1) within all blocks to manage the high connectivity of the Dense architecture (Cite solution_lesson_node_00038). We use **Standard Convolutions** throughout (Cite solution_lesson_node_00018).

3.  **Global Aggregation (BiGRU):**
    *   The Stage 2 output is processed by a **Bidirectional GRU (BiGRU)** to capture global sequence constraints (Cite solution_lesson_node_00003).
    *   **Constraint:** The hidden size is set to `input_dim // 2` (Cite solution_lesson_node_00004).

4.  **Output Head:**
    *   A linear projection maps the BiGRU output to the 5 target variables.

# Data

1.  **Preprocessing & Cache Safety:**
    *   **Explicit Cache Invalidation:** To ensure the removal of the static Partner Identity feature is effective, we will force the data loader to ignore existing cache files or use a new cache key (Cite solution_lesson_node_00032).
    *   **Feature Generation:** Generate One-Hot encodings and the **Partner Index Map** (required for the inter-stage gather operation).
    *   **Target Parsing:** Parse stringified targets in `train.csv` to numerical arrays.

2.  **Loaders:**
    *   Data loaders will yield the Parsimonious Input Tensor (Seq/Struct/Loop only), the Partner Index Map, and the Target Tensor.

# Training

1.  **Loss Function (Masked Optimization):**
    *   Use **MCRMSE** (Mean Columnwise Root Mean Squared Error).
    *   **Strategy:** Calculate loss **only on the three scored columns** (`reactivity`, `deg_Mg_pH10`, `deg_Mg_50C`).
    *   **Rationale:** We adhere to **Lesson 00016**, masking out auxiliary targets to prevent negative transfer and align the objective with the competition metric.

2.  **Optimizer:**
    *   Use **AdamW** with a learning rate of 1e-3 and a `ReduceLROnPlateau` scheduler.
