Based on the lessons learned from previous experiments, particularly the superior performance of simple models on the full dataset (Idea 3) compared to complex models on subsets (Idea 4), and the critical need for calibrated thresholding (Lesson 00006), I propose the following optimized strategy.

This strategy evolves the **Wide-and-Deep** concept (Idea 6) by upgrading the "Deep" component from a simple averaging network to a **Multi-Scale Convolutional Neural Network (TextCNN)**. This structural innovation captures local sequential patterns (phrases) that averaging misses, while remaining computationally efficient enough to train on the full dataset, unlike Transformers.

# Model
I propose a **Hybrid Wide-and-Deep Network with Multi-Scale CNN**. This architecture processes the input text through two parallel pathways to capture both exact keyword matches and local semantic context.

1.  **Wide Component (Lexical Exactness):**
    *   **Input:** Sparse **TF-IDF vectors** (unigrams and bigrams). This component explicitly exploits the finding that high-coverage lexical matching is superior for this task **Cite {solution_lesson_node_00007}**. It ensures that specific technical keywords (e.g., "NullPointerException", "ggplot2") map directly to tags without dilution.
    *   **Layer:** A single fully connected linear layer mapping the TF-IDF dimension (e.g., 100,000) to the output tag dimension.

2.  **Deep Component (Local Semantics):**
    *   **Input:** Integer token sequences (padded/truncated).
    *   **Architecture:** A **TextCNN** backbone.
        *   **Embedding Layer:** Maps tokens to dense vectors.
        *   **Multi-Scale Convolutions:** Applies parallel 1D Convolutional layers with varying kernel sizes (e.g., 3, 4, and 5). This allows the model to learn optimal n-gram detectors (phrases) dynamically, offering a neural evolution of the fixed bigrams used in the MNB baseline.
        *   **Global Max Pooling:** Extracts the most salient features from each convolution map.
        *   **Projection:** Concatenated pooled features are passed through a Dense layer with ReLU activation.
    *   **Rationale:** This replaces the "Averaging" mechanism of previous baselines. It captures local word order (e.g., "not working" vs "working") while being significantly faster than Transformers, enabling full-dataset training **Cite {solution_lesson_node_00007}**.

3.  **Fusion & Output:**
    *   The logits from the Wide and Deep paths are summed.
    *   **Activation:** A **Sigmoid** function is applied to the final sum. This ensures predictions are bounded probabilities in $[0, 1]$, directly addressing the issue of unbounded scores that caused the failure of the Naive Bayes approach **Cite {solution_lesson_node_00006}**.

# Data
1.  **Full Dataset Utilization:** The model will be trained on the **entire 4.3M sample training set**. We will strictly avoid subsampling, prioritizing data coverage over model complexity **Cite {solution_lesson_node_00007}**.
2.  **Dual Preprocessing:**
    *   **Wide Stream:** Concatenate Title and Body, clean HTML, and compute TF-IDF features (top 100,000 unigrams/bigrams).
    *   **Deep Stream:** Tokenize text using a vocabulary of the top 50,000 words. Pad sequences to a fixed length (e.g., 150 tokens) to capture the most informative initial content.
3.  **Targets:** Encode the top 5,000 most frequent tags as Multi-Hot binary vectors.

# Training
1.  **Loss Function:** Implement **Focal Loss**. Standard Binary Cross Entropy fails due to the extreme class imbalance (sparsity) of the target vectors. Focal Loss will dynamically down-weight easy negatives and focus learning on hard, misclassified examples **Cite {solution_lesson_node_00007}**.
2.  **Optimizer:** Use **AdamW** with a linear learning rate warmup.
3.  **Efficiency:** Utilize **Mixed Precision (FP16)** training to handle the memory footprint of the Wide (sparse) and Deep (dense) components simultaneously on the A100 GPU.

# Evaluation
1.  **Inference:** Generate probability scores for the validation set.
2.  **Adaptive Thresholding:** Instead of a fixed search range, calculate the **percentiles** of the predicted probabilities on the validation set. Dynamically define the threshold search range based on these statistics (e.g., searching between the 95th and 99.9th percentiles) to ensure the decision boundary adapts to the model's confidence distribution **Cite {solution_lesson_node_00006}**.
