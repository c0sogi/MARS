Based on the dataset analysis and the need for a highly efficient, distinct baseline, I propose the **Nearest Centroid Classifier (NCC)**.

This approach differs fundamentally from the discriminative models (SVM, LightGBM), deep neural networks (DAN, CNN, Transformers), and instance-based methods (k-NN) previously suggested. It relies on a geometric prototype-based learning strategy, which is computationally inexpensive and highly interpretable.

### Model
The core architecture is a **Nearest Centroid Classifier**. Instead of learning complex decision boundaries or training distinct classifiers for each tag, this model represents each target tag as a single "prototype" or "centroid" vector in the feature space.
*   **Tag Prototypes**: Each tag $t$ is defined by a vector $\vec{c}_t$, which is the arithmetic mean (centroid) of the vectors of all training questions associated with that tag.
*   **Inference Mechanism**: The relevance of a tag to a new question is determined by the **Cosine Similarity** between the question's vector and the tag's centroid. This assumes that questions sharing the same tag cluster around a central mean in the high-dimensional text space.

### Data
1.  **Text Preprocessing**:
    *   Concatenate the `Title` and `Body` columns to form the input text.
    *   Strip HTML tags and remove non-alphanumeric characters to reduce noise.
2.  **Vectorization**:
    *   Apply **TF-IDF (Term Frequency-Inverse Document Frequency)** vectorization to convert text into sparse numerical vectors.
    *   Use a vocabulary of the top $N$ (e.g., 100,000) features, including unigrams and bigrams, to capture technical terminology (e.g., "visual studio").
    *   Apply L2 normalization to the document vectors to facilitate cosine similarity computation.
3.  **Target Selection**:
    *   To maintain high efficiency and relevance, restrict the output space to the top $K$ (e.g., 5,000) most frequent tags. This covers the majority of the dataset while keeping the centroid matrix size manageable.

### Training
1.  **Centroid Computation**:
    *   Unlike gradient-based methods (SGD), this training phase is non-iterative and requires only a single pass over the data.
    *   Compute the Centroid Matrix $C$ of shape $(K, N)$, where $K$ is the number of tags and $N$ is the vocabulary size.
    *   This is efficiently implemented as a sparse matrix multiplication: $C_{raw} = Y^T X$, where $Y$ is the binary label matrix and $X$ is the TF-IDF feature matrix.
    *   Normalize each row in $C_{raw}$ (dividing by the tag frequency or applying L2 normalization) to obtain the final unit-length prototypes.

### Evaluation
1.  **Similarity Calculation**:
    *   Transform the test set using the fitted TF-IDF vectorizer to obtain $X_{test}$.
    *   Compute the similarity score matrix $S$ via a dense matrix multiplication: $S = X_{test} C^T$. This yields a cosine similarity score for every tag for every test question.
2.  **Prediction**:
    *   **Thresholding**: Apply a probability threshold (tuned on the validation set) to the similarity scores. If $S_{ij} > \text{threshold}$, predict tag $j$ for question $i$.
    *   **Formatting**: Map the indices of the predicted tags back to their string representations and join them with spaces for the final submission.
