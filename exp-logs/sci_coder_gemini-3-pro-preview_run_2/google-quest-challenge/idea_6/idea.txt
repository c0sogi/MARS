# Proposed Strategy: Granular Siamese DeBERTa with Metadata Fusion

Based on the accumulated lessons, I propose a **Granular Siamese DeBERTa** architecture that integrates **Segment-Aware Pooling** and **Metadata Fusion**. This strategy evolves the previous "Unified Context" approach (Idea 4) by resolving the information dilution caused by pooling the entire Question (Title + Body) into a single vector, and by incorporating previously unused categorical signals.

## Model

**Backbone:** We will utilize **DeBERTa-v3-base** as the shared encoder. Its disentangled attention mechanism is critical for capturing the subjective nuances of the targets (Cite solution_lesson_node_00018).

**Architecture:** We retain the **Siamese Bi-Encoder** structure to process the Question and Answer in separate streams. This ensures that both the Question and the Answer have access to their full 512-token context windows, avoiding the truncation issues inherent in Cross-Encoders (Cite solution_lesson_node_00027).

**Segment-Aware Granular Pooling (Structural Innovation):**
Instead of reducing the Question stream to a single global mean ($u_{total}$), we will implement **Segment-Aware Mean Pooling**.
1.  **Question Stream:** Input `[CLS] Title [SEP] Body [SEP]`. Using the position of the separator tokens, we will generate two distinct embeddings:
    *   $u_{title}$: Mean pool of tokens belonging to the `question_title`.
    *   $u_{body}$: Mean pool of tokens belonging to the `question_body`.
    *   This preserves the distinct semantic signal of the Title (often the core intent) from being washed out by the much longer Body (Cite solution_lesson_node_00004).
2.  **Answer Stream:** Input `[CLS] Answer [SEP]`. We generate $v_{answer}$ via standard Mean Pooling.

**Granular Interaction Layer:**
We will compute explicit interaction features (Cite solution_lesson_node_00005) at two levels of granularity:
1.  **Title-Answer Interaction:** $[u_{title}, v_{answer}, |u_{title} - v_{answer}|, u_{title} \cdot v_{answer}]$
2.  **Body-Answer Interaction:** $[u_{body}, v_{answer}, |u_{body} - v_{answer}|, u_{body} \cdot v_{answer}]$

**Metadata Fusion:**
We will introduce a third input modality by learning low-dimensional embeddings for the `category` and `host` features. These embeddings will be concatenated with the text interaction vectors.

**Unified Prediction Head:**
All features (Title-Interactions, Body-Interactions, and Metadata Embeddings) will be concatenated into a single dense vector and fed into a **Non-Linear MLP** (Linear -> LayerNorm -> GELU -> Dropout -> Linear) to predict all 30 targets simultaneously. This retains the "Contextual Entanglement" benefit where Answer quality informs Question predictions (Cite solution_lesson_node_00011) and leverages the superior modeling capacity of MLPs (Cite solution_lesson_node_00022).

## Data

1.  **Tokenization:** Use the `microsoft/deberta-v3-base` tokenizer.
2.  **Input Formatting:**
    *   **Stream 1 (Question):** `[CLS] Title [SEP] Body [SEP]`. Max length 512.
    *   **Stream 2 (Answer):** `[CLS] Answer [SEP]`. Max length 512.
    *   **Stream 3 (Metadata):** Integer indices for `category` and `host`.
3.  **Mask Generation:** During preprocessing, generate auxiliary binary masks for Stream 1 that identify which token indices correspond to the Title and which to the Body. This enables the Segment-Aware Pooling operation.

## Training

1.  **Strategy:** Perform **Full Fine-Tuning** of the backbone (Cite solution_lesson_node_00008).
2.  **Optimization:** Use AdamW with **Differential Learning Rates**:
    *   Backbone: 1e-5.
    *   MLP Head / Embeddings: 1e-4.
3.  **Schedule:** Train for **6 to 8 epochs**. The increased complexity of the granular interaction features requires an extended schedule to converge compared to simple baselines (Cite solution_lesson_node_00015).
4.  **Checkpointing:** Save the model state with the highest **Mean Column-wise Spearman's Correlation** on the validation set. Explicitly use `copy.deepcopy(model.state_dict())` to ensure the weights are correctly snapshotted (Cite solution_lesson_node_00001).
5.  **Early Stopping:** Monitor the Spearman metric (not Loss) to prevent overfitting (Cite solution_lesson_node_00007).

## Evaluation

1.  **Inference:** Process the test set using the Siamese network with Segment-Aware Pooling.
2.  **Prediction:** The Unified MLP head will output the 30 probability values directly.
3.  **Submission:** Format the predictions into the required CSV structure.
