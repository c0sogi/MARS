Based on the lessons learned, I propose a structural evolution that transitions from learning embeddings from scratch (which struggles with vocabulary coverage on small datasets) to a **Transfer Learning** approach using a pre-trained Transformer backbone. This strategy addresses the high variance and overfitting observed in complex sequence models trained from scratch (Lesson 00002) while integrating the successful interaction modeling components (Lesson 00005).

# Model
**Architecture: Siamese DistilRoBERTa with Explicit Interaction Head**
1.  **Backbone (Siamese Encoder):** Replace the learnable embedding layer with a pre-trained **DistilRoBERTa** model. This model will process the *Question* and *Answer* text streams independently but share the same weights (Siamese configuration). This leverages robust, pre-learned linguistic features, avoiding the "cold start" problem of learning a 23k vocabulary from only 4,000 samples.
2.  **Pooling Strategy:** Apply **Mean Pooling** to the token embeddings of the last hidden layer for both the Question and Answer streams. This generates fixed-size representations ($u$ and $v$). We explicitly choose parameter-free Mean Pooling over learnable Attention Pooling or CLS tokens to minimize overfitting, as established in **Cite Lesson 00004**.
3.  **Interaction Fusion Layer:** Construct a combined feature vector by concatenating the pooled representations with their explicit interactions: $[u, v, |u - v|, u \cdot v]$. This preserves the highly effective inductive biases for semantic distance and alignment identified in **Cite Lesson 00005**.
4.  **Classification Head:** A Multi-Layer Perceptron (MLP) with Dropout and Batch Normalization maps the fused vector to the 30 target probabilities.

# Data
1.  **Tokenization:** Use the pre-trained DistilRoBERTa tokenizer. This handles subword tokenization automatically, resolving the vocabulary coverage issues inherent in the previous whitespace-based approach.
2.  **Input Formatting:**
    - Stream 1: `question_title` + ` [SEP] ` + `question_body`
    - Stream 2: `answer`
    - Truncate sequences to a maximum length (e.g., 512 tokens) to fit GPU memory constraints.
3.  **Evaluation Data:** Preprocess the test set identically to the training set.

# Training
1.  **Strategy:** Implement a **Fine-Tuning** workflow.
    - Use **Binary Cross Entropy (BCE)** as the loss function.
    - Apply **Differential Learning Rates**: Use a lower learning rate (e.g., 2e-5) for the Transformer backbone to preserve pre-trained knowledge, and a higher learning rate (e.g., 1e-3) for the Interaction Head.
2.  **Early Stopping & Checkpointing:**
    - Monitor **Mean Column-wise Spearman's Correlation** on the validation set for early stopping, rather than the loss. This addresses the divergence between the proxy loss and the ranking metric observed in **Cite Lesson 00002**.
    - When saving the best model, use `copy.deepcopy(model.state_dict())` to ensure the weights are physically snapshotted and not just referenced, preventing the "State Dict Reference" trap identified in **Cite Lesson 00001**.
3.  **Regularization:** Apply weight decay (AdamW optimizer) and Dropout within the MLP head to mitigate overfitting on the small dataset.

# Evaluation
1.  **Inference:** Pass the tokenized test set through the trained Siamese network.
2.  **Prediction:** The model outputs 30 probabilities per row. Ensure these are detached from the computation graph and moved to CPU for submission file generation.
3.  **Validation:** Compute the Spearman correlation on the validation split to confirm the model's ranking performance before submission.
