### **Idea 3: k-Nearest Neighbors (k-NN) Classification with Deterministic Formatting**

This approach utilizes **Model 4 (Retrieval-Augmented Classification)** as its conceptual foundation. It is strictly distinct from the generative Deep Learning approach (Idea 1) and the Feature-Based Boosting approach (Idea 2). It prioritizes simplicity and speed by adopting a "lazy learning" paradigm that relies on memory rather than iterative training.

#### **Model**
*   **Architecture**: The system consists of a **Retrieval-Based Classifier** coupled with a **Rule-Based Normalizer**.
    *   **Encoder**: A pre-trained, static embedding model (specifically **FastText**) is used to generate dense vector representations. FastText is chosen over GloVe/Word2Vec because its subword information (character n-grams) effectively captures the orthographic features crucial for normalization (e.g., recognizing that "1st" and "2nd" are similar). The final query vector is a concatenation of the target token's embedding and the average embedding of its immediate context window (previous and next tokens).
    *   **Classifier**: A **k-Nearest Neighbors (k-NN)** classifier backed by a highly optimized similarity search index (e.g., **FAISS**). Instead of learning a decision boundary via gradient descent, the model classifies a test token by retrieving the $k$ most similar tokens from the training set and performing a weighted majority vote on their semiotic classes (e.g., `DATE`, `MONEY`, `PLAIN`).
    *   **Normalizer**: A set of deterministic, logic-based functions mapped to each semiotic class. Once the class is predicted, the raw text is passed to the corresponding function (e.g., a `DATE` class triggers a date parser/formatter; a `CARDINAL` class triggers a number-to-words converter).

#### **Data**
*   **Preprocessing**:
    1.  **Filtering**: The training set is filtered to downsample the majority `PLAIN` class (which constitutes ~93% of data). We retain only a small representative fraction of `PLAIN` tokens, while keeping 100% of the "interesting" classes (e.g., `DATE`, `CARDINAL`, `MEASURE`). This keeps the index size manageable and efficient.
    2.  **Vectorization**: For every remaining token in the training set, we compute the context-aware FastText embedding vector.
    3.  **Storage**: The vectors are stored in the index, associated with their ground-truth `class` label.
*   **Balancing**: The downsampling step acts as a manual class balancing technique, preventing the k-NN from being overwhelmed by the high frequency of `PLAIN` neighbors.

#### **Training**
*   **Procedure**: This approach requires **no iterative training** (no epochs, no backpropagation). "Training" consists solely of:
    1.  Loading the pre-trained FastText model.
    2.  Computing vectors for the filtered training dataset.
    3.  Building and saving the FAISS index (using L2 distance or Cosine similarity).
*   **Optimization**: The only hyperparameters to tune are $k$ (the number of neighbors, e.g., 5 or 10) and the distance metric, which can be selected based on a quick evaluation of the validation set.

#### **Evaluation**
*   **Inference**:
    1.  **Embed**: For each token in the test set, generate its query vector using the FastText encoder and its local context.
    2.  **Retrieve**: Query the FAISS index to find the nearest $k$ neighbors.
    3.  **Vote**: Determine the predicted semiotic class via weighted majority voting (closer neighbors get higher weight).
    4.  **Normalize**:
        *   If the predicted class is `PLAIN` or `PUNCT`, output the raw token (Copy).
        *   Otherwise, pass the raw token to the specific formatting function for that class (e.g., `format_money("$3.50")` $\rightarrow$ "three dollars, fifty cents") to generate the final string.
