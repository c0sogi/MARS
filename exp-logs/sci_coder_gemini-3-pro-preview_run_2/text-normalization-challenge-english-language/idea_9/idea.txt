Based on the progression of experiments and the specific lessons learned, I propose the **Context-Enhanced Hybrid Router-Generator**. This strategy is a structural evolution of the Hybrid Router (Idea 7), explicitly addressing the context-blindness of the previous neural generator while maintaining the safety of deterministic rules.

### Model
The architecture is a two-stage pipeline that strictly adheres to the principle of **decoupling classification from generation** Cite {solution_lesson_node_00006}, while implementing the **Hybrid Router** design Cite {solution_lesson_node_00017}.

1.  **The Router (Contextual Classifier)**:
    *   **Backbone**: **DeBERTa-v3-base**. We upgrade the backbone from RoBERTa (used in Idea 7) to DeBERTa-v3. Its disentangled attention mechanism provides superior capability in resolving the subtle positional dependencies required for text normalization (e.g., distinguishing a year from a cardinal number based on surrounding words).
    *   **Function**: This model operates as a sequence labeler, predicting the semantic `class` (e.g., `DATE`, `PLAIN`, `ADDRESS`) for every token in the sentence.

2.  **The Refiners (Dual-Path Execution)**:
    *   **Path A: Deterministic Rule Engine (Rigid Classes)**: Tokens classified as `PLAIN`, `PUNCT`, `CARDINAL`, `ORDINAL`, `DIGIT`, or `LETTERS` are routed to a registry of deterministic Python functions. These classes follow strict, algorithmic rules where neural hallucination is unacceptable.
    *   **Path B: Context-Aware Neural Generator (Ambiguous Classes)**: Tokens classified as `DATE`, `TIME`, `MEASURE`, `ADDRESS`, `TELEPHONE`, `ELECTRONIC`, `VERBATIM`, or `MONEY` are routed to a **ByT5-small** Sequence-to-Sequence model.
    *   **Structural Innovation**: Unlike the previous generator (Idea 7) which processed tokens in isolation (e.g., `[DATE] 12`), this generator receives a **Context-Augmented Input**. The input string includes the predicted class tag, the immediate left context, the target token, and the right context (e.g., `[DATE] ... Jan [ 12 ] 2022 ...`). This allows the model to resolve intra-class ambiguities (like "12" becoming "twelfth" due to the preceding "Jan") that the isolated generator failed to capture.

### Data
1.  **Router Dataset (Strategic Sampling)**:
    *   We construct a training set that retains 100% of sentences containing at least one non-`PLAIN` token.
    *   For the majority `PLAIN` class, we apply **Hard-Negative Mining**: we keep `PLAIN` sentences that contain digits, capitalization, or symbols (distractors), while aggressively downsampling trivial lowercase sentences. This focuses the Router's capacity on the decision boundary.
    *   We use the ground-truth `class` labels provided in the dataset, explicitly avoiding **Inverse Label Engineering** Cite {solution_lesson_node_00014} to prevent data corruption from incomplete rule sets.

2.  **Generator Dataset (Contextual Windowing)**:
    *   We filter the training data to include *only* tokens belonging to the "Path B" (Ambiguous) classes.
    *   **Input Formatting**: We format the source text to include a window of $\pm 3$ tokens around the target, using special sentinel tokens to mark the target boundaries (e.g., `[CLASS] left_ctx <extra_id_0> target <extra_id_1> right_ctx`).
    *   **Target**: The ground-truth normalized text (`after` column).

### Training
1.  **Stage 1: Router Training**:
    *   Fine-tune the DeBERTa-v3 model on the Router Dataset using Cross-Entropy Loss.
    *   Use a linear learning rate decay and early stopping based on validation accuracy.

2.  **Stage 2: Generator Training**:
    *   Train the ByT5-small model on the Generator Dataset using standard Seq2Seq Cross-Entropy Loss with Teacher Forcing.
    *   Because the "Path B" classes constitute a small fraction of the total dataset (<5%), this model will train rapidly despite being generative.

### Evaluation
1.  **Classify**: Pass the test sentences through the **Router** (DeBERTa-v3) to obtain the predicted semantic class for every token.
2.  **Route and Refine**:
    *   **If Class $\in$ Path A**: Pass the raw token to the corresponding Python function (e.g., `cardinal_to_words`) to generate the output.
    *   **If Class $\in$ Path B**: Construct the context-augmented input string (using the sentence context from the test file) and pass it to the **Generator** (ByT5). Decode the output greedily.
    *   **If Class $\in$ Copy**: Directly copy the `before` text.
3.  **Submission**: Concatenate the resulting strings to form the final submission. This strategy leverages the robustness of the **Hybrid Router** Cite {solution_lesson_node_00017} while fixing the context-blindness of the previous neural component.
