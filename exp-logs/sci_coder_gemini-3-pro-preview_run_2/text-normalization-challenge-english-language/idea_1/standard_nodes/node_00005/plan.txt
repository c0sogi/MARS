The previous execution failed with a `torch.OutOfMemoryError` because the GPU memory was still occupied by "zombie" tensors from a prior crashed run in the persistent environment. As explained in **debug_lesson_3**, the Python interpreter stores stack traces of unhandled exceptions in `sys.last_traceback`, which keeps references to local variables (including models and tensors) alive, preventing garbage collection. Additionally, **debug_lesson_2** notes that simply restarting the script is insufficient; explicit cleanup is required.
