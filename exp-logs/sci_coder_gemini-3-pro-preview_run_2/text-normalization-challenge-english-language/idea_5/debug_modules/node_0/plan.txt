The implementation strategy involves creating a self-contained script that orchestrates the text normalization pipeline using the provided library modules. 

1.  **Configuration & Setup**: We will first modify the `Config` class attributes to enable a "Debug" mode. This sets the batch sizes to be small, limits the number of epochs to 1, and redirects output files to a dedicated `./working/demo_run` directory. This ensures the script runs quickly and does not interfere with existing files.
2.  **Normalization Rule Verification**: We will explicitly test the `normalize_token` function from `library.normalization_rules` with specific test cases (e.g., converting "$3.50" to "three dollars, fifty cents") to verify the rule-based logic is functioning correctly.
3.  **Data Loading & Preparation**: Instead of processing the entire 7-million-row training set (which would be slow), we will load the smaller validation set using `library.dataset.load_data` with `debug=True`. We will then split this small subset into training and validation dataframes. We will also load a subset of the test data.
4.  **Dataset & Tokenizer**: We will initialize the tokenizer and create instances of `TextNormalizationDataset` for our created data splits. We will assert that the dataset yields tensors of the correct shape.
5.  **Model Initialization**: We will instantiate the `TransformerCRF` model and perform a dummy forward pass on CPU to ensure the architecture (Transformer + CRF) is correctly assembled and can compute loss.
6.  **Training & Inference Execution**: We will use the `library.engine` module to run the `fit` function (training loop) and then the `predict` function (inference). This demonstrates the end-to-end workflow.
7.  **Output Verification**: Finally, we will verify that the submission file has been created and follows the expected format.
