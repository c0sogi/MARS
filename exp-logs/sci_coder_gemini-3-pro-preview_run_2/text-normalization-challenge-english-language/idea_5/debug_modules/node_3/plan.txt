The execution failure in `runfile.py` is caused by a grammatical inaccuracy in the `_num2words` function within `library/normalization_rules.py`. The function currently concatenates the "tens" and "ones" parts of a number (e.g., 23) using a space ("twenty three"), whereas standard English grammar and the validation tests require a hyphen ("twenty-three"). This discrepancy triggers an `AssertionError` during the verification step (Cite debug_lesson_3).

To fix this:
1.  I will modify `_num2words` to use a hyphen instead of a space when joining tens and ones.
2.  I will also update the `_ordinal2words` function in the same file. Since it relies on `_num2words` to generate the base text before converting the last word to an ordinal, it must now be able to handle and preserve the hyphen in compound numbers (e.g., converting "twenty-one" to "twenty-first" instead of "twenty-oneth").
