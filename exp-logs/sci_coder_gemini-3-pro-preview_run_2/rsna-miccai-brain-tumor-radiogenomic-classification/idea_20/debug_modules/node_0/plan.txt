This implementation strategy focuses on demonstrating the complete pipeline—from data loading and model initialization to training and inference—while overriding configuration parameters to ensure rapid execution.

1.  **Configuration Override**: We will modify the `Config` class attributes at runtime to direct outputs to a specific demo directory (`./working/demo_run`), reduce the number of epochs to 1, and set a small batch size. This ensures the script runs quickly and doesn't overwrite any production work.
2.  **Data Loading Verification**: We will call `get_dataloaders` to initialize the data pipeline. We will explicitly fetch a single batch from the training loader to verify the tensor shapes (`[Batch, 12, 224, 224]`) and label integrity, ensuring the custom `MGMTDataset` and `read_dicom_robust` logic functions correctly.
3.  **Model Instantiation & Check**: We will initialize the `AsymmetricEfficientNet` and perform a dummy forward pass with random data. This verifies that the custom input stem (handling 12 channels) and the classifier head are structurally correct and compatible with the compute device.
4.  **Training Loop Execution**: We will run `train_one_epoch` and `validate` for a single epoch. This demonstrates the integration of the optimizer, loss function, and logging utilities. We will assert that the loss is a valid number.
5.  **Inference & Submission**: We will save the model state from the short training run and call `generate_submission`. We will then verify that the output CSV exists and contains the required columns (`BraTS21ID`, `MGMT_value`), confirming the Test-Time Augmentation (TTA) and post-processing logic.
