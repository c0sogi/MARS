The implementation strategy is as follows:

1.  **Setup and Configuration**: We start by setting reproducible seeds and overriding specific `Config` parameters to ensure the run completes quickly (Fast Baseline). We reduce the number of epochs to 10, which is sufficient given the small dataset size (approx. 400 training samples) and the powerful A100 GPU.
2.  **Data Loading**: We utilize the provided `get_dataloaders` function to load the training, validation, and test sets. We enable `load_cached_data=True` to leverage any pre-computed ROI caches.
3.  **Training Loop**: We instantiate the provided `Trainer` class but orchestrate the training loop manually in `runfile.py` instead of using `trainer.run()`. This allows us to control the flow, capture the best validation metrics, and implement the specific conditional logic required.
    *   We iterate through epochs, performing training and validation steps.
    *   We track the best AUC and save the model state when a new best is achieved.
4.  **Final Evaluation**: After training, we reload the best model weights. We perform a final inference pass on the validation set to compute the `Final Validation Metric`.
5.  **Failure Analysis**: We calculate the absolute error for each validation sample. We then extract a metadata feature (the number of FLAIR slices, representing scan depth) for each validation subject by inspecting the file system. We compute and print the correlation between the model's error and this structural feature to identify if scan depth impacts performance.
6.  **Conditional Submission**: We check if the final validation AUC exceeds the strict threshold of `0.6254545454545455`. If it does, we generate predictions for the test set using the `trainer.generate_submission` method.
