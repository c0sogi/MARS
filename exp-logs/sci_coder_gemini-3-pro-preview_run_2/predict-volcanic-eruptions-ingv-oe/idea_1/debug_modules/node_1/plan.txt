The error occurs because the scaler parameters loaded from disk are in `float64` (double) precision. When these are applied to the `float32` input features during inference (`(X_test - mean) / scale`), NumPy implicitly promotes the resulting array to `float64`. Consequently, `torch.tensor(X_test)` creates a DoubleTensor, causing a type mismatch with the model's FloatTensor (float32) weights during the forward pass. The fix is to explicitly cast the scaled data back to `float32` before creating the tensor.
