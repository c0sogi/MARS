To establish a robust and efficient baseline for the Ventilator Pressure Prediction task, I propose a solution based on the **Stacked Bidirectional LSTM Network** (Model 1), simplified for speed and stability.

### Model
The architecture is designed as a sequence-to-sequence regression model that captures the temporal dynamics of airflow and pressure accumulation.
*   **Input Layer:** Accepts a sequence of shape `(Sequence Length, Feature Dimension)` representing a single breath. The features include control signals and lung attributes.
*   **Recurrent Encoder:** Consists of **two layers of Bidirectional LSTMs**. The bidirectional wrapper allows the network to access context from both past and future time steps within the breath, which is crucial for understanding how pressure builds up and releases relative to the valve control phases.
*   **Projection Head:** A single fully connected (Dense) layer is applied to the hidden states at every time step to map the LSTM output directly to the scalar `pressure` value.

### Data
*   **Reshaping:** The provided data is in a "long" CSV format (one row per time step). This must be reshaped into a 3D tensor of shape `(Number of Breaths, 80, Number of Features)` to be compatible with the LSTM. We assume a fixed sequence length of 80 based on the dataset characteristics.
*   **Feature Engineering:**
    *   **Cumulative Flow (Volume Proxy):** We will generate a new feature `u_in_cumsum` by calculating the cumulative sum of the `u_in` control input. Physically, `u_in` represents flow rate; therefore, its integral approximates the volume of air in the lung, which is highly correlated with pressure.
    *   **Normalization:** Continuous features (`u_in`, `time_step`, `u_in_cumsum`) and lung attributes (`R`, `C`) will be normalized (e.g., using RobustScaler) to ensure stable gradient descent.
*   **Splitting:** We will utilize the generated `train_metadata.csv` and `val_metadata.csv` to load data, ensuring that the train/validation split respects `breath_id` boundaries to prevent data leakage.

### Training
*   **Loss Function:** We will minimize the **Mean Absolute Error (L1 Loss)**. Although the competition metric only evaluates the inspiratory phase (`u_out=0`), we will calculate the loss over the entire breath sequence. This forces the model to learn the complete physical dynamics (inflation and deflation), resulting in more stable hidden state representations.
*   **Optimizer:** We will use the **AdamW** optimizer, which couples the adaptive learning rates of Adam with decoupled weight decay for better regularization.
*   **Scheduler:** A `ReduceLROnPlateau` scheduler will be employed to lower the learning rate if the validation loss stops improving, allowing the model to fine-tune its weights.

### Evaluation
*   **Inference:** The trained model will process the test dataset (loaded via `test_metadata.csv`) in batches.
*   **Formatting:** The model's output, a 3D tensor of predicted pressures, will be flattened to match the original `id` order of the test file.
*   **Submission:** The resulting predictions will be paired with their corresponding `id`s and saved to `submission.csv` in the required format.
