The issue is caused by the "early binding" of default argument values in Python. The `SC_GI_BiLSTM` class constructor in `library/model.py` defines default values using `Config` attributes (e.g., `lstm_hidden_dim=Config.LSTM_HIDDEN_DIM`). These are evaluated once at import time. Although `runfile.py` overrides `Config` for the demo execution, and explicitly trains a smaller model (128 hidden units vs 512), the inference function in `library/inference.py` instantiates `SC_GI_BiLSTM()` without arguments. This causes it to revert to the original import-time defaults (512 hidden units), creating a model architecture that mismatches the saved checkpoint.

To fix this, I will:
1.  Modify `library/model.py` to use `None` as the default value for configuration-dependent arguments and resolve them inside `__init__`. This forces the class to look up the current `Config` values at runtime (Cite debug_lesson_1).
2.  Update `runfile.py` to explicitly overwrite the architecture-related attributes in `Config` (`LSTM_HIDDEN_DIM`, `PROJECTION_DIM`, `LSTM_LAYERS`) to match the parameters used in the demo training. This ensures that when the inference function resolves the defaults, it gets the correct "demo" architecture.
