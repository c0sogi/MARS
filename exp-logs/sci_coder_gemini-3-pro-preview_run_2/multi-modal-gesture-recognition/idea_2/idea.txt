Based on the lessons learned from the Bi-LSTM baseline, I propose evolving the solution to a **Multi-Stage Temporal Convolutional Network (MS-TCN)**. This architecture is specifically designed for temporal action segmentation and addresses the "jitter" and long-term dependency issues more structurally than a recurrent model.

# Model
**Architecture: Multi-Stage Temporal Convolutional Network (MS-TCN)**
Instead of the recurrent Bi-LSTM, we will implement a feed-forward architecture composed of stacked **Single-Stage TCNs (SS-TCNs)**.
*   **Stage 1 (Prediction Generation):** The first SS-TCN takes the frame-wise feature vector (Skeleton + Audio) as input. It consists of multiple layers of **dilated residual convolutions**. The dilation factors ($1, 2, 4, \dots, 2^N$) increase exponentially, allowing the model to capture a large temporal receptive field (global context) without downsampling resolution. This stage outputs initial frame-wise class probabilities.
*   **Stage 2 (Refinement):** The second SS-TCN takes the *probabilities* from Stage 1 as input. This stage learns to refine the predictions, correcting isolated errors and smoothing the sequence based on the context of neighboring predictions. This structural refinement directly addresses the high-frequency "jitter" observed in previous experiments.

# Data
**Preprocessing:**
*   **Feature Engineering:** We will retain the robust feature set established in previous iterations.
    *   **Skeleton:** Compute 3D joint coordinates relative to the `HipCenter` to ensure translation invariance. Explicitly calculate and concatenate the temporal velocity (first derivative) of these coordinates to capture dynamics (Cite solution_lesson_node_00004).
    *   **Audio:** Extract MFCCs aligned to the video frame rate and concatenate them with the skeleton features.
*   **Augmentation:** During training, inject Gaussian noise into the skeleton and velocity features to prevent overfitting and improve robustness (Cite solution_lesson_node_00006).

**Validation Rigor:**
*   **Deterministic Validation:** The validation dataset must be instantiated with augmentation strictly disabled (`is_train=False`). This ensures that metric fluctuations are due to model changes, not random noise injection, preventing the instability observed in previous runs (Cite solution_lesson_node_00011).

# Training
**Loss Function:**
We will employ a combined loss function to enforce both classification accuracy and temporal smoothness:
*   **Weighted Cross-Entropy Loss:** Applied to the output of *each* stage to classify frames, with higher weights for gesture classes to handle imbalance.
*   **Smoothing Loss (T-MSE):** We will add a Truncated Mean Squared Error loss term applied to the difference between log-probabilities of adjacent frames ($\| \log y_t - \log y_{t-1} \|^2$). This explicitly penalizes rapid flickering during optimization, internalizing the smoothing lesson into the model's objective.

**Strategy:**
*   **Metric Stabilization:** Given the observed volatility of the Levenshtein metric despite loss convergence (Cite solution_lesson_node_00010), we will implement a **moving average** of the validation Levenshtein score (or Stochastic Weight Averaging) to select the best checkpoint, rather than relying on a single noisy epoch.

# Evaluation
**Inference Pipeline:**
1.  **Prediction:** Pass the test sequence through the full MS-TCN. The output of the final refinement stage is used as the prediction.
2.  **Post-Processing:** While the MS-TCN provides smoother outputs naturally, we will apply a lightweight **median filter** as a final safeguard. Crucially, we will use **nearest-neighbor padding** (replicating boundary values) instead of zero-padding to prevent the deletion of valid gestures at the start or end of the sequence (Cite solution_lesson_node_00009).
3.  **Decoding:** Apply greedy decoding (argmax per frame), collapse consecutive repeats, and remove the background class to generate the final gesture list.
