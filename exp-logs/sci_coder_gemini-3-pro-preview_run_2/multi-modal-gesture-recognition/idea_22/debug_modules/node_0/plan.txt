Implementation Strategy:
1.  **Environment Setup**: Initialize the random seeds using `library.utils.set_seed` for reproducibility. Define a temporary working directory within `./working` to store intermediate files (like a mini-dataset CSV and cache) to avoid modifying the main metadata or cache.
2.  **Data Loading Demonstration**:
    *   Load the existing `train.csv` metadata.
    *   Create a subset (mini-batch) of the metadata containing only 4 samples to ensure the script runs quickly.
    *   Save this mini-metadata to the working directory.
    *   Use `library.data_loader.load_data` to process these specific samples from the read-only `./input` directory. This verifies the parsing logic for `.mat` files and audio.
    *   Instantiate `GestureDataset` and `DataLoader` to demonstrate how raw data is converted into tensors (features, targets, boundaries) and collated into batches.
3.  **Model Instantiation and Forward Pass**:
    *   Initialize the `DSG_CRCN` model from `library.model`.
    *   Move the model and the batch of data to the configured device (CPU/GPU).
    *   Perform a forward pass to generate outputs.
    *   Validate the output shapes (classification probabilities, boundary probabilities) using assertions.
4.  **Loss Calculation**:
    *   Instantiate `DeepSupervisionLoss` from `library.loss`.
    *   Compute the loss based on the model outputs and ground truth targets.
    *   Assert that the loss is a valid scalar and requires gradient computation, ensuring the computational graph is intact.
5.  **Utility and Metric Verification**:
    *   Demonstrate the `decode_sequence` function (from `library.train`) which converts frame-wise predictions into a gesture sequence.
    *   Demonstrate the `compute_levenshtein` metric (from `library.utils`) using mock predictions and targets to verify the scoring logic.
6.  **Cleanup**: Remove the temporary directory to leave the environment clean.
