The implementation strategy is as follows:

1.  **Setup & Configuration**: Initialize the environment by setting random seeds for reproducibility. We utilize the provided `library` modules for configuration, data loading, modeling, and training.
2.  **Data Loading**: We load the training, validation, and test datasets using `get_dataloaders`. We use the full dataset (`sample_limit=None`) as the dataset size (~1700 samples) is manageable for the available A100 GPU, ensuring the model has sufficient data to learn.
3.  **Training**: We instantiate the `Trainer` and run the training loop. To adhere to the "fast baseline" requirement, we limit the training to 15 epochs. This allows the RLSG-CN model (which converges relatively quickly due to the pre-processed features and residual connections) to reach a reasonable performance level without exceeding the time limit.
4.  **Validation & Metrics**: After training, we reload the best model checkpoint. We perform a full inference pass on the validation set to compute the `Final Validation Metric` (Levenshtein Error Rate) exactly as required.
5.  **Failure Analysis**: We analyze the validation results by computing the correlation between the error rate (Levenshtein distance) and input characteristics (sequence length and number of gestures). This identifies if the model struggles with longer or more complex sequences.
6.  **Submission**: We check if the validation metric is below the specified threshold (`0.06789606035205364`). If successful, we generate predictions for the test set and ensure the final `submission.csv` is saved in the required `./submission/` directory.
