The issue identified is that the library modules (`data_loader.py`, `model.py`, `train.py`, `inference.py`, `loss.py`) import configuration variables using `from library.config import *` or specific imports like `from library.config import WORKING_DIR`. In Python, these imports copy the values into the local namespace at import time. When `runfile.py` patches `library.config` at runtime (e.g., changing `config.WORKING_DIR` to a demo directory), the other modules continue to use the stale, original values they imported earlier. This causes the inference pipeline to load the full test set instead of the demo subset, leading to an assertion error (Cite debug_lesson_16, debug_lesson_5).

To fix this, I will modify the import statements in all affected files to import the configuration module itself (`import library.config as config`) and access variables via the module object (e.g., `config.WORKING_DIR`). Additionally, I will update function signatures that use configuration values as default arguments (which are evaluated at definition time) to use `None` as the default and assign the configuration value inside the function body (evaluated at runtime).
