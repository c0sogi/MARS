The issue is that `library/data_loader.py` imports configuration variables using `from library.config import *`. This binds the values (like `METADATA_DIR`) to the local namespace at import time. When `runfile.py` subsequently patches `config.METADATA_DIR` to point to the demo subset, `data_loader.py` continues to use the original value ("./metadata"), causing it to load the full test set (95 samples) instead of the demo subset (5 samples). This leads to the assertion failure.

To fix this, I will modify `library/data_loader.py` to import the configuration module directly (`import library.config as config`) and access all configuration variables via the `config` namespace (e.g., `config.METADATA_DIR`). This ensures that the code looks up the current value of these variables at runtime, respecting the patches applied by `runfile.py`. This solution applies **Debug Lesson 5: Import Modules, Not Values, to Enable Runtime Configuration Patching** (Cite debug_lesson_5).
