The issue is that the custom BSON parser blindly attempts to read 4-byte integers (for size prefixes) without verifying that the buffer has sufficient remaining data. This causes a `struct.error` when processing truncated or malformed records where the offset reaches the end of the buffer. To fix this, I will implement "defensive parsing" by adding explicit boundary checks (`offset + 4 <= len(buffer)`) before every `struct.unpack_from` call in both `skip_value` and `extract_images_from_record`. If the check fails, the parser will safely stop processing the current record instead of crashing, directly applying **Cite debug_lesson_3**.
