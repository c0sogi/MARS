The `IndexError` is caused by a stale data cache. The script is loading preprocessed data arrays from a previous run where `Config.debug = True` (creating arrays of size 500), but the current execution has `Config.debug = False` (expecting ~20,000 samples). Because the cache filenames (`train_arrays.npz`, etc.) are static, the script fails to detect the configuration change, loads the tiny arrays, and crashes when `StratifiedKFold` (running on the full dataset) requests indices larger than 500.

To fix this, I will modify `library/dataset.py` to append the configuration parameters (specifically `debug` status and `max_len`) to the cache filenames. This ensures that incompatible cache files are ignored, forcing the data to be reprocessed when settings change (Cite debug_lesson_7).
