The following strategy outlines the implementation of the demonstration script:

1.  **Configuration Patching**: To ensure the script runs quickly (within the 1-hour limit) and serves as a valid demonstration, we will modify the `Config` class attributes at runtime. We will enable `DEBUG` mode, reduce the number of epochs to 1, set the number of folds to 1, and switch the model backbone to `roberta-base` (a standard, faster model). We will also redirect artifacts to a temporary directory.
2.  **Data Loading**: We will utilize `data_factory.get_loaders` with `debug=True` to generate small subsets of the data. We will verify that the returned DataLoaders yield batches with the correct keys and shapes.
3.  **Model Initialization**: We will instantiate the `TweetModel` and perform a dummy forward pass with a batch of data to confirm the architecture produces logits of the expected shape.
4.  **Training & Evaluation**: We will run `training_engine.train_fn` and `training_engine.eval_fn` for a single epoch/pass on the debug dataset. We will assert that the loss and Jaccard scores are valid (non-NaN).
5.  **Artifact Management**: We will save the trained model state dictionary to the specific path expected by the inference engine (`{model_name}_fold_{fold}.pth`).
6.  **Inference**: We will execute `inference_engine.generate_submission`. This demonstrates the end-to-end flow: loading the saved model, performing inference on the test set (using the cached debug data for speed), and generating the final `submission.csv` file.
7.  **Validation**: Throughout the script, assertions will be used to enforce correctness.
