The implementation strategy follows a strict pipeline designed to verify the proposed idea efficiently while ensuring rigorous validation.

1.  **Setup & Configuration**: We initialize the environment with a fixed seed for reproducibility. We override the default `Config` to point the training data to `./metadata/train.csv` (the 80% split) and reduce `EPOCHS` to 2. This ensures the "fast baseline" requirement is met and prevents data leakage into the hold-out validation set (`./metadata/val.csv`).
2.  **Data Processing**: We clear any existing cached data to force the regeneration of stratified folds based on the new training subset.
3.  **Model Training (5-Fold CV)**: We execute a 5-Fold Cross-Validation loop. For each fold, we train the `TweetModel` (DeBERTa-v3-Large with Multi-Sample Dropout) using Mixed Precision (AMP) and the Hybrid Loss function. We save the best model checkpoint based on the validation Jaccard score.
4.  **Hold-out Validation**: We load the unseen `./metadata/val.csv` dataset. We perform **Ensemble Inference** by averaging the logits from all 5 trained fold models. We apply the "neutral" heuristic (predicting the full text for neutral tweets) and compute the final Word-level Jaccard score.
5.  **Failure Analysis**: We analyze the errors on the validation set by calculating the Pearson correlation between the error magnitude (1 - Jaccard) and input features like text length and sentiment.
6.  **Submission**: If the final validation metric exceeds `0.7205`, we run the ensemble inference on the test set (`test.csv`) and generate the `submission.csv` file.
