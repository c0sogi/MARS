The issue arises because PyTorch 2.6+ enables `weights_only=True` by default in `torch.load`, which blocks the loading of NumPy scalars (like `numpy.float64`) often found in training metadata (e.g., `best_score`). To fix this, I will cast the metric to a native Python `float` before saving it in `library/train.py` and explicitly set `weights_only=False` in `library/utils.py` to allow loading legacy or NumPy-containing checkpoints. Cite debug_lesson_1.
