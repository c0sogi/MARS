### Model
The proposed solution is a **Siamese Gated Convolutional Ranker**. This architecture leverages the efficiency of convolutional neural networks (CNNs) to capture local context and phrase-level semantics, offering a middle ground between the order-agnostic Bag-of-Embeddings approach and computationally expensive Transformers.

*   **Embedding Layer:** The model uses pre-trained static word embeddings (e.g., GloVe) to represent tokens. This minimizes training time and parameter count compared to learning embeddings from scratch.
*   **Siamese Encoder:** A shared **1D Convolutional Neural Network** processes both the Question and the Long Answer Candidate independently.
    *   **Gated Convolutions:** The encoder utilizes 1D convolutional filters of varying kernel sizes (e.g., 2, 3, and 4) to detect n-gram patterns. These are followed by **Gated Linear Units (GLU)**, which control the information flow, allowing the model to focus on relevant keywords while suppressing noise.
    *   **Max-Pooling:** A global max-pooling operation aggregates the output of the gated convolutions, producing a single fixed-size vector representation for the question ($V_q$) and the candidate ($V_c$) that emphasizes the most salient features observed in the text.
*   **Interaction Layer:** The relevance score is computed using the **Cosine Similarity** between the encoded question vector $V_q$ and the candidate vector $V_c$. This similarity score is then scaled and shifted by a learnable bias to produce a probability logit.
*   **Short Answer Module:** To extract the short answer, the model employs a **Token Overlap Sliding Window** heuristic. A window of fixed token length slides over the predicted long answer text. For each window, the algorithm calculates the count of overlapping unigrams and bigrams with the question. The window with the highest overlap count is selected.

### Data
*   **Preprocessing:**
    *   **Tokenization:** The text is tokenized based on whitespace. Punctuation is treated as separate tokens to preserve n-gram structure.
    *   **Sequence Padding:** Question and candidate sequences are padded or truncated to fixed lengths (e.g., 20 tokens for questions, 300 for candidates) to facilitate batch processing in the CNN.
    *   **Vocabulary Mapping:** Tokens are mapped to indices corresponding to the pre-trained embedding matrix. Out-of-vocabulary words are assigned to a generic `<UNK>` token.
*   **Candidate Generation:** The `document_text` is segmented into candidate strings using the start and end indices provided in the `long_answer_candidates` field.
*   **Labeling:** Candidates that match the ground truth `long_answer_index` are labeled as positive (`1`), while all other candidates from the same document are labeled as negative (`0`).

### Training
*   **Strategy:** The model is trained as a pointwise binary classifier. It learns to predict the probability that a given candidate text answers the input question.
*   **Loss Function:** The model minimizes **Binary Cross-Entropy Loss** between the predicted probability and the ground truth label.
*   **Sampling:** To address the extreme class imbalance (one correct answer vs. dozens of incorrect candidates per document), **Random Negative Sampling** is used. For each training step, the positive candidate is paired with a fixed number of randomly selected negative candidates (e.g., 4) from the same document.
*   **Optimization:** The Adam optimizer is employed with a standard learning rate to update the convolutional filters and the scaling parameters of the similarity function.

### Evaluation
*   **Long Answer Prediction:**
    1.  The trained model encodes the question and all candidates for a test example.
    2.  Cosine similarity scores are computed for all pairs.
    3.  The candidate with the highest score is identified.
    4.  If the score exceeds a tuned **confidence threshold**, the candidate is predicted as the long answer; otherwise, the prediction is `BLANK`.
*   **Short Answer Prediction:**
    1.  If a long answer is predicted, the **Token Overlap Sliding Window** heuristic is applied to that text.
    2.  The window with the maximum n-gram overlap with the question is extracted.
    3.  If the overlap count is zero or falls below a secondary threshold, the short answer is predicted as `BLANK`.
*   **Yes/No Prediction:**
    *   A rule-based check is performed on the extracted short answer span. If the span starts with the words "Yes" or "No" (case-insensitive) and is followed by punctuation, the corresponding label is assigned; otherwise, it defaults to `NONE`.
