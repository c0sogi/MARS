### Proposed Baseline: Window-Based Max-Pooling Network

This approach introduces a **Window-Based Max-Pooling** architecture. It addresses the limitation of Global Pooling models (like Idea 1), which lose local context by averaging the entire text, and avoids the computational cost of sequential models (RNNs/Transformers) or deep convolutional stacks. By treating the document as a collection of fixed-size "views" (windows), the model can detect specific relevant phrases efficiently using simple feed-forward operations.

#### **Model**
*   **Embedding Layer:** The model uses pre-trained static word embeddings (e.g., GloVe) to convert tokens into dense vectors. These are frozen to ensure maximum training throughput and low memory footprint.
*   **Question Encoder:** The question tokens are aggregated into a single fixed-size vector using **Mean Pooling**, followed by a dense projection layer.
*   **Candidate Encoder (Bag-of-Windows):**
    *   Instead of processing the long answer candidate as a single sequence, it is sliced into multiple **Overlapping Windows** of fixed length (e.g., 50 tokens with a stride of 25).
    *   Each window is independently encoded using **Mean Pooling**, resulting in a set of window vectors for a single candidate.
*   **Local Scoring Module:**
    *   A shared **Multi-Layer Perceptron (MLP)** processes each pair of `(Question Vector, Window Vector)` independently.
    *   This outputs a **Relevance Score** for each window, indicating the likelihood that the specific window contains the answer.
*   **Ranking Head (Long Answer):** The score for the entire Long Answer Candidate is determined by **Max-Pooling** over its constituent window scores. The logic is that a candidate is relevant if *at least one* of its windows is highly relevant.
*   **Span Prediction Heads (Short Answer):**
    *   The model identifies the "Top Window" (the one with the maximum score).
    *   The unpooled token embeddings of this Top Window are concatenated with the Question Vector.
    *   This combined sequence is fed into two parallel linear layers to predict the **Start Token** and **End Token** indices relative to the window's boundaries.
*   **Yes/No Head:** The vector of the Top Window is passed through a small classifier to predict `YES`, `NO`, or `NONE`.

#### **Data**
*   **Preprocessing:**
    *   **Tokenization:** Input text is split using a fast whitespace tokenizer.
    *   **Window Generation:** For every long answer candidate, the text is segmented into fixed-length windows. Padding is applied to the last window if necessary.
    *   **Vocabulary:** Tokens are mapped to indices in the pre-trained embedding matrix.
*   **Labeling:**
    *   **Window Labels:** A window is labeled positive (`1`) if it contains the ground truth short answer span (or a significant portion of it). All other windows are labeled negative (`0`).
    *   **Span Labels:** Start and End indices are calculated relative to the start of the positive window.
    *   **Yes/No:** Categorical labels.

#### **Training**
*   **Strategy:** The model is trained primarily as a **Window Classifier**. It learns to identify the specific segment of text that answers the question.
*   **Sampling:** **Random Negative Sampling** is applied at the window level. Each training batch consists of positive windows (containing the answer) and a ratio of negative windows (sampled from the same or different candidates).
*   **Loss Function:** A weighted sum of three losses:
    *   **Window Classification Loss:** Binary Cross-Entropy to optimize the relevance scores.
    *   **Span Loss:** Sparse Categorical Cross-Entropy for the start/end indices within the positive window.
    *   **Class Loss:** Categorical Cross-Entropy for the Yes/No classification.
*   **Optimizer:** The Adam optimizer is used with a standard learning rate schedule.

#### **Evaluation**
1.  **Inference:** For a test document, the model generates windows for the question paired with every available long answer candidate.
2.  **Long Answer Selection:** The model computes scores for all windows. Each candidate is assigned the score of its highest-scoring window. The candidate with the maximum aggregate score is selected. If this score is below a **confidence threshold**, the prediction is `BLANK`.
3.  **Short Answer Extraction:** The specific window responsible for the candidate's maximum score is processed by the Span Prediction Heads to identify the start and end tokens. These relative indices are mapped back to the global document indices.
4.  **Yes/No Prediction:** The label is predicted by the Yes/No head based on the Top Window's representation.
