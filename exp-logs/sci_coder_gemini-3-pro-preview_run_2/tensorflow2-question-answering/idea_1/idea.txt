### Model
The proposed solution is a **Neural Bag-of-Embeddings (BoE) Ranker**. This architecture is designed to be computationally inexpensive while leveraging semantic word representations to rank answer candidates.

*   **Embedding Layer:** The model utilizes pre-trained static word embeddings (e.g., GloVe) to convert tokenized text into dense vectors. This avoids the high computational cost of training embeddings from scratch or using heavy Transformer models.
*   **Encoder:** Both the Question and the Long Answer Candidate text are encoded independently using **Global Average Pooling**. This operation aggregates the word embeddings into a single fixed-size vector for the question ($V_q$) and one for the candidate ($V_c$). This approach sacrifices word order information for extreme speed and memory efficiency.
*   **Interaction Layer:** To capture the relationship between the question and the candidate, the two vectors are combined using heuristic matching features. The input to the classifier is a concatenation of:
    *   The raw vectors ($V_q, V_c$)
    *   Element-wise product ($V_q \odot V_c$)
    *   Absolute element-wise difference ($|V_q - V_c|$)
*   **Scoring Head:** The combined feature vector is passed through a shallow Multi-Layer Perceptron (MLP) with ReLU activations, outputting a single probability score indicating whether the candidate answers the question.
*   **Short Answer Module:** Instead of a trainable neural span predictor, the model uses a deterministic **TF-IDF Sliding Window** heuristic. Once the best long answer candidate is identified, a window of fixed token length slides over the text. The window with the highest TF-IDF cosine similarity to the question vector is selected as the short answer.

### Data
*   **Candidate Extraction:** The raw `document_text` is segmented into discrete text chunks using the start and end tokens provided in `long_answer_candidates`.
*   **Tokenization:** A fast, whitespace-based tokenizer processes the question and candidate texts to map tokens to the pre-trained embedding vocabulary. Unknown words are mapped to a generic `<UNK>` vector.
*   **Labeling:** For the training set, candidates that match the `long_answer_index` are labeled as positive (`1`). All other candidates within the document are potential negatives (`0`).
*   **Vectorization:** TF-IDF vectors for the questions and candidate texts are pre-computed and cached to accelerate the short answer heuristic during evaluation.

### Training
*   **Strategy:** The problem is framed as a pointwise binary classification task. The model sees pairs of `(Question, Candidate)` and predicts the probability of a match.
*   **Negative Sampling:** Since each document contains dozens of candidates but only one correct answer, training on all negatives is inefficient. The data loader employs **random negative sampling** (e.g., pairing the positive candidate with 4 random negative candidates from the same document) to maintain a balanced training signal.
*   **Loss Function:** The model is optimized using **Binary Cross-Entropy Loss**.
*   **Optimization:** The Adam optimizer is used with a standard learning rate schedule (linear warmup followed by decay) to ensure stable convergence.

### Evaluation
*   **Long Answer Prediction:** For every example in the test set, the model generates a score for every available long answer candidate. The candidate with the highest score is selected. If this maximum score falls below a tuned confidence threshold $\tau_{long}$, the model predicts a `BLANK` (no long answer).
*   **Short Answer Prediction:** If a long answer is selected, the TF-IDF sliding window heuristic is applied to that specific text span. The window with the highest similarity score is extracted. If this score is below a secondary threshold $\tau_{short}$, the prediction defaults to `BLANK`.
*   **Yes/No Prediction:** A rule-based post-processor checks the extracted short answer span. If the question begins with an auxiliary verb (e.g., "Did", "Is", "Can") and the extracted span starts with "Yes" or "No", the `YES/NO` label is assigned accordingly; otherwise, it defaults to `NONE`.
