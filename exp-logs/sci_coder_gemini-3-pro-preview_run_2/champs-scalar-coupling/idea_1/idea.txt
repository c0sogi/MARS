# Baseline Approach: Distance-Weighted Graph Convolutional Network (GCN)

### Model
I propose a **Distance-Weighted Graph Convolutional Network (GCN)**. This architecture serves as a lightweight alternative to the complex interaction blocks of SchNet (Model 2) or the attention mechanisms of Graph Transformers (Model 4).
*   **Graph Construction**: Molecules are represented as graphs where atoms are nodes and chemical bonds (or spatial proximity) are edges. An edge is defined between any two atoms within a fixed cutoff radius (e.g., 3.0 Å).
*   **Node Embeddings**: A simple lookup table embeds the atomic species (e.g., H, C, N) into a low-dimensional vector.
*   **Graph Convolution Layers**: The core consists of 2-3 layers of standard Graph Convolutions (e.g., `GCNConv` or `GraphConv`). Unlike SchNet's continuous filters, this model uses a simpler aggregation where messages are weighted by the inverse Euclidean distance between atoms, capturing the decay of interaction strength without complex radial basis functions.
*   **Readout & Prediction**: To predict the coupling constant for a specific pair of atoms (Atom $i$, Atom $j$):
    1.  Extract the final learned node embeddings for Atom $i$ and Atom $j$.
    2.  Concatenate these embeddings with the **Euclidean distance** between them and a **learned embedding of the coupling type** (e.g., `1JHC`).
    3.  Pass this concatenated vector through a small Multi-Layer Perceptron (MLP) to regress the scalar coupling constant.

### Data
*   **Graph Generation**: Iterate through `structures.csv` to create a graph object for each molecule.
    *   **Nodes**: Integer indices representing atom types.
    *   **Edges**: Compute pairwise distances. Create an edge list (`edge_index`) for pairs with distance < Cutoff. Store inverse distances as edge weights.
*   **Coupling Mapping**: Map the `train.csv` and `test.csv` entries to the corresponding graph nodes. Each training sample becomes a reference to a specific graph and a pair of node indices.
*   **Normalization**: Normalize the target `scalar_coupling_constant` (e.g., standardization) to assist convergence, as values vary significantly by coupling type.

### Training
*   **Loss Function**: Use **Mean Absolute Error (L1 Loss)**, as it directly correlates with the competition metric (Log MAE).
*   **Optimizer**: Use **Adam** with a standard learning rate (e.g., 1e-3).
*   **Strategy**: Train a single unified model for all coupling types. The inclusion of the "coupling type embedding" in the readout head allows the MLP to adapt its output scale and sign based on the specific interaction type (e.g., 1JHC vs 3JHH).
*   **Efficiency**: Use `torch_geometric`'s `DataLoader` to batch multiple molecular graphs together, enabling efficient GPU utilization.

### Evaluation
*   **Inference**: Load the test set graphs and coupling pairs. Pass them through the trained model to generate predictions.
*   **Post-Processing**: If target standardization was used during training, apply the inverse transform to the predictions to obtain the final values.
*   **Submission**: Format the output as `id,scalar_coupling_constant` and save to `submission.csv`.
