The issue is that the `TargetScaler.inverse_transform` method expects the `types` argument to contain string representations of coupling types (e.g., "1JHC") to match the keys in its internal statistics dictionaries. However, the `runfile.py` script passes integer-encoded types (e.g., 0, 1) obtained directly from the DataLoader. This causes the lookup in the scaler to fail, returning `NaN` values for the mean and standard deviation, which results in `NaN` predictions and metrics. The fix is to map the integer types back to their string equivalents using the `int_to_type` dictionary before calling `inverse_transform` in both the validation and submission loops.
