Based on the accumulated lessons and the analysis of previous experiments, I propose a **Robust Multi-Task XLM-RoBERTa Large Ensemble with Weighted Layer Pooling**.

This strategy synthesizes the high-capacity backbone and gating mechanism of the current best solution (Idea 7) with the advanced representation and optimization techniques attempted in Idea 8, while explicitly correcting the training duration error that caused Idea 8 to fail.

# Model
We will utilize **`xlm-roberta-large`** as the backbone, enhanced with structural modifications to improve feature quality and task alignment.
*   **Backbone:** `xlm-roberta-large`. This model provides the necessary capacity for Hindi and Tamil (Cite solution_lesson_node_00028) and avoids the `token_type_ids` architectural mismatch that caused MuRIL to fail (Cite solution_lesson_node_00018).
*   **Weighted Layer Pooling (Structural Innovation):** Instead of utilizing only the final hidden state (which can be over-specialized to the pre-training objective), we will implement a **Weighted Layer Pooling** mechanism. This computes a learnable weighted average of the **last 4 transformer layers** to form the token representations. This allows the model to leverage richer semantic and syntactic features captured in lower layers, which were underutilized in previous iterations.
*   **Multi-Task Heads:** We will retain the dual-head architecture that successfully filtered noise in Idea 7 (Cite solution_lesson_node_00032):
    1.  **QA Head:** Predicts `start_logits` and `end_logits` for span extraction.
    2.  **Answerability Head:** A binary classifier on the `[CLS]` token to predict whether the window contains an answer.

# Data
*   **Preprocessing (Sliding Windows):** We will apply a **sliding window strategy with overlap** (stride=128, window=384) to handle the long context passages (Cite solution_lesson_node_00001).
*   **Negative Retention:** We will **retain all generated windows**, including those without answers. We explicitly reject negative downsampling, as previous experiments proved this removes essential context and degrades performance on long documents (Cite solution_lesson_node_00025). The Answerability Head will manage the resulting class imbalance.
*   **Splitting:** We will use the full training set for training (no validation split during final production) to maximize data usage, relying on the stability techniques below to prevent overfitting.

# Training
We will implement a rigorous training loop designed to stabilize the large model without the computational overhead of adversarial training.
*   **Layer-wise Learning Rate Decay (LLRD):** We will implement **Layer-wise Learning Rate Decay** (Cite solution_lesson_node_00034). We will assign geometrically decreasing learning rates from the top layer (head) to the bottom layer (embeddings). This allows the task-specific heads to adapt quickly while preserving the robust multilingual features in the lower backbone, preventing catastrophic forgetting.
*   **Optimization Configuration:**
    *   **Optimizer:** AdamW with a linear scheduler and warmup (Cite solution_lesson_node_00003).
    *   **Gradient Accumulation:** We will accumulate gradients to simulate a larger effective batch size (e.g., 16 or 32), which is critical for stabilizing the optimization of the Large model on limited hardware (Cite solution_lesson_node_00034).
    *   **Weight Decay Exclusion:** We will explicitly exclude bias terms and LayerNorm parameters from weight decay to prevent model collapse (Cite solution_lesson_node_00035).
*   **Duration:** We will train for **3 to 4 epochs**. We will strictly avoid the error of reducing epochs to save time, as heavier models require sufficient iterations to converge (Cite solution_lesson_node_00009, solution_lesson_node_00040).

# Evaluation
*   **Seed Ensembling:** To mitigate the high variance observed in single-model runs (Cite solution_lesson_node_00038), we will train the model using **3 distinct random seeds**.
*   **Inference:** During testing, we will generate logits from all 3 models. The final score for a candidate span will be the **average** of the weighted scores from the ensemble members:
    $\text{FinalScore} = \frac{1}{3} \sum_{k=1}^3 [(\text{Start}_k + \text{End}_k) \times \sigma(\text{Answerability}_k)]$
    This averaging is critical to smooth out stochastic noise (Cite solution_lesson_node_00038) and leverage the answerability gate (Cite solution_lesson_node_00032).
