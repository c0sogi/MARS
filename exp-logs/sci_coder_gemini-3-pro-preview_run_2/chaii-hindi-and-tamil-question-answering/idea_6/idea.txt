Based on the comprehensive analysis of previous experiments and lessons learned, I propose a **Robust XLM-RoBERTa Cross-Validation Ensemble**.

This strategy introduces a structural shift in the backbone architecture to **XLM-RoBERTa**, which offers superior multilingual performance while inherently bypassing the architectural mismatch (Segment Embeddings) that caused the MuRIL experiments to fail. It combines this with a rigorous training regimen that prioritizes stability and convergence over speed.

# Model
I propose replacing the previous backbones with **`xlm-roberta-base`**.
*   **Architecture:** XLM-RoBERTa is a Transformer model pre-trained on 100 languages using significantly more data than Multilingual BERT. It consistently outperforms mBERT and DistilBERT on cross-lingual benchmarks.
*   **Structural Advantage (Feature Alignment):** Unlike MuRIL and BERT, XLM-RoBERTa (like RoBERTa) does **not** use `token_type_ids` (Segment Embeddings). This structural difference is critical: it eliminates the risk of the "dead code" and "architecture mismatch" failures observed in previous attempts where the preprocessing pipeline failed to generate the segment IDs required by MuRIL (Cite solution_lesson_node_00016, solution_lesson_node_00018).
*   **Head:** We will attach a standard linear Question Answering head to the backbone to predict start and end logits.

# Data
*   **Preprocessing (Sliding Windows):** We will apply a **sliding window strategy with overlap** (e.g., stride=128, window=384) to the long context passages. This ensures that answer spans located deep in the text are preserved (Cite solution_lesson_node_00001).
*   **Negative Retention:** We will **retain all generated windows**, including those without answers. We explicitly reject the strategy of aggressive negative downsampling. While high noise was suspected to be a problem, empirical results demonstrated that removing negative context biases the model and degrades performance on long documents (Cite solution_lesson_node_00025).
*   **Splitting Strategy:** We will implement **Group K-Fold Cross-Validation** (K=3), grouping data by `context`. This ensures no leakage between folds while allowing the ensemble to learn from the entire dataset, mitigating the high variance of small-data training (Cite solution_lesson_node_00008).

# Training
*   **Training Duration:** We will train each fold for **5 to 6 epochs**. We will strictly adhere to the lesson that heavier models require more iterations to converge than distilled ones. We will not shorten training to save time, as undertraining has been proven to lead to catastrophic failure (Cite solution_lesson_node_00009).
*   **Optimization:** We will use the **AdamW** optimizer with a **linear learning rate scheduler with warmup**. This is mandatory to stabilize the fine-tuning of the randomly initialized head and prevent the optimization oscillations observed with constant learning rates (Cite solution_lesson_node_00003).
*   **Precision:** Mixed Precision (FP16) will be used to maximize throughput on the A100 GPU.

# Evaluation
*   **Ensemble Inference:** During the test phase, we will process inputs using all $K$ models from the cross-validation. We will **average the start and end logits** across the ensemble members before decoding. This aggregation is essential to smooth out the stochastic noise inherent in single-model predictions (Cite solution_lesson_node_00020).
*   **Span Selection:** The aggregated logits will be used to select the best answer span across all sliding windows for a given question.
*   **Regression Gate:** We will implement a conditional submission workflow. The final submission file will only be generated if the cross-validated Jaccard score of the current ensemble exceeds the best historical performance, protecting the leaderboard standing from stochastic regression (Cite solution_lesson_node_00002).
