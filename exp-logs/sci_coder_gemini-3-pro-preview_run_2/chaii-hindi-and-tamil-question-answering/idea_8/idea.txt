Based on the comprehensive analysis of previous experiments and the "Lessons Learned," I propose a **Robust Multi-Task XLM-RoBERTa Large Ensemble with Adversarial Training**.

This strategy synthesizes the superior capacity of the `xlm-roberta-large` backbone (Cite solution_lesson_node_00028) and the noise-filtering capability of the Multi-Task Answerability Head (Cite solution_lesson_node_00032) with a new **Adversarial Training** paradigm. This structural innovation is specifically designed to address the high variance and overfitting risks inherent in fine-tuning large models on small datasets (Cite solution_lesson_node_00008).

# Model
We will utilize **`xlm-roberta-large`** as the backbone, augmented with structural enhancements to maximize feature extraction and task alignment.
*   **Backbone:** XLM-RoBERTa Large. This model avoids the `token_type_ids` architectural mismatch that caused MuRIL to fail (Cite solution_lesson_node_00018) and provides the necessary capacity for Hindi/Tamil (Cite solution_lesson_node_00028).
*   **Weighted Layer Pooling (Structural Innovation):** Instead of utilizing only the final hidden state (which can be over-specialized to the pre-training objective), we will implement a **Weighted Layer Pooling** mechanism. This computes a learnable weighted average of the **last 4 transformer layers** to form the token representations. This allows the model to leverage richer semantic and syntactic features captured in lower layers.
*   **Multi-Task Heads:** We will retain the successful dual-head architecture (Cite solution_lesson_node_00032):
    1.  **QA Head:** Predicts `start_logits` and `end_logits` for span extraction.
    2.  **Answerability Head:** A binary classifier on the `[CLS]` token to predict if the window contains an answer.

# Data
*   **Preprocessing (Sliding Windows):** We will apply a **sliding window strategy with overlap** (stride=128, window=384) to handle the long context passages (Cite solution_lesson_node_00001).
*   **Negative Retention:** We will **retain all generated windows**, including those without answers. We explicitly reject negative downsampling, as removing these samples degrades performance on long documents (Cite solution_lesson_node_00025). The Answerability Head will manage the resulting class imbalance.

# Training
We will implement a rigorous training loop designed for stability on small data.
*   **Adversarial Training (FGM) (Structural Innovation):** We will integrate the **Fast Gradient Method (FGM)** into the training loop. After the initial forward/backward pass, we will compute perturbations for the input embeddings based on the gradient, inject this noise, and perform a second forward/backward pass to minimize the loss on the perturbed data. This explicitly smooths the loss landscape and improves generalization on the small dataset.
*   **Layer-wise Learning Rate Decay (LLRD):** We will refine the differential learning rate strategy (Cite solution_lesson_node_00034) by implementing **Layer-wise Learning Rate Decay**. Instead of two groups, we will assign geometrically decreasing learning rates from the top layer to the bottom layer (e.g., decay factor 0.9). This preserves the robust lower-level multilingual features while allowing the task-specific top layers to adapt quickly.
*   **Optimization:**
    *   **Optimizer:** AdamW with a linear scheduler and warmup.
    *   **Gradient Accumulation:** We will accumulate gradients to simulate a larger effective batch size (e.g., 16 or 32), stabilizing the optimization of the Large model (Cite solution_lesson_node_00034).
    *   **Weight Decay Exclusion:** We will explicitly exclude bias terms and LayerNorm parameters from weight decay to prevent model collapse (Cite solution_lesson_node_00035).

# Evaluation
*   **Seed Ensembling:** To mitigate the high variance observed in single-model runs (Cite solution_lesson_node_00008), we will train the model using **3 distinct random seeds** on the full training set (or a fixed high-data split).
*   **Inference:** During testing, we will generate logits from all 3 models. The final score for a candidate span will be the **average** of the weighted scores from the ensemble members:
    $\text{FinalScore} = \frac{1}{3} \sum_{k=1}^3 [(\text{Start}_k + \text{End}_k) \times \sigma(\text{Answerability}_k)]$
    This averaging is critical to smooth out stochastic noise (Cite solution_lesson_node_00038).
