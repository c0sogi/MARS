Based on the accumulated lessons, I propose the **Sky-Conditioned Kinematic Filtering Network (SKF-Net)**.

This solution structurally evolves the successful Windowed MLP approach by integrating a **Shallow 1D-CNN** for trajectory smoothing with a parallel **Sky-State MLP** for environmental bias correction. It specifically addresses the failures of previous sequence models (loss of temporal alignment via pooling) and spatial models (overfitting to absolute coordinates) by enforcing translation invariance and center-focused processing.

### Model
**Architecture: Dual-Stream Sequence-to-Point Network**
The model processes a sliding window of sensor data to predict the residual correction for the window's *center* timestamp using two specialized streams that are fused at the penultimate layer.

1.  **Kinematic Stream (Shallow 1D-CNN):**
    *   **Input:** A sliding time-series window of size $N$ (e.g., 15 epochs). Each timestep contains **Window-Relative Coordinates** (meters), **Dynamics** (Velocity/Deltas), and **Signal Metrics** (Cn0).
    *   **Backbone:** A stack of **Residual 1D Convolutional Layers** (e.g., 2-3 layers with kernel size 3). Unlike the MLP which treats inputs as independent features, the CNN explicitly learns local filtering kernels (e.g., smoothing jitter, detecting acceleration trends) while preserving the geometric shape of the path **Cite solution_lesson_node_00013**.
    *   **Temporal Preservation:** Crucially, **Global Pooling is strictly avoided**. The output of the CNN is **flattened**. This preserves the specific feature representation of the *center* timestamp relative to its neighbors, ensuring the model retains the temporal alignment required for point estimation **Cite solution_lesson_node_00032**.

2.  **Sky-Context Stream (MLP):**
    *   **Input:** A vector of aggregated **Satellite Geometry Statistics** for the entire window (e.g., Mean/Std of Satellite Elevation and Azimuth, Signal Strength distribution).
    *   **Purpose:** This stream creates an embedding of the environmental state (e.g., "Urban Canyon" vs. "Open Sky"). By relying on the physical configuration of satellites rather than absolute Latitude/Longitude, the model learns to correct state-dependent biases **Cite solution_lesson_node_00011** while strictly preventing spatial overfitting to training locations **Cite solution_lesson_node_00017**.

3.  **Fusion Head:**
    *   The flattened kinematic features and the sky-context embedding are concatenated.
    *   A Multi-Layer Perceptron (MLP) projects this fused vector to a 2D output: the residual correction ($\Delta$East, $\Delta$North) in meters.

### Data
**Preprocessing Pipeline:**
1.  **Target Transformation:** Calculate ground truth residuals in a local metric frame (Meters). The target is the difference between Ground Truth and the WLS Baseline. This ensures the target magnitude matches network initialization **Cite solution_lesson_node_00001**.
2.  **Sequence Feature Engineering:**
    *   **Relative Centering:** For each window, subtract the WLS Latitude/Longitude/Altitude of the *center* timestamp from all steps in the window.
    *   **Simple Scaling:** Convert these relative differences to meters using **Simple Element-wise Scaling** (e.g., $\Delta Lat^\circ \times 111,320$). This avoids the numerical instability and artifacts associated with complex ECEF/ENU projections on noisy data **Cite solution_lesson_node_00020**.
    *   **Dynamics:** Explicitly include first-order differences (velocities) for Latitude, Longitude, and **Altitude**. Vertical dynamics are retained as a critical orthogonal signal for detecting GNSS anomalies **Cite solution_lesson_node_00005**, **Cite solution_lesson_node_00006**.
    *   **Signal Metrics:** Include standardized Cn0 and Uncertainty estimates.
3.  **Windowing:** Use a short sliding window (e.g., 15 seconds) to capture local motion context without overfitting to long-term trajectory signatures **Cite solution_lesson_node_00010**.
4.  **Filtering:** Train only on windows where the center timestamp has valid ground truth. **Do not use interpolation** to fill gaps, as this creates artificial error signals **Cite solution_lesson_node_00035**.
5.  **Normalization:** Apply Standard Scaling (Z-score) to all inputs.

### Training
*   **Loss Function:** **Mean Absolute Error (MAE)**. This L1 loss is selected for its robustness to the extreme outliers (multipath effects) inherent in urban GNSS data.
*   **Optimizer:** **AdamW** optimizer with a `ReduceLROnPlateau` learning rate scheduler to ensure stable convergence.
*   **Strategy:** Train on the **full dataset**. As observed, simpler models trained on all available data outperform complex models trained on subsets **Cite solution_lesson_node_00040**.
*   **Cache Safety:** Use configuration hashing for data caching to prevent training on stale features **Cite solution_lesson_node_00037**.

### Evaluation
**Inference Process:**
1.  **Preprocessing:** Apply the same windowing, relative-centering, simple scaling, and sky-context aggregation steps to the test data.
2.  **Prediction:** Feed the processed windows into the SKF-Net to predict the metric residuals ($\Delta$East, $\Delta$North).
3.  **Reconstruction:** Convert the predicted metric residuals back to decimal degrees using local approximation factors derived from the test sample's latitude. Add these corrections to the baseline WLS Latitude/Longitude to generate the final submission coordinates.
