Based on the lessons learned, particularly the conflict between the need for state-dependent bias correction (**Cite solution_lesson_node_00011**) and the risk of spatial overfitting when using global coordinates (**Cite solution_lesson_node_00017**), I propose the **Geometry-Conditioned Residual 1D-CNN**. This solution introduces a new "Environmental Context" branch based on satellite geometry (Elevation/Azimuth) to predict error biases without memorizing the map.

# Model
**Architecture: Geometry-Conditioned Residual 1D-CNN**
The model employs a dual-stream architecture to disentangle local motion dynamics from environmental signal conditions.

1.  **Trajectory Stream (ResNet-1D):**
    *   **Input:** A time-series sequence of size $N$ (e.g., 15 epochs) containing kinematic and signal quality data.
    *   **Backbone:** A stack of **Residual 1D Convolutional Blocks**. Convolutional layers are chosen for their ability to learn local smoothing filters (noise reduction) while preserving the temporal structure of the path.
    *   **Output:** A feature vector representing the smoothed trajectory dynamics, obtained via Global Average Pooling.

2.  **Context Stream (MLP):**
    *   **Input:** A vector of aggregated **Satellite Geometry Statistics** for the window (e.g., Mean Satellite Elevation, Azimuth Spread, Count of Low-Elevation Satellites).
    *   **Purpose:** This stream provides the "state" context required to correct environmental biases (like urban canyons) as suggested by **Cite solution_lesson_node_00011**, but relies on the *physical configuration of the sky* rather than *absolute geospatial coordinates*, thereby strictly avoiding the spatial overfitting observed in **Cite solution_lesson_node_00017**.

3.  **Fusion Head:**
    *   The outputs of both streams are concatenated.
    *   A final Multi-Layer Perceptron (MLP) projects this fused representation to a 2D output vector: the residual correction ($\Delta$East, $\Delta$North) in meters.

# Data
**Preprocessing Pipeline:**
1.  **Target Transformation:** Calculate ground truth residuals in **meters** relative to the WLS baseline. This ensures the target magnitude aligns with network initialization **Cite solution_lesson_node_00001**.
2.  **Sequence Feature Engineering (Trajectory Stream):**
    *   **Window-Relative Coordinates:** For each window, subtract the WLS Latitude/Longitude of the *center* timestamp from all steps. Scale these differences to meters using **Simple Element-wise Scaling** (e.g., $\Delta Lat^\circ \times 1.11e5$). This preserves the geometric "shape" of the path (**Cite solution_lesson_node_00013**) while ensuring translation invariance and avoiding the numerical instability of complex projections (**Cite solution_lesson_node_00020**).
    *   **Dynamics:** Explicitly include first-order differences (velocity) for Latitude, Longitude, and **Altitude**. Vertical dynamics are included as a critical orthogonal signal for detecting GNSS anomalies **Cite solution_lesson_node_00005**, **Cite solution_lesson_node_00006**.
    *   **Signal Metrics:** Include Cn0 and Uncertainty.
3.  **Context Feature Engineering (Context Stream):**
    *   Aggregate the `SvElevationDegrees` and `SvAzimuthDegrees` fields from the raw GNSS logs. Compute summary statistics (Mean, Std, Min) for each epoch to characterize the "view of the sky" (e.g., low mean elevation implies an obstructed view).
4.  **Windowing:** Use a short sliding window (e.g., 15 seconds) to prevent overfitting to long-term trajectory signatures unique to the training set **Cite solution_lesson_node_00010**.
5.  **Normalization:** Apply Standard Scaling to all inputs.

# Training
*   **Loss Function:** **Mean Absolute Error (MAE)**. This L1 loss is selected for its robustness to the extreme outliers (multipath effects) inherent in the dataset.
*   **Optimizer:** **AdamW** optimizer with a `ReduceLROnPlateau` scheduler to ensure stable convergence.
*   **Regularization:** Apply Batch Normalization within the CNN blocks and Dropout in the Fusion MLP.

# Evaluation
**Inference Process:**
1.  **Preprocessing:** Apply the same windowing, relative-centering, simple scaling, and geometry aggregation steps to the test data.
2.  **Prediction:** Feed the processed windows into the model to predict the metric residuals ($\Delta$East, $\Delta$North).
3.  **Reconstruction:** Convert the predicted metric residuals back to decimal degrees using the same local scaling factors used in preprocessing. Add these corrections to the baseline WLS Latitude/Longitude to generate the final predictions.
