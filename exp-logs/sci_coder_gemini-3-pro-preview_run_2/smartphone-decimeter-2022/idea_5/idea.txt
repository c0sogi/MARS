Based on the accumulated lessons, I propose the **Local-Shape Preserving 1D-CNN**. This solution addresses the critical failure of previous spatial models (overfitting to global coordinates) while retaining the geometric context required for effective trajectory smoothing (which pure delta-based models lacked).

### Model
**Architecture: Relative-Trajectory 1D-CNN**
The model is a sequence-to-vector regression network designed to act as a learnable smoothing filter that operates on the *local geometry* of the path rather than global coordinates.

1.  **Input Representation:** A sliding time-series window of size $N$ (e.g., 11 epochs, representing $\pm 5$ seconds). Crucially, the spatial features are transformed into a **Local Metric Frame**:
    *   **Local Shape Sequence:** For every timestamp in the window, the input features include the position (East, North, Up in meters) *relative* to the baseline position at the window's center. This preserves the "shape" and "smoothness" of the trajectory (addressing **Cite solution_lesson_node_00013**) while being completely translation-invariant (preventing the spatial overfitting observed in **Cite solution_lesson_node_00017**).
    *   **Dynamics:** The sequence also includes the first-order differences (velocities) for Latitude, Longitude, and **Altitude**. The inclusion of vertical dynamics provides a robust signal for anomaly detection (**Cite solution_lesson_node_00006**).
    *   **Signal Quality:** Standard metrics (Cn0, Uncertainty, Satellite Count) are included for each step.

2.  **Convolutional Backbone:** A stack of **1D Convolutional Layers** (e.g., 3-4 layers) with ReLU activations and Batch Normalization. This backbone extracts high-level features describing the trajectory's coherence (e.g., "is this path jagged or smooth?") and the correlation between signal drops and position jumps.

3.  **Prediction Head:** A Global Average Pooling layer aggregates the temporal features, followed by a Multi-Layer Perceptron (MLP). The output is a 2D vector representing the residual correction ($\Delta$East, $\Delta$North) needed for the center timestamp.

### Data
**Preprocessing:**
1.  **Target Transformation:** Calculate the ground truth residuals in a local metric frame (ENU - East, North, Up). The target variable is the difference in **meters** between the Ground Truth and the WLS baseline, ensuring the loss scale matches the model initialization (**Cite solution_lesson_node_00001**).
2.  **Feature Engineering:**
    *   **Windowing:** Create sliding windows of a short, fixed length (e.g., 11 epochs). Short windows are preferred to prevent overfitting to long-term trajectory signatures (**Cite solution_lesson_node_00010**).
    *   **Relative Centering:** For each window, subtract the WLS Latitude/Longitude/Altitude of the *center* frame from all frames in that window. Convert these differences into meters.
    *   **Normalization:** Apply Standard Scaling (Z-score) to all inputs (Local Offsets, Deltas, Signal Metrics).

### Training
*   **Loss Function:** **Mean Absolute Error (MAE)**. This L1 loss is selected for its robustness to the extreme outliers typical of urban GNSS data (e.g., multipath reflections).
*   **Optimizer:** **AdamW** with a learning rate scheduler (e.g., `ReduceLROnPlateau`) to ensure convergence.
*   **Strategy:** Train on the relative sequences. Since the inputs are translation-invariant, the model can learn universal smoothing rules that apply to any location, avoiding the map-memorization pitfalls of previous iterations.

### Evaluation
**Inference Process:**
1.  **Preprocessing:** Apply the same windowing and "Relative Centering" transformation to the test data. Ensure the conversion to meters uses local approximation factors based on the test latitude.
2.  **Prediction:** Feed the relative test windows into the CNN to predict the metric residuals ($\Delta$East, $\Delta$North).
3.  **Reconstruction:** Convert the predicted metric residuals back to decimal degrees (1m $\approx$ 1/111,320 degrees Lat; Lon varies by Lat). Add these corrections to the baseline WLS position to generate the final submission coordinates.
