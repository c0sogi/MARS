Based on the dataset analysis and the provided model architectures, here is a proposal for a highly efficient baseline approach.

### Model: Windowed Multi-Layer Perceptron (MLP) Regressor

**Design & Components:**
The proposed solution is a **Windowed MLP Regressor**. Unlike the tree-based approach (Model 1) or recurrent/convolutional architectures (Models 2 & 3), this model treats the trajectory smoothing problem as a fixed-size vector regression task. It uses a simple Feed-Forward Neural Network (FNN) that operates on a flattened "sliding window" of sensor data.

*   **Input Layer:** Accepts a flattened vector representing a small temporal context window (e.g., $t-2$ to $t+2$ seconds) of the baseline Weighted Least Squares (WLS) position and aggregated signal quality metrics.
*   **Hidden Layers:** A sequence of fully connected (Dense) layers (e.g., 3 layers with 128, 64, 32 units).
*   **Activation:** ReLU activation functions for non-linearity.
*   **Regularization:** Batch Normalization and Dropout layers to prevent overfitting and ensure stable training on the noisy sensor data.
*   **Output Layer:** A linear projection to 2 units, predicting the **residual correction** ($\Delta$Latitude, $\Delta$Longitude) for the center timestamp of the window.

This architecture is "lightweight" because it avoids the computational overhead of graph construction (GCN), sequential unrolling (LSTM), or state covariance updates (Kalman Filter), while still capturing local temporal context through the windowing mechanism.

### Data

**Preprocessing Steps:**
1.  **GNSS Aggregation:** The raw GNSS logs (`device_gnss.csv`) are grouped by timestamp (`utcTimeMillis`). For each epoch, we compute:
    *   **Baseline Position:** Extract the provided `WlsPositionXEcefMeters`, `Y`, `Z` and convert them to Geodetic coordinates (Latitude, Longitude, Altitude).
    *   **Signal Stats:** Calculate the mean `Cn0DbHz` (signal strength), mean `RawPseudorangeUncertaintyMeters`, and the count of unique satellites (`Svid`).
2.  **IMU Integration:** Read `device_imu.csv` and calculate the magnitude of the accelerometer readings. Resample or aggregate this data to match the 1Hz GNSS timestamps (using the nearest neighbor or mean).
3.  **Target Generation:** Calculate the residuals: `Target_Lat = GroundTruth_Lat - WLS_Lat` and `Target_Lon = GroundTruth_Lon - WLS_Lon`.
4.  **Windowing:** Create sliding windows of size $N$ (e.g., 5 seconds). For each timestamp $t$, concatenate the feature vectors from $t - \lfloor N/2 \rfloor$ to $t + \lfloor N/2 \rfloor$ into a single flat input vector.
5.  **Normalization:** Apply Standard Scaling (Z-score normalization) to all input features to ensure the MLP converges efficiently.

### Training

**Procedure:**
*   **Loss Function:** Use **Mean Absolute Error (MAE)**. MAE is preferred over MSE for this task as it is more robust to the extreme outliers often present in GNSS data (e.g., due to "urban canyon" multipath effects).
*   **Optimizer:** Use the **AdamW** optimizer, which decouples weight decay from gradient updates, often yielding better generalization.
*   **Strategy:**
    *   Train on the flattened window vectors.
    *   Use a learning rate scheduler (e.g., `ReduceLROnPlateau`) to lower the learning rate when validation loss stagnates.
    *   Implement **Early Stopping** based on the validation set performance to prevent overfitting.

### Evaluation

**Inference Process:**
1.  **Preprocessing:** Apply the same aggregation, coordinate conversion, windowing, and normalization steps to the test data (`device_gnss.csv` and `device_imu.csv`).
2.  **Prediction:** Feed the flattened test windows into the trained MLP to predict the latitude and longitude residuals ($\Delta \hat{lat}, \Delta \hat{lon}$).
3.  **Reconstruction:** Add the predicted residuals back to the baseline WLS position to obtain the final predicted coordinates:
    *   $\text{Pred}_{lat} = \text{WLS}_{lat} + \Delta \hat{lat}$
    *   $\text{Pred}_{lon} = \text{WLS}_{lon} + \Delta \hat{lon}$
4.  **Submission:** Format these reconstructed coordinates into the required submission CSV format.
