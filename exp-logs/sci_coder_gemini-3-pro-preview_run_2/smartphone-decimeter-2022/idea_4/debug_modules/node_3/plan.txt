The issue is that the training and validation datasets contain missing values (`NaN`) in the input features derived from raw GNSS data (e.g., `WlsLat`, `MeanCn0`). These `NaN` values propagate through the model, causing the loss to become `nan`. Consequently, the logic for saving the best model checkpoint (`if val_loss < best_val_loss`) never triggers because comparisons with `nan` always evaluate to `False`. This leads to a `FileNotFoundError` when the pipeline attempts to load the non-existent `best_model.pth` after training.

To fix this, I will modify `library/dataset.py` to explicitly drop rows containing `NaN` values in the training and validation datasets after merging with the ground truth and calculating targets. This ensures the model trains on valid data, preventing `nan` loss and enabling model checkpointing (Cite debug_lesson_2).
