Based on the lessons learned from previous experiments, I propose the **Sky-Anchored Relative-State Transformer (SAR-Transformer)**.

This solution addresses the limitations of the Windowed MLP (lack of dynamic attention) and the failures of previous sequence models (spatial overfitting, loss of temporal alignment, and caching errors). It introduces a structural innovation by using a **Dual-Stream** architecture that separates kinematic smoothing (via Self-Attention) from environmental bias correction (via Satellite Geometry), strictly adhering to translation invariance.

### Model
**Architecture: Dual-Stream Transformer with Center-Focus**
The model consists of two parallel branches that fuse to predict the residual correction for a specific timestamp.

1.  **Kinematic Stream (Transformer Backbone):**
    *   **Input:** A sliding time-series window of size $N$ (e.g., 15 epochs). Each timestep contains **Window-Relative Coordinates** (meters), **Dynamics** (Velocity/Deltas), and **Signal Metrics**.
    *   **Mechanism:** A stack of **Transformer Encoder Layers**. The Self-Attention mechanism allows the model to dynamically weigh the importance of neighboring epochs based on their signal quality and geometric consistency to refine the noisy center epoch.
    *   **Center Extraction:** Crucially, instead of Global Average Pooling (which destroys temporal alignment **Cite solution_lesson_node_00032**), the output embedding corresponding specifically to the **center timestamp** is extracted. This preserves the exact feature state of the target moment while enriching it with attended context.

2.  **Environmental Stream (Sky-State MLP):**
    *   **Input:** A vector of aggregated **Satellite Geometry Statistics** for the window (e.g., Mean/Std of Satellite Elevation and Azimuth, Mean Signal Strength).
    *   **Purpose:** This stream generates a "Sky-State" embedding that proxies the environmental context (e.g., "Urban Canyon" vs. "Open Sky") based on the physical configuration of satellites. This enables state-dependent bias correction **Cite solution_lesson_node_00011** without using absolute geospatial coordinates, thereby preventing spatial overfitting **Cite solution_lesson_node_00017**.

3.  **Fusion Head:**
    *   The **Center Token** (Kinematic) and **Sky-State Embedding** (Environmental) are concatenated.
    *   A **Residual MLP** projects this fused vector to a 2D output: the residual correction ($\Delta$East, $\Delta$North) in meters.

### Data
**Preprocessing Pipeline:**
1.  **Target Transformation:** Calculate ground truth residuals in a local metric frame (Meters). The target is the difference between Ground Truth and the WLS Baseline **Cite solution_lesson_node_00001**.
2.  **Sequence Feature Engineering:**
    *   **Window-Relative Coordinates:** For each window, subtract the WLS Latitude/Longitude/Altitude of the *center* timestamp from all steps.
    *   **Simple Scaling:** Convert these relative differences to meters using **Simple Element-wise Scaling** (e.g., $\Delta Lat^\circ \times 111,320$). This avoids the numerical instability of complex ECEF/ENU projections on noisy data **Cite solution_lesson_node_00020**.
    *   **Dynamics:** Explicitly include first-order differences (velocities) for Latitude, Longitude, and **Altitude**. Vertical dynamics are retained as a critical orthogonal signal for detecting GNSS anomalies **Cite solution_lesson_node_00005**, **Cite solution_lesson_node_00006**.
    *   **Signal Metrics:** Include standardized Cn0 and Uncertainty estimates.
3.  **Windowing:** Use a short sliding window (e.g., 15 seconds) to capture local motion without overfitting to long-term trajectory signatures **Cite solution_lesson_node_00010**.
4.  **Filtering:** Construct windows only where valid data exists. **Do not use interpolation** to fill gaps, as this creates artificial error signals **Cite solution_lesson_node_00035**.
5.  **Normalization:** Apply Standard Scaling (Z-score) to all inputs.

### Training
*   **Loss Function:** **Mean Absolute Error (MAE)**. This L1 loss is selected for its robustness to the extreme outliers (multipath effects) inherent in urban GNSS data.
*   **Optimizer:** **AdamW** optimizer with a `ReduceLROnPlateau` learning rate scheduler to ensure stable convergence.
*   **Cache Safety:** Implement **Configuration Hashing** for data caching. The preprocessed data filename must include a hash of the configuration (window size, scaling factors, feature list) to automatically trigger regeneration when logic changes, preventing the stale data failure observed in previous attempts **Cite solution_lesson_node_00037**.

### Evaluation
**Inference Process:**
1.  **Preprocessing:** Apply the same windowing, relative-centering, simple scaling, and sky-context aggregation steps to the test data.
2.  **Prediction:** Feed the processed windows into the SAR-Transformer to predict the metric residuals ($\Delta$East, $\Delta$North).
3.  **Reconstruction:** Convert the predicted metric residuals back to decimal degrees using the local approximation factors derived from the test sample's latitude. Add these corrections to the baseline WLS Latitude/Longitude to generate the final submission coordinates.
