Implementation strategy:
1.  **Setup and Imports**: Import necessary modules and classes from the provided library files (`config`, `data_loader`, `model`, `train`, `inference`, `utils`).
2.  **Training**: Execute `train_model` with `debug_sample_fraction=0.5` and `load_cached_data=False` to ensure a fast training run on a subset of data, as required for a baseline.
3.  **Validation Data Preparation**:
    *   Load the validation dataset tensors using `load_data`.
    *   Manually parse `validation_metadata.csv` and replicate the windowing logic (dropping start/end frames) to map each sample in the validation tensor back to its `phone_name`. This is crucial for the specific competition metric which averages errors per phone.
4.  **Inference on Validation**:
    *   Load the best saved model state.
    *   Run inference on the validation set in batches to compute predicted residuals.
    *   Calculate the Euclidean distance error (in meters) between predicted residuals and target residuals.
5.  **Metric Calculation**:
    *   Group errors by phone.
    *   Compute the 50th and 95th percentiles for each phone.
    *   Calculate the average of these percentiles per phone, then the mean across all phones to get the final metric.
6.  **Failure Analysis**:
    *   Compute correlations between the error magnitude and input features (specifically GNSS signal strength, uncertainty, and IMU magnitudes) to identify error sources.
7.  **Submission**:
    *   Check if the validation metric is below the threshold (4.256982128481356).
    *   If successful, call `generate_submission` to create the final CSV.
