### Model
I propose a **Pillar-Based Single-Stage Detector**, a streamlined architecture designed for high-speed 3D object detection using LiDAR point clouds. This model synthesizes the efficiency of vertical feature encoding (from Model 1) with a simplified single-shot detection head.

1.  **Pillar Feature Net (PFN)**: Instead of computationally expensive 3D convolutions, the model discretizes the raw point cloud into a 2D grid in the x-y plane. Points within each grid cell form a "pillar" (a voxel with infinite height). A simplified PointNet (consisting of a linear layer followed by BatchNorm, ReLU, and MaxPooling) extracts a feature vector for each pillar. This converts the sparse 3D point cloud into a dense 2D pseudo-image of size $(C, H, W)$.
2.  **2D CNN Backbone**: The pseudo-image is processed by a lightweight 2D Convolutional Neural Network. This backbone consists of a top-down network with three blocks of convolutional layers to downsample the feature map and increase the receptive field. This extracts high-level spatial features representing object shapes and orientations.
3.  **SSD Detection Head**: A Single Shot Detector (SSD) head operates on the final feature map. It uses predefined 3D anchors (fixed size boxes based on the mean dimensions of classes like cars and pedestrians) assigned to each grid location. The head predicts:
    *   **Class Probability**: The confidence that an anchor contains an object.
    *   **Box Regression**: Offsets $(\Delta x, \Delta y, \Delta z, \Delta w, \Delta l, \Delta h, \Delta \theta)$ to refine the anchor into a precise 3D bounding box.

### Data
The data preparation focuses on unifying the coordinate systems and converting the sparse data into a trainable format.

1.  **Coordinate Transformation (Crucial Step)**: The LiDAR data is provided in the **sensor coordinate frame**, while the ground truth annotations in `train.csv` are in the **global world frame**.
    *   Load `ego_pose.json` and `calibrated_sensor.json` to construct the transformation matrices.
    *   For training, transform the global ground truth bounding boxes into the LiDAR sensor frame.
    *   For test submission, the inverse transformation will be applied to the model's predictions.
2.  **Point Cloud Preprocessing**:
    *   **Filtering**: Clip points to a fixed range (e.g., $[-51.2, 51.2]$ meters in X/Y and $[-5, 3]$ meters in Z) to remove outliers and background noise.
    *   **Pillarization**: Group points into vertical pillars with a grid resolution of $0.2m \times 0.2m$.
    *   **Feature Decorating**: Augment each point with its offset from the geometric center of the pillar and the arithmetic mean of the points in the pillar, creating a rich input feature vector $(x, y, z, intensity, x_c, y_c, z_c, x_p, y_p)$.
3.  **Augmentation**: To improve robustness without heavy computation, apply:
    *   Random flipping along the X-axis.
    *   Global rotation (random angle between $[-\pi/4, \pi/4]$).
    *   Global scaling (random factor between $[0.95, 1.05]$).

### Training
The training procedure is designed for stability and convergence speed.

*   **Loss Function**: A multi-task loss combines:
    *   **Focal Loss**: For classification, to handle the extreme class imbalance between background (empty space) and foreground objects.
    *   **Smooth L1 Loss**: For regressing the bounding box location and dimensions.
    *   **Softmax Cross-Entropy**: For discrete orientation classification (binning the yaw angle) to avoid the singularity of angle regression.
*   **Optimizer**: Use **AdamW** with a weight decay of 0.01.
*   **Scheduler**: Implement the **OneCycleLR** policy, which warms up the learning rate to a maximum and then anneals it, ensuring fast convergence within the limited runtime.

### Evaluation
The evaluation pipeline generates the final submission file.

1.  **Inference**: Forward pass the test set LiDAR data through the network to generate bounding box predictions in the sensor frame.
2.  **Post-Processing**:
    *   **Filter**: Discard predictions with confidence scores below a low threshold (e.g., 0.1).
    *   **NMS**: Apply 3D Non-Maximum Suppression (IoU threshold of 0.5) to remove overlapping duplicate boxes.
3.  **Coordinate Restoration**: Apply the inverse coordinate transformation (Sensor $\rightarrow$ Ego $\rightarrow$ Global) to map the predicted boxes back to the world coordinates required by the submission format.
4.  **Formatting**: Construct the prediction string with confidence scores and 7-DOF box parameters, saving the result to `submission.csv`.
