### Model
I propose a **Classical "Cluster-and-Classify" Pipeline**, a non-neural network approach that serves as an extremely lightweight and interpretable baseline. This method moves away from the deep learning paradigm of "Idea 1" and instead relies on geometric heuristics and shallow machine learning, significantly reducing computational overhead and training time.

The architecture consists of four sequential stages:
1.  **Ground Plane Removal**: The raw LiDAR point cloud is processed using **RANSAC (Random Sample Consensus)** to fit a geometric plane model to the road surface. Points falling within a small distance threshold of this plane are identified as "ground" and removed. This drastically reduces the number of points to be processed, leaving only potential obstacles.
2.  **Euclidean Clustering**: The remaining non-ground points are grouped into distinct objects using **DBSCAN (Density-Based Spatial Clustering of Applications with Noise)**. This algorithm groups points that are closely packed together (marking them as object candidates) and marks points that lie alone in low-density regions as outliers.
3.  **Geometric Feature Extraction**: For each generated cluster, a fixed-length feature vector is computed. These features capture the geometric properties of the point cluster, including:
    *   **Spatial Statistics**: Minimum, maximum, and mean values for x, y, and z coordinates; cluster centroid; and point count.
    *   **Shape Descriptors**: Dimensions of the axis-aligned bounding box and the volume.
    *   **Covariance Features**: Eigenvalues ($\lambda_1, \lambda_2, \lambda_3$) of the cluster's covariance matrix, which help distinguish between linear objects (poles), planar objects (walls), and volumetric objects (cars).
4.  **Gradient Boosting Head**: The extracted feature vectors are fed into a **Gradient Boosting Machine (XGBoost)**. This model acts as the detection head, performing two tasks:
    *   **Classification**: Predicting the object class (e.g., car, pedestrian, background).
    *   **Box Estimation**: Regressing the parameters of the oriented 3D bounding box (center, dimensions, and yaw) based on the cluster's geometric properties.

### Data
Data preparation focuses on converting the raw sensor data into a tabular format suitable for training the gradient boosting model.

1.  **Coordinate Transformation**: As with previous approaches, the global ground truth annotations must be transformed into the **LiDAR sensor coordinate frame**. This ensures that the ground truth boxes align spatially with the raw point clouds.
2.  **Training Set Generation**:
    *   The full "Cluster-and-Classify" pipeline (Ground Removal + Clustering) is run on the training split images/LiDAR.
    *   Generated clusters are matched with ground truth bounding boxes based on **Intersection over Union (IoU)** or center distance.
    *   Clusters with a high overlap with a ground truth box are labeled with that class and the specific box parameters (target). Clusters with no overlap are labeled as "Background".
    *   This process results in a large **tabular dataset** where each row represents a cluster's feature vector and its corresponding target label.
3.  **Preprocessing**: To ensure cleaner clustering, the LiDAR data is cropped to a Region of Interest (ROI) matching the dataset's effective range (e.g., 100 meters) before processing.

### Training
The training process is "offline" and computationally inexpensive compared to deep learning.

1.  **Classifier Training**: An XGBoost classifier is trained on the tabular dataset to predict the class label of a cluster. The loss function used is **Multi-Class Log Loss**. To handle class imbalance (many background clusters vs. few objects), sample weights are adjusted to penalize errors on minority classes (e.g., pedestrians/bicycles) more heavily.
2.  **Regressor Training**: Separate XGBoost regressors are trained specifically for the "positive" samples (excluding background). These models minimize the **Mean Squared Error (MSE)** between the cluster's geometric center/dimensions and the ground truth box parameters.
3.  **Hyperparameter Tuning**: Since training is fast (minutes), a randomized search is performed to optimize tree depth, learning rate, and subsampling ratios.

### Evaluation
The evaluation pipeline mirrors the training data generation but uses the trained models for inference.

1.  **Inference Pipeline**:
    *   Load test LiDAR sample.
    *   Apply RANSAC to remove ground.
    *   Apply DBSCAN to generate candidate clusters.
    *   Extract geometric features for each cluster.
    *   Pass features through the trained XGBoost Classifier to get class scores.
    *   Pass features through the trained XGBoost Regressor to get final box coordinates.
2.  **Filtering**: Clusters classified as "Background" or having a confidence score below a threshold (e.g., 0.3) are discarded.
3.  **Global Mapping**: The predicted bounding boxes (currently in sensor coordinates) are transformed back to the **Global World Frame** using the inverse of the ego-pose and sensor calibration matrices.
4.  **Submission**: The final global boxes are formatted into the required prediction string and saved to the submission file.
