The `CalibrationRegistry` in `library/utils.py` fails to load sensor transforms because it strictly expects a "channel" column in the `calibrated_sensor` data. In the provided dataset, this information is likely missing or implicit (using "token"), causing the registry to return an empty lookup table. Consequently, the data processing pipeline silently discards all samples because it cannot retrieve the necessary coordinate transforms (Cite debug_lesson_1).

To fix this, I will modify `_load_data` in `library/utils.py` to:
1.  Ensure the `calibrated_sensor` DataFrame (`df_cs`) has a "channel" column by defaulting to "token" if it is missing.
2.  Update the post-merge check to correctly handle cases where the "channel" column might be suffixed (e.g., `channel_cs`) due to column name collisions during the merge.
