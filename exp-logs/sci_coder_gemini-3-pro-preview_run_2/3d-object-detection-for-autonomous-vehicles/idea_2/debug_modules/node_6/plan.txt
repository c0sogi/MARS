The issue is that the `LabelEncoder` is being fitted dynamically on the training data subset (`fit_transform`). When using a small debug sample (or if the dataset is imbalanced), the training split may not contain every possible object class. If the validation set subsequently contains a class that was absent from the training set, the `LabelEncoder` throws a "previously unseen labels" error because it hasn't learned that class ID.

To fix this, I will modify `library/model.py` to explicitly fit the `LabelEncoder` on the complete set of defined class IDs (0 to `bg_class_id`) before transforming the training labels. This ensures the encoder is aware of the full schema regardless of the specific data distribution in the current batch, preventing crashes on unseen valid labels. Cite debug_lesson_5.
