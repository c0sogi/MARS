The issue is caused by a combination of stale cache files and silent failure handling in the dataset class. The training process loads defective cached data (likely missing critical sensor mappings) because `load_cached_data` is set to `True`, preventing the system from regenerating the lookup tables from the source JSONs. Furthermore, the `NuScenesDataset` silently catches the resulting missing data errors (specifically missing `LIDAR_TOP` tokens), returning empty inputs instead of crashing. This causes the model to train on "empty" samples (leading to a trivial solution) and the validation set to generate no targets (resulting in 0.0 loss and an invalid metric of 1.0).

To fix this, I will:
1.  **Invalidate the cache** in `runfile.py` by setting `load_cached_data=False` during training. This forces the data loader to rebuild the lookup tables correctly (Cite debug_lesson_1).
2.  **Remove silent failure** in `library/dataset.py` by raising a `ValueError` if a sample's LiDAR token is missing, ensuring the pipeline fails fast rather than processing invalid data (Cite debug_lesson_2).
