The `torch.OutOfMemoryError` during the Infiller training is caused by the massive memory footprint of the DeBERTa-v3 output logits. As detailed in **debug_lesson_6** ("Account for Vocabulary Size in Activation Memory"), DeBERTa-v3 has a vocabulary size of ~128,000, which is significantly larger than RoBERTa's ~50,000.

With a batch size of 32 and sequence length of 256, the logits tensor alone requires approximately:
$$ 32 \times 256 \times 128,000 \times 4 \text{ bytes} \approx 4.2 \text{ GB} $$
During training, gradients for this tensor are also stored, doubling the requirement to ~8.4 GB just for the output layer, excluding activations and model weights. The traceback confirms an attempted allocation of 8.80 GiB failed.

To fix this, I will reduce the `TRAIN_BATCH_SIZE` to 8 and `INF_BATCH_SIZE` to 16 in both the configuration file and the run script. This keeps the memory usage within the limits of the A100 GPU.

```diff
runfile.py
<<<<<<< SEARCH
    Config.TRAIN_BATCH_SIZE = 32
    Config.INF_BATCH_SIZE = 128
=======
    # Cite debug_lesson_6: Account for Vocabulary Size in Activation Memory
    Config.TRAIN_BATCH_SIZE = 8
    Config.INF_BATCH_SIZE = 16
>>>>>>> REPLACE
```
