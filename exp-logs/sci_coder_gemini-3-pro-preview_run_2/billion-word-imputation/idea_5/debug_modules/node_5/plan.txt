The error was caused by using a large batch size (128) for training, which exhausted the GPU memory (OOM) because training requires storing gradients and optimizer states, unlike inference. The `runfile.py` script set a global `BATCH_SIZE` of 128 to optimize for the demo speed, but this was unsustainable for the training loop.

To fix this, I will apply the strategy from **Cite debug_lesson_5 (Decouple Training and Inference Batch Sizes)**. I will introduce separate configuration parameters for training and inference batch sizes. Specifically:
1.  Update `library/config.py` to define `TRAIN_BATCH_SIZE` and `INF_BATCH_SIZE`.
2.  Update `library/data.py` to use `TRAIN_BATCH_SIZE` for training DataLoaders and `INF_BATCH_SIZE` for validation/test DataLoaders.
3.  Update `runfile.py` to set `TRAIN_BATCH_SIZE` to a safe value (32) while keeping `INF_BATCH_SIZE` high (128) for speed, and update the assertions to verify the correct training batch dimensions.
