### Implementation Strategy

I will reduce the training dataset size to 100,000 samples and set epochs to 2. I will also optimize batch sizes and reduce the beam search width (`LOCATOR_TOP_K`) from 5 to 3 to speed up the inference pipeline on the large test set.
2.  **Training Orchestration**: I will explicitly trigger the training of the Locator, Infiller, and Verifier models. I will force the data loading functions to ignore cached data (`load_cached_data=False`) to ensure the reduced dataset size is used, preventing the loading of potentially larger pre-existing caches.
3.  **Validation & Metric**: I will construct a custom evaluation loop using the hold-out validation set (`metadata/val.parquet`). I will sample 2,000 sentences, synthetically remove one word (mimicking the test condition), run the full inference pipeline, and compute the Levenshtein distance. The result will be printed as `Final Validation Metric: <value>`.
4.  **Failure Analysis**: Using the results from the validation step, I will calculate the Pearson correlation between the Levenshtein distance (error) and the sentence length.
5.  **Submission**: If the validation metric meets the threshold (< 3.7089...), I will invoke the `generate_submission` function to process the full test set and save the `submission.csv`.
