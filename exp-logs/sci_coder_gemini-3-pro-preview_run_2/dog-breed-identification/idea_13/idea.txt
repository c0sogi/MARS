Based on the comprehensive analysis of the "Lessons Learned" and the failures of previous ensemble attempts, I propose the **Hybrid Supervised-SSL Multi-View Ensemble** strategy.

This approach structurally evolves the solution by introducing **Self-Supervised Learning (SSL)** features to complement the Supervised CNN baseline. It addresses the failure of previous heterogeneous ensembles (Lesson 00029) where standard or MIM Transformers (like EVA02) proved to be weak linear learners compared to ConvNeXt. By utilizing **DINOv2**, a Vision Transformer explicitly optimized for discriminative feature matching, we ensure the secondary stream is competitive in a linear probing regime while providing high-quality, orthogonal features derived from pixel-level consistency rather than class labels.

# Model
We will construct a dual-stream prediction system that strictly adheres to the "Late Fusion for Heterogeneous Architectures" protocol (Cite solution_lesson_node_00009).

1.  **Stream A (Supervised CNN):** The **`ConvNeXt-Large`** architecture initialized with **`torchvision` "New Recipe" weights** (`IMAGENET1K_V1`). This retains the high-performance, linearly separable features of the current best solution (Cite solution_lesson_node_00006).
2.  **Stream B (Self-Supervised ViT):** The **`ViT-Large`** architecture initialized with **DINOv2 weights** (e.g., `vit_large_patch14_dinov2` from `timm`).
    *   *Innovation:* Unlike previous attempts with EVA02 (MIM) or standard ViTs, DINOv2 is trained via self-distillation, producing features that are exceptionally robust for Nearest Neighbor and Linear Probing tasks. This solves the "weak base learner" issue observed in Idea 12 (Cite solution_lesson_node_00029).
3.  **Feature Extraction Head:** For both streams, we will replace the classification head with an Identity mapping (using `reset_classifier(0)` in `timm` or equivalent). This ensures we extract the pooled embedding **after** the final Layer Normalization, preserving the feature distribution (Cite solution_lesson_node_00025).
4.  **Classifiers:** Each stream will be equipped with its own **`LogisticRegressionCV`** head. We will **not** share heads or concatenate embeddings between streams.

# Data
We will implement a **Stream-Specific Multi-View Pipeline** for *each* backbone. This leverages the "Multi-View Early Fusion" strategy (Cite solution_lesson_node_00019) to maximize the signal-to-noise ratio for each architecture independently.

1.  **View Generation:** For every image, generate three geometric representations (Cite solution_lesson_node_00016):
    *   **Global View:** Resize to 224x224 (Squish). Captures object topology and shape.
    *   **Standard View:** Resize to 232 and Center Crop 224. Matches standard pre-training.
    *   **Local View:** Resize to 288 and Center Crop 224 (Zoom). Captures high-frequency texture details.
2.  **Stream-Specific Preprocessing:**
    *   **Stream A:** Use `torchvision` transforms (Bilinear interpolation, standard ImageNet Mean/Std).
    *   **Stream B:** Use `timm` transforms specific to DINOv2 (often Bicubic interpolation, specific Mean/Std) to ensure alignment with the SSL pre-training (Cite solution_lesson_node_00005).

# Training
The training process combines **Intra-Stream Early Fusion** (concatenation of views) and **Inter-Stream Late Fusion** (ensemble of probabilities).

1.  **Feature Extraction & TTA:**
    *   Apply **Horizontal Flipping** to all views and average the embeddings of the original and flipped versions (Cite solution_lesson_node_00006).
    *   Ensure embeddings are extracted after the native LayerNorm (Cite solution_lesson_node_00025).
2.  **Intra-Stream Early Fusion:**
    *   For Stream A, **concatenate** the embeddings from Global, Standard, and Local views into a single vector (approx. 4608 dims). Do **not** apply L2 normalization (Cite solution_lesson_node_00015).
    *   For Stream B, similarly concatenate the embeddings from its three views (approx. 3072 dims).
    *   This allows each linear classifier to learn correlations between shape and texture within its own coherent feature space (Cite solution_lesson_node_00019).
3.  **Parallel Optimization:**
    *   Train `LogisticRegressionCV` on Stream A's features.
    *   Train `LogisticRegressionCV` on Stream B's features.
    *   Using Cross-Validation to automatically tune `C` is mandatory to prevent the underfitting observed in Idea 6 (Cite solution_lesson_node_00021).
4.  **Ensemble Weight Optimization:** Learn optimal scalar weights $(w_A, w_B)$ on the validation set to minimize Log Loss. This leverages the diversity of Supervised vs. Self-Supervised features (Cite solution_lesson_node_00014).

# Evaluation
1.  **Weighted Late Fusion:**
    *   Generate probability predictions $P_A$ using the full Stream A pipeline.
    *   Generate probability predictions $P_B$ using the full Stream B pipeline.
    *   Compute final prediction: $P_{final} = w_A \cdot P_A + w_B \cdot P_B$.
2.  **Cache Safety:** Store embeddings in directories named `convnext_large_sup` and `vit_large_dinov2` to avoid cache collisions (Cite solution_lesson_node_00018).
