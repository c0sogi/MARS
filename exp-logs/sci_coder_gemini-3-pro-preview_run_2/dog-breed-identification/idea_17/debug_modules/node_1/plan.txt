The execution failure is caused by an **inhomogeneous shape error** in `LogisticRegressionCV`, which occurs because the debug dataset (100 samples) contains too many unique classes relative to its size. When cross-validation (`cv=2`) splits this small dataset, the set of classes in the training fold differs from the validation fold, causing the model to generate coefficient arrays of inconsistent shapes that cannot be stacked (Cite debug_lesson_8).

To resolve this, I will:
1.  **Modify `library/data_loader.py`**: Filter the debug dataset to the top 5 most frequent breeds. This ensures that even with only 100 samples, each class has sufficient representation for stable cross-validation (Cite debug_lesson_8).
2.  **Modify `library/hybrid_model.py`**:
    *   Update `optimize_weights` to filter out validation samples belonging to classes the model hasn't learned, preventing `log_loss` crashes (Cite debug_lesson_2).
    *   Update `generate_submission` to detect when the model predicts a subset of classes and map these predictions into the full 120-class schema required for submission, padding missing columns with zeros (Cite debug_lesson_3).
