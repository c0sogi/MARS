Based on the comprehensive analysis of the "Lessons Learned" and the trajectory of previous experiments, I propose the **Dual-Stream Heterogeneous Multi-View Ensemble with Optimized Linear Probing** strategy.

This approach structurally evolves the best-performing "Multi-View Early Fusion" strategy (Lesson 00019) by integrating a second, architecturally distinct backbone (Lesson 00009) while rigorously addressing the implementation failures—specifically hyperparameter tuning (Lesson 00021) and weight provenance (Lesson 00011)—that hindered previous ensemble attempts.

# Model
We will construct a prediction system composed of two independent, high-capacity processing streams. This design leverages the complementary strengths of a Convolutional Neural Network (CNN) and a Masked Image Modeling (MIM) Vision Transformer.

1.  **Stream A (CNN):** The **`ConvNeXt-Large`** architecture initialized with **`torchvision` "New Recipe" weights** (`IMAGENET1K_V1`). This retains the proven, high-performance base estimator from the current best solution (Cite solution_lesson_node_00006).
2.  **Stream B (Transformer):** The **`EVA02-Large`** (or `ViT-Large` SWAG) architecture initialized with **`timm` weights** (e.g., `eva02_large_patch14_448.mim_m38m_ft_in22k_in1k`).
    *   *Innovation:* Unlike previous attempts that used standard supervised ViTs (which failed to compete with ConvNeXt), EVA02 utilizes Masked Image Modeling pre-training, generating fundamentally different feature representations (shape/structure vs. texture) that maximize ensemble diversity.
3.  **Independent Classifiers:** Each stream will terminate in its own independent **`LogisticRegressionCV`** head.
    *   *Correction:* We will strictly avoid sharing heads or concatenating embeddings between streams (Early Fusion) to prevent feature space mismatch (Cite solution_lesson_node_00009).
    *   *Correction:* We will use Cross-Validation (`LogisticRegressionCV`) for *both* streams to automatically tune the regularization parameter `C`, ensuring the Transformer stream is not unfairly penalized by suboptimal hyperparameters as observed previously (Cite solution_lesson_node_00021).

# Data
We will implement a **Stream-Specific Multi-View Pipeline** that generates three distinct geometric representations for every image, maximizing signal extraction (Cite solution_lesson_node_00016).

1.  **View Generation:** For every image, generate:
    *   **Global View:** Resize to model input size (Squish). Preserves object topology.
    *   **Standard View:** Resize and Center Crop. Matches pre-training defaults.
    *   **Local View:** Resize to a larger scale and Center Crop (Zoom). Captures high-frequency texture.
2.  **Stream-Specific Preprocessing:**
    *   **Stream A:** Use `torchvision` transforms (Crop 224, Mean/Std `[0.485, ...]`).
    *   **Stream B:** Use `timm` specific transforms (likely Crop 448 or 224, Bicubic interpolation, specific Mean/Std) to ensure perfect alignment with the EVA02 pre-training recipe (Cite solution_lesson_node_00005).

# Training
The training process combines **Intra-Stream Early Fusion** (for homogeneous data views) and **Inter-Stream Late Fusion** (for heterogeneous architectures).

1.  **Feature Extraction & TTA:**
    *   Apply **Horizontal Flipping** to all views and average the embeddings of the original and flipped versions (Cite solution_lesson_node_00006).
    *   **Crucially**, ensure feature extraction for Stream B retains the architecture's native **Layer Normalization** (e.g., extracting the CLS token *after* the final Norm layer) to avoid the performance degradation observed with raw feature maps (Cite solution_lesson_node_00025).
2.  **Intra-Stream Early Fusion:**
    *   For Stream A, **concatenate** the embeddings from the Global, Standard, and Local views into a single feature vector. Do **not** apply L2 normalization (Cite solution_lesson_node_00015).
    *   Perform the same concatenation for Stream B.
    *   This allows the linear classifiers to learn correlations between shape and texture within a coherent feature space (Cite solution_lesson_node_00019).
3.  **Parallel Optimization:**
    *   Train `LogisticRegressionCV` on Stream A's concatenated features.
    *   Train `LogisticRegressionCV` on Stream B's concatenated features.
4.  **Ensemble Weight Optimization:** Learn optimal scalar weights $(w_A, w_B)$ on the validation set to minimize the combined Log Loss. This acts as a safety mechanism: if Stream B underperforms, $w_B$ will vanish, reverting to the strong single-model baseline (Cite solution_lesson_node_00012, solution_lesson_node_00014).

# Evaluation
1.  **Weighted Late Fusion:**
    *   Generate probability predictions $P_A$ using the Stream A pipeline.
    *   Generate probability predictions $P_B$ using the Stream B pipeline.
    *   Compute the final prediction: $P_{final} = w_A \cdot P_A + w_B \cdot P_B$.
2.  **Cache Safety:** Store embeddings in directories explicitly named with the model architecture and version (e.g., `convnext_large_v1`, `eva02_large_v1`) to prevent cache collision failures (Cite solution_lesson_node_00018).
