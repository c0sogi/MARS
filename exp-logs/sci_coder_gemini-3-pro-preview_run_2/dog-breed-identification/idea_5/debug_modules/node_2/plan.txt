The `ValueError` occurs because the model is trained on a small subset of data (Debug Mode: 100 samples) that does not cover all 120 classes. As a result, the validation set contains classes that the model has never seen (e.g., class 34, 99). When `log_loss` is called, it validates `y_true` against the model's known classes (`clf.classes_`) and fails because of the unseen labels. This is a known issue when debugging high-cardinality datasets with small sample sizes (Cite debug_lesson_2).

To fix this, I will modify `library/classifier.py` to filter the validation samples in both `train_logreg` and `optimize_ensemble_weights`. The metric calculation will only consider samples whose labels are present in the model's training classes, preventing the crash while allowing the pipeline to run in debug mode.
