Based on the analysis of the "Lessons Learned" and the trajectory of previous experiments, I propose the **Hybrid Supervised-SSL Dual-Stream Ensemble with Multi-View Early Fusion** strategy.

This approach synthesizes the highly successful "Multi-View Early Fusion" data strategy (Cite solution_lesson_node_00019) with a "Heterogeneous Backbone" architectural strategy. It explicitly addresses the failure of previous heterogeneous ensembles (Cite solution_lesson_node_00029) by replacing the weak "Masked Image Modeling" Transformer (EVA02) with a **Self-Supervised Learning (SSL)** Transformer (**DINOv2**), which is specifically optimized for discriminative linear probing.

# Model
We will construct a prediction system composed of two independent, high-capacity processing streams. This design leverages the complementary strengths of Supervised CNNs (class-discriminative texture) and Self-Supervised Transformers (instance-discriminative shape) while strictly avoiding feature space mismatches.

1.  **Stream A (Supervised CNN):** The **`ConvNeXt-Large`** architecture initialized with **`torchvision` "New Recipe" weights** (`IMAGENET1K_V1`). This retains the proven, high-performance base estimator from the current best solution (Cite solution_lesson_node_00006, solution_lesson_node_00011).
2.  **Stream B (Self-Supervised ViT):** The **`ViT-Large`** architecture initialized with **DINOv2 weights** (e.g., `vit_large_patch14_dinov2` from `timm`).
    *   *Innovation:* Unlike previous attempts with EVA02 or standard ViTs, DINOv2 is trained via discriminative self-distillation. This produces features that are highly separable linearly, addressing the "weak base learner" failure observed in heterogeneous ensembles (Cite solution_lesson_node_00029).
3.  **Independent Classifiers:** Each stream will terminate in its own independent **`LogisticRegressionCV`** head.
    *   We will **not** concatenate embeddings between streams (Early Fusion) to prevent distribution mismatch (Cite solution_lesson_node_00009).
    *   We will use Cross-Validation to automatically tune the regularization parameter `C` for each stream independently (Cite solution_lesson_node_00021).

# Data
We will implement a **Stream-Specific Multi-View Pipeline** that generates three distinct geometric representations for every image. This maximizes signal extraction (Cite solution_lesson_node_00016) while ensuring input distributions match pre-training recipes (Cite solution_lesson_node_00005).

1.  **View Generation:** For every image, generate:
    *   **Global View:** Resize to 224x224 (Squish). Preserves object topology.
    *   **Standard View:** Resize to 232 and Center Crop to 224. Matches standard pre-training.
    *   **Local View:** Resize to 288 and **Center Crop** to 224 (Zoom).
        *   *Constraint:* We will use a deterministic Center Crop, **rejecting** the "TenCrop/FiveCrop" spatial averaging strategy which was proven to degrade performance by introducing background noise (Cite solution_lesson_node_00028).
2.  **Stream-Specific Preprocessing:**
    *   **Stream A:** Use `torchvision` transforms (Bilinear interpolation, standard Mean/Std).
    *   **Stream B:** Use `timm` DINOv2-specific transforms (Bicubic interpolation, specific Mean/Std).

# Training
The training process combines **Intra-Stream Early Fusion** (for homogeneous data views) and **Inter-Stream Late Fusion** (for heterogeneous architectures).

1.  **Feature Extraction & TTA:**
    *   Apply **Horizontal Flipping** to all views and average the embeddings of the original and flipped versions (Cite solution_lesson_node_00006).
    *   **Crucially**, ensure feature extraction retains the architecture's native **Layer Normalization** (e.g., extracting the pooled output *after* the final Norm layer) to avoid the performance degradation observed with raw feature maps (Cite solution_lesson_node_00025).
2.  **Intra-Stream Early Fusion:**
    *   For Stream A, **concatenate** the embeddings from the Global, Standard, and Local views into a single feature vector. Do **not** apply L2 normalization (Cite solution_lesson_node_00015).
    *   Perform the same concatenation for Stream B.
    *   This allows the linear classifiers to learn correlations between shape and texture within a coherent feature space (Cite solution_lesson_node_00019).
3.  **Parallel Optimization:**
    *   Train `LogisticRegressionCV` on Stream A's concatenated features.
    *   Train `LogisticRegressionCV` on Stream B's concatenated features.
4.  **Ensemble Weight Optimization:** Learn optimal scalar weights $(w_A, w_B)$ on the validation set to minimize the combined Log Loss (Cite solution_lesson_node_00012).

# Evaluation
1.  **Weighted Late Fusion:**
    *   Generate probability predictions $P_A$ using the Stream A pipeline.
    *   Generate probability predictions $P_B$ using the Stream B pipeline.
    *   Compute the final prediction: $P_{final} = w_A \cdot P_A + w_B \cdot P_B$.
2.  **Cache Safety:** Store embeddings in directories explicitly named with the model architecture (e.g., `convnext_large_sup`, `vit_large_dinov2`) to prevent cache collisions (Cite solution_lesson_node_00018).
