Implementation Strategy:
1.  **Environment Setup**: Initialize random seeds and create a temporary working directory (`./working/demo_run`) to store demo artifacts, ensuring isolation from any existing production files.
2.  **Data Subsetting**: To ensure the demo runs quickly (within minutes) while remaining functionally complete:
    *   Load the original `train.csv` and sample exactly one image per breed (120 images total). This ensures the model output layer has the correct dimensions (120 classes) without requiring the full dataset.
    *   Create small subsets for validation (20 images) and test (20 images).
    *   Save these subsets to a temporary metadata directory.
3.  **Dynamic Patching**:
    *   Patch the path constants in `library.config` and `library.dataset` to point to the new subset metadata files.
    *   Patch `WORKING_DIR` in all relevant modules to use the demo directory.
    *   **Crucial Step**: Patch `library.training.LogisticRegressionCV` with a custom `MockLogisticRegressionCV` class. The standard `LogisticRegressionCV` requires at least 2 samples per class per fold, which fails on our 1-sample-per-class demo dataset. The mock class will accept the same arguments but behave like a standard `LogisticRegression` (no cross-validation), allowing the pipeline to execute successfully on the minimal dataset.
4.  **Pipeline Execution**:
    *   Execute `library.ensemble.run_ensemble()`. This orchestrates the entire flow: feature extraction (ConvNeXt & MaxViT), caching, training (using the mock classifier), ensemble optimization, and submission generation.
5.  **Validation**:
    *   Verify that the submission file is generated.
    *   Check that the submission has the correct dimensions (N_test rows, 120 breed columns + id).
