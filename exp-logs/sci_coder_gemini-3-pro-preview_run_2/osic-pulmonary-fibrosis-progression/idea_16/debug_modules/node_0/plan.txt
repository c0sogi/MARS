Implementation Strategy:
1.  **Setup and Configuration**: Initialize the environment, suppress warnings, and define paths for temporary working files.
2.  **Mini-Dataset Generation**: Create a small subset of the training, validation, and test metadata to ensure the demonstration runs quickly. Save these mini-datasets to the `./working` directory.
3.  **Module Patching**: Since the library modules import configuration constants (like file paths) at the top level, dynamically patch these variables within the imported modules (`library.dicom_feature_extractor`, `library.data_processor`) to point to the newly created mini-datasets.
4.  **Component Demonstration**:
    *   **Feature Extraction**: Instantiate `VarianceWeightedExtractor` and process the mini-datasets. Verify that the output features have the correct dimensionality (1280).
    *   **Data Processing**: Instantiate `TabularPreprocessor`, fit it on the training data, and transform all splits. Verify the shapes of the generated feature matrices (`X_fvc`, `X_unc`) and target vectors.
    *   **Model Training**: Instantiate and train `BaggedQuantileRegressor` (for FVC) and `BaggedElasticNet` (for uncertainty). Verify predictions are generated correctly.
5.  **Workflow Integration**: Execute the high-level `run_workflow` function (which utilizes the patched modules) to simulate an end-to-end run. Verify that the submission file is generated with the correct format.
6.  **Cleanup**: Clean up temporary files and directories.
