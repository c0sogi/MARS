The `RuntimeError` is caused by a data type mismatch: the input image data is implicitly promoted to `float64` (Double) during preprocessing because the normalization constants in `VarianceSelector` are default NumPy arrays (`float64`). Consequently, `torch.tensor(img_batch_np)` creates a `DoubleTensor`, but the `EfficientNet` model expects `float32` inputs (`FloatTensor`). To resolve this, I will explicitly cast the input tensor to `float32` in `ImageExtractor.extract_features` before passing it to the model.
