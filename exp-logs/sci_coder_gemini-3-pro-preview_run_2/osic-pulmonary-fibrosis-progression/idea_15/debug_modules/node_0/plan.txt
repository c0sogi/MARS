The implementation strategy involves creating a self-contained script that validates and demonstrates the core components of the lung function decline prediction pipeline.

1.  **Environment Setup**: Initialize random seeds and define paths for temporary working files.
2.  **Data Subsetting**: To ensure the demonstration runs quickly (under the 1-hour limit) and respects the "Optimize for Speed" requirement, we will load the provided metadata files and create "mini" versions containing only a few patients (5 for training, 2 for validation, 2 for testing). These mini-datasets will be saved to the `./working` directory.
3.  **Configuration Patching**: Since the library modules import file paths as constants, we will monkey-patch these constants in the `library.model_pipeline` module to point to our newly created mini-datasets. This redirects the pipeline to use the small data subset without modifying the library code on disk.
4.  **Component Verification**:
    *   **Metric**: Validate the `laplace_log_likelihood` function with known inputs.
    *   **DICOM Processing**: Instantiate `DicomProcessor` and process a single patient from the mini-dataset to verify that image loading, resizing, and histogram generation produce arrays of the expected shapes (Images: `[6, 224, 224]`, Histogram: `[4]`).
    *   **Feature Generation**: Instantiate `FeatureGenerator` to verify that it correctly combines image features (via EfficientNet), histograms, and clinical data into a single feature vector (Expected dimension: 1280 + 4 + 7 = 1291).
5.  **Pipeline Execution**: Instantiate the `LungFunctionPredictor`. We will run the full `prepare_data`, `fit`, and `predict` cycle using the mini-datasets. We will explicitly disable loading from cache (`load_cached_data=False`) to demonstrate the processing logic.
6.  **Output Validation**: Finally, we will check that the submission file is generated at the expected location and contains the required columns (`Patient_Week`, `FVC`, `Confidence`) with valid data types.
