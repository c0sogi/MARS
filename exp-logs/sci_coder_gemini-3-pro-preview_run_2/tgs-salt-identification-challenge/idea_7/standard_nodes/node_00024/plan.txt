The implementation strategy follows a structured pipeline to ensure robustness and compliance with the task requirements:

1.  **Setup & Initialization**: The script initializes the environment by setting the random seed and detecting the computation device (GPU) using the provided `library` modules.
2.  **Training**: It executes the training loop via `library.train.run_training`. I have selected **30 epochs** as the optimal balance for a "fast baseline." This is sufficient for the ResNet34-LinkNet architecture to converge on the small dataset (2400 images) without exceeding the time limit, while ensuring the model is capable of meeting the high performance threshold.
3.  **Validation & Metric Reporting**: The script loads the hold-out validation set and the best saved model. It computes the official Mean Average Precision (mAP) metric using `library.model.validate` and prints it in the required format (`Final Validation Metric: <value>`).
4.  **Failure Analysis**: To identify error patterns, the script calculates the Average Precision (AP) for each individual image in the validation set. It then computes and prints the Pearson correlation coefficients between the model's error (1 - AP) and the metadata features (Depth and Salt Coverage).
5.  **Submission Generation**: Finally, the script checks if the validation mAP exceeds the strict threshold of `0.7916666666666666`. If the condition is met, it triggers the inference pipeline (`library.predict.predict`), which optimizes the binarization threshold and generates the `submission.csv` file using Test-Time Augmentation (TTA).
