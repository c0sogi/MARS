The implementation strategy follows a Semi-Supervised Self-Training pipeline designed to optimize performance within the 2-hour constraint.

1.  **Configuration & Setup**: The script initializes the environment and overrides default configuration parameters to create a "fast baseline". Specifically, the number of epochs is reduced to 15 per phase, and 5-fold cross-validation is maintained. This ensures the pipeline fits within the time limit while still leveraging the full dataset (2400 training images).
2.  **Data Loading**: Training, validation, and test datasets are loaded using the provided `load_data` utility, which utilizes cached numpy arrays for efficient I/O.
3.  **Phase 1 (Supervised Training)**: A 5-Fold Cross-Validation is executed on the labeled training set. For each fold, a `DepthAwareLinkNet` is trained using `BCEDiceLoss`. The best model from each fold (based on internal validation mAP) is saved for the ensemble.
4.  **Phase 2 (Pseudo-Labeling)**: The ensemble of 5 models from Phase 1 generates predictions for the unlabeled test set using Test-Time Augmentation (TTA). These predictions are binarized (threshold 0.5) to create "pseudo-labels".
5.  **Phase 3 (Retraining)**: The models are retrained from scratch. The training set for each fold is augmented with the entire pseudo-labeled test set. This step allows the models to learn from high-confidence predictions on the test distribution.
6.  **Final Evaluation**: The retrained Phase 3 ensemble is evaluated on the hold-out validation set (`val.csv`). The binarization threshold is optimized via a linear search to maximize the Mean Average Precision (mAP). The final metric is printed in the required format.
7.  **Failure Analysis**: The script calculates the error (1 - IoU) for each validation image and computes the Pearson correlation between error and two features: depth (`z`) and salt coverage. This identifies systematic weaknesses in the model.
8.  **Submission**: If the final validation metric exceeds the threshold of 0.7916666666666666, the Phase 3 ensemble generates predictions for the test set. These are formatted as Run-Length Encoding (RLE) strings and saved to `submission.csv`.
