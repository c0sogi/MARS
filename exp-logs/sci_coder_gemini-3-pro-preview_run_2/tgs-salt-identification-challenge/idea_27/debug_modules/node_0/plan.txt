### Implementation Strategy

1.  **Environment Setup**: Initialize the environment by setting a fixed random seed for reproducibility using the provided `set_seed` utility. Define a dedicated working directory (`./working/demo_execution`) to store checkpoints and temporary files, ensuring clean separation from existing data.

2.  **Data Loading & Subsetting**:
    *   Instantiate the `SaltDataset` for training, validation, and testing modes.
    *   To satisfy the "Optimize for Speed" requirement, manually slice the internal data arrays of these dataset objects to retain only a small subset (e.g., 32 samples). This ensures the demonstration runs quickly while still exercising the full data loading pipeline.
    *   Wrap these subsets in PyTorch `DataLoader`s.
    *   **Verification**: Assert that the batch shapes yielded by the loaders match the expected dimensions (Batch Size, Channels, Height, Width).

3.  **Model Initialization**:
    *   Instantiate the `ResNet34WideLinkNet` model and move it to the available device (GPU/CPU).
    *   **Verification**: Perform a dummy forward pass with random noise to verify that the model architecture produces outputs with the correct shapes for both segmentation logits and depth predictions.

4.  **Training Loop Execution**:
    *   Set up the `MultiTaskLoss` criterion and an Adam optimizer.
    *   Initialize the `SaltTrainer` class.
    *   Execute the `fit` method for a minimal number of epochs (e.g., 2) using the subsetted data.
    *   **Verification**: Check that the training process generates a `best_model.pth` checkpoint file.

5.  **Inference & Post-Processing**:
    *   Load the best model checkpoint.
    *   Run the `optimize_threshold` function on the validation subset to determine the optimal binarization threshold.
    *   **Verification**: Assert that the calculated threshold is a valid probability (0.0 to 1.0).

6.  **Submission Generation**:
    *   Use the `generate_submission` function to predict masks for the test subset and save the results to a CSV file.
    *   **Verification**: Load the generated `submission.csv` to confirm it contains the correct columns (`id`, `rle_mask`) and that the RLE strings are valid.

7.  **Utility Verification**:
    *   Perform a unit test on the `rle_encode` and `rle_decode` functions to ensure that encoding a mask and immediately decoding it results in the original array.
