Implementation Strategy:
1.  **Configuration & Setup**: Import the provided library modules. Override `Config` parameters to minimize runtime (1 epoch, small batch size, limited folds) and ensure reproducibility.
2.  **Data Preparation**: Use `prepare_data` to load the dataset. Crucially, slice the returned data arrays to a very small subset (e.g., 32 samples) to ensure the demonstration completes almost instantly while still exercising the data loading and processing logic.
3.  **Component Verification**: Instantiate the `SaltNet` model (both Teacher and Student configurations) and the custom losses (`LovaszHingeLoss`, `StudentLoss`). Perform a dummy forward pass to verify tensor shapes and loss calculation.
4.  **Pipeline Simulation**: Instead of calling the high-level `run_stage_X` functions (which contain hardcoded performance thresholds that a quick demo won't meet), manually execute the core logic of the three stages:
    *   **Stage 1 (Teacher)**: Train a Teacher model for one epoch on the subset and validate.
    *   **Stage 2 (Marginalization)**: Use the trained Teacher to generate soft pseudo-labels for the test subset.
    *   **Stage 3 (Student)**: Train a Student model using both labeled data and the generated pseudo-labels.
5.  **Inference**: Optimize the threshold on the validation set and generate a submission file using the Student model.
6.  **Assertions**: Include assertions throughout to verify data shapes, output types, and file creation.
