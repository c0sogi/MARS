The following script demonstrates the usage of the provided library modules for the Notebook Cell Ordering task.

### Implementation Strategy

1.  **Configuration Override**: We modify the `Config` class attributes at runtime to enable `DEBUG` mode, reduce dataset size (50 notebooks), and lower model complexity (fewer trees, smaller dimensions). This ensures the demonstration runs quickly within the time limit.
2.  **Utility Validation**: We verify the `compute_kendall_tau` metric function using a synthetic case with a known number of swaps to ensure scoring logic is correct.
3.  **Component-Level Testing**:
    *   **Data Loader**: We load the training dataset using `NotebookLoader` and verify that the resulting DataFrame contains the expected columns and correct number of rows for the debug sample.
    *   **Vectorization**: We initialize `SemanticSpace`, fit it on the loaded data, and verify that TF-IDF and SVD transformations produce matrices of the correct shape.
    *   **Feature Engineering**: We use `AnchorEngine` to compute the multi-view features (lexical and latent similarities) and assert that the output contains the specific feature columns required for the model.
    *   **Modeling**: We instantiate `Stage1Ridge` and `Stage2LGBM`, train them on the processed features, and verify that they produce predictions of the correct shape.
4.  **Pipeline Integration**: Finally, we instantiate the `RankingPipeline` class and execute the full end-to-end workflow (`execute_training` and `predict_submission`). This confirms that all components interact correctly to produce a submission file.
5.  **Output Suppression**: We monkey-patch `tqdm` to disable progress bars as per the requirements.
