The `LightGBMError: Length of labels differs from the length of #data` was caused by a row duplication issue in `runfile.py`. Specifically, the `add_metadata_features` function attempted to map `cell_id` back to notebook `id` by merging with `df_cells`. Since `cell_id` is not globally unique (e.g., due to forks), this merge created a Cartesian product for duplicate cells, causing the feature matrix to grow larger than the target vector.

To fix this, I will:
1.  Update `library/anchor_engine.py` to explicitly include the notebook `id` in the extracted features, ensuring the identifier propagates correctly through the pipeline (Cite debug_lesson_2).
2.  Modify `runfile.py` to remove the problematic merge on `cell_id` and instead use the `id` column that is now preserved in the features, ensuring strict alignment between features and labels (Cite debug_lesson_3).
3.  Update `library/config.py` to point to a new working directory (`idea_22`), ensuring that stale caches (which lack the `id` column) are invalidated and regenerated.
