The implementation strategy involves orchestrating the Dual-View Stacked Ranking pipeline directly within `runfile.py` using the provided component classes (`DataLoader`, `DualViewFeatureGenerator`, `Stage1Ridge`, `Stage2LGBM`). This approach is necessary because the provided `OrderingPipeline` class does not expose the validation predictions or metrics required for the mandatory failure analysis and conditional submission logic.

The script will proceed as follows:
1.  **Setup & Configuration**: Initialize the environment, set random seeds, and define sample sizes for a fast baseline run (e.g., 10,000 training samples).
2.  **Data Loading**: Load a subset of training and validation data using `DataLoader` with `debug=True` to ensure the process completes within the time limit.
3.  **Feature Engineering**: Generate TF-IDF, LSA, and Dual-View Anchor (Lexical + Semantic) features using `DualViewFeatureGenerator`.
4.  **Stage 1 Training (Ridge)**: Train the sparse lexical regressor on TF-IDF features, generate Out-Of-Fold (OOF) predictions for training data, and predict on validation data.
5.  **Stage 2 Training (LightGBM)**: Train the gradient boosting model using the stacked features (Ridge predictions + Anchor features + LSA).
6.  **Validation & Metric**: Predict ranks for the validation set, reconstruct the cell order, and compute the Kendall Tau metric. The result is printed strictly as `Final Validation Metric: <value>`.
7.  **Failure Analysis**: Calculate the absolute error of predictions on the validation set and compute/print correlations between the error and key features (e.g., character length, anchor similarities) to identify failure modes.
8.  **Conditional Submission**: Check if the validation metric exceeds the threshold (`0.7959...`). If passed, load the **full** test set, generate features, run inference through both stages, sort the cells, and save `submission.csv`.
