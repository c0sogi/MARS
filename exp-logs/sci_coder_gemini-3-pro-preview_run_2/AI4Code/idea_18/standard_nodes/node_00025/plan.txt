The implementation strategy follows a streamlined version of the provided workflow, optimized for the "Fast Baseline" requirement while ensuring all specific task constraints are met.

1.  **Setup & Configuration**: The script initializes the environment and random seeds. It detects if a GPU is available and dynamically updates the LightGBM parameters in the `Config` class to enable GPU acceleration (`device='gpu'`) for faster training.
2.  **Data Loading & Subsampling**: It loads the training and validation datasets using `NotebookProcessor`. To satisfy the time limit and "fast baseline" constraint, the training set is subsampled to 30,000 notebook groups (ancestors). The validation set is kept intact to ensure accurate metric reporting.
3.  **Feature Engineering**: The global vectorizers (TF-IDF, SVD) are fitted on the subsampled training data. Feature extraction is performed for both stages. For the training set, caching is disabled to ensure features correspond exactly to the subsampled data.
4.  **Stage 1 (Ridge) Training**: A 5-fold GroupKFold cross-validation is performed on the subsampled training data to generate Out-Of-Fold (OOF) predictions. The final Stage 1 model is then fitted on the entire subsampled training set.
5.  **Stage 2 (LightGBM) Training**: Multi-view instance-based features are generated. The OOF predictions from Stage 1 are added as features. The LightGBM model is trained with early stopping using the validation set.
6.  **Validation & Metric**: The model predicts on the validation set. The predictions are converted into cell orders, and the Kendall Tau correlation is computed and printed in the required format (`Final Validation Metric: <value>`).
7.  **Failure Analysis**: The script calculates the absolute error of the rank predictions on the validation set. It computes and prints the Pearson correlation between the error and the input features to identify sources of systematic failure.
8.  **Submission**: If the validation metric exceeds the specified threshold (0.7959...), the inference pipeline is triggered. This involves loading the test set, generating Stage 1 and Stage 2 predictions, sorting the cells based on the predicted ranks, and saving the `submission.csv`.
