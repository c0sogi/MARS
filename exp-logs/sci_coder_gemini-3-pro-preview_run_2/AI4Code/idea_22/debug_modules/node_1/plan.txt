The issue is that LightGBM internally canonicalizes the metric name `mae` (Mean Absolute Error) to `l1`. Consequently, when the code attempts to retrieve the validation score using the key `mae` from `model.best_score["valid"]`, it fails with a `KeyError` because the actual key present is `l1`. This mismatch between the configuration string and the library's runtime behavior requires synchronizing the code to handle the canonical name. Cite debug_lesson_5.

I will update `library/modeling.py` to attempt retrieving the score using the canonical key `l1` first, falling back to `mae` if necessary.
