The issue is caused by a discrepancy between how the LightGBM model is saved and how it is loaded. In the demo configuration, the model path ends with `.joblib`, causing `save_artifacts` to serialize it using `joblib.dump`. However, `Stage2LGBM.predict` unconditionally attempts to load the model using `lgb.Booster(model_file=...)`, which expects LightGBM's native text or binary format, resulting in a `LightGBMError`. To fix this, I will modify `Stage2LGBM.predict` to check the file extension: if it ends in `.txt`, it will use the native loader; otherwise, it will use `joblib.load`, mirroring the logic in `save_artifacts`.
