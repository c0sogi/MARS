# Proposed Strategy: Faster R-CNN with Decoupled Data Validation Pipeline

Based on the failure analysis of the previous RetinaNet attempt, I propose a structural evolution focusing on a **Two-Stage Detection Architecture** and a **Decoupled Data Ingestion Pipeline**. The primary failure mode identified was the silent suppression of data loading errors, leading to a trivial model. This strategy explicitly mitigates that risk while moving to a more accurate detection paradigm suitable for medical imaging.

## Model
I propose replacing the single-stage RetinaNet with a **Faster R-CNN** architecture equipped with a **ResNet-50-FPN** backbone.
*   **Two-Stage Design:** Unlike RetinaNet, Faster R-CNN utilizes a Region Proposal Network (RPN) to first generate candidate regions of interest (RoIs) before classifying and refining them. This two-stage process typically yields higher localization accuracy for small, subtle findings (like nodules or masses) and handles the extreme foreground-background imbalance of medical images more robustly than focal loss alone.
*   **Backbone:** We will utilize a ResNet-50 backbone pre-trained on ImageNet, integrated with a Feature Pyramid Network (FPN) to capture pathology at various scales (from small pneumothorax edges to large cardiomegaly).

## Data
To address the critical failure of the previous attempt, I will implement a **Decoupled Offline Preprocessing Pipeline** rather than loading DICOMs on-the-fly during training.
*   **Ingestion & Validation:** We will create a standalone script to convert all DICOM images to high-quality PNGs or NumPy arrays before training begins. This script will utilize `rasterio` (which leverages GDAL) to read the DICOM files. Crucially, we will implement **strict validation assertions**: every loaded image must be checked to ensuring the pixel value sum is greater than zero and the variance is non-trivial. If a file fails to load or results in a black image, the script will raise an immediate exception rather than falling back to zeros. Cite {solution_lesson_node_00001}.
*   **Normalization:** Since DICOM headers (Window Center/Width) are difficult to parse without specific libraries, we will apply Min-Max normalization per image to scale pixel intensities to the 0-255 range during conversion, preserving the relative contrast required for diagnosis.
*   **Caching:** The converted images will be saved to the local fast storage. The training data loader will then read these verified PNG/NPY files, guaranteeing that the model never receives empty inputs.

## Training
*   **Loss Functions:** We will use the standard Faster R-CNN losses: Binary Cross-Entropy for the RPN objectness, Cross-Entropy for the final classification, and Smooth L1 Loss for bounding box regression.
*   **Sampling Strategy:** We will utilize the provided group-stratified metadata to ensure the validation set is representative. To handle the "No finding" class (Class 14), we will treat these images as background samples. The RPN will naturally sample negative regions from these images, teaching the model to suppress false positives on healthy scans.
*   **Optimizer:** We will use SGD with Momentum (0.9) and a linear warmup followed by cosine decay, which is standard for stabilizing the training of two-stage detectors.

## Evaluation
*   **Inference:** The model will predict bounding boxes on the test set (converted using the same robust pipeline).
*   **Prediction Formatting:** We will apply Non-Maximum Suppression (NMS) to merge overlapping boxes.
    *   If valid detections exist (confidence > threshold), we output the class and box.
    *   If no detections remain after NMS (or all confidences are low), we explicitly output the "No finding" prediction string: `14 1 0 0 1 1`. This aligns with the "No finding" logic learned implicitly by the RPN.
