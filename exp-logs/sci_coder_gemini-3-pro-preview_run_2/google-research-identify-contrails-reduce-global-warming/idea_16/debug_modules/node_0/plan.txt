Implementation Strategy:
1.  **Configuration Setup**: Override the default `Config` parameters to create a "Demo Mode". This includes setting a unique project directory, reducing the number of epochs to 1, setting a small batch size, and limiting the training/validation dataset sizes to 20 samples each to ensure the script completes quickly.
2.  **Utility Verification**: Validate the correctness of the helper functions. specifically `rle_encode` (using a known binary mask pattern) and `dice_coef` (using known tensor inputs) to ensure metric calculations are accurate.
3.  **Dataset & Pipeline Verification**: Instantiate the `ContrailDataset` with the limited metadata. Fetch a single sample to verify the data loading logic, including the shape of the generated 6-channel input tensor and the corresponding mask.
4.  **Model Architecture Verification**: Initialize the `ConvNeXtUNet` model. Perform a forward pass with a dummy batch of data to confirm that the input flows correctly through the encoder, decoder, and pyramid fusion head, producing an output of the expected shape `(B, 1, 256, 256)`.
5.  **Loss Function Verification**: Instantiate the `HybridLoss` class and compute the loss between the model's output and a dummy target. Assert that the loss is a valid scalar and that gradients can be backpropagated.
6.  **Full Training Loop Execution**: Execute the `train_model()` function from the library. This serves as an integration test, ensuring the data loader, model, optimizer, and loss function work together without runtime errors.
7.  **Inference Execution**: Create a subset of the test metadata (to save time) and execute the `inference()` function. Verify that the submission file is generated correctly and follows the required format.
