The implementation strategy is as follows:

1.  **Configuration Overrides**: To satisfy the "fast baseline" requirement while maintaining enough performance to potentially pass the submission threshold, I will set the training epochs to 5 and use the full training dataset (as the A100 GPU is sufficiently fast to process ~18k images in a few minutes per epoch).
2.  **Training**: I will invoke the `train_model` function from the `library.train` module. This handles the training loop, validation monitoring, and checkpointing of the best model.
3.  **Evaluation & Failure Analysis**:
    *   I will implement a custom evaluation routine that loads the best saved model and iterates over the validation dataset in inference mode (`eval`, `no_grad`).
    *   I will calculate the **Global Dice** score across the entire validation set to satisfy the metric reporting requirement.
    *   Simultaneously, I will compute per-sample Dice scores. I will map these scores back to the validation metadata (accessed via the dataset object) to calculate the correlation between the model's error (1 - Dice) and metadata features (Time of day, Month, Latitude/Longitude).
4.  **Submission**:
    *   I will compare the calculated Global Dice against the strict threshold provided (0.5676456935477064).
    *   If the model passes, I will call `predict_and_submit` from `library.predict` to generate the run-length encoded submission file for the test set.
