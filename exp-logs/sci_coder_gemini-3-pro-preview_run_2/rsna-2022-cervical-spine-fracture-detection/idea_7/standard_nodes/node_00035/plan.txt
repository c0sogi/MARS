To resolve the `torch.OutOfMemoryError`, I will reduce the memory footprint of the model by decreasing the input image resolution and sequence length, and enabling gradient checkpointing.

1.  **Reduce Input Dimensions**: The error analysis identifies that the effective batch size (Batch Size × Sequence Length) of 120 images at $384 \times 384$ resolution exceeds the GPU memory capacity. I will reduce the image size to $256 \times 256$ and the sequence length to 48 in both `runfile.py` (which overrides the config) and `library/config.py` (to set safe defaults). This significantly lowers the memory required for storing activations (Cite debug_lesson_1).
2.  **Enable Gradient Checkpointing**: I will modify `library/model.py` to enable gradient checkpointing on the backbone. This trades a small amount of computation for significant memory savings. I will use the `set_grad_checkpointing` method instead of passing it as a constructor argument to avoid potential `TypeError`s with the factory function (Cite debug_lesson_5).
