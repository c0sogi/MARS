The previous execution failed with a CUDA Out of Memory (OOM) error because the effective batch size (Batch Size × Sequence Length) passed to the 2D backbone was too large for the GPU memory (Cite debug_lesson_1). Specifically, processing 4 batches of 96 slices (384 images) simultaneously exceeded the memory capacity. Additionally, to prevent the validation logic from loading a stale checkpoint if the new training run fails or produces NaNs, we must clean up existing artifacts before training starts (Cite debug_lesson_11).

To fix this:
1.  **Reduce Batch Size:** In `library/config.py`, I will lower `batch_size` from 4 to 2 to halve the memory footprint.
2.  **Increase Gradient Accumulation:** In `library/config.py`, I will increase `accum_iter` from 4 to 8 to maintain the same effective optimization batch size.
3.  **Optimize Memory Allocation:** In `library/config.py`, I will set `PYTORCH_CUDA_ALLOC_CONF=expandable_segments:True` to reduce memory fragmentation.
4.  **Clean Stale Artifacts:** In `runfile.py`, I will add logic to delete `best_model.pth` before training begins.
