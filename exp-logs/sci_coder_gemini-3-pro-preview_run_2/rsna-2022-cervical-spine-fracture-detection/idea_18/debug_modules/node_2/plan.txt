The issue is that `load_checkpoint` in `library/utils.py` blindly prepends `Config.working_dir` to any non-absolute path. Since `library/inference.py` constructs a full relative path (e.g., `./working/demo_execution/best_model.pth`) and passes it to this function, the directory path gets duplicated (e.g., `./working/demo_execution/./working/demo_execution/best_model.pth`), causing a `FileNotFoundError`.

To fix this, I will modify `load_checkpoint` to prioritize checking if the provided `filename` exists as-is. If it does, that path is used. Only if the direct path does not exist and is relative will the function attempt to resolve it relative to `Config.working_dir`. This ensures compatibility with both bare filenames and valid relative paths.
