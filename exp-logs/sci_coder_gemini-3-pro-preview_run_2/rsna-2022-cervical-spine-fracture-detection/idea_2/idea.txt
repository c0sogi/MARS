# Proposed Solution: Sequential 2.5D Multiple Instance Learning Network

## Model
The proposed architecture evolves the solution from a "Bag of Slices" approach to a **Spatially-Aware Sequential Network**. This addresses the limitation of the previous MIL design, which treated slices as independent or unordered instances, ignoring the strict anatomical ordering of the spine.

1.  **2.5D Input Representation:**
    Instead of passing a single grayscale slice (replicated 3 times) to the CNN, the input will be formed by stacking **3 adjacent slices** along the channel dimension (i.e., slices $z-1$, $z$, and $z+1$). This introduces a "2.5D" local context, allowing the 2D CNN to detect features that persist across depth (like fracture lines) while filtering out single-slice noise or artifacts.

2.  **CNN Feature Extractor:**
    A lightweight, pre-trained 2D CNN (e.g., EfficientNet-B0 or ResNet18) processes these 2.5D inputs to extract feature vectors for each spatial location in the sequence.

3.  **Sequential Context Modeling (Bi-LSTM):**
    **Structural Innovation:** Insert a **Bidirectional LSTM (Bi-LSTM)** layer after the CNN backbone.
    The sequence of CNN embeddings (representing the spine from top to bottom) is passed through the Bi-LSTM. This allows the model to refine the feature representation of a specific vertebra based on the context of the vertebrae above and below it, effectively modeling the anatomical structure of the spine.

4.  **Embedding-Space Aggregation:**
    The output of the Bi-LSTM (context-aware embeddings) is aggregated into a single study-level feature vector using **Attention-based Pooling**. This retains the successful strategy of aggregating high-dimensional embeddings rather than scalar probabilities, avoiding the information bottleneck (Cite solution_lesson_node_00005).

## Data
1.  **Dataset-Encapsulated 3D Augmentation:**
    Geometric augmentations (random affine transformations including rotation, translation, and scaling) will be implemented directly within the `Dataset.__getitem__` method. This ensures that the exact same random transformation parameters are applied to every slice in the volume, preserving the physical alignment of the spine (Cite solution_lesson_node_00010).

2.  **2.5D Slice Loading:**
    The data loader will uniformly sample a fixed number of slices (e.g., 64) to represent the volume. For each sampled index $i$, the loader will retrieve slices $i-1$, $i$, and $i+1$ to construct the 3-channel image. Boundary conditions (first/last slices) will be handled by padding with the nearest valid slice.

## Training
1.  **Gradient Accumulation:**
    To accommodate the increased memory footprint of the 2.5D input and LSTM layer without sacrificing optimization stability, **Gradient Accumulation** will be used. This allows the model to train with a small physical batch size (to fit in GPU memory) while maintaining a sufficiently large *effective* batch size (e.g., 8 or 16 studies) to ensure stable gradient convergence (Cite solution_lesson_node_00007).

2.  **Loss Function:**
    The model will be optimized using the competition's **Weighted Multi-Label Logarithmic Loss** applied to the final study-level predictions.

## Evaluation
The inference pipeline will mirror the training data preparation:
1.  Load the test study.
2.  Uniformly sample slices and construct 2.5D inputs (stacking neighbors).
3.  Pass the sequence through the CNN-LSTM-Attention pipeline.
4.  Output the final probabilities for the 8 target labels.
