Based on the comprehensive analysis of the provided lessons and the trajectory of previous ideas, I propose the following optimized strategy. This approach structurally evolves the solution by introducing a **Calibrated Progressive Resolution Curriculum**, specifically designed to solve the "EMA Lag" and "Regularization Conflict" issues identified in the most recent lessons.

# Model
I propose using the **ConvNeXt Small** architecture, initialized with pre-trained ImageNet-1k weights.
*   **Architecture**: We will utilize **ConvNeXt Small** (approx. 50M parameters). This model has been proven to outperform the "Tiny" variant and ResNet baselines when trained to convergence **(Cite solution_lesson_node_00027)**.
*   **Weight Averaging with Phase Reset**: We will implement **Model EMA (Exponential Moving Average)**. However, to address the latency issue identified in **Lesson 00030**, we will implement a **Phase Reset Strategy**. Instead of maintaining a continuous EMA across resolution changes (which causes the shadow weights to lag with "coarse" features), we will re-initialize the EMA weights to match the model weights at the start of the fine-tuning phase. This ensures the inference model immediately benefits from the high-resolution features.
*   **Internal Regularization**: We will implement **Stochastic Depth (Drop Path)** with a rate of 0.4 to prevent co-adaptation **(Cite solution_lesson_node_00011)**.

# Data
*   **Preprocessing**: We will strictly utilize **PIL (Python Imaging Library)** for image loading to ensure native alignment with the augmentation pipeline **(Cite solution_lesson_node_00010)**.
*   **Augmentation Pipeline**:
    1.  **Geometric**: **RandomResizedCrop** is mandatory. It forces the model to learn scale-invariant features and prevents memorization of global image patterns **(Cite solution_lesson_node_00013)**.
    2.  **Photometric**: **RandAugment** will be used for automated, diverse distortions **(Cite solution_lesson_node_00005)**.
    3.  **Mixing**: **MixUp and CutMix** will be applied dynamically based on the training phase (see Training).

# Training
*   **Strategy (Structural Innovation)**: We will implement **5-Fold Stratified Cross-Validation** with a **Calibrated Progressive Curriculum**. This leverages the 24-hour budget to ensure full convergence for all folds **(Cite solution_lesson_node_00022)** while optimizing the feature extraction quality.
    *   **Phase 1 (Coarse Feature Learning)**: Train with input resolution **$224 \times 224$** for the first ~60% of epochs.
        *   **Regularization**: Apply **MixUp/CutMix** with probability **0.5**. This balances the need for regularization against the need for the model to see "clean" data for convergence **(Cite solution_lesson_node_00023)**.
        *   **Loss**: Soft Target Cross-Entropy.
    *   **Phase 2 (Fine-Grained Resolution Tuning)**: Increase input resolution to **$384 \times 384$** for the remaining ~40% of epochs.
        *   **Regularization Annealing**: **Disable MixUp/CutMix (p=0.0)**. This allows the model to focus purely on resolving high-frequency spatial details (spots, textures) without the noise of interpolation **(Cite solution_lesson_node_00023)**.
        *   **Loss**: Cross-Entropy with **Label Smoothing (0.1)** **(Cite solution_lesson_node_00006)**.
*   **Batch Size**: We will maintain an effective **Batch Size of 32** (using Gradient Accumulation during Phase 2 if necessary) to leverage implicit gradient noise for generalization **(Cite solution_lesson_node_00008)**.
*   **Optimizer**: **AdamW** with a **Cosine Annealing** scheduler **(Cite solution_lesson_node_00005)**.

# Evaluation
*   **Ensemble Inference**: The final submission will be generated by averaging the softmax probabilities from the **EMA weights** of all **5 Fold Models**. By strictly isolating the folds and ensuring fresh execution, we avoid stale artifacts **(Cite solution_lesson_node_00028)**.
*   **Test Time Augmentation (TTA)**: We will average predictions from the original and a horizontally flipped view for each image to leverage orientation invariance **(Cite solution_lesson_node_00013)**.
