The previous implementation suffered from **data leakage** because it evaluated the 5-fold cross-validation ensemble on a fixed hold-out set (`metadata/val.csv`) that was a subset of the training data used by 4 out of the 5 models. This resulted in an artificially low validation metric.

To fix this, I will implement **Out-Of-Fold (OOF) Validation**. I will modify the `runfile.py` script to:
1.  Iterate through each fold, train the model, and then immediately generate predictions on that fold's specific validation set (which the model has not seen).
2.  Accumulate these OOF predictions and targets across all folds.
3.  Calculate the final log loss metric using these aggregated OOF predictions.
4.  Increase the submission threshold to `0.4` to reflect the realistic performance expected from a valid evaluation.

This strategy ensures that the reported metric represents the model's ability to generalize to unseen data.
