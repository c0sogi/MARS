The implementation strategy follows the requirements to orchestrate the "GeM-Augmented Wide-Body Network" pipeline.

1.  **Setup & Initialization**: The script initializes the environment by setting random seeds for reproducibility and detecting the compute device (GPU).
2.  **Data Pipeline**: It triggers the `process_and_cache_data` function to load the JSON datasets, apply global normalization, and cache the processed tensors. This ensures consistent data is available for both training and inference.
3.  **Cross-Validation Loop**: The script iterates through 5 stratified folds. For each fold:
    *   It calls `run_fold_training` to train the model with Early Stopping and save the best checkpoint.
    *   It immediately loads the best checkpoint for that fold and performs inference on the validation set.
    *   It collects predictions, targets, and metadata (incidence angles, image statistics) to build an Out-Of-Fold (OOF) dataset.
4.  **Metric Calculation**: Once all folds are processed, it aggregates the OOF predictions and calculates the global Log Loss. This is printed as the "Final Validation Metric".
5.  **Failure Analysis**: The script calculates the absolute error for each validation sample. It then computes and prints the Pearson correlation between the error magnitude and key input features (`inc_angle`, image mean intensity, image standard deviation) to diagnose performance bottlenecks.
6.  **Conditional Submission**: Finally, it compares the Final Validation Metric against the target threshold (0.15744). If the model performs sufficiently well, it calls `generate_submission` to create the ensemble prediction file for the test set.
