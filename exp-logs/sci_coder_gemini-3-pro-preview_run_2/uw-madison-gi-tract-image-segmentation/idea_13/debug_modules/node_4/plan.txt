The issue is that the `segmentation_models_pytorch` (smp) library's `UnetPlusPlus` implementation does not accept a `deep_supervision` argument in its constructor. The current code attempts to enable this feature by passing `deep_supervision=Config.DEEP_SUPERVISION` to the model, but this argument is ignored (passed to the encoder kwargs), resulting in the model returning a standard single output tensor instead of the expected list of tensors. This causes the `AssertionError` in `runfile.py` because the test expects a list when `Config.DEEP_SUPERVISION` is True.

To fix this, I will:
1.  Disable `DEEP_SUPERVISION` in `library/config.py` to align the configuration with the library's actual behavior and the model's output.
2.  Remove the invalid `deep_supervision` argument from the `smp.UnetPlusPlus` initialization in `library/model.py`.
