### Implementation Strategy

1.  **Configuration Override**: We first modify the `Config` class attributes to adapt the pipeline for a quick demonstration. This includes enabling `DEBUG` mode to use a small subset of data, setting epochs to 1, and redirecting file paths to a dedicated `./working/demo` directory to avoid conflicts.
2.  **Data Pipeline Verification**: We utilize `get_dataloaders` to fetch a training batch. We assert the correctness of the input tensor shapes (Batch, Channels, Height, Width) and the binary nature of the masks.
3.  **Model Architecture Verification**: We instantiate both the `GhostUNet` (Coarse) and `EfficientNetUNet` (Fine) models. We perform a forward pass with dummy data to confirm that the output shapes match the expected segmentation map dimensions.
4.  **Loss Function Verification**: We test `BCEDiceLoss` and `TverskyLoss` with the model outputs and ground truth masks to ensure they return valid scalar loss values.
5.  **Training Loop Execution**: We instantiate the `Trainer` for both stages and run `fit()`. This demonstrates the full training cycle, including backpropagation and model checkpointing, on the reduced dataset.
6.  **Inference & Submission**: We create a small subset of the test metadata to speed up the inference step. We then run the `InferenceEngine` to generate predictions using the newly trained (albeit undertrained) models and verify the format of the resulting `submission.csv`.
7.  **Metric Utilities**: We perform unit tests on the `calculate_dice` and `calculate_hausdorff` functions using synthetic 3D volumes to verify the scoring logic.
