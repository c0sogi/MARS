### Idea 10: 2.5D ShuffleNet-PSPNet

#### Model
I propose a **2.5D PSPNet** architecture. This design introduces the **Pyramid Pooling Module (PPM)**, a distinct architectural philosophy from the Encoder-Decoder (U-Net), Dilated Convolutions (DeepLab), and Feature Pyramids (FPN) used in previous ideas. It focuses on aggregating global context through pooling rather than convolution.

*   **Backbone (Encoder):** The model utilizes a **ShuffleNetV2** backbone pre-trained on ImageNet. This backbone is chosen for its **Channel Shuffle** operation, which enables information exchange between feature channels with significantly lower computational cost than the depthwise separable convolutions of MobileNet or the dense connections of ResNet. This ensures the baseline remains extremely lightweight.
*   **Context Module (PPM):** The core component is the Pyramid Pooling Module attached to the end of the backbone. Instead of using dilated convolutions to expand the receptive field (as in Idea 3), the PPM applies **Adaptive Average Pooling** to the feature map at four distinct grid scales (e.g., 1x1, 2x2, 3x3, and 6x6). This captures global priors (the overall spatial arrangement of the abdomen) and coarse sub-region context simultaneously.
*   **Decoder:** The pooled feature maps are upsampled to the size of the backbone's output via bilinear interpolation and concatenated with the original feature map. A final convolution block processes this fused representation to predict the class probabilities.
*   **Input:** The model processes **2.5D inputs** (3 channels: Slice $i-1$, Slice $i$, Slice $i+1$) to incorporate volumetric context into the 2D network.

#### Data
The data preparation strategy prioritizes simplicity and consistency to establish a stable baseline.

1.  **2.5D Stack Generation:** For every target slice, we construct a 3-channel image consisting of the target slice flanked by its immediate superior ($i-1$) and inferior ($i+1$) neighbors. Replicate padding is used for the first and last slices of a scan.
2.  **Min-Max Normalization:** We apply min-max normalization to each 3-channel stack, scaling pixel intensities to the range $[0, 1]$. This standardizes the MRI data, which often varies in intensity ranges between cases.
3.  **Resizing:** All input images are resized to a fixed resolution of **256x256** pixels. This resolution is sufficient for the PPM to generate meaningful context grids while ensuring rapid training.
4.  **Balanced Sampling:** To handle class imbalance efficiently, the training set is constructed using all positive slices (containing masks) and a random subsample (e.g., 50%) of negative slices (background).

#### Training
The training pipeline uses a classic optimization strategy often favored for PSPNet architectures to ensure robust generalization.

*   **Loss Function:** We employ a composite **Cross Entropy + Dice Loss**. Cross Entropy ensures accurate pixel-level classification probabilities, while Dice Loss directly optimizes the overlap metric.
*   **Optimizer:** **SGD with Momentum** is used instead of Adam. While SGD may require slightly more epochs, it often leads to better generalization on unseen data for ResNet/ShuffleNet-based architectures.
*   **Scheduler:** A **Poly Learning Rate Policy** is implemented. The learning rate is decayed by $(1 - \frac{iter}{max\_iter})^{power}$ (typically power=0.9). This is the standard, proven scheduler for PSPNet training.
*   **Augmentation:** Only lightweight augmentations are applied: Random Horizontal Flips and Vertical Flips.

#### Evaluation
The evaluation process includes specific post-processing to minimize the Hausdorff distance error.

1.  **Inference:** The model generates probability maps for every slice in the test set using the 2.5D input format.
2.  **Thresholding:** A fixed threshold (0.5) is applied to binarize the predictions.
3.  **3D Connected Component Analysis:** To optimize the **3D Hausdorff distance**, the predicted 2D masks are stacked into 3D volumes for each case. We identify 3D connected components for each class and **retain only the largest connected component**, discarding smaller floating artifacts (noise) that would otherwise severely penalize the Hausdorff metric.
4.  **Submission:** The refined masks are converted to Run-Length Encoding (RLE) for the final submission.
