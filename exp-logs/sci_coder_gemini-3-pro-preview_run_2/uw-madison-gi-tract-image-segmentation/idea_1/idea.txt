To establish a highly efficient and robust baseline, I propose a solution that synthesizes the lightweight feature extraction of Model 5 (MobileNetV2) with the structural efficacy of Model 1 (U-Net), while stripping away computational bottlenecks like Attention Gates or ASPP modules.

### Model
The architecture is a **2.5D MobileNetV2 U-Net**.
*   **Encoder**: We utilize **MobileNetV2** pre-trained on ImageNet as the backbone. This encoder is chosen for its "inverted residual" blocks, which provide a superior trade-off between parameter count and feature abstraction compared to EfficientNet-B0 or ResNet. It extracts multi-scale features at strides of 2, 4, 8, 16, and 32.
*   **Decoder**: Instead of the complex "All-MLP" decoder of Model 2 or the ASPP of Model 5, we employ a standard **U-Net Decoder**. This decoder progressively upsamples low-resolution feature maps (using bilinear interpolation) and concatenates them with the corresponding high-resolution maps from the encoder (skip connections). This recovers spatial details essential for organ boundary definition.
*   **Head**: A simple 1x1 convolution maps the final feature map to 3 class channels (Stomach, Small Bowel, Large Bowel) plus a background channel, followed by a Sigmoid activation.
*   **Input**: To capture 3D volumetric context without the cost of 3D convolutions, the model accepts **2.5D inputs**. The input tensor has 3 channels comprising the target slice $i$, the superior neighbor $i-1$, and the inferior neighbor $i+1$.

### Data
Preprocessing focuses on normalizing the high-variance MRI pixel data and formatting it for the 2.5D architecture.
1.  **Slice Extraction**: For every slice in the dataset, we construct a 3-channel image. If a neighbor slice is missing (at the start or end of a scan), we use replicate padding (duplicating the current slice).
2.  **Normalization**: MRI pixel intensities (uint16) are not standardized. We apply **Min-Max Normalization** per volume or per slice, clipping the top 1% of outliers to prevent intensity spikes from skewing the scaling. The data is scaled to the $[0, 1]$ range.
3.  **Resizing**: To ensure consistent batch processing and reduce memory footprint, all images are resized to a fixed resolution of **256x256** pixels.
4.  **Augmentation**: We apply minimal augmentations to prevent overfitting while maintaining speed: horizontal/vertical flips and slight random rotations ($\pm 10^\circ$).

### Training
The training process is designed for stability and fast convergence.
*   **Loss Function**: We use a composite loss of **BCE (Binary Cross Entropy) + Dice Loss**. BCE stabilizes the pixel-wise classification, while Dice Loss directly optimizes the overlap metric used in the competition.
*   **Optimizer**: **AdamW** is used for its efficiency in handling weight decay, with a starting learning rate of 1e-3.
*   **Scheduler**: A **Cosine Annealing** learning rate scheduler is implemented to gradually lower the learning rate, helping the model settle into a robust local minimum.
*   **Strategy**: We train on all available slices containing masks and a subsample of empty slices (background) to handle class imbalance without discarding too much negative context.

### Evaluation
*   **Inference**: We iterate through the test set, generating 2.5D inputs for each slice as done in training. The model predicts probability maps for the three classes.
*   **Post-Processing**:
    1.  **Thresholding**: A fixed threshold (e.g., 0.5) is applied to the probability maps to generate binary masks.
    2.  **3D Consistency**: Since the metric includes 3D Hausdorff distance, we treat the stack of 2D predictions as a 3D volume. Small isolated noise (tiny clusters of pixels) is removed using morphological opening.
*   **Submission**: The final binary masks are converted to the required Run-Length Encoding (RLE) format for submission.
