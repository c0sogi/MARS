# Proposed Solution: Context-Enriched DeBERTa-v3-Large Cross-Encoder with Expected Value Scoring

### Model
**Architecture:**
We will utilize a **Cross-Encoder** architecture based on the **`microsoft/deberta-v3-large`** backbone. This choice is driven by the finding that Cross-Encoders significantly outperform Bi-Encoders for high-precision semantic scoring (Cite solution_lesson_node_00003). The "Large" variant is feasible given the A100 GPU and offers superior natural language understanding compared to the "Small" or "Base" models.

**Structural Innovation (Classification Head & Pooling):**
Instead of a simple linear regression head, we will implement a **5-Class Classification Head**. The output layer will have 5 neurons corresponding to the discrete similarity levels defined in the dataset: `{0.0, 0.25, 0.5, 0.75, 1.0}`.
Additionally, we will replace the standard `[CLS]` token pooling with **Attention Pooling** (a weighted average of the last hidden states), which allows the model to dynamically emphasize the most informative tokens in the sequence before classification.

### Data
**Preprocessing (Context Enrichment):**
A key weakness in previous iterations was the under-utilization of the `context` column (CPC codes like "A47"). We will structurally enhance the input by mapping these codes to their **textual descriptions** using a predefined dictionary derived from the CPC scheme (e.g., mapping "A47" to "Furniture; Domestic Articles or Appliances").
*   **Format:** The input sequence will be constructed as:
    `[CLS] Context Description [SEP] Anchor [SEP] Target [SEP]`
    This allows the model to "attend" to the explicit domain definition when evaluating the relationship between the anchor and target.

**Validation Strategy:**
We will employ **Stratified K-Fold Cross-Validation (K=5)**, stratifying by the `score` column. This ensures that the label distribution in every validation fold mirrors the training set, preventing bias towards the majority class (0.50).

### Training
**Loss Function:**
We will use **Cross-Entropy Loss** treating the problem as a multi-class classification task. This avoids the "regression to the mean" problem often seen with MSE loss on discrete ordinal data.
*   **Label Smoothing:** We will apply mild label smoothing (e.g., 0.1) to prevent the model from becoming overconfident in the expert annotations, which may contain subjective noise.

**Optimization:**
*   **Optimizer:** AdamW with a weight decay of 0.01.
*   **Scheduler:** Linear decay with a warmup period (10% of total steps).
*   **Precision:** Mixed Precision (FP16) to maximize training speed and batch size on the A100 GPU.

### Evaluation
**Inference (Expected Value):**
To generate the final scalar `score` for submission (which requires a continuous value for Pearson correlation), we will not output the argmax class. Instead, we will compute the **Expected Value** of the predicted probability distribution:
$$ \text{Score} = \sum_{i \in \{0, 0.25, 0.5, 0.75, 1.0\}} P(\text{class}_i) \times i $$
This approach yields a smooth, continuous score that captures the model's uncertainty (e.g., a split probability between 0.5 and 0.75 results in a score of 0.625), which is mathematically optimal for maximizing correlation metrics.
