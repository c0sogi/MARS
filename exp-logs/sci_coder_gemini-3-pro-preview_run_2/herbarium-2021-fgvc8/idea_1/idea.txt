Based on the dataset characteristics (high cardinality, long-tailed distribution, hierarchical taxonomy) and the requirement for a simple, efficient baseline distinct from the provided examples, I propose the following solution.

### Model: Taxonomy-Regularized Multi-Task ResNet

**Architecture Design**
The model utilizes a **Multi-Task Learning (MTL)** framework to leverage the biological hierarchy inherent in the dataset.
*   **Backbone:** A standard **ResNet-18**, chosen for its balance between inference speed and feature extraction capability. It is significantly lighter than the EfficientNet or Transformer models listed in the previous ideas.
*   **Heads:** Instead of a single classification layer, the backbone feeds into **three parallel linear classification heads**:
    1.  **Species Head:** Predicts the specific `category_id` (64,500 classes).
    2.  **Family Head:** Predicts the `family` label (Auxiliary Task).
    3.  **Order Head:** Predicts the `order` label (Auxiliary Task).
*   **Rationale:** In a long-tailed dataset, rare species (1-2 samples) are difficult to learn in isolation. However, these rare species share visual characteristics with other members of their *Family* or *Order*. By forcing the backbone to predict the higher-level taxonomy (which has abundant data per class), the model learns robust, generalized features that prevent overfitting on rare species. Unlike Model 4 (which uses hard routing to separate GBDTs), this is a fully differentiable, end-to-end neural network.

### Data

**Preprocessing**
1.  **Taxonomy Mapping:** Parse `train/metadata.json` to create mapping dictionaries: `Species ID -> Family ID` and `Species ID -> Order ID`. Encode the string labels for families and orders into integer targets.
2.  **Image Resizing:** Resize all images to **224x224** pixels. This standard resolution minimizes I/O and compute overhead compared to larger sizes, fitting the "speed" requirement.
3.  **Normalization:** Normalize pixel values using standard ImageNet mean and standard deviation to accelerate convergence.
4.  **Augmentation:** Apply only minimal augmentations (e.g., horizontal flip) to maintain high throughput and simplicity.

### Training

**Procedure**
*   **Loss Function:** A weighted sum of Cross-Entropy losses:
    $$L_{total} = L_{species} + \lambda_1 L_{family} + \lambda_2 L_{order}$$
    where $\lambda_1$ and $\lambda_2$ are set to 1.0 or 0.5. This ensures the gradients from the easier, data-rich tasks (Family/Order) stabilize the learning of the backbone.
*   **Optimizer:** Use **AdamW** with a standard learning rate (e.g., 1e-3) and weight decay.
*   **Strategy:** Train for a fixed number of epochs (e.g., 10-15) or use early stopping based on the validation Macro F1 score of the *Species* head. This avoids the complexity of multi-stage training.

### Evaluation

**Inference Process**
1.  **Forward Pass:** Pass the test images through the network.
2.  **Prediction:** Ignore the output of the Family and Order heads. Take the **argmax** of the **Species Head** output vector to obtain the predicted `category_id`.
3.  **Submission:** Map the predicted index to the final label and save to CSV.
