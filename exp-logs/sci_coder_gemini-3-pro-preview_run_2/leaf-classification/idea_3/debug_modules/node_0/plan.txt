### Implementation Strategy

1.  **Environment Setup**: Initialize random seeds using `library.utils.set_seed` and define temporary directories in `./working` to ensure the demonstration does not interfere with existing caches.
2.  **Component Verification (Unit Tests)**:
    *   **Feature Pipeline**: Verify `FeatureProcessor` by creating synthetic data, fitting the processor, and asserting that the output shapes for both scaled and PCA-transformed views are correct.
    *   **Model Definitions**: Instantiate Logistic Regression, LDA, and GPC using the factory functions in `library.model_definitions`. Train them on small synthetic data to ensure they fit and predict without errors.
    *   **Ensemble Logic**: Instantiate `HybridEnsemble` from `library.ensemble_manager`. Verify the `fit` and `predict_proba` methods using the synthetic feature views (scaled and PCA) to ensure the soft voting mechanism works and produces valid probabilities.
3.  **Data Management Verification**: Call `library.data_manager.load_and_merge_data` to process the actual metadata files. Verify that the training and validation sets are correctly merged (checking sample counts) and that label encoding is consistent.
4.  **Full Pipeline Execution (Integration Test)**: Execute `library.ensemble_manager.run_pipeline` using the real dataset. This function orchestrates data loading, ensemble training, and submission generation.
5.  **Output Validation**: Check the generated submission file from the pipeline run to ensure it follows the required format (correct columns, row count, and value ranges).
