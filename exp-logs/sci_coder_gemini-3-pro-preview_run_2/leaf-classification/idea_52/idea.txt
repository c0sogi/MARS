Based on the comprehensive analysis of the previous experiments and the distilled lessons, I propose the **Component-Wise Polynomial Precision-Generative Ensemble (CW-PPGE)**.

This strategy structurally evolves the "Orthogonal Preprocessing Views" (Idea 45, Lesson 109) and "Precision-Generative" (Idea 30) concepts. It addresses the limitation that while the Global Linear model is excellent (Lesson 63), it cannot capture **non-linear interactions** (e.g., quadratic dependencies). Since expanding the full global feature set ($P=192$) polynomially is infeasible ($D \gg N$), and standard QDA is unstable (Lesson 94), I propose decomposing the features into their semantic components (Margin, Shape, Texture) to generate **Component-Specific Quadratic Views**. These are integrated into a library alongside Global Linear and Physical experts, managed by **Greedy Forward Selection**.

# Model
The solution utilizes a **Dynamic Ensemble Selection** architecture. We generate a library of probabilistic experts defined by distinct **Preprocessing Topologies** and **Feature Scopes**, allowing the ensemble to exploit Global Linear, Physical Non-Linear, and Component-Specific Non-Linear signals simultaneously.

### 1. The Expert Library
All experts operate in **double precision (`float64`)** to strictly minimize numerical noise at the metric floor (Cite `solution_lesson_node_00073`).

*   **Group A: Global Linear Anchors (The Baseline)**
    *   **Input:** Global View (192 provided features).
    *   **Topologies:**
        1.  **Marginal:** `PowerTransformer(method='yeo-johnson')`.
        2.  **Rotational:** `PowerTransformer` $\rightarrow$ **PCA(whiten=False)** $\rightarrow$ `PowerTransformer`. (Aligns data without noise amplification, Cite `solution_lesson_node_00104`, `solution_lesson_node_00109`).
    *   **Algorithm:** **Linear Discriminant Analysis (LDA)** with **OAS** (Cite `solution_lesson_node_00090`) and **Fixed Shrinkage** (`[0.001, 0.01]`, Cite `solution_lesson_node_00081`).
    *   **Role:** Preserves the state-of-the-art baseline, modeling global linear correlations with robust covariance estimation.

*   **Group B: Physical Polynomial Experts (The Domain Signal)**
    *   **Input:** **Polarity-Corrected Morphometrics** (Hu Moments + Geometric Scalars).
        *   *Correction:* Invert images if corner mean > 0.5 to ensure leaf is foreground (Cite `solution_lesson_node_00106`).
    *   **Pipeline:** `PowerTransformer` $\rightarrow$ **PolynomialFeatures(degree=2)** $\rightarrow$ `PowerTransformer`.
    *   **Algorithm:** **LDA** (Ledoit-Wolf).
    *   **Rationale:** Captures non-linear physical constraints (e.g., $Solidity \times Eccentricity$) from raw images, treating them as an orthogonal view (Cite `solution_lesson_node_00050`).

*   **Group C: Component-Wise Polynomial Experts (The Innovation)**
    *   **Input:** Split the 192 features into three subsets: **Margin** (64), **Shape** (64), and **Texture** (64).
    *   **Pipeline (per subset):** `PowerTransformer` $\rightarrow$ **PCA(n_components=0.95)** $\rightarrow$ **PolynomialFeatures(degree=2)** $\rightarrow$ `PowerTransformer`.
    *   **Algorithm:** **LDA** (OAS/Fixed).
    *   **Rationale:** While Global Quadratic expansion is impossible, Component-wise expansion is feasible. By isolating "Texture", densifying it via PCA, and then expanding it polynomially, we can model complex **intra-component interactions** (e.g., non-linear texture patterns) that the Global Linear model misses. The Greedy Selector will combine these specific non-linear signals with the Global Linear baseline, strictly avoiding the signal dilution of naive concatenation (Cite `solution_lesson_node_00063` context).

*   **Group D: Discriminative-Subspace Expert**
    *   **Input:** Global View.
    *   **Pipeline:** `PowerTransformer` $\rightarrow$ **LDA(n_components=15)** $\rightarrow$ **PolynomialFeatures(degree=2)** $\rightarrow$ `PowerTransformer`.
    *   **Algorithm:** **LDA** with Shrinkage.
    *   **Rationale:** Projects global features onto the most class-discriminative axes before expansion, creating a "Bottleneck Quadratic" view.

### 2. Selection Mechanism
*   **Greedy Forward Selection:** We employ the selection strategy from Lesson 56. We iteratively add experts to the ensemble *if and only if* they maximize the improvement in Validation Log Loss (Cite `solution_lesson_node_00056`).

# Data
1.  **Feature Engineering:**
    *   **Global View:** Load the provided 192 feature vectors.
    *   **Component Views:** Slice the Global View into Margin (cols 0-63), Shape (64-127), Texture (128-191).
    *   **Morphometric View:** Load raw binary images.
        *   **Polarity Correction:** Check corner pixels; if mean > 0.5 (white), invert image (Cite `solution_lesson_node_00106`).
        *   **Extraction:** Extract **Hu Moments** (7 invariants) and **Geometric Scalars** (Aspect Ratio, Solidity, Extent, Eccentricity) (Cite `solution_lesson_node_00050`).
2.  **Preprocessing:**
    *   **Precision:** Cast **all** feature matrices to `float64` (Cite `solution_lesson_node_00073`).
    *   **Pipelines:** Apply the specific transformation sequences (Marginal, Rotational, Component-Poly, Physical-Poly) to generate the feature views.
    *   **Leakage Prevention:** Transformers are fit on the training split and applied to the test split.

# Training
The training procedure rigorously separates the Selection phase from the Final Retraining phase to maximize data utilization (Cite `solution_lesson_node_00010`).

1.  **Phase 1: Selection (Train/Val Split)**
    *   Split training data (80/20).
    *   **Train Library:** Train all experts (Groups A-D $\times$ Shrinkage Estimators) on the 80% split.
    *   **Generate Predictions:** Compute `float64` probability matrices on the 20% hold-out set.
    *   **Run Selection:** Apply Greedy Forward Selection (with replacement) to determine the optimal subset of experts and their integer weights.

2.  **Phase 2: Final Retraining (Full Data)**
    *   Retrain *only* the selected experts on the **Combined Training + Validation Set**.
    *   Use the exact hyperparameters (e.g., shrinkage values, PCA components) identified in Phase 1 to prevent configuration drift (Cite `solution_lesson_node_00028`).

# Evaluation
1.  **Inference:**
    *   Extract Polarity-Corrected Morphometrics for the Test set.
    *   Process the test set through the retrained pipelines of the selected experts.
2.  **Aggregation:**
    *   Compute the final submission probabilities using the **Weighted Average** determined in Phase 1.
