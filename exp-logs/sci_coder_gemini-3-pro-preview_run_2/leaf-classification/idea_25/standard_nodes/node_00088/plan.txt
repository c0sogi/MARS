The error `ValueError: y has only 1 sample in class 3` is caused by the pipeline loading a stale cache file (`train_features_mc.parquet`) that was generated during a previous debug run (`DEBUG_MODE=True`) where the dataset was subsampled to 50 rows. Even though `DEBUG_MODE` is now `False`, the system reuses this small file and performs an inner join with the full metadata, effectively discarding the majority of the training data and leading to extreme class imbalance (Cite debug_lesson_8).

To fix this, I will modify `library/config.py` to incorporate the `DEBUG_MODE` state into the cache filenames (e.g., `train_features_mc_full.parquet` vs. `train_features_mc_debug.parquet`). This ensures that toggling the debug flag automatically invalidates the cache and forces the regeneration of the appropriate dataset size. I will also reorder the configuration sections so that `DEBUG_MODE` is defined before it is used in the path construction.
