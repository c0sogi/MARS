The `RuntimeError: cuDNN error: CUDNN_STATUS_EXECUTION_FAILED` is caused by two issues related to target labels in the `PlantDataset` and loss function:

1.  **Sparse Species Labels (Cite debug_lesson_1):** The dataset contains `category_id`s up to 15505, but the model is configured for 15501 classes (the actual number of unique taxa). Passing a raw `category_id` $\ge$ 15501 as a target index causes a device-side assertion error because it exceeds the model's output dimension. We must map these sparse IDs to a contiguous range `[0, 15500]`.
2.  **Invalid Ignore Index (Cite debug_lesson_6):** The dataset currently uses `-1` as the default value for missing genus/family IDs. However, `nn.CrossEntropyLoss` uses `-100` as the default `ignore_index`. Passing `-1` as a target class is invalid (since class indices must be $\ge 0$) and triggers an execution failure.

To fix this, I will:
1.  Update `library/config.py` to generate a contiguous `species_label` mapping and ensure the cache is refreshed.
2.  Update `library/utils.py` to expose the `species_to_label` and `label_to_species` mappings.
3.  Update `library/dataset.py` to use `species_label` as the training target and `-100` as the default for missing auxiliary labels.
4.  Update `library/train.py`, `library/inference.py`, and `runfile.py` to map the contiguous predictions back to the original `category_id`s for submission and analysis.
