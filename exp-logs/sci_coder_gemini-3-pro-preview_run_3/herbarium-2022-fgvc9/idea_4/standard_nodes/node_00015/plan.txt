The `RuntimeError: cuDNN error: CUDNN_STATUS_EXECUTION_FAILED` during the backward pass is caused by a mismatch between the default value used for missing hierarchical labels (`-1`) and the default `ignore_index` of PyTorch's `nn.CrossEntropyLoss` (`-100`). The `PlantDataset` assigns `-1` to auxiliary targets (Genus/Family) when mappings are missing, but the loss function treats `-1` as a valid class index (since it is not `-100`), leading to an illegal memory access on the GPU (Cite {debug_lesson_6}).

To fix this, I will:
1.  Update `library/utils.py` to use `-100` instead of `-1` when filling missing values in the hierarchy mapping.
2.  Update `library/dataset.py` to initialize the lookup arrays with `-100`.
3.  Update `library/dataset.py` to explicitly convert any remaining `-1` values (e.g., from cached metadata) to `-100` in the lookup tables, and set the fallback value to `-100`.
