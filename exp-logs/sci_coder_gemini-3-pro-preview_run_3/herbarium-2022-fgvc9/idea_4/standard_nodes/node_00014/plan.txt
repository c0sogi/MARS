The error `RuntimeError: cuDNN error: CUDNN_STATUS_EXECUTION_FAILED` during `loss.backward()` is caused by an index out-of-bounds access on the GPU. The dataset contains `category_id` values up to 15505, but there are only 15501 unique classes, and the model is configured with `NUM_CLASSES = 15501`. Passing raw, sparse IDs (e.g., 15505) to `CrossEntropyLoss` exceeds the model's output dimension (0-15500), triggering the crash.

To fix this, I will implement a bidirectional mapping between the raw sparse `category_id`s and contiguous indices `[0, 15500]`.
1.  **`library/utils.py`**: Update `process_hierarchy_mappings` to generate a contiguous `label_id` for each category and ensure the cache is refreshed to include this new column.
2.  **`library/dataset.py`**: Update `PlantDataset` to create a lookup table (`species_lookup`) mapping raw IDs to contiguous `label_id`s, and return these mapped labels during training/validation.
3.  **`library/inference.py`**: Update the prediction logic to map the model's output (contiguous indices) back to the original `category_id`s using the hierarchy metadata before generating the submission file.
