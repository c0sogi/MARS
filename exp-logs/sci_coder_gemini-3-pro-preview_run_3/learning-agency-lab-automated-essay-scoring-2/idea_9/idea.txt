Based on the progression of experiments and the available 24-hour computational budget, I propose a **Hybrid-Objective K-Fold Ensemble Strategy**.

This solution structurally evolves the pipeline from a single-objective approach (Idea 8) to a **multi-objective ensemble**. It addresses the limitations of relying solely on MSE (which assumes linear distances between ordinal classes) by integrating an **Ordinal Classification** model, while strictly adhering to the "Full Data" requirement established in Lesson 20.

### Model
*   **Dual-Backbone Architecture**: The solution employs two parallel `deberta-v3-large` backbones (Cite solution_lesson_node_00014).
    *   **Model A (Regression Expert)**: Uses a standard linear head trained with **Mean Squared Error (MSE)**. This preserves the distance-sensitive properties that align with the QWK metric (Cite solution_lesson_node_00001).
    *   **Model B (Ordinal Expert)**: Uses a multi-head binary classification structure trained with **Ordinal Binary Cross-Entropy (BCE)**.
        *   *Mechanism*: It predicts 5 binary probabilities: $P(Score > 1), P(Score > 2), ..., P(Score > 5)$. The final score is derived from the sum of these probabilities + 1.
        *   *Innovation*: This captures the probabilistic uncertainty and non-linear thresholds between scores that MSE might smooth over.
*   **Pooling Mechanism**: Both models utilize **Attention Pooling** applied to the **final hidden layer** (Cite solution_lesson_node_00013) to dynamically weight informative tokens.
*   **Stacking Head**: A **LightGBM** regressor serves as the meta-learner. It takes the concatenated OOF predictions from both Model A and Model B, along with **Explicit Meta-Features** (Cite solution_lesson_node_00004).

### Data
*   **Full-Scale Stratified Cross-Validation**: Partition the `train.csv` dataset into **5 Stratified Folds**. Crucially, we will use the **entire dataset** for training, rejecting the subsampling strategy that caused failure in previous experiments (Cite solution_lesson_node_00020).
*   **Context Processing**: Apply a **sliding window** approach (e.g., 512 tokens with stride) to process full texts. The embeddings/predictions for all chunks of an essay will be averaged to generate the document-level representation.
*   **Meta-Feature Engineering**: Calculate structural scalar features (character count, word count, sentence count, unique word ratio) to be injected at the stacking stage (Cite solution_lesson_node_00002).

### Training
*   **Stage 1: Backbone Fine-Tuning (Parallel Streams)**
    *   **Optimization**: Use **Layer-wise Learning Rate Decay (LLRD)** and **Gradient Checkpointing** to manage the memory footprint of the Large models (Cite solution_lesson_node_00014). Use the unified **`torch.amp`** API for mixed precision (Cite solution_lesson_node_00012).
    *   **Adversarial Regularization**: Apply **Adversarial Weight Perturbation (AWP)** to both models. With the 24-hour budget, we can afford the 2x compute cost of AWP on the full dataset to maximize generalization (Cite solution_lesson_node_00020).
    *   **Cache Management**: Implement strict **hash-based cache invalidation** to ensure Stage 2 never loads stale features (Cite solution_lesson_node_00015).
*   **Stage 2: Stacking**
    *   Train the LightGBM regressor on the combined OOF predictions (from Model A and Model B) and meta-features.
    *   **Regularization**: Set `feature_fraction` < 1.0 to force the GBM to utilize the model predictions and prevent over-reliance on length features (Cite solution_lesson_node_00006).

### Evaluation
*   **Inference**:
    *   Pass test essays through both fine-tuned ensembles (Model A and Model B, 5 folds each).
    *   Generate two distinct prediction signals (Regression Score and Ordinal Probability Score).
*   **Prediction**: Feed these signals and the meta-features into the LightGBM stacker.
*   **Post-Processing**: Clip predictions to [1, 6] and round to the nearest integer to maximize the Quadratic Weighted Kappa (Cite solution_lesson_node_00001).
