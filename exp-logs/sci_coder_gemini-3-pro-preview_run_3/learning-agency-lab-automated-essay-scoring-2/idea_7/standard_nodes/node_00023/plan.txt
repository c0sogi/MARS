The issue stems from using a hardcoded value of `-1e9` to mask padding tokens in the attention mechanism. When mixed precision training is enabled, the model operates with `float16` tensors, which have a minimum representable value of approximately -65,504. Attempting to use `-1e9` causes an overflow error because it falls outside the range of `float16`. To fix this, I will replace the hardcoded constant with `torch.finfo(w.dtype).min`, which dynamically retrieves the lowest representable number for the tensor's current data type, ensuring compatibility with mixed precision.
