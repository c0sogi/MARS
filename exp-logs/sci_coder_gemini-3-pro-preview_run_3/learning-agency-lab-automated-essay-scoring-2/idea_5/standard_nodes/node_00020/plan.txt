The issue is **Data Leakage** in the evaluation of the Stacking model. The original code trained the LightGBM stacker on the full dataset (`X_full`) and then evaluated it on the same dataset to compute the final metric, leading to an invalid, overly optimistic score.

To fix this, I will:
1.  **Update `library/stacking.py`**: Modify `LGBMStacker.train` to accept an optional `eval_set`. This allows the caller to provide specific validation data, which is necessary for Cross-Validation (CV).
2.  **Update `runfile.py`**: Implement a Stratified K-Fold CV loop for the stacker. This will generate Out-Of-Fold (OOF) predictions for the stacker stage, ensuring that the metric is calculated on data the model has not seen during training. The final submission model will still be retrained on the full dataset.
