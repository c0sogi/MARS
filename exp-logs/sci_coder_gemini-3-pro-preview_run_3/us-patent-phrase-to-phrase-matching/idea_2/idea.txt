# Cross-Encoder Transformer with Pre-trained Knowledge

### Model
I propose replacing the Siamese Deep Averaging Network with a **Transformer-based Cross-Encoder**. 

The previous attempt failed because the "neural bag-of-words" learned from scratch lacked the external world knowledge required to map synonyms (e.g., "mobile" and "cell") to nearby points in vector space. To address this, I will incorporate the lesson to **initialize with pre-trained representations to inject linguistic topology** (Cite solution_lesson_node_00001). However, rather than using static vectors (like GloVe), I will leverage a pre-trained Transformer backbone (e.g., `deberta-v3-small` or similar).

Structurally, this moves from a **Siamese architecture** (where inputs are encoded independently and combined heuristically) to a **Cross-Encoder architecture**. In this design, the `anchor`, `target`, and `context` are concatenated into a single input sequence. This allows the model's self-attention mechanism to directly model the complex interactions and dependencies between the phrase pairs and their technical context at the token level, rather than relying on simple distance metrics between averaged vectors. A simple linear regression head will be placed on top of the `[CLS]` token output to predict the similarity score.

### Data
1.  **Input Formatting:** Instead of treating inputs as separate tensors, we will construct a single input string for each sample. To effectively utilize the `context` (CPC code), we will prepend it to the phrases. The format will be: `[CLS] context [SEP] anchor [SEP] target [SEP]`. This allows the model to condition the semantic relationship of the phrases on the specific technical domain (e.g., distinguishing "bridge" in dentistry vs. construction).
2.  **Tokenization:** We will use the specific tokenizer associated with the chosen pre-trained backbone to convert these strings into input IDs and attention masks.
3.  **Dynamic Padding:** To optimize computational efficiency, batches will be dynamically padded to the length of the longest sequence in the batch rather than a fixed global maximum.

### Training
1.  **Loss Function:** We will continue to use **Mean Squared Error (MSE)** loss, as it aligns well with the regression nature of the target scores (0.0 to 1.0).
2.  **Optimizer:** We will use **AdamW** with a standard learning rate (e.g., 2e-5) and weight decay to prevent overfitting.
3.  **Scheduler:** A linear learning rate scheduler with a warmup period (e.g., 10% of total steps) will be employed to stabilize the fine-tuning of the pre-trained weights.
4.  **Freezing:** Optionally, we may freeze the lower layers of the Transformer during the initial epochs to adapt the regression head first, preserving the pre-trained linguistic features.

### Evaluation
1.  **Inference:** The test set pairs will be preprocessed into the same concatenated format and passed through the fine-tuned Cross-Encoder.
2.  **Post-Processing:** The raw scalar outputs will be clipped to the range [0, 1] to ensure valid predictions.
3.  **Submission:** The predicted scores will be mapped to their `id`s and written to the submission CSV.
