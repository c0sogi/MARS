The implementation strategy is as follows:

1.  **Configuration & Setup**: Import the necessary modules and the provided library classes. We will override `Config.debug` to `True` and `Config.epochs` to `1`. This ensures the demonstration runs on a small subset of the data (100 training samples) and finishes quickly.
2.  **Data Loading Verification**: Initialize the tokenizer and call `prepare_loaders`. We will fetch a single batch from the training loader to verify the keys (`input_ids`, `attention_mask`, `labels`) and tensor shapes.
3.  **Model Initialization & Forward Pass**: Instantiate the `CustomModel`. We will perform a dummy forward pass with the fetched batch to confirm the model architecture produces outputs of the correct shape `(batch_size, 1)`.
4.  **Training & Validation Loop**: Set up the optimizer and scheduler using the provided utility functions. We will run `train_one_epoch` and `valid_one_epoch` to demonstrate the training loop. We will assert that the loss is a valid float and the validation score is computed.
5.  **Model Saving**: Manually save the trained model state to `Config.model_path`. This is necessary because the `predict` function expects a saved model checkpoint to exist.
6.  **Inference Pipeline**: Call the `predict` function from `library.inference`. This function handles the full inference process on the test set (loading the saved model, predicting, and saving the submission CSV).
7.  **Submission Verification**: Finally, we will verify that the submission file exists, load it, and check that it contains the expected columns (`id`, `score`) and row count.
