# Optimized Strategy: Domain-Adaptive Context-Aware Cross-Encoder

I propose a structural evolution of the previous strategies by introducing **Domain-Adaptive Pre-training (DAPT)** and **Contextual Description Enrichment**. While previous iterations focused on architectural tweaks (pooling, heads) and regularization (AWP), this solution fundamentally improves the *quality of the input representation* and the *domain alignment* of the backbone itself.

### Model
1.  **Backbone:** We will utilize **`microsoft/deberta-v3-large`** to leverage its superior pre-trained linguistic representations (Cite solution_lesson_node_00001).
2.  **Context-Aware Input Structure:** We will evolve the Cross-Encoder input format. Instead of providing only the opaque CPC code (e.g., "H04"), we will inject the **full textual description** of the CPC classification (e.g., "H04: ELECTRIC COMMUNICATION TECHNIQUE"). The input sequence will be: `[CLS] Context Code [SEP] Context Description [SEP] Anchor [SEP] Target [SEP]`. This allows the model's cross-attention mechanism to explicitly model the semantic relationship between the phrases and their specific technical definition (Cite solution_lesson_node_00008).
3.  **Head Architecture:** We will retain the high-performing **Attention Pooling** mechanism (Cite solution_lesson_node_00011) to aggregate token embeddings. The pooled output will be passed through **Multi-Sample Dropout (MSD)** to two parallel heads:
    *   **Regression Head:** Predicts the continuous score.
    *   **Classification Head:** Predicts the discrete score bucket.
    This dual-head structure (Cite solution_lesson_node_00014) stabilizes the gradient signal.

### Data
1.  **Context Enrichment:** We will construct a mapping dictionary that links each unique `context` code in the dataset to its official CPC text description. These descriptions will be concatenated into the input strings as described above.
2.  **DAPT Corpus Generation:** We will aggregate all unique text data (Context Descriptions, Anchors, and Targets) from both the training and test sets into a single unlabelled corpus.
3.  **Tokenization:** We will use the `deberta-v3-large` tokenizer with dynamic padding to handle the increased sequence length efficiently.

### Training
The training procedure will be split into two distinct stages:

**Stage 1: Domain-Adaptive Pre-training (DAPT)**
Before supervised fine-tuning, we will further pre-train the `deberta-v3-large` backbone on the generated DAPT corpus using a **Masked Language Modeling (MLM)** objective. This step adapts the model's vocabulary and embeddings to the specific technical jargon of patents, ensuring the backbone is not "learning from scratch" regarding domain terminology (Cite solution_lesson_node_00001).

**Stage 2: Supervised Fine-Tuning**
1.  **Loss Function:** We will optimize a **Hybrid Loss** ($L_{Total} = L_{MSE} + \lambda L_{CE}$), combining the geometric constraints of regression with the decision-boundary sharpness of classification (Cite solution_lesson_node_00014).
2.  **Optimization:** We will employ **Layer-wise Learning Rate Decay (LLRD)** (Cite solution_lesson_node_00011) to preserve the DAPT-adapted features in the lower layers while aggressively training the heads.
3.  **Regularization:** We will integrate **Adversarial Weight Perturbation (AWP)** (Cite solution_lesson_node_00012) into the training loop to flatten the loss landscape and prevent overfitting to the specific phrasing of the training set.

### Evaluation
1.  **Inference:** Test inputs will be generated using the same Context Enrichment strategy.
2.  **Prediction:** The model will output raw regression scores (ignoring the classification head).
3.  **Post-Processing:** Scores will be clipped to the [0, 1] range and saved to the submission file.
