Based on the accumulated lessons, I propose the **High-Capacity Smoothed Semantic Regressor (HC-SSR)**. This solution synthesizes the successful explicit feature engineering of the Current Best Solution with the high-capacity modeling attempted in Idea 5, while specifically correcting the data starvation and proximity heuristic flaws that caused previous failures.

# Model
The architecture employs a two-stage pipeline designed to maximize semantic resolution and structural alignment:

1.  **Semantic Backbone (High-Capacity):**
    *   **Architecture:** `sentence-transformers/all-mpnet-base-v2`.
    *   **Rationale:** I replace the lightweight `all-MiniLM-L6-v2` with the more powerful `MPNet` backbone. Previous experiments with high-capacity models failed due to data starvation (Cite solution_lesson_node_00028) or strict adjacency constraints (Cite solution_lesson_node_00027). By applying the correct data strategy (see below) to this stronger backbone, we address the "Lexical Gap" (Cite solution_lesson_node_00004) where generic embeddings fail to link abstract markdown descriptions to specific code implementations.

2.  **Feature Extractor (Smoothed):**
    *   **Innovation:** Instead of extracting features from the raw similarity matrix, I introduce a **1D Smoothing Convolution** (window size=3, kernel=`[0.25, 0.5, 0.25]`) over the code-axis of the similarity vector.
    *   **Rationale:** Markdown cells often describe a *block* of code split across multiple cells. Raw `argmax` is noisy and may pick a single outlier. Smoothing identifies the "dense center" of the semantic match, providing a more robust spatial anchor.
    *   **Features:** From the *smoothed* vector, extract **Spatial Anchors** (`best_match_loc`, `center_of_mass`) (Cite solution_lesson_node_00004) and **Signal Strength** (`sim_max`) (Cite solution_lesson_node_00025).
    *   **Context:** Explicitly include `n_code` and `md_len` to scale predictions (Cite solution_lesson_node_00015).

3.  **Regressor Head:**
    *   **Architecture:** **LightGBM Regressor**.
    *   **Rationale:** Tree-based models consistently outperform end-to-end Transformers when provided with explicit alignment features (Cite solution_lesson_node_00012).

# Data
**Preprocessing:**
1.  **Fine-Tuning Dataset (Relaxed Proximity):**
    *   Construct Positive Pairs $(M, C_{target})$ by pairing every markdown cell $M$ with its **nearest subsequent** code cell $C_{target}$ in the ground truth order.
    *   **Correction:** This explicitly corrects the "Strict Adjacency" flaw from Idea 5, ensuring we generate ~370k training pairs instead of <1k, preventing data starvation for the MPNet backbone (Cite solution_lesson_node_00027).
2.  **Regression Dataset (Full Volume):**
    *   Utilize the **Full Training Dataset** (~95,000 notebooks) for the LightGBM stage.
    *   **Rationale:** High-capacity embeddings contain nuanced signals that require maximum data volume for the regressor to resolve (Cite solution_lesson_node_00009).

# Training
1.  **Stage 1: Contrastive Fine-Tuning**
    *   **Objective:** Optimize **Multiple Negatives Ranking Loss (MNRL)**.
    *   **Procedure:** Train the `all-mpnet-base-v2` backbone for 1 epoch on the Relaxed Proximity pairs. This aligns the embedding space such that markdown cells are topologically close to the code blocks they describe (Cite solution_lesson_node_00025).
2.  **Stage 2: Regression Training**
    *   **Objective:** Minimize **Mean Squared Error (MSE)**.
    *   **Procedure:** Train LightGBM to predict the normalized rank $y \in [0, 1]$ using the smoothed alignment features and global context.

# Evaluation
1.  **Inference:**
    *   Encode all test set cells using the fine-tuned MPNet backbone.
    *   Compute the Pairwise Cosine Similarity Matrix for each notebook.
    *   Apply **1D Smoothing** to the similarity vectors.
    *   Extract features (`best_match_loc`, `center_of_mass`, `sim_max`, `n_code`, `md_len`).
    *   Predict normalized position $\hat{y}$ using LightGBM.
2.  **Ordering:**
    *   Convert $\hat{y}$ to integer rank: $Rank_{pred} = \hat{y} \times n\_code$.
    *   Construct the sequence with Code cells at fixed indices and Markdown cells at $Rank_{pred}$.
    *   Sort to produce the final `cell_order`.
