# Solution: Domain-Adaptive Semantic Alignment Regressor (DASAR)

### Model
I propose a two-stage **Hybrid Architecture** that integrates a fine-tuned semantic backbone with a gradient-boosting regressor. This design directly addresses the "Lexical Gap" identified in failure analyses (Cite solution_lesson_node_00004) while retaining the superior performance of explicit feature engineering over end-to-end deep learning (Cite solution_lesson_node_00012).

1.  **Stage 1: Domain-Adaptive Semantic Backbone**
    *   **Architecture:** A Siamese Network based on the `all-MiniLM-L6-v2` Sentence Transformer.
    *   **Purpose:** Unlike the generic pre-trained model used previously, this backbone is fine-tuned to project markdown cells and their corresponding (subsequent) code cells into a shared embedding space. This ensures that the "Best Match" signal is topologically predictive, not just semantically related (Cite solution_lesson_node_00006).

2.  **Stage 2: Explicit Alignment Regressor**
    *   **Architecture:** A **LightGBM Regressor**.
    *   **Input:** A dense feature vector derived from the similarity matrix produced by the fine-tuned backbone.
    *   **Features:**
        *   **Spatial Alignment:** `best_match_loc` (index of the code cell with max similarity) and `center_of_mass` (similarity-weighted average index). These are prioritized over distributional statistics like entropy to avoid noise (Cite solution_lesson_node_00007).
        *   **Signal Strength:** `sim_max` (value of the highest similarity score) and `sim_mean`.
        *   **Global Context:** `n_code` (total code cells) and `md_len` (markdown length). These are strictly required to scale the normalized position predictions correctly against variable notebook lengths (Cite solution_lesson_node_00015).

### Data
**Preprocessing:**
1.  **Fine-Tuning Dataset:** Construct a dataset of **Positive Pairs** $(M, C_{next})$ from the training notebooks, where $M$ is a markdown cell and $C_{next}$ is the code cell immediately following it in the ground truth order.
2.  **Feature Extraction (Post-Tuning):**
    *   Pass all cells in the full dataset through the *fine-tuned* backbone to generate updated embeddings.
    *   Compute the pairwise Cosine Similarity Matrix for each notebook.
    *   Extract the **Spatial Alignment**, **Signal Strength**, and **Global Context** features defined above.
3.  **Target Generation:** Calculate the normalized rank $y \in [0, 1]$ for each markdown cell ($Position / n\_code$).

### Training
1.  **Phase 1: Contrastive Fine-Tuning**
    *   **Objective:** Optimize **Multiple Negatives Ranking Loss (MNRL)**. This maximizes the similarity of true $(M, C_{next})$ pairs while minimizing the similarity of $M$ to other code cells in the batch.
    *   **Strategy:** Train for 1 epoch on the training set. This is computationally efficient and sufficient to align the vector space for the downstream task.

2.  **Phase 2: Regression Training**
    *   **Objective:** Minimize **Mean Squared Error (MSE)**.
    *   **Strategy:** Train the LightGBM regressor on the **full dataset** (~95k notebooks). Utilizing the maximum data volume is critical for the regressor to resolve the nuanced signals provided by the high-dimensional embeddings (Cite solution_lesson_node_00009).

### Evaluation
1.  **Inference:**
    *   Encode test set cells using the fine-tuned backbone.
    *   Construct the feature vector (Alignment + Global Context) for each markdown cell.
    *   Predict the normalized position $\hat{y}$ using LightGBM.
2.  **Ordering:**
    *   Convert the normalized prediction to an integer rank: $Rank_{pred} = \hat{y} \times n\_code$.
    *   Construct the final sequence by placing code cells at their fixed indices $0, 1, \dots$ and inserting markdown cells at their predicted $Rank_{pred}$.
    *   Sort the combined list to produce the submission `cell_order`.
