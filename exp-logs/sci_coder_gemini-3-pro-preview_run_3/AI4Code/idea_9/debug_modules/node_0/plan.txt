The strategy for the implementation is as follows:

1.  **Setup and Configuration Override**: To ensure the script runs quickly (within the time limit) and uses the provided environment correctly, we will first override the `Config` class attributes. We will define a new working directory (`./working/demo_run`) and point the metadata paths to a new location where we will store small subsets of the original metadata. We will also reduce training hyperparameters like epochs, batch size, and boosting rounds.

2.  **Data Preparation**: We will load the original metadata files from `./metadata`, sample a small number of rows (e.g., 20 notebooks), and save these subsets to our new metadata directory. This ensures that when the library functions call `get_data_splits`, they receive the small datasets, preventing the pipeline from processing the full 140k+ notebooks.

3.  **Pipeline Execution**:
    *   **Data Loading**: Demonstrate `read_notebook` and `create_relaxed_pairs` to verify data access and pair generation logic.
    *   **Fine-Tuning**: Run `train_semantic_model`. This will fine-tune the SentenceTransformer on the small subset of pairs we generated.
    *   **Regression Training**: Run `train_lgbm_regressor`. This will generate features using the fine-tuned model and train the LightGBM ranker.
    *   **Inference**: Run `generate_submission_file` to produce predictions on the test set (also subsetted).

4.  **Validation**: Throughout the process, we will use assertions to verify that files are created (models, features, submissions) and that the metric calculation function works correctly using a manual test case.
