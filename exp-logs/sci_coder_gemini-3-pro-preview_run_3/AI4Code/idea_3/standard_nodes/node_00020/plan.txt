My solution implements the proposed **Contrastive Fine-Tuned Semantic Regressor (CFSR)** pipeline.

### Implementation Strategy

1.  **Configuration & Setup**: I initialize the environment with a fixed random seed and enforce a `DEBUG_SAMPLE_SIZE` of 10,000. This ensures the pipeline (fine-tuning and feature extraction) completes well within the 2-hour limit while providing sufficient data for a robust baseline.
2.  **Contrastive Fine-Tuning**: I instantiate the `FineTuner`. The script checks for an existing fine-tuned model; if absent, it triggers the training loop which optimizes the semantic backbone to align markdown cells with their subsequent code cells using Multiple Negatives Ranking Loss.
3.  **Feature Extraction**: I use the `FeatureExtractor` to generate semantic alignment features (e.g., `best_match_loc`, `center_of_mass`) for the Train, Validation, and Test sets.
4.  **Regression Training**: I train the `RankRegressor` (LightGBM) on the extracted features to predict the normalized position of each markdown cell.
5.  **Validation & Analysis**:
    *   I reconstruct the cell order for the validation set by interleaving markdown cells (sorted by predicted rank) into the fixed sequence of code cells.
    *   I compute and print the **Final Validation Metric** (Kendall Tau).
    *   I perform **Failure Analysis** by calculating the correlation between prediction errors and input features (e.g., notebook length, signal strength) to identify weaknesses.
6.  **Submission**: If the validation score exceeds the threshold (0.7633), the script ensures features are extracted for the *entire* test set (overriding the debug limit if necessary), generates predictions, reconstructs the orders, and saves the `submission.csv`.
