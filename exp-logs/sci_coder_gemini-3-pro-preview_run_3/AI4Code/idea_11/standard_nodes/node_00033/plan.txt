The solution implements the **Multi-Scale Structural Heatmap Regressor (MS-SHR)** pipeline as described.

### Strategy Outline
1.  **Setup & Initialization**: We initialize the configuration and set random seeds to ensure reproducibility.
2.  **Backbone Fine-Tuning**: We train the `SentenceTransformer` (MPNet) backbone using Contrastive Learning on a subset of 40,000 notebook pairs (defined in `Config`). This aligns the semantic vector spaces of code and markdown cells. We use `load_cached_data=True` to utilize pre-processed pairs if available.
3.  **Feature Extraction**: We extract features for the full training and validation sets. This involves encoding all cells with the fine-tuned backbone, computing pairwise similarity matrices, and generating the Multi-Scale Smoothing and Structural Heatmap features. These features are cached to Parquet files to speed up subsequent runs.
4.  **Regressor Training**: We train a LightGBM regressor on the extracted features to predict the normalized rank (0 to 1) of each markdown cell.
5.  **Validation**: We run the full inference pipeline on the validation set to reconstruct cell orders and compute the Kendall Tau correlation. The final metric is printed in the required format.
6.  **Failure Analysis**: We calculate the absolute error of the model's predictions on the validation set and compute the Pearson correlation between this error and the input features. This identifies which features (e.g., markdown length, specific similarity patterns) are associated with higher uncertainty.
7.  **Submission**: If the validation score exceeds the threshold of 0.8061, we generate predictions for the test set and save the `submission.csv` file.
