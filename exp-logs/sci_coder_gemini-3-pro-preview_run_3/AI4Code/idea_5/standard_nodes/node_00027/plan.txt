The `KeyError` during LightGBM training is caused by a schema mismatch between the training and validation feature sets. The pipeline loaded stale training features from `train_features_debug.parquet` (containing columns from a previous `bert-tiny` model) while generating fresh validation features with the current `codebert` and `mpnet` architecture. To fix this, I will modify `runfile.py` to disable cache loading for the training feature generation step (`load_cached_data=False`). This ensures the training features are regenerated using the active model configuration, aligning the schemas and resolving the crash, as per **Cite debug_lesson_8**.
