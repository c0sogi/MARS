# Solution: Multi-View Semantic Alignment with Contextual Smoothing (MVSS)

### Model
I propose a **Multi-View Hybrid Architecture** that integrates two distinct semantic backbones to resolve the "Lexical Gap" from complementary perspectives, coupled with a robust feature extraction strategy that accounts for the block-structure of code.

1.  **Dual-Backbone Semantic Encoder:**
    *   **Code-View Backbone:** `microsoft/codebert-base`. Unlike the generic models used previously, this model is pre-trained on bimodal (Natural Language + Programming Language) data. It is structurally superior for detecting syntactic alignment (e.g., linking "plot" to `matplotlib.pyplot`). (Cite solution_lesson_node_00006)
    *   **Text-View Backbone:** `all-mpnet-base-v2`. This is a larger, more powerful general-purpose Sentence Transformer than the `all-MiniLM-L6-v2` used in previous iterations. It captures high-level semantic abstractions and linguistic nuances that CodeBERT might miss.
    *   **Rationale:** By stacking features from both backbones, the downstream regressor can leverage specific code-token matching (CodeBERT) *and* broad semantic understanding (MPNet), offering a "Stereoscopic" view of the notebook structure.

2.  **Contextual Feature Engineering:**
    *   **Smoothed Similarity:** Markdown cells often describe a *block* of code (multiple cells), not just a single line. A raw `argmax` on the similarity vector can be noisy (picking a single outlier cell). I introduce a **1D Smoothing Convolution** (window size=3) over the code-axis of the similarity matrix.
    *   **Feature Extraction:** From both the *Raw* and *Smoothed* similarity matrices of *both* backbones, extract:
        *   **Spatial Anchors:** `best_match_loc` (index of max similarity) and `center_of_mass` (weighted average index). (Cite solution_lesson_node_00004)
        *   **Signal Strength:** `sim_max` and `sim_mean`. (Cite solution_lesson_node_00025)
    *   **Global Context:** Explicitly include `n_code` (total code cells) and `md_len` (markdown length) to allow the regressor to scale normalized positions correctly. (Cite solution_lesson_node_00015)

3.  **Regressor Head:**
    *   A **LightGBM Regressor** trained on the concatenated feature vector (Code-View + Text-View + Global Context). (Cite solution_lesson_node_00012)

### Data
**Preprocessing:**
1.  **Fine-Tuning Dataset:** Construct a dataset of **Positive Pairs** $(M, C_{next})$ from the training notebooks, where $M$ is a markdown cell and $C_{next}$ is the code cell immediately following it. (Cite solution_lesson_node_00025)
2.  **Feature Generation:**
    *   Pass all cells through *both* fine-tuned backbones.
    *   Compute two Similarity Matrices per notebook (one per backbone).
    *   Apply smoothing and extract the defined features.
3.  **Target:** Normalized rank $y \in [0, 1]$ for each markdown cell.

### Training
1.  **Phase 1: Independent Contrastive Fine-Tuning**
    *   Fine-tune `microsoft/codebert-base` and `all-mpnet-base-v2` *independently* using **Multiple Negatives Ranking Loss (MNRL)**.
    *   **Objective:** Maximize similarity for $(M, C_{next})$ pairs while minimizing it for in-batch negatives.
    *   **Budget:** 1 epoch per model. This is computationally feasible within the 24-hour limit and sufficient for alignment.

2.  **Phase 2: Regression Training**
    *   Train the LightGBM regressor on the **full dataset** (~95k notebooks).
    *   **Objective:** Minimize **Mean Squared Error (MSE)**.
    *   **Strategy:** Utilizing the full dataset is critical for the regressor to resolve the complex interactions between the multi-view features. (Cite solution_lesson_node_00009)

### Evaluation
1.  **Inference:**
    *   Encode test set cells using both fine-tuned backbones.
    *   Generate the stacked feature vector (Code-View + Text-View + Context).
    *   Predict normalized position $\hat{y}$ using LightGBM.
2.  **Ordering:**
    *   Convert $\hat{y}$ to integer rank: $Rank_{pred} = \hat{y} \times n\_code$.
    *   Construct the sequence: Code cells at fixed indices $0, 1, \dots$, Markdown cells at $Rank_{pred}$.
    *   Sort to produce the final `cell_order`.
