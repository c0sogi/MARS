### Implementation Strategy

1.  **Configuration Override**: To ensure the demonstration runs quickly (within minutes) on the provided hardware, I will override specific `Config` class attributes at runtime. I will reduce the number of epochs, warmup epochs, batch size, and image size. I will also switch to a lightweight model (`resnet18`) to minimize download and inference time for the demo.
2.  **Data Preparation**: I will load the metadata using the provided `load_metadata` function but subsample the DataFrames significantly (e.g., 50 training samples, 20 validation samples) to speed up the epoch loops.
3.  **Component Validation**:
    *   **Dataset**: Verify `DogDataset` returns images of the correct shape and valid labels.
    *   **Model**: Instantiate `DogModel`, verify forward pass output shapes, and test the `freeze_backbone`/`unfreeze_backbone` methods by inspecting gradient requirements.
    *   **Engine**: Execute `train_fold` on the subset. This validates the full training loop, including warmup, fine-tuning, and the in-memory greedy model soup.
    *   **Soup (Disk-based)**: Manually save two checkpoint files and utilize `library.soup.create_greedy_soup` to demonstrate and verify the disk-based soup construction logic.
    *   **Inference**: Run `predict_tta` on a small test subset and generate a submission file using `save_submission`.
4.  **Assertions**: I will place assertions after each critical step to ensure the outputs (shapes, types, file existence) match expectations.
