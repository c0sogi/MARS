To optimize the solution, I will implement a **Pointer Head** mechanism for the Locator model as recommended in the lessons. This changes the problem from dense binary classification (per-token) to a sequence-level ranking task, effectively handling the extreme class imbalance. I will also increase the training sample size to 1,000,000 to improve model generalization while staying within the 4-hour time limit.

Here are the specific changes:
1.  **`library/config.py`**: Add `TRAIN_SAMPLE_SIZE` and ensure `DEBUG` is False.
2.  **`library/models.py`**: Modify `LocatorNetwork` to output a single scalar score per token (Cite solution_lesson_node_00001).
3.  **`library/data.py`**: Update `LocatorDataset` to return the target index instead of a one-hot-like sequence, and update `get_dataloaders` to utilize the larger sample size.
4.  **`library/trainer.py`**: Update the Locator training loop to mask padding tokens and use `CrossEntropyLoss` on the sequence dimension.
5.  **`library/inference.py`**: Adapt the inference logic to handle the scalar output from the new Locator architecture.
6.  **`runfile.py`**: Configure the run to use the optimized settings and enforce the validation threshold.
