To address the task of inserting a missing word into a sentence, I propose a **Two-Stage "Locate-and-Fill" Pipeline**. This approach decouples the problem into two distinct sub-tasks: (1) identifying the position of the missing word, and (2) predicting the word itself. This differs fundamentally from the brute-force search of Model 1, the sequence generation of Model 2, and the feature-ranking of Model 3.

### Model
The solution utilizes two lightweight, distinct components sharing a common architectural backbone (e.g., DistilBERT):

1.  **The Locator Model**: A Transformer encoder fine-tuned as a token-level classifier. Instead of predicting masked tokens, this model takes the **incomplete sentence** (without any mask or indicator) as input. A classification head projects the contextual embedding of each token to a binary score, representing the probability that a word is missing *immediately after* this token.
2.  **The Filler Model**: A standard Masked Language Model (MLM). This model takes a sentence with a generic `[MASK]` token inserted at a specific position and predicts the most likely original word for that position.

This architecture is highly efficient for inference: instead of running the model $N$ times for a sentence of length $N$ (as in Model 1), we run the Locator once to find the index, insert the mask, and run the Filler once.

### Data
1.  **Preprocessing**:
    *   The training data (24M sentences) consists of complete sentences. We will create a dynamic data pipeline that generates training samples on the fly.
    *   For each training step, we sample a batch of complete sentences.
    *   For the **Locator**, we uniformly select one word to remove. The target label is the index of the token immediately preceding the removal.
    *   For the **Filler**, we replace the selected word with a `[MASK]` token. The target label is the token ID of the removed word.
2.  **Tokenization**:
    *   We will use a standard subword tokenizer (e.g., WordPiece). We must ensure that the "word" removal aligns with token boundaries (i.e., removing all subword tokens constituting that word).

### Training
We will train the two components separately or sequentially to ensure stability, prioritizing the Locator as it determines the input for the Filler.

1.  **Locator Training**:
    *   **Objective**: Minimize Cross-Entropy Loss over the sequence length.
    *   **Input**: Sentence with one word deleted.
    *   **Target**: One-hot vector corresponding to the position of the deletion.
2.  **Filler Training**:
    *   **Objective**: Standard Masked Language Modeling (MLM) loss.
    *   **Input**: Sentence with one word replaced by `[MASK]`.
    *   **Target**: The original token(s).
    *   *Note*: Since Model 1 already suggests fine-tuning an MLM, we can optionally use a pre-trained MLM off-the-shelf and focus our training budget on the Locator to establish a strong baseline.

### Evaluation
For each sentence in the test set:
1.  **Locate**: Pass the raw test sentence through the **Locator Model**. Apply `argmax` to the output logits to identify the index $k$ with the highest probability of a missing word gap.
2.  **Construct**: Insert a `[MASK]` token into the sentence at index $k+1$.
3.  **Fill**: Pass the masked sentence through the **Filler Model**. Extract the logits for the `[MASK]` token and select the word ID with the highest probability.
4.  **Format**: Decode the predicted token ID into a string and insert it into the original test sentence at the predicted location to generate the final submission.
