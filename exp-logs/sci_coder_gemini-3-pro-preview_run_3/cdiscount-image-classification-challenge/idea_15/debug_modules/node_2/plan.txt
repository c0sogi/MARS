The `ModelTrainer` class in `library/trainer.py` initializes the best accuracy tracker (`self.best_acc`) to `0.0`. During the demo execution, the model achieved a validation accuracy of exactly `0.0`. Because the checkpoint saving logic uses a strict inequality (`if val_acc > self.best_acc`), the condition `0.0 > 0.0` evaluated to `False`, and the model was not saved. This caused the subsequent inference step to load a stale, incompatible model checkpoint that existed in the directory, leading to a key mismatch error. To fix this, I will initialize `self.best_acc` to `-1.0`, ensuring that the first validation result (even if it is `0.0`) is considered an improvement and triggers a save (Cite debug_lesson_1).
