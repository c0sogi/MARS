# Baseline Proposal: Multi-Backbone Feature Fusion with Hierarchical Regularization

### Model
I propose a **Dual-Backbone Feature Fusion Network** that leverages the complementary strengths of two distinct architectural families (CNN and MBConv) to create a robust product representation.
*   **Dual Frozen Backbones:** Instead of relying on a single feature extractor, the model will utilize two pre-trained backbones in parallel:
    1.  **ResNet-50:** Captures robust texture and shape features (2048 dimensions).
    2.  **EfficientNet-B0:** Captures efficient, multi-scale features (1280 dimensions).
    *   *Rationale:* Ensembling diverse architectures typically yields higher performance gains than simply scaling up a single architecture. Both backbones will be **frozen** to maintain the computational efficiency established in **Cite solution_lesson_node_00003**.
*   **Fusion Aggregation:**
    *   For each product, extract features for all images using both backbones.
    *   Apply **Mean Pooling** independently for each backbone to aggregate image features into product features.
    *   **Concatenate** the two resulting vectors to form a single **3328-dimensional** (2048 + 1280) product embedding.
*   **Hierarchical Classification Head:** The fused embedding will be fed into a Multi-Layer Perceptron (MLP) with a **Hierarchical Multi-Task structure**:
    *   **Shared Trunk:** Fully connected layers with Batch Normalization and ReLU.
    *   **Branch 1 (Level 1):** Predicts the 49 coarse categories.
    *   **Branch 2 (Level 2):** Predicts the 483 sub-categories.
    *   **Branch 3 (Level 3 - Target):** Predicts the 5270 fine-grained categories.
    *   *Innovation:* This structure utilizes the taxonomy provided in `category_names.csv` to regularize the learning process, forcing the model to learn semantically consistent features.

### Data
*   **Full-Dataset Decoupled Caching:** I will apply the decoupled feature extraction strategy to the **entire training dataset (~7 million products)**.
    *   *Strategic Retention:* This preserves the extreme speed of the decoupled approach (**Cite solution_lesson_node_00003**).
    *   *Correction:* Processing the full dataset is the direct remedy for the overfitting observed in **Cite solution_lesson_node_00005**. With 7 million samples, the model can effectively support the high dimensionality (3328-dim) of the fused embeddings, avoiding the "curse of dimensionality" that caused the failure on the 100k subset.
    *   *Feasibility:* Storing 7 million x 3328-dim vectors requires ~93 GB of RAM, which fits comfortably within the 220 GB available.
*   **Label Engineering:** Map `category_id` to Level 1 and Level 2 parents to create multi-task targets.

### Training
*   **Feature-Space MixUp:** To compensate for the lack of image augmentation (due to frozen backbones), I will apply **MixUp** directly to the cached feature vectors during training. This interpolates between samples to enforce linear decision boundaries and improve generalization.
*   **Loss Function:** Use a **Multi-Task Sum of Cross-Entropy Losses** ($L_{total} = L_{L3} + L_{L2} + L_{L1}$).
    *   *Correction:* I will explicitly **exclude** inverse-frequency class weights. As demonstrated in **Cite solution_lesson_node_00004**, class weighting optimizes for macro-recall and degrades the target metric (global accuracy). The hierarchical auxiliary tasks will instead provide supervision for rare classes by grouping them into frequent parent categories.
*   **Optimizer:** Use **AdamW** with Weight Decay and **Label Smoothing** (e.g., 0.1) to prevent the model from becoming over-confident on the noisy fine-grained labels.

### Evaluation
*   **Inference Pipeline:**
    1.  Load pre-computed test set features (extracted via both backbones and fused).
    2.  Pass the fused features through the trained Hierarchical MLP.
    3.  Select the category with the highest probability from the **Level 3 Head** as the final prediction.
