### Implementation Strategy

1.  **Configuration Setup**: Modify the global `Config` class attributes to enable `DEBUG` mode and reduce `NUM_EPOCHS` to 1. This ensures the demonstration runs quickly on a small subset of data.
2.  **Utility Verification**: Validate the `rle_encode` and `dice_coefficient` functions using synthetic data to ensure the metric calculation and submission formatting logic are correct.
3.  **Data Loading**: Initialize the data loaders using `get_dataloaders` in debug mode. Fetch a single batch to verify the input tensor shapes (Batch, 6, 256, 256) and mask shapes (Batch, 1, 256, 256).
4.  **Model Initialization and Forward Pass**: Instantiate the `LightUNet` model. Pass the fetched batch through the model to confirm the forward pass works without errors and produces outputs in the expected range [0, 1].
5.  **Loss Calculation**: Instantiate the `DiceBCELoss` and compute the loss on the model outputs and ground truth masks to verify the loss function is operational.
6.  **Full Training Pipeline**: Execute `run_training` (which wraps the training loop, validation, and checkpointing) for one epoch. Verify that the "best model" checkpoint is saved to the working directory.
7.  **Inference Pipeline**: Execute `generate_submission` using the trained checkpoint. Verify that the submission CSV is generated and follows the correct format.
