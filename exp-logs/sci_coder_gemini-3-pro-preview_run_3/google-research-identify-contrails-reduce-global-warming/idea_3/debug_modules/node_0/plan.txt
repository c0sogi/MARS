This implementation strategy demonstrates the functionality of the provided Contrail Identification library. It is designed to run quickly and verify the integrity of the pipeline components.

**Strategy Outline:**
1.  **Configuration Override**: We first import the `Config` class and modify its attributes (enabling `DEBUG` mode, reducing `EPOCHS` to 1, and lowering `BATCH_SIZE`) to ensure the demonstration completes within seconds rather than hours.
2.  **Utility Verification**: We unit-test the `rle_encode` function with a manually constructed binary mask and the `dice_score` function with known tensors to confirm metric calculation logic.
3.  **Dataset Inspection**: We instantiate the `ContrailDataset` in debug mode. We assert that it loads data correctly and produces tensors of the expected shape `(6, 256, 256)` for inputs and `(1, 256, 256)` for masks.
4.  **Model Forward Pass**: We initialize the `UNetPlusPlus` model and perform a forward pass with dummy data to verify that the architecture accepts the 6-channel input and produces the correct output dimensions.
5.  **Full Pipeline Execution**: We instantiate the `ContrailTrainer` and execute its `run()` method. This triggers a complete lifecycle: training for one epoch, validation, checkpoint saving, weight averaging, and inference.
6.  **Artifact Validation**: Finally, we check the filesystem to ensure that checkpoints, the best model weights, and the `submission.csv` file were generated correctly.
