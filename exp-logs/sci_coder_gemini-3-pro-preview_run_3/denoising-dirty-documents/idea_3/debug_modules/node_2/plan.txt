The issue is caused by saving NumPy scalar types (specifically `numpy.float64` returned by `np.sqrt`) into the PyTorch checkpoint. Recent versions of PyTorch default to `weights_only=True` in `torch.load`, which restricts the allowed types for security, causing the `UnpicklingError` when it encounters the unlisted NumPy scalar. To fix this, I will explicitly cast the calculated RMSE values to native Python `float` types before they are returned or saved. This addresses the root cause described in the error analysis and adheres to **Cite debug_lesson_1** regarding casting NumPy scalars at API boundaries.

I will update `library/utils.py`, `library/model.py`, and `library/trainer.py` to ensure RMSE calculations return native floats.
