Based on the analysis of the previous experiments and the derived lessons, I propose the **Channel-Attention Compressed 2.5D Network**.

This solution structurally evolves the "2.5D Stacking" approach by introducing a **Learnable Input Compression Stem**. It directly resolves the conflict between the need for high volumetric information density (Cite solution_lesson_node_00012) and the model capacity constraints that lead to overfitting with high-channel inputs (Cite solution_lesson_node_00013).

# Model
The architecture is a **2.5D Convolutional Neural Network** with a specialized pre-processing stem designed to dynamically filter and compress volumetric data.
1.  **Input:** The model accepts a tensor of shape $(B, 128, 256, 256)$, representing **32 spatial slices** stacked depth-wise for each of the 4 modalities ($32 \times 4 = 128$).
2.  **Channel-Attention Stem:**
    *   **Squeeze-and-Excitation (SE) Block:** The raw input is passed through a global channel attention module. It computes a global descriptor (Global Average Pooling) and learns a weight vector (via two small Fully Connected layers with a reduction ratio) to rescale the 128 input channels.
    *   **Purpose:** This acts as a **soft slice selection** mechanism. The model learns to suppress channels corresponding to empty slices (background/skull) or irrelevant modalities, effectively performing the "ROI-aware selection" recommended in Cite solution_lesson_node_00001 without requiring segmentation masks.
3.  **Channel Bottleneck:**
    *   **Layer:** `Conv2d(in_channels=128, out_channels=64, kernel_size=1, stride=1)`.
    *   **Purpose:** This 1x1 convolution linearly compresses the reweighted 128 channels down to 64. This drastically reduces the parameter count for the subsequent spatial convolution compared to a standard 3x3 kernel (8k params vs 36k params), preventing the parameter explosion and overfitting observed in Cite solution_lesson_node_00013.
4.  **Backbone:** The compressed 64-channel feature map is fed into an **EfficientNet-B0** (modified to accept 64 inputs). This preserves the robust 2D feature extraction capabilities of the architecture.
5.  **Head:** Global Average Pooling followed by a single fully connected layer (Sigmoid activation).

# Data
1.  **Global Volumetric Normalization:** For each patient, load the full 3D volume and normalize pixel intensities based on the global minimum and maximum of that volume. This preserves inter-slice contrast, ensuring that the "empty" slices (which the SE block needs to identify) remain distinct from tissue (Cite solution_lesson_node_00015).
2.  **High-Density Uniform Sampling:** Extract **32 slices** uniformly distributed across the 10%-90% depth range of the MRI volume. This maximizes the volumetric information provided to the model (Cite solution_lesson_node_00012).
3.  **Deterministic Stacking:** Stack the slices to form the 128-channel input. Maintain a consistent sorted order to ensure the physical stride is preserved, allowing the 1x1 convolution to learn consistent cross-channel correlations (Cite solution_lesson_node_00016).
4.  **Library Usage:** Use standard `pydicom` libraries for robust data loading (Cite solution_lesson_node_00020).

# Training
1.  **Optimizer:** Use **Adam** with a learning rate of `1e-4`.
2.  **Regularization:** Do **not** use Weight Decay (AdamW) or aggressive geometric augmentations, as these have been shown to suppress signal learning in this dataset (Cite solution_lesson_node_00007). The bottleneck structure of the stem itself acts as the primary regularizer.
3.  **Loss Function:** **Binary Cross Entropy with Logits Loss**.
4.  **Strategy:** Train end-to-end. The SE block and Bottleneck are initialized randomly and learned simultaneously with the backbone fine-tuning.

# Evaluation
For each subject in the test set:
1.  Load the metadata and file paths.
2.  Apply **Global Volumetric Normalization** and **High-Density Uniform Sampling** (32 slices) to generate the $(128, 256, 256)$ input tensor.
3.  Pass the tensor through the network. The Channel-Attention Stem will automatically highlight the most relevant slices/modalities and compress the information for the backbone.
4.  Output the probability for `MGMT_value`.
