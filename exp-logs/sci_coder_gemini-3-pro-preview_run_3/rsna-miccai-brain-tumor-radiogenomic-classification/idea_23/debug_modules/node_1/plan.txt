The issue stems from two interacting problems:
1.  **Undefined Metric Handling:** In `library/engine.py`, the `evaluate` function passes 2D arrays of shape `(N, 1)` to `roc_auc_score`. When the validation set is small and contains only one class (as in the demo), Scikit-learn returns `nan` instead of raising a `ValueError`, bypassing the existing exception handler. Flattening the inputs to 1D arrays `(N,)` enforces binary classification logic, ensuring a `ValueError` is raised and caught, defaulting the AUC to 0.5 **Cite debug_lesson_9**.
2.  **Stale Artifacts:** In `runfile.py`, the script does not clean up the output directory before starting. Because the metric was `nan`, the current run failed to save a new model. The script then fell back to loading a "ghost" `best_model.pth` from a previous run (with a different architecture), causing the `RuntimeError`. Explicitly deleting the checkpoint file before training ensures the script relies only on fresh artifacts **Cite debug_lesson_8**.
