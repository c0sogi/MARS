To establish a robust and efficient baseline for the taxi fare prediction task, I propose using a **Histogram-based Gradient Boosting Decision Tree (GBDT)** architecture. This approach balances high execution speed with the ability to capture non-linear spatial and temporal patterns, making it ideal for the large-scale tabular data provided.

### Model
The core architecture is a **Histogram-based Gradient Boosting Regressor**.
*   **Design:** The model functions as an ensemble of weak learners (decision trees). Unlike traditional decision trees that sort feature values to find split points (computationally expensive for 55M rows), this architecture discretizes continuous features (latitude, longitude) into integer-mapped bins (histograms). This reduces the complexity of split-finding from $O(\text{samples})$ to $O(\text{bins})$.
*   **Growth Strategy:** The trees will be grown **leaf-wise** (best-first) rather than level-wise. This strategy expands the leaf with the maximum delta loss, which typically results in lower error rates with fewer trees compared to level-wise growth, further optimizing for speed.

### Data
Given the data analysis revealed significant outliers (e.g., coordinates > 3000, negative fares), preprocessing is critical.
1.  **Cleaning:**
    *   **Spatial Filtering:** Apply a bounding box filter to retain only coordinates within the New York City metropolitan area (approx. Lat 40°N–42°N, Long 73°W–75°W). Rows with coordinates outside this range (like the outliers seen in the analysis) will be dropped.
    *   **Logical Filtering:** Remove rows with negative `fare_amount` or `passenger_count` equal to 0.
2.  **Feature Engineering:**
    *   **Geodesic Distance:** Explicitly calculate the **Haversine distance** between pickup and dropoff points. The data analysis indicated this is the single most important predictor.
    *   **Temporal Features:** Decompose the `pickup_datetime` timestamp into numerical components: `Year`, `Month`, `Day of Week`, and `Hour`. This captures traffic seasonality and yearly fare inflation.
    *   **Coordinate Deltas:** Compute the absolute differences between pickup and dropoff latitudes/longitudes to approximate Manhattan distance.

### Training
The training process prioritizes efficiency and prevention of overfitting.
*   **Loss Function:** The model will be trained to minimize the **Mean Squared Error (MSE)**, which directly aligns with the RMSE metric.
*   **Optimization:** We will use the `train.parquet` metadata file. A portion of this data will be held out as an internal validation set.
*   **Early Stopping:** The model will train iteratively. After each round of tree addition, performance will be evaluated on the validation set. Training will automatically halt if the validation RMSE does not improve for a defined number of consecutive rounds, ensuring the model does not waste time or overfit.
*   **Compute:** The histogram construction and split-finding will be parallelized across the available 12 vCPUs.

### Evaluation
1.  **Inference:** Load the `test.parquet` file and apply the exact same feature engineering pipeline (Haversine calculation, date extraction).
2.  **Prediction:** Pass the processed test set through the trained GBDT model to regress the `fare_amount`.
3.  **Output:** Construct a submission file mapping the unique `key` from the test set to the predicted `fare_amount`.
