The issue is that the validation dataset is being filtered using the same strict criteria as the training set (bounding box and fare range), which removes outliers and results in an invalid metric calculation on a subset of the validation data. Additionally, because the pipeline caches processed data, simply changing the filtering logic without invalidating the cache would cause the system to reload the previously filtered (incorrect) dataset.

To fix this:
1.  In `library/feature_engineering.py`, I will update `process_dataset` to accept an optional `output_name` parameter. This allows callers to specify a custom cache filename, enabling us to bypass the stale cache file.
2.  In `library/data_loader.py`, I will modify `get_val_data` to call `process_dataset` with `is_train=False` to disable row filtering. I will also pass `output_name="val_full"` to ensure the full validation set is saved to a new cache file (`val_full_processed.parquet`), effectively invalidating the old cache as per **debug_lesson_2** ("Update Hardcoded Paths When Renaming Cache Artifacts").
