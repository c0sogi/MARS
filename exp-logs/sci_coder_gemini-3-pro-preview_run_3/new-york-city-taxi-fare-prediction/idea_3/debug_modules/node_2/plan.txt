The issue is caused by an API mismatch with the installed version of XGBoost (3.0.5). In newer versions of the library, the `early_stopping_rounds` parameter is no longer accepted in the `.fit()` method; instead, it must be passed to the `XGBRegressor` constructor. The fix involves modifying `train_xgboost_model` in `library/trainers.py` to stop removing `early_stopping_rounds` from the parameters dictionary (so it gets passed to the constructor) and to remove the argument from the `.fit()` call.
