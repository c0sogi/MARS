The strategy for the implementation is as follows:

1.  **Configuration Override**: Since the default configuration uses a large model (`deberta-v3-large`) and runs for multiple epochs, we will override the `Config` class attributes at runtime. We will switch to a lightweight model (`prajjwal1/bert-tiny`) and set `DEBUG=True`, `EPOCHS=1`, and `BATCH_SIZE=4` to ensure the script executes within a few minutes while still exercising all code paths.
2.  **Verification of Components**: We will systematically instantiate and verify the logic of each library component:
    *   **Utils**: Verify random seeding and text decoding logic.
    *   **Dataset**: Load a debug subset of data, create the `InsultDataset`, and verify that the `DataLoader` yields batches with the correct shapes (input IDs, attention masks, and targets).
    *   **Model**: Instantiate the `InsultModel` with the tiny architecture and perform a forward pass to confirm the output shape is `(Batch_Size, 1)`.
    *   **AWP (Adversarial Weight Perturbation)**: Simulate a training step, apply the adversarial attack, verify that weights have changed, and then restore them to verify the restoration logic.
3.  **Pipeline Execution**:
    *   **Training**: Call `run_training(seed=42)` to execute the full training loop using the overridden configuration. We will assert that the model artifact is saved.
    *   **Inference**: Call `run_inference()` to generate predictions on the test set. We will verify that the submission file is created, has the correct dimensions, and contains valid probability scores.
4.  **Error Handling**: Assertions are used throughout to ensure strict validation. Any failure will immediately stop the execution.
