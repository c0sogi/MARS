The implementation strategy follows a sequential execution pipeline designed to leverage the provided library modules while satisfying the specific constraints of the task.

1.  **Setup and Initialization**: The script begins by setting a global random seed to ensure reproducibility. It suppresses unnecessary warnings to keep the output clean.
2.  **Statistical Stream Execution**: It calls `run_nblr` from the execution library. This function handles the loading of cached TF-IDF features and trains the NBSVM (Naive Bayes - Logistic Regression) model. It returns the validation and test probability predictions.
3.  **Neural Stream Execution**: It calls `run_neural` from the execution library. This function fine-tunes a RoBERTa transformer model. Given the dataset size (~3,000 samples) and the powerful A100 GPU available, the model is trained on the full dataset for 3 epochs with a batch size of 16. This ensures high performance while remaining well within the "fast baseline" time limits.
4.  **Ensemble Optimization**: The script loads the true validation labels using `load_data`. It then utilizes `optimize_ensemble` to find the weighted average of the Statistical and Neural predictions that maximizes the AUC on the validation set.
5.  **Validation Reporting**: The final optimized AUC is printed in the strictly required format: `Final Validation Metric: <value>`.
6.  **Failure Analysis**: The script calculates the absolute error of the ensemble predictions against the true labels. It then computes and prints the Pearson correlation between this error magnitude and input features (specifically, character length and word count) to identify if the model struggles with longer or shorter comments.
7.  **Conditional Submission**: The script compares the final validation AUC against the specified threshold (`0.8839408866995074`). If the model performs better than this baseline, it computes the final weighted test predictions and saves the submission file to `./submission/submission.csv`.
