The `torch.OutOfMemoryError` occurred because the `microsoft/deberta-v3-large` model, particularly when using Adversarial Weight Perturbation (AWP) which requires additional memory for backup weights and a second forward pass, exceeded the available ~16GB VRAM with a batch size of 16. To fix this, I will modify `runfile.py` to reduce `ModelConfig.train_batch_size` to 8 and increase `ModelConfig.accumulation_steps` to 4. This reduces the immediate memory footprint while maintaining the target effective batch size of 32. By applying these configuration overrides directly in the running script (`runfile.py`) rather than relying on editing the imported `library/config.py` file, we ensure the changes are active in the current process and avoid issues with stale cached modules in persistent environments (Cite debug_lesson_4).
