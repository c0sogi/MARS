The issue identified is **Data Leakage**, where the validation dataset (`val_df`) was explicitly concatenated with the training dataset (`train_df`) to create `full_train_df`. This combined dataset was used to train both the Teacher and Student models. As a result, the models were evaluated on data they had already seen during training, leading to an invalid and artificially inflated AUC metric (~0.99). To fix this and ensure a valid performance evaluation, I will modify `runfile.py` to use only `train_df` for training, keeping `val_df` strictly isolated as a hold-out set for evaluation. This aligns with **Cite debug_lesson_6** ("Strictly Isolate Validation Data to Prevent Data Leakage").
