Based on the lessons learned, particularly the superiority of Gradient Boosted Trees on flattened windows (Cite Lesson 00016) and the specific noise introduced by "Ground" contact imputation (Cite Lesson 00002), I propose a **Task-Decomposed Split-Stream Gradient Boosting Architecture**.

### Model
Instead of a single monolithic model attempting to learn the physics of both player-to-player collisions and player-to-ground impacts simultaneously, I propose splitting the problem into two distinct streams, each handled by a specialized **XGBoost Classifier**.
1.  **Stream A (Player-Interaction Model):** Trained exclusively on player-pair samples (`player2 != 'G'`). This model focuses on relative kinematics and interaction dynamics.
2.  **Stream B (Ground-Impact Model):** Trained exclusively on player-ground samples (`player2 == 'G'`). This model focuses on ego-motion derivatives (sudden stops, jerk) without the noise of imputed "zero" features for a non-existent second player (Cite Lesson 00002).

Both models will utilize the **Flattened Temporal Window** approach (concatenating features from $t-4$ to $t+4$), as this preserves the absolute positional sensitivity required for accurate timestamp detection (Cite Lesson 00015).

### Data
**Preprocessing & Feature Engineering:**
*   **Pipeline Integrity:** Implement **hash-based cache invalidation** derived from the feature configuration to ensure that feature updates are correctly propagated (Cite Lesson 00004).
*   **Stream A Features (Player-Interaction):**
    *   **Kinematics:** Position, Speed, Acceleration, and Cyclical Orientation/Direction (sin/cos) for both players (Cite Lesson 00005).
    *   **Interaction Dynamics:** Explicitly engineer **Relative Speed**, **Relative Acceleration**, **Closure Rate**, and the **Cosine Similarity of Direction** (to capture alignment) for every timestep in the window (Cite Lesson 00006, Lesson 00022).
    *   **Deterministic Ordering:** Use a hardcoded whitelist to strictly define the feature order (Cite Lesson 00008).
*   **Stream B Features (Ground-Impact):**
    *   **Ego-Kinematics:** Position, Speed, Acceleration, and Cyclical Orientation/Direction for the subject player only.
    *   **Impact Proxies:** Calculate **Jerk** (derivative of acceleration) and **Angular Velocity** (derivative of orientation) to capture the sudden physical changes characteristic of hitting the ground. Remove all "relative" features and Player 2 features to eliminate noise.

**Sampling:**
*   Apply **Random Undersampling** (10:1 negative-to-positive ratio) independently to each stream's training data to handle class imbalance while retaining sufficient variety (Cite Lesson 00005).

### Training
*   **Algorithm:** Train two separate **XGBoost** models using the `gpu_hist` tree method for efficiency.
*   **Loss Function:** Minimize **Binary Logistic Loss** with `scale_pos_weight` tuned for each stream's specific imbalance profile.
*   **Validation:** Use the existing GroupShuffleSplit (by `game_play`) to maintain a consistent validation set across both streams.

### Evaluation
*   **Inference:** Route test set samples to the appropriate model based on the `contact_id` (i.e., if the ID ends in "G", send to Stream B; otherwise, Stream A).
*   **Threshold Optimization:** Decouple the decision boundaries. Perform a linear search on the validation set to find the optimal probability threshold **independently for each stream** that maximizes the combined MCC (Cite Lesson 00002). Apply these specific thresholds to the corresponding test subsets.
