Based on the comprehensive analysis of the "Lessons Learned," specifically the conflicting requirements of **Interaction Detection** (which benefits from robust positional differentials and visual consensus, Cite solution_lesson_node_00080, solution_lesson_node_00074) versus **Impact Detection** (which requires high-order rotational differentials and strict invariance, Cite solution_lesson_node_00068, solution_lesson_node_00075), I propose the **Asymmetric-Physics Dual-Stream GBDT with Differential Consistency**.

This solution structurally evolves the previous "Dual-Stream" architectures by formalizing a **Divergent Feature Complexity Paradigm**. We explicitly reject the "one-size-fits-all" feature engineering approach. Instead, **Stream A** is designed for **Robustness** (using low-order differentials to mitigate sensor noise in relative geometry), while **Stream B** is designed for **Sensitivity** (using high-order differentials to capture subtle inertial shocks in ego-motion).

# Model

The architecture consists of two specialized **XGBoost** classifiers (Cite solution_lesson_node_00016) operating on physically disentangled feature spaces with asymmetric complexity constraints.

1.  **Stream A: The Interaction Model (Robust Consistency)**
    *   **Scope:** Predicts contact between two players (`player2 != 'G'`).
    *   **Philosophy:** **Low-Order Physics & Visual Consistency**. Interactions are defined by spatial convergence. Since tracking data contains noise, we rely on robust **Positional Differentials** (Closure Rate) rather than noisy Vector Projections (Cite solution_lesson_node_00080). We also explicitly model the **Consistency** between Tracking (Physical Closure) and Video (Visual Looming) to gate perspective artifacts.
    *   **Backbone:** A **Conditional Early-Fusion GBDT** (Cite solution_lesson_node_00036).

2.  **Stream B: The Impact Model (Sensitive Dynamics)**
    *   **Scope:** Predicts contact between a player and the ground (`player2 == 'G'`).
    *   **Philosophy:** **High-Order Physics & Strict Invariance**. Ground impacts are defined by force transients. Here, we *must* use **Rotational Differentials** (Ego-Jerk) derived from projected velocity to capture the inertial signature of a fall (Cite solution_lesson_node_00068).
    *   **Backbone:** A **Uni-Modal Invariant GBDT** with **Shallow Depth** (Cite solution_lesson_node_00070).

# Data

**Preprocessing:**
*   **Pipeline Integrity:** Implement **hash-based cache invalidation** derived from the full feature configuration (Cite solution_lesson_node_00004).
*   **Validation Mapping:** Explicitly map the `validation` mode to read from `train_player_tracking.csv` to ensure correct data loading (Cite solution_lesson_node_00054).

**Feature Engineering - Stream A (Interaction):**
1.  **Positional Differentials (Robustness):**
    *   Calculate **Closure Rate** as the finite difference of Euclidean Distance: $-(d_t - d_{t-1}) / \Delta t$.
    *   **Constraint:** Explicitly reject high-order derivatives (e.g., Relative Acceleration) which amplify noise (Cite solution_lesson_node_00032) and Vector Projections which fail in non-frontal impacts (Cite solution_lesson_node_00080).
2.  **Visual-Kinematic Consistency (The Innovation):**
    *   Calculate **Visual Looming Rate**: $\Delta \text{Max\_IoU} / \Delta t$.
    *   **Consistency Feature:** The difference/ratio between **Normalized Closure Rate** and **Visual Looming Rate**. Large divergence (e.g., high closure, zero looming) indicates a "Phantom Approach" (perspective artifact).
3.  **Visual Consensus Pyramids:**
    *   Calculate `Max_IoU`, `Min_IoU`, and `IoU_Diff` at sparse lags ($t, t\pm4, t\pm8, t\pm15$) (Cite solution_lesson_node_00074, solution_lesson_node_00044).
    *   **Imputation:** Use **Left Join + Sentinel** (`-999`) (Cite solution_lesson_node_00036).
4.  **System Energy:** Flattened pyramids of Absolute Speed/Accel to define collision intensity (Cite solution_lesson_node_00075).

**Feature Engineering - Stream B (Impact):**
1.  **Rotational Differentials (Sensitivity):**
    *   **Step 1:** Project Velocity ($v$) onto Orientation ($\hat{o}$) $\rightarrow$ $v_{surge}, v_{sway}$.
    *   **Step 2:** Differentiate $v_{surge/sway}$ $\rightarrow$ **Ego-Acceleration**.
    *   **Step 3:** Differentiate Ego-Acceleration $\rightarrow$ **Ego-Jerk**.
    *   **Rationale:** This pipeline captures rotational Coriolis terms that projecting global acceleration misses (Cite solution_lesson_node_00068).
2.  **Rotational Energy:** Include $v_{sway}^2$ and $v_{surge}^2$ to distinguish controlled cuts from tumbles.
3.  **Strict Invariance:** Explicitly **exclude** `x`, `y`, `direction`, `orientation`, and all visual features (Cite solution_lesson_node_00075, solution_lesson_node_00034).
4.  **Invariant Baseline:** Scalar Speed/Accel (Cite solution_lesson_node_00055).

# Training

*   **Sampling:** Apply **Targeted Majority Undersampling**. Retain **100%** of the positive class and randomly subsample the negative class to a 10:1 ratio (Cite solution_lesson_node_00060).
*   **Algorithm:** Train both streams using **XGBoost** with the `gpu_hist` tree method (Cite solution_lesson_node_00016).
*   **Asymmetric Regularization:**
    *   **Stream A:** **Standard Depth** (`max_depth=6`) to model the complex non-linear interactions between physical closure and visual consistency.
    *   **Stream B:** **Shallow Depth** (`max_depth=6` to `8`) + **Explicit Physics**. By providing the robust `Ego-Jerk` signal, we avoid the need for deep trees that overfit sensor noise (Cite solution_lesson_node_00070, solution_lesson_node_00045).
*   **Objective:** Minimize **Binary Logistic Loss**.

# Evaluation

1.  **Inference:**
    *   Route test samples to Stream A or Stream B based on the `contact_id`.
    *   Stream A receives the "Robust Consistency" vector. Stream B receives the "Sensitive Dynamics" vector.
2.  **Optimization:**
    *   **Thresholding:** Decouple the decision boundary from the probability. Perform a linear search on the Validation set to find the optimal probability threshold **independently for each stream** that maximizes the Matthews Correlation Coefficient (MCC) (Cite solution_lesson_node_00002, solution_lesson_node_00025).
    *   **Submission:** Apply these specific thresholds to the Test set predictions.
