The execution failure was caused by a "one-to-many" merge explosion resulting in duplicate rows in the submission file. Specifically, the helmet data contains multiple entries for the same player and frame (due to multiple camera views), and the tracking data may contain artifacts. Merging these without deduplication increased the dataset size beyond the expected count (Cite debug_lesson_17). Additionally, the logs indicated a `ValueError` when loading cached NumPy arrays containing strings, requiring `allow_pickle=True` (Cite debug_lesson_1).

I will fix this by:
1.  Explicitly deduplicating `df_tracking` on `['game_play', 'step', 'nfl_player_id']` in both `generate_stream_a_features` and `generate_stream_b_features`.
2.  Explicitly deduplicating `df_helmets` on `['game_play', 'frame', 'nfl_player_id']` in `_add_visual_features`.
3.  Updating `np.load` calls in `_load_from_cache` to use `allow_pickle=True`.
