Based on the progression of empirical findings—specifically the success of **Gradient Boosted Trees** on flattened windows (Cite solution_lesson_node_00016), the necessity of **Stream Splitting** (Cite solution_lesson_node_00025), and the critical insight regarding **Modality Suitability** (Cite solution_lesson_node_00034)—I propose an **Asymmetric Modality-Selective Dual-Stream GBDT**.

This solution structurally evolves the previous "Early-Fusion" attempt (Idea 8) by correcting the feature engineering strategy for the Player-Ground stream. Instead of forcing visual features into both streams, this architecture applies a strict **Modality Selection** protocol: it fuses Visual Geometry with Tracking for interaction detection (where spatial overlap is key) but restricts the ground-impact stream to Sensor Kinematics (where visual derivatives proved detrimental).

# Model

The architecture consists of two specialized **XGBoost** classifiers that utilize **Asymmetric Feature Sets** tailored to the physics of their respective tasks.

1.  **Stream A: Interaction Model (Player-Player)**
    *   **Scope:** Predicts contacts between two players (`player2 != 'G'`).
    *   **Architecture:** An **Early-Fusion GBDT** that processes a unified vector of **Tracking Kinematics** and **Visual Geometry**.
    *   **Rationale:** Contact between players is a spatial phenomenon. While tracking data measures center-of-mass proximity, visual data (Helmet IoU) measures physical overlap. Fusing these allows the model to differentiate "Near Misses" (low tracking distance, zero IoU) from "Collisions" (low distance, high IoU) (Cite solution_lesson_node_00034).

2.  **Stream B: Impact Model (Player-Ground)**
    *   **Scope:** Predicts contacts between a player and the ground (`player2 == 'G'`).
    *   **Architecture:** A **Uni-Modal GBDT** that processes **Tracking Kinematics Only**.
    *   **Rationale:** Ground impact is a force/momentum phenomenon defined by sudden deceleration (Jerk) and loss of control. Previous attempts to use visual derivatives (e.g., "Helmet Drop Velocity") failed because bounding box jitter introduced excessive noise (Cite solution_lesson_node_00034). This stream explicitly rejects visual features to preserve signal integrity.

# Data

**Preprocessing:**
*   **Pipeline Integrity:** Implement **hash-based cache invalidation** derived from the feature configuration to ensure that the asymmetric feature logic is correctly propagated (Cite solution_lesson_node_00004).
*   **Deterministic Ordering:** Use hardcoded whitelists to strictly define the feature order for each stream (Cite solution_lesson_node_00008).

**Feature Engineering - Stream A (Tracking + Visual):**
1.  **Multi-Resolution Tracking:**
    *   **Micro ($t \pm 4$):** Flattened raw kinematics, **Relative Speed**, and **Closure Rate** (Cite solution_lesson_node_00006).
    *   **Macro ($t \pm 15$):** Aggregated rolling statistics (Mean, Max, Std) to capture the approach trajectory (Cite solution_lesson_node_00031).
2.  **View-Specific Visual Geometry:**
    *   Interpolate helmet bounding boxes to 10Hz.
    *   Calculate **Intersection over Union (IoU)** and **Centroid Pixel Distance** for the pair.
    *   **Flatten by View:** Instead of aggregating, include features for both **Sideline** and **Endzone** views separately (e.g., `Sideline_IoU_t0`, `Endzone_IoU_t0`). This allows the tree to learn view reliability based on field position (Cite solution_lesson_node_00016).

**Feature Engineering - Stream B (Tracking Only):**
1.  **Multi-Resolution Tracking:**
    *   **Micro ($t \pm 4$):** Flattened raw kinematics. Crucially, include **Pose-Motion Alignment** (dot product of orientation and velocity) and **Jerk** (derivative of acceleration) to detect tumbling and impact forces (Cite solution_lesson_node_00027).
    *   **Macro ($t \pm 15$):** Aggregated rolling statistics to capture the context of the fall (Cite solution_lesson_node_00031).
2.  **Exclusion:** Explicitly exclude all visual features and "Player 2" relative features to prevent noise injection (Cite solution_lesson_node_00034).

# Training

*   **Sampling:** Apply **Random Undersampling** with a 10:1 negative-to-positive ratio independently to each stream. This maintains training efficiency while providing sufficient negative examples (Cite solution_lesson_node_00005).
*   **Algorithm:** Train both streams using **XGBoost** with the `gpu_hist` tree method. This backbone is selected for its superior performance on flattened tabular windows and ability to model non-linear "Ground" logic (Cite solution_lesson_node_00016).
*   **Objective:** Minimize **Binary Logistic Loss**.

# Evaluation

1.  **Inference:**
    *   Route test samples to Stream A or Stream B based on the `contact_id`.
    *   Stream A receives the fused Tracking+Visual vector. Stream B receives the pure Tracking vector.
2.  **Optimization:**
    *   **Thresholding:** Decouple the decision boundary from the probability. Perform a linear search on the Validation set to find the optimal probability threshold **independently for each stream** that maximizes the Matthews Correlation Coefficient (MCC) (Cite solution_lesson_node_00002).
    *   **Submission:** Apply these specific thresholds to the Test set predictions to generate the final binary labels.
