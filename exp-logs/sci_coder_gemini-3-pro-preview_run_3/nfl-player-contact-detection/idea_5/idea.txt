# Solution: Multi-Resolution Dual-Stream GBDT with Physics-Informed Kinematics

### Model
I propose a **Multi-Resolution Dual-Stream Gradient Boosting Architecture**. This approach structurally evolves the previous "Dual-Stream" concept by integrating a **Multi-Resolution Temporal Feature Space**.
*   **Architecture:** The solution consists of two distinct **XGBoost** classifiers (Cite Lesson 00016).
    1.  **Stream A (Interaction Model):** Specialized for Player-Player contact detection (`player2 != 'G'`).
    2.  **Stream B (Impact Model):** Specialized for Player-Ground contact detection (`player2 == 'G'`).
*   **Rationale:** This split allows the model to learn distinct physical signatures for collisions versus falls (Cite Lesson 00025). By using Gradient Boosted Trees, we leverage their superior performance on flattened tabular windows compared to MLPs (Cite Lesson 00016) and their ability to handle the non-linear "Ground" imputation logic (Cite Lesson 00002).

### Data
**Preprocessing:**
*   **Pipeline Integrity:** Implement **hash-based cache invalidation** derived from the feature configuration to ensure that any logic changes automatically trigger data regeneration (Cite Lesson 00004).
*   **Deterministic Ordering:** Use a hardcoded whitelist to strictly define the feature order, preventing "silent drops" of computed features (Cite Lesson 00008, Lesson 00022).

**Feature Engineering (Multi-Resolution):**
We will construct the input vector using two distinct temporal scopes to balance instantaneous precision with trajectory context:
1.  **Micro-Window ($t \pm 4$):**
    *   **Method:** Flattened raw features for every timestep in the 9-frame window.
    *   **Purpose:** Preserves absolute positional sensitivity to distinguish the exact moment of contact ($t=0$) from adjacent frames (Cite Lesson 00015).
    *   **Features:**
        *   **Cyclical Encoding:** Sine/Cosine for all angular variables (Cite Lesson 00005).
        *   **Stream A:** Relative Speed, Closure Rate, and Cosine Similarity of Directions (Cite Lesson 00006).
        *   **Stream B:** Jerk (derivative of acceleration), Angular Velocity, and **Pose-Motion Alignment** (dot product of orientation and velocity vectors) to detect loss of control (Cite Lesson 00027).
2.  **Macro-Window ($t \pm 15$):**
    *   **Method:** Aggregated statistical features (Mean, Max, Min, Std) over a wider 31-frame window (approx. 3 seconds).
    *   **Purpose:** Captures the broader "Play Context" (e.g., sustained high-speed pursuit vs. stationary piling) to inform the likelihood of contact, effectively expanding the receptive field without exploding the feature dimension (Cite Lesson 00006).

### Training
*   **Sampling:** Apply **Random Undersampling** with a 10:1 negative-to-positive ratio independently to each stream. This maintains training efficiency while providing sufficient negative examples for the model to learn the decision boundary (Cite Lesson 00005).
*   **Objective:** Minimize **Binary Logistic Loss**.
*   **Strategy:** Train both streams using the `gpu_hist` tree method for computational efficiency.

### Evaluation
*   **Inference:** Route test samples to Stream A or Stream B based on the `contact_id`.
*   **Threshold Optimization:** Decouple the decision boundary from the training objective. Perform a linear search on the validation set to find the optimal probability threshold **independently for each stream** that maximizes the combined Matthews Correlation Coefficient (MCC). Apply these specific thresholds to the corresponding test subsets (Cite Lesson 00002, Lesson 00025).
