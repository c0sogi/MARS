Based on the lessons learned, particularly the success of the **Multi-Resolution Dual-Stream GBDT** (Cite Lesson 00031) and the persistent "Distance Ambiguity" identified in failure analyses, I propose a **Late-Fusion Multi-Modal Ensemble**.

This approach structurally evolves the solution by introducing a second parallel modeling stream based on **Helmet Bounding Box Data** (Visual Geometry) and fusing it with the existing **Player Tracking** (Kinematic) stream. This addresses the limitation of tracking data—which represents the player's center of mass—by incorporating the precise location of the head, a key contact point, without the computational cost of raw video processing.

# Model

The architecture is a **Late-Fusion Ensemble** consisting of two independent Gradient Boosted Decision Tree (XGBoost) subsystems, whose predictions are combined via a learned blending layer.

1.  **Stream A: Kinematic Predictor (The "Body" Model)**
    *   **Backbone:** The **Multi-Resolution Dual-Stream GBDT** from Idea 5 (Cite Lesson 00031).
    *   **Structure:** Two specialized XGBoost classifiers:
        *   **A1 (Player-Interaction):** Trained on player-pair tracking data.
        *   **A2 (Ground-Impact):** Trained on single-player tracking data.
    *   **Input:** Flattened temporal windows of tracking data (Position, Velocity, Acceleration) at both Micro ($t\pm4$) and Macro ($t\pm15$) resolutions.

2.  **Stream B: Visual-Geometric Predictor (The "Head" Model)**
    *   **Backbone:** A new Dual-Stream XGBoost architecture designed to process **Helmet Bounding Box** data.
    *   **Structure:** Similar split (Player-Player vs. Player-Ground) (Cite Lesson 00025).
    *   **Input:** Flattened temporal windows of helmet geometry derived from `[train/test]_baseline_helmets.csv`.
    *   **Rationale:** While tracking data measures "Body-to-Body" proximity (yards), this stream measures "Head-to-Head" proximity (pixels) and "Visual Overlap" (IoU). This resolves ambiguity where bodies are close but heads are not (e.g., running side-by-side) versus true collisions.

3.  **Fusion Layer:**
    *   A **Linear Blending** mechanism that computes the final probability as a weighted average of Stream A and Stream B. The weights are optimized on the validation set to maximize MCC (Cite Lesson 00002).

# Data

**Preprocessing:**
*   **Pipeline Integrity:** Maintain hash-based cache invalidation to ensure feature updates propagate correctly (Cite Lesson 00004).
*   **Stream A (Tracking):**
    *   Generate **Micro-Window** features (raw kinematics, relative speed, pose-motion alignment) (Cite Lesson 00027).
    *   Generate **Macro-Window** features (aggregated rolling statistics) (Cite Lesson 00031).
    *   Decompose all angles into Sine/Cosine components (Cite Lesson 00005).
*   **Stream B (Helmets):**
    *   **Synchronization:** Interpolate helmet bounding box data to match the 10Hz tracking timestamps.
    *   **View Aggregation:** For each timestep, calculate features for both "Sideline" and "Endzone" views and take the **Max** value (e.g., Max IoU) to capture the contact from the most visible angle.
    *   **Feature Engineering:**
        *   **Visual IoU:** Intersection over Union of the two players' helmet boxes. A non-zero IoU is a strong, independent signal of contact.
        *   **Visual Centroid Distance:** Euclidean pixel distance between helmet centers.
        *   **Visual Agitation:** The "Jerk" of the helmet bounding box (pixel acceleration changes), serving as a proxy for head impact.

**Sampling:**
*   Apply **Random Undersampling** (10:1 negative-to-positive ratio) independently to all underlying models to handle class imbalance (Cite Lesson 00005).

# Training

1.  **Independent Training:**
    *   Train **Stream A** (Kinematic) using the established XGBoost `gpu_hist` configuration.
    *   Train **Stream B** (Visual-Geometric) using XGBoost `gpu_hist`.
    *   Both streams use **Binary Logistic Loss** and are validated on the same GroupShuffleSplit (by `game_play`) to ensure consistent out-of-sample evaluation.
2.  **Optimization:**
    *   Use Early Stopping based on Validation MCC.
    *   Avoid over-engineering high-order derivatives for the GBDTs, relying instead on the raw geometric signals (IoU, Distance) (Cite Lesson 00032).

# Evaluation

1.  **Inference:**
    *   Generate probability predictions $P_A$ (from Stream A) and $P_B$ (from Stream B) for the test set.
2.  **Blending:**
    *   On the Validation set, perform a grid search to find the optimal blending weight $w$ such that $P_{final} = w \cdot P_A + (1-w) \cdot P_B$ maximizes the MCC.
3.  **Thresholding:**
    *   Decouple the decision boundary from the probability. Perform a linear search on the blended Validation probabilities to find the optimal cutoff threshold that maximizes MCC (Cite Lesson 00002).
    *   Apply this optimized weight $w$ and threshold to the Test set to generate the final submission.
