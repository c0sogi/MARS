Based on the comprehensive analysis of the "Lessons Learned," specifically the need for **Perspective-Awareness** in cross-modal consistency (refining Cite solution_lesson_node_00105) and the robustness of **Trajectory Deviation** over instantaneous derivatives for impacts (refining Cite solution_lesson_node_00068), I propose the **Perspective-Corrected Dual-Stream GBDT with Inertial Deviation Pyramids**.

This solution structurally evolves the "Bidirectional Hybrid-Context" architecture (Idea 33). It replaces the static "Global Scale Factor" in Stream A with a **Dynamic Perspective Correction** based on field position, and it augments Stream B with **Inertial Deviation Profiles** to capture "Loss of Control" more robustly than simple jerk.

# Model

The architecture consists of two specialized **XGBoost** classifiers (Cite solution_lesson_node_00016) operating on physically disentangled feature spaces with asymmetric complexity constraints.

1.  **Stream A: The Interaction Model (Perspective-Corrected Consistency)**
    *   **Scope:** Predicts contact between two players (`player2 != 'G'`).
    *   **Backbone:** A **Conditional Early-Fusion GBDT** (Cite solution_lesson_node_00036).
    *   **Structural Innovation:** **Perspective-Corrected Cross-Modal Residuals**.
        *   Instead of scaling `Closure_Rate` by a global constant (which ignores camera depth), we calculate a **Depth Proxy** ($Z_{est}$) based on the player's Euclidean distance to the standard NFL camera locations (Sideline: $y= -5$ or $58$, Endzone: $x= -5$ or $125$).
        *   We generate the **Perspective-Corrected Residual**: $(\frac{\text{Closure\_Rate}}{Z_{est}}) - \text{Visual\_Looming\_Rate}$.
        *   This aligns the physical signal (yards/s) with the visual signal (pixels/s) dynamically, allowing the tree to isolate "Phantom Approaches" (perspective artifacts) with high precision (Evolution of Cite solution_lesson_node_00105, solution_lesson_node_00074).
    *   **Base Features:** Fuses **Relational Scalars**, **System Energy**, and **Visual Consensus** over a **Dense Bidirectional Window**.

2.  **Stream B: The Impact Model (Inertial Deviation & Hybrid Context)**
    *   **Scope:** Predicts contact between a player and the ground (`player2 == 'G'`).
    *   **Backbone:** A **Uni-Modal Hybrid GBDT**.
    *   **Structural Innovation:** **Inertial Deviation Profiles**.
        *   Instead of relying solely on instantaneous derivatives (Jerk), we calculate the **Trajectory Deviation**: the vector difference between the *actual* position at time $t$ and the *predicted* position based on linear inertia from $t-5$ ($p_{pred} = p_{t-5} + v_{t-5} \cdot \Delta t$).
        *   This deviation vector is projected into the **Ego-Centric Frame** (Surge/Sway) and flattened over the window.
        *   **Rationale:** This captures the *integral* of unpredicted forces (e.g., a fall or tackle) over a short horizon, providing a more robust signal for "Loss of Control" than noisy instantaneous jerk (Evolution of Cite solution_lesson_node_00068, solution_lesson_node_00086).

# Data

**Preprocessing:**
*   **Pipeline Integrity:**
    *   Implement **Configuration-Hashed Cache Invalidation** (Cite solution_lesson_node_00093).
    *   Enforce **Strict Schema Validation**; raise a `RuntimeError` if features are missing (Cite solution_lesson_node_00088).
    *   Explicitly map `validation` mode to `train_player_tracking.csv` (Cite solution_lesson_node_00054).

**Feature Engineering - Stream A (Interaction):**
1.  **Dense Bidirectional Pyramids:** Flatten features at lags $t \in \{0, \pm1, \pm2, \pm4, \pm8, \pm15\}$ (Cite solution_lesson_node_00107, solution_lesson_node_00112).
2.  **Perspective-Corrected Consistency:**
    *   Calculate `Sideline_Depth_Proxy` ($|y - 26.65| + C$) and `Endzone_Depth_Proxy`.
    *   Compute **Corrected Residuals** for both views: $(\text{Closure} / \text{Depth}) - \text{Looming}$. Flatten these sequences.
3.  **Visual Consensus:** Flatten `Max_IoU`, `Min_IoU`, and `IoU_Diff` at sparse lags (Cite solution_lesson_node_00074).
4.  **Relational Primitives:** Euclidean Distance and Finite-Difference Closure Rate (Cite solution_lesson_node_00080).
5.  **Imputation:** Left Join + Sentinel (`-999`) (Cite solution_lesson_node_00036).

**Feature Engineering - Stream B (Impact):**
1.  **Inertial Deviation:**
    *   Calculate linear prediction error: $\vec{\delta} = \vec{p}_t - (\vec{p}_{t-5} + \vec{v}_{t-5} \cdot 0.5s)$.
    *   Project $\vec{\delta}$ onto Orientation $\hat{o}$ $\rightarrow$ $\delta_{surge}, \delta_{sway}$.
    *   Flatten these profiles over the bidirectional window.
2.  **Hybrid Context:**
    *   **Field-Centric:** Flattened pyramids of `x`, `y`, `speed`, `acceleration`, `direction` (Cite solution_lesson_node_00091).
    *   **Ego-Dynamics:** Finite-Difference Surge/Sway Velocity, Acceleration, and Jerk (Cite solution_lesson_node_00068).
3.  **Exclusion:** Block all visual features (Cite solution_lesson_node_00034).

# Training

*   **Sampling:** Apply **Targeted Majority Undersampling**. Retain **100%** of the positive class and randomly subsample the negative class to a 10:1 ratio (Cite solution_lesson_node_00060, solution_lesson_node_00113).
*   **Algorithm:** Train both streams using **XGBoost** with the `gpu_hist` tree method (Cite solution_lesson_node_00016).
*   **Asymmetric Regularization:**
    *   **Stream A:** **Standard Depth** (`max_depth=6`) for complex cross-modal logic.
    *   **Stream B:** **Shallow Depth** (`max_depth=6` to `8`) and **Conservative Learning Rate** (0.02) to prevent overfitting sensor noise (Cite solution_lesson_node_00070, solution_lesson_node_00045).
*   **Objective:** Minimize **Binary Logistic Loss**.

# Evaluation

1.  **Inference:**
    *   Route test samples to Stream A or Stream B based on the `contact_id`.
    *   Stream A receives the "Perspective-Corrected Consistency" vector. Stream B receives the "Inertial Deviation + Hybrid Context" vector.
2.  **Optimization:**
    *   **Thresholding:** Decouple the decision boundary from the probability. Perform a linear search on the Validation set to find the optimal probability threshold **independently for each stream** that maximizes the Matthews Correlation Coefficient (MCC) (Cite solution_lesson_node_00002, solution_lesson_node_00025).
    *   **Submission:** Apply these specific thresholds to the Test set predictions.
