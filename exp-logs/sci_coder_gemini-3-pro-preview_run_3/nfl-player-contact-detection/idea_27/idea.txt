Based on the comprehensive analysis of the "Lessons Learned," specifically the critical finding that **Temporal Window Flattening** is superior to **Instantaneous Derivatives** (Cite solution_lesson_node_00086), while **Strict Biomechanical Invariance** is essential for ground impacts (Cite solution_lesson_node_00075), I propose the **Invariant-Physics Temporal Pyramid Dual-Stream GBDT**.

This solution structurally evolves the previous "Dual-Stream" architectures by correcting the "Instantaneous Physics" fallacy of Idea 26. Instead of reducing the temporal window to a single timestep's derivative (which amplifies noise), we applies **Exponential Temporal Pyramids** (Cite solution_lesson_node_00042) to the **Invariant Physical Primitives** derived in previous successful iterations. This allows the GBDT to learn the *trajectory* of the physics (e.g., the "shape" of a fall in ego-centric coordinates) rather than just a noisy snapshot.

# Model

The architecture consists of two specialized **XGBoost** classifiers (Cite solution_lesson_node_00016) operating on physically disentangled feature spaces that combine robust temporal context with physics-informed transformations.

1.  **Stream A: The Interaction Model (Relational Trajectories)**
    *   **Scope:** Predicts contact between two players (`player2 != 'G'`).
    *   **Backbone:** A **Conditional Early-Fusion GBDT** (Cite solution_lesson_node_00036).
    *   **Feature Strategy:** **Relational Temporal Pyramids**.
    *   **Rationale:** Interactions are defined by the convergence of trajectories. We fuse **Relational Scalars** (Distance, Closure Rate) with **Visual Consensus**, flattened over exponentially spaced lags. This restores the "System Energy" context lost in Idea 22 (Cite solution_lesson_node_00075) and uses robust positional differentials (Cite solution_lesson_node_00080).

2.  **Stream B: The Impact Model (Invariant Ego-Trajectories)**
    *   **Scope:** Predicts contact between a player and the ground (`player2 == 'G'`).
    *   **Backbone:** A **Uni-Modal Invariant GBDT**.
    *   **Feature Strategy:** **Invariant Ego-Centric Pyramids**.
    *   **Rationale:** Ground impacts are invariant to field position. Instead of feeding raw $(x, y)$ lags (which overfit to location) or instantaneous Jerk (which is noisy), we project the *entire temporal window* of kinematics into the **Ego-Centric Frame** (Surge/Sway). This exposes the invariant *motion signature* of a fall (e.g., a sequence of lateral sway deceleration) regardless of where it happens on the field (Cite solution_lesson_node_00075, solution_lesson_node_00068).

# Data

**Preprocessing:**
*   **Pipeline Integrity:** Implement **hash-based cache invalidation** (Cite solution_lesson_node_00004) and **Strict Schema Validation** to ensure no features are silently zero-filled (Cite solution_lesson_node_00088).
*   **Validation Mapping:** Explicitly map the `validation` mode to read from `train_player_tracking.csv` (Cite solution_lesson_node_00054).

**Feature Engineering - Stream A (Interaction):**
1.  **Relational Temporal Pyramids:**
    *   Flatten features at sparse lags ($t, t\pm1, t\pm2, t\pm4, t\pm8, t\pm15$) (Cite solution_lesson_node_00042).
    *   **Features:** **Euclidean Distance**, **Relative Speed** (Scalar), and **Closure Rate** (Finite Difference of Distance) (Cite solution_lesson_node_00080).
2.  **System Energy:** Flattened pyramids of **Absolute Speed** and **Scalar Acceleration** for both players (Cite solution_lesson_node_00075).
3.  **Visual Consensus Pyramids:**
    *   Flatten `Sideline_IoU`, `Endzone_IoU`, `Max_IoU`, `Min_IoU`, and `IoU_Diff` at sparse lags ($t, t\pm4, t\pm8, t\pm15$).
    *   **Imputation:** Use **Left Join + Sentinel** (`-999`) (Cite solution_lesson_node_00036).
    *   **Cross-Modal Consistency:** Flatten the difference between `Normalized_Closure_Rate` and `Visual_Looming_Rate` at each lag to detect sustained perspective artifacts (Extension of Cite solution_lesson_node_00080).

**Feature Engineering - Stream B (Impact):**
1.  **Invariant Ego-Centric Pyramids (The Innovation):**
    *   For *every* timestep $\tau$ in the exponential window ($t, t\pm1... t\pm15$):
        *   Project Velocity $v_\tau$ onto Orientation $o_\tau$ $\rightarrow$ $v_{surge,\tau}, v_{sway,\tau}$.
        *   Calculate Ego-Acceleration via finite difference of these projected velocities (Cite solution_lesson_node_00068).
    *   **Flatten** these sequences. This provides the tree with the full time-series of the player's body-relative motion, allowing it to match temporal patterns (signatures) of impacts (Cite solution_lesson_node_00086).
2.  **Invariant Baseline:** Flattened pyramids of Scalar Speed and Scalar Acceleration (Cite solution_lesson_node_00055).
3.  **Strict Invariance:** Explicitly **exclude** `x`, `y`, `direction`, `orientation`, and all visual features (Cite solution_lesson_node_00075, solution_lesson_node_00034).

# Training

*   **Sampling:** Apply **Targeted Majority Undersampling**. Retain **100%** of the positive class and randomly subsample the negative class to a 10:1 ratio (Cite solution_lesson_node_00060).
*   **Algorithm:** Train both streams using **XGBoost** with the `gpu_hist` tree method (Cite solution_lesson_node_00016).
*   **Asymmetric Regularization:**
    *   **Stream A:** Standard depth (`max_depth=6`) to model complex interactions.
    *   **Stream B:** **Shallow Depth** (`max_depth=6` to `8`). By providing the robust, flattened Ego-Centric trajectories, we avoid the need for deep trees to infer dynamics, preventing overfitting to sensor noise (Cite solution_lesson_node_00070).
*   **Objective:** Minimize **Binary Logistic Loss**.

# Evaluation

1.  **Inference:**
    *   Route test samples to Stream A or Stream B based on the `contact_id`.
    *   Stream A receives the "Relational Trajectory" vector. Stream B receives the "Invariant Ego-Trajectory" vector.
2.  **Optimization:**
    *   **Thresholding:** Decouple the decision boundary from the probability. Perform a linear search on the Validation set to find the optimal probability threshold **independently for each stream** that maximizes the Matthews Correlation Coefficient (MCC) (Cite solution_lesson_node_00002, solution_lesson_node_00025).
    *   **Submission:** Apply these specific thresholds to the Test set predictions.
