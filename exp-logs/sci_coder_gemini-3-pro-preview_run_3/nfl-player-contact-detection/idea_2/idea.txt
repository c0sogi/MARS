# Idea: Temporal 1D-Convolutional Network with Interaction Dynamics

### Model
I propose replacing the flattened Multi-Layer Perceptron (MLP) with a **1D Convolutional Neural Network (1D-CNN)** to better capture the temporal evolution of contact events.
*   **Architecture:** The model will accept a 3D input tensor of shape $(Batch, Features, Time)$, where $Time$ represents the temporal window. The backbone will consist of stacked 1D Convolutional layers with Batch Normalization and ReLU activations. This structure allows the model to learn translation-invariant temporal filters (e.g., detecting a "rapid deceleration" or "sudden jerk" pattern anywhere within the window) rather than treating the window as a static, flattened snapshot (Cite Lesson 00002).
*   **Pooling:** A Global Max Pooling layer will follow the convolutions to aggregate the strongest activation signals across the time window, making the detection robust to slight temporal misalignments.
*   **Ground Handling:** To address the confusion caused by imputing zeros for ground contacts (Cite Lesson 00002), the model will include a dedicated `is_ground` feature channel. This allows the convolutional filters to learn distinct activation patterns for player-ground impacts versus player-player impacts.

### Data
*   **Feature Engineering:**
    *   **Temporal Window:** We will maintain the expanded window of $\pm 4$ frames (9 timesteps total) to provide sufficient context for the approach trajectory (Cite Lesson 00006).
    *   **Cyclical Encoding:** All angular features (orientation, direction) will be transformed into their sine and cosine components to preserve topological continuity (Cite Lesson 00005).
    *   **Explicit Interaction Features:** We will calculate and include **Relative Speed** and **Relative Acceleration** (magnitude of the difference vectors) at each timestep. Explicitly engineering these derivatives significantly aids the model in distinguishing "moving past" from "moving into" (Cite Lesson 00006).
    *   **Deterministic Ordering:** The feature set will be defined by a hardcoded, ordered list to ensure reproducibility and prevent implicit column reordering (Cite Lesson 00008).
*   **Preprocessing:**
    *   **Cache Invalidation:** The data loading pipeline will use hashed filenames based on the feature configuration to ensure that any changes to feature logic automatically trigger data regeneration (Cite Lesson 00004).

### Training
*   **Strategy:** We will continue to use **Random Undersampling** with a 10:1 negative-to-positive ratio, as this provided a good balance between training speed and exposure to negative examples (Cite Lesson 00005).
*   **Optimization:** The model will be trained using the **AdamW** optimizer with **Binary Cross-Entropy Loss**.

### Evaluation
*   **Threshold Optimization:** We will decouple the training objective from the evaluation metric by performing a post-hoc search for the optimal probability threshold that maximizes the Matthews Correlation Coefficient (MCC) on the validation set (Cite Lesson 00002). This threshold will then be applied to the test set predictions.
