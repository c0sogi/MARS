Based on the progression of insights—specifically the superiority of Gradient Boosted Trees on flattened windows (Cite solution_lesson_node_00016), the necessity of splitting "Player" and "Ground" tasks (Cite solution_lesson_node_00025), and the limitations of "Late Fusion" in capturing cross-modal dependencies—I propose an **Early-Fusion Dual-Stream GBDT with View-Specific Geometry**.

This solution structurally evolves the previous "Late-Fusion" approach (Idea 7) by merging the Kinematic (Tracking) and Visual (Helmet) data streams *upstream* of the model. This allows the decision trees to learn non-linear conditional interactions between modalities (e.g., "High Tracking Proximity" **AND** "Zero Visual IoU" $\rightarrow$ No Contact), effectively resolving the "Distance Ambiguity" that independent models struggle with.

# Model

The architecture consists of two specialized **XGBoost** classifiers that process a unified, multi-modal feature vector.

1.  **Stream A (Interaction Model):**
    *   **Scope:** Predicts contacts between two players (`player2 != 'G'`).
    *   **Input:** A concatenated vector of **Player-Pair Tracking Kinematics** and **Paired Helmet Geometry**.
    *   **Mechanism:** By seeing both signals simultaneously, the model can distinguish "Near Misses" (where tracking distance is low but visual intersection is zero) from true "Collisions" (where both signals align).

2.  **Stream B (Impact Model):**
    *   **Scope:** Predicts contacts between a player and the ground (`player2 == 'G'`).
    *   **Input:** A concatenated vector of **Single-Player Tracking Kinematics** and **Single-Player Helmet Dynamics**.
    *   **Mechanism:** Integrates **Pseudo-3D** features. Since tracking data lacks Z-axis (height) information, the model uses the vertical movement of the helmet bounding box (from video data) combined with field position to detect "drops" and "sudden vertical stops" characteristic of hitting the ground.

# Data

**Preprocessing:**
*   **Pipeline Integrity:** Implement **hash-based cache invalidation** derived from the feature configuration to ensure data consistency (Cite solution_lesson_node_00004).
*   **Deterministic Ordering:** Use a hardcoded whitelist to strictly define the feature order (Cite solution_lesson_node_00008).

**Feature Engineering (Early Fusion Strategy):**
We construct a single flattened feature vector for every timestep $t$ by concatenating the following:

1.  **Multi-Resolution Tracking (Micro + Macro):**
    *   **Micro ($t \pm 4$):** Raw kinematics, Relative Speed, and Pose-Motion Alignment (Cite solution_lesson_node_00027) to capture instantaneous mechanics.
    *   **Macro ($t \pm 15$):** Aggregated rolling statistics (Mean, Max, Std) to capture trajectory context (Cite solution_lesson_node_00031).
    *   **Cyclical Encoding:** Sine/Cosine for all angles (Cite solution_lesson_node_00005).

2.  **View-Specific Helmet Geometry:**
    *   Instead of aggregating video views (e.g., taking the "Max IoU"), we **flatten** features from both the **Sideline** and **Endzone** views into separate columns (e.g., `Sideline_IoU`, `Endzone_IoU`).
    *   **Rationale:** This allows the GBDT to learn view reliability based on the player's tracking position (e.g., "Trust Endzone features when `x_position` is near the goal line").

3.  **Pseudo-3D Dynamics (Stream B Focus):**
    *   **Helmet Drop Velocity:** The rate of change of the helmet bounding box `top` coordinate.
    *   **Visual Compression:** The ratio of bounding box `height` to `width`, serving as a proxy for body posture (standing vs. crumpled).

# Training

*   **Sampling:** Apply **Random Undersampling** with a 10:1 negative-to-positive ratio independently to Stream A and Stream B. This balances training efficiency with sufficient negative exposure (Cite solution_lesson_node_00005).
*   **Algorithm:** Train both streams using **XGBoost** with the `gpu_hist` tree method. The tree-based architecture is chosen for its superior performance on flattened tabular windows (Cite solution_lesson_node_00016) and ability to handle the "Ground" class discontinuities (Cite solution_lesson_node_00002).
*   **Objective:** Minimize **Binary Logistic Loss**.

# Evaluation

1.  **Inference:**
    *   Route test samples to Stream A or Stream B based on the `contact_id`.
    *   Generate probability predictions using the unified feature vectors.
2.  **Optimization:**
    *   **Thresholding:** Decouple the decision boundary from the probability. Perform a linear search on the Validation set to find the optimal probability threshold **independently for each stream** that maximizes the Matthews Correlation Coefficient (MCC) (Cite solution_lesson_node_00002).
    *   **Submission:** Apply these specific thresholds to the Test set predictions to generate the final binary labels.
