The `KeyError: 'max_iou'` occurs because of a schema collision during the temporal flattening process in `process_stream_a`. The `_flatten_temporal_context` method initializes the result DataFrame (`df_res`) as a copy of the input `df_main`. In Stream A, `df_main` already contains the computed feature columns (like `max_iou`). When the method subsequently merges the features for Lag 0 (which are also derived from `df_main`), Pandas detects duplicate column names that are not join keys and automatically renames them with suffixes (e.g., `max_iou_x`, `max_iou_y`). Consequently, the expected column `max_iou` is no longer present by its original name, causing downstream calculations to fail.

To fix this, I will modify `_flatten_temporal_context` to explicitly drop the target `feature_cols` from the base `df_res` before starting the merge loop. This ensures that the Lag 0 merge is the sole source of these columns, preventing duplication and renaming. This applies the principle from **debug_lesson_11** regarding strict column projection before merging.
