Based on the comprehensive analysis of the "Lessons Learned," specifically the finding that **Stream A (Interaction)** requires "System Energy" and "Relative Geometry" (Cite solution_lesson_node_00075, solution_lesson_node_00051), while **Stream B (Impact)** requires "Strict Biomechanical Invariance" and "Finite-Difference Dynamics" (Cite solution_lesson_node_00075, solution_lesson_node_00068), I propose the **Energy-Preserving Dual-Stream GBDT with Visual Consensus Pyramids**.

This solution structurally evolves the previous "Biomechanical Invariance" approach (Idea 22) by correcting the feature deficiency that caused the Interaction Stream to regress. It fuses the **Robust Invariance** of Idea 22 (for impacts) with the **Rich Context** of Idea 18 (for interactions), augmented by the **Visual Consensus** logic of Idea 21.

# Model

The architecture consists of two specialized **XGBoost** classifiers (Cite solution_lesson_node_00016) operating on physically optimized, disentangled feature spaces.

1.  **Stream A: The Energy-Aware Collider (Interaction Model)**
    *   **Scope:** Predicts contact between two players (`player2 != 'G'`).
    *   **Philosophy:** **Maximal Context & System Energy**. Unlike Idea 22, which simplified features to differentials, this model explicitly retains **Absolute Kinematics** (to define collision energy) alongside **Relational Geometry**.
    *   **Backbone:** A **Conditional Early-Fusion GBDT** (Cite solution_lesson_node_00036).
    *   **Structural Innovation:** **Visual Consensus Pyramids**. Instead of just flattening visual lags, the model calculates consensus metrics (Max/Min/Diff IoU) *at every temporal lag*, allowing it to weigh visual reliability dynamically over the approach trajectory (Synthesis of Cite solution_lesson_node_00044 and solution_lesson_node_00074).

2.  **Stream B: The Invariant Accelerometer (Impact Model)**
    *   **Scope:** Predicts contact between a player and the ground (`player2 == 'G'`).
    *   **Philosophy:** **Strict Biomechanical Invariance**.
    *   **Backbone:** A **Uni-Modal Invariant GBDT**.
    *   **Feature Strategy:** Retains the successful **Finite-Difference Ego-Dynamics** from Idea 22. It strictly excludes absolute coordinates (`x`, `y`) to prevent spatial overfitting (Cite solution_lesson_node_00075) but retains **Scalar Speed/Acceleration** to provide a robust signal baseline (Cite solution_lesson_node_00055).

# Data

**Preprocessing:**
*   **Pipeline Integrity:** Implement **hash-based cache invalidation** derived from the feature configuration (Cite solution_lesson_node_00004).
*   **Validation Mapping:** Explicitly map the `validation` mode to read from `train_player_tracking.csv` to ensure correct data loading (Cite solution_lesson_node_00054).

**Feature Engineering - Stream A (Interaction):**
1.  **System Energy (Restored):** Flattened Exponential Pyramids ($t, t\pm1... t\pm15$) of **Individual Speed** and **Scalar Acceleration** for both players. This restores the energy context lost in Idea 22 (Cite solution_lesson_node_00075).
2.  **Relational Scalars:** Explicit **Euclidean Distance**, **Relative Speed** (scalar), and **Closure Rate** (Cite solution_lesson_node_00062).
3.  **Visual Consensus Pyramids:**
    *   At each sparse lag ($t, t\pm4, t\pm8, t\pm15$), calculate `Sideline_IoU` and `Endzone_IoU`.
    *   Compute **Consensus Features**: `Max_IoU`, `Min_IoU`, and `IoU_Diff`.
    *   Flatten these to capture the *trajectory of visual certainty* (Cite solution_lesson_node_00074).
    *   **Imputation:** Use **Left Join + Sentinel** (`-999`) (Cite solution_lesson_node_00036).

**Feature Engineering - Stream B (Impact):**
1.  **Finite-Difference Ego-Dynamics:**
    *   Project Velocity ($v$) onto Orientation ($\hat{o}$) $\rightarrow$ $v_{surge}, v_{sway}$.
    *   Differentiate $v_{surge/sway}$ $\rightarrow$ **Ego-Acceleration**.
    *   Differentiate Ego-Acceleration $\rightarrow$ **Ego-Jerk**.
    *   (Cite solution_lesson_node_00068).
2.  **Robust Invariance:**
    *   Include **Scalar Speed** and **Scalar Acceleration** (Baseline).
    *   Explicitly **exclude** `x`, `y`, `direction`, `orientation`, and all visual features (Cite solution_lesson_node_00075, solution_lesson_node_00034).

# Training

*   **Sampling:** Apply **Targeted Majority Undersampling**. Retain **100%** of the positive class and randomly subsample the negative class to a 10:1 ratio (Cite solution_lesson_node_00060).
*   **Algorithm:** Train both streams using **XGBoost** with the `gpu_hist` tree method (Cite solution_lesson_node_00016).
*   **Asymmetric Regularization:**
    *   **Stream A:** Standard depth (`max_depth=6`) to model the complex interaction between energy, geometry, and visual consensus.
    *   **Stream B:** **Shallow Depth** (`max_depth=6` to `8`) with **Explicit Physics**. By relying on the robust `Ego-Jerk` signal, we avoid the need for deep trees that overfit sensor noise (Cite solution_lesson_node_00070).
*   **Objective:** Minimize **Binary Logistic Loss**.

# Evaluation

1.  **Inference:**
    *   Route test samples to Stream A or Stream B based on the `contact_id`.
    *   Stream A receives the "Energy + Consensus" vector. Stream B receives the "Invariant Dynamics" vector.
2.  **Optimization:**
    *   **Thresholding:** Decouple the decision boundary from the probability. Perform a linear search on the Validation set to find the optimal probability threshold **independently for each stream** that maximizes the Matthews Correlation Coefficient (MCC) (Cite solution_lesson_node_00002, solution_lesson_node_00025).
    *   **Submission:** Apply these specific thresholds to the Test set predictions.
