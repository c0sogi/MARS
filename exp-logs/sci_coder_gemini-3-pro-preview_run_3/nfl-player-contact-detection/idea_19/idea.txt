Based on the comprehensive analysis of the "Lessons Learned," specifically the failure of uniform sampling (Cite solution_lesson_node_00060), the danger of replacing raw data with projections (Cite solution_lesson_node_00055), and the distinct feature requirements for interactions vs. impacts (Cite solution_lesson_node_00062, solution_lesson_node_00057), I propose the **Physically-Disentangled Dual-Stream GBDT with Hybrid-Coordinate Augmentation**.

This solution structurally evolves the previous "Dual-Stream" approaches by strictly **disentangling** the feature engineering strategies. It rejects the "one-size-fits-all" complexity (e.g., applying ego-centric projections to interactions) and instead implements two divergent, physics-grounded pipelines: a **Relational-Visual Pipeline** for interactions and a **Hybrid-Coordinate Kinematic Pipeline** for ground impacts.

# Model

The architecture consists of two specialized **XGBoost** classifiers operating on completely distinct feature spaces, optimized for the specific physics of their target classes.

1.  **Stream A: Interaction Model (Player-Player)**
    *   **Scope:** Predicts contact between two players (`player2 != 'G'`).
    *   **Backbone:** A **Conditional Early-Fusion GBDT**.
    *   **Feature Strategy:** **Relational Scalars + Visual Pyramids**.
    *   **Rationale:** Interactions are defined by spatial convergence. As learned in Lesson 00062, explicit scalars (Closure Rate, Distance) outperform frame-dependent vector projections for this task. Visual Temporal Pyramids (Cite solution_lesson_node_00044) provide the necessary "looming" signal that tracking data misses.

2.  **Stream B: Impact Model (Player-Ground)**
    *   **Scope:** Predicts contact between a player and the ground (`player2 == 'G'`).
    *   **Backbone:** A **Hybrid-Coordinate Kinematic GBDT**.
    *   **Feature Strategy:** **Raw Field-Centric Anchor + Ego-Centric Augmentation**.
    *   **Rationale:** Ground impacts are invariant to field position but highly correlated with body-relative forces (e.g., lateral sway). As learned in Lesson 00055 and 00057, the model requires *both* the stable raw data (to prevent collapse) and the ego-centric projections (to capture the invariant signature).

# Data

**Preprocessing:**
*   **Pipeline Integrity:** Implement **hash-based cache invalidation** (Cite solution_lesson_node_00004) and **deterministic feature ordering** (Cite solution_lesson_node_00008).
*   **Validation Mapping:** Explicitly map the `validation` mode to read from `train_player_tracking.csv` to prevent the "Test Data" merge failure (Cite solution_lesson_node_00054).

**Feature Engineering - Stream A (Interaction):**
1.  **Tracking (Relational Scalars):**
    *   **Exponential Temporal Pyramids:** Flatten features at sparse lags ($t, t\pm1, t\pm2, t\pm4, t\pm8, t\pm15$) (Cite solution_lesson_node_00042).
    *   **Explicit Scalars:** Calculate **Euclidean Distance**, **Relative Speed** (scalar), and **Closure Rate** (derivative of distance) at each lag. **Do not** project these into the body frame (Cite solution_lesson_node_00062).
    *   **Cyclical Encoding:** Sine/Cosine for all angles (Cite solution_lesson_node_00005).
2.  **Visuals (Temporal Pyramids):**
    *   Flatten Sideline and Endzone IoU/Distance at sparse lags ($t, t\pm4, t\pm8, t\pm15$) (Cite solution_lesson_node_00044).
    *   **Robust Imputation:** Use **Left Join + Sentinel** (`-999`) to handle missing helmet detections without data loss (Cite solution_lesson_node_00036).

**Feature Engineering - Stream B (Impact):**
1.  **Field-Centric Anchor (Raw):**
    *   Flattened Exponential Pyramids of raw Position, Velocity, Acceleration, and Jerk. This provides the robust baseline (Cite solution_lesson_node_00055).
2.  **Ego-Centric Augmentation (Projected):**
    *   For every timestep, project Velocity, Acceleration, and Jerk into **Surge** (Forward/Backward) and **Sway** (Lateral) components relative to the player's orientation.
    *   Flatten these as additional columns to expose invariant impact signatures (Cite solution_lesson_node_00057).
3.  **Physics Derivatives:** Include **Pose-Motion Alignment** (Cite solution_lesson_node_00027).
4.  **Exclusion:** Explicitly **block** all visual features (Cite solution_lesson_node_00034) and relational context (Cite solution_lesson_node_00053).

# Training

*   **Sampling:** Apply **Targeted Majority Undersampling**. Retain **100%** of the positive class and randomly subsample the negative class to a 10:1 ratio. **Do not** use uniform sampling (Cite solution_lesson_node_00060).
*   **Algorithm:** Train both streams using **XGBoost** with the `gpu_hist` tree method (Cite solution_lesson_node_00016).
*   **Regularization:**
    *   **Stream A:** Standard regularization.
    *   **Stream B:** **Relaxed Regularization**. Allow deeper trees (e.g., `max_depth=8` or `10`) to capture the complex non-linear interactions between the Raw and Ego-centric features. Do not over-prune (Cite solution_lesson_node_00045).
*   **Objective:** Minimize **Binary Logistic Loss**.

# Evaluation

1.  **Inference:**
    *   Route test samples to Stream A or Stream B based on the `contact_id`.
    *   Stream A receives the Relational-Visual vector. Stream B receives the Hybrid-Coordinate Kinematic vector.
2.  **Optimization:**
    *   **Thresholding:** Decouple the decision boundary from the probability. Perform a linear search on the Validation set to find the optimal probability threshold **independently for each stream** that maximizes the Matthews Correlation Coefficient (MCC) (Cite solution_lesson_node_00002, solution_lesson_node_00025).
    *   **Submission:** Apply these specific thresholds to the Test set predictions.
