The implementation strategy follows the "Physically-Disentangled Dual-Stream" architecture. The pipeline is orchestrated as follows:

1.  **Configuration & Setup**: The script initializes the environment, setting random seeds and configuring `XGBoost` hyperparameters (reducing boosting rounds and enabling early stopping) to ensure a fast baseline execution within the time limit.
2.  **Feature Generation**: It utilizes `StreamAFeatureGenerator` (Relational-Visual) and `StreamBFeatureGenerator` (Kinematic-Hybrid) to load and process data for training, validation, and testing. It leverages caching (`load_cached_data=True`) to minimize redundant computation.
3.  **Data Preparation**: To adhere to the "fast baseline" requirement, the script implements a safety cap on the training dataset size (e.g., max 200k samples) to guarantee quick turnaround while maintaining representation.
4.  **Model Training**: The `DualStreamModel` is instantiated and trained. This class handles the distinct training logic for both streams, including targeted undersampling and threshold optimization.
5.  **Validation**: The model predicts on the hold-out validation set. The script reconstructs the ground truth, merges it with predictions, and computes the Matthews Correlation Coefficient (MCC).
6.  **Failure Analysis**: It calculates the correlation between prediction errors and input features on the validation set to identify systematic weaknesses.
7.  **Submission**: If the validation MCC exceeds the specified threshold (0.6968), the model generates predictions for the test set and saves the submission file.
