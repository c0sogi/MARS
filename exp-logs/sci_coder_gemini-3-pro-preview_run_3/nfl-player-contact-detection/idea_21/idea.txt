Based on the comprehensive analysis of the "Lessons Learned," particularly the critical need for **Explicit Relational Scalars** in interactions (Cite solution_lesson_node_00062), the superiority of **Finite-Difference Ego-Dynamics** for impacts (Cite solution_lesson_node_00068), and the importance of **Targeted Sampling** (Cite solution_lesson_node_00060), I propose the **Orthogonal-Physics Dual-Stream GBDT with Cross-View Visual Consensus and Finite-Difference Jerk**.

This solution structurally evolves the previous "Dual-Stream" approaches by implementing a **Physics-Orthogonal Feature Strategy**: Stream A (Interaction) is optimized for **Spatial Convergence** using scalar primitives and visual consensus, while Stream B (Impact) is optimized for **Force Transients** using a corrected finite-difference pipeline to capture directional jerk.

# Model

The architecture consists of two specialized **XGBoost** classifiers (Cite solution_lesson_node_00016) operating on physically distinct feature spaces designed to maximize signal-to-noise ratio for their respective tasks.

1.  **Stream A: Interaction Model (Player-Player)**
    *   **Scope:** Predicts contact between two players (`player2 != 'G'`).
    *   **Backbone:** A **Conditional Early-Fusion GBDT**.
    *   **Structural Innovation:** **Cross-View Visual Consensus**.
        *   Instead of simply flattening `Sideline` and `Endzone` features (which forces the tree to learn view selection implicitly), we explicitly engineer **Consensus Metrics** across the temporal window.
        *   **Features:** `Max_IoU` (Optimistic signal), `Min_IoU` (Pessimistic signal), and `IoU_Disagreement` (`|Sideline - Endzone|`).
        *   **Rationale:** High disagreement implies occlusion or perspective illusion. Explicitly exposing this uncertainty allows the model to down-weight visual signals in ambiguous frames and rely more on tracking data (Extension of Cite solution_lesson_node_00016).
    *   **Kinematic Backbone:** **Relational Scalars**.
        *   Strictly utilizes **Euclidean Distance**, **Relative Speed** (scalar), and **Closure Rate**.
        *   **Constraint:** Explicitly rejects frame-dependent vector projections (e.g., "Relative Surge") which fail during non-frontal impacts (Cite solution_lesson_node_00062).

2.  **Stream B: Impact Model (Player-Ground)**
    *   **Scope:** Predicts contact between a player and the ground (`player2 == 'G'`).
    *   **Backbone:** A **Hybrid-Coordinate Kinematic GBDT**.
    *   **Structural Innovation:** **Finite-Difference Directional Jerk**.
        *   Implements a corrected differentiation pipeline to capture **Rotational Dynamics**.
        *   **Pipeline:** Project Velocity $\rightarrow$ Differentiate to get Ego-Acceleration $\rightarrow$ Differentiate to get **Ego-Jerk**.
        *   **Rationale:** Previous attempts failed because they projected global acceleration (losing rotational Coriolis terms) or used noisy scalar jerk. This pipeline isolates **Surge Jerk** (sudden forward stop) and **Sway Jerk** (lateral impact), which are the definitive signatures of ground impact (Cite solution_lesson_node_00068, solution_lesson_node_00070).
    *   **Constraint:** Explicitly **blocks** all visual features (Cite solution_lesson_node_00034) and relational context (Cite solution_lesson_node_00053).

# Data

**Preprocessing:**
*   **Pipeline Integrity:** Implement **hash-based cache invalidation** derived from the feature configuration (Cite solution_lesson_node_00004).
*   **Validation Mapping:** Explicitly map the `validation` mode to read from `train_player_tracking.csv` (Cite solution_lesson_node_00054).

**Feature Engineering - Stream A (Interaction):**
1.  **Tracking (Relational Scalars):**
    *   **Exponential Temporal Pyramids:** Flatten features at sparse lags ($t, t\pm1, t\pm2, t\pm4, t\pm8, t\pm15$) (Cite solution_lesson_node_00042).
    *   **Explicit Scalars:** Distance, Relative Speed, Closure Rate.
    *   **Cyclical Encoding:** Sine/Cosine for all angles (Cite solution_lesson_node_00005).
2.  **Visuals (Consensus Pyramids):**
    *   Calculate `Sideline_IoU` and `Endzone_IoU` at sparse lags ($t, t\pm4, t\pm8, t\pm15$) (Cite solution_lesson_node_00044).
    *   Compute **Consensus Features**: `Max`, `Min`, and `Diff` between views at each lag.
    *   **Robust Imputation:** Use **Left Join + Sentinel** (`-999`) for missing detections (Cite solution_lesson_node_00036).

**Feature Engineering - Stream B (Impact):**
1.  **Field-Centric Anchor (Raw):**
    *   Flattened Exponential Pyramids of raw Position, Velocity, and Acceleration to provide a stable baseline (Cite solution_lesson_node_00055).
2.  **Finite-Difference Ego-Dynamics (The Innovation):**
    *   For every timestep, project **Velocity** ($v$) onto Orientation ($\hat{o}$) $\rightarrow$ $v_{surge}, v_{sway}$.
    *   Calculate **Ego-Acceleration**: $a_{surge} = \Delta v_{surge} / \Delta t$.
    *   Calculate **Ego-Jerk**: $j_{surge} = \Delta a_{surge} / \Delta t$.
    *   Flatten these features to expose the "Rate of Change of Force" in the body frame (Cite solution_lesson_node_00070).

# Training

*   **Sampling:** Apply **Targeted Majority Undersampling**. Retain **100%** of the positive class and randomly subsample the negative class to a 10:1 ratio. **Do not** use uniform sampling (Cite solution_lesson_node_00060).
*   **Algorithm:** Train both streams using **XGBoost** with the `gpu_hist` tree method (Cite solution_lesson_node_00016).
*   **Regularization Strategy:**
    *   **Stream A:** Standard regularization (`max_depth=6`).
    *   **Stream B:** **Moderate Depth Constraint**. Set `max_depth=8`. This balances the need for capacity (to model non-linear ego-dynamics) with the risk of overfitting sensor noise observed with deeper trees (Cite solution_lesson_node_00070, solution_lesson_node_00045).
*   **Objective:** Minimize **Binary Logistic Loss**.

# Evaluation

1.  **Inference:**
    *   Route test samples to Stream A or Stream B based on the `contact_id`.
    *   Stream A receives the Relational-Scalar + Visual-Consensus vector.
    *   Stream B receives the Hybrid-Coordinate + Finite-Difference Jerk vector.
2.  **Optimization:**
    *   **Thresholding:** Decouple the decision boundary from the probability. Perform a linear search on the Validation set to find the optimal probability threshold **independently for each stream** that maximizes the Matthews Correlation Coefficient (MCC) (Cite solution_lesson_node_00002, solution_lesson_node_00025).
    *   **Submission:** Apply these specific thresholds to the Test set predictions.
