# Idea: Time-Windowed Gradient Boosting on Flattened Temporal Features

### Model
I propose a structural shift from the Neural Network paradigms (MLP/CNN) used in previous iterations to a **Gradient Boosted Decision Tree (GBDT)** ensemble, specifically utilizing **XGBoost** with GPU acceleration.
*   **Rationale:** While the Time-Windowed MLP (Idea 1) established a strong baseline, Neural Networks can struggle with the sharp discontinuities introduced by imputing "Ground" tracking data as zeros (Cite Lesson 00002). Decision trees are structurally better suited for this tabular data as they can learn specific split paths for "Ground" cases (e.g., `if is_ground == 1`) versus "Player" cases, without forcing a continuous mathematical function to fit both regimes. Furthermore, GBDTs naturally capture high-order feature interactions (e.g., "high speed" AND "close distance") which MLPs must laboriously approximate.
*   **Architecture:** The model will consist of an ensemble of decision trees trained with the `gpu_hist` method to leverage the available NVIDIA A100. We will utilize a deep tree structure (e.g., max_depth 8-10) to capture the complex kinematic dependencies.

### Data
*   **Input Structure:** We will strictly adhere to the **Flattened Temporal Window** approach (concatenating features from $t-4$ to $t+4$). This preserves the absolute positional sensitivity required to distinguish the exact frame of contact ($t=0$) from near-misses or adjacent frames, avoiding the "smearing" effect observed with translation-invariant architectures like CNNs with Global Pooling (Cite Lesson 00015).
*   **Feature Engineering:**
    *   **Cyclical Encoding:** All angular features (orientation, direction) will be decomposed into sine and cosine components to preserve topological continuity (Cite Lesson 00005).
    *   **Explicit Interactions:** We will engineer physics-based interaction features—specifically **Relative Speed**, **Relative Acceleration**, and **Closure Rate**—for every timestep in the window. This explicitly provides the "rate of convergence" signals that proved critical for performance (Cite Lesson 00006).
    *   **Deterministic Pipeline:** The feature set will be defined by a hardcoded, ordered list to ensure deterministic input construction (Cite Lesson 00008).
    *   **Robust Caching:** The data loading pipeline will use hash-based filenames derived from the feature configuration to ensure that any logic changes automatically invalidate old caches (Cite Lesson 00004).

### Training
*   **Sampling:** We will continue to use **Random Undersampling** on the majority class (No Contact) with a 10:1 negative-to-positive ratio. This creates a balanced enough dataset for the trees to learn the minority class structure without being overwhelmed by empty frames (Cite Lesson 00005).
*   **Objective:** The model will be trained to minimize **Binary Logistic Loss**. To further address imbalance within the sampled set, we will tune the `scale_pos_weight` parameter.
*   **Validation:** We will employ Early Stopping based on the validation set's Log Loss or AUC to determine the optimal number of boosting rounds.

### Evaluation
*   **Threshold Optimization:** Recognizing that the default 0.5 probability cutoff is suboptimal for this imbalanced metric, we will decouple the training objective from the decision boundary. We will perform a linear search on the validation set predictions to find the probability threshold that maximizes the **Matthews Correlation Coefficient (MCC)** and apply this specific threshold to the test set predictions (Cite Lesson 00002).
