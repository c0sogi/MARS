To demonstrate the usage of the provided library files for the contact detection task, I will implement a script that executes the full machine learning pipeline on a reduced subset of the data to ensure speed.

The strategy involves:
1.  **Data Subsetting**: Creating smaller versions of the training and validation metadata files containing only a few plays. This drastically reduces the time spent on feature engineering (merging tracking and helmet data).
2.  **Configuration Patching**: Modifying the `Config` class at runtime to point to these smaller metadata files and to reduce the number of boosting rounds for the XGBoost models.
3.  **Pipeline Execution**:
    *   **Data Loading**: Using `DataManager` to generate features for Stream A (Player-Player) and Stream B (Player-Ground).
    *   **Training**: Using `ContactGBDT` (Gradient Boosted Decision Trees) to train models for both streams.
    *   **Inference**: generating predictions on the test set.
    *   **Optimization**: Finding the optimal probability thresholds using the validation set.
    *   **Submission**: Combining predictions and saving the final CSV.
