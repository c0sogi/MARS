Based on the comprehensive analysis of previous attempts and lessons learned, I propose a **Robust Asymmetric Modality-Selective GBDT**.

This solution structurally evolves the failed "Idea 9" by addressing the catastrophic data loss identified in **Lesson 00036**. While the conceptual insight of "Asymmetric Modality" (using Visuals for interactions but not for ground impacts) was sound (Cite solution_lesson_node_00034), the implementation failed because it enforced a strict dependency on visual data. The new architecture fundamentally restructures the data pipeline into a **Primary-Secondary Fusion** system, treating Tracking as the reliable backbone and Visuals as conditional enrichments, ensuring data integrity while leveraging the high-signal geometric features.

# Model

The architecture consists of two specialized **XGBoost** classifiers operating on distinct, physically-informed feature spaces.

1.  **Stream A: Interaction Model (Player-Player)**
    *   **Scope:** Predicts contact between two players (`player2 != 'G'`).
    *   **Architecture:** A **Robust Early-Fusion GBDT**.
    *   **Structural Innovation:** Unlike previous "Early Fusion" attempts that performed an intersection (Inner Join) of modalities, this stream utilizes a **Left-Join Fusion Topology**. The model accepts a feature vector where Tracking data is mandatory, but Visual data is treated as a sparse enrichment. Missing visual data (due to occlusion or detection failure) is explicitly handled via imputation (e.g., `IoU = -1`), allowing the GBDT to learn a "Trust" branch: *If Visual Data exists, use it; otherwise, fall back to Tracking.*
    *   **Rationale:** This resolves the "Silent Data Loss" (Cite solution_lesson_node_00036) while retaining the critical "Visual Geometry" signals (IoU) that outperform tracking centroids for spatial overlap (Cite solution_lesson_node_00034).

2.  **Stream B: Impact Model (Player-Ground)**
    *   **Scope:** Predicts contact between a player and the ground (`player2 == 'G'`).
    *   **Architecture:** A **Uni-Modal Kinematic GBDT**.
    *   **Constraint:** Explicitly **blocks** all visual features.
    *   **Rationale:** Ground impact is defined by force transients (Jerk) and loss of control. Visual bounding box derivatives (e.g., "drop velocity") introduce fatal noise (Cite solution_lesson_node_00034). This stream relies exclusively on high-fidelity sensor kinematics.

# Data

**Preprocessing:**
*   **Pipeline Integrity:** Implement **hash-based cache invalidation** derived from the full feature configuration to prevent stale data loading (Cite solution_lesson_node_00004).
*   **Deterministic Ordering:** Use hardcoded whitelists to strictly define feature order (Cite solution_lesson_node_00008).

**Feature Engineering - Stream A (Tracking + Robust Visuals):**
1.  **Primary Modality (Tracking):**
    *   **Multi-Resolution Windows:** Flattened Micro ($t \pm 4$) and Macro ($t \pm 15$) windows (Cite solution_lesson_node_00031).
    *   **Interaction Features:** Relative Speed, Closure Rate (Cite solution_lesson_node_00006), and Cyclical Angle Encoding (Cite solution_lesson_node_00005).
2.  **Secondary Modality (Visual Geometry):**
    *   **View-Specific Flattening:** Instead of aggregating views, flatten **Sideline** and **Endzone** features separately (e.g., `Sideline_IoU`, `Endzone_IoU`). This allows the tree to learn view reliability based on field position (Cite solution_lesson_node_00016).
    *   **Geometry Only:** Calculate **Intersection over Union (IoU)** and **Centroid Pixel Distance**. Do *not* calculate derivatives (velocity/acceleration) of these boxes (Cite solution_lesson_node_00034).
    *   **Robust Imputation:** During the merge, use `how='left'` on the Tracking index. Fill missing visual records with a distinct sentinel value (e.g., -1) to preserve the row count (Cite solution_lesson_node_00036).

**Feature Engineering - Stream B (Tracking Only):**
1.  **Kinematics:** Flattened Micro/Macro windows of Position, Velocity, and Acceleration.
2.  **Physics Derivatives:** Explicitly include **Jerk** (derivative of acceleration) and **Pose-Motion Alignment** (dot product of orientation and velocity) to detect tumbling and sudden stops (Cite solution_lesson_node_00027).
3.  **Exclusion:** Remove all visual features and "Player 2" relative features to prevent noise injection.

# Training

*   **Sampling:** Apply **Random Undersampling** with a 10:1 negative-to-positive ratio independently to each stream. This balances training efficiency with sufficient negative exposure (Cite solution_lesson_node_00005).
*   **Algorithm:** Train both streams using **XGBoost** with the `gpu_hist` tree method. This backbone is selected for its superior performance on flattened tabular windows (Cite solution_lesson_node_00016) and ability to handle the non-linear "Ground" logic (Cite solution_lesson_node_00002).
*   **Objective:** Minimize **Binary Logistic Loss**.
*   **Validation:** Use GroupShuffleSplit by `game_play` to ensure no data leakage.

# Evaluation

1.  **Inference:**
    *   Route test samples to Stream A or Stream B based on the `contact_id`.
    *   Stream A receives the fused vector (with imputed missing visuals). Stream B receives the pure tracking vector.
2.  **Optimization:**
    *   **Thresholding:** Decouple the decision boundary from the probability. Perform a linear search on the Validation set to find the optimal probability threshold **independently for each stream** that maximizes the Matthews Correlation Coefficient (MCC) (Cite solution_lesson_node_00002, solution_lesson_node_00025).
    *   **Submission:** Apply these specific thresholds to the Test set predictions to generate the final binary labels.
