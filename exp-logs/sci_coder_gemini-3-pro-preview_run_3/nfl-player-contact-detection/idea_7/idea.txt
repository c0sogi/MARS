Based on the progression of empirical findings—specifically the superiority of Gradient Boosted Trees on flattened windows (Cite solution_lesson_node_00016), the success of splitting "Player" and "Ground" tasks (Cite solution_lesson_node_00025), and the diminishing returns of over-engineering tracking derivatives (Cite solution_lesson_node_00032)—I propose a **Multi-Modal Late-Fusion Ensemble**.

This solution structurally evolves the previous "Multi-Resolution Dual-Stream" approach by integrating a secondary modeling stream based on **Helmet Bounding Box** data. This directly addresses the "Distance Ambiguity" limitation of tracking data (Center of Mass) by incorporating "Head-to-Head" visual geometry without the cost of raw video processing.

# Model

The architecture consists of two independent feature extraction streams feeding into a final fusion layer.

1.  **Stream A: Kinematic Predictor (Tracking Data)**
    *   **Backbone:** The **Multi-Resolution Dual-Stream GBDT** established in previous iterations.
    *   **Structure:** Two specialized XGBoost classifiers:
        *   **A1 (Player-Interaction):** Trained on player-pair tracking data to detect collisions.
        *   **A2 (Ground-Impact):** Trained on single-player tracking data to detect falls/tackles.
    *   **Input:** Flattened temporal windows of tracking data.
    *   **Rationale:** Retains the high performance of GBDTs on tabular kinematic data (Cite solution_lesson_node_00016) and the specialized handling of heterogeneous classes (Cite solution_lesson_node_00025).

2.  **Stream B: Visual-Geometric Predictor (Helmet Data)**
    *   **Backbone:** A parallel **Dual-Stream XGBoost** architecture.
    *   **Structure:** Identical split (Player-Player vs. Player-Ground).
    *   **Input:** Flattened temporal windows of helmet bounding box geometry derived from `baseline_helmets.csv`.
    *   **Rationale:** Incorporates distinct physical signals—specifically **Visual Intersection over Union (IoU)** and **Head Proximity**—which provide orthogonal information to the "Center of Mass" distance measured by tracking sensors. This follows the guidance to prioritize new context over mathematical reformulations of existing signals (Cite solution_lesson_node_00032).

3.  **Fusion Layer:**
    *   A **Learned Linear Blender** that combines the probability outputs of Stream A and Stream B ($P_{final} = w_A P_A + w_B P_B$).

# Data

**Preprocessing:**
*   **Pipeline Integrity:** Implement **hash-based cache invalidation** derived from the feature configuration to ensure that any logic changes automatically trigger data regeneration (Cite solution_lesson_node_00004).
*   **Deterministic Ordering:** Use a hardcoded whitelist to strictly define the feature order, preventing "silent drops" of computed features (Cite solution_lesson_node_00008, solution_lesson_node_00022).

**Feature Engineering (Stream A - Tracking):**
*   **Multi-Resolution Windows:** Construct features from two scopes (Cite solution_lesson_node_00031):
    *   **Micro ($t \pm 4$):** Raw kinematics, **Relative Speed** (Cite solution_lesson_node_00006), and **Pose-Motion Alignment** (Cite solution_lesson_node_00027) to capture instantaneous mechanics.
    *   **Macro ($t \pm 15$):** Aggregated rolling statistics (Mean, Max, Std) to capture trajectory context.
*   **Cyclical Encoding:** Transform all angular features into Sine/Cosine components (Cite solution_lesson_node_00005).

**Feature Engineering (Stream B - Helmets):**
*   **Synchronization:** Interpolate helmet bounding box data to match the 10Hz tracking timestamps.
*   **View Aggregation:** For each timestep, calculate features for both "Sideline" and "Endzone" views and take the **Max** value (e.g., Max IoU) to capture the contact from the most visible angle.
*   **Geometry:** Calculate **Visual IoU**, **Centroid Pixel Distance**, and **Box Area** (proxy for depth). Flatten these over a $t \pm 4$ window.

# Training

*   **Sampling:** Apply **Random Undersampling** with a 10:1 negative-to-positive ratio independently to all four sub-models (A1, A2, B1, B2). This balances training efficiency with sufficient negative exposure (Cite solution_lesson_node_00005).
*   **Algorithm:** Train all sub-models using **XGBoost** with the `gpu_hist` tree method for computational speed.
*   **Objective:** Minimize **Binary Logistic Loss**.

# Evaluation

1.  **Inference:** Generate independent probability predictions for the Test set using Stream A and Stream B.
2.  **Optimization:**
    *   **Blending:** On the Validation set, perform a grid search to find the optimal blending weights ($w_A, w_B$) that maximize the Matthews Correlation Coefficient (MCC).
    *   **Thresholding:** Decouple the decision boundary from the probability. Perform a linear search on the *blended* Validation probabilities to find the optimal cutoff threshold that maximizes MCC (Cite solution_lesson_node_00002).
3.  **Submission:** Apply the optimized weights and threshold to the Test predictions to generate the final binary labels.
