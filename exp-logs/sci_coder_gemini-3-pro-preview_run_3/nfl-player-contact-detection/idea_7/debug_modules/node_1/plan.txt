The issue stems from the use of an `inner` join in `HelmetFeatureGenerator` when merging the ground truth metadata with Player 1's helmet tracking data. Because the helmet detection model is imperfect, there are time steps where Player 1 is not detected. The `inner` join discards these rows, reducing the size of the dataset (`X_train_b`) compared to the Tracking stream (`X_train_a`), which uses a `left` join and preserves all time steps. This mismatch causes the assertion error in the ensemble pipeline.

To fix this, I will change the merge strategy in `library/features_helmets.py` from `how="inner"` to `how="left"`. This ensures that every row in the metadata is retained, even if Player 1 is not visible in the video. The missing visual features will result in `NaN` values, which are already handled by the subsequent `fillna(0)` operation in the pipeline, effectively treating missing detections as having no visual contact signal. This aligns with the need to maintain consistent dataset dimensions across different modalities (Cite debug_lesson_2).
