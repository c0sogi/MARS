The issue is caused by the default behavior of `pandas.DataFrame.groupby`, which drops rows where any of the grouping keys are `NaN` (`dropna=True`). In `library/features_helmets.py`, the code coerces `nfl_player_id_2` to numeric, converting "G" (Ground) to `NaN`. Consequently, all "Player vs. Ground" contact rows are silently discarded during the view aggregation and windowing steps, causing a dataset size mismatch with Stream A (Tracking).

To fix this, I will explicitly set `dropna=False` in the `groupby` calls within `_compute_interactions_and_aggregate` and `_apply_windowing` in `library/features_helmets.py`. This ensures that rows with `NaN` in `nfl_player_id_2` (Ground contacts) are preserved, aligning the dataset sizes. Cite debug_lesson_9.
