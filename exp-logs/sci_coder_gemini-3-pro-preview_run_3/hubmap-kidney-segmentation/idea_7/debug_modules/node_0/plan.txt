The following implementation demonstrates the end-to-end workflow of the provided HuBMAP FTU detection library. The strategy involves:

1.  **Configuration Override**: Dynamically modifying the `Config` class to create a "demo" environment. This includes setting the `DEBUG` flag to `True`, reducing image tile sizes to 256x256, lowering batch sizes, and setting epochs to 1 to ensure the script completes rapidly (within minutes).
2.  **Utility Verification**: Testing the Run-Length Encoding (RLE) logic (`rle_encode` and `rle_decode`) with a synthetic binary mask to confirm data integrity.
3.  **Dataset Verification**: Instantiating the `HubmapDataset` with the training metadata, fetching a sample, and asserting that the output tensors for the image and mask have the correct shapes and data types.
4.  **Model Architecture Check**: Building the U-Net++ model, passing a dummy input tensor, and verifying that the Deep Supervision output structure (a list of tensors) and dimensions are correct.
5.  **Training Simulation**: Executing the `train_model` function. This runs a shortened training cycle (Phase 1 and Phase 2) using the modified configuration and saves a `best_model.pth`.
6.  **Inference Execution**: Running `run_inference` to generate predictions on the test set using the trained model, resulting in a `submission.csv`.
7.  **Final Validation**: checking that the model checkpoint and submission file were successfully created.
