The issue is a discrepancy between the configuration contract and the model implementation. The configuration enables `DEEP_SUPERVISION = True` and defines loss weights for multiple outputs, but the custom `Unet` class in `library/model.py` ignores this flag and returns only a single tensor. This violates the interface expected by the training and verification scripts, which require a list of multi-scale outputs when deep supervision is active. Cite debug_lesson_5.

To fix this, I will modify `library/model.py` to:
1.  Update the `Unet` constructor to accept a `deep_supervision` argument.
2.  Initialize auxiliary segmentation heads for intermediate decoder levels if deep supervision is enabled.
3.  Update the `forward` method to collect intermediate feature maps, pass them through the auxiliary heads, upsample them to the input size, and return a list of tensors.
4.  Update `build_model` to pass the `Config.DEEP_SUPERVISION` flag to the `Unet` constructor.
