Based on the synthesis of the provided lessons, I propose a **Multi-Task Neuro-Symbolic Cascade**. This solution structurally evolves the "Tail" solver by integrating the semantic supervision attempted in Idea 5 with the robust recurrent backbone validated in Lesson 18, while strictly maintaining the specificity-based routing established in Lessons 1, 6, and 8.

# Model

The architecture is a three-stage cascade designed to balance speed, precision, and semantic disambiguation:

1.  **Stage 1: Bidirectional Symbolic Memory (The "Head")**
    *   **Component:** A prioritized hierarchy of hash maps: **Trigrams** ($t_{i-1}, t_i, t_{i+1}$) $\to$ **Left/Right Bigrams** $\to$ **Unigrams**.
    *   **Role:** This layer resolves the Zipfian "head" of the distribution. By prioritizing **Trigrams**, it handles context-dependent ambiguities (e.g., "St." $\to$ "Street" vs. "Saint") via exact memorization (Cite solution_lesson_node_00006).

2.  **Stage 2: Heuristic Router (The "Gate")**
    *   **Component:** A logical filter that checks if an Out-Of-Vocabulary (OOV) token is **purely alphabetic**.
    *   **Role:** If the condition is met, it predicts the **Identity** (raw token). This prevents the neural model from hallucinating on rare proper nouns, restricting the neural problem space to structure-rich entities (digits, symbols) (Cite solution_lesson_node_00008).

3.  **Stage 3: Multi-Task Attentional Recurrent Network (The "Tail")**
    *   **Backbone:** A **Bi-Directional GRU Encoder** paired with a **Uni-Directional GRU Decoder** using **Bahdanau Attention**.
        *   *Rationale:* We revert to the Recurrent architecture because it possesses the necessary inductive bias for monotonic, character-level transduction, which was proven superior to Transformers for this specific task (Cite solution_lesson_node_00018).
    *   **Structural Innovation (Multi-Task Learning):** We attach an **Auxiliary Classification Head** to the final hidden state of the Encoder.
        *   *Mechanism:* While the Decoder generates the normalized text, the Auxiliary Head simultaneously predicts the token's `class` (e.g., `DATE`, `MONEY`, `CARDINAL`).
        *   *Rationale:* This forces the Encoder to learn semantic representations that distinguish ambiguous inputs (e.g., "1998" as a Date vs. a Cardinal) to satisfy the classification loss. This achieves the disambiguation goal of "Class-Conditioning" (Idea 5) without the inference-time fragility of generating class tokens in the output sequence (Cite solution_lesson_node_00018).

# Data

**Preprocessing for Training:**
1.  **Symbolic Aggregation:** Construct Trigram, Bigram, and Unigram frequency maps from the full `train.parquet` using Maximum Likelihood Estimation.
2.  **Neural Dataset Construction:**
    *   **Filtering:** Retain only "Hard" samples (exclude `PLAIN`, `PUNCT`, and purely alphabetic tokens) to focus capacity on the "long tail" (Cite solution_lesson_node_00001).
    *   **Input Formatting:** Create a context-aware character sequence: `[prev_token] <SEP> [target_token] <SEP> [next_token]`. This local window is critical for resolving context-dependent patterns (Cite solution_lesson_node_00006).
    *   **Target Formatting:** Extract both the `after` text (for generation) and the `class` label (for the auxiliary task).

**Preprocessing for Evaluation:**
*   Generate N-gram keys for all test tokens.
*   Identify "Neural Candidates" (OOV + Non-Alpha).
*   Format inputs as `[prev] <SEP> [target] <SEP> [next]` for the Neural model.

# Training

1.  **Symbolic Training:** Instantaneous count-based aggregation (MLE).
2.  **Neural Training:**
    *   **Objective:** Minimize a joint loss function: $L_{total} = L_{generation} + \lambda L_{classification}$.
        *   $L_{generation}$: Cross-Entropy loss on the character sequence (with Teacher Forcing).
        *   $L_{classification}$: Cross-Entropy loss on the class label prediction.
        *   $\lambda$: A weighting factor (e.g., 0.5) to balance the tasks.
    *   **Optimizer:** Adam optimizer.
    *   **Strategy:** The auxiliary classification task acts as a regularizer, shaping the encoder's latent space to cluster structurally similar but semantically distinct tokens, thereby aiding the attention mechanism during decoding (Cite solution_lesson_node_00010).

# Evaluation

The inference pipeline follows the "Specificity-Based Cascade" (Cite solution_lesson_node_00008):
1.  **Lookup:** Query Trigram $\to$ Bigram $\to$ Unigram. If a match is found, output the stored value.
2.  **Safety Check:** If the token is OOV and `isalpha()`, output the Identity (raw token).
3.  **Neural Inference:**
    *   Pass the context-augmented input to the Bi-GRU Encoder.
    *   (Optional) The classification head prediction can be ignored during inference, or used for logging/debugging.
    *   Use **Beam Search** decoding on the GRU Decoder to generate the final normalized text string.
