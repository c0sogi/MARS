The implementation strategy follows a Hybrid Neuro-Symbolic approach to balance speed, accuracy, and generalization:

1.  **Training Phase**:
    *   **Symbolic Memory**: We first utilize the `SymbolicMemory` component (N-gram lookup tables) to memorize frequent patterns from the training data. This handles the vast majority of "easy" cases (e.g., standard words, punctuation) with 100% precision.
    *   **Neural Solver**: We train a Seq2Seq (GRU-based) model specifically on the "hard" cases. We use the `run_training` function with a `debug_sample_size` limit (100,000 samples) to ensure the training completes quickly within the time limit. The model learns to normalize complex tokens (dates, numbers, symbols) that are not covered by the lookup tables.

2.  **Validation Phase**:
    *   We load the **full** validation set using `load_metadata("val")`. We manually generate the context columns (`prev`, `next`) to avoid the filtering applied by the standard data loader, ensuring we evaluate on the entire hold-out set as required.
    *   We run the hybrid inference pipeline:
        1.  **Symbolic Lookup**: Check Trigram/Bigram/Unigram tables.
        2.  **Heuristic Filter**: If the token is purely alphabetic and OOV, predict identity (prevents over-correction of rare names).
        3.  **Neural Inference**: For remaining complex tokens, use the trained Seq2Seq model.
    *   We calculate and print the `Final Validation Metric` (accuracy).

3.  **Failure Analysis**:
    *   We compare predictions against ground truth to identify errors.
    *   We calculate the correlation between the error occurrence and input features (length, number of digits) to understand the model's weaknesses.

4.  **Submission**:
    *   If the validation accuracy exceeds the specified threshold (`0.9922596405123719`), we execute the `predict_dataset` method of the `HybridNormalizer` to generate the final `submission.csv` for the test set.
