Based on the progression of insights from the provided lessons, I propose a **Hybrid Neuro-Symbolic Architecture with Transformer-Based Transduction**. This solution evolves the "Tail" solver from a recurrent architecture to a self-attention based one, while strictly preserving the highly effective symbolic "Head" and routing logic.

# Model

The architecture is designed as a three-stage cascade, prioritizing specificity and computational efficiency:

1.  **Stage 1: Bidirectional Symbolic Memory (The "Head")**
    *   This component retains the **Bidirectional N-Gram Hierarchy** identified as optimal in previous iterations. It consists of four prioritized lookup layers: **Trigrams** ($t_{i-1}, t_i, t_{i+1}$), **Left Bigrams** ($t_{i-1}, t_i$), **Right Bigrams** ($t_i, t_{i+1}$), and **Unigrams** ($t_i$).
    *   This layer resolves the vast majority of tokens (the Zipfian "head") and context-dependent ambiguities (e.g., "Dr." followed by a name vs. an address) using exact memorization (Cite solution_lesson_node_00006).

2.  **Stage 2: Heuristic Router (The "Gate")**
    *   This logic gate filters Out-Of-Vocabulary (OOV) tokens before they reach the neural network. It checks if the OOV token is **purely alphabetic**. If so, it predicts the **Identity** (raw token).
    *   This prevents the neural model from hallucinating on rare proper nouns or obscure words, effectively restricting the neural problem space to complex, non-standard entities (Cite solution_lesson_node_00008).

3.  **Stage 3: Transformer-Based Character Transducer (The "Tail")**
    *   This component replaces the previous RNN/GRU architecture with a **Character-Level Transformer Encoder-Decoder**.
    *   **Architecture:** A lightweight Transformer (e.g., 4-6 layers, 4 heads) trained from scratch.
    *   **Rationale:** While the Attention mechanism in the GRU was beneficial (Cite solution_lesson_node_00010), a full Transformer architecture allows for **global self-attention**. This enables the model to simultaneously attend to the currency symbol at the start of a string ("$") and the decimal point in the middle (".") to correctly generate the suffix "dollars" and "cents" without the information bottleneck inherent in recurrent steps.

# Data

**Preprocessing for Training:**
1.  **Symbolic Aggregation:** Perform a single pass over the full `train.parquet` to build the Trigram, Bigram, and Unigram frequency maps using Maximum Likelihood Estimation.
2.  **Neural Dataset Filtering:** Create a specialized "hard" dataset by filtering the training corpus. Keep only samples where the token class is **not** `PLAIN` or `PUNCT`, or where the token contains digits or symbols. This focuses the Transformer's capacity solely on the complex patterns it needs to solve (Cite solution_lesson_node_00001).
3.  **Contextual Input Formatting:** For the neural dataset, format the input as a character sequence: `[prev] <SEP> [target] <SEP> [next]`. This explicitly provides the local context required for disambiguation (Cite solution_lesson_node_00006).
4.  **Character Tokenization:** Use a character-level tokenizer (mapping unique characters to IDs) rather than subwords. This is crucial for normalization, where output is strictly determined by the sequence of input characters (digits, punctuation).

**Preprocessing for Evaluation:**
*   Generate N-gram keys for all test tokens.
*   Identify "Neural Candidates" (OOV tokens that fail the alphabetic heuristic) and pre-format them into the context-augmented character sequences required by the Transformer.

# Training

1.  **Symbolic Training:** Instantaneous construction of hash maps from the aggregated counts.
2.  **Neural Training:** Train the Transformer on the filtered "hard" dataset.
    *   **Optimization:** Use the **AdamW** optimizer with a **Linear Warmup and Cosine Decay** learning rate schedule. This is essential for stabilizing Transformer training compared to RNNs.
    *   **Loss Function:** Use Cross-Entropy Loss with **Label Smoothing** (e.g., 0.1). This prevents the model from becoming over-confident on specific training examples, improving its generalization to unseen numerical formats in the test set.

# Evaluation

The inference pipeline follows the strict "Specificity-Based Cascade":
1.  **Lookup:** Query the hierarchy (Trigram $\to$ Left/Right Bigram $\to$ Unigram). If a match is found, output the stored value immediately.
2.  **Safety Check:** If Lookup fails, check if the token is `isalpha()`. If yes, output the raw token.
3.  **Neural Generation:** If the token contains digits/symbols, tokenize the `[prev] <SEP> [target] <SEP> [next]` string, pass it through the Transformer, and decode the output sequence to produce the normalized text.
