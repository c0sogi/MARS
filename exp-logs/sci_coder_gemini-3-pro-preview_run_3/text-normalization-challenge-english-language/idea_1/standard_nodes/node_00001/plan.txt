3.  **Validation**: We run `model.evaluate()` on the validation split. This computes the accuracy of the symbolic retrieval approach. We explicitly print the result in the required format `Final Validation Metric: <value>`.
4.  **Failure Analysis**: To understand where the model fails, we manually generate predictions on the validation set again (or reuse the data loaded during evaluation logic if accessible, though re-loading is cleaner given the API). 5.  **Submission**: Finally, we invoke `model.generate_submission()` to process the test set and save the `submission.csv` file, ensuring the output directory exists.
