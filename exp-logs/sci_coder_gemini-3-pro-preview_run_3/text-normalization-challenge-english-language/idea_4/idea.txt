Based on the progression of insights from the provided lessons, I propose a **Retrieval-Augmented Hybrid Cascade**. This solution structurally evolves the "Tail" solver by shifting from a purely generative paradigm to a **Retrieval-Augmented Generation (RAG)** framework. This directly addresses the "Long Tail" problem (Cite solution_lesson_node_00001) by providing the neural model with explicit, similar examples from the training data, effectively bridging the gap between rigid memorization and fluid generalization.

# Model

The architecture is a three-stage cascade designed to maximize precision and coverage:

1.  **Stage 1: Bidirectional Symbolic Memory (The "Head")**
    *   **Component:** A prioritized hierarchy of hash maps: **Trigrams** ($t_{i-1}, t_i, t_{i+1}$) $\to$ **Left/Right Bigrams** $\to$ **Unigrams**.
    *   **Role:** Instantly resolves frequent tokens and context-dependent ambiguities (e.g., "Dr." $\to$ "Doctor" vs. "Drive") using exact memorization. This preserves the high-precision "Head" solution established in previous iterations (Cite solution_lesson_node_00006).

2.  **Stage 2: Heuristic Router (The "Gate")**
    *   **Component:** A logical filter that checks if an Out-Of-Vocabulary (OOV) token is **purely alphabetic**.
    *   **Role:** If the condition is met, it predicts the **Identity** (raw token). This prevents the neural model from hallucinating on rare proper nouns, restricting the neural problem space to complex, structure-rich entities (digits, symbols) (Cite solution_lesson_node_00008).

3.  **Stage 3: Retrieval-Augmented Character Transformer (The "Tail")**
    *   **Component:** A **Character-Level Transformer** (Encoder-Decoder) augmented with a **Non-Parametric Memory**.
    *   **Mechanism:** For a given input token (e.g., "12.5kg"), the system retrieves the most structurally similar token from the "Hard" training set (e.g., "5.2kg") along with its ground truth normalization ("five point two kilograms").
    *   **Input Representation:** The Transformer receives a concatenated sequence: `[Context_Window] <SEP> [Retrieved_Raw] <SEP> [Retrieved_Norm] <SEP> [Target_Raw]`.
    *   **Role:** This allows the model to "copy" the transformation logic from a known, similar example rather than relying solely on implicit weights. This is superior to standard Seq2Seq for the "Long Tail" of unseen numerical formats. The Transformer architecture ensures precise character alignment via global self-attention (Cite solution_lesson_node_00010).

# Data

**Preprocessing for Training:**
1.  **Symbolic Aggregation:** Construct the Trigram, Bigram, and Unigram frequency maps from the full `train.parquet`.
2.  **Neural Index Construction:** Filter the training data to retain only "Hard" tokens (excluding `PLAIN`, `PUNCT`, and purely alphabetic tokens). Build a **Nearest Neighbor Index** (using `scikit-learn` or `faiss`) on these tokens based on **Character N-gram TF-IDF** vectors. This captures structural similarity (e.g., "12.5kg" is close to "5.2kg").
3.  **Dynamic Context Generation:** For each training sample in the "Hard" set, query the index to retrieve 1-3 nearest neighbors (excluding the sample itself). Format the input sequence to include these retrieved examples as prompts.

**Preprocessing for Evaluation:**
*   Generate N-gram keys for all test tokens.
*   Identify "Neural Candidates" (OOV + Non-Alpha).
*   Query the "Hard" Token Index to retrieve the nearest neighbor for each candidate and format the Transformer input.

# Training

1.  **Symbolic Training:** Perform count-based aggregation (MLE) for the lookup tables.
2.  **Neural Training:** Train the Retrieval-Augmented Transformer on the "Hard" dataset.
    *   **Objective:** Cross-Entropy Loss on the character output sequence.
    *   **Strategy:** Use **Teacher Forcing** and **Label Smoothing**. Crucially, the retrieval mechanism must be active during training (retrieving neighbors for the current batch) to teach the model how to utilize the provided "cheat sheet" (the retrieved example) to infer the normalization logic.

# Evaluation

The inference pipeline follows the "Specificity-Based Cascade" (Cite solution_lesson_node_00008):
1.  **Lookup:** Query the Bidirectional Hierarchy (Trigram $\to$ Bigram $\to$ Unigram). If found, output result.
2.  **Safety Check:** If OOV, check `isalpha()`. If true, output Identity.
3.  **Retrieval-Augmented Generation:**
    *   Encode the target token using the TF-IDF vectorizer.
    *   Retrieve the nearest neighbor from the training index.
    *   Construct the prompt: `[Context] [Neighbor_Raw] [Neighbor_Norm] [Target]`.
    *   Pass to the Transformer to generate the normalized text.
