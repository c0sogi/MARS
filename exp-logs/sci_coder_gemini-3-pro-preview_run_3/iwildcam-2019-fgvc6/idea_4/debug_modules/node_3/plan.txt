The issue is that the training loop initializes `best_f1` to `0.0` and only saves the model checkpoint if the current validation F1 score strictly exceeds this value (`val_f1 > best_f1`). In the demonstration run, the model achieved an F1 score of `0.0`, causing the condition `0.0 > 0.0` to fail. As a result, no new checkpoint was saved, and the inference script subsequently loaded a stale `demo_model.pth` file containing weights from a previous, incompatible architecture (EfficientNet), leading to a `RuntimeError` due to key mismatches (Cite debug_lesson_2).

To fix this, I will initialize `best_f1` to `-1.0` in `library/train.py`. This ensures that the first epoch's result (even if `0.0`) triggers a save, overwriting the stale checkpoint with the correct architecture weights.

    early_stop_counter = 0
