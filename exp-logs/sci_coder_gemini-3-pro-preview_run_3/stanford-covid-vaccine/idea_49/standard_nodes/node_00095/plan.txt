The implementation strategy focuses on establishing a fast, reproducible, and compliant baseline using the provided library components.

1.  **Configuration & Setup**: We will initialize the environment using `seed_everything` for reproducibility. We will leverage the existing `Config` class but override the training duration (`EPOCHS = 10`) to ensure the "fast baseline" requirement is met within the 2-hour limit.
2.  **Data Loading**: We will utilize `get_dataloaders(load_cached_data=True)` to efficiently load the preprocessed training, validation, and test sets, minimizing I/O overhead.
3.  **Model Training**: The `DeepStabilizedBiGRU` model will be instantiated and moved to the GPU. We will employ the `AdamW` optimizer and `MCRMSELoss` as defined in the library. The training loop will include gradient clipping and validation monitoring to save the best model checkpoint based on the specific scored columns (`reactivity`, `deg_Mg_pH10`, `deg_Mg_50C`).
4.  **Validation & Metrics**: Post-training, we will reload the best model state and perform inference on the full validation set. The `calculate_metric` utility will be used to compute the official MCRMSE. This value will be printed strictly as `Final Validation Metric: <value>`.
5.  **Failure Analysis**: We will compute the Root Mean Squared Error (RMSE) for each validation sample. By merging these errors with the validation metadata (loaded from `./metadata/val.parquet`), we will calculate and print the Pearson correlation between the error magnitude and key input features like `signal_to_noise` and `SN_filter`.
6.  **Submission**: A conditional check will be applied to the final metric. If it falls below the threshold `0.5884495377540588`, we will generate predictions for the test set, format them into the required `id_seqpos` structure, and save the result to `./submission/submission.csv`.
