# Proposed Strategy: Conformer-based RNA Encoder with Full-Spectrum Training

This strategy introduces a **Conformer (Convolution-augmented Transformer)** architecture. This structural evolution synthesizes the sequential stability of the baseline BiGRU (Idea 1), the global context capabilities of the Transformer (Idea 3), and the local feature extraction of CNNs, while correcting the data filtering error that handicapped the previous Transformer attempt.

### Model
The architecture is a **1D Conformer Encoder**, designed to explicitly model both the local physicochemical interactions (dominant in RNA stability) and global folding patterns (tertiary structure) within a unified block structure.

1.  **Input Representation:**
    *   The input is a sequence-preserved tensor of shape $(N, 107, C)$. **Cite solution_lesson_node_00002**.
    *   **Feature Channels:** We strictly use **One-Hot Encoding** for the nucleotide sequence (4), secondary structure (3), and predicted loop type (7), concatenated to form $C=14$ channels. We avoid learned embeddings to minimize parameter overhead on this small dataset. **Cite solution_lesson_node_00009**.
    *   **Structure Integration:** By including the secondary structure (dot-bracket) as a feature channel, we provide the model with explicit topology information without the complexity and noise of graph message passing. **Cite solution_lesson_node_00010**.

2.  **Conformer Backbone:**
    *   The core network consists of a stack of **Conformer Blocks** (e.g., 4-6 layers). Unlike a standard Transformer (which only uses Self-Attention) or a pure CNN, the Conformer block interleaves these mechanisms:
        *   **Feed-Forward Module:** Projects features to a higher dimension.
        *   **Multi-Head Self-Attention Module:** Captures global, long-range dependencies (e.g., base pairing across the sequence) dynamically.
        *   **Convolution Module:** A dedicated 1D Depthwise Convolution layer (with Swish activation) sandwiched inside the block. This explicitly enforces **locality**, allowing the model to learn local motifs (k-mers) and neighbor interactions effectively, mimicking the inductive bias of the BiGRU/CNN but within a parallelizable structure.
        *   **Feed-Forward Module:** Final projection.
    *   This hybrid approach addresses the weakness of pure Transformers (lack of local inductive bias) and pure RNNs (difficulty with long-range global context).

3.  **Output Head:**
    *   A final Linear projection maps the hidden dimension to the 5 target values for each of the 107 positions.

### Data
1.  **Full-Spectrum Training:**
    *   We will train on the **entire training dataset**, including samples with low signal-to-noise ratios (`SN_filter == 0`). While filtering for high-quality data improves theoretical signal learning (Lesson 13), it creates a distribution shift that degrades performance on the noisy public test set. Training on the full distribution is statistically safer for this specific competition metric. **Cite solution_lesson_node_00015**.
2.  **Robust Pipeline:**
    *   We will implement **hash-based caching** for the preprocessed data (e.g., `train_data_{hash(config)}.npy`) to ensure that any changes in feature engineering are correctly propagated, preventing the silent failures observed previously. **Cite solution_lesson_node_00011**.

### Training
1.  **Objective:** We optimize the **MCRMSE** (Mean Columnwise Root Mean Squared Error) directly.
2.  **Optimizer:** **AdamW** with a cosine annealing learning rate scheduler. This is crucial for stabilizing the training of Transformer-based components.
3.  **Regularization:**
    *   **Dropout:** Applied within the Conformer blocks (attention dropout and feed-forward dropout) to prevent overfitting, given the high capacity of the model relative to the dataset size (2160 samples).
    *   **Weight Decay:** Standard weight decay to regularize the dense layers.

### Evaluation
1.  **Inference:** The model processes the `test.json` sequences (converted to one-hot tensors) to produce a $(N, 107, 5)$ prediction tensor.
2.  **Submission:** We extract the first 68 positions (as defined by `seq_scored`) from the output and flatten them into the `id_seqpos` format required for the submission file.
