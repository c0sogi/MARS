The `RuntimeError` encountered during training is caused by using `.view()` on a non-contiguous tensor. The model output is sliced (`preds[:, :68, :]`), which creates a view with gaps in memory, making it incompatible with `.view()`. To fix this, I will replace `.view()` with `.reshape()` in `library/utils.py`, as `.reshape()` automatically handles non-contiguous tensors by copying data if necessary.

Additionally, I will update all `torch.load` calls across `library/utils.py`, `library/data.py`, `library/train.py`, and `runfile.py` to include `weights_only=False`. This ensures compatibility with newer PyTorch versions when loading complex objects or trusted local files, preventing potential unpickling errors (Cite debug_lesson_1).
