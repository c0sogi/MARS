The issue is caused by an incorrect argument signature passed to `albumentations.Resize`. While `RandomResizedCrop` in the installed version of Albumentations (v2.0.8) accepts a `size` tuple, `Resize` strictly requires explicit `height` and `width` arguments. The current implementation incorrectly generalizes the `size` parameter usage to `Resize`, causing a validation error (Cite debug_lesson_4).

To fix this, I will update the `Resize` instantiation in both the `PetDataset` class (fallback transform) and the `get_transforms` function in `library/data.py` to use `height` and `width` instead of `size`.
