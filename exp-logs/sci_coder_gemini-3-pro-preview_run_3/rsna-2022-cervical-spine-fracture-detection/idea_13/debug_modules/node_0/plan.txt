### Implementation Strategy

1.  **Configuration Override**: We will dynamically modify the `Config` class attributes to adapt the pipeline for a rapid demonstration. This includes reducing `NUM_SLICES` (to minimize memory/IO), setting `N_SAMPLES` (to train on a tiny subset), and reducing `EPOCHS` to 1.
2.  **Data Loading Verification**: We will instantiate the `RSNADataset` and manually retrieve a batch. We will assert that the output tensor shapes match the expected dimensions `(Batch, Slices, Channels, H, W)` for both global and local streams, and verify the target shape.
3.  **Model Initialization & Forward Pass**: We will initialize the `DualStreamConvNeXt` model, move it to the available device, and perform a dummy forward pass with the retrieved data batch to ensure the architecture (backbone, fusion, context module, heads) functions correctly without shape mismatches.
4.  **Training Loop Execution**: We will execute `engine.fit()` using the reduced dataset. This validates the optimizer setup, loss calculation (`weighted_multitask_loss`), backpropagation, and checkpoint saving logic.
5.  **Inference & Submission**: We will run `engine.inference()` on the test set (also reduced) to generate predictions. We will verify that the output `submission.csv` exists and contains the correct number of rows (8 rows per study).
6.  **Metric Validation**: We will perform a unit test on `utils.competition_metric` using synthetic data to confirm the weighted log loss calculation is accurate.
