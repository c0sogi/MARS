The issue stems from the `process_study` method in `library/dataset.py` loading cached `.npy` files without verifying if their dimensions match the current runtime configuration (specifically `n_slices` and the 3-channel 2.5D structure). This leads to a shape mismatch when the pipeline runs with modified parameters (e.g., debugging with 8 slices) but loads stale cache files generated with different settings (e.g., full volume). To fix this, I will add a shape validation check immediately after loading the cache. If the loaded array's shape does not match the expected `(n_slices, IMAGE_SIZE, IMAGE_SIZE, 3)`, the cache will be ignored, forcing a re-computation. This ensures cache consistency as described in Cite debug_lesson_2.
