The implementation strategy involves the following steps:

1.  **Configuration Patching**: Since the `Config` class is provided in a read-only file, we will modify its class attributes at runtime before instantiating any pipelines. This allows us to redirect output to a specific demo directory (`./working/demo_run`), reduce the number of cross-validation folds to 2, and drastically lower the number of estimators (trees) and iterations for all models to ensure the script completes quickly.
2.  **Training Execution**: We will instantiate the `TrainingPipeline` and run it in debug mode (`debug_size=50`). This triggers the entire workflow: loading data, generating features (Lexical, Community, Semantic, Metadata), training Level-1 base learners (both volatile and stable types), and training the Level-2 Meta-Learner.
3.  **Artifact Validation**: We will assert that the expected output files (OOF predictions and saved model binaries) exist in the specified working directory.
4.  **Inference Execution**: We will instantiate the `InferencePipeline` and run it, reusing the features generated during the training step (via caching) to generate predictions for the test set.
5.  **Submission Validation**: Finally, we will verify that the generated submission DataFrame has the correct shape, columns, and valid probability values, confirming the end-to-end logic is sound.
