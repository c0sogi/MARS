The error arises because the `community_vectorizer` (used for subreddit history) enforces a hardcoded `min_df=2` constraint. When the demo script (`runfile.py`) subsamples the data to just 50 rows, the sparsity of subreddit usage results in no tokens meeting this frequency threshold, causing the `TfidfVectorizer` to crash with an empty vocabulary.

To fix this, I will implement the strategy from **Lesson ID: debug_lesson_12** (Cite debug_lesson_12) by relaxing the statistical constraint for the debug run while preserving the production setting. I will:
1.  Add a `SUBREDDIT_MIN_DF` parameter to `library/config.py` with a default of 2.
2.  Update `library/feature_extraction.py` to use this configuration parameter instead of the hardcoded value.
3.  Override this parameter to 1 in `runfile.py` during the demo execution to ensure valid vocabulary generation on the small subset.
