Based on the comprehensive analysis of previous experiments and lessons learned, I propose a **Tri-View Stacking Ensemble with Latent Community Profiling**.

This solution structurally evolves the previous "Multi-Paradigm Stacking" approach (Idea 3) by replacing the redundant "Semantic Booster" branch with a dedicated "Community Profiling" branch. Instead of applying a second algorithm to the text embeddings—which yielded diminishing returns—this new branch explicitly models the user's Reddit history (subreddits) as a latent dense vector, capturing "User Persona" signals (e.g., "Gamer", "Parent", "Trader") that are orthogonal to the request text.

# Model

The architecture is a **Stacking Ensemble** consisting of three "Level 1" base learners, each processing a distinct modality of the data (Lexical, Semantic, Behavioral), feeding into a "Level 2" meta-learner.

**Level 1: Base Learners**
1.  **Lexical Bagger (Sparse Text View):** A **Random Forest Classifier** trained on **TF-IDF** vectors of the request text concatenated with **User Metadata**.
    *   *Rationale:* Retained from the best performing branch of previous ideas. Random Forests on sparse TF-IDF features consistently outperform dense embeddings for capturing specific high-impact keywords (e.g., "paycheck", "rent") in this dataset (Cite 00013, Cite 00005).
2.  **Semantic Bagger (Dense Text View):** A **Random Forest Classifier** trained on **Frozen SBERT Embeddings** of the request text concatenated with **User Metadata**.
    *   *Rationale:* Retained to capture high-level intent and sentiment. We use frozen embeddings rather than fine-tuning to avoid the severe overfitting observed with end-to-end transformers on this small dataset (Cite 00015). We use Random Forest here as it proved more stable than Boosting for these embeddings (Cite 00013).
3.  **Community Booster (Dense Behavior View):** An **XGBoost Classifier** trained on **Latent Subreddit Components (SVD)** concatenated with **User Metadata**.
    *   *Innovation:* This replaces the previous "Semantic Booster". We process the `requester_subreddits_at_request` list as a bag-of-communities, apply TF-IDF, and then reduce dimensionality via **Truncated SVD (LSA)** to create a dense "User Persona" vector.
    *   *Rationale:* This segregates the user history signal from the request text signal (Cite 00009). Since SVD produces dense, continuous features, we use XGBoost, which excels in dense structured regimes (Cite 00005), unlike its performance on sparse text.

**Level 2: Meta-Learner**
*   **Stacking Classifier:** A **Logistic Regression** model that takes the probability outputs of the three base learners as input features.
    *   *Rationale:* Stacking with a linear meta-learner effectively calibrates the ensemble, automatically assigning higher weights to the dominant Lexical view while extracting residual value from the Semantic and Community views (Cite 00012).

# Data

The data pipeline enforces strict leakage prevention and generates three distinct feature sets:

1.  **Leakage Prevention:**
    *   Select `request_text_edit_aware` as the source text to remove post-hoc edits indicating success (Cite 00003).
    *   Drop all columns suffixed with `_at_retrieval` to ensure temporal validity.
2.  **Feature Engineering:**
    *   **Lexical Features:** Generate a **TF-IDF Matrix** (Unigrams/Bigrams, Top 3,000) from the request text.
    *   **Semantic Features:** Extract **Frozen Embeddings** (384-dim) using a pre-trained Sentence-BERT model (e.g., `all-MiniLM-L6-v2`).
    *   **Community Features:** Treat the list of `requester_subreddits_at_request` as a document. Apply TF-IDF and then **Truncated SVD** to reduce it to ~20 latent components (Dense).
    *   **Metadata:** Include `requester_account_age`, `requester_upvotes_minus_downvotes`, and derived temporal features. **Crucially**, ensure all new SVD and derived features are explicitly added to the configuration allow-list to prevent silent dropping (Cite 00007).
3.  **Preprocessing:**
    *   Impute missing numerical values with the median.
    *   No scaling is required for the Tree/Boosting base learners.

# Training

The training procedure utilizes **5-Fold Cross-Validation Stacking** to prevent data leakage during ensemble construction:

1.  **Fold Generation:** Split the training data into 5 stratified folds.
2.  **Level 1 Training (OOF Generation):**
    *   **Lexical RF:** Train on 4 folds, predict on the 5th. Use `class_weight='balanced'`.
    *   **Semantic RF:** Train on 4 folds, predict on the 5th. Use `class_weight='balanced'`.
    *   **Community XGB:** Train on 4 folds, predict on the 5th. Use `scale_pos_weight` to handle class imbalance.
3.  **Level 2 Training:** Train the Logistic Regression meta-learner on the matrix of Out-Of-Fold (OOF) predictions from all three branches.
4.  **Final Retraining:** Retrain all Level 1 models on the full training dataset. Retrain the Level 2 model on the full OOF matrix.

# Evaluation

For the test set:
1.  Process the test data to generate TF-IDF text vectors, SBERT embeddings, and Subreddit SVD vectors using the transformers fitted on the training set.
2.  Pass the specific feature subsets to their respective Level 1 models (Lexical, Semantic, Community) to obtain three probability scores per sample.
3.  Feed these three probabilities into the trained Level 2 Meta-Learner.
4.  The output of the Meta-Learner is the final predicted probability for `requester_received_pizza`.
