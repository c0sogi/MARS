Based on the extensive empirical analysis and the specific trade-offs identified in the "Lessons" (particularly the performance drop observed when replacing Boosting with Bagging for dense features in Lesson 00018), I propose a **Topology-Aware Stacking Ensemble**.

This solution structurally evolves the previous "Tri-View Stacking" approach (Idea 8) by moving from a homogeneous "All-Bagging" layer to a **Heterogeneous Layer 1**, where the learning algorithm is explicitly matched to the data topology (Sparse vs. Dense) of each view.

# Model

The architecture is a **Stacking Ensemble** composed of three "Level 1" base learners feeding into a "Level 2" meta-learner. The core innovation is the assignment of algorithmic inductive biases: **Random Forests (Bagging)** are assigned to high-dimensional sparse views to handle noise (Cite solution_lesson_node_00005), while **XGBoost (Boosting)** is assigned to the low-dimensional dense view to exploit structure (addressing the regression noted in Cite solution_lesson_node_00018).

**Level 1: Base Learners (Topology-Matched)**
1.  **Lexical Bagger (Sparse Text View):** A **Random Forest Classifier** trained on **TF-IDF** vectors of the request text concatenated with **User Metadata**.
    *   *Rationale:* Retained as the foundational baseline. Random Forests consistently outperform Boosting on the high-dimensional, noisy sparse data of this dataset (Cite solution_lesson_node_00005, Cite solution_lesson_node_00013).
2.  **Behavioral Bagger (Sparse History View):** A **Random Forest Classifier** trained on **TF-IDF vectors of the Subreddit History** concatenated with **User Metadata**.
    *   *Rationale:* We treat the list of subreddits as a "Bag-of-Concepts" document (Cite solution_lesson_node_00018). Since this results in a high-dimensional sparse matrix similar to the text view, Bagging is the optimal choice to capture specific community signals without overfitting.
3.  **Semantic Booster (Dense Context View):** An **XGBoost Classifier** trained on **Frozen SBERT Embeddings** concatenated with **User Metadata**.
    *   *Innovation:* We revert the decision in Idea 8 (which used RF here) and restore XGBoost for this specific branch. Lesson 00018 indicated that while RF is better for sparse data, it was "less effective at exploiting the dense embeddings" than Gradient Boosting. By restricting XGBoost solely to this dense view, we leverage its superior capacity for structured data without exposing it to the sparse noise that caused it to fail in earlier iterations (Cite solution_lesson_node_00009).

**Level 2: Meta-Learner**
*   **Stacking Classifier:** A **Logistic Regression** model that combines the probability outputs of the three base learners.
    *   *Rationale:* Stacking with a linear meta-learner effectively calibrates the ensemble, dynamically balancing the strong Lexical signal with the subtle Semantic/Behavioral signals (Cite solution_lesson_node_00012).

# Data

The data pipeline enforces strict leakage prevention and generates three distinct, topology-specific feature sets.

1.  **Leakage Prevention:**
    *   Use `request_text_edit_aware` to remove post-hoc edits (Cite solution_lesson_node_00003).
    *   Drop all columns suffixed with `_at_retrieval`.
2.  **Feature Engineering:**
    *   **Lexical View (Sparse):** Generate a **TF-IDF Matrix** (Unigrams/Bigrams, Top 3,000) from the request text.
    *   **Behavioral View (Sparse):** Flatten the `requester_subreddits_at_request` list into a string using robust duck typing (Cite solution_lesson_node_00017) and generate a **TF-IDF Matrix** (Unigrams, Top 1,000).
    *   **Semantic View (Dense):** Extract **Frozen Embeddings** (384-dim) using a pre-trained SBERT model. We strictly avoid fine-tuning to prevent overfitting (Cite solution_lesson_node_00015).
    *   **Metadata (Dense):** Include user statistics and explicitly **allow-list** derived features (text length, sentiment, temporal) to prevent silent dropping (Cite solution_lesson_node_00007).
3.  **Preprocessing:**
    *   **Imputation:** Median imputation for numerical columns.
    *   **Scaling:** Apply `StandardScaler` *only* to the features entering the **Semantic Booster** (XGBoost) and the **Level 2 Meta-Learner**. The Random Forest models (Lexical/Behavioral) do not require scaling.

# Training

The training procedure utilizes **5-Fold Cross-Validation Stacking**:

1.  **Fold Generation:** Split the training data into 5 stratified folds.
2.  **Level 1 Training (OOF Generation):**
    *   **Lexical RF & Behavioral RF:** Train on 4 folds, predict on the 5th. Use `class_weight='balanced'`.
    *   **Semantic XGB:** Train on 4 folds, predict on the 5th. Use `scale_pos_weight` to handle class imbalance and early stopping based on validation loss.
3.  **Level 2 Training:** Train the Logistic Regression meta-learner on the matrix of Out-Of-Fold (OOF) predictions from all three branches.
4.  **Final Retraining:** Retrain all Level 1 models on the full training dataset. Retrain the Level 2 model on the full OOF matrix.

# Evaluation

For the test set:
1.  Process the test data to generate the three feature views (Lexical TF-IDF, Behavioral TF-IDF, Semantic Embeddings) using the transformers fitted on the training set.
2.  Pass each view to its specific Level 1 model (RF for sparse views, XGB for the dense view) to obtain probability scores.
3.  Feed the three probability scores into the Level 2 Meta-Learner.
4.  The output is the final predicted probability for `requester_received_pizza`.
