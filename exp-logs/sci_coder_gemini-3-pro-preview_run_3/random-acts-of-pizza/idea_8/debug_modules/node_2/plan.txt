The error occurs because the feature `post_was_edited` is present in the training data and automatically selected as a numerical feature during the `fit` phase, but it is missing from the test data, causing a schema mismatch during `transform`. To fix this, I will explicitly add `post_was_edited` to the `exclude_cols` set in the `_augment_metadata` method of `FeaturePipeline`. This ensures the model relies only on the intersection of features available in both training and inference environments, effectively preventing the reported train-serving skew. Cite debug_lesson_1.
