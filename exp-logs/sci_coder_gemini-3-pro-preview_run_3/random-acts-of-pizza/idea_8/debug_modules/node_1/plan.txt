The issue stems from passing dense NumPy arrays directly to `scipy.sparse.hstack`. When `hstack` receives a list of dense arrays with matching row counts but differing column counts, NumPy attempts to broadcast them into a single array structure during internal processing, which fails with a shape mismatch error. To resolve this, I will modify the `_prepare_view_data` method in `library/ensemble_trainer.py` to explicitly convert any dense feature matrices (such as SBERT embeddings or tabular metadata) into sparse CSR matrices before attempting to stack them. This ensures `hstack` receives compatible sparse inputs, bypassing the problematic dense broadcasting logic.
