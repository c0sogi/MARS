The issue is that the pipeline uses a "Union Strategy" where the validation set is merged into the training data, but the validation step subsequently evaluates the models on this same validation set. Since the models have seen these samples during training, this causes data leakage and invalid metrics. To fix this, we must use Out-of-Fold (OOF) predictions—generated during cross-validation on samples held out from each fold—to evaluate the validation subset.

I will apply the following changes:
1.  **`library/trainer.py`**: Update `train_meta_learner` to collect and return the OOF predictions for the meta-learner (Cite `debug_lesson_9`).
2.  **`library/pipeline.py`**: Update `run_training_pipeline` to save these OOF predictions to disk (Cite `debug_lesson_11`).
3.  **`runfile.py`**: Refactor Step 2 to load the OOF predictions and slice the portion corresponding to the validation set for evaluation, replacing the leaky inference logic.
