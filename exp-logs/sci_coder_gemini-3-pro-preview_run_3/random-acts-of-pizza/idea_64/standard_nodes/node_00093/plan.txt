The issue is that the pipeline implements a "Union Dataset" strategy where the validation set is merged with the training set to retrain the final "stable" models. However, the `runfile.py` script subsequently attempts to evaluate these retrained models on the original validation set. Since the validation samples were explicitly included in the training data for these models, this constitutes testing on training data (data leakage), resulting in the inflated AUC of ~0.9995.

To fix this, we must rely on the **Out-of-Fold (OOF)** predictions generated during the cross-validation phase as the definitive estimate of generalization performance (Cite debug_lesson_9). The fix involves:
1.  Modifying `library/training_engine.py` to save the OOF predictions to disk so they can be used for analysis.
2.  Modifying `runfile.py` to remove the leaky "Validation Assessment" block and instead use the OOF AUC and saved OOF predictions for decision-making and failure analysis.
