Implementation Strategy:

1.  **Configuration & Setup**: Import necessary libraries and the provided modules (`Config`, `TrainingEngine`, etc.). Set random seeds for reproducibility.
2.  **Runtime Optimization**: Patch the `Config` class to reduce the number of estimators for the base learners (Random Forest, XGBoost, LightGBM) to ensure the training completes quickly (Fast Baseline) while enabling GPU acceleration for the boosting models.
3.  **Data Isolation (Monkey-Patching)**: The provided `TrainingEngine` merges training and validation data for Cross-Validation. To strictly satisfy the requirement of evaluating on a "hold-out" validation set, I will monkey-patch `TrainingEngine._prepare_data` to only load and use the training split for the CV process. This leaves the validation split completely unseen by the models during the `TrainingEngine.run()` phase.
4.  **Training**: Instantiate and run the `TrainingEngine`. This will train the 5-fold base learners and the meta-learner using only the training data.
5.  **Hold-Out Validation**:
    *   Manually load the validation features using `FeaturePipeline`.
    *   Reconstruct the specific input matrices required by each learner for the validation set.
    *   Perform inference using the saved fold-models (Bagging) and the meta-learner.
    *   Compute and print the `Final Validation Metric` (AUC).
6.  **Failure Analysis**: Calculate the absolute error on the validation set and compute Pearson correlations with the dense metadata features. Print the top features associated with model error.
7.  **Conditional Submission**: Check if the validation AUC exceeds the specified threshold (0.7138...). If successful, execute `InferenceEngine.run_inference()` to generate the final submission file for the test set. If not, ensure no invalid submission is left behind.
