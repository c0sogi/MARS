The issue stems from `runfile.py` forcing all models to be treated as "volatile" to enable cross-validation bagging for the validation set. However, the `fit` method in `HybridStackingEnsemble` unconditionally passes the `eval_set` argument to all volatile models, assuming they are Gradient Boosting machines that support early stopping. This causes a `TypeError` for Scikit-Learn models (like Random Forest) which do not accept `eval_set` in their `fit` method.

To fix this, I will modify `library/hybrid_ensemble.py` to explicitly check the estimator type. Only models identified as XGBoost or LightGBM will receive the `eval_set` parameter; others will use the standard `fit` call. This ensures the code respects the API constraints of different model classes, applying **Cite debug_lesson_10**.
