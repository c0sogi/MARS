Specifically, `str(row["labels"])` converts `NaN` to the string `"nan"`, which evaluates to `True` in the check `if lbl_str:`, leading to a crash when `int("nan")` is called.

To fix this, I will modify `library/data.py` to explicitly check for missing values using `pd.notna()` before processing the labels string. This ensures that `NaN` values (representing recordings with no labels) fall through to the `else` block, where a zero-vector is correctly assigned, rather than attempting to parse them.
