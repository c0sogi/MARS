The issue arises because the `ModelEMA.update` method attempts to perform an in-place floating-point multiplication on all model state tensors, including integer-based buffers like `num_batches_tracked` found in Batch Normalization layers. Multiplying a `LongTensor` by a float results in a `FloatTensor`, which cannot be cast back into the original `LongTensor` storage during an in-place operation, causing the `RuntimeError`. To fix this, I will modify the update loop to check the data type of each tensor: floating-point tensors will be updated using the EMA formula, while non-floating-point tensors (integers) will be directly copied from the source model to the EMA model.
