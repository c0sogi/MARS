The data leakage issue arises because the cross-validation loop in `library/data_loader.py` currently uses the entire labeled dataset (loaded from `train.json`), which includes both the intended training samples and the hold-out validation samples. This means models are trained on data that is later used for the final "unseen" evaluation, invalidating the metric.

To fix this, I will modify `library/data_loader.py` to explicitly filter the dataset used for cross-validation. I will update `process_data` to extract and cache the training IDs (`ids_train`) from the raw data. Then, in `get_loaders`, I will load the strict training set definition from `metadata/train.csv` and use these IDs to filter the full dataset, ensuring the hold-out validation set (`metadata/val.csv`) is excluded from the CV splits. This aligns with **debug_lesson_7** (Prevent Data Leakage) and **debug_lesson_4** (Invalidate Stale Data Caches), as adding the new `ids_train` file to the cache manifest will force a cache refresh. I will also update `library/inference.py` to handle the expanded return signature of `process_data`.
