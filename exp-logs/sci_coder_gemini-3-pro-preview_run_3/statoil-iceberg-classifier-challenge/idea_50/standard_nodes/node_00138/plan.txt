The issue is caused by **Data Leakage** where the hold-out validation set (`val.csv`) is merged with the training set (`train.csv`) before performing K-Fold Cross-Validation. This results in the models being trained on data that is later used for final evaluation, leading to overly optimistic performance metrics. To fix this, I will modify `library/trainer.py` to exclude the validation set from the Cross-Validation process. The `run_fold` function will be updated to load only the training split (`train.csv`) for generating the folds, ensuring that `val.csv` remains a strictly unseen hold-out set. Cite debug_lesson_7.
