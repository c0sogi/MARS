The `IndexError` is caused by a stale and inconsistent data cache in `./working/cache`, where `X_train.npy` (containing image data) corresponds to the full dataset size, while `ids_train.npy` (containing IDs) corresponds to a smaller subset. This mismatch causes the cross-validation splitter (which uses the larger `X` array) to generate indices that are out of bounds for the smaller `ids` array.

To fix this, I will modify `runfile.py` to explicitly delete the `Config.CACHE_DIR` if it exists, forcing the data loader to regenerate consistent cache files from the raw `train.json`. This applies **Cite {debug_lesson_4}** ("Invalidate Stale Data Caches When Dataset Scope Changes").
