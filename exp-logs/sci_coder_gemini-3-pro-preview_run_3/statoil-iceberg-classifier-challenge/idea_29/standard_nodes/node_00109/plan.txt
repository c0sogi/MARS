The issue is a case of **Data Leakage** where the cross-validation process uses the entire raw dataset, including samples that are reserved for the final hold-out validation. This results in the model training on data it is later evaluated on, producing an invalid, overly optimistic metric. To fix this, I will modify `library/data_loader.py` to filter the dataset loaded in `get_loaders`. By using the `original_index` from `metadata/train.csv`, I will restrict the data passed to the K-Fold splitter to only the designated training subset, ensuring the hold-out set remains completely unseen during training.
