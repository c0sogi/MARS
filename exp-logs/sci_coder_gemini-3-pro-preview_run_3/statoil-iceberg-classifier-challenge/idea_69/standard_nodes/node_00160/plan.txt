Implementation strategy:
1.  **Setup & Configuration**: Initialize the environment, set random seeds for reproducibility, and ensure directory structures exist. Override the default `NUM_EPOCHS` and `PATIENCE` in `library.config` to 25 and 5 respectively to satisfy the "fast baseline" requirement while maintaining sufficient convergence.
2.  **Training Loop**: Iterate through the 5 folds defined in the configuration. For each fold, execute the training process using `library.train_eval.train_fold`. This handles model training, validation monitoring, and checkpoint saving.
3.  **Validation & Data Collection**: After training each fold, reload the best saved checkpoint. Run inference on the corresponding validation set to collect predictions, ground truth labels, and metadata (incidence angles, image statistics) required for failure analysis.
4.  **Metric Calculation**: Aggregate the validation predictions from all folds to calculate the global Log Loss. Print this strictly in the required format: `Final Validation Metric: <value>`.
5.  **Failure Analysis**: Compute the absolute error for each validation sample. Calculate and print the Pearson correlation between the error magnitude and key features (Incidence Angle, Band 1 Mean, Band 2 Mean) to identify systematic weaknesses.
6.  **Submission Logic**: Compare the calculated final validation metric against the threshold (0.17174082291273365). If the metric is lower (better), invoke `library.train_eval.generate_submission` to create the `submission.csv` file.
