### Implementation Strategy

1.  **Configuration & Monkey Patching**: Since the library modules import configuration constants (like `NUM_EPOCHS`, `BATCH_SIZE`) at the top level, we will import the relevant modules (`library.config`, `library.train_eval`, `library.data_loader`) and update these constants directly within those modules. This ensures the demonstration runs quickly (e.g., 1 epoch, small batch size, debug mode) without modifying the source files.
2.  **Data Loading Demonstration**: We will initialize the directory structure and use `get_data_loaders` to retrieve training and validation batches. We will verify the integrity of the data (shapes, types, and absence of NaNs).
3.  **Model Architecture Verification**: We will instantiate the `MCICNN` model, inspect its parameter count, and perform a forward pass with dummy data to confirm the output shape is correct `(Batch_Size, 1)`.
4.  **Training Loop Execution**: We will run `train_fold(0)` for a single epoch. This validates the training pipeline, loss calculation, backpropagation, and checkpoint saving mechanisms.
5.  **Inference & Submission**: We will run `generate_submission` to demonstrate the full inference pipeline, including test data loading, prediction aggregation across folds (simulated with fewer folds), and CSV generation.
6.  **Validation**: Throughout the script, `assert` statements will be used to enforce correctness.
