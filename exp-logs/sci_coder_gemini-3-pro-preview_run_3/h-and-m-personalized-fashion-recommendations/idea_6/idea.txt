Based on the accumulated lessons, I propose a **Multi-Temporal Cascade System** with **Dynamic Ensemble Ranking**. This solution structurally evolves the "Vectorized Sparse Propagation" baseline by decomposing the retrieval stage into distinct temporal views (Short-Term Trends vs. Long-Term Style) and Visual Similarity. It then employs a Ranker trained via a **Sliding Window** strategy to dynamically weight these signals, addressing the "Signal Destruction" and "Overfitting" failures of previous ranking attempts.

# Model

The architecture consists of two stages designed to maximize Recall via multi-view propagation and maximize Precision via a robust, generalized ranker.

### Stage 1: Multi-Temporal Vectorized Retrieval (High Recall)
Instead of a single transition matrix, we construct three distinct sparse graphs to capture different aspects of user behavior.
1.  **Short-Term Trend Graph ($T_{short}$):** A **Sequential Transition Matrix** built using **Strict Recency** (e.g., only the last 4 weeks of data) (Cite Lesson 17). This captures fast-moving fashion trends ($A \to B$). We **retain raw edge weights** (Cite Lesson 6) to prioritize high-confidence transitions.
2.  **Long-Term Style Graph ($T_{long}$):** A Transition Matrix built on a longer historical window (e.g., weeks 5-20), representing stable style affinities that persist beyond immediate trends.
3.  **Visual Content Graph ($T_{vis}$):** A sparse K-Nearest Neighbors graph where edges represent Cosine Similarity between item image embeddings. This provides a fallback for cold-start items by linking visually similar products.

**User Representation:** We construct the user vector $U$ using **Importance-Based Aggregation** (Cite Lesson 12), summing time-decayed weights for all historical items and selecting the top components, rather than arbitrarily truncating to the last $N$ events.

**Candidate Generation:** We compute three separate score vectors:
*   $S_{short} = U \cdot T_{short}$
*   $S_{long} = U \cdot T_{long}$
*   $S_{vis} = U \cdot T_{vis}$
*   $S_{repurchase} = U_{history}$ (weighted low to avoid bias, Cite Lesson 11).

We merge these scores to extract the **Top-100 unique candidates** (Cite Lesson 15) for the next stage.

### Stage 2: Context-Aware Dynamic Ensemble (High Precision)
A **LightGBM** model acts as a "Meta-Learner" or Dynamic Ensemble.
*   **Signal Preservation:** To prevent **Signal Destruction** (Cite Lesson 10), the *primary* features fed to the ranker are the raw scores ($S_{short}, S_{long}, S_{vis}$) and their respective ranks. This forces the model to use the strong heuristic signals as a baseline.
*   **Context Features:** We add features that allow the model to decide *which* graph to trust (e.g., "User Activity Level", "Item Age", "Days since last purchase"). For example, the model can learn to trust $T_{vis}$ more for cold-start items and $T_{short}$ for active users.

# Data

### 1. Preprocessing & Graph Construction
*   **Image Embeddings:** Use a pre-trained CNN (e.g., ResNet18) to generate embeddings for all `article_id` images. Construct $T_{vis}$ by keeping the Top-20 nearest neighbors for each item.
*   **Transaction Splits:** Filter `transactions_train.csv` to create the source data for $T_{short}$ (Last 4 weeks) and $T_{long}$ (Weeks 5-20). Apply power-law time decay to edge weights (Cite Lesson 2).

### 2. Ranker Dataset (Sliding Window Strategy)
To address the **Fragility of Learned Rankers** (Cite Lesson 10), we will not train on a single validation split. Instead, we generate a **Sliding Window Dataset**:
*   **Windows:** Create 3-4 training instances (e.g., Train on Weeks 1-10 $\to$ Target Week 11; Train on Weeks 2-11 $\to$ Target Week 12).
*   **Candidate Generation:** For each window, run the Stage 1 retrieval *strictly* using the past data available in that window.
*   **Labeling:** Positive (1) if purchased in the Target Week, Negative (0) otherwise.
*   This ensures the Ranker learns generalized rules (e.g., "Downrank high $S_{short}$ items if they haven't sold in 3 days") rather than memorizing specific item identities from a single week.

# Training

### 1. Retrieval (Deterministic)
*   Construct sparse matrices $T_{short}$, $T_{long}$, and $T_{vis}$ using `scipy.sparse`. No gradient descent is required.

### 2. Ranking (Supervised)
*   **Objective:** Train LightGBM using `lambdarank` (optimizing NDCG).
*   **Regularization:** Use a final hold-out week (not included in the sliding window) for Early Stopping to prevent overfitting.

# Evaluation

### 1. Sparse Inference
*   Construct the sparse user vectors $U$ for all test customers.
*   Perform the sparse matrix multiplications to get $S_{short}, S_{long}, S_{vis}$.
*   **Optimization:** Use **Direct CSR Array Access** (Cite Lesson 16) to efficiently extract the union of Top-K indices from these vectors, strictly avoiding dense matrix materialization (Cite Lesson 7).

### 2. Scoring & Submission
*   Generate features for the retrieved candidates (Raw Scores + Metadata).
*   Predict scores using the trained LightGBM model.
*   Select the Top-12 items.
*   **Fallback:** If a user has no history or fewer than 12 candidates, fill with **Global Popularity** (computed on the last week of training).
