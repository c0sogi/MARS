The issue is a **cache collision** caused by coupling the cache filename to the processing `mode`. Both the validation step and the final submission step use `mode="test"` (to skip label generation), causing the validation process to incorrectly load `features_test.parquet` (which contains features for the leaderboard test users) instead of generating features for the validation users. This leads to a mismatch between prediction users and ground truth users, resulting in an empty score list and a `NaN` metric.

To fix this, I will decouple the cache identity from the processing mode as per **Debug Lesson 3**. I will modify `library/features.py` to accept an explicit `split_name` argument in `generate_features`, allowing the caller to specify unique cache filenames (e.g., `features_val.parquet`, `features_test.parquet`) regardless of the `mode`. I will then update `runfile.py` to pass the appropriate `split_name` ("train", "val", "test") during the training, validation, and submission steps.
