Based on the accumulated lessons, I propose a **Dual-Graph Vectorized Cascade** system. This solution structurally evolves the "Vectorized Sparse Propagation" baseline (Idea 1/Lesson 5) by integrating a multi-modal retrieval stage with a robust, signal-preserving ranking stage. This specifically addresses the "Signal Destruction" observed in previous ranking attempts (Lesson 10) while maintaining the computational efficiency of sparse matrix operations (Lesson 16).

# Model

The architecture consists of two tightly coupled stages designed to maximize Recall through multi-view propagation and Precision through calibrated re-ranking.

### Stage 1: Dual-Graph Vectorized Retrieval (High Recall)
This stage generates a pool of high-quality candidates by propagating user history through two distinct sparse graphs. It preserves the **Vectorized Sparse Propagation** backbone (Cite Lesson 5) but extends it to handle visual signals alongside behavioral ones.

1.  **Sequential Graph ($T_{seq}$):** A **Time-Aware Transition Matrix** capturing sequential patterns ($A \to B$). We enforce **Strict Recency** (e.g., using only the last 10-12 weeks of data) (Cite Lesson 17) and explicitly **retain raw edge weights** (Cite Lesson 6) rather than normalizing them. This ensures that transitions backed by high transaction volumes (high confidence) naturally dominate the retrieval scores.
2.  **Visual Graph ($T_{vis}$):** To address the sparsity of behavioral data and the "Cold Start" problem, we introduce a sparse K-Nearest Neighbors graph where edges represent the cosine similarity between item image embeddings. This links items that look similar even if they haven't been bought together.
3.  **User Representation ($U$):** We employ **Importance-Based Aggregation** (Cite Lesson 12). Instead of arbitrarily truncating history to the last $N$ chronological events, we aggregate all user transactions within the window, sum their time-decayed weights, and select the top components.
4.  **Score Aggregation:** The retrieval score is computed as a linear combination of sparse matrix multiplications:
    $$S = U \cdot T_{seq} + \lambda_{vis} (U \cdot T_{vis}) + \alpha U_{history}$$
    The repurchase weight $\alpha$ will be kept low (e.g., ~1.5) to prevent historical bias from overpowering new trends (Cite Lesson 11).
5.  **Output:** We extract the **Top-100 candidates** per user (Cite Lesson 15) to ensure the subsequent ranker has a sufficient pool of relevant items to sort, adhering to the Funnel Principle.

### Stage 2: Signal-Preserving Re-Ranking (High Precision)
A **LightGBM** model trained with a ranking objective (`lambdarank`) sorts the 100 candidates.
*   **Signal Preservation:** To prevent **Signal Destruction** (Cite Lesson 10), where a learned ranker overfits and discards valid heuristic signals, we explicitly feed the **Raw Component Scores** ($S_{seq}$, $S_{vis}$) and their **Ranks** from Stage 1 as primary features. This forces the ranker to use the strong sequential signal as a baseline and only re-order based on secondary features.
*   **Visual Consistency:** We compute the cosine distance between the candidate item's embedding and the **centroid of the user's recent purchase history**. This gives the ranker a "Style Consistency" feature.
*   **Context Features:** We augment the candidate vectors with User Demographics (Age), Global Item Popularity, and Temporal Recency.

# Data

1.  **Visual Graph Construction:**
    *   Load all article images and pass them through a pre-trained CNN (e.g., `resnet18` via `timm`) to generate dense embeddings.
    *   Compute the Top-20 nearest neighbors for each item based on Cosine Similarity.
    *   Store this as a sparse adjacency matrix $T_{vis}$.

2.  **Ranker Dataset (Sliding Window):**
    *   **Strategy:** To address the **Fragility of Learned Rankers** (Cite Lesson 10), we will use a **Sliding Window** strategy. We will generate training data from multiple past weeks (e.g., Train on W1-W9 $\to$ Target W10; Train on W2-W10 $\to$ Target W11).
    *   **Labeling:** For each window, Positive samples (1) are items actually purchased in the target week. Negative samples (0) are items retrieved by Stage 1 that were *not* purchased.

# Training

1.  **Retrieval (Deterministic):**
    *   Construct $T_{seq}$ using the time-decay formula on the filtered transaction log.
    *   Construct $T_{vis}$ using the pre-computed image embeddings.
    *   No gradient descent is required for this stage.

2.  **Ranking (Supervised):**
    *   Train the LightGBM model using the `lambdarank` objective (optimizing NDCG).
    *   Use Early Stopping based on a hold-out validation set (the final week of the sliding window) to prevent overfitting.

# Evaluation

1.  **Sparse Inference:**
    *   Construct the sparse user vectors $U$ for all test customers.
    *   Perform the sparse matrix operation: $S = U \cdot T_{seq} + \lambda_{vis} (U \cdot T_{vis}) + \alpha U_{history}$.
    *   **Optimization:** Use **Direct CSR Array Access** (Cite Lesson 16) to efficiently extract the indices of the Top-100 items. This avoids the computational trap of materializing dense score matrices (Cite Lesson 7).
2.  **Scoring & Submission:**
    *   Compute the feature vectors (Heuristic Scores + Visual Consistency + Metadata) for these 100 candidates.
    *   Score them using the trained LightGBM model.
    *   Select the Top-12 items with the highest predicted scores for the final submission.
