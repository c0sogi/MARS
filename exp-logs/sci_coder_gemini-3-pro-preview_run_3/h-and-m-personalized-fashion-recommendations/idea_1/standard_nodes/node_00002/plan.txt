The issue identified is **Temporal Data Leakage** (look-ahead bias) within the validation process. The validation set is split into history and a 7-day target period, but the model is trained on the `train_df` which currently includes transactions from that same 7-day target period. This allows the model to "peek" at future popularity trends (global popularity of the target week) that would be unknown in a real forecasting scenario.

To fix this, I will modify `runfile.py` in the `run_validation` function. After loading the training data, I will strictly filter it to exclude any transactions occurring after the `split_date`. This ensures the model is trained only on information available prior to the validation target period.
