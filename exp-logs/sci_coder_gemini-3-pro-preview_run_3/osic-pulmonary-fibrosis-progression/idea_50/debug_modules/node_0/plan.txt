### Implementation Strategy

1.  **Configuration Override**: To ensure the demonstration runs quickly (under the time limit), the script first creates a subset of the metadata (train, val, test) containing only a few patients. It then overrides the paths in the `Config` class to point to these smaller datasets. This prevents the data loader from processing and caching hundreds of DICOM scans.
2.  **Library Usage Demonstration**:
    *   **Utils**: Validates the `calculate_metric` function against a manual calculation to ensure the scoring logic is correct.
    *   **Data Loading**: Initializes the `OSICDataset` and `DataLoader` using the provided `get_dataloaders` function. It fetches a single batch to verify tensor shapes (images, tabular features, and targets).
    *   **Model Initialization**: Instantiates the `CRDSNet` model. It performs a forward pass with the fetched batch to verify the output shape `(Batch, 2)` and ensures the predicted confidence (sigma) is positive.
    *   **Loss Calculation**: Computes the loss using `MetricAlignedLaplaceLoss` on the model outputs and asserts the loss is a valid scalar.
    *   **Training Step**: Simulates a single training optimization step (forward, loss, backward, optimizer step) to demonstrate the training loop mechanics.
    *   **Inference & Submission**: Simulates the inference process on the test set, including the inverse transformation of scaled predictions back to the original units (ml), and generates a sample submission file.
3.  **Verification**: Assertions are placed throughout the script to validate data types, shapes, and logic (e.g., loss > 0, sigma > 0).
