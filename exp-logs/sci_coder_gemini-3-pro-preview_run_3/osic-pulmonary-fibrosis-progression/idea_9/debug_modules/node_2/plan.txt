The `pickle.UnpicklingError` is caused by the default `weights_only=True` setting in `torch.load` (introduced in PyTorch 2.6+), which blocks the loading of the NumPy scalar (`numpy.float64`) stored in the `best_score` field of the checkpoint.

To fix this, I will:
1.  **Sanitize the metric value**: In `library/train.py`, cast `val_score` to a native Python `float` before assigning it to `self.best_score` in the `fit` method. This ensures the checkpoint stores standard Python types, addressing the root cause of the unsafe global error and applying **Cite debug_lesson_2**.
2.  **Relax loading restrictions**: In `library/train.py`, explicitly set `weights_only=False` in the `torch.load` call within `generate_submission`. This ensures the checkpoint (which may contain optimizer states or other complex objects) can be loaded reliably from the trusted local source.
