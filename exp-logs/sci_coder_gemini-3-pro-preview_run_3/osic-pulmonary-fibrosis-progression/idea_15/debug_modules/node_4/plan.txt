The execution failure stems from a combination of training instability (resulting in `NaN` scores) and the subsequent attempt to load a stale, incompatible checkpoint from a previous run. The `UnpicklingError` occurs because the stale checkpoint contains NumPy scalars, which are blocked by default in PyTorch 2.6+ `weights_only=True` loading (Cite debug_lesson_4).

To fix this, I will:
1.  **Clean the Environment (`runfile.py`)**: Recursively delete the `working/demo` directory before setup to ensure no stale artifacts persist.
2.  **Stabilize Training (`library/train.py`)**: Add gradient clipping (`clip_grad_norm_`) to the training loop to prevent exploding gradients and `NaN` losses.
3.  **Robust Loading (`library/train.py`)**: Modify the submission generation phase to check if the checkpoint file exists before attempting to load it. If training failed to produce a valid checkpoint (due to `NaN` scores), it will gracefully proceed with the current model state.
4.  **Prevent Division by Zero (`library/utils.py`)**: Update `TargetScaler` to handle cases where the standard deviation is zero (common in small subsets), preventing `NaN` inputs to the model.
