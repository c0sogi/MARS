The issue stems from a redundant merge operation in `library/data.py` within the `get_dataloaders` function. The `test_expanded` DataFrame is created by merging `sample_sub` with `test_df`. Since `test_df` already contains the columns `Baseline_Weeks` and `Baseline_FVC` (added by `add_baseline_features` and not dropped), the initial merge includes them in `test_expanded`. The subsequent code attempts to merge these columns again via `test_baselines`, causing Pandas to automatically rename the colliding columns to `Baseline_Weeks_x`/`y`, which results in a `KeyError` when the code later tries to access `Baseline_Weeks`. The fix is to remove the redundant second merge, as the required information is already present.
