# Solution Proposal: Character-Level Transformer with Auxiliary Classification

## Model
I propose replacing the Recurrent Neural Network (LSTM) architecture with a **Character-Level Transformer Encoder-Decoder**.
-   **Transformer Backbone:** The core innovation is the shift to a Transformer architecture. The **Cross-Attention mechanism** in the Transformer explicitly resolves the "Fixed-Context Bottleneck" identified in the previous lesson Cite {solution_lesson_node_00001}. Unlike the LSTM's single hidden state, Cross-Attention allows the decoder to dynamically query the entire encoded input sequence at every generation step. This ensures that information from long sequences (like complex numbers or dates) is preserved and accessible throughout the decoding process.
-   **Auxiliary Classification Head:** I will attach a classification head to the output of the Transformer Encoder. This head will predict the token category (e.g., `DATE`, `CARDINAL`, `PLAIN`) using the `class` column provided in the training data. This serves two purposes:
    1.  **Multi-Task Learning:** It forces the encoder to learn high-level semantic representations of the token type, which aids the decoder in applying the correct normalization rules.
    2.  **Inference Routing:** During inference (where ground truth classes are absent), this predicted class can be used to apply specific logic (e.g., if the predicted class is `PLAIN`, strictly copy the input).

## Data
-   **Tokenization:** We will retain **Character-Level Tokenization**. This is essential for handling the open vocabulary of numbers and transliterated names without encountering Out-Of-Vocabulary (OOV) issues.
-   **Vocabulary:** The vocabulary will consist of all unique characters in the dataset, plus special tokens (`<PAD>`, `<SOS>`, `<EOS>`, `<UNK>`).
-   **Sampling Strategy:** To address the extreme class imbalance (where ~87% of data is `PLAIN` or `PUNCT`), we will employ **Weighted Random Sampling** or downsampling of the `PLAIN` class during training. This ensures the model spends significantly more updates learning the complex transformations (Dates, Numbers) rather than just learning to copy text.

## Training
-   **Loss Function:** A composite loss function will be used: $L_{total} = L_{generation} + \lambda L_{classification}$.
    -   $L_{generation}$: Cross-Entropy loss for the character sequence generation.
    -   $L_{classification}$: Cross-Entropy loss for the auxiliary class prediction.
-   **Optimizer:** We will use **AdamW** with a **Learning Rate Warmup and Decay** schedule, which is standard and critical for stabilizing Transformer training.
-   **Regularization:** Dropout and Label Smoothing will be applied to prevent overfitting, especially given the repetitive nature of the "PLAIN" class.

## Evaluation
-   **Beam Search:** Instead of Greedy Decoding, we will use **Beam Search** (e.g., beam width = 3) during inference. This allows the model to explore multiple potential normalization paths and select the most probable sequence, improving performance on ambiguous inputs.
-   **Hybrid Inference Logic:** We will utilize the predicted class from the Auxiliary Head. If the model predicts `PLAIN` or `PUNCT` with high confidence, we will bypass the decoder's text output and simply return the input string. This guarantees 100% accuracy on the "unchanged" portion of the dataset, provided the classification is correct.
