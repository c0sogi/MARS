Based on the task requirements and the provided model architectures, I propose the following baseline approach. This solution prioritizes simplicity and establishes a fundamental neural performance benchmark using a standard architecture distinct from the advanced methods listed.

# Vanilla Character-Level LSTM Encoder-Decoder

### Model
The proposed architecture is a classic **Sequence-to-Sequence (Seq2Seq)** model without attention mechanisms. It consists of two main components:
*   **Encoder:** A single-layer, **uni-directional** Long Short-Term Memory (LSTM) network. It ingests the input text character-by-character. The final hidden state and cell state of the encoder serve as a fixed-size "context vector" that encapsulates the information of the entire input token. Unlike Model 3, this encoder is not bi-directional, reducing computational overhead.
*   **Decoder:** A corresponding single-layer LSTM initialized with the context vector from the encoder. It generates the normalized text sequence one character at a time.
*   **Projection:** A simple linear layer maps the decoder's hidden state at each time step to a probability distribution over the character vocabulary.
*   **Distinction:** This model differs from Model 3 by removing the Attention mechanism and Bi-directionality, creating a pure "information bottleneck" architecture. It differs from Model 1 by being a monolithic neural network trained on all data, rather than a hybrid router/rule-based system.

### Data
*   **Vocabulary Construction:** Create a character-level vocabulary containing all unique characters found in the `before` and `after` columns of the training set, plus special control tokens: `<SOS>` (Start of Sequence), `<EOS>` (End of Sequence), `<PAD>` (Padding), and `<UNK>` (Unknown).
*   **Input/Output Pairs:** The model processes data at the token level. The input is the raw `before` string (e.g., "Sept."), and the target is the `after` string (e.g., "september").
*   **No Class Dependency:** Unlike Model 1, this baseline does not require the `class` column for inference. It learns to infer the transformation type (or identity mapping) solely from the character patterns in the input string.

### Training
*   **Loss Function:** Use **Cross-Entropy Loss**, computed between the predicted character probabilities and the ground truth characters.
*   **Optimizer:** Use the **Adam** optimizer for efficient convergence.
*   **Teacher Forcing:** Employ Teacher Forcing during training. This means feeding the *ground truth* character from the previous time step as input to the current step (instead of the model's predicted character). This stabilizes gradients and speeds up training.
*   **Batching:** Group input tokens into batches, padding sequences to the maximum length within the batch using the `<PAD>` token.

### Evaluation
*   **Greedy Decoding:** For inference on the test set, use a greedy decoding strategy. At each time step, select the character with the highest probability (argmax). Feed this predicted character as the input for the next time step.
*   **Termination:** Continue decoding until the model generates the `<EOS>` token or reaches a pre-defined maximum sequence length (e.g., derived from the training data statistics).
*   **Reconstruction:** Concatenate the generated characters to form the final normalized string for the submission file.
