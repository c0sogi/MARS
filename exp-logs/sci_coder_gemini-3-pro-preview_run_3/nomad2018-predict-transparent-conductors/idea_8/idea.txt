Based on the comprehensive analysis of previous attempts and the lessons learned, I propose a **Chemically-Resolved Structural Fingerprinting** strategy. This approach replaces the "black box" GNN embeddings (which failed due to lack of pre-training, Cite Lesson 10) and naive statistical aggregates (which failed due to lack of chemical specificity, Cite Lesson 24) with a deterministic, physics-informed feature engineering pipeline that explicitly models the local environments of specific cation-anion pairs.

# Model
The architecture is a single-stage regression model designed to capture the specific physical drivers of formation and bandgap energies in oxide alloys:

1.  **Feature Engineering Engine**: A deterministic pipeline that extracts three classes of features:
    *   **Global Physical Descriptors**: Macroscopic properties of the crystal.
    *   **Elemental Property Moments**: Statistical summaries of the fundamental chemical properties of the constituent atoms.
    *   **Chemically-Resolved Bond Statistics (Structural Innovation)**: Instead of global average bond lengths (which act as noise, Cite Lesson 24), this module computes the mean and variance of interatomic distances **specifically for each cation-anion pair type** (Al-O, Ga-O, In-O). This explicitly encodes the local structural distortion and bond strength variations that govern the electronic band structure.

2.  **Predictor**: An **XGBoost Regressor** (Cite Lesson 3). The tree ensemble is well-suited to handle the non-linear interactions between these distinct physical features without assuming a functional form.

# Data
1.  **Global Physical Descriptors**:
    *   Calculate **Unit Cell Volume** and **Mass Density** directly from the raw `.xyz` geometry files using the `ase` library. This ensures high fidelity to the simulation constraints (Cite Lesson 18).
    *   Include tabular features: Spacegroup (one-hot) and atomic composition fractions.

2.  **Elemental Property Moments**:
    *   Inject external domain knowledge by mapping atomic species (Al, Ga, In, O) to their **Electronegativity (Pauling)**, **Atomic Radius**, and **Valence Electron Count**.
    *   Compute the composition-weighted **Mean** and **Standard Deviation** of these properties for each crystal. This provides the model with "chemical intuition" absent from the raw coordinate data (Cite Lesson 14).

3.  **Chemically-Resolved Bond Statistics**:
    *   Parse the `.xyz` files to generate a neighbor list for each atom (using a cutoff, e.g., 3.0 Å).
    *   Filter neighbors to identify specific bond types: **Al-O**, **Ga-O**, and **In-O**.
    *   Calculate the **Mean Bond Length** and **Bond Length Variance** for each pair type independently. If a bond type is missing (e.g., no In atoms), use a constant placeholder (NaN) to avoid feature dilution (Cite Lesson 16).

4.  **Target Transformation**:
    *   Apply the natural logarithm transformation $z = \log(1 + y)$ to both `formation_energy_ev_natom` and `bandgap_energy_ev`. This aligns the regression objective with the RMSLE metric (Cite Lesson 2).

# Training
1.  **Algorithm**: Train separate XGBoost regressors for each target variable.
2.  **Optimization Strategy**:
    *   **Shrinkage**: Use a low learning rate (e.g., $\eta \approx 0.01$) combined with a high number of estimators (e.g., 2,500) to maximize generalization (Cite Lesson 4).
    *   **Stochastic Subsampling**: Enable row (`subsample`) and column (`colsample_bytree`) subsampling ($\approx 0.6 - 0.7$). This prevents the model from over-relying on any single dominant feature (like density) and forces it to learn from the subtler bond-statistic features (Cite Lesson 4).
3.  **Loss Function**: Minimize Squared Error on the log-transformed targets.

# Evaluation
1.  **Inference**:
    *   Process the test set `.xyz` files to generate the Chemically-Resolved Structural Fingerprint.
    *   Generate predictions in log-space using the trained XGBoost models.
2.  **Post-Processing**:
    *   Apply the inverse transformation $\hat{y} = \exp(z) - 1$ to obtain the final energy predictions in eV.
