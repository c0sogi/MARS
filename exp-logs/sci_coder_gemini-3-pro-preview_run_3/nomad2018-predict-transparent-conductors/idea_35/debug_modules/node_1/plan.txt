The previous implementation failed because `library/data_loader.py` and other modules imported configuration variables using the `from library.config import VARIABLE` syntax. This binds the value of the variable to the importing module's namespace at the time of import. When `runfile.py` subsequently modified `library.config.DEBUG`, the other modules continued to use the old, cached values (e.g., `DEBUG=False`), causing the data loader to load the full dataset instead of the debug sample. Additionally, the XGBoost model initialization used an outdated API pattern where `early_stopping_rounds` was passed to `.fit()` instead of the constructor, which is incompatible with newer XGBoost versions.

To fix this, I will modify `library/data_loader.py`, `library/features.py`, `library/preprocessing.py`, and `library/model.py` to import the configuration module itself (`import library.config as config`) and access variables via dot notation (e.g., `config.DEBUG`). This ensures that all modules see the current, runtime-modified values of the configuration variables. I will also update `library/model.py` to pass `early_stopping_rounds` to the `XGBRegressor` constructor, complying with the modern XGBoost API.
