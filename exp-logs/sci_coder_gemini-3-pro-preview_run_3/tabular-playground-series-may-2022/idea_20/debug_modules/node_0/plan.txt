The following strategy outlines the implementation of the demonstration script:

1.  **Configuration Setup**: We will import the `Config` class from `library.config` and override specific parameters to create a "demo" environment. This includes setting a dedicated working directory (`./working/demo_execution`), reducing `NUM_EPOCHS` to 1 for rapid execution, and updating cache paths to avoid conflicts with existing experiment data.
2.  **Execution**: We will utilize the `run_training` function from `library.train_eval`. This high-level function orchestrates the entire pipeline: data loading, preprocessing (via `library.data_utils`), model initialization (via `library.model`), training, validation, and prediction.
3.  **Verification**: After the training loop completes, we will perform rigorous checks:
    *   Verify that the "best model" checkpoint file was created.
    *   Verify that the submission file exists.
    *   Load the submission file and assert that it adheres to the required format (correct shape, column names, and probability range).
4.  **Reproducibility**: We will set random seeds at the beginning to ensure consistent behavior.
