The implementation strategy follows the orchestration of the provided library components to establish a fast, high-performance baseline.

1.  **Configuration & Setup**: We override specific `Config` parameters to optimize for the "fast baseline" requirement while leveraging the A100 GPU. Specifically, we reduce `EPOCHS` to 10 and increase `BATCH_SIZE` to 2048 to maximize throughput without sacrificing convergence on the full dataset.
2.  **Data Loading**: We utilize `preprocess_features` with `load_cached_data=True` to efficiently load the pre-split and pre-processed (scaled/encoded) data.
3.  **Model Initialization**: We instantiate the `ParallelFunnelEnsemble` using the vocabulary sizes derived from the data processing step.
4.  **Training Loop**: We execute a standard training loop using `train_epoch` and `validate`. We employ the `OneCycleLR` scheduler as defined in the library to ensure rapid convergence.
5.  **Failure Analysis**: Post-training, we compute the absolute error on the validation set and calculate the Pearson correlation between this error and all input features (continuous and categorical) to identify failure modes.
6.  **Submission Logic**: We evaluate the final validation AUC against the strict threshold (`0.9975746465492954`). If the model passes, we run inference on the test set and generate the submission file.
