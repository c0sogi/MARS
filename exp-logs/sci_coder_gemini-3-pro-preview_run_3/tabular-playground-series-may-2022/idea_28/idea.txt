# Proposed Strategy: Independent-Projection Parallel Funnel Ensemble (IPPFE)

## Model
We will implement an **Independent-Projection Parallel Funnel Ensemble (IPPFE)**. This architecture introduces a structural innovation to the "Parallel In-Network Ensemble" by explicitly decoupling the continuous feature representation across streams. While previous successful ensembles decoupled the *categorical* representations via independent embeddings (Cite solution_lesson_node_00065), they shared the exact same *continuous* input vector. This new design introduces a learnable **Feature Transformation Layer (FTL)** for the continuous variables within each stream, maximizing ensemble diversity by allowing each member to learn a distinct rotation and scaling of the sensor manifold.

1.  **Parallel Independent Architecture:**
    *   The model will consist of **5 independent streams** instantiated within a single computational graph (Cite solution_lesson_node_00064).
    *   **Independent Embeddings:** Each stream will possess its own **independent Entity Embedding layers** (Dim 16) for the categorical features (Cite solution_lesson_node_00027).
    *   **Independent Feature Transformation (The Innovation):** Instead of feeding the raw normalized continuous features directly to the concatenation layer, each stream will process them through an independent **Linear Layer** (Input Dim $\to$ Input Dim). This allows each stream to learn a unique linear projection of the continuous space *before* fusion, correcting the representation bottleneck of shared inputs without the complexity of dual-stream non-linearities (Cite solution_lesson_node_00029).
    *   **Early Fusion:** The flattened embeddings and the *projected* continuous features are concatenated immediately (Cite solution_lesson_node_00029).

2.  **Backbone Topology (The Funnel):**
    *   All streams utilize the **Funnel MLP** structure (decreasing layer widths) to leverage its compressive inductive bias (Cite solution_lesson_node_00004).
    *   **Activation:** Standard **ReLU** exclusively (Cite solution_lesson_node_00069).
    *   **Exclusions:** No Layer Normalization (Cite solution_lesson_node_00039), No Batch Normalization (Cite solution_lesson_node_00091).

3.  **Heterogeneous Configuration:**
    *   We employ **Regularization Heterogeneity** (Cite solution_lesson_node_00069) and **Capacity Variation** (Cite solution_lesson_node_00066) while respecting the **Safety Floor** (Cite solution_lesson_node_00077).
    *   **Streams 1 & 2 (Anchors):** Standard Funnel (512 $\to$ 256 $\to$ 128), **Dropout 0.20**.
    *   **Stream 3 (Capacity Variant):** **Wide Funnel** (1024 $\to$ 512 $\to$ 256), **Dropout 0.25**.
    *   **Stream 4 (Safe-Aggressive):** Standard Funnel, **Dropout 0.15**. (Raised from 0.10 to prevent overfitting).
    *   **Stream 5 (Conservative):** Standard Funnel, **Dropout 0.30**.

## Data
The preprocessing pipeline is designed to ensure maximum signal fidelity and correct previous vocabulary alignment errors:

1.  **Transductive Vocabulary Alignment:** We will fit the categorical `OrdinalEncoder` on the **concatenation of the Train, Validation, and Test sets**. This ensures every unique token in the test set is assigned a distinct embedding index (Cite solution_lesson_node_00021).
2.  **Feature Engineering:**
    *   **String Decomposition:** Decompose `f_27` into 10 fixed-position character columns (Cite solution_lesson_node_00001).
    *   **Discrete Features:** Treat `f_29` and `f_30` as categorical variables (Cite solution_lesson_node_00008).
    *   **Aggregate Signal:** Compute and append the `unique_character_count` of `f_27` (Cite solution_lesson_node_00002).
3.  **Normalization:** Scale all continuous features using **StandardScaler**.
4.  **Data Volume:** Utilize the **full training dataset**, strictly avoiding subsampling (Cite solution_lesson_node_00022).

## Training
The training configuration is calibrated to facilitate super-convergence while respecting the sensitivities of AdamW:

1.  **Optimizer:** **AdamW** with a uniform weight decay of **1e-4**. We use `1e-4` to account for AdamW's decoupled implementation (Cite solution_lesson_node_00079) but avoid the aggressive `1e-2` (Cite solution_lesson_node_00023). We strictly avoid heterogeneous weight decay (Cite solution_lesson_node_00082).
2.  **Scheduler:** **One-Cycle Learning Rate Policy** with `max_lr=1e-2`. We explicitly maintain the high learning rate magnitude to ensure the model can escape local minima (Cite solution_lesson_node_00072).
3.  **Loss Function:** The training objective is the **sum of Binary Cross-Entropy losses** calculated independently for each of the 5 streams.
4.  **Batch Size:** **1024** (Cite solution_lesson_node_00024).
5.  **Duration:** Train for **50 Epochs**. We explicitly avoid premature truncation to allow the highly regularized streams to fully converge (Cite solution_lesson_node_00080).

## Evaluation
1.  **Preprocessing:** Apply the global (transductive) vocabulary mappings and training set scalers to the test set.
2.  **Inference:** The IPPFE model will generate 5 independent probability predictions per sample.
3.  **Submission:** The final prediction will be the **arithmetic mean** of these 5 probabilities.
