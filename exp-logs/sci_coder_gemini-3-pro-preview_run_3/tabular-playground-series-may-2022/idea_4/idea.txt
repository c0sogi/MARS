# Proposed Strategy: Gated Funnel Network with High-Capacity Embeddings

## Model
We will implement a **Gated Funnel MLP**, a structural evolution of the standard Feed-Forward network. While we retain the effective "Funnel" macroscopic structure (decreasing layer widths) to enforce feature compression (Cite solution_lesson_node_00004), we will fundamentally alter the microscopic layer architecture.

1.  **Gated Linear Unit (GLU) Backbone:** Instead of standard Dense layers with ReLU activations, we will utilize **Gated Linear Unit (GLU)** blocks. A GLU block processes the input $x$ through two parallel linear projections: a "value" branch and a "gate" branch. The output is the element-wise product of the value and the sigmoid-activated gate ($y = (xW + b) \otimes \sigma(xV + c)$). This mechanism allows the network to dynamically select relevant features and suppress noise at each stage of the funnel, providing a more sophisticated inductive bias for the simulated control logic than simple rectification.
2.  **High-Capacity Entity Embeddings:** We will employ learnable embeddings for all categorical inputs. Crucially, we will set the embedding dimension to a minimum of **16** for all categorical variables. This addresses the bottleneck identified in previous iterations where aggressive compression (dimension 8) caused signal loss in the complex string feature (Cite solution_lesson_node_00018).
3.  **Input Composition:** The input layer will concatenate the normalized continuous features with the flattened embedding vectors from:
    *   The 10 decomposed character positions of `f_27` (Cite solution_lesson_node_00001).
    *   The discrete integer features `f_29` and `f_30`, which will be treated strictly as categorical variables to preserve their non-linear state information (Cite solution_lesson_node_00008).

## Data
The data preprocessing pipeline integrates the most successful feature engineering steps while ensuring the input format aligns with the new architecture:
1.  **String Decomposition:** The `f_27` column will be split into 10 fixed-position character columns. These, along with `f_29` and `f_30`, will be integer-encoded for embedding lookup (Cite solution_lesson_node_00001).
2.  **Feature Engineering:** We will compute and append the `unique_character_count` of `f_27` as a continuous feature, as this aggregate signal aids convergence (Cite solution_lesson_node_00002).
3.  **Normalization:** All continuous features (original sensor data `f_00`-`f_28` and the engineered count feature) will be normalized using **StandardScaler** based on training set statistics.

## Training
We will employ a direct supervised training approach, avoiding the complexity and sub-optimal performance of autoencoder pretraining on this high-signal dataset (Cite solution_lesson_node_00013).
*   **Optimizer:** AdamW with weight decay to regularize the increased parameter count of the GLU blocks.
*   **Scheduler:** We will utilize the **One-Cycle Learning Rate Policy**. This schedule (warm-up to high LR, then decay) is essential for achieving super-convergence and finding robust minima in the loss landscape (Cite solution_lesson_node_00002).
*   **Loss Function:** Binary Cross-Entropy.
*   **Regularization:** Dropout will be applied within the GLU blocks to prevent overfitting.

## Evaluation
1.  **Preprocessing:** The test set will undergo the identical pipeline: string decomposition, integer encoding (using training mappings), and standard scaling (using training statistics).
2.  **Inference:** The trained Gated Funnel MLP will predict the probability of the target class `1` on the processed test data.
3.  **Submission:** The resulting probabilities will be formatted into the submission CSV.
