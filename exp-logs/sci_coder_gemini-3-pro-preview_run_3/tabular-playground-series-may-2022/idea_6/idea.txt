# Proposed Strategy: Hybrid Transformer-Funnel Network

## Model
We will implement a **Hybrid Transformer-Funnel Architecture**. This design introduces a structural innovation by treating the categorical state variables as a coherent sequence of interacting tokens, processed by a self-attention mechanism, while retaining the proven "Funnel" MLP backbone for global feature integration.

1.  **Categorical Interaction Branch (The Innovation):**
    *   **Inputs:** The 10 decomposed character positions of `f_27` (Cite solution_lesson_node_00001) and the discrete features `f_29` and `f_30` (Cite solution_lesson_node_00008).
    *   **Embeddings:** Each feature will be mapped to a learnable embedding vector of dimension **32**. This ensures sufficient capacity to capture high-cardinality signal without bottlenecks (Cite solution_lesson_node_00018).
    *   **Transformer Encoder:** The embeddings will be stacked to form a sequence of length 12 (10 chars + 2 discrete). We will apply a single **Transformer Encoder Layer** (Multi-Head Self-Attention + Feed-Forward Network). This allows the model to explicitly learn the complex, non-linear dependencies between the manufacturing codes (e.g., "Char 1 interacts with State 29") within a dedicated subspace, avoiding the noise-fitting issues seen when crossing continuous features (Cite solution_lesson_node_00006).
    *   **Flattening:** The output of the Transformer layer will be flattened into a single dense vector.

2.  **Continuous Branch:**
    *   **Inputs:** All normalized continuous features (`f_00`–`f_28`) and the engineered `unique_character_count`.

3.  **Funnel Backbone (The Exploitation):**
    *   **Fusion:** The flattened categorical representation and the continuous features will be concatenated.
    *   **Architecture:** The combined vector will be processed by a **Funnel MLP** with decreasing layer widths (512 $\to$ 256 $\to$ 128). We retain this structure as it provides the beneficial inductive bias of feature compression superior to constant-width ResNets for this data (Cite solution_lesson_node_00004).
    *   **Head:** The final 128-unit representation connects directly to the output neuron, avoiding narrow bottlenecks (Cite solution_lesson_node_00020).

## Data
The preprocessing pipeline synthesizes the most effective techniques while correcting previous vocabulary alignment errors:

1.  **Transductive Vocabulary Alignment:** We will fit the categorical `OrdinalEncoder` on the **concatenation of the Train, Validation, and Test sets**. This ensures every unique token in the test set has a distinct embedding index, preventing the information loss caused by mapping unseen test tokens to "unknown" (Cite solution_lesson_node_00021).
2.  **String Decomposition:** `f_27` will be split into 10 fixed-position character columns (Cite solution_lesson_node_00001).
3.  **Feature Engineering:** We will compute and append the `unique_character_count` of `f_27` (Cite solution_lesson_node_00002).
4.  **Normalization:** Continuous features will be scaled using StandardScaler.
5.  **Data Volume:** We will utilize the **full training dataset**, strictly avoiding subsampling to ensure the complex architecture has sufficient data to converge (Cite solution_lesson_node_00022).

## Training
The training configuration is optimized to balance convergence speed with generalization, correcting previous regularization missteps:

1.  **Optimizer:** **AdamW** with a calibrated weight decay of **1e-5**. We explicitly avoid the default `1e-2`, which was proven too aggressive for this tabular task (Cite solution_lesson_node_00023).
2.  **Batch Size:** **1024**. We revert to this moderate batch size to leverage the implicit regularization of stochastic gradient noise, avoiding the generalization gap observed with larger batches (Cite solution_lesson_node_00024).
3.  **Scheduler:** **One-Cycle Learning Rate Policy**. We retain this schedule to facilitate super-convergence and robust minima selection (Cite solution_lesson_node_00002).
4.  **Regularization:** Dropout (rate 0.2) will be applied within the Funnel MLP layers.

## Evaluation
1.  **Preprocessing:** The test set will be processed using the global vocabulary mappings and training set scalers.
2.  **Inference:** The trained Hybrid Transformer-Funnel model will predict probabilities for the target class `1`.
3.  **Submission:** Predictions will be formatted into the submission CSV for AUC evaluation.
