This strategy structurally evolves the "Current Best" Idea 15 and the high-potential Idea 29 by synthesizing the **Orthogonal Decomposition** framework with a critical physics-based correction: **Trend-Sensitive Temporal Profiling**. It explicitly resolves the conflict between "Flattened Windows" (Lesson 00010) and "Shift Invariance" (Lesson 00050) by augmenting temporal snapshots with **Linear Trend Metrics** (e.g., the slope of energy over time), allowing the model to detect "ramping up" events robustly. Furthermore, it strictly enforces **Polynomial Order Constraints** (Lesson 00094) and **High-Resolution Spectral** protocols (Lesson 00082).

# Model
The predictive architecture will be a **Homogeneous Ensemble of High-Capacity LightGBM Regressors**.

*   **Architecture:** Five independent instances of a **High-Capacity LightGBM** (e.g., `num_leaves=128`, `n_estimators=10,000`, `learning_rate` < 0.05) trained on different data folds (Bagging).
*   **Rationale:** Lesson 00075 demonstrated that **Cross-Validation Ensembling (Bagging)** is the superior regularization strategy for this dataset, allowing the use of deep trees to capture complex non-linearities while mitigating variance.
*   **Objective Function:** The models will be trained using **L2 Loss (Mean Squared Error)**.
    *   **Rationale:** Lesson 00060 proved that optimizing L2 Loss yields better convergence and lower final MAE than L1 Loss due to superior gradient dynamics (informative gradients vs. constant sign gradients).

# Data
The data processing pipeline implements a **Pyramidal Orthogonal Decomposition** to extract physically distinct signal components at multiple temporal scales.

1.  **Preprocessing:**
    *   **Imputation:** Fill missing values with the segment-wise column mean to preserve DC offsets (Cite solution_lesson_node_00002).
    *   **Decomposition:** For each sensor, generate three distinct signal views:
        *   **View A (Trend):** Apply a **Savitzky-Golay filter** with a **large window size (e.g., 51)** and a **Low Polynomial Order (Order 2)**.
            *   *Correction:* Strictly use **Order 2** (Quadratic) instead of Order 3. Lesson 00094 proved that Order 3 fits local noise, creating artificial acceleration artifacts that lead to overfitting.
        *   **View B (Texture):** Apply a **Discrete Wavelet Transform (DWT)** (e.g., `db4`) to the **Residuals** ($Raw - Trend$) and extract Detail Coefficients. (Cite solution_lesson_node_00060).
        *   **View C (Raw):** Retain the original **Raw** signal.

2.  **Feature Engineering (The Pyramidal Paradigm):**
    *   **Level 1: Global Intensity & Spectrum (From View C):**
        *   Extract **Global Minimum**, **Global Maximum**, and **Peak-to-Peak Range**. (Cite solution_lesson_node_00031).
        *   Compute **PSD Band Power** using **Welch's Method** with **Closed Intervals** (Low: 0.1-3Hz, Mid: 3-10Hz, High: 10-45Hz).
        *   *Constraint:* Set `nperseg=1024` to ensure high resolution in the 0.1-3Hz band (Cite solution_lesson_node_00082).
    *   **Level 2: Robust Kinematics (From View A):**
        *   Compute **First (Velocity)** and **Second (Acceleration)** derivatives.
        *   Extract **Higher-Order Moments (Skewness, Kurtosis)**, Mean, and Std.
        *   *Constraint:* Prioritize Moments over Dense Quantiles to capture signal impulsiveness without overfitting noise (Cite solution_lesson_node_00077).
    *   **Level 3: Texture Complexity (From View B):**
        *   Extract **Energy**, **Entropy**, **Skewness**, and **Kurtosis** from DWT coefficients (Cite solution_lesson_node_00049).
    *   **Level 4: Trend-Sensitive Temporal Profiling (Structural Innovation):**
        *   Divide the signal into $N$ non-overlapping windows. Compute RMS and Mean for each.
        *   **Feature Set A (Snapshots):** Flatten these into explicit features (e.g., `w1_rms`) to preserve the "arrow of time" (Cite solution_lesson_node_00010).
        *   **Feature Set B (Dynamics):** Compute the **Linear Slope** (regression coefficient) and **Volatility** (std) of the window RMS sequence.
            *   *Rationale:* This explicitly encodes *whether the seismic activity is escalating* (ramping up) or stabilizing, providing a robust physical descriptor that complements the static snapshots.

3.  **Feature Organization:**
    *   **Spatial Concatenation:** Concatenate features for all 10 sensors side-by-side (Cite solution_lesson_node_00018).
    *   **No Selection:** Feed the full feature set to the models (Cite solution_lesson_node_00017).

# Training
*   **Strategy:** Use **Stratified K-Fold Cross-Validation** (5 folds) based on the provided metadata bins. Train one high-capacity LightGBM per fold.
*   **Optimization:** Use **Early Stopping** based on the *Validation MAE* (Cite solution_lesson_node_00002).
