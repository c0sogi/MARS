The feature engineering pipeline is failing validation because it produces `NaN` values in the output features. This stems from two issues:
1.  **Incomplete Imputation:** The current imputation strategy `df.fillna(df.mean())` fails when a column contains *only* `NaN` values, as the mean itself is `NaN`. This leaves the column empty (Cite debug_lesson_1).
2.  **Zero Variance Instability:** When a sensor signal is constant (e.g., after being filled with zeros or if the sensor was dead), its standard deviation is zero. Calculating skewness and kurtosis involves dividing by the standard deviation, which results in `NaN` or infinity (Cite debug_lesson_4).

I will fix this by:
1.  Modifying `extract_segment_features` to chain `.fillna(0)` after the mean imputation, ensuring all missing data is handled.
2.  Updating `calculate_moments` to explicitly check for zero standard deviation and return 0 for skewness/kurtosis in those cases.
