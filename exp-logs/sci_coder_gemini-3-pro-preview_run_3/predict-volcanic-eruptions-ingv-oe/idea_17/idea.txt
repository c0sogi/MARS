Based on the progression of empirical results—specifically the breakthrough performance of **Orthogonal Signal Decomposition** (Idea 15, MAE ~2.61M) and the identified failures of aggressive feature selection (Idea 5), spatial pooling (Idea 6), and raw periodograms (Idea 17)—I propose the **Augmented Orthogonal Decomposition with Cepstral Texture and Spatial Consistency** strategy.

This approach structurally evolves the "Current Best" Idea 15 by enhancing the "Texture" view with robust cepstral features (addressing the need for better complexity descriptors) and introducing "Spatial Consistency" features to explicitly model array-wide synchronization without losing sensor identity.

# Model
The predictive core will remain a **Single, Highly-Optimized LightGBM Regressor**.
*   **Rationale:** Previous experiments demonstrated that a single, well-tuned Gradient Boosted Decision Tree (GBDT) significantly outperforms complex Stacking Ensembles of under-optimized base learners (Cite solution_lesson_node_00046) and Deep Learning approaches (Cite solution_lesson_node_00008). By focusing computational resources on optimizing one strong backbone (specifically tuning `num_leaves` > 64 and `learning_rate`), we avoid the variance and "weak learner" pitfalls observed in prior attempts.

# Data
The data processing pipeline implements the **Orthogonal Signal Decomposition** paradigm to extract non-overlapping information views, augmented with spatial context.

1.  **Preprocessing:**
    *   **Imputation:** Fill missing values with the segment-wise column mean to preserve DC offsets (Cite solution_lesson_node_00002).
    *   **Decomposition:** For each of the 10 sensors, generate three distinct signal views (Cite solution_lesson_node_00049):
        *   **View A (Trend):** Apply a **Savitzky-Golay filter** with a **large window size (> 20)** (e.g., window=51, poly=3). This isolates low-frequency kinematic motion.
        *   **View B (Texture):** Compute the **Residuals** ($Texture = Raw - Trend$). This isolates high-frequency tremors and noise structure.
        *   **View C (Energy):** Retain the original **Raw** signal.

2.  **Feature Engineering (The Augmented Paradigm):**
    *   **From View A (Trend - Kinematics):** Compute **First (Velocity)** and **Second (Acceleration)** derivatives. Extract **Quantiles (1st, 5th, 95th, 99th)**, Mean, and Std.
        *   *Benefit:* Captures pure kinematic evolution using robust shape descriptors, avoiding the noise amplification of raw derivatives (Cite solution_lesson_node_00006) and the instability of higher-order moments on derivatives (Cite solution_lesson_node_00026).
    *   **From View B (Texture - Timbre):** Extract **Mel-Frequency Cepstral Coefficients (MFCCs)** (top 5 coefficients) and **Higher-Order Moments (Skewness, Kurtosis)**.
        *   *Innovation:* MFCCs provide a robust, decorrelated representation of the signal's "timbre" or texture (Cite solution_lesson_node_00005) which generic moments might miss, applied specifically to the residual stream where this information lives.
    *   **From View C (Energy - Intensity):** Extract **Global Minimum**, **Global Maximum**, and **Peak-to-Peak Range**.
        *   *Benefit:* Strictly preserves the absolute intensity of the event, correcting the failure of robust statistics to capture critical outliers (Cite solution_lesson_node_00031).
    *   **From View C (Spectral Structure):** Compute **Power Spectral Density (PSD)** using **Welch's Method**. Extract **Band Power** (Low/Mid/High) and **Spectral Centroid**.
        *   *Constraint:* Strictly use Welch's method to ensure stability, avoiding the noise of Raw Periodograms (Cite solution_lesson_node_00054).
    *   **From View C (Temporal Evolution):** Divide the signal into non-overlapping windows. Compute **RMS** and **Mean** for each.
        *   *Constraint:* **Flatten** these into explicit features (e.g., `w1_rms`, `w2_rms`) to preserve the temporal "arrow of time" (Cite solution_lesson_node_00010).
    *   **Spatial Consistency Augmentation (Structural Innovation):**
        *   After computing the per-sensor features, calculate **Cross-Sensor Statistics** (e.g., the standard deviation and range of the `Mean` and `RMS` values *across* the 10 sensors).
        *   *Benefit:* This adds explicit information about the *synchronization* of the array (distinguishing localized noise from generalized events) without destroying the individual sensor identities via pooling (Cite solution_lesson_node_00018).

3.  **Feature Organization:**
    *   **Concatenation:** Concatenate the feature vectors of all 10 sensors side-by-side, followed by the Spatial Consistency features.
    *   **No External Selection:** Feed the full feature set to the model. Do **not** use RFE, allowing the GBDT to utilize distributed signal information (Cite solution_lesson_node_00017).

# Training
*   **Strategy:** Use **Stratified K-Fold Cross-Validation** (e.g., 5 folds) based on the provided metadata bins.
*   **Objective:** Minimize **Mean Absolute Error (MAE)**.
*   **Optimization:**
    *   Set a high `n_estimators` (e.g., 5,000+) to ensure convergence (Cite solution_lesson_node_00002).
    *   Implement **Early Stopping** based on the validation set MAE.
    *   Tune `num_leaves` (start > 64) to handle the rich feature set, preventing the underfitting observed in previous ensembles (Cite solution_lesson_node_00046).
