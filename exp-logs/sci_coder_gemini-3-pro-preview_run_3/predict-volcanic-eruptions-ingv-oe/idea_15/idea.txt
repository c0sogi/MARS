Based on the comprehensive analysis of previous experiments and the specific lessons derived, I propose the **Orthogonal Signal Decomposition with Optimized Gradient Boosting** strategy.

This approach introduces a **Structural Innovation** in the feature engineering pipeline. Instead of treating the signal as a single stream or a simple "Raw vs. Smoothed" dual-stream, it explicitly decomposes the sensor data into three orthogonal components: **Trend**, **Texture**, and **Energy**. This resolves the fundamental conflict identified in previous lessons where noise suppression techniques (smoothing) destroyed signal intensity (peaks), and peak preservation techniques amplified noise.

# Model
The predictive core will be a **Single, Highly-Optimized LightGBM Regressor**.
*   **Rationale:** Previous experiments confirmed that a single, well-tuned Gradient Boosted Decision Tree (GBDT) significantly outperforms complex Stacking Ensembles of under-optimized base learners (Cite solution_lesson_node_00046) and Deep Learning approaches (Cite solution_lesson_node_00008). By focusing computational resources on optimizing a single strong backbone, we avoid the variance and implementation pitfalls of complex ensembles.

# Data
The data processing pipeline implements the **Orthogonal Signal Decomposition** paradigm to extract non-overlapping information views.

1.  **Preprocessing:**
    *   **Imputation:** Fill missing values with the segment-wise column mean to preserve DC offsets (Cite solution_lesson_node_00002).
    *   **Decomposition:** For each sensor, generate three distinct signal views:
        *   **View A (Trend):** Apply a **Savitzky-Golay filter** with a **large window size (> 20)**. This isolates the low-frequency kinematic motion (Cite solution_lesson_node_00023).
        *   **View B (Texture):** Compute the **Residuals** by subtracting the Trend from the Raw signal ($Texture = Raw - Trend$). This isolates high-frequency tremors and noise structure without the bias of the macro-trend.
        *   **View C (Energy):** Retain the original **Raw** signal.

2.  **Feature Engineering (The Orthogonal Paradigm):**
    *   **From View A (Trend):** Compute **First (Velocity)** and **Second (Acceleration)** derivatives. Extract **Quantiles (1st, 99th)**, Mean, and Std.
        *   *Benefit:* Captures pure kinematic evolution without amplifying high-frequency noise (Cite solution_lesson_node_00021, solution_lesson_node_00026).
    *   **From View B (Texture):** Apply **Discrete Wavelet Transform (DWT)** (using `db4`) and compute **RMS** of the residuals.
        *   *Benefit:* Captures the "roughness" and harmonic complexity of the seismic event, similar to the success of Idea 4.
    *   **From View C (Energy):** Extract **Global Minimum**, **Global Maximum**, and **Peak-to-Peak Range**.
        *   *Benefit:* Strictly preserves the absolute intensity of the event, correcting the failure of "robust" statistics to capture critical outliers (Cite solution_lesson_node_00031).
    *   **Spectral & Temporal (From View C):** Compute **PSD Band Power** (Low/Mid/High) (Cite solution_lesson_node_00007) and **Flattened Window Statistics** (Mean, RMS per window) (Cite solution_lesson_node_00010).

3.  **Feature Organization:**
    *   **Spatial Concatenation:** Concatenate the feature vectors of all 10 sensors into a single wide input. Do **not** aggregate features across sensors (Cite solution_lesson_node_00018).
    *   **No External Selection:** Feed the full feature set to the model. Do **not** use RFE, allowing the GBDT to utilize distributed signal information (Cite solution_lesson_node_00017).

# Training
*   **Strategy:** Use **Stratified K-Fold Cross-Validation** (e.g., 5 folds) based on the provided metadata bins.
*   **Objective:** Minimize **Mean Absolute Error (MAE)**.
*   **Optimization:**
    *   Set a high `n_estimators` (e.g., 10,000) to ensure the model is not artificially constrained (Cite solution_lesson_node_00002).
    *   Implement **Early Stopping** based on the validation set MAE.
    *   Tune `num_leaves` and `learning_rate` specifically for this high-dimensional feature set to prevent the under-fitting observed in previous ensemble attempts (Cite solution_lesson_node_00046).

# Evaluation
1.  **Feature Extraction:** Process the test set using the Orthogonal Decomposition pipeline (Imputation -> Trend/Texture/Energy Separation -> Feature Extraction -> Concatenation).
2.  **Inference:** Generate predictions using the trained LightGBM model.
3.  **Submission:** Format the output as `segment_id,time_to_eruption`.
