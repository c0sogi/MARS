Implementation Strategy:
1.  **Configuration Setup**: Import the provided library modules (`library.config`, `library.feature_engineering`, `library.model_handler`, `library.training_manager`). Patch the global variables in `library.config` to adapt the pipeline for a quick demonstration. This includes setting a small `DEBUG_SAMPLE_SIZE` (20 samples), reducing LightGBM estimators and leaves for speed, setting `N_FOLDS` to 2, and redirecting output files to a temporary working directory.
2.  **Feature Engineering Demonstration**: Explicitly call `feature_engineering.get_train_data` to generate features for the small subset. Verify the resulting DataFrame's shape and the presence of critical columns (`segment_id`, `time_to_eruption`, sensor features) using assertions.
3.  **Training Pipeline Demonstration**: Invoke `training_manager.run_cross_validation`. This function orchestrates the data loading (using the features generated/cached in the previous step), stratified splitting, and model training. Assert that the returned Mean Absolute Error (MAE) is valid and that model files are correctly saved to the working directory.
4.  **Direct Model Interaction**: Demonstrate the lower-level `model_handler` API by manually splitting the data and training a single fold model, then generating predictions. This verifies the component-level logic independent of the manager.
5.  **Inference and Submission**: Call `training_manager.generate_test_predictions` on a small subset of test data. Verify that the submission CSV is created, follows the correct schema (`segment_id`, `time_to_eruption`), and contains the expected number of rows.
6.  **Cleanup**: The script runs in a self-contained manner and cleans up the working directory logic via configuration (though physical deletion is optional, the script overwrites/creates new files in its specific folder).
