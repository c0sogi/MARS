Based on the lessons learned from previous iterations, I propose a **Cepstral-Temporal Energy Fingerprinting with Recursive Feature Selection** strategy. This approach maintains the high-efficiency Gradient Boosting backbone (Exploitation) while introducing a robust, physically-motivated feature engineering pipeline (Innovation) designed to capture signal texture and evolution without the noise sensitivity of previous attempts.

# Model
The core model will remain a **LightGBM Regressor**.
*   **Rationale:** Previous experiments demonstrated that Gradient Boosting on tabular features is significantly more data-efficient and performant than Deep Learning (CNNs) for this specific dataset size (Cite solution_lesson_node_00008).
*   **Architecture:** A standard GBDT ensemble. However, unlike previous iterations where the model was fed raw engineered features directly, this solution introduces a **Feature Selection Wrapper** (Recursive Feature Elimination) upstream to strictly control model complexity and prevent the overfitting observed when feature counts increased (Cite solution_lesson_node_00012).

# Data
The data processing pipeline is redesigned to prioritize **integral-based** and **decorrelated** representations over noise-sensitive derivatives.

1.  **Preprocessing & Imputation:**
    *   Load sensor data and impute missing values with the segment-wise column mean to preserve DC offsets (Cite solution_lesson_node_00002).
    *   **Cache Safety:** Ensure all features are computed fresh for this run to avoid the stale data issues observed previously (Cite solution_lesson_node_00013).

2.  **Feature Engineering (Structural Innovation & Correction):**
    *   **Cepstral Analysis (Innovation):** Instead of using raw FFT magnitudes or generic spectral stats (which lose structure or are too high-dimensional), compute **Mel-Frequency Cepstral Coefficients (MFCCs)** for each sensor. MFCCs compactly represent the "texture" and harmonic content of the seismic signal (Cite solution_lesson_node_00005) in a decorrelated format that is robust to noise.
    *   **Robust Temporal Integration (Correction):** Replace the noise-amplifying derivative features (Velocity/Acceleration) used in Idea 4 (Cite solution_lesson_node_00006, solution_lesson_node_00012) with **Rolling Root-Mean-Square (RMS) Energy**. RMS is an integral-based metric that smooths out high-frequency noise while accurately capturing the signal's intensity evolution.
    *   **Explicit Windowing (Exploitation):** Apply the RMS calculation and basic stats (Mean, Std) over non-overlapping windows and flatten them into explicit features (e.g., `win1_rms`, `win2_rms`) to preserve the temporal trajectory ("arrow of time") (Cite solution_lesson_node_00010).
    *   **Structural Spectral Power (Exploitation):** Retain the extraction of **Band Power** (Low/Mid/High frequency energy) and **Spectral Centroid**, as these physically interpretable features outperformed generic FFT statistics (Cite solution_lesson_node_00007).
    *   **Spatial Aggregation (Innovation):** Compute summary statistics (Mean, Max, Std) *across the 10 sensor channels* for the global features. This creates "Volcano-Level" descriptors that are robust to individual sensor anomalies.

3.  **Feature Selection (Correction):**
    *   Implement **Recursive Feature Elimination (RFE)** using a Random Forest Regressor on a subsample of the training data. This step is mandatory to prune non-predictive or redundant features before they reach the LightGBM model, directly addressing the "curse of dimensionality" and overfitting observed in Idea 4 (Cite solution_lesson_node_00012).

# Training
*   **Algorithm:** LightGBM Regressor with `objective='mae'`.
*   **Hyperparameters:** Use a high limit for `n_estimators` (e.g., 10,000) to ensure convergence, as previous limits of 2,000 were insufficient (Cite solution_lesson_node_00002).
*   **Strategy:** Train on the features selected by RFE. Use **Early Stopping** based on the stratified validation set (Cite solution_lesson_node_00002) to prevent overfitting.

# Evaluation
1.  **Feature Extraction:** Process the test files listed in `metadata/test.csv`. Apply the full pipeline: Imputation -> MFCC/RMS/BandPower Extraction -> Spatial Aggregation.
2.  **Selection Application:** Filter the test feature set to retain only the columns selected by the RFE step during training.
3.  **Inference:** Generate predictions using the trained LightGBM model and format the submission as `segment_id,time_to_eruption`.
