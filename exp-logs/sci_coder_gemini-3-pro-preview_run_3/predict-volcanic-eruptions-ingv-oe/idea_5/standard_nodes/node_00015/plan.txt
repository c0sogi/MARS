The issue is caused by the cached feature files (e.g., `train_features.parquet`) already containing the target column `time_to_eruption`. When `runfile.py` loads these features and merges them with the metadata (which also contains `time_to_eruption`), Pandas handles the name collision by renaming the columns to `time_to_eruption_x` and `time_to_eruption_y`. As a result, the subsequent code expecting the exact column name `time_to_eruption` fails with a `KeyError`.

To fix this, I will modify `library/feature_engineering.py` to validate the cached data upon loading (Cite debug_lesson_1). I will add a check to detect if the `TARGET_COL` is present in the loaded DataFrame and drop it if found. This ensures the feature DataFrame is clean before it is returned to the pipeline, preventing the merge collision.
