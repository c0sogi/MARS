Based on the progression of empirical findings—specifically the success of **Orthogonal Signal Decomposition** (Idea 15) and the critical corrective lessons regarding **Feature Granularity** (Lesson 00077), **Model Capacity** (Lesson 00075), and **Temporal Invariance** (Lesson 00050)—I propose the **Hierarchical Moment-Based Orthogonal Decomposition Ensemble**.

This strategy structurally evolves the "Current Best" solution by resolving the conflict between "Temporal Evolution" and "Overfitting." It replaces the "Flattened Window" and "Dense Quantile" approaches (which caused overfitting in Ideas 20-23) with a **Hierarchical Aggregation** and **Higher-Order Moment** paradigm. This ensures the model captures signal volatility and impulsiveness without memorizing noise at specific time indices.

# Model
The predictive architecture will be a **Homogeneous Ensemble of High-Capacity LightGBM Regressors**.
*   **Architecture:** Five instances of a **High-Capacity LightGBM** (e.g., `num_leaves=128`, `n_estimators=5000+`) trained on different data folds.
*   **Rationale:** Lesson 00075 demonstrated that **Cross-Validation Ensembling (Bagging)** is a superior regularization strategy compared to artificially constraining model capacity (e.g., small trees). High-capacity trees are required to capture the complex non-linear dependencies in the decomposed signal, while the ensemble averaging mitigates the variance that plagued single-model attempts (Cite solution_lesson_node_00075).

# Data
The data processing pipeline implements a **Hierarchical Orthogonal Decomposition** to extract physically distinct signal components using statistically robust descriptors.

1.  **Preprocessing:**
    *   **Imputation:** Fill missing values with the segment-wise column mean to preserve DC offsets (Cite solution_lesson_node_00002).
    *   **Decomposition:** For each sensor, generate three distinct signal views:
        *   **View A (Trend):** Apply a **Savitzky-Golay filter** with a **large window size (e.g., 51)**. This strictly isolates the low-frequency baseline drift from oscillatory tremors, preventing frequency leakage (Cite solution_lesson_node_00070).
        *   **View B (Texture):** Compute the **Residuals** ($Texture = Raw - Trend$).
        *   **View C (Energy):** Retain the original **Raw** signal.

2.  **Feature Engineering (The Hierarchical Moment Paradigm):**
    *   **From View A (Trend Kinematics):** Compute **First (Velocity)** and **Second (Acceleration)** derivatives. Extract **Higher-Order Moments (Skewness, Kurtosis)**, Mean, and Std.
        *   *Correction:* Explicitly prioritize **Skewness/Kurtosis** over Dense Quantiles. Lesson 00077 proved that moments capture the "impulsiveness" of the kinematic signal better than quantiles, which tend to overfit noise (Cite solution_lesson_node_00077).
    *   **From View B (Wavelet Texture):** Apply **Discrete Wavelet Transform (DWT)** (e.g., `db4`) to the **Residuals**. Extract **Energy**, **Entropy**, **Skewness**, and **Kurtosis** from the coefficients.
        *   *Rationale:* Wavelets preserve multi-resolution structures that simple residual stats miss (Cite solution_lesson_node_00060).
    *   **From View C (Absolute Intensity):** Extract **Global Minimum**, **Global Maximum**, and **Peak-to-Peak Range**.
        *   *Rationale:* Strictly preserves the absolute intensity of the event, adhering to the lesson that "outliers are the signal" (Cite solution_lesson_node_00031).
    *   **From View C (Spectral Structure):** Compute **PSD Band Power** using **Welch's Method** with **Closed Intervals** (Low/Mid/High).
        *   *Rationale:* Avoids the noise of Raw Periodograms (Cite solution_lesson_node_00054) and the artifacts of open-ended filters (Cite solution_lesson_node_00058).
    *   **From View C (Hierarchical Temporal Aggregation):**
        *   Divide the signal into $N$ non-overlapping windows.
        *   Compute statistics (RMS, Mean) for *each* window.
        *   **Structural Innovation:** Instead of flattening these (e.g., `w1_rms`, `w2_rms`), compute **Aggregated Statistics of the Window Statistics** (e.g., `std(window_means)`, `mean(window_rms)`, `max(window_rms)`).
        *   *Rationale:* This captures the *volatility* and *evolution* of the signal (e.g., "how much does the baseline fluctuate?") without forcing the model to look for patterns at specific absolute time indices, preventing the overfitting observed with flattened windows (Cite solution_lesson_node_00050, solution_lesson_node_00077).

3.  **Feature Organization:**
    *   **Spatial Concatenation:** Concatenate features for all 10 sensors side-by-side. Do **not** aggregate across sensors (Cite solution_lesson_node_00018).

# Training
*   **Strategy:** Use **Stratified K-Fold Cross-Validation** (5 folds) based on the provided metadata bins. Train one high-capacity LightGBM per fold.
*   **Loss Function:** Optimize using **L2 Loss (Mean Squared Error)**.
    *   *Rationale:* Lesson 00060 proved that L2 optimization yields better convergence and lower final MAE than L1 optimization due to superior gradient dynamics.
*   **Optimization:** Use **Early Stopping** based on the validation MAE. Allow the model to grow deep (`num_leaves=128`) to fully exploit the rich moment-based features (Cite solution_lesson_node_00075).

# Evaluation
1.  **Feature Extraction:** Process the test set using the Hierarchical Pipeline (Imputation -> Large-Window SG Trend / Wavelet Texture / Raw Energy -> Moment & Hierarchical Aggregation Extraction -> Concatenation).
2.  **Inference:** Generate predictions from all 5 trained fold models.
3.  **Aggregation:** Compute the arithmetic mean of the 5 predictions to produce the final `time_to_eruption`.
4.  **Submission:** Format the output as `segment_id,time_to_eruption`.
