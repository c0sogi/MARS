The issue identified is **Data Leakage**. The `train_ensemble` function in `library/model_handler.py` was loading both the training and validation datasets (`get_train_data` and `get_val_data`) and concatenating them before performing Cross-Validation. This meant that the models were trained on data that was later used for final validation in `runfile.py`, leading to an invalid, overly optimistic metric.

To fix this, I will modify `library/model_handler.py` to:
1.  Remove the import and usage of `get_val_data` within the model handler.
2.  Update `train_ensemble` to load only the training data using `get_train_data`.
3.  Remove the concatenation logic, ensuring the models are trained strictly on the training subset defined in the metadata.

This ensures the validation set remains a true hold-out set for the final evaluation.
