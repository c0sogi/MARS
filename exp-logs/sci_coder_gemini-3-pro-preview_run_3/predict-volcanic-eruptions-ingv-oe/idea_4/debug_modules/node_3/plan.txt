The `AssertionError: Training features contain NaNs` occurs because the feature engineering process generates `NaN` values when processing "dead" sensors (sensors with all missing values). Although the data cleaning step fills these sensors with zeros (Cite debug_lesson_1), this results in a signal with zero variance. When `scipy.stats.skew` and `scipy.stats.kurtosis` are calculated on these constant signals, they attempt to divide by the standard deviation (which is zero), resulting in `NaN`s (Cite debug_lesson_4).

To fix this, I will modify `calculate_stats` in `library/feature_engineering.py` to explicitly check if the standard deviation is zero. If it is, I will assign a default value of `0.0` to the skewness and kurtosis features instead of attempting the calculation.
