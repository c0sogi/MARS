Based on the critical failure of the previous deep learning attempt (Idea 4) due to optimization instability, and the fundamental inadequacy of geometric heuristics (Idea 2), I propose a **Pillar-Based Center-Regression Network**.

This strategy represents a structural shift from an **Anchor-Based (SSD)** detection paradigm to an **Anchor-Free (Center-Based)** paradigm. By removing the complexity of anchor matching and offset regression—which caused the pathological loss values observed in the previous attempt—we can stabilize training while retaining the deep semantic learning required to handle Lidar occlusions.

# Model
The architecture abandons the SSD Head in favor of a simpler, more robust Center Head, while maintaining the efficient Pillar encoder.

1.  **Pillar Feature Encoder (Retained)**:
    *   We utilize the same voxelization strategy as PointPillars to discretize the point cloud into a 2D grid of vertical columns. A simplified PointNet aggregates point features (x, y, z, intensity, offsets) into a dense pseudo-image $(C \times H \times W)$. This preserves the deep learning capability needed to solve the "L-shape" occlusion problem **Cite solution_lesson_node_00005**.
2.  **2D Backbone**:
    *   A standard 2D Convolutional Neural Network (e.g., a lightweight ResNet or VGG-based FPN) processes the pseudo-image to extract high-level spatial features and expand the receptive field.
3.  **Center-Based Detection Head (Innovation)**:
    *   Instead of predicting offsets for thousands of pre-defined anchor boxes (which led to exploding gradients **Cite solution_lesson_node_00008**), the head produces dense heatmaps and regression maps directly:
        *   **Heatmap Branch**: Outputs a $K$-channel heatmap (where $K$ is the number of classes). Peaks in this heatmap represent object centers.
        *   **Dimension Branch**: Predicts the log-normalized dimensions $(\log l, \log w, \log h)$ at each pixel.
        *   **Position Offset Branch**: Predicts the sub-pixel discretization error $(\delta x, \delta y)$ to recover the exact center.
        *   **Orientation Branch**: Predicts the sine and cosine of the yaw angle.
    *   This formulation decouples the classification task (heatmap) from the regression task, preventing the "tug-of-war" and scaling issues inherent in anchor-based loss functions.

# Data
1.  **Preprocessing**:
    *   **Voxelization**: The point cloud is clipped to a defined range (e.g., $[-75m, 75m]$) and pillarized.
    *   **Target Generation**:
        *   **Heatmaps**: For every ground truth object, we project its 3D center onto the 2D grid. We splat a 2D Gaussian kernel at this location, where the radius is determined by the object's size. This creates a smooth, normalized (0-1) training signal that is far more stable than binary anchor matching.
        *   **Regression Maps**: At the specific grid index of each object center, we store the ground truth values. Crucially, dimensions are **log-transformed** to compress the dynamic range (e.g., preventing a bus and a pedestrian from generating loss values orders of magnitude apart), directly addressing the optimization instability **Cite solution_lesson_node_00008**.
2.  **Augmentation**:
    *   We apply global rotation, scaling, and "GT Database Sampling" (pasting ground truth objects from other scenes) to maintain high object density and diversity.

# Training
1.  **Loss Functions**:
    *   **Gaussian Focal Loss**: Applied to the heatmap branch. This handles class imbalance by down-weighting easy background examples, similar to the previous approach but adapted for continuous heatmaps.
    *   **L1 Loss**: Applied to the dimension, offset, and orientation branches. Crucially, this loss is **only calculated at positive object centers**, masking out the vast majority of the grid. This prevents the network from trying to regress shapes in empty space, stabilizing convergence.
2.  **Optimizer**:
    *   **AdamW** with a **One-Cycle Learning Rate** schedule. This provides a warm-up phase to stabilize the initial gradients before aggressive training.

# Evaluation
1.  **Inference**:
    *   The model outputs the heatmap and regression maps.
    *   We perform a $3 \times 3$ Max Pooling operation on the heatmap to identify local peaks (candidate object centers).
    *   Top $N$ peaks (based on confidence scores) are selected.
2.  **Decoding**:
    *   For each selected peak, we extract the corresponding values from the regression maps.
    *   The 3D bounding box is reconstructed: Center $(x, y)$ is recovered using the grid index and predicted offsets; Dimensions are recovered via exponential transform of the log-predictions.
    *   This process naturally handles non-maximum suppression (NMS) via the max-pooling step, though a fast IoU-based NMS can be applied as a final cleanup.
