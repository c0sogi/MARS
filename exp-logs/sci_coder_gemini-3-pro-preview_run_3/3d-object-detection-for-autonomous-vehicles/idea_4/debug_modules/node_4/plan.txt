The issue is caused by the `GTDatabase` generating an empty list of objects (`db_infos`) when no valid ground truth samples are found (e.g., in the small demo subset). When `pd.DataFrame(db_infos)` is called with an empty list, pandas creates a DataFrame with no columns. Attempting to access `self.metadata["class_name"]` later raises a `KeyError`. To fix this, we must explicitly define the DataFrame columns when `db_infos` is empty, ensuring the schema is preserved even without data. This aligns with the principle of validating data structure integrity before processing, similar to the dimension checks in **Cite debug_lesson_4**.
