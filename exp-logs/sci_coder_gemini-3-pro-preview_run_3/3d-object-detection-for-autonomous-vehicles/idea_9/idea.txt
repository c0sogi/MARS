Based on the progression of experiments and the specific lessons learned, I propose a **Two-Stage PointPillars Detector with IoU-Aware Confidence Rectification**.

This strategy structurally evolves the successful "Idea 8" (Two-Stage PointPillars) by introducing a **Confidence Rectification Module** in the second stage. It addresses the limitation where high-confidence proposals from the first stage may still possess poor geometric fit (low IoU), and conversely, well-localized boxes might be suppressed due to lower classification scores. Furthermore, it re-introduces the critical data augmentation technique (GT Sampling) that was previously discarded, but wraps it in a strict validation protocol to prevent the coordinate failures observed in Lesson 00014.

# Model

The architecture retains the efficient PointPillars encoder and CenterHead proposal mechanism but fundamentally alters the second stage to predict detection *quality* alongside coordinates.

1.  **Encoder & Backbone (Retained):**
    *   We utilize the **PointPillars Encoder** to discretize the single-frame point cloud into a pseudo-image.
    *   We employ the **ResNet-FPN Backbone** established in Idea 8. This deep multi-scale representation is essential for capturing semantic context to resolve "L-shape" ambiguities **Cite solution_lesson_node_00005**.
2.  **Stage 1: Anchor-Free Proposal (Retained):**
    *   We use the **CenterHead** to generate class-agnostic object proposals via heatmap peak extraction. This avoids the optimization instability of anchor-based methods **Cite solution_lesson_node_00008**.
3.  **Stage 2: IoU-Aware Refinement (Structural Innovation):**
    *   **RoI Extraction:** We apply **Rotated RoI Align** to extract feature maps for each Stage 1 proposal **Cite solution_lesson_node_00018**.
    *   **Refinement Branch:** A lightweight MLP regresses residuals $(\delta x, \delta y, \delta z, \delta w, \delta l, \delta h, \delta \theta)$ to fine-tune the box.
    *   **Rectification Branch (New):** A parallel MLP branch predicts the **3D Intersection-over-Union (IoU)** between the refined box and the ground truth.
    *   **Purpose:** This branch learns to estimate the *geometric quality* of a detection. During inference, this predicted IoU is used to rectify the classification confidence ($Score_{final} = Score_{cls} \times IoU_{pred}^{\alpha}$), ensuring that the final ranking prioritizes boxes that are both semantically correct and geometrically precise.

# Data

We implement a rigorous data pipeline that balances the need for augmentation with the strict requirement for coordinate integrity.

1.  **Single-Sweep Processing:**
    *   We continue to use **only the current Lidar sweep** to guarantee coordinate consistency between input points and annotations, avoiding the multi-sweep misalignment failures **Cite solution_lesson_node_00014**.
2.  **Verified Ground Truth Sampling (Process Innovation):**
    *   We re-introduce **GT Database Sampling** (Copy-Paste augmentation) to address object sparsity.
    *   **Geometric Unit Test:** To prevent the "silent failure" observed in previous attempts **Cite solution_lesson_node_00014**, we implement a pre-training validation step. We will generate the GT Database and immediately verify that the cropped point clouds contain a non-zero number of points. If a database entry is empty (indicating frame misalignment), it is automatically discarded. This allows us to safely use augmentation.
3.  **Target Normalization:**
    *   We maintain **Log-Space Dimensions** for regression targets to prevents gradient explosion **Cite solution_lesson_node_00008**.

# Training

1.  **Loss Functions:**
    *   **Stage 1:** Gaussian Focal Loss (Heatmap) + Masked L1 Loss (Proposal Regression).
    *   **Stage 2 Refinement:** L1 Loss on box residuals.
    *   **Stage 2 Rectification:** **Binary Cross Entropy (BCE) Loss** applied to the IoU branch, where the target is the actual calculated IoU between the refined proposal and the matched ground truth box.
2.  **Optimizer:**
    *   **AdamW** with **One-Cycle Learning Rate Policy** to ensure stable convergence within the runtime limits.

# Evaluation

1.  **Inference:**
    *   **Step 1:** Generate proposals using the CenterHead.
    *   **Step 2:** Extract RoI features and pass them through the Stage 2 network.
    *   **Step 3:** Apply the predicted residuals to refine the boxes.
    *   **Step 4 (Rectification):** Multiply the Stage 1 classification score by the Stage 2 predicted IoU to obtain the **Rectified Confidence Score**.
    *   **Step 5:** Perform final Non-Maximum Suppression (NMS) using these rectified scores. This ensures that the boxes submitted for the mAP calculation are ranked by their true expected quality.
