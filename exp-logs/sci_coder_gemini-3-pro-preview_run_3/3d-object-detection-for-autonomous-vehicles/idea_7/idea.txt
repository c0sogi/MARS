Based on the analysis of previous failures and the specific insights from the provided lessons, I propose a **High-Resolution PointPillars with Feature Pyramid Network (FPN)**.

This strategy structurally evolves the "Current Best" baseline by replacing the shallow convolutional backbone with a deep, multi-scale **ResNet-FPN** architecture. It explicitly rejects the complex multi-sweep data pipeline that caused the failure in Idea 6, focusing instead on maximizing the semantic extraction from single-frame data to ensure geometric integrity.

### Model
The architecture retains the efficient PointPillars encoder but introduces a sophisticated 2D backbone to resolve the "L-shape" ambiguity and scale variation issues.

1.  **Pillar Feature Encoder (Retained):**
    *   We utilize the proven PointPillars voxelization strategy. The raw point cloud is discretized into vertical columns. A simplified PointNet aggregates points into a feature vector, forming a pseudo-image.
    *   **Innovation:** We will increase the grid resolution (e.g., reducing voxel size from $0.16m$ to $0.08m$). This preserves finer geometric details required for small objects like pedestrians, leveraging the learned proposal capability to handle occlusion **Cite solution_lesson_node_00005**.
2.  **ResNet Backbone with FPN (Structural Innovation):**
    *   Instead of the standard, shallow VGG-like blocks used in previous PointPillars attempts, we implement a **ResNet-18** backbone. This provides deep residual learning to capture complex semantic cues (e.g., inferring a car from just a rear bumper).
    *   We attach a **Feature Pyramid Network (FPN)** to the ResNet output. The FPN fuses high-resolution features from early layers (good for localization) with high-semantic features from deep layers (good for classification). This multi-scale representation is critical for simultaneously detecting large objects (buses) and small objects (pedestrians), addressing the limitations of single-scale architectures.
3.  **Anchor-Free Center Head (Retained & Stabilized):**
    *   We employ the **Center-Based Detection Head** proposed in Idea 5.
    *   **Heatmap Branch:** Predicts object centers as continuous Gaussian peaks.
    *   **Regression Branch:** Predicts log-dimensions, offsets, and rotation.
    *   This design avoids the optimization instability of anchor matching **Cite solution_lesson_node_00008** and decouples the localization task from the regression task.

### Data
The data pipeline is simplified to strictly enforce coordinate consistency, prioritizing data integrity over data quantity.

1.  **Single-Sweep Processing:**
    *   We will use **only the current Lidar sweep**. We explicitly discard the multi-sweep temporal aggregation and Ground Truth Database Sampling proposed in Idea 6.
    *   **Rationale:** Lesson 00014 proved that complex coordinate transformations (Global $\to$ Ego $\to$ Sensor) are error-prone and can lead to silent failures (empty targets). By using raw, single-frame data, we guarantee that the input points and ground truth boxes are in the same coordinate frame **Cite solution_lesson_node_00014**.
2.  **Target Normalization:**
    *   **Log-Space Dimensions:** Ground truth dimensions $(l, w, h)$ are log-transformed ($\log(x)$) to compress dynamic range.
    *   **Offset Normalization:** Regression offsets are normalized by the voxel stride.
    *   This strict normalization prevents the exploding gradients observed in Idea 4 **Cite solution_lesson_node_00008**.
3.  **Safe Augmentation:**
    *   We apply **Global Rotation**, **Scaling**, and **Flipping** to the single frame. These operations are mathematically simple and do not require cross-frame alignment, preserving geometric consistency.

### Training
1.  **Loss Functions:**
    *   **Gaussian Focal Loss:** For the heatmap branch, down-weighting easy background samples.
    *   **L1 Loss:** For regression branches, calculated **only at ground truth center locations**. This masking is crucial to prevent the network from trying to regress shapes in empty space **Cite solution_lesson_node_00008**.
2.  **Optimizer:**
    *   **AdamW** with a **One-Cycle Learning Rate Policy**. The warm-up phase ensures stable gradient descent onset, preventing divergence in the early epochs.

### Evaluation
1.  **Inference:**
    *   The test point cloud is voxelized and passed through the ResNet-FPN backbone.
    *   The Center Head outputs a heatmap and regression maps.
    *   A $3 \times 3$ Max Pooling operation extracts local peaks from the heatmap as object candidates.
2.  **Decoding:**
    *   Regression values at peak locations are extracted. Log-dimensions are exponentiated, and offsets are added to grid coordinates to reconstruct the 3D bounding boxes.
    *   This process relies purely on the learned heatmap for object presence, avoiding the pitfalls of geometric clustering **Cite solution_lesson_node_00005**.
