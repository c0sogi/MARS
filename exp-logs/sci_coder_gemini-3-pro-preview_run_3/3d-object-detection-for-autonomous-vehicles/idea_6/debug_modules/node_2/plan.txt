The issue is that the `TemporalPointPillars` model attempts to infer the `batch_size` from the `coordinates` tensor using `.max()`. When the input data is sparse or heavily filtered (as in the demo run), the `coordinates` tensor can be empty, causing a `RuntimeError` because `.max()` is undefined for empty tensors. This is a robustness issue when handling edge cases with empty data (Cite debug_lesson_6).

To fix this, I will modify the `forward` method in `library/model.py` to accept an explicit `batch_size` argument, falling back to inference only if necessary and handling the empty tensor case safely. I will then update `library/trainer.py`, `library/inference.py`, and `runfile.py` to pass the known batch size (derived from the batch metadata) to the model.
