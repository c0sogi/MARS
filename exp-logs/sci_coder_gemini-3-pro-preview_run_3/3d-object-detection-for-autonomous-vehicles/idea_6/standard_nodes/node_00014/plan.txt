The issue is that the Ground Truth Database generation fails to find any points inside the bounding boxes because of a coordinate system mismatch. The Lidar points are in the **Sensor Frame** (relative to the ego vehicle), while the `train.csv` annotations are in the **Global Frame**. Comparing them directly results in zero matches, an empty database, and subsequently a `KeyError: 'class_name'` when the dataset tries to access the empty database.

To fix this, I will modify `library/utils.py` to:
1.  Implement a helper `_get_transform_matrix` to handle coordinate transformations.
2.  Update `create_gt_database` to load the necessary NuScenes metadata (`sample_data`, `ego_pose`, `calibrated_sensor`) and calculate the Global-to-Sensor transformation matrix for each sample.
3.  Transform the Ground Truth bounding boxes from Global Frame to Sensor Frame before performing the point-in-box check.
4.  Add logic to invalidate/regenerate the cache if it is found to be empty or invalid (Cite debug_lesson_1, debug_lesson_5).
5.  Explicitly define DataFrame columns to prevent `KeyError` even if the database ends up empty.

def _get_transform_matrix(translation, rotation):
    """
    Convert translation list and rotation quaternion to 4x4 homogenous matrix.
    Rotation is [w, x, y, z].
    """
    w, x, y, z = rotation
    # Rotation matrix from quaternion
    R = np.array(
        [
            [1 - 2 * y**2 - 2 * z**2, 2 * x * y - 2 * z * w, 2 * x * z + 2 * y * w],
            [2 * x * y + 2 * z * w, 1 - 2 * x**2 - 2 * z**2, 2 * y * z - 2 * x * w],
            [2 * x * z - 2 * y * w, 2 * y * z + 2 * x * w, 1 - 2 * x**2 - 2 * y**2],
        ]
    )
    T = np.array(translation)

    M = np.eye(4)
    M[:3, :3] = R
    M[:3, 3] = T
    return M
