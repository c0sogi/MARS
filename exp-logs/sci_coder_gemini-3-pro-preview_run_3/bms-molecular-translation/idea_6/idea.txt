Based on the analysis of the task, dataset, and previous ideas, I propose the following highly efficient baseline approach.

### Proposed Solution: Multi-Task Formula-Conditioned CNN-GRU

This approach synthesizes the global compression efficiency of the "Show and Tell" framework (Idea 1) with the explicit domain guidance of the Hybrid architecture (Model 5). Instead of using complex attention mechanisms (Idea 4) or separate tree-based regressors (Model 5), this model integrates a lightweight **molecular formula predictor** directly into the end-to-end neural network. By explicitly training the model to count atoms (C, H, N, O, etc.) alongside generating the sequence, we provide the decoder with a strong "stoichiometric budget" to guide the generation of the InChI string, addressing a common baseline failure mode where models hallucinate or drop atoms.

#### Model
*   **Encoder (CNN Backbone):** Utilize **ResNet-34** (pre-trained on ImageNet). This backbone offers a superior balance of feature extraction capability and throughput compared to smaller MobileNets or larger EfficientNets.
    *   **Global Compression:** Apply **Global Average Pooling** to the final feature map to produce a single fixed-length visual context vector. This ensures maximum inference speed by eliminating the need to process spatial grids during decoding.
*   **Auxiliary Head (Formula Predictor):** A simple Multi-Layer Perceptron (MLP) branch takes the visual context vector and predicts a vector of **atom counts** (e.g., number of Carbon, Hydrogen, Nitrogen, Oxygen, etc. atoms). This acts as a differentiable "formula estimator."
*   **Decoder (RNN):** Use a **GRU (Gated Recurrent Unit)** for sequence generation.
    *   **Conditioning:** The predicted atom count vector from the Auxiliary Head is concatenated with the visual context vector. This combined representation is used to **initialize the hidden state** of the GRU.
    *   **Input:** At each decoding step, the GRU receives the embedding of the previously generated character.
    *   **Output:** A linear classification layer maps the GRU state to the vocabulary probability distribution.

#### Data
*   **Preprocessing:**
    *   **Images:** Resize all images to a fixed resolution of **256 $\times$ 256**. This resolution is sufficient to capture molecular connectivity while maximizing batch size and training speed. Normalize pixel values to the $[0, 1]$ range.
    *   **Text:** Tokenize the InChI strings into character sequences with `<SOS>` and `<EOS>` tokens.
    *   **Auxiliary Labels:** During the preprocessing phase, parse the ground truth InChI strings to extract the **molecular formula** (the layer starting with `1S/`). Convert this formula into a normalized numerical vector representing the counts of the top $K$ most frequent elements (e.g., C, H, N, O, S, F, Cl, Br, I) plus a "length" target.
*   **Augmentation:** No augmentation will be applied to ensure a stable, deterministic, and fast baseline.

#### Training
*   **Loss Function:** Implement a **Multi-Task Loss**: $L_{total} = L_{CE} + \lambda L_{MSE}$.
    *   $L_{CE}$: Standard Cross-Entropy loss for the character sequence generation.
    *   $L_{MSE}$: Mean Squared Error loss between the predicted atom counts and the ground truth counts derived from the InChI string.
    *   $\lambda$: A weighting factor (e.g., 0.5) to balance the two tasks.
*   **Optimizer:** Use **AdamW** with a standard learning rate and weight decay.
*   **Strategy:** Use **Teacher Forcing** (feeding ground truth characters) for the sequence decoder to ensure rapid convergence. The auxiliary head provides gradients that help the CNN learn to "count" atoms early in training, stabilizing the visual features.

#### Evaluation
*   **Inference Process:**
    *   Pass the test image through the ResNet encoder to obtain the visual vector.
    *   Pass the visual vector through the Auxiliary Head to predict the atom counts.
    *   Concatenate the visual vector and predicted counts to initialize the GRU decoder.
    *   **Greedy Decoding:** Feed the `<SOS>` token. At each step, select the character with the highest probability, append it to the sequence, and feed it as input to the next step.
    *   Terminate when `<EOS>` is predicted or a maximum length is reached.
