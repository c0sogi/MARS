To demonstrate the usage of the provided library files for the Hotel Identification task, I will implement a script that overrides the default configuration to run in a fast "Debug" mode. This allows us to verify the entire pipeline—data loading, model architecture, training loop, and inference—within a short timeframe using a small subset of the data.

### Implementation Strategy
1.  **Environment Setup**: Import necessary libraries and the provided modules (`Config`, `utils`, `dataset`, `model`, `engine`).
2.  **Configuration Override**: Dynamically modify `Config` attributes (enable `DEBUG`, reduce `NUM_EPOCHS`, `BATCH_SIZE`) to ensure the script runs quickly and efficiently within the time limits.
3.  **Data Pipeline Verification**: Manually invoke `get_dataloaders` to verify that data can be loaded, transformed, and batched correctly. Assert shapes of images and labels.
4.  **Model Verification**: Instantiate the `HotelRecognitionModel`, perform a forward pass with and without labels to verify the architecture (Backbone -> Pooling -> Neck -> ArcFace) and output shapes.
5.  **Training Integration**: Execute `engine.train_model()` to demonstrate the training loop, loss calculation, and model checkpointing.
6.  **Inference Integration**: Execute `engine.generate_submission()` to demonstrate loading the trained model, generating embeddings, performing retrieval (cosine similarity), and formatting the submission file.
7.  **Validation**: Use assertions to ensure all outputs (files, tensor shapes) meet expectations.
