The issue is that the variable tracking the best validation metric (`best_map5`) is initialized to `0.0`, which is the minimum possible value for the MAP@5 metric. The logic to save the model relies on a strict inequality (`val_map5 > best_map5`). In the failing run, the model achieved a MAP@5 of exactly `0.0`, causing the check `0.0 > 0.0` to evaluate to `False`. Consequently, the model checkpoint was never saved, causing the subsequent assertion in `runfile.py` to fail.

To fix this, I will initialize `best_map5` to `-1.0` in `library/train.py`. This ensures that the first validation result, even if it is `0.0`, will be considered an improvement (`0.0 > -1.0`), triggering the model save logic. This applies the guidance from **Cite debug_lesson_1**.
