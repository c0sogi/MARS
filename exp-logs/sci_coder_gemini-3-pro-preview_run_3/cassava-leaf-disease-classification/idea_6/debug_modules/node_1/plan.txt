The issue is caused by a configuration mismatch between the demo script (`runfile.py`) and the model initialization in `library/model.py`. The `runfile.py` script overrides `Config.IMG_SIZE` to 128 for a fast demo run, but the `DualStreamModel` initializes the ViT backbone (`vit_base_patch16_384`) using only its name. By default, this specific ViT model expects a fixed input resolution of 384x384. When the model receives the 128x128 dummy input for dimension inference, it raises an assertion error because the input size does not match the model's expected size.

To fix this, we need to explicitly pass the `img_size` argument to `timm.create_model` when initializing the ViT backbone. This tells the `timm` library to adapt the model (e.g., by interpolating position embeddings) to the resolution defined in the configuration, ensuring it works with both the default 384x384 and the demo's 128x128.
