### Strategy: Parallel TCN-LSTM with Direct Physics Injection

Building on the successes of the simple physics-based models and the failures of the engineering pipelines, I propose a **Parallel TCN-LSTM Hybrid** architecture. This strategy structurally separates the modeling of high-frequency dynamics (valve changes, flow rates) from low-frequency state accumulation (lung volume), while enforcing strict pipeline integrity to avoid previous silent failures.

#### 1. Model: Parallel TCN-LSTM Hybrid
This architecture moves away from the strictly sequential "Stack" (CNN then LSTM) to a **Parallel Branch** design. This allows the model to process the signal in two distinct ways simultaneously, mirroring the physical components of the Equation of Motion ($P = \frac{V}{C} + R \cdot \dot{V}$), before fusing them for the final prediction.

*   **Branch 1: The "Fast" Path (Dilated TCN)**
    *   **Structure:** A Temporal Convolutional Network (TCN) consisting of stacked 1D Residual Blocks with dilated convolutions.
    *   **Purpose:** This branch focuses on **local dynamics and derivatives**. It efficiently models the "Resistive" pressure component ($R \cdot \dot{V}$), which depends on instantaneous flow and rapid valve changes. The residual connections allow it to act as a learnable finite-difference operator, capturing the "Derivative" component of the PID state. **Cite Lesson 3**.
*   **Branch 2: The "Slow" Path (Bidirectional LSTM)**
    *   **Structure:** A deep Bidirectional LSTM (3 layers).
    *   **Purpose:** This branch focuses on **global integration and memory**. It models the "Elastic" pressure component ($\frac{V}{C}$), which depends on the cumulative volume of air in the lung over the entire breath. This retains the successful sequential modeling capability of the LSTM. **Cite Lesson 3**.
*   **Fusion with Direct Physics Injection:**
    *   The outputs of Branch 1 and Branch 2 are concatenated.
    *   **Crucial Addition:** The original engineered physics features (R, C, u_in, Volume, etc.) are concatenated *again* directly to this fused representation. This "skip connection" ensures the final regression head has immediate access to the governing physical constants ($R, C$) without needing to extract them from the deep network's hidden state. This directly addresses the errors in high-restriction lungs observed in the baseline. **Cite Lesson 1**.
*   **Output Head:** A Dense MLP projects the combined vector to the scalar `pressure`.

#### 2. Data: Full PID State with Pipeline Integrity
We will employ a rigorous data pipeline to ensure the model actually receives the features we engineer, preventing the silent failures observed previously.

*   **Feature Engineering (The PID State):**
    *   **Integral:** Compute cumulative sum of `u_in` (Volume proxy). **Cite Lesson 1**.
    *   **Derivative:** Compute 1st and 2nd finite differences of `u_in` (Flow acceleration). **Cite Lesson 3**.
    *   **Interaction:** Pre-compute physical terms $R \cdot u_{in}$ and $Volume / C$. **Cite Lesson 1**.
*   **Pipeline Controls:**
    *   **Unified Configuration:** Define a single `FEATURE_CONFIG` list that controls both the dataframe column generation and the model input dimension. This guarantees synchronization between the engineering and modeling steps. **Cite Lesson 5**.
    *   **Cache Invalidation:** The script will explicitly delete any existing pre-processed `.npy` or `.pt` files in the working directory at the start of execution. This forces the pipeline to re-compute features from the raw CSVs, ensuring the new derivative features are actually used. **Cite Lesson 6**.

#### 3. Training: Metric-Aligned Optimization
*   **Loss Function:** **Masked L1 Loss (MAE)**. The loss will be calculated only where `u_out == 0` (inspiratory phase). This ensures the model dedicates its capacity solely to the scored portion of the breath, ignoring the complex expiratory dynamics. **Cite Lesson 1**.
*   **Optimizer & Scheduler:** Use AdamW combined with `ReduceLROnPlateau`. This allows the model to converge rapidly initially and then fine-tune the weights for the parallel branches as the loss levels off. **Cite Lesson 3**.

#### 4. Evaluation
*   The test set will be processed using the exact same `FEATURE_CONFIG` and pipeline.
*   Inference will be performed in batches, and the predictions will be flattened and joined with `id` for submission.
