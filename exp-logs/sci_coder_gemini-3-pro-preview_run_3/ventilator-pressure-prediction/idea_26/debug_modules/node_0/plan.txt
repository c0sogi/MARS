### Implementation Strategy

1.  **Data Subsetting**: To ensure the code runs quickly (within seconds), I will create small subsets of the provided metadata CSVs (e.g., 50 breaths for training, 10 for validation/test) and save them to a temporary directory.
2.  **Configuration Injection**: I will dynamically modify the `Config` class attributes at runtime. This allows me to redirect the library to use the subset data, reduce the batch size (to accommodate the small dataset), minimize the model architecture (fewer layers/filters), and set the epoch count to 1 for a quick integration test.
3.  **Component-Level Verification**:
    *   **Data Loading**: I will call `get_transformed_data` and assert that the resulting DataLoaders yield tensors of the correct shape `(Batch, 80, Features)`.
    *   **Model Forward Pass**: I will instantiate `DKRHNet` and pass a batch of data through it to verify the output shape `(Batch, 80)`.
    *   **Loss Calculation**: I will verify that `MaskedL1Loss` computes a valid scalar value.
4.  **Full Pipeline Execution**: I will call the `train_model()` driver function from `train_utils.py`. This serves as an end-to-end test, verifying the training loop, validation, model checkpointing, and submission file generation.
5.  **Cleanup**: Temporary directories created for the demo will be cleaned up (optional, but good practice; here I leave them for inspection if needed).
