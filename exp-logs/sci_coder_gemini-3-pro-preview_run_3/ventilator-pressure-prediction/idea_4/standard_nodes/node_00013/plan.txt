The issue stems from an incomplete cache validation check in `library/features.py`. The current implementation considers the training data cache valid if `train_x.npy` exists, but it fails to verify the existence of `scaler_stats.npz`. Since the validation and test data processing steps depend on `scaler_stats.npz` for feature normalization, a missing scaler file (even with existing training data arrays) causes a `FileNotFoundError` when the pipeline attempts to process the validation set.

To fix this, I will update `load_and_preprocess_data` in `library/features.py` to explicitly check for the existence of `Config.SCALER_PATH` when the split is "train". If the scaler statistics are missing, the cache will be marked as invalid, forcing a regeneration of the training data and the scaler statistics.
