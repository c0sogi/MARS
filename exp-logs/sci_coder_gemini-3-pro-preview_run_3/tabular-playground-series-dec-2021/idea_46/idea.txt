Based on the comprehensive analysis of the experimental history and the accumulated lessons, I propose the following optimized strategy.

This approach introduces an **Asymmetric Parallel Vector-DCN-ResNet with Inverted Bottleneck Backbone**.

This structural evolution addresses the **"Capacity vs. Stability"** paradox. Previous experiments established that **Capacity** (Depth/Width) is the primary performance driver (Cite Lesson 00054, 00029), but naive scaling leads to **Optimization Stagnation** (Depth=6, Cite Lesson 00073) or **Divergence** (Width=1024, Cite Lesson 00081).

This strategy implements the **Inverted Bottleneck Topology** (inspired by Transformer FFNs and ConvNeXt). By keeping the residual stream narrow (512) for stability while expanding the internal processing width (2048) for capacity, we decouple signal propagation from representation power. This is integrated with the **Asymmetric** (Cite Lesson 00071), **Warm-Start** (Cite Lesson 00066), and **Aggressive Optimization** (Cite Lesson 00068) protocols.

# Model: Asymmetric Parallel Vector-DCN-ResNet (Inverted Bottleneck)

I propose a hybrid architecture that processes inputs through two parallel branches.

1.  **Input Layer:** The model will accept a dense concatenated vector of standardized continuous features and **raw one-hot encoded** binary features. We explicitly reject entity embeddings, adhering to **Cite Lesson 00011**.
2.  **Branch 1: Asymmetric Vector-Based Deep & Cross Network (Warm-Start):**
    *   **Asymmetric Depth:** We will strictly limit this branch to **3 Cross Layers**, decoupling it from the deeper backbone to avoid high-order noise **Cite Lesson 00071**.
    *   **Mechanism:** We will use **Vector-based (Rank-1) Cross Layers** with **Dot-Product Mixing** ($x_{l+1} = x_0 \odot (x_l^T w) + b + x_l$) **Cite Lesson 00032**.
    *   **Warm-Start Initialization:** We will initialize the learnable weight vectors $w$ with a **Near-Zero Standard Deviation** (e.g., $\mathcal{N}(0, 10^{-4})$). This ensures the branch starts as an approximate identity mapping, preventing early multiplicative noise from destabilizing the backbone **Cite Lesson 00066**.
3.  **Branch 2: Deep Inverted Bottleneck ResNet Backbone (Structural Innovation):**
    *   **Topology:** We will replace the standard Basic Block with an **Inverted Bottleneck Block**.
        *   **Structure:** `Input -> BN -> Linear(512 -> 2048) -> ReLU -> Dropout -> Linear(2048 -> 512) -> Add(Input)`.
        *   **Reasoning:** This topology provides a **4x increase in representational capacity** (Internal Width 2048) to capture complex non-linearities (**Cite Lesson 00054**), while maintaining a **stable residual stream** (IO Width 512) to prevent the gradient instability observed in globally wide models (**Cite Lesson 00081**). It satisfies the requirement for two learnable layers per block (**Cite Lesson 00064**).
    *   **Projection Initialization:** We will initialize the weights of the second linear layer (projection back to 512) with **Near-Zero Standard Deviation** (e.g., $10^{-4}$). This ensures the massive internal expansion starts as a silent contribution, allowing the network to train as a shallow identity function initially before gradually utilizing the extra capacity.
    *   **Depth:** We will maintain a depth of **4 Blocks**, which is proven stable **Cite Lesson 00031**.
4.  **Combination Head:** The outputs of both branches will be concatenated and passed through a final linear classification layer.

# Data: Augmented Physics-Informed Engineering

We will employ a feature engineering paradigm that prioritizes physical consistency and **Augmentation over Replacement**.

1.  **Cyclical Augmentation:** We will calculate `Aspect_Sin` and `Aspect_Cos` but **retain the raw `Aspect` column**. **Cite Lesson 00034** demonstrated that replacing the raw value destroys the direct magnitude signal utilized by ReLU networks.
2.  **Geometric Magnitude:** We will explicitly calculate the **Euclidean Distance to Hydrology** ($\sqrt{\text{Horizontal}^2 + \text{Vertical}^2}$) **Cite Lesson 00016**.
3.  **Directional Preservation:** We will calculate **Absolute Hydrology Elevation** (`Elevation - Vertical_Distance`) to preserve water flow directionality **Cite Lesson 00019**.
4.  **Global Context:** We will include **Mean Distance to Amenities** (Hydrology, Roadways, Fire Points) **Cite Lesson 00009**.
5.  **Preprocessing:** Continuous features will be standardized (zero mean, unit variance). Binary features will remain as 0/1 integers. We reject unsupervised clustering features **Cite Lesson 00089**.

# Training: Decoupled Regularization & Aggressive Scheduling

The training pipeline is designed to correct specific optimizer and scheduler failures identified in previous experiments.

1.  **Optimizer:** We will strictly use **AdamW** (Decoupled Weight Decay) to regularize the increased parameter count **Cite Lesson 00058**.
2.  **Scheduler:** We will employ a **ReduceLROnPlateau** scheduler with an **aggressive decay factor of 0.1**. **Cite Lesson 00068** demonstrated that aggressive decay is required to freeze the model into a sharp minimum.
3.  **Regularization:** We will maintain a **Dropout rate of 0.2** within the blocks **Cite Lesson 00056**.
4.  **Budgeting:** We will use a batch size of **4096** and strictly set the training duration to **60 Epochs** **Cite Lesson 00022**.
5.  **System:** We will **disable strict CuDNN determinism** (`cudnn.deterministic = False`) to maximize kernel performance **Cite Lesson 00070**.
6.  **Checkpointing:** We will implement Early Stopping with a callback that uses `copy.deepcopy(model.state_dict())` **Cite Lesson 00003**.
7.  **Dataset:** The model will be trained on the **full labeled training set**, rejecting subsampling **Cite Lesson 00021**.

# Evaluation

1.  **Inference:** The test set will be processed in batches using the best-checkpointed model weights (restored via the deepcopy mechanism).
2.  **Prediction:** The class with the highest softmax probability will be selected for each `Id`, and the results will be formatted into the required CSV submission file.
