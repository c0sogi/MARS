The strategy for this implementation focuses on balancing the "fast baseline" requirement with the high performance threshold (>96.25%) needed for submission.

1.  **Orchestration**: We will use the provided `train_utils.run_training` function as the core driver.
2.  **Data & Training**: To ensure we meet the accuracy threshold, we must use the **full dataset** (`max_train_samples=None`) rather than a subset. To keep the runtime "fast", we will limit the training to **25 epochs** (instead of the default 60). This provides a sufficient number of gradient updates on the A100 GPU to converge without running for the full duration.
3.  **Validation**: We will explicitly load the validation set using `data_utils.process_data` to compute the `Final Validation Metric` with full precision as required.
4.  **Failure Analysis**: We will perform a custom inference pass on the validation set to calculate the Point-Biserial correlation between input features and the error vector (misclassifications). This identifies which features are most strongly associated with model failure.
5.  **Submission Control**: Since `run_training` automatically generates a submission, we will add a post-processing step to check the validation metric against the threshold (`0.9625222222222222`). If the metric is insufficient, we will delete the submission file to strictly adhere to the "if and only if" requirement.
