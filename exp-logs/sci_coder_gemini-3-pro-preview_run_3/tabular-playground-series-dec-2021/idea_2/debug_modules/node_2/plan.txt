The issue is a configuration mismatch between the model saved in the verification script (`runfile.py`) and the model initialized for inference (`library/inference.py`). The verification script creates a model with `num_blocks=2` and `hidden_dim=128`, but the inference function hardcodes these values to `3` and `256` respectively, causing a `RuntimeError` when loading weights due to shape mismatches.

To fix this, I will update `library/inference.py` to accept `num_blocks` and `hidden_dim` as arguments in `generate_submission`, allowing dynamic configuration. I will then update `runfile.py` to pass the correct hyperparameters (`num_blocks=2`, `hidden_dim=128`) during the inference verification step. This ensures pipeline consistency between the training/saving and inference/loading stages (Cite debug_lesson_2).
