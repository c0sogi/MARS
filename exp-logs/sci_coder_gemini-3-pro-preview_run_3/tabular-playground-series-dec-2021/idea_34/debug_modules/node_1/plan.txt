The `RuntimeError` occurs because the `test_training_loop` function trains the model in memory but fails to save the updated state dictionary to `Config.MODEL_PATH`. Consequently, when `main()` later attempts to load weights from this path, it reads a stale file from a previous execution (likely generated with different hyperparameters/architecture), causing a key mismatch. This is a classic instance of "Zombie Behavior" where the code interacts with persistent artifacts from a previous state (Cite debug_lesson_9). To fix this, we must explicitly save the model to disk immediately after training within the `test_training_loop`, ensuring the file matches the current model architecture (Cite debug_lesson_3).
