The implementation strategy involves creating a lightweight demonstration pipeline that validates the functionality of the provided library components while adhering to the speed and correctness requirements.

1.  **Data Subsetting for Speed**: Instead of processing the full 3.6 million row dataset, the script will first read a small subset (e.g., 2000 rows) of the provided Parquet metadata files and save them as temporary "mini" datasets in the working directory.
2.  **Configuration Override**: The `Config` class attributes will be dynamically modified to point to these mini datasets, use a separate cache directory, and reduce training intensity (fewer epochs, smaller batch size, smaller model width) to ensure the script completes in seconds.
3.  **Component Execution & Verification**:
    *   **Data Loading**: Call `get_dataloaders` and assert that the returned PyTorch DataLoaders produce batches of the correct shape and data types.
    *   **Model Initialization**: Instantiate the `ParallelLowRankDCNResNet` model and perform a dummy forward pass to verify input-output tensor shapes.
    *   **Training Loop**: Execute `run_training` (which utilizes `train_one_epoch` and `validate`) for a minimal number of epochs to verify the training logic and early stopping mechanism.
    *   **Inference**: Run `predict_and_submit` to generate predictions on the mini test set and verify that the submission CSV is created with the correct format and length.

This approach ensures all provided logic (`data_utils`, `model_utils`, `train_utils`) is exercised and verified without the computational overhead of the full dataset.
