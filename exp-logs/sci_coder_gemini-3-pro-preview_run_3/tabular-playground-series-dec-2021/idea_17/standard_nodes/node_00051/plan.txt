The implementation strategy focuses on orchestrating a high-performance training pipeline while adhering to the strict time and format constraints.

1.  **Environment & Setup**: The script initializes the environment by importing necessary library modules and setting a global random seed for reproducibility. It detects the available device (A100 GPU) to ensure efficient computation.
2.  **Training Phase**: We invoke `library.train.run_training` with `debug=False` and the default `EPOCHS=60`. We utilize the full dataset rather than a subset because the target validation metric (>0.9625) is high and requires maximum data utilization. The A100 GPU is sufficiently powerful to process the 2.8M row tabular dataset within the 2-hour limit.
3.  **Validation & Metric Reporting**: Post-training, we reload the validation dataset using `library.data_loader.get_dataloaders`. We run inference in evaluation mode (`model.eval()`) without gradient computation to calculate the final validation accuracy. This metric is printed in the exact required format: `Final Validation Metric: <value>`.
4.  **Failure Analysis**: We perform a systematic failure analysis on the validation set. We calculate the "Error Magnitude" for each sample defined as $1.0 - P(\text{True Class})$. We then compute the Pearson correlation coefficient between this error vector and each input feature. This identifies which features are most strongly associated with model failure. Feature names are reconstructed to provide interpretable output.
5.  **Conditional Submission**: Finally, we compare the calculated validation accuracy against the threshold (0.9625041666666667). If the model passes this check, we generate predictions for the test set and save them to `./submission/submission.csv`.
