### Implementation Strategy

1.  **Configuration Override**: Since the goal is a quick demonstration, we will dynamically modify the `Config` class attributes at runtime. We will set `DEBUG_SAMPLES` to a small number (e.g., 50) and reduce the number of epochs to ensure the entire pipeline runs in under a few minutes.
2.  **Utility Verification**: We will start by verifying the core utility functions (`rle_encode`, `rle_decode`, `do_kaggle_metric`) using synthetic numpy arrays to ensure the metric calculation and submission format logic are correct.
3.  **Data Pipeline Check**: We will initialize the data loaders using `get_dataloaders` in debug mode. We will iterate through one batch to verify input shapes (checking for the 3-channel input: Seismic-Seismic-Depth) and mask integrity.
4.  **Model & Loss Verification**: We will instantiate the `SaltUNetPlusPlus` model and perform a forward pass with dummy data to verify the output shapes for both "Deep Supervision" mode (Phase 1) and standard mode (Phase 2). We will also compute loss values using `BCEDiceLoss` and `LovaszHingeLoss` to ensure gradients can be calculated.
5.  **Training Loop Simulation**: We will use the `SaltEngine` to run a minimal training loop:
    *   One epoch representing Phase 1 (Structural Warm-up).
    *   One validation pass.
    *   One epoch representing Phase 2 (Metric Fine-tuning).
6.  **Inference & Submission**: We will generate predictions on the test set, apply the Run-Length Encoding, and save the result to a CSV file, verifying the file structure at the end.
