The previous implementation generated a malformed CSV submission file. It used commas to separate predicted gesture IDs (e.g., `Sample001,1,2,3`), creating variable column counts per row ("ragged CSV"), which caused the grading system to fail with a tokenization error. Additionally, it used the raw string filename (e.g., `Sample00300`) as the identifier instead of the required integer format (e.g., `300`).

To fix this, I will modify `library/predict.py` and `library/train.py` to:
1.  Use spaces instead of commas to join the predicted sequence, ensuring the CSV has exactly two columns (`Id` and `Sequence`). Cite `debug_lesson_1`.
2.  Sanitize the `sample_id` by extracting the numeric digits to conform to the integer ID requirement. Cite `debug_lesson_5`.
3.  Add the required `Id,Sequence` header to the submission file.
