Based on the rigorous analysis of the "Lessons Learned" and the progression of "Previous Ideas," I propose the **Root-Centric Moderate-Capacity Network (RC-MCN)**.

This solution represents a structural synthesis that explicitly resolves the **"Input Engineering Trilemma"** (Magnitude vs. Hierarchy vs. Saturation) and the **Capacity-Stability Trade-off**. It replaces the failed complex gating and normalization strategies with a **Deterministic Root-Centric Alignment** and optimizes the encoder capacity to the "Goldilocks" zone identified in the lessons. It is underpinned by the mandatory **Polymorphic Data Ingestion** (Cite solution_lesson_node_00045) and **Physically Consistent Inference** (Cite solution_lesson_node_00071).

# Model
The architecture is a **Three-Stage Cascaded Network** designed for geometric invariance, optimal capacity, and temporal stability.

1.  **Stage 1: Root-Centric Moderate-Capacity Encoder**
    *   **Input:** An **Early Fusion** vector consisting of two streams:
        *   **Skeleton Stream:** Kinematically Consistent features (Position, Velocity, Acceleration). **Structural Innovation:** We apply **Root-Relative Centering** (subtracting the Hip Center coordinates from all joints) while keeping the units in **Raw Millimeters**.
            *   *Rationale:* This ensures **Translation Invariance** (users can stand anywhere) using a strictly linear transformation, avoiding the geometric distortion of non-linear scalings (Cite solution_lesson_node_00102). Retaining raw millimeters (~1000) preserves the natural **Signal-to-Noise Hierarchy** (Position $\gg$ Acceleration) and ensures the robust skeletal signal dominates the auxiliary audio signal during early training, preventing the "Audio Dominance" failure (Cite solution_lesson_node_00082, solution_lesson_node_00085).
        *   **Audio Stream:** MFCC features.
        *   **Fusion:** Concatenation.
    *   **Backbone:** A **Bi-directional GRU (Bi-GRU)** with a hidden dimension of **96 units per direction** (192 total).
        *   *Rationale:* This capacity is strictly calibrated. It avoids the information bottleneck of lightweight (64-unit) encoders (Cite solution_lesson_node_00066) while preventing the instability and overfitting observed in high-capacity (256-unit) encoders on this small dataset (Cite solution_lesson_node_00110).
    *   **Regularization:** We apply **Dropout (p=0.4)** to the encoder outputs. This is mandatory to prevent overfitting given the moderate capacity (Cite solution_lesson_node_00091).
    *   **No Over-Engineering:** We explicitly **remove** Input Gating and Batch Normalization layers, as these introduced optimization overhead and slowed convergence in previous attempts (Cite solution_lesson_node_00104).
    *   **Output:** Initial frame-wise class probabilities ($P_1$) over 21 classes (Softmax).

2.  **Stage 2: Monotonic Non-Causal Refinement**
    *   **Input:** Strictly the **class probabilities** ($P_1$) from Stage 1. We enforce a strict Information Bottleneck (Cite solution_lesson_node_00020).
    *   **Architecture:** A stack of **Gated Dilated Temporal Convolutional Layers** ($\tanh \times \sigma$) using **Standard Convolutions** (Cite solution_lesson_node_00065).
    *   **Dilation Schedule:** **Monotonically Increasing** $[1, 2, 4, 8, 16]$.
        *   *Rationale:* This schedule yields a receptive field of 63 frames, fitting perfectly within the 64-frame training window ($63 < 64$). This maximizes context without reading invalid zero-padding, correcting the edge artifacts observed in previous attempts (Cite solution_lesson_node_00057, solution_lesson_node_00080).
    *   **Causality:** **Centered Padding** (Non-Causal) to leverage future context, correcting the failure of Causal TCNs in offline settings (Cite solution_lesson_node_00078).
    *   **Regularization:** **Dropout (p=0.2)** after every block (Cite solution_lesson_node_00091).
    *   **Output:** Refined class probabilities ($P_2$).

3.  **Stage 3: Independent Iterative Refinement**
    *   **Structure:** Identical to Stage 2 but with **independent weights**. We strictly avoid recursive weight sharing to allow the stage to specialize in fine-grained boundary polishing (Cite solution_lesson_node_00054).
    *   **Output:** Final class probabilities ($P_3$).

# Data
The data pipeline incorporates critical engineering fixes for robustness and strict physical consistency.

1.  **Robust Polymorphic Parsing (Structural Requirement):**
    *   The data loader implements a **Polymorphic Parser** for the `.mat` files. It explicitly checks the data type of the `Skeleton` field (struct array vs. cell array vs. primitive) and handles each case dynamically. This prevents the "silent failure" (zero-filling) that crippled previous attempts (Cite solution_lesson_node_00045).

2.  **Kinematically Consistent Augmentation:**
    *   **Load:** Raw 3D Joint Positions ($P_{raw}$).
    *   **Center:** Apply **Root-Relative Centering** ($P_{centered} = P_{raw} - P_{hip}$).
    *   **Augment:** Apply random 3D rotations (Y-axis) and scaling to $P_{centered}$.
    *   **Derive:** Calculate **Velocity** ($V_t$) and **Acceleration** ($A_t$) from the *augmented* positions. This ensures physical validity (Cite solution_lesson_node_00029).
    *   **Fusion:** Concatenate $P_{aug}$, $V_t$, $A_t$, and Audio MFCCs.

3.  **Sampling Strategy:**
    *   **Windowing:** Generate training samples using **Sliding Windows of 64 frames** (Cite solution_lesson_node_00017).
    *   **Stride:** Use a **Moderate Stride** (e.g., 32 frames) to avoid the overfitting caused by dense sampling (Cite solution_lesson_node_00053).

# Training
The training strategy prioritizes stability and smoothness using Deep Supervision.

1.  **Cascaded Loss Function:**
    *   $L_{total} = L(P_1) + L(P_2) + L(P_3)$ (Deep Supervision) (Cite solution_lesson_node_00025).
    *   **Weighted Cross-Entropy:** Applied with a weight of **0.2** for the "background" class (Cite solution_lesson_node_00010). We strictly avoid Focal Loss (Cite solution_lesson_node_00034).
    *   **Log-Space Smoothing Loss:** A Truncated MSE loss applied to the log-probabilities of adjacent frames for $P_2$ and $P_3$.
    *   **Calibration:** We use a **Low Weight** ($\lambda=0.15$) and **Low Threshold** (1.0). This prevents the under-segmentation observed when smoothing was too aggressive (Cite solution_lesson_node_00111, solution_lesson_node_00055).

2.  **Optimizer:**
    *   **Adam** optimizer with **Weight Decay** (L2) to prevent overfitting (Cite solution_lesson_node_00026, solution_lesson_node_00055).

# Evaluation
1.  **Inference:** **Full Sequence Inference**. We process validation/test sequences in a single pass (Batch Size=1) or using stateful windowing to preserve global temporal context, avoiding the fragmentation caused by independent sliding windows (Cite solution_lesson_node_00079).
2.  **Model Selection:** Select the best checkpoint based on **Levenshtein Distance** computed on full sequences (Cite solution_lesson_node_00052, solution_lesson_node_00075).
3.  **Decoding:**
    *   Apply `argmax` to the final probabilities ($P_3$).
    *   Perform **Run-Length Encoding (RLE)**.
    *   **Min Duration Filter:** Explicitly remove segments shorter than **5 frames**. This is a critical post-processing step to align the output with physical gesture constraints and prevent metric degradation (Cite solution_lesson_node_00071).
