The issue lies in how the `scipy.io.loadmat` result is accessed in `library/dataset.py`. The function `loadmat` returns a Python dictionary where keys are the MATLAB variable names, regardless of the `struct_as_record` setting. The original code incorrectly attempts to access the top-level variable `Video` as an attribute (`mat.Video`) using `hasattr`, which fails and causes the data loading to return `None` for all samples (Cite debug_lesson_2). The fix involves accessing `Video` using dictionary syntax (`mat["Video"]`) before accessing its nested attributes (like `Frames`).
