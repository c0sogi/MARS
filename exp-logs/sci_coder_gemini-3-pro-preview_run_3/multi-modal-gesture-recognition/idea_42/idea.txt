Based on the rigorous analysis of the "Lessons Learned" and the progression of "Previous Ideas," I propose the **Linearly-Scaled Moderate-Capacity Network (LSM-CN)**.

This solution is a structural synthesis that explicitly resolves the **"Input Engineering Trilemma"** (Magnitude vs. Hierarchy vs. Saturation) identified in Lessons 00082, 00085, and 00096. It replaces the failed manual normalization and complex gating strategies with a **Learnable Diagonal Scaling Interface**. It combines this with a **Moderate-Capacity Encoder** (balancing under/overfitting risks) and a **Monotonic Non-Causal Refinement** module, strictly adhering to the stability constraints established in the lessons.

# Model
The architecture is a **Three-Stage Cascaded Network** designed for numerical stability, optimal capacity, and temporal coherence.

1.  **Stage 1: Linearly-Scaled Moderate-Capacity Encoder**
    *   **Input:** An **Early Fusion** vector consisting of Audio MFCCs and **Raw** Kinematically Consistent Skeleton features (Position in mm, Velocity, Acceleration). We explicitly **retain Raw Features** to preserve the natural signal-to-noise hierarchy (Position $\gg$ Acceleration) (Cite solution_lesson_node_00085).
    *   **Structural Innovation (Learnable Diagonal Scaling):** Immediately upon input, the raw feature vector $X$ is passed through a **Learnable Diagonal Scaling Layer**: $Y = X \odot w$, where $w$ is a learnable parameter vector of the same size as $X$.
        *   *Rationale:* Unlike dense projections (which mix features) or Z-score normalization (which destroys hierarchy), this layer learns a specific scalar for each channel. It allows the model to automatically scale down Millimeters (~1000) and Audio (~100) to a common neural-compatible range (~1.0) via gradient descent, solving the **Magnitude Alignment** problem (Cite solution_lesson_node_00082) without inducing **Saturation** (Cite solution_lesson_node_00096).
    *   **Backbone:** A **Bi-directional GRU (Bi-GRU)** with a hidden dimension of **96 units per direction** (192 total).
        *   *Rationale:* This capacity is calibrated to the dataset size. It avoids the information bottleneck of lightweight (64-unit) encoders (Cite solution_lesson_node_00066) while preventing the instability and overfitting observed in high-capacity (256-unit) encoders (Cite solution_lesson_node_00110).
    *   **Regularization:** Standard **Dropout (p=0.3)** is applied to the encoder outputs (Cite solution_lesson_node_00091).
    *   **Output:** Initial frame-wise class probabilities ($P_1$) over 21 classes (Softmax).

2.  **Stage 2: Monotonic Non-Causal Refinement**
    *   **Input:** Strictly the **class probabilities** ($P_1$) from Stage 1. We enforce a strict Information Bottleneck (Cite solution_lesson_node_00020).
    *   **Architecture:** A stack of **Dilated Temporal Convolutional Layers** with Gated Activations ($\tanh \times \sigma$). We use **Standard Convolutions** (Cite solution_lesson_node_00065).
    *   **Dilation Schedule:** **Monotonically Increasing** $[1, 2, 4, 8, 16]$.
        *   *Rationale:* This schedule yields a receptive field of 63 frames, fitting perfectly within the 64-frame training window ($63 < 64$). This maximizes context without reading invalid zero-padding, correcting the edge artifacts observed in previous attempts (Cite solution_lesson_node_00057).
    *   **Causality:** **Centered Padding** (Non-Causal) to leverage future context, correcting the failure of Causal TCNs in offline settings (Cite solution_lesson_node_00078).
    *   **Output:** Refined class probabilities ($P_2$).

3.  **Stage 3: Independent Iterative Refinement**
    *   **Structure:** Identical to Stage 2 but with **independent weights**. We strictly avoid recursive weight sharing to allow the stage to specialize in fine-grained boundary polishing (Cite solution_lesson_node_00054).
    *   **Output:** Final class probabilities ($P_3$).

# Data
The data pipeline incorporates critical engineering fixes for robustness and strict physical consistency.

1.  **Robust Polymorphic Parsing (Structural Requirement):**
    *   The data loader implements a **Polymorphic Parser** for the `.mat` files. It explicitly checks the data type of the `Skeleton` field (struct array vs. cell array vs. primitive) and handles each case dynamically. This prevents the "silent failure" (zero-filling) that crippled previous attempts (Cite solution_lesson_node_00045).

2.  **Kinematically Consistent Augmentation:**
    *   **Load:** Raw 3D Joint Positions ($P_{raw}$).
    *   **Augment:** Apply random 3D rotations (Y-axis) and scaling to $P_{raw}$.
    *   **Derive:** Calculate **Velocity** ($V_t$) and **Acceleration** ($A_t$) from the *augmented* positions. This ensures physical validity (Cite solution_lesson_node_00029).
    *   **Fusion:** Concatenate $P_{aug}$, $V_t$, $A_t$, and Audio MFCCs.

3.  **Sampling Strategy:**
    *   **Windowing:** Generate training samples using **Sliding Windows of 64 frames** (Cite solution_lesson_node_00017).
    *   **Stride:** Use a **Moderate Stride** (e.g., 32 frames) to avoid the overfitting caused by dense sampling (Cite solution_lesson_node_00053).

# Training
The training strategy prioritizes stability and smoothness using Deep Supervision.

1.  **Cascaded Loss Function:**
    *   $L_{total} = L(P_1) + L(P_2) + L(P_3)$ (Deep Supervision) (Cite solution_lesson_node_00025).
    *   **Weighted Cross-Entropy:** Applied with a weight of **0.2** for the "background" class (Cite solution_lesson_node_00010). We strictly avoid Focal Loss (Cite solution_lesson_node_00034).
    *   **Log-Space Smoothing Loss:** A Truncated MSE loss applied to the log-probabilities of adjacent frames for $P_2$ and $P_3$.
    *   **Threshold:** We use a **Low Truncation Threshold** (e.g., 1.0) and low weight ($\lambda=0.15$) to strictly enforce smoothness without causing under-segmentation (Cite solution_lesson_node_00111, solution_lesson_node_00055).

2.  **Optimizer:**
    *   **Adam** optimizer with **Weight Decay** (L2) (Cite solution_lesson_node_00055, solution_lesson_node_00026).

# Evaluation
1.  **Inference:** **Full Sequence Inference**. We process validation/test sequences in a single pass (Batch Size=1) to preserve global temporal context, avoiding the fragmentation caused by sliding windows (Cite solution_lesson_node_00079).
2.  **Model Selection:** Select the best checkpoint based on **Levenshtein Distance** computed on full sequences (Cite solution_lesson_node_00052).
3.  **Decoding:**
    *   Apply `argmax` to the final probabilities ($P_3$).
    *   Perform **Run-Length Encoding (RLE)**.
    *   **Min Duration Filter:** Explicitly remove segments shorter than **5 frames**. This is a critical post-processing step to align the output with physical gesture constraints (Cite solution_lesson_node_00071).
