Based on the rigorous analysis of the "Lessons Learned" and the progression of "Previous Ideas," I propose the **Physically-Aligned Kinematic Refinement Network (PAK-RN)**.

This solution is a structural synthesis that explicitly resolves the **"Input Engineering Trilemma"** (Magnitude vs. Hierarchy vs. Saturation) identified in Lessons 00082, 00085, and 00096. Unlike previous attempts that failed due to over-engineering (Input Gating, Learnable Norms) or improper scaling (Raw mm, Global Z-Score), the PAK-RN implements a **Deterministic Physical Alignment** strategy. It combines this with a **Moderate-Capacity Encoder** and **Full-Sequence Inference**, strictly adhering to the stability constraints established in the lessons.

# Model
The architecture is a **Three-Stage Cascaded Network** designed for mathematical consistency and temporal stability.

1.  **Stage 1: Physically-Aligned Kinematic Encoder**
    *   **Input:** An **Early Fusion** vector.
        *   **Skeleton Stream:** Kinematically Consistent features (Position, Velocity, Acceleration). **Structural Innovation:** We apply **Deterministic Physical Scaling** by converting units from millimeters to meters (multiply by 0.001).
            *   *Rationale:* This brings Position values to $\sim 1.0$, aligning them with the magnitude of normalized Audio features (Cite solution_lesson_node_00082). Crucially, unlike Z-Score normalization, this linear scaling strictly preserves the **Signal-to-Noise Hierarchy** (Position $\gg$ Velocity $\gg$ Acceleration) required for the model to filter high-frequency noise (Cite solution_lesson_node_00085).
        *   **Audio Stream:** MFCC features standardized (zero mean, unit variance).
        *   **Fusion:** Concatenation.
    *   **Backbone:** A **Bi-directional GRU (Bi-GRU)** with a hidden dimension of **96 units per direction** (192 total).
        *   *Rationale:* This represents a "Goldilocks" capacity. It avoids the information bottleneck of lightweight (64-unit) encoders (Cite solution_lesson_node_00066) while preventing the overfitting and instability observed in high-capacity (128-unit) encoders on this small dataset (Cite solution_lesson_node_00110).
    *   **No Over-Engineering:** We explicitly **remove** Input Gating and Batch Normalization layers, as these introduced optimization overhead and slowed convergence in previous attempts (Cite solution_lesson_node_00104).
    *   **Output:** Initial frame-wise class probabilities ($P_1$) over 21 classes.

2.  **Stage 2: Monotonic Non-Causal Refinement**
    *   **Input:** Strictly the **class probabilities** ($P_1$) from Stage 1 (Cite solution_lesson_node_00020).
    *   **Architecture:** A stack of **Gated Dilated Temporal Convolutional Layers** ($\tanh \times \sigma$) using **Standard Convolutions** (Cite solution_lesson_node_00065).
    *   **Dilation Schedule:** **Monotonically Increasing** $[1, 2, 4, 8, 16]$. This yields a receptive field of 63 frames, maximizing context within the 64-frame training window without reading invalid padding (Cite solution_lesson_node_00080, solution_lesson_node_00057).
    *   **Causality:** **Centered Padding** (Non-Causal) to leverage future context (Cite solution_lesson_node_00078).
    *   **Regularization:** **Dropout (p=0.2)** after every block (Cite solution_lesson_node_00091).
    *   **Output:** Refined class probabilities ($P_2$).

3.  **Stage 3: Independent Iterative Refinement**
    *   **Structure:** Identical to Stage 2 but with **independent weights** (Cite solution_lesson_node_00054).
    *   **Output:** Final class probabilities ($P_3$).

# Data
The data pipeline incorporates critical engineering fixes for robustness and strict physical consistency.

1.  **Robust Polymorphic Parsing (Structural Requirement):**
    *   The data loader implements a **Polymorphic Parser** for the `.mat` files. It explicitly checks the data type of the `Skeleton` field (struct array vs. cell array vs. primitive) and handles each case dynamically. This prevents the "silent failure" (zero-filling) that crippled previous attempts (Cite solution_lesson_node_00045).

2.  **Kinematically Consistent Augmentation:**
    *   **Load:** Raw 3D Joint Positions ($P_{raw}$).
    *   **Augment:** Apply random 3D rotations (Y-axis) and scaling to $P_{raw}$.
    *   **Derive:** Calculate **Velocity** ($V_t$) and **Acceleration** ($A_t$) from the *augmented* positions (Cite solution_lesson_node_00029).
    *   **Scale:** Apply the **Physical Scaling** (mm to meters) *after* derivation.

3.  **Sampling Strategy:**
    *   **Windowing:** Generate training samples using **Sliding Windows of 64 frames** (Cite solution_lesson_node_00017).
    *   **Stride:** Use a **Moderate Stride** (e.g., 32 frames) to avoid overfitting (Cite solution_lesson_node_00053).

# Training
The training strategy prioritizes stability and smoothness using Deep Supervision.

1.  **Cascaded Loss Function:**
    *   $L_{total} = L(P_1) + L(P_2) + L(P_3)$ (Deep Supervision) (Cite solution_lesson_node_00025).
    *   **Weighted Cross-Entropy:** Applied with a weight of **0.2** for the "background" class (Cite solution_lesson_node_00010).
    *   **Log-Space Smoothing Loss:** A Truncated MSE loss applied to the log-probabilities of adjacent frames for $P_2$ and $P_3$.
    *   **Calibration:** We use a **Low Weight** ($\lambda=0.15$) and **Low Threshold** (1.0). This prevents the under-segmentation observed when smoothing was too aggressive (Cite solution_lesson_node_00111, solution_lesson_node_00055).

2.  **Optimizer:**
    *   **Adam** optimizer with **Weight Decay** (L2) (Cite solution_lesson_node_00026, solution_lesson_node_00055).

# Evaluation
1.  **Inference:** **Full Sequence Inference**. Instead of chopping validation sequences into independent windows (which destroys context, Cite solution_lesson_node_00079), we process the entire sequence in a single pass (Batch Size=1) or use stateful windowing if memory is constrained.
2.  **Model Selection:** Select the best checkpoint based on **Levenshtein Distance** on full sequences (Cite solution_lesson_node_00052).
3.  **Decoding:**
    *   Apply `argmax` to the final probabilities.
    *   Perform **Run-Length Encoding (RLE)**.
    *   **Min Duration Filter:** Explicitly remove segments shorter than **5 frames**. This aligns the output with physical gesture constraints (Cite solution_lesson_node_00071).
