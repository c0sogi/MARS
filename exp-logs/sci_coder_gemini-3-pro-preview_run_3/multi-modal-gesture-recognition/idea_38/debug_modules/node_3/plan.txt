The `RuntimeError` occurs because the model architecture uses `.permute()` in the forward pass (specifically in the TCN stages), which results in non-contiguous tensors. The `.view()` method strictly requires tensors to be contiguous in memory, causing the crash when calculating the loss. To fix this, I will replace the `.view()` calls with `.reshape()` in the `train_epoch` method of `library/trainer.py`. The `.reshape()` method handles non-contiguous inputs by automatically creating a contiguous copy if necessary (Cite debug_lesson_18).
