My strategy for the `runfile.py` implementation is as follows:

1.  **Setup and Reproducibility**: Import necessary standard libraries and the provided custom library modules (`library.*`). Set random seeds for Python, NumPy, and PyTorch to ensure reproducible training and inference results.

2.  **Training**: Instantiate the `Trainer` class from `library.trainer`. Execute the `fit` method with a reduced number of epochs (20) to ensure the solution runs quickly as a baseline while still allowing convergence. This utilizes the `RGHC_MN` model and the data pipeline defined in the library.

3.  **Validation and Metric Calculation**:
    *   Load the best model checkpoint saved during training.
    *   Load the full validation dataset (skeletons, audio, and ground truth labels).
    *   Perform inference on the validation set using the `predict_sequence` and `decode_predictions` functions.
    *   Calculate the global Levenshtein distance metric using the provided `levenshtein_score` utility.
    *   Print the required output: `Final Validation Metric: <value>`.

4.  **Failure Analysis**:
    *   Compute sample-level error rates (Levenshtein distance normalized by sequence length).
    *   Extract meta-features for each validation sample: sequence duration, number of ground truth gestures, and average kinematic velocity.
    *   Calculate and print the Pearson correlation between the error rates and these features to identify potential causes of failure (e.g., does the model fail more on longer sequences or faster movements?).

5.  **Submission Generation**:
    *   Check if the `Final Validation Metric` is strictly less than 0.2251.
    *   If the condition is met, call `generate_submission` from `library.inference` to create predictions for the test set and save them to `./submission/submission.csv`.
    *   If the condition is not met, skip submission generation to save time and resources.
