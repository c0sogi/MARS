Based on the lessons learned, specifically the strong baseline performance of the Bi-GRU (Lesson 10) and the importance of explicit motion features (Lesson 5), combined with the potential for learnable smoothing offered by TCNs (Idea 2), I propose a **Cascaded Recurrent-Convolutional Refinement Network**.

This approach structurally evolves the previous ideas by replacing the brittle heuristic post-processing of the Bi-GRU solution with a learnable Temporal Convolutional Network (TCN) refinement module. This allows the model to learn optimal segmentation boundaries and smoothing rules directly from the data, while retaining the superior feature extraction capabilities of the RNN on this specific dataset.

# Model
The architecture consists of two distinct, sequentially connected stages:

1.  **Stage 1: Sequence Encoder (Bi-GRU)**
    *   This component is responsible for extracting local temporal dynamics and generating initial frame-wise class probabilities.
    *   It utilizes a **Bi-directional Gated Recurrent Unit (Bi-GRU)** backbone. The bi-directional nature ensures that the prediction for each frame is informed by both past context (onset) and future context (offset).
    *   The output of this stage is a sequence of probability vectors (Softmax) over the 21 classes (20 gestures + background).

2.  **Stage 2: Temporal Refinement Module (Dilated TCN)**
    *   This component takes the **probability sequence** generated by Stage 1 as its input (not the raw features).
    *   It consists of a stack of **Dilated Convolutional Layers** (similar to the refinement stage of an MS-TCN). The dilations allow the network to view a wide temporal context of initial predictions to correct isolated errors (jitter) and enforce temporal consistency (e.g., filling in small gaps or removing impossibly short segments).
    *   This effectively replaces the manual median filter used in previous attempts with a trained neural network layer.

# Data
The data pipeline strictly adheres to the strategies identified as critical for convergence on this small dataset:

1.  **Feature Engineering:**
    *   **Skeleton:** Normalized 3D joint coordinates.
    *   **Velocity:** Explicit first-order temporal derivatives of the skeleton joints are concatenated to the input vector to capture dynamic motion (Cite solution_lesson_node_00005).
    *   **Audio:** MFCC vectors synchronized to the video frame rate.
2.  **Windowing Strategy:**
    *   Instead of training on full sequences (which caused the MS-TCN to fail in previous attempts), we will employ **Sliding Window Training** (e.g., windows of 128 frames with 50% overlap). This drastically increases the number of training samples and gradient updates, ensuring robust convergence (Cite solution_lesson_node_00010).

# Training
The training process is designed to handle class imbalance and enforce smoothness:

1.  **Loss Function:**
    *   **Weighted Cross-Entropy:** Applied to the outputs of both Stage 1 and Stage 2. We will apply a specific weight (e.g., 0.2) to the "background" class to prevent the model from biasing towards the majority class (Cite solution_lesson_node_00010).
    *   **Smoothing Loss:** A Truncated Mean Squared Error (MSE) loss is applied to the output of Stage 2. This penalizes rapid changes in log-probabilities between adjacent frames, encouraging the model to produce continuous, stable gesture segments.
2.  **Optimizer:** The Adam optimizer will be used to train both stages.
3.  **Strategy:** The model can be trained end-to-end, allowing the Bi-GRU to learn features that are not only accurate but also "refinable" by the TCN.

# Evaluation
1.  **Inference:** During testing, the full continuous sequence (or stitched overlapping windows) is passed through the network.
2.  **Prediction:** The final frame-wise predictions are taken from the output of **Stage 2**.
3.  **Decoding:** A simple `argmax` is applied to the smoothed probabilities. Due to the learned refinement, aggressive post-processing is no longer necessary; we simply collapse consecutive identical labels (Run-Length Encoding) and remove the background class to generate the final ordered list of gesture IDs.
