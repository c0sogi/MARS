The implementation strategy follows a structured pipeline to ensure robustness and reproducibility while adhering to the time constraints.

1.  **Environment Setup**: We begin by importing necessary libraries and the provided helper modules. Warnings are suppressed to keep the output clean, and random seeds are set to `Config.SEED` to guarantee reproducibility. The output directory `./submission` is created if it doesn't exist.
2.  **Training**: The training process is initiated using `library.train.run_training`. We utilize the full dataset (`limit_samples=None`) and the default configuration of 60 epochs. Given the relatively small dataset size (approx. 300 videos) and GPU availability, this fits well within the "fast baseline" requirement while ensuring sufficient convergence.
3.  **Validation & Metric Calculation**: To calculate the "Final Validation Metric" accurately, we cannot rely on the window-based metric used during training. Instead, we implement a **Temporal Ensembling** validation loop. This involves:
    *   Loading the best model checkpoint.
    *   Running sliding-window inference on the validation set.
    *   Aggregating probabilities for overlapping windows to reconstruct the full temporal sequence for each sample.
    *   Decoding the sequences using Run-Length Encoding (RLE) and computing the Levenshtein distance against the ground truth.
    *   The final metric is printed exactly as requested: `Final Validation Metric: <value>`.
4.  **Failure Analysis**: We perform a correlation analysis on the validation results. Specifically, we calculate the Pearson correlation coefficient between the error magnitude (Levenshtein distance) and two meta-features: the sequence length (frames) and the number of gestures in the sequence. This helps identify if the model struggles with longer sequences or denser gesture chains.
5.  **Submission**: Finally, the code checks if the calculated validation metric is below the threshold of `0.2251`. If successful, it triggers the test set inference using `library.inference.run_inference` and copies the resulting CSV to `./submission/submission.csv`.
