The `ValueError` is caused by incorrect parsing of the `.mat` files, resulting in an empty dataset where every sample has 0 frames. Specifically, `scipy.io.loadmat` returns a dictionary, but the code attempts to access the `Video` structure using dot notation (`mat.Video`), which fails (Cite debug_lesson_2). Additionally, when `squeeze_me=True` is used, the `Video` struct is often wrapped in a 0-d NumPy array that must be explicitly unwrapped (Cite debug_lesson_16). These issues cause the parser to extract zero frames, leading to empty arrays in the dataset that crash the reshaping logic in `__getitem__`.

To fix this:
1.  Update `RobustMatParser.parse_skeleton` to accept the unwrapped `video_struct` directly instead of the full `mat` dictionary.
2.  Modify `process_and_cache_data` to access `mat` as a dictionary (`mat["Video"]`), unwrap the 0-d array using `.item()`, and pass the valid `video` object to the parser.
3.  Add a guard clause in `GestureDataset.__getitem__` to handle cases where `extract_len` is 0, returning zero-padded features instead of attempting invalid operations.
