### Model
The proposed solution is a **Direct Interaction Pooling Ranker** and a **Query-Initialized Recurrent Reader**. This architecture prioritizes speed by extracting relevance signals directly from interaction matrices without heavy encoders (Ranker) and conditioning the reading process via efficient state initialization rather than concatenation or attention (Reader).

1.  **Long Answer Ranker (Direct Interaction Pooling Network - DIPN):**
    *   **Input:** Accepts the Question and a Candidate Long Answer (paragraph) as separate inputs.
    *   **Embedding:** Maps tokens to pre-trained static word embeddings (e.g., GloVe).
    *   **Interaction Matrix:** Computes a **Word-to-Word Similarity Matrix** (Dot Product) between every Question token and every Candidate token.
    *   **Direct Pooling:** Instead of processing this matrix with convolutions (Idea 12) or histograms (Idea 11), the model applies direct pooling operations to extract semantic matching signals:
        *   **Row-wise Max Pooling:** For each Question word, find its maximum similarity score within the paragraph. This generates a vector representing "how well is each query term matched?".
        *   **Column-wise Mean Pooling:** For each Paragraph word, find its average similarity to the Question. This generates a vector representing "how relevant is this text segment overall?".
    *   **Scoring:** These two pooled vectors are concatenated and passed through a Multi-Layer Perceptron (MLP) to predict a relevance probability.

2.  **Short Answer Reader (Query-Initialized Recurrent Network - QIRN):**
    *   **Input:** Accepts the Question and the Top-Ranked Candidate Paragraph.
    *   **Query Encoding:** The Question is encoded using a lightweight LSTM. The final hidden state ($h_T$) is extracted as the "Question Vector".
    *   **State Initialization:** Instead of concatenating the question vector to every paragraph token (Idea 3), the Question Vector is used to **initialize the starting hidden state** ($h_0, c_0$) of the Paragraph Reader LSTM.
    *   **Reading:** The Paragraph is processed by this initialized Bi-Directional LSTM. The network dynamics are thus conditioned on the question context from the very first step without increasing the input dimensionality or computational complexity per step.
    *   **Output:** The LSTM outputs are fed into two independent dense layers to predict the logits for the `start` and `end` token indices.

### Data
*   **Preprocessing:**
    *   **Segmentation:** The raw `document_text` is parsed to split the article into discrete candidate paragraphs based on top-level HTML tags (e.g., `<P>`, `<Table>`, `<Ul>`).
    *   **Tokenization:** Text is tokenized by splitting on whitespace. A vocabulary is built from the training corpus, mapping tokens to indices in the pre-trained embedding matrix.
*   **Dataset Construction:**
    *   **Ranker Data:** Training samples are created as pairs. Positive pairs consist of the Question and the ground-truth paragraph. Negative pairs are selected using **TF-IDF Hard Negatives** (paragraphs with high lexical overlap but no answer) to force the model to learn semantic relevance beyond keyword matching.
    *   **Reader Data:** Only positive paragraphs containing valid short answers are used. The start and end token indices are adjusted to be relative to the beginning of the paragraph.

### Training
*   **Strategy:** The Ranker and Reader are trained as independent models to minimize memory usage and allow for parallel experimentation.
*   **Ranker Optimization:** Trained using **Binary Cross-Entropy Loss**. The model learns to classify whether a Question-Paragraph pair is a match (1) or a non-match (0).
*   **Reader Optimization:** Trained using **Categorical Cross-Entropy Loss** applied independently to the start and end token predictions.
*   **Optimizer:** The **Adam** optimizer is used for both models to ensure fast and stable convergence.

### Evaluation
1.  **Candidate Generation:** The test document is segmented into candidate paragraphs.
2.  **Ranking:** The DIPN Ranker computes the interaction matrix for the Question and each candidate, pools the signals, and outputs a relevance score.
3.  **Selection:** The candidate with the highest probability is selected as the predicted Long Answer.
4.  **Extraction:** The QIRN Reader encodes the Question to initialize the LSTM, processes the selected paragraph, and outputs probability distributions for the start and end tokens.
5.  **Inference:** The valid span (`start <= end`) with the highest joint probability is identified. A global confidence score is computed; if it falls below a tuned threshold, the system predicts "Null", otherwise it outputs the predicted Long Answer indices and Short Answer text.
