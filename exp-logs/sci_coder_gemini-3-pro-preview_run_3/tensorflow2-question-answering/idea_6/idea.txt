### Model
The proposed solution is a **Dense Retrieval Ranker and Similarity-Projection Reader**. This architecture leverages the efficiency of pre-trained distilled Transformers for retrieval and a parameter-light interaction mechanism for extraction, avoiding the heavy computational cost of full cross-attention or recurrent networks.

1.  **Long Answer Ranker (Distilled Transformer Dual-Encoder):**
    *   **Architecture:** Utilizes a **Pre-trained Distilled Transformer** (e.g., MiniLM or TinyBERT) arranged as a **Dual-Encoder**.
    *   **Encoding:** The Question and each Candidate Long Answer (paragraph) are processed independently by the same encoder. A pooling operation (e.g., on the `[CLS]` token) reduces each input to a single dense vector representation.
    *   **Scoring:** Relevance is determined by calculating the **Cosine Similarity** between the Question vector and the Candidate vector. This allows for rapid scoring of all candidates without re-encoding the question for every paragraph.

2.  **Short Answer Reader (Similarity-Projection Network):**
    *   **Input:** Reuses the sequence of token-level embeddings generated by the Ranker for the Question and the Top-Ranked Candidate.
    *   **Interaction:** Computes a **Token-to-Token Similarity Matrix** (Dot Product) between the Question tokens and the Candidate tokens.
    *   **Feature Extraction:** Applies **Max-Pooling** along the question dimension for each candidate token. This results in a scalar "relevance intensity" value indicating how strongly each token in the paragraph relates to the most similar part of the question.
    *   **Output:** This relevance scalar is concatenated with the original candidate token embedding. The combined vector is passed to a simple **Linear Layer** (dense projection) that predicts the logits for the `start` and `end` positions.

### Data
*   **Preprocessing:** The `document_text` is segmented into candidate paragraphs based on top-level HTML tags. All text is tokenized using the sub-word tokenizer associated with the pre-trained model (e.g., WordPiece).
*   **Ranker Dataset:** Training data is formatted as triplets: an Anchor (Question), a Positive (Paragraph containing the answer), and a Negative (Paragraph from the same document without the answer, selected via TF-IDF overlap).
*   **Reader Dataset:** Includes only positive paragraphs containing valid short answers. Start and end indices are adjusted to align with the sub-word tokenization of the specific paragraph.

### Training
*   **Strategy:** The Ranker and Reader are trained as independent modules to minimize memory usage.
*   **Ranker Optimization:** Trained using **Triplet Loss** or **Contrastive Loss**. The objective is to minimize the distance between the Question and Positive Paragraph vectors while maximizing the distance to Negative Paragraph vectors.
*   **Reader Optimization:** Trained using **Categorical Cross-Entropy Loss** for the start and end pointers.
*   **Optimizer:** The AdamW optimizer is used. To ensure the "baseline" remains lightweight, the lower layers of the pre-trained Transformer backbone can be frozen, fine-tuning only the top layers and the projection heads.

### Evaluation
1.  **Encoding:** For a test example, the Question and all Candidate Paragraphs are encoded into dense vectors using the Ranker.
2.  **Ranking:** Candidates are ranked based on their Cosine Similarity to the Question vector. The candidate with the highest score is selected as the Long Answer.
3.  **Extraction:** The token embeddings of the Question and the selected Long Answer are passed to the Similarity-Projection Reader.
4.  **Inference:** The Reader outputs probability distributions for start and end tokens. The valid span (`start <= end`) with the highest joint probability is selected. If the Ranker's similarity score is below a calibrated threshold, the system predicts "Null"; otherwise, it outputs the predicted Long and Short answers.
