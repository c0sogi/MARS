The implementation strategy involves three targeted fixes to ensure data integrity and valid submission format:
1.  **Sanitize Identifiers in Output Generation**: In `library/eval_engine.py`, the `example_id` extracted from the raw test file will be explicitly sanitized (removing commas and newlines) before being used to look up predictions or written to the CSV. This directly addresses the "Expected 141 fields... saw 334" error caused by CSV injection (Cite `debug_lesson_4`).
2.  **Source Identifiers from Raw Data**: In `library/data_loader.py`, the `NQRankerTestDataset` will be updated to extract the `example_id` directly from the raw JSON content rather than the potentially unreliable metadata CSV. This ensures the ID matches the content exactly (Cite `debug_lesson_1`).
3.  **Disable Caching for Inference**: In `runfile.py`, the inference call will be changed to `load_cached_data=False`. This forces the pipeline to ignore any existing (potentially corrupted) test feature cache and regenerate the dataset using the corrected logic (Cite `debug_lesson_8`).
