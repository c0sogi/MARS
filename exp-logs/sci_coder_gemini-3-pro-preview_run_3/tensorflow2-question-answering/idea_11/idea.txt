### Model
The proposed solution is a **Histogram-Based Matching Ranker** and a **Quasi-Recurrent Reader**. This architecture prioritizes high-throughput inference by converting expensive semantic matching operations into efficient binning operations for ranking, and utilizing parallelizable recurrence for extraction.

1.  **Long Answer Ranker (Histogram-Based Matching Network):**
    *   **Input:** Accepts the Question and a Candidate Long Answer (paragraph) as separate inputs.
    *   **Embedding:** Maps tokens to pre-trained static word embeddings (e.g., GloVe).
    *   **Interaction Matrix:** Computes the **Cosine Similarity** between every Question token embedding and every Candidate token embedding, resulting in a similarity matrix.
    *   **Histogram Binning:** Instead of aggregating these scores via pooling or attention, the model discretizes the similarity scores for each question word into a fixed number of **bins** (e.g., counts of matches in ranges [1.0-0.9], [0.9-0.8], etc.). This converts the variable-length interaction data into a fixed-size "matching density" vector for each query term, explicitly capturing exact matches and soft semantic matches.
    *   **Scoring:** These density vectors are passed through a Feed-Forward Network (MLP) to weight the importance of each match type and produce a final relevance score.

2.  **Short Answer Reader (Quasi-Recurrent Neural Network - QRNN):**
    *   **Input:** Concatenates the Question and the Top-Ranked Candidate Paragraph into a single sequence.
    *   **Encoder:** The sequence is processed by a stack of **Quasi-Recurrent** layers. Each layer applies a **1D-Convolution** on the input to extract local features, followed by a parallelizable **Dynamic Pooling** (f-pooling) mechanism. This structure captures sequential dependencies like an LSTM but allows for parallel computation across the time dimension like a CNN, offering a superior speed-accuracy trade-off.
    *   **Output:** Two independent linear layers project the QRNN output states to logits, predicting the probability of each token being the `start` and `end` of the answer span.

### Data
*   **Preprocessing:**
    *   **Segmentation:** The raw `document_text` is parsed to isolate candidate paragraphs using top-level HTML tags (e.g., `<P>`, `<Table>`, `<Ul>`).
    *   **Tokenization:** Text is tokenized by splitting on whitespace. A vocabulary is built from the training corpus, mapping tokens to indices compatible with the pre-trained embedding matrix.
*   **Dataset Construction:**
    *   **Ranker Data:** Training samples are constructed as pairs. Positive pairs consist of the Question and the ground-truth paragraph. Negative pairs are selected using **TF-IDF Hard Negatives** (paragraphs with high lexical overlap but no answer) to force the histogram model to distinguish between simple keyword matching and true relevance.
    *   **Reader Data:** Only positive paragraphs containing valid short answers are used. The start and end token indices are adjusted to be relative to the beginning of the concatenated sequence.

### Training
*   **Strategy:** The Ranker and Reader are trained as independent modules to minimize memory footprint and allow for specialized hyperparameter tuning.
*   **Ranker Optimization:** Trained using **Pairwise Hinge Loss** (Ranking Loss). The model learns to assign a higher score to the positive paragraph than to the negative paragraph by a specified margin.
*   **Reader Optimization:** Trained using **Categorical Cross-Entropy Loss** for the start and end positions.
*   **Optimizer:** The **RMSProp** or **Adam** optimizer is used for both models to ensure stable convergence.

### Evaluation
1.  **Candidate Generation:** The test document is segmented into candidate paragraphs.
2.  **Ranking:** The Histogram-Based Matching Ranker processes the Question against all candidates. It computes the interaction matrix, bins the scores, and outputs a relevance probability for each candidate.
3.  **Selection:** The candidate with the highest probability is selected as the predicted Long Answer.
4.  **Extraction:** The selected paragraph is concatenated with the Question and passed to the QRNN Reader, which predicts probability distributions for the start and end tokens.
5.  **Inference:** The valid span (`start <= end`) with the highest joint probability is identified. A global confidence score is calculated; if it falls below a tuned threshold, the system predicts "Null", otherwise it outputs the predicted Long Answer indices and Short Answer text.
