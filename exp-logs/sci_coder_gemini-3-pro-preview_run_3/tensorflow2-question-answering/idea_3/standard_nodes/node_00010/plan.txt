The implementation strategy involves two key fixes in `library/inference.py`. First, to address the `torch.OutOfMemoryError`, the inference logic for the Ranker model will be modified to process candidate paragraphs in smaller batches (e.g., 64) rather than stacking all candidates for a document into a single large tensor. This reduces peak GPU memory usage. Second, to ensure data integrity and prevent CSV parsing errors in the submission file, the `example_id` will be sourced directly from the raw JSON data (`data["example_id"]`) instead of the metadata CSV (`row["example_id"]`), applying the principle from `debug_lesson_1`.
