### Model
The proposed solution is a **Convolutional Ranking and Attention-MLP Extraction Network**. This architecture prioritizes computational speed by avoiding recurrent connections (RNNs) and heavy self-attention mechanisms, relying instead on parallelizable convolutions and simple feed-forward attention.

1.  **Long Answer Ranker (Siamese TextCNN):**
    *   **Input:** Processes the Question and a Candidate Long Answer (paragraph) as independent inputs.
    *   **Embedding:** Maps tokens to fixed pre-trained word embeddings.
    *   **Encoder:** Instead of simple averaging, this module uses a **Multi-Scale 1D-Convolutional Network** (TextCNN). It applies multiple parallel convolutional filters of varying kernel sizes (e.g., covering 2, 3, and 4 tokens) to capture local phrase patterns.
    *   **Aggregation:** A **Max-Over-Time Pooling** operation extracts the most salient features from the convolutional maps, producing a fixed-size vector for both the Question and the Candidate.
    *   **Scoring:** The two vectors are combined using a heuristic matching function (concatenation, element-wise difference, and element-wise product) and passed through a binary classification MLP to predict the probability that the candidate contains the answer.

2.  **Short Answer Reader (Attention-MLP):**
    *   **Input:** The Question and the Top-Ranked Candidate Paragraph.
    *   **Context-Query Attention:** For every token in the paragraph, the model computes a similarity score against all Question tokens. These scores are used to create a weighted sum of the Question embeddings, resulting in a specific "Question Context Vector" for each paragraph token.
    *   **Fusion & Prediction:** The original paragraph token embedding is concatenated with its corresponding Question Context Vector. This combined representation is fed into a **Time-Distributed Feed-Forward Network** (Dense MLP) that independently predicts the logits for being the `start` and `end` of the answer span. This avoids the sequential processing delay of LSTMs while still explicitly conditioning every token on the question.

### Data
*   **Preprocessing:** The raw HTML document is split into candidate paragraphs based on top-level tags (e.g., `<P>`, `<Table>`). Text is tokenized and mapped to a vocabulary derived from the pre-trained embeddings.
*   **Ranker Dataset:** Training samples are constructed as pairs. Positive pairs consist of the Question and the ground-truth paragraph. Negative pairs are created using **Hard Negative Mining**: selecting paragraphs that do not contain the answer but have high lexical overlap (e.g., high TF-IDF score) with the question, forcing the CNN to learn semantic distinctions beyond simple keyword matching.
*   **Reader Dataset:** Only positive paragraphs containing valid short answers are used. The start and end token indices are recalculated to be relative to the beginning of the paragraph.

### Training
*   **Procedure:** The Ranker and Reader are trained separately to reduce memory overhead and allow for parallel experimentation.
*   **Ranker Optimization:** The Ranker is trained as a binary classifier using **Binary Cross-Entropy Loss**. The objective is to classify whether a given Question-Paragraph pair is a "match" (1) or "no-match" (0).
*   **Reader Optimization:** The Reader is trained using **Sparse Categorical Cross-Entropy Loss**, treating the start and end positions as two separate multi-class classification problems over the length of the paragraph.
*   **Optimizer:** The Adam optimizer is employed for both models with early stopping based on validation loss.

### Evaluation
1.  **Candidate Generation:** The test document is segmented into paragraphs.
2.  **Ranking:** The TextCNN Ranker processes the Question against all candidates to generate a relevance probability for each.
3.  **Selection:** The candidate with the highest probability is identified as the predicted Long Answer.
4.  **Extraction:** The Attention-MLP Reader processes the selected paragraph to generate probability distributions for start and end indices. The valid span (where `start <= end`) with the highest joint probability is selected.
5.  **Prediction Logic:** A global confidence score is computed (Ranker Probability $\times$ Reader Span Probability). If this score is below a tuned threshold, the system returns a "Null" prediction; otherwise, it outputs the Long Answer indices and the Short Answer text.
