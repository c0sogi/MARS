### Model
The proposed solution is an **Attention-Weighted Neural Bag-of-Words Ranker** and a **Convolutional Bi-Directional Attention Flow Reader**. This architecture synthesizes the interaction mechanisms of Model 3 (Attention Flow) with the computational efficiency of Model 4 (Separable Convolutions), creating a fast yet semantically robust baseline that avoids both Recurrent Neural Networks and heavy Transformers.

1.  **Long Answer Ranker (Attention-Weighted Neural Bag-of-Words - ANBoW):**
    *   **Input:** Accepts the Question and a Candidate Long Answer (paragraph) as separate inputs.
    *   **Embedding:** Maps tokens to pre-trained static word embeddings (e.g., GloVe).
    *   **Attention Aggregation:** Instead of simple averaging or max-pooling, a learnable **Self-Attention mechanism** assigns a scalar weight to each token embedding based on its semantic importance.
    *   **Encoding:** The weighted sum of the embeddings is computed to produce a single, content-rich vector for the Question and one for the Candidate. This allows the model to downweight stop words and emphasize keywords without complex encoding layers.
    *   **Interaction & Scoring:** The two vectors are combined using a heuristic matching function (concatenation of the vectors, their element-wise difference, and their element-wise product). This combined vector is passed through a Feed-Forward Network (MLP) to predict a relevance score.

2.  **Short Answer Reader (Convolutional Bi-Directional Attention Flow - Conv-BiDAF):**
    *   **Input:** The Question and the Top-Ranked Candidate Paragraph.
    *   **Local Context Layer:** Both inputs are passed through a **1D-Convolutional** layer to capture local n-gram context (e.g., "New York") before interaction.
    *   **Attention Flow Layer:** Computes a similarity matrix between every Question token and every Context token. It then calculates **Bi-Directional Attention**:
        *   *Context-to-Query:* Which query words are most relevant to each context word.
        *   *Query-to-Context:* Which context words are most relevant to each query word.
        These attention vectors are fused with the original context embeddings to create a "query-aware" representation of the paragraph.
    *   **Modeling Layer:** The query-aware representations are processed by a stack of **Depth-wise Separable Convolutions**. This replaces the slow LSTM modeling layer found in traditional BiDAF architectures with a highly efficient convolutional equivalent.
    *   **Output:** Two independent linear layers predict the logits for the `start` and `end` indices of the answer span.

### Data
*   **Preprocessing:**
    *   **Segmentation:** The raw `document_text` is parsed to extract discrete candidate paragraphs based on top-level HTML tags (e.g., `<P>`, `<Table>`, `<Ul>`).
    *   **Tokenization:** Text is tokenized by splitting on whitespace. A vocabulary is built from the training data, and tokens are mapped to indices corresponding to the pre-trained embedding matrix.
    *   **Labeling:** For the training set, paragraphs containing the annotated long answer are marked as positive. Within positive paragraphs, the short answer span indices are adjusted to be relative to the paragraph start.
*   **Dataset Construction:**
    *   **Ranker Data:** Constructed as pairs. Positive pairs consist of the Question and the ground-truth paragraph. Negative pairs are sampled from the same document, specifically targeting paragraphs that do not contain the answer.
    *   **Reader Data:** Only positive paragraphs containing valid short answers are used for training the reader.

### Training
*   **Strategy:** The Ranker and Reader are trained as independent models to maximize modularity and training speed.
*   **Ranker Optimization:** Trained using **Binary Cross-Entropy Loss**. The model learns to classify whether a Question-Paragraph pair is relevant (1) or irrelevant (0).
*   **Reader Optimization:** Trained using **Categorical Cross-Entropy Loss**. The model minimizes the negative log-likelihood for the correct start and end token positions.
*   **Optimizer:** The **Adadelta** or **Adam** optimizer is used. Dropout is applied to the embeddings and convolutional layers to prevent overfitting.

### Evaluation
1.  **Candidate Generation:** The test document is segmented into candidate paragraphs.
2.  **Ranking:** The ANBoW Ranker processes the Question against all candidates to generate a relevance probability for each.
3.  **Selection:** The candidate with the highest probability is selected as the predicted Long Answer.
4.  **Extraction:** The Conv-BiDAF Reader processes the selected paragraph and the question to generate probability distributions for the start and end indices.
5.  **Inference:** The valid span (`start <= end`) with the highest joint probability is identified. A global confidence score is calculated (Ranker Score $\times$ Reader Span Score). If this confidence is below a tuned threshold, the system predicts "Null"; otherwise, it outputs the predicted Long Answer indices and Short Answer text.
