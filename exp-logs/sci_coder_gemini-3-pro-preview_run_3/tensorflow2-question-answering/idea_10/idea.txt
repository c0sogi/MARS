### Model
The proposed solution is an **Early-Fusion Convolutional Ranker** and a **Dynamic Kernel Convolutional Reader**. This architecture distinguishes itself by using an "early fusion" strategy for ranking (processing question and answer as a single sequence) and a dynamic weight generation mechanism for extraction, prioritizing speed by avoiding static deep encoders or recurrent steps.

1.  **Long Answer Ranker (Early-Fusion CNN):**
    *   **Input:** Concatenates the Question tokens and Candidate Long Answer (paragraph) tokens into a single contiguous sequence, separated by a special delimiter token. This differs from Siamese/Dual-Encoder approaches by allowing the model to learn interaction patterns (like exact phrase matching across the boundary) in the first layer.
    *   **Embedding:** Maps tokens to pre-trained static word embeddings (e.g., GloVe).
    *   **Encoder:** The combined sequence is passed through a stack of **1D-Convolutional** layers with Max-Pooling between them. This hierarchically reduces the sequence length while extracting n-gram features that span both the question and the answer text.
    *   **Scoring:** The final pooled representation is flattened and passed through a fully connected layer (MLP) to output a relevance probability.

2.  **Short Answer Reader (Dynamic Kernel Network):**
    *   **Input:** Accepts the Question and the Top-Ranked Candidate Paragraph as separate inputs.
    *   **Filter Generation:** The Question embeddings are aggregated (e.g., via Max-Pooling) into a single dense vector. This vector is passed through a "Hypernetwork" (a linear projection layer) to generate a set of weights $W$. These weights are reshaped to form specific **Convolutional Kernels**.
    *   **Dynamic Convolution:** The generated kernels are convolved over the Candidate Paragraph embeddings. This effectively creates a filter that is custom-tailored to detect features relevant to the specific question (e.g., looking for dates if the question asks "when").
    *   **Output:** The feature map resulting from the dynamic convolution is fed into two independent linear layers to predict the logits for the `start` and `end` token indices.

### Data
*   **Preprocessing:**
    *   **Segmentation:** The raw `document_text` is parsed to split the article into discrete candidate paragraphs based on top-level HTML tags.
    *   **Tokenization:** Text is tokenized by splitting on whitespace. A vocabulary is constructed from the training set, mapping tokens to indices in the pre-trained embedding matrix.
*   **Dataset Construction:**
    *   **Ranker Data:** Training samples are created as single sequences: `[Question; <SEP>; Paragraph]`. Positive samples use paragraphs containing the ground truth. Negative samples are drawn from the same document using TF-IDF sampling to ensure they are lexically similar but semantically incorrect.
    *   **Reader Data:** Only positive paragraphs containing valid short answers are used. The start and end indices are adjusted to be relative to the paragraph start.

### Training
*   **Strategy:** The Ranker and Reader are trained independently to minimize computational overhead and allow for modular tuning.
*   **Ranker Optimization:** Trained using **Binary Cross-Entropy Loss**. The model learns to classify the concatenated sequence as either a "Match" (1) or "No-Match" (0).
*   **Reader Optimization:** Trained using **Categorical Cross-Entropy Loss**. The model minimizes the error for predicting the correct start and end positions within the paragraph.
*   **Optimizer:** The **Adam** optimizer is used for both models. To prevent overfitting, Dropout is applied after the embedding layers and between convolutional blocks.

### Evaluation
1.  **Candidate Generation:** The test document is segmented into candidate paragraphs.
2.  **Ranking:** For each candidate, the Question and Paragraph are concatenated and fed into the Early-Fusion CNN Ranker to produce a relevance score.
3.  **Selection:** The candidate with the highest score is selected as the predicted Long Answer.
4.  **Extraction:** The Question and the selected Long Answer are passed to the Dynamic Kernel Reader. The Question generates the filters, which are convolved over the Paragraph to produce start/end probabilities.
5.  **Inference:** The valid span (`start <= end`) with the highest joint probability is selected. A global confidence score is calculated; if it falls below a tuned threshold, the system predicts "Null", otherwise it outputs the predicted Long Answer indices and Short Answer text.
