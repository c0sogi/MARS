### Model
The proposed solution is a **K-Max Interaction Ranker** and a **Highway Co-Attention Reader**. This architecture prioritizes the efficient extraction of matching signals using sorting operations for ranking and replaces slow recurrent modeling layers with fast, depth-capable Highway layers for extraction.

1.  **Long Answer Ranker (K-Max Interaction Pooling Network):**
    *   **Input:** Accepts the Question and a Candidate Long Answer (paragraph) as separate inputs.
    *   **Embedding:** Maps tokens to pre-trained static word embeddings (e.g., GloVe).
    *   **Interaction Matrix:** Computes the **Word-to-Word Similarity Matrix** (Dot Product) between every Question token and every Candidate token.
    *   **K-Max Pooling:** For each Question token (row), the model selects the **Top-K** highest similarity scores from the Candidate paragraph (column). This operation captures the strength of the best matches (e.g., exact keyword hits) and secondary matches (e.g., synonyms) for each query term, preserving more information than simple Max-Pooling.
    *   **Aggregation:** The Top-K vectors for all Question tokens are aggregated via **Sum-Pooling**. This produces a single fixed-size vector of length $K$ representing the global "matching profile" of the pair (i.e., the accumulated strength of the 1st best matches, 2nd best matches, etc.).
    *   **Scoring:** This profile vector is passed through a Multi-Layer Perceptron (MLP) to predict the relevance probability.

2.  **Short Answer Reader (Highway Co-Attention Network):**
    *   **Input:** Accepts the Question and the Top-Ranked Candidate Paragraph.
    *   **Co-Attention Layer:** Computes a similarity matrix between the Question and Paragraph. It calculates **Context-to-Query Attention** (which query words are relevant to each paragraph word) and fuses this information with the original paragraph embeddings to create a query-aware context representation.
    *   **Modeling Layer:** Instead of using LSTMs or CNNs, the query-aware representations are passed through a stack of **Highway Layers**. Highway layers utilize a gating mechanism that allows information to flow through unchanged, enabling the training of deep networks to capture complex semantic dependencies without the computational overhead of recurrence or the vanishing gradient problem.
    *   **Output:** Two independent linear layers project the output of the Highway network to logits, predicting the probability of each token being the `start` and `end` of the answer span.

### Data
*   **Preprocessing:**
    *   **Segmentation:** The raw `document_text` is parsed to extract discrete candidate paragraphs based on top-level HTML tags (e.g., `<P>`, `<Table>`, `<Ul>`).
    *   **Tokenization:** Text is tokenized by splitting on whitespace. A vocabulary is built from the training corpus, and tokens are mapped to indices corresponding to the pre-trained embedding matrix.
*   **Dataset Construction:**
    *   **Ranker Data:** Training samples are created as pairs. Positive pairs consist of the Question and the ground-truth paragraph. Negative pairs are generated using **Hard Negative Mining** (selecting paragraphs from the same document with high TF-IDF overlap but no answer) to force the model to distinguish between lexical overlap and true semantic relevance.
    *   **Reader Data:** Only positive paragraphs containing valid short answers are used. The start and end token indices are adjusted to be relative to the beginning of the paragraph.

### Training
*   **Strategy:** The Ranker and Reader are trained as independent models to minimize peak memory usage and allow for parallel experimentation.
*   **Ranker Optimization:** Trained using **Margin Ranking Loss**. The model learns to score the positive candidate higher than the negative candidate by a specified margin, which is effective for ranking tasks.
*   **Reader Optimization:** Trained using **Categorical Cross-Entropy Loss** for the start and end positions.
*   **Optimizer:** The **Adam** optimizer is used for both models to ensure fast convergence. Dropout is applied within the Highway layers to prevent overfitting.

### Evaluation
1.  **Candidate Generation:** The test document is segmented into candidate paragraphs.
2.  **Ranking:** The K-Max Interaction Ranker computes the interaction matrix, extracts Top-K signals, and outputs a relevance score for every candidate.
3.  **Selection:** The candidate with the highest probability is selected as the predicted Long Answer.
4.  **Extraction:** The Question and the selected Long Answer are processed by the Highway Co-Attention Reader to generate probability distributions for the start and end tokens.
5.  **Inference:** The valid span (`start <= end`) with the highest joint probability is identified. A global confidence score is computed; if it falls below a tuned threshold, the system predicts "Null", otherwise it outputs the predicted Long Answer indices and Short Answer text.
