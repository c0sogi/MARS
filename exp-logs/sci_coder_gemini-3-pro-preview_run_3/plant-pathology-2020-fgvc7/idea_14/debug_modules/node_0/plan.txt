The implementation strategy involves the following steps:

1.  **Configuration Override**: We first import the `Config` class and modify its attributes to optimize for a quick demonstration. This includes enabling `DEBUG` mode (to use data subsets), reducing `EPOCHS` to 1, setting a small `BATCH_SIZE`, and swapping the heavy EfficientNet/MaxViT backbones for a lightweight `resnet18`. We also redirect output directories to avoid conflicts.
2.  **Component Validation**: We implement specific functions to validate individual components of the library:
    *   `demo_utils`: Verifies the reproducibility seed and the calculation of class weights.
    *   `demo_dataset`: Loads a subset of the metadata, instantiates the `AppleDataset`, and validates the shape and type of the returned tensors.
    *   `demo_model_and_loss`: Instantiates the `AppleNet` model, performs a forward pass with dummy data to check output structure, and computes a loss using `HybridLoss` to ensure numerical stability.
3.  **Pipeline Execution**: We execute the high-level `run_training()` and `run_inference()` functions. This demonstrates the end-to-end flow: training the teacher, distilling to the student, and generating an ensemble submission on the test set.
4.  **Final Verification**: We verify that the expected artifacts (model checkpoints and the submission CSV) are created and have the correct format.
