### Implementation Strategy

1.  **Data Loading**: We will manually load the training metadata and select a small subset of trips (2 unique drives) to ensure the demonstration runs quickly. We will use the `_process_trip` function from `library.data_factory` to generate features and targets (ENU residuals) for these trips.
2.  **Preprocessing**: We will split the processed data into training and validation sets based on `drive_id`. We will handle any missing values in the feature columns using simple filling.
3.  **Model Training**: We will instantiate the `QuantileLGBMWrapper` from `library.quantile_regressor`. We will override the default hyperparameters to use a very small number of estimators (10) for speed. We will train two separate models: one for the East component and one for the North component of the error.
4.  **Prediction**: We will use the trained models to predict the median error and the uncertainty (90th percentile - 10th percentile) for the validation set.
5.  **Post-Processing (Smoothing)**: We will apply the `AdaptiveKalmanFilter` from `library.adaptive_smoother` to the predictions. This filter uses the predicted uncertainty to gate the measurement noise, smoothing the trajectory.
6.  **Coordinate Recovery**: We will convert the smoothed ENU (East-North-Up) predictions back to WGS84 (Latitude/Longitude) coordinates using the `enu_to_wgs84` function from `library.utils`, using the WLS baseline positions as reference.
7.  **Evaluation**: Finally, we will calculate the competition metric (mean of 50th and 95th percentile errors) using `library.metrics` to verify the pipeline's end-to-end functionality.
