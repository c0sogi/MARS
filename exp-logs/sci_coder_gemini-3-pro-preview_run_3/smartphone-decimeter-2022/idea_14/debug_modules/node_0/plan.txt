Implementation strategy:
1.  **Environment Setup**: Import necessary libraries and define paths for temporary working directories to ensure the original input/metadata is not modified.
2.  **Utility Verification**: Implement unit tests for the coordinate conversion functions (`ecef_to_geodetic`, `geodetic_to_ecef`) in `library.utils` to ensure geometric logic is correct.
3.  **Data Preparation (Subsampling)**:
    *   Create a temporary metadata directory.
    *   Read the original metadata files (`train_metadata.csv`, `test_metadata.csv`).
    *   Sample a small subset (e.g., 2 trips) from the original metadata to create "demo" metadata files.
    *   Save these demo metadata files to the temporary directory.
4.  **Monkeypatching**:
    *   Dynamically update the `METADATA_DIR` and `CACHE_DIR` variables in `library.data_loader`, `library.train`, and `library.inference` to point to the temporary directories. This forces the library code to use the subsampled data and write outputs to a temporary location.
    *   Update `SUBMISSION_PATH` to avoid overwriting the actual submission file.
5.  **Pipeline Execution**:
    *   **Data Loading**: Call `get_train_data` and `get_test_data` to process the raw sensor data for the subsampled trips. Verify the shape of the resulting DataFrames.
    *   **Model Training**: Execute `run_cross_validation` with `n_folds=2`. This will train LightGBM models on the small dataset.
    *   **Inference**: Execute `generate_submission` to produce predictions using the trained models.
6.  **Validation**: Check if the submission file is generated and has the correct format.
