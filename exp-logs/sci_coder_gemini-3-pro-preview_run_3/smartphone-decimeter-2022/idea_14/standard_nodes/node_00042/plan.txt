The validation strategy in the previous run suffered from data leakage because the training and validation datasets were concatenated before cross-validation, allowing models to train on data from drives that were intended to be held out for evaluation. To fix this, I will modify `library/train.py` to load only the training split for the cross-validation process, ensuring the validation split remains unseen. Additionally, I will update `runfile.py` to use cached data to speed up the run and increase the submission threshold to ensure a submission is generated even if the unbiased metric is higher than the previous leaked metric. This ensures data consistency between the training and evaluation phases (Cite debug_lesson_10).
