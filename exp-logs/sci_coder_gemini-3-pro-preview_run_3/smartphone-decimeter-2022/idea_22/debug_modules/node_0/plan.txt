Implementation Strategy:
1.  **Environment Setup**: Import necessary standard libraries and the provided library modules (`config`, `data_loader`, `feature_engineering`, `odometry`, `model`, `optimizer`).
2.  **Configuration Override**: Modify hyperparameters in `library.config` at runtime to ensure the script executes quickly (e.g., reduce LightGBM estimators, limit dataset size).
3.  **Progress Bar Suppression**: Monkey-patch `tqdm` in the library modules to prevent progress bar output as per requirements.
4.  **Feature Engineering**:
    *   Use `extract_features` to load a small subset of the training data (2 drives) and compute features.
    *   Verify the existence of generated features (e.g., force vectors) and ground truth columns.
5.  **Model Training**:
    *   Instantiate the `ResidualRegressor` class.
    *   Train the model on the extracted training features using a 2-fold cross-validation strategy for speed.
    *   Verify that the internal LightGBM models for East and North components are successfully created.
6.  **Inference (Validation)**:
    *   Extract features for a small validation subset (1 drive).
    *   Use the trained model to predict latitude and longitude (`lat_pred`, `lon_pred`).
    *   Verify the structure of the prediction output.
7.  **Odometry Estimation**:
    *   Use `extract_odometry` on the same validation subset to compute relative motion (`odom_x`, `odom_y`, `odom_z`) using TDCP/Doppler algorithms.
    *   Verify the structure of the odometry output.
8.  **Graph Optimization**:
    *   Use `process_optimization` to combine the ML predictions (anchors) and Odometry (edges) into a refined trajectory.
    *   Verify the output contains the final optimized coordinates.
    *   Compare ML predictions vs. Optimized predictions to confirm the optimizer had an effect.
