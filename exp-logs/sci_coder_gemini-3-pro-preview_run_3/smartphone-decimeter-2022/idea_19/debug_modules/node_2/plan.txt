The issue is that `GroupKFold` with `n_splits=5` requires at least 5 distinct groups (drives) in the training data, but the current `runfile.py` filters the dataset to a single drive for demonstration purposes. Additionally, `DataManager` applies random sampling when `config.DEBUG` is True, which breaks the contiguous time-series requirement for kinematic features.

To fix this, I will modify `runfile.py` to:
1.  Set `config.DEBUG = False` to load the full metadata without random sampling.
2.  Implement logic to select contiguous subsets from at least 5 different drives instead of just one. This ensures we satisfy the cross-validation group requirement (Cite debug_lesson_8) while maintaining the time-series integrity needed for feature engineering.
