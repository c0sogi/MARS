The error `InvalidSubmissionError: Submission and answers DataFrames must have the same number of rows` indicates that the submission file generated by the pipeline contains a different number of rows than expected (likely 50 instead of 37,088). This is caused by the pipeline loading a **stale cached dataset** (`dataset_test.parquet` or `dataset_train.parquet`) that was generated during a previous run where `DEBUG=True` (which samples only a few rows). Even though `Config.DEBUG` is now `False`, the pipeline prefers loading the existing (truncated) cache files over regenerating the full dataset.

To fix this, I will modify `runfile.py` to:
1.  **Clean Stale Artifacts**: Implement a `clean_stale_artifacts` function to explicitly delete `dataset_*.parquet` and `submission.csv` files at the start of execution. This ensures no truncated data persists.
2.  **Force Data Regeneration**: Update the calls to `prepare_dataset` (in `train_and_validate`) and `run_global_optimization` (in `main`) to use `load_cached_data=False`. This forces the pipeline to ignore any potential cache and process the full dataset as defined by the metadata.

This strategy applies **Debug Lesson 3** (Invalidate Data Caches) and **Debug Lesson 4** (Preserve Row Cardinality).
