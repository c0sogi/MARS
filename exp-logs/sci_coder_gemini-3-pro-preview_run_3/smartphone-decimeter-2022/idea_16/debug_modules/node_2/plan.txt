While the data loader adds `tripId` for test data (where no ground truth exists), it does not automatically add it for training/validation data (where ground truth is merged but lacks the `tripId` column in the raw CSVs).

To fix this, I will modify `library/feature_engineering.py` to explicitly construct and add the `tripId` column (formatted as `{drive_id}-{phone_name}`) to the processed dataframe within the aggregation loop. This ensures the identifier is present for all data splits, adhering to the principle of propagating context identifiers in data loaders (Cite debug_lesson_5).
