### Solution: Aggregated Signal Residual Boosting

This approach establishes a highly efficient baseline by leveraging the robustness of Gradient Boosting Decision Trees (GBDT) on aggregated signal statistics. Unlike the previous neural network approach which processed raw features from individual satellites, this solution abstracts the entire constellation into a set of global quality metrics (e.g., "average signal strength") to predict the error in the provided baseline solution.

#### **1. Model**
The architecture consists of two independent **LightGBM Regressors**:
*   **Latitude Regressor**: Predicts the correction factor ($\Delta Lat$) for the baseline Latitude.
*   **Longitude Regressor**: Predicts the correction factor ($\Delta Lon$) for the baseline Longitude.
*   **Input**: A compact, fixed-size vector of aggregated statistics derived from GNSS and IMU sensors for a given timestamp. Unlike neural networks, this tree-based model requires no complex architecture design (e.g., hidden layers, activation functions) and naturally handles non-linear relationships between signal quality and position error.

#### **2. Data**
The preprocessing pipeline focuses on reducing the high-dimensional raw sensor data into a lightweight tabular format.
*   **Baseline Conversion**: Convert the Weighted Least Squares (WLS) positions provided in the `device_gnss.csv` file (ECEF coordinates) into Geodetic coordinates (Latitude, Longitude) to serve as the baseline prediction.
*   **Feature Engineering (Aggregation)**: For each second (`UnixTimeMillis`), compute summary statistics across all visible satellites and sensors:
    *   **GNSS Quality**: `mean_Cn0DbHz`, `std_Cn0DbHz`, `satellite_count` (number of visible satellites), and `mean_SvElevationDegrees`. These proxies indicate whether the device is in an open sky or an urban canyon.
    *   **IMU Dynamics**: Calculate the magnitude of the accelerometer vector ($\sqrt{x^2+y^2+z^2}$) and compute its mean and standard deviation over the 1-second window. This helps the model distinguish between static and moving states.
*   **Target Generation**: Compute the residual error between the Ground Truth and the Baseline WLS position:
    $$ \text{Target}_{lat} = \text{Lat}_{GT} - \text{Lat}_{WLS} $$
    $$ \text{Target}_{lon} = \text{Lon}_{GT} - \text{Lon}_{WLS} $$
*   **Dataset Construction**: Join the aggregated features with the targets on `tripId` and `UnixTimeMillis`.

#### **3. Training**
*   **Loss Function**: **Mean Absolute Error (MAE)** (L1 Loss). This is critical for positioning tasks as it is robust to the extreme outliers often present in GNSS data due to signal reflections (multipath).
*   **Optimizer**: The standard Gradient Boosting algorithm provided by LightGBM.
*   **Strategy**: 
    *   Train the Latitude and Longitude models independently.
    *   Use a simple validation split (e.g., hold out 20% of the drives) to perform early stopping, preventing overfitting.
    *   Because the feature set is small (approx. 10-15 columns) and the model is tree-based, no feature scaling or normalization is required.

#### **4. Evaluation**
*   **Inference**: For each timestamp in the test set, calculate the same aggregated GNSS and IMU features used in training. Pass these features to the two trained LightGBM models to predict the corrections $\hat{\Delta Lat}$ and $\hat{\Delta Lon}$.
*   **Correction**: Apply the predicted corrections to the test baseline WLS positions:
    $$ \text{Final}_{lat} = \text{Lat}_{WLS} + \hat{\Delta Lat} $$
    $$ \text{Final}_{lon} = \text{Lon}_{WLS} + \hat{\Delta Lon} $$
*   **Output**: Save the corrected coordinates to the submission file.
