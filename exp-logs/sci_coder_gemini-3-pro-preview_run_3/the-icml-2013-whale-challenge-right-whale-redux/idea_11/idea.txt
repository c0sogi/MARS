Based on the lessons learned, particularly the trade-off between frequency and temporal resolution (Cite solution_lesson_node_00017) and the superiority of established CNN backbones over Transformers for this task (Cite solution_lesson_node_00016), I propose a **Dual-Stream Multi-Resolution Architecture**. This approach structurally evolves the single-stream models by explicitly processing the audio at two distinct resolutions to capture both the fine-grained spectral morphology (pitch contours) and the rapid temporal dynamics (transient attacks) of right whale calls.

# Model

**Architecture: Dual-Stream EfficientNetV2-Medium**
Instead of a single backbone, the model will consist of two parallel **EfficientNetV2-Medium** feature extractors (Cite solution_lesson_node_00016) that process different representations of the same audio clip.
1.  **Spectral Stream:** This branch takes a **High-Frequency Resolution Spectrogram** as input. It focuses on resolving the dense harmonic structure and specific "up-sweep" pitch contour of the call.
2.  **Temporal Stream:** This branch takes a **High-Temporal Resolution Spectrogram** as input. It focuses on capturing the transient onset and short-duration characteristics of the signal.

**Fusion & Head: Concatenated GeM Pooling**
The feature maps from both backbones will be independently aggregated using **Generalized Mean (GeM) Pooling** (Cite solution_lesson_node_00009). The resulting feature vectors will be concatenated to form a unified representation, which is then passed to a single fully connected layer with a Sigmoid activation. This allows the model to dynamically weigh the importance of spectral texture versus temporal shape for each sample.

# Data

**Input Representation: Multi-Resolution Log-Mel Spectrograms**
For each audio clip, two distinct Log-Mel Spectrograms will be generated:
1.  **High-Frequency Input:** Generated with **384 Mel bands** (Cite solution_lesson_node_00017) and a longer window size (e.g., 40-50ms) to maximize spectral definition.
2.  **High-Temporal Input:** Generated with **128 Mel bands** (Cite solution_lesson_node_00010) and a short window/hop length (e.g., 10ms) to maximize temporal fidelity (Cite solution_lesson_node_00006).

**Normalization**
Both inputs will be independently normalized using **Instance-level Min-Max Normalization**. This preserves the spectral contrast (relative energy) of the signal, which was found to be superior to frequency-wise standardization (Cite solution_lesson_node_00015).

# Training

**Loss Function: Weighted Binary Cross-Entropy**
The model will be trained using **Binary Cross-Entropy Loss weighted by the inverse class frequency** (approx. 9.0 for positive samples). This remains the most effective method for handling the dataset's imbalance (Cite solution_lesson_node_00001).

**Regularization & Augmentation**
*   **Synchronized Mixup:** **Mixup** augmentation will be applied to both streams simultaneously (using the same mixing coefficient $\lambda$ for both inputs). The loss will be calculated by mixing the **weighted scalar losses** of the pair to preserve minority class gradients (Cite solution_lesson_node_00005).
*   **SpecAugment:** Random time and frequency masking will be applied to both spectrogram inputs to encourage robust feature learning (Cite solution_lesson_node_00003).

**Optimization**
The model will be optimized using **AdamW** with a **Cosine Annealing Learning Rate Scheduler** to ensure stable convergence (Cite solution_lesson_node_00003).

# Evaluation

**Inference Strategy**
*   **Preprocessing:** Test clips will be processed into the same dual-spectrogram format (384-Mel and 128-Mel) used in training.
*   **Checkpoint Reloading:** The training pipeline will monitor Validation AUC and save the best model state. Before generating the final submission, the system will explicitly **reload these best-saved weights**, ensuring the predictions reflect the model's peak performance rather than the final epoch's state (Cite solution_lesson_node_00008).
