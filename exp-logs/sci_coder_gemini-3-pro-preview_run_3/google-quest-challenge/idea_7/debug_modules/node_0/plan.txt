### Implementation Strategy

1.  **Configuration Override**: To ensure the demonstration runs quickly (under 1 hour) and uses minimal resources, we first import the `Config` class and modify its attributes. We switch the backbone model to `prajjwal1/bert-tiny` (a very small, fast model), reduce the number of epochs to 1, set the number of folds to 2, and shorten the maximum sequence length to 32.
2.  **Environment Setup**: We clean and recreate the working directory (`./working/demo_run`) to ensure a fresh run.
3.  **Monkey-Patching**: We override the `get_tokenizer` function in the `library.dataset` module. This is necessary because the original function's default argument is evaluated at import time (pointing to the large Deberta model). Our patch ensures the data preparation pipeline uses the tokenizer corresponding to our tiny demo model.
4.  **Pipeline Execution**:
    *   **DAPT**: Run Domain-Adaptive Pre-Training for 1 epoch.
    *   **Fine-Tuning**: Run Supervised Fine-Tuning with 2-fold cross-validation. This generates Out-of-Fold (OOF) features and test predictions.
    *   **Stacking**: Train the Level 1 and Level 2 Ridge regressors to generate the final submission.
5.  **Validation**: We verify the existence and shape of the generated artifacts (model weights, feature arrays, submission file) using assertions to guarantee correctness.
