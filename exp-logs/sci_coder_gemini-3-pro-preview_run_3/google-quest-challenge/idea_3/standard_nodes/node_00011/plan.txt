The implementation strategy follows the orchestration of a Cross-Encoder pipeline with Segment-Aware Feature Extraction.

1.  **Setup & Data Loading**: The script initializes the random seed and loads the training and validation data using `library.dataset.load_data`. It constructs `QuestDataset` and `DataLoader` instances with appropriate batch sizes and worker settings to optimize throughput on the A100 GPU.
2.  **Backbone Training**: It executes `library.engine.run_backbone_training` to fine-tune the MPNet Cross-Encoder. This step learns the joint representation of Question-Answer pairs.
3.  **Feature Extraction**: It calls `library.feature_pipeline.run_feature_extraction` with `load_cached_data=False`. This forces the system to run inference using the newly trained backbone, extracting the segment-aware features ($h_{CLS}, h_{Q}, h_{A}, h_{diff}$) and caching them to disk as `.npy` files.
4.  **Ridge Regression**: It runs `library.ridge_head.train_ridge_and_predict` to train the Ridge Regression head on the extracted features and generate the initial `submission.csv`.
5.  **Validation & Failure Analysis**:
    *   The script manually re-loads the cached validation features and the trained Ridge model.
    *   It computes the **Final Validation Metric** (Mean Column-wise Spearman Correlation) and prints it in the required format.
    *   It performs failure analysis by calculating the Mean Absolute Error (MAE) for each validation sample and computing the Spearman correlation between this error magnitude and input text lengths (Question Body, Answer, Question Title).
6.  **Conditional Submission**: It compares the final validation metric against the specified threshold (`0.39678116179820055`). If the metric is insufficient, the `submission.csv` file generated in step 4 is deleted to strictly comply with the "If and only if" requirement.
