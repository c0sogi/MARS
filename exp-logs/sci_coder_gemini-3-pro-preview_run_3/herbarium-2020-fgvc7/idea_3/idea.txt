Based on the progression of experiments and the specific challenges of this fine-grained, long-tailed dataset (32,093 classes), I propose the following solution. This approach evolves the architecture from a simple classification network to a **Hierarchical Multi-Task Learning** framework, leveraging the biological taxonomy to regularize the learning of rare species.

# Proposed Solution: Hierarchical ResNet-50 with ArcFace and Multi-Task Regularization

### Model
*   **Backbone Architecture:** Upgrade the backbone to **ResNet-50**. The previous experiments with ResNet-18 provided a fast baseline, but a deeper network is required to capture the subtle, fine-grained features necessary to distinguish between over 32,000 plant species.
*   **Primary Head (Species):** Retain the **ArcFace (Additive Angular Margin)** head for the species classification task. As demonstrated in previous results, optimizing for angular margin significantly outperforms standard linear classification for high-cardinality datasets by enforcing intra-class compactness. Cite {solution_lesson_node_00012}
*   **Auxiliary Head (Genus - Structural Innovation):** Introduce a secondary **Cross-Entropy Classification Head** that predicts the **Genus** of the plant.
    *   *Rationale:* A major bottleneck is the "tail" where thousands of species have only 1-2 images. However, these rare species often belong to genera that, in aggregate, have many samples. By forcing the backbone to predict the genus, we ensure that the feature extractor learns robust botanical characteristics shared across the genus, effectively transferring knowledge from frequent species to rare species within the same biological group.

### Data
*   **Taxonomy Mapping:** During the metadata generation phase, parse the `categories` table in `metadata.json` to create a mapping from `category_id` (Species) to `genus` (and optionally `family`). This label will be used for the auxiliary head.
*   **Sampling Strategy:** Employ **Inverse Square-Root Weighted Random Sampling** ($1/\sqrt{N}$). This has been proven to balance the representation of head and tail classes better than aggressive inverse-frequency sampling ($1/N$), which leads to overfitting. Cite {solution_lesson_node_00007}
*   **Artifact Validation:** Explicitly implement checks when loading cached data (e.g., sampling weights). The code must verify that the length of the cached file matches the current dataset size to prevent silent failures where DataLoaders operate on stale, mismatched indices. Cite {solution_lesson_node_00010}
*   **Preprocessing:** Resize images to **224x224** and apply standard normalization.

### Training
*   **Loss Function:** Minimize a weighted multi-task loss: $L_{total} = L_{ArcFace}(Species) + \lambda \cdot L_{CE}(Genus)$.
*   **Optimizer:** Use **SGD with Momentum** (0.9) and Weight Decay ($1e-4$).
*   **Training Duration:** Train for **20-25 epochs**. Since we are using a deeper backbone, strong regularization (ArcFace), and data augmentation, the model requires a longer training horizon to converge compared to the under-regularized baselines. Cite {solution_lesson_node_00008}
*   **Validation:** Use a **Stratified Subset** of the training data. This ensures that the validation set accurately reflects the long-tail distribution and includes rare classes, which are otherwise statistically likely to be dropped in a random subset. Cite {solution_lesson_node_00004}

### Evaluation
*   **Inference:** During the test phase, only the output from the **Primary Species Head (ArcFace)** is used. The Genus head is discarded as it serves only as a regularizer during training.
*   **Prediction:** Compute the cosine similarity between the test image embedding and the learned ArcFace class centers, selecting the class with the highest similarity.
