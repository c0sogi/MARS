The following script demonstrates the end-to-end usage of the provided library modules for the ink detection task.

**Implementation Strategy:**
1.  **Environment Setup:** We define a temporary working directory (`./working/demo_execution`) to store outputs and cache. To ensure the script runs within the time limit, we attempt to symlink pre-computed `.npy` data files (volumes, masks, labels) from the provided `./working/demo_cache` directory. This avoids the computationally expensive step of loading and stacking 3D TIFF volumes from scratch.
2.  **Configuration Overrides:** We modify the static `Config` class attributes to adapt the pipeline for a quick demonstration. This includes reducing the number of epochs to 1, setting a very small number of training samples per epoch, disabling Test-Time Augmentation (TTA), and increasing the validation stride to speed up inference.
3.  **Component Verification:** We explicitly verify the correctness of key utility functions (`rle_encode`, `fbeta_score`), the model architecture (`FRDUNet` forward pass and output shape), and the loss function (`BCEDiceLoss`).
4.  **Training Execution:** We execute the `train_model` function, which initializes the datasets, runs the training loop for the reduced number of steps, performs validation, and saves the best model checkpoint.
5.  **Inference Execution:** We execute the `generate_submission` function, which loads the saved model, (optionally) optimizes the threshold, generates predictions for the test set, and creates the `submission.csv` file.
6.  **Result Validation:** Finally, we verify that the output files exist and contain the expected data format.
