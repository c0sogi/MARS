The `RuntimeError: expected scalar type Double but found Float` occurs because the normalization statistics (`mean`, `std`) loaded from `normalization_stats.npy` are 64-bit floats (Double). When applied to the image data, they promote the resulting tensor to `Double` precision, causing a mismatch with the model's 32-bit `Float` weights. I will explicitly cast the normalized data back to `float32` in `library/dataset.py`.

Additionally, I will update the `f05_score` function in `library/utils.py` to use the direct F-beta formula with smoothing. This prevents the metric from collapsing to 0.0 when both the prediction and ground truth are empty (a correct "no ink" prediction), ensuring stability for sparse segmentation tasks. Cite debug_lesson_1.
