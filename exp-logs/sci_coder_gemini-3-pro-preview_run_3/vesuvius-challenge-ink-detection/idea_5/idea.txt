Based on the comprehensive analysis of previous experiments and lessons learned, I propose the **Deep Sequential Dilated Network with Group Normalization (DSDN-GN)**.

This solution addresses the primary bottleneck identified in recent failures: the trade-off between **Model Capacity** and **Training Stability**. Previous attempts to increase capacity (Idea 4) failed because the resulting memory constraints forced small batch sizes, which destabilized Batch Normalization (Lesson 00025). This proposal resolves that conflict by structurally decoupling normalization statistics from batch size, enabling the training of a much deeper, high-capacity model required to resolve complex ink textures (Lesson 00017) without sacrificing the critical spatial context (Lesson 00019).

### Model: Deep Sequential Dilated Network with Group Normalization (DSDN-GN)

The architecture is a high-capacity, fully convolutional network designed to operate at full resolution, utilizing a batch-independent normalization scheme to ensure stability.

1.  **Learnable 2.5D Projection (Input Stage):**
    The network accepts the full 3D volume `(Batch, 65, H, W)` and initializes with a learnable `1x1` convolution to compress the depth dimension into a compact feature space (e.g., 32 channels). This retains the highly effective "soft" slice selection mechanism verified in previous experiments **Cite solution_lesson_node_00002**.

2.  **Deep Sequential Dilated Backbone:**
    To address the underfitting observed in shallower models **Cite solution_lesson_node_00017**, this backbone significantly increases depth (e.g., 16-20 residual blocks).
    *   **Sequential Hierarchy:** The blocks are arranged with sequentially increasing dilation rates (e.g., $r=1, 2, 4, 8, 16, 1, 2, \dots$). This structure builds receptive fields hierarchically—assembling edges into textures, and textures into shapes—which was proven superior to parallel aggregation for feature extraction **Cite solution_lesson_node_00015**.
    *   **Full Resolution:** The network uses **no downsampling (pooling)** layers. It maintains the original spatial resolution throughout to preserve fine, pixel-thin ink traces **Cite solution_lesson_node_00008**.

3.  **Group Normalization (Structural Innovation):**
    All Batch Normalization (BN) layers within the residual blocks are replaced with **Group Normalization (GN)**.
    *   **Rationale:** Increasing model depth and maintaining large patch sizes puts significant pressure on GPU memory, often forcing a reduction in batch size (e.g., to 8 or 4). Previous experiments showed that BN fails in this regime, causing instability and divergence **Cite solution_lesson_node_00025**. GN computes statistics per sample (grouping channels), making it invariant to batch size. This allows us to train this "Deep" model stably, even with small batches.

4.  **Lean Channel Width:**
    To balance the parameter increase from added depth, the channel width is kept constant and lean (e.g., 32 or 48) throughout the backbone. This acts as a structural regularizer to prevent overfitting to spatial noise **Cite solution_lesson_node_00004**.

### Data: High-Fidelity Context and Deterministic Validation

1.  **Preprocessing:**
    Input volumes are Z-score normalized using global training statistics (mean/std) to ensure consistent intensity distributions.

2.  **Patch Size & Augmentation:**
    *   **Large Context:** Training will strictly use **large patches (256x256 minimum)**. We explicitly reject the strategy of reducing patch size to gain throughput, as this destroys the structural context required for ink recognition **Cite solution_lesson_node_00019**.
    *   **Geometric Augmentation:** Random horizontal/vertical flips and discrete 90-degree rotations will be applied to force the model to learn rotationally invariant features, critical for distinguishing ink from oriented fibers **Cite solution_lesson_node_00005**.

3.  **Deterministic Validation:**
    Validation will be performed on a **large, fixed grid of tiles** covering the validation fragment. This eliminates the metric volatility caused by stochastic sampling, ensuring that improvements in the F0.5 score reflect genuine model progress rather than sampling noise **Cite solution_lesson_node_00010**, **Cite solution_lesson_node_00007**.

### Training: Balanced Optimization

1.  **Loss Function:**
    The model will be trained using a **Balanced Loss** (e.g., `BCE + Dice`). We will explicitly avoid using Tversky Loss with high alpha (precision bias) during training. Optimizing a balanced objective produces a higher quality probability landscape; the precision requirement will be handled via threshold tuning **Cite solution_lesson_node_00011**, **Cite solution_lesson_node_00009**.

2.  **Optimization Strategy:**
    *   **Optimizer:** AdamW with a standard learning rate.
    *   **Patience:** We will adhere to a strict early stopping patience (e.g., 3-5 epochs) based on the stabilized validation metric. We will not extend patience in hopes of overcoming volatility, as the deterministic validation grid solves the root cause **Cite solution_lesson_node_00006**.

### Evaluation: Precision-Oriented Inference

1.  **Tiled Inference with TTA:**
    Predictions will be generated using overlapping tiles. **Test-Time Augmentation (TTA)** (averaging predictions across 4 rotations and 2 flips) will be applied. This is computationally expensive but essential for suppressing false positives caused by specific fiber orientations **Cite solution_lesson_node_00005**.

2.  **Dynamic Threshold Tuning:**
    Instead of a fixed 0.5 threshold, the optimal binarization threshold will be explicitly searched for on the validation set to maximize the F0.5 score. This effectively adapts the balanced model output to the competition's precision-weighted metric **Cite solution_lesson_node_00011**.
