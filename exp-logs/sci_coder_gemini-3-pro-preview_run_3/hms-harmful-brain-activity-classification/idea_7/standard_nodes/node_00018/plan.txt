The implementation strategy follows the requirements to create a fast, reproducible, and complete baseline for the brain activity classification task.

1.  **Configuration & Setup**: We import the provided library modules (`config`, `utils`, `data_loader`, `model`, `engine`). We modify the `Config` class attributes to define a "Fast Baseline" mode: limiting the training set to 10,000 samples and epochs to 6. This ensures the code completes well within the 2-hour limit while providing enough data for convergence. Random seeds are fixed for reproducibility.
2.  **Data Preparation**: We load the metadata CSVs from the `./metadata` directory. The training dataframe is shuffled and subsampled. The validation and test dataframes are kept intact to ensure accurate metrics and submission. We utilize `get_dataloaders` to efficiently handle data loading and caching.
3.  **Training Loop**: We implement a custom training loop (orchestrating `train_one_epoch` and `validate` from `library.engine`) to have precise control over checkpointing. We use the AdamW optimizer and Cosine Annealing scheduler as specified. The best model (lowest Validation KL) is saved to `./working`.
4.  **Validation & Metrics**: After training, we reload the best model and perform a full inference pass on the validation set. We calculate the Kullback-Leibler divergence and print it in the required format: `Final Validation Metric: <value>`.
5.  **Failure Analysis**: We compute the KL divergence for each validation sample individually. We then calculate the Pearson correlation between these error values and metadata features (specifically `total_votes` and label offsets) to identify if the model struggles with specific data characteristics (e.g., low annotator agreement).
6.  **Submission**: We check if the `Final Validation Metric` is strictly less than `1.0065`. If this condition is met, we generate predictions for the test set using the best model and save the result to `./submission/submission.csv` in the correct format.
