The issue is that the `SwinBackbone` initializes the `timm` model with the default resolution of 224x224, causing an assertion error when processing 640x640 images. Furthermore, `timm`'s Swin Transformer implementation outputs feature maps in Channel-Last format `(N, H, W, C)`, while the downstream `DyHead` and `ATSSHead` (built with standard `nn.Conv2d` layers) expect Channel-First format `(N, C, H, W)`.

I will fix this by:
1.  Passing `img_size=Config.IMG_SIZE` to `timm.create_model` in `SwinBackbone.__init__`.
2.  Permuting the output features in `SwinBackbone.forward` to match the expected layout (Cite debug_lesson_11).
