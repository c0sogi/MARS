# Idea 8: Multi-Task Deformable DETR with Unified Query Interaction

## Model
I propose a **Multi-Task Deformable DETR (Detection Transformer)** architecture. This represents a fundamental structural evolution from the region-based CNN detectors (Cascade R-CNN) and one-stage detectors (YOLO) of previous ideas, shifting to a query-based set prediction paradigm.

-   **Backbone**: I will use a **ResNet-50** backbone to extract multi-scale feature maps. This balances the high computational cost of the Transformer head with a standard, efficient feature extractor.
-   **Transformer Encoder-Decoder (Structural Innovation)**:
    -   **Deformable Attention**: Unlike standard Transformers, the encoder/decoder will use Deformable Attention modules, which attend to a small set of key sampling points around a reference. This allows the model to process high-resolution feature maps (crucial for small opacities) without the quadratic complexity of global attention.
    -   **Unified Query Mechanism**: I will introduce a **Hybrid Query Set** into the decoder.
        1.  **Object Queries**: Standard learnable embeddings ($N$ queries) responsible for detecting and localizing "opacity" instances.
        2.  **Study Query**: A dedicated, learnable "Global Diagnosis" token ($1$ query) inserted alongside the object queries.
    -   **Interaction**: Through the decoder's self-attention layers, the **Study Query** will dynamically interact with the **Object Queries**. This explicitly models the diagnostic reasoning process: the study prediction is derived not just from global image statistics, but from the aggregation and arrangement of the specific detected findings (Object Queries).
-   **Heads**:
    -   **Detection Head**: Predicts box coordinates and binary "opacity" class for each Object Query.
    -   **Classification Head**: A separate Multi-Layer Perceptron (MLP) attached to the Study Query output to predict the four study-level categories ("Negative", "Typical", "Indeterminate", "Atypical").

## Data
-   **Preprocessing (Strategic Retention)**: I will strictly implement **Letterbox Resizing** for all input images. Instead of warping the image to a square, I will resize the longest dimension to the target size (e.g., 800 pixels) and pad the shorter dimension with zeros. This preserves the original aspect ratio of the radiograph, preventing the morphological distortion of lung opacities that was identified as a critical failure mode in direct resizing approaches **Cite solution_lesson_node_00010**.
-   **Augmentation**: I will employ **Multi-Scale Training** (resizing the shortest side within a range) and **Random Horizontal Flipping**. I will avoid "Mosaic" augmentation to preserve the global anatomical structure necessary for the Study Query to learn spatial dependencies.

## Training
-   **Loss Function**: The model will be trained end-to-end using a bipartite matching loss:
    -   **Object Loss**: A linear combination of **Focal Loss** (for class probability), **L1 Loss** (for box coordinates), and **GIoU Loss** (for box overlap), calculated between the predicted object queries and ground truth boxes via Hungarian Matching.
    -   **Study Loss**: **Cross-Entropy Loss** applied to the output of the Study Query against the study-level label.
-   **Optimizer**: I will use **AdamW**, which is essential for training Transformer-based architectures, with a lower learning rate for the backbone and a higher learning rate for the Transformer components.

## Evaluation
-   **Inference**: A single forward pass produces outputs for all queries.
-   **Prediction Logic**:
    1.  **Study Level**: The label is determined by the argmax of the Study Query's output.
    2.  **Image Level**:
        -   If the Study Label is "Negative for Pneumonia", the image prediction is forced to `none 1 0 0 1 1`.
        -   Otherwise, the bounding boxes predicted by the Object Queries are filtered by a confidence threshold. Note that **Non-Maximum Suppression (NMS) is NOT required**, as the DETR architecture inherently learns to perform set prediction without duplicate boxes.
    3.  **Submission**: The study label and the formatted prediction string are combined for the final CSV.
