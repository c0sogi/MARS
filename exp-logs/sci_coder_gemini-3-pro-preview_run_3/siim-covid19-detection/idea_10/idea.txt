# Idea 10: Co-DETR with Collaborative Hybrid Supervision and Relational Diagnosis Query

## Model
I propose a **Multi-Task Co-DETR (Collaborative Detection Transformer)** architecture. This represents a structural evolution from the standard Deformable DETR (Idea 8) and the individual CNN-based detectors (Idea 5, 7) by introducing a **Collaborative Hybrid Training Scheme** that unifies the strengths of one-stage, two-stage, and query-based detectors.

-   **Backbone**: I will employ a **Swin Transformer Large (Swin-L)** backbone. This hierarchical transformer provides the necessary capacity to capture both fine-grained features (for small opacities) and global context (for diffuse patterns), surpassing the ResNet-50 used in Idea 8.
-   **Collaborative Hybrid Encoder (Structural Innovation)**: Standard DETRs (Idea 8) often suffer from slow convergence and limited feature discrimination. To address this, I will attach **two auxiliary detection heads**—specifically an **ATSS Head** (Anchor-free One-stage) and a **Faster R-CNN Head** (Two-stage)—to the output of the Deformable Encoder. These heads are **only used during training** to provide dense, diverse supervision signals to the encoder, forcing it to learn robust features that satisfy multiple detection paradigms simultaneously. This "collaborative" approach significantly boosts the performance of the main DETR decoder.
-   **Relational Diagnosis Decoder**:
    -   **Object Queries**: A set of learnable queries responsible for detecting "opacity" bounding boxes.
    -   **Diagnosis Query**: I will insert a dedicated **Global Diagnosis Query** into the decoder. Through the decoder's self-attention mechanism, this query dynamically interacts with the Object Queries. This explicitly models the diagnostic reasoning process as a **relation** between the detected findings (e.g., "multiple bilateral opacities imply Typical"), rather than just aggregating global image statistics.

## Data
-   **Preprocessing (Strategic Retention)**: I will strictly implement **Letterbox Resizing** for all training and test images. Instead of warping images to a fixed square, I will resize the longest dimension to the target size (e.g., 1024 pixels) and pad the shorter dimension with zeros. This preserves the original aspect ratio of the radiographs, preventing the morphological distortion of lung opacities that was identified as a critical failure mode **Cite solution_lesson_node_00010**.
-   **Augmentation**: I will employ **Large Scale Jittering (LSJ)**, which resizes images with a scale range (e.g., 0.1 to 2.0) followed by fixed-size cropping/padding, ensuring the aspect ratio is maintained. I will also use **Random Horizontal Flipping**. I will explicitly exclude "Mosaic" to preserve the global anatomical structure required for the Diagnosis Query.

## Training
-   **Loss Function**: The model will be trained end-to-end using a comprehensive multi-task objective:
    $$L_{total} = L_{DETR} + \lambda_1 L_{Aux\_ATSS} + \lambda_2 L_{Aux\_RCNN} + \lambda_3 L_{Study}$$
    -   $L_{DETR}$: Hungarian matching loss (Focal + L1 + GIoU) for the main decoder outputs.
    -   $L_{Aux\_ATSS}$ & $L_{Aux\_RCNN}$: Standard detection losses for the auxiliary heads, providing intermediate supervision.
    -   $L_{Study}$: Cross-Entropy loss for the Diagnosis Query output.
-   **Optimizer**: **AdamW** with a layer-wise learning rate decay (lower rates for the backbone) to stabilize the training of the Swin Transformer.

## Evaluation
-   **Inference**: During inference, the **auxiliary heads (ATSS and Faster R-CNN) are discarded**. The input image passes through the Backbone and the DETR Encoder-Decoder.
-   **Prediction Logic**:
    1.  **Study Level**: The label is determined by the argmax of the **Diagnosis Query's** output.
    2.  **Image Level**:
        -   If the Diagnosis Query predicts "Negative for Pneumonia", the image prediction is forced to `none 1 0 0 1 1`.
        -   Otherwise, the bounding boxes predicted by the **Object Queries** are used. Since DETR performs set prediction, **Non-Maximum Suppression (NMS) is not required**, simplifying the pipeline. The boxes are formatted as the "opacity" prediction string.
