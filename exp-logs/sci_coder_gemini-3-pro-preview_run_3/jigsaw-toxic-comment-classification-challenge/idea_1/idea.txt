# Proposed Baseline Approach: NBSVM (Naive Bayes - Logistic Regression)

## Model
I propose a **NBSVM (Naive Bayes - Support Vector Machine)** architecture, interpreted here as a Naive Bayes-weighted Logistic Regression. This approach is a strong, lightweight baseline for text classification that often outperforms standard linear models and simple neural networks on toxicity detection tasks.

The architecture follows a **Binary Relevance** strategy, treating the multi-label problem as six independent binary classification problems. For each label, the model consists of:
1.  **Sparse Feature Representation**: A high-dimensional representation of text using n-grams.
2.  **Naive Bayes Weighting**: An intermediate layer that scales feature values by their log-odds ratio (the likelihood of the feature appearing in the toxic class vs. the clean class). This effectively "pre-activates" features that are strong signals for toxicity.
3.  **Linear Classifier**: A Logistic Regression layer that takes the weighted features and outputs a probability.

## Data
Preprocessing and feature engineering will prioritize retaining information while managing dimensionality:
1.  **Cleaning**: Minimal preprocessing will be applied. Missing values will be filled with empty strings, and text will be lowercased. We will avoid aggressive stemming or stop-word removal, as specific function words and precise spellings can be indicative of tone.
2.  **Vectorization**: We will generate two separate TF-IDF (Term Frequency-Inverse Document Frequency) matrices:
    *   **Word n-grams**: (1, 2) range to capture individual toxic words and short phrases.
    *   **Character n-grams**: (2, 6) range to capture subword structures, which makes the model robust to intentional misspellings and obfuscation (e.g., "sh!t").
3.  **Combination**: These two sparse matrices will be horizontally concatenated to form the final feature set for the model.

## Training
The training process focuses on speed and handling class imbalance via the NB-weighting scheme:
1.  **Log-Count Ratio Calculation**: For each of the 6 target columns:
    *   Compute the probability of each feature occurring in positive samples ($p$) and negative samples ($q$).
    *   Calculate the log-count ratio vector $r = \log(p/q)$.
2.  **Feature Scaling**: Multiply the training TF-IDF matrix element-wise by $r$. This transforms the generic frequency features into class-specific relevance features.
3.  **Optimization**: Train a Logistic Regression classifier on these scaled features. We will use the **L-BFGS** or **liblinear** solver, which are highly optimized for wide, sparse datasets. L2 regularization will be used to ensure generalization.

## Evaluation
1.  **Transform**: The test set will be vectorized using the fitted TF-IDF vectorizers from the training step.
2.  **Scale & Predict**: For each of the 6 models:
    *   Scale the test features using the specific log-count ratio $r$ calculated for that label during training.
    *   Predict probabilities using the trained Logistic Regression model.
3.  **Output**: Concatenate the predictions into the required submission format.
