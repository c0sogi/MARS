# Proposed Solution: Homogeneous Bagged Ensemble of Linear Discriminant Analysis with Multi-View Self-Supervised Features

## Model
The proposed architecture represents a structural evolution from the previous "Hybrid Deep-Linear" ensembles to a **Homogeneous Bagged Ensemble of Linear Discriminant Analysis (LDA)**. This design explicitly rejects the inclusion of Logistic Regression or other discriminative classifiers, addressing the "Ensemble Contamination" and "Boundary Precision" issues identified in previous iterations (Cite solution_lesson_node_00013, solution_lesson_node_00014).

1.  **Dual-Stream Feature Extraction**:
    *   **Global Geometry Stream**: We will utilize **DINOv2 (ViT-Large)**. As a self-supervised Vision Transformer, DINOv2 is trained to understand object geometry and part-whole relationships without reliance on texture labels, providing a superior inductive bias for binary leaf shapes compared to supervised models.
    *   **Local Texture Stream**: We will employ **ConvNeXt Large**. This modern CNN architecture captures high-frequency margin details and generates feature manifolds that are more linearly separable than traditional ResNets (Cite solution_lesson_node_00019).
2.  **Classifier**: The classification head will be a **Bagging (Bootstrap Aggregating) Ensemble of $K$ LDA models**. By training multiple LDA instances on bootstrapped subsets of the data, we directly address the variance inherent in estimating covariance matrices in "High Dimension, Low Sample Size" (HDLSS) regimes (Cite solution_lesson_node_00021).

## Data
1.  **Multi-View Canonical Averaging**: To enforce strict rotation invariance in the feature space, we will generate 4 canonical rotated views (0°, 90°, 180°, 270°) for every image. We will extract embeddings for all views using both backbones and compute the **element-wise average** of the raw embeddings. This creates a robust, orientation-invariant representation for each sample before any dimensionality reduction occurs (Cite solution_lesson_node_00017).
2.  **Independent Dimensionality Reduction**: We will apply **Principal Component Analysis (PCA)** independently to the averaged embeddings of the DINOv2 and ConvNeXt streams. We will retain **99% of the variance** for each, ensuring that subtle discriminative signals in the tail of the spectrum are preserved (Cite solution_lesson_node_00019).
3.  **Tabular Gaussianization**: The 192 engineered features (margin, shape, texture) will be transformed using a **Quantile Transformer (Output distribution = Normal)**. This explicitly aligns the non-Gaussian histogram data with the normality assumptions of the downstream LDA classifier (Cite solution_lesson_node_00021).
4.  **Fusion**: The final feature vector is the concatenation of the PCA-reduced DINOv2 embeddings, PCA-reduced ConvNeXt embeddings, and Gaussianized tabular features.

## Training
The training process utilizes a **Bagging** strategy rather than a simple train/validation split:
1.  **Feature Extraction**: Perform the multi-view extraction and averaging for the entire dataset once.
2.  **Ensemble Construction**: We will train $K=20$ independent LDA models. For each model $k$:
    *   **Bootstrap**: Sample the training data with replacement to create a bootstrap dataset.
    *   **Fit Transformers**: Fit the PCA and Quantile Transformers solely on this bootstrap sample to prevent data leakage.
    *   **Fit Classifier**: Train an **LDA model with Ledoit-Wolf shrinkage** on the transformed bootstrap data. The shrinkage is critical for regularizing the covariance matrix in this high-dimensional space (Cite solution_lesson_node_00009).
    *   **Discard Weak Learners**: We explicitly exclude Logistic Regression from this pipeline to prevent the "contamination" observed when mixing models with vastly different performance profiles (Cite solution_lesson_node_00013).

## Evaluation
1.  **Inference**: For each test sample, generate the multi-view averaged embeddings and raw tabular features.
2.  **Ensemble Prediction**: Pass the raw features through each of the $K$ saved pipelines (Transformer + LDA). Each pipeline will project the data and predict a probability vector.
3.  **Aggregation**: Compute the **arithmetic mean** of the probability vectors from all $K$ models. This averaging stabilizes the decision boundaries and minimizes the risk of overfitting to specific artifacts in the training set.
4.  **Formatting**: Apply the required probability clipping ($[10^{-15}, 1-10^{-15}]$) and format the final CSV.
