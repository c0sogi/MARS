### Implementation Strategy

1.  **Configuration Override**: We will modify the static `Config` class attributes to point to a temporary working directory (`./working/demo_run`) and use a subset of the data. This ensures the demo runs quickly without modifying the original input or metadata files.
2.  **Data Subsetting**: We will load the existing metadata files (`./metadata/train.csv` and `./metadata/test.csv`), select a small sample (e.g., 4 images), and save these as demo metadata files. This drastically reduces the runtime of the heavy feature extraction (DINOv2/ConvNeXt).
3.  **Feature Extraction**: We will invoke `run_feature_extraction` with `load_cached_data=False` to demonstrate the dual-stream (Geometry + Texture) extraction and 12-view rotation logic on the subset.
4.  **Data Processing**: We will instantiate `DataProcessor` to transform the raw 12-view features into densified orthogonal centroids (3 samples per image), verifying the shape transformations.
5.  **Model Training**: We will use `train_fold` to train the LDA pipeline on the densified training data. We will use the same small set for validation to demonstrate the API mechanics.
6.  **Inference & Submission**: We will generate predictions using `generate_submission`, which performs the Full-Manifold Test-Time Aggregation, and verify the final output format.
7.  **Validation**: Assertions are placed after every major step to verify data shapes, types, and value ranges.
