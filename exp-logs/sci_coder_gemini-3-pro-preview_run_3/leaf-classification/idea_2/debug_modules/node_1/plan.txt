The issue arises because the `DEBUG` mode aggressively subsamples the dataset (50 samples), leading to a situation where the validation set contains species classes that were not present in the training set. When `sklearn.metrics.log_loss` is called, it detects a mismatch between the number of classes in the truth labels (`y_val`) and the predicted probabilities (`lr_preds_val`), causing a `ValueError`.

To fix this, I will implement a `safe_log_loss` helper function within the `train_models` method. This function will filter the validation data to include only samples belonging to classes seen during training before calculating the metric. This ensures the pipeline can evaluate performance on the overlapping classes without crashing due to disjoint sets in debug mode.
