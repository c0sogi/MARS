Based on the progression of previous experiments and the specific insights from **Lesson 00006**, **Lesson 00010**, and **Lesson 00014**, I propose the **Dual-View Attentive Graph Network (DV-AGN)**.

This strategy is a structural evolution of the "Dual-Frame" approach (Idea 7). While Idea 7 successfully introduced the concept of using both raw and canonical coordinates, it fused them at the *input level* (concatenation), forcing a single GNN backbone to simultaneously learn to trust the SVD alignment (for tracks) and correct for it (for cascades). The **DV-AGN** decouples these tasks into two parallel processing streams—one specialized for the physics-aligned frame and one for the raw detector frame—fused by an attention mechanism that dynamically weighs the reliability of the geometric prior.

# Proposed Solution: Dual-View Attentive Graph Network (DV-AGN)

### Model
The architecture consists of a two-tower Graph Neural Network that processes the event in parallel coordinate systems, followed by an attentional fusion layer.

1.  **Dual-View Encoders (Structural Innovation):**
    *   **Canonical Stream (The "Fine-Tuner"):** This stream receives the point cloud transformed into the **Canonical Frame** (aligned via SVD, Cite solution_lesson_node_00014). Since the gross rotation is removed, this encoder focuses on extracting fine-grained trajectory details and deviations from the principal axis.
    *   **Raw Stream (The "Anchor"):** This stream receives the point cloud in **Raw Coordinates** $(x, y, z)$. It acts as a fail-safe, preserving the absolute detector geometry to handle "blob-like" cascade events where the SVD alignment might be noisy or arbitrary.
    *   **Backbone:** Both streams utilize **Dynamic Edge Convolution (DynEdge)** blocks. The graph topology in both streams is constructed using the **Spatiotemporal k-NN** metric ($D^2 = \Delta \vec{x}^2 + \alpha \Delta t^2$) to strictly preserve the causal structure of the particle track (Cite solution_lesson_node_00010).

2.  **Cross-View Attention Fusion:**
    Instead of simple concatenation, the node embeddings from both streams are fused using a **Cross-Attention Mechanism**. The model learns to query the Raw Stream using the Canonical Stream (and vice versa).
    *   *Intuition:* If the event is a clear track, the Canonical Stream's features will be highly coherent, and the attention weights will favor it. If the event is a cascade (noisy SVD), the Canonical features will be inconsistent, and the model will attend more heavily to the Raw Stream's spatial context.

3.  **Global Pooling & Prediction Head:**
    The fused features are aggregated using a Global Attention Pooling layer (to weigh high-information pulses) and passed to an MLP that regresses the 3D unit vector $(n_x, n_y, n_z)$.

### Data
1.  **Geometry Merging:**
    Merge `sensor_geometry.csv` with the pulse data to obtain $(x, y, z, t, q)$.

2.  **Canonical Frame Computation (Cite solution_lesson_node_00014):**
    For every event:
    *   Compute the charge-weighted covariance matrix of pulse positions.
    *   Perform SVD to extract the principal axis $\vec{v}_1$.
    *   **Orientation Correction:** Calculate the covariance between the projection of positions onto $\vec{v}_1$ and time $t$. If negative, flip $\vec{v}_1$ to ensure the axis points in the direction of time flow.
    *   Generate **Canonical Coordinates** $(x', y', z')$ by rotating the event such that $\vec{v}_1$ aligns with the Z-axis.

3.  **Hybrid Sampling:**
    Sample a fixed number of pulses (e.g., $N=196$) per event. Use a 50/50 mix of **highest charge** (to capture the energy core) and **earliest time** (to capture the track start), ensuring the input contains the necessary spatiotemporal signal (Cite solution_lesson_node_00006).

### Training
*   **Loss Function:** **Cosine Similarity Loss** ($L = 1 - \vec{y}_{true} \cdot \vec{y}_{pred}$). This directly optimizes the angular alignment, which is the competition metric, and avoids the scale ambiguity of MSE (Cite solution_lesson_node_00010).
*   **Optimizer:** **AdamW** with a **OneCycleLR** scheduler. This schedule provides a warm-up phase to stabilize the gradients in the dual-stream architecture before aggressive annealing.
*   **Strategy:** Train on the GPU. The parallel streams increase memory usage slightly, but the separation of concerns (Alignment vs. Robustness) should lead to faster convergence and a lower error floor than the single-stream approach.

### Evaluation
1.  **Inference:**
    *   Load test batches.
    *   Compute SVD and generate the Canonical View for each event.
    *   Pass both the Canonical View and Raw View to the DV-AGN.
2.  **Prediction:**
    *   The model outputs the predicted direction vector $\vec{v}_{pred}$.
3.  **Post-Processing:**
    *   Normalize $\vec{v}_{pred}$ to unit length.
    *   Convert to spherical coordinates (`azimuth`, `zenith`) and generate the submission CSV.
