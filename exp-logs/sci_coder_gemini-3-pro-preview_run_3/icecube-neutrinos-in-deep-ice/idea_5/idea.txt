# Proposed Solution: Attentive Dynamic Graph Network with Geometric Priors

### Model
The architecture is a **Hybrid Geometric Deep Learning Model** that combines the local feature extraction capabilities of Dynamic Graph Neural Networks with the global context modeling of Transformers.

1.  **Backbone: Dynamic Edge Convolution (DynEdge):**
    Instead of a static graph or simple MLP (Idea 1), the model utilizes **Dynamic Edge Convolution** layers. For each pulse, the model dynamically constructs a graph by finding its $k$-nearest neighbors in the high-dimensional feature space (not just physical space). It computes edge features based on the relative differences in coordinates and features between neighbors. This allows the model to learn local topological structures (e.g., track segments) and preserves the geometric relationships required for direction prediction (Cite solution_lesson_node_00010).

2.  **Global Aggregator: Self-Attention Transformer:**
    Previous GNN approaches (Idea 4) typically rely on Global Max/Average Pooling to aggregate node features into a graph embedding. This destroys the sequential/causal information of the track (e.g., the difference between the start and end of the event). To resolve this, I replace the pooling layer with a **Transformer Encoder (Self-Attention)** block. This mechanism allows the model to weigh pulses dynamically, attending more heavily to the "head" of the neutrino track (early high-charge pulses) while suppressing scattered noise, effectively capturing the global trajectory flow.

3.  **Geometric Shortcut: Spatiotemporal Eigen-Priors:**
    To guarantee the model has access to the gross directional information that scalar aggregation destroys, I explicitly compute **Spatiotemporal Eigen-Features** (eigenvalues and eigenvectors of the charge-weighted covariance matrix) and the **Covariance of Position and Time** (Cite solution_lesson_node_00006). These dense geometric descriptors are concatenated with the output of the Transformer Aggregator before the final regression head. This "skip connection" provides a robust physics-based initialization for the direction vector, stabilizing training.

4.  **Head:**
    A Multi-Layer Perceptron (MLP) that projects the fused embedding (Transformer output + Eigen-Priors) to a 3D unit vector $(n_x, n_y, n_z)$.

### Data
1.  **Geometry Merging & Normalization:**
    Merge `sensor_geometry.csv` with the pulse data. Normalize spatial coordinates $(x, y, z)$ to the detector scale and time $t$ relative to the event start. Log-transform the charge $q$.

2.  **Pulse Sampling:**
    To manage memory and computational cost, sample a fixed number of pulses (e.g., $N=196$) per event. Use a **hybrid sampling strategy**: select the top $N/2$ pulses by charge (to capture the core event) and $N/2$ pulses by time (earliest pulses) to capture the track initiation.

3.  **Geometric Feature Engineering:**
    For every event, compute the explicit geometric priors required by the model:
    *   **Inertia Tensor:** Compute the charge-weighted covariance matrix of pulse positions. Perform Eigendecomposition to get the principal axis (eigenvector $\vec{v}_1$) and shape factors (eigenvalues).
    *   **Directional Covariance:** Project pulse positions onto $\vec{v}_1$ and calculate the covariance with pulse time $t$. This explicitly encodes the "forward vs. backward" motion that scalar stats miss (Cite solution_lesson_node_00006).

### Training
*   **Loss Function:** **Cosine Similarity Loss** ($L = 1 - \vec{y}_{true} \cdot \vec{y}_{pred}$). This directly optimizes the angular alignment between the predicted and true vectors, which is the exact metric of the competition, and avoids the scale issues of MSE.
*   **Optimizer:** **AdamW** with a **Cosine Annealing Warm Restarts** scheduler. This helps the model escape local minima in the complex loss landscape.
*   **Strategy:** Train on the GPU. Monitor the validation loss to save the best model checkpoint. The use of Dynamic EdgeConv ensures the model learns robust geometric features even with limited data (Cite solution_lesson_node_00010).

### Evaluation
1.  **Inference:**
    Process the test set batches. For each event, perform the geometry merging, hybrid sampling, and eigen-feature computation.
2.  **Prediction:**
    Pass the pulse cloud and geometric priors through the trained network to obtain the predicted vector $\vec{v}_{pred} = (n_x, n_y, n_z)$.
3.  **Post-Processing:**
    Normalize $\vec{v}_{pred}$ to unit length. Convert the Cartesian components to spherical coordinates:
    *   `zenith` = $\arccos(n_z)$
    *   `azimuth` = $\arctan2(n_y, n_x)$ (mapped to $[0, 2\pi]$).
    Save the result to the submission CSV.
