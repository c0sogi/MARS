Based on the failure of the scalar aggregation approach in "Idea 2" and the specific insights from **Lesson 00006**, I propose a structural evolution of the feature-based strategy. The previous attempt failed because scalar statistics (mean, std) are time-invariant and discard the directional correlations required to define a trajectory. To address this, we must transition from a "Scalar Aggregate" paradigm to a "Tensorial/Geometric" feature engineering paradigm.

# Proposed Solution: Spatiotemporal Eigen-Feature Boosting (SE-GBM)

### Model
The core model remains **LightGBM (Gradient Boosting Decision Trees)**, retaining the efficiency and robustness of "Idea 2" (Exploitation). However, the input representation is fundamentally altered. Instead of feeding the model simple scalar distributions, we will feed it **geometric descriptors** derived from the eigen-decomposition of the event's spatiotemporal structure. We will train three independent regressors to predict the Cartesian unit vector components ($n_x, n_y, n_z$).

### Data
The critical innovation lies in the feature engineering pipeline, which explicitly reconstructs the vector information destroyed in the previous attempt.
1.  **Geometry Merging:** As before, merge `sensor_geometry.csv` with pulse data to obtain $(x, y, z, t, q)$.
2.  **Tensorial Feature Extraction:** For each event, compute features that capture the **spatiotemporal covariance** and **geometric structure** as mandated by **Cite solution_lesson_node_00006**:
    *   **Spatial Eigen-Decomposition:** Construct the charge-weighted covariance matrix of the pulse positions $(x, y, z)$. Perform **Singular Value Decomposition (SVD)** or PCA to extract the three eigenvalues ($\lambda_1, \lambda_2, \lambda_3$) and eigenvectors ($\vec{v}_1, \vec{v}_2, \vec{v}_3$). The primary eigenvector $\vec{v}_1$ represents the axis of the neutrino track.
    *   **Spatiotemporal Covariance (Direction Resolution):** The eigenvector $\vec{v}_1$ provides the *axis* but not the *direction* (forward vs. backward). To resolve this, project all pulse positions onto $\vec{v}_1$ to obtain scalar positions $p_i$. Calculate the **covariance between $p_i$ and pulse time $t_i$** (i.e., $\text{Cov}(p, t)$). A positive covariance indicates motion along $+\vec{v}_1$, while negative indicates $-\vec{v}_1$.
    *   **Raw Covariances:** Explicitly include the covariance terms $\text{Cov}(x, t)$, $\text{Cov}(y, t)$, and $\text{Cov}(z, t)$ as features to allow the model to learn non-linear dependencies directly from the spatiotemporal correlation.
3.  **Normalization:** Normalize eigenvalues to capture the shape (spherical vs. track-like) rather than just absolute size.

### Training
*   **Loss Function:** **Mean Squared Error (MSE)** on the target vector components ($n_x, n_y, n_z$).
*   **Optimizer:** Use LightGBM's standard gradient-based optimization.
*   **Strategy:** Train the three component regressors ($X, Y, Z$) independently. Given the efficiency of LightGBM and the high-quality features, we can utilize the available time to perform **Bayesian Hyperparameter Optimization** (tuning tree depth, learning rate, and feature fraction) to maximize performance.

### Evaluation
1.  **Inference:** Compute the SVD and covariance features for the test set batches.
2.  **Prediction:** Generate predictions $\hat{n}_x, \hat{n}_y, \hat{n}_z$ using the trained models.
3.  **Vector Normalization:** Construct the prediction vector $\vec{v} = [\hat{n}_x, \hat{n}_y, \hat{n}_z]$ and normalize it to unit length: $\vec{v}_{unit} = \vec{v} / \|\vec{v}\|$.
4.  **Conversion:** Convert $\vec{v}_{unit}$ to `azimuth` and `zenith` using standard spherical coordinate formulas.
