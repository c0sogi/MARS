Based on the comprehensive analysis of previous experiments and lessons learned, I propose the **Multi-Resolution ResNet34-CRNN**.

This strategy addresses the critical trade-off between temporal and frequency resolution identified in **Lesson 00012** by fundamentally changing the input representation from a single spectrogram to a **Multi-Resolution Stack**. It retains the highly successful CRNN architecture and Attention Pooling from **Lesson 00017** while optimizing the feature extraction capability without resorting to the over-regularization that caused underfitting in **Lesson 00019**.

### Model
I propose a **Multi-Resolution Convolutional Recurrent Neural Network (MR-CRNN)**.

*   **Input Representation (Structural Innovation):** Instead of a single-channel spectrogram or a redundant 3-channel copy, the model will accept a **3-Channel Multi-Resolution Log-Mel Spectrogram**.
    *   **Channel 1 (High Temporal Resolution):** Generated with a short STFT window (e.g., 20ms). This captures rapid phoneme transitions (plosives like "t", "p") crucial for short commands **Cite solution_lesson_node_00012**.
    *   **Channel 2 (Balanced Resolution):** Generated with a medium STFT window (e.g., 40ms).
    *   **Channel 3 (High Frequency Resolution):** Generated with a long STFT window (e.g., 60ms). This captures harmonic structures and formants (vowels) often smeared by short windows.
    *   *Constraint:* All channels will share the same **hop length** and **number of Mel bands** (e.g., 64) to ensuring perfect spatial alignment (Time $\times$ Frequency) across the depth dimension.
*   **Backbone:** A **ResNet34** pretrained on ImageNet.
    *   **Input Adaptation:** The 3-channel audio input will be mapped directly to the pretrained RGB weights (Channel 1 $\to$ Red, Channel 2 $\to$ Green, etc.), preserving the learned low-level feature detectors **Cite solution_lesson_node_00005**.
    *   **Temporal Preservation:** The strides of the final two residual blocks (Layer 3 and Layer 4) will be set to `(1, 1)` to prevent excessive downsampling of the time dimension, ensuring the output feature map retains sufficient length for sequence modeling **Cite solution_lesson_node_00017**.
*   **Neck (Sequence Modeling):** The output features will be averaged over the frequency dimension and passed to a **Bidirectional GRU (BiGRU)** to explicitly model the sequential order of phonemes **Cite solution_lesson_node_00017**.
*   **Head (Aggregation):** An **Attention Pooling** layer will aggregate the recurrent states, allowing the model to dynamically weight the active speech segments and ignore silence/padding **Cite solution_lesson_node_00017**.

### Data
*   **Preprocessing:** Audio will be resampled to 16kHz and padded/cropped to exactly 1 second.
*   **Feature Engineering:**
    *   We will generate the 3-channel spectrogram stack on-the-fly.
    *   **Parameters:** `n_mels=64` **Cite solution_lesson_node_00006**, `hop_length=160` (10ms).
    *   **Window Sizes:** `n_fft` will vary per channel (e.g., 320, 640, 960 samples).
*   **Sampling Strategy:** We will use the **Balanced Batch Sampler**:
    *   **Undersample** the `unknown` class to the median count of target labels.
    *   **Oversample** the `silence` class by stochastically cropping the long background noise files **Cite solution_lesson_node_00001**.
*   **Augmentation:**
    *   **SpecAugment Only:** Apply Frequency and Time Masking to the 3-channel image simultaneously.
    *   **Configuration:** Use **inclusive bounds** for mask generation **Cite solution_lesson_node_00011**. Masked regions will be filled with the **minimum value** of the spectrogram (not zero) **Cite solution_lesson_node_00010**. Time masks will be limited to <20% of the duration **Cite solution_lesson_node_00008**.
    *   **Exclusion:** We will **NOT** use MixUp or Label Smoothing, as previous experiments showed these caused underfitting by over-regularizing the model given the already small generalization gap **Cite solution_lesson_node_00016** **Cite solution_lesson_node_00019**.

### Training
*   **Loss Function:** Standard **Cross-Entropy Loss**.
*   **Optimizer:** **AdamW** with weight decay.
*   **Scheduler:** **Cosine Annealing** learning rate scheduler to ensure smooth convergence.
*   **Validation:** We will monitor accuracy on the speaker-disjoint validation set provided in the metadata.

### Evaluation
*   **Inference:** For each test file, we will generate the same 3-channel Multi-Resolution Spectrogram (without augmentation).
*   **Prediction:** The model will process the input and output the class with the highest probability. The Attention Pooling head will naturally handle the uncropped nature of test files by focusing on the speech segment.
