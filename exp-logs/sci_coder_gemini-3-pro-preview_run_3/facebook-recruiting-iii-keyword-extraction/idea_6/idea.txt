# Solution Proposal: Wide-and-Deep TextCNN

## Model
I propose a **Wide-and-Deep TextCNN** architecture. This design structurally evolves the baseline by integrating a linear "memorization" channel alongside the deep "generalization" channel, addressing the need for both explicit keyword matching and contextual pattern recognition.

*   **Input**: The model accepts a single stream of integer token IDs representing the concatenated Title and Body. This adheres to the lesson that shared representations are superior for same-modality fields (Cite solution_lesson_node_00009).
*   **Wide Component (Linear Stream)**: A learnable `nn.EmbeddingBag` layer with an output dimension equal to the number of target classes (tags) and `mode='sum'`.
    *   **Function**: This effectively implements a Logistic Regression (or Naive Bayes-like) model over the Bag-of-Words. It learns a direct weight for every word-tag pair (e.g., the token "python" contributes +5.0 to the "python" tag logit).
    *   **Purpose**: This provides a direct gradient path for strong keyword signals, ensuring the model captures the explicit 1-to-1 mappings common in technical tagging without needing to propagate through deep layers.
*   **Deep Component (Context Stream)**: A **TextCNN** backbone.
    *   **Architecture**: An embedding layer (dimension ~128) followed by parallel 1D Convolutional layers (kernel sizes 3, 4, 5) and **Global Max Pooling**.
    *   **Purpose**: This retains the highly efficient inductive bias for detecting local n-gram phrases and context (Cite solution_lesson_node_00006), handling cases where word order matters (e.g., "visual studio" vs. "studio").
*   **Fusion**: The logits from the Wide component and the Deep component are summed element-wise to produce the final prediction logits.

## Data
*   **Preprocessing**: Concatenate `Title` and `Body` into a single string (Cite solution_lesson_node_00009). Normalize text (lowercase, remove non-alphanumeric characters).
*   **Tokenization**: Build a vocabulary of the top $N$ (e.g., 50,000) most frequent words. Convert text into sequences of integer IDs.
*   **Sequence Standardization**: Pad or truncate sequences to a fixed length (e.g., 400 tokens). This allows for efficient batch processing on the GPU.
*   **Target Encoding**: Encode the top $K$ (e.g., 5,000) most frequent tags using a Multi-Label Binarizer.

## Training
*   **Strategy**: Train on the **full dataset (4.3M samples)**. The efficiency of the CNN and Linear components allows for processing the entire corpus within the time limit, avoiding the "data starvation" issues observed in previous experiments (Cite solution_lesson_node_00008).
*   **Loss Function**: **Binary Cross-Entropy with Logits Loss** (BCEWithLogitsLoss).
*   **Optimizer**: **AdamW** with a standard learning rate schedule (linear warmup and decay). The "Wide" component acts as a skip-connection, likely accelerating convergence by allowing the model to quickly learn easy keyword associations.
*   **Mixed Precision**: Utilize Automatic Mixed Precision (AMP) to minimize memory usage, specifically to handle the large parameter table required for the Wide component (Vocabulary $\times$ Number of Tags).

## Evaluation
*   **Inference**: Process the test set using the trained Wide-and-Deep model.
*   **Thresholding**: Determine the optimal probability threshold by maximizing the F1-score on the validation set.
*   **Formatting**: Convert predicted indices to tag strings and format as a space-delimited list for submission.
