The issue is that the `eval_fn` function in `library/engine.py` attempts to store the entire validation set's predictions and labels in memory to calculate the Micro F1 score. With over 1 million samples and 3,000 classes, this results in a dense array requiring approximately 12GB of contiguous memory, causing a `numpy._core._exceptions._ArrayMemoryError`.

To fix this, I will refactor `eval_fn` to calculate the necessary statistics for the Micro F1 score (True Positives, Total Predicted Positives, Total Actual Positives) incrementally batch-by-batch. This reduces memory usage from $O(N \times C)$ to $O(1)$. I will also apply a similar fix to the "Validation Assessment" section in `runfile.py`, which suffers from the same issue during failure analysis.
