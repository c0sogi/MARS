# Solution Proposal: Dual-Stream TextCNN with Feature Fusion

## Model
I propose a **Dual-Stream TextCNN** architecture. This design structurally evolves the previous single-stream TextCNN by explicitly recognizing the distinct semantic roles of the "Title" (concise, high-signal summaries) and the "Body" (verbose, detailed context).

*   **Shared Embedding Layer**: A single learnable embedding matrix maps token IDs to dense vectors for both Title and Body inputs. This ensures that identical words (e.g., "Python") share the same semantic representation across both fields.
*   **Dual-Stream Encoders**:
    *   **Title Stream**: A 1D-CNN processing the Title input with smaller kernel sizes (e.g., 2, 3, 4). This stream is optimized to extract explicit keywords and short phrases, preserving the high signal-to-noise ratio of the title.
    *   **Body Stream**: A parallel 1D-CNN processing the Body input with larger kernel sizes (e.g., 3, 4, 5). This stream captures broader context and code snippets.
*   **Feature Fusion**: The output of both streams is aggregated via **Global Max Pooling** independently. This is a critical structural innovation: in the previous single-stream approach, the Max Pooling operation over the concatenated text often caused strong signals in the short Title to be "drowned out" by the sheer volume of features in the long Body. Independent pooling preserves the strongest features from *both* sources.
*   **Classifier**: The two pooled vectors are concatenated and passed through a fully connected layer with Dropout to predict the tag probabilities.

This architecture retains the highly efficient **parallel convolution and max pooling** mechanism that was proven effective (Cite solution_lesson_node_00006) while avoiding the complexity and data-inefficiency of attention-based Transformers which failed to converge on this task (Cite solution_lesson_node_00008).

## Data
*   **Preprocessing**: Unlike the previous approach which concatenated text, we will tokenize `Title` and `Body` separately.
*   **Sequence Standardization**:
    *   **Title**: Pad/Truncate to a short fixed length (e.g., 30 tokens).
    *   **Body**: Pad/Truncate to a longer fixed length (e.g., 400 tokens).
*   **Scale**: We will utilize the **full training dataset (4.3M samples)**. The previous failure of the Hybrid model was exacerbated by training on a small subset (Cite solution_lesson_node_00008). The efficiency of the CNN architecture allows us to process the entire corpus within the 24-hour limit on the A100 GPU, significantly improving the model's exposure to rare tags.

## Training
*   **Strategy**: Use **Automatic Mixed Precision (AMP)** to maximize GPU throughput and reduce memory footprint, allowing for larger batch sizes (e.g., 2048).
*   **Loss Function**: **Binary Cross-Entropy with Logits Loss**.
*   **Optimizer**: **AdamW** with a **One Cycle Learning Rate Policy**. This scheduler provides a rapid warm-up to a high learning rate followed by a decay, ensuring fast convergence on the massive dataset.

## Evaluation
*   **Inference**: The test set will be processed through the dual-stream pipeline.
*   **Thresholding**: We will calculate the optimal probability threshold that maximizes the F1-score on the validation set and apply this threshold to the test predictions.
*   **Formatting**: Predicted indices will be mapped to tag strings and formatted as a space-delimited list.
