Based on the comprehensive analysis of the provided lessons and the progression of previous experiments, I propose the following optimized strategy. This solution synthesizes the structural innovation of **Task-Adaptive Pretraining (TAPT)** with a rigorous set of engineering corrections derived from the failure analysis of previous attempts (specifically addressing labeling, batch sizing, and inference logic).

# Model
**Architecture:**
I will utilize the **`xlm-roberta-base`** model (Cite solution_lesson_node_00004) as the backbone, given its proven superiority over distilled variants in this multilingual context. The model will be architected as a **Token Classifier**, projecting hidden states into 3 classes (`B-ANS`, `I-ANS`, `O`). This approach is chosen over start/end logits to support the robust span decoding strategies found to be effective in earlier iterations.

**Structural Innovation: Task-Adaptive Pretraining (TAPT)**
To bridge the domain gap between the generic pre-training of XLM-R and the specific Hindi/Tamil dataset, I will implement a **two-stage training pipeline**:
1.  **Stage 1 (Adaptation):** I will fine-tune the `xlm-roberta-base` model using a **Masked Language Modeling (MLM)** objective on the concatenation of the raw `context` text from both the Training and Test sets. This aligns the embeddings with the specific vocabulary and morphology of the target data.
2.  **Stage 2 (Supervised Learning):** The TAPT-adapted weights will serve as the initialization for the Token Classification model.

# Data
**Preprocessing:**
*   **Sliding Window:** The text will be tokenized and split into overlapping windows of **384 tokens** with a **stride of 128**.
*   **Labeling Strategy (Soft Overlap):** I will strictly employ **Soft Overlap** labeling (Cite solution_lesson_node_00017). A token will be labeled as positive (`B-ANS` or `I-ANS`) if it has *any* character overlap with the ground truth span. This corrects the "Strict Containment" flaw that previously removed valid training signals due to subword tokenization artifacts.
*   **Full Distribution:** I will retain **all** generated windows for training. I will **not** perform any negative downsampling (Cite solution_lesson_node_00011), ensuring the model learns to suppress false positives by seeing the full "background" distribution.
*   **Coupled Metadata:** To prevent the inference failures observed in previous TAPT attempts, I will bundle all necessary metadata (e.g., `offset_mapping`, `example_id`) directly into the PyTorch tensors/batches via a custom `collate_fn`. I will **not** decouple metadata into separate files/lists (Cite solution_lesson_node_00018).

# Training
**Hyperparameters & Strategy:**
*   **Update Frequency:** I will strictly utilize a **small batch size (e.g., 8)**. This addresses the "Gradient Update Frequency" lesson (Cite solution_lesson_node_00015), ensuring that the model receives a sufficient number of optimization steps to escape the "majority class" local minimum, which a larger batch size (e.g., 32) previously prevented on this small dataset.
*   **Duration:** The model will be fine-tuned for **10 epochs** (Cite solution_lesson_node_00005) to accommodate the "delayed onset" of convergence.
*   **Ensembling:** I will train **3 independent model instances** using different random seeds to mitigate the high variance inherent in low-resource training (Cite solution_lesson_node_00008).

# Evaluation
**Inference Pipeline:**
The prediction process will employ a **Global Confidence Aggregation** strategy followed by **Majority Voting**:

1.  **Global Confidence Selection (Per Model):** For a given document, each model will process **all** overlapping sliding windows. Instead of stopping at the first valid span (Greedy First-Match), the model will collect all candidate spans across all windows and select the single span with the **highest confidence score** (Cite solution_lesson_node_00016). This corrects the "Greedy First-Match" flaw that locked in early false positives.
2.  **Robust Decoding:** Answer strings will be decoded directly from the predicted token IDs using the tokenizer, ensuring alignment without reliance on external offset mapping lists (Cite solution_lesson_node_00018).
3.  **Majority Voting (Ensemble):** The final prediction will be determined by a **Majority Vote** on the exact string outputs from the 3 models. This avoids the "smearing" artifacts caused by averaging raw token probabilities (Cite solution_lesson_node_00009).
