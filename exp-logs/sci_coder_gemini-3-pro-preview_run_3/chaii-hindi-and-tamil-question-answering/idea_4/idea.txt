Based on the analysis of the provided lessons and the progression of previous experiments, I propose the following optimized strategy. This solution introduces **Task-Adaptive Pretraining (TAPT)** as a structural innovation to specialize the multilingual backbone, while rigorously correcting the hyperparameters and inference logic that caused previous attempts to fail.

# Model
**Architecture:**
The core backbone will remain the **`xlm-roberta-base`** model (Cite solution_lesson_node_00004), as it has proven superior to distilled variants for this multilingual task. The model will be architected as a **Token Classifier**, projecting hidden states into 3 classes (`B-ANS`, `I-ANS`, `O`).

**Structural Innovation: Task-Adaptive Pretraining (TAPT)**
To address the domain gap between the generic pre-training of XLM-R and the specific Hindi/Tamil dataset, I will implement a **multi-stage training pipeline**:
1.  **Stage 1 (Adaptation):** I will continue pre-training the `xlm-roberta-base` model using a **Masked Language Modeling (MLM)** objective on the concatenation of the raw `context` text from both the Training and Test sets. This aligns the embeddings with the specific vocabulary and morphology of the target data before any supervised learning occurs.
2.  **Stage 2 (Fine-Tuning):** The adapted weights will then be used to initialize the Question Answering model.

# Data
**Preprocessing:**
*   **Sliding Window:** The text will be tokenized and split into overlapping windows of **384 tokens** with a **stride of 128**.
*   **Full Distribution:** Crucially, I will retain **all** generated windows for training. I will **not** perform any negative downsampling (Cite solution_lesson_node_00011), ensuring the model learns to suppress false positives by seeing the full "background" distribution.

**Ensembling:**
To mitigate the high variance observed in single-run experiments (Cite solution_lesson_node_00008), I will prepare data to train **3 independent model instances** using different random seeds.

# Training
**Hyperparameters & Strategy:**
*   **Update Frequency:** I will strictly utilize a **small batch size (e.g., 8 or 16)**. This corrects the failure of previous TAPT attempts where a large batch size reduced the number of gradient updates, leading to model collapse (Cite solution_lesson_node_00015).
*   **Duration:** Each model will be fine-tuned for **10 epochs**. This extended duration is necessary to overcome the "delayed onset" of convergence characteristic of this dataset (Cite solution_lesson_node_00005).
*   **Optimization:** The optimizer will be AdamW with a standard learning rate (e.g., 2e-5), applied to the TAPT-initialized weights.

# Evaluation
**Inference Pipeline:**
The prediction process will employ a **Global Confidence Aggregation** strategy followed by **Majority Voting**, correcting previous flaws in decoding:

1.  **Global Confidence Selection (Per Model):** For a given document, each model will process **all** overlapping sliding windows. Instead of stopping at the first valid span (Greedy First-Match), the model will collect all candidate spans across all windows and select the single span with the **highest confidence score** (Cite solution_lesson_node_00016). This filters out low-confidence false positives that often appear in early context windows.
2.  **Majority Voting (Ensemble):** The final prediction will be determined by a **Majority Vote** on the exact string outputs from the 3 models. This avoids the "smearing" artifacts caused by averaging raw token probabilities (Cite solution_lesson_node_00009).
