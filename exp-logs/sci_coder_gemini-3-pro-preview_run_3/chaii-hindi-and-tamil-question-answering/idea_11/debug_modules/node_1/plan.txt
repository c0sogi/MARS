The issue is that the training loop initializes `best_jaccard` to `0.0` and only saves the model checkpoint if the current validation score strictly exceeds this value (`val_jaccard > best_jaccard`). In the provided run, the model achieved a Jaccard score of exactly `0.0`, so the condition `0.0 > 0.0` evaluated to `False`, resulting in no model file being saved. This caused the subsequent `FileNotFoundError` when the script attempted to load the model. The fix is to initialize `best_jaccard` to `-1.0` so that even a score of `0.0` triggers the initial save.
