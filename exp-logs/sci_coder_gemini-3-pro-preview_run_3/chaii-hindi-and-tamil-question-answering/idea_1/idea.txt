To establish a robust and efficient baseline, I propose a **Sparse Retrieval-Augmented Sequence Labeling (SR-SL)** approach. This method addresses the primary challenge of the dataset—extremely long contexts (mean ~1700 words) versus short answers—by decoupling the problem into a fast retrieval step and a focused extraction step.

### Model
The architecture consists of two distinct stages designed to minimize computational overhead while maintaining accuracy:

1.  **Sparse Retrieval Module (The Filter):**
    Instead of processing the entire document with a neural network, this module utilizes a statistical **TF-IDF (Term Frequency-Inverse Document Frequency)** vectorizer. It treats the `Question` and every individual sentence within the `Context` as separate documents. By computing the cosine similarity between the question vector and the sentence vectors, it identifies and retrieves the single most semantically relevant sentence from the massive context.

2.  **Sequence Labeling Module (The Extractor):**
    The second component is a lightweight, pre-trained multilingual Transformer (e.g., `distilbert-base-multilingual-cased`). Unlike the standard Question Answering architecture (Model 1) that predicts global start and end logits, this model is architected as a **Token Classifier** (similar to Named Entity Recognition). It takes the `Question` and the `Retrieved Sentence` as input and projects the hidden states of the sentence tokens into a 3-class probability space: **B-ANS** (Beginning of Answer), **I-ANS** (Inside Answer), and **O** (Outside).

### Data
The data preparation process focuses on reducing noise and sequence length:

1.  **Sentence Segmentation:**
    For both training and testing, the raw `context` text is split into individual sentences using language-specific punctuation rules (handling Hindi/Tamil sentence endings).

2.  **Training Data Construction:**
    *   We filter the training set to create pairs of `(Question, Gold_Sentence)`, where `Gold_Sentence` is the specific sentence from the context that contains the ground truth answer.
    *   We tokenize these pairs and generate token-level labels. Tokens corresponding to the answer string are labeled `B-ANS` (first token) and `I-ANS` (subsequent tokens), while all other tokens are labeled `O`.

3.  **Inference Data Construction:**
    For the test set, since we do not know the gold sentence, we preserve the entire list of sentences for the retrieval step.

### Training
The training procedure is designed for speed and stability on the small dataset:

*   **Objective:** Minimize **Cross-Entropy Loss** computed over the token classifications (B/I/O tags).
*   **Efficiency:** By training only on the `Gold_Sentence` rather than the full document, the effective input sequence length drops from ~1700 tokens to ~30-50 tokens. This allows for significantly faster epochs and larger batch sizes compared to standard QA approaches.
*   **Optimizer:** Use AdamW with a linear learning rate decay.

### Evaluation
The prediction pipeline for the test set follows these steps:

1.  **Retrieve:** For a given test ID, segment the `context` and use the TF-IDF module to rank all sentences against the `question`. Select the top-1 ranked sentence.
2.  **Predict:** Feed the `[CLS] Question [SEP] Top_Sentence [SEP]` sequence into the fine-tuned Sequence Labeling model.
3.  **Reconstruct:** Decode the output tags. Extract the contiguous span of tokens labeled `B-ANS` and `I-ANS`. If multiple spans are detected, select the one with the highest average probability.
4.  **Format:** Detokenize the selected tokens to form the final prediction string.
