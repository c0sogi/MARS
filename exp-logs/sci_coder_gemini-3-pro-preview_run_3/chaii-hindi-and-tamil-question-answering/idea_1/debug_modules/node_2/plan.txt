The `SparseRetriever` implementation in `library/data_loader.py` currently uses the default word-level `TfidfVectorizer`. This causes the retrieval failure in `runfile.py` because the word-level TF-IDF with cosine similarity is biased towards shorter sentences when the query contains common stop words (like "is", "the") that match the shorter sentence. The meaningful match ("answer") in the longer target sentence is outweighed by the length normalization penalty.

To fix this, I will modify `SparseRetriever` to use character n-grams (`analyzer="char", ngram_range=(2, 4)`). This change significantly increases the number of matching features for longer, meaningful words (like "answer") compared to short stop words (like "is"), allowing the correct sentence to achieve a higher similarity score despite its length. This approach is also more robust for the multilingual (Hindi/Tamil) nature of the dataset.
