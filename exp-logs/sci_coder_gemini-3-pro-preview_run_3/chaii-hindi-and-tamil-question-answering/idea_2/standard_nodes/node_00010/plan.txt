The implementation strategy follows the requirements to create a fast, reproducible, and robust baseline for the Question Answering task.

1.  **Orchestration**: The script `runfile.py` serves as the main entry point. It imports the necessary configurations and functions from the provided library files (`config`, `trainer`, `inference`, `model`, `data_loader`, `utils`) to avoid code duplication.
2.  **Training**: It executes `run_training_pipeline(debug=False)` to train an ensemble of 3 XLM-RoBERTa models. The training uses the full dataset (approx. 800 samples) and 10 epochs per seed, which fits well within the "fast baseline" requirement given the small dataset size and powerful compute resources (A100).
3.  **Validation & Metric Calculation**:
    *   It loads the validation dataset and the trained models.
    *   It runs inference on the validation set for each model and aggregates predictions using **Majority Voting**.
    *   It computes the **Word-level Jaccard score** for each sample and calculates the average to produce the `Final Validation Metric`.
4.  **Failure Analysis**:
    *   It constructs a DataFrame containing error magnitudes ($1 - \text{Jaccard}$), context lengths, question lengths, and answer start positions.
    *   It calculates and prints the Pearson correlation between the error magnitude and these features to identify potential biases or weaknesses (e.g., performance drops on longer contexts).
5.  **Submission**:
    *   It checks if the `Final Validation Metric` exceeds the threshold of `0.3011529653320698`.
    *   If the condition is met, it triggers `run_inference_pipeline()` to generate predictions on the test set and save the `submission.csv`.
