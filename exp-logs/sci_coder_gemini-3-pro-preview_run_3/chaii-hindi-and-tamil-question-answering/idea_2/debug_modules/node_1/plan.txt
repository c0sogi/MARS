The issue stems from the `QADataset` class in `library/data_loader.py` attempting to convert DataFrame columns directly into PyTorch tensors. When the data is loaded from a Parquet cache, columns containing complex structures like `offset_mapping` (lists of tuples) are often deserialized as NumPy arrays with `dtype=object`. The `torch.tensor()` constructor does not support creating tensors from NumPy object arrays, causing the `TypeError`. To fix this, I will modify the `__getitem__` method to explicitly convert these NumPy arrays back into standard Python lists using `.tolist()` before tensor creation.
