Implementation Strategy:
1.  **Configuration Patching**: To ensure the demonstration runs quickly and stays within the compute limits, I will modify the `Config` class attributes at runtime. I will set the number of epochs to 1, reduce the seed list to a single seed, and redirect the working directories to a specific `./working/demo_run` folder.
2.  **Data Subsetting**: I will load the original metadata files, sample a very small subset (e.g., 20 rows for training, 10 for validation/test), and save them to a temporary metadata directory. I will then update the `Config` file paths to point to these smaller datasets. This ensures the training loops complete in seconds rather than hours.
3.  **Component Verification**:
    *   **Utils**: Verify `jaccard` and `clean_text` logic with assertions.
    *   **Data Processing**: Instantiate the tokenizer, load the subsetted data using `get_qa_data`, and verify the structure of the resulting datasets and the `qa_collate_fn`.
    *   **TAPT Engine**: Execute `run_tapt_training` to fine-tune the model on the subset data. Verify the model artifact is created.
    *   **QA Engine**: Execute `run_qa_training` using the TAPT model. Verify that the QA model weights are saved.
    *   **Inference Engine**: Execute `generate_submission` to produce predictions on the subset test data. Verify the output file format and content.
4.  **Execution**: The script will run these steps sequentially, printing status updates and using assertions to validate success at each stage.
