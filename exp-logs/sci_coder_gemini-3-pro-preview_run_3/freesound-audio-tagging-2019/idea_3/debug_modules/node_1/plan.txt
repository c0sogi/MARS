The issue is located in the `calculate_lwlrap` function within `library/utils.py`. The current implementation calculates the mean LWLRAP score across all classes, including those with zero support (classes that do not appear in the ground truth for the given batch). This creates a deflation of the metric because absent classes contribute a score of 0.0 to the average. According to `debug_lesson_1` (Cite debug_lesson_1), the correct approach for label-weighted metrics is to exclude zero-support classes from the aggregation. I will modify the function to calculate the mean only over the classes where the support count is greater than zero using the existing `mask`.
