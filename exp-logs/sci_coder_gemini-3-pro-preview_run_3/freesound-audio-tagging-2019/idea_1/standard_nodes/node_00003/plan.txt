To improve the model's performance, I will implement the following changes based on the analysis and the provided lesson (Cite solution_lesson_node_00002):

1.  **Data Pipeline Optimization**: I will increase the `DURATION` from 5 seconds to 30 seconds. The EDA showed that the maximum file duration is 30 seconds. By processing the entire audio clip, we eliminate the "naive cropping" issue where the target sound event might be cropped out while the label remains, which was a major source of label noise.
2.  **Model Architecture Adaptation**: I will replace the default Global Average Pooling in the MobileNetV3 backbone with **Global Max Pooling**. As per the lesson, Max Pooling is superior for weakly labeled time-series data because it focuses on the most prominent features (the event) rather than averaging them with the background silence/noise, which is crucial when padding short clips to 30 seconds.
3.  **Hyperparameter Tuning**:
    *   Reduce `BATCH_SIZE` from 128 to 32 to accommodate the significantly larger input tensors (30s vs 5s).
    *   Increase `EPOCHS` to 15 to ensure convergence with the new data distribution.
4.  **Submission Logic**: I will add a conditional check to `runfile.py` to ensure a submission file is generated only if the model outperforms the previous baseline LWLRAP of ~0.115.
