The strategy for the `runfile.py` implementation is as follows:

1.  **Configuration Override**: To adhere to the "fast baseline" requirement while ensuring high performance, I will modify the `Config` class attributes at runtime. I will increase `BATCH_SIZE` to 128 to fully utilize the NVIDIA A100 GPU and set `EPOCHS` to 12. This ensures the training completes quickly (well within the 1-hour limit) while providing enough iterations for the `OneCycleLR` scheduler to converge and potentially beat the high validation threshold.
2.  **Data Loading**: I will use the provided `get_dataloaders` function with `load_cached_data=True`. This leverages the pre-computed spectrograms in the `./working` directory, significantly speeding up the pipeline by skipping the audio processing step.
3.  **Training**: I will instantiate the `Trainer` class and execute the `fit()` method. This handles the training loop, validation, and model checkpointing based on the LWLRAP metric.
4.  **Validation Reporting**: After training, I will access `trainer.best_score` and print it in the strictly required format: `Final Validation Metric: <value>`.
5.  **Failure Analysis**: I will implement a dedicated function `analyze_failures` that:
    *   Runs inference on the validation set (using the trained model in eval mode) to retrieve raw predictions and targets.
    *   Computes the "Error Magnitude" for each sample using the Mean Absolute Error (MAE) between predictions and targets.
    *   Extracts input features: "Number of Labels" (from ground truth) and "Audio Duration" (by reading audio headers using `soundfile`).
    *   Calculates and prints the Pearson correlation coefficients between the error magnitude and these features to identify systematic weaknesses.
6.  **Submission**: I will compare the best validation score against the threshold `0.7117108825122853`. If the model succeeds, I will trigger the `predict_test` method and generate the `submission.csv` using `generate_submission`.
