# Baseline Approach: 2.5D Feature Pyramid Network (FPN)

## Model
To establish a robust and efficient baseline, I propose a **Feature Pyramid Network (FPN)** architecture adapted for **2.5D input**. 

*   **Architecture Design**: Unlike the U-Net (Model 1), which relies on symmetric concatenation-based skip connections, FPN uses a top-down pathway with lateral connections to build high-level semantic feature maps at all scales. This allows the model to detect objects of varying sizes (e.g., small cross-sections of the small bowel vs. larger stomach regions) efficiently.
*   **Encoder**: We will use a **ResNet-18** backbone pre-trained on ImageNet. This is significantly lighter than the EfficientNet used in Model 1 and provides a standard, well-understood feature extractor that balances speed and accuracy.
*   **2.5D Input Strategy**: Drawing on the conceptual foundation of Model 1, the input layer will accept a 3-channel tensor. These channels will correspond to the target slice ($t$), the slice immediately above ($t-1$), and the slice immediately below ($t+1$). This pseudo-3D approach allows the 2D CNN to leverage volumetric spatial context—crucial for tracing continuous organs like intestines—without the computational cost of full 3D convolutions.
*   **Segmentation Head**: The decoder outputs a feature map which is passed through a final 1x1 convolution layer with a Sigmoid activation function to predict independent probabilities for the three classes (Large Bowel, Small Bowel, Stomach).

## Data
*   **Preprocessing**:
    1.  **Normalization**: MRI pixel values can have a wide range (up to ~15,000 based on EDA). We will apply Min-Max normalization per image to scale pixel intensities to the [0, 1] range.
    2.  **2.5D Channel Construction**: For each file in the training and test sets, we will load the corresponding image and its neighbors. Boundary slices (first/last of a case) will use the adjacent slice duplicated to fill the missing neighbor.
    3.  **Resizing**: Since the dataset contains varying resolutions (266x266 and 360x310), all images will be resized to a fixed resolution of **320x320** pixels. This ensures consistent tensor shapes for batch processing while maintaining sufficient spatial detail.
    4.  **Mask Generation**: The RLE strings in `train.csv` will be decoded into binary masks. These masks will be stacked to form a (Height, Width, 3) target tensor.
*   **Augmentation**: To maintain the "baseline" philosophy, we will use only lightweight augmentations: random horizontal flipping and small random rotations ($\pm 10^\circ$).

## Training
*   **Loss Function**: We will use a composite loss function: **BCE + Dice Loss**. Binary Cross Entropy (BCE) will provide smooth gradients for pixel-level classification, while Dice Loss directly optimizes the competition metric and handles the class imbalance (background vs. organs).
*   **Optimizer**: The **Adam** optimizer will be used with a default learning rate of 1e-4.
*   **Procedure**: The model will be trained for a fixed number of epochs (e.g., 10-15) with a batch size that maximizes GPU utilization (e.g., 32 or 64). We will monitor the validation Dice score to save the best model checkpoint.

## Evaluation
*   **Inference**: The model will generate predictions on the test set using the same 2.5D input construction and resizing steps.
*   **Post-Processing**:
    1.  **Resizing**: Predicted probability maps (320x320) will be resized back to the original dimensions of the scan (e.g., 266x266 or 360x310) using bilinear interpolation.
    2.  **Thresholding**: A fixed threshold of **0.5** will be applied to convert probabilities into binary masks.
    3.  **Encoding**: The binary masks will be flattened and converted into the required Run-Length Encoding (RLE) format for submission.
