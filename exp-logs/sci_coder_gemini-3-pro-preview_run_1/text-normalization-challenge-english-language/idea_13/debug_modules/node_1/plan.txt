The issue is caused by a schema collision in the `vocab_classes.json` file. The `Vocabulary` class (in `library/data_loader.py`) saves the class vocabulary as a nested dictionary containing metadata like `{"token2id": {...}, "special_tokens": ...}`, whereas the `GlobalPriorMap` class (in `library/features.py`) expects a simple flat dictionary mapping class names to indices. When `GlobalPriorMap` attempts to load the cache file generated by `Vocabulary`, it blindly iterates over the dictionary items. Encountering the nested `token2id` dictionary as a value triggers a `TypeError: unhashable type: 'dict'` when it attempts to invert the mapping.

To fix this, I will update `GlobalPriorMap._load_cache` to validate the structure of the loaded JSON. It will check for the presence of the `"token2id"` key and extract the inner mapping if found, ensuring it can handle both the flat format it generates and the nested format generated by the `Vocabulary` class. This solution applies **debug_lesson_5** (Validate Schema of Cached Artifacts Before Loading).
