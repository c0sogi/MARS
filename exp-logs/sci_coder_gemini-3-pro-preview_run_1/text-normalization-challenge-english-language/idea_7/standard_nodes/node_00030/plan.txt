To address the `torch.OutOfMemoryError` caused by the first model's resources not being released before the second model starts, I will isolate the training of each model into separate operating system processes. This ensures that when a training stage completes, the OS forcibly reclaims all associated GPU resources (Cite debug_lesson_5).

I will implement this by:
1.  Creating a new module `library/training_tasks.py` containing self-contained functions `train_tagger_safe` and `train_seq2seq_safe`. These functions will handle the full training lifecycle for their respective models and include exception handling to propagate errors (Cite debug_lesson_6, debug_lesson_7, debug_lesson_8).
2.  Modifying `runfile.py` to remove the inline sequential training logic and instead execute these new functions using `torch.multiprocessing` with the `spawn` context. After the subprocesses complete, the main process will reload the saved checkpoints for inference.
