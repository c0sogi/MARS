To resolve the `torch.OutOfMemoryError` caused by lingering GPU memory allocations in the sequential training pipeline, I will isolate the training of the Tagger and Seq2Seq models into separate operating system processes using `torch.multiprocessing`. This ensures that when a training stage completes, the OS forcibly reclaims all associated resources, providing a clean GPU state for the next stage (Cite debug_lesson_5).

Additionally, since spawned subprocesses do not inherit runtime configuration overrides from the parent script, I will update the default values in `library/config.py` to match the "Fast Baseline" settings (Cite debug_lesson_14). I will also implement wrapper functions in `library/trainer.py` that handle exceptions and flush output streams to ensure any subprocess errors are properly logged (Cite debug_lesson_7, debug_lesson_8).
