To optimize performance, I will implement a strategy focused on scaling the data and model capacity while retaining the effective "classify-and-lookup" architecture described in **solution_lesson_node_00005**.

**Strategy:**
1.  **Full Dataset Training**: The previous solution used only ~37% of the data (200k sentences). I will enable training on the full dataset (`MAX_TRAIN_SAMPLES = None`). This is the most critical optimization because the "Knowledge Base" (KB) relies on seeing exact `(token, class)` pairs to perform deterministic normalization. Increasing data size directly increases KB coverage, reducing the number of "unseen" entities that force a fallback to raw text.
2.  **Increased Model Capacity**: To handle the larger dataset and ensure the LSTM can distinguish subtle context for rare classes:
    -   Increase `VOCAB_SIZE` from 50k to 200k to reduce `<UNK>` tokens.
    -   Increase `EMBEDDING_DIM` (256 -> 512) and `HIDDEN_DIM` (512 -> 1024).
    -   Increase `MAX_LEN` from 128 to 300 to fully cover the maximum sentence length (233 tokens) found in the EDA, preventing truncation errors at the end of long sentences.
3.  **Hardware Optimization**: Increase `BATCH_SIZE` to 1024 to utilize the A100 GPU efficiently and keep training time within limits despite the larger dataset.
4.  **Conditional Submission**: Update `runfile.py` to check the validation metric against the threshold (0.97928) before generating the submission file.
