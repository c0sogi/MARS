Based on the accumulated lessons and the analysis of previous attempts, I propose the **Morphologically-Aware Bi-LSTM Tagger with Neural Fallback**. This strategy represents a structural evolution of the baseline by integrating character-level features to address input fidelity limitations and replacing heuristic fallbacks with a learnable neural component.

# Model
The architecture follows a decoupled "Classify-and-Generate" paradigm **Cite {solution_lesson_node_00005}**, splitting the problem into semantic classification and conditional normalization.

1.  **Stage 1: Morphologically-Aware Tagger (Classification)**
    *   **Backbone:** We will utilize a **Bi-directional LSTM (Bi-LSTM)** network. Previous experiments demonstrated that Bi-LSTMs converge significantly faster and achieve higher accuracy than raw Transformer Encoders for this specific dataset and constraint profile **Cite {solution_lesson_node_00012}**.
    *   **Structural Innovation (Input):** To address the "Input Fidelity" bottleneck **Cite {solution_lesson_node_00009}**, we will augment the standard word embeddings with **Character-Level Embeddings**. A 1D-Convolutional Neural Network (CNN) will process the character sequence of each token to extract local morphological features (e.g., digit strings, capitalization patterns, suffixes). These character features will be concatenated with the word embeddings before entering the Bi-LSTM. This ensures the model can robustly classify Out-of-Vocabulary (OOV) tokens (like novel dates or serial numbers) based on their internal structure.
    *   **Output:** The model predicts the semantic class (e.g., `DATE`, `CARDINAL`, `PLAIN`) for each token.

2.  **Stage 2: Hybrid Decoder (Normalization)**
    *   **Primary (Memory):** We employ a deterministic **Knowledge Base (KB)** constructed from the training data. This maps `(raw_token, predicted_class)` to the normalized text. This component handles the vast majority of cases with 100% precision.
    *   **Secondary (Neural Fallback):** For tokens not found in the KB (OOV), we replace brittle regex heuristics with a lightweight **Character-Level Seq2Seq Model** (LSTM Encoder-Decoder with Attention). This model is trained to translate raw text into normalized text, conditioned on the class predicted by the Tagger.

# Data
1.  **Knowledge Base Construction:** We will build the KB using the **entire training dataset** (not just the training split) to maximize coverage, as performance is bounded by the memory capacity **Cite {solution_lesson_node_00007}**.
2.  **Tagger Data:** The Tagger is trained on the full dataset. We will use a maximized word vocabulary size to minimize `<UNK>` tokens **Cite {solution_lesson_node_00009}**.
3.  **Seq2Seq Data:** We will create a specialized dataset by filtering the training data to include only tokens where `before != after`. This focuses the generative model on non-trivial transformations (e.g., numbers, dates) and prevents it from bias towards identity mapping.

# Training
1.  **Tagger Training:**
    *   **Loss Function:** We will use Cross-Entropy Loss with **Square-Root Smoothed Class Weights** ($\sqrt{N/N_c}$). This ensures the model focuses on rare classes (like `MONEY`) without the gradient instability caused by raw inverse frequency weighting **Cite {solution_lesson_node_00013}**.
    *   **Optimization:** We will use the **Adam** optimizer paired with a **ReduceLROnPlateau** scheduler. This dynamic learning rate schedule is critical for allowing the LSTM to escape local minima early in training, outperforming static conservative rates **Cite {solution_lesson_node_00011}**.
2.  **Seq2Seq Training:** The fallback model will be trained using standard teacher forcing on the filtered "changed" dataset.

# Evaluation
1.  **Inference Pipeline:**
    *   Pass the test sentence through the **Morphologically-Aware Tagger** to obtain the predicted class for each token.
    *   **Step 1 (Lookup):** Query the **Knowledge Base** with the pair `(token, predicted_class)`. If a match is found, output the stored value.
    *   **Step 2 (Fallback):** If the pair is missing from the KB (and the class is not `PLAIN`/`PUNCT`), pass the token to the **Seq2Seq Fallback Model** to generate the normalized string. This ensures robust handling of unseen entities while maintaining the safety of the deterministic lookup for known ones.
