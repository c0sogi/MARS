Based on the accumulated lessons and the analysis of previous iterations, I propose the **Regex-Augmented Bi-LSTM Tagger with Signal-Dense Training and Recurrent Fallback**.

This solution represents a structural synthesis that optimizes "Input Fidelity" and "Training Efficiency." It explicitly retains the robust Bi-LSTM/LSTM architecture proven superior to Transformers for this specific task **Cite {solution_lesson_node_00012}** **Cite {solution_lesson_node_00037}**, while introducing a **Signal-Dense Data Strategy** and **Explicit Feature Injection** to maximize learning efficiency and rare-class detection.

# Model
The architecture follows the decoupled "Classify-Retrieve-Generate" paradigm **Cite {solution_lesson_node_00005}**, enhanced with an explicit morphological input channel to guide the classifier.

1.  **Stage 1: Regex-Augmented Tagger (Classification)**
    *   **Structural Innovation (Input):** To definitively address the "Needle-in-a-haystack" nature of detecting rare classes (like `MONEY` or `DATE`) amidst a sea of `PLAIN` text, we employ a **Tri-Hybrid Input Representation**:
        1.  **Word Embeddings:** A trainable embedding layer with a maximized vocabulary size (100k+) to capture high-level semantics and minimize `<UNK>` tokens **Cite {solution_lesson_node_00009}**.
        2.  **Character-Level CNN:** A 1D-CNN processing character sequences to extract learned morphological features (e.g., suffixes, capitalization).
        3.  **Explicit Regex Features:** A dense vector of binary flags derived from **Regex Matching** (e.g., `is_digit`, `is_date_format`, `has_currency_symbol`, `is_upper`). Unlike previous "blind" neural approaches, this injects hard-coded, high-fidelity signals directly into the model, allowing the LSTM to distinguish complex classes instantly without needing to "discover" these patterns from scratch.
    *   **Backbone:** The concatenated representation is fed into a **Bi-directional LSTM (Bi-LSTM)**. We explicitly retain this recurrent architecture as it converges significantly faster and captures local dependencies more effectively than Transformers for this specific tagging task **Cite {solution_lesson_node_00012}**.
    *   **Head:** A standard **Softmax Classification Head**. We explicitly reject the Conditional Random Field (CRF) layer, as lessons prove it hinders convergence for this locally-determinable task **Cite {solution_lesson_node_00028}**.

2.  **Stage 2: Hybrid Normalization Strategy**
    *   **Primary (Deterministic Memory):** A **Knowledge Base (KB)** maps `(raw_token, predicted_class)` pairs to their normalized text. This handles the vast majority of cases with 100% precision.
    *   **Secondary (Neural Fallback):** For Out-of-Vocabulary (OOV) tokens, we employ a **Character-Level LSTM Seq2Seq Model with Attention**.
        *   **Strategic Retention:** We explicitly use an **LSTM** (not a Transformer) for the fallback. As identified in **Cite {solution_lesson_node_00037}**, LSTMs outperform Transformers on character-level transduction tasks with rigid formatting rules (like dates/numbers) due to their inherent sequential inductive bias.
        *   **Conditioning:** The model is conditioned on the **Class Embedding** predicted by the Tagger.

# Data
1.  **Knowledge Base Construction:**
    *   Use the **entire training dataset** to build the KB `(token, class) -> normalization` map. Maximizing coverage is the single most effective way to reduce error **Cite {solution_lesson_node_00007}**.
2.  **Tagger Data (Structural Innovation - Signal-Dense Sampling):**
    *   To solve the "Update Budget" issue **Cite {solution_lesson_node_00042}** without losing rare class signals, we construct a **Signal-Dense Training Set**.
    *   Instead of random subsampling (which floods the model with trivial `PLAIN` tokens) or using the full dataset (which is too slow), we filter the corpus to include **100% of sentences containing at least one rare class** (e.g., DATE, MONEY) and a **small random subsample (e.g., 10%) of purely PLAIN sentences**.
    *   This creates a compact, high-signal dataset that allows for many training epochs (high gradient updates) while ensuring the model sees every difficult example available.
3.  **Fallback Data:**
    *   Filter the training data to include only token pairs where `before != after` to focus the generative model on non-trivial transformations **Cite {solution_lesson_node_00027}**.

# Training
1.  **Tagger Training:**
    *   **Loss Function:** Cross-Entropy Loss with **Square-Root Smoothed Class Weights** ($\sqrt{N/N_c}$). This penalizes errors on rare classes without the gradient instability caused by raw inverse frequency weights **Cite {solution_lesson_node_00013}**.
    *   **Optimizer:** **Adam** optimizer paired with a **ReduceLROnPlateau** scheduler. This dynamic schedule is critical for allowing the LSTM to escape local minima **Cite {solution_lesson_node_00011}**.
    *   **Strategy:** Train for a high number of epochs (e.g., 10-15) on the Signal-Dense dataset. This ensures the model receives sufficient gradient updates to converge on the complex Regex/Character features **Cite {solution_lesson_node_00042}**.
2.  **Fallback Training:**
    *   Train the LSTM Seq2Seq using standard Cross-Entropy Loss with Teacher Forcing on the filtered "changed" dataset.

# Evaluation
1.  **Inference Pipeline:**
    *   **Step 1 (Feature Extraction):** Generate Word, Char-CNN, and Regex features for the test sentence.
    *   **Step 2 (Tagging):** Pass features through the **Regex-Augmented Bi-LSTM** to predict the class.
    *   **Step 3 (Retrieval):** Query the **Knowledge Base** using `(token, predicted_class)`. If a match is found, return the stored value.
    *   **Step 4 (Generation):** If the pair is missing from the KB (OOV) and the class is not `PLAIN`, pass the token and its class to the **LSTM Seq2Seq Fallback Model** to generate the normalized text **Cite {solution_lesson_node_00027}**.
