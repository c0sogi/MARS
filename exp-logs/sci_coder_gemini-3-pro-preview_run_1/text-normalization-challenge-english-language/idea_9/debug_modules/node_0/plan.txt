### Implementation Strategy

1.  **Configuration Patching**: Since the `Config` class defines paths and hyperparameters as static class attributes, we will modify them immediately after import. This ensures the demonstration runs in a separate directory (`./working/demo_execution`) with reduced hyperparameters (1 epoch, small batch size, debug mode enabled) to satisfy the time and speed constraints.

2.  **Data Preprocessing & Loading**: We will utilize `build_vocabularies` and `process_tagger_data` to generate the necessary artifacts. We will assert that vocabularies are populated and dataframes have the correct columns. We will then invoke `get_tagger_loaders` and `get_seq2seq_loaders` to verify that DataLoaders produce batches with the expected tensor shapes.

3.  **Model Verification**: We will instantiate the `MultiGranularityTagger` and `TransformerFallback` models using the vocabulary sizes derived from the previous step. We will perform a forward pass with a real batch of data to verify that the output logits have the correct dimensions corresponding to `(Batch Size, Sequence Length, Class Vocabulary Size)`.

4.  **Training Simulation**: We will instantiate `TaggerTrainer` and `Seq2SeqTrainer` and execute their `train()` methods. With `Config.NUM_EPOCHS` set to 1 and `Config.DEBUG` set to True (limiting the dataset size), this will quickly demonstrate the training loop mechanics and save model checkpoints.

5.  **Inference Pipeline**: Finally, we will initialize the `NormalizationPipeline`. It will load the trained (demo) models and process the test set. We will verify that the final submission file is generated at the expected location and adheres to the required format.
