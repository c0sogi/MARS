The implementation strategy is designed to create a robust yet fast baseline pipeline that meets all competition requirements within the time limit.

1.  **Orchestration & Configuration**: The script initializes by setting fixed random seeds for reproducibility and optimizing configuration parameters (e.g., increasing batch size to 32) to maximize GPU utilization during the compute-intensive feature generation phase.
2.  **Pipeline Execution**:
    *   **Stage 1 (Localizer)**: We train the 2D U-Net for 1 epoch. This is sufficient for the model to learn rough anatomical localization of vertebrae C1-C7.
    *   **Stage 2 (Encoder)**: We train the 2.5D CNN Encoder for 1 epoch on slice-level fracture labels to learn visual features of fractures.
    *   **Feature Generation**: We execute the `generate_features` module. This runs the Stage 1 and Stage 2 models in inference mode across the Train, Validation, and Test sets, converting raw DICOMs into lightweight feature sequences. This step utilizes caching to avoid redundant computation.
    *   **Stage 3 (Aggregator)**: We train the Bi-GRU model for 5 epochs on the generated feature sequences. This stage is computationally cheap and learns to aggregate temporal context.
3.  **Validation & Analysis**: We perform a dedicated validation pass on the hold-out set. We compute the exact **Weighted Multi-label Logarithmic Loss** and print it in the required format. We then perform failure analysis by correlating the loss with metadata (fracture count and segmentation availability) to identify error patterns.
4.  **Submission**: Finally, we check the validation metric against the threshold (0.9254). If the model performs well enough, we trigger the inference module to generate the `submission.csv` file for the test set.
