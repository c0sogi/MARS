To establish a robust and efficient baseline, I propose a **Slice-Level 2D Classification Network with Max-Pooling Aggregation**. This approach treats the 3D fracture detection problem as a Multiple Instance Learning (MIL) task, where a patient is considered "fractured" if at least one 2D slice in their scan is predicted to contain a fracture. This avoids the computational cost of 3D networks and the complexity of sequence modeling.

### Model
The architecture is a streamlined 2D Convolutional Neural Network (CNN) designed to classify individual axial slices.
*   **Input**: The model accepts a 2.5D input image formed by stacking 3 consecutive axial slices (slice $i-1$, slice $i$, slice $i+1$) as the Red, Green, and Blue channels. This captures immediate local context along the Z-axis without requiring 3D convolutions.
*   **Backbone**: A lightweight, pretrained encoder such as **ResNet-18** or **EfficientNet-B0** is used to extract spatial features from the slice stack.
*   **Classification Head**: The backbone's feature map is pooled (Global Average Pooling) and passed to a single fully connected layer with 8 output units (corresponding to C1, C2, C3, C4, C5, C6, C7, and `patient_overall`).
*   **Activation**: A Sigmoid activation function is applied to each output to generate independent probabilities for each class.

### Data
Preprocessing focuses on converting the high-volume 3D DICOM data into a manageable set of 2D training samples.
*   **Windowing**: Raw DICOM pixel values are converted to Hounsfield Units and normalized using a "bone window" (e.g., Center: 400, Width: 1800) to maximize the contrast of skeletal structures and fractures.
*   **Training Set Construction**: To ensure high signal quality for the baseline:
    *   **Positives**: Use the provided `train_bounding_boxes.csv` to identify specific slices that contain fractures. Crop or resize these slices to a standard resolution (e.g., 256x256) and label them with the specific vertebrae class (C1-C7) and `patient_overall = 1`.
    *   **Negatives**: Randomly sample slices from patients known to have no fractures (control group) and label them as all-zeros.
*   **Validation Set**: The validation set remains at the patient level (entire scans) to properly measure the competition metric, rather than slice-level accuracy.

### Training
The training process treats the task as a standard multi-label image classification problem.
*   **Loss Function**: Use **Binary Cross Entropy (BCE)** loss. While the competition metric is weighted log loss, standard BCE is sufficient and more stable for training the slice-level classifier.
*   **Optimizer**: Use **AdamW** with a standard learning rate (e.g., 1e-4) and a cosine annealing scheduler to converge quickly.
*   **Sampling Strategy**: Construct training batches with a balanced ratio of positive (fractured) slices to negative (normal) slices (e.g., 1:1 or 1:3) to prevent the model from being overwhelmed by the vast majority of healthy tissue in the dataset.

### Evaluation
Inference aggregates slice-level predictions to form a patient-level diagnosis.
*   **Inference Loop**: For each scan in the test set, iterate through the axial slices. To save time, a stride can be used (e.g., process every 2nd or 3rd slice), as fractures typically span multiple slices.
*   **Aggregation (Max Pooling)**: Collect the predicted probabilities for all processed slices in a scan. For each of the 8 targets (C1-C7, `patient_overall`), select the **maximum probability** observed across all slices. This aligns with the logic that a patient has a fracture if *any* part of their spine is fractured.
*   **Submission**: Format these aggregated maximum probabilities into the required row-based CSV format for submission.
