### Implementation Strategy

1.  **Configuration Override**: We will modify the `Config` class attributes at runtime to enable `DEBUG` mode, reduce `EPOCHS` to 1, set `BATCH_SIZE` to 4, and disable multiprocessing (`NUM_WORKERS = 0`). This ensures the code runs quickly within the demonstration constraints.
2.  **Utility Verification**: We will manually invoke `read_dicom_windowed` on a sample DICOM file to verify image loading and preprocessing (windowing/normalization). We will also test the `weighted_log_loss` function with dummy data.
3.  **Dataset Pipeline Verification**: We will generate the training dataframe using `prepare_training_data`. We will then instantiate the `FractureSliceDataset` and retrieve a single sample to verify tensor shapes (Channels, Height, Width) and label integrity.
4.  **Model Architecture Verification**: We will instantiate the `FractureClassifier` and perform a forward pass with the sample tensor from the previous step to confirm the output shape matches the expected `(Batch_Size, Num_Classes)`.
5.  **Training Loop Execution**: We will execute `run_training()`. Thanks to the debug configuration, this will train on a tiny subset of data for one epoch and save a checkpoint.
6.  **Inference Pipeline Execution**: We will execute `run_inference()`. This will load the checkpoint saved in the previous step, predict on the test set (also truncated by debug mode), and generate a `submission.csv`.
7.  **Final Output Check**: We will assert that the submission file exists and has the correct dimensions.
