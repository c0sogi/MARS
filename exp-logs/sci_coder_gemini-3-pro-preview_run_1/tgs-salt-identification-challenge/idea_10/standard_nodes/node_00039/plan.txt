The implementation strategy focuses on creating a robust yet efficient execution pipeline that fits within the time constraints while aiming for the high accuracy target (>0.833).

1.  **Configuration**: We will set the training to **50 epochs**. Given the dataset size (2400 training images) and the A100 GPU, each epoch takes mere seconds. 50 epochs allow the Cosine Annealing scheduler (configured with $T_0=50$) to complete one full cycle, maximizing convergence probability without wasting time. We use the full dataset (`debug=False`) because the subset is too small to reach the required metric.
2.  **Training**: We utilize the provided `Trainer` class. This handles the data loading, model initialization, and the compound loss optimization loop. It automatically saves the `best_model.pth` based on validation mAP.
3.  **Validation & Metrics**: Post-training, we reload the best model to perform a dedicated validation pass. This ensures we calculate the exact "Final Validation Metric" on the hold-out set. We apply the classification gating (multiplying segmentation probability by classification probability) and crop the padded predictions back to the original 101x101 size before metric calculation.
4.  **Failure Analysis**: We calculate the per-image Average Precision (AP) to quantify error. We then merge these scores with the metadata (depth `z` and salt `coverage`) to compute Pearson correlations. This identifies if the model struggles with specific depths or salt amounts.
5.  **Submission**: Conditional on the validation metric exceeding 0.833, we invoke the `predict_and_submit` function from the library to generate the submission file using the best checkpoint.
