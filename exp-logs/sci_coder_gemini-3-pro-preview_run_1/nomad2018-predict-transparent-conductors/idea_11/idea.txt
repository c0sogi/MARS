Based on the lessons learned, I propose the **Element-Wise Aggregated Deep Sets (EWA-DeepSets)** strategy. 

This strategy structurally evolves the "Augmented Point-Cloud Deep Sets" (Idea 4) by refining the aggregation mechanism. Instead of pooling all atoms into a single global vector (which dilutes species-specific geometric information), this approach performs **Per-Element Pooling** (aggregating Al, Ga, In, and O atoms into separate vectors) alongside global pooling. This aligns with **Lesson 13** (Explicit Stoichiometry) by lifting stoichiometric distinctness into the geometric representation. It also incorporates **Fractional Coordinates** to couple local positions with global lattice constraints (**Lesson 2**) and strictly enforces **Dropout** (**Lesson 24**) and **Wide MLPs** (**Lesson 17**) to manage capacity and generalization.

### Model
The architecture consists of two parallel streams with a hierarchical aggregation scheme:

1.  **Atomic Stream (Wide Point Processor):**
    *   **Input Features:** For each atom, the feature vector includes:
        *   **Atomic Identity:** One-hot encoding (Al, Ga, In, O).
        *   **Centered Cartesian Coordinates:** $(x, y, z)$ relative to the centroid (**Cite Lesson 10**).
        *   **Fractional Coordinates:** $(u, v, w)$ representing position relative to the lattice vectors. This provides a coordinate system normalized to the unit cell shape, explicitly linking local position to the global boundary conditions.
        *   **PBC-Corrected Nearest Neighbor Distance:** The scalar distance to the closest neighbor, calculated using Periodic Boundary Conditions (**Cite Lesson 15, 21**).
    *   **Encoder:** A **Wide MLP** (e.g., 512 hidden units, 3 layers) with **Batch Normalization** and **ReLU**. Crucially, **Dropout** is applied after activations to prevent overfitting to specific geometric configurations (**Cite Lesson 24**).
    *   **Linear Projection:** The final layer of the encoder projects to the latent dimension (512) *without* an activation function, allowing the full vector space to be utilized during pooling (**Cite Lesson 18**).
    *   **Hierarchical Aggregation:**
        *   **Global Pooling:** Compute **Mean** and **Max** across *all* atoms to capture system-wide properties (**Cite Lesson 5**).
        *   **Per-Element Pooling:** Compute **Mean** vectors specifically for each element type (Al-Mean, Ga-Mean, In-Mean, O-Mean). If an element is absent, its vector is zeroed. This ensures the model can distinctly weigh the geometric environments of different species (e.g., "strained Al" vs "relaxed In").

2.  **Global Stream (Thermodynamic Context):**
    *   **Input:** Lattice vector lengths, lattice angles, unit cell volume, atomic density, and **explicit stoichiometry** (**Cite Lesson 13**).
    *   **Encoder:** A **High-Capacity MLP** (256 units) with Dropout to model macroscopic boundary conditions (**Cite Lesson 9**).

3.  **Fusion Head:**
    *   **Late Fusion:** Concatenate the Global Mean, Global Max, the four Per-Element Mean vectors, and the Global Embedding (**Cite Lesson 19**).
    *   **Regressor:** A final MLP predicts `formation_energy_ev_natom` and `bandgap_energy_ev`.

### Data
1.  **Geometry Preprocessing:**
    *   Parse `geometry.xyz` files.
    *   **Centering:** Subtract unit cell centroid from Cartesian coordinates.
    *   **Fractionalization:** Multiply Cartesian coordinates by the inverse of the lattice matrix to obtain fractional coordinates.
    *   **PBC Neighbor:** Compute pairwise distance matrix using lattice vectors (minimum image convention) and extract the minimum non-zero distance per atom.
2.  **Tabular Preprocessing:**
    *   Extract lattice parameters and stoichiometry.
    *   Calculate **Volume** and **Density**.
    *   **Scaling:** Apply Standard Scaling (z-score) to all continuous features.
3.  **Target Transformation:**
    *   Apply `log(1+y)` to targets to align with RMSLE.

### Training
*   **Loss Function:** Mean Squared Error (MSE) on log-transformed targets.
*   **Optimizer:** AdamW with weight decay ($1e-4$) to regularize the wide layers.
*   **Scheduler:** `ReduceLROnPlateau` monitoring validation loss.
*   **Strategy:** Train for **200 epochs** with early stopping (patience 20). The wide, regularized architecture allows for stable convergence without the overfitting seen in residual or high-order statistical models (**Cite Lesson 33**).

### Evaluation
1.  **Inference:** Process test data using the same pipeline (Centering, Fractionalization, PBC-Neighbors, Scaling).
2.  **Prediction:** Pass through the trained model.
3.  **Inverse Transform:** Apply `exp(x) - 1`.
4.  **Submission:** Format as `id,formation_energy_ev_natom,bandgap_energy_ev`.
