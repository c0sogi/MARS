The implementation strategy involves the following steps:

1.  **Configuration Patching**: Modify the `Config` class at runtime to reduce the number of epochs (e.g., to 30) and patience, ensuring the training completes within the allotted time while using the GPU.
2.  **Training Orchestration**: Utilize `library.engine.run_training` to train the AMSA-DS model. This handles data loading, scaling, model initialization, and the training loop with early stopping.
3.  **Validation**:
    *   Reload the validation data and the best saved model.
    *   Perform inference to get predictions (which are in log space).
    *   Convert predictions back to the original scale.
    *   Compute the **Column-wise Root Mean Squared Logarithmic Error (RMSLE)**. Since the model predicts $\log(1+y)$, the RMSLE is effectively the RMSE of the model outputs versus the log-transformed ground truth.
    *   Print the metric exactly as required.
4.  **Failure Analysis**:
    *   Compute the squared error per sample in the log space.
    *   Correlate these errors with the global features (lattice parameters, density, stoichiometry, etc.) to identify which physical properties are associated with higher prediction errors.
5.  **Submission**:
    *   Compare the calculated validation metric against the threshold (0.04819517582654953).
    *   If the model performs sufficiently well, call `library.engine.generate_submission` to create the final `submission.csv` file for the test set.
