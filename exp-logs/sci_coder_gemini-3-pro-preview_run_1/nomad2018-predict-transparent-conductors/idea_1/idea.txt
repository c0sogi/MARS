To establish a robust and efficient baseline for predicting material properties, I propose a **Lattice-Conditioned Deep Sets (LCDS)** model. This approach treats the crystal structure as a permutation-invariant set of atoms, processing them independently before aggregating their features and conditioning the result on global lattice parameters. This design avoids the computational overhead of graph connectivity construction (as in GNNs) or hierarchical sampling (as in PointNet++), making it highly efficient while still leveraging both the detailed 3D geometry and the macroscopic tabular data.

### Model
The architecture consists of two parallel branches that merge for the final prediction:
1.  **Atomic Branch (Deep Sets)**:
    *   **Input**: A set of atoms for each material, where each atom is represented by its atomic type (one-hot encoded) and its 3D Cartesian coordinates $(x, y, z)$.
    *   **Processing**: A shared Multi-Layer Perceptron (MLP) is applied to each atom independently. This projects the atomic features into a higher-dimensional latent space.
    *   **Aggregation**: A global **Max Pooling** operation is applied across all atoms in a unit cell. This extracts a single, fixed-size feature vector representing the "geometric fingerprint" of the material, ensuring the model is invariant to the order of atoms in the input file.
2.  **Lattice Branch**:
    *   **Input**: The macroscopic properties provided in the tabular data: lattice vectors ($lv1, lv2, lv3$), lattice angles ($\alpha, \beta, \gamma$), and the total number of atoms.
    *   **Processing**: These features are normalized and passed through a shallow MLP to create a "lattice embedding."
3.  **Fusion and Prediction**:
    *   The geometric fingerprint and lattice embedding are concatenated to form a complete material representation.
    *   This combined vector is passed through a final regressor MLP to simultaneously predict the `formation_energy_ev_natom` and `bandgap_energy_ev`.

### Data
1.  **Geometry Parsing**: Iterate through the `geometry.xyz` files. For each material, extract the atomic coordinates and atomic species. Map the species (Al, Ga, In, O) to integer indices.
2.  **Coordinate Normalization**: Center the atomic coordinates by subtracting the geometric mean of the unit cell to ensure translation invariance.
3.  **Tabular Features**: Extract lattice vectors, angles, and composition percentages from the CSV files. Apply standard scaling (z-score normalization) to these features to ensure stable training dynamics.
4.  **Target Transformation**: Since the metric is Root Mean Squared Logarithmic Error (RMSLE) and the targets are non-negative, apply a $\log(1+y)$ transformation to the formation and bandgap energies. This allows the model to optimize Mean Squared Error (MSE) in the log-space, directly aligning the training objective with the evaluation metric.
5.  **Batching**: Use a geometric data loader (e.g., from `torch_geometric`) to handle the variable number of atoms per crystal efficiently without manual padding.

### Training
*   **Loss Function**: Mean Squared Error (MSE) on the log-transformed targets.
*   **Optimizer**: AdamW optimizer with a modest weight decay to prevent overfitting on the relatively small dataset.
*   **Scheduler**: A `ReduceLROnPlateau` scheduler to decay the learning rate when validation loss stagnates.
*   **Procedure**: Train the model for a fixed number of epochs (e.g., 100-200) with early stopping based on the validation RMSLE. Monitor both targets, potentially weighting the loss if one target dominates the gradient.

### Evaluation
1.  **Inference**: Pass the preprocessed test set (geometry + tabular data) through the trained model.
2.  **Inverse Transformation**: Apply the exponential function $\exp(x) - 1$ to the model's output to convert predictions back to the original energy scale.
3.  **Submission**: Format the IDs and predicted values into the required CSV format.
