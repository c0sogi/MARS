The implementation strategy for the `runfile.py` script is as follows:

1.  **Setup and Imports**: Import necessary libraries (`torch`, `numpy`, `pandas`, `sklearn`) and modules from the provided `library` package (`data`, `model`, `train`, `predict`, `config`). Set random seeds for reproducibility.
2.  **Device Configuration**: Automatically detect and assign the computation device (CUDA if available, else CPU).
3.  **Data Preparation**: Use `get_loaders` to load the training, validation, and test datasets. Enable caching to speed up loading.
4.  **Model Instantiation**: Initialize the `BA_ADS_Model` and move it to the configured device.
5.  **Training**: Execute `train_model` with the training and validation loaders. Limit the number of epochs (e.g., 50) to ensure the process completes quickly as a baseline, while utilizing the built-in early stopping mechanism.
6.  **Validation & Metric Calculation**:
    *   Switch the model to evaluation mode.
    *   Iterate through the validation loader to generate predictions.
    *   Calculate the Column-wise Root Mean Squared Logarithmic Error (RMSLE). Since the targets and model outputs are already in log space (`log1p`), this is equivalent to the RMSE of the model outputs against the targets.
    *   Compute the final metric as the average of the column-wise RMSLEs and print it in the required format: `Final Validation Metric: <value>`.
7.  **Failure Analysis**:
    *   Compute the mean absolute error for each validation sample.
    *   Construct a DataFrame using the global features (with appropriate names derived from `features.py`) and the computed errors.
    *   Calculate the Pearson correlation between each feature and the error magnitude.
    *   Print the top 5 features most strongly correlated with the error to identify failure modes.
8.  **Submission**:
    *   Compare the calculated final validation metric against the threshold `0.04819517582654953`.
    *   If the metric is lower than the threshold, invoke `generate_predictions` to create the submission file at `./submission/submission.csv`. This function handles test data loading, inference, inverse target transformation (`expm1`), and file saving.
