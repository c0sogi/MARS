The previous implementation failed because it did not robustly handle missing or invalid Weighted Least Squares (WLS) baseline positions in the raw GNSS data. Specifically, gaps in the WLS data led to `NaN` values in the regression targets (`target_east`, `target_north`), which immediately caused the training loss to become `NaN` (Cite debug_lesson_7). Additionally, the fallback mechanism for missing WLS columns set coordinates to `0.0`, potentially creating massive target outliers that could cause gradient explosion (Cite debug_lesson_11).

To fix this, I will:
1.  Update `library/config.py` to use a new working directory (`idea_16`), ensuring cached data is regenerated (Cite debug_lesson_2).
2.  Modify `library/data_processing.py` to:
    *   Interpolate missing WLS positions in `process_gnss_data` to fill gaps in the baseline trajectory.
    *   Set the fallback WLS position to `NaN` instead of `0.0` if columns are missing, ensuring these invalid samples can be identified.
    *   Explicitly drop samples with `NaN` targets in `load_and_process_dataset` to prevent them from entering the training loop.
