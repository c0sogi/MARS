Since raw GNSS data contains gaps (missing values), these functions return `nan` when any `NaN` is present in a column. These `nan` statistics are then used to normalize the input features in `__getitem__`, causing the model to receive invalid inputs.

To fix this, I will modify `library/dataset.py` to use `np.nanmean` and `np.nanstd`, which ignore `NaN` values during computation. Additionally, I will use `np.nan_to_num` to safely handle cases where a feature column might be entirely `NaN` (setting the mean to 0 and standard deviation to 1), ensuring that the normalization parameters are always valid.
