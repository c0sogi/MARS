The following changes address the runtime error and training instability caused by `NaN` values and stale model weights.

1.  **Sanitize Data (`library/data_processing.py`)**:
    *   In `load_and_aggregate_gnss`, I interpolate the aggregated Weighted Least Squares (WLS) position columns (`WlsPositionXEcefMeters_mean`, etc.) to fill gaps in the baseline trajectory. This prevents `NaN`s from propagating into the baseline coordinates. I also drop rows where interpolation fails (e.g., completely empty files). (Cite debug_lesson_2)
    *   In `process_dataset`, I explicitly drop rows where the calculated target residuals (`lat_res_m`, `lon_res_m`) are `NaN`. This ensures that `NaN` values do not enter the loss function, preventing the training loss from becoming `nan`.

2.  **Clean State (`library/trainer.py`)**:
    *   In `train_model`, I added a check to delete any existing `model_weights.pth` file before training begins. This prevents the `RuntimeError` where the code attempts to load incompatible weights from a previous, different experiment if the current training run fails to save a new best model.

3.  **Force Reprocessing (`runfile.py`)**:
    *   I updated the `run()` function to set `load_cached_data=False` for training, validation, and submission generation. This forces the data pipeline to re-run the processing logic (applying the new interpolation and cleaning steps) instead of loading potentially corrupt cached data.
