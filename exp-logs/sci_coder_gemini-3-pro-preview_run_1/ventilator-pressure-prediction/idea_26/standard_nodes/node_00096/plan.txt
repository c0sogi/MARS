The issue is that the `u_out` control variable, which is binary (0 or 1), is being scaled by the `RobustScaler` along with other features, resulting in float values (e.g., -1.0 and 0.0). This breaks the masking logic in the loss function and metric calculation, which relies on `u_out` being exactly 0 or 1 (or at least strictly non-negative for the `< 0.5` check) to distinguish the inspiratory phase. Consequently, the model is evaluating on the expiratory phase as well, inflating the error.

To fix this, I will:
1.  Update `library/config.py` to change `WORKING_DIR` to `idea_27`, forcing the pipeline to ignore the stale cache and regenerate the data (Cite debug_lesson_5).
2.  Modify `library/data.py` to preserve the raw `u_out` values in a new column `u_out_raw` during feature engineering.
3.  Update `reshape_to_sequences` in `library/data.py` to use this `u_out_raw` column for generating the mask tensor, ensuring the training loop and evaluation metrics receive correct binary values.
