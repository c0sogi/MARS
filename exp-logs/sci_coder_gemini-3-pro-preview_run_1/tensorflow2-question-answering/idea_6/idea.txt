### **Model: Interaction Map Convolutional Network (IMCN)**

This approach treats the relationship between the Question and the Candidate Answer not as a sequence of text, but as a **2D image of semantic similarity**. By visualizing the "texture" of matching words, the model uses efficient computer vision techniques (2D Convolutions) to identify patterns of relevance—such as diagonal lines indicating exact phrase matches or clusters indicating keyword density—without the computational cost of recurrent networks or deep Transformers.

*   **Interaction Matrix Generation:**
    *   The model begins by mapping the tokens of the Question and the Candidate to fixed, pre-trained word embeddings.
    *   It computes a **Similarity Matrix** (Interaction Map) by calculating the dot product (or cosine similarity) between every Question token embedding and every Candidate token embedding. This results in a 2D matrix where the grid points represent the similarity between specific word pairs.
*   **2D Pattern Extraction (Long Answer):**
    *   This matrix is treated as a single-channel image and passed through a **2D Convolutional Layer**. Filters scan the matrix to detect geometric patterns: a diagonal line of high similarity indicates a consecutive phrase match, while scattered high values indicate loose keyword matching.
    *   The output feature maps are passed through a **Global Max Pooling** layer to extract the strongest matching signals, which are then fed into a dense layer with sigmoid activation to predict the probability of the candidate being the Long Answer.
*   **Relevance Projection (Short Answer):**
    *   To find the specific span, the 2D feature maps are **pooled along the Question axis** (column-wise max pooling). This projects the 2D matching information down to a 1D sequence corresponding to the Candidate text length, effectively creating a "relevance profile" for the candidate.
    *   This 1D profile is passed through a lightweight convolutional layer to predict the **Start** and **End** token logits, identifying the segment with the highest density of matches.

### **Data**

*   **Preprocessing:**
    *   **Flattening:** The dataset is flattened into individual `(Question, Candidate)` pairs.
    *   **Padding:** To allow for efficient batch processing of 2D matrices, both the Question and Candidate sequences are padded or truncated to fixed lengths (e.g., Question=32 tokens, Candidate=300 tokens). This ensures the Interaction Matrix always has a consistent resolution (e.g., $32 \times 300$).
    *   **Embedding:** Tokens are mapped to a static embedding matrix (e.g., GloVe) to minimize training overhead.
*   **Labeling:**
    *   **Long Answer:** Binary labels (`1` for correct candidates, `0` for others).
    *   **Short Answer:** Start and End indices relative to the fixed candidate length.

### **Training**

*   **Multi-Task Optimization:** The model is trained using a weighted sum of two loss functions: **Binary Cross-Entropy** for the Long Answer classification and **Categorical Cross-Entropy** for the Short Answer span indices.
*   **Negative Sampling:** The training set is balanced by keeping all positive examples and randomly subsampling negative examples (e.g., retaining 20% of negatives) to prevent the model from biasing heavily towards "No Answer."
*   **Optimizer:** The Adam optimizer is used with a standard learning rate.

### **Evaluation**

1.  **Inference:** For every candidate in the test set, generate the Interaction Matrix and pass it through the IMCN to obtain the Long Answer probability and Short Answer span logits.
2.  **Long Answer Selection:** Select the candidate with the highest probability for each example. If this probability is below a tuned threshold $\tau_{long}$, predict `NULL`.
3.  **Short Answer Extraction:** If a Long Answer is selected, parse the Start/End logits to find the valid span (`Start` $\le$ `End`) with the highest cumulative score.
4.  **Final Decision:** If the confidence of the best span exceeds a secondary threshold $\tau_{short}$, output the Short Answer token indices (or YES/NO if applicable); otherwise, output only the Long Answer indices.
