### **Model: Decomposable Attention and Alignment Network (DAAN)**

This approach synthesizes the **Context-Query Attention** mechanisms from Model 2 with the **retrieval-style logic** of Model 5, but implements them in a highly parallelizable feed-forward architecture (Decomposable Attention) that avoids the sequential slowness of RNNs (Model 3) or the heavy compute of deep Transformers (Model 1).

*   **Soft Alignment (Attention):** Instead of encoding the Question and Candidate into single vectors (as in Idea 3) or processing them with convolutions (Idea 2), this model computes a **Similarity Matrix** between every Question token and every Candidate token. For each token in the Candidate, the model calculates a weighted sum of Question embeddings (an "aligned question vector"). This effectively aligns specific parts of the question (e.g., "who") to relevant parts of the text (e.g., proper nouns), providing fine-grained interaction.
*   **Comparison (Local Inference):** The original Candidate token embedding is concatenated with its corresponding "aligned question vector." This combined representation is passed through a shared **Feed-Forward Network (FFN)** (the "Compare" function). This produces a "match vector" for *every* token in the candidate, representing how well that specific word answers the aligned part of the question.
*   **Aggregation (Long Answer):** The token-level match vectors are summed to create a single global vector. This aggregate vector is passed through a binary classifier to predict the probability that the candidate is the correct Long Answer.
*   **Span Prediction (Short Answer):** The un-summed token-level match vectors are reused and passed through a linear layer to independently predict the logits for being the **Start** and **End** token of a short answer.

### **Data**

*   **Flattening:** The hierarchical dataset is flattened into individual `(Question, Candidate)` pairs.
*   **Preprocessing:** Text is tokenized and mapped to pre-trained embeddings (e.g., GloVe) to minimize training time. Candidate sequences are padded or truncated to a fixed length (e.g., 256 tokens) to enable efficient batched matrix multiplication.
*   **Labeling:**
    *   **Long Answer:** Binary label (`1` if the candidate contains the answer, `0` otherwise).
    *   **Short Answer:** Two target vectors representing the indices of the Start and End tokens relative to the candidate length. If no short answer exists, these are masked.

### **Training**

*   **Multi-Task Optimization:** The model is trained to minimize a joint loss function combining **Binary Cross-Entropy** (for the Long Answer classification) and **Categorical Cross-Entropy** (for the Start/End token predictions).
*   **Negative Sampling:** To handle class imbalance, the training set retains all positive candidates and a random subset of negative candidates (e.g., 20%).
*   **Optimizer:** Use the Adam optimizer with a standard learning rate, employing early stopping based on the validation set's loss to prevent overfitting.

### **Evaluation**

1.  **Inference:** Process all test set candidates through the DAAN model to obtain Long Answer probabilities and Short Answer span logits.
2.  **Long Answer Selection:** Identify the candidate with the highest Long Answer probability for each `example_id`. If this probability is below a tuned threshold $\tau_{long}$, predict `NULL`.
3.  **Short Answer Extraction:** If a Long Answer is selected, identify the valid span (where `Start Index <= End Index`) that maximizes the sum of the Start and End logits.
4.  **Final Decision:** If the confidence of the best span exceeds a secondary threshold $\tau_{short}$, output the Short Answer indices and the YES/NO label (if applicable); otherwise, output only the Long Answer indices.
