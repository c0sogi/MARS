The following strategy outlines the implementation of the demonstration script:

1.  **Configuration Patching**: Before initializing the pipeline, we will override the default `Config` attributes. We will redirect the working directory to a demo-specific folder (`./working/demo_execution`), reduce the vocabulary size, sequence length, and training epochs to ensure the script runs rapidly (within minutes).
2.  **Data Subsampling**: To avoid processing the massive 23M+ row dataset, we will read the first 2,000 rows from the existing metadata files (`train.csv`, `val.csv`, `test.csv`) and save them as smaller CSV files in the demo working directory. We will update `Config` paths to point to these subsets.
3.  **Vocabulary Creation**: We will use `get_vocabulary` with `load_cached_data=False` to force the creation of a new, small vocabulary based on the subsampled data.
4.  **DataLoader Initialization**: We will generate DataLoaders using `get_dataloaders`. We will verify that the batching and padding logic works by inspecting a single batch.
5.  **Model Instantiation**: We will instantiate the `GapTransformer` model. Crucially, we will explicitly pass reduced model dimensions (e.g., `d_model=64`, `n_layers=2`) to the constructor to override the default large architecture, ensuring fast CPU/GPU execution.
6.  **Training Loop**: We will execute `run_training` for 1 epoch. This demonstrates the training engine, loss calculation, and model saving functionality.
7.  **Inference & Submission**: We will run `generate_submission` to produce predictions on the subsampled test set and verify that the output CSV is correctly formatted.
8.  **Validation**: Throughout the script, assertions will be used to confirm data shapes, file existence, and logical correctness.
