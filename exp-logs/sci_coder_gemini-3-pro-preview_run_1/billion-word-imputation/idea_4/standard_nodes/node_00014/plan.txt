The strategy for the implementation of `runfile.py` is as follows:

1.  **Configuration Override**: Before initializing any data or models, we will modify the `Config` class attributes to enable `DEBUG` mode and set a limited `DEBUG_SAMPLE_SIZE` (100,000 samples) and `NUM_EPOCHS` (1). This ensures the pipeline runs as a fast baseline within the 2-hour limit.
2.  **Environment Setup**: Initialize the random seeds and logger using the provided utility functions to ensure reproducibility.
3.  **Data Loading**: Call `get_vocab` and `get_dataloaders`. We will pass `load_cached_data=False` to `get_dataloaders` to force the generation of a new, smaller dataset based on our debug settings, avoiding the overhead of processing the full 30M dataset.
4.  **Model Training**: Initialize the `InterleavedTransformer` and use the `fit_model` engine to train the model for one epoch.
5.  **Validation & Metric**: Implement a custom validation loop that:
    *   Iterates through the validation set.
    *   Reconstructs the ground truth sentence from the input tokens and target indices.
    *   Reconstructs the predicted sentence using the model's output.
    *   Computes the Levenshtein distance using `nltk.edit_distance`.
    *   Prints the "Final Validation Metric" as required.
6.  **Failure Analysis**: Compute and print the Pearson correlation between the Levenshtein distance (error magnitude) and the length of the ground truth sentences.
7.  **Submission**: If the validation metric is below the specified threshold (7.70033), generate the submission file using `generate_submission` on the test set.
