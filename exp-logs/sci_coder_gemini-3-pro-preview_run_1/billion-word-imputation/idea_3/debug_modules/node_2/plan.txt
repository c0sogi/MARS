The issue is a tensor shape mismatch in `library/trainer.py` (and potentially `library/inference.py`) caused by the model truncating input sequences that exceed `Config.MAX_LEN` (set to 32 in the demo). The `Trainer` calculates targets and masks based on the original batch sequence length (e.g., 42), while the model returns logits for the truncated length (32). This causes a `ValueError` in loss calculation and dimension mismatches in operations involving `attention_mask`.

To fix this, I will:
1.  Update `train_epoch` and `validate` in `library/trainer.py` to derive `seq_len` from the model's output (`loc_logits.size(1)`) rather than the input batch.
2.  Truncate `attention_mask` to match this output length.
3.  Filter targets (`gap_idxs`, `target_ids`) to exclude samples where the gap position falls outside the truncated sequence, ensuring loss and accuracy are only calculated for valid predictions within the model's effective window.
4.  Apply similar truncation to `attention_mask` in `generate_submission` and `library/inference.py` to prevent broadcasting errors during inference.
