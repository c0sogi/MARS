The following strategy outlines the implementation of the demonstration script:

1.  **Configuration Override**: We will first modify the `Config` class attributes to enable "Debug Mode". This involves setting `DEBUG=True`, reducing the sample size (`DEBUG_SAMPLE_SIZE=200`), shrinking the model dimensions (hidden size, layers), and limiting training to 1 epoch. This ensures the entire pipeline runs in seconds rather than hours.
2.  **Vocabulary Demonstration**: We will call `get_or_build_vocab` to generate a small vocabulary from the debug subset. We will validate that special tokens (SOS, EOS, PAD, MASK) are correctly registered.
3.  **Dataset & DataLoader Verification**: We will instantiate the `GapDataset` and `DataLoader` manually to inspect a single batch. We will assert that the input shapes are correct and that the "gap index" (the target label for localization) falls within valid bounds of the sequence.
4.  **Model Architecture Check**: We will instantiate the `DecoupledTransformer` with the reduced configuration and perform a forward pass with dummy data. We will verify that the output logits for localization and identification match the expected dimensions `(Batch, Seq_Len)` and `(Batch, Seq_Len, Vocab_Size)`.
5.  **Training Loop Execution**: We will instantiate the `Trainer` class and call `fit()`. This will run a full training cycle (train, validation, checkpointing, and submission generation) on the small debug dataset.
6.  **Inference & Submission Validation**: Finally, we will use the `InferenceEngine` to generate predictions on the test set. We will verify the existence of the submission file and check that its format (header and row structure) complies with the requirements.
