Based on the accumulated lessons, I propose the following optimized strategy. This solution structurally evolves the previous ideas by integrating a **Multi-Task Architecture** with a **Full-Data Seed Ensemble** pipeline, specifically designed to mitigate the high variance and data starvation issues identified in this low-resource setting.

# Model
**Architecture: Multi-Task XLM-R Large with Seed Ensembling**
*   **Backbone:** We will utilize **`xlm-roberta-large`**. Previous experiments confirmed that in low-data regimes (<1000 samples), this generalist massive multilingual model significantly outperforms region-specific models like MuRIL due to superior cross-lingual transfer capabilities (Cite solution_lesson_node_00024).
*   **Multi-Task Heads:** Instead of a simple span predictor, the model will employ two distinct heads (Cite solution_lesson_node_00030):
    1.  **Span Head:** A standard linear layer predicting `start_logits` and `end_logits` for the answer boundaries (Cite solution_lesson_node_00008).
    2.  **Relevance Head:** A binary classification head applied to the `[CLS]` token embedding to predict whether the input window contains the answer. This auxiliary task explicitly supervises the model to handle the "no-answer" windows generated by the sliding window process.
*   **Seed Ensemble Structure:** To address the high run-to-run variance (Cite solution_lesson_node_00013) without reducing the effective training data via cross-validation (Cite solution_lesson_node_00027), we will train **5 independent models** on the **full training dataset**. These models will be identical in architecture but initialized with different random seeds. This allows us to utilize 100% of the data for training while statistically smoothing predictions during inference.

# Data
**Preprocessing & Caching:**
1.  **Token-Based Windowing:** We will use the `xlm-roberta-large` tokenizer with `return_overflowing_tokens=True` and `return_offsets_mapping=True`. This ensures precise splitting of long documents based on the model's actual token capacity, avoiding heuristic truncation errors (Cite solution_lesson_node_00005).
2.  **Strategic Negative Sampling:** We will generate all possible sliding windows. We will retain 100% of "Positive" windows (containing the answer) and randomly downsample "Negative" windows to maintain a strict **2:1 Negative-to-Positive ratio**. This prevents the class imbalance that previously caused convergence failure (Cite solution_lesson_node_00021).
3.  **Full Dataset Merging:** We will concatenate the provided `train.csv` and `val.csv` metadata files into a single training set. With only ~800 total samples, withholding data for validation starves the model; we will rely on the ensemble strategy for robustness (Cite solution_lesson_node_00027).
4.  **Deterministic Caching:** The processed features for all 5 seeds (specifically the stochastic negative samples) will be saved to disk with explicit type sanitization (converting Numpy arrays to Lists). This guarantees that the data fed to the model is consistent and prevents serialization artifacts (Cite solution_lesson_node_00010, solution_lesson_node_00014).

# Training
**Optimization Strategy:**
*   **Differential Learning Rates (DLR):** We will implement a parameter-specific optimization strategy. The pre-trained backbone will be assigned a low learning rate (e.g., `1e-5`) to preserve its features (Stability), while the randomly initialized heads will receive a significantly higher rate (e.g., `5e-5`) to learn the task quickly (Plasticity) (Cite solution_lesson_node_00031).
*   **Explicit Parameter Grouping:** Crucially, we will define these groups using **explicit module references** (e.g., `model.backbone.parameters()`) rather than string matching on parameter names. Previous attempts using string heuristics failed to correctly isolate parameters, leading to overfitting (Cite solution_lesson_node_00033).
*   **Extended Duration:** We will train for **7 to 8 epochs**. The use of DLR slows down the backbone's adaptation; therefore, we must extend the training schedule beyond the standard 3-5 epochs to ensure full convergence (Cite solution_lesson_node_00032).
*   **Small Batch Regularization:** We will use a batch size of **4 to 8**. This introduces gradient noise that acts as an implicit regularizer, preventing the high-capacity model from memorizing the small dataset (Cite solution_lesson_node_00011).
*   **Loss Function:** A weighted sum: $L = L_{span} + \lambda L_{relevance}$.

# Evaluation
**Inference Pipeline:**
1.  **Exhaustive Sliding Windows:** The test set will be processed into overlapping token-based windows. We will run inference on **every** chunk (Cite solution_lesson_node_00004).
2.  **Ensemble Aggregation:** For each window, we will compute the logits from all 5 seed models and **average them**. This reduces the noise inherent in any single training run.
3.  **Gated Scoring:** We will calculate a final score for each candidate span using the averaged logits:
    $$ \text{Score} = (\text{Start\_Logit} + \text{End\_Logit}) + \text{Relevance\_Logit} $$
    This uses the Relevance Head to suppress high-confidence span predictions that appear in contextually irrelevant windows (Cite solution_lesson_node_00030).
4.  **Selection & Reconstruction:** For each document ID, we select the span with the maximum Gated Score and map it back to the original text using the offset mapping to produce the final quoted string.
