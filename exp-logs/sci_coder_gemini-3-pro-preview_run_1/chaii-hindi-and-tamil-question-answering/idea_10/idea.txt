Based on the extensive history of experiments and the specific lessons learned, I propose the following optimized strategy. This solution structurally evolves the approach from a single-point model to a **Full-Data Seed Ensemble**, specifically designed to resolve the conflict between **Data Starvation** (which prohibits cross-validation) and **High Variance** (which makes single-model training unreliable).

# Model
**Architecture: Multi-Task XLM-R Large Ensemble**
*   **Backbone:** We will utilize **`xlm-roberta-large`**. As established, this massive generalist model outperforms region-specific models like MuRIL in low-data regimes due to superior cross-lingual transfer (Cite solution_lesson_node_00024).
*   **Multi-Task Heads:** Each ensemble member will employ the successful dual-head architecture (Cite solution_lesson_node_00030):
    1.  **Span Head:** A linear layer predicting `start_logits` and `end_logits`.
    2.  **Relevance Head:** A binary classifier on the `[CLS]` token to predict window relevance.
*   **Ensemble Structure (Innovation):** Instead of a single model or a data-splitting Cross-Validation ensemble (which failed due to data starvation, Cite solution_lesson_node_00027), we will implement a **Full-Data Seed Ensemble**. We will train **5 independent models** on the **complete combined dataset**, each initialized with a different random seed. This allows the system to learn from 100% of the available data while statistically smoothing out the high run-to-run variance observed in this low-resource setting (Cite solution_lesson_node_00013).

# Data
**Preprocessing & Caching:**
1.  **Token-Based Windowing:** Use the `xlm-roberta-large` tokenizer with `return_overflowing_tokens=True` and `return_offsets_mapping=True` to ensure precise, token-aligned splitting of long documents (Cite solution_lesson_node_00005).
2.  **Random Negative Sampling:** Generate all sliding windows. Retain 100% of "Positive" windows and randomly downsample "Negative" windows to maintain a strict **2:1 Negative-to-Positive ratio**. We will explicitly avoid "Hard Negative Mining" as it was proven to degrade performance in this low-resource regime (Cite solution_lesson_node_00038, solution_lesson_node_00021).
3.  **Dataset Merging:** Concatenate the provided `train.csv` and `val.csv` metadata files into a single training set to maximize signal (Cite solution_lesson_node_00027).
4.  **Deterministic Caching:** Save the processed features (including the specific random selection of negatives) to disk with explicit type sanitization (converting Numpy arrays to Lists) to ensure reproducibility and prevent serialization artifacts (Cite solution_lesson_node_00010, solution_lesson_node_00014).

# Training
**Optimization Recipe:**
We will apply a rigorous optimization strategy derived from the failure analysis of previous runs:
*   **Differential Learning Rates (DLR):** Apply a low learning rate (`1e-5`) to the backbone and a higher rate (`5e-5`) to the heads (Cite solution_lesson_node_00031).
*   **Explicit Parameter Grouping:** Define parameter groups using **explicit module references** (e.g., `model.backbone.parameters()`) rather than string matching to prevent overfitting (Cite solution_lesson_node_00033).
*   **Global Weight Decay:** Apply weight decay to **ALL** parameters, including biases and LayerNorms. In this extreme low-data regime, global decay is necessary to dampen the capacity of the Large model and prevent memorization (Cite solution_lesson_node_00036).
*   **Loss Weighting:** Strictly down-weight the auxiliary relevance loss: $L = L_{span} + 0.5 \times L_{relevance}$ (Cite solution_lesson_node_00035).
*   **Small Batch Regularization:** Use a batch size of **4** to introduce gradient noise (Cite solution_lesson_node_00011).
*   **Extended Duration:** Train each seed for **7 to 8 epochs**. The use of DLR slows down backbone adaptation, requiring a longer schedule for full convergence (Cite solution_lesson_node_00032).

# Evaluation
**Inference Pipeline:**
1.  **Exhaustive Sliding Windows:** Process the test set into overlapping token-based windows and run inference on **every** chunk (Cite solution_lesson_node_00004).
2.  **Ensemble Aggregation:** For each window, compute the `start`, `end`, and `relevance` logits from all 5 seed models and **average them**. This reduces the stochastic noise inherent in any single training run.
3.  **Gated Scoring:** Calculate the final confidence score using the averaged logits:
    $$ \text{Score} = (\text{Start\_Logit} + \text{End\_Logit}) + \text{Relevance\_Logit} $$
    (Cite solution_lesson_node_00030).
4.  **Reconstruction:** Select the span with the maximum Gated Score across all windows for a given document ID and map it back to the original text using the offset mapping.
