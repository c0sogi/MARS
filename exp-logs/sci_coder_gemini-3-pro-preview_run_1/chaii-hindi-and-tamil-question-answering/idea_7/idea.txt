Based on the comprehensive analysis of the provided lessons and previous experiments, I propose the following optimized strategy. This solution structurally evolves the approach by integrating **Adversarial Training** and **Hard Negative Mining** into a **Full-Data Seed Ensemble**, specifically addressing the critical issues of data starvation, high variance, and window discrimination in this low-resource setting.

### Model
**Architecture: Multi-Task XLM-R Large with Adversarial Regularization**
*   **Backbone:** We will utilize **`xlm-roberta-large`**. Previous lessons confirmed that in low-data regimes (<1000 samples), this massive generalist model significantly outperforms region-specific models like MuRIL due to superior cross-lingual transfer (Cite solution_lesson_node_00024).
*   **Multi-Task Heads:** The model will employ two distinct heads to explicitly model answer presence (Cite solution_lesson_node_00030):
    1.  **Span Head:** A linear layer predicting `start_logits` and `end_logits` for the answer boundaries (Cite solution_lesson_node_00008).
    2.  **Relevance Head:** A binary classification head on the `[CLS]` token to predict whether the window contains the answer.
*   **Structural Innovation (Adversarial Training):** We will integrate **Fast Gradient Method (FGM)** into the training loop. By injecting small perturbations into the input embeddings during training, we smooth the loss landscape. This acts as a powerful structural regularizer, directly addressing the high run-to-run variance and overfitting tendencies observed in small-sample fine-tuning (Cite solution_lesson_node_00013, solution_lesson_node_00011).

### Data
**Preprocessing & Sampling:**
1.  **Token-Based Windowing:** Use the `xlm-roberta-large` tokenizer with `return_overflowing_tokens=True` and `return_offsets_mapping=True` to prevent heuristic truncation errors (Cite solution_lesson_node_00005).
2.  **Hard Negative Mining:** We will refine the negative sampling strategy. Instead of purely random sampling, we will explicitly prioritize **"Boundary Negatives"**—windows that are adjacent to or partially overlap the answer context but do not contain the answer span. These "Hard Negatives" force the Relevance Head to learn fine-grained discrimination rather than relying on simple keyword heuristics. We will fill the remainder of the quota with random negatives to maintain the proven **2:1 Negative-to-Positive ratio** (Cite solution_lesson_node_00021).
3.  **Full Dataset Merging:** We will concatenate the `train.csv` and `val.csv` metadata files. With only ~800 samples, we must utilize 100% of the data for training to avoid the starvation effects observed in cross-validation (Cite solution_lesson_node_00027).
4.  **Deterministic Caching:** Processed features (including the specific negative samples) will be saved to disk with explicit type sanitization to ensure reproducibility and prevent serialization artifacts (Cite solution_lesson_node_00010, solution_lesson_node_00014).

### Training
**Procedure: Full-Data Seed Ensemble**
*   **Ensemble Strategy:** We will train **5 independent models** on the full merged dataset, each initialized with a different random seed. This leverages the entire dataset for learning while mitigating stochastic noise through inference-time averaging (Cite solution_lesson_node_00013, solution_lesson_node_00027).
*   **Optimization:**
    *   **Differential Learning Rates (DLR):** Apply a low learning rate (`1e-5`) to the backbone and a higher rate (`5e-5`) to the heads (Cite solution_lesson_node_00031).
    *   **Explicit Grouping:** Use explicit module references (e.g., `model.backbone.parameters()`) to define these groups, avoiding the failure modes of string matching (Cite solution_lesson_node_00033).
    *   **Small Batch Size:** Use a batch size of **4**. This maintains the gradient noise necessary for regularization on small datasets (Cite solution_lesson_node_00011).
    *   **Extended Duration:** Train for **8 epochs**. The use of DLR and Adversarial Training requires a longer schedule to ensure full convergence of the throttled backbone (Cite solution_lesson_node_00032).

### Evaluation
**Inference Pipeline:**
1.  **Exhaustive Sliding Windows:** Process the test set into overlapping token-based windows and run inference on **every** chunk (Cite solution_lesson_node_00004).
2.  **Ensemble Aggregation:** For each window, average the `start`, `end`, and `relevance` logits across all 5 seed models.
3.  **Gated Scoring:** Calculate the final confidence score using the averaged logits:
    $$ \text{Score} = (\text{Start\_Logit} + \text{End\_Logit}) + \text{Relevance\_Logit} $$
    This suppresses high-confidence span predictions from irrelevant windows (Cite solution_lesson_node_00030).
4.  **Reconstruction:** Select the span with the maximum Gated Score and map it back to the original text using the offset mapping.
