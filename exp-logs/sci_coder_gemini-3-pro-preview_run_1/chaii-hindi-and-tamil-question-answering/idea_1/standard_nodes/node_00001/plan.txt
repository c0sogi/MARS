Here is the implementation strategy and the complete `runfile.py` script.

### Implementation Strategy

1.  **Configuration & Setup**: We initialize the environment by calling `Config.setup()` to ensure directories exist and random seeds are set for reproducibility. We override `Config.EPOCHS` to a lower value (5) to ensure the training runs quickly as a baseline, while still allowing the model to learn from the small dataset (~800 samples).

2.  **Data Loading**: We utilize `get_dataloaders(load_cached_data=True)` from the `library.dataset` module. This efficiently loads the training, validation, and test sets, handling tokenization and batching.

3.  **Model Training**: We load the `google/mt5-small` model using `load_model` and initialize the `Trainer`. The `trainer.fit()` method is executed to fine-tune the model on the training set and validate it against the validation set, saving the best checkpoint based on the Jaccard score.

4.  **Validation & Metric Reporting**: After training, we reload the best saved model checkpoint. We run a full evaluation on the validation set to compute the overall Jaccard score and print it strictly in the format `Final Validation Metric: <value>`.

5.  **Failure Analysis**: We implement a specific function `perform_failure_analysis` that iterates through the validation set in inference mode. For each sample, it generates a prediction, calculates the Jaccard score, and computes the error magnitude ($1 - \text{Jaccard}$). It then calculates and prints the Pearson correlation between this error and input features (Context Length and Question Length) to identify potential weaknesses (e.g., does the model fail on longer contexts?).

6.  **Submission Generation**: Finally, we invoke `generate_predictions()` from `library.inference`. This function uses the trained model to generate answers for the test set, post-processes them to ensure they are substrings of the context, and saves the `submission.csv` file.
