To optimize the solution for the low-resource Hindi/Tamil Question Answering task, I will implement the following changes based on the provided lessons:

1.  **Model Architecture**: Switch from the region-specific `google/muril-base-cased` back to the generalist `xlm-roberta-base`. As noted in **Lesson 00024**, generalist models often outperform specialist models in extremely low-data regimes due to better cross-lingual transfer capabilities from high-resource languages.
2.  **Training Strategy**: Abandon the 5-Fold Cross-Validation approach in favor of training a single model on the full training set. **Lesson 00027** highlights that in data-starved environments (<1000 samples), splitting data for CV reduces the effective training set size too much, harming convergence more than ensembling helps. I will use the provided `val.csv` as a fixed validation set for early stopping.
3.  **Data Loading Robustness**: Add a check in `data_loader.py` to ensure deserialized `offset_mapping` arrays are converted to native Python lists before tensor creation, preventing potential serialization issues with cached Parquet files (**Lesson 00010**).
4.  **Hyperparameters**: Reduce `EPOCHS` from 7 to 5 to prevent overfitting, as suggested by **Lesson 00011** for small-batch fine-tuning.
