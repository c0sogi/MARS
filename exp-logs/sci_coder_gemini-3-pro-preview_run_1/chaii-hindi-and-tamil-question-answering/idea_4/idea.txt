Based on the comprehensive analysis of previous experiments and lessons learned, I propose a solution that integrates the language-specific capabilities of the MuRIL backbone with the robust data sampling and ensembling strategies proven necessary for this dataset.

### Model
I propose replacing the generic multilingual `xlm-roberta-base` with **`google/muril-base-cased` (Multilingual Representations for Indian Languages)**.
*   **Architecture:** The model will function as an **Extractive Pointer Network**, utilizing a linear classification head on top of the encoder's hidden states to predict the start and end token indices of the answer span (Cite solution_lesson_node_00008).
*   **Rationale:** While XLM-R is effective, MuRIL is pre-trained specifically on Indian languages and their transliterated forms. This provides a representation space that is fundamentally better aligned with the Hindi and Tamil text in this dataset compared to a massively multilingual model.
*   **Ensemble Structure:** To mitigate the high run-to-run variance observed in small-sample fine-tuning (Cite solution_lesson_node_00013), the solution will employ a **5-Fold Cross-Validation Ensemble**. Five independent instances of the MuRIL model will be trained, each on a distinct 80% subset of the data, ensuring the system utilizes 100% of the available training samples for learning.

### Data
The data pipeline will be rigorously structured to avoid the pitfalls of previous iterations:
1.  **Token-Based Windowing:** We will utilize the MuRIL tokenizer with `return_overflowing_tokens=True` and `return_offsets_mapping=True`. This ensures that long documents are split into overlapping chunks based on the model's actual token capacity, avoiding the data loss associated with character-based heuristics (Cite solution_lesson_node_00005).
2.  **Stratified Negative Sampling (Crucial Correction):** Unlike the failed attempt in Idea 3, we will explicitly implement **Negative Sampling**. We will retain all windows containing the answer ("Positives") and randomly downsample the windows containing no answer ("Negatives") to maintain a fixed ratio (e.g., 2:1). This prevents the severe class imbalance that previously caused model instability and convergence failure (Cite solution_lesson_node_00021).
3.  **Deterministic Caching:** The processed features for all 5 folds—including the specific random selection of negative samples—will be saved to disk (Parquet) before training. This ensures that the stochastic sampling is locked in, eliminating variance from data loading and ensuring reproducibility (Cite solution_lesson_node_00014). We will explicitly sanitize deserialized data types to avoid PyTorch/NumPy conflicts (Cite solution_lesson_node_00010).

### Training
*   **Procedure:** Train one model for each of the 5 folds.
*   **Hyperparameters:** We will use a **Batch Size of 8** and train for **5 to 8 Epochs**. This specific configuration provides the necessary regularization (via gradient noise) and update frequency required for the model to generalize from this small dataset without overfitting (Cite solution_lesson_node_00011).
*   **Loss Function:** Standard Cross-Entropy Loss applied to the start and end logits.

### Evaluation
*   **Exhaustive Inference:** The test set will be processed using the same token-based sliding window strategy to generate overlapping chunks for every document. We will run inference on **all** generated chunks, avoiding heuristic retrieval steps that create bottlenecks (Cite solution_lesson_node_00004).
*   **Ensemble Aggregation:** For each test window, the start and end logits will be computed by all 5 models. We will **average these logits** to produce a robust, noise-reduced probability distribution.
*   **Span Selection:** The final answer will be the span `(start, end)` that maximizes the sum of the averaged start and end logits across all windows for a given document ID.
*   **Reconstruction:** The selected token span will be mapped back to the original text using the offset mapping to ensure the prediction is a valid, quoted substring.
