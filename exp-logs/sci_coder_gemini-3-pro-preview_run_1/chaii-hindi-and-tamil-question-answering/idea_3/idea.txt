Based on the lessons learned and the specific constraints of the Hindi/Tamil dataset, I propose the following optimized strategy. This solution introduces a **Language-Specific Backbone** (MuRIL) and a **Cross-Validation Ensemble** pipeline to maximize performance on the small dataset while mitigating the high variance observed in previous experiments.

# Model
**Backbone Upgrade:**
I propose replacing the generic `xlm-roberta-base` with **`google/muril-base-cased` (Multilingual Representations for Indian Languages)**.
- **Rationale:** While XLM-R is a strong multilingual baseline, MuRIL is pre-trained specifically on Indian languages and their transliterated counterparts. This provides a fundamentally more aligned representation space for Hindi and Tamil, capturing phonological and syntactic nuances that a 100-language model might dilute. This represents a structural shift from "Massively Multilingual" to "Language-Family Specific" encoding.

**Architecture:**
The model will retain the **Extractive Pointer Network** design (Cite Lesson 00008), using a linear QA head to predict the `start_logits` and `end_logits` for the answer span.

**Ensemble Structure:**
To address the high run-to-run variance identified in Lesson 00013, the solution will implement a **5-Fold Cross-Validation Ensemble**. Instead of a single model trained on an 80/20 split, we will train 5 independent models, each on a different 80% subset of the data. This ensures the system learns from 100% of the available training samples and statistically smooths out noise during inference.

# Data
**Preprocessing:**
1.  **Tokenization:** Use the MuRIL tokenizer. Crucially, apply **Token-Based Windowing** using `return_overflowing_tokens=True` and `return_offsets_mapping=True` to handle long documents without heuristic truncation (Cite Lesson 00005).
2.  **Stratified Splitting:** Create 5 folds using `GroupKFold` on the `context` column to prevent leakage, ensuring all windows from a single document reside in the same fold.
3.  **Window Classification:** For each fold's training set, generate:
    - **Positive Samples:** All windows containing the answer, centered or jittered.
    - **Negative Samples:** A deterministic subset of "No Answer" windows (e.g., ratio 2:1) to force the model to learn discrimination (Cite Lesson 00006).
4.  **Caching:** Persist the processed features for all 5 folds to disk (Parquet/Arrow) before training. This locks in the stochastic negative sampling, ensuring that the ensemble members are trained on fixed, reproducible data distributions (Cite Lesson 00014).

# Training
**Procedure:**
- Train 5 separate instances of the MuRIL model, one for each fold.
- **Hyperparameters:** Use a **Batch Size of 8** and train for **5 Epochs** per fold. This configuration was empirically proven to provide the necessary regularization and update frequency for this dataset size (Cite Lesson 00011).
- **Optimization:** Use AdamW with a linear learning rate decay.
- **Loss:** Standard Cross-Entropy Loss on start and end logits.

# Evaluation
**Inference Strategy:**
1.  **Exhaustive Sliding Windows:** Process the test set using the same strided window approach (e.g., stride 128, window 384) to generate overlapping chunks for every document (Cite Lesson 00004).
2.  **Ensemble Aggregation:** Pass each test window through all 5 trained models. Instead of voting on text strings, **average the raw logits** (start and end scores) across the 5 models for each token position.
3.  **Span Selection:** Identify the span `(start, end)` that maximizes the sum of the averaged start and end logits.
4.  **Reconstruction:** Use the offset mapping to extract the precise substring from the original context, ensuring the prediction is a valid, quoted answer.
