The implementation follows a streamlined "Fast Baseline" approach using the provided library modules. 
1. **Configuration**: We override the default configuration to reduce epochs to 2 and use a single seed (42) for the ensemble, ensuring execution within the 2-hour limit.
2. **Data Loading**: We manually load `metadata/train.csv` and `metadata/val.csv`. The training data is processed using `process_train_data` (with negative sampling), while the validation data is processed using `process_test_data` (sliding windows without labels) to simulate the inference pipeline and enable accurate metric calculation. A compatibility fix (converting offset mappings to numpy arrays) is applied to the validation dataframe to ensure compatibility with `QADataset`.
3. **Training**: We train the `CustomXLMRoberta` model for 2 epochs using the imported `train_fn` and `get_optimizer`/`get_scheduler`. The model is saved to the output directory.
4. **Validation**: We perform inference on the validation set, aggregating predictions across sliding windows using the same Gated Scoring logic (Start+End+Relevance) as the test pipeline. We reconstruct the answer strings and compute the Jaccard score.
5. **Failure Analysis**: We calculate the correlation between the error (1 - Jaccard) and input features (context and question length) to identify performance bottlenecks.
6. **Submission**: If the validation metric exceeds 0.60025, we trigger the `generate_submission` function (imported from `library/predict.py`) to produce the final `submission.csv` for the test set.
