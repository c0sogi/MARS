Based on the comprehensive analysis of the accumulated lessons, I propose the following optimized strategy. This solution structurally evolves the previous approaches by integrating **Adversarial Training** into a **Full-Data Seed Ensemble** pipeline. This design specifically targets the critical tension between the need for high model capacity (`xlm-roberta-large`) and the instability caused by the extremely small dataset size (~800 samples).

### Model
**Architecture: Adversarial Multi-Task XLM-R Large**
*   **Backbone:** We will utilize **`xlm-roberta-large`**. Previous lessons confirmed that in low-data regimes, this massive generalist model significantly outperforms region-specific models like MuRIL due to superior cross-lingual transfer capabilities (Cite solution_lesson_node_00024).
*   **Multi-Task Heads:** The model will employ two distinct heads to explicitly model answer presence (Cite solution_lesson_node_00030):
    1.  **Span Head:** A linear layer predicting `start_logits` and `end_logits` for the answer boundaries (Cite solution_lesson_node_00008).
    2.  **Relevance Head:** A binary classification head applied to the `[CLS]` token embedding to predict whether the window contains the answer.
*   **Structural Innovation (Adversarial Regularization):** We will integrate **Fast Gradient Method (FGM)** into the training loop. By injecting small, calculated perturbations into the input embeddings during the forward pass, we force the model to be robust to small variations in the input space. This acts as a powerful structural regularizer, directly addressing the high run-to-run variance and overfitting tendencies observed in small-sample fine-tuning (Addressing solution_lesson_node_00013, solution_lesson_node_00011).

### Data
**Preprocessing & Sampling:**
1.  **Token-Based Windowing:** Use the `xlm-roberta-large` tokenizer with `return_overflowing_tokens=True` and `return_offsets_mapping=True`. This ensures precise splitting of long documents based on the model's actual token capacity, avoiding heuristic truncation errors (Cite solution_lesson_node_00005).
2.  **Stochastic Negative Sampling with Caching:** We will generate all possible sliding windows. We will retain 100% of "Positive" windows (containing the answer) and randomly downsample "Negative" windows to maintain a strict **2:1 Negative-to-Positive ratio** (Cite solution_lesson_node_00021). Crucially, the processed features—including the specific random selection of negatives—will be saved to disk with explicit type sanitization. This locks in the data distribution, ensuring reproducibility and preventing serialization artifacts (Cite solution_lesson_node_00014, solution_lesson_node_00010).
3.  **Full Dataset Merging:** We will concatenate the provided `train.csv` and `val.csv` metadata files into a single training set. With only ~800 total samples, withholding data for validation starves the model; we will instead rely on the ensemble strategy for robustness (Cite solution_lesson_node_00027).

### Training
**Procedure: Full-Data Seed Ensemble**
*   **Ensemble Strategy:** We will train **5 independent models** on the full merged dataset, each initialized with a different random seed. This allows us to utilize 100% of the available data for training (avoiding starvation) while statistically smoothing predictions during inference (Cite solution_lesson_node_00027, solution_lesson_node_00013).
*   **Optimization Strategy:**
    *   **Differential Learning Rates (DLR):** We will apply a low learning rate (e.g., `1e-5`) to the backbone and a significantly higher rate (e.g., `5e-5`) to the heads (Cite solution_lesson_node_00031).
    *   **Explicit Parameter Grouping:** We will define these groups using **explicit module references** (e.g., `model.backbone.parameters()`) rather than string matching, ensuring that the pre-trained features are correctly isolated and preserved (Cite solution_lesson_node_00033).
    *   **Small Batch Regularization:** We will use a batch size of **4**. This introduces gradient noise that acts as an implicit regularizer, preventing the high-capacity model from memorizing the small dataset (Cite solution_lesson_node_00011).
    *   **Extended Duration:** We will train for **7 to 8 epochs**. The combination of DLR and Adversarial Training slows down the effective adaptation rate; therefore, we must extend the training schedule to ensure full convergence (Cite solution_lesson_node_00032).

### Evaluation
**Inference Pipeline:**
1.  **Exhaustive Sliding Windows:** The test set will be processed into overlapping token-based windows. We will run inference on **every** generated chunk without heuristic filtering (Cite solution_lesson_node_00004).
2.  **Ensemble Aggregation:** For each window, we will compute the `start`, `end`, and `relevance` logits from all 5 seed models and **average them**. This reduces the stochastic noise inherent in any single training run.
3.  **Gated Scoring:** We will calculate a final confidence score for each candidate span using the averaged logits:
    $$ \text{Score} = (\text{Start\_Logit} + \text{End\_Logit}) + \text{Relevance\_Logit} $$
    This uses the Relevance Head to suppress high-confidence span predictions that appear in contextually irrelevant windows (Cite solution_lesson_node_00030).
4.  **Reconstruction:** We will select the span with the maximum Gated Score across all windows for a given document ID and map it back to the original text using the offset mapping.
