### Implementation Strategy

1.  **Configuration & Setup**: Initialize the `Config` class and set random seeds for reproducibility. Adjust `epochs` to 3 to ensure the script completes well within the time limit while allowing convergence.
2.  **Custom Data Loading**: Instead of using the library's `get_train_data` (which merges train and val), I will manually load `metadata/train.csv` for training and `metadata/val.csv` for validation. This ensures a strict hold-out set for metric calculation.
3.  **Training Loop**: Implement a training loop using `MultiTaskQAModel`. I will use the `prepare_train_features` function to tokenize and create sliding windows. The model will be trained using mixed precision (AMP) to speed up execution and reduce memory usage.
4.  **Validation & Metric**: Implement an inference loop for the validation set. I will use `prepare_test_features` to handle sliding windows and offset mapping. Predictions will be reconstructed from logits, and the Jaccard score will be computed against the ground truth in `val.csv`.
5.  **Failure Analysis**: Compute the correlation between the error (1 - Jaccard) and metadata features (Context Length, Question Length) to identify performance bottlenecks.
6.  **Submission**: Check if the validation metric exceeds the threshold (0.4804...). If successful, run inference on `metadata/test.csv` and generate the `submission.csv` file in the required format.
