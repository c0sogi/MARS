# Solution Proposal

### Model
**Architecture:** Fine-Tuned Siamese DeBERTa with Densely Injected Structural Features
To overcome the failure of frozen embeddings to capture response quality (Cite **solution_lesson_node_00002**), the proposed solution moves to an **end-to-end fine-tuning** paradigm using a Transformer backbone, specifically `microsoft/deberta-v3-small`. This replaces the static feature extractor with a learnable one.
1.  **Siamese Backbone:** The model utilizes a shared DeBERTa encoder to process two input sequences independently:
    *   Branch A: `[CLS] Prompt [SEP] Response A [SEP]`
    *   Branch B: `[CLS] Prompt [SEP] Response B [SEP]`
    *   This generates contextualized `[CLS]` embeddings ($u$ and $v$) that represent the semantic quality of each response in the context of the prompt.
2.  **Interaction Layer:** We compute standard Siamese interaction terms: $|u - v|$ and $u * v$.
3.  **Structural Injection:** Crucially, we inject a vector of **Explicit Scalar Features** ($S$) directly into this dense layer. This vector preserves the specific orthogonal signals proven to be effective in previous experiments:
    *   **Relative Granularity:** Differences in both word counts and character counts (Cite **solution_lesson_node_00008**).
    *   **Non-Linear Ratios:** Length ratios ($Len(A)/Len(B)$) to provide scale-invariant signals that neural networks struggle to approximate from raw inputs (Cite **solution_lesson_node_00010**).
    *   **Formatting Signals:** Differences in newline counts to capture structural density (Cite **solution_lesson_node_00006**).
4.  **Classification Head:** The concatenated vector $[u, v, |u-v|, u*v, S]$ is passed through a multi-layer perceptron to predict the probability distribution over the three classes (Model A, Model B, Tie).

### Data
1.  **Preprocessing:**
    *   Tokenize inputs using the DeBERTa tokenizer with truncation to fit within the model's max sequence length (e.g., 512 tokens).
    *   **Feature Engineering:** Compute the auxiliary scalar vector $S$ for all samples. This includes calculating character lengths, word lengths, newline counts, and their respective pairwise differences and ratios (Cite **solution_lesson_node_00008**, **solution_lesson_node_00010**).
2.  **Cache Management:** Implement strict versioning or hashing for the cached scalar features to ensure the model does not train on stale data when feature logic is updated (Cite **solution_lesson_node_00007**).
3.  **Dataset:** Utilize the **full training dataset** (~41k samples) rather than a subset to ensure the model has sufficient data to learn complex semantic nuances (Cite **solution_lesson_node_00006**).

### Training
1.  **Strategy:** End-to-end fine-tuning of the Transformer backbone and the classification head.
2.  **Optimization:** Use the **AdamW** optimizer with a **differential learning rate** schedule:
    *   **Backbone:** Low learning rate (e.g., 2e-5) to preserve pre-trained knowledge.
    *   **Head:** Higher learning rate (e.g., 1e-3) to rapidly adapt the random initialization to the injected structural features.
3.  **Loss Function:** Categorical Cross-Entropy (Log Loss).
4.  **Regularization:** Early Stopping based on validation Log Loss.

### Evaluation
1.  **Inference:** Process the test set `Prompt + Response` pairs through the fine-tuned Siamese backbone.
2.  **Fusion:** Concatenate the resulting embeddings with the pre-computed test set scalar features (ratios, diffs).
3.  **Prediction:** Generate logits via the MLP head and apply Softmax to produce the final probabilities.
