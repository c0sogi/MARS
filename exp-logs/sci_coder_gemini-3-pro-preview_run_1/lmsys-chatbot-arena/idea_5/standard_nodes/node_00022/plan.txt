Implementation strategy:
1.  **Configuration Override**: To adhere to the "Fast Baseline" and "Limit maximum number of training samples" requirements, I will programmatically subsample the training dataset (e.g., to 25,000 samples) and save it to the working directory. I will then update `Config.train_path` to point to this subsampled file and set `Config.epochs` to 1. This ensures the training completes well within the 2-hour limit on the provided hardware.
2.  **Training**: I will execute `library.train.run_training()`. This function handles data loading (respecting the updated `Config`), model initialization, training with mixed precision and gradient accumulation, and saves the best model checkpoint.
3.  **Validation & Failure Analysis**:
    *   I will manually load the validation data using `library.data_processing.get_dataloaders` and the trained model.
    *   I will run inference in `eval` mode to compute predictions, ground truth targets, and per-sample losses (using `CrossEntropyLoss(reduction='none')`).
    *   I will calculate and print the `Final Validation Metric` (Log Loss).
    *   I will perform failure analysis by calculating the Pearson correlation between the per-sample loss (error magnitude) and the relative scalar features (e.g., length differences) to identify systematic biases.
4.  **Conditional Submission**: I will compare the calculated validation metric against the strict threshold (`1.0115036312379488`). If the metric is lower, I will call `library.inference.generate_predictions()` to generate the submission file.
