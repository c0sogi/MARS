# Optimized Solution: EfficientNet-B0 with Hierarchical Multi-Task Learning and Hard Undersampling

### Model
I propose a **Hierarchical Multi-Task Learning (MTL)** architecture designed to leverage the taxonomic structure of the dataset (Species $\rightarrow$ Family) to improve performance on rare classes.
*   **Backbone**: **EfficientNet-B0** pre-trained on ImageNet. This replaces the ResNet-18 used in the baseline, offering better parameter efficiency and feature extraction capabilities for fine-grained recognition.
*   **Dual-Head Architecture**: Instead of a single classification layer, the backbone's features (after Global Average Pooling) will branch into two parallel linear heads:
    1.  **Species Head**: Projects features to the 64,500 species classes (Primary Task).
    2.  **Family Head**: Projects features to the corresponding plant families (Auxiliary Task).
*   **Rationale**: By jointly training on Family and Species, the model can learn robust visual features for "tail" (rare) species by sharing gradients with "head" (frequent) species that belong to the same family. This acts as a structural regularizer, preventing overfitting on classes with few examples.

### Data
To address the extreme class imbalance and training time constraints, I will employ a **Hard Undersampling** strategy, which was proven to be superior to complex decoupling methods in this specific context **Cite solution_lesson_node_00009**.
*   **Preprocessing**: I will parse the `train/metadata.json` to create a mapping from `category_id` (Species) to `family` (Supercategory).
*   **Sampling Strategy**: I will construct a static training subset by capping the number of images per species at **50**.
    *   Classes with $>50$ images will be randomly subsampled to 50.
    *   Classes with $\le 50$ images will be kept in their entirety.
*   **Justification**: This reduces the dataset size from ~1.7 million to a manageable size (approx. 500k), removing the massive redundancy of frequent classes. This reduction allows for significantly more training epochs (iterations) within the compute budget, which is critical for convergence **Cite solution_lesson_node_00009**.
*   **Constraint**: The cap is set to 50 (well above 10-12) to ensure the backbone sees enough diversity per class to learn generalizable features, avoiding the feature collapse observed with aggressive truncation **Cite solution_lesson_node_00003**.
*   **Input**: Images will be resized to **224x224** and normalized.

### Training
*   **Loss Function**: A weighted multi-task loss will be used:
    $$ L_{total} = L_{species} + \lambda \cdot L_{family} $$
    where both $L_{species}$ and $L_{family}$ are Cross-Entropy losses. $\lambda$ (e.g., 0.5) balances the contribution of the auxiliary task.
*   **Optimizer**: **AdamW** will be used to optimize the weights.
*   **Scheduler**: A **One-Cycle Learning Rate Policy** will be employed to accelerate convergence.
*   **Procedure**: The model will be trained end-to-end. Unlike the decoupled approach which froze the backbone, this strategy allows the backbone to adapt to the specific fine-grained nature of the dataset, facilitated by the "Hard Undersampling" which makes full fine-tuning computationally feasible.

### Evaluation
*   **Inference**: Test images will be resized to 224x224.
*   **Prediction**: The model will perform a forward pass, and the prediction will be taken solely from the **Species Head** (argmax of the 64,500 logits). The Family Head is discarded at inference time.
