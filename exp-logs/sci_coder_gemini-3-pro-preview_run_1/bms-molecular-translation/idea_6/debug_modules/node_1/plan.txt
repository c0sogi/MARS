The issue is a dimension mismatch in the `VisualEncoder` class within `library/model.py`. The code hardcodes `self.out_channels = 1280`, assuming the output of the EfficientNet-B0 backbone has 1280 channels. However, when `timm.create_model` is called with `features_only=True`, the last feature map for EfficientNet-B0 actually has 320 channels. This causes a runtime error when the 320-channel output is passed to the `AttributeBranch`, which expects 1280 channels based on the hardcoded value. The fix is to dynamically retrieve the number of output channels from the backbone's `feature_info` attribute.
