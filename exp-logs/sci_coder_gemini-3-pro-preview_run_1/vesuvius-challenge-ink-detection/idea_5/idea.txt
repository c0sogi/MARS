Based on the lessons learned from previous iterations—specifically the success of resolution-preserving dilated convolutions and the failure of downsampling architectures—I propose the **Split-Frequency Resolution-Preserving Network (SFRP-Net)**.

This solution evolves the "Current Best" sequential model into a parallel, dual-stream architecture. It directly addresses the trade-off identified in **Lesson 00009**: the need to capture large-scale structural context without sacrificing the fine-grained pixel resolution required to detect faint ink textures.

### Model
The architecture is a fully convolutional network that maintains the original spatial resolution (1x) throughout, avoiding the information loss associated with U-Net style downsampling.

1.  **Depth-Projection Stem (Input):**
    The model accepts the 3D volume as a 65-channel input tensor. A **1x1 Convolution** projects these depth slices into a dense feature map.
    *   **Normalization:** This projection is immediately followed by **Instance Normalization**. This decouples the model from the global intensity shifts inherent in X-ray density, forcing it to learn relative structural features rather than absolute brightness (Cite solution_lesson_node_00002).

2.  **Dual-Stream Backbone (Structural Innovation):**
    The features are split into two parallel processing streams that operate simultaneously, rather than sequentially. This ensures that high-frequency texture information is not "diluted" by passing through the large-receptive-field layers required for context.
    *   **Stream A (High-Fidelity Texture):** A stack of Residual Blocks with **fixed Dilation = 1**. This stream focuses exclusively on local pixel neighborhoods, preserving the sharp edges and fine texture of the ink (Cite solution_lesson_node_00009).
    *   **Stream B (Structural Context):** A stack of Residual Blocks with **exponentially increasing dilation (1, 2, 4, 8)**. This stream expands the receptive field to capture the shape and continuity of ink strokes, allowing the model to bridge disjointed segments (Cite solution_lesson_node_00003).
    *   **Spatial Normalization:** Within both streams, all convolutional layers utilize **Batch Normalization**. Unlike the input stem, these layers benefit from the global statistics of the dataset to define consistent texture boundaries (Cite solution_lesson_node_00005).

3.  **Fusion Head:**
    The outputs of Stream A and Stream B are concatenated along the channel dimension. A final **1x1 Convolution** fuses the local texture cues with the global context features, followed by a Sigmoid activation to produce the probability map.

### Data
1.  **Preprocessing:**
    The 65 z-slices of the 3D surface volumes will be stacked to form a `(65, H, W)` input tensor. Pixel values will be normalized to the `[0, 1]` range.
2.  **Batch Strategy:**
    We will strictly maintain a **Batch Size of 32**. Although the dual-stream architecture increases parameter count, we will adjust the channel width (e.g., to 32 or 48 channels per stream) to fit within GPU memory rather than reducing the batch size. This ensures we preserve the total "iteration budget" required for the optimizer to converge on this small dataset (Cite solution_lesson_node_00004).

### Training
1.  **Loss Function:**
    We will use **Binary Cross Entropy (BCE) with Logits Loss**, applying a positive class weight (e.g., 2.0) to counteract the sparse nature of the ink signal.
2.  **Optimization:**
    The model will be trained using the **Adam** optimizer for 15-20 epochs. The parallel architecture allows gradients to flow directly to the specific scale (texture vs. context) that requires adjustment, facilitating stable convergence.

### Evaluation
1.  **Inference:**
    Predictions will be generated on the test set using a sliding window approach with the trained model.
2.  **Threshold Calibration:**
    We will not use a default decision threshold of 0.5. After generating probability maps for the validation set, we will perform a **post-hoc threshold search** to identify the specific cutoff value that maximizes the F0.5 score. This calibrated threshold will then be applied to the test set predictions to generate the final run-length encoded submission (Cite solution_lesson_node_00001).
