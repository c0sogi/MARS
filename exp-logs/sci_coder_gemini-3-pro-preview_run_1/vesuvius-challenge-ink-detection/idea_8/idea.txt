Based on the lessons learned, I propose the **Full-Resolution Dilated U-Net (FR-UNet)**.

This solution represents a structural evolution of the "Depth-Compressed U-Net" (Idea 2) and the "Hyper-Dense Network" (Idea 7). It resolves the conflict between the need for high-resolution texture (Lesson 00009) and deep contextual abstraction (Lesson 00016) by implementing a U-Net-style skip-connection topology that operates entirely at full spatial resolution (1x) using dilated convolutions, rather than downsampling.

### Model
The architecture is a symmetric encoder-decoder network that maintains the original image dimensions throughout the entire forward pass.

1.  **Input Stem (Intensity Decoupling):**
    The 65-channel volumetric input is projected into a dense feature map (e.g., 64 channels) using a **1x1 Convolution**.
    *   **Normalization:** This layer is immediately followed by **Instance Normalization**. This is strictly retained to decouple the model from global X-ray intensity shifts, ensuring the network learns relative structural features (Cite solution_lesson_node_00002).

2.  **Dilated Encoder (Context Expansion):**
    The stem output passes through a sequence of 4 Residual Blocks with **Exponentially Increasing Dilation (1, 2, 4, 8)**.
    *   **Purpose:** This section mimics the "downsampling" path of a traditional U-Net by expanding the receptive field to capture global shape and stroke continuity (Cite solution_lesson_node_00003).
    *   **Constraint:** Unlike a standard U-Net, we **do not use pooling or strided convolutions**. The spatial resolution remains fixed (Cite solution_lesson_node_00009).
    *   **Normalization:** All blocks in the encoder utilize **Batch Normalization** to preserve texture statistics (Cite solution_lesson_node_00005).

3.  **Dilated Decoder (Hierarchical Refinement):**
    The features are processed by a symmetric sequence of 4 Residual Blocks that progressively reduce dilation (8, 4, 2, 1).
    *   **Skip Connections:** At each stage, the input to the decoder block is the **summation** (or concatenation) of the previous decoder output and the corresponding encoder block's output.
    *   **Structural Innovation:** This topology addresses the failure of the "Hyper-Dense" network (Idea 7). Instead of feeding early, intensity-correlated features directly to the classifier (which causes overfitting to brightness), the skip connections inject these fine details into the *decoder*. This forces the model to process and refine the low-level texture through deep, non-linear layers before making a final prediction (Cite solution_lesson_node_00016).

4.  **Classification Head:**
    The final refined feature map is passed through a **1x1 Convolution** and **Sigmoid** activation to generate the probability map.

### Data
1.  **Preprocessing:**
    Load the 65 z-slices for each patch from `metadata/train.csv` and stack them to form a `(65, H, W)` input volume. Normalize pixel values to `[0, 1]`.
2.  **Batch Strategy:**
    We will strictly maintain a **Batch Size of 32**. To accommodate the memory requirements of the full-resolution encoder-decoder without reducing the batch size, we will fix the channel width (e.g., at 64 channels) rather than doubling it at each stage. This ensures we preserve the total "iteration budget" required for the optimizer to converge on this small dataset, avoiding the underfitting observed with larger batches or the instability of tiny batches (Cite solution_lesson_node_00004, solution_lesson_node_00013).

### Training
1.  **Loss Function:**
    Use **BCEWithLogitsLoss** with a positive class weight (e.g., 2.0) to address the class imbalance (approx. 13% ink).
2.  **Optimizer:**
    Train using the **Adam** optimizer.
3.  **Procedure:**
    Train for 15-20 epochs. The skip connections facilitate gradient flow to early layers, while the sequential structure ensures stable convergence compared to parallel-branch architectures.

### Evaluation
1.  **Inference:**
    Generate probability maps for the test set using a sliding window approach with the trained model.
2.  **Threshold Calibration:**
    We will not use a default threshold of 0.5. After generating predictions on the **validation set**, we will perform a **post-hoc threshold search** to identify the specific probability cutoff that maximizes the **F0.5 score**. This calibrated threshold will then be applied to the test predictions to generate the final binary masks (Cite solution_lesson_node_00001).
