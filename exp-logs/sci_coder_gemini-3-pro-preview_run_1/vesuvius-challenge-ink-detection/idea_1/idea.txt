# Baseline Approach: Shallow Depth-Projection CNN

## Model
I propose a **Shallow Depth-Projection CNN**, a lightweight fully convolutional neural network designed to efficiently condense volumetric data into a 2D segmentation mask without the computational overhead of U-Nets or Transformers.

The architecture consists of three distinct stages:
1.  **Learnable Surface Projection (Depth Compression):** The input is a tensor of shape `(Batch, 65, H, W)`, treating the 65 z-slices of the scan as input channels. The first layer is a **1x1 Convolution** with a small number of output filters (e.g., 16). This layer effectively learns a weighted average of the depth slices, identifying which layers in the vertical stack contain the ink signal and projecting the relevant information into a condensed 2D feature map.
2.  **Spatial Denoising:** The projected features are passed through a shallow stack of **two 3x3 Convolutional layers** followed by ReLU activations. These layers operate spatially to aggregate context from neighboring pixels, smoothing out noise and ensuring that detected ink pixels form coherent shapes (letters/strokes) rather than isolated artifacts.
3.  **Classification Head:** A final **1x1 Convolution** reduces the features to a single channel, followed by a Sigmoid activation to output a probability map `(Batch, 1, H, W)` representing the likelihood of ink presence.

This design differs from the provided architectures by avoiding downsampling/upsampling (U-Net), complex attention mechanisms (TimeSformer), or non-differentiable tree ensembles (GBDT). It maintains full spatial resolution throughout, ensuring high precision for fine ink details.

## Data
**Preprocessing:**
1.  **Loading:** Utilizing the `metadata/train.csv` generated in the provided metadata script, load the 3D surface volumes for each patch. All 65 `.tif` slices will be stacked to form a 65-channel input image.
2.  **Normalization:** The EDA indicates pixel values range from 0 to 255 with a mean around 83. We will normalize inputs to the `[0, 1]` range by dividing by 255.0 to accelerate convergence.
3.  **Batching:** Data will be served in batches of patches (e.g., size 256x256 or 512x512) to fit within GPU memory.

**Validation Split:**
We will strictly adhere to the `metadata/val.csv` split provided in the task description to ensure our internal F0.5 metrics correlate with the leaderboard and to prevent data leakage.

## Training
**Objective Function:**
We will use **Binary Cross Entropy (BCE) with Logits Loss**. To address the class imbalance (approx. 13% ink pixels vs. 87% background), we will apply a fixed `pos_weight` (e.g., 2.0 or 3.0) to the positive class. This encourages the model to recall ink pixels without aggressively over-predicting, which is crucial for the precision-heavy F0.5 metric.

**Optimization:**
-   **Optimizer:** Adam optimizer with a default learning rate of 1e-3.
-   **Procedure:** Train for a fixed number of epochs (e.g., 10-15) or until the validation loss plateaus. Given the simplicity of the model, convergence should be rapid.

## Evaluation
**Inference:**
1.  **Tiled Prediction:** For the test fragments, the large volumes will be processed in sliding window tiles (patches) corresponding to the training input size.
2.  **Stitching:** The predicted patches will be stitched back together to reconstruct the full-size probability map for the fragment.
3.  **Thresholding:** A global probability threshold will be determined by maximizing the F0.5 score on the validation set. This threshold will be applied to the test predictions to create a binary mask.

**Submission:**
The binary mask will be converted into the required Run-Length Encoding (RLE) format. The pixel indices will be flattened (column-major order: left-to-right, then top-to-bottom) and converted to `start length` pairs for the final `submission.csv`.
