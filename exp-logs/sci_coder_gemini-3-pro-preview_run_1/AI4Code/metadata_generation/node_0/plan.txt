The strategy for generating the metadata is as follows:

1.  **Setup and Directory Creation**: Initialize the paths for input data (`./input`) and output metadata (`./metadata`). Create the metadata directory if it doesn't exist.
2.  **Load Data**: Read `train_orders.csv`, `train_ancestors.csv`, and `sample_submission.csv` using pandas.
3.  **Data Merging and Preprocessing**:
    - Merge the training orders with ancestor information to facilitate group-based splitting.
    - Fill missing `ancestor_id` values with the notebook's own `id` to ensure every notebook belongs to a group.
    - Construct relative file paths for training and test notebooks (e.g., `train/{id}.json`).
4.  **Group-based Splitting**:
    - Identify unique `ancestor_id`s.
    - Shuffle these groups using a fixed random state (42).
    - Split the groups into 80% training and 20% validation sets. This ensures that all versions/forks of a specific notebook (which share an ancestor) stay within the same split, preventing data leakage.
5.  **Metadata Generation**:
    - Create the training and validation dataframes based on the group split.
    - Create the test dataframe from the sample submission file.
    - Save these dataframes as CSV files in the `./metadata` directory.
6.  **Verification**:
    - Load the generated metadata files.
    - Print summary statistics (count, unique ancestors).
    - Verify that there is no overlap of `ancestor_id` between training and validation sets.
    - Perform a random check of 1000 file paths from each dataset to ensure they resolve to existing files in the `./input` directory.
    - Raise assertions if any validation step fails.
