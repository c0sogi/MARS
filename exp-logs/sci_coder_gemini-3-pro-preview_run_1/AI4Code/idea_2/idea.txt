Based on the accumulated lessons, I propose the **Hybrid Anchor-Pairwise Sorting Network (HAPS)**. This solution evolves the previous "Semantic Anchor Classifier" by integrating a secondary pairwise mechanism specifically designed to resolve the "micro-ordering" collisions identified as a weakness in dense notebooks.

### Model
The architecture employs a multi-task learning framework built upon a frozen backbone.

1.  **Backbone:** We retain the **Sentence Transformer (MiniLM)** to generate fixed, pre-computed embeddings for all code and markdown cells. This ensures high throughput and low resource consumption.
2.  **Symmetric Projection Towers:** We employ two distinct, learnable MLP projection heads—one for Code cells and one for Markdown cells. Both project the 384-dimensional backbone embeddings into a shared **512-dimensional latent space**. This symmetric design aligns the heterogeneous manifolds of code and text, a critical improvement over asymmetric designs **Cite solution_lesson_node_00003**. The 512-dimensional width provides sufficient capacity to capture fine-grained geometric relationships **Cite solution_lesson_node_00004**.
3.  **Head 1: Macro-Ordering (Anchor Attention):** This head computes the dot product between a projected Markdown embedding (Query) and all projected Code embeddings (Keys) in the notebook. A Softmax function converts these scores into probabilities, representing the likelihood of the markdown cell belonging to the interval preceding each code cell **Cite solution_lesson_node_00002**.
4.  **Head 2: Micro-Ordering (Pairwise Coherence):** To address the "collision" failure mode where multiple markdown cells map to the same code anchor **Cite solution_lesson_node_00002**, we introduce a **Bilinear Pairwise Head**. This head takes the projected embeddings of two markdown cells, $M_i$ and $M_j$, and outputs a scalar probability $P(M_i \prec M_j)$ indicating whether $M_i$ should semantically precede $M_j$. This head shares the markdown projection tower with Head 1, ensuring feature efficiency.

### Data
1.  **Preprocessing:** We pre-compute and cache the MiniLM embeddings for the entire dataset to avoid repeated forward passes of the Transformer.
2.  **Label Generation:**
    *   **Anchor Labels:** For Head 1, each markdown cell is labeled with the index of the code cell that immediately follows it.
    *   **Pairwise Labels:** For Head 2, we generate training pairs specifically from **hard examples**. We sample pairs of markdown cells that fall within the *same* ground-truth interval (i.e., between the same two code cells). These are the pairs the Anchor head cannot distinguish. We assign binary labels (0 or 1) based on their true relative order.

### Training
1.  **Objective Function:** We minimize a joint loss: $L = L_{CrossEntropy} + \lambda L_{BinaryCrossEntropy}$. The first term optimizes the global placement relative to code anchors, while the second term optimizes the relative ordering of colliding markdown cells.
2.  **Optimization:** We use the Adam optimizer with a **constant, aggressive learning rate (e.g., 1e-3)**. We explicitly **disable warmup schedules and label smoothing**, as these were found to hinder convergence when training adapters on frozen features **Cite solution_lesson_node_00006**.
3.  **Batching:** We use a batch size of 64 to maintain a high frequency of gradient updates, which is crucial for training the projection heads effectively **Cite solution_lesson_node_00004**.

### Evaluation
1.  **Step 1: Global Sort:** For a test notebook, we compute the "Expected Index" for each markdown cell using the output probabilities from the Anchor Head (Head 1). We perform an initial sort of all markdown cells based on these continuous values.
2.  **Step 2: Local Refinement:** We apply a **Sliding Window Refinement** pass. We iterate through the sorted list and identify adjacent markdown cells whose Expected Indices are within a small threshold $\epsilon$ (indicating uncertainty or collision). For these pairs, we query the Pairwise Head (Head 2). If the Pairwise Head predicts a high probability that the second cell should precede the first, we swap them. This resolves local ordering ambiguities without the cost of a full $O(N^2)$ comparison.
