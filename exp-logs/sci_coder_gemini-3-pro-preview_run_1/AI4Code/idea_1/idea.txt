Based on the dataset characteristics and the requirement for a distinct, highly efficient baseline, I propose the **Semantic Anchor Classifier**.

### Model
The architecture reframes the ordering problem as a "dynamic classification" task, where markdown cells are classified into positions defined by the code cells in their specific notebook.

1.  **Frozen Backbone:** We utilize a lightweight, pre-trained Sentence Transformer (e.g., `sentence-transformers/all-MiniLM-L6-v2`) to extract fixed semantic embeddings for all markdown and code cells. This backbone remains frozen to minimize resource usage and training time.
2.  **Projection Head:** A small, trainable Multilayer Perceptron (MLP) acts as an adapter. It projects the frozen markdown embeddings into a "Query" vector space.
3.  **Dynamic Anchors:** For any given notebook, the code cells serve as the class labels (anchors). We append a learnable "End-of-Notebook" vector to this set to capture markdown cells that appear after the final code cell.
4.  **Attention Scoring:** The model calculates the dot product between the projected markdown "Query" and all code "Anchor" embeddings in the notebook.
5.  **Output:** A Softmax is applied to these scores to produce a probability distribution, representing the likelihood of the markdown cell appearing immediately before each specific code cell.

### Data
1.  **Preprocessing:** Cell text will be cleaned and truncated to a modest length (e.g., 128 tokens) to maximize throughput.
2.  **Pre-computation:** To ensure efficiency, we will run the frozen backbone once over the entire dataset to generate and cache embeddings for all cells. This avoids re-running the Transformer during the training of the MLP head.
3.  **Label Generation:** For training, each markdown cell is assigned a target integer label corresponding to the 0-based index of the code cell that immediately follows it. If a markdown cell is at the end of the notebook, it is assigned to the index of the "End-of-Notebook" anchor.

### Training
1.  **Loss Function:** We will use **Cross-Entropy Loss**. Unlike standard classification with fixed classes (e.g., "Cat" vs. "Dog"), here the classes are dynamic (the specific code cells of the current notebook).
2.  **Optimization:** We will use the Adam optimizer. Since we are only training the lightweight MLP projection head and the single "End" token embedding, the model is expected to converge very quickly (likely within a few epochs).
3.  **Batching:** Data will be batched by notebook. This allows us to efficiently compute the matrix multiplication between all markdown queries and all code keys for a given notebook in a single operation.

### Evaluation
1.  **Inference:** For each test notebook, we generate probabilities for every markdown cell against the notebook's code anchors.
2.  **Soft Ranking:** Instead of assigning a markdown cell to a single integer position (which causes sorting collisions), we compute the **Expected Index** ($ \sum_{i} \text{Probability}_i \times i $). This results in a continuous scalar value for each markdown cell.
3.  **Ordering:** The final `cell_order` is generated by sorting the markdown cells based on their Expected Index values. Code cells retain their original relative positions.
