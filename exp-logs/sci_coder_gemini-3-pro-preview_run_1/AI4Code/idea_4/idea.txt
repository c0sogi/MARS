# Proposed Solution: Dual-Context CodeBERT Network (DC-CodeBERT)

Based on the empirical lessons, I propose a structural evolution of the "Contextualized Anchor-Attention Network" (Idea 3). The new solution, **DC-CodeBERT**, introduces two major advancements:
1.  **Domain-Specific Backbone:** Replacing the generic `MiniLM` with `microsoft/codebert-base` to better capture the semantic dependencies between code execution logic and markdown descriptions.
2.  **Dual-Context Architecture:** Extending the "Contextualized Anchor" concept (which modeled code as a sequence) to the markdown domain by introducing a **Permutation-Invariant Set Encoder**. This allows markdown cells to resolve ambiguities by attending to the global *content* of the notebook (the set of other markdown cells) without assuming a ground-truth order.

## Model
The architecture is a two-tower network built upon a frozen backbone, designed to align a set of shuffled markdown queries against a sequence of code anchors.

1.  **Backbone (CodeBERT):** We replace the generic `sentence-transformers/all-MiniLM-L6-v2` with **`microsoft/codebert-base`**. Code cells constitute ~66% of the data, and their semantics (e.g., distinguishing `model.fit` from `plt.plot`) are the primary signal for ordering. CodeBERT is pre-trained specifically on bimodal code-text data, providing a far richer starting representation than MiniLM. We freeze this backbone to maintain computational feasibility.
2.  **Symmetric Projection:** We employ two separate MLP projection heads to map the CodeBERT embeddings (768-dim) into a shared 512-dimensional latent space. This symmetric projection is retained to geometrically align the heterogeneous modalities **Cite solution_lesson_node_00003**.
3.  **Code Branch (Sequence Context):** The ordered sequence of projected code embeddings is fed into a **Transformer Encoder with Sinusoidal Positional Encodings**. This generates "Contextualized Anchors" that represent the execution flow of the notebook **Cite solution_lesson_node_00013**.
4.  **Markdown Branch (Set Context - Structural Innovation):**
    *   In previous iterations, markdown cells were processed as independent queries.
    *   We introduce a **Set Transformer Encoder** (a Transformer *without* positional encodings) to process the shuffled markdown cells.
    *   **Mechanism:** This allows each markdown cell to attend to all other markdown cells in the notebook. By aggregating global context (e.g., "I am one of 5 markdown cells" or "I contain the word 'Conclusion' while another cell contains 'Introduction'"), the model can refine the representation of each markdown cell based on the *set* of available contents, creating "Contextualized Queries" that are permutation-invariant.
5.  **Attention Head:** We compute Cross-Attention where the **Contextualized Markdown Set** serves as Queries and the **Contextualized Code Sequence** serves as Keys/Values. A Softmax over the code positions produces the placement probabilities.

## Data
1.  **Pre-computation:** We perform a single inference pass over the entire dataset using the frozen `microsoft/codebert-base` model. We extract and cache the `[CLS]` token embedding for every code and markdown cell. This is feasible within the runtime limits and avoids repeated heavy forward passes.
2.  **Input Construction:**
    *   **Anchors:** The cached embeddings of code cells are loaded as an ordered sequence.
    *   **Queries:** The cached embeddings of markdown cells are loaded as a shuffled bag (set).
3.  **Full Dataset Training:** We utilize the entire training dataset (~140k notebooks) rather than a subset, as scaling data volume was proven to be the primary driver of performance **Cite solution_lesson_node_00014**.

## Training
1.  **Loss Function:** We use **Cross-Entropy Loss**, treating the problem as a classification task where each markdown cell must predict the index of the code cell that immediately follows it (or the "End-of-Notebook" token).
2.  **Optimization:** We use the **AdamW** optimizer with a **constant learning rate of 1e-3**. We explicitly disable warmup schedules and label smoothing, as these were found to hinder the convergence of lightweight adapters on frozen features **Cite solution_lesson_node_00006**.
3.  **Batching:** We use a batch size of **64 notebooks**. This balances memory constraints with the need for a high frequency of gradient updates to train the projection heads and context encoders effectively **Cite solution_lesson_node_00004**.

## Evaluation
1.  **Inference:** For each test notebook, the model outputs a probability distribution for each markdown cell over the contextualized code anchors.
2.  **Soft Ranking:** We calculate the **Expected Index** ($ \sum_{i} P_i \times i $) for each markdown cell. This continuous score implicitly handles local ordering ambiguities better than explicit pairwise refinement **Cite solution_lesson_node_00008**.
3.  **Sorting:** The final `cell_order` is generated by sorting the markdown cells based on their Expected Index and interleaving them into the fixed code sequence. We acknowledge the ~0.4% metric noise floor when comparing results **Cite solution_lesson_node_00015**.
