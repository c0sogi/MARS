Implementation Strategy:
1.  **Environment Setup**: We begin by patching `tqdm` to suppress progress bars, complying with the requirement for silent execution. We then import the necessary modules from the provided library files (`library.config`, `library.trainer`, `library.hybrid_system`).
2.  **Configuration Override**: To ensure the "fast baseline" completes within the 2-hour limit, we override specific `Config` parameters. We set `DEBUG_SUBSET_SIZE` to 150,000 to train on a representative subset of digit-containing tokens, reduce `NUM_EPOCHS` to 3, and increase `BATCH_SIZE` to 512 to fully utilize the A100 GPU.
3.  **Training**: We execute `run_training(load_cached_data=True)`. This function orchestrates the entire training pipeline: building/loading the tokenizer, generating N-gram statistics, creating the dataset (filtered for relevant tokens), and training the Neural Seq2Seq model.
4.  **Validation**:
    *   We instantiate the `HybridPredictor`, which loads the trained model and N-gram stats.
    *   We load the validation dataset (`metadata/val.csv`) and preprocess it (filling NaNs, casting IDs).
    *   We run the hybrid inference logic: routing tokens to either the N-gram memory (standard text) or the Neural model (complex/digit-heavy text) based on the heuristic router.
    *   We calculate the exact prediction accuracy (percentage of tokens where predicted string matches target string exactly).
    *   We print the `Final Validation Metric` with full precision.
5.  **Failure Analysis**: We perform a post-hoc analysis on the validation results. We calculate the correlation between prediction errors and input token length and analyze error rates across different semiotic classes to identify weaknesses.
6.  **Submission**: We compare the calculated validation accuracy against the strict threshold (`0.9784130832472395`). If the model's performance exceeds this threshold, we generate the final submission file for the test set using `predictor.generate_submission()`.
