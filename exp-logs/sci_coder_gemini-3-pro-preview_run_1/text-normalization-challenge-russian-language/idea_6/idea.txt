Based on the provided lessons and the analysis of previous attempts, I propose the **Dual-Granularity Hybrid Neuro-Symbolic System**. This solution structurally evolves the architecture by introducing a **Hybrid Tokenization Strategy** to resolve the "Context Starvation" issue while maintaining the efficiency of the "Hierarchical Lookup".

# Model

The architecture consists of two distinct solvers managed by a **Context-Precedence Router**:

1.  **Symbolic Solver (The "Head"):** Retain the **Hierarchical N-gram Lookup** (Trigram $\to$ Bigram $\to$ Unigram). This component provides $O(1)$ retrieval for the 90%+ of tokens (`PLAIN`, `PUNCT`) that are deterministic and frequent (Cite solution_lesson_node_00001).

2.  **Neural Solver (The "Tail"):** A **Dual-Granularity Transformer**.
    *   **Structural Innovation:** Unlike previous iterations that treated the entire input sequence as characters (leading to weak context representations, Cite solution_lesson_node_00012) or full sentences (leading to noise, Cite solution_lesson_node_00013), this model employs **Hybrid Tokenization**:
        *   **Context Encoders:** The context words (±2 window) are tokenized using a **BPE (Byte-Pair Encoding)** tokenizer learned on the training corpus. This captures high-level syntactic and morphological information (e.g., case endings, root words) much more efficiently than raw characters, enabling the model to grasp the grammatical rules governing inflection.
        *   **Target Encoder:** The target token (the number/symbol to be normalized) is tokenized at the **Character Level**. This preserves the precise orthography of open-set sequences (e.g., "1,234.56") which BPE might fragment inconsistently.
    *   **Fusion:** The BPE embeddings (Context) and Character embeddings (Target) are projected to a shared dimension and concatenated into a single sequence `[BPE_Prev2, BPE_Prev1, <SEP>, Char_Target, <SEP>, BPE_Next1, BPE_Next2]` fed into the Transformer Encoder-Decoder.

3.  **Router:** A deterministic logic layer that implements the **Contextual Precedence** strategy (Cite solution_lesson_node_00018):
    *   **Priority 1 (Specific Memory):** Query the **Trigram** table. If the exact `(prev, target, next)` sequence exists, return the value.
    *   **Priority 2 (Contextual Generalization):** If the token contains **digits** (Regex `\d`), route it to the **Neural Solver**. This bypasses the "Unigram Trap" where generic statistics override local grammar.
    *   **Priority 3 (Generic Memory):** Back off to **Bigram** and then **Unigram** lookups.
    *   **Priority 4:** Identity fallback.

# Data

1.  **Sequence Reconstruction:** Reconstruct full sentences from the tabular data using `sentence_id` and `token_id` to enable context extraction.
2.  **Vocabulary Generation:**
    *   Train a BPE Tokenizer (vocab size ~32k) on the `before` text of the entire training set.
    *   Build a Character Vocabulary from the `before` text of the training set.
3.  **Neural Dataset Construction:** Construct a training set that explicitly prevents "Context Starvation" (Cite solution_lesson_node_00012):
    *   **Hard Samples:** Include 100% of tokens from semiotic classes (`DATE`, `CARDINAL`, `MEASURE`, etc.) and any token containing digits.
    *   **Context Anchors:** Include a **30% random subset of `PLAIN` and `PUNCT` tokens**. This volume is critical for the BPE embeddings to learn robust representations of Russian syntax (the "background" data), ensuring the model understands the grammatical case imposed by the context words.
4.  **Input Formatting:** For each sample, extract the ±2 word window. Tokenize the context words with BPE and the target token with the Character tokenizer.

# Training

1.  **Artifact Versioning:** All saved artifacts (BPE tokenizer, N-gram maps, Model Checkpoints) will be saved with filenames containing a **configuration hash**. This strictly prevents the silent caching failures observed in previous runs (Cite solution_lesson_node_00002).
2.  **Symbolic Training:** Perform a single-pass Maximum Likelihood Estimation on the *full* dataset to populate the N-gram hash maps.
3.  **Neural Training:** Train the Dual-Granularity Transformer from scratch.
    *   **Loss:** Cross-Entropy with Label Smoothing (0.1) to handle valid orthographic variations.
    *   **Optimization:** Use AdamW with a cosine annealing schedule. The use of BPE for context significantly reduces the sequence length compared to full-character models, allowing for larger batch sizes and faster convergence on the A100 GPU.

    *   Else, if `contains_digit` $\to$ Extract ±2 context, tokenize (Context$\to$BPE, Target$\to$Char), predict with **Neural Solver** $\to$ Result.
    *   Else, check **Bigram** $\to$ **Unigram**.
    *   Else $\to$ Identity.
