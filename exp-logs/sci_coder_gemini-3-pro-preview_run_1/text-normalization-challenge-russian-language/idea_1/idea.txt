Based on the task requirements and the provided dataset analysis, here is a proposal for a highly efficient baseline approach.

# Baseline Proposal: Hierarchical N-gram Frequency Backoff

### Model
The proposed architecture is a **Non-Parametric Hierarchical Lookup Model**. Unlike neural or tree-based approaches that learn weights to approximate a function, this model explicitly memorizes the most probable mapping from input patterns to output tokens based on observed statistics. It relies on the linguistic property that text normalization is often locally deterministic (e.g., the pronunciation of "2" depends largely on the immediate preceding or succeeding word).

The model consists of a cascade of four deterministic hash maps (dictionaries), ordered by specificity:
1.  **Trigram Layer (L3):** Maps the tuple `(previous_token, current_token, next_token)` to the most frequent `target_token`. This captures specific phrases (e.g., "Chapter 5 starts").
2.  **Bigram Layer (L2):** Maps `(previous_token, current_token)` and `(current_token, next_token)` to the most frequent `target_token`. This handles common grammatical agreements (e.g., prepositions affecting the case of a number).
3.  **Unigram Layer (L1):** Maps `current_token` to its global most frequent `target_token`. This handles the vast majority of tokens (91% PLAIN/PUNCT) and unambiguous entities.
4.  **Identity Layer (L0):** A fallback mechanism that returns the `current_token` unchanged if it was never seen in the training data (effective for unseen proper nouns).

### Data
1.  **Sequence Reconstruction:** Since the data is provided in a tabular format (one token per row), the first step is to group the training and test data by `sentence_id` and sort by `token_id` to reconstruct the full ordered sequences.
2.  **Boundary Padding:** Add special `<BOS>` (Beginning of Sentence) and `<EOS>` (End of Sentence) tokens to the start and end of each reconstructed sentence. This ensures that the first and last tokens have valid context for bigram/trigram generation.
3.  **Tokenization:** No additional tokenization is required as the data is already tokenized. Text should be kept case-sensitive to preserve distinctions (e.g., "US" vs "us").

### Training
The training procedure is a single-pass statistical aggregation (Maximum Likelihood Estimation):
1.  **Counting:** Iterate through the entire training corpus. For every token, extract three keys: the Unigram (current), the Left-Bigram (prev, current), the Right-Bigram (current, next), and the Trigram (prev, current, next). Update a frequency counter for the mapping `Key -> Target` for each.
2.  **Resolution:** For each unique key in the counters, select the target string with the highest frequency (`argmax`).
3.  **Optimization:** Construct the final lookup tables. To optimize for speed and memory, strictly enforce the hierarchy: if a Trigram key perfectly predicts the target, it is stored in L3. If a Unigram mapping is ambiguous (e.g., "2" maps to "два" 50% of the time and "две" 50% of the time), the Unigram layer stores the global mode, while the Bigram/Trigram layers resolve the specific instances.

### Evaluation
To generate predictions for the test set:
1.  Reconstruct the test sentences and apply boundary padding.
2.  Iterate through each token in the test set.
3.  **Query L3 (Trigram):** If the sequence `(prev, cur, next)` exists in the L3 table, return the stored value.
4.  **Backoff to L2 (Bigram):** If not found, query `(prev, cur)` and `(cur, next)`. If both exist, prioritize the Left-Bigram (as left context often defines grammatical case in Russian). If a match is found, return the value.
5.  **Backoff to L1 (Unigram):** If not found, query `(cur)` in the L1 table.
6.  **Backoff to L0 (Identity):** If the token is unknown (OOV), return the original text.
7.  Format the output by joining `sentence_id` and `token_id` to match the submission requirement.
