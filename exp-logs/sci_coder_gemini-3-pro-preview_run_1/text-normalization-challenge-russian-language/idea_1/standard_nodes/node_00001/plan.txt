The following strategy outlines the implementation of the `runfile.py` script to orchestrate the text normalization task using the provided library components.

### Strategy
1.  **Setup & Configuration**: The script initializes the environment by setting random seeds for reproducibility and setting up a logger. It detects available hardware (GPU/CPU), although the core N-gram model is designed for CPU-efficient pandas operations.
2.  **Model Training**: It utilizes the `train_model` function from `library.ngram_model`. This function leverages the caching mechanism (`load_or_process`) to avoid re-computing the N-gram statistics if they already exist in the `./working` directory. The model learns hierarchical mappings (Trigram -> Bigram -> Unigram) from the training data.
3.  **Validation & Metric Calculation**:
    *   The script loads the validation set using `get_data("val")`.
    *   It generates predictions using the trained model.
    *   It calculates the exact match accuracy between the predicted normalized text and the ground truth.
    *   **Crucial Step**: It prints the `Final Validation Metric: <value>` as required for evaluation.
4.  **Failure Analysis**:
    *   The script identifies error instances (where prediction $\neq$ target).
    *   It calculates correlations between the error occurrence and input features such as **Token Length** (longer tokens might be harder) and **Sentence Length** (context complexity).
    *   It aggregates error rates by **Token Class** (e.g., CARDINAL, DATE) to identify which categories are most challenging for the model.
5.  **Submission Generation**: Finally, it calls `generate_submission`, which predicts on the test set, formats the IDs correctly (`sentence_id`_`token_id`), and saves the result to `./submission/submission.csv`.
