# Hybrid Semantic-Tabular Random Forest

## Model
I propose a **Hybrid Random Forest** architecture that fuses dense semantic text representations with structured metadata.
*   **Backbone**: The core classifier will remain a **Random Forest**, preserving the architecture that proved empirically more robust than Gradient Boosting for this specific small-scale dataset (Cite solution_lesson_node_00004). The Random Forest's bagging mechanism effectively manages variance and noise, which is critical given the limited training samples (~2,000).
*   **Input Fusion**: Unlike the previous baseline which treated text as sparse word counts, this model will ingest a concatenated vector of **dense text embeddings** and **numerical metadata**. This structural shift allows the robust tree-based classifier to make decisions based on semantic concepts (e.g., "gratitude," "desperation," "reciprocity") rather than just keyword presence.

## Data
1.  **Leakage Prevention**: I will strictly maintain the programmatic feature intersection strategy. The pipeline will identify the set of columns present in both the training and test files and restrict the input features to this intersection. This ensures that "at_retrieval" features (future information) are automatically excluded (Cite solution_lesson_node_00002).
2.  **Semantic Text Encoding (Innovation)**: Instead of the Bag-of-Words (CountVectorizer) approach used previously, I will employ a pre-trained **Sentence Transformer** (e.g., `all-MiniLM-L6-v2`) to encode the combined `request_title` and `request_text_edit_aware` fields. This will transform variable-length text into fixed-size, dense vectors (e.g., 384 dimensions) that capture semantic meaning and context, addressing the limitation of the baseline which lost syntactic and emotional nuance.
3.  **Dynamic Feature Engineering**: I will implement the ratio-based features previously attempted (e.g., `requester_upvotes_ratio_at_request` = upvotes / (upvotes + downvotes)). Crucially, the feature selection logic will be updated to dynamically accept these new columns rather than filtering them out via a static whitelist, ensuring the engineered signals actually reach the model (Cite solution_lesson_node_00005).

## Training
*   **Algorithm**: The Random Forest will be trained with **balanced class weights** to address the ~25% positive class prevalence.
*   **Hyperparameters**: I will use a moderate number of estimators (e.g., 200-300) to ensure sufficient voting power across the expanded feature space (embeddings + metadata). The `max_features` parameter will be set to `sqrt` or `log2` to force the trees to decorrelate and explore different dimensions of the semantic embeddings.
*   **Dimensionality Management**: Since the input dimension will increase (384 embedding dims + metadata), the depth of the trees may need to be slightly deeper than the baseline to capture interactions between specific semantic dimensions and user history.

## Evaluation
*   **Inference**: The test set will undergo the exact same transformation: text will be embedded using the frozen Transformer, and metadata will be intersected.
*   **Prediction**: The model will output probabilities (`predict_proba`), which will be used to calculate the ROC AUC score. This approach combines the state-of-the-art text representation of Transformers with the stability of Random Forests on tabular/small data.
