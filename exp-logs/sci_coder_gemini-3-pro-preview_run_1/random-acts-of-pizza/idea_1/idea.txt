# Baseline Approach: Random Forest with Bag-of-Words

## Model
I propose a **Random Forest Classifier** architecture. This model operates as an ensemble of decision trees trained in parallel using the bagging (bootstrap aggregating) method. Unlike the sequential gradient boosting in Model 1 or the linear hyperplanes in Model 5, the Random Forest builds independent non-linear estimators that vote on the outcome. This approach is chosen for its robustness to noise, ability to handle the mixture of numerical and text data without complex scaling, and resistance to overfitting compared to single decision trees.

## Data
1.  **Feature Selection**: To ensure a valid baseline and prevent data leakage, the feature set will be restricted to the **intersection** of columns available in both the training and test datasets. This automatically excludes "at_retrieval" features (e.g., upvotes received after posting) which are not present at inference time.
2.  **Text Processing**: The `request_title` and `request_text_edit_aware` fields will be concatenated into a single string per sample. A **CountVectorizer** (Bag-of-Words) will be applied to convert this text into a sparse matrix of token counts. To maintain efficiency and low memory usage, the vocabulary will be limited to the top $N$ (e.g., 2,000) most frequent words, and common English stop words will be removed.
3.  **Tabular Processing**: Numerical features (e.g., `requester_account_age...`, `requester_upvotes...`) will be processed using a simple median imputer to handle missing values. Complex list-based columns (like lists of subreddits) will be excluded in favor of their pre-computed count statistics already present in the dataset.
4.  **Integration**: The dense tabular features and the sparse text features will be concatenated into a single feature matrix for training.

## Training
The model will be trained using the standard Random Forest algorithm.
*   **Class Balancing**: To address the moderate class imbalance (~25% positive), the model will utilize **balanced class weights**, which automatically adjust the penalty for misclassification inversely proportional to class frequencies.
*   **Parameters**: A moderate number of trees (e.g., 100) will be used to balance performance with runtime. The splitting criterion will be Gini impurity.
*   **Optimization**: No iterative optimization (like SGD) is required; the trees are constructed deterministically based on the bootstrap samples.

## Evaluation
For the test set, the model will generate predictions using the **predict_proba** method. This calculates the probability of success as the fraction of trees in the forest that vote for the positive class (received pizza). These probabilities will be used directly to compute the Area Under the ROC Curve (AUC) and formatted for submission.
