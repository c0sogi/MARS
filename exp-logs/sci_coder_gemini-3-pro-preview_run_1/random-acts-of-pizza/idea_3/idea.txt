# Idea: Hybrid Representation Ensemble (Sparse-Tree + Dense-Linear)

## Model
I propose a **Hybrid Ensemble Architecture** that decouples the processing of sparse and dense information, assigning each representation to the model type best suited for it.
1.  **Sparse-Tabular Learner (Random Forest)**: This branch retains the **Random Forest** classifier operating on **Bag-of-Words (BoW)** text features and numerical metadata. This component preserves the proven robustness of bagging on high-dimensional sparse data and specific keyword triggers, as identified in previous experiments (Cite Lesson 00004).
2.  **Dense-Semantic Learner (Regularized Logistic Regression)**: This branch introduces a **Logistic Regression** classifier operating on **Sentence Transformer Embeddings** and standardized metadata. This addresses the failure of tree models to handle dense embeddings (Cite Lesson 00006). Unlike decision trees, which struggle to find orthogonal splits in distributed vector spaces and overfit to noise, a regularized linear model can effectively learn the optimal weighting of semantic dimensions (e.g., capturing the "direction" of gratitude or desperation) without memorizing the training data.
3.  **Fusion**: The final prediction is a weighted average of the probability outputs from both branches.

## Data
1.  **Leakage Prevention**: The pipeline will rigorously apply the programmatic feature intersection strategy. It will identify the common columns between training and test sets and restrict the input to this intersection, ensuring that "at_retrieval" features are automatically excluded (Cite Lesson 00002).
2.  **Dynamic Feature Engineering**: I will implement ratio-based features (e.g., `upvotes_ratio`) and ensure they are programmatically appended to the active feature list rather than relying on a static whitelist, preventing the silent dropping of engineered features (Cite Lesson 00005).
3.  **Dual-Stream Preprocessing**:
    *   **Stream A (Sparse)**: Text fields are concatenated and vectorized using `CountVectorizer` (unigrams and bigrams). Numerical metadata is imputed but left unscaled (trees are scale-invariant).
    *   **Stream B (Dense)**: Text fields are encoded using a pre-trained Sentence Transformer (e.g., `all-MiniLM-L6-v2`) into dense vectors. Numerical metadata is processed with `StandardScaler` to ensure it shares the same magnitude as the embeddings, which is critical for the convergence and interpretability of the Logistic Regression.

## Training
*   **Random Forest**: Trained with balanced class weights and a moderate number of estimators (e.g., 300).
*   **Logistic Regression**: Trained with L2 regularization (Ridge) and balanced class weights. The regularization strength (C) will be optimized (or set to a robust default like 1.0) to prevent overfitting on the small dataset.
*   **Independence**: Both models will be trained independently on the full training set (after validation tuning).

## Evaluation
*   **Inference**: The test data will be processed through both streams: Stream A generating the sparse matrix for the RF, and Stream B generating the dense matrix for the LR.
*   **Prediction**: Both models will output `predict_proba`. The final submission probabilities will be calculated as the arithmetic mean of the two outputs. This approach captures both the specific keyword-based signals (via RF) and the broader semantic/emotional context (via LR) while mitigating the weaknesses of applying a single algorithm to mixed data types.
