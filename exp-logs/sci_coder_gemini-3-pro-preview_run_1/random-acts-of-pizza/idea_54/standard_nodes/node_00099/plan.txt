The issue is that the system is loading stale cached feature files (generated from a small "demo" or debug run with 50 samples) instead of regenerating features for the full dataset (2302 samples). This happens because the caching logic checks for file existence but fails to validate if the cached data dimensions match the current input dataset, leading to invalid model training and evaluation (**Cite debug_lesson_1**). Additionally, the text encoder has its own independent caching; if the top-level cache is invalidated but the text cache remains stale, it will cause shape mismatches during the regeneration process (**Cite debug_lesson_7**).

To fix this, I will:
1.  Update `library/text_encoder.py` to validate the size of loaded SBERT and TF-IDF features against the current training dataframe length, discarding the cache if there is a mismatch.
2.  Update `library/feature_engine.py` to similarly validate the loaded Random Forest feature dimensions against the training dataframe, raising an exception to trigger the fallback regeneration logic if a mismatch is detected.
