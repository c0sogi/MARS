The issue is caused by a data type mismatch: the cached NumPy arrays are loaded as `float64` (Double) by default, while the PyTorch model expects `float32` (Float) inputs. This only occurs when loading from the cache because the `load_mlp` helper function lacks explicit type casting, unlike the `to_tensors` function used during fresh generation. The fix is to explicitly specify `dtype=torch.float32` when converting the cached NumPy arrays to PyTorch tensors in `library/feature_extractor.py`.
