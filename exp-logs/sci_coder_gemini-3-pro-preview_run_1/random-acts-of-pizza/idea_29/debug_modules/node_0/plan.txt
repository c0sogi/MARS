The implementation strategy is as follows:

1.  **Environment Setup**: We will import the necessary standard libraries and the provided custom library modules (`library.config`, `library.utils`, `library.data_processing`, `library.model_rf`, `library.model_nn`, `library.trainer`).
2.  **Configuration Patching**: To ensure the demo runs quickly and does not interfere with production artifacts, we will programmatically override configuration parameters. This includes setting a temporary cache directory, reducing the number of Random Forest estimators, reducing Neural Network epochs and batch sizes, and limiting TF-IDF features.
3.  **Data Processing Demonstration**: We will invoke the data processing functions (`get_rf_dataset`, `get_nn_dataset`) to generate features from the raw input data. We will force re-computation to verify the processing logic, then create small subsets of the data to speed up the subsequent training steps.
4.  **Model Training & Verification**:
    *   **Random Forest**: We will instantiate the `PizzaRandomForest` class, train it on the subsampled data, generate predictions, and verify that the model can be saved and loaded.
    *   **Neural Network**: We will instantiate the `PizzaNeuralNet` class, wrap the subsampled data in PyTorch DataLoaders, train the model for a few epochs, and verify predictions and persistence.
5.  **Ensemble & Submission**: We will demonstrate how to combine predictions using the weights defined in the config and use the `save_submission` utility to generate a correctly formatted CSV file.
6.  **Assertions**: Throughout the script, assertions will be used to validate data shapes, prediction ranges (0-1), and file existence.
