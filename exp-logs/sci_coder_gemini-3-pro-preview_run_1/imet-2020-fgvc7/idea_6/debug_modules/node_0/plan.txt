To demonstrate the usage of the provided library files, I have implemented a comprehensive script that overrides the default configuration for speed and verifies the core components (Dataset, Model, EMA, Utils) before executing the full training and inference pipelines on a small subset of data.

### Implementation Strategy
1.  **Configuration Override**: I modify the `Config` class attributes to create a "demo" environment. This includes setting a unique project directory, disabling pre-trained weight downloads (to ensure offline capability), reducing image size, and setting `EPOCHS=1` with a small batch size.
2.  **Component Verification**:
    *   **Dataset**: I instantiate `ArtworkDataset` with a small `data_limit` to verify it loads images and targets correctly with the expected shapes.
    *   **Model**: I initialize `ArtworkModel` and perform a forward pass with dummy tensors to confirm the output dimensions match `(Batch_Size, Num_Classes)`.
    *   **EMA**: I verify `ModelEMA` by manually updating model weights and asserting that the EMA shadow weights update according to the decay factor.
    *   **Utils**: I validate the `calculate_micro_f1` function with known synthetic data.
3.  **Pipeline Integration**:
    *   **Training**: I call `train_model` with `data_limit=32` and `num_epochs=1`. This runs the complete training loop, including data loading, forward/backward passes, validation, and model saving.
    *   **Inference**: I call `run_inference` using the model saved in the previous step. I verify that it generates a valid `submission.csv` file with the correct columns.
