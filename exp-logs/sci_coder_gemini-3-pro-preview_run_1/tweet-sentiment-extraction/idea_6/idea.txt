Based on the comprehensive analysis of the "Lessons" and "Previous Ideas," I propose the following optimized strategy. This solution focuses on correcting the data alignment issues that plagued recent attempts while introducing a robust architectural evolution that balances global, sequential, and local feature extraction.

# Model
**Architecture:** **DeBERTa-v3 with Recurrent-Convolutional Aggregation**
We will utilize `microsoft/deberta-v3-base` as the backbone to leverage its disentangled attention mechanism, which has proven superior for span extraction Cite {solution_lesson_node_00011}. We will introduce a **Sequential-Local Refinement Head** to process the transformer's output:
1.  **Weighted Layer Pooling:** We will aggregate hidden states from the last four layers to capture both semantic and syntactic information Cite {solution_lesson_node_00007}.
2.  **Bi-Directional LSTM:** The pooled embeddings will be passed through a **BiLSTM layer**. While Transformers excel at global attention, they can sometimes struggle with the explicit sequential continuity required for span extraction. The BiLSTM introduces a recurrent inductive bias, ensuring that the hidden states encode the sequential dependencies of the sentiment phrase.
3.  **CNN Context Layer:** The BiLSTM output will be fed into a **1D Convolutional Layer** (kernel size 3). This retains the success of previous iterations by explicitly capturing local n-gram context and sharpening the decision boundaries for the start and end tokens Cite {solution_lesson_node_00011}.

# Data
**Preprocessing & Alignment:**
*   **Synchronized Normalization:** We will implement a strict **"Normalize-First" pipeline**. We will normalize whitespace (collapsing multiple spaces) on the raw text *before* tokenization. Crucially, we will use this **same normalized string** for the final substring extraction during inference. This corrects the critical misalignment error identified in previous attempts where tokenizer offsets were applied to mismatched raw text Cite {solution_lesson_node_00018}.
*   **Strategic Filtering:** We will continue to **exclude 'neutral' tweets** from the training set entirely, as they follow a trivial identity mapping that wastes model capacity Cite {solution_lesson_node_00002}.

**Target Generation:**
*   **Soft Targets:** We will generate **Gaussian-smoothed targets** ($\sigma=1.0$) for the start and end indices. This accounts for the inherent annotation noise and prevents the model from overfitting to specific, potentially flawed boundaries Cite {solution_lesson_node_00006}.

# Training
**Loss Function:**
*   We will use **Kullback-Leibler (KL) Divergence Loss** to minimize the difference between the predicted log-probabilities and the Gaussian-smoothed target distributions Cite {solution_lesson_node_00007}.

**Optimization Strategy:**
*   **Simplified Optimization:** We will strictly **avoid** stacking complex regularization techniques like Adversarial Weight Perturbation (AWP) or Layer-wise Learning Rate Decay (LLRD) in this iteration. Previous experiments demonstrated that combining these with structural changes leads to optimization instability and catastrophic failure Cite {solution_lesson_node_00015}. We will use a standard AdamW optimizer with a linear scheduler to establish a stable baseline for the new architecture.
*   **Regularization:** We will use standard Dropout within the model, avoiding aggressive techniques like Multi-Sample Dropout which were shown to degrade precision in this specific task Cite {solution_lesson_node_00012}.

# Evaluation
**Inference Pipeline:**
1.  **Neutral Samples:** Deterministically predict the full text Cite {solution_lesson_node_00002}.
2.  **Positive/Negative Samples:** Pass the normalized text through the DeBERTa-BiLSTM-CNN model.
    *   **Joint Decoding:** Calculate the score for span $(i, j)$ as $P_{start}(i) + P_{end}(j)$. Select the span that maximizes this sum subject to $i \le j$ Cite {solution_lesson_node_00007}.
    *   **Reconstruction:** Extract the predicted substring from the **normalized** input text using the tokenizer offsets, ensuring bit-wise alignment Cite {solution_lesson_node_00018}.
