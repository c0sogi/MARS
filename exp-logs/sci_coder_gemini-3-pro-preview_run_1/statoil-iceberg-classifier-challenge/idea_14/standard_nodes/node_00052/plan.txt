The issue is that `torch.optim.swa_utils.AveragedModel` wraps the original model, causing the state dictionary keys to be prefixed with `module.` (e.g., `module.features...`) and including internal counters like `n_averaged`. When the script attempts to load this checkpoint into a standard `IcebergResNet18` instance in `runfile.py`, it fails due to key mismatches. The fix is to save the underlying model (`swa_model.module`) instead of the wrapper, ensuring the saved state dictionary matches the original architecture's keys.
