The issue is that the `BirdDataset` class uses implicit pattern matching (`startswith("species_")`) to identify label columns. The metadata generation process created 20 label columns (`species_0` through `species_19`)—likely due to an extra newline in the species list file—while the configuration and task definition strictly specify 19 classes. This causes the dataset to yield targets with shape `[Batch, 20]`, triggering an assertion failure when the training loop expects `[Batch, 19]`.

To fix this, I will update `BirdDataset` to explicitly construct the list of expected label columns based on a `num_classes` argument, ensuring only valid columns (0-18) are loaded regardless of artifacts in the CSV. This aligns with the principle of prioritizing explicit schema definition over implicit matching. Cite {debug_lesson_1}.
