The issue is that `sklearn.metrics.roc_auc_score` with `average='macro'` returns `nan` (Not a Number) instead of raising a `ValueError` when one or more classes in the validation set have no positive samples (i.e., the target vector for that class is all zeros). This `nan` value bypasses the existing `try...except ValueError` block and propagates through the training loop, causing the validation metric to be invalid (`nan`) and preventing the submission generation.

To fix this, I will modify the AUC calculation in both `library/engine.py` and `runfile.py` to compute the AUC for each class individually (`average=None`). I will then explicitly filter out any `nan` values (which correspond to undefined AUCs for missing classes) before calculating the mean. This approach ensures a valid macro-averaged AUC is computed even when the validation split is sparse or unbalanced. Cite debug_lesson_2.
