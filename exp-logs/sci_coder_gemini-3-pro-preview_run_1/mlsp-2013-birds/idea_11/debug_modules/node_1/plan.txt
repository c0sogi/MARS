The issue is that the `BirdDataset` class uses implicit pattern matching (`startswith("species_")`) to identify label columns in the metadata CSV. The upstream metadata generation process inadvertently created 20 label columns (likely due to a trailing newline in the species list), while the configuration and model expect exactly 19 classes. This mismatch causes the `AssertionError` during data loading.

To fix this, I will modify `BirdDataset` to accept a `num_classes` argument and explicitly construct the list of expected label columns (`['species_0', ..., 'species_18']`). This enforces the schema defined in the configuration and ignores any extraneous artifact columns in the data file. I will also update the `get_dataloaders` function to pass `cfg.NUM_CLASSES` when instantiating the dataset. This applies **Debug Lesson 1** (Prioritize Explicit Column Selection Over Implicit Pattern Matching).
