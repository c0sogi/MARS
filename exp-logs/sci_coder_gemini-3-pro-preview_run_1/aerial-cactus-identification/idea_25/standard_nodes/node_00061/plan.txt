The implementation strategy follows the **Multi-Task Multi-Scale RepVGG** design outlined in the idea.

1.  **Orchestration**: The `run()` function manages the pipeline. It initializes the environment, loads data using the provided `dataset` module, and executes the training and inference phases.
2.  **Training (Bagging Ensemble)**: Given that `get_dataloaders` provides a fixed stratified split (Train/Val), we implement the "5-Fold" requirement as a **Bagging Ensemble**. We train 5 separate models on the training set with different random initializations. Each model utilizes **Stochastic Weight Averaging (SWA)** (via `Engine`) to find a robust flat minimum in the loss landscape.
3.  **Model Handling**: We initialize `MultiTaskRepVGG` in training mode (`deploy=False`) to utilize the multi-branch topology. After training, we load the SWA weights and perform **Structural Re-parameterization** (`reparameterize()`) to fuse the blocks into a single fast inference stream.
4.  **Inference & Validation**:
    *   We employ **Test Time Augmentation (TTA)** with 4 views (Original, HFlip, VFlip, Rot180).
    *   We aggregate predictions from both the **Texture Head** and **Semantic Head**.
    *   We average predictions across all 5 models and all 4 views.
    *   We compute the **ROC AUC** on the hold-out validation set.
5.  **Failure Analysis**: We calculate the Pearson correlation between the absolute prediction error and input meta-features (File Size, Mean Intensity, Contrast) to identify systematic weaknesses.
6.  **Submission**: If the model performs better than random guessing (AUC > 0.5), we generate predictions for the test set using the full ensemble and save to `submission.csv`.
