The `run_demo` function initializes `Config.N_FOLDS = 2` to satisfy the `StratifiedKFold` requirement (which demands `n_splits >= 2`), but the script manually executes training for only the first fold (`fold_idx=0`). This creates a state inconsistency: the `Trainer` object expects 2 folds, but artifacts (checkpoints) exist only for Fold 0. Consequently, `trainer.predict_test_set()` iterates over the configured range and crashes when attempting to load the missing checkpoint for Fold 1. The fix is to explicitly update `trainer.n_folds` to `1` immediately after the training step in `runfile.py`. This synchronizes the parent object's state with the actual execution history before invoking the component-iterating inference method. Cite debug_lesson_14.
