The error is caused by an inconsistency between the model architecture used during training and the one used during the stacking/inference phase. In `runfile.py`, `CactusResNet` is initialized with a reduced configuration (`layers=[1, 1, 1, 1]`) to speed up the demo. However, the `StackingEnsemble` in `library/stacking.py` re-instantiates the model using its default configuration (`layers=[2, 2, 2, 2]`), leading to a `RuntimeError` during `load_state_dict` because the in-memory model expects weights for layers that do not exist in the checkpoint (Cite debug_lesson_11). To resolve this, I will modify `runfile.py` to use the default `CactusResNet` configuration, ensuring the architecture remains consistent across both phases.
