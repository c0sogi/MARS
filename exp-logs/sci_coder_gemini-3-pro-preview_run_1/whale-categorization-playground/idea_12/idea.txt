Based on the lessons learned from previous experiments, I propose the following optimized strategy. This solution implements a **Style-Invariant Heterogeneous Ensemble**, combining the proven **DenseNet121** architecture with a **ResNet50-IBN** architecture.

This strategy addresses the "variance" and "feature diversity" issues identified in Lesson 00040 by moving beyond simple seed ensembling. It introduces **Instance-Batch Normalization (IBN)** to explicitly tackle the domain shifts (lighting, water color) that act as noise in whale identification, while strictly adhering to the regularization and optimization constraints defined in the lessons.

# Model
I propose a **Heterogeneous Ensemble of 4 Models**: 2 instances of **DenseNet121** and 2 instances of **ResNet50-IBN-a**.

*   **Backbone 1: DenseNet121**
    *   *Rationale:* Retained for its proven superiority in this few-shot, fine-grained regime due to dense feature reuse **Cite solution_lesson_node_00016**.
*   **Backbone 2 (Structural Innovation): ResNet50-IBN-a**
    *   *Rationale:* I introduce the **IBN-Net** architecture. Standard CNNs (like ResNet) can overfit to appearance variations (e.g., water color, lighting) rather than the object identity. IBN blocks combine **Instance Normalization** (which provides invariance to style/appearance) with **Batch Normalization** (which preserves discriminative content). This "Style-Invariance" is critical for Re-Identification tasks where the background varies significantly but the subject (fluke) remains the same.
*   **Common Components for All Models:**
    *   **Pooling:** **Global Average Pooling (GAP)**. We explicitly reject GeM pooling **Cite solution_lesson_node_00010**.
    *   **Neck:** **Projection Head**. Structure: `Linear (Features -> 512)` $\to$ `Batch Normalization`. We explicitly **exclude Dropout** from this neck to prevent underfitting **Cite solution_lesson_node_00030** and ensure the features are adapted for the metric loss **Cite solution_lesson_node_00015**.
    *   **Head:** **ArcFace (Additive Angular Margin)**. Retained as the superior loss for high-cardinality classification **Cite solution_lesson_node_00012**.

# Data
*   **Splitting Strategy:** Strictly maintain the **Singleton-Inclusive Split**. All classes with only 1 sample must be in the training set **Cite solution_lesson_node_00002**.
*   **Resolution:** Fixed **320x320**.
    *   *Rationale:* This is the empirical sweet spot, avoiding the information loss of 224x224 **Cite solution_lesson_node_00005** and the overfitting of 448x448 **Cite solution_lesson_node_00007**. We reject progressive resizing **Cite solution_lesson_node_00023**.
*   **Augmentation:**
    *   **Geometric:** **Conservative** Affine transformations (Rotation $\pm 20^\circ$, Scale 0.9-1.1) and Horizontal Flips. Aggressive distortions are avoided **Cite solution_lesson_node_00014**.
    *   **Photometric:** Brightness and Contrast only. Explicitly **exclude** Saturation and Hue jitter **Cite solution_lesson_node_00004**.

# Training
I propose an **Independent Convergence Protocol** for the ensemble.

*   **Strategy:** Train each of the 4 models (2x DenseNet, 2x ResNet-IBN) independently with different random seeds.
    *   *Rationale:* We explicitly reject fixed-epoch training. Each model must be trained until it triggers **Early Stopping** based on its own validation metric to avoid the "undertrained ensemble" trap **Cite solution_lesson_node_00026, solution_lesson_node_00027**.
*   **Loss Function:** **ArcFace Loss**.
*   **Optimization:**
    *   **Learning Rate:** Use a **Conservative Learning Rate** (e.g., `3e-4`). We explicitly avoid aggressive rates (e.g., `1e-3`) which caused instability in previous metric learning experiments **Cite solution_lesson_node_00038**.
    *   **Optimizer:** **AdamW** with **Cosine Annealing**.
*   **Regularization:** **Enable Label Smoothing (0.1)**.
    *   *Rationale:* Critical for preventing overfitting on singleton classes. We explicitly retain this despite using a margin loss **Cite solution_lesson_node_00024**.

# Evaluation
*   **Protocol:** Implement **Test-Time Augmentation (TTA)** using Horizontal Flips for **both** the validation loop and final inference.
    *   *Rationale:* The validation metric for *each* ensemble member must be calculated using TTA to ensure accurate checkpoint selection **Cite solution_lesson_node_00011**.
*   **Inference:**
    1.  Load the **Best Checkpoint** for each of the 4 models.
    2.  For each test image, generate logits from all 4 models using both **Original** and **Horizontally Flipped** views (Total 8 predictions per image).
    3.  Average the logits across all views and models.
    4.  Select the top 5 `Id`s.
