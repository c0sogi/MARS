The execution failed because `torch.load` now defaults to `weights_only=True` in recent PyTorch versions, which prevents loading checkpoints containing NumPy scalars (like the `best_map5` metric saved in our checkpoint) for security reasons. Since the checkpoint is generated locally and is trusted, I will fix this by explicitly setting `weights_only=False` in the `torch.load` call in `runfile.py` to allow the deserialization of the NumPy data.
