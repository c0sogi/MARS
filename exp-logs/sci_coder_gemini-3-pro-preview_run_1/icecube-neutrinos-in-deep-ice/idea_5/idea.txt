# Baseline Approach: Spatiotemporal Point Transformer

## Model
I propose a **Spatiotemporal Point Transformer**. This architecture evolves the geometric deep learning approach established in the Dynamic Graph Convolutional Network (Idea 4) by replacing local message-passing layers with global self-attention mechanisms. While the DGCN (Idea 4) successfully utilized the point-cloud structure of the data (Cite {solution_lesson_node_00011}), it relied on local k-nearest neighbor graphs, which can struggle to efficiently capture long-range dependencies across the entire detector (e.g., correlating the interaction vertex with the distal end of a long muon track).

*   **Input Embedding**: The model accepts a set of $N$ sampled pulses. Each pulse's scalar features (charge $q$, auxiliary status) are projected into a hidden dimension $d$.
*   **Spatiotemporal Positional Encoding**: Crucially, the geometric coordinates $(x, y, z)$ and timestamp $t$ are not just treated as input features but are encoded using **Fourier Feature Mappings** (or Sinusoidal Positional Encodings) and added to the input embedding. This explicitly injects the spatiotemporal geometry into the model, allowing the permutation-invariant attention mechanism to understand the "arrow of time" and spatial trajectory, which are essential for direction reconstruction (Cite {solution_lesson_node_00011}).
*   **Transformer Backbone**: The core consists of stacked **Transformer Encoder** layers (Multi-Head Self-Attention followed by Feed-Forward Networks). This allows every pulse to attend to every other pulse in the input set, enabling the model to learn global event topology and long-range correlations directly.
*   **Attention Pooling**: Instead of simple Max or Mean pooling, the final sequence of pulse embeddings is aggregated using a learnable **Attention Pooling** (or "Class Token") mechanism. This allows the network to dynamically weight the most informative pulses (e.g., high-charge deposits or early-arrival photons) when forming the final event vector.
*   **Prediction Head**: The aggregated vector is passed through an MLP to predict the 3D direction vector $(v_x, v_y, v_z)$.

## Data
*   **Physics-Informed Sampling**: To fit the computational budget while preserving critical signal, we will sample a fixed number of pulses (e.g., $N=512$) using a hybrid strategy:
    1.  **Temporal Priority**: Always include the first $K$ pulses (e.g., $K=64$) sorted by time. These define the interaction vertex and are the strongest predictors of direction.
    2.  **Charge-Weighted Sampling**: Sample the remaining $N-K$ pulses from the rest of the event, with probability proportional to their charge. This ensures the "body" of the track (high energy deposits) is represented.
*   **Normalization**: Coordinates $(x, y, z)$ and time $t$ are standardized. Charge $q$ is log-transformed.
*   **Robust Caching**: To enable rapid iteration without re-processing the expensive sampling steps, the processed point clouds will be cached to disk. **Crucially, the cache filename will be generated by hashing the full configuration dictionary** (including $N$, $K$, sampling seed, and feature scaling parameters). This ensures that any change to the preprocessing logic automatically invalidates the cache, preventing the "silent failure" of training on stale data observed previously. Cite {solution_lesson_node_00008}

## Training
*   **Loss Function**: **Cosine Similarity Loss** ($1 - \text{cosine\_similarity}$). This directly optimizes the alignment of the predicted vector with the ground truth.
*   **Optimizer**: **AdamW** with a **Cosine Annealing with Warmup** scheduler. The warmup phase is critical for Transformers to stabilize the attention weights.
*   **Strategy**: Train on the full training set. The global attention mechanism is computationally efficient for $N=512$ (sequence length), allowing for a deeper model than the previous GNN or RNN attempts.

## Evaluation
*   **Inference**:
    1.  Load test batches and apply the same **Physics-Informed Sampling** and normalization.
    2.  Pass the point clouds through the trained Transformer.
*   **Post-processing**:
    1.  Normalize the predicted 3D vector to unit length.
    2.  Convert to spherical coordinates:
        *   `zenith` = $\arccos(v_z)$
        *   `azimuth` = $\arctan2(v_y, v_x)$ (mapped to $[0, 2\pi)$).
*   **Submission**: Save the predictions to the required CSV format.
