The `ArrowMemoryError` is caused by inefficient random access to large Parquet files (shards) combined with redundant data loading across multiple workers. The current `NeutrinoDataset` is a map-style dataset that, when used with `DataLoader(shuffle=True)`, forces workers to constantly load and discard entire multi-gigabyte batch files to access single events ("cache thrashing"). Additionally, without explicit file-level sharding, all workers may attempt to load the same files simultaneously, leading to memory exhaustion.

To fix this, I will convert `NeutrinoDataset` to an `IterableDataset` and implement a file-based sharding strategy. This ensures that:
1.  **Sequential Access**: Each worker loads a batch file once, processes all assigned events from it, and then moves to the next file (Cite debug_lesson_1).
2.  **Worker Sharding**: Files are explicitly partitioned among workers so that no two workers load the same file, preventing redundant memory usage (Cite debug_lesson_2).
3.  **Internal Shuffling**: Shuffling is performed at the file level and then at the event level within each file, maintaining randomness without the memory cost of global random access.

I will also update `get_dataloaders` to set `shuffle=False` for the `DataLoader`, as `IterableDataset` handles shuffling internally.
