# Baseline Approach: Temporal 1D Convolutional Network

## Model
I propose a **Temporal 1D Convolutional Neural Network (1D-CNN)**. This architecture treats the neutrino event as a temporal sequence of sensor readings, distinct from the spatial graph (Model 1), point-cloud (Model 2), or image projection (Model 4) approaches.

The design leverages the strong causal relationship in the data: pulses occurring earlier in time correspond to the initial interaction vertex and the early development of the particle track, which are critical for determining direction.

*   **Input Layer**: The model accepts a fixed-size sequence of pulses with shape $(L, C)$, where $L$ is the sequence length (number of pulses) and $C$ is the number of features per pulse (spatial coordinates $x, y, z$, time $t$, and charge $q$).
*   **Feature Extractor**: A stack of 1D Convolutional layers processes the sequence. These layers slide over the time-sorted pulses to detect local temporal patterns (e.g., wavefronts passing through adjacent sensors). Each convolution is followed by Batch Normalization and ReLU activation.
*   **Aggregation**: A Global Max Pooling layer is applied after the final convolutional block. This aggregates the most salient features detected across the entire sequence into a single fixed-size latent vector, providing invariance to the exact position of the pattern within the window.
*   **Prediction Head**: The latent vector is passed through a shallow Multi-Layer Perceptron (MLP) to regress a 3D direction vector $(v_x, v_y, v_z)$.

## Data
*   **Filtering**: Filter the raw pulse data to exclude rows where `auxiliary` is `True`, as these are lower-quality measurements likely to be noise.
*   **Sequence Construction**: For each event, sort the remaining pulses by `time`. Select the first $L$ pulses (e.g., $L=128$) to capture the critical onset of the event. If an event has fewer than $L$ pulses, zero-pad the sequence. If it has more, truncate the later pulses.
*   **Normalization**:
    *   Apply logarithmic scaling to the `charge` feature ($\log(1 + q)$) to handle its long-tailed distribution.
    *   Standardize `time`, `x`, `y`, and `z` values (subtract mean, divide by standard deviation) to ensure stable gradients.
*   **Target Transformation**: Convert the scalar targets `azimuth` and `zenith` into a normalized 3D unit vector $(x_{gt}, y_{gt}, z_{gt})$ using spherical coordinate formulas. This avoids issues with the periodicity of the azimuth angle during training.

## Training
*   **Loss Function**: Use **Cosine Similarity Loss** (or $1 - \text{cosine\_similarity}$). This directly optimizes the alignment between the predicted vector and the ground truth vector, which correlates strongly with the Mean Angular Error metric.
*   **Optimizer**: Use the Adam optimizer with a standard learning rate (e.g., 1e-3) and a learning rate scheduler (e.g., ReduceLROnPlateau) to refine weights as the loss stabilizes.
*   **Strategy**: Train for a fixed number of epochs with early stopping based on the validation loss. Given the efficiency of 1D convolutions, this model will train significantly faster than Transformer or GNN counterparts.

## Evaluation
*   **Inference**: Pass the preprocessed test batches through the trained network to obtain predicted 3D vectors.
*   **Post-processing**: Convert the predicted 3D vectors $(v_x, v_y, v_z)$ back into angular coordinates:
    *   $\text{zenith} = \arccos(v_z / ||v||)$
    *   $\text{azimuth} = \arctan2(v_y, v_x)$
    *   Ensure the azimuth is mapped to the range $[0, 2\pi)$.
*   **Submission**: Format these angular predictions into the required CSV format for submission.
