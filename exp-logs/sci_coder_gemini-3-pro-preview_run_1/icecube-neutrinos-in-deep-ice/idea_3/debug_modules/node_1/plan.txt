The issue identified is that `NaN` values are introduced when merging raw pulse data with sensor geometry because some `sensor_id`s in the data do not exist in the geometry file. These `NaN`s propagate into the feature engineering and model inputs, causing the loss to be `NaN`. To fix this, I will modify `library/data.py` to drop rows with missing spatial coordinates immediately after the merge. Additionally, I will update the `DataLoader` initialization to conditionally enable `persistent_workers` only when `num_workers > 0`, citing `debug_lesson_1`.
