# Baseline Approach: Feature-Based Gradient Boosting

## Model
I propose a **Feature-Based Gradient Boosting** approach (based on Model 5). Unlike the previous 1D-CNN idea which attempts to learn features from raw sequences, this approach relies on deterministic, physics-informed feature engineering to compress the variable-length event data into a fixed-size tabular format.

The architecture consists of **three independent LightGBM regressors**. LightGBM is chosen for its high training speed and low memory footprint.
*   **Structure**: Each regressor predicts one component of the normalized neutrino direction unit vector $(v_x, v_y, v_z)$.
*   **Input**: A fixed-length vector of aggregated statistics derived from the cloud of sensor pulses.
*   **Output**: The three scalar outputs are combined to form the predicted 3D vector.

## Data
*   **Feature Engineering**: The raw pulse data (thousands of rows per event) must be aggregated into a single row per event. We will extract the following features:
    *   **Charge-Weighted Centroids**: The center of gravity for the event, calculated as the weighted mean of sensor coordinates $(x, y, z)$ and time $(t)$, using the pulse charge $q$ as weights.
    *   **Signal Magnitude**: Total accumulated charge and the total count of pulses (excluding auxiliary noise).
    *   **Temporal Evolution**: The 10th, 50th, and 90th percentiles of the pulse times. The 10th percentile is particularly critical as it proxies the "first arrival" time of the wavefront.
    *   **Spatial Spread**: The standard deviation of the active sensor positions $(x, y, z)$ to capture the compactness of the event (e.g., track vs. cascade signatures).
*   **Preprocessing**:
    *   Filter out `auxiliary` pulses to reduce noise.
    *   Normalize the calculated features (e.g., standard scaling) is generally not strictly required for tree-based models but can be helpful.
*   **Target Transformation**: Convert the ground truth `azimuth` and `zenith` angles into a Cartesian unit direction vector $(target_x, target_y, target_z)$. This avoids the discontinuity problem at $0/2\pi$ radians in the azimuth angle.

## Training
*   **Loss Function**: Use **Mean Squared Error (MSE)** for each of the three regressors. Minimizing the squared error on the vector components is a robust proxy for minimizing the angular error.
*   **Optimizer**: Use the native gradient boosting optimization provided by LightGBM.
*   **Strategy**:
    *   Split the training data to create a validation set.
    *   Train the three models (X, Y, Z) independently.
    *   Use **Early Stopping**: Monitor the validation MSE and stop training when performance plateaus to prevent overfitting.

## Evaluation
*   **Inference**: Generate the feature vector for each test event and pass it through the three trained LightGBM models to obtain $(pred_x, pred_y, pred_z)$.
*   **Normalization**: The raw output vector might not have a unit magnitude. Normalize it: $V_{final} = V_{pred} / ||V_{pred}||$.
*   **Post-processing**: Convert the normalized vector back to spherical coordinates:
    *   `zenith` = $\arccos(z_{final})$
    *   `azimuth` = $\arctan2(y_{final}, x_{final})$ (mapped to $[0, 2\pi)$).
*   **Submission**: Save these angular predictions to the submission CSV.
