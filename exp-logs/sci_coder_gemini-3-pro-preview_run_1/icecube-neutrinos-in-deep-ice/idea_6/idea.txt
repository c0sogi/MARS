# Solution Proposal: Dynamic Graph Transformer with Global Exchange (DynGT)

## Model
I propose the **Dynamic Graph Transformer with Global Exchange (DynGT)**. This architecture represents a structural evolution of the Dynamic Graph Convolutional Network (DGCN) and the Point Transformer. While the DGCN successfully utilized the geometric structure of the data (Cite {solution_lesson_node_00011}), it relied on static aggregation functions (max/mean) within local neighborhoods. The DynGT replaces these with **Attention Mechanisms** to dynamically weight the importance of neighboring pulses and introduces a **Virtual Global Node** to capture event-wide topology.

*   **Input Representation**: The event is treated as a point cloud of $N$ selected pulses. Features $(x, y, z, t)$ are encoded using **Fourier Spatiotemporal Embeddings** to explicitly preserve high-frequency geometric and temporal details, concatenated with the log-transformed charge.
*   **Dynamic Graph Construction**: At the beginning of each block, a k-nearest neighbor (k-NN) graph is computed dynamically in the latent feature space. This allows the model to group pulses that are semantically related (e.g., belonging to the same track segment) even if they are not spatially adjacent in the raw input.
*   **Local Transformer Block**: Instead of a simple EdgeConv, we employ a **Graph Transformer Convolution** (e.g., `TransformerConv`). This applies multi-head self-attention over the local k-NN neighborhood, allowing the model to learn anisotropic filters that align with the particle's direction vector.
*   **Global Exchange Mechanism**: To address the limitation of local message passing in capturing long-range dependencies (e.g., relating the vertex to the track end), a **Virtual Global Node** is initialized. In each layer, this node aggregates information from all pulse nodes and then broadcasts the global context back to them.
*   **Readout and Prediction**: The final pulse representations are aggregated using **Attention Pooling** (weighted sum based on learnable scores) into a single vector, which is passed to an MLP to predict the 3D direction $(v_x, v_y, v_z)$.

## Data
*   **Stratified Causal-Signal Sampling**: To maximize information density within a fixed budget (e.g., $N=256$), we employ a multi-tier sampling strategy:
    1.  **Causal Set**: Select the first $K=64$ pulses sorted by time. These capture the interaction vertex and the initial "arrow of time" essential for directionality.
    2.  **Signal Set**: Select the top $M=128$ pulses sorted by charge from the remaining pool. These capture the high-energy "body" of the track.
    3.  **Context Set**: Randomly sample the remainder to provide background context.
*   **Robust Caching**: We will implement a strict caching system where the cache filename is generated by hashing the **entire configuration dictionary** (including sampling counts, seed, normalization parameters, and feature lists). This ensures that any modification to the preprocessing logic automatically invalidates the cache, preventing the model from training on stale or mismatched data (Cite {solution_lesson_node_00008}).
*   **Normalization**: Coordinate and time features will be standardized; charge will be log-transformed.

## Training
*   **Loss Function**: **Cosine Similarity Loss** ($1 - \cos(\theta)$). This directly optimizes the alignment of the predicted vector with the ground truth, which is the primary metric.
*   **Optimizer**: **AdamW** with a **OneCycleLR** scheduler. This schedule provides a warm-up phase to stabilize the dynamic graph construction and attention weights, followed by a decay to fine-tune convergence.
*   **Augmentation**: Apply **Random Jittering** to the $(x, y, z, t)$ coordinates during training. Adding small Gaussian noise improves the model's robustness to detector resolution limits and prevents overfitting to specific sensor locations.

## Evaluation
*   **Inference**:
    1.  Load test batches and apply the **Stratified Causal-Signal Sampling**.
    2.  Pass the processed point clouds through the trained DynGT model.
    3.  The model predicts a 3D vector.
*   **Post-processing**:
    1.  Normalize the predicted vector to unit length: $\hat{v} = v_{pred} / ||v_{pred}||$.
    2.  Convert to spherical coordinates:
        *   `zenith` = $\arccos(\hat{v}_z)$
        *   `azimuth` = $\arctan2(\hat{v}_y, \hat{v}_x)$ (mapped to $[0, 2\pi)$).
*   **Submission**: Format the predictions into the required CSV structure.
