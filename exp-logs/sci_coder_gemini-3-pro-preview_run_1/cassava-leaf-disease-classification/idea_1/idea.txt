Based on the provided model architectures and the requirement for a simple, lightweight baseline, I propose the following approach derived from **Model 1 (EfficientNet-B0)**. This solution prioritizes computational efficiency and ease of implementation while addressing the specific characteristics of the dataset (e.g., class imbalance).

# Model
I will utilize the **EfficientNet-B0** architecture as the backbone. This model is chosen for its superior trade-off between accuracy and computational cost (FLOPS/parameters) compared to older architectures like ResNet.
*   **Backbone**: The EfficientNet-B0 network, pre-trained on the ImageNet dataset, will serve as the feature extractor. This leverages learned features (edges, textures) that are transferable to leaf classification.
*   **Head**: The original ImageNet classification head will be removed. It will be replaced with a **Global Average Pooling** layer to reduce the spatial feature maps to a single vector, followed by a **single Fully Connected (Dense) layer** with 5 output units corresponding to the 5 disease categories.
*   **Initialization**: The backbone weights will be frozen for the first epoch to stabilize the new head, then unfrozen for fine-tuning (or kept frozen if training speed is the absolute priority, but fine-tuning is standard for baselines).

# Data
*   **Input Resizing**: The original 800x600 images will be resized to **224x224** pixels. This matches the native input resolution of EfficientNet-B0, significantly reducing memory usage and inference time compared to processing full-resolution images.
*   **Normalization**: Pixel values will be normalized using the standard ImageNet mean (`[0.485, 0.456, 0.406]`) and standard deviation (`[0.229, 0.224, 0.225]`) to align with the pre-trained weights.
*   **Augmentation (Training)**: To prevent overfitting without adding significant computational overhead, only **Random Horizontal Flips** will be applied. This is computationally cheap and semantically valid for leaf images.
*   **Handling Imbalance**: No oversampling or undersampling will be performed during data loading to maintain the simplest pipeline. Instead, imbalance will be handled in the loss function.

# Training
*   **Loss Function**: **Weighted Cross-Entropy Loss**. To address the heavy class imbalance (where Class 3 represents ~61% of data), scalar weights will be assigned to each class inversely proportional to their frequency in the training set. This ensures the model does not bias heavily towards the majority class.
*   **Optimizer**: The **Adam** optimizer will be used for its ability to handle sparse gradients and its robustness with default hyperparameters. A conservative learning rate (e.g., 1e-4) will be employed.
*   **Strategy**: Training will proceed for a fixed, small number of epochs (e.g., 5-10). A validation set (20% of training data) will be used to monitor accuracy, saving the model checkpoint with the highest validation accuracy.

# Evaluation
*   **Inference**: Test images will undergo the same resizing (to 224x224) and normalization as the training data.
*   **Prediction**: The model will output logits for each image. The final class prediction will be determined by the index of the maximum logit (`argmax`). No test-time augmentation (TTA) will be used to ensure fast runtime.
