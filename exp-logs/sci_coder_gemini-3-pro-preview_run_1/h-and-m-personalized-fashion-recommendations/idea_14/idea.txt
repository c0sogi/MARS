Based on the comprehensive analysis of the "Lessons Learned" and the specific trade-offs identified between "Recency" (Lesson 00007) and "Long-Tail Density" (Lesson 00012), I propose the **Inventory-Gated Dual-Window Cascade (IGDC)**.

This solution introduces a structural innovation by **decoupling the temporal windows** used for three distinct components of the Collaborative Filtering process: **Structure Learning** (the Similarity Graph), **Intent Inference** (the User Query), and **Feasibility Filtering** (the Inventory Mask). This allows the model to simultaneously exploit deep historical data for stable item relationships while strictly enforcing immediate relevance for user intent and item availability, resolved within a vectorized cascade.

### Model
The architecture is a **Three-Stage Stratified Retrieval System** implemented via vectorized sparse linear algebra. It generates a single unified score vector $R_u$ for each user, where signal sources are mapped to disjoint numerical ranges to enforce a strict priority hierarchy: **Habit > Gated CF > Global Trend**.

1.  **Stratum 1: Habitual Repurchase (The "Priors" Layer)**
    *   **Logic:** Users are overwhelmingly likely to rebuy items purchased recently. **Cite {solution_lesson_node_00002}**.
    *   **Mechanism:** Retrieve the user's history vector $U_{hist}$ from the last 4 weeks. Apply strict temporal decay ($1 / \text{days\_elapsed}$).
    *   **Stratification:** Scores are shifted to the range $[2000, \infty)$. This ensures explicit history *always* outranks inferred similarity, strictly adhering to the "Cascade > Ensemble" principle. **Cite {solution_lesson_node_00016}**.

2.  **Stratum 2: Inventory-Gated Dual-Window CF (The "Discovery" Layer)**
    *   **Structural Innovation (Decoupled Windows):**
        *   **Structure Learning ($S_{long}$):** We construct the Item-Item Similarity Matrix using a **16-week** window. This long horizon captures the "Long Tail" of sparse item correlations (e.g., specific pants that go with a specific top) that are lost in shorter windows. **Cite {solution_lesson_node_00012}**.
        *   **Intent Inference ($U_{short}$):** We construct the User Query Vector using only the **Last 2 Weeks** of history. This restricts the "seed" signals to the user's immediate context, preventing obsolete purchases from triggering irrelevant recommendations, effectively addressing "Concept Drift". **Cite {solution_lesson_node_00007}**.
        *   **Feasibility Filtering ($M_{active}$):** We construct a binary mask of all items sold in the **Last 1 Week**.
    *   **Matrix Construction:** $S_{long}$ is built using **Row-wise (User) Normalization** (**Cite {solution_lesson_node_00004}**) and **IDF Weighting** (**Cite {solution_lesson_node_00011}**) to mitigate power-user and popularity biases.
    *   **Inference:** $R_{cf} = (U_{short} \times S_{long}) \odot M_{active}$.
    *   **Logic:** "Based on what I bought *now* ($U_{short}$), recommend items that are *intrinsically related* ($S_{long}$), provided they are *currently available* ($M_{active}$)."
    *   **Stratification:** Scores are normalized and scaled to the range $[100, 1000]$.

3.  **Stratum 3: Global Trend (The "Fallback" Layer)**
    *   **Logic:** Sales velocity from the **Last 1 Week** for cold-start users.
    *   **Stratification:** Scores are scaled to $[0, 10]$.

**Final Aggregation:**
$$ R_{total} = R_{rep} + R_{cf} + R_{trend} $$
Sorting $R_{total}$ is mathematically equivalent to the heuristic cascade: Sort(Repurchase) $\rightarrow$ Sort(Gated CF) $\rightarrow$ Sort(Trend).

### Data
1.  **Temporal Windowing:**
    *   **Training Set:** We partition the transaction data into three views:
        *   `View_Structure`: Weeks $T-16$ to $T-1$ (for $S_{long}$).
        *   `View_Intent`: Weeks $T-2$ to $T-1$ (for $U_{short}$).
        *   `View_Inventory`: Week $T-1$ (for $M_{active}$ and $R_{trend}$).
2.  **Validation Strategy:**
    *   **Time-Based Split:** Train on the windows defined above relative to Week $T$, and validate on Week $T$. This ensures the model has access to the user history required for Strata 1 and 2. **Cite {solution_lesson_node_00026}**.
3.  **Precision:**
    *   Use **float32** for all matrix accumulators. This prevents the numerical overflow issues observed when using `float16` with stratified offsets. **Cite {solution_lesson_node_00010}**.
4.  **Exclusion:**
    *   Explicitly exclude Visual Embeddings (**Cite {solution_lesson_node_00020}**) and Metadata Hybridization (**Cite {solution_lesson_node_00027}**) to maintain behavioral signal purity.

### Training
Since this is a memory-based heuristic model, "training" is the efficient construction of the sparse matrices:
1.  **Similarity Matrix:** Construct sparse interaction matrix $X$ from `View_Structure`. Apply IDF to columns and L2 normalization to rows. Compute $S_{long} = X^T X$ (pruned to top-100 neighbors).
2.  **Inventory Mask:** Identify unique `article_id`s in `View_Inventory` to create the binary mask vector $M_{active}$.
3.  **Trend Vector:** Compute sales counts from `View_Inventory`.

### Evaluation
1.  **Vectorized Inference:**
    *   Construct the sparse query matrix $U_{short}$ for all test users.
    *   Compute $R_{raw} = U_{short} \times S_{long}$ via sparse matrix multiplication.
    *   Apply the mask: $R_{gated} = R_{raw} \odot M_{active}$ (element-wise multiplication).
2.  **Retrieval Strategy:**
    *   Employ the **Mask-and-Partition** technique: Densify the score vector, mask history items (unless Repurchase score overrides), and use `np.argpartition` to select top 12 items in linear time. **Cite {solution_lesson_node_00013}**.
