Based on the lessons learned, I propose a **Two-Stage Recommender System: Heuristic Retrieval followed by Gradient Boosted Re-ranking**. This approach evolves the solution from a purely rule-based cascade to a machine-learning-based ranking system that learns the optimal combination of signals.

# Model
The architecture consists of two distinct stages:

1.  **Candidate Generation (Retrieval Layer):**
    This stage is designed to efficiently reduce the search space from ~100,000 items to a manageable subset (e.g., top 20-50 items) per user. It retains the highly effective, low-latency components identified in previous experiments:
    *   **Repurchase Signal:** Retrieves items previously bought by the user, prioritizing recency. Cite {solution_lesson_node_00002}.
    *   **Collaborative Filtering Signal:** Retrieves items similar to the user's history using a sparse Item-Item similarity matrix. Crucially, this matrix will be constructed using **row-wise (user) normalization** to mitigate the bias of power users, Cite {solution_lesson_node_00004}, and the retrieval will apply **temporal decay propagation**, weighting neighbor items by the recency of the seed item in the user's history. Cite {solution_lesson_node_00005}.
    *   **Global Trend Signal:** A fallback list of bestsellers, weighted by a time-decay factor to prioritize current fashion trends. Cite {solution_lesson_node_00002}.

2.  **Re-ranking (Precision Layer):**
    A **LightGBM Ranker** (Gradient Boosted Decision Trees) will be employed to score and re-order the candidates generated in the first stage. Unlike the rigid cascade used previously, this model learns to dynamically weight the importance of "Repurchase" vs. "Trend" vs. "CF Similarity" based on the user's context (e.g., user activity level) and item metadata (e.g., product category matching).

# Data
1.  **Temporal Windowing:**
    Adhering to the "Recency over Volume" principle, the candidate generation logic will rely on a restricted historical window (e.g., the last 4-6 weeks) to avoid noise from obsolete trends. Cite {solution_lesson_node_00007}.

2.  **Feature Engineering for Ranker:**
    For every `(user, item)` pair in the candidate pool, we will generate a feature vector including:
    *   **Heuristic Scores:** The raw similarity score from the CF model, the recency rank from the Repurchase list, and the popularity score from the Trend list.
    *   **Temporal Features:** Days since the user last bought this item, and days since the user last bought *any* item in this item's `product_group`.
    *   **Metadata Features:** Categorical features from `articles.csv` (e.g., `department_no`, `garment_group_no`) to allow the model to learn category-specific preferences.
    *   **User Stats:** Purchase frequency and average spend.

3.  **Train/Validation Split:**
    We will use a "time-split" strategy.
    *   **Training Set:** We will simulate the inference process on Week $T-1$ (the week prior to the validation week). We generate candidates for users using data up to Week $T-2$, and label them as `1` if purchased in Week $T-1$ and `0` otherwise.
    *   **Validation Set:** The actual validation week (Week $T$) defined in the metadata.

# Training
The re-ranking model will be trained using the **LambdaRank** objective (specifically `lambdarank` in LightGBM), which optimizes the Mean Average Precision (MAP) directly rather than simple binary classification accuracy.
*   **Groups:** The data will be grouped by `customer_id`, ensuring the model learns to rank items *relative to each other* for a specific user.
*   **Negative Sampling:** The "negatives" are implicitly provided by the retrieval stage—items that were recommended by the heuristic candidates but *not* purchased by the user. This effectively teaches the model to discriminate between "good" and "bad" candidates generated by the baseline.

# Evaluation
The inference pipeline for the test set is as follows:
1.  **Retrieve:** For each customer in the sample submission, generate the top $K$ candidates using the Heuristic Retrieval layer (Repurchase + CF + Trend).
2.  **Enrich:** Compute the feature vectors for these $K$ candidates.
3.  **Score:** Pass the feature vectors through the trained LightGBM Ranker to obtain a relevance score.
4.  **Sort & Truncate:** Sort the candidates by the predicted score in descending order and select the top 12 `article_id`s for the final submission.
