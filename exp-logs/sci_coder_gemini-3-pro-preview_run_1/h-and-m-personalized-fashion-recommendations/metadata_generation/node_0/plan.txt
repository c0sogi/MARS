Implementation Strategy:
1.  **Environment Setup**: Define input (`./input`) and output (`./metadata`) directories. Ensure the output directory exists.
2.  **Data Loading**: Load `transactions_train.csv` to get user history and `sample_submission.csv` to identify test users. I will use appropriate data types (e.g., `int32` for IDs) to optimize memory usage, although the provided 220GB RAM is more than sufficient.
3.  **Image Path Generation**: Construct relative image paths for each article. Based on the dataset description, `article_id`s are integers in the CSV but correspond to 0-padded 10-digit filenames in subfolders named after the first 3 digits. I will vectorize this string manipulation for performance.
4.  **Metadata Splitting (Group Sampling)**:
    -   Extract unique `customer_id`s from the training transactions.
    -   Shuffle the customers with a fixed random seed (`42`).
    -   Split customers into 80% training and 20% validation sets.
    -   Partition the transaction data based on these customer groups. This ensures no data leakage of user history between sets, satisfying the "Group Sampling" requirement.
5.  **File Generation**:
    -   Save the partitioned transactions as `train.csv` and `val.csv` in the metadata directory, including the generated image paths.
    -   Save the list of test customers (from `sample_submission.csv`) as `test.csv`.
6.  **Validation & Verification**:
    -   **Stats**: Reload the saved files and print summary statistics (shapes, unique counts).
    -   **File Integrity**: Randomly sample 1000 image paths from the generated metadata and verify their existence in the `./input` directory. Raise an error if >50% are missing.
    -   **Split Verification**: Programmatically assert that there is no overlap of users between train and validation sets and that the split ratio is approximately 80:20.
