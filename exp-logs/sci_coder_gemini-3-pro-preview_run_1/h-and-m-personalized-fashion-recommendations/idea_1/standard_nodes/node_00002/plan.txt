The issue arises from a column name collision during the merge between `analysis_df` and `cust_df` in `runfile.py`. Both DataFrames contain a column named `customer_id` (integer ID in `analysis_df`, string ID in `cust_df`). When merging with `left_on="customer_id"` and `right_on="customer_id_int"`, pandas retains both `customer_id` columns but renames them to `customer_id_x` and `customer_id_y` to distinguish them. Consequently, the resulting `merged_df` no longer has a column named exactly `customer_id`, causing the subsequent merge with `activity_counts` to fail with a `KeyError`.

To fix this, I will modify the merge operation to drop the string-based `customer_id` column from `cust_df` (the right DataFrame) before merging. This prevents the collision, preserving the integer-based `customer_id` column from `analysis_df` in the output DataFrame.
