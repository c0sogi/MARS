The implementation strategy follows the Shared-Bottom Multi-Branch RoBERTa Dual-Encoder architecture described in the idea.

1.  **Setup & Data**: Initialize the environment with a fixed seed and load the dataset using the provided `get_dataloaders` function. We utilize the pre-split metadata (train/val/test) and enable caching to speed up data loading.
2.  **Model Construction**: Instantiate the `SharedBottomMultiBranchModel`. This model shares the first 10 layers of RoBERTa between question and answer inputs, then splits into independent branches for the last 2 layers, followed by a hybrid pooling and interaction head.
3.  **Training Configuration**:
    *   **Optimizer**: Use AdamW with differential learning rates: `1e-3` for the head and `2e-5` for the backbone.
    *   **Scheduler**: Implement "Phantom Scheduling" by configuring the linear scheduler for 7 epochs but training for only 3. This ensures the learning rate decay curve is optimal for fine-tuning.
    *   **Head Warmup**: The training loop (via `train_one_epoch`) handles freezing the backbone during the first epoch to stabilize the randomly initialized head.
4.  **Execution Loop**: Train for 3 epochs. After each epoch, validate on the hold-out set using Spearman's correlation. The best model state is saved.
5.  **Failure Analysis**: After training, reload the best model and analyze the validation set errors. Compute the correlation between the mean absolute error and input text lengths (title, body, answer) to diagnose performance bottlenecks.
6.  **Submission**: If the best validation score exceeds the threshold (0.4118...), generate predictions for the test set and save the `submission.csv` file.
