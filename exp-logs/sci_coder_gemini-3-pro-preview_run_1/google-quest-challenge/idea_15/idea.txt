Based on the accumulated "Lessons Learned" and the analysis of previous experiments, I propose the following optimized strategy.

# Model
I propose a **LoRA-Augmented DeBERTa-v3-Base Dual-Encoder**.

This architecture introduces a **Structural Innovation** by shifting the training paradigm from Full Fine-Tuning to **Parameter-Efficient Fine-Tuning (PEFT)** using **Low-Rank Adaptation (LoRA)**. This strategy directly resolves the "Capacity vs. Trainability" conflict that plagued previous attempts.

*   **Backbone Architecture:** Utilize **`microsoft/deberta-v3-base`**.
    *   *Rationale:* Previous experiments showed that `deberta-v3-base` failed due to "Starved Batch" instability caused by memory constraints (**Cite solution_lesson_node_00022**) and overfitting risks on the small dataset (**Cite solution_lesson_node_00023**). However, it possesses superior disentangled attention capabilities compared to `distilroberta`. By using LoRA, we freeze the backbone weights, drastically reducing activation memory (no optimizer states for the backbone), which allows us to run this powerful model with a robust batch size.
*   **Low-Rank Adaptation (LoRA):**
    *   Inject trainable rank-decomposition matrices ($r=8, \alpha=16$) into the **Query, Key, Value, and Output** projection layers of the Transformer blocks.
    *   *Benefit:* This reduces the trainable parameter count to <1% of the model. This acts as a strong structural regularizer, preventing the "large model on small data" overfitting issue (**Cite solution_lesson_node_00023**) while retaining the pre-trained semantic knowledge of the Base model (**Cite solution_lesson_node_00045**).
*   **Dual-Branch Structure:** Maintain the Siamese design, processing "Question" (Title + Body) and "Answer" streams independently. This preserves the full context window for both inputs (**Cite solution_lesson_node_00032**) and prevents the leakage of answer information into intrinsic question features (**Cite solution_lesson_node_00030**).
*   **Masked Hybrid Pooling:** Apply **Masked Global Average and Max Pooling** to the final hidden state of both branches (**Cite solution_lesson_node_00003**).
*   **Interaction-Aware Fusion:**
    1.  Compute explicit interactions (Element-wise Product and Absolute Difference) *only* on the **Average Pooled** vectors (**Cite solution_lesson_node_00007**).
    2.  Concatenate the components: $[u_{avg}, u_{max}, v_{avg}, v_{max}, u_{avg} \odot v_{avg}, |u_{avg} - v_{avg}|]$.
    3.  Apply **Layer Normalization** to the fused vector (**Cite solution_lesson_node_00009**).
*   **Monolithic Simple Head:**
    *   Pass the normalized vector through a simple MLP: `Linear` (Fused $\to$ 768) $\to$ `ReLU` $\to$ `Dropout` ($p=0.1$) $\to$ `Linear` (768 $\to$ 30).
    *   *Rationale:* This maintains the non-linearity required for feature mixing (**Cite solution_lesson_node_00027**) while avoiding the optimization instability of complex Gated/LayerNormed heads (**Cite solution_lesson_node_00054**) and the information loss of aggressive bottlenecks (**Cite solution_lesson_node_00048**). It predicts all 30 targets simultaneously to leverage inter-label correlations (**Cite solution_lesson_node_00016**).

# Data
*   **Preprocessing:** Concatenate `question_title` and `question_body` for the Question input; use `answer` for the Answer input.
*   **Feature Selection:** Rely solely on text. Do not inject metadata or use auxiliary embeddings, as these have proven to cause overfitting (**Cite solution_lesson_node_00039**, **Cite solution_lesson_node_00049**).
*   **Tokenization:** Use the `microsoft/deberta-v3-base` tokenizer.
*   **Dynamic Padding:** Pad sequences to the longest length in the batch to optimize throughput (**Cite solution_lesson_node_00018**).

# Training
*   **Batch Size:** Use **16**. The memory savings from LoRA make this feasible with the `base` model on a single GPU, ensuring we avoid the "Starved Batch" penalty (**Cite solution_lesson_node_00022**) and provide sufficient gradient noise for generalization (**Cite solution_lesson_node_00012**).
*   **Optimizer:** Use **AdamW**.
*   **Learning Rate:** Use a higher learning rate for the LoRA parameters and Head (e.g., **5e-4** or **1e-3**). Since the backbone is frozen, we do not need the conservative `2e-5` rate used for full fine-tuning. This ensures the adapters converge efficiently (**Cite solution_lesson_node_00015**).
*   **Parameter Grouping:** Explicitly exclude `bias` and `LayerNorm` parameters from weight decay (**Cite solution_lesson_node_00018**).
*   **Schedule:** Train for **10 epochs**. LoRA typically requires slightly more steps than full fine-tuning to align the adapters, and the efficient architecture allows for this extended runtime. Use a continuous linear decay schedule with warmup (**Cite solution_lesson_node_00019**, **Cite solution_lesson_node_00011**).
*   **Loss Function:** Binary Cross Entropy (BCE) with Logits Loss.

# Evaluation
*   **Inference:** Pass the test set through the LoRA-adapted model.
*   **Prediction:** Apply Sigmoid activation to the 30 output logits.
*   **Validation:** Monitor Mean Column-wise Spearman's Correlation. Accept the model if it exceeds the previous best (`~0.408`) plus a small noise margin (**Cite solution_lesson_node_00010**).
