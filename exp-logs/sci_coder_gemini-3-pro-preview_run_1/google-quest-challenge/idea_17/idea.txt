Based on the comprehensive analysis of the "Lessons Learned" and the trajectory of previous experiments, I propose the following optimized strategy.

# Model
I propose a **DistilRoBERTa Dual-Encoder with Residual-Interaction Fusion**.

This architecture represents a **Structural Evolution** that synthesizes the robust feature engineering of the "Current Best" solution with the advanced head design attempted in Idea 11, while explicitly correcting the training strategy flaws that caused the latter to fail.

*   **Backbone Architecture:** Utilize **`distilroberta-base`**.
    *   *Rationale:* This backbone (82M params) is the empirically verified "Right-Sized" model for this dataset (**Cite solution_lesson_node_00023**, **Cite solution_lesson_node_00045**). It avoids the "Starved Batch" instability of larger models like `deberta-v3-base` (**Cite solution_lesson_node_00022**) and provides sufficient capacity for the task.
*   **Dual-Branch Structure:** Maintain the Siamese design, processing the "Question" and "Answer" streams independently. This preserves the full context window for both inputs (**Cite solution_lesson_node_00032**) and prevents the leakage of answer information into intrinsic question features (**Cite solution_lesson_node_00030**).
*   **Optimized Input Structure:**
    *   **Question Branch:** Use the tokenizer's native pairing: `tokenizer(title, body)`. This inserts special separators (`[CLS] Title [SEP] Body [SEP]`) to preserve the semantic boundary between intent and context, outperforming string concatenation (**Cite solution_lesson_node_00070**).
    *   **Answer Branch:** Use `tokenizer(answer)`. Crucially, do **not** prepend the Title here. Previous experiments proved that redundant context forces truncation of the unique Answer text, degrading performance (**Cite solution_lesson_node_00063**).
*   **Masked Hybrid Pooling:** Apply **Masked Global Average and Max Pooling** to the final hidden state of both branches (**Cite solution_lesson_node_00003**).
*   **Interaction-Aware Fusion:**
    *   Compute explicit interactions (Element-wise Product and Absolute Difference) *only* on the **Average Pooled** vectors (**Cite solution_lesson_node_00007**).
    *   Construct the Fused Vector $F = [u_{avg}, u_{max}, v_{avg}, v_{max}, u_{avg} \odot v_{avg}, |u_{avg} - v_{avg}|]$.
    *   Apply **Layer Normalization** to $F$ (**Cite solution_lesson_node_00009**).
*   **Residual-Interaction Head (Structural Innovation):**
    *   Replace the standard MLP with a **Residual Projection Block**.
    *   **Path A (Non-Linear):** $H_{proj} = \text{Dropout}(\text{ReLU}(\text{Linear}(F)))$. (Projects to hidden dim 768).
    *   **Path B (Skip Connection):** $F$ (The raw fused vector).
    *   **Output:** $\text{Linear}(\text{Concat}(F, H_{proj})) \to 30 \text{ Targets}$.
    *   *Rationale:* This architecture resolves the conflict between the need for non-linearity (**Cite solution_lesson_node_00027**) and the risk of signal vanishing in deep heads (**Cite solution_lesson_node_00011**). By concatenating the raw interaction features (like $u \cdot v$) directly with the non-linear features at the final layer, the model can leverage both explicit heuristics and learned abstractions.
    *   *Correction:* Unlike Idea 11, which failed due to aggressive backbone re-initialization (**Cite solution_lesson_node_00053**), this head is applied to a standard pre-trained backbone.
    *   **Initialization:** Initialize the new linear layers using a Normal distribution ($\mu=0, \sigma=0.02$) to match the backbone's scale (**Cite solution_lesson_node_00051**).

# Data
*   **Preprocessing:**
    *   **Stream A:** `tokenizer(question_title, question_body)`
    *   **Stream B:** `tokenizer(answer)`
*   **Feature Selection:** Rely solely on text. Do not inject metadata or use auxiliary embeddings, as these induce overfitting and shortcut learning (**Cite solution_lesson_node_00039**, **Cite solution_lesson_node_00049**).
*   **Tokenization:** Use the `distilroberta-base` tokenizer.
*   **Dynamic Padding:** Pad sequences to the longest length in the batch to optimize throughput (**Cite solution_lesson_node_00018**).

# Training
*   **Differential Learning Rates:** Apply a high learning rate (`1e-3`) to the **Residual-Interaction Head** and a low learning rate (`2e-5`) to the **Backbone** (**Cite solution_lesson_node_00015**).
*   **Strict Parameter Preservation:** Do **not** re-initialize any backbone layers (**Cite solution_lesson_node_00052**). Do **not** group top backbone layers with the head; treat the backbone as a single pre-trained unit (**Cite solution_lesson_node_00053**).
*   **Parameter Grouping:** Explicitly exclude `bias` and `LayerNorm` parameters from weight decay (**Cite solution_lesson_node_00018**).
*   **Schedule:**
    *   **Epoch 1 (Head Warmup):** Freeze the backbone completely. Train only the head (**Cite solution_lesson_node_00050**).
    *   **Epochs 2-5 (Fine-tuning):** Unfreeze the backbone. Use a continuous linear decay schedule with a 10% warmup. Do **not** reset the optimizer/scheduler; allow momentum to carry over (**Cite solution_lesson_node_00019**, **Cite solution_lesson_node_00060**).
*   **Batch Size:** Use **16**. This fits in memory and provides the necessary gradient noise for robust generalization (**Cite solution_lesson_node_00012**).
*   **Loss Function:** Monolithic Binary Cross Entropy (BCE) with Logits Loss (**Cite solution_lesson_node_00016**, **Cite solution_lesson_node_00074**).

# Evaluation
*   **Inference:** Pass the test set through the trained model.
*   **Prediction:** Apply Sigmoid activation to the 30 output logits.
*   **Validation:** Monitor Mean Column-wise Spearman's Correlation. Accept the model if it exceeds the previous best (`~0.408`) plus a small noise margin (**Cite solution_lesson_node_00010**).
