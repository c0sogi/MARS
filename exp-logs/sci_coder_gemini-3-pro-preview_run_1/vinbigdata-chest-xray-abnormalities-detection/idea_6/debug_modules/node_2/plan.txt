The issue stems from a mismatch between the bounding box coordinates in the metadata and the dimensions of the image loaded by the pipeline. Specifically, when the custom DICOM parser fails to read a compressed image, it falls back to a default 1024x1024 placeholder, but the pipeline continues to use the original (potentially larger) bounding box coordinates. This causes the data augmentation library (Albumentations) to throw a `ValueError` because the coordinates are outside the image boundaries.

To fix this, I will:
1.  Update `library/utils.py` to include `cv2` and use `cv2.imdecode` as a robust fallback for reading compressed DICOM pixel data, reducing the frequency of fallback to the placeholder.
2.  Update `library/dataset.py` to explicitly clamp bounding box coordinates to the dimensions of the *actually loaded* image (`orig_w`, `orig_h`) before passing them to the augmentation pipeline. This ensures consistency between the image and its annotations, directly applying **Debug Lesson 3** (Synchronize Dependent Metadata When Triggering Data Fallbacks).
