### Implementation Strategy

1.  **Environment Setup**: Initialize the random seeds using `library.utils.seed_everything` to ensure reproducibility.
2.  **Configuration Override**: Modify the `library.config.Config` class attributes at runtime. We will redirect the working directories to a demo folder (`./working/demo_run`) and point the metadata paths to temporary subset CSVs. This ensures the dataset loading is instantaneous and does not process the full 60k+ dataset.
3.  **Data Subsetting**: Load the original metadata files from `./metadata`, sample a small fraction (e.g., 50 rows), and save them to the new temporary paths. This creates a valid but tiny dataset for the demonstration.
4.  **Model Verification**: Instantiate the `DetModel`. Perform a forward pass with a dummy tensor to verify that the output shapes (Heatmap, Width/Height, Regression, Global Class) are correct relative to the input size and model stride.
5.  **Loss Function Verification**: Instantiate `CenterNetLoss`. Create synthetic ground truth data matching the dictionary structure expected by the loss function and assert that the loss calculation returns a valid scalar.
6.  **Full Pipeline Execution**:
    *   Initialize the `Engine` with the model, optimizer, and device.
    *   Use `get_dataloaders` to create loaders based on the subset metadata.
    *   Run `engine.run()` with `epochs=1` and `debug=True`. The debug flag limits the number of batches per epoch, ensuring rapid execution.
7.  **Result Validation**: After the run, verify that the submission file (`submission.csv`) has been generated in the specified output directory.
