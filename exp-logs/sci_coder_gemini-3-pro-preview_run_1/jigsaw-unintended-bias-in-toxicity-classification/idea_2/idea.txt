# Baseline Solution: NBSVM with Bias-Centric Sample Weighting

### Model
The proposed model is an **NBSVM (Naive Bayes - Support Vector Machine)**. This architecture bridges the gap between simple linear models and more complex probabilistic approaches, making it an extremely efficient baseline for text classification.
*   **Feature Scaling (Naive Bayes Component)**: Unlike standard linear models that use raw TF-IDF features, this model first computes the **log-count ratio** for each feature (token). This ratio represents the probability of a token appearing in a toxic comment versus a non-toxic comment. The input feature matrix is element-wise multiplied by these ratios, effectively amplifying words that are strong indicators of toxicity and dampening neutral words.
*   **Classifier**: A **Logistic Regression** classifier is trained on these scaled features. This provides a calibrated probability output (0 to 1), which is suitable for the ROC-AUC metric.

### Data
1.  **Text Vectorization**:
    *   Generate a sparse feature matrix using **TF-IDF Vectorization** on the `comment_text`.
    *   Include both **word n-grams** (unigrams and bigrams) and **character n-grams** to capture specific terminology and obfuscated spellings.
2.  **Bias-Centric Sample Weighting**:
    *   Instead of physically resampling the data (as in Idea 1), calculate a **sample weight** vector to be passed directly to the loss function.
    *   Define a weighting schema that assigns higher importance to examples that fall into the "bias trap" categories (BPSN and BNSP). Specifically, assign higher weights (e.g., 5x) to:
        *   **Subgroup Negative**: Non-toxic comments that mention an identity (to prevent false positives).
        *   **Subgroup Positive**: Toxic comments that mention an identity (to prevent false negatives).
    *   This ensures the model is heavily penalized for misclassifying identity-related comments without altering the dataset size.

### Training
*   **Objective Function**: Minimize **Binary Cross-Entropy (Log-Loss)**.
*   **Optimization**: Use the **L-BFGS** or **Coordinate Descent** solver (standard for Logistic Regression) to fit the model.
*   **Weight Application**: Apply the pre-calculated sample weights during the training step. This forces the optimizer to prioritize the decision boundary around the weighted identity examples, directly optimizing for the generalized mean of bias AUCs.

### Evaluation
*   **Inference**: Transform the test set using the fitted TF-IDF vectorizer and apply the pre-computed Naive Bayes log-count ratios.
*   **Prediction**: Pass the transformed features through the trained Logistic Regression layer to obtain toxicity probabilities.
*   **Submission**: Format the probabilities into the required submission file.
