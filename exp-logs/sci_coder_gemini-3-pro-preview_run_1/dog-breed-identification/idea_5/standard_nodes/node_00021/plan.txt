Based on the lessons learned, specifically **Lesson ID: solution_lesson_node_00020**, the previous attempt to use a heterogeneous ensemble failed because the training time was split between two models, preventing either from converging. A single, fully converged `ConvNeXt-Base` model has been shown to achieve a validation log loss of `0.1414`, whereas the under-trained ensemble only reached `0.1720`.

Therefore, the optimization strategy is to:
1.  **Simplify the Architecture**: Revert to a single `convnext_base.fb_in1k` model. This allows us to dedicate the entire compute budget to optimizing one strong backbone.
2.  **Extend Training Duration**: Increase `EPOCHS_FINE` from the artificially constrained 4 epochs to 15 epochs. This ensures the model has sufficient time to minimize the loss and capture fine-grained features (Cite solution_lesson_node_00020).
3.  **Stabilize Initialization**: Maintain `EPOCHS_HEAD` at 3 to align the classifier head without overfitting to frozen features before fine-tuning begins (Cite solution_lesson_node_00009).
4.  **Remove Constraints**: Delete the code in `runfile.py` that was overriding the configuration to force a fast, under-performing run.
