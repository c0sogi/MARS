To resolve the `CUDA error: out of memory` caused by unreleased GPU resources from previous runs and high memory usage, I will implement the following changes based on the provided debug lessons:

1.  **Isolate Training in a Subprocess (Cite debug_lesson_8, debug_lesson_9, debug_lesson_10):**
    The training logic currently runs in the main process, which shares state with the persistent interpreter. I will move the execution logic from `runfile.py` into a new function `run_experiment_isolated` within `library/trainer.py` (reusing an existing module to avoid pickling errors). `runfile.py` will then serve as a launcher that executes this function in a separate process using `multiprocessing.get_context("spawn")`. This ensures that when the process finishes, the OS immediately reclaims all VRAM.

2.  **Reduce Memory Footprint (Cite debug_lesson_3):**
    I will reduce `IMG_SIZE` in `library/config.py` from `(768, 768)` to `(512, 512)` to significantly lower the memory requirement for the Siamese network. I will also update the cache directory to `idea_19_v2` to prevent loading stale cached data (Cite debug_lesson_2).

3.  **Enforce Spawn in DataLoaders (Cite debug_lesson_13):**
    To prevent crashes when worker processes are forked from a process with an initialized CUDA context, I will explicitly set `multiprocessing_context="spawn"` in the `DataLoader` initialization in `library/data.py`.
