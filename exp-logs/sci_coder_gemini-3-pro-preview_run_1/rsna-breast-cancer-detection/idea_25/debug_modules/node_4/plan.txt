To resolve the `CUDA error: out of memory` issue, I will implement a multi-layered fix addressing resource contention and zombie processes.

1.  **Preempt TensorFlow Memory Allocation:** I will modify both `library/config.py` and `runfile.py` to import TensorFlow and disable its GPU visibility *before* PyTorch is imported. This prevents TensorFlow (which might be imported by dependencies like `timm`) from greedily allocating all VRAM (Cite Lesson 13 & 16).
2.  **Enhance Memory Cleanup:** I will update the `cleanup_memory` function in `runfile.py` to explicitly iterate through `globals()` and delete any persistent `torch.nn.Module`, `torch.Tensor`, or `torch.optim.Optimizer` instances. This addresses "zombie" objects that persist in the interpreter session (Cite Lesson 7, 15, 18, 19).
3.  **Robust Resource Management:** I will refactor the model inspection block in `runfile.py` to use a `try...finally` structure. I will decouple the model instantiation from the device transfer and ensure that `del net` and `cleanup_memory()` are called in the `finally` block. This ensures that the GPU memory used for inspection is released before the training loop begins, even if errors occur (Cite Lesson 21, 27, 34).

def cleanup_memory():
    # Cite debug_lesson_18: Purge System Tracebacks to Release Zombie GPU Memory
    if hasattr(sys, "last_traceback"):
        sys.last_traceback = None
    
    # Cite debug_lesson_7 & 15: Purge Global Variables (including Optimizers/Containers)

    keys = list(gl.keys())
    for key in keys:
        if key in ["sys", "os", "torch", "gc", "shutil", "pd", "np", "config", "utils", "data", "model", "train", "tf"]:
