The issue is that the `val_rmse` metric calculated during training is a NumPy scalar (the result of `np.sqrt`), which is then saved into the model checkpoint. When `library/inference.py` attempts to load this checkpoint using `torch.load`, it fails because PyTorch 2.6+ defaults to `weights_only=True`, which restricts deserialization to a safe allowlist that excludes NumPy scalars by default. To fix this, we must explicitly cast `val_rmse` to a native Python `float` before it is used or saved. This ensures the checkpoint only contains standard types compatible with the secure loader (Cite debug_lesson_7).
