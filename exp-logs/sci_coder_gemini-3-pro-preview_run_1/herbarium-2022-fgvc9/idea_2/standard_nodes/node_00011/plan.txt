The solution involves orchestrating the training and evaluation of a hierarchical ConvNeXt-Tiny model. We will leverage the provided library modules to load data, initialize the model, and manage the training process. The strategy includes:

1.  **Setup & Configuration**: Initialize the environment with a fixed random seed and detect the GPU. We will use a batch size of 128 to fully utilize the A100 GPU and speed up training.
2.  **Data Loading**: Use the `get_dataloaders` function to prepare training, validation, and test loaders. We will increase `num_workers` to 8 to minimize data bottlenecks.
3.  **Model Training**: Instantiate the `HierarchicalConvNeXt` and `HierarchicalTrainer`. We will train for 3 epochs, which is calculated to fit comfortably within the 2-hour limit on an A100 (approx. 15-20 mins per epoch).
4.  **Validation & Metrics**: After training, we load the best model checkpoint and perform a full inference pass on the validation set to calculate the Macro F1 score. This metric determines if we proceed to submission.
5.  **Failure Analysis**: We will analyze the validation results by correlating prediction errors with class frequency (a proxy for data imbalance) to identify if rare classes are disproportionately misclassified.
6.  **Submission**: If the validation F1 score exceeds the threshold (0.62919...), we generate predictions for the test set, map the internal labels back to the original `category_id`s, and save the result to `submission.csv`.
