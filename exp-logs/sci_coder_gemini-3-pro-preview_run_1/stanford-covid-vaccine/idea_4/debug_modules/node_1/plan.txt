The error arises because the `ReduceLROnPlateau` scheduler in PyTorch 2.0+ no longer supports the `verbose` argument, causing a `TypeError`. Additionally, the `library/train.py` script executes `run_training()` at the global scope, which triggers the training loop immediately upon import in `runfile.py`, preventing the demo script from configuring the environment correctly.

To fix this, I will:
1.  Remove the `verbose=True` argument from the `ReduceLROnPlateau` initialization in `library/train.py`.
2.  Wrap the `run_training()` call in `library/train.py` within an `if __name__ == "__main__":` block to prevent execution during import.

These changes ensure the module can be imported safely and runs correctly when executed directly, while resolving the API incompatibility.
