### Implementation Strategy

1.  **Configuration Override**: We will modify the global `Config` class attributes to create a lightweight "demo" environment. This includes reducing model dimensions (hidden size, layers), setting a small batch size, and defining a temporary working directory to avoid interfering with production outputs.
2.  **Data Loading & Verification**: We will utilize `get_dataset` to load the training data. We will explicitly verify the integrity of the data pipeline by checking the shapes and data types of a single batch yielded by the `DataLoader`.
3.  **Model Initialization & Forward Pass**: We will instantiate the `InterleavedBiGRU` model using the reduced configuration. We will perform a forward pass with the sample batch to verify that the model architecture processes inputs correctly and produces outputs of the expected shape `(Batch, SeqLen, 3)`.
4.  **Loss Calculation**: We will demonstrate the `MaskedMSELoss` and `mcrmse` metric functions. We will manually create a scenario (e.g., zero predictions vs. targets) to verify the loss logic behaves as expected.
5.  **Training Step Simulation**: We will execute a single optimization step (backward pass and optimizer update) to ensure the gradient flow works correctly.
6.  **Inference & Submission Formatting**: We will simulate the inference process on a small batch of test data, demonstrating how to reshape the 3D model outputs into the flat CSV format required for submission.
7.  **Cleanup**: The script will operate within `./working/demo_run` and can optionally clean up, though we will leave artifacts for inspection as per standard practice in these environments.
