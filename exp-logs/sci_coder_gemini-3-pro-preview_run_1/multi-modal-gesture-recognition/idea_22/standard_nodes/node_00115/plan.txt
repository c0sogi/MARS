The implementation strategy follows a streamlined orchestration pipeline designed to meet the time constraints while ensuring robust validation and analysis.

1.  **Configuration & Setup**: We override the default `Config` to set `NUM_EPOCHS` to 25. This ensures the training completes rapidly (well within the 2-hour limit) while allowing sufficient convergence for the baseline model on the relatively small dataset (~300 samples). We explicitly set the random seed for reproducibility.
2.  **Training**: We utilize the provided `Trainer` class to handle the training loop, optimizer stepping, and checkpointing. The trainer automatically handles mixed-modality data loading (Skeleton + Audio) and GPU acceleration.
3.  **Validation & Metric Calculation**: After training, we reload the best saved checkpoint to perform a dedicated inference pass on the validation set. We calculate the Levenshtein Error Rate (LER) using the provided utility functions. This metric is printed exactly as requested (`Final Validation Metric: <value>`).
4.  **Failure Analysis**: Concurrently with validation inference, we collect sample-level statistics: sequence length (frames), ground truth complexity (number of gestures), and the resulting Levenshtein distance. We use `scipy.stats.pearsonr` to compute and print the correlation between the error magnitude and these input features, identifying if long or complex sequences systematically confuse the model.
5.  **Submission Generation**: We compare the final validation metric against the strict threshold (`0.05697278911564626`). If the model performs sufficiently well, we invoke the trainer's submission generation method to create `submission.csv` for the test set.
