The `zipfile.BadZipFile` error occurs because `np.load` returns an `NpzFile` object that maintains an open file handle. When this object is serialized and shared across multiple `DataLoader` worker processes, concurrent access to the single file descriptor leads to race conditions and data corruption (Cite debug_lesson_12). To fix this, I will modify `_get_global_stats` in `library/data_loader.py` to materialize the statistics into a standard Python dictionary using a context manager (`with np.load(...)`) or by returning the computed dictionary directly. This ensures that only safe, in-memory data structures are passed to the workers, eliminating the shared file handle.
