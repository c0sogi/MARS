The `zipfile.BadZipFile` error occurs because the `GestureDataset` stores an open `numpy.lib.npyio.NpzFile` handle (returned by `np.load`) in `self.stats`. When `num_workers > 0`, this handle is pickled and shared across worker processes. Concurrent access to the same file descriptor by multiple workers causes race conditions and file pointer corruption. To fix this, I will modify `_get_global_stats` to explicitly materialize the data into a Python dictionary and close the file handle immediately using a context manager (`with np.load(...) as data`). This ensures that `self.stats` contains safe, in-memory data before it is distributed to workers. I will also update `_load_sample` to use the same pattern for robustness. Cite debug_lesson_12.
