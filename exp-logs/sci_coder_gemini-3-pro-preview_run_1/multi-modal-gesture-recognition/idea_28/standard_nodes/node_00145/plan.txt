The `zipfile.BadZipFile: Truncated file header` error occurs because `np.load` returns a lazy-loading `NpzFile` object that maintains an open file handle. When this object is passed to multiple `DataLoader` worker processes, concurrent access to the same file descriptor causes race conditions and file pointer corruption. To fix this, I will modify `compute_dataset_stats` to explicitly materialize the cached statistics into an in-memory dictionary and close the file handle immediately, ensuring safe serialization across processes.
