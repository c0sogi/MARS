# Frame-wise Supervised Recurrent Baseline

### Model
The proposed model is a **Frame-wise Supervised Gated Recurrent Unit (GRU)**. Unlike the CTC-based approach (Model 4) which learns alignment implicitly, or the Sliding Window approach (Model 2) which uses fixed contexts, this model leverages the explicit start/end timestamps provided in the training data to learn a direct mapping from frame features to gesture classes.

*   **Input Layer:** A dense projection layer that fuses multimodal features (Skeleton + Audio) into a unified embedding vector for each frame.
*   **Recurrent Core:** A single-layer, unidirectional GRU. This allows the model to maintain a "memory" of the current gesture state and temporal context without the computational overhead of deep stacked layers or bidirectional processing.
*   **Classification Head:** A standard fully connected layer followed by a Softmax activation that outputs a probability distribution over 21 classes (20 gesture categories + 1 "background/null" class) for every individual frame.

### Data
*   **Feature Engineering:**
    *   **Skeleton:** To ensure user independence, raw WorldPosition coordinates will be normalized by subtracting the coordinates of a central joint (e.g., `HipCenter`) from all other joints in every frame. This makes the features invariant to the user's position in the room. We will also compute the first-order derivatives (velocity) of the joints to capture motion dynamics.
    *   **Audio:** We will extract Mel-frequency cepstral coefficients (MFCCs) from the audio stream. The hop length for the MFCC extraction will be calculated to strictly align the audio features with the video frame rate (20 fps), resulting in a one-to-one correspondence between audio feature vectors and video frames.
*   **Label Generation:**
    *   Using the provided training annotations (Start Frame, End Frame, Label Name), we will construct a dense frame-wise target vector for each training video. Frames falling within the annotated bounds of a gesture will be assigned that gesture's ID (1-20). All other frames will be assigned the background class ID (0).

### Training
*   **Loss Function:** We will use standard **Frame-wise Cross-Entropy Loss**. This forces the model to explicitly learn the boundaries of gestures as defined by the annotators.
*   **Class Balancing:** Since the "background" class likely dominates the timeline, we will apply class weighting to the loss function to penalize errors on gesture classes more heavily than errors on the background.
*   **Optimization:** The model will be trained using the Adam optimizer. We will feed full sequences (or long truncated backpropagation through time chunks) to allow the GRU to learn long-term dependencies.

### Evaluation
*   **Inference:** The test sequences (which lack start/end annotations) will be passed through the trained GRU to generate a probability matrix of shape $(T \times 21)$.
*   **Decoding:** We will apply a greedy decoding strategy:
    1.  **Argmax:** Select the class with the highest probability for each frame.
    2.  **Smoothing:** Apply a simple temporal filter (e.g., a median filter) to the sequence of predicted labels to remove high-frequency noise (single-frame glitches).
    3.  **Run-Length Encoding:** Collapse consecutive identical labels into a single instance (e.g., `[2, 2, 2, 0, 0, 3, 3]` becomes `[2, 0, 3]`).
    4.  **Filtering:** Remove the background class (0) and any gesture instances that are unrealistically short (e.g., less than 5 frames) to produce the final ordered list of gesture IDs.
