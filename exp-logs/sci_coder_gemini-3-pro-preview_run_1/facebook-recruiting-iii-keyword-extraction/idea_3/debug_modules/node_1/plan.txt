The error is caused by **stale artifacts** in the demo environment (`./working/demo_env`). Specifically, a `cached_train.parquet` file from a previous or failed run exists but lacks the required `title_idxs` column. The `StackExchangeDataset` blindly loads this invalid cache file without validating its schema, leading to a `KeyError` when accessing the missing column. This is a classic example of **Global State Fragility** (Cite debug_lesson_2), where the application state depends on unverified external files.

To fix this:
1.  **In `runfile.py`**: Add a cleanup step to remove the demo directory before starting. This ensures the demo runs in a clean environment and forces the regeneration of correct dataset artifacts.
2.  **In `library/dataset.py`**: Add schema validation to `_load_data`. If the loaded cache file is missing required columns, discard it and rebuild the dataset. This makes the data loading robust against corrupted or incompatible cache files.
