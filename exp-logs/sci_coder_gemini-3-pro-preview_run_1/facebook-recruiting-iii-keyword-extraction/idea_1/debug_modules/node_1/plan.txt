The issue stems from Python evaluating default argument values at function definition time (import time), rather than at execution time. In `library/data_loader.py`, the `TextTokenizer` and `TagEncoder` classes define their `__init__` parameters using `Config` attributes as defaults (e.g., `num_tags=Config.NUM_TAGS`). When `runfile.py` subsequently modifies `Config.NUM_TAGS` to 20 for the demo, the classes retain the original value (5000) captured during import. This causes the `TagEncoder` to generate targets for up to 5000 tags (finding 2173 in the debug subset), while the model is initialized with the updated 20 classes, resulting in a shape mismatch error.

To fix this, I will modify the `__init__` methods of both `TextTokenizer` and `TagEncoder` in `library/data_loader.py` to use `None` as the default value for these parameters. Inside the method, I will check if the value is `None` and, if so, read the current value from `Config`. This ensures the classes use the configuration values active at the time of instantiation.
