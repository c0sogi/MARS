# Solution: Domain-Adapted DeBERTa-v3 with Weighted Layer Aggregation and AWP

## Model
I propose a robust architecture designed to capture both the high-level semantics and the low-level lexical triggers of toxicity.

1.  **Backbone (Strategic Retention):** We will utilize **DeBERTa-v3-base**. This model outperforms RNNs (Cite solution_lesson_node_00007) and offers superior context understanding via disentangled attention. We select the "Base" variant to ensure we can train on the **full dataset** and perform Cross-Validation within the 24-hour limit, avoiding the performance pitfalls of subsampling required by "Large" models (Cite solution_lesson_node_00014).
2.  **Weighted Layer Aggregation (Structural Innovation):** Instead of using only the final hidden state, we will implement a **learnable weighted sum of the last 4 encoder layers**. Lesson 00009 highlighted that lower layers contain critical lexical information (slang, profanity) that must be adapted. By aggregating these layers, we provide the classification head with direct access to these raw signals alongside the high-level semantic context.
3.  **Hybrid Pooling Head (Strategic Retention):** We will apply the proven hybrid pooling strategy to the aggregated representation:
    *   **Global Max Pooling:** To extract the strongest local toxic signal (e.g., a specific slur) regardless of context (Cite solution_lesson_node_00001).
    *   **Linear Attention Pooling:** To compute a context-aware weighted average, prioritizing relevant tokens while filtering noise (Cite solution_lesson_node_00002). We will strictly use **Linear Attention** ($w^T h_t$) to ensure efficient convergence (Cite solution_lesson_node_00003).
    *   These two vectors will be concatenated.
4.  **Multi-Sample Dropout (Strategic Retention):** The concatenated vector will pass through 5 parallel dropout masks to smooth the loss landscape and improve generalization (Cite solution_lesson_node_00016).

## Data
1.  **Tokenization:** We will use the **DeBERTa-v3 Tokenizer** (SentencePiece). This is critical as it preserves punctuation and special characters (e.g., "!!", "f**k") as distinct tokens, which are high-signal features for toxicity often lost in standard cleaning (Cite solution_lesson_node_00004).
2.  **Unsupervised Corpus Construction:** We will concatenate the text from both `train.csv` and `test.csv` to create a large domain-specific corpus for the pre-training stage.
3.  **Supervised Dataset:** We will use the **Full Training Dataset** for the classification stage (Cite solution_lesson_node_00014).

## Training
I propose a **Two-Stage Training Pipeline** to maximize domain adaptation and robustness.

**Stage 1: Domain-Adaptive Pre-training (DAPT)**
*   **Objective:** We will fine-tune the DeBERTa-v3 backbone on the combined (train + test) text using the **Masked Language Modeling (MLM)** objective for 3 epochs.
*   **Rationale:** This adapts the model's embeddings and lower layers to the specific vocabulary, slang, and structural idiosyncrasies of Wikipedia comments *before* supervised learning begins. This directly addresses the need for lower-layer adaptation identified in Lesson 00009 without relying on labeled data.

**Stage 2: Robust Supervised Fine-Tuning (5-Fold CV)**
*   **Strategy:** We will fine-tune the domain-adapted backbone using **5-Fold Cross-Validation**.
*   **Optimization:** We will use the **AdamW** optimizer with a **Uniform Learning Rate**. We will explicitly **reject Layer-wise Learning Rate Decay (LLRD)**, allowing all layers (especially the aggregated lower layers) to update at the full rate to capture toxic vocabulary (Cite solution_lesson_node_00009).
*   **Adversarial Weight Perturbation (AWP):** We will implement **AWP** starting from the second epoch. This technique minimizes the "worst-case" loss by perturbing weights during training, significantly improving robustness and generalization (Cite solution_lesson_node_00018).
*   **Scheduling:** We will use a **OneCycleLR** scheduler with a duration of **5 epochs per fold**. This extended duration is crucial to allow the complex architecture (Layer Aggregation + Multi-Sample Dropout) to converge effectively, avoiding the failure modes of compressed schedules (Cite solution_lesson_node_00006, solution_lesson_node_00016).

## Evaluation
1.  **Inference:** We will generate predictions for the test set using each of the 5 trained fold models.
2.  **Ensembling:** The final prediction for each comment will be the arithmetic mean of the probabilities output by the 5 models. This reduces variance and maximizes the Mean Column-wise ROC AUC.
3.  **Submission:** The averaged probabilities will be formatted into the required CSV structure.
