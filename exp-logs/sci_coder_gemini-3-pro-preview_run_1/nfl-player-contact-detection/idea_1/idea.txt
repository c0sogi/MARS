# Baseline Approach: Instantaneous Kinematic MLP

## Model
The proposed model is a **Kinematic Feed-Forward Network (K-FFN)**, a lightweight Multi-Layer Perceptron (MLP) designed to classify contact events based solely on instantaneous tracking data.

*   **Architecture:** The network consists of a simple stack of fully connected (Dense) layers: an input layer, two hidden layers with 64 and 32 units respectively (using ReLU activation and Batch Normalization), and a single output neuron with a Sigmoid activation.
*   **Differentiation:**
    *   Unlike **Model 1** (LightGBM), this is a differentiable neural network that allows for batch-based training and easy GPU acceleration.
    *   Unlike **Model 2** (1D-CNN) and **Model 1**, it eschews temporal windows, treating each timestep as an independent observation. This drastically reduces the input dimensionality and preprocessing overhead.
    *   Unlike **Model 3** and **Model 4**, it relies exclusively on tabular kinematics without image processing or graph construction, ensuring maximum throughput.

## Data
Preprocessing focuses on generating a compact, instantaneous feature vector for each `contact_id` in the metadata.

1.  **Tracking Merge:** Join the tracking data to the metadata based on `game_play`, `step`, and player IDs.
2.  **Feature Engineering:**
    *   **Player-Player Pairs:** Calculate Euclidean distance, relative speed (absolute difference), and relative orientation between the two players.
    *   **Player-Ground Pairs:** Since the ground has no specific X/Y coordinate, set distance to zero and use the player's absolute speed and acceleration magnitude as features. Create a binary flag `is_ground` (1 for ground, 0 for player) to allow the network to distinguish these two modalities.
3.  **Normalization:** Apply standard scaling (Z-score normalization) to all continuous features to ensure efficient gradient descent.
4.  **Imbalance Handling:** The dataset is heavily imbalanced (~98% no-contact). For training, create a subset by keeping all positive contact samples and randomly undersampling the negative samples to achieve a manageable ratio (e.g., 1:5). This significantly reduces the data volume and training time.

## Training
The training process prioritizes stability and convergence speed.

*   **Loss Function:** Use **Binary Cross-Entropy (BCE) Loss**.
*   **Optimizer:** Use **Adam** with a default learning rate of 0.001.
*   **Strategy:** Train for a small number of epochs (e.g., 5-10) with a large batch size (e.g., 1024 or 2048). The undersampled dataset allows for extremely rapid epoch completion.
*   **Validation:** Monitor the Matthews Correlation Coefficient (MCC) on a held-out validation set (which should *not* be undersampled, to reflect real-world performance) to determine the optimal decision threshold.

## Evaluation
To generate predictions for the test set:

1.  **Preprocessing:** Apply the same feature engineering and normalization steps to the test metadata. Do not undersample.
2.  **Inference:** Run a forward pass of the trained K-FFN on the full test feature matrix.
3.  **Thresholding:** Convert the continuous probability output (0-1) into binary predictions (0 or 1) using the optimal threshold derived during the validation phase.
4.  **Submission:** Format the results into the required CSV structure.
