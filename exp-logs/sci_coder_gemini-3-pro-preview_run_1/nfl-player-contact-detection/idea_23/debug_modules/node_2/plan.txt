The issue is caused by the indiscriminate application of `df_final.fillna(0)` on the entire dataframe, which contains both numeric feature columns and string metadata columns (like `datetime_p1`). When `df_players` (which has tracking data) and `df_ground` (which does not) are concatenated, the string columns present only in `df_players` are filled with `NaN` for the ground rows. The global `fillna(0)` replaces these `NaN`s with the integer `0`, creating a mixed-type column (strings and integers) that causes `pyarrow` to crash during Parquet serialization.

To fix this, I will restrict the imputation to numeric columns only. This ensures that missing values in numeric features are filled with 0 as intended, while missing values in string/object columns remain as `NaN` (null), which is a valid state for Parquet serialization. This aligns with **debug_lesson_11** ("Restrict Imputation to Numeric Columns") and **debug_lesson_16** ("Enforce Strict Schema Consistency").
