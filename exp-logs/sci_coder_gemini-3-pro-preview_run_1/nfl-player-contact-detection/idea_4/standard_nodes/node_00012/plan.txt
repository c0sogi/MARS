The implementation strategy follows the requirements to create a fast baseline execution of the contact detection task.

1.  **Configuration & Setup**: We import the necessary classes from the provided library files. To ensure the process completes within the 2-hour limit, we dynamically modify the `Config` parameters to reduce the number of estimators for both LightGBM and XGBoost (from 2000 to 800) and set a fixed random seed for reproducibility.

2.  **Data Loading & Processing**: We utilize the `FeatureProcessor` to load and process the training and validation datasets. `load_cached_data=True` is used to leverage any existing precomputed features. To strictly adhere to the "Limit maximum number of training samples" requirement for a fast baseline, we downsample the training data to 500,000 rows after loading. The validation set is kept intact to ensure accurate metric calculation.

3.  **Model Training**: We instantiate and train the `LGBMWrapper` and `XGBWrapper` models on the sampled training data. The models are saved to the working directory for later use during inference.

4.  **Ensemble & Evaluation**: We generate probability predictions on the validation set using both models and compute an unweighted average. We then use the `optimize_threshold` function to find the classification threshold that maximizes the Matthews Correlation Coefficient (MCC). The final validation metric is printed with full precision.

5.  **Failure Analysis**: We calculate the absolute error magnitude (`|y_true - y_prob|`) for the validation set and compute the correlation between this error and all input features. The top 10 features most correlated with the error are printed to identify systematic weaknesses.

6.  **Submission**: We compare the final validation MCC against the required threshold (0.5979349867102601). If the score is higher, we trigger the `predict_and_submit` function to generate the submission file for the test set; otherwise, submission is skipped.
