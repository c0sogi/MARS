# Baseline Approach: Windowed Feature Gradient Boosting

## Model
The proposed model is a **Temporal Gradient Boosting Machine (T-GBM)**, utilizing the LightGBM framework. This approach diverges from the instantaneous MLP by leveraging decision tree ensembles, which are exceptionally efficient at handling tabular data with varying scales and discrete features.

*   **Architecture:** The core architecture is a Gradient Boosting Decision Tree (GBDT) classifier. Unlike the previous neural network approach, this model builds a sequence of weak learners (decision trees) that iteratively correct the errors of their predecessors.
*   **Temporal Context:** Instead of treating each timestep in isolation, this model incorporates a **flattened temporal window**. The input for a specific timestep includes tracking features from the current moment as well as several preceding and succeeding timesteps (e.g., $t-5$ to $t+5$). This allows the model to infer contact based on trajectory convergence and sudden deceleration patterns, which are invisible to an instantaneous model.

## Data
The data preparation focuses on transforming sequential tracking data into a rich, windowed tabular format suitable for tree-based algorithms.

1.  **Sequence Construction:** For every `contact_id`, extract the tracking data for the involved pair. If the second "player" is the Ground (`G`), impute the second player's features (position, speed, acceleration) as zeros or fixed constants.
2.  **Windowed Feature Engineering:**
    *   Define a window size (e.g., 1 second, representing 10 frames).
    *   For the target frame, collect the raw tracking features (speed, acceleration, orientation) and calculated pair features (distance, relative speed) for all frames within the window.
    *   Flatten these temporal steps into a single wide feature vector (e.g., `dist_t-5`, `dist_t-4`, ..., `dist_t+5`).
3.  **Categorical Handling:** Explicitly encode the `is_ground` flag and `position` (player role) as categorical features, allowing the LightGBM algorithm to natively handle the distinction between player-player and player-ground interactions without separate processing pipelines.
4.  **No Scaling:** Unlike the MLP approach, this method requires **no normalization or scaling** of features, as decision trees are invariant to monotonic transformations of feature values, simplifying the pipeline.

## Training
The training procedure is designed to maximize the Matthews Correlation Coefficient (MCC) while handling the severe class imbalance without discarding data.

*   **Objective:** Train using **Binary Log-Loss**.
*   **Imbalance Strategy:** Instead of undersampling (which removes data), use **Class Weighting** (specifically `scale_pos_weight` or `is_unbalance=True`). This forces the model to penalize false negatives more heavily during the gradient calculation, utilizing the full training dataset.
*   **Validation & Early Stopping:** Split the training data by `game_play` to create a validation set. Train the model with early stopping, halting the addition of new trees when the validation Log-Loss stops improving for a set number of rounds.

## Evaluation
1.  **Feature Generation:** Apply the same sliding window logic to the test metadata to generate the flattened feature vectors.
2.  **Inference:** Run the trained LightGBM model on the test set to output contact probabilities.
3.  **Threshold Optimization:** Because the competition metric is MCC, the default 0.5 probability threshold is rarely optimal. Use the validation set predictions to perform a grid search for the probability threshold that maximizes the MCC score.
4.  **Submission:** Apply this optimized threshold to the test probabilities to generate the final binary `contact` labels for submission.
