# Strategy: Split-Stream Kinematic Architecture (SSKA)

Based on the provided lessons, I propose a structural evolution that moves away from a monolithic model. The core insight is that "Player-Player" contact (geometric proximity) and "Player-Ground" contact (kinematic impact) are fundamentally different physical events. The previous failure to detect ground contacts (Cite Lesson 1) and the rapid saturation of the tree model (Cite Lesson 3) suggest that a single architecture cannot optimally solve both problems simultaneously.

This solution implements a **Split-Stream Kinematic Architecture (SSKA)**, which routes data to specialized models based on the contact type, leveraging the efficiency of Gradient Boosting for interaction detection and the temporal pattern recognition of Convolutional Neural Networks for ground impact detection.

### 1. Model
The architecture consists of two distinct parallel streams:

*   **Stream A: Interaction Model (Player-Player)**
    *   **Architecture:** **Windowed LightGBM (GBDT)**.
    *   **Rationale:** We explicitly retain the **flattened temporal window approach** (Cite Lesson 1), as the previous experiments proved it is highly efficient and effective for detecting contacts driven by relative geometry (distance, closing speed).
    *   **Enhancement:** To address the "Early Convergence" issue where the model saturated at ~20 trees, this stream will utilize a **High-Capacity Configuration** (Cite Lesson 3), significantly increasing `num_leaves` and training data volume to force the model to learn subtler interaction patterns beyond simple distance thresholds.

*   **Stream B: Impact Model (Player-Ground)**
    *   **Architecture:** **1D-ResNet (Temporal Convolutional Network)**.
    *   **Rationale:** Ground contact was the primary failure mode of the previous solution. Unlike player-player contact, ground contact has no "distance" feature (the ground is everywhere). It is characterized by a specific *temporal signature* in the trajectory (e.g., sudden deceleration, change in orientation, "jerk"). A 1D-CNN is structurally superior here as it learns temporal filters to detect these "impact impulses" within the sequence, rather than treating time steps as independent features like the GBDT.

### 2. Data
The data pipeline will be engineered to support this split-stream approach while enforcing strict version control.

*   **Dynamic Cache Invalidation:** To prevent the "Implicit Caching Hazards" observed previously (Cite Lesson 2), the feature generation pipeline will enforce **parameter-aware caching**. Output filenames will automatically include a hash of the window size and feature list (e.g., `train_features_w20_v3.parquet`), ensuring that any change in logic triggers a recompute.
*   **Stream-Specific Feature Engineering:**
    *   **Common:** A temporal window of +/- 10 steps (1.0 second) centered on the target frame.
    *   **Stream A (Interaction):** Flattens the window into a 1D vector. Features include **Relative Kinematics** (Distance, Speed Difference, Relative Orientation) and **Interaction Context** (Player roles).
    *   **Stream B (Impact):** Retains the temporal dimension `(Window_Size, Features)`. Features focus on **Absolute Kinematics** (Speed, Acceleration, Orientation) and **Derived Signals** (Jerk/Derivative of Acceleration) for the single player involved.

### 3. Training
The training process is decoupled to optimize each stream for its specific modality.

*   **Stream A (GBDT):**
    *   **Objective:** Binary Log-Loss.
    *   **Strategy:** Apply the **Information Density Maximization** strategy (Cite Lesson 3). We will use a massive subsample (e.g., 3M+ rows) or the full dataset with heavy class weighting (`scale_pos_weight`), avoiding aggressive undersampling to ensure the deep trees have sufficient data to model complex boundaries.
*   **Stream B (1D-CNN):**
    *   **Objective:** Binary Cross-Entropy.
    *   **Optimizer:** AdamW with a Cosine Annealing scheduler.
    *   **Strategy:** Train on all available "Player-Ground" samples (positive and negative). Since this dataset is smaller than the full pairwise set, we can train for more epochs without exceeding the time limit.

### 4. Evaluation
The inference pipeline will function as a router:

1.  **Preprocessing:** Generate windowed features for the test set.
2.  **Routing:**
    *   If `nfl_player_id_2 == "G"`, route the sample to **Stream B (Impact Model)**.
    *   Otherwise, route the sample to **Stream A (Interaction Model)**.
3.  **Submission:** Concatenate the predictions from both streams into the final submission file. This ensures that ground contacts are predicted by the model best suited to detect falls, while player contacts are predicted by the model best suited to measure proximity.
