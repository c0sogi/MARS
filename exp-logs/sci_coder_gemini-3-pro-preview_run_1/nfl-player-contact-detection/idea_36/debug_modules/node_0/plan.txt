The following strategy outlines the implementation of the demonstration script:

1.  **Configuration & Setup**: Import the provided library modules (`config`, `utils`, `data_processing`, `feature_engineering`, `models`, `training_pipeline`, `inference`). Set the random seed for reproducibility. Crucially, override the global configuration parameters in `config.py` (e.g., reducing `N_ESTIMATORS` to 10, disabling verbosity) to ensure the script runs quickly within the time limit.

2.  **Data Processing & Feature Engineering**: Demonstrate the generation of training and validation features using a small subset of data (`sample_size=500`). This utilizes `feature_engineering.generate_train_features` and `generate_val_features`. We will verify the output DataFrames contain the expected feature columns (e.g., lag features like `dist_t+0`) and target variables.

3.  **Model Training Workflow**: Manually execute the stages of the training pipeline:
    *   **Scout Training**: Train lightweight "Scout" models using `training_pipeline.train_scouts`.
    *   **Hard Negative Mining**: Use the trained scouts to identify hard negatives via `training_pipeline.mine_hard_negatives`.
    *   **Expert Dataset Construction**: Combine positives, hard negatives, and random anchors using `training_pipeline.construct_expert_dataset`.
    *   **Expert Training**: Train the final Dual-Ensemble (LightGBM + XGBoost) using `training_pipeline.train_experts`.
    *   **Threshold Optimization**: Find the optimal decision threshold using `training_pipeline.optimize_threshold`.
    *   Throughout these steps, assertions will verify that models are instantiated and data shapes are correct.

4.  **Inference Execution**: To demonstrate inference without processing the full test set (which takes time), create a temporary "mini" test metadata file in the working directory. Point `config.TEST_METADATA_PATH` to this file. Then, execute `inference.run_inference` to generate predictions and a submission file.

5.  **Validation**: Finally, load the generated `submission.csv` to verify it adheres to the expected format and schema.
