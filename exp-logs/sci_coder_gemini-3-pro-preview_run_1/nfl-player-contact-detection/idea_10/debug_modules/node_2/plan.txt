The issue is caused by the `nfl_player_id_2` column containing a mixture of integers (for player IDs) and the string `'G'` (for ground contact) after the player-player and player-ground DataFrames are concatenated. When `pyarrow` attempts to save this DataFrame to a Parquet file, it infers the column type as integer based on the initial values but fails when it encounters the string `'G'`. To fix this, we must explicitly cast the `nfl_player_id_2` column to a string type immediately after recombining the data subsets in `FeatureEngineer.generate_dataset`. This enforces a consistent schema for the identifier column, preventing type inference failures during serialization. Cite debug_lesson_13.
