The issue is caused by a column naming collision in `library/feature_engineering.py` during the merging of Player 1 features. When `pd.merge` joins the metadata and tracking DataFrames, it automatically handles the `datetime` column collision by creating `datetime` (from metadata) and `datetime_p1` (from tracking, via the suffix). However, the subsequent renaming logic blindly attempts to rename the remaining `datetime` column to `datetime_p1`, creating a duplicate column name which causes the `to_parquet` serialization to fail.

To fix this, I will modify the dictionary comprehension for `rename_map` to explicitly check if the target column name (e.g., `datetime_p1`) already exists in the DataFrame before adding it to the map. This ensures that columns already handled by the merge suffixes are not overwritten or duplicated. Cite debug_lesson_13.
