Based on the progression of lessons learned, specifically the success of **Geometric Gating** (Cite solution_lesson_node_00026) and **Hard-Negative Mining** (Cite solution_lesson_node_00019), combined with the identified need for **Full-Fidelity Filtering** (Cite solution_lesson_node_00022), I propose the **Vectorized Flow-Field Mining Cascade (VFF-MC)**.

This strategy introduces a structural innovation in feature engineering—**Vectorized Flow Context**—to resolve the ambiguity between "dense crowds" and "active collisions" (Cite solution_lesson_node_00023), implemented within a rigorous **Gated Full-Context Mining** pipeline.

### 1. Model
The architecture employs a **Unified Heterogeneous Ensemble** designed for maximum capacity and stability.

*   **Unified Backbone:** We utilize a single modeling framework for both Player-Player and Player-Ground contacts. We explicitly retain the **Unified Architecture** (Cite solution_lesson_node_00007), using an `is_ground` categorical feature to leverage the shared non-contact majority class for stability, rather than splitting the streams.
*   **Heterogeneous Components:** The final predictor consists of two distinct Gradient Boosting models: **LightGBM** (Leaf-wise growth) and **XGBoost** (Level-wise growth).
*   **High-Capacity Configuration:** Both models will be configured with deep trees (e.g., `num_leaves=256`, `max_depth=10`) to maximize information density and prevent the "Early Convergence" observed in shallower models (Cite solution_lesson_node_00003).

### 2. Data
The data pipeline implements a **Geometric Gating** paradigm to enable the computation of computationally expensive **Flow-Field Features** for the entire relevant search space.

*   **Stage 0: Geometric Gating (The Sieve)**
    *   **Filter:** For the full training set (~3.4M rows), calculate instantaneous Euclidean distance.
    *   **Logic:** Discard Player-Player pairs with `Distance > 2.5` yards. Keep **ALL** Player-Ground pairs.
    *   *Rationale:* This eliminates trivial non-contacts (Cite solution_lesson_node_00026), reducing the dataset to a manageable size (~600k rows) while preserving all potential "Hard Negatives".

*   **Stage 1: Vectorized Flow-Field Feature Engineering**
    *   **Base Kinematics:** We retain **Flattened Temporal Windows** (+/- 10 steps) of relative position, speed, and acceleration (Cite solution_lesson_node_00001).
    *   **Physics Derivatives:** We retain **Jerk** and **Angular Jerk** to explicitly detect impact impulses for Ground contact (Cite solution_lesson_node_00012).
    *   **Innovation: Vectorized Flow Context:** Instead of simple "Spatial Density" counts (Cite solution_lesson_node_00023) or static grids, we model the **Local Velocity Flux**. For the target player, we identify neighbors within 2 yards and compute:
        *   **Radial Flux:** The average velocity of neighbors projected onto the vector connecting them to the target. (Negative = Crushing/Converging, Positive = Dispersing).
        *   **Tangential Flux:** The average velocity perpendicular to the connecting vector. (High = Swarming/Orbiting).
        *   *Rationale:* This physically distinguishes between a "formation running in sync" (High Density, Low Radial Flux) and a "tackle pile-up" (High Density, High Negative Radial Flux), addressing the limitations of scalar density features.
    *   **Invariance:** All features are strictly relative; absolute coordinates are excluded (Cite solution_lesson_node_00024).

*   **Caching:** Strict **parameter-aware caching** is enforced to prevent implicit hazards (Cite solution_lesson_node_00002).

### 3. Training
The training process executes a **Full-Fidelity Mining Curriculum** to ensure the model learns from the hardest examples without semantic gaps.

*   **Phase 1: Scout Training**
    *   Construct a balanced dataset from the **Gated Survivors** (All Positives + Equal Random Negatives).
    *   Train a **Scout LightGBM** using the **Full Feature Set** (Flow + Windows).
    *   *Crucial Correction:* Unlike previous tiered attempts, the Scout sees the *exact same* high-fidelity features as the Expert, preventing the "Semantic Gap" failure (Cite solution_lesson_node_00022).

*   **Phase 2: Full-Scale Mining**
    *   Run Scout inference on the **Entire Gated Survivor Pool** (~600k rows).
    *   Select **Hard Negatives**: Instances where $P(Contact) > 0.05$ but Ground Truth is 0.
    *   *Rationale:* This leverages the scale-dependent efficacy of mining (Cite solution_lesson_node_00021) to find the most confusing edge cases across the entire season.

*   **Phase 3: Expert Training**
    *   Construct the **Expert Dataset**: All Positives + All Mined Hard Negatives + Small Buffer of Random Gated Negatives.
    *   Train the **Expert Ensemble** (LGBM + XGB) on this high-information-density dataset.
    *   **Imbalance Handling:** Use `is_unbalance=True` (LGBM) and `scale_pos_weight` (XGB) to manage the remaining difficulty-based imbalance without discarding data (Cite solution_lesson_node_00011).

### 4. Evaluation
1.  **Feature Generation:** Generate the **Full Feature Set** (Flow + Windows) for the **Entire Test Set**. (The test set is small enough that Geometric Gating is unnecessary for inference speed).
2.  **Inference:** Run the **Expert Ensemble** on the test features.
3.  **Ensembling:** Compute the unweighted average of the probability outputs from LightGBM and XGBoost.
4.  **Thresholding:** Apply the decision threshold optimized on the validation set (maximizing MCC) to generate the final binary submission.
