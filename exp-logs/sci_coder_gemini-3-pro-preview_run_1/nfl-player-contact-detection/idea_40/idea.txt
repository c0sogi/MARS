Based on the comprehensive analysis of the "Lessons Learned" and the trajectory of previous experiments, I propose the **Relative-Velocity-Aligned Anchored-Mining Ensemble (RVA-AME)**.

This strategy introduces a **Structural Evolution** in Feature Engineering by implementing **Dynamic Relative-Velocity Basis Alignment**. It explicitly resolves the "Singularity Risk" of displacement-based projections (Cite solution_lesson_node_00063) and the "Scalar Collapse" of magnitude-based features (Cite solution_lesson_node_00043). By defining the coordinate system using the **Relative Velocity Vector** (which is maximal and stable at impact) rather than the Displacement Vector (which vanishes/flips at impact), we capture the precise geometry of "Head-on" vs. "Glancing" collisions without numerical instability. This is synthesized with the robust **Anchored Diversity Mining** pipeline (Cite solution_lesson_node_00059) and **Relaxed Quadratic Gating** (Cite solution_lesson_node_00039).

### 1. Model
The architecture employs a **Unified Heterogeneous Dual-Ensemble** designed to maximize algorithmic diversity and decision boundary resolution while ensuring runtime stability.

*   **Unified Backbone:** We utilize a single modeling framework for both Player-Player and Player-Ground contacts. We explicitly retain the **Sentinel Value Strategy** (Cite solution_lesson_node_00035), setting the `distance` feature for Ground interactions to `-1.0` (a distinct, non-physical value). This allows the tree-based models to isolate distinct modalities via root-level splits while leveraging the shared non-contact majority class for stability (Cite solution_lesson_node_00007).
*   **Dual-Model Expert Tier:** The final predictor consists of two distinct Gradient Boosting implementations:
    1.  **LightGBM:** Leaf-wise growth (Best for dense numerical data).
    2.  **XGBoost:** Level-wise growth (Best for approximate splits).
    *   *Rationale:* We explicitly exclude CatBoost to avoid the API/dependency failures observed in Lesson 00061, prioritizing the robustness of the proven LightGBM/XGBoost pair (Cite solution_lesson_node_00061).
*   **High-Capacity Configuration:** Both models are configured with deep trees (e.g., `num_leaves=256`, `max_depth=10`) to maximize information density (Cite solution_lesson_node_00003).

### 2. Data
The data pipeline implements **Relaxed Quadratic Gating** and **Relative-Velocity Aligned Feature Engineering** to capture high-fidelity interaction physics without singularities or information loss.

*   **Stage 0: Relaxed Quadratic Reachability Gating**
    *   **Logic:** Model relative distance as a quadratic function: $d(t) = d_0 + v_{rel}t + 0.5 a_{rel}t^2$. Solve for $\min(d(t))$ in the window.
    *   **Filter:** Keep pairs where $\min(d(t)) < 3.0$ yards.
    *   *Rationale:* This captures high-acceleration events (like dives) (Cite solution_lesson_node_00039) while retaining the "buffer zone" of near-misses required to define the decision boundary (Cite solution_lesson_node_00042).

*   **Stage 1: Relative-Velocity Aligned Feature Engineering (Structural Innovation)**
    *   **Dynamic Basis Definition:** For *each timestep* $t$ in the window ($t \in [-10, +10]$), calculate the instantaneous basis vectors:
        *   **Basis $\hat{u}_t$:** The unit vector of the **Relative Velocity** ($\vec{v}_{rel} = \vec{v}_1 - \vec{v}_2$).
        *   **Basis $\hat{u}_{t,\perp}$:** The vector orthogonal to $\hat{u}_t$.
        *   *Rationale:* Unlike the Displacement Vector ($\vec{r}$), which vanishes at contact (singularity), the Relative Velocity is typically maximal at impact, providing a **Stable Reference Frame** (Cite solution_lesson_node_00063). For Player-Ground, $\vec{v}_{rel} = \vec{v}_{p1}$, naturally aligning with the motion axis.
    *   **Geometric Projection:** Project the **Relative Position** ($\vec{r}$) and **Relative Acceleration** ($\vec{a}$) onto this basis.
        *   **$r_{long}$ (Longitudinal Distance):** $\vec{r} \cdot \hat{u}_t$. Measures distance along the motion path (Time-space to collision).
        *   **$r_{trans}$ (Transverse Distance):** $\vec{r} \cdot \hat{u}_{t,\perp}$. Measures "Miss Distance" (how far off-center the collision is).
        *   **$a_{long}$ (Impact Force):** $\vec{a} \cdot \hat{u}_t$.
        *   **$a_{trans}$ (Turning Force):** $\vec{a} \cdot \hat{u}_{t,\perp}$.
        *   *Rationale:* This explicitly distinguishes "Head-on" ($r_{trans} \approx 0$) from "Glancing" ($r_{trans} > 0$) interactions in a rotation-invariant manner (Cite solution_lesson_node_00024), fixing "Scalar Collapse" (Cite solution_lesson_node_00043).
    *   **Explicit Interaction Primitives:** Explicitly compute **Time-To-Collision (TTC)** ($r / v_{close}$), **Jerk**, and **Angular Jerk**.
        *   *Rationale:* Re-integrating TTC corrects the failure of Idea 39 (Cite solution_lesson_node_00065).
    *   **Explicit Time-Domain Lags:** Flatten these projected values into a wide row. This avoids the information loss of spectral abstractions (Cite solution_lesson_node_00054).

*   **Caching:** Enforce **parameter-aware caching** (Cite solution_lesson_node_00002).

### 3. Training
The training process executes a **Dual-Scout Anchored Mining Curriculum** using a strict **Binary Classification Objective**.

*   **Phase 1: Dual-Scout Training**
    *   Construct a balanced dataset from the **Relaxed Gated Survivors**.
    *   Train **Scout A (LGBM)** and **Scout B (XGB)** using the **Full Relative-Velocity Aligned Feature Set**.
    *   *Constraint:* Scouts must see the exact same features as the Expert to prevent "Semantic Gaps" (Cite solution_lesson_node_00022).

*   **Phase 2: Diversity Mining**
    *   Run Scouts on the **Entire Gated Survivor Pool**.
    *   Select **Hard Negatives**: Instances where $P(Contact) > 0.05$ from **either** Scout (Union) (Cite solution_lesson_node_00021).

*   **Phase 3: Anchored Expert Training**
    *   **Dataset Construction:** Create the Expert Dataset using three components:
        1.  **All Positives**.
        2.  **Mined Hard Negatives** (The Union).
        3.  **Random Easy Negatives (Anchors):** A random sample of the Gated Survivors maintained at a **1:1 Ratio** with Positives.
        *   *Rationale:* A 1:1 Anchor ratio prevents the model from overfitting to edge cases (Cite solution_lesson_node_00048) while ensuring the loss function isn't flooded by easy negatives (Cite solution_lesson_node_00059).
    *   **Objective:** Train using standard **Binary LogLoss**. We explicitly reject Temporal Label Smoothing to maintain precision for sharp contact events (Cite solution_lesson_node_00056).
    *   **Imbalance Handling:** Use internal rebalancing parameters (`is_unbalance`, `scale_pos_weight`) (Cite solution_lesson_node_00011).

### 4. Evaluation
1.  **Feature Generation:** Generate the **Full Relative-Velocity Aligned Feature Set** for the **Entire Test Set**.
2.  **Inference:** Run the **Dual-Model Expert Ensemble** on the test features.
3.  **Ensembling:** Compute the unweighted average of the probability outputs from the two models.
4.  **Thresholding:** Apply the decision threshold optimized on the validation set (maximizing MCC) to generate the final submission.
