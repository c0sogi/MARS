# Strategy: Tiered Cascade with Full-Scale Hard-Negative Mining

Based on the progression of lessons—specifically the critical need for **Hard-Negative Mining** (Cite solution_lesson_node_00019) and the observation that **Mining Efficacy Scales with Volume** (Cite solution_lesson_node_00021)—I propose a **Tiered Cascade Architecture**.

This solution introduces a structural innovation: **Tiered Feature Engineering**. Previously, the computational cost of generating complex windowed/contextual features (Cite solution_lesson_node_00012) limited the size of the dataset we could effectively mine. By decoupling feature complexity from data volume, we can scan 100% of the available training data (3.4 million rows) to isolate the most informative examples, maximizing **Information Density** (Cite solution_lesson_node_00011) while respecting the computational budget.

### 1. Model
The architecture consists of two distinct modeling stages, forming a **Unified Heterogeneous Cascade**:

*   **Stage 1: The Scout (Global Filter)**
    *   **Architecture:** A lightweight **LightGBM** model with shallow trees.
    *   **Role:** High-throughput filtration. It is designed to aggressively discard the "trivial negatives" (e.g., players 10 yards apart) that constitute ~98% of the dataset.
*   **Stage 2: The Expert (Precision Ensemble)**
    *   **Architecture:** A **Heterogeneous Ensemble** of high-capacity **LightGBM** and **XGBoost** models (Cite solution_lesson_node_00003).
    *   **Role:** Fine-grained decision making. It focuses exclusively on the "Hard Negatives" and Positives.
*   **Unified Design:** Both stages utilize a **Unified Architecture** (Cite solution_lesson_node_00007), predicting both Player-Player and Player-Ground contacts within a single model using an `is_ground` indicator. This preserves the stability provided by the shared non-contact class.

### 2. Data
The data pipeline implements the **Tiered Feature Engineering** paradigm to enable full-scale mining:

*   **Tier 1 Features (Global / Low-Cost):**
    *   Computed for the **Full Training Dataset (3.4M rows)**.
    *   Includes only instantaneous, computationally cheap metrics: **Distance**, **Speed**, **Acceleration**, and **is_ground**.
    *   *Purpose:* Sufficient to identify "proximity" or "high-g" events, allowing the Scout to filter out obvious non-contacts.
*   **Tier 2 Features (Local / High-Cost):**
    *   Computed **only for the Mined Subset** (Positives + Hard Negatives).
    *   Includes **Flattened Temporal Windows** (+/- 10 steps) (Cite solution_lesson_node_00001) to capture trajectory convergence.
    *   Includes **Physics Derivatives** (Jerk, Angular Jerk) and **Spatial Density** (Cite solution_lesson_node_00012) to resolve complex pile-ups and ground impacts.
    *   *Purpose:* Provides the deep context required for the Expert to distinguish "near misses" from actual contact.
*   **Caching:** Strict **parameter-aware caching** (Cite solution_lesson_node_00002) is enforced for both tiers to prevent re-computation.

### 3. Training
The training process executes a **Three-Phase Curriculum**:

1.  **Phase 1 (Scout Training):**
    *   Construct a balanced dataset using Tier 1 features (All Positives + Random Negatives).
    *   Train the **Scout Model** to maximize Recall (minimizing False Negatives is critical here).
2.  **Phase 2 (Full-Scale Mining):**
    *   Run Scout inference on the **Full Training Dataset (3.4M rows)** using Tier 1 features.
    *   Select **Hard Negatives**: Instances where $P(Contact) > 0.01$ (a low threshold to ensure no positives are lost). This effectively mines the entire dataset for edge cases (Cite solution_lesson_node_00021).
3.  **Phase 3 (Expert Training):**
    *   Generate Tier 2 features for the selected Hard Negatives and all Positives.
    *   Train the **Expert Ensemble** (LGBM + XGB) on this high-density dataset.
    *   Use internal rebalancing (`is_unbalance=True` / `scale_pos_weight`) to handle the remaining difficulty-based imbalance (Cite solution_lesson_node_00011).

### 4. Evaluation
1.  **Feature Generation:** Generate **Tier 2 Features** for the Test Set. (Since the test set is relatively small, we can afford the full feature computation without filtering).
2.  **Inference:** Run the **Expert Ensemble** on the test data.
3.  **Ensembling:** Average the probability outputs from the LightGBM and XGBoost models.
4.  **Thresholding:** Apply the decision threshold optimized on the validation set (maximizing MCC) to generate the final submission.
