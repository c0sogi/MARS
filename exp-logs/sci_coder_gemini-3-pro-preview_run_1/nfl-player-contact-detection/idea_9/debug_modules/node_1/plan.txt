The error arises because the `DataFactory` class (and other classes like `MiningTrainer` and `LGBMWrapper`) imports configuration variables (like `TRAIN_METADATA_PATH` and `WORKING_DIR`) directly from `library.config` at the module level. In Python, these imports bind the values at the time of import. When `runfile.py` later patches `library.config` with new paths for the demo environment, the `DataFactory` module retains the old, original values it imported earlier. Consequently, the trainer attempts to load the full dataset instead of the mini-dataset, triggering the assertion failure.

To fix this, we must modify the modules to import the `library.config` module itself rather than specific variables, and access the configuration attributes dynamically (e.g., `config.TRAIN_METADATA_PATH`) at runtime. This ensures that any updates made to the `config` object are reflected immediately. We will apply this fix to `library/data_factory.py` (the source of the assertion error), as well as `library/trainer.py` and `library/model_zoo.py`, which also rely on the patched `WORKING_DIR` to pass subsequent assertions in the demo script. Cite debug_lesson_8.
