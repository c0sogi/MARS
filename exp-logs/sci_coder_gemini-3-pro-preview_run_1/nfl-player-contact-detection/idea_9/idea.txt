Based on the analysis of the previous experiments and the extracted lessons, I propose the **Geometrically-Gated Full-Context Mining Ensemble (GGFC-ME)**.

This strategy introduces a **Structural Evolution** by decoupling the *Candidate Generation* phase from the *Feature Engineering* phase. It resolves the conflict between the need for **Full-Scale Mining** (Cite solution_lesson_node_00021) and the computational cost of **Contextual Feature Engineering** (Cite solution_lesson_node_00012). By applying a strict but computationally cheap geometric sieve, we can afford to generate high-fidelity contextual features for the entire "plausible" search space, preventing the "Semantic Gap" failure of the previous Tiered Cascade (Cite solution_lesson_node_00022).

### 1. Model
The architecture employs a **Unified Heterogeneous Ensemble** designed for high-capacity decision making.

*   **Unified Backbone:** We utilize a single modeling framework for both Player-Player and Player-Ground contacts, using an `is_ground` categorical feature. This leverages the stability of the shared non-contact majority class (Cite solution_lesson_node_00007).
*   **Heterogeneous Ensemble:** The final predictor consists of two distinct Gradient Boosting models: **LightGBM** (Leaf-wise growth) and **XGBoost** (Level-wise growth).
*   **High-Capacity Configuration:** Both models will be configured with deep trees (e.g., `num_leaves=256`, `max_depth=10`) to maximize information density and prevent early convergence (Cite solution_lesson_node_00003).

### 2. Data
The data pipeline implements a **Geometrically-Gated Feature Engineering** paradigm.

*   **Stage 0: Geometric Gating (The Sieve)**
    *   **Input:** The full training dataset (~3.4 million rows).
    *   **Logic:** We compute only computationally cheap, instantaneous invariants: **Euclidean Distance** (for pairs) and **Entity Type**.
    *   **Filter:**
        *   **Player-Player:** Keep row if `Distance < 3.0` yards. (Discards ~90% of trivial non-contacts).
        *   **Player-Ground:** Keep **ALL** rows. (Ground contact physics are subtle and cannot be safely filtered by simple position).
    *   *Rationale:* This step eliminates the vast majority of the dataset where contact is physically impossible, reducing the volume for the expensive next stage without discarding any "Hard Negatives" (which, by definition, are near-misses).

*   **Stage 1: Full-Context Feature Generation**
    *   **Input:** The survivor dataset from Stage 0 (~400k - 600k rows).
    *   **Features:** We generate the full suite of high-fidelity features for these rows:
        *   **Flattened Temporal Windows:** +/- 10 steps (1.0s) of relative position, speed, and acceleration (Cite solution_lesson_node_00001).
        *   **Physics Derivatives:** **Jerk** and **Angular Jerk** to capture impact impulses (Cite solution_lesson_node_00012).
        *   **Spatial Context:** **Local Density** (neighbor counts) and **Cluster Kinematics** (avg speed of neighbors) (Cite solution_lesson_node_00023).
        *   **Invariance:** Strictly exclude absolute coordinates (Cite solution_lesson_node_00024).
    *   *Rationale:* By running this only on the gated subset, we ensure the Scout and Expert models see the **exact same high-quality features** (Cite solution_lesson_node_00022), fixing the failure of Idea 7.

*   **Caching:** Strict parameter-aware caching is enforced (Cite solution_lesson_node_00002).

### 3. Training
The training procedure executes a **High-Fidelity Mining Curriculum**:

1.  **Phase 1 (Scout Training):**
    *   Construct a balanced dataset from the **Gated Survivors** (All Positives + Equal Random Negatives).
    *   Train a **Scout LightGBM** on this set.
    *   *Objective:* Learn a coarse decision boundary on the plausible subset.
2.  **Phase 2 (Focused Mining):**
    *   Run Scout inference on the **Entire Gated Survivor Pool**.
    *   Select **Hard Negatives**: Instances where $P(Contact) > 0.05$ but Ground Truth is 0.
    *   *Rationale:* This effectively mines the "hardest" examples from the entire season (Cite solution_lesson_node_00021) because the Geometric Gate has already removed the "easy" ones.
3.  **Phase 3 (Expert Training):**
    *   Construct the **Expert Dataset**: All Positives + All Mined Hard Negatives + Small Buffer of Random Gated Negatives.
    *   Train the **Expert Ensemble** (LGBM + XGB) on this high-information-density dataset.
    *   **Imbalance Handling:** Use `is_unbalance=True` (LGBM) and `scale_pos_weight` (XGB) to manage the remaining difficulty-based imbalance (Cite solution_lesson_node_00011).

### 4. Evaluation
1.  **Feature Generation:** Generate **Full-Context Features** for the **Entire Test Set**.
    *   *Note:* We do *not* apply the Geometric Gate during inference. The test set size (~460k rows) is small enough to process fully, ensuring no potential edge-case contacts are missed due to gating thresholds.
2.  **Inference:** Run the **Expert Ensemble** on the test features.
3.  **Ensembling:** Compute the unweighted average of the probability outputs from LightGBM and XGBoost.
4.  **Thresholding:** Apply the decision threshold optimized on the validation set (maximizing MCC) to generate the final binary submission.
