# Strategy: Dual-Scout Physics-Enhanced Mining Ensemble (DSP-EME)

Based on the comprehensive analysis of the previous experiments and lessons learned, I propose the **Dual-Scout Physics-Enhanced Mining Ensemble (DSP-EME)**.

This strategy introduces a **Structural Evolution** in the *Hard-Negative Mining* pipeline. While Idea 9 successfully utilized a "Scout" model to filter the dataset, it relied on a single LightGBM model trained on a balanced subsample. This creates a potential "Model Bias Gap" where the Expert model is starved of edge cases that the single Scout failed to identify (false negatives at the filtering stage).

By deploying a **Heterogeneous Scout Tier** (LightGBM + XGBoost) and explicitly engineering **Primary Interaction Physics** (Time-to-Collision, Kinetic Energy) while strictly limiting environmental noise (Cite solution_lesson_node_00036), we maximize the recall of the mining phase and the precision of the expert phase.

### 1. Model
The architecture employs a **Unified Heterogeneous Ensemble** within a **Two-Stage Cascade**.

*   **Unified Backbone:** We utilize a single modeling framework for both Player-Player and Player-Ground contacts, utilizing an `is_ground` categorical feature and **Sentinel Values** (Cite solution_lesson_node_00035) to leverage the shared non-contact majority class (Cite solution_lesson_node_00007).
*   **Stage 1: Heterogeneous Scout Tier (Innovation):**
    *   Instead of a single Scout, we train **Two Distinct Scouts**: one **LightGBM** and one **XGBoost**.
    *   **Role:** Each Scout scans the gated dataset to identify "Hard Negatives". We take the **Union** of their findings. This diversity ensures that edge cases missed by the leaf-wise growth of LightGBM might be caught by the level-wise growth of XGBoost, maximizing the "Mining Efficacy" (Cite solution_lesson_node_00021).
*   **Stage 2: The Expert Ensemble:**
    *   **Architecture:** A high-capacity **Heterogeneous Ensemble** (LightGBM + XGBoost).
    *   **Configuration:** Deep trees (`num_leaves=256`, `max_depth=10`) to maximize information density (Cite solution_lesson_node_00003).

### 2. Data
The data pipeline implements **Geometric Gating** and **Physics-Enhanced Feature Engineering**.

*   **Stage 0: Geometric Gating (The Sieve)**
    *   **Filter:** For the full training set (~3.4M rows), calculate instantaneous Euclidean distance.
    *   **Logic:** Discard Player-Player pairs with `Distance > 3.0` yards. Keep **ALL** Player-Ground pairs.
    *   *Rationale:* Eliminates trivial non-contacts (Cite solution_lesson_node_00026) to focus compute on the decision boundary.

*   **Stage 1: Physics-Enhanced Feature Engineering (Innovation)**
    *   **Flattened Windows:** Retain +/- 10 step (1.0s) windows for relative position, speed, and acceleration (Cite solution_lesson_node_00001).
    *   **Physics Derivatives:** Retain **Jerk** and **Angular Jerk** for ground impact detection (Cite solution_lesson_node_00012).
    *   **Primary Interaction Physics (New):** Explicitly compute non-linear interaction terms for the **Primary Pair Only** (Cite solution_lesson_node_00036):
        *   **Time-to-Collision (TTC):** `Distance / Closing_Speed`. (Handles non-linearity that trees struggle to approximate).
        *   **Kinetic Energy Proxy:** `Relative_Speed^2`.
        *   *Note:* Use **Sentinel Values** (e.g., -1.0) for these features when `is_ground=True` or when diverging (Cite solution_lesson_node_00035).
    *   **Minimal Context:** Retain simple **Spatial Density** (neighbor count) but **strictly exclude** complex 3rd-party kinematics (e.g., neighbor speeds) to avoid diluting the primary signal (Cite solution_lesson_node_00036).
    *   **Invariance:** Strictly exclude absolute coordinates (Cite solution_lesson_node_00024).

*   **Caching:** Enforce **parameter-aware caching** (Cite solution_lesson_node_00002).

### 3. Training
The training process executes a **Dual-Path Mining Curriculum**:

1.  **Phase 1 (Scout Training):**
    *   Construct a balanced dataset from the **Gated Survivors** (All Positives + Equal Random Negatives).
    *   Train **Scout A (LightGBM)** and **Scout B (XGBoost)** on this set using the **Full Feature Set** (preventing Semantic Gap, Cite solution_lesson_node_00022).
2.  **Phase 2 (Diversity Mining):**
    *   Run *both* Scouts on the **Entire Gated Survivor Pool** (~600k rows).
    *   Select **Hard Negatives**: Instances where $P(Contact) > 0.05$ from *either* Scout (Union).
    *   *Rationale:* This maximizes the capture of "near-misses" and confusing patterns.
3.  **Phase 3 (Expert Training):**
    *   Construct the **Expert Dataset**: All Positives + The Union of Mined Hard Negatives + Small Buffer of Random Gated Negatives.
    *   Train the **Expert Ensemble** (LGBM + XGB) on this high-information-density dataset.
    *   **Imbalance Handling:** Use `is_unbalance=True` (LGBM) and `scale_pos_weight` (XGB) (Cite solution_lesson_node_00011).

### 4. Evaluation
1.  **Feature Generation:** Generate the **Full Feature Set** for the **Entire Test Set**.
2.  **Inference:** Run the **Expert Ensemble** on the test features.
3.  **Ensembling:** Compute the unweighted average of the probability outputs.
4.  **Thresholding:** Apply the decision threshold optimized on the validation set (maximizing MCC) to generate the final submission.
