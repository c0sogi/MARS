Based on the comprehensive analysis of the "Lessons Learned" and the trajectory of previous experiments, I propose the **Vector-Aligned Soft-Mining Ensemble (VASM-E)**.

This strategy introduces a **Structural Evolution** in both Feature Engineering and Training Objectives. It synthesizes the robust **Anchored Mining** pipeline of the Current Best Solution (Idea 17) with a physically disentangled **Collision-Aligned Representation** (addressing the "Scalar Collapse" of Idea 20) and **Temporal Label Smoothing** (addressing the dataset's inherent label noise).

### 1. Model
The architecture employs a **Unified Heterogeneous Tri-Ensemble** designed to maximize algorithmic diversity and decision boundary resolution.

*   **Unified Backbone:** We utilize a single modeling framework for both Player-Player and Player-Ground contacts. We explicitly retain the **Sentinel Value Strategy** (Cite solution_lesson_node_00035), setting the `distance` feature for Ground interactions to `-1.0` (a distinct, non-physical value). This allows the tree-based models to isolate distinct modalities via root-level splits while leveraging the shared non-contact majority class for stability (Cite solution_lesson_node_00007).
*   **Tri-Model Expert Tier:** The final predictor consists of three distinct Gradient Boosting implementations:
    1.  **LightGBM:** Leaf-wise growth (Best for dense numerical data).
    2.  **XGBoost:** Level-wise growth (Best for approximate splits).
    3.  **CatBoost:** Symmetric/Oblivious trees (Best for reducing overfitting on noisy data).
    *   *Rationale:* Adding CatBoost introduces a third structural bias, maximizing the ensemble's ability to resolve the "Hard Negatives" mined by the Scouts (Cite solution_lesson_node_00039).
*   **High-Capacity Configuration:** All models are configured with deep trees (e.g., `num_leaves=256`, `max_depth=10`) to maximize information density (Cite solution_lesson_node_00003).

### 2. Data
The data pipeline implements **Relaxed Kinematic Gating** and **Collision-Aligned Feature Engineering** to capture impact physics without losing directional context or support vectors.

*   **Stage 0: Relaxed Kinematic Reachability Gating**
    *   **Logic:** Instead of static distance, we compute the **Projected Minimum Distance** using a quadratic motion model ($d(t) = d_0 + v_{rel}t + 0.5 a_{rel}t^2$).
    *   **Filter:** Retain pairs where $\min(d(t)) < 3.0$ yards.
    *   *Rationale:* This captures high-velocity "diving" impacts (Cite solution_lesson_node_00039) while maintaining a sufficient "buffer zone" of near-misses to define the decision boundary, preventing the Support Vector Fallacy (Cite solution_lesson_node_00042).

*   **Stage 1: Collision-Aligned Vector Feature Engineering (Structural Innovation)**
    *   **Basis Transformation:** For every timestep, define the **Collision Axis** ($\hat{u}_r$, unit vector pointing from Player 2 to Player 1) and the **Tangent Axis** ($\hat{u}_t$, orthogonal to $\hat{u}_r$).
    *   **Vector Decomposition:** Project all relative velocity and acceleration vectors onto these axes.
        *   **Radial Components:** $v_r$ (Closing Speed), $a_r$ (Impact Force).
        *   **Tangential Components:** $v_t$ (Sliding/Shearing Speed), $a_t$ (Turning Force).
        *   *Rationale:* This explicitly disentangles "Impact" (Radial) from "Jockeying" (Tangential). Unlike raw $x/y$ coordinates (Idea 17), this is rotation invariant (Cite solution_lesson_node_00024). Unlike scalar magnitudes (Idea 20), this preserves the geometry of the collision (Cite solution_lesson_node_00043).
    *   **Radial Shock:** Compute the **Jerk** and **High-Frequency Energy** specifically on the **Radial Acceleration** component. This isolates the physical signal of a hard stop/impact (Cite solution_lesson_node_00012).
    *   **Context Exclusion:** Strictly exclude 3rd-party context to prevent signal dilution (Cite solution_lesson_node_00036).

*   **Caching:** Enforce **parameter-aware caching** (Cite solution_lesson_node_00002).

### 3. Training
The training process executes a **Tri-Scout Anchored Mining Curriculum** with **Temporal Label Smoothing**.

*   **Phase 1: Tri-Scout Training**
    *   Construct a balanced dataset from the **Relaxed Gated Survivors**.
    *   Train **Scout A (LGBM)**, **Scout B (XGB)**, and **Scout C (CatBoost)** on this set using the **Full Feature Set**.
    *   *Constraint:* Scouts must see the exact same features as the Expert to prevent "Semantic Gaps" (Cite solution_lesson_node_00022).

*   **Phase 2: Diversity Mining**
    *   Run Scouts on the **Entire Gated Survivor Pool**.
    *   Select **Hard Negatives**: Instances where $P(Contact) > 0.05$ from **any** Scout (Union) (Cite solution_lesson_node_00021).

*   **Phase 3: Anchored Expert Training with Soft Targets (Structural Innovation)**
    *   **Dataset Construction:** Create the Expert Dataset using three components:
        1.  **All Positives**.
        2.  **Mined Hard Negatives** (The Union).
        3.  **Random Easy Negatives (Anchors):** A random sample of the Gated Survivors that were *not* mined as hard negatives.
        *   *Rationale:* The random anchors preserve the global decision boundary, preventing the model from overfitting exclusively to the edge cases (Cite solution_lesson_node_00048).
    *   **Temporal Label Smoothing:** Instead of binary targets $\{0, 1\}$, apply **Gaussian Smoothing** ($\sigma=1$ step) to the contact labels over the temporal window.
        *   *Rationale:* The dataset description notes labels are "within +/- 10Hz". Soft targets encourage the model to learn the *approach dynamics* rather than being penalized for slight temporal misalignments, effectively making the loss function differentiable with respect to temporal uncertainty.
    *   **Training:** Train the **Tri-Model Expert Ensemble** on this Anchored Dataset.

### 4. Evaluation
1.  **Feature Generation:** Generate the **Full Collision-Aligned Feature Set** for the **Entire Test Set**.
2.  **Inference:** Run the **Tri-Model Expert Ensemble** on the test features.
3.  **Ensembling:** Compute the unweighted average of the probability outputs from the three models.
4.  **Thresholding:** Apply the decision threshold optimized on the validation set (maximizing MCC) to generate the final submission.
