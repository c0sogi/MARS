Based on the comprehensive analysis of the "Lessons Learned" and the performance of "Previous Ideas," I propose the **Invariant Extremum-Context Mining Ensemble (IEC-ME)**.

This strategy introduces a **Structural Evolution** in the *Contextual Feature Engineering* paradigm. While Idea 9 (the current best) successfully utilized "Geometric Gating" and "Hard-Negative Mining," it relied on "Cluster Averages" (e.g., mean speed of neighbors) to model the environment. This averaging operation washes out critical signals—such as a single third-party player crashing into the pair at high speed while others are static.

By shifting from *Average-Based Context* to **Extremum-Based Context** (e.g., Max Closing Speed, Min Third-Party Distance), we capture the physics of "worst-case" local interactions (e.g., blindsides, pile-ups) using **Continuous Invariant Scalars** (Cite solution_lesson_node_00031), avoiding the discretization noise of grids (Idea 12) and the sentinel hazards of imputation (Idea 14).

### 1. Model
The architecture employs a **Unified Heterogeneous Ensemble** designed for maximum capacity and topological stability.

*   **Unified Backbone:** We utilize a single modeling framework for both Player-Player and Player-Ground contacts. We explicitly use a **Sentinel Value Strategy** (Cite solution_lesson_node_00035), setting the `distance` feature for Ground interactions to `-1.0` (a distinct, non-physical value) rather than `0.0`. This allows the tree-based models to isolate Ground interactions into separate branches via a root-level split, preserving the stability of the shared non-contact majority class (Cite solution_lesson_node_00007).
*   **Heterogeneous Components:** The predictor consists of two distinct Gradient Boosting models: **LightGBM** (Leaf-wise) and **XGBoost** (Level-wise).
*   **High-Capacity Configuration:** Both models will be configured with deep trees (e.g., `num_leaves=256`, `max_depth=10`) to maximize information density (Cite solution_lesson_node_00003).

### 2. Data
The data pipeline implements **Geometric Gating** to enable the computation of the new **Extremum Context Features** for the entire candidate pool without semantic gaps.

*   **Stage 0: Geometric Gating (The Sieve)**
    *   **Filter:** For the full training set (~3.4M rows), calculate instantaneous Euclidean distance.
    *   **Logic:** Discard Player-Player pairs with `Distance > 3.0` yards. Keep **ALL** Player-Ground pairs.
    *   *Rationale:* This eliminates trivial non-contacts (Cite solution_lesson_node_00026), reducing the dataset to ~600k rows while preserving all potential "Hard Negatives".

*   **Stage 1: Invariant Extremum-Context Feature Engineering (Innovation)**
    *   **Target Pair Kinematics:** Retain **Flattened Temporal Windows** (+/- 10 steps) and **Physics Derivatives** (Jerk) for the primary pair (Cite solution_lesson_node_00001, solution_lesson_node_00012).
    *   **Extremum Context Aggregates:**
        *   For the target pair, identify all *other* players (neighbors) within a 2-yard radius.
        *   Compute relative kinematics for each neighbor with respect to the target pair.
        *   **Aggregate via Extremums:** Instead of just means, compute:
            *   `min_dist_3rd_party`: Distance to the closest *third* player (Is someone else interfering?).
            *   `max_closing_speed_3rd_party`: The highest closing speed of any neighbor (Is someone crashing in?).
            *   `max_acceleration_3rd_party`: The highest acceleration magnitude in the cluster.
        *   *Rationale:* These features explicitly capture the **most dangerous element** in the local crowd, providing a stronger predictive signal than averages (Cite solution_lesson_node_00023) while maintaining strict **Translation Invariance** (Cite solution_lesson_node_00024) and avoiding discretization (Cite solution_lesson_node_00031).

*   **Caching:** Enforce **parameter-aware caching** to prevent implicit hazards (Cite solution_lesson_node_00002).

### 3. Training
The training process executes a **Full-Fidelity Mining Curriculum** to ensure the model learns from the hardest examples.

*   **Phase 1: Scout Training**
    *   Construct a balanced dataset from the **Gated Survivors** (All Positives + Equal Random Negatives).
    *   Train a **Scout LightGBM** using the **Full Feature Set** (Extremums + Windows).
    *   *Constraint:* The Scout must see the exact same high-fidelity features as the Expert to prevent the "Semantic Gap" failure (Cite solution_lesson_node_00022).

*   **Phase 2: Full-Scale Mining**
    *   Run Scout inference on the **Entire Gated Survivor Pool** (~600k rows).
    *   Select **Hard Negatives**: Instances where $P(Contact) > 0.05$ but Ground Truth is 0.
    *   *Rationale:* This leverages the scale-dependent efficacy of mining (Cite solution_lesson_node_00021) to find the most confusing edge cases.

*   **Phase 3: Expert Training**
    *   Construct the **Expert Dataset**: All Positives + All Mined Hard Negatives + Small Buffer of Random Gated Negatives.
    *   Train the **Expert Ensemble** (LGBM + XGB) on this high-information-density dataset.
    *   **Imbalance Handling:** Use `is_unbalance=True` (LGBM) and `scale_pos_weight` (XGB) to manage the remaining difficulty-based imbalance (Cite solution_lesson_node_00011).

### 4. Evaluation
1.  **Feature Generation:** Generate the **Full Feature Set** (Extremums + Windows) for the **Entire Test Set**. (Test set size allows full computation without gating).
2.  **Inference:** Run the **Expert Ensemble** on the test features.
3.  **Ensembling:** Compute the unweighted average of the probability outputs.
4.  **Thresholding:** Apply the decision threshold optimized on the validation set (maximizing MCC) to generate the final submission.
