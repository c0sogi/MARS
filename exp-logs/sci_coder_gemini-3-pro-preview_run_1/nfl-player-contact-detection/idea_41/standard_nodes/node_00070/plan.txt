### Implementation Strategy

1.  **Orchestration & Sampling**: Instead of using the pre-packaged `TrainingLoop` which processes the full dataset, we will manually orchestrate the pipeline within `runfile.py`. This allows us to inject a `sample_size` limit (e.g., 100,000 rows) into the `DataProcessor` for the training set to satisfy the "Fast Baseline" requirement and time constraints.
2.  **Data & Feature Engineering**: We will use `DataProcessor` to load sampled training data and the **full** validation data (as required for proper metric calculation). `FeatureEngineer` will be used to generate the kinematically-aligned features for both sets.
3.  **Mining & Training**: We will instantiate `MiningStrategy` to train "Scout" models on the sampled data, mine hard negatives, and construct the "Expert" dataset. We will then train `LGBMExpert` and `XGBExpert` models. To ensure speed, we will override the default configuration to reduce `n_estimators` to 500.
4.  **Validation & Metrics**: We will generate predictions on the full validation set, compute the ensemble average, and optimize the decision threshold. The final Matthews Correlation Coefficient (MCC) will be printed in the required format: `Final Validation Metric: <value>`.
5.  **Failure Analysis**: We will calculate the absolute error between predictions and ground truth, then compute the Pearson correlation between this error and each feature to identify sources of model failure.
6.  **Conditional Inference**: If the validation MCC exceeds 0.6865, we will initialize the `InferencePipeline` to generate predictions for the test set and save the `submission.csv`.
