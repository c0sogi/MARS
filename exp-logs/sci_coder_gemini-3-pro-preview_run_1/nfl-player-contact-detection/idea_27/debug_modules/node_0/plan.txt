### Implementation Strategy

1.  **Configuration Override**: To ensure the script runs quickly (under 1 hour) and uses the writable `./working` directory, I will monkey-patch the `Config` class. I will reduce the number of estimators/epochs for all models (LightGBM, XGBoost, CatBoost) to minimal values (e.g., 10) and redirect file paths to a temporary demo directory.
2.  **Mini-Dataset Creation**:
    *   Since the original datasets are large, I will create smaller subsets ("mini-batches") of the metadata and tracking data.
    *   I will select a small number of unique `game_play` identifiers from the training set to ensure consistency between metadata and tracking data.
    *   I will filter the original CSVs (Metadata and Tracking) to include only data relevant to these selected plays and save them to the `./working` directory.
    *   I will verify that the mini-datasets contain both positive and negative target classes to prevent training errors.
3.  **Pipeline Execution**:
    *   **Training**: I will instantiate the `TrainingPipeline` and execute the `run()` method. This will trigger feature engineering, scout training, hard negative mining, expert training, and threshold optimization.
    *   **Inference**: I will instantiate the `InferencePipeline` and execute `predict_test_set()`. This will generate predictions on the mini-test set using the trained models.
4.  **Verification**: Throughout the process, I will use assertions to verify:
    *   Intermediate files (Parquet features, NPY indices) are created.
    *   Models are successfully saved to disk.
    *   The final submission file exists and follows the correct format.
