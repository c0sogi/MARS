The implementation strategy follows the **Vector-Decomposed Spectral Mining Ensemble** architecture described in the Idea.

1.  **Configuration & Setup**: We override the default hyperparameter configuration in `library.config` to reduce the number of estimators (from 3000 to 800) for the LightGBM and XGBoost models. This ensures the "Fast Baseline" requirement is met within the runtime constraints while retaining the high-capacity tree depth.
2.  **Pipeline Orchestration**: We instantiate the `Trainer` class from the provided library. The `run_pipeline` method is executed to:
    *   Load and cache features (using `DataFactory` and `FeatureEngineer`).
    *   Train the "Scout" models on balanced data.
    *   Mine "Hard Negatives" (instances where Scouts falsely predict contact).
    *   Train the "Expert" ensemble on the enriched dataset (Positives + Hard Negatives).
    *   Optimize the decision threshold on the validation set.
3.  **Validation & Failure Analysis**:
    *   We reload the full validation set and perform inference using the trained ensemble.
    *   The Matthews Correlation Coefficient (MCC) is computed and printed as the `Final Validation Metric`.
    *   We calculate the absolute error residuals (`|y_true - y_prob|`) and compute their Pearson correlation with all input features. This identifies which physical properties (e.g., `distance`, `closing_speed`) are most associated with model failure.
4.  **Submission**:
    *   A conditional check is performed against the threshold `0.6865`.
    *   If passed, the test set features are loaded, predictions are generated, and the results are merged with the `sample_submission.csv` template to ensure strict format compliance before saving to `./submission/submission.csv`.
