Based on the analysis of the "Lessons Learned" and the trajectory of previous experiments, I propose the **Vector-Decomposed Spectral Mining Ensemble (VDS-ME)**.

This strategy introduces a **Structural Evolution** in Feature Engineering to resolve the conflict between *Advanced Physics Modeling* (Idea 20) and *Geometric Integrity* (Idea 17). It explicitly corrects the "Scalar Collapse" failure (Cite solution_lesson_node_00043) by decomposing kinematic windows into **Directional Spectral Components** rather than magnitudes. This is integrated into a **Tri-Model Diversity Mining** pipeline to maximize the capture of hard negatives.

### 1. Model
The architecture employs a **Unified Heterogeneous Tri-Ensemble** designed to maximize algorithmic diversity and decision boundary resolution.

*   **Unified Backbone:** We utilize a single modeling framework for both Player-Player and Player-Ground contacts. We explicitly retain the **Sentinel Value Strategy** (Cite solution_lesson_node_00035), setting the `distance` feature for Ground interactions to `-1.0`. This allows the tree-based models to isolate distinct modalities via root-level splits while leveraging the shared non-contact majority class for stability (Cite solution_lesson_node_00007).
*   **Tri-Model Expert Tier:** The final predictor consists of three distinct Gradient Boosting implementations:
    1.  **LightGBM:** Leaf-wise growth (Best for dense numerical data).
    2.  **XGBoost:** Level-wise growth (Best for approximate splits).
    3.  **CatBoost:** Symmetric trees (Best for reducing overfitting on noisy data).
    *   *Rationale:* Adding CatBoost introduces a third structural bias (oblivious trees), maximizing the ensemble's ability to resolve the "Hard Negatives" mined by the Scouts (Cite solution_lesson_node_00039).
*   **High-Capacity Configuration:** All models are configured with deep trees (e.g., `num_leaves=256`, `max_depth=10`) to maximize information density (Cite solution_lesson_node_00003).

### 2. Data
The data pipeline implements **Relaxed Quadratic Gating** and **Vector-Decomposed Spectral Feature Engineering** to capture impact physics without losing directional context.

*   **Stage 0: Relaxed Quadratic Reachability Gating**
    *   **Logic:** Model relative distance as a quadratic function: $d(t) = d_0 + v_{rel}t + 0.5 a_{rel}t^2$. Solve for $\min(d(t))$ in the window.
    *   **Filter:** Keep pairs where $\min(d(t)) < 3.0$ yards.
    *   *Rationale:* This captures high-acceleration events (like dives) (Cite solution_lesson_node_00039) while retaining the "buffer zone" of near-misses required to define the decision boundary (Cite solution_lesson_node_00042).

*   **Stage 1: Vector-Decomposed Spectral Feature Engineering (Innovation)**
    *   **Raw Kinematic Components:** Retain flattened windows of **raw relative vector components** ($rv_x, rv_y, ra_x, ra_y$) to allow the models to learn interaction geometry (Cite solution_lesson_node_00043).
    *   **Directional Spectral Energy:** Instead of scalar magnitude energy (which failed in Idea 20), we decompose the acceleration window into two orthogonal components relative to the **Collision Axis** (vector connecting the pair):
        1.  **Radial Acceleration:** Along the connecting vector (Impact/Compression forces).
        2.  **Tangential Acceleration:** Perpendicular to the connecting vector (Shear/Glancing forces).
    *   **Spectral Processing:** Apply a high-pass filter to these component windows and compute the **RMS Energy**.
        *   *Rationale:* This explicitly quantifies "Impact Shock" (High-Freq Radial) vs. "Jockeying/Shuffling" (High-Freq Tangential) without collapsing the directional signal, fixing the flaw of Idea 20 (Cite solution_lesson_node_00043) while capturing the impulse physics of Idea 19 (Cite solution_lesson_node_00012).
    *   **Primary Physics Primitives:** Retain **Time-To-Collision** and **Closing Speed** (Cite solution_lesson_node_00036).
    *   **Context Exclusion:** Strictly exclude 3rd-party context (Cite solution_lesson_node_00036) and absolute coordinates (Cite solution_lesson_node_00024).

*   **Caching:** Enforce **parameter-aware caching** (Cite solution_lesson_node_00002).

### 3. Training
The training process executes a **Tri-Scout Diversity Mining Curriculum**.

*   **Phase 1: Tri-Scout Training**
    *   Construct a balanced dataset from the **Relaxed Gated Survivors** (All Positives + Equal Random Negatives).
    *   Train **Scout A (LGBM)**, **Scout B (XGB)**, and **Scout C (CatBoost)** on this set using the **Full Feature Set**.
    *   *Constraint:* Scouts must see the exact same features as the Expert to prevent "Semantic Gaps" (Cite solution_lesson_node_00022).

*   **Phase 2: Diversity Mining**
    *   Run *all three* Scouts on the **Entire Gated Survivor Pool**.
    *   Select **Hard Negatives**: Instances where $P(Contact) > 0.05$ from **any** Scout (Union).
    *   *Rationale:* Mining the union of errors from three distinct architectures maximizes the capture of edge cases and reduces "Model Bias Gap" (Cite solution_lesson_node_00021).

*   **Phase 3: Expert Training**
    *   Construct the **Expert Dataset**: All Positives + The Union of Mined Hard Negatives + Small Buffer of Random Gated Negatives.
    *   Train the **Tri-Model Expert Ensemble** on this high-information-density dataset.
    *   **Imbalance Handling:** Use internal rebalancing parameters (`is_unbalance`, `scale_pos_weight`, `auto_class_weights`) (Cite solution_lesson_node_00011).

### 4. Evaluation
1.  **Feature Generation:** Generate the **Full Vector-Decomposed Feature Set** for the **Entire Test Set**.
2.  **Inference:** Run the **Tri-Model Expert Ensemble** on the test features.
3.  **Ensembling:** Compute the unweighted average of the probability outputs from the three models.
4.  **Thresholding:** Apply the decision threshold optimized on the validation set (maximizing MCC) to generate the final submission.
