Based on the comprehensive analysis of the "Lessons Learned" and the trajectory of previous experiments, I propose the **Vector-Decomposed Physics Ensemble with Temporal Label Smoothing (VDP-TLS)**.

This strategy introduces a **Structural Evolution** in both the *Feature Engineering* and *Training* paradigms. It explicitly resolves the "Scalar Collapse" failure (Cite solution_lesson_node_00043) by enforcing **Vector Decomposition** for all kinematic features, and it addresses the documented label noise (+/- 10Hz) by implementing **Temporal Label Smoothing** within the Hard-Negative Mining pipeline.

### 1. Model
The architecture employs a **Unified Heterogeneous Tri-Ensemble** designed to maximize algorithmic diversity and decision boundary resolution.

*   **Unified Backbone:** We utilize a single modeling framework for both Player-Player and Player-Ground contacts. We explicitly retain the **Sentinel Value Strategy** (Cite solution_lesson_node_00035), setting the `distance` feature for Ground interactions to `-1.0` (a distinct, non-physical value). This allows the tree-based models to isolate distinct modalities via root-level splits while leveraging the shared non-contact majority class for stability (Cite solution_lesson_node_00007).
*   **Tri-Model Expert Tier:** The final predictor consists of three distinct Gradient Boosting implementations:
    1.  **LightGBM:** Leaf-wise growth (Best for dense numerical data).
    2.  **XGBoost:** Level-wise growth (Best for approximate splits).
    3.  **CatBoost:** Symmetric/Oblivious trees (Best for reducing overfitting on noisy data).
    *   *Rationale:* Adding CatBoost introduces a third structural bias, maximizing the ensemble's ability to resolve the "Hard Negatives" mined by the Scouts (Cite solution_lesson_node_00039).
*   **High-Capacity Configuration:** All models are configured with deep trees (e.g., `num_leaves=256`, `max_depth=10`) to maximize information density (Cite solution_lesson_node_00003).

### 2. Data
The data pipeline implements **Relaxed Quadratic Gating** and **Vector-Decomposed Kinematic Feature Engineering** to capture impact physics without losing directional context.

*   **Stage 0: Relaxed Quadratic Reachability Gating**
    *   **Logic:** Model relative distance as a quadratic function: $d(t) = d_0 + v_{rel}t + 0.5 a_{rel}t^2$. Solve for $\min(d(t))$ in the window.
    *   **Filter:** Keep pairs where $\min(d(t)) < 3.0$ yards.
    *   *Rationale:* This captures high-acceleration events (like dives) (Cite solution_lesson_node_00039) while retaining the "buffer zone" of near-misses required to define the decision boundary (Cite solution_lesson_node_00042).

*   **Stage 1: Vector-Decomposed Kinematic Feature Engineering (Structural Innovation)**
    *   **Collision Axis Definition:** For every timestep, define the unit vector $\hat{r}$ pointing from Player 2 to Player 1.
    *   **Vector Decomposition:** Instead of collapsing kinematics into scalars (Speed, Accel), decompose all motion vectors into **Radial** (Parallel to $\hat{r}$) and **Tangential** (Perpendicular to $\hat{r}$) components.
        *   *Features:* `radial_velocity` (Impact Speed), `tangential_velocity` (Shear Speed), `radial_acceleration`, `tangential_acceleration`.
        *   *Rationale:* This explicitly distinguishes between "Head-on Collision" (High Radial) and "Running Alongside" (High Tangential), fixing the failure of Idea 20 (Cite solution_lesson_node_00043).
    *   **Transient Spectral Energy:** Apply a high-pass filter to the **Radial Acceleration** window and compute RMS Energy. This isolates the "Impact Shock" from the "Trend" (Cite solution_lesson_node_00012).
    *   **Primary Physics Primitives:** Retain **Time-To-Collision** and **Sentinel-Aware Distance** (Cite solution_lesson_node_00035).
    *   **Invariance:** Strictly exclude absolute coordinates (Cite solution_lesson_node_00024) and 3rd-party context (Cite solution_lesson_node_00036).

*   **Caching:** Enforce **parameter-aware caching** (Cite solution_lesson_node_00002).

### 3. Training
The training process executes a **Dual-Scout Mining Curriculum** with **Temporal Label Smoothing**.

*   **Phase 1: Dual-Scout Training**
    *   Construct a balanced dataset from the **Relaxed Gated Survivors**.
    *   Train **Scout A (LGBM)** and **Scout B (XGB)** on this set using the **Full Vector Feature Set**.
    *   *Constraint:* Scouts must see the exact same features as the Expert to prevent "Semantic Gaps" (Cite solution_lesson_node_00022).

*   **Phase 2: Diversity Mining**
    *   Run Scouts on the **Entire Gated Survivor Pool**.
    *   Select **Hard Negatives**: Instances where $P(Contact) > 0.05$ from **either** Scout (Union). (Cite solution_lesson_node_00021).

*   **Phase 3: Expert Training with Label Smoothing (Structural Innovation)**
    *   **Target Engineering:** Instead of hard binary targets (`0` or `1`), apply **Temporal Gaussian Smoothing** ($\sigma=1$ step) to the contact labels in the Expert dataset.
        *   *Rationale:* The dataset description notes labels are "within +/- 10Hz". Hard targets punish the model for predicting contact at $t$ when the label is at $t+1$. Soft targets (e.g., `0.2, 0.9, 0.2`) encourage the model to learn the *approach* dynamics and provide robustness against label jitter.
    *   **Training:** Train the **Tri-Model Expert Ensemble** on the Mined Data using these soft targets (Objective: LogLoss/CrossEntropy).
    *   **Imbalance Handling:** Use internal rebalancing parameters (`is_unbalance`, `scale_pos_weight`) (Cite solution_lesson_node_00011).

### 4. Evaluation
1.  **Feature Generation:** Generate the **Full Vector-Decomposed Feature Set** for the **Entire Test Set**.
2.  **Inference:** Run the **Tri-Model Expert Ensemble** on the test features.
3.  **Ensembling:** Compute the unweighted average of the probability outputs from the three models.
4.  **Thresholding:** Apply the decision threshold optimized on the validation set (maximizing MCC) to generate the final submission.
