Based on the comprehensive analysis of the previous experiments and the extracted lessons, I propose the **Variable-Resolution Contextual Mining Ensemble (VRC-ME)**.

This strategy introduces a **Structural Evolution** in the form of a **Multi-Fidelity Feature Cascade**. It resolves the critical conflict between the need for **Full-Scale Hard-Negative Mining** (Cite solution_lesson_node_00021) and the computational cost of **Contextual Feature Engineering** (Cite solution_lesson_node_00012). By decoupling the temporal resolution of "Context" features from "Kinematic" features, we can effectively mine the entire 3.4 million row dataset without sacrificing the temporal receptive field required for accurate filtration (addressing the failure of Idea 7).

### 1. Model
The architecture employs a **Unified Heterogeneous Ensemble** within a **Two-Stage Cascade**.

*   **Unified Backbone:** Both stages utilize unified classifiers (predicting Player-Player and Player-Ground simultaneously) to leverage the stability of the shared non-contact class (Cite solution_lesson_node_00007).
*   **Stage 1: The Scout (High-Throughput / Mixed-Resolution):**
    *   **Architecture:** A lightweight **LightGBM** model.
    *   **Role:** Scans the full dataset to identify "Hard Negatives" using a mix of high-resolution kinematics and low-resolution context.
*   **Stage 2: The Expert (High-Precision / Full-Resolution):**
    *   **Architecture:** A **Heterogeneous Ensemble** of high-capacity **LightGBM** and **XGBoost** models (Cite solution_lesson_node_00003).
    *   **Role:** Distinguishes complex boundary cases using full-resolution temporal context.

### 2. Data
The data pipeline implements a **Variable-Resolution Feature Engineering** strategy to maximize information density while managing computational load.

*   **Tier 1: Global Features (Computed for all 3.4M rows)**
    *   **High-Res Kinematics:** We retain the **Flattened Temporal Window** (+/- 10 steps) for relative distance, speed, acceleration, and orientation. This ensures the Scout can see trajectory dynamics (convergence/divergence), preventing the "Snapshot Failure" observed in Idea 7 (Cite solution_lesson_node_00022).
    *   **Physics Derivatives:** **Jerk** and **Angular Jerk** are computed over the window to detect impact impulses (Cite solution_lesson_node_00012).
    *   **Low-Res Context:** **Spatial Density** (neighbor count) and **Cluster Speed** are computed *only for the target frame* ($t=0$). This captures the immediate environmental context (Cite solution_lesson_node_00023) but avoids the 20x computational cost of generating rolling windows for neighbor searches across the full dataset.
    *   **Invariance:** All spatial features are relative; absolute coordinates are strictly excluded to prevent overfitting (Cite solution_lesson_node_00024).

*   **Tier 2: Enriched Features (Computed only for Mined Subset)**
    *   **High-Res Context:** For the selected Positives and Hard Negatives, we expand the context features into **Flattened Temporal Windows** (+/- 10 steps). This allows the Expert model to analyze the *evolution* of the pile-up (e.g., "Is the crowd density increasing or dispersing?"), providing the deep context needed for final disambiguation.

*   **Caching:** Strict parameter-aware caching is enforced (Cite solution_lesson_node_00002).

### 3. Training
The training procedure executes a **Full-Scale Mining Curriculum**:

1.  **Phase 1 (Scout Training):**
    *   Train the Scout model on a balanced subset (All Positives + 10x Random Negatives) using **Tier 1 Features**.
    *   *Objective:* Maximize Recall to ensure no potential contacts are discarded.
2.  **Phase 2 (Full-Scale Mining):**
    *   Run Scout inference on the **Full Training Dataset (3.4M rows)**.
    *   Select **Hard Negatives**: Instances where $P(Contact) > 0.01$. This leverages the scale-dependent efficacy of mining (Cite solution_lesson_node_00021) to find rare edge cases across the entire season.
3.  **Phase 3 (Expert Training):**
    *   Generate **Tier 2 Features** for the Mined Subset (Positives + Hard Negatives).
    *   Train the **Expert Ensemble** (LGBM + XGB) on this high-information-density dataset.
    *   **Imbalance Handling:** Use `is_unbalance=True` (LGBM) and `scale_pos_weight` (XGB) to manage the remaining difficulty-based imbalance without discarding data (Cite solution_lesson_node_00011).

### 4. Evaluation
1.  **Feature Generation:** Generate full **Tier 2 Features** for the Test Set (since the test set is small, we can afford the full computational cost).
2.  **Inference:** Run the **Expert Ensemble** (LGBM + XGB) on the test data.
3.  **Ensembling:** Compute the unweighted average of the probability outputs.
4.  **Thresholding:** Apply the decision threshold optimized on the validation set (maximizing MCC) to generate the final submission.
