The implementation strategy is as follows:

1.  **Configuration Override**: To ensure the solution runs within the "fast baseline" time limits while processing the full dataset (required for the "entire hold-out validation set" metric), we will reduce the number of boosting estimators (`N_ESTIMATORS`) in the `Config` from 2000 to 800. We will keep `DEBUG = False` to ensure we use the full validation set and match standard cache keys.
2.  **Training Pipeline**: We will instantiate the `Trainer` and execute `trainer.run(load_cached_data=True)`. This handles feature extraction (leveraging caching), dual-scout training, hard negative mining, expert training, and threshold optimization.
3.  **Validation & Metric**: After training, we will use the `DataProcessor` to load the full validation set and the `InferenceManager` to load the trained models. We will generate predictions, calculate the Matthews Correlation Coefficient (MCC), and print it in the required format (`Final Validation Metric: <value>`).
4.  **Failure Analysis**: We will compute the absolute error of the model's probability predictions against the ground truth on the validation set. We will then calculate the Pearson correlation between this error and the input features to identify systematic weaknesses.
5.  **Submission**: If the calculated validation MCC exceeds the threshold of 0.6865, we will generate the submission file using `InferenceManager.generate_submission` on the full test set.
