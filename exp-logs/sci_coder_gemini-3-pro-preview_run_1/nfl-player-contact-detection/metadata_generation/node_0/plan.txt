The implementation strategy involves the following steps:

1.  **Setup and Loading**: Define the input and metadata directories. Load the `train_labels.csv` (containing ground truth) and `sample_submission.csv` (representing the test set).
2.  **Training/Validation Split**:
    *   Identify unique `game_play` identifiers from the training labels.
    *   Perform a Group Shuffle Split on `game_play` with a fixed random state (42) and an 80:20 ratio. This ensures that all time steps and player pairs for a specific play remain in the same split, preventing data leakage.
    *   Create separate DataFrames for training and validation based on this split.
3.  **Metadata Enrichment**:
    *   For the training and validation sets, generate relative file paths for the associated video files (Endzone, Sideline, and All29 views) using the `game_play` identifier. The paths will point to `./input/train/`.
    *   For the test set (derived from `sample_submission.csv`), parse the `contact_id` column to extract `game_play`, `step`, `nfl_player_id_1`, and `nfl_player_id_2`.
    *   Generate video file paths for the test set pointing to `./input/test/`.
4.  **Saving**: Save the processed DataFrames as `train_metadata.csv`, `val_metadata.csv`, and `test_metadata.csv` in the `./metadata` directory.
5.  **Verification**:
    *   Reload the generated metadata files.
    *   Verify the 80:20 split ratio and ensure there is no overlap of `game_play` between training and validation sets.
    *   Perform a file existence check on a random sample of 1000 generated file paths. If more than 50% of paths are invalid, raise an error.
