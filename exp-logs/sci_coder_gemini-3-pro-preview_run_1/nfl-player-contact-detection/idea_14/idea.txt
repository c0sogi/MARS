Based on the progression of lessons learned—specifically the failure of **Discretized Grids** (Cite solution_lesson_node_00031) and the limitations of **Scalar Density** (Cite solution_lesson_node_00023)—I propose the **Ordered Neighbor Kinematic Mining Ensemble (ONK-ME)**.

This strategy introduces a **Structural Evolution** in Contextual Feature Engineering. Instead of reducing the local crowd to lossy aggregates (mean/max) or noisy spatial bins, we model the local environment as a **Sequence of Ordered Interaction Primitives**. By explicitly encoding the kinematics of the $K$-nearest neighbors as distinct feature blocks sorted by proximity, we preserve the **Entity Integrity** of potential collisions (e.g., linking the speed and distance of a specific threat) while maintaining strict **Permutation and Translation Invariance** (Cite solution_lesson_node_00024).

### 1. Model
The architecture employs a **Unified Heterogeneous Ensemble** designed for maximum capacity and stability.

*   **Unified Backbone:** We utilize a single modeling framework for both Player-Player and Player-Ground contacts, utilizing an `is_ground` categorical feature. This leverages the shared non-contact majority class to stabilize the decision boundary, avoiding the pitfalls of split architectures (Cite solution_lesson_node_00007).
*   **Heterogeneous Components:** The predictor consists of two distinct Gradient Boosting models: **LightGBM** (Leaf-wise) and **XGBoost** (Level-wise).
*   **High-Capacity Configuration:** Both models will be configured with deep trees (e.g., `num_leaves=256`, `max_depth=10`) to maximize information density and prevent early convergence (Cite solution_lesson_node_00003).

### 2. Data
The data pipeline implements **Geometric Gating** to enable the computation of the new **Ordered Neighbor Features** for the entire candidate pool without semantic gaps.

*   **Stage 0: Geometric Gating (The Sieve)**
    *   **Filter:** For the full training set (~3.4M rows), calculate instantaneous Euclidean distance.
    *   **Logic:** Discard Player-Player pairs with `Distance > 2.5` yards. Keep **ALL** Player-Ground pairs.
    *   *Rationale:* This eliminates trivial non-contacts (Cite solution_lesson_node_00026), reducing the dataset to ~600k rows while preserving all potential "Hard Negatives".

*   **Stage 1: Ordered Neighbor Feature Engineering (Innovation)**
    *   **Target Pair Kinematics:** Retain **Flattened Temporal Windows** (+/- 10 steps) and **Physics Derivatives** (Jerk) for the primary pair (Cite solution_lesson_node_00001, solution_lesson_node_00012).
    *   **Sorted Neighbor Vectors (Context):**
        *   For the target pair (or single player in P-G), identify the **$K=3$ Nearest Neighbors**.
        *   **Sort** these neighbors by ascending distance.
        *   For each neighbor, compute a **Kinematic Block**: `[Relative_Distance, Relative_Speed, Closing_Speed, Relative_Acceleration]`.
        *   **Flatten** into the feature row: `n1_dist, n1_speed, ..., n2_dist, n2_speed, ..., n3_dist...`.
        *   *Rationale:* This approach is **Continuous** (avoiding grid discretization noise, Cite solution_lesson_node_00031) and **Entity-Preserving**. Unlike aggregates (mean/max), it allows the tree to learn complex logic like "If Neighbor 1 is close AND Neighbor 1 is closing fast -> Contact", without confusing Neighbor 1's speed with Neighbor 2's distance.
    *   **Invariance:** All features are strictly relative; absolute coordinates are excluded (Cite solution_lesson_node_00024).

*   **Caching:** Enforce **parameter-aware caching** (hashing feature configs into filenames) to prevent implicit hazards (Cite solution_lesson_node_00002).

### 3. Training
The training process executes a **Full-Fidelity Mining Curriculum** to ensure the model learns from the hardest examples.

*   **Phase 1: Scout Training**
    *   Construct a balanced dataset from the **Gated Survivors** (All Positives + Equal Random Negatives).
    *   Train a **Scout LightGBM** using the **Full Feature Set** (Ordered Neighbors + Windows).
    *   *Constraint:* The Scout must see the exact same high-fidelity features as the Expert to prevent the "Semantic Gap" failure (Cite solution_lesson_node_00022).

*   **Phase 2: Full-Scale Mining**
    *   Run Scout inference on the **Entire Gated Survivor Pool** (~600k rows).
    *   Select **Hard Negatives**: Instances where $P(Contact) > 0.05$ but Ground Truth is 0.
    *   *Rationale:* This leverages the scale-dependent efficacy of mining (Cite solution_lesson_node_00021) to find the most confusing edge cases (e.g., high-speed near-misses).

*   **Phase 3: Expert Training**
    *   Construct the **Expert Dataset**: All Positives + All Mined Hard Negatives + Small Buffer of Random Gated Negatives.
    *   Train the **Expert Ensemble** (LGBM + XGB) on this high-information-density dataset.
    *   **Imbalance Handling:** Use `is_unbalance=True` (LGBM) and `scale_pos_weight` (XGB) to manage the remaining difficulty-based imbalance (Cite solution_lesson_node_00011).

### 4. Evaluation
1.  **Feature Generation:** Generate the **Full Feature Set** (Ordered Neighbors + Windows) for the **Entire Test Set**. (The test set is small enough that Geometric Gating is unnecessary for inference speed).
2.  **Inference:** Run the **Expert Ensemble** on the test features.
3.  **Ensembling:** Compute the unweighted average of the probability outputs.
4.  **Thresholding:** Apply the decision threshold optimized on the validation set (maximizing MCC) to generate the final submission.
