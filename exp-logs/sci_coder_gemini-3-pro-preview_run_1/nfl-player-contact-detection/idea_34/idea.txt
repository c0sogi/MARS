Based on the comprehensive analysis of the "Lessons Learned" and the trajectory of previous experiments, I propose the **Reference-Anchored Decoupled-Mining Ensemble (RAD-ME)**.

This strategy introduces a **Structural Evolution** in the *Feature Engineering* paradigm. It addresses a latent ambiguity in previous "Collision-Aligned" approaches (Idea 27, 33) regarding the temporal stability of the coordinate basis. By implementing a **Reference-Anchored Basis** (frozen at the target frame $t=0$), we isolate the true inertial trajectories of the players relative to the impact geometry, preventing the "Basis Noise" that occurs when the coordinate system rotates during the temporal window. This is synthesized with **Orientation-Aware Projections** and the robust **Anchored Diversity Mining** pipeline.

### 1. Model
The architecture employs a **Unified Heterogeneous Tri-Ensemble** designed to maximize algorithmic diversity and decision boundary resolution.

*   **Unified Backbone:** We utilize a single modeling framework for both Player-Player and Player-Ground contacts. We explicitly retain the **Sentinel Value Strategy** (Cite solution_lesson_node_00035), setting the `distance` feature for Ground interactions to `-1.0` (a distinct, non-physical value). This allows the tree-based models to isolate distinct modalities via root-level splits while leveraging the shared non-contact majority class for stability (Cite solution_lesson_node_00007).
*   **Tri-Model Expert Tier:** The final predictor consists of three distinct Gradient Boosting implementations:
    1.  **LightGBM:** Leaf-wise growth (Best for dense numerical data).
    2.  **XGBoost:** Level-wise growth (Best for approximate splits).
    3.  **CatBoost:** Symmetric/Oblivious trees (Best for native categorical handling and reducing overfitting).
    *   *Rationale:* Adding CatBoost introduces a third structural bias, maximizing the ensemble's ability to resolve the "Hard Negatives" mined by the Scouts (Cite solution_lesson_node_00039).
*   **High-Capacity Configuration:** All models are configured with deep trees (e.g., `num_leaves=256`, `max_depth=10`) to maximize information density (Cite solution_lesson_node_00003).

### 2. Data
The data pipeline implements **Relaxed Quadratic Gating** and **Reference-Anchored Decoupled Feature Engineering** to capture high-fidelity interaction physics without "Basis Noise."

*   **Stage 0: Relaxed Quadratic Reachability Gating**
    *   **Logic:** Model relative distance as a quadratic function: $d(t) = d_0 + v_{rel}t + 0.5 a_{rel}t^2$. Solve for $\min(d(t))$ in the window.
    *   **Filter:** Keep pairs where $\min(d(t)) < 3.0$ yards.
    *   *Rationale:* This captures high-acceleration events (like dives) (Cite solution_lesson_node_00039) while retaining the "buffer zone" of near-misses required to define the decision boundary (Cite solution_lesson_node_00042).

*   **Stage 1: Reference-Anchored Decoupled Feature Engineering (Structural Innovation)**
    *   **Reference Frame Definition:** For every target timestep ($t=0$), define the **Basis Vectors** and **Freeze** them for the entire temporal window ($t \in [-10, +10]$).
        *   **P-P Basis:** $\hat{u}$ = Unit vector from Player 2 to Player 1 *at t=0*.
        *   **P-G Basis:** $\hat{u}$ = Unit vector of Player 1's velocity *at t=0*.
        *   *Rationale:* Previous ideas updated the basis at every lag step. This mixed "Player Turning" with "Basis Rotating," muddying the signal. Freezing the basis at the event horizon ($t=0$) ensures that the features represent the pure inertial trajectory relative to the impact point (Cite solution_lesson_node_00057).
    *   **Decoupled Trajectory Projection:** Project the full window of Motion Vectors ($v, a$) AND **Orientation Vectors** ($\hat{o}$) onto the Frozen Basis.
        *   **Features:** $v_{long}(t), v_{trans}(t), a_{long}(t), a_{trans}(t)$ separately for P1 and P2.
        *   **Orientation Awareness:** $o_{long}(t), o_{trans}(t)$. This explicitly captures "Awareness" (e.g., is P1 facing the collision axis or being blindsided?) which scalar speeds miss.
    *   **Explicit Time-Domain Lags:** Retain the projected values as explicit lags. This avoids the information loss of spectral abstractions (Cite solution_lesson_node_00054).
    *   **Invariance:** Strictly exclude absolute coordinates (Cite solution_lesson_node_00024).

*   **Caching:** Enforce **parameter-aware caching** (Cite solution_lesson_node_00002).

### 3. Training
The training process executes a **Tri-Scout Anchored Mining Curriculum** using a strict **Binary Classification Objective**.

*   **Phase 1: Tri-Scout Training**
    *   Construct a balanced dataset from the **Relaxed Gated Survivors**.
    *   Train **Scout A (LGBM)**, **Scout B (XGB)**, and **Scout C (CatBoost)** using the **Full Reference-Anchored Feature Set**.
    *   *Constraint:* Scouts must see the exact same features as the Expert to prevent "Semantic Gaps" (Cite solution_lesson_node_00022).

*   **Phase 2: Diversity Mining**
    *   Run Scouts on the **Entire Gated Survivor Pool**.
    *   Select **Hard Negatives**: Instances where $P(Contact) > 0.05$ from **any** Scout (Union) (Cite solution_lesson_node_00021).

*   **Phase 3: Anchored Expert Training**
    *   **Dataset Construction:** Create the Expert Dataset using three components:
        1.  **All Positives**.
        2.  **Mined Hard Negatives** (The Union).
        3.  **Random Easy Negatives (Anchors):** A random sample of the Gated Survivors maintained at a **1:1 Ratio** with Positives.
        *   *Rationale:* A 1:1 Anchor ratio prevents the model from overfitting to edge cases (Cite solution_lesson_node_00048) while ensuring the loss function isn't flooded by easy negatives (Cite solution_lesson_node_00059).
    *   **Objective:** Train using standard **Binary LogLoss**. We explicitly reject Temporal Label Smoothing to maintain precision for sharp contact events (Cite solution_lesson_node_00056).
    *   **Imbalance Handling:** Use internal rebalancing parameters (`is_unbalance`, `scale_pos_weight`) (Cite solution_lesson_node_00011).

### 4. Evaluation
1.  **Feature Generation:** Generate the **Full Reference-Anchored Feature Set** for the **Entire Test Set**.
2.  **Inference:** Run the **Tri-Model Expert Ensemble** on the test features.
3.  **Ensembling:** Compute the unweighted average of the probability outputs from the three models.
4.  **Thresholding:** Apply the decision threshold optimized on the validation set (maximizing MCC) to generate the final submission.
