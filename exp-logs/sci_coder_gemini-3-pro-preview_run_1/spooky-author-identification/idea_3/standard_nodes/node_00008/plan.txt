The implementation strategy involves a two-phase approach to satisfy the requirements for validation metrics and conditional submission, while optimizing for runtime.

1.  **Configuration & Setup**: First, we import the `Config` class and modify key parameters (`EPOCHS=2`, `N_FOLDS=3`, `TRAIN_BATCH_SIZE=32`) to ensure the solution runs quickly as a baseline.
2.  **Phase 1: Validation**:
    *   We load the data and isolate `train_df` and `val_df`.
    *   We run 3-Fold Cross-Validation on `train_df` using `CrossValidationRunner` to generate Out-of-Fold (OOF) predictions.
    *   We extract meta-features (length, punctuation) for `train_df`.
    *   We train the `StackingMetaLearner` (XGBoost) on these OOF predictions and meta-features.
    *   To evaluate on the hold-out `val_df`, we train fresh Level 1 experts (TF-IDF and DeBERTa) on the full `train_df` and predict on `val_df`.
    *   We combine these validation predictions with validation meta-features and pass them through the trained Meta-Learner.
    *   We calculate and print the **Final Validation Metric** (Log Loss).
3.  **Failure Analysis**: We compute the per-sample log loss on the validation set and calculate the correlation between this error and the input text meta-features (length, word count, punctuation), printing the results.
4.  **Phase 2: Submission**:
    *   If the validation metric meets the threshold, we combine `train_df` and `val_df` into a larger training set.
    *   We retrain the Level 1 experts on this combined data.
    *   We generate predictions for `test_df` and extract test meta-features.
    *   We use the Meta-Learner trained in Phase 1 to aggregate these signals and generate the final submission file.
