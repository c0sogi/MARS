The issue is caused by data leakage in the ensemble phase: the XGBoost meta-learner is trained on a subset of the validation data but evaluated on the entire validation set (including the training subset), leading to an artificially low loss and an invalid metric. To fix this, I will implement **Stacking with Out-of-Fold (OOF) predictions** in `library/ensemble.py`. Instead of a single hold-out split, I will use `StratifiedKFold` to generate predictions for the validation set where each sample is predicted by a model that did not see it during training. This ensures the validation metric is unbiased (Cite debug_lesson_2). I will also retrain the final meta-learner on the full validation set to generate predictions for the test set.
