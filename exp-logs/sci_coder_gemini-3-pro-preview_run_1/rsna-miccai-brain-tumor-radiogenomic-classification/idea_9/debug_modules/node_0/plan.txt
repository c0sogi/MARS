### Implementation Strategy

This includes reducing the number of epochs to 1, setting a small batch size, disabling pretrained weight downloads (to ensure speed and independence from network status), and defining a specific working directory for demo outputs.
2.  **Reproducibility**: We will call `library.utils.seed_everything` to ensure the demonstration is deterministic.
3.  **Data Pipeline Verification**: We will invoke `library.data.get_dataloaders` with a small `debug_sample_size`. We will assert that the data loaders return tensors of the correct shape (Batch Size, Channels, Height, Width) and that the custom slice expansion logic (3 slices per subject) is functioning.
4.  **Model Architecture Verification**: We will instantiate the `library.model.MGMTClassifier`, perform a forward pass with a batch of dummy data (or real data from the loader), and verify that the output shape matches the binary classification requirement `(Batch Size, 1)`.
5.  **Training Loop Execution**: We will run `library.train.run_training` using the reduced configuration. This will test the entire pipeline: data loading, forward/backward passes, validation metric calculation, checkpoint saving, and submission generation.
6.  **Output Validation**: Finally, we will verify that the expected artifacts (best model checkpoint and submission CSV) exist and that the submission file adheres to the required format.
