The implementation failure stems from a combination of undefined metric handling and stale artifact persistence. The validation metric (`Val AUC`) evaluated to `nan` during the training loop, causing the checkpointing condition `if val_auc > best_auc` to fail (as comparisons with `nan` are always False). Consequently, the model trained in the current session was never saved. When the inference step ran, it detected an existing file at `Config.MODEL_SAVE_PATH` (leftover from a previous run with a different architecture) and attempted to load it, triggering a `RuntimeError` due to mismatched keys.

To fix this:
1.  **Sanitize the Metric:** In `library/engine.py`, explicitly check if the calculated AUC is `nan` and replace it with a fallback value (0.5). This ensures the control flow allows the model to be saved (Cite debug_lesson_1).
2.  **Clean Stale Artifacts:** In `library/engine.py`, remove any existing model file at `Config.MODEL_SAVE_PATH` before initializing the training loop. This ensures that if training fails to save a new model, the inference step will correctly report "No trained model found" rather than crashing on an architecture mismatch.
