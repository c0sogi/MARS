The issue stems from a mismatch between the keys returned by the loss function and the keys initialized in the statistics accumulator within the training loop. Specifically, `DKNLoss` returns a dictionary containing `"loss_total"`, but `train_one_epoch` in `library/engine.py` initializes `running_stats` only with `"loss_hm"`, `"loss_cls"`, and `"loss_reg"`. This causes a `KeyError` when the code attempts to update the running statistics with the returned values. The fix involves adding `"loss_total": 0.0` to the initialization of `running_stats` in `library/engine.py`.
