The previous implementation suffered from two critical issues:
1.  **Stale Cache Usage**: The `_process_data` method blindly loaded cached metadata (`val_parsed.npy`) without verifying if the number of cached samples matched the current dataset configuration. This caused the validation loop to run on a truncated subset (20 images from a previous debug run) instead of the full validation set (999 images).
2.  **Silent Data Loading Failures**: The `__getitem__` method silently caught missing images (returning `None` from `cv2.imread`) and substituted them with black placeholders. This masked underlying path errors and fed garbage data to the model (Cite debug_lesson_3).

The fix involves:
1.  Updating `_process_data` to load the metadata CSV first and verify that the cached data length matches the expected length before using it.
2.  Updating `__getitem__` to raise a `FileNotFoundError` immediately if an image fails to load, ensuring that data pipeline errors are detected rather than suppressed.
