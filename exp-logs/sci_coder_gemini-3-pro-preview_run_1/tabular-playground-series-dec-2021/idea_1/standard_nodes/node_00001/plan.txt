The implementation strategy follows a streamlined pipeline designed for speed and robustness on the provided hardware. 

1.  **Setup & Data Loading**: We initialize the environment with a fixed seed for reproducibility. We use the `DataManager` to load the full training, validation, and test datasets. Loading the full data first allows us to cache it efficiently and ensures the `LabelEncoder` sees all potential class labels before any subsampling occurs.
2.  **Preprocessing & Subsampling**: We encode the target variable `Cover_Type` on the full training set. To comply with the requirement for a fast baseline, we then subsample the training data to 500,000 samples. This size is sufficient to train a high-performing XGBoost model while significantly reducing training time. The validation and test sets are kept intact to ensure accurate metrics and a complete submission.
3.  **Model Training**: We utilize the `XGBClassifierWrapper` with parameters optimized for the NVIDIA A100 GPU (`tree_method='hist'`, `device='cuda'`). This ensures the training process is hardware-accelerated. We use `multi:softmax` for the classification objective and implement early stopping to prevent overfitting.
4.  **Validation & Failure Analysis**: We evaluate the model on the full hold-out validation set and print the required `Final Validation Metric`. For failure analysis, we calculate the correlation between the model's binary error vector (correct/incorrect) and the input features to identify which features are most associated with misclassifications.
5.  **Submission**: Finally, we generate predictions for the test set, inverse-transform the encoded labels back to their original values, and save the formatted submission file to `./submission/submission.csv`.
