The `ValueError: Invalid classes inferred from unique values of y` occurs because the aggressive random subsampling (2000 samples) in `runfile.py` excluded all instances of a rare class (Class 4, mapped to 3). This resulted in non-contiguous target labels `[0, 1, 2, 4, 5]`, violating XGBoost's requirement for zero-indexed, contiguous class labels `0..N-1` (Cite debug_lesson_3).

To fix this, I will modify `library/features.py` to use stratified sampling (`train_test_split` with `stratify`) instead of simple random sampling when `DEBUG_SAMPLES` is enabled. This ensures that the subsampled training data retains at least one example of every class, preserving the contiguous label structure required by the model.
