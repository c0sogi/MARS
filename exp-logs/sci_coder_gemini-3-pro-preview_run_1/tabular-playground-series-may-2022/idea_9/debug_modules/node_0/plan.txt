Here is the implementation strategy followed by the complete Python script.

### Implementation Strategy

1.  **Environment Setup**: Import necessary libraries (`torch`, `pandas`, `numpy`, `os`) and the provided modules (`config`, `architecture`, `data_factory`, `trainer`). Set random seeds for reproducibility.
2.  **Mock Data Generation**: Create a temporary directory in `./working/demo_metadata` and generate small, synthetic CSV files (`train.csv`, `val.csv`, `test.csv`) mimicking the structure of the real dataset (numerical features `f_00`-`f_30`, sequence feature `f_27`, `target`, `id`). This ensures the demonstration runs quickly without loading the massive original dataset.
3.  **Configuration Override**: Create a `DemoConfig` class that inherits from the provided `Config` but points to the synthetic data paths and adjusts hyperparameters (e.g., `BATCH_SIZE=4`, `EPOCHS=1`) for rapid execution.
4.  **Data Pipeline Verification**:
    *   Execute `preprocess_data` using the demo configuration.
    *   Verify the existence and shape of the processed numpy arrays (numerical features, sequence tokens, targets).
    *   Instantiate `ManufacturingDataset` and verify the output of `__getitem__` (shapes and types).
5.  **Model Architecture Verification**:
    *   Instantiate the `DiGUT` model using metadata derived from the preprocessing step.
    *   Perform a forward pass with a batch of data.
    *   Assert that the output shapes for `target_logits` and `discriminator_logits` are correct.
6.  **Training Logic Verification**:
    *   Test the `apply_swap_noise` function from `trainer.py` to ensure it returns corrupted views and masks correctly.
    *   Run `train_one_epoch` on the synthetic data to verify the training loop, loss calculation, and backward pass.
    *   Run `evaluate` to verify metric calculation (AUC).
7.  **Inference Verification**:
    *   Simulate the inference phase by generating predictions on the test set.
    *   Verify the format of the generated submission file.
