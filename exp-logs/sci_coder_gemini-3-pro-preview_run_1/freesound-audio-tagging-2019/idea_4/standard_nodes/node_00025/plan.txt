The optimization strategy focuses on improving the quality of the training data and ensuring the model has sufficient time to learn from it.

1.  **Increase Input Duration**: I will increase `TRAIN_DURATION` from 5.0s to 10.0s. The previous 5s crops, while providing augmentation, introduced significant false-positive label noise because the labeled event often fell outside the crop window (Cite `solution_lesson_node_00001`). A 10s window (closer to the 13.4s mean duration) ensures the global labels are more likely to be valid for the input crop.
2.  **Leverage Attention Pooling**: The existing Attention Pooling mechanism acts as a soft Multiple Instance Learning (MIL) detector. It is perfectly suited to handle the longer 10s inputs by dynamically focusing on the relevant event segments and suppressing the increased background noise/silence inherent in longer crops (Cite `solution_lesson_node_00007`).
3.  **Extended Training Schedule**: I will increase `EPOCHS` from 28 to 35 and `EARLY_STOPPING_PATIENCE` from 7 to 10. The doubled input dimensionality and the reduced "crop diversity" (fewer unique crops per file) create a different optimization landscape that requires a longer schedule to converge fully, similar to the requirements for scaled-up models (Cite `solution_lesson_node_00017`).
4.  **Adjust Batch Size**: To accommodate the doubled input duration within GPU memory constraints while maintaining stability, I will reduce `BATCH_SIZE` from 64 to 48.
5.  **Clean Output**: I will remove the `tqdm` progress bars to comply with the requirement for clean logs.
