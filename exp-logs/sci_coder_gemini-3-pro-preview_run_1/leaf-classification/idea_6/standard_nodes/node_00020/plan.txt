The implementation strategy follows the "Filter-then-Refine" pipeline described in the idea.

1.  **Setup & Loading**: We initialize the environment with a fixed seed and load the dataset using `load_dataset`, which handles the train/val/test splits and metadata reading.
2.  **Preprocessing**: We apply the `preprocess_data` pipeline. This applies the Yeo-Johnson Power Transformation to enforce Gaussianity (critical for LDA) and Standard Scaling for numerical stability.
3.  **Training**: We train the `FisherBayesianEnsemble`. This involves:
    *   Fitting the LDA backbone to learn the discriminative Fisher subspace.
    *   Projecting the data into this subspace.
    *   Fitting the Gaussian Process Classifier (GPC) on the projected features to learn the probabilistic decision boundary.
4.  **Validation**: We evaluate the model on the hold-out validation set to compute the Multi-class Log Loss. This metric is printed exactly as required.
5.  **Failure Analysis**: We analyze the validation errors. We compute the "error magnitude" (defined as $1.0 - P(\text{true class})$) for each validation sample and calculate the Pearson correlation between this error and each of the 192 input features. This identifies which features are most associated with model uncertainty or misclassification.
6.  **Submission**: If the validation metric meets the strict threshold defined in the task, we generate predictions for the test set using the ensemble (weighted average of LDA and GPC probabilities) and save the submission file.
