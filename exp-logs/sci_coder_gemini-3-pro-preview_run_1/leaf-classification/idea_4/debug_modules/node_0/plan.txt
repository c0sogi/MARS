### Implementation Strategy

1.  **Configuration Verification**: Initialize the `Config` class and verify that directory paths and utility functions (like genus extraction and feature column generation) work as expected.
2.  **Data Loading**: Use `load_data(debug=True, load_cached_data=False)` to load a small subset of the data. This tests the raw data loading, feature extraction, taxonomy derivation, and the Yeo-Johnson + StandardScaling preprocessing pipeline without consuming excessive time.
3.  **Data Validation**: Assert the shapes of the returned feature matrices and target arrays to ensure the preprocessing pipeline is functioning correctly (e.g., `(N, 192)` for features).
4.  **Model Training & Inference**:
    *   **GlobalLDA**: Train the baseline model and verify prediction shapes.
    *   **HierarchicalLDA**: Train the taxonomy-aware model. Since `debug=True` provides very sparse data (50 samples for 99 classes), this effectively tests the robust fallback mechanisms (falling back to global priors when local genus data is insufficient).
    *   **TaxonomyEnsemble**: Train the ensemble that combines both approaches and generate predictions.
5.  **Evaluation**: Calculate the multi-class log loss using the provided metric function to ensure numerical stability (clipping logic).
6.  **Submission Generation**: Create a sample submission file using the test set predictions and verify the file structure matches the competition requirements.
