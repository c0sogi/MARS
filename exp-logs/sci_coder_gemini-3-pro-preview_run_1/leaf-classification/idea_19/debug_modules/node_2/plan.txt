The issue is caused by the naive truncation of the training data (`X_train[:100]`) for debugging, which results in the model being trained on only a subset of the 99 plant species. However, the validation set `y_val` retains all original classes, causing `log_loss` to crash when it encounters labels that the model never learned (Cite debug_lesson_1). Furthermore, the downstream submission generation would fail because the model's predicted probabilities would have fewer columns than the expected 99 classes (Cite debug_lesson_2).

To fix this, I will modify `train_and_predict` in `library/model.py` to:
1.  Filter `X_val` and `y_val` when `debug_sample_size` is active, ensuring the validation set only contains classes present in the truncated training set.
2.  Expand the predictions on the test set to the full (N, 99) shape by mapping the model's subset-specific predictions to their correct column indices in the global schema, filling missing classes with zeros.
