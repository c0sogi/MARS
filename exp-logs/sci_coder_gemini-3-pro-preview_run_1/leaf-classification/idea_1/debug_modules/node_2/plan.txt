The `ValueError: y contains previously unseen labels` is caused by the naive slicing of the dataset in debug mode. When `Config.DEBUG_SAMPLES` is small (50) and the number of classes is high (99), a simple slice results in a sparse distribution where many classes have only a single instance. When `train_test_split` is applied to this subset (without stratification, which is impossible for singletons), it creates disjoint sets of classes between training and validation. LightGBM then crashes because the validation set contains classes not present in the training set.

To fix this, I will update `library/data_loader.py` to implement the strategy from **debug_lesson_1** ("Filter Classes, Don't Just Slice Rows"). Instead of taking the first N rows, I will filter the dataset to include only the top 5 most frequent classes before sampling. This ensures that the debug subset has sufficient density (multiple samples per class), guaranteeing that both training and validation splits will contain the same set of classes.
