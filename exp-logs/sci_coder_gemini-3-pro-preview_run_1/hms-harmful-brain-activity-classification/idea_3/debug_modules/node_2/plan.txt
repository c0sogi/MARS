The issue is that `model_save_path` is defined as a class attribute in `Config` and is evaluated only once when the module is imported, using the initial value of `working_dir` (`./working/idea_3`). Although `runfile.py` patches `Config.working_dir` to `./working/demo_run`, the `model_save_path` remains stale, pointing to the non-existent `./working/idea_3` directory. When `run_training` executes, it creates the new working directory but attempts to save the model to the old path, causing a `RuntimeError`.
