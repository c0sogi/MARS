The implementation strategy involves the following steps:

1.  **Directory Scanning**: We will traverse the `./input/train` and `./input/test` directories to identify all available image files. Since the filenames contain metadata (slice dimensions and pixel spacing) that cannot be inferred solely from the case/day/slice IDs, this scan is essential to map abstract IDs to concrete file paths. We will parse these filenames to extract the `case`, `day`, `slice`, `width`, `height`, and `pixel spacing`.

2.  **Data Merging**: We will load the provided `train.csv`, which contains segmentation masks in a long format (one row per class per slice). We will pivot this dataframe to a wide format (one row per slice, with columns for 'large_bowel', 'small_bowel', and 'stomach' masks) and merge it with the file information obtained from the directory scan. This ensures every metadata entry has a valid file path.

3.  **Grouped Splitting**: To create a valid validation set, we will identify unique `case` identifiers (representing individual patients). We will perform a Group Shuffle Split (80% train, 20% validation) based on these cases to ensuring that all slices from a single patient (across all days) remain in the same split. This prevents data leakage.

4.  **Metadata Generation**: We will save the resulting dataframes as `train.csv`, `val.csv`, and `test.csv` in the `./metadata` directory.

5.  **Verification**: Finally, the script will reload the generated metadata to verify the file paths exist, confirm the data split integrity (no patient overlap), and print summary statistics.
