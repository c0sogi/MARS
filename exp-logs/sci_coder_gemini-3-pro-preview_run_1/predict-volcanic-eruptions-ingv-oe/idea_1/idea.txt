# Baseline Approach: Statistical Feature Engineering with Gradient Boosting

## Model
The proposed baseline utilizes a **Statistical Feature Aggregator coupled with a Gradient Boosting Regressor**. This architecture prioritizes computational efficiency and interpretability by transforming the high-dimensional raw sensor data into a compact tabular representation before learning.

The model consists of two distinct stages:
1.  **Deterministic Feature Extraction Layer:** This component collapses the temporal dimension (60,001 time steps) of the ten sensor channels into a fixed-size vector of global descriptive statistics. This avoids the heavy computational cost of processing long sequences with recurrent or convolutional layers.
2.  **Gradient Boosting Regressor (LightGBM):** The resulting tabular features are fed into a LightGBM model. This algorithm is chosen for its speed, low memory usage, and native ability to handle the non-linear relationships and potential interactions between sensor statistics.

## Data
To prepare the data for this architecture, the following preprocessing steps are required:

1.  **Imputation:** As identified in the data analysis, several sensors (specifically `sensor_2`, `sensor_3`, and `sensor_5`) contain significant missing values. These will be filled using mean imputation within each segment to ensure consistent calculation of statistics.
2.  **Feature Engineering:** For each of the 10 sensors in a segment, a set of time-domain statistics will be calculated to capture the signal's characteristics:
    *   **Distribution:** Mean, Standard Deviation, Skewness, and Kurtosis to describe the signal's shape and spread.
    *   **Extremes:** Minimum, Maximum, and specific Quantiles (e.g., 1%, 5%, 95%, 99%) to capture the intensity of seismic spikes.
    *   **Dynamics:** Median and Mean Absolute Deviation (MAD) to provide robust measures of central tendency and variability.
3.  **Flattening:** The statistics for all 10 sensors will be concatenated into a single feature vector for each `segment_id`, resulting in a training matrix of shape `(N_segments, N_sensors * N_stats)`.

## Training
The training procedure focuses on robustness and direct optimization of the target metric:

*   **Loss Function:** The model will be trained using **Mean Absolute Error (L1 Loss)**. This aligns perfectly with the evaluation metric and ensures the model is less sensitive to extreme outliers in the `time_to_eruption` target compared to Mean Squared Error (L2).
*   **Validation Strategy:** A **5-Fold Cross-Validation** scheme will be employed. Given the relatively small size of the training set (~4,000 samples), this ensures that the performance estimate is reliable and allows the model to train on 80% of the available data in each fold.
*   **Optimization:** The Gradient Boosting model will be trained with early stopping based on the validation MAE to prevent overfitting.

## Evaluation
To generate predictions for the submission:

1.  **Inference Pipeline:** The test data files will be processed individually. The same feature extraction pipeline used for training will be applied to each test CSV to generate a feature vector.
2.  **Prediction:** The trained LightGBM model (or an average of the models from the 5 cross-validation folds) will predict the `time_to_eruption` for each test segment.
3.  **Formatting:** The predictions will be paired with their corresponding `segment_id` and saved to a CSV file in the required submission format.
