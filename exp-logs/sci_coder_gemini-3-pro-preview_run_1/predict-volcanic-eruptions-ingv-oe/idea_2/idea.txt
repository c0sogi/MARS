Based on the analysis of the previous results and the identified failure modes, I propose a strategy that evolves the baseline by implementing a **Hierarchical Time-Frequency Feature Engineering** pipeline. This approach addresses the limitations of global statistics by capturing signal evolution and spectral content, while rigorously fixing the caching mechanism that caused the previous iteration to fail.

# Model
The core model remains a **Gradient Boosting Regressor (LightGBM)**, chosen for its proven effectiveness with tabular data (Cite Lesson ID: solution_lesson_node_00001). However, the input architecture will undergo a structural innovation. Instead of a flat vector of global statistics, the model will be trained on a **Hierarchical Multi-Domain Feature Matrix**. This matrix explicitly represents:
1.  **Temporal Dynamics:** The evolution of the signal over time (via windowing).
2.  **Spectral Content:** The frequency characteristics of the seismic tremors (via FFT).
3.  **Spatial Interactions:** The relationships between different sensors (via cross-correlation).

# Data
The data processing pipeline will be significantly expanded to generate this rich feature set, incorporating strict safeguards against stale data.

1.  **Robust Caching Strategy:**
    To prevent the silent failures observed previously, the feature caching mechanism will use **Configuration Hashing** (Cite Lesson ID: solution_lesson_node_00002). Instead of checking for a static filename like `train_features.parquet`, the system will compute an MD5 hash of the feature engineering configuration (e.g., window sizes, list of functions) and append it to the filename (e.g., `train_features_{hash}.parquet`). This guarantees that any change to the logic forces a re-computation of the features.

2.  **Hierarchical Feature Extraction:**
    For each segment (10 sensors $\times$ 60,001 time steps), features will be extracted at two levels:
    *   **Level 1: Windowed Analysis (Local):** The 10-minute segment will be sliced into $N$ non-overlapping windows (e.g., 10 windows of 6,000 steps). Within each window, we will compute:
        *   **Time-Domain Stats:** Mean, Std, Skew, Kurtosis, Quantiles (Retaining the successful baseline features - Cite Lesson ID: solution_lesson_node_00001).
        *   **Frequency-Domain Stats:** Apply Fast Fourier Transform (FFT) to extract Spectral Centroid, Dominant Frequency, and Spectral Power. This captures the harmonic tremors typical of volcanic activity.
    *   **Level 2: Aggregation (Global):** We will compute summary statistics *across* the windows (e.g., the standard deviation of the window means) to quantify the **stability** and **evolution** of the signal over the 10-minute period.

3.  **Spatial Features:**
    We will calculate Pearson correlation coefficients between pairs of sensors to capture the spatial coherence of the seismic wavefield across the volcano's geometry.

4.  **Preprocessing:**
    Missing values in the raw sensor data will be imputed with the segment mean prior to feature extraction (Cite Lesson ID: solution_lesson_node_00001).

# Training
*   **Strategy:** A **5-Fold Cross-Validation** scheme will be used to ensure robustness given the dataset size (~3,000 samples).
*   **Objective:** The model will minimize **Mean Absolute Error (MAE)**, aligning directly with the competition metric.
*   **Optimization:** We will employ early stopping based on the validation score to prevent overfitting to the high-dimensional feature space.

# Evaluation
The evaluation pipeline will mirror the training process:
1.  Load test files and apply the exact same **Hierarchical Feature Extraction** pipeline (using the hashed cache to ensure consistency).
2.  Generate predictions using the trained LightGBM ensemble (averaging predictions across all 5 folds).
3.  Format the output into the required `segment_id, time_to_eruption` CSV format.
