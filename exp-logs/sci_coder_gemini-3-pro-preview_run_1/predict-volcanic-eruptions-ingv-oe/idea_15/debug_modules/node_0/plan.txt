Implementation Strategy:
1.  **Configuration Override**: We will dynamically modify the `Config` class attributes to adapt the pipeline for a rapid demonstration. This includes redirecting directories to a temporary workspace, reducing the number of folds to 2, setting epochs to 1, and lowering the number of estimators for LightGBM.
2.  **Data Subsetting**: We will create a "mini" dataset by reading the provided metadata files, sampling a small number of rows (e.g., 20 training, 10 test), and saving these new metadata files to the configured temporary metadata directory. This ensures the pipeline runs on real data but completes in seconds.
3.  **Feature Engineering**: We will instantiate the `FeatureEngineer` class and process the mini-dataset. We will verify the generation of tabular features (Parquet) and spectrograms (NPY files) using assertions.
4.  **Component Demonstration**:
    *   **Dataset**: We will instantiate `VolcanoDataset` and `DataLoader` to verify data loading and shape consistency (Spectrograms, Scalars, Targets).
    *   **Vision Model**: We will instantiate `EfficientNetFiLM`, perform a forward pass with a batch of data, and verify the output shape.
    *   **Tabular Model**: We will manually trigger the `train_lgbm_fold` function on the processed features and verify the returned model and predictions.
5.  **Integration Run**: Finally, we will execute the high-level orchestration functions (`run_tabular_cv`, `run_vision_cv`, `train_meta_learner`, `generate_submission`) to demonstrate the full end-to-end workflow and generate a submission file.
