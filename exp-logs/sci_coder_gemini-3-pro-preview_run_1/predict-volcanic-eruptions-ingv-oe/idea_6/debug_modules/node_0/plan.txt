The following script demonstrates the end-to-end execution of the seismic eruption prediction pipeline using the provided library.

### Implementation Strategy
1.  **Configuration Override**: We dynamically modify the global `Config` class to reduce computational intensity. We set epochs to 1, batch sizes to 4, and estimators to 10 to ensure the script runs quickly (within minutes) while exercising all code paths.
2.  **Mini-Dataset Creation**: Instead of processing the full dataset (which would take hours), we create "mini" metadata files by sampling the first few rows of the provided metadata. This allows us to run the real feature engineering pipeline on a small subset of real data.
3.  **Feature Engineering**: We utilize `FeatureProcessor` to extract tabular features (MFCCs, stats) and generate spectrograms for the mini-datasets. We force the processor to save these as the standard "train", "val", and "test" caches so downstream models find them automatically.
4.  **Model Training (Tabular & Vision)**: We execute the Cross-Validation routines (`run_lgbm_cv` and `run_vision_cv`) in debug mode. These functions load the cached features, train the respective models (LightGBM and EfficientNet), and generate Out-of-Fold (OOF) and Test predictions.
5.  **Stacking**: We run the `run_stacking` function to train the Meta-Learner (Ridge Regression) on the OOF predictions and generate the final submission file.
6.  **Verification**: Throughout the process, we use assertions to verify that files are created, shapes are correct, and the submission file follows the required format.
