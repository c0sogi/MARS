Based on the analysis of the previous experiments and the provided lessons, I propose a **Hybrid Spectral-Temporal Ensemble** strategy. This approach structurally evolves the solution by combining the efficiency of the statistical baseline with the representation learning capabilities of Deep Learning, while strictly adhering to the feature engineering best practices identified in the lessons.

# Model
The solution will employ a **Heterogeneous Ensemble** comprising two distinct modeling paradigms:

1.  **Branch A: Enhanced Gradient Boosting Machine (LightGBM)**
    *   This branch retains the high-performance tabular approach but upgrades the feature set. It uses a LightGBM regressor trained on a rigorous "Expert Feature Matrix".
    *   **Structural Innovation (Wavelets):** To better capture the non-stationary nature of seismic signals (which global FFT misses), we will introduce **Discrete Wavelet Transform (DWT)** features. By decomposing the signal into approximation and detail coefficients, we can extract energy and entropy statistics from specific frequency bands, providing a more granular spectral representation.

2.  **Branch B: Deep 1D-Residual Network (1D-ResNet)**
    *   **Structural Innovation (Deep Learning):** To address the limitation of compressing 60,000 time-steps into a single vector, we will implement a deep convolutional neural network (e.g., ResNet-18 modified for 1D data). This model will ingest the raw (normalized) sensor waveforms directly, allowing it to learn complex, non-linear temporal filters that manual feature engineering might overlook.

**Ensemble Strategy:** The final prediction will be a weighted average of the predictions from Branch A and Branch B, leveraging the uncorrelated error distributions of the two algorithms.

# Data
The data pipeline will be split to serve both branches, underpinned by a robust caching layer.

1.  **Caching & Integrity:**
    *   Implement **Configuration Hashing** for all feature extraction steps. The cache filename will include a hash of the feature configuration dictionary to ensure that any change in logic (e.g., adding Wavelets) forces a re-computation, preventing the "stale data" failure (Cite Lesson ID: solution_lesson_node_00002).

2.  **Branch A Preprocessing (Feature Engineering):**
    *   **Global Statistics:** Compute global mean, std, skew, kurtosis, and quantiles (e.g., 99th percentile). We will explicitly **avoid aggregating local window statistics** (e.g., mean of window maxes) to preserve the magnitude of sparse, high-intensity seismic events (Cite Lesson ID: solution_lesson_node_00004).
    *   **Spectral & Structural:** Calculate FFT statistics (mean, std, dominant frequency) and Total Variation (Cite Lesson ID: solution_lesson_node_00006).
    *   **Amplitude-Gated Frequency:** Compute the **Raw Zero-Crossing Rate** (on raw data, not mean-centered) to utilize the signal's offset as a natural noise filter, capturing only significant oscillations (Cite Lesson ID: solution_lesson_node_00007).
    *   **Wavelet Features:** Compute energy and entropy of DWT coefficients (e.g., using a Daubechies wavelet).

3.  **Branch B Preprocessing (Raw Sequence):**
    *   **Imputation & Scaling:** Fill missing values with the segment mean and apply **Robust Scaling** (using median and IQR) to normalize the sensor readings, minimizing the impact of the outliers identified in the data analysis.
    *   **Formatting:** Reshape the data into `(Batch_Size, 10, 60001)` tensors for GPU ingestion.

# Training
Both branches will be trained using a **5-Fold Cross-Validation** scheme to ensure robustness.

1.  **Loss Function:** Both models will minimize **Mean Absolute Error (MAE)**, directly optimizing the competition metric.
2.  **Optimization:**
    *   **LightGBM:** Train with early stopping based on validation MAE.
    *   **1D-ResNet:** Train on the NVIDIA A100 GPU using the **AdamW** optimizer and a **Cosine Annealing** learning rate scheduler to converge efficiently.
3.  **Explicit vs. Dynamic:** The feature extraction code will use explicit function calls rather than dynamic configuration loops to prevent silent failures (Cite Lesson ID: solution_lesson_node_00005).

# Evaluation
1.  **Inference:** For each test segment, generate two predictions: one from the LightGBM (using the hashed feature pipeline) and one from the 1D-ResNet (using the raw data pipeline).
2.  **Aggregation:** Average the predictions across the 5 folds for each model.
3.  **Submission:** Compute the mean of the LightGBM and ResNet outputs to produce the final `time_to_eruption` estimate.
