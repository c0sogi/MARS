The `RuntimeError` is caused by `pydicom`'s lazy loading mechanism: `dcmread` successfully reads the file headers, but the actual decompression of pixel data (which requires missing `gdcm` or `pylibjpeg` dependencies) only happens when `.pixel_array` is accessed in `get_pixels_hu`, causing a crash outside the error handling block.

To fix this, I will modify `load_scan` in `library/data.py` to explicitly access `.pixel_array` within the existing `try-except` block. This forces the decompression attempt to happen where it can be safely caught (Cite debug_lesson_2). If decompression fails, the file is skipped. If all files for a patient fail, `slices` will be empty, triggering the fallback logic in `process_patient_dicom` which generates and caches black placeholder images, preventing retry loops in future epochs (Cite debug_lesson_8).
