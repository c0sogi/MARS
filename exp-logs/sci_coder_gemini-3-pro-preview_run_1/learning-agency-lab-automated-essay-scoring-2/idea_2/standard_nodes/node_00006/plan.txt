The implementation strategy involves orchestrating the provided library components to create a fast and effective baseline. 

1.  **Configuration**: I will override the default `Config` parameters within the script. Specifically, I will set `epochs` to 2 and `train_batch_size` to 16. This ensures the training fits well within the time limit on the A100 GPU while processing the 12k training samples efficiently.
2.  **Data & Model**: I will use `get_dataloaders` to load the stratified splits and `EssayRegressor` to initialize the DeBERTa-v3-small model. The model will be moved to the GPU defined in `Config.device`.
3.  **Training**: I will use the `train_model` function from `library.engine`, passing in the model, dataloaders, `AdamW` optimizer, and a linear learning rate scheduler.
4.  **Evaluation**: Post-training, I will use `validate` to obtain the final Quadratic Weighted Kappa (QWK) score and print it in the required format.
5.  **Failure Analysis**: I will manually compute predictions on the validation set using `predict`, calculate the absolute errors (residuals) against the ground truth, and compute the Pearson correlation between these errors and the essay character counts.
6.  **Submission**: Finally, I will check if the validation QWK exceeds the threshold of `0.7309333854955005`. If it does, I will trigger `generate_submission` to create the submission file.
