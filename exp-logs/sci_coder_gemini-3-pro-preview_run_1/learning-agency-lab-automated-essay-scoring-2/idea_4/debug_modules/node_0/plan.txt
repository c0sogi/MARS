Implementation Strategy:
1.  **Configuration Override**: Create a `DemoConfig` class inheriting from the provided `Config`. We will override parameters to ensure rapid execution: enabling `debug` mode (subsets data), reducing `max_length` to 64, setting `epochs` to 1, and using a tiny model (`prajjwal1/bert-tiny`) to avoid large downloads and memory usage during this verification script.
2.  **Utility Verification**: Test `set_seed` and `compute_qwk` with deterministic inputs to ensure metric calculation is correct.
3.  **Data Pipeline Verification**: Initialize `get_dataloaders` with the demo config. Fetch a single batch to verify the presence of required keys (`input_ids`, `attention_mask`, `labels`, `essay_id`) and correct tensor shapes.
4.  **Model Initialization & Forward Pass**: Instantiate `EssayScorerModel` with the tiny model config. Perform a forward pass with the fetched batch to confirm the model outputs a scalar regression value per sample without errors.
5.  **Optimizer Setup**: Verify `get_llrd_optimizer_params` correctly groups parameters for the specific model architecture.
6.  **Training Loop Simulation**: Manually set up the optimizer, scheduler, and scaler, then run `train_fn` for a single epoch. This verifies the training logic, gradient accumulation, and logging hooks.
7.  **Inference & Submission**: Run `inference_fn` on the test loader, process the predictions (clip/round), and generate a dummy submission file to verify the output format.
