The error `RuntimeError: value cannot be converted to type at::Half without overflow` occurs because the code uses `-1e9` as a masking value while running in mixed precision (FP16). In IEEE 754 half-precision, the minimum representable value is approximately -65,504, so `-1e9` causes an overflow when cast to FP16 Cite debug_lesson_1. To fix this, I will replace `-1e9` with `-1e4`, which is within the FP16 range but sufficiently small to ensure the softmax output is effectively zero for masked tokens.
