The `torch.AcceleratorError: CUDA error: device-side assert triggered` is caused by the dataset containing sparse or non-contiguous `category_id` values (e.g., IDs up to 15505 for 15501 classes). When `nn.CrossEntropyLoss` receives a target label that exceeds `num_classes - 1`, it triggers a CUDA assertion failure. To fix this, I will implement a label mapping system: `label2id` to convert raw category IDs to contiguous indices `[0, N-1]` for training, and `id2label` to map predictions back to the original IDs for submission. This ensures the model only sees valid indices within its output range. Cite debug_lesson_1.
