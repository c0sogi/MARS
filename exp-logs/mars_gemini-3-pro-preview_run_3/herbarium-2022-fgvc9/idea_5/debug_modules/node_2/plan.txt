The issue is that `Config.HIERARCHY_CACHE_PATH` and `Config.SUBMISSION_FILE` are defined as static class attributes in `library/config.py`. They are evaluated once at import time using the initial value of `Config.OUTPUT_DIR` (`./working/idea_5`). When `runfile.py` patches `Config.OUTPUT_DIR` to `./working/demo_run` at runtime, the dependent paths are not updated and continue to point to the old, non-existent directory, causing an `OSError`. To fix this, I will remove the static definitions of these paths and modify the code to construct them dynamically using the current `Config.OUTPUT_DIR` at runtime. This ensures that any changes to the output directory are correctly reflected in file operations (Cite debug_lesson_6).
