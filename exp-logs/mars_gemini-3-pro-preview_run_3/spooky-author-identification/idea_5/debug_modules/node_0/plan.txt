The following strategy outlines the implementation of the demonstration script:

1.  **Configuration & Setup**: We will start by importing the necessary modules and setting the random seed for reproducibility. We will override specific `Config` parameters (like `EPOCHS`, `DEBUG` flags) to ensure the script runs quickly on a small subset of data, validating the "Optimize for Speed" requirement.

2.  **Data Loading & Processing**: We will utilize `load_data` to fetch the metadata. We will manually slice these DataFrames to create a tiny dataset (e.g., 20 samples) for demonstration purposes. We will then verify the functionality of `create_dataloader` and `create_mlm_dataloader` by checking the structure and shapes of the batches they produce.

3.  **Feature Engineering**: We will call `get_tfidf_features` to generate sparse TF-IDF matrices. We will validate the dimensions of the returned matrices to ensure they match the dataset sizes.

4.  **Statistical Modeling**: We will instantiate the `StatisticalModel` (ensemble of Logistic Regression and Naive Bayes), fit it on the TF-IDF features, and verify that it produces valid predictions and probabilities.

5.  **Neural Network Modeling & Training**:
    *   We will instantiate the `CustomTransformer` using the DeBERTa backbone defined in the config.
    *   We will simulate a training run using `train_fn` (with Adversarial Weight Perturbation enabled) and `eval_fn` on the small data subset.
    *   We will check that the loss is a valid float and predictions have the correct shape.
    *   We will briefly demonstrate `train_mlm` logic, though we might skip the full run or limit it to 1 step to save time, verifying the model saving mechanism.

6.  **Ensemble Optimization**: We will simulate an ensemble scenario by generating synthetic Out-of-Fold (OOF) predictions. We will then use `optimize_weights` to find optimal blending weights and `apply_ensemble` to generate final weighted predictions, asserting that the results are properly normalized.

7.  **Validation**: Throughout the script, `assert` statements will be used to enforce expected behaviors (e.g., probability sums, array shapes, data types).
