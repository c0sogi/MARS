The implementation strategy follows the "Granular Hept-View Stacking" architecture defined in the idea.

1.  **Data Loading & Preparation**: We load the pre-generated `train.parquet` and `val.parquet` metadata files and merge them into a "Union Dataset" using the provided `data_factory`. This maximizes the data available for training the base learners and the meta-learner. We also identify the specific indices corresponding to the original validation set to ensure we report the required hold-out metric.

2.  **Feature Engineering**: We utilize the `FeaturePipeline` to generate the four specific feature views:
    *   **Metadata**: Allow-listed numerical/categorical features (e.g., account age, restored RAOP history).
    *   **Lexical**: Sparse TF-IDF vectors of concatenated title and body text, using a granular token pattern to capture agency.
    *   **Behavioral**: Sparse TF-IDF vectors of subreddit history (Bag-of-Concepts).
    *   **Semantic**: Dense embeddings using `all-MiniLM-L6-v2`.

3.  **Model Training (Stacking)**: We use the `PipelineManager` to execute the training protocol:
    *   **Level 1 (Base Learners)**: We perform 5-Fold Stratified Cross-Validation on the Union Dataset.
        *   *Volatile Learners* (XGBoost, LightGBM) use the fold's validation set for early stopping.
        *   *Stable Learners* (Random Forest, Logistic Regression) are trained on the fold.
    *   **OOF Generation**: We collect Out-Of-Fold predictions for the entire Union Dataset.
    *   **Level 2 (Meta-Learner)**: A Logistic Regression meta-learner is trained on the OOF predictions.
    *   **Refit**: Stable learners are retrained on the full Union Dataset to maximize signal for the final inference.

4.  **Validation & Failure Analysis**:
    *   We extract the OOF predictions corresponding strictly to the original validation set indices.
    *   We calculate the **Area Under ROC Curve (AUC)** as the final validation metric.
    *   We compute the correlation between the model's error magnitude (absolute difference between prediction and target) and input features to identify failure modes (e.g., correlation with text length or account age).

5.  **Submission**:
    *   If the validation AUC exceeds the threshold (0.7222...), we generate features for the test set.
    *   We produce final predictions using the **Hybrid Inference Protocol** (averaging fold-models for volatile learners, using the full-refit model for stable learners), stack them via the meta-learner, and save the submission CSV.
