The issue is a classic data leakage problem in the validation phase of `runfile.py`. Specifically, the XGBoost model (`SemanticBooster`) uses the hold-out validation set (`X_val_view`, `y_val`) as the `eval_set` for early stopping. This allows the model to "peek" at the validation targets during training to optimize the number of trees, rendering the subsequent AUC calculation on that same validation set biased and invalid.

To fix this, I will modify `runfile.py` to create an internal validation split from the training data using `train_test_split`. The `SemanticBooster` will then use this internal subset for early stopping, ensuring that the external hold-out validation set (`y_val`) remains completely unseen during the training process. This aligns with the principle of synchronizing hyperparameters with data availability (Cite debug_lesson_5), ensuring valid metrics.
