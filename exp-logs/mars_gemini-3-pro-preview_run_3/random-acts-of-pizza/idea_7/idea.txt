Based on the comprehensive empirical analysis from the provided lessons, I propose a **Tri-View Stacking Ensemble with Sparse Behavioral Profiling**.

This solution structurally evolves the previous "Multi-Paradigm Stacking" approach (Idea 3) by introducing a third, dedicated "Behavioral" view. This view elevates the user's subreddit posting history from a simple metadata count to a high-fidelity sparse feature set, applying the "Lexical Specificity" lesson to user behavior.

# Model

The architecture is a **Stacking Ensemble** composed of three "Level 1" base learners, each targeting a specific modality of the data (Lexical, Semantic, Behavioral), feeding into a "Level 2" meta-learner.

**Level 1: Base Learners**
1.  **Lexical Bagger (Sparse Text View):** A **Random Forest Classifier** trained on **TF-IDF** vectors of the request text concatenated with **User Metadata**.
    *   *Retention:* Random Forests on sparse TF-IDF features consistently provided the strongest predictive signal, outperforming dense embeddings for capturing specific high-impact keywords (Cite 00013, Cite 00005).
2.  **Semantic Bagger (Dense Text View):** A **Random Forest Classifier** trained on **Frozen SBERT Embeddings** of the request text concatenated with **User Metadata**.
    *   *Retention:* We retain this branch to capture high-level intent and sentiment. We strictly use **frozen embeddings** rather than fine-tuning to avoid the severe overfitting observed with end-to-end transformers on this small dataset (Cite 00015). We segregate this into its own branch to prevent the high-dimensional sparse features from drowning out the dense semantic signal (Cite 00009).
3.  **Behavioral Bagger (Sparse History View):** A **Random Forest Classifier** trained on **TF-IDF vectors of the Subreddit History** concatenated with **User Metadata**.
    *   *Innovation:* Instead of reducing subreddit history to a count or a dense SVD vector (which XGBoost struggled with in Idea 5), we treat the list of `requester_subreddits_at_request` as a "bag-of-communities" text document.
    *   *Rationale:* Subreddits act as "behavioral keywords" (e.g., posting in "frugal" vs. "gaming"). Applying the lesson that **Bagging on Sparse features outperforms Boosting on Dense features** for this dataset (Cite 00005, Cite 00013), we model this view using the same robust Sparse-RF architecture as the Lexical view.

**Level 2: Meta-Learner**
*   **Stacking Classifier:** A **Logistic Regression** model that takes the probability outputs of the three base learners as input features.
    *   *Retention:* Stacking with a linear meta-learner effectively calibrates the ensemble, automatically assigning weights based on the competence of each view (Cite 00012).

# Data

The data pipeline enforces strict leakage prevention and generates three distinct feature sets:

1.  **Leakage Prevention:**
    *   Select `request_text_edit_aware` as the source text to remove post-hoc edits indicating success (Cite 00003).
    *   Rigorously exclude all columns suffixed with `_at_retrieval` to ensure temporal validity.
2.  **Feature Engineering:**
    *   **Lexical Features:** Generate a **TF-IDF Matrix** (Unigrams/Bigrams, Top 3,000) from the request text.
    *   **Semantic Features:** Extract **Frozen Embeddings** (384-dim) using a pre-trained Sentence-BERT model (e.g., `all-MiniLM-L6-v2`).
    *   **Behavioral Features:** Flatten the `requester_subreddits_at_request` list into a space-separated string. Generate a **TF-IDF Matrix** (Unigrams, Top 1,000) from these strings.
    *   **Metadata:** Include `requester_account_age`, `requester_upvotes_minus_downvotes`, and derived temporal features (`request_hour`, `day_of_week`). **Crucially**, ensure all derived features are explicitly added to the configuration allow-list to prevent silent dropping (Cite 00007).
3.  **Preprocessing:**
    *   Impute missing numerical values with the median.
    *   Apply `StandardScaler` only to the inputs of the Level 2 Logistic Regression (if necessary), but not to the tree-based Level 1 models.

# Training

The training procedure utilizes **5-Fold Cross-Validation Stacking** to prevent data leakage during ensemble construction:

1.  **Fold Generation:** Split the training data into 5 stratified folds.
2.  **Level 1 Training (OOF Generation):**
    *   **Lexical RF:** Train on 4 folds, predict on the 5th. Use `class_weight='balanced'` to handle the ~25% positive class prevalence.
    *   **Semantic RF:** Train on 4 folds, predict on the 5th. Use `class_weight='balanced'`.
    *   **Behavioral RF:** Train on 4 folds, predict on the 5th. Use `class_weight='balanced'`.
3.  **Level 2 Training:** Train the Logistic Regression meta-learner on the matrix of Out-Of-Fold (OOF) predictions from all three branches.
4.  **Final Retraining:** Retrain all Level 1 models on the full training dataset. Retrain the Level 2 model on the full OOF matrix.

# Evaluation

For the test set:
1.  Process the test data to generate Lexical (Text TF-IDF), Semantic (Text Embeddings), and Behavioral (Subreddit TF-IDF) features using the transformers fitted on the training set.
2.  Pass the specific feature subsets to their respective Level 1 models to obtain three probability scores per sample.
3.  Feed these three probabilities into the trained Level 2 Meta-Learner.
4.  The output of the Meta-Learner is the final predicted probability for `requester_received_pizza`.
