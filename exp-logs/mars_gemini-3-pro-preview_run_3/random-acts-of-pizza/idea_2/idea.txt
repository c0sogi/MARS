# Solution Proposal: Multi-View Hybrid Ensemble with Semantic Embeddings

### Model
I propose a **Multi-View Hybrid Ensemble** that aggregates predictions from three distinct modeling paradigms to capture lexical, semantic, and metadata signals simultaneously. This architecture structurally evolves the previous "Hybrid Ensemble" (Cite 00006) by introducing a dedicated semantic branch and expanding the feature scope.

The ensemble consists of three parallel estimators combined via **Soft Voting** (averaging predicted probabilities):
1.  **Lexical-Linear Branch (Regularization):** A **Logistic Regression** model trained on TF-IDF vectors. This component provides a high-bias, linear baseline that effectively captures strong keyword associations (e.g., "paycheck", "job") and acts as a regularizer against overfitting (Cite 00006).
2.  **Lexical-Tree Branch (Interaction):** A **Random Forest Classifier** trained on a concatenated feature set of TF-IDF vectors and dense metadata. This component retains the successful baseline approach (Cite 00005), leveraging the robustness of Bagging on high-dimensional sparse data to model non-linear interactions between specific words and user statistics.
3.  **Semantic-Tree Branch (Innovation):** A **Random Forest Classifier** trained on **Pre-trained Transformer Embeddings** (dense vectors) concatenated with dense metadata. Unlike TF-IDF, which relies on exact word matching, this branch utilizes a pre-trained Sentence Transformer (e.g., `all-MiniLM-L6-v2`) to capture the *semantic intent* and emotional tone of the request (e.g., distinguishing between "urgent hunger" and "casual craving" even if vocabularies differ).

### Data
The data processing pipeline will be upgraded to support this multi-view approach while strictly adhering to anti-leakage protocols:

1.  **Leakage Prevention:** Explicitly use `request_text_edit_aware` instead of `request_text` to remove post-hoc edits indicating success (Cite 00003). Drop all columns suffixed with `_at_retrieval`.
2.  **Feature Engineering:**
    *   **Textual:** Concatenate `request_title` and `request_text_edit_aware`.
    *   **Subreddits:** Flatten the `requester_subreddits_at_request` list into a space-separated string and treat it as a secondary text corpus for TF-IDF to capture community-based signals.
    *   **Embeddings:** Pass the concatenated text through a pre-trained Transformer model to generate a fixed-size dense vector (e.g., 384 dimensions) for the Semantic Branch.
    *   **Metadata Expansion:** Generate derived numerical features including `request_hour`, `request_day_of_week`, `text_word_count`, and `title_word_count`. **Crucially**, verify that these newly generated feature names are explicitly added to the configuration allow-list to prevent the silent failure observed previously (Cite 00007).
3.  **Preprocessing:**
    *   Apply **TF-IDF Vectorization** (top 3,000 features, unigrams/bigrams) for Lexical branches.
    *   Apply **StandardScaler** to all dense features (metadata and embeddings) to ensure compatibility with the Logistic Regression component and to stabilize the ensemble (Cite 00006).
    *   Impute missing numerical values with the median.

### Training
The training procedure prioritizes stability and robustness:
*   **Split:** Use a stratified validation split (20%) to monitor performance.
*   **Class Balancing:** Apply `class_weight='balanced'` to all three estimators to address the ~25% positive class prevalence.
*   **Ensembling:** Train the three estimators independently on the same training fold. The final prediction is the unweighted average of the probability outputs from all three models. This combines the variance-reduction of Bagging (Random Forests) with the bias-reduction of the Linear model (Cite 00005, Cite 00006).

### Evaluation
For the test set:
1.  Generate all features (TF-IDF, Embeddings, Expanded Metadata) using the transformers fitted on the training set.
2.  Pass the processed data through the three distinct branches.
3.  Average the probability scores to produce the final `requester_received_pizza` prediction.
4.  The submission will be evaluated using the Area Under the ROC Curve (AUC).
