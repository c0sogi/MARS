The implementation strategy follows a strict pipeline to ensure reproducibility, correct validation, and robust submission generation.

1.  **Setup & Data Loading**: We initialize random seeds and load the `train`, `val`, and `test` datasets separately using the provided `data_loader`. We explicitly avoid mixing `val` into the training set to preserve it for the required hold-out metric calculation.
2.  **Feature Engineering**: The `FeatureFactory` is fitted solely on the `train` dataset to prevent data leakage.
3.  **Training**: The `HybridTrainer` is used to train the Level 1 base learners (using Stratified K-Fold on `train`) and the Level 2 Meta-Learner (using OOF predictions). This adheres to the stacking architecture described.
4.  **Validation**: We use the `HybridPredictor` to generate probabilities for the `val` set. Since the predictor internally caches features under the "test" key, we perform a cache cleanup before and after this step to avoid collisions with the actual test set. The `Final Validation Metric` is computed and printed.
5.  **Failure Analysis**: We analyze the correlation between the model's absolute errors on the validation set and the dense metadata features to identify systematic weaknesses.
6.  **Submission**: If the validation AUC exceeds the specified threshold, we clear the cache one last time and generate the final submission for the `test` set.
