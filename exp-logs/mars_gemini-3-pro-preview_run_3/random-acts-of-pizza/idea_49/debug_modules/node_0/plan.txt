Here is the implementation strategy and the complete Python script.

### Implementation Strategy

1.  **Configuration & Setup**:
    -   Import the necessary library modules (`Config`, `DataLoader`, `FeaturePipeline`, `ModelFactory`, `TrainingEngine`, `InferenceEngine`).
    -   Define a temporary working directory (`./working/demo_run`) to store intermediate files and models, ensuring we don't clutter the main environment.
    -   Set a fixed random seed for reproducibility.

2.  **Data Subsetting for Speed**:
    -   Load the original metadata files (`train.parquet`, `val.parquet`, `test.parquet`) from `./metadata`.
    -   Create extremely small subsets (e.g., 20 samples each) to ensure the demonstration runs in seconds rather than minutes.
    -   Save these subsets to the temporary working directory.

3.  **Runtime Configuration Overrides**:
    -   Monkey-patch the `Config` class attributes to point to the new subset data paths and the temporary working directory.
    -   Drastically reduce model hyperparameters (e.g., `n_estimators=2`, `max_depth=2`, `n_folds=2`) and feature extraction limits (e.g., `max_features=50`) to minimize computational overhead while preserving the pipeline's logic.

4.  **Pipeline Execution & Verification**:
    -   **Data Loading**: Instantiate `DataLoader` and verify it loads the subset data correctly.
    -   **Feature Engineering**: Instantiate `FeaturePipeline` and trigger feature generation. Verify the output shapes match the subset sizes and expected feature dimensions.
    -   **Model Factory**: Smoke-test the `ModelFactory` to ensure it returns the correct sklearn/xgboost/lightgbm objects.
    -   **Training**: Instantiate `TrainingEngine` and run the full training loop (Level 1 base learners + Level 2 meta-learner). Verify that model files and OOF predictions are saved.
    -   **Inference**: Instantiate `InferenceEngine` and run the inference pipeline. Verify that the final submission file is generated and follows the required format.

5.  **Cleanup**:
    -   The script relies on the `./working` directory which is scratch space, so explicit cleanup isn't strictly necessary, but the code is structured to be self-contained.
