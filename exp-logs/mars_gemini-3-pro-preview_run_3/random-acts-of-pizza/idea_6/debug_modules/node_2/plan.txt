The issue is caused by the way configuration variables are imported in `library/data_loader.py` (and similarly in `library/feature_pipeline.py` and `library/stacking_engine.py`). By using `from library.config import DEBUG_SAMPLE_SIZE, ...`, the variables are bound to their values at import time. When `runfile.py` subsequently modifies `config.DEBUG_SAMPLE_SIZE` (monkey-patching), these changes are not reflected in the modules that have already imported the variables by value. This leads to `load_data` using the default sample size (200) instead of the patched one (50), causing the assertion failure.

To fix this, I will modify `library/data_loader.py`, `library/feature_pipeline.py`, and `library/stacking_engine.py` to import the entire `library.config` module and access the configuration variables as attributes (e.g., `config.DEBUG_SAMPLE_SIZE`). This ensures that any runtime updates to the configuration module are correctly propagated.
