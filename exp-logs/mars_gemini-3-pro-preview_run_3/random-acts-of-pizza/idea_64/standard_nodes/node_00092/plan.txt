The issue is that the pipeline uses a "Union Dataset" strategy (merging train and validation sets) to maximize training data, but then attempts to evaluate the trained models on the original validation set. Since the validation samples were included in the training process, this constitutes data leakage, resulting in an invalid, inflated metric (~0.9995 AUC) and triggering the `InvalidMetricValueError`.

To fix this, I will:
1.  Update `library/training_engine.py` to return the Out-of-Fold (OOF) AUC from the `run()` method. This OOF AUC is calculated during cross-validation on data the model hasn't seen in that specific fold, making it a valid generalization metric even when the final model is retrained on the full dataset (Cite debug_lesson_9).
2.  Refactor `runfile.py` to use this returned OOF AUC for validation instead of performing a separate, leaky evaluation on the hold-out set.
3.  Remove the configuration overrides in `runfile.py` to restore the "High-Fidelity" model complexity, ensuring the OOF AUC is maximized.
