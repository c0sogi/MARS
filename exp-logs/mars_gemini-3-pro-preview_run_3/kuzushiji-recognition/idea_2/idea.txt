Based on the analysis of the previous "Sparse-Query CenterNet" approach and the derived lessons, I propose a structural evolution to a **Decoupled Two-Stage Recognition Pipeline**.

### Model
I propose splitting the problem into two distinct, specialized stages to address the high-cardinality bottleneck identified in previous attempts.

1.  **Stage 1: Class-Agnostic Keypoint Detector (Modified CenterNet)**
    *   **Architecture:** Retain the **ResNet-18 backbone with FPN** from the previous idea as it proved effective for localization.
    *   **Heads:** Instead of predicting class embeddings, modify the heads to perform pure **Class-Agnostic Detection**:
        *   **Heatmap Head (1 channel):** Predicts a binary "textness" probability map to locate character centers.
        *   **Offset Head (2 channels):** Refines sub-pixel center coordinates.
        *   **Size Head (2 channels):** **New addition.** Regresses the Width and Height of the character bounding box at each center location. This is essential to generate accurate regions for the second stage.
    *   **Rationale:** This removes the burden of distinguishing 3,848 classes from the detector's lightweight feature map, allowing it to focus entirely on robust localization.

2.  **Stage 2: Dedicated Character Classifier**
    *   **Architecture:** A separate, higher-capacity CNN (e.g., **ResNet-34** or **EfficientNet-B0**) designed to classify cropped character images.
    *   **Input:** Fixed-resolution image crops (e.g., $64 \times 64$) centered on the keypoints detected by Stage 1.
    *   **Output:** A probability vector over the 3,848 Unicode classes.
    *   **Rationale:** This directly addresses the "High-Cardinality Bottleneck" by allocating a dedicated deep network to resolve fine-grained character differences, ensuring the feature dimensionality matches the label complexity. Cite solution_lesson_node_00001

### Data
The data processing pipeline will be bifurcated to support the two-stage model:

1.  **Detector Data (Page-Level):**
    *   **Input:** Full page images resized to a fixed dimension (e.g., $1024 \times 1024$) with padding.
    *   **Target:** A class-agnostic Gaussian heatmap (all characters = 1, background = 0) and dense regression maps for offsets and box sizes (width/height).
    *   **Augmentation:** Apply dynamic geometric augmentations (Random Scaling, Shifting, and Rotation) to prevent overfitting to spatial templates. Cite solution_lesson_node_00006. However, strictly limit rotation to a narrow range (e.g., $\pm 15^\circ$) to respect the inherent structural alignment of the document text. Cite solution_lesson_node_00007

2.  **Classifier Data (Crop-Level):**
    *   **Generation:** Pre-process the training set by using the ground truth bounding boxes to extract individual character crops. Resize these crops to $64 \times 64$ pixels.
    *   **Augmentation:** Apply character-specific augmentations such as slight rotation ($\pm 10^\circ$), brightness/contrast jitter, and random erasing to encourage robustness against noise and paper texture.

### Training
The models will be trained independently to maximize stability:

1.  **Detector Training:**
    *   **Loss:** Use **Modified Focal Loss** for the heatmap to handle the background/foreground imbalance and **L1 Loss** for the offset and size regression heads.
    *   **Optimization:** Train for ~30-50 epochs using AdamW.

2.  **Classifier Training:**
    *   **Loss:** Use **Cross Entropy Loss**. To handle the extreme class imbalance (some characters appear only once), implement a **Class-Balanced Sampler** or weighted loss to ensure rare characters are seen frequently during training.
    *   **Optimization:** Train on the crop dataset. Since this is a standard classification task, convergence should be reliable.

### Evaluation
The inference process will follow a sequential pipeline:
1.  **Detection:** Pass the test image through the Stage 1 Detector to generate a heatmap and size map.
2.  **Keypoint Extraction:** Extract the top $K$ peaks (e.g., $K=1200$) from the heatmap and retrieve their corresponding sizes and offsets.
3.  **Cropping:** Use the predicted center $(X, Y)$ and size $(W, H)$ to crop character regions from the *original high-resolution test image*.
4.  **Classification:** Batch these crops and pass them through the Stage 2 Classifier to obtain the specific Unicode labels.
5.  **Submission:** Combine the predicted center coordinates from Stage 1 with the labels from Stage 2 to format the submission string.
