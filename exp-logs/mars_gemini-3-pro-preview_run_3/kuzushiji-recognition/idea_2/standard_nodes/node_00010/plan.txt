The implementation strategy follows a decoupled two-stage approach:
1.  **Initialization**: We import all necessary modules and set the random seed and device using the `Config` class to ensure reproducibility.
2.  **Configuration Override**: To ensure the "fast baseline" requirement is met and the script completes within the 2-hour limit, we programmatically adjust `Config.DETECTOR_EPOCHS` to 10 and `Config.CLASSIFIER_EPOCHS` to 5.
3.  **Preprocessing**: We call `prepare_classifier_data` for both training and validation splits. This function pre-crops characters from the pages and saves them to disk, which is essential for efficient training of the second-stage classifier.
4.  **Detector Training**: We initialize the `CenterNetDetector` and `KuzushijiDetectorDataset`. The detector is trained to locate character centers and regress their bounding box sizes using the `train_detector` engine.
5.  **Classifier Training**: We initialize the `CharacterClassifier` and `KuzushijiCropDataset`. The classifier is trained on the pre-generated crops to identify the specific Unicode character using the `train_classifier` engine.
6.  **Validation**: We implement a custom `validate_pipeline` function. This function mimics the inference process on the validation set: it runs the detector, transforms coordinates back to the original image space, extracts crops, runs the classifier, and finally computes the modified F1 score using `f1_score_calc`.
7.  **Failure Analysis**: Within the validation loop, we collect performance statistics per image. We then calculate and print correlations between the error rate (1 - F1) and image metadata (number of characters, area, aspect ratio) to identify systematic failure modes.
8.  **Submission**: Finally, we check if the computed validation metric exceeds the threshold of `0.5505656207057533`. If it does, we instantiate the `InferencePipeline` to generate predictions for the test set and save them to `submission.csv`.
