Based on the task requirements and the provided model architectures, I propose a highly efficient baseline approach derived from the **Keypoint-based CNN (Model 1)** concept. This solution is adapted to handle the large number of classes (3,848) without the computational overhead of a dense classification map.

### **Model: Sparse-Query CenterNet**

The architecture is a streamlined, one-stage detector designed to predict character points and their classes directly.
*   **Backbone**: Use a **ResNet-18** pre-trained on ImageNet as the feature extractor. It provides a good balance between speed and feature hierarchy.
*   **Neck**: A simple **Feature Pyramid Network (FPN)** or a series of deconvolution layers to upsample the backbone features to $1/4$ of the input resolution. This high-resolution feature map is crucial for distinguishing small, adjacent characters.
*   **Heads**: The model branches into three lightweight outputs:
    1.  **Heatmap Head (1 channel)**: Predicts a class-agnostic "textness" score. It outputs a probability map where peaks represent the centers of characters.
    2.  **Offset Head (2 channels)**: Predicts the local sub-pixel offset $(\Delta x, \Delta y)$ to correct the quantization error caused by the output stride.
    3.  **Classification Embedding Head (64 channels)**: Instead of a massive 3,848-channel output map, this head outputs a dense feature vector for each pixel.
*   **Sparse Classification Module**: During both training and inference, the model identifies the top-$K$ peaks from the Heatmap Head. It then samples the feature vectors from the Embedding Head at these specific peak coordinates. These sampled vectors are passed through a shared **Linear Classifier (MLP)** to predict the final class label (1 of 3,848). This "point-query" approach drastically reduces memory usage and computation compared to a dense classification grid.

### **Data**

*   **Preprocessing**:
    *   **Resizing**: Resize all images to a fixed dimension (e.g., $1024 \times 1024$) while preserving the aspect ratio. Pad the shorter side with zeros (black) to maintain the grid alignment.
    *   **Normalization**: Normalize pixel values using standard ImageNet mean and standard deviation.
*   **Target Generation**:
    *   **Heatmap**: Generate a ground truth heatmap where each character center is a peak of a 2D Gaussian kernel. The radius of the Gaussian is determined by the character's bounding box size.
    *   **Offsets**: Calculate the difference between the exact floating-point center and the discretized integer coordinate on the $1/4$ resolution grid.
    *   **Labels**: Map each Unicode string to an integer index ($0$ to $3847$).

### **Training**

*   **Loss Functions**:
    *   **Heatmap**: Use **Modified Focal Loss** to handle the extreme class imbalance between character centers (positives) and background pixels (negatives).
    *   **Offset**: Use **L1 Loss** (or Smooth L1) to minimize the error in center point prediction.
    *   **Classification**: Use **Cross Entropy Loss**, applied *only* at the ground truth center locations.
*   **Strategy**:
    *   Train for a fixed number of epochs (e.g., 30-50) using the **AdamW** optimizer.
    *   Use a learning rate scheduler (e.g., Cosine Annealing) to stabilize convergence.
    *   Since the dataset is moderate (~3,000 images), aggressive augmentation is avoided to keep the baseline simple, but random horizontal flips are **disabled** (as text orientation matters).

### **Evaluation**

1.  **Forward Pass**: Input the test image to generate the Heatmap, Offset, and Embedding maps.
2.  **Peak Extraction**: Apply a $3 \times 3$ Max Pooling operation on the Heatmap to find local maxima.
3.  **Thresholding**: Select the top $K$ peaks (e.g., $K=1200$, matching the submission limit) that exceed a confidence threshold (e.g., 0.1).
4.  **Point Refinement**: Add the predicted offsets to the integer grid coordinates of the selected peaks to get precise locations.
5.  **Classification**: Extract the embedding vectors at the selected peak coordinates and pass them through the MLP to get the class labels.
6.  **Rescaling**: Map the coordinates back to the original image size and format the output as `image_id, {label X Y} ...`.
