The issue is that the `KuzushijiDetector` model in `library/models.py` is initializing the `timm` backbone with `out_indices=(0,)`, which extracts the feature map at stride 2 (1/2 resolution). However, the configuration (`Config.DETECTOR_OUTPUT_STRIDE = 4`) and the verification logic in `runfile.py` expect a stride-4 feature map (1/4 resolution). This mismatch caused the `AssertionError` where the output shape was double the expected size (256x256 instead of 128x128 for a 512x512 input). To fix this, I will update `out_indices` to `(1,)` to select the stride-4 feature map, ensuring the model output dimensions align with the pipeline requirements.
