The issue identified is a CUDA device-side assertion triggered by an index out-of-bounds error. This occurs because the `Voxelizer` calculates grid coordinates using floating-point division (`(point - min) / size`) and then casts to long. Due to floating-point precision, points at the exact upper boundary of the range (or slightly beyond due to representation error) can result in an index equal to the grid size (e.g., 768 instead of max index 767), causing a crash when `PointPillarsScatter` attempts to write to the canvas.

To fix this, I will modify `library/utils.py` to explicitly clamp the calculated voxel coordinates to the valid range `[0, grid_size - 1]` before they are used to generate pillar keys. This ensures that any boundary-condition points are mapped to the last valid voxel instead of overflowing the grid. I will cite **debug_lesson_8** regarding robust grid indexing.
