Based on the analysis of the previous failures and the specific insights from the provided lessons, I propose a **Two-Stage PointPillars Detector with BEV-RoI Refinement**.

This strategy structurally evolves the "Current Best" single-stage baseline (Idea 7) into a **Two-Stage** architecture. It integrates the stability of anchor-free detection (Stage 1) with the precision of feature-based refinement (Stage 2), explicitly rejecting the flawed geometric heuristics and risky multi-sweep pipelines of previous attempts.

# Model
The architecture consists of a Proposal Stage (Stage 1) and a Refinement Stage (Stage 2), designed to progressively resolve object geometry.

1.  **Encoder & Backbone (Retained):**
    *   We utilize the **PointPillars Encoder** to discretize the single-frame point cloud into a pseudo-image.
    *   We employ a **ResNet-FPN Backbone** to extract multi-scale semantic features. This deep learned representation is critical for identifying objects based on context (e.g., road boundaries, partial occlusion) rather than just density, addressing the "L-shape" failure of geometric clustering **Cite solution_lesson_node_00005**.
2.  **Stage 1: Anchor-Free Proposal Head (CenterHead):**
    *   Instead of an SSD head (which caused optimization instability **Cite solution_lesson_node_00008**), we use a **CenterHead**.
    *   This head predicts a **Heatmap** for object centers and coarse **Regression Maps** (log-dimensions, rotation, offsets).
    *   The output of this stage is a set of high-confidence 3D bounding box proposals.
3.  **Stage 2: BEV-RoI Refinement Module (Structural Innovation):**
    *   **RoI Extraction:** We project the 3D proposals from Stage 1 onto the 2D Bird's Eye View (BEV) feature map produced by the backbone. Using **RoI Align** (or grid sampling), we extract a fixed-size feature patch (e.g., $7 \times 7$) corresponding to each proposal.
    *   **Refinement Network:** These feature patches are passed through a lightweight MLP (Multi-Layer Perceptron).
    *   **Residual Prediction:** The network predicts a second set of residuals $(\delta x, \delta y, \delta z, \delta w, \delta l, \delta h, \delta \theta)$ to fine-tune the Stage 1 boxes.
    *   **Rationale:** While Stage 1 is robust, it relies on a single point (the center) to regress the entire box. Stage 2 "looks" at the entire spatial extent of the object's features, allowing it to correct misalignment caused by occlusion—solving the "PCA misalignment" issue using learned features instead of geometric heuristics **Cite solution_lesson_node_00005**.

# Data
The data pipeline is strictly designed for coordinate integrity and optimization stability.

1.  **Single-Sweep Processing:**
    *   We will use **only the current Lidar sweep**. We explicitly reject the multi-sweep temporal aggregation pipeline.
    *   **Rationale:** Previous attempts at multi-sweep integration failed due to coordinate frame mismatches (Global $\to$ Ego $\to$ Sensor) **Cite solution_lesson_node_00014**. By using raw, single-frame data, we guarantee geometric consistency between inputs and ground truth.
2.  **Target Normalization:**
    *   **Log-Space Dimensions:** Ground truth dimensions are log-transformed ($\log(x)$) for both Stage 1 and Stage 2 targets. This prevents the exploding gradients caused by unnormalized regression targets **Cite solution_lesson_node_00008**.
    *   **Proposal Matching:** For Stage 2 training, we sample Stage 1 proposals that have high IoU with ground truth and regress the difference.

# Training
1.  **Loss Functions:**
    *   **Stage 1 Loss:** Gaussian Focal Loss (Heatmap) + Masked L1 Loss (Initial Regression).
    *   **Stage 2 Loss:** L1 Loss applied to the residuals between the Proposal box and the Ground Truth box.
    *   **Total Loss:** Weighted sum of Stage 1 and Stage 2 losses.
2.  **Optimizer:**
    *   **AdamW** with a **One-Cycle Learning Rate Policy** to ensure rapid convergence within the 24-hour limit.

# Evaluation
1.  **Inference:**
    *   **Step 1:** The model generates dense heatmap predictions. Top $K$ peaks are decoded into initial 3D boxes.
    *   **Step 2:** We apply Non-Maximum Suppression (NMS) to remove overlapping Stage 1 proposals.
    *   **Step 3:** The surviving boxes are projected to the feature map, their features are extracted, and the Refinement Module updates their coordinates and dimensions.
    *   **Step 4:** Final predictions are formatted for submission.
