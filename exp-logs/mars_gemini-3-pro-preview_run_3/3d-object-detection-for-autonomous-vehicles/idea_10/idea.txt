Based on the progression of experiments and the critical lessons learned, I propose a **High-Resolution Two-Stage PointPillars Detector with Multi-Scale Refinement and Verified Augmentation**.

This strategy structurally evolves the successful "Idea 8" (Two-Stage PointPillars) by addressing the resolution bottleneck identified in "Idea 9" (Lesson 00021) and safely reintegrating the data augmentation techniques that previously failed due to alignment issues (Lesson 00014).

# Model

The architecture is designed to maximize precision through high-resolution input processing and a sophisticated second-stage refinement module that leverages multi-scale features.

1.  **High-Resolution Pillar Encoder (Structural Adjustment):**
    *   We utilize the **PointPillars Encoder** but strictly enforce a fine voxel resolution (e.g., $0.08m \times 0.08m$).
    *   **Rationale:** Previous experiments proved that coarse voxelization (e.g., $0.5m$) creates a hard ceiling on performance by introducing quantization noise that makes high-IoU matches mathematically impossible **Cite solution_lesson_node_00021**. A fine grid is a prerequisite for the high-precision metric (mAP @ IoU 0.5-0.95).
2.  **ResNet-FPN Backbone (Retained):**
    *   We employ a **ResNet Backbone with a Feature Pyramid Network (FPN)**. This provides a rich, multi-scale feature representation (e.g., strides 4, 8, 16), capturing both fine geometric details and broad semantic context **Cite solution_lesson_node_00005**.
3.  **Stage 1: Anchor-Free Proposal Head (Retained):**
    *   We use the **CenterHead** to generate class-agnostic object proposals via heatmap peak extraction. This avoids the optimization instability and gradient explosions associated with anchor-based methods **Cite solution_lesson_node_00008**.
4.  **Stage 2: Multi-Scale RoI Fusion & Rectification (Structural Innovation):**
    *   **Multi-Scale RoI Align:** Instead of sampling features from a single BEV map (as in Idea 8), we project the Stage 1 proposals onto *multiple* levels of the FPN (e.g., P3, P4, P5). We use **Rotated RoI Align** to extract features at each scale and concatenate them. This ensures that the refinement stage has access to both high-resolution texture (for precise localization) and large receptive fields (for context) **Cite solution_lesson_node_00018**.
    *   **IoU Rectification Branch:** We integrate the **IoU Prediction Head** proposed in Idea 9. This branch predicts the expected IoU of the refined box with the ground truth, allowing us to down-weight false positives that have high classification scores but poor geometric fit.

# Data

The data pipeline prioritizes geometric integrity while re-introducing necessary augmentation under strict validation.

1.  **Single-Sweep Processing:**
    *   We use **only the current Lidar sweep**. We explicitly reject multi-sweep temporal aggregation to guarantee that input points and ground truth annotations exist in the exact same coordinate frame, avoiding the silent misalignment failures observed previously **Cite solution_lesson_node_00014**.
2.  **Verified Ground Truth Sampling (Process Innovation):**
    *   We apply **GT Database Sampling (Copy-Paste Augmentation)** to address object sparsity.
    *   **Geometric Unit Test:** To preventing the "empty database" failure, we implement a strict pre-processing check. Before training, we generate the database and programmatically verify that every cropped object contains a non-zero number of points. Any empty or misaligned boxes are discarded immediately. This allows us to safely use augmentation to learn object shapes without confusing the model with empty space **Cite solution_lesson_node_00014**.
3.  **Target Normalization:**
    *   We continue to use **Log-Space Dimensions** for regression targets to compress the dynamic range and prevent loss divergence **Cite solution_lesson_node_00008**.

# Training

1.  **Loss Functions:**
    *   **Stage 1:** Gaussian Focal Loss (Heatmap) + Masked L1 Loss (Proposal Regression).
    *   **Stage 2 Refinement:** L1 Loss applied to the residuals between the Proposal box and the Ground Truth.
    *   **Stage 2 Rectification:** Binary Cross Entropy (BCE) Loss on the predicted IoU, targeting the true calculated IoU.
2.  **Optimizer:**
    *   **AdamW** with a **One-Cycle Learning Rate Policy**. This schedule warms up the learning rate to stabilize the initial gradients before aggressive training, fitting the runtime constraints.

# Evaluation

1.  **Inference:**
    *   **Step 1:** Generate dense proposals using the CenterHead.
    *   **Step 2:** Extract Multi-Scale RoI features for the top proposals.
    *   **Step 3:** Pass features through the Refinement Module to update box coordinates.
    *   **Step 4 (Rectification):** Multiply the Stage 1 classification confidence by the Stage 2 predicted IoU ($Score_{final} = Score_{cls} \times IoU_{pred}^{\alpha}$).
    *   **Step 5:** Perform final Non-Maximum Suppression (NMS) using the rectified scores to generate the submission.
