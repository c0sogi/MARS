The strategy to generate the metadata files involves the following steps:

1.  **Data Loading**: Load the `train.csv` and `sample_submission.csv` files to identify the samples. Load the JSON tables (`sample.json`, `sample_data.json`) from both `train_data` and `test_data` directories to link sample identifiers (`sample_token`) to file paths and scene identifiers (`scene_token`).
2.  **Path Construction**: Map each `sample_token` to its corresponding LIDAR file path. The script will parse `sample_data.json` to find entries with `.bin` extension (LIDAR data) associated with each sample. It will construct the relative path by appending the filename (basename) to the respective directory (`train_lidar` or `test_lidar`).
3.  **Grouped Splitting**: To create a validation set that respects the temporal correlation of the data, the script will group training samples by `scene_token`. It will then use `GroupShuffleSplit` to create an 80:20 train/validation split, ensuring that all frames from a single scene end up in the same split to prevent data leakage.
4.  **Metadata Generation**: Create three DataFrames (`train`, `val`, `test`) containing `sample_token`, `lidar_path`, `label` (for train/val), and `scene_token` (for verification). These will be saved as CSV files in the `./metadata` directory.
5.  **Validation**: The script will perform post-generation checks:
    *   **Summary Statistics**: Print counts of samples and unique scenes.
    *   **File Existence**: Randomly check 1000 generated file paths to ensure they point to existing files in `./input`.
    *   **Leakage Check**: Verify that the set of `scene_token`s in training and validation sets are disjoint.
