The `torch.OutOfMemoryError` is caused by expanding the feature map `(1, C, H, W)` to match the number of proposals `(K, C, H, W)` in `RoIHead.get_roi_features`. While PyTorch's `expand` is memory-efficient in the forward pass, the backward pass for `F.grid_sample` computes gradients for the expanded batch size, resulting in massive memory consumption (approx. 70GB for 64 proposals).

To fix this, I will modify `library/model_blocks.py` to reshape the sampling grid instead of expanding the feature map. By treating the $K$ proposals as a single "tall" grid applied to the original feature map (batch size 1), we ensure the backward pass only allocates gradients for a single image, significantly reducing memory usage.
