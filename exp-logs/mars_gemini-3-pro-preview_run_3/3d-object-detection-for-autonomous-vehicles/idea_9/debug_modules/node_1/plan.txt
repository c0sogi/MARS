The `ValueError: cannot reshape array of size 301205 into shape (4)` occurs because the raw LIDAR data contains 5 features per point (likely x, y, z, intensity, ring_index/timestamp) instead of the expected 4, causing the total number of elements to be divisible by 5 but not 4. To fix this, I will update the data loading logic in both `LidarDataset.__getitem__` and `GTDatabase._generate_database` to detect the feature stride dynamically. If the data size is divisible by 5, the code will reshape it to `(N, 5)` and slice the first 4 columns to match `Config.NUM_POINT_FEATURES`; otherwise, it will proceed with the default 4-feature reshape. This applies the principle of validating binary dimensions before reshaping (Cite debug_lesson_4).
