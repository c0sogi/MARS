The issue is caused by a class distribution mismatch between the subsampled training and validation sets. Specifically, the rare class `emergency_vehicle` (ID 9) appears in the validation set but was completely absent from the subsampled training set. When LightGBM attempts to evaluate the model on the validation set, its internal label encoder encounters this unseen label and raises a `ValueError`. The fix is to filter the validation set within `library/lgbm_model.py` to ensure it only contains class labels that are present in the training set before passing it to the `fit` method.
