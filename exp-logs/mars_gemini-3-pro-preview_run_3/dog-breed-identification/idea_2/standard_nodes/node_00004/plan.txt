Here is the implementation strategy and the complete `runfile.py` script.

### Implementation Strategy

1.  **Configuration Override**: To ensure the solution runs as a "fast baseline" within the time limit while utilizing the powerful A100 GPU, we will override the default `Config` parameters. We will set `FINE_TUNE_EPOCHS` to 5 (down from 50) and `WARMUP_EPOCHS` to 1. This provides enough training to potentially meet the metric threshold without running for hours.
2.  **Training Orchestration**: We will call `library.train.run_training()` to execute the two-phase transfer learning pipeline. This handles data loading, model initialization, warm-up, and fine-tuning, saving the best model to `./working/best_model.pth`.
3.  **Validation & Metric Calculation**:
    *   We will reload the validation dataset and the best saved model.
    *   We will perform inference on the full validation set to obtain predictions.
    *   We will calculate the **Multi Class Log Loss** using `library.utils.calculate_log_loss` and print it strictly in the required format: `Final Validation Metric: <value>`.
4.  **Failure Analysis**:
    *   We will calculate the per-sample Log Loss (error magnitude) for each validation image.
    *   We will extract metadata features (File Size, Width, Height) from the validation images on disk.
    *   We will compute and print the Pearson correlation between the error magnitude and these features to identify potential biases (e.g., does the model fail on smaller or larger images?).
5.  **Submission Generation**:
    *   We will compare the calculated validation metric against the threshold `0.5640784429467243`.
    *   If the model performs well enough, we will invoke `library.predict.generate_submission()` to create the submission file for the test set.
