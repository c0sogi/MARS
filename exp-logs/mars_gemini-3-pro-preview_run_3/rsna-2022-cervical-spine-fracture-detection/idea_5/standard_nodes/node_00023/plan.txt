Based on the empirical findings in **Lesson ID: solution_lesson_node_00022**, the previous attempt to upgrade the backbone to ResNet34 failed because it forced a reduction in batch size (from 8 to 4) to fit in memory. This "micro-batch" regime caused training instability and poor generalization (Metric: 0.5331). The lesson explicitly states that a shallower model (ResNet18) with a stable batch size ($\ge 8$) is superior in this constrained environment.

Therefore, I will optimize the solution by:
1.  **Reverting the backbone to ResNet18** in `library/model.py` and `library/config.py`.
2.  **Increasing the Batch Size to 8** in `library/config.py` to stabilize Batch Normalization statistics and gradient updates.
3.  Updating the cache directory to ensure a clean run.

This strategy directly addresses the instability identified in the failure analysis while maintaining the effective architectural components (Sequence Smoothing, Hierarchical Loss) that previously yielded the target metric of ~0.1307.
