Based on the analysis of the provided lessons and the trajectory of previous experiments, I propose the following optimized strategy. This solution synthesizes the structural advantage of **Task-Adaptive Pretraining (TAPT)** with a robust, engineered fine-tuning pipeline that specifically resolves the conflicts between gradient update frequency, class imbalance, and inference logic identified in the failure modes of previous ideas.

# Model
**Architecture:**
I will utilize the **`xlm-roberta-base`** model (Cite solution_lesson_node_00004) as the backbone, given its superior capacity for multilingual understanding compared to distilled variants. The model will be architected as a **Token Classifier**, projecting hidden states into 3 classes (`B-ANS`, `I-ANS`, `O`).

**Structural Innovation: Stabilized Task-Adaptive Pretraining (TAPT)**
To bridge the domain gap while avoiding the engineering pitfalls of previous attempts, I will implement a rigorous two-stage training pipeline:
1.  **Adaptation (TAPT):** I will fine-tune the `xlm-roberta-base` model using a **Masked Language Modeling (MLM)** objective on the concatenation of the raw `context` text from both the Training and Test sets. This aligns the embeddings with the specific Hindi/Tamil vocabulary and syntax (Cite solution_lesson_node_00004).
2.  **Supervised Initialization:** The TAPT-adapted weights will serve as the initialization for the Question Answering model.

# Data
**Preprocessing:**
*   **Sliding Window:** The text will be tokenized and split into overlapping windows of **384 tokens** with a **stride of 128** (Cite solution_lesson_node_00002).
*   **Labeling (Soft Overlap):** I will strictly employ **Soft Overlap** labeling. A token will be labeled as positive (`B-ANS` or `I-ANS`) if it has *any* character overlap with the ground truth span. This corrects the "Strict Containment" flaw that previously deleted valid training signals (Cite solution_lesson_node_00017).
*   **Full Distribution:** I will retain **all** generated windows for training. I will **not** perform any negative downsampling, ensuring the model learns to suppress false positives by seeing the full background distribution (Cite solution_lesson_node_00011).
*   **Coupled Metadata:** I will implement a custom `collate_fn` to bundle necessary metadata (e.g., `offset_mapping`, `input_ids`) directly into the training batches. This prevents the inference failures caused by decoupled data streams in previous TAPT attempts (Cite solution_lesson_node_00018).

# Training
**Strategy:**
*   **Batch Size:** I will strictly utilize a **Batch Size of 16**. This specific value is the empirical "sweet spot" that balances the need for frequent gradient updates (Cite solution_lesson_node_00015) with the need for sufficient batch density to avoid gradient starvation (Cite solution_lesson_node_00020).
*   **Loss Function:** I will implement a **Class-Weighted Cross-Entropy Loss**. I will assign significantly higher weights to the `B-ANS` and `I-ANS` classes (inversely proportional to their frequency). This ensures that even in batches dominated by "O" tokens, the model receives a strong gradient signal for answer spans, preventing the "majority class collapse" observed in previous small-batch experiments (Cite solution_lesson_node_00020).
*   **Ensembling:** I will train **3 independent model instances** using different random seeds to mitigate the high variance inherent in this low-resource task (Cite solution_lesson_node_00008).
*   **Duration:** Each model will be fine-tuned for **10 epochs** to accommodate the "delayed onset" of convergence (Cite solution_lesson_node_00005).

# Evaluation
**Inference Pipeline:**
1.  **Global Confidence Aggregation (Per Model):** For a given document, the model will process **all** overlapping windows. Instead of a greedy first-match approach (which locks in early false positives), the model will collect all candidate spans across the entire document and select the single span with the **highest confidence score** (Cite solution_lesson_node_00016).
2.  **Self-Contained Decoding:** Answer strings will be decoded directly from the predicted token IDs using the tokenizer, ensuring robustness against offset mapping errors (Cite solution_lesson_node_00018).
3.  **Majority Voting (Ensemble):** The final prediction will be determined by a **Majority Vote** on the exact string outputs from the 3 models. This avoids the "smearing" artifacts caused by averaging raw token probabilities (Cite solution_lesson_node_00009).
