The issue is a data alignment bug in the validation pipeline. The `process_data` function drops samples from the validation set when the answer text cannot be found in the context sentences (using `find_gold_sentence`), causing the `DataLoader` to have fewer samples than the original validation DataFrame. Since the `Trainer` iterates over the `DataLoader` while slicing the DataFrame sequentially, predictions are compared against the wrong ground truth. Additionally, using `find_gold_sentence` for validation is inconsistent with the test phase which uses `SparseRetriever`.

To fix this:
1.  Modify `library/data_loader.py` to use `SparseRetriever` for the validation set (mode="val"). This ensures no samples are dropped (preserving alignment) and the metric reflects the full retrieval-reader pipeline performance.
2.  Update the label generation logic in `process_data` to gracefully handle cases where the answer text is not present in the retrieved sentence (assigning all "O" labels instead of crashing or mislabeling).
3.  Update `runfile.py` to disable cache loading (`load_cached_data=False`) so the datasets are reprocessed with the fixed logic.
