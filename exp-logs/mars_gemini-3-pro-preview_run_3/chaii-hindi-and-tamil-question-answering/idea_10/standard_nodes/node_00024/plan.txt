The implementation strategy involves the following steps:

1.  **Initialization**: Setup the environment by initializing the `Config` (creating directories) and setting the random seed for reproducibility.
2.  **Task-Adaptive Pretraining (TAPT)**: Execute the `run_tapt_training` function. This fine-tunes the `xlm-roberta-base` model on the domain-specific text (concatenated train and test contexts) using a Masked Language Modeling objective. This step bridges the domain gap.
3.  **Question Answering Training**: Execute `run_qa_training`, passing the TAPT-adapted model directory. This trains three separate QA models (using seeds 42, 43, 44) on the training set. The models are saved to the `qa_models` directory.
4.  **Validation & Ensemble Evaluation**:
    *   Load the validation dataset using `get_qa_data`.
    *   Iterate through the three trained model checkpoints. For each model, generate predictions on the validation set using `predict_single_model`.
    *   Combine the predictions from the three models using `ensemble_predictions` (majority voting).
    *   Compare the ensemble predictions against the ground truth in `metadata/val.csv` using the Jaccard metric.
    *   Print the **Final Validation Metric** in the required format.
5.  **Failure Analysis**:
    *   Construct a DataFrame containing error magnitudes ($1 - \text{Jaccard}$) and input features (Context Length, Question Length).
    *   Compute and print the Pearson correlation between the error and these features to identify performance bottlenecks.
6.  **Submission**:
    *   Check if the validation metric exceeds the threshold ($0.3011529653320698$).
    *   If successful, trigger `generate_submission`, which runs the ensemble inference on the test set and saves `submission.csv`.
