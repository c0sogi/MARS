Based on the systematic analysis of the "Lessons Learned" and the progression of previous experiments, I propose the following optimized strategy. This solution integrates the structural advantage of **Task-Adaptive Pretraining (TAPT)** with a robust **Stratified Sampling** mechanism to resolve the conflict between gradient update frequency and label sparsity.

# Model
**Architecture:**
I will utilize the **`xlm-roberta-base`** model (Cite solution_lesson_node_00004) as the backbone, given its superior representational capacity for multilingual text compared to distilled variants. The model will be architected as a **Token Classifier**, projecting hidden states into 3 classes (`B-ANS`, `I-ANS`, `O`).

**Structural Innovation: Task-Adaptive Pretraining (TAPT)**
To address the domain gap, I will implement a two-stage training pipeline:
1.  **Adaptation:** I will further pre-train the `xlm-roberta-base` model using a **Masked Language Modeling (MLM)** objective on the combined raw text from the `context` columns of both the Training and Test sets. This aligns the model's embeddings with the specific vocabulary and morphology of the Hindi/Tamil dataset.
2.  **Fine-Tuning:** The TAPT-adapted weights will serve as the initialization for the Question Answering task.

# Data
**Preprocessing:**
*   **Sliding Window:** The text will be split into overlapping windows of **384 tokens** with a **stride of 128**.
*   **Labeling (Soft Overlap):** I will strictly employ **Soft Overlap** labeling (Cite solution_lesson_node_00017). Tokens will be labeled positive if they have *any* character overlap with the ground truth span, preventing the loss of training signals caused by strict containment checks.
*   **Full Distribution:** I will retain **all** generated windows, performing no static negative downsampling (Cite solution_lesson_node_00011).

**Structural Innovation: Stratified "Positive-Anchored" Sampling**
To resolve the conflict between the need for frequent gradient updates (requiring small batches - Cite solution_lesson_node_00015) and the risk of zero-signal batches (caused by sparsity - Cite solution_lesson_node_00010), I will implement a **Stratified Batch Sampler**.
*   Instead of random sampling, this sampler will construct batches such that **every batch contains at least one positive window** (a window containing the answer).
*   This allows the use of a small batch size (e.g., 8) to maximize the number of optimization steps while guaranteeing that the model never experiences "gradient starvation" from purely negative batches.

**Coupled Metadata:**
I will use a custom `collate_fn` to bundle necessary metadata (e.g., `input_ids` and original text mappings) directly into the batch, preventing the decoupling failures observed in previous attempts (Cite solution_lesson_node_00018).

# Training
**Strategy:**
*   **Ensembling:** I will train **3 independent model instances** with different random seeds to mitigate the high variance inherent in this low-resource task (Cite solution_lesson_node_00008).
*   **Duration:** Each model will be fine-tuned for **10 epochs** (Cite solution_lesson_node_00005) to accommodate the "delayed onset" of convergence.
*   **Optimization:** AdamW optimizer will be used with the TAPT-initialized weights.

# Evaluation
**Inference Pipeline:**
1.  **Global Confidence Aggregation (Per Model):** For a given document, the model will process **all** overlapping windows. Instead of a greedy first-match approach, it will collect all candidate spans and select the single span with the **highest confidence score** (Cite solution_lesson_node_00016). This filters out low-confidence false positives often found in partial contexts.
2.  **Self-Contained Decoding:** The selected answer string will be decoded directly from the predicted token IDs using the tokenizer, ensuring robustness against offset mapping errors (Cite solution_lesson_node_00018).
3.  **Majority Voting (Ensemble):** The final prediction will be determined by a **Majority Vote** on the exact string outputs from the 3 models (Cite solution_lesson_node_00009).
