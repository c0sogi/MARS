Based on the empirical lessons learned, I propose a **Seed-Ensembled Sliding Window Strategy with Majority Voting**. This approach addresses the high variance observed in low-resource settings and corrects the flaws in previous aggregation methods.

### Model
I will utilize the **`xlm-roberta-base`** transformer model (Cite solution_lesson_node_00004) adapted for **Token Classification**.
*   **Architecture:** The model will classify each token into one of three classes: `B-ANS` (Beginning), `I-ANS` (Inside), or `O` (Outside). This token-level approach is retained over standard start/end logits to support the specific decoding strategy found to be effective.
*   **Ensemble:** Instead of a single model, the solution will consist of **3 distinct instances** of this architecture, initialized with different random seeds (Cite solution_lesson_node_00008). This structural change from a single-point solution to a bagging ensemble is critical to mitigate the ~18% metric volatility observed between identical runs.

### Data
*   **Preprocessing:** The long context documents will be processed using a **Sliding Window** approach (Cite solution_lesson_node_00002).
    *   The text will be chunked into overlapping windows (e.g., 384 tokens with a stride of 128).
    *   Crucially, **no heuristic filtering** (like TF-IDF) will be applied; the model will evaluate all windows to prevent the information loss observed in earlier iterations.
*   **Labeling:** For training, windows containing the answer span will be labeled with `B-ANS`/`I-ANS` tags. Windows without the answer will be fully labeled as `O`.

### Training
*   **Regimen:** Each of the 3 model instances will be trained independently for **10 epochs** (Cite solution_lesson_node_00005). This extended duration is necessary to overcome the "delayed onset" of learning where validation metrics remain flat for the first several epochs.
*   **Optimization:** Use the AdamW optimizer with a learning rate of roughly 2e-5 or 3e-5.
*   **Data Usage:** To maximize the learning signal from the small dataset (~800 samples), the models will be trained on the stratified training split.

### Evaluation
The inference pipeline introduces a **Vote-then-Decode** structural change to address previous failures in probability averaging:

1.  **Independent Inference:** For a given test question, each of the 3 models will process the context windows independently.
2.  **Greedy First-Match Decoding:** Within each model's pass, windows will be evaluated sequentially. The **first valid span** (a `B-ANS` tag followed by optional `I-ANS` tags) detected by the model will be selected as that model's candidate answer, and subsequent windows for that document will be ignored. This strategy acts as a regularizer against length-biased hallucinations (Cite solution_lesson_node_00007).
3.  **Majority Voting:** The final prediction will be determined by a **Majority Vote** on the exact string outputs from the 3 models (Cite solution_lesson_node_00009).
    *   If Model A predicts "String X", Model B predicts "String X", and Model C predicts "String Y", the output is "String X".
    *   This avoids the "smearing" effect of averaging raw probabilities, which was shown to degrade performance by producing invalid spans.
