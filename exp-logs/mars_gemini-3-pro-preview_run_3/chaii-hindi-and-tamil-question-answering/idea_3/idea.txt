Based on the comprehensive analysis of the "Lessons Learned," I propose the following optimized strategy. This solution introduces **Task-Adaptive Pretraining (TAPT)** as a structural innovation to adapt the multilingual backbone to the specific linguistic distribution of the dataset, while rigorously adhering to the empirical constraints identified in previous experiments (e.g., avoiding negative downsampling and using specific decoding logic).

### Model
**Architecture:**
The backbone will be the **`xlm-roberta-base`** model (Cite solution_lesson_node_00004), modified for **Token Classification**. The output layer will project the hidden states into 3 classes: `B-ANS`, `I-ANS`, and `O`.

**Structural Innovation: Task-Adaptive Pretraining (TAPT)**
Before fine-tuning on the Question Answering task, I will introduce an intermediate **Masked Language Modeling (MLM)** training stage.
*   **Concept:** The standard XLM-RoBERTa model is trained on general-purpose web crawls. The provided dataset contains specialized, long-form contexts in Hindi and Tamil.
*   **Implementation:** I will concatenate the raw text from the `context` columns of both the **Train and Test** sets. The `xlm-roberta-base` model will be trained on this unlabeled corpus using the MLM objective (masking 15% of tokens) for a short duration (e.g., 3-5 epochs).
*   **Benefit:** This aligns the model's embeddings with the specific vocabulary, morphology, and syntactic structures of the target documents, providing a better initialization for the downstream task than the generic pre-trained weights.

### Data
**Preprocessing:**
*   **Sliding Window:** The text will be tokenized and split into overlapping windows of **384 tokens** with a **stride of 128**.
*   **Full Context Retention:** Crucially, **all** generated windows will be retained. No heuristic filtering (like TF-IDF) will be applied (Cite solution_lesson_node_00002).
*   **Labeling:** Windows containing the answer span will be labeled with `B-ANS`/`I-ANS`. All other windows will be labeled entirely as `O`.

**Data Split:**
*   **Stratified K-Fold:** Instead of a single train/validation split, I will employ **Stratified K-Fold Cross-Validation** (e.g., 3 or 5 folds). This ensures that every training sample is used for learning in at least one fold, maximizing the utility of the small dataset (~800 samples) and mitigating the high variance observed in single-seed runs (Cite solution_lesson_node_00008).

### Training
**Procedure:**
*   **Ensemble Training:** A separate model instance will be fine-tuned for each of the K folds, initialized with the **TAPT-adapted weights**.
*   **Duration:** Each fold will be trained for **10 epochs**. This extended duration is strictly maintained to accommodate the "delayed onset" of convergence observed in previous experiments (Cite solution_lesson_node_00005).
*   **Batch Size:** The batch size will be set to **32 or higher** (utilizing the A100 GPU). This ensures that the ratio of positive-to-negative windows within a batch remains statistically healthy, preventing the model collapse associated with small batches in sparse sliding window tasks (Cite solution_lesson_node_00010).
*   **Negative Sampling:** I will use the **full distribution** of windows. No negative downsampling will be performed, ensuring the model learns to suppress false positives in the background text (Cite solution_lesson_node_00011).

### Evaluation
**Inference Pipeline:**
1.  **Independent Prediction:** Each of the K models (from the K-Fold) will process the test set independently.
2.  **Greedy First-Match Decoding:** For a given model and document, windows will be processed sequentially. The **first valid span** (a `B-ANS` tag followed by optional `I-ANS` tags) detected will be selected as the answer, and subsequent windows for that document will be ignored. This strategy is retained to regularize against length-biased hallucinations (Cite solution_lesson_node_00007).
3.  **Majority Voting:** The final prediction will be derived by performing a **Majority Vote** on the exact string outputs from the K models. This avoids the "smearing" artifacts caused by averaging token probabilities (Cite solution_lesson_node_00009).
