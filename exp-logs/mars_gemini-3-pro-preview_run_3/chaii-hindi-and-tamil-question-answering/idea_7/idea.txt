Based on the comprehensive analysis of the "Lessons Learned" and the failure modes of previous experiments, I propose the following optimized strategy. This solution synthesizes the structural advantage of **Task-Adaptive Pretraining (TAPT)** with a robust **Weighted Optimization** framework to resolve the persistent conflict between gradient update frequency and class imbalance.

# Model
**Architecture:**
I will utilize the **`xlm-roberta-base`** model (Cite solution_lesson_node_00004) as the backbone, given its proven superiority over distilled variants for this multilingual task. The model will be architected as a **Token Classifier**, projecting hidden states into 3 classes (`B-ANS`, `I-ANS`, `O`).

**Structural Innovation: Class-Weighted Optimization**
To address the critical trade-off between "Gradient Update Frequency" (Cite solution_lesson_node_00015) and "Gradient Starvation" (Cite solution_lesson_node_00020), I will implement a **Class-Weighted Cross-Entropy Loss**.
*   **Problem:** Previous attempts failed because small batches (needed for frequent updates) caused model collapse due to the overwhelming number of "O" (Outside) tokens, while large batches (needed for stability) reduced the number of updates too drastically.
*   **Solution:** I will assign higher loss weights to the minority classes (`B-ANS` and `I-ANS`) inversely proportional to their frequency. This ensures that even in batches dominated by background text, the model receives a strong, stable gradient signal for the answer spans, preventing the "majority class collapse" observed in previous small-batch runs.

# Data
**Preprocessing:**
*   **Task-Adaptive Pretraining (TAPT):** I will perform an intermediate training stage using **Masked Language Modeling (MLM)** on the concatenated `context` text from both Train and Test sets. This aligns the model's embeddings with the specific Hindi/Tamil vocabulary (Cite solution_lesson_node_00004).
*   **Sliding Window:** The text will be split into overlapping windows of **384 tokens** with a **stride of 128** (Cite solution_lesson_node_00002).
*   **Labeling (Soft Overlap):** I will strictly employ **Soft Overlap** labeling, marking tokens as positive if they have *any* character overlap with the ground truth. This prevents the loss of valid training signals caused by strict containment checks (Cite solution_lesson_node_00017).
*   **Full Distribution:** I will retain **all** generated windows, performing no negative downsampling, to ensure the model learns the true background distribution (Cite solution_lesson_node_00011).
*   **Coupled Metadata:** I will use a custom `collate_fn` to bundle metadata (e.g., `offset_mapping`) directly with the tensor batches, preventing the inference failures caused by decoupled data streams (Cite solution_lesson_node_00018).

# Training
**Strategy:**
*   **Batch Size:** I will strictly use a **Batch Size of 16**. This specific value is the empirical "sweet spot" that provides sufficient gradient density to avoid starvation (Cite solution_lesson_node_00020) while maintaining a high enough update frequency to escape local minima (Cite solution_lesson_node_00015).
*   **Duration:** The model will be fine-tuned for **10 epochs** to accommodate the "delayed onset" of convergence characteristic of this dataset (Cite solution_lesson_node_00005).
*   **Ensembling:** I will train **3 independent model instances** with different random seeds to mitigate the high variance of low-resource training (Cite solution_lesson_node_00008).

# Evaluation
**Inference Pipeline:**
1.  **Global Confidence Aggregation:** For a given document, the model will process **all** overlapping windows. Instead of a greedy first-match approach, it will collect all candidate spans and select the single span with the **highest confidence score** across the entire document. This filters out low-confidence false positives often found in partial contexts (Cite solution_lesson_node_00016).
2.  **Self-Contained Decoding:** Answer strings will be decoded directly from the predicted token IDs, ensuring robustness against offset mapping errors (Cite solution_lesson_node_00018).
3.  **Majority Voting:** The final prediction will be determined by a **Majority Vote** on the exact string outputs from the 3 ensemble models, avoiding the "smearing" artifacts of probability averaging (Cite solution_lesson_node_00009).
