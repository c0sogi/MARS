The implementation strategy follows the requirements to create a fast baseline, validate the model, perform failure analysis, and generate a submission if the metric threshold is met.

1.  **Configuration & Setup**: We import the provided library modules (`config`, `utils`, `data`, `train`, `model`). We explicitly set `Config.EPOCHS = 8`. Given the dataset size (~4.3M samples) and the powerful A100 GPU, 8 epochs provide a balance between sufficient convergence for a baseline and the strict 2-hour runtime limit (estimated runtime ~45-60 mins). Fixed seeds are set for reproducibility.
2.  **Training**: We utilize the `train_model` function from `library.train`. This function encapsulates the data loading (with caching), model initialization, and the training loop with AdamW and ReduceLROnPlateau.
3.  **Validation**: After training, we retrieve the validation `DataLoader` using `prepare_datasets`. We run inference in `eval` mode to collect predictions. The validation metric (MAE) is computed strictly on the inspiratory phase (`u_out == 0`), as per the task description. The result is printed in the required format: `Final Validation Metric: <value>`.
4.  **Failure Analysis**: We compute the absolute error for each prediction in the inspiratory phase. We then calculate the Pearson correlation between this error and each input feature to identify which variables (e.g., `u_in`, `time_step`, `R`, `C`) are associated with higher model error.
5.  **Submission**: The code checks if the `Final Validation Metric` is strictly less than `0.1642141044139862`. If successful, it runs inference on the test set, loads the `test_ids` from the cached numpy file, formats the data into a CSV with `id` and `pressure` columns, and saves it to `./submission/submission.csv`.
