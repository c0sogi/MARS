Based on the accumulated lessons and previous iterations, I propose a **Physically-Disentangled Hybrid Strategy**. This approach evolves the "Parallel TCN-LSTM" concept (Idea 3) by explicitly routing input features to the architectural components best suited to model them, while correcting the training deficiencies identified in Lesson 10 and enforcing the rigorous pipeline controls from Lessons 5 and 6.

### 1. Model: Disentangled TCN-LSTM Hybrid
Instead of feeding all features into a monolithic backbone, this architecture structurally separates the modeling of the two primary physical components of the Equation of Motion ($P = R \cdot \dot{V} + \frac{V}{C}$) into specialized parallel branches.

*   **Branch 1: The Resistive Stream (Deep TCN)**
    *   **Input:** Receives only "fast" dynamic features: `u_in` and its derivatives (`u_in_diff1`, `u_in_diff2`).
    *   **Architecture:** A Temporal Convolutional Network (TCN) with dilated convolutions.
    *   **Rationale:** Convolutional layers are effective learnable finite-difference operators. This branch is structurally biased to model the **Resistive Pressure** ($R \cdot \dot{V}$), which depends on instantaneous flow rates and rapid valve accelerations. **Cite solution_lesson_node_00010**.
*   **Branch 2: The Elastic Stream (Bidirectional LSTM)**
    *   **Input:** Receives only "slow" state features: `u_in` and the integral `u_in_cumsum`.
    *   **Architecture:** A deep Bidirectional LSTM (2-3 layers).
    *   **Rationale:** Recurrent networks excel at maintaining state over time. This branch is structurally biased to model the **Elastic Pressure** ($\frac{V}{C}$), which depends on the accumulated volume history. **Cite solution_lesson_node_00010**.
*   **Fusion & Physics Injection (Skip Connection)**
    *   The outputs of both branches are concatenated.
    *   **Crucial Step:** The raw physical attributes (`R`, `C`) and pre-computed interaction terms (`R_flow`, `C_volume`) are concatenated directly to this fused representation *before* the final regression head. This "Skip Connection" ensures the final decision layer has immediate access to the governing constants without needing to extract them from deep hidden states. **Cite solution_lesson_node_00001**.

### 2. Data: Robust PID Engineering & Pipeline Integrity
We will implement a "PID" feature set with strict controls to prevent the silent failures observed in previous attempts.

*   **Feature Engineering:**
    *   **Integral (I):** Compute `u_in_cumsum` to represent Volume.
    *   **Derivative (D):** Compute `u_in_diff1` (velocity) and `u_in_diff2` (acceleration/jerk) using finite differences. **Cite solution_lesson_node_00003**.
    *   **Physics Interactions:** Pre-compute $R \cdot u_{in}$ and $Volume / C$.
*   **Pipeline Controls:**
    *   **Unified Configuration:** Define a single `FEATURE_CONFIG` dictionary that dictates both the column generation in the dataframe *and* the input channel dimensions for the specific model branches. This prevents the "generation-selection mismatch" where features are created but ignored. **Cite solution_lesson_node_00005**.
    *   **Automated Cache Invalidation:** The script will explicitly detect and delete any existing `.npy` or `.pt` pre-processed files in the working directory at the start of the run. This guarantees that the model trains on fresh data containing the new derivative features. **Cite solution_lesson_node_00006**.

### 3. Training: Metric-Aligned & Extended Regime
We will optimize the training process to align with the competition metric and correct the under-training observed in the hybrid experiment.

*   **Loss Function:** **Masked L1 Loss (MAE)**. The loss will be calculated strictly where `u_out == 0` (inspiratory phase). Gradients from the expiratory phase will be zeroed out to focus model capacity solely on the scored region. **Cite solution_lesson_node_00001**.
*   **Optimizer & Schedule:**
    *   Use **AdamW** with a **ReduceLROnPlateau** scheduler.
    *   **Correction:** Unlike the previous hybrid attempt which stopped at 15 epochs, we will set the training budget to **50-70 epochs**. The hybrid architecture is efficient per-step, but requires sufficient iterations to converge fully. **Cite solution_lesson_node_00010**.
    *   **Batch Size:** Use a large batch size (e.g., 512 or 1024) to maximize GPU throughput and gradient stability.

### 4. Evaluation
*   The test set will be processed using the identical `FEATURE_CONFIG` and cache-cleared pipeline.
*   Inference will be performed in batches, and predictions will be flattened and joined with `id` for the final submission.
