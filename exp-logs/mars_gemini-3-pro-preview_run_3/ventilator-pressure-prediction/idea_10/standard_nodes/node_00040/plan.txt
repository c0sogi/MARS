The implementation strategy focuses on orchestrating the `NCPNet` pipeline efficiently within the 2-hour time limit while ensuring rigorous validation and analysis.

1.  **Configuration Override**: I will import the `Config` class and override `Config.EPOCHS` to **10**. While the default is 80, 10 epochs on the full dataset (approx 4.3M rows) using an A100 GPU provides a balanced trade-off between convergence and execution speed, ensuring the script completes well within the limit. I will retain the full dataset (`debug=False`) to maximize the chance of beating the strict validation threshold.
2.  **Data Loading**: I will use `get_data_loaders(debug=False)`. This function handles feature engineering (PID/Physics), RobustScaling, and caching. It ensures the model receives the correct input shapes `(Batch, Seq, Features)`.
3.  **Training**: The `Trainer` class will be used to fit the model. The training loop includes masked L1 loss (ignoring expiratory phase) and a learning rate scheduler.
4.  **Validation & Metrics**: I will perform a manual validation pass after loading the best model. This is necessary to:
    *   Compute the "Final Validation Metric" (MAE on inspiratory phase) with full precision by aggregating sums and counts globally, rather than averaging batch means.
    *   Collect element-wise errors and feature vectors for failure analysis.
5.  **Failure Analysis**: I will construct a DataFrame from the collected validation errors and features to calculate Pearson correlations. This identifies which features (e.g., `u_in`, `R`, `C`) are most strongly associated with prediction errors.
6.  **Submission**: The script will check if the calculated metric is strictly less than `0.22291307151317596`. If satisfied, it will generate predictions on the test set, align them with the cached `id`s, and save the `submission.csv`.
