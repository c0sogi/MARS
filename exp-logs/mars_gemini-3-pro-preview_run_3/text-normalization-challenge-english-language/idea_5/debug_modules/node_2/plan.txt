The issue is a model architecture mismatch between the training and inference stages of the demo pipeline. The `demo_training` function creates a lightweight model with hardcoded dimensions (e.g., `d_model=64`), while the `CascadePredictor` used in `demo_inference` initializes the model using the default `Config` values (e.g., `d_model=256`). This causes a `RuntimeError` when loading the checkpoint.

To fix this, I will update `setup_demo_environment` in `runfile.py` to patch the `Config` object with the reduced model hyperparameters used for the demo. I will then update `demo_training` to use these `Config` values instead of hardcoded numbers. This ensures consistency across the pipeline, applying the principle of ensuring configuration state matches generated artifacts (Cite debug_lesson_4).
