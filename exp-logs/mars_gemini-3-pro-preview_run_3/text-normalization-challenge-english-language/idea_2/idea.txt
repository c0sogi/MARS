Based on the lessons learned, I propose a **Hybrid Neuro-Symbolic Architecture** that combines the speed and precision of the N-gram lookup tables with the generalization capabilities of a sequence-to-sequence neural network.

### Model
The architecture consists of two distinct stages operating in a cascade:

1.  **Stage 1: Bidirectional Symbolic Memory (The "Head" Solver)**
    *   This component retains the successful **Bidirectional N-Gram Hierarchy** (Trigram $\rightarrow$ Left/Right Bigram $\rightarrow$ Unigram). It acts as a high-speed cache to instantly resolve all tokens seen during training.
    *   By prioritizing Trigrams ($t_{i-1}, t_i, t_{i+1}$) and Bigrams, it effectively handles context-dependent ambiguities (e.g., "St." as "Street" vs. "Saint") using exact memorization (Cite solution_lesson_node_00006).

2.  **Stage 2: Context-Aware Neural Fallback (The "Tail" Solver)**
    *   This component replaces the heuristic Regex transducer with a **Character-Level Sequence-to-Sequence (Seq2Seq) Model** (e.g., a lightweight GRU/LSTM or a small Transformer).
    *   This model is specifically designed to handle **Out-Of-Vocabulary (OOV)** tokens, particularly those containing digits or symbols (the "long tail" identified as the main error source).
    *   **Input Design:** To replicate the context sensitivity of the lookup tables, the neural model will receive the target token along with its immediate neighbors. The input format will be a character sequence representing: `[prev_token] <SEP> [target_token] <SEP> [next_token]`. This allows the model to infer that "1998" is a year in the context of "in 1998" but a cardinal number in "1998 apples".

### Data
**Preprocessing for Training:**
1.  **Symbolic Data Construction:** Iterate through the entire `train.parquet` to build the Trigram, Bigram, and Unigram frequency maps as done previously.
2.  **Neural Data Selection:** Create a specialized training set for the Seq2Seq model by filtering the corpus. Discard all samples where the token class is `PLAIN` or `PUNCT` (which are trivial identity mappings). Keep only "complex" classes (`DATE`, `CARDINAL`, `MEASURE`, `MONEY`, etc.) or tokens containing digits/symbols. This focuses the neural network's capacity strictly on the difficult patterns that lookups cannot handle (Cite solution_lesson_node_00001).

**Preprocessing for Evaluation:**
*   Prepare the test data by generating the N-gram keys (Trigram, Bigram, Unigram) for every token.
*   Identify "Neural Candidates": Tokens that are OOV *and* contain non-alphabetic characters. Pre-format these into the context-window character sequences required by the Seq2Seq model.

### Training
1.  **Symbolic Training:** Perform the count-based aggregation and Maximum Likelihood Estimation for the lookup tables. This remains a one-pass, CPU-bound operation.
2.  **Neural Training:** Train the Seq2Seq model on the filtered "complex" dataset.
    *   **Objective:** Standard Cross-Entropy Loss on the character output sequence.
    *   **Strategy:** Use Teacher Forcing during training. Since the dataset is filtered to only "hard" cases, convergence should be rapid compared to training on the full corpus.

### Evaluation
The inference pipeline follows a strict "specificity-first" logic:
1.  **Lookup Check:** Query the N-gram hierarchy (Trigram $\rightarrow$ Bigram $\rightarrow$ Unigram). If a match is found, output the stored normalization immediately.
2.  **Heuristic Filter:** If the lookup fails (OOV), check the token content.
    *   If the token is **purely alphabetic** (e.g., a rare proper noun), predict the **Identity** (raw token), as the error analysis showed alphabetic tokens rarely require normalization (Cite solution_lesson_node_00001).
3.  **Neural Generation:** If the token contains digits or symbols (e.g., "12.5kg", "Jan-2024"), pass the context-augmented string to the Seq2Seq model to generate the normalized text.
