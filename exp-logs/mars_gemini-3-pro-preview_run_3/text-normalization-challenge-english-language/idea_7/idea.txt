Based on the comprehensive analysis of the provided lessons and the failure modes of previous iterations, I propose a **Robust Multi-Task Neuro-Symbolic Cascade with Factored Embeddings**.

This solution synthesizes the high-precision symbolic hierarchy (Lesson 6), the robust recurrent architecture (Lesson 18), and the multi-task semantic grounding (Lesson 19). Crucially, it introduces **Factored Embeddings** to improve generalization on unseen numerical patterns and implements **Soft Filtering** to resolve the catastrophic "Training-Inference Skew" identified in Lesson 19.

# Model

The architecture follows a "Specificity-Based Cascade" (Cite solution_lesson_node_00008) with three distinct stages:

1.  **Stage 1: Bidirectional Symbolic Memory (The "Head")**
    *   **Structure:** A prioritized hierarchy of hash maps: **Trigrams** ($t_{i-1}, t_i, t_{i+1}$) $\to$ **Left/Right Bigrams** $\to$ **Unigrams**.
    *   **Role:** This layer resolves the Zipfian "head" of the distribution. By utilizing **Trigrams** and **Right-Context Bigrams**, it handles context-dependent ambiguities (e.g., "Dr." followed by a name vs. an address) via exact memorization (Cite solution_lesson_node_00006).

2.  **Stage 2: Heuristic Router (The "Gate")**
    *   **Structure:** A logical filter that checks if an Out-Of-Vocabulary (OOV) token is **purely alphabetic**.
    *   **Role:** If the condition is met, it predicts the **Identity** (raw token). This prevents the neural model from hallucinating on rare proper nouns, restricting the neural problem space to structure-rich entities like digits and symbols (Cite solution_lesson_node_00008).

3.  **Stage 3: Factored Multi-Task Recurrent Network (The "Tail")**
    *   **Input Layer (Structural Innovation):** Instead of a simple character ID embedding, the model uses **Factored Embeddings**. Each input character is represented as the concatenation of three learned embeddings:
        1.  **Character ID:** The specific character identity (e.g., '9').
        2.  **Case Type:** Upper, Lower, or None.
        3.  **Character Type:** Digit, Letter, Symbol, or Punctuation.
        *   *Rationale:* This allows the model to generalize patterns more effectively (e.g., recognizing that the sequence `Digit-Digit-Symbol-Digit` implies a specific normalization rule regardless of the specific digits used).
    *   **Backbone:** A **Bi-Directional GRU Encoder** paired with a **Uni-Directional GRU Decoder** using **Bahdanau Attention**.
        *   *Rationale:* We strictly prefer RNNs over Transformers for this task due to their superior inductive bias for monotonic character-level transduction (Cite solution_lesson_node_00018) and their ability to maintain precise alignment via attention (Cite solution_lesson_node_00010).
    *   **Auxiliary Head:** A classification layer attached to the Encoder's final hidden state that predicts the token's `class` (e.g., `DATE`, `MONEY`).
        *   *Rationale:* This forces the encoder to learn semantic representations to disambiguate inputs (e.g., "1998" as Year vs. Cardinal) without the fragility of generating class tokens in the output sequence.

# Data

**Preprocessing for Training:**
1.  **Symbolic Aggregation:** Construct Trigram, Bigram, and Unigram frequency maps from the full `train.parquet` using Maximum Likelihood Estimation.
2.  **Neural Dataset Construction (Soft Filtering):**
    *   **Hard Samples:** Retain 100% of samples where the class is *not* `PLAIN` or `PUNCT`.
    *   **Easy Samples (Correction for Lesson 19):** Randomly sample 5-10% of the `PLAIN` and `PUNCT` samples and include them in the neural training set.
    *   *Rationale:* This **Soft Filtering** ensures the neural model learns the identity function for punctuation and common words. This acts as a safety net: if the Symbolic Memory misses a simple token (e.g., a comma), the neural model can correctly output it instead of hallucinating, preventing the "Training-Inference Skew" failure (Cite solution_lesson_node_00019).
    *   **Input Formatting:** Create a context-aware character sequence: `[prev_token] <SEP> [target_token] <SEP> [next_token]`.

**Preprocessing for Evaluation:**
*   Generate N-gram keys for all test tokens.
*   Identify "Neural Candidates" (OOV + Non-Alpha).
*   Format inputs as `[prev] <SEP> [target] <SEP> [next]` for the Neural model.

# Training

1.  **Symbolic Training:** Instantaneous count-based aggregation (MLE).
2.  **Neural Training:**
    *   **Objective:** Minimize a joint loss function: $L_{total} = L_{generation} + \lambda L_{classification}$.
        *   $L_{generation}$: Cross-Entropy loss on the character sequence (with Teacher Forcing).
        *   $L_{classification}$: Cross-Entropy loss on the class label prediction.
    *   **Optimizer:** Adam optimizer with a ReduceLROnPlateau scheduler.
    *   **Strategy:** Train on the mixed (Soft Filtered) dataset. The auxiliary task acts as a regularizer, shaping the latent space to cluster structurally similar tokens.

# Evaluation

The inference pipeline follows the "Specificity-Based Cascade" (Cite solution_lesson_node_00008):
1.  **Lookup:** Query Trigram $\to$ Left/Right Bigram $\to$ Unigram. If a match is found, output the stored value.
2.  **Safety Check:** If the token is OOV and `isalpha()`, output the Identity (raw token).
3.  **Neural Inference:**
    *   Pass the context-augmented input to the Bi-GRU Encoder.
    *   Use **Greedy Decoding** (or Beam Search with width 3) on the GRU Decoder to generate the final normalized text string.
    *   The auxiliary class prediction is unused at inference time, serving only to structure the encoder's latent space during training.
