The issue is that the `predict_and_submit` function in `library/train_utils.py` uses `Config.SUBMISSION_PATH` as a default argument. Since Python evaluates default arguments at definition time, the function captures the original configuration path (`./submission/submission.csv`) when the module is imported, ignoring the runtime override in `runfile.py` (`./working/demo_execution/submission/submission.csv`). Consequently, the predictions are saved to the wrong location, causing the verification step to read a stale file. To fix this, I will change the default argument to `None` and resolve the path dynamically inside the function, ensuring the current value of `Config.SUBMISSION_PATH` is used. Cite debug_lesson_10.
