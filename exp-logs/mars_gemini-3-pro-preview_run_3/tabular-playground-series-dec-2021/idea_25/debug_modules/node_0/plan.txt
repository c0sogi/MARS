### Implementation Strategy

1.  **Environment Setup**: We will define a temporary working directory (`./working/demo_execution`) to store all intermediate files (mini-datasets, cache, model checkpoints) to ensure we don't interfere with existing files and to keep the run clean.
2.  **Data Subsampling**: To satisfy the "Optimize for Speed" requirement, we will load the first 2,000 rows from the provided metadata parquet files (`train.parquet`, `val.parquet`, `test.parquet`). We will save these mini-datasets to the temporary directory.
3.  **Configuration Override**: We will dynamically modify the `Config` class attributes in `library.config` to point to our new mini-datasets and adjust hyperparameters (e.g., reducing `EPOCHS` to 2, `BATCH_SIZE` to 64) for a rapid execution cycle.
4.  **Component Verification**:
    *   **Utils**: Verify `seed_everything` and the logic of the `EarlyStopping` class by simulating a loss sequence.
    *   **Data Loader**: Execute `process_data` and `get_dataloaders` to verify feature engineering, caching mechanisms, and tensor shapes.
    *   **Model**: Instantiate the `DeepParallelDCNResNet`, perform a forward pass with dummy data, and verify output dimensions.
    *   **Training Loop**: Execute the `run_training` function using the mini-dataset to ensure the full pipeline (training, validation, checkpointing) runs without errors.
5.  **Cleanup**: (Optional but good practice) We leave the artifacts in `./working` as per instructions allowing usage of that directory.
