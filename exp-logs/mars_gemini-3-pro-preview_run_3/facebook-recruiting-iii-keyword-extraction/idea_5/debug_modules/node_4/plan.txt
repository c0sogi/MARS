The issue stems from the fact that default arguments in Python are evaluated only once at function definition time (Cite debug_lesson_2). The `Vocabulary` class constructor uses `Config.VOCAB_SIZE` as a default value, capturing the initial configuration (100,000) when the module is imported. Even though `runfile.py` updates `Config.VOCAB_SIZE` to 1,000 at runtime, the `Vocabulary` instance in `get_dataloaders` is initialized without arguments, causing it to use the stale default of 100,000. This results in a vocabulary larger than the model's embedding layer (initialized with the correct runtime size of 1,000), triggering a CUDA device-side assertion when the model encounters out-of-bounds token indices. To fix this, I will explicitly pass the current `Config` values when instantiating `Vocabulary` in `library/data.py`.
