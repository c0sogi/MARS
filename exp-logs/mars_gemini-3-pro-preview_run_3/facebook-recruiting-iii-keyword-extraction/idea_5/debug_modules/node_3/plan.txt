The issue is that default arguments in Python functions (like `__init__`) are evaluated only once at module definition time. In `library/data.py`, the `Vocabulary` class defines `vocab_size=Config.VOCAB_SIZE` in its constructor. This captures the original configuration value (100,000) when the module is first imported. Although `runfile.py` updates `Config.VOCAB_SIZE` to 1000 at runtime, the `Vocabulary` instance continues to use the stale default value of 100,000. Consequently, the tokenizer generates token IDs up to ~4800, which exceeds the model's embedding layer size of 1000, triggering a CUDA device-side assertion error.

To fix this, we must explicitly pass the current `Config.VOCAB_SIZE` and `Config.MIN_FREQ` values when instantiating the `Vocabulary` class inside `get_dataloaders`. This forces the code to use the runtime configuration values instead of the frozen defaults. Cite debug_lesson_2.
