The `FileNotFoundError` arises because the `fit` method in `library/trainer.py` initializes `best_f1` to `0.0` and only saves a model checkpoint if the validation F1 score strictly exceeds this value (`val_f1 > best_f1`). In the failed run, the model's F1 score remained at `0.0` for all epochs. Since `0.0 > 0.0` evaluates to `False`, the `torch.save` function was never called, leaving no file to load at the end of the training process.

To fix this, I will initialize `best_f1` to `-1.0`. This ensures that the first validation result (even if it is `0.0`) satisfies the condition `val_f1 > best_f1`, guaranteeing that a model checkpoint is created at least once. This change preserves the early stopping logic (subsequent `0.0` scores will not reset patience) while preventing the crash.
