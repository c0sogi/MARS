The issue is caused by Python's handling of default arguments, which are evaluated only once at module definition time. In `library/data.py`, the `Tokenizer.transform` method defines `max_len=config.MAX_LEN` as a default. When `runfile.py` modifies `config.MAX_LEN` to 20 at runtime, the `transform` method continues to use the original value (400) captured at import time because `prepare_data` calls it without arguments. To fix this, I will modify `library/data.py` to explicitly pass `max_len=config.MAX_LEN` when calling `tokenizer.transform`. This ensures the method uses the current runtime value of the configuration variable. Cite debug_lesson_2.
