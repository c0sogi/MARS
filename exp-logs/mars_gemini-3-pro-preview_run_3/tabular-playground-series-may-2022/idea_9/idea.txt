# Proposed Strategy: Input-Injected Funnel MLP

## Model
We will implement an **Input-Injected Funnel MLP**. This architecture introduces a structural innovation by creating direct "skip-connections" from the input layer to every hidden layer in the network. This design retains the beneficial compressive inductive bias of the "Funnel" backbone while solving the potential information bottleneck problem by ensuring that deep layers maintain direct access to the original raw signals.

1.  **Input Construction:** The input vector $x_{in}$ will consist of the concatenation of:
    *   Normalized continuous features (`f_00`–`f_28` and `unique_character_count`).
    *   Flattened **Entity Embeddings** for all categorical variables.
    *   **Embedding Configuration:** We will set the embedding dimension to **16** for all categorical features (the 10 decomposed `f_27` characters, `f_29`, and `f_30`). This dimension is the empirically determined "sweet spot," avoiding the signal bottleneck of dimension 8 (Cite solution_lesson_node_00018) and the noise overhead of dimension 32 (Cite solution_lesson_node_00027).

2.  **Input-Injected Backbone:**
    *   **Layer 1:** Processes $x_{in}$ through a Dense layer (width 512) $\to$ ReLU $\to$ Dropout. Output is $h_1$.
    *   **Layer 2 (The Innovation):** Concatenates $[h_1, x_{in}]$ and processes the combined vector through a Dense layer (width 256) $\to$ ReLU $\to$ Dropout. Output is $h_2$.
    *   **Layer 3:** Concatenates $[h_2, x_{in}]$ and processes the combined vector through a Dense layer (width 128) $\to$ ReLU $\to$ Dropout. Output is $h_3$.
    *   **Rationale:** This structure strictly adheres to the "Funnel" topology (decreasing widths) which outperforms constant-width ResNets (Cite solution_lesson_node_00004). However, the input injection mechanism prevents the "aggressive tapering" from causing information loss (Cite solution_lesson_node_00020) and ensures that the final decision boundary can rely on both high-level abstractions and low-level raw signals.

3.  **Unified Stream:** We explicitly use a single unified stream with early concatenation, rejecting the "Dual-Stream" approach which was shown to degrade performance by isolating feature interactions (Cite solution_lesson_node_00029).

## Data
The preprocessing pipeline is designed to maximize data fidelity and correct previous vocabulary alignment errors:

1.  **Transductive Vocabulary Alignment:** We will fit the categorical `OrdinalEncoder` on the **concatenation of the Train, Validation, and Test sets**. This ensures that every unique token in the test set is assigned a distinct embedding index, preventing the significant signal loss caused by mapping unseen test tokens to a generic "unknown" bucket (Cite solution_lesson_node_00021).
2.  **String Decomposition:** The `f_27` feature will be split into 10 fixed-position character columns (Cite solution_lesson_node_00001).
3.  **Discrete Feature Handling:** `f_29` and `f_30` will be treated strictly as categorical variables and embedded, preserving their non-linear state information (Cite solution_lesson_node_00008).
4.  **Feature Engineering:** We will compute and append the `unique_character_count` of `f_27` as a normalized continuous feature (Cite solution_lesson_node_00002).
5.  **Normalization:** All continuous features will be scaled using StandardScaler.

## Training
The training configuration is precisely calibrated to balance convergence speed with generalization, adhering to the specific sensitivities of this dataset:

1.  **Optimizer:** **AdamW** with a calibrated weight decay of **1e-5**. We explicitly avoid the default `1e-2`, which was proven too aggressive for this tabular task (Cite solution_lesson_node_00023).
2.  **Batch Size:** **1024**. We utilize this moderate batch size to leverage the implicit regularization of stochastic gradient noise, avoiding the generalization gap observed with larger batches (Cite solution_lesson_node_00024).
3.  **Scheduler:** **One-Cycle Learning Rate Policy**. We retain this schedule to facilitate super-convergence and robust minima selection (Cite solution_lesson_node_00002).
4.  **Regularization:** We will use **Dropout (0.2)**. We explicitly avoid BatchNorm, as previous experiments showed it caused performance degradation compared to Dropout for this specific architecture (Cite solution_lesson_node_00018).
5.  **Data Volume:** We will utilize the **full training dataset**, strictly avoiding subsampling (Cite solution_lesson_node_00022) or unsupervised pretraining (Cite solution_lesson_node_00013).

## Evaluation
1.  **Preprocessing:** The test set will be processed using the global (transductive) vocabulary mappings and training set scalers.
2.  **Inference:** The trained Input-Injected Funnel MLP will predict probabilities for the target class `1`.
3.  **Submission:** The resulting probabilities will be formatted into the submission CSV for AUC evaluation.
