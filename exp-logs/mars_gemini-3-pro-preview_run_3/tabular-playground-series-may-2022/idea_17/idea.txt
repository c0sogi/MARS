# Proposed Strategy: Tree-Structured Funnel Ensemble

## Model
We will implement a **Tree-Structured Funnel Ensemble**. This architecture introduces a structural innovation by evolving the standard single-path MLP into a "Tree" topology. It features a shared, wide "trunk" that learns a common low-level representation, which then branches into multiple independent "heads." This design internalizes the benefits of ensembling (variance reduction and robust minima selection) into a single end-to-end differentiable model, while strictly adhering to the "Funnel" inductive bias that has proven superior for this dataset.

1.  **Input & Embeddings:**
    *   **Categorical Inputs:** The 10 decomposed character positions of `f_27` (Cite solution_lesson_node_00001) and the discrete features `f_29`, `f_30` (Cite solution_lesson_node_00008).
    *   **Optimal Capacity:** All categorical features will be mapped to **Entity Embeddings of dimension 16**. This adheres to the empirically determined "sweet spot," avoiding the signal bottleneck of dimension 8 (Cite solution_lesson_node_00018) and the noise overhead of dimension 32 (Cite solution_lesson_node_00027).
    *   **Early Fusion:** The embeddings will be flattened and concatenated immediately with the normalized continuous features (`f_00`–`f_28` and `unique_character_count`) (Cite solution_lesson_node_00029).

2.  **Shared Trunk (The Root):**
    *   The concatenated input is processed by a **Shared Dense Block**: `Linear(Input_Dim -> 512) -> ReLU -> Dropout(0.2)`.
    *   This layer extracts the fundamental, shared features required by all subsequent decision paths.

3.  **Independent Funnel Heads (The Branches):**
    *   The output of the trunk splits into **3 Independent Branches**.
    *   **Branch Topology:** Each branch follows a "Funnel" structure: `Linear(512 -> 256) -> ReLU -> Dropout(0.2) -> Linear(256 -> 128) -> ReLU -> Dropout(0.2) -> Linear(128 -> 1)`.
    *   **Rationale:** This structure preserves the compressive inductive bias of the Funnel MLP (Cite solution_lesson_node_00004) while creating diverse high-level representations.
    *   **Bottleneck Avoidance:** We explicitly terminate the hidden layers at width 128 before the final projection, avoiding the information loss associated with tapering to 64 units (Cite solution_lesson_node_00020).
    *   **Activation:** We use **ReLU** exclusively, avoiding the overfitting risks of GLUs (Cite solution_lesson_node_00019) and the lack of gain from Swish/SELU (Cite solution_lesson_node_00041, solution_lesson_node_00047).
    *   **Normalization:** We explicitly exclude LayerNorm and BatchNorm, relying on Dropout and the ensemble structure for regularization (Cite solution_lesson_node_00039, solution_lesson_node_00018).

## Data
The preprocessing pipeline is designed to ensure maximum signal fidelity and correct previous vocabulary alignment errors:

1.  **Transductive Vocabulary Alignment:** We will fit the categorical `OrdinalEncoder` on the **concatenation of the Train, Validation, and Test sets**. This ensures that every unique token in the test set is assigned a distinct embedding index, preventing the significant signal loss caused by mapping unseen test tokens to a generic "unknown" bucket (Cite solution_lesson_node_00021).
2.  **String Decomposition:** `f_27` will be split into 10 fixed-position character columns (Cite solution_lesson_node_00001). We explicitly avoid N-gram expansion (Cite solution_lesson_node_00035) and Token Dropout (Cite solution_lesson_node_00040) to preserve non-redundant positional signals.
3.  **Feature Engineering:** We will compute and append the `unique_character_count` of `f_27` as a normalized continuous feature (Cite solution_lesson_node_00002).
4.  **Normalization:** All continuous features will be scaled using **StandardScaler**.
5.  **Data Volume:** We will utilize the **full training dataset**, strictly avoiding subsampling (Cite solution_lesson_node_00022).

## Training
The training configuration is precisely calibrated to facilitate super-convergence while maintaining generalization:

1.  **Multi-Head Loss:** The training loss will be the **sum of the Binary Cross-Entropy losses** calculated independently for each of the 3 heads. This forces each branch to learn a complete predictive function, encouraging diversity in the feature extraction process.
2.  **Optimizer:** **AdamW** with a calibrated weight decay of **1e-5**. We explicitly avoid the default `1e-2`, which was proven too aggressive for this tabular task (Cite solution_lesson_node_00023).
3.  **Scheduler:** **One-Cycle Learning Rate Policy**. We retain this schedule (max LR ~1e-2) to facilitate super-convergence and robust minima selection (Cite solution_lesson_node_00002).
4.  **Batch Size:** **1024**. We utilize this moderate batch size to leverage the implicit regularization of stochastic gradient noise, avoiding the generalization gap observed with larger batches (Cite solution_lesson_node_00024).
5.  **Strategy:** Direct Supervised Learning. We avoid autoencoder pretraining (Cite solution_lesson_node_00013) and input noise injection (Cite solution_lesson_node_00053).

## Evaluation
1.  **Preprocessing:** The test set will be processed using the global (transductive) vocabulary mappings and training set scalers.
2.  **Inference:** The trained Tree-Structured Funnel Ensemble will generate 3 probability predictions per sample (one from each head). The final submission will be the **arithmetic mean** of these 3 probabilities.
3.  **Submission:** The resulting averaged probabilities will be formatted into the submission CSV for AUC evaluation.
