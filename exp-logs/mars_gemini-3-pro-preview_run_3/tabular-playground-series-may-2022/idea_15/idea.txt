# Proposed Strategy: Input-Attentive Swish Funnel Network

## Model
We will implement an **Input-Attentive Swish Funnel Network**. This architecture introduces two structural innovations designed to refine signal quality before processing and improve gradient dynamics, while retaining the proven "Funnel" backbone.

1.  **Input & Embeddings:**
    *   **Categorical Inputs:** The 10 decomposed character positions of `f_27` (Cite solution_lesson_node_00001) and the discrete features `f_29`, `f_30` (Cite solution_lesson_node_00008).
    *   **Optimal Capacity:** All categorical features will be mapped to **Entity Embeddings of dimension 16**. This adheres to the empirically determined "sweet spot," avoiding the signal bottleneck of dimension 8 (Cite solution_lesson_node_00018) and the noise overhead of dimension 32 (Cite solution_lesson_node_00027).
    *   **Early Fusion:** The embeddings will be flattened and concatenated immediately with the normalized continuous features (`f_00`–`f_28` and `unique_character_count`) (Cite solution_lesson_node_00029).

2.  **Input Attention Block (Innovation 1):**
    *   Before entering the main backbone, the combined input vector $x$ will pass through an **Input Attention Mechanism** (conceptually similar to a Squeeze-and-Excitation block applied to the feature dimension).
    *   **Structure:** $x$ is projected down to a bottleneck dimension (e.g., 64) and then back up to the original input dimension, followed by a Sigmoid activation to generate a mask $m \in [0, 1]$.
    *   **Operation:** The original input is re-weighted: $x_{weighted} = x \otimes m$.
    *   **Rationale:** This allows the network to dynamically suppress noise in the continuous sensors or irrelevant embedding dimensions *before* they are mixed in the deep layers. This addresses the feature selection needs identified in GLU experiments (Cite solution_lesson_node_00019) without the overfitting caused by applying gating at every layer.

3.  **Swish-Activated Funnel Backbone (Innovation 2):**
    *   **Topology:** We retain the **Funnel MLP** structure (decreasing layer widths: 512 $\to$ 256 $\to$ 128) as it provides the beneficial inductive bias of feature compression (Cite solution_lesson_node_00004).
    *   **Activation:** We replace standard ReLU with the **Swish (SiLU)** activation function ($f(x) = x \cdot \sigma(x)$).
    *   **Rationale:** Swish provides the self-gating properties of GLUs (smooth, non-monotonic) which aids in modeling continuous control functions (Cite solution_lesson_node_00006), but preserves the parameter efficiency of ReLU, avoiding the overfitting risks of full GLU layers (Cite solution_lesson_node_00019).
    *   **Regularization:** We will apply **Dropout (0.2)** after activations. We explicitly avoid Layer Normalization (Cite solution_lesson_node_00039) and Batch Normalization (Cite solution_lesson_node_00018).

4.  **Head:**
    *   The final 128-unit representation connects directly to the output neuron, explicitly avoiding tapering to narrower layers (e.g., 64) to prevent information bottlenecks (Cite solution_lesson_node_00020).

## Data
The preprocessing pipeline is designed to ensure maximum signal fidelity and correct previous vocabulary alignment errors:

1.  **Transductive Vocabulary Alignment:** We will fit the categorical `OrdinalEncoder` on the **concatenation of the Train, Validation, and Test sets**. This ensures that every unique token in the test set is assigned a distinct embedding index, preventing the significant signal loss caused by mapping unseen test tokens to a generic "unknown" bucket (Cite solution_lesson_node_00021).
2.  **String Decomposition:** `f_27` will be split into 10 fixed-position character columns (Cite solution_lesson_node_00001). We explicitly avoid N-gram expansion (Cite solution_lesson_node_00035) and Token Dropout (Cite solution_lesson_node_00040) to preserve non-redundant positional signals.
3.  **Feature Engineering:** We will compute and append the `unique_character_count` of `f_27` as a normalized continuous feature (Cite solution_lesson_node_00002).
4.  **Normalization:** All continuous features will be scaled using **StandardScaler**.
5.  **Data Volume:** We will utilize the **full training dataset**, strictly avoiding subsampling (Cite solution_lesson_node_00022).

## Training
The training configuration is precisely calibrated to facilitate super-convergence while maintaining generalization:

1.  **Optimizer:** **AdamW** with a calibrated weight decay of **1e-5**. We explicitly avoid the default `1e-2`, which was proven too aggressive for this tabular task (Cite solution_lesson_node_00023).
2.  **Scheduler:** **One-Cycle Learning Rate Policy**. We retain this schedule (max LR ~1e-2) to facilitate super-convergence and robust minima selection (Cite solution_lesson_node_00002).
3.  **Batch Size:** **1024**. We utilize this moderate batch size to leverage the implicit regularization of stochastic gradient noise, avoiding the generalization gap observed with larger batches (Cite solution_lesson_node_00024).
4.  **Strategy:** Direct Supervised Learning. We avoid autoencoder pretraining as it provides no benefit for this high-signal dataset (Cite solution_lesson_node_00013).

## Evaluation
1.  **Preprocessing:** The test set will be processed using the global (transductive) vocabulary mappings and training set scalers.
2.  **Inference:** The trained Input-Attentive Swish Funnel Network will predict probabilities for the target class `1`.
3.  **Submission:** The resulting probabilities will be formatted into the submission CSV for AUC evaluation.
