# Proposed Strategy: Dual-Stream Funnel MLP with Optimized Embeddings

## Model
We will implement a **Dual-Stream Funnel MLP**. This architecture evolves the previous "Dual-Stream" concept by stripping away the overfitting-prone Gated Linear Units (GLUs) and optimizing the embedding capacity, focusing on robust feature extraction and compression.

1.  **Dual-Stream Input Stage:**
    *   **Stream 1 (State Representation):** Accepts the categorical inputs (10 decomposed `f_27` characters and discrete features `f_29`, `f_30`). These are mapped to **Entity Embeddings of dimension 16**. We strictly adhere to this dimension as it provides the optimal balance between signal capacity and regularization, avoiding the bottlenecks of dimension 8 (Cite solution_lesson_node_00018) and the noise overhead of dimension 32 (Cite solution_lesson_node_00027). The embeddings are flattened and passed through a Dense-ReLU layer to project them into a latent "State" space.
    *   **Stream 2 (Sensor Representation):** Accepts the normalized continuous features (`f_00`–`f_28` and `unique_character_count`). These are passed through a separate Dense-ReLU layer to project them into a latent "Sensor" space.
    *   **Innovation:** By projecting these modalities separately before concatenation, we allow the network to form non-linear representations of the "Machine State" and "Sensor Readings" independently, preventing the raw high-variance sensor noise from dominating the gradients of the embedding layers in the initial steps.

2.  **Funnel Backbone:**
    *   **Fusion:** The outputs of the two streams are concatenated.
    *   **Architecture:** The combined vector is processed by a **Funnel MLP** with decreasing layer widths (512 $\to$ 256 $\to$ 128). We retain this structure as it provides the beneficial inductive bias of feature compression, which has consistently outperformed ResNets on this dataset (Cite solution_lesson_node_00004).
    *   **Activation:** We utilize standard **ReLU** activations with **Dropout (0.2)**, avoiding the complexity and overfitting issues associated with GLUs (Cite solution_lesson_node_00019) or Transformers (Cite solution_lesson_node_00025).

3.  **Output Head:**
    *   The final 128-unit representation connects directly to the output neuron. We explicitly avoid tapering to a narrower layer (e.g., 64) to prevent information bottlenecks (Cite solution_lesson_node_00020).

## Data
The preprocessing pipeline is designed to maximize data fidelity and correct previous vocabulary alignment errors:

1.  **Transductive Vocabulary Alignment:** We will fit the categorical `OrdinalEncoder` on the **concatenation of the Train, Validation, and Test sets**. This ensures that every unique token in the test set is assigned a distinct embedding index, preventing the signal loss caused by mapping unseen test tokens to "unknown" (Cite solution_lesson_node_00021).
2.  **String Decomposition:** The `f_27` feature will be split into 10 fixed-position character columns (Cite solution_lesson_node_00001).
3.  **Discrete Feature Handling:** `f_29` and `f_30` will be treated strictly as categorical variables and embedded (Cite solution_lesson_node_00008).
4.  **Feature Engineering:** We will compute and append the `unique_character_count` of `f_27` as a normalized continuous feature (Cite solution_lesson_node_00002).
5.  **Normalization:** All continuous features will be scaled using StandardScaler.

## Training
The training configuration is precisely calibrated to balance convergence speed with generalization, avoiding aggressive regularization pitfalls:

1.  **Optimizer:** **AdamW** with a calibrated weight decay of **1e-5**. We explicitly avoid the default `1e-2`, which was proven too aggressive for this tabular task (Cite solution_lesson_node_00023).
2.  **Batch Size:** **1024**. We utilize this moderate batch size to leverage the implicit regularization of stochastic gradient noise, avoiding the generalization gap observed with larger batches (Cite solution_lesson_node_00024).
3.  **Scheduler:** **One-Cycle Learning Rate Policy**. We retain this schedule to facilitate super-convergence and robust minima selection (Cite solution_lesson_node_00002).
4.  **Data Volume:** We will utilize the **full training dataset**, strictly avoiding subsampling (Cite solution_lesson_node_00022) or unsupervised pretraining (Cite solution_lesson_node_00013).

## Evaluation
1.  **Preprocessing:** The test set will be processed using the global (transductive) vocabulary mappings and training set scalers.
2.  **Inference:** The trained Dual-Stream Funnel MLP will predict probabilities for the target class `1`.
3.  **Submission:** The resulting probabilities will be formatted into the submission CSV for AUC evaluation.
