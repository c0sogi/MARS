# Proposed Strategy: Layer-Normalized Gated Funnel Network

## Model
We will implement a **Layer-Normalized Gated Funnel MLP**. This architecture synthesizes the rapid convergence properties of Gated Linear Units (GLU) observed in previous attempts with robust regularization and normalization to prevent the overfitting that caused them to fail.

1.  **Input Layer:** The network will accept concatenated inputs consisting of normalized continuous features and flattened **Entity Embeddings**.
    *   **High-Fidelity Embeddings:** We will set the embedding dimension to **32** for all categorical variables (the decomposed `f_27` characters, `f_29`, and `f_30`). This addresses the signal bottleneck observed when using lower dimensions (e.g., 8 or 16) for high-information features (Cite solution_lesson_node_00018).
2.  **Gated Backbone with LayerNorm:** Instead of standard Dense-ReLU blocks or the unstable GLU blocks used previously, we will employ a **Transformer-style Feed-Forward Block** structure adapted for a funnel topology:
    *   Structure: `LayerNorm -> Gated Linear Unit (GLU) -> Dropout`.
    *   **Layer Normalization:** We introduce Layer Normalization before the gating mechanism. This stabilizes the distribution of inputs to the gates, addressing the volatility and early overfitting issues seen with raw GLUs (Cite solution_lesson_node_00019).
    *   **Funnel Topology:** We retain the macroscopic "Funnel" structure (Layer widths: 512 $\to$ 256 $\to$ 128) to enforce the beneficial inductive bias of feature compression (Cite solution_lesson_node_00004).
    *   **Dropout:** We will increase the dropout rate to **0.25** within these blocks to provide the "stronger regularization" explicitly called for in the analysis of Gated Networks (Cite solution_lesson_node_00019).
3.  **Output Head:** The final 128-unit representation will be connected directly to the output neuron. We explicitly avoid tapering to a narrower layer (e.g., 64) to prevent information bottlenecks at the classification boundary (Cite solution_lesson_node_00020).

## Data
The preprocessing pipeline combines the most effective feature engineering steps with a transductive vocabulary strategy:
1.  **Global Vocabulary Alignment:** We will fit the categorical encoders (Ordinal Encoding) on the **concatenation of the Train, Validation, and Test sets**. This ensures that every unique character and discrete value in the test set is assigned a distinct integer index and embedding vector, preventing the information loss associated with mapping unseen test tokens to a generic "unknown" bucket (Cite solution_lesson_node_00021).
2.  **String Decomposition:** The `f_27` feature will be split into 10 fixed-position character columns (Cite solution_lesson_node_00001).
3.  **Discrete Feature Handling:** Features `f_29` and `f_30` will be treated strictly as categorical variables and embedded, preserving their non-linear state information (Cite solution_lesson_node_00008).
4.  **Feature Engineering:** We will compute and append the `unique_character_count` of `f_27` as a normalized continuous feature (Cite solution_lesson_node_00002).
5.  **Normalization:** All continuous features will be scaled using StandardScaler.

## Training
We will utilize a direct supervised training approach, leveraging the high signal-to-noise ratio of the dataset.
*   **Strategy:** Direct Supervised Learning. We will avoid Denoising Autoencoder pretraining, as it was shown to add computational cost without improving performance on this specific dataset (Cite solution_lesson_node_00013).
*   **Scheduler:** We will employ the **One-Cycle Learning Rate Policy**. This schedule is critical for achieving super-convergence and finding a robust global minimum (Cite solution_lesson_node_00002).
*   **Optimizer:** AdamW, to couple the high dropout with weight decay for maximum regularization.

## Evaluation
1.  **Preprocessing:** The test set will be processed using the global vocabulary mappings and training set scalers.
2.  **Inference:** The trained Layer-Normalized Gated Funnel model will predict probabilities for the target class `1`.
3.  **Submission:** Predictions will be formatted into the submission CSV for AUC evaluation.
