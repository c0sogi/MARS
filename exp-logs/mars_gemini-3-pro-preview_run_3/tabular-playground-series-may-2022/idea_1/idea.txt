# Baseline Approach: Entity Embedding MLP

## Model
We will design a standard **Feed-Forward Neural Network (MLP) with Entity Embeddings**. Unlike the Convolutional or Transformer architectures that interpret the `f_27` string as a temporal sequence, this approach treats the string as a set of distinct, fixed-position categorical features. The model consists of an input layer that accepts normalized continuous features and integer-encoded categorical features. Each categorical input (including the discrete variables `f_29`, `f_30` and the decomposed character positions of `f_27`) is passed through a learnable embedding layer to capture dense vector representations. These embeddings are flattened and concatenated with the continuous feature vector. The combined representation is then processed by a stack of fully connected (Dense) layers with ReLU activations and Dropout regularization, concluding with a single output neuron with a sigmoid activation function to predict the class probability.

## Data
The data preprocessing will focus on converting the mixed data types into a format suitable for a neural network:
1.  **Numerical Features**: The continuous columns (`f_00` through `f_26`, and `f_28`) will be normalized using **Standard Scaling** (subtracting the mean and dividing by the standard deviation) to ensure stable training dynamics.
2.  **String Decomposition**: The high-cardinality string feature `f_27` will be split into fixed-width character columns (e.g., `char_pos_0`, `char_pos_1`, etc.).
3.  **Categorical Encoding**: These new character-position columns, along with the original discrete features (`f_29`, `f_30`), will be **Label Encoded** (mapped to integers) to serve as indices for the embedding layers.

## Training
The model will be trained using the **Binary Cross-Entropy** loss function and the **Adam** optimizer with default parameters. To maintain efficiency and prevent overfitting, we will utilize **Early Stopping** monitoring the validation AUC score, terminating training when improvement stalls. A moderate batch size (e.g., 1024) will be used to balance computational speed with gradient estimate stability.

## Evaluation
During evaluation, the test data will undergo the same preprocessing pipeline (scaling numericals using training statistics and splitting/encoding the string feature). The trained model will perform a forward pass on the processed test set to generate probability scores for the target variable `1`, which will be recorded in the submission file.
