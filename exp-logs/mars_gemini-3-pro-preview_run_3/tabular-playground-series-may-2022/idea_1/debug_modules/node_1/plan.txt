The issue is caused by a mismatch between the vocabulary sizes used to initialize the model's embedding layers and the actual indices present in the validation or test data. The `ManufacturingDataset` class currently calculates `vocab_sizes` based solely on the data it holds. Consequently, the training dataset computes vocabulary sizes based only on the training subset. If the validation or test sets contain category indices (assigned by the global `OrdinalEncoder`) that are larger than the maximum index in the training set, the model—initialized with the training set's smaller vocabulary sizes—will crash with a CUDA device-side assertion error (index out of bounds) when looking up embeddings for those unseen indices.

To fix this, we need to calculate the vocabulary sizes globally (across training, validation, and test sets) and pass these consistent sizes to the `ManufacturingDataset` instances. This ensures the model's embedding layers are dimensioned to handle all possible category indices defined by the global encoder.
