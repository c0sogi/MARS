To improve the model's performance on the long-tailed iNaturalist 2019 dataset, I will implement a **Class-Balanced Loss** strategy (Cite solution_lesson_node_00001). The failure analysis confirmed a negative correlation between class frequency and accuracy, indicating the model is biased towards frequent classes. By weighting the CrossEntropyLoss inversely proportional to class frequency, we force the model to pay more attention to rare species.

Additionally, since the previous model showed signs of overfitting (validation loss diverging from training loss) after Epoch 7, I will increase regularization by raising the **Dropout Rate** to 0.3 and **Stochastic Depth Rate** to 0.2. To accommodate the slower convergence expected from these changes, I will extend the training duration to 12 epochs, which fits comfortably within the 4-hour runtime limit. Finally, I will enforce the conditional submission generation requirement in the execution script.

    def _compute_class_weights(self):
        """Computes class weights inversely proportional to frequency."""
        try:
            df = pd.read_csv(Config.TRAIN_METADATA)
            class_counts = df["category_id"].value_counts().sort_index()
            
            # Initialize with 1s to avoid division by zero for any missing classes
            counts = np.ones(Config.NUM_CLASSES, dtype=np.float32)
            
            for cid, count in class_counts.items():
                if 0 <= cid < Config.NUM_CLASSES:
                    counts[cid] = count
            
            # Calculate weights: N / (C * n_c)
            # This balances the contribution of each class to the loss
            total_samples = counts.sum()
            weights = total_samples / (Config.NUM_CLASSES * counts)
            
            return torch.tensor(weights, dtype=torch.float32).to(self.device)
        except Exception as e:
            print(f"Error computing class weights: {e}. using None.")
            return None
