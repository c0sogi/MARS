The implementation strategy involves the following steps:

1.  **Configuration Setup**: Override the default `Config` parameters to satisfy the "fast baseline" requirement. We will enable debug mode but increase the `DEBUG_SAMPLE_SIZE` to 20,000 (approx. 50% of the training data) and reduce `EPOCHS` to 6. This ensures the training completes well within the 2-hour limit while providing sufficient data for model convergence.
2.  **Training**: Execute the training pipeline using `library.engine.run_training`. This handles data loading (with the configured subset), model initialization, training loops with Mixup augmentation, and saving the best model based on validation AUC.
3.  **Full Validation & Metrics**: After training, load the best saved model and the **full** validation dataset (ignoring the debug subset used during training). Compute the ROC AUC score on this complete hold-out set to meet the reporting requirement.
4.  **Failure Analysis**: During the full validation pass, extract signal statistics (mean, max, std for On/Off targets) for each sample. Calculate the absolute prediction error and compute the correlation between this error and the extracted features to identify potential failure modes.
5.  **Submission**: Compare the final validation AUC against the specified threshold (0.7770832449065452). If the model performs sufficiently well, generate the submission file using `library.engine.predict`.
