Based on the lessons learned, I propose a **Heterogeneous Gradient Boosting Ensemble** strategy. This approach evolves the solution from a single Scikit-learn model to a robust ensemble of industry-standard boosters, while introducing a statistical feature engineering paradigm to resolve spatial limitations.

# Model
I propose a **Dual-Branch Ensemble** comprising **LightGBM** and **XGBoost** regressors.
*   **Design:** Instead of relying on a single implementation (`HistGradientBoostingRegressor`), this strategy leverages two distinct gradient boosting frameworks. LightGBM utilizes Gradient-based One-Side Sampling (GOSS) for efficiency, while XGBoost offers exact and approximate greedy split-finding algorithms.
*   **Structural Innovation:** By combining predictions from two "strong" learners trained with different internal algorithms, we reduce the variance and bias inherent in any single tree-growing strategy. This directly addresses the failure of the previous hybrid ensemble, which failed because it combined a strong learner with a weak, unoptimized Neural Network (Cite solution_lesson_node_00011).

# Data
**Preprocessing (Exploitation):**
*   **Target Sanitization:** I will strictly filter the training data to keep `fare_amount` between 0 and 500. This removes the extreme outliers (e.g., $93,000 fares) that were proven to destabilize the MSE loss function and degrade performance (Cite solution_lesson_node_00005).
*   **Data Volume:** The model will be trained on the **full 55 million row dataset**. Previous experiments confirmed that data volume is the primary driver of performance, and subsampling leads to significant error (Cite solution_lesson_node_00012).

**Feature Engineering (Exploration - Spatial Target Encoding):**
*   **Concept:** To address the inefficiency of decision trees in modeling complex spatial neighborhoods (Cite solution_lesson_node_00003), I will implement **Spatial Target Encoding**.
*   **Implementation:**
    1.  Discretize the spatial domain by clustering pickup and dropoff coordinates into $K$ regions (e.g., using K-Means with $K=500$).
    2.  Calculate the **Mean Fare Amount** for each cluster using the training data. To prevent data leakage, this will be computed using K-Fold holdout statistics.
    3.  Inject these "Average Neighborhood Prices" as continuous features. This provides the trees with a direct "lookup table" for the baseline cost of a region, removing the need to learn these base rates through deep, inefficient splits.

**Feature Engineering (Exploitation):**
*   **Rotated Coordinates & Landmarks:** I will retain the coordinate rotation (29° alignment) and Haversine distances to key landmarks (JFK, WTC, etc.). These features have been proven to help the model capture the diagonal street grid and traffic hubs (Cite solution_lesson_node_00003, Cite solution_lesson_node_00010).

# Training
*   **Procedure:** The LightGBM and XGBoost models will be trained independently on the full dataset.
*   **Compute Strategy:**
    *   **XGBoost:** Will utilize the NVIDIA A100 GPU (`tree_method='gpu_hist'`) to handle the massive dataset efficiently.
    *   **LightGBM:** Will utilize the 12 vCPUs, leveraging its highly optimized histogram-based algorithm.
*   **Hyperparameters:** Both models will use a high capacity configuration (e.g., `num_leaves=512`, `n_estimators=5000`). We will rely on **Early Stopping** with a validaton set to determine the optimal number of trees, ensuring the models fully converge without overfitting (Cite solution_lesson_node_00004).

# Evaluation
*   **Inference:** The test set will be processed through the same pipeline (Cluster assignment -> Target Encoding mapping -> Feature extraction).
*   **Prediction:** Both models will generate predictions for the test set.
*   **Ensembling:** The final submission will be the **simple average** of the LightGBM and XGBoost predictions. Since both models are high-capacity "strong" learners trained on the full data, this averaging will smooth out individual model idiosyncrasies and reduce the overall RMSE.
