Based on the comprehensive analysis of previous attempts and the specific lessons learned, I propose a **Corrected Heterogeneous Ensemble with Spatiotemporal Target Encoding**. This strategy addresses the critical data preprocessing failure that invalidated "Idea 3" (Lesson 00016) while introducing a more sophisticated feature engineering paradigm to capture dynamic traffic patterns.

# Model
I propose a **Dual-Branch Gradient Boosting Ensemble** consisting of **XGBoost** and **LightGBM**.
*   **Architecture:** The solution will leverage two distinct "strong" learners.
    1.  **XGBoost Regressor:** Utilizes the `gpu_hist` tree method to exploit the NVIDIA A100 GPU for massive parallel throughput on the 55M row dataset.
    2.  **LightGBM Regressor:** Utilizes the `gbdt` boosting type, optimized for the 12 vCPUs.
*   **Rationale:** This structure adheres to the lesson that ensembles require "strong" constituent models to be effective (Cite solution_lesson_node_00011). By combining two high-capacity models trained with different algorithmic implementations (XGBoost's exact/approximate split finding vs. LightGBM's GOSS), we reduce variance without introducing the noise of a weak learner (like the unoptimized Neural Network in Idea 2).

# Data
**Preprocessing (Correction & Exploitation):**
*   **Strict Coordinate Sanitation:** I will enforce a strict bounding box filter (Lat 40-42, Lon -73 to -75) on **both the training and the test/validation sets**. This directly addresses the critical failure in Lesson 00016, where outlier coordinates in the validation set (e.g., 0,0) caused distance features to explode, rendering the RMSE metric useless.
*   **Target Sanitation:** The training data will be filtered to exclude `fare_amount` values outside the range [0, 500]. This prevents extreme outliers from destabilizing the squared-error loss (Cite solution_lesson_node_00005).
*   **Full Dataset Utilization:** The models will be trained on the complete 55 million row dataset. We will not subsample, as data volume has been proven to be the primary driver of performance (Cite solution_lesson_node_00012).

# Feature Engineering
**Structural Innovation: Spatiotemporal Target Encoding**
*   **Concept:** Standard decision trees struggle to model the interaction between "Location" and "Time" (e.g., a ride from Midtown is more expensive at 5 PM due to traffic than at 3 AM) without creating excessive splits. I propose explicitly encoding this interaction.
*   **Implementation:**
    1.  **Spatial Clustering:** Use `MiniBatchKMeans` to discretize pickup and dropoff coordinates into $K=500$ clusters.
    2.  **Interaction Feature:** Create a composite key combining `Pickup_Cluster_ID` and `Hour_of_Day`.
    3.  **Target Encoding:** Calculate the **Mean Fare Amount** for each (Cluster, Hour) pair. To prevent data leakage, these means will be computed using a **5-Fold Cross-Validation** scheme (calculating means on 4 folds and mapping them to the 5th).
    4.  **Result:** This injects a continuous feature representing the "Average Rush Hour Price" for a specific neighborhood directly into the model.

**Strategic Retention:**
*   **Rotated Coordinates:** We will retain the coordinate rotation (29° alignment) to align the feature space with the NYC street grid, enabling efficient splits (Cite solution_lesson_node_00003).
*   **Landmark Distances:** We will retain the Haversine distances to major hubs (JFK, LGA, WTC) as they provide critical global context (Cite solution_lesson_node_00003).

# Training
*   **Procedure:** The XGBoost and LightGBM models will be trained independently on the full processed dataset.
*   **Hyperparameters:** Both models will use high-capacity settings (e.g., `max_depth=10-12`, `num_leaves=512+`) to ensure they can capture the fine-grained patterns in the massive dataset (Cite solution_lesson_node_00010).
*   **Optimization:** We will use **Early Stopping** based on a held-out validation set (from the metadata split) to determine the optimal number of boosting rounds (Cite solution_lesson_node_00004).

# Evaluation
*   **Inference:** The test set will undergo the exact same cleaning (bounding box) and feature engineering pipeline. For the Target Encoding features in the test set, we will map the global means calculated from the full training set.
*   **Ensembling:** The final prediction will be a **Weighted Average** of the XGBoost and LightGBM predictions. Weights will be determined by minimizing RMSE on the validation set (e.g., 0.5/0.5 or 0.6/0.4).
