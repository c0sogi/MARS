# Model
I propose a **Two-Stage Stacked Ensemble** architecture designed to maximize the predictive power of "strong" learners while learning the optimal combination strategy.

*   **Level 0 (Base Learners):**
    1.  **XGBoost Regressor:** Configured to use the **NVIDIA A100 GPU** (`tree_method='gpu_hist'`) with deep trees (e.g., `max_depth=12`) to capture complex non-linear spatial interactions in the 55M row dataset.
    2.  **LightGBM Regressor:** Configured to use the **12 vCPUs** (`boosting_type='gbdt'`) with a high leaf count (e.g., `num_leaves=512`), leveraging its efficient Gradient-based One-Side Sampling (GOSS).
*   **Level 1 (Meta-Learner):**
    *   **Ridge Regression:** Instead of a static weighted average (as used in Idea 4 and 6), I will train a linear meta-model on the out-of-sample predictions of the base learners. This allows the system to dynamically adjust weights based on the correlation and error distribution of the base models, correcting for systematic biases.

# Data
**Preprocessing (Correction & Exploitation):**
1.  **Universal Coordinate Sanitation:** I will apply a strict bounding box filter (Latitude 40–42, Longitude -73 to -75) to the **Training, Validation, AND Test sets**. This is a mandatory correction to prevent the "distance explosion" caused by outliers (e.g., 0,0 coordinates) that invalidated previous ensemble attempts (Cite solution_lesson_node_00016).
2.  **Target Filtering:** The training data will be filtered to keep `fare_amount` between 0 and 500. This sanitization protects the squared-error loss function from extreme outliers (Cite solution_lesson_node_00005).
3.  **Full Dataset Utilization:** The base models will be trained on the complete 55 million row dataset. I will ensure no debug subsampling occurs, as data volume is the primary driver of performance (Cite solution_lesson_node_00012).

# Feature Engineering
**Strategic Retention (Correcting Idea 6):**
*   **Raw Integer Temporal Features:** I will revert to using **Raw Integers** for `Hour`, `Day_of_Week`, and `Month`. I will explicitly **discard** the Sine/Cosine cyclical embeddings used in Idea 6, as decision trees perform superior splits on raw ordinal integers compared to projected cyclical pairs (Cite solution_lesson_node_00024).
*   **Rotated Coordinates:** I will retain the 29°-rotated coordinate system to align the feature space with the NYC street grid, enabling efficient axis-aligned splits (Cite solution_lesson_node_00003).
*   **Landmark Distances:** I will retain Haversine distances to major hubs (JFK, LGA, WTC, etc.) to provide global context (Cite solution_lesson_node_00003).

**Structural Innovation (Physics & Domain Awareness):**
*   **Rotated Manhattan Distance:** I will calculate the L1 norm (Manhattan distance) specifically within the **Rotated Coordinate System** ($|\Delta Lat_{rot}| + |\Delta Lon_{rot}|$). Unlike the "crow-flies" Haversine distance, this feature approximates the actual driving distance along the grid more accurately.
*   **Airport Bounding Box Flags:** I will introduce explicit binary features (e.g., `is_JFK`, `is_LGA`) that flag if a pickup or dropoff coordinate falls within the specific bounding boxes of major airports. This allows the trees to immediately isolate "Flat Rate" trips (common for JFK) without needing to learn the complex spatial boundaries of the airport through deep splits.

# Training
*   **Strategy:** I will employ a **Hold-out Blending** strategy to train the stack efficiently given the massive dataset.
    1.  **Split:** The 55M row training set will be split into a "Base Train" set (e.g., 90%) and a "Meta Train" (Validation) set (e.g., 10%).
    2.  **Base Training:** XGBoost and LightGBM will be trained on the "Base Train" set. **Early Stopping** will be used to determine optimal iterations (Cite solution_lesson_node_00004).
    3.  **Meta Training:** The trained base models will predict on the "Meta Train" set. These predictions will form the input features for training the Ridge Regression meta-learner.

# Evaluation
*   **Inference:** The test set will undergo the exact same cleaning (bounding box) and feature engineering pipeline.
*   **Prediction:**
    1.  Generate predictions from XGBoost and LightGBM using the processed test set.
