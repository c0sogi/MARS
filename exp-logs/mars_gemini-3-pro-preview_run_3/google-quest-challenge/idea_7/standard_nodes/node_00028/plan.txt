Here is the implementation strategy and the complete `runfile.py` script.

### Implementation Strategy

1.  **Configuration & Setup**:
    *   Import the global `Config` and monkey-patch `Config.EPOCHS` and `Config.N_FOLDS` to smaller values (2 epochs, 2 folds) to satisfy the "fast baseline" requirement while ensuring the pipeline completes within the time limit.
    *   Set random seeds for reproducibility.

2.  **Pipeline Execution**:
    *   **DAPT**: Execute `run_dapt()` to adapt the DeBERTa backbone to the StackExchange domain. This utilizes the unlabeled text from train and test sets.
    *   **Fine-Tuning**: Run `run_fine_tuning()` for two streams:
        1.  `deberta`: Uses the DAPT-adapted weights.
        2.  `mpnet`: Uses the base pre-trained weights.
        This step extracts topological features ($h_{CLS}, h_Q, h_A, h_{diff}$) using Cross-Validation.
    *   **Stacking**: Execute `train_meta_stacker()` which trains Level 1 Ridge models on the extracted features and a Level 2 Meta-Ridge on the L1 predictions. This function automatically generates the submission file.

3.  **Validation & Analysis**:
    *   **Metric Calculation**: Re-load the trained Meta-Stacker and L1 predictions to generate predictions on the hold-out validation set. Compute the official metric (Mean Column-wise Spearman) and print it in the required format: `Final Validation Metric: <value>`.
    *   **Failure Analysis**: Calculate the Mean Absolute Error (MAE) for each validation row. Compute and print the correlation between this error magnitude and input text lengths (Question Body, Answer, Title) to identify error sources.

4.  **Submission Logic**:
    *   Compare the calculated validation metric against the threshold (`0.40698660691461275`).
    *   If the metric is below the threshold, remove the generated `submission.csv` file to strictly adhere to the "If and only if" requirement.
