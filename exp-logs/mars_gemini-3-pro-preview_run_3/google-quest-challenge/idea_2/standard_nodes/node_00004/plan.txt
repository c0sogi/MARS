Implementation strategy:
1.  **Configuration & Data Management**:
    - Import `library.config` first.
    - Check the size of the training metadata. If it exceeds 6,000 rows, create a subsampled version in the `./working` directory and monkey-patch `library.config.TRAIN_METADATA_PATH` to point to it. This ensures the training completes quickly within the time limit.
    - Monkey-patch `library.config.NUM_EPOCHS` if necessary to ensure runtime constraints, though the default of 3 on a small dataset is acceptable.

2.  **Pipeline Execution**:
    - **Stage 1 (Fine-tuning)**: Call `library.trainer.train_stage_1(debug=False)`. This fine-tunes the MPNet backbone and MLP head end-to-end.
    - **Feature Caching**: Call `library.feature_caching.cache_features(debug=False)`. This extracts interaction features using the fine-tuned backbone and saves them to disk as `.npy` files.
    - **Stage 2 (Refinement)**: Call `library.refinement.train_ridge_head(load_cached_model=False)`. This trains a Ridge Regression model on the cached features for better calibration.

3.  **Validation & Analysis**:
    - Manually load the validation features (`X_val`), targets (`y_val`), and the trained Ridge model.
    - Generate predictions and compute the Mean Column-wise Spearman Correlation.
    - Print the metric in the required format: `Final Validation Metric: <value>`.
    - Perform **Failure Analysis**: Calculate the row-wise Mean Absolute Error (MAE). Load the validation metadata to extract text length features (Question Length, Answer Length). Compute and print the correlation between these features and the model error.

4.  **Submission**:
    - Compare the final validation metric against the threshold `0.3001487994080418`.
    - If the score is higher, call `library.inference.predict_and_submit()` to generate the `submission.csv` file.
