Based on the comprehensive analysis of previous experiments and the derived lessons, I propose the **Dual-Backbone Cross-Encoder Ensemble with Hybrid Feature Fusion**.

This strategy represents a structural evolution from a single-model pipeline to a **multi-backbone ensemble system**. It leverages the massive available compute budget (24 hours vs. ~15 minutes used previously) to capture diverse semantic signals while strictly adhering to the efficient "Fine-Tune then Ridge" paradigm.

### Model
The architecture is a **Stacking Ensemble** composed of two distinct deep learning streams and one structural stream, feeding into a unified linear solver.

1.  **Stream 1: MPNet Cross-Encoder (The Semantic Anchor)**
    *   **Backbone:** `sentence-transformers/all-mpnet-base-v2`.
    *   **Architecture:** A **Cross-Encoder** that processes the Question and Answer as a single sequence. This preserves the "Early Interaction" advantage (Cite solution_lesson_node_00012).
    *   **Feature Extraction:** We extract **Segment-Aware Features** ($h_{CLS}, h_{Q}, h_{A}, h_{diff}$) as defined in Idea 3. This explicitly models the interaction between question and answer embeddings (Cite solution_lesson_node_00001).

2.  **Stream 2: RoBERTa Cross-Encoder (The Diversity Booster)**
    *   **Backbone:** `roberta-base`.
    *   **Rationale:** While MPNet is powerful, RoBERTa utilizes a different pre-training objective (dynamic masking) and tokenizer. Adding a second diverse backbone increases the robustness of the feature space, utilizing the available compute time to maximize performance.
    *   **Feature Extraction:** Identical Segment-Aware extraction ($h'_{CLS}, h'_{Q}, h'_{A}, h'_{diff}$).

3.  **Stream 3: Structural Meta-Features**
    *   **Components:** Explicitly engineered scalar features derived from the Data Analysis, which are often lost in high-dimensional embeddings. These include:
        *   Text Lengths (Character and Word counts for Title, Body, Answer).
        *   Length Ratios (Answer length / Question length).
    *   **Rationale:** The data analysis indicated that `answer_len_word` is a top predictor for target values.

4.  **Prediction Head: Unified Ridge Regression**
    *   **Input:** A massive concatenated vector containing features from Stream 1, Stream 2, and Stream 3.
    *   **Solver:** A Multi-Output **Ridge Regression** (RidgeCV). This replaces the neural heads of the backbones, leveraging the "Fine-Tune then Ridge" lesson to find the optimal global solution (Cite solution_lesson_node_00004).

### Data
1.  **Text Preprocessing:**
    *   Format inputs as `[CLS] Question_Title + Question_Body [SEP] Answer [SEP]` (adapted for RoBERTa's special tokens as needed).
    *   Tokenize separately for MPNet and RoBERTa, enforcing a max length of 512 tokens.
2.  **Meta-Feature Engineering:**
    *   Compute log-normalized length features to ensure they are on a similar scale to the embeddings.
    *   Standardize these features (Z-score) before passing them to the Ridge regressor.
3.  **Caching:**
    *   Implement a strict caching mechanism. After fine-tuning, run inference on all splits (Train, Val, Test) and save the feature arrays to disk. This decouples the expensive neural forward passes from the fast Ridge regression training (Cite solution_lesson_node_00003).

### Training
1.  **Stage 1: Independent Backbone Fine-Tuning**
    *   Train Stream 1 (MPNet) and Stream 2 (RoBERTa) independently on the training set.
    *   **Objective:** Minimize `BCEWithLogitsLoss` using a temporary linear head.
    *   **Stopping Criteria:** Train for up to 6 epochs, but monitor the **Validation Loss** (not the Spearman metric). Stop training immediately if the loss plateaus, to prevent the embeddings from overfitting to the temporary head and degrading for the downstream Ridge task (Cite solution_lesson_node_00013).
    *   **Optimization:** Use `AdamW` with a learning rate of 2e-5.
    *   **Batch Size:** Use a physical batch size of 8 with gradient accumulation steps of 2 (Effective Batch Size = 16). This prioritizes update frequency over gradient stability, which is crucial for this dataset size (Cite solution_lesson_node_00007).

2.  **Stage 2: Hybrid Feature Construction**
    *   Load cached features from both backbones.
    *   Compute Meta-Features.
    *   Concatenate all vectors to form the final training matrix $X_{train}$.

3.  **Stage 3: Regressor Training**
    *   Train `RidgeCV` on $X_{train}$ with Leave-One-Out Cross-Validation to automatically select the regularization strength.

### Evaluation
1.  **Inference:**
    *   Pass test data through the fine-tuned MPNet (Stream 1) and RoBERTa (Stream 2) to extract embeddings.
    *   Compute Meta-Features (Stream 3) for the test set.
2.  **Prediction:**
    *   Concatenate the features and feed them into the trained Ridge Regression model.
    *   Clip the output probabilities to the range [0, 1].
