The issue is that the `fbeta_score` function in `library/utils.py` calculates precision and recall separately. When both the predictions and targets are empty (which is common given the sparse nature of the ink), True Positives (TP), False Positives (FP), and False Negatives (FN) are all zero. This results in Precision = 0 and Recall = 0, leading to an F-Beta score of 0.0. However, a perfect match (even on empty data) should ideally score 1.0. This causes the assertion `assert np.isclose(score_perfect, 1.0)` in `runfile.py` to fail.

The fix is to modify `fbeta_score` to calculate the score directly using TP, FP, and FN counts, adding the smoothing factor to both the numerator and denominator. This mathematically equivalent formula handles the empty-empty case correctly (yielding `smooth/smooth = 1.0`) and aligns with standard segmentation metric implementations.
