Based on the accumulated lessons, I propose the **Extended Sequential Dilated Network with Parallel Context Head (ESDN-PCH)**.

This solution represents a structural synthesis of the successful sequential backbone (Lesson 00036) and the recommendation to reserve parallel aggregation for the network head (Lesson 00015). It explicitly rejects the U-Net skip connections that propagated noise (Lesson 00035) and the Group Normalization that failed on sparse signals (Lesson 00037), prioritizing a high-batch-size, full-resolution approach.

### Model: Extended Sequential Dilated Network with Parallel Context Head

The architecture is a fully convolutional network operating at full spatial resolution, designed to maximize receptive field size while maintaining training stability through batch-size preservation.

1.  **Learnable 2.5D Projection (Input Stage):**
    The network accepts the full 3D volume `(Batch, 65, H, W)` and initializes with a learnable `1x1` convolution to compress the depth dimension into a compact feature space (e.g., 32 channels). This retains the highly effective "soft" slice selection mechanism **Cite solution_lesson_node_00002**.

2.  **Extended Sequential Dilated Backbone:**
    The core feature extractor is a deep stack of **Dilated Residual Blocks** arranged sequentially.
    *   **Hierarchy:** We extend the dilation hierarchy beyond previous limits to `r = 1, 2, 4, 8, 16, 32`. This maximizes the receptive field to capture long-range stroke continuity, directly addressing the need to disambiguate signal from noise based on geometric shape **Cite solution_lesson_node_00036**.
    *   **Sequential Flow:** We strictly adhere to a sequential arrangement for the backbone, as this has been proven superior to parallel blocks for building hierarchical features (edges $\to$ textures $\to$ shapes) **Cite solution_lesson_node_00015**.
    *   **Full Resolution:** No downsampling or pooling is used. We maintain the original spatial resolution to preserve pixel-thin ink traces **Cite solution_lesson_node_00008**.
    *   **Lean Width:** The channel width is kept constant and lean (e.g., 32 or 48) to ensure the model fits in memory with a healthy batch size **Cite solution_lesson_node_00004**.

3.  **Parallel Context Head (Structural Innovation):**
    At the end of the backbone, we introduce a **Parallel Context Module** (conceptually similar to ASPP, but applied to the full-resolution map).
    *   **Structure:** The final feature map is processed by four parallel branches with dilation rates `r = 1, 6, 12, 18`. These are concatenated and fused via a `1x1` convolution.
    *   **Rationale:** As suggested in **Cite solution_lesson_node_00015**, parallel aggregation is best used at the network head. This allows the classifier to simultaneously view the local pixel neighborhood (for precision) and the broad geometric context (for consistency) immediately before making a decision, without disrupting the hierarchical feature learning in the backbone.

4.  **Batch Normalization:**
    We strictly use **Batch Normalization (BN)** throughout the network. We explicitly reject Group Normalization, as it was shown to degrade performance on sparse signals by contrast-stretching background noise **Cite solution_lesson_node_00037**.

### Data: Global Consistency and Regularization

1.  **Preprocessing:**
    Input volumes are Z-score normalized using **Global Statistics** (mean/std) derived from the training set. We reject instance normalization to preserve the physical density signal of the ink **Cite solution_lesson_node_00028**.

2.  **Patch Size & Augmentation:**
    *   **Large Context:** Training will use **large patches (256x256)**. We will not sacrifice spatial context for throughput, as this destroys the structural signal required for the extended dilation to work **Cite solution_lesson_node_00019**.
    *   **Geometric Augmentation:** Random horizontal/vertical flips and discrete 90-degree rotations will be applied to force rotational invariance **Cite solution_lesson_node_00005**.

### Training: Balanced Optimization and Stability

1.  **Batch Size Priority:**
    We will prioritize a **Batch Size of 32**. By keeping the backbone "lean" (32-48 channels), we ensure we can fit this batch size in memory. This is critical to stabilize the Batch Normalization statistics, avoiding the failure modes observed with small batches **Cite solution_lesson_node_00025**.

2.  **Loss Function:**
    The model will be trained using a **Balanced Loss** (`BCE + Dice`). We avoid skewing the loss weights (e.g., Tversky with high alpha) during training, as this degrades the quality of the learned probability landscape **Cite solution_lesson_node_00011**.

3.  **Sampling Regularization:**
    We will explicitly **limit the number of patches sampled per epoch** (e.g., to 12,000). This acts as a regularizer to prevent the model from overfitting to the specific high-frequency noise patterns of the single training fragment **Cite solution_lesson_node_00034**.

4.  **Diagnostic Monitoring:**
    We will monitor the correlation between the prediction error map and the input intensity map. A low correlation will confirm that the model is learning structural features rather than simple brightness thresholding **Cite solution_lesson_node_00017**.

### Evaluation: Precision-Oriented Inference

1.  **Tiled Inference with TTA:**
    Predictions will be generated using overlapping tiles. **Test-Time Augmentation (TTA)** (averaging predictions across 4 rotations and 2 flips) will be applied to suppress false positives caused by specific fiber orientations **Cite solution_lesson_node_00033**.

2.  **Dynamic Threshold Tuning:**
    The optimal binarization threshold will be explicitly searched for on the validation set to maximize the F0.5 score. This adapts the balanced model output to the competition's precision-weighted metric without biasing the training process **Cite solution_lesson_node_00033**.
