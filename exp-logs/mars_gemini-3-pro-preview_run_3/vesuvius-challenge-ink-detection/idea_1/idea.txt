Based on the task requirements and the provided dataset information, here is a proposal for a highly efficient baseline approach.

### Model: Shallow Full-Resolution FCN with Learnable Depth Compression

**Design & Key Components:**
The proposed model is a **Shallow Fully Convolutional Network (FCN)** that operates entirely at the original image resolution, avoiding the complex encoder-decoder structures (like U-Net) or heavy backbones (like ResNet/MiT) found in the provided examples. The architecture is designed to efficiently handle the high-dimensional Z-axis input (65 channels) while capturing local spatial context.

1.  **Input Layer:** Accepts a tensor of shape `(Batch, 65, Height, Width)`, treating the 65 depth slices as input channels.
2.  **Learnable Depth Compression (Bottleneck):** The first layer is a **1x1 Convolution** that reduces the 65 input channels to a small number of feature maps (e.g., 8 or 16). This acts as a learnable projection, allowing the network to determine the optimal weighted combination of depth slices to highlight ink, rather than relying on fixed statistics or heavy 3D operations.
3.  **Spatial Context Block:** A stack of 3 to 4 standard **3x3 Convolutional layers** (with ReLU activation and Batch Normalization). These layers capture the local spatial continuity of ink strokes (neighboring pixels) which pixel-wise models (LightGBM/SVM) miss, but without the computational cost of deep downsampling encoders.
4.  **Output Layer:** A final **1x1 Convolution** with a Sigmoid activation to produce a single probability map `(Batch, 1, Height, Width)`.

**Distinction:**
- Unlike **Model 1 (U-Net)** and **Model 2 (SegFormer)**, this architecture does not use downsampling/upsampling or deep pre-trained backbones, making it significantly faster and lighter.
- Unlike **Models 3, 4, and 5** (LightGBM, LSTM, SVM), this model utilizes 2D spatial convolutions (3x3), allowing it to learn character shapes and stroke continuity rather than treating pixels in isolation.

### Data: Preprocessing for Training and Evaluation

**Preprocessing Steps:**
1.  **Normalization:** Compute the global mean and standard deviation of pixel intensities from the training set (or a subset). Normalize all input volumes (Z-slices) using these values (Z-score normalization) to ensure consistent input distribution for the neural network.
2.  **Patch Extraction (Training):** Since the full fragment images are too large to fit in GPU memory, generate training samples by extracting fixed-size patches (e.g., $256 \times 256$) from the source volumes. Center these patches on coordinates derived from the valid `mask.png` to avoid training on empty background areas.
3.  **Label Preparation:** Crop the corresponding `inklabels.png` to match the input patches, creating binary ground truth masks (0 for no-ink, 1 for ink).

### Training: Procedure and Strategy

**Training Outline:**
1.  **Loss Function:** Use a combined **Binary Cross Entropy (BCE) + Dice Loss**. The Dice component directly optimizes the overlap metric, while BCE provides smooth gradients for pixel-level classification.
2.  **Optimizer:** Use the **Adam** optimizer with a standard learning rate (e.g., 1e-3) for fast convergence.
3.  **Strategy:** Train for a fixed number of epochs or until validation loss plateaus. Given the "baseline" nature, avoid complex scheduling or heavy augmentations. Simple random flips (horizontal/vertical) can be applied to patches to prevent overfitting.

### Evaluation: Inference on Test Data

**Prediction Process:**
1.  **Tiled Inference:** Divide the large test fragment images into overlapping tiles (e.g., $256 \times 256$ with a 32-pixel overlap).
2.  **Forward Pass:** Feed each tile into the trained model to generate probability maps.
3.  **Stitching:** Reconstruct the full-size probability map by placing the predicted tiles back into the original image coordinates. Handle overlaps by averaging the predictions in the overlapping regions to reduce edge artifacts.
4.  **Thresholding & Encoding:** Apply a fixed threshold (e.g., 0.5) to convert probabilities into a binary mask. Finally, flatten the binary mask and convert it to the required **Run-Length Encoding (RLE)** format for the `submission.csv` file.
