The `InvalidSubmissionError` with the message "setting an array element with a sequence... detected shape was (3,) + inhomogeneous part" indicates that the grading system expects the submission file to be strictly ordered by slice (grouping the 3 class predictions for each slice together). The previous implementation generated the CSV by iterating through classes first, then slices, resulting in a file sorted by class (e.g., all `large_bowel` rows, then all `small_bowel` rows). When the grader processes the file in chunks of 3 (expecting them to be the 3 classes for a single image), it encounters predictions for different slices which may have different image dimensions, causing the shape mismatch error when stacking them.

To fix this, I will apply **Cite debug_lesson_1 (Enforce Submission Structure via Template Mapping)**. I will modify `library/inference.py` to:
1.  Import `INPUT_DIR` from the configuration.
2.  Store the generated RLE predictions in a dictionary keyed by `(id, class)` instead of appending them to a list.
3.  Load the provided `sample_submission.csv` as a template.
4.  Fill the `predicted` column of the template using the lookup dictionary. This guarantees the submission file exactly matches the row order and structure expected by the grader.
