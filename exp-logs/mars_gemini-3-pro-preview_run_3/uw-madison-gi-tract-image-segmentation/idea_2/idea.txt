Based on the analysis of the previous failures and the specific lessons learned, I propose a new strategy that fundamentally improves the data normalization pipeline and upgrades the model architecture to better handle the specific challenges of MRI segmentation.

### Model
I propose replacing the Feature Pyramid Network (FPN) with a **U-Net architecture using an EfficientNet-B1 backbone**.
*   **Architecture**: While FPN is efficient, U-Net's symmetric encoder-decoder structure with concatenation-based skip connections preserves high-resolution spatial features more effectively, which is critical for delineating the complex, folded boundaries of the stomach and intestines. The **EfficientNet-B1** backbone offers a stronger feature extraction capability than the previously used ResNet-18, balancing parameter efficiency with the depth required to capture semantic context.
*   **2.5D Input**: We will retain the **2.5D input strategy** (using slices $t-1, t, t+1$ as RGB channels). This leverages volumetric context without the computational cost of 3D convolutions, a component identified as viable when normalized correctly (Cite solution_lesson_node_00004).

### Data
The primary failure mode in previous attempts was inconsistent intensity scaling. We will implement a **Robust Per-Slice Normalization** strategy to resolve the conflict between the pitfalls of simple min-max (Cite solution_lesson_node_00002) and volume-global scaling (Cite solution_lesson_node_00004).
*   **Robust Preprocessing**:
    1.  **Percentile Clipping**: For each slice, we will calculate the 1st and 99th percentiles of pixel intensity. We will clip the image values to this range $[p_{1}, p_{99}]$. This eliminates high-intensity artifacts that ruined volume-global scaling (Cite solution_lesson_node_00004).
    2.  **Min-Max Scaling**: After clipping, we apply min-max scaling to the $[0, 1]$ range.
    3.  **Noise Suppression**: To prevent the amplification of background noise in empty slices (the root cause of failure in Lesson 00002), we will check if the dynamic range ($p_{99} - p_{1}$) is below a small threshold. If so, the slice is treated as empty/background and set to zero.
*   **Augmentation**: To address the severe overfitting observed (Train Dice 0.59 vs Val Dice 0.11), we will implement a **heavy augmentation pipeline** using `Albumentations`. This will include spatial transforms (ElasticTransform, GridDistortion, ShiftScaleRotate) to mimic anatomical variations and pixel-level transforms (CoarseDropout, GaussNoise) to force the model to rely on shape context rather than texture memorization.

### Training
*   **Loss Function**: We will use a combined **BCE + Tversky Loss**. Tversky loss allows us to weigh false negatives higher than false positives (using $\alpha=0.3, \beta=0.7$), which is beneficial for segmenting small, sparse organs like the small bowel compared to standard Dice loss.
*   **Optimizer**: We will use **AdamW** with a **Cosine Annealing** learning rate scheduler to ensure convergence to a robust local minimum.

### Evaluation
*   **3D Post-Processing**: To specifically target the **Hausdorff distance** metric, we will implement **3D Connected Component Analysis (CCA)** during inference. After generating 2D predictions for all slices in a case, we will stack them into a 3D volume and retain only the largest connected component for each class. This removes scattered false-positive pixels that disproportionately penalize the Hausdorff score.
