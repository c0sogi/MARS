The implementation strategy involves the following steps:

1.  **Configuration Setup**: I will override the default `Config` parameters to create a "fast baseline". This involves setting `DEBUG` to `True` but increasing `DEBUG_SAMPLE_SIZE` to 5000 to ensure enough training data for a stable model while keeping runtime short. I will also reduce `EPOCHS` to 2.
2.  **Training**: I will execute the training pipeline using `library.train.run_training()`. This utilizes the provided U-Net EfficientNet model, BCE+Tversky loss, and data loaders.
3.  **Full Validation**: Since the training routine's debug mode also subsamples the validation set, I will manually load the *full* validation dataset after training to compute the official metric.
4.  **Metric Computation**: I will implement a custom evaluation loop that groups 2D predictions into 3D volumes (by case and day) to calculate the 3D Hausdorff distance and Dice coefficient. The final metric will be a weighted sum ($0.4 \times \text{Dice} + 0.6 \times \text{Hausdorff}$).
5.  **Failure Analysis**: I will compute the correlation between the prediction error ($1 - \text{Dice}$) and metadata features (image height, width, and normalized slice position) on the validation set to identify potential biases.
6.  **Submission**: If the calculated validation metric exceeds the threshold (0.00463659), I will invoke `library.inference.predict()` to generate the submission file.
