Based on the empirical findings and lessons learned, I propose a structural evolution of the solution from **Euclidean Triplet Learning** to **Angular Margin Classification (ArcFace)**. This approach addresses the limitations of triplet mining and margin sensitivity while preserving the robust DenseNet backbone and the open-set inference strategy.

### Model
**Backbone:** I will retain the **DenseNet121** architecture, as it was proven to outperform ResNet18 in feature extraction for this dataset (Cite `solution_lesson_node_00004`).
**Head (Structural Innovation):** Instead of the Siamese/Triplet embedding layer, I will implement an **ArcFace (Additive Angular Margin)** head.
*   **Concept:** While standard Softmax is inadequate for open-set tasks (Cite `solution_lesson_node_00001`), ArcFace modifies the classification layer to enforce a strict **Angular Margin** penalty on the hypersphere. This forces the model to learn highly discriminative, normalized embeddings where intra-class variance is minimized and inter-class distance is maximized.
*   **Pooling:** I will use a fixed **Global Average Pooling (GAP)** layer, avoiding the instability observed with learnable pooling mechanisms in this low-data regime (Cite `solution_lesson_node_00007`).
*   **Projection:** The backbone output will be fed into a Batch Normalization layer followed by a Fully Connected layer (the ArcFace "centers") that outputs the class logits.

### Data
**Preprocessing:**
*   **Filtering:** The training set will be filtered to include only images with known `Id`s. `new_whale` images will be excluded from the training loop to prevent the model from clustering distinct unknown individuals into a single class.
*   **Augmentation:** Standard geometric augmentations (rotation, flip) will be applied.
*   **Normalization:** Crucially, the input feature vectors and the ArcFace weight vectors (class centers) will be **L2-normalized** during the forward pass, as required by the angular margin objective.

### Training
**Objective:** The model will be trained using the **ArcFace Loss**.
*   **Why ArcFace?** This addresses the **Triplet Loss Margin Sensitivity** issue (Cite `solution_lesson_node_00005`) by mathematically enforcing a constant, robust margin in the angular domain ($m=0.5$) rather than tuning a Euclidean distance threshold. It also solves the "mining efficiency" problem inherent in Triplet Loss (Cite `solution_lesson_node_00004`) because every sample is compared against the learned class centers (which act as "proxies"), effectively performing hard-negative mining at every step without the computational overhead of triplet generation.
**Strategy:**
*   **Optimizer:** AdamW optimizer with a cosine annealing learning rate schedule.
*   **Class Handling:** Singletons (classes with 1 sample) are naturally handled by ArcFace; the single sample will pull the class center vector towards itself, establishing a "prototype" for that whale in the angular space.

### Evaluation
**Inference Pipeline:**
1.  **Embedding Generation:** Pass test images and the "Gallery" (training images of known whales) through the backbone to extract **L2-normalized embeddings**.
2.  **Metric:** Calculate **Cosine Similarity** between test embeddings and Gallery embeddings. This aligns the inference metric with the training objective (Angular Margin), ensuring consistency.
3.  **Ranking & Thresholding:**
    *   Retrieve the Top-K nearest neighbors from the Gallery based on Cosine Similarity.
    *   **Open-Set Recognition:** Apply a similarity threshold. If the cosine similarity to the nearest neighbor is below the threshold, predict `new_whale` (Cite `solution_lesson_node_00001`). Otherwise, predict the `Id` of the nearest neighbor.
    *   This preserves the successful "Information Retrieval" paradigm established in Lesson 1, simply swapping the Euclidean metric for the more robust Cosine metric.
