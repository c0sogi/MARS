The issue is that the `train_test_split` function with `stratify` requires the test set to be large enough to hold at least one sample from every class present in the data being split. With `test_size=0.2`, this means every class must have at least 5 samples ($0.2 \times 5 = 1$) to guarantee representation in the test set. The original code only filtered out singletons (count < 2), leaving classes with 2, 3, or 4 samples in the stratification pool. This caused the calculated test size (831) to be smaller than the number of classes (941), triggering the `ValueError`.

To fix this, I will increase the filtering threshold from `< 2` to `< 5`, ensuring that only classes with sufficient samples for a 20% split remain in the stratification process. Classes with fewer than 5 samples will be moved entirely to the training set. I will also add a safeguard to handle the case where `df_multi` might be empty.
