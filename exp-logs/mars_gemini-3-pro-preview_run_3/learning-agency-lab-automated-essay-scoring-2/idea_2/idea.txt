Based on the lessons learned and the available computational resources (NVIDIA A100), I propose a **Two-Stage Hybrid Architecture** that evolves from using frozen generic embeddings to **fine-tuned task-specific representations**, while retaining the successful structural meta-features and gradient boosting head.

### Model
The proposed solution utilizes a two-stage architecture designed to overcome the limitations of generic embeddings and length truncation:

1.  **Stage 1: Fine-Tuned Backbone with Sliding Window Pooling**
    *   **Architecture:** Replace the frozen `all-MiniLM-L6-v2` with a **DeBERTa-v3-base** transformer. This model is significantly more powerful at capturing subtle semantic nuances and argumentation structures.
    *   **Innovation (Task-Adaptation):** Unlike previous iterations where the backbone was frozen, this model will be **fine-tuned** on the training data. This allows the embeddings to align with the specific scoring rubric rather than relying on generic semantic similarity.
    *   **Innovation (Context Handling):** To address the essay length truncation observed in the EDA (essays up to 18k characters vs. 512 token limits), we will implement a **Sliding Window Embedding Strategy**. During inference/feature extraction, the text will be split into overlapping chunks (e.g., 512 tokens with 128 overlap). Each chunk will be encoded by the fine-tuned backbone, and the resulting `[CLS]` embeddings will be **mean-pooled** to create a single, comprehensive "Whole-Essay" representation vector.

2.  **Stage 2: Hybrid Gradient Boosting Head**
    *   **Input:** The high-dimensional task-specific embeddings from Stage 1 are concatenated with the **explicit structural meta-features** (word counts, sentence counts, lexical diversity, etc.) identified as critical in previous experiments (Cite solution_lesson_node_00002, solution_lesson_node_00004).
    *   **Regressor:** A **LightGBM** model is used as the final scoring head. This preserves the ability to model non-linear interactions between the dense semantic vectors and the scalar structural features (Cite solution_lesson_node_00004).

### Data
1.  **Text Preprocessing:**
    *   Use the `DeBERTa-v3-base` tokenizer.
    *   For Stage 1 training: Apply dynamic padding and random cropping/truncation to fit the sequence length (e.g., 1024 tokens if memory permits, or 512).
    *   For Stage 2 feature extraction: Implement the sliding window logic to generate chunks for every essay in Train, Validation, and Test sets.
2.  **Meta-Feature Extraction:**
    *   Calculate the suite of structural features: character count, word count, sentence count, paragraph count, average sentence length, and unique word ratio.
    *   Apply standard scaling to these features before concatenation (Cite solution_lesson_node_00002).

### Training
1.  **Stage 1 (Backbone Fine-Tuning):**
    *   Train the DeBERTa-v3-base model with a linear regression head.
    *   **Objective:** Minimize **Mean Squared Error (MSE)**, treating the ordinal scores as continuous targets (Cite solution_lesson_node_00001).
    *   **Optimization:** Use AdamW optimizer with a linear learning rate decay. Save the checkpoint with the best validation MSE.
2.  **Feature Extraction:**
    *   Load the best Stage 1 checkpoint.
    *   Pass all data (Train/Val/Test) through the model using the Sliding Window strategy to generate the pooled embedding vectors (e.g., 768 dimensions).
3.  **Stage 2 (GBM Training):**
    *   Train the LightGBM model on the combined dataset (Pooled Embeddings + Meta-Features).
    *   **Objective:** Minimize MSE (Regression).
    *   **Critical Hyperparameter:** Set `feature_fraction` (subsampling) to < 1.0 (e.g., 0.7-0.9) to ensure the model utilizes the semantic embeddings and does not over-rely on the strong length-based meta-features (Cite solution_lesson_node_00006).

### Evaluation
1.  **Inference:**
    *   Preprocess test essays into overlapping chunks.
    *   Generate embeddings using the fine-tuned DeBERTa model and mean-pool them.
    *   Calculate meta-features for test essays.
    *   Predict continuous scores using the trained LightGBM model.
2.  **Post-Processing:**
    *   Clip predictions to the range [1, 6].
    *   Round predictions to the nearest integer to satisfy the submission format and maximize the Quadratic Weighted Kappa metric (Cite solution_lesson_node_00001).
