The implementation strategy follows a two-stage hybrid approach orchestrated within a single script. 

1.  **Configuration & Setup**: We initialize the environment and set random seeds for reproducibility. Crucially, we override `Config.EPOCHS` to 1. This ensures the fine-tuning process is fast enough to serve as a baseline while still adapting the DeBERTa backbone to the task.
2.  **Meta-Feature Engineering**: We execute the `FeatureEngineer` to extract structural features (e.g., word counts, sentence lengths) from the text. Caching is enabled to avoid redundant computation if the files already exist.
3.  **Stage 1 (Backbone Fine-Tuning)**: We instantiate `Stage1Trainer` to fine-tune the DeBERTa-v3-base model on the training data. After training, we run the embedding extraction process. We explicitly disable loading cached embeddings (`load_cached_data=False`) to ensure the embeddings are generated from the newly trained model, utilizing the sliding window strategy to handle long essays.
4.  **Stage 2 (Gradient Boosting Head)**: We use `LGBMHandler` to train a LightGBM regressor. This model learns to predict scores based on the concatenation of the dense semantic embeddings from Stage 1 and the explicit meta-features.
5.  **Validation & Analysis**: We manually reconstruct the validation set features to generate predictions. We compute the Quadratic Weighted Kappa (QWK) and print it in the required format. We also perform failure analysis by calculating the correlation between the model's prediction errors and the input meta-features to identify systematic weaknesses.
6.  **Submission**: Finally, we check if the validation QWK exceeds the specified threshold. If it does, we generate predictions for the test set and save the `submission.csv`.
