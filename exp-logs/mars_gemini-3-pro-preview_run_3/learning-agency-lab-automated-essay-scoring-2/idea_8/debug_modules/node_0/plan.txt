This ensures the code runs quickly and doesn't overwrite existing work.
2.  **Module Imports**: Import the necessary functions from `library.data`, `library.model`, `library.trainer`, and `library.stacking` *after* modifying the `Config` to ensure default arguments in those modules reflect the updated configuration.
3.  **Data Pipeline Verification**: Call `get_dataloaders` and inspect a single batch from the training loader. Assert that all required keys (`input_ids`, `attention_mask`, `batch_ids`, etc.) are present and that tensor shapes match the configured batch size and sequence length.
4.  **Model Logic Verification**: Instantiate the `EssayModel`, move it to the configured device, and perform a forward pass using the verified batch. Assert that the model outputs valid `logits` and `embeddings` with the correct dimensions.
5.  **Training Loop Execution**: Execute `train_fold(0)`. This tests the entire training pipeline, including the optimizer, scheduler, and Adversarial Weight Perturbation (AWP). Verify that the model checkpoint and Out-Of-Fold (OOF) embeddings are saved to disk.
6.  **Stacking and Inference**: Execute `train_stacking` to train the LightGBM head on the generated OOF embeddings, followed by `predict_stacking` to generate predictions on the test set. Verify that the final `submission.csv` is created and follows the correct format.
