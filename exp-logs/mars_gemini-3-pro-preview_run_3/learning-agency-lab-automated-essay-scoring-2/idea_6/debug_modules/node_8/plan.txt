The training process fails with `NaN` loss because the Adversarial Weight Perturbation (AWP) implementation mixes unscaled and scaled gradients. Specifically, `scaler.unscale_(optimizer)` is called before the AWP attack (correctly, per Debug Lesson 8, to ensure perturbations are based on true gradient magnitudes), converting existing gradients in `param.grad` to unscaled float32 values. However, the subsequent adversarial backward pass uses `scaler.scale(loss_adv).backward()`, which accumulates *scaled* gradients (multiplied by the scaling factor, e.g., 65536) into the now-unscaled `param.grad`. This results in gradient values that are orders of magnitude too large, causing the optimizer step to explode the weights. The fix is to remove the scaling from the adversarial backward pass by calling `loss_adv.backward()` directly, ensuring that unscaled gradients are accumulated consistent with the state of the optimizer (Cite debug_lesson_8).
