The `RuntimeError` is caused by using `-1e9` as a masking value in the `AttentionPooling` layer. During mixed precision training (`torch.amp.autocast`), operations are performed in `float16`, which has a minimum representable value of approximately -65,504. The value `-1e9` causes an overflow when cast to `float16`. To fix this, I will change the masking value to `-1e4`, which fits within the `float16` range and is sufficiently small to ensure the softmax output is zero (Cite debug_lesson_3).
