### Implementation Strategy

1.  **Configuration Override**: To ensure the demonstration runs quickly (well within the time limit), we will override specific `Config` parameters at runtime. We will reduce the number of epochs to 1, the number of stacking folds to 2, and significantly subset the dataset (e.g., 50 training samples) to simulate the pipeline without processing the entire 40GB+ dataset.
2.  **Data Pipeline Verification**: We will load the metadata using `library.data`, subset the DataFrames manually for speed, and create DataLoaders. We will verify the batch shapes produced by the DataLoaders.
3.  **Model Instantiation & Fine-Tuning (Stage 1)**: We will instantiate the `AdaptiveBackbone` model from `library.models`. We will run the `run_fine_tuning` function from `library.engine` on the subsetted data to demonstrate the training loop and weight saving mechanism.
4.  **Feature Extraction**: Using the fine-tuned model, we will extract embeddings for the training, validation, and test sets using `library.engine.extract_features`. We will assert that the output dimensions match the expected feature size (Backbone embeddings + Metadata features).
5.  **Ensemble Training (Stage 2)**: We will initialize the `StackingRegressor` from `library.ensemble`. We will run `cross_validate_and_fit` on the extracted training features to train the Level 1 (SVR, LightGBM, Ridge) and Level 2 (Linear Regression) models.
6.  **Inference & Submission**: We will generate predictions for the test set using the fitted ensemble and save the results using `library.utils.save_submission`. Finally, we will verify the existence and format of the submission file.
