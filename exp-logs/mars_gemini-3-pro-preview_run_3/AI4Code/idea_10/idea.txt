# Solution: Distribution-Aware Semantic Regressor (DASR)

### Model
I propose a **Distribution-Aware Hybrid Architecture** that evolves the "High-Capacity Smoothed Semantic Regressor" (Idea 8) by introducing a **Global Structural Heatmap** feature. This addresses the limitation of scalar point-estimates (like `argmax`) which discard the global context of the alignment distribution, while strictly adhering to the "Spatial Location" priority identified in Lesson 00007.

1.  **High-Capacity Semantic Backbone:**
    *   **Architecture:** `sentence-transformers/all-mpnet-base-v2`.
    *   **Rationale:** I retain the MPNet backbone as it offers superior semantic resolution for abstract markdown compared to smaller models, provided it is fed sufficient data. Cite solution_lesson_node_00030
2.  **Distribution-Aware Feature Engineering:**
    *   **Local Spatial Anchors (Smoothed):** Apply **1D Convolutional Smoothing** to the pairwise cosine similarity vector and extract `best_match_loc` and `center_of_mass`. This provides robust, precise localization for the primary alignment target. Cite solution_lesson_node_00030
    *   **Global Structural Heatmap (Innovation):** Resample (interpolate) the raw similarity vector of every notebook to a fixed length $K=20$. This creates a normalized "heatmap" vector representing the markdown cell's affinity across the *entire* topological span of the notebook (e.g., "high similarity in the first 5% vs. the last 5%"). Unlike scalar statistics (entropy/quantiles) which failed because they were spatially invariant (Cite solution_lesson_node_00007), this feature vector preserves **spatial structure** at a coarse resolution, allowing the regressor to learn global patterns (e.g., "Imports are at the beginning") that complement the local `argmax`.
    *   **Global Context:** Explicitly include `n_code` and `md_len` to scale the normalized predictions. Cite solution_lesson_node_00015
3.  **Regressor Head:**
    *   **Architecture:** **LightGBM Regressor**.
    *   **Rationale:** Tree-based models outperform end-to-end Transformers when provided with explicit, spatially-grounded alignment features. Cite solution_lesson_node_00012

### Data
**Preprocessing:**
1.  **Fine-Tuning Dataset (Scaled Relaxed Proximity):**
    *   Construct **Positive Pairs** $(M, C_{target})$ by pairing every markdown cell with its **nearest subsequent** code cell.
    *   **Volume:** Scale the fine-tuning dataset to **50,000 notebooks** (~50% of the training data).
    *   **Rationale:** This corrects the "Strict Adjacency" flaw (Cite solution_lesson_node_00027) and maximizes the data volume for the high-capacity MPNet backbone. Lesson 00028 proved that data volume trumps model complexity; 50k samples is the maximum feasible volume to process with MPNet within the 24-hour limit.
2.  **Regression Dataset (Full Volume):**
    *   Utilize the **Full Training Dataset** (~95,000 notebooks) for the LightGBM stage.
    *   **Rationale:** The regressor requires the maximum possible data volume to resolve the interactions between the new high-dimensional "Heatmap" features and the target position. Cite solution_lesson_node_00009

### Training
1.  **Stage 1: Contrastive Fine-Tuning**
    *   **Objective:** Optimize **Multiple Negatives Ranking Loss (MNRL)**.
    *   **Procedure:** Train the `all-mpnet-base-v2` backbone for 1 epoch on the 50k notebook subset. This aligns the embedding space to encode structural proximity. Cite solution_lesson_node_00025
2.  **Stage 2: Regression Training**
    *   **Objective:** Minimize **Mean Squared Error (MSE)**.
    *   **Procedure:** Train LightGBM to predict the normalized rank $y \in [0, 1]$ using the concatenated feature vector (Local Anchors + Global Heatmap + Context).

### Evaluation
1.  **Inference:**
    *   Encode all test set cells using the fine-tuned MPNet backbone.
    *   Compute the Pairwise Cosine Similarity Matrix.
    *   **Feature Extraction:**
        *   Apply Smoothing -> Extract `best_match_loc`, `center_of_mass`.
        *   Apply Resampling (Interpolation) -> Extract 20-dim `heatmap` vector.
        *   Append `n_code`, `md_len`.
    *   Predict normalized position $\hat{y}$ using LightGBM.
2.  **Ordering:**
    *   Convert $\hat{y}$ to integer rank: $Rank_{pred} = \hat{y} \times n\_code$.
    *   Sort the combined sequence of Code (fixed) and Markdown (predicted) cells to produce the final `cell_order`.
