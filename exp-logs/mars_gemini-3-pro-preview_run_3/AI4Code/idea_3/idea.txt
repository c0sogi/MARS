Based on the lessons learned from the previous experiments, I propose a solution that evolves the "Aggregated Semantic Signal Regressor" by introducing a **Domain-Adaptive Contrastive Fine-Tuning** stage. This addresses the "Lexical Gap" identified in failure analyses (where generic embeddings fail to link abstract markdown to specific code) while retaining the robust, explicit feature engineering strategy that outperformed end-to-end deep learning.

# Solution: Contrastive Fine-Tuned Semantic Regressor (CFSR)

### Model
The architecture consists of a three-stage pipeline designed to maximize the quality of the alignment signal before it reaches the regressor:

1.  **Semantic Backbone (Fine-Tuned):** Instead of using the off-the-shelf `all-MiniLM-L6-v2` (which generates generic embeddings), we employ a **Siamese Network** architecture initialized with `all-MiniLM-L6-v2`. This backbone is fine-tuned to explicitly project markdown cells and their subsequent code cells into a shared embedding space where they are spatially close. This ensures that the "Best Match" signal is not just semantically related but **topologically predictive**. (Cite solution_lesson_node_00006)
2.  **Explicit Feature Extractor:** We retain the logic of converting the similarity matrix into explicit positional statistics. By using the fine-tuned embeddings, the **Argmax (Best Match Location)** and **Center of Mass** features become significantly more reliable "anchors" for the downstream model. (Cite solution_lesson_node_00012)
3.  **Regressor Head:** We utilize **LightGBM** as the final predictor. As proven in previous iterations, tree-based models outperform Transformers when provided with explicit alignment features and global context metadata. (Cite solution_lesson_node_00012)

### Data
**Preprocessing:**
1.  **Fine-Tuning Dataset Construction:** Iterate through the training notebooks to create **Positive Pairs** $(M_i, C_{next})$, where $M_i$ is a markdown cell and $C_{next}$ is the code cell immediately following it in the ground truth order.
2.  **Feature Extraction (Post-Tuning):**
    *   Pass all code and markdown cells through the *fine-tuned* backbone to generate updated embeddings.
    *   Compute the pairwise Cosine Similarity Matrix.
    *   Extract **Alignment Features**: `best_match_loc` (index of max similarity), `center_of_mass` (weighted average index), `sim_max` (value of max similarity), and `sim_mean`. (Cite solution_lesson_node_00004)
    *   Extract **Global Context Features**: Explicitly include `n_code` (total number of code cells) and `md_len` (length of markdown text). This allows the regressor to scale the normalized position predictions correctly against the notebook size. (Cite solution_lesson_node_00015)
3.  **Target Generation:** Calculate the normalized rank $y \in [0, 1]$ for each markdown cell based on the ground truth order.

### Training
1.  **Stage 1: Contrastive Fine-Tuning:**
    *   Train the backbone using **Multiple Negatives Ranking Loss (MNRL)**. For a given batch of positive pairs $(M_i, C_{next})$, the model optimizes to maximize the similarity of the true pair while minimizing the similarity of $M_i$ to all other code cells in the batch (in-batch negatives).
    *   Train for 1-2 epochs on the full training set. This is computationally efficient and sufficient to align the vector space.
2.  **Stage 2: Regression Training:**
    *   Train the LightGBM regressor on the full dataset (~95k notebooks) using the features derived from the new embeddings. (Cite solution_lesson_node_00009)
    *   Objective: Minimize **Mean Squared Error (MSE)**.

### Evaluation
1.  **Inference:**
    *   Generate embeddings for the test set using the fine-tuned backbone.
    *   Construct the feature vector (Alignment + Global Context) for each markdown cell.
    *   Predict the normalized position $\hat{y}$ using LightGBM.
2.  **Ordering:**
    *   Convert the predicted normalized position to an integer rank: $Rank_{pred} = \hat{y} \times n\_code$.
    *   Sort all cells (Code cells at fixed indices $0, 1, \dots$, Markdown cells at $Rank_{pred}$) to produce the final `cell_order`.
