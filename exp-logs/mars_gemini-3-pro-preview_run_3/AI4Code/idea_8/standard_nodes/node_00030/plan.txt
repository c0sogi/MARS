Implementation Strategy:
1.  **Configuration & Setup**: I will override the default `Config` parameters to enable `DEBUG` mode and reduce the sample size to 3000. This ensures the pipeline (fine-tuning, feature extraction, and training) completes within the 2-hour limit while providing enough data for a robust baseline. I will also set random seeds for reproducibility.
2.  **Pipeline Execution**:
    *   **Fine-Tuning**: Initialize the `FineTuner` and train the MPNet backbone on "relaxed pairs" (Markdown + Nearest Subsequent Code) to align semantic spaces.
    *   **Feature Extraction**: Use the fine-tuned model to generate features (`smoothed_best_match_loc`, `sim_max`, etc.) for both training and validation sets. This involves encoding cells, computing similarity matrices, and applying 1D smoothing.
    *   **Regressor Training**: Train the `LGBMRanker` on the extracted features to predict the normalized rank of markdown cells.
3.  **Validation & Analysis**:
    *   Predict ranks for the validation set and rescale them by `n_code` to get relative positions.
    *   Reconstruct the cell order using the `reconstruct_order` utility.
    *   Compute the Kendall Tau correlation against the ground truth.
    *   Perform failure analysis by correlating the prediction error with input features (`n_code`, `md_len`, `sim_max`) to diagnose weaknesses.
4.  **Submission**:
    *   Check if the validation metric exceeds the threshold (0.8061).
    *   If successful, generate features for the *full* test set (ignoring debug limits), predict ranks, reconstruct orders, and save the `submission.csv` file.
