# Solution: High-Capacity Smoothed Semantic Regressor (HC-SSR)

### Model
I propose a **High-Capacity Hybrid Architecture** that synthesizes the superior semantic resolution of large Transformers with the robust explicit feature engineering of tree-based regressors. This design directly addresses the "Lexical Gap" (Cite solution_lesson_node_00004) and "Data Starvation" (Cite solution_lesson_node_00027) issues identified in previous iterations.

1.  **Semantic Backbone:**
    *   **Architecture:** `sentence-transformers/all-mpnet-base-v2`.
    *   **Rationale:** I replace the lightweight `all-MiniLM-L6-v2` with the significantly more powerful MPNet. Previous attempts to use specialized models (like CodeBERT) failed due to the complexity penalty reducing the training data volume (Cite solution_lesson_node_00028). MPNet offers a superior balance: it is a single, high-capacity model capable of resolving abstract markdown descriptions (e.g., "Visualization") into specific code semantics, provided it is fed sufficient data.
2.  **Contextual Density Smoothing:**
    *   **Component:** A **1D Smoothing Convolution** (window size=3, kernel=`[0.2, 0.6, 0.2]`) applied to the code-axis of the cosine similarity matrix.
    *   **Rationale:** Raw `argmax` extraction is brittle; a single outlier code cell can trigger a false positive. By smoothing the similarity vector before feature extraction, we identify the "dense center" of the semantic match (e.g., a block of 3 code cells), creating a more robust spatial anchor (Cite solution_lesson_node_00004).
3.  **Regressor Head:**
    *   **Architecture:** **LightGBM Regressor**.
    *   **Features:**
        *   **Spatial Anchors:** `smoothed_best_match_loc` and `smoothed_center_of_mass`. (Cite solution_lesson_node_00007)
        *   **Signal Strength:** `sim_max` (from the smoothed vector). This acts as a confidence gate. (Cite solution_lesson_node_00025)
        *   **Global Context:** `n_code` (sequence length) and `md_len`. These are strictly required to scale the normalized position predictions. (Cite solution_lesson_node_00015)
    *   **Rationale:** Explicit alignment features fed into a tree-based model consistently outperform end-to-end deep learning for this task (Cite solution_lesson_node_00012).

### Data
**Preprocessing:**
1.  **Fine-Tuning Dataset (Relaxed Proximity):**
    *   Construct **Positive Pairs** $(M, C_{target})$ by pairing *every* markdown cell $M$ with its **nearest subsequent** code cell $C_{target}$ in the ground truth order.
    *   **Innovation:** This explicitly corrects the "Strict Adjacency" flaw from previous multi-view attempts. By allowing non-adjacent pairing (e.g., capturing the relationship in `MD -> MD -> Code`), we ensure the high-capacity MPNet backbone receives the full volume of ~370k training pairs needed to learn robust alignment, preventing data starvation (Cite solution_lesson_node_00027).
2.  **Regression Dataset (Full Volume):**
    *   Utilize the **Full Training Dataset** (~95,000 notebooks) for the LightGBM stage.
    *   **Rationale:** High-capacity embeddings contain nuanced signals that require maximum data volume for the regressor to resolve without saturating (Cite solution_lesson_node_00009).

### Training
1.  **Stage 1: Contrastive Fine-Tuning**
    *   **Objective:** Optimize **Multiple Negatives Ranking Loss (MNRL)**.
    *   **Procedure:** Train the `all-mpnet-base-v2` backbone for 1 epoch on the Relaxed Proximity pairs. This aligns the embedding space such that markdown cells are topologically close to the code blocks they describe (Cite solution_lesson_node_00025).
2.  **Stage 2: Regression Training**
    *   **Objective:** Minimize **Mean Squared Error (MSE)**.
    *   **Procedure:** Train LightGBM to predict the normalized rank $y \in [0, 1]$ using the smoothed alignment features and global context.

### Evaluation
1.  **Inference:**
    *   Encode all test set cells using the fine-tuned MPNet backbone.
    *   Compute the Pairwise Cosine Similarity Matrix for each notebook.
    *   Apply **1D Smoothing** to the similarity vectors.
    *   Extract features (`smoothed_best_match_loc`, `smoothed_center_of_mass`, `sim_max`, `n_code`, `md_len`).
    *   Predict normalized position $\hat{y}$ using LightGBM.
2.  **Ordering:**
    *   Convert $\hat{y}$ to integer rank: $Rank_{pred} = \hat{y} \times n\_code$.
    *   Construct the sequence with Code cells at fixed indices and Markdown cells at $Rank_{pred}$.
    *   Sort to produce the final `cell_order`.
