# Solution: Multi-Scale Structural Alignment Regressor (MSSAR)

### Model
I propose a **Multi-Scale Hybrid Architecture** that evolves the "Smoothed Semantic Regressor" (Idea 8) by introducing a **Multi-Scale Feature Extraction** paradigm. This addresses the limitation of using a fixed smoothing kernel, allowing the model to dynamically resolve alignment signals for both atomic code lines and large code blocks.

1.  **High-Capacity Semantic Backbone:**
    *   **Architecture:** `sentence-transformers/all-mpnet-base-v2`.
    *   **Rationale:** I retain the MPNet backbone, which demonstrated extreme data efficiency and superior semantic resolution compared to smaller models like MiniLM. Cite solution_lesson_node_00030
2.  **Multi-Scale Signal Processing:**
    *   **Innovation:** Instead of applying a single fixed smoothing kernel (as in Idea 8), I introduce **Multi-Scale Convolutional Smoothing**. The pairwise cosine similarity vector (representing the markdown cell's affinity to the sequence of code cells) is processed through three parallel channels:
        *   **Fine Scale (k=1):** Raw similarity scores. Captures precise alignment to single code cells (e.g., specific variable definitions).
        *   **Medium Scale (k=3):** Smoothed with a window of 3. Captures alignment to small logical blocks (e.g., a function definition).
        *   **Coarse Scale (k=5):** Smoothed with a window of 5. Captures alignment to large code chunks (e.g., an entire plotting routine).
    *   **Rationale:** Markdown cells vary in scope; some describe a single line, while others introduce a multi-cell module. A fixed kernel forces a compromise (blurring fine details or missing broad trends). Multi-scale extraction preserves the signal structure at all relevant resolutions.
3.  **Regressor Head:**
    *   **Architecture:** **LightGBM Regressor**.
    *   **Input:** A concatenated feature vector containing **Spatial Anchors** (`best_match_loc`, `center_of_mass`) and **Signal Strength** (`sim_max`) extracted from *each* of the three scales, plus **Global Context** (`n_code`, `md_len`).
    *   **Rationale:** Explicit alignment features fed into a tree-based model outperform end-to-end deep learning. Cite solution_lesson_node_00012. Including global context is strictly required for scaling normalized predictions. Cite solution_lesson_node_00015

### Data
**Preprocessing:**
1.  **Fine-Tuning Dataset (Scaled Relaxed Proximity):**
    *   Construct **Positive Pairs** $(M, C_{target})$ by pairing every markdown cell with its **nearest subsequent** code cell in the ground truth order.
    *   **Volume:** Scale the fine-tuning dataset to **40,000 notebooks** (approx. 40% of training data).
    *   **Rationale:** This strategy corrects the "Strict Adjacency" flaw (Cite solution_lesson_node_00027) and significantly increases the data volume compared to Idea 8 (3k notebooks), ensuring the high-capacity MPNet backbone is robustly trained without violating the 24-hour time limit.
2.  **Regression Dataset (Full Volume):**
    *   Utilize the **Full Training Dataset** (~95,000 notebooks) for the LightGBM stage.
    *   **Rationale:** The regressor requires the maximum possible data volume to learn the complex interactions between the multi-scale features and resolve subtle positioning logic. Cite solution_lesson_node_00009

### Training
1.  **Stage 1: Contrastive Fine-Tuning**
    *   **Objective:** Optimize **Multiple Negatives Ranking Loss (MNRL)**.
    *   **Procedure:** Train the `all-mpnet-base-v2` backbone for 1 epoch on the 40k notebook subset. This transforms the embedding space to encode "structural proximity" rather than just linguistic similarity. Cite solution_lesson_node_00025
2.  **Stage 2: Regression Training**
    *   **Objective:** Minimize **Mean Squared Error (MSE)**.
    *   **Procedure:** Train LightGBM to predict the normalized rank $y \in [0, 1]$ using the multi-scale alignment features.

### Evaluation
1.  **Inference:**
    *   Encode all test set cells using the fine-tuned MPNet backbone.
    *   Compute the Pairwise Cosine Similarity Matrix for each notebook.
    *   Apply **Multi-Scale Smoothing** (k=1, 3, 5) to generate three versions of the similarity vector per markdown cell.
    *   Extract features (`best_match_loc`, `center_of_mass`, `sim_max`) from all three scales and append `n_code` and `md_len`.
    *   Predict normalized position $\hat{y}$ using LightGBM.
2.  **Ordering:**
    *   Convert $\hat{y}$ to integer rank: $Rank_{pred} = \hat{y} \times n\_code$.
    *   Construct the sequence with Code cells at fixed indices and Markdown cells at $Rank_{pred}$.
    *   Sort to produce the final `cell_order`.
