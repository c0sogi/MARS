The solution implements the **Dual-View Structural Alignment Regressor (DVSAR)** pipeline.

### Strategy Outline
1.  **Data Sampling**: To ensure the pipeline runs within the strict time limits while maintaining performance, we sample 5,000 notebooks from the training set. This sampled dataset is used for both the contrastive fine-tuning of the backbones and the training of the LightGBM regressor. The validation is performed on the **full** validation set to ensure rigorous metric calculation.
2.  **Stage 1: Backbone Fine-Tuning**: We fine-tune two separate sentence transformer models:
    *   **Text-View**: `all-MiniLM-L6-v2` to capture semantic similarity.
    *   **Code-View**: `microsoft/codebert-base` to capture syntactic and structural alignment.
    *   We use **Multiple Negatives Ranking Loss** on pairs of (Markdown, Nearest Subsequent Code) to align the vector spaces.
3.  **Stage 2: Feature Extraction**: We use the fine-tuned backbones to compute similarity matrices between all markdown and code cells in a notebook. From these matrices, we extract explicit structural features: `sim_max` (confidence), `best_match_loc` (position of max similarity), and `center_of_mass` (weighted position).
4.  **Stage 3: Regression**: A **LightGBM Regressor** is trained to predict the normalized rank ($rank / n\_code$) of each markdown cell based on the extracted features and global context (`n_code`, `md_len`).
5.  **Validation & Analysis**: We evaluate the model on the full validation set using the **Kendall Tau** metric. We also perform failure analysis by correlating prediction errors with input features to identify weaknesses (e.g., performance on long notebooks).
6.  **Submission**: If the validation score exceeds the baseline threshold (0.8061), we generate predictions for the test set and save the `submission.csv`.
