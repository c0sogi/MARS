# Solution: Dual-View Structural Alignment Regressor (DVSAR)

### Model
I propose a **Dual-View Hybrid Architecture** that synthesizes the strengths of semantic text understanding and code-specific structural understanding. This approach corrects the data starvation flaw identified in previous multi-view attempts while retaining the superior explicit feature engineering strategy.

1.  **Dual-Backbone Encoder:**
    *   **Text-View Backbone:** `all-MiniLM-L6-v2`. This model is retained for its efficiency and proven performance in capturing general linguistic similarity between markdown descriptions and code comments. Cite solution_lesson_node_00006
    *   **Code-View Backbone:** `microsoft/codebert-base`. This model is introduced to address the "Lexical Gap" where generic sentence transformers fail to recognize specific library calls or syntactic structures (e.g., `plt.plot` vs. "visualization"). By processing the notebook through this bimodal model (pre-trained on code and text), we extract a complementary set of alignment signals rooted in programming syntax.
2.  **Explicit Feature Extractor:**
    *   For each markdown cell, we compute two distinct **Cosine Similarity Matrices** (one from each backbone) against the notebook's code cells.
    *   From *each* matrix, we extract **Spatial Alignment Features**: `best_match_loc` (index of max similarity) and `center_of_mass` (similarity-weighted average index). We prioritize these over distributional statistics like entropy to avoid noise. Cite solution_lesson_node_00007
    *   We also extract **Signal Strength Features**: `sim_max` (maximum similarity value). This serves as a confidence gate, allowing the regressor to weigh the "Code-View" vs. "Text-View" signals dynamically (e.g., trusting CodeBERT more when `sim_max` is high for a code-specific query).
    *   **Global Context:** We explicitly include `n_code` (total code cells) and `md_len` (markdown length) to enable the regressor to correctly scale the normalized position predictions. Cite solution_lesson_node_00015
3.  **Regressor Head:**
    *   A **LightGBM Regressor** is trained on the concatenated feature vector (Text-View Features + Code-View Features + Global Context). This retains the finding that tree-based models outperform end-to-end Transformers when provided with explicit alignment anchors. Cite solution_lesson_node_00012

### Data
**Preprocessing:**
1.  **Relaxed Proximity Pairing (Correction):**
    *   We construct the fine-tuning dataset by pairing **every** markdown cell with the **nearest subsequent** code cell in the ground truth order.
    *   *Crucial Correction:* Unlike previous attempts that used strict adjacency (discarding markdown cells not immediately touching code), this "Relaxed Proximity" strategy ensures we capture valid semantic relationships even in blocks of multiple markdown cells (e.g., `MD -> MD -> Code`), preventing data starvation. Cite solution_lesson_node_00027
2.  **Feature Generation:**
    *   Pass all notebook cells through both fine-tuned backbones to generate embeddings.
    *   Compute the two similarity matrices and extract the explicit features defined above.
    *   Normalize the `best_match_loc` and `center_of_mass` by `n_code` to create scale-invariant features.

### Training
1.  **Stage 1: Independent Contrastive Fine-Tuning:**
    *   We fine-tune `all-MiniLM-L6-v2` and `microsoft/codebert-base` independently using **Multiple Negatives Ranking Loss (MNRL)** on the Relaxed Proximity pairs.
    *   This step aligns the vector spaces of both models such that a markdown cell and its corresponding code block are spatially close, transforming the embeddings from "semantically similar" to "structurally predictive." Cite solution_lesson_node_00025
2.  **Stage 2: Regression Training:**
    *   We train the LightGBM regressor on the **full dataset** (~95k notebooks).
    *   Using the full data volume is critical to allow the regressor to learn the complex interactions between the two views (e.g., learning when to rely on CodeBERT's syntax matching vs. MiniLM's semantic matching) without saturating. Cite solution_lesson_node_00009
    *   **Objective:** Minimize Mean Squared Error (MSE) between the predicted normalized rank and the true normalized rank.

### Evaluation
1.  **Inference:**
    *   Encode the test set using both fine-tuned backbones.
    *   Generate the concatenated feature vector for every markdown cell.
    *   Predict the normalized relative position $\hat{y} \in [0, 1]$ using the trained LightGBM model.
2.  **Ordering:**
    *   Convert the predicted normalized position to an integer rank: $Rank_{pred} = \hat{y} \times n\_code$.
    *   Construct the final sequence by placing code cells at their fixed indices $0, 1, \dots$ and inserting markdown cells at their predicted $Rank_{pred}$.
    *   Sort the combined list to produce the final `cell_order`.
