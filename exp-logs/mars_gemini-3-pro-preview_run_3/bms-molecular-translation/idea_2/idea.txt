Based on the dataset analysis and the requirement for a highly efficient, novel baseline distinct from previous ideas, I propose the following solution.

### Proposed Solution: CNN-Transformer "Spatial" Baseline

This approach synthesizes the visual feature extraction power of **Model 1** (CNN) with the sequence modeling capabilities of **Model 2** (Transformer), but simplifies both to create a lightweight, high-throughput baseline. Unlike **Idea 1**, which compresses the image into a single global vector (losing spatial detail), this model preserves the spatial grid of features, allowing the decoder to attend to specific atoms via Cross-Attention. Unlike **Model 1**, it replaces the sequential RNN with a parallelizable Transformer Decoder, speeding up training. Unlike **Model 2**, it replaces the heavy Swin Transformer encoder with a standard lightweight CNN.

#### Model
*   **Encoder (CNN Backbone):** Utilize **ResNet-18**, a standard lightweight Convolutional Neural Network.
    *   Remove the final Global Average Pooling and Fully Connected layers.
    *   The output is a spatial feature map of shape $(C, H', W')$.
    *   **1x1 Convolution:** Apply a $1 \times 1$ convolution to project the channel dimension $C$ to the Transformer's hidden dimension $d_{model}$.
    *   **Spatial Flattening:** Flatten the spatial dimensions to produce a sequence of feature vectors of length $H' \times W'$.
    *   **Positional Encoding:** Add learnable 2D positional embeddings to these vectors so the Transformer understands the relative 2D positions of atoms and bonds.
*   **Decoder (Transformer):** Use a shallow **Vanilla Transformer Decoder** (e.g., 3 layers, 4 attention heads).
    *   The decoder receives the flattened image features as "memory" (Keys/Values) and the InChI sequence as inputs (Queries).
    *   It utilizes **Masked Self-Attention** to model the syntax of the InChI string and **Cross-Attention** to align specific characters (like atom symbols) with their corresponding visual regions in the feature map.

#### Data
*   **Preprocessing:**
    *   **Resizing:** Resize all images to a fixed resolution of **384x384**. This resolution is chosen as a baseline trade-off: large enough to resolve atomic characters in the majority of the dataset (based on the average image size analysis), but small enough for large batch sizes and fast training.
    *   **Normalization:** Normalize pixel values to the $[0, 1]$ range.
    *   **Tokenization:** Create a character-level vocabulary from the training labels. Map the InChI strings to integer sequences, wrapping them with `<SOS>` (Start) and `<EOS>` (End) tokens.
*   **Augmentation:** None. To establish a reliable and deterministic baseline, no test-time or heavy training-time augmentations will be used.

#### Training
*   **Loss Function:** Standard **Cross-Entropy Loss**.
*   **Optimizer:** **AdamW** optimizer, which is standard for Transformers to ensure convergence and generalization.
*   **Strategy:**
    *   **Parallelism:** Unlike RNN-based approaches (Model 1, Idea 1), the Transformer Decoder allows for parallel computation of the entire sequence during training using causal masking. This significantly increases training throughput.
    *   **Scheduler:** Use a **OneCycleLR** learning rate scheduler. This ramps up the learning rate for the first portion of training to quickly traverse the loss landscape and then decays it for fine-tuning, ensuring efficient convergence within the time limit.

#### Evaluation
*   **Inference Process:**
    *   Pass the test image through the ResNet encoder to generate the spatial memory bank.
    *   **Greedy Decoding:** Initialize the decoder with the `<SOS>` token. At each step, select the character with the highest softmax probability. Append this character to the input sequence for the next step.
    *   Stop generation when `<EOS>` is predicted or the maximum length (derived from metadata analysis, e.g., 400) is reached.
    *   This avoids the computational overhead of Beam Search while providing a strong baseline performance.
