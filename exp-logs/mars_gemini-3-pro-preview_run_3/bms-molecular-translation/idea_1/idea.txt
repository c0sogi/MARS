Based on the provided constraints and the need for a highly efficient baseline that remains distinct from the previous ideas, I propose the following approach.

### Proposed Solution: Non-Attentional "Show and Tell" Architecture

This solution adapts the classic "Show and Tell" image captioning framework (Vinyals et al., 2015) to the molecular translation task. Unlike **Model 1** (which uses Bahdanau Attention to focus on specific image regions) or **Model 2** (which uses a Transformer to model complex dependencies), this approach relies on a **global bottleneck vector**. It forces the encoder to compress the entire molecular structure into a single fixed-length representation, which initializes the decoder. This design drastically reduces computational complexity during the decoding steps, as there is no need to compute attention weights over a spatial grid at every timestep.

#### Model
*   **Encoder (Lightweight CNN):** Utilize **MobileNetV3-Large** (pre-trained on ImageNet) as the backbone. This model is specifically designed for efficiency and low latency.
    *   The CNN processes the input image to extract high-level features.
    *   Apply **Global Average Pooling** to the final feature map. This collapses the spatial dimensions ($H \times W$) into a single 1D feature vector, effectively summarizing the entire image into a global context vector.
    *   A linear projection layer maps this vector to the hidden state dimension of the decoder.
*   **Decoder (RNN):** Use a standard **LSTM (Long Short-Term Memory)** network.
    *   **Initialization:** The projected global vector from the encoder is used to initialize the hidden state ($h_0$) and cell state ($c_0$) of the LSTM.
    *   **Generation:** The LSTM generates the InChI string character-by-character. At each step, it receives the embedding of the previously predicted character (or the ground truth during training).
    *   **Output:** A linear classifier maps the LSTM output to the vocabulary size (the unique characters found in the InChI dataset) to predict the next character.

#### Data
*   **Preprocessing:**
    *   **Resizing:** Resize all images to a fixed square dimension (e.g., $384 \times 384$). This resolution balances the need to resolve small atomic symbols with the requirement for fast batch processing.
    *   **Normalization:** Normalize pixel values using standard ImageNet mean and standard deviation to align with the pre-trained backbone.
    *   **Tokenization:** Construct a character-level vocabulary from the training labels (including special tokens for `<SOS>`, `<EOS>`, and `<PAD>`). Convert ground truth InChI strings into sequences of integer indices.
*   **Augmentation:** Apply minimal augmentations such as slight random rotations ($\pm 5$ degrees) and random brightness contrast to improve generalization without incurring significant preprocessing overhead.

#### Training
*   **Loss Function:** Use **Cross-Entropy Loss**, calculated between the predicted character probability distribution and the ground truth character indices at each time step.
*   **Optimizer:** Use **AdamW** for efficient convergence.
*   **Strategy:** Implement **Teacher Forcing**, where the ground truth character from the previous time step is fed as input to the current time step during training. This stabilizes and accelerates the training of the recurrent decoder.

#### Evaluation
*   **Inference Process:**
    *   Pass the test image through the MobileNet encoder to obtain the initial LSTM states.
    *   Feed the `<SOS>` (Start of Sequence) token into the LSTM.
    *   Perform **Greedy Decoding**: At each step, select the character with the highest probability from the softmax output. Feed this predicted character as the input for the next time step.
    *   Terminate generation when the `<EOS>` (End of Sequence) token is predicted or a maximum sequence length (e.g., 400) is reached.
    *   Reconstruct the InChI string from the sequence of predicted characters and format it for submission.
