The failure is caused by a security feature in PyTorch 2.6+ where `torch.load` defaults to `weights_only=True`, preventing the loading of checkpoints that contain NumPy scalars (like the `best_map` metric saved in the checkpoint dictionary). To fix this, we need to explicitly set `weights_only=False` when loading the checkpoint, as we trust the locally generated file. Additionally, I will correct the invalid escape sequences in `library/losses.py` that were flagged in the traceback.
