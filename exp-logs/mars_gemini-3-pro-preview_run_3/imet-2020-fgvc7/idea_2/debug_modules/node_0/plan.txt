### Implementation Strategy

1.  **Configuration Overrides**: To ensure the demonstration runs quickly and respects the "Optimize for Speed" requirement, I will override the `Config` class attributes at runtime. I will set `DEBUG=True` (to use a tiny subset of data), reduce `EPOCHS` to 1, `BATCH_SIZE` to 4, and `IMAGE_SIZE` to 128. I will also redirect outputs to a specific `./working/demo` directory.

2.  **Dataset Verification**: I will call `get_dataloaders` and iterate through a single batch from the training loader. I will assert that the output shapes for images and multi-hot targets are correct based on the batch size and number of classes.

3.  **Model Verification**: I will instantiate the `ArtworkModel` (disabling pretraining weights for the unit test to avoid network dependency issues, though the full pipeline uses them) and perform a forward pass with the dummy batch from the previous step. I will assert that the output logits have the expected dimensions.

4.  **Full Pipeline Execution**: I will execute `run_training` to simulate the training process on the debug subset. This verifies the integration of the dataset, model, loss function, and optimizer. I will assert that the function returns a trained model and a valid threshold, and that the model checkpoint is saved.

5.  **Inference Verification**: I will execute `run_inference` using the trained model. I will verify that a submission file is generated at the specified path and that it follows the required CSV format (`id`, `attribute_ids`).

6.  **Cleanup**: I will verify the generated artifacts exist but leave them in the `./working` directory as allowed.
