The previous implementation failed because the `DEBUG` mode logic naively sliced the first $N$ rows of the metadata. Since the training metadata was shuffled, these rows were scattered across hundreds of different batch files, forcing the data loader to open and read ~676 large Parquet files (approx. 115 GB of data) to retrieve just 1000 events. Additionally, the inference pipeline lacked a `DEBUG` check entirely, attempting to process the full 13.2 million event test set within the remaining demo time.

To fix this, I will modify `library/train.py` and `library/inference.py` to ensure that in `DEBUG` mode, the data is filtered to a single batch ID first. This restricts the I/O to a single file per dataset split, drastically reducing runtime.
