Based on the progression of previous ideas and the specific insights from the provided lessons, I propose the **Canonical-Frame Dynamic Graph Network (CF-DGN)**.

This strategy addresses the core difficulty of the task: the model must learn complex 3D rotational symmetries while simultaneously extracting a directional vector. By explicitly standardizing the geometric frame of reference using the insights from **Lesson 00006**, we simplify the learning manifold for the GNN (proven effective in **Lesson 00010**), allowing it to focus on fine-grained trajectory resolution rather than gross orientation.

# Proposed Solution: Canonical-Frame Dynamic Graph Network (CF-DGN)

### Model
The architecture combines a physics-informed geometric transformation layer with a Graph Neural Network backbone.

1.  **Canonical Alignment Module (Structural Innovation):**
    Instead of feeding raw coordinates to the network, we dynamically transform the input point cloud into a standardized "Canonical Frame" for each event.
    *   **Axis Extraction:** Compute the charge-weighted covariance matrix of the pulse positions and perform Singular Value Decomposition (SVD) to find the principal axis $\vec{v}_1$ (Cite solution_lesson_node_00006).
    *   **Directional Orientation:** Calculate the covariance between the projection of pulse positions onto $\vec{v}_1$ and pulse times $t$. If the covariance is negative, flip $\vec{v}_1$ to $-\vec{v}_1$. This ensures the "time-flow" of the event is always aligned with the positive Z-axis in the new frame (Cite solution_lesson_node_00006).
    *   **Rotation:** Construct a rotation matrix $R$ that aligns $\vec{v}_1$ with the global Z-axis $(0,0,1)$. Apply $R$ to all pulse coordinates $(x, y, z)$.
    *   **Benefit:** In this frame, every neutrino track points roughly "upwards." The model no longer needs to learn global rotational invariance; it only needs to predict the *deviation* from the vertical axis and the azimuthal angle in the XY plane.

2.  **Backbone: Spatiotemporal DynEdge:**
    The transformed point cloud is processed by a **Dynamic Edge Convolution (DynEdge)** network (Cite solution_lesson_node_00010).
    *   **Graph Construction:** Construct k-Nearest Neighbor graphs in the 4D spatiotemporal space $(x', y', z', \alpha \cdot t)$ to link causally connected pulses.
    *   **Edge Features:** Explicitly encode relative differences $(\Delta x', \Delta y', \Delta z', \Delta t)$ to capture local trajectory vectors.

3.  **Inverse Projection Head:**
    *   The model predicts the normalized direction vector $\vec{u}_{local}$ in the canonical frame.
    *   The final output is generated by applying the inverse rotation: $\vec{u}_{global} = R^T \cdot \vec{u}_{local}$.

### Data
1.  **Geometry Merging:** Merge `sensor_geometry.csv` with pulse data to obtain $(x, y, z, t, q)$.
2.  **Hybrid Sampling:** Select a fixed number of pulses (e.g., $N=128$) per event. Prioritize high-charge pulses (to capture the core energy) and the earliest pulses (to capture the track start point), ensuring the topological structure is preserved (Cite solution_lesson_node_00010).
3.  **Canonical Transformation:** For every event in the training and test set, compute the SVD-based rotation matrix and the time-covariance sign flip (Cite solution_lesson_node_00006). Store the rotation matrix for the inverse step and feed the rotated coordinates to the model.
4.  **Target Transformation:** Apply the same rotation matrix to the ground truth target vector during training, so the model learns to predict the target in the canonical frame.

### Training
*   **Loss Function:** **Cosine Similarity Loss** applied in the canonical frame. Since the transformation is orthogonal (rotation), optimizing angular error in the canonical frame is equivalent to optimizing it in the global frame.
*   **Optimizer:** **AdamW** with a Cosine Annealing scheduler to refine weights.
*   **Strategy:** Train on GPU. The simplified task (predicting deviations from Z-axis rather than arbitrary vectors) should lead to faster convergence and lower angular error compared to the raw GNN approach.

### Evaluation
1.  **Inference:**
    *   Load test batches and apply the **Canonical Alignment** (SVD + Time-Covariance Flip) to the pulse data.
    *   Pass the rotated pulses to the trained CF-DGN to predict $\vec{u}_{local}$.
2.  **Reconstruction:**
    *   Apply the inverse rotation to obtain the global direction: $\vec{u}_{global} = R^T \cdot \vec{u}_{local}$.
3.  **Formatting:**
    *   Convert $\vec{u}_{global}$ to `azimuth` and `zenith` and save to CSV.
