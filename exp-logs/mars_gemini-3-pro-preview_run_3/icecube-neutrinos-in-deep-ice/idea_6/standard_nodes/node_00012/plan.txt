The implementation strategy follows a streamlined process to ensure the task is completed within the time and compute constraints while satisfying all requirements.

1.  **Configuration & Fast Baseline**: We override the default configuration to enable `DEBUG` mode, which limits the training dataset to 200,000 samples. We also reduce the number of epochs to 3. This ensures the training phase completes in minutes rather than hours, serving as a fast baseline.
2.  **Hybrid Data Loading**: We manually instantiate `DataLoader` objects.
    *   For **Training**, we use the subset (debug mode) to speed up learning.
    *   For **Validation**, we switch `DEBUG` to `False` after training to load the **entire** hold-out validation set. This ensures the reported metric is accurate and complies with the requirement to use the full validation set.
3.  **Training Loop**: We execute a standard training loop using the provided `train_one_epoch` and `validate` functions from the library. We save the best model based on a subset validation score during training.
4.  **Full Validation & Failure Analysis**: After training, we load the best model and perform a single pass over the full validation set (23M events). During this pass, we accumulate the Mean Angular Error for the official metric and collect feature statistics (number of pulses, mean charge) to calculate correlations with the error, fulfilling the failure analysis requirement.
5.  **Conditional Submission**: We check if the final validation metric is below the specified threshold (1.5013689469017657). If it is, we invoke the `inference.run_inference` function (which loads the full test set) to generate the `submission.csv`.
