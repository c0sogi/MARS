The `TimeoutError` is caused by inefficient data loading in debug mode. The `IceCubeDataset` naively subsamples the first `N` events from the metadata using `iloc[:DEBUG_SIZE]`. Since the training metadata is shuffled, these events are scattered across many different batch files. This causes the data loader to constantly reload large Parquet files for just a few events each, leading to severe I/O thrashing. To fix this, I will modify `library/data.py` to filter the metadata by `batch_id` before slicing. By restricting the debug dataset to a single batch, we ensure data locality (Cite debug_lesson_1), allowing the cache to function correctly and drastically reducing runtime.
