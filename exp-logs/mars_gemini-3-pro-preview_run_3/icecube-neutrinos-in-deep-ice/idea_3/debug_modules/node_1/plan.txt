The previous implementation of `load_dataset` in `library/trainer.py` caused a `TimeoutError` because it performed a global random sample on the metadata. This scattered the selected events across hundreds of different batch files, forcing the `FeatureExtractor` to perform excessive I/O operations (loading ~170MB files for single events) which exceeded the time limit.

To fix this, I will modify the sampling logic to preserve data locality (Cite debug_lesson_1). The new implementation will first identify and select a random subset of `batch_id`s that contain enough events to satisfy the `sample_size`, filter the metadata to those specific batches, and only then perform row-level sampling. This ensures that the data loader only needs to open a minimal number of Parquet files (e.g., 1 file for 100 events), drastically reducing runtime.
