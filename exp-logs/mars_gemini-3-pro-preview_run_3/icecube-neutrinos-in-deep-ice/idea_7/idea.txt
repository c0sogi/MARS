Based on the progression of previous ideas and the critical insights from the provided lessons, I propose the **Dual-Frame Causal Graph Network (DF-CGN)**.

This strategy represents a structural evolution of **Idea 6 (Canonical-Frame DGN)**. While Idea 6 correctly identified that standardizing the reference frame simplifies the learning task (Cite solution_lesson_node_00006), relying *solely* on a hard rotation based on SVD is risky: if the initial SVD is noisy (common in "blob-like" cascade events), the entire coordinate system becomes corrupted.

The **DF-CGN** resolves this by providing the network with a **Hybrid Representation**: it sees both the raw physical coordinates (ground truth) and the physics-informed canonical coordinates (simplified view) simultaneously. Furthermore, it upgrades the graph construction from spatial to **spatiotemporal (causal)** to better capture the particle trajectory (Cite solution_lesson_node_00010).

# Proposed Solution: Dual-Frame Causal Graph Network (DF-CGN)

### Model
The architecture is a Graph Neural Network that fuses raw geometric truth with physics-informed priors at the input level, followed by a topology-aware backbone.

1.  **Dual-Frame Input Embedding:**
    Instead of replacing the coordinates with a rotated version (Idea 6), we **augment** the feature space. For each pulse, the input vector contains:
    *   **Raw Coordinates:** $(x, y, z, t)$. This preserves the absolute geometry, ensuring the model can recover if the SVD approximation fails.
    *   **Canonical Coordinates:** $(x', y', z')$. These are the coordinates rotated such that the event's principal axis (derived from SVD) aligns with the Z-axis, and the "time flow" is positive (Cite solution_lesson_node_00006). This provides the model with a "hint" about the gross direction.
    *   **Pulse Features:** Charge $q$ and auxiliary status.

2.  **Causal Graph Construction:**
    Standard k-NN connects points based only on spatial distance, which can link unrelated pulses in complex events. We replace this with **Spatiotemporal k-NN**. The distance metric $D_{ij}$ between pulses $i$ and $j$ includes a time component:
    $$D_{ij} = \sqrt{||\vec{r}_i - \vec{r}_j||^2 + \alpha \cdot (t_i - t_j)^2}$$
    This ensures that the graph topology respects the causal structure of the particle track (Cite solution_lesson_node_00010).

3.  **Eigen-Informed Edge Convolution:**
    The backbone consists of **Dynamic Edge Convolution (DynEdge)** layers. To explicitly inject the vectorial information required for direction prediction (Cite solution_lesson_node_00006), the edge features are augmented with the **projection onto the global axis**:
    *   Standard Edge Feature: $(\vec{r}_j - \vec{r}_i)$
    *   Global Context Feature: $(\vec{r}_j - \vec{r}_i) \cdot \vec{v}_{eigen}$
    This tells the local convolution how much the local segment aligns with the global event axis.

4.  **Head:**
    A global pooling layer (using Attention or Max pooling) followed by an MLP to regress the 3D unit vector $(n_x, n_y, n_z)$.

### Data
1.  **Geometry Merging:** Merge `sensor_geometry.csv` with the pulse data.
2.  **Canonical Frame Computation:**
    For every event:
    *   Compute the charge-weighted covariance matrix of pulse positions.
    *   Perform SVD to obtain the principal axis $\vec{v}_1$.
    *   Check the covariance between "position projected on $\vec{v}_1$" and "time". If negative, flip $\vec{v}_1$ to ensure it points in the direction of motion (Cite solution_lesson_node_00006).
    *   Construct the rotation matrix $R$ that aligns $\vec{v}_1$ with $(0,0,1)$ and apply it to generate $(x', y', z')$.
3.  **Hybrid Sampling:**
    Sample a fixed number of pulses (e.g., $N=196$). Use a mix of **highest charge** (energy core) and **earliest time** (track start) to ensure the causal chain is captured.
4.  **Normalization:** Scale raw coordinates to detector size; scale canonical coordinates similarly. Log-transform charge.

### Training
*   **Loss Function:** **Cosine Similarity Loss** ($L = 1 - \vec{y}_{true} \cdot \vec{y}_{pred}$). This is the most direct proxy for the competition metric (Mean Angular Error).
*   **Optimizer:** **AdamW** with a **OneCycleLR** scheduler. This schedule warms up the learning rate to encourage exploration of the loss landscape before annealing for convergence.
*   **Strategy:** Train on GPU. The dual-frame input allows the model to learn a robust mapping: it can rely on the Canonical coordinates for simple tracks (fast convergence) and fall back to Raw coordinates for complex cascades (robustness).

### Evaluation
1.  **Inference:**
    *   Load test batches.
    *   Compute SVD and generate Canonical Coordinates $(x', y', z')$ for each event.
    *   Construct the Dual-Frame input and Causal Graph.
2.  **Prediction:**
    *   Forward pass to obtain $\vec{v}_{pred}$.
3.  **Post-Processing:**
    *   Normalize $\vec{v}_{pred}$ to unit length.
    *   Convert to `azimuth` and `zenith` and save to CSV.
