The `ArrowMemoryError` is caused by inefficient data access patterns when `DEBUG_SAMPLE_SIZE` is enabled. The training metadata is shuffled, so selecting the first 50,000 events results in a subset scattered across hundreds of large batch files. This forces the `DataLoader` workers to constantly load and discard large parquet files (cache thrashing) to retrieve only a few events per file, leading to memory exhaustion.

To fix this, I will:
1.  **Sort metadata by `batch_id`** in `library/data.py` before applying the debug slice. This ensures the sampled events are contiguous and contained within a minimal number of batch files, stabilizing memory usage (Cite debug_lesson_1).
2.  **Reduce `NUM_WORKERS`** in `library/config.py` from 4 to 2 to further lower peak memory pressure during data loading.
