This approach prioritizes computational efficiency and simplicity by utilizing classical machine learning on engineered features, offering a distinct contrast to the deep learning approach suggested in the previous idea.

### **Aggregate Feature Gradient Boosting (AF-GBM)**

**Model**
The architecture utilizes **Gradient Boosting Decision Trees (LightGBM)**. Instead of processing raw, variable-length pulse sequences with a neural network, this approach treats the problem as a tabular regression task. The model operates on a fixed-size vector of statistical descriptors (engineered features) summarizing each event.

To address the periodicity of the `azimuth` angle (where 0 and $2\pi$ are identical) and the spherical nature of the target, the solution will not predict angles directly. Instead, it will employ **three independent regressors** to predict the components of the normalized direction vector: **$n_x$**, **$n_y$**, and **$n_z$**. This geometric projection avoids boundary discontinuities and provides a stable regression target.

**Data**
The data preprocessing pipeline transforms the raw pulse data into a structured tabular dataset suitable for tree-based models:
1.  **Geometry Integration:** Merge the `sensor_geometry.csv` data with the pulse batches to associate physical $(x, y, z)$ coordinates with every pulse.
2.  **Feature Engineering:** For each `event_id`, compress the cloud of pulses into a single row of aggregate features:
    *   **Center of Mass:** The charge-weighted average of pulse coordinates $(\bar{x}, \bar{y}, \bar{z})$. This locates the "center" of the light emission.
    *   **Spatial Spread:** The standard deviation of pulse coordinates along each axis. This helps distinguish between elongated "track" events and spherical "cascade" events.
    *   **Time Statistics:** The duration ($t_{max} - t_{min}$) and the standard deviation of pulse times.
    *   **Signal Intensity:** The total charge sum and the count of pulses (N_pulses), which serve as proxies for the neutrino's energy.
3.  **Target Transformation:** Convert the training labels (`azimuth`, `zenith`) into unit vector components using spherical-to-Cartesian formulas to create the ground truth for the three regressors.

**Training**
*   **Loss Function:** Use **Mean Squared Error (MSE)**. Each of the three regressors (for $x, y, z$) will independently minimize the error between the predicted vector component and the true vector component.
*   **Optimizer:** Utilize the native LightGBM optimization (gradient-based one-side sampling). This is highly optimized for CPU execution and handles large datasets efficiently.
*   **Strategy:** Train the three models in parallel or sequence. Use the validation set to monitor MSE and apply **early stopping** to prevent overfitting. No complex augmentation or GPU acceleration is required, making this extremely lightweight.

**Evaluation**
1.  **Inference:** For each event in the test set, compute the same aggregate features derived during training.
2.  **Prediction:** Feed the features into the three trained regressors to obtain the predicted vector components $\hat{n}_x, \hat{n}_y, \hat{n}_z$.
3.  **Post-Processing:**
    *   **Normalization:** The resulting vector may not be of unit length. Normalize it: $\vec{v}_{final} = \frac{\vec{v}_{pred}}{||\vec{v}_{pred}||}$.
    *   **Conversion:** Transform the normalized vector $\vec{v}_{final}$ back into spherical coordinates (`azimuth` and `zenith`) using standard trigonometric functions ($\arctan2$ and $\arccos$) to generate the final submission CSV.
