The implementation strategy follows a structured pipeline to ensure robustness and adherence to the constraints.
1.  **Configuration**: We first override the default `Config` parameters to establish a "fast baseline" mode. This involves enabling `DEBUG` mode, setting a sample limit (2000 tiles), and reducing the training duration to 3 epochs. This ensures the script executes within the time limit while processing enough data to verify the pipeline.
2.  **Training**: We invoke the `train_model` function from the library, which handles dataset initialization, the training loop, deep supervision loss calculation, and saving the best model checkpoint (`best_model.pth`).
3.  **Validation & Analysis**: We manually instantiate the validation dataset and the trained model to perform a detailed evaluation. We iterate through the validation set to compute the Dice coefficient for every sample. Concurrently, we map each tile back to its parent image metadata (age, weight, BMI, etc.) to calculate the correlation between the model's error (1 - Dice) and these features. This satisfies the failure analysis requirement.
4.  **Reporting**: We print the `Final Validation Metric` with full precision as required.
5.  **Submission**: A conditional check compares the final metric against the threshold (0.9132). If the model performs sufficiently well, `predict_test_set` is called to generate the RLE-encoded `submission.csv`.
