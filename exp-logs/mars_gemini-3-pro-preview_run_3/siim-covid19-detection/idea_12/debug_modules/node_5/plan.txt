The issue is a configuration mismatch between the input image resolution and the Swin Transformer backbone's expected input size. The `swin_large_patch4_window12_384` backbone defaults to a 384x384 input resolution and requires the input dimensions to be divisible by the window size (in pixels), which is $12 \times 4 = 48$. The current `IMG_SIZE` of 1024 is not divisible by 48 ($1024 / 48 \approx 21.33$), which would cause a window partitioning error, and the backbone initialization is missing the explicit `img_size` argument, causing the immediate assertion failure.

To fix this, I will:
1.  Update `Config.IMG_SIZE` in `library/config.py` to **1056**, which is the nearest resolution divisible by 48 ($22 \times 48 = 1056$).
2.  Update `library/model.py` to explicitly pass `img_size=Config.IMG_SIZE` within `backbone_kwargs` when manually initializing the model configuration. This ensures the `timm` backbone initializes its patch embeddings and position interpolations for the correct resolution. Cite debug_lesson_31.
