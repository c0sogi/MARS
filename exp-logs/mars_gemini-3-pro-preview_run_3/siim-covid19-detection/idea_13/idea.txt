# Idea 13: Multi-Task DINO with RoI-Transformer Diagnosis Module

## Model
I propose a **Multi-Task DINO (DETR with Improved DeNoising Anchor Boxes)** architecture enhanced with a **RoI-Transformer Diagnosis Module**. This represents a structural evolution from Idea 12 (which relied on latent query embeddings) and Idea 10 (which used auxiliary supervision), focusing on explicitly modeling the detailed texture and spatial configuration of findings for the study-level classification.

-   **Backbone**: I will utilize a **Swin Transformer Large (Swin-L)** backbone. This hierarchical transformer provides the necessary capacity to capture both fine-grained details and global context.
-   **Detector Core**: The model employs the **DINO** decoder with **Contrastive DeNoising (CDN)**. DINO is selected for its state-of-the-art convergence speed and localization accuracy.
-   **RoI-Transformer Diagnosis Module (Structural Innovation)**:
    -   **Motivation**: While DINO's object queries capture the *presence* and *location* of opacities, they are compressed latent vectors that may lose the fine-grained spatial texture information (e.g., "ground-glass" vs. "consolidation") required to distinguish "Typical" from "Indeterminate" appearances.
    -   **Mechanism**:
        1.  **RoI Extraction**: Using the top-$K$ bounding boxes predicted by the DINO decoder, I will extract high-resolution feature maps from the backbone using **Multi-Scale RoIAlign**. This explicitly recovers the spatial structure of the detected opacities.
        2.  **Global Context Token**: A global feature vector is extracted via Global Average Pooling from the backbone and projected into a token. This ensures the model can detect "Negative" cases where no distinct opacities exist.
        3.  **Transformer Encoder**: The flattened RoI features and the Global Context Token are fed into a lightweight Transformer Encoder. This allows the model to perform relational reasoning (e.g., checking for bilateral distribution) while attending to the specific textural morphology of each finding.
        4.  **Classification Head**: The output of the Global Context Token is fed into an MLP to predict the four study-level categories.

## Data
-   **Preprocessing (Strategic Retention)**: I will strictly implement **Letterbox Resizing** for all training and test images. Instead of warping images to a fixed square, I will resize the longest dimension to the target size (e.g., 1024 pixels) and pad the shorter dimension with zeros. This preserves the original aspect ratio of the radiographs, preventing the morphological distortion of lung opacities that was identified as a critical failure mode **Cite solution_lesson_node_00010**.
-   **Augmentation**: I will employ **Large Scale Jittering (LSJ)** (resizing images between scales 0.1 to 2.0 followed by cropping) and **Random Horizontal Flipping**. I will explicitly exclude "Mosaic" augmentation to preserve the global anatomical structure required for the RoI-Transformer to learn valid spatial dependencies.

## Training
-   **Loss Function**: The model will be trained end-to-end using a multi-task objective:
    -   **Detection Loss**: A combination of **Focal Loss** (classification), **L1 Loss** (box coordinates), and **GIoU Loss** (box overlap) for the DINO decoder outputs.
    -   **Study Loss**: **Cross-Entropy Loss** applied to the output of the RoI-Transformer Diagnosis Module.
    -   **Contrastive DeNoising (CDN)**: I will use DINO's denoising training strategy to accelerate bipartite matching convergence.
-   **Optimizer**: **AdamW** with a layer-wise learning rate decay to effectively fine-tune the Swin-L backbone.

## Evaluation
-   **Inference**: A single forward pass generates the study-level probabilities (via the Diagnosis Module) and image-level bounding boxes (via the DINO decoder).
-   **Prediction Logic**:
    1.  **Study Level**: The label is determined by the argmax of the Diagnosis Module's output.
    2.  **Image Level**:
        -   If the predicted Study Label is "Negative for Pneumonia", the image prediction is forced to `none 1 0 0 1 1`.
        -   Otherwise, the bounding boxes predicted by the DINO decoder are formatted as the "opacity" prediction string. **Non-Maximum Suppression (NMS) is not required** due to DINO's one-to-one set prediction property.
