# Idea 5: Cascade R-CNN with ResNeXt-101 and Global Context Modeling

## Model
I propose a **Multi-Task Cascade R-CNN** architecture. This represents a structural evolution of the two-stage detector used in Idea 1, designed to address the high-precision requirements of the mAP metric and the complex feature hierarchy of COVID-19 findings.

-   **Backbone**: I will upgrade the feature extractor to a **ResNeXt-101 (32x4d)** with a Feature Pyramid Network (FPN). This backbone provides significantly stronger feature representational capacity than the ResNet-18 (Idea 1) or EfficientNet-B3 (Idea 4), allowing the model to capture subtle texture differences in "Atypical" vs. "Typical" appearances.
-   **Detection Head (Cascade Architecture)**: Unlike the standard Faster R-CNN, the **Cascade R-CNN** employs a sequence of three detection heads trained with increasing IoU thresholds (e.g., 0.5, 0.6, 0.7). This multi-stage refinement progressively rejects false positives and improves the localization quality of bounding boxes, directly optimizing the mAP metric at higher strictness levels.
-   **Study Classification Head**: To predict the four study-level categories, I will attach a classification branch to the deepest FPN layer. To improve upon simple Global Average Pooling, I will incorporate a **Global Context (GC) Block**. This lightweight module models long-range dependencies and global scene context (e.g., diffuse lung involvement) before feeding the features into the final dense classification layers.

## Data
-   **Preprocessing (Aspect Ratio Preservation)**: I will implement **Letterbox Resizing** for all input images. Instead of forcibly squashing images into a square, I will resize the longest dimension to the target size (e.g., 800 pixels) and pad the shorter dimension with zeros to create a square input. This ensures that the physical morphology of the lung opacities remains undistorted, directly addressing the critical failure mode identified where geometric distortion degraded performance **Cite solution_lesson_node_00010**.
-   **Augmentation**: I will utilize a robust augmentation pipeline including **Horizontal Flipping**, **Random Brightness/Contrast**, and **ShiftScaleRotate**. I will avoid "Mosaic" (used in Idea 2/4) for this two-stage detector to preserve the integrity of the global context required for the study-level classification.

## Training
-   **Loss Function**: The network will be trained end-to-end using a multi-task objective:
    -   **Cascade Detection Loss**: A weighted sum of the classification (Cross-Entropy) and regression (Smooth L1) losses from all three cascade stages.
    -   **Study Classification Loss**: A **Focal Loss** will be applied to the study-level head to handle the class imbalance between the frequent "Typical" cases and the rarer "Atypical" cases.
-   **Optimizer**: I will use **SGD with Momentum** (standard for R-CNN family) with a linear warmup and a step decay learning rate schedule.
-   **Sampling**: A **Class-Balanced Sampler** will be used to ensure that minibatches contain a representative mix of the four study categories, preventing the model from biasing towards the majority "Typical" class.

## Evaluation
-   **Inference**: For each test image, the model will generate bounding boxes and study-level class probabilities.
-   **Test Time Augmentation (TTA)**: I will perform inference on both the original and horizontally flipped versions of the test images. The resulting bounding boxes will be merged using **Weighted Boxes Fusion (WBF)**, which is generally superior to NMS for ensembling, to produce the final prediction string.
-   **Prediction Logic**:
    -   The study label is determined by the argmax of the study classification head.
    -   If the study label is "Negative for Pneumonia", the image prediction is forced to `none 1 0 0 1 1`.
    -   Otherwise, the merged bounding boxes from the Cascade detector are formatted as the "opacity" prediction string.
