Based on the lessons learned, I propose an optimized **"Pointer-Locator & Offset-Insertion"** strategy. This approach structurally evolves the previous two-stage pipeline by replacing the dense classification head with a pointer mechanism and fundamentally changing the inference reconstruction process to eliminate formatting errors.

# Model
I propose retaining the **Two-Stage (Locator + Filler)** architecture but upgrading the backbone and the Locator's prediction mechanism.

1.  **Backbone:** Upgrade from DistilBERT to **RoBERTa-base**. RoBERTa offers a more robust understanding of syntactic dependencies required to identify missing words, while remaining computationally feasible within the 24-hour limit on an A100 GPU.
2.  **The Locator (Pointer Network):** Instead of classifying every token as "Gap" or "No-Gap" (which suffers from class imbalance), the Locator will utilize a **Pointer Head**. This head projects token embeddings to a scalar score and applies a **Softmax over the sequence dimension** to predict the probability distribution of the missing word's location. This explicitly models the constraint that there is exactly one missing word per sentence (Cite solution_lesson_node_00001).
3.  **The Filler (MLM):** A standard RoBERTa-base model with a Masked Language Modeling head. It takes the sentence with a mask inserted at the predicted location and outputs the missing token.

# Data
1.  **Dynamic One-Pass Generation:** Instead of repeating a smaller static dataset, we will implement a dynamic data loader that streams unique samples from the 24M training sentences. We will train for a single epoch on a massive subset (e.g., 5 million unique sentences) to maximize exposure to linguistic diversity (Cite solution_lesson_node_00005).
2.  **Offset Mapping:** During preprocessing, we will utilize the tokenizer's `return_offsets_mapping=True` feature. This allows us to track the exact character start and end positions of every token in the original raw text, which is critical for the evaluation phase.

# Training
1.  **Optimization:** Train the Locator and Filler components. Given the shared backbone architecture, we can either train them sequentially or distinct copies.
2.  **Locator Loss:** Use **Negative Log-Likelihood (NLL) Loss** on the specific index of the token preceding the gap. This aligns with the Pointer Head design, forcing the model to rank the correct position higher than all others (Cite solution_lesson_node_00001).
3.  **Filler Loss:** Standard Cross-Entropy Loss for Masked Language Modeling.

# Evaluation
The most significant structural change occurs here to address the Levenshtein distance degradation caused by detokenization.

1.  **Prediction:**
    *   Pass the raw test sentence through the **Locator**. The Pointer Head returns the token index $k$ with the highest probability.
    *   Insert a `<mask>` token after token $k$ and pass the sequence to the **Filler** to predict the word string $w$.
2.  **Reconstruction (Offset-Based Insertion):**
    *   Do **not** decode the model's input tokens to reconstruct the sentence.
    *   Instead, use the **offset mapping** generated during tokenization to find the character index $C_{end}$ corresponding to the end of token $k$ in the *original* raw sentence string.
    *   Perform a direct string operation: `New_Sentence = Original_Sentence[:C_{end}] + " " + w + Original_Sentence[C_{end}:]`.
    *   This ensures that all original spacing, punctuation, and formatting remain 100% distinct, minimizing the Levenshtein penalty to only the inserted word (Cite solution_lesson_node_00006).
