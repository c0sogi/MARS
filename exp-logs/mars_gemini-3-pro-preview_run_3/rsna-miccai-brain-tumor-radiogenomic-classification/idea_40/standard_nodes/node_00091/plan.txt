The implementation strategy involves orchestrating the training and evaluation pipeline using the provided library modules while maintaining explicit control over the execution flow to satisfy the conditional submission requirement.

1.  **Setup and Initialization**: We will define necessary constants and set the random seed for reproducibility. The device (CPU/GPU) will be detected automatically.
2.  **Data Loading**: We utilize `library.data_loader.get_dataloaders` to load the training and validation datasets, leveraging the caching mechanism to speed up data preparation.
3.  **Training Loop**: We implement a training loop for a fixed number of epochs (10) using `library.train.train_one_epoch` and `library.train.validate`. We employ a "save best model" strategy based on validation AUC to ensure we retain the highest performing checkpoint.
4.  **Final Evaluation**: After training, we reload the best model state and perform a full inference pass on the validation set. This allows us to compute the `Final Validation Metric` with full precision and gather predictions for failure analysis.
5.  **Failure Analysis**: We calculate the absolute error for each validation sample. We then load the validation metadata to extract meta-features (specifically, the number of slices per modality). We compute and print the correlation between these features and the model's error to identify potential sources of bias or failure.
6.  **Conditional Submission**: We check if the `Final Validation Metric` exceeds the specified threshold (0.697818...). If satisfied, we invoke `library.predict.generate_submission` to generate the `submission.csv` file for the test set.
