The issue is that the `process_dataset` function relies on an exact string match (`split_name == "test"`) to identify the test set. In debug mode, the split name is modified to `"test_debug"`, causing this check to fail. Consequently, the code erroneously treats the test data as training data and attempts to access the `MGMT_value` label, which does not exist in the test set, triggering a `KeyError`.

To fix this, I will update the condition to check if `split_name` starts with `"test"`. I will also update the cache file paths to dynamically use `split_name` instead of the hardcoded `"test"` string. This ensures that debug cache files (e.g., `X_test_debug_even.npy`) do not overwrite the full dataset cache, preventing potential corruption of cached data (Cite debug_lesson_6).
