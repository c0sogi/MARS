The issue is that `roc_auc_score` returns `nan` (Not a Number) instead of raising a `ValueError` when the validation set contains only one class (e.g., all positives), which is common in small subsets like the demo validation set. This `nan` value propagates to the training loop, causing the comparison `if val_auc > best_auc` to always evaluate to `False` (since `nan > 0` is false). Consequently, the model checkpoint is never saved, leading to an `AssertionError` at the end of the script.

To fix this, I will modify `library/engine.py` to explicitly check if the calculated AUC is `nan` using `np.isnan()`. If it is `nan`, I will assign a fallback value of 0.5. This ensures that the metric is always a valid number, allowing the model saving logic to function correctly even when the metric is undefined. This applies the guidance from **debug_lesson_1** (Cite debug_lesson_1) regarding robustly handling undefined metrics in small datasets. I will apply this fix in both `train_one_epoch` and `validate` functions to ensure consistency.
