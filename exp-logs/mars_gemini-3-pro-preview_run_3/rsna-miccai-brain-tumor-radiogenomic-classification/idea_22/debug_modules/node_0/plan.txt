Implementation Strategy:
1.  **Setup and Mocking**: Since processing the full DICOM dataset would take too long for a quick demonstration (potentially hours given the volume of data), I will generate synthetic pre-processed data (numpy arrays) and save them to the cache directory defined in `library.config`. This allows the `data_loader` to skip the raw DICOM processing and load the cached data immediately, satisfying the "Optimize for Speed" requirement while still verifying the logic of the DataLoaders, Model, Trainer, and Inference modules.
2.  **Data Generation**: I will create random tensors matching the shape expected by the model `(N, 128, 224, 224)` for training, validation, and testing sets. I will ensure the training set size is at least equal to the batch size (32) to accommodate the `drop_last=True` setting in the training loader.
3.  **Pipeline Execution**:
    *   **Data Loading**: Initialize the dataloaders using `library.data_loader.get_dataloaders`. Verify the batch shapes.
    *   **Model Initialization**: Instantiate the `MSSHDNetwork` from `library.model` and perform a forward pass with a sample batch to verify output dimensions.
    *   **Training**: Initialize the `Trainer` from `library.trainer` and execute the training loop. Since we are using random data, the model won't learn meaningful features, but this validates that the training loop, backpropagation, and checkpointing logic function correctly without crashing.
    *   **Inference**: Execute `library.inference.predict_and_submit` to generate predictions on the mock test set and verify the submission file format.
4.  **Validation**: Throughout the script, I will use `assert` statements to confirm shapes, file existence, and data integrity.
