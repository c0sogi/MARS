The `RuntimeError` is caused by the data loader loading stale cached datasets (`.npy` files) that do not match the current model configuration. The cached data contains 5D tensors (likely `[Batch, Modality, Slice, H, W]`) with a spatial resolution of 224x224, whereas the current `VolumetricEfficientNet` expects 4D tensors `[Batch, Channels, H, W]` with a resolution of 256x256. Additionally, there is a discrepancy in `Config` where `INPUT_CHANNELS` (64) does not match `NUM_SLICES_TOTAL * 4` (32 * 4 = 128), which would cause a channel mismatch error even after regeneration.

To fix this, I will:
1.  **Update `library/config.py`**: Dynamically calculate `INPUT_CHANNELS` based on `NUM_SLICES_TOTAL` to ensure consistency between the data generation pipeline and the model architecture (Cite debug_lesson_6).
2.  **Update `library/data.py`**: Implement validation logic in `prepare_datasets` to check the shape of loaded cached data against the active `Config`. If the dimensions (channels or image size) mismatch, the cache will be ignored, and the data will be regenerated (Cite debug_lesson_1).
