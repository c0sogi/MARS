The issue is that the `best_acc` variable is initialized to `0.0`, which is the theoretical minimum for accuracy. In the provided execution, the model achieved exactly `0.0` accuracy on the validation set. Because the checkpointing logic uses a strict inequality (`if val_acc > best_acc`), the condition `0.0 > 0.0` evaluated to `False`, causing the save step to be skipped. This resulted in the `AssertionError` when the script later tried to load the non-existent model file.

To fix this, I will initialize `best_acc` to `-1.0` in both `library/trainer.py` (where the error occurred) and `library/model.py` (which shares the same logic). This ensures that the first epoch's result will always trigger a save, guaranteeing the model file exists regardless of performance. This applies the guidance from Cite debug_lesson_1.
