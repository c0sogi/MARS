# Baseline Proposal: Full-Scale Dual-Stream Projected Multi-Task Network

### Model
I propose a **Dual-Stream Projected Multi-Task Network** designed to robustly fuse heterogeneous visual features while maintaining the training stability of flat architectures.

*   **Dual Frozen Backbones:** The model will utilize two distinct pre-trained backbones in parallel to extract complementary visual features.
    1.  **ResNet-50:** Selected for its deep architecture and robust texture/shape feature extraction (2048 dimensions).
    2.  **EfficientNet-B0:** Selected for its efficient, multi-scale representation (1280 dimensions).
    *   *Strategic Retention:* Both backbones will be **frozen** to ensure the pipeline remains I/O bound rather than compute-bound (Cite solution_lesson_node_00003).
*   **Dual-Stream Projection & Fusion:** Instead of simple concatenation (which risks feature dominance by the larger vector), I will implement **Independent Feature Projection**:
    *   **Stream 1 (ResNet):** Projects the 2048-dim input to a **1024-dim** latent space via a Linear-BatchNorm-ReLU block.
    *   **Stream 2 (EfficientNet):** Projects the 1280-dim input to a **1024-dim** latent space via a Linear-BatchNorm-ReLU block.
    *   **Fusion:** The two projected vectors are **concatenated** to form a balanced 2048-dimensional product embedding.
    *   *Structural Innovation:* This "Early Projection" aligns the latent spaces of the two different architectures before fusion and controls the parameter count of the downstream classifier, directly addressing the dimensionality-induced overfitting risks identified in **Cite solution_lesson_node_00005**.
*   **Flat Multi-Task Classifier:** The fused embedding feeds into a shared MLP trunk that branches into three **parallel, independent heads**:
    *   **Head 1 (Level 1):** Predicts the 49 coarse categories.
    *   **Head 2 (Level 2):** Predicts the 483 sub-categories.
    *   **Head 3 (Level 3 - Target):** Predicts the 5270 fine-grained targets.
    *   *Strategic Correction:* I explicitly adopt the **Flat Multi-Task** architecture. As demonstrated in **Cite solution_lesson_node_00023**, this structure outperforms sequential cascading by ensuring direct gradient flow from the fine-grained labels to the shared trunk, avoiding the error propagation and instability observed in cascade networks.

### Data
*   **Full-Dataset Decoupled Caching:** I will apply the decoupled feature extraction strategy to the **entire training dataset (~7 million products)** and the test set.
    *   *Strategic Correction:* This directly addresses the failure in **Cite solution_lesson_node_00013**, where complex models failed due to data starvation. By using the full dataset, we provide sufficient signal to train the Dual-Stream architecture, preventing the overfitting observed in **Cite solution_lesson_node_00005**.
    *   *Processing:* Images will be resized to 224x224. For products with multiple images, I will apply **Mean Pooling** independently for each backbone to generate the product-level feature vectors.
    *   *Feasibility:* The storage requirement for the cached features fits comfortably within the 220 GB RAM limit.
*   **Label Engineering:** Map each `category_id` to its Level 1 and Level 2 parents to generate the hierarchical targets.

### Training
*   **Loss Function:** Use a **Sum of Cross-Entropy Losses** ($L_{total} = L_{L3} + L_{L2} + L_{L1}$).
    *   *Correction:* I will explicitly **exclude** inverse-frequency class weights. As demonstrated in **Cite solution_lesson_node_00004**, class weighting optimizes for macro-recall and degrades the target metric (global accuracy). The auxiliary tasks will instead provide structural regularization.
*   **Feature-Space MixUp:** Since the backbones are frozen, I will apply **MixUp** regularization ($x' = \lambda x_i + (1-\lambda)x_j$) directly on the cached feature vectors during training. This enforces linear decision boundaries and prevents the MLP from memorizing the tabular data.
*   **Optimizer:** Train using **AdamW** with Weight Decay and **Label Smoothing** (0.1).

### Evaluation
*   **Inference Pipeline:**
    1.  Load the pre-computed test set features from RAM.
    2.  Pass the features through an **Ensemble of 5** trained Dual-Stream models.
    3.  Average the probability distributions (Softmax) from the **Head 3 (Level 3)** outputs across the ensemble.
    4.  Select the category with the highest average probability as the final prediction.
