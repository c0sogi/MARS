# Baseline Proposal: Full-Scale Dual-Backbone with Conditional Cascade & Feature MixUp

### Model
I propose a **Dual-Backbone Conditional Cascade Network (DB-CCN)** designed to maximize feature diversity while explicitly modeling the hierarchical dependencies of the product categories.

*   **Dual Frozen Backbones:** The model will utilize two distinct pre-trained backbones in parallel to extract complementary visual features.
    1.  **ResNet-50:** Captures robust texture and shape representations (2048 dimensions).
    2.  **EfficientNet-B0:** Captures efficient, multi-scale features (1280 dimensions).
    *   *Rationale:* Combining architectures with different inductive biases provides a richer representation than scaling a single backbone. Both will be **frozen** to ensure the pipeline remains I/O bound rather than compute-bound (Cite solution_lesson_node_00003).
*   **Fused Aggregation:** For every product, features will be extracted for all associated images using both backbones. I will apply **Mean Pooling** independently to the ResNet and EfficientNet features, then **concatenate** the results to form a single **3328-dimensional** product embedding.
    *   *Feasibility:* Storing these embeddings for the full 7 million product dataset requires ~93 GB of RAM, fitting comfortably within the 220 GB limit.
*   **Conditional Cascade Classifier:** Unlike previous parallel multi-task proposals, I will implement a **Sequential Cascade MLP** that explicitly models the taxonomy ($P(Level3 | Level2, Features)$):
    *   **Stage 1 (Level 1):** An MLP takes the product embedding and predicts the 49 coarse categories.
    *   **Stage 2 (Level 2):** An MLP takes the **concatenation** of the product embedding and the *Stage 1 logits* to predict the 483 sub-categories.
    *   **Stage 3 (Level 3 - Target):** An MLP takes the **concatenation** of the product embedding and the *Stage 2 logits* to predict the 5270 fine-grained categories.
    *   *Innovation:* This structure forces the model to refine its predictions sequentially, using the coarse category prediction as a strong prior feature for the fine-grained decision, effectively guiding the optimization through the massive class space.

### Data
*   **Full-Dataset Decoupled Caching:** I will apply the decoupled feature extraction strategy to the **entire training dataset (~7 million products)** and the test set.
    *   *Strategic Correction:* This directly addresses the failure in **Cite solution_lesson_node_00013**, where a complex Dual-Backbone model failed because it was trained on a subset. By using the full dataset, we provide sufficient signal to train the high-capacity (3328-dim) features, preventing the overfitting observed in **Cite solution_lesson_node_00005** (where 4096-dim features failed on 100k samples).
*   **Label Engineering:** Map each `category_id` to its Level 1 and Level 2 parents to generate the hierarchical targets for the cascade stages.

### Training
*   **Loss Function:** Use a **Sum of Cross-Entropy Losses** from all three stages ($L_{total} = L_{L3} + L_{L2} + L_{L1}$).
    *   *Correction:* I will explicitly **exclude** inverse-frequency class weights. As demonstrated in **Cite solution_lesson_node_00004**, class weighting optimizes for macro-recall and degrades the target metric (global accuracy). The cascading structure naturally handles class imbalance by leveraging the more balanced high-level categories to guide the lower levels.
*   **Feature-Space MixUp:** Since the backbones are frozen, standard image augmentation is impossible. I will apply **MixUp** regularization ($x' = \lambda x_i + (1-\lambda)x_j$) directly on the cached feature vectors during MLP training. This enforces linear decision boundaries and prevents the MLP from memorizing the tabular data.
*   **Optimizer:** Train using **AdamW** with Weight Decay and **Label Smoothing** (0.1) to prevent overconfidence in the fine-grained predictions.

### Evaluation
*   **Inference Pipeline:**
    1.  Load the pre-computed test set features (Dual-Backbone Fused) from RAM.
    2.  Pass the features through an **Ensemble of 3** trained DB-CCN models.
    3.  Average the probability distributions (Softmax) from the **Stage 3 (Level 3)** outputs across the ensemble.
    4.  Select the category with the highest average probability as the final prediction.
