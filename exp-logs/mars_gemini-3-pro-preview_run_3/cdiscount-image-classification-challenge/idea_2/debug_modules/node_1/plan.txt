The issue is that `best_acc` is initialized to `0.0`, and the model checkpointing logic requires the validation accuracy to be strictly greater than `best_acc` to save the model. In the demonstration run, the validation accuracy was `0.0`, causing the condition `0.0 > 0.0` to fail, which meant the model was never saved to disk. This triggered a `FileNotFoundError` when the code attempted to load the best model at the end of training. To fix this, I will initialize `best_acc` to `-1.0` so that the first validation result (even if `0.0`) triggers a save, ensuring the model file exists while preserving the correct early stopping behavior for subsequent epochs.
