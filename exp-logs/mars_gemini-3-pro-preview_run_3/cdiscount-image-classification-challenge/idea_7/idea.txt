# Baseline Proposal: Hierarchical EfficientNet-B0 on Full-Scale Decoupled Data

### Model
I propose a **Hierarchical Multi-Task Network** built upon a compact **EfficientNet-B0** backbone.
*   **Backbone:** Use **EfficientNet-B0** (pre-trained on ImageNet) instead of the ResNet family.
    *   **Structural Innovation:** EfficientNet-B0 produces a **1280-dimensional** embedding, which is significantly more compact than ResNet-50's 2048 dimensions. This reduction is strategic: it lowers the parameter count of the downstream classifier, directly mitigating the risk of overfitting identified in **Cite solution_lesson_node_00005**, while still providing a modern, powerful feature set. The backbone will be **frozen**.
*   **Aggregation:** Apply **Mean Pooling** to the image features of each product. This retains the computational efficiency proven in **Cite solution_lesson_node_00003** and avoids the dimensionality explosion of concatenation strategies (e.g., Dual Pooling).
*   **Hierarchical Classifier:** Instead of a simple flat MLP, the classification head will be structured to reflect the dataset's taxonomy. A shared MLP trunk will branch into three output heads:
    1.  **Level 1 Head:** Predicts the parent category (e.g., "Sports").
    2.  **Level 2 Head:** Predicts the sub-category (e.g., "Cycles").
    3.  **Level 3 Head (Target):** Predicts the specific product category (e.g., "Bike Helmets").
    *   *Rationale:* This structure forces the shared layers to learn robust, semantically meaningful features that respect the category hierarchy, acting as a powerful regularizer against the noise in fine-grained classes.

### Data
*   **Full-Dataset Decoupled Caching:** I will apply the decoupled feature extraction strategy to the **entire training dataset (~7 million products)** and the test set.
    *   **Strategic Retention:** This leverages the extreme speed of the decoupled approach (**Cite solution_lesson_node_00003**), transforming the heavy visual task into a RAM-bound tabular one.
    *   **Correction:** By processing the full dataset, we ensure the volume of training data is sufficient to support the model's capacity. This directly addresses the failure mode in **Cite solution_lesson_node_00005**, where high-dimensional features combined with data subsets led to memorization.
    *   **Storage:** The resulting 1280-dimensional embeddings for 7 million products will require approximately **35 GB of RAM**, fitting comfortably within the available 220 GB.

### Training
*   **Loss Function:** Use a **Multi-Task Sum of Cross-Entropy Losses**: $L_{total} = L_{Level3} + L_{Level2} + L_{Level1}$.
    *   **Correction:** I will explicitly **exclude** inverse-frequency class weights. As demonstrated in **Cite solution_lesson_node_00004**, class weighting optimizes for macro-recall and harms the target metric (global accuracy). The hierarchical auxiliary tasks will instead provide the necessary gradient signal for under-represented classes by grouping them into larger parent categories.
*   **Optimizer:** Use **AdamW** with Weight Decay on the in-memory dataset.
*   **Throughput:** Utilize a large batch size (e.g., 4096) to maximize GPU utilization during the tabular training phase.

### Evaluation
*   **Inference Pipeline:**
    1.  Load the pre-computed test set features from RAM.
    2.  Pass the features through the trained Hierarchical Network.
    3.  Select the category with the highest probability from the **Level 3 Head** (the primary target) as the final prediction.
