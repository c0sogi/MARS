The issue is a data leakage problem in the cross-validation logic within `library/train.py`. The function `run_fold` currently loads the entire dataset (`train.json`) and performs K-Fold cross-validation on all of it. However, the final evaluation in `runfile.py` uses a fixed holdout validation set defined in `metadata/val.csv`. Because `run_fold` does not exclude this holdout set from the training process, the models in the ensemble have already trained on the validation data, leading to an artificially low validation loss and invalid metrics.

To fix this, I will modify `library/train.py` to:
1.  Import `pandas` and `TRAIN_META_CSV`.
2.  Update `run_fold` to load the training metadata (`metadata/train.csv`).
3.  Filter the full dataset to include only the samples listed in the training metadata before performing the K-Fold split. This ensures the holdout validation set remains strictly unseen during training.
