The issue identified is **Data Leakage** caused by training the cross-validation models on the entire dataset (`train.json`) without excluding the fixed hold-out validation set defined in `metadata/val.csv`. This results in the model being trained on the same data used for final evaluation, leading to an invalid, overly optimistic metric.

To fix this, I will modify the `get_fold_loaders` function in `library/data_loader.py`. Before performing the K-Fold split, I will filter the loaded dataset to include *only* the samples listed in `metadata/train.csv`. This ensures the hold-out set remains strictly unseen during the training of the ensemble models. Cite debug_lesson_7.
