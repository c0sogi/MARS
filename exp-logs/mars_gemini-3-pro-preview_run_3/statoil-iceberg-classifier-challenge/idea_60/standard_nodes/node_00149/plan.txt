The implementation strategy follows the requirements to orchestrate a 5-Fold Cross-Validation workflow, evaluate on a specific hold-out set defined by metadata, perform failure analysis, and conditionally generate a submission.

1.  **Setup**: We initialize the environment and set random seeds using the provided `library` modules.
2.  **Training**: We invoke `train_eval.train_model(debug=False)` to execute the full 5-Fold Cross-Validation training. This ensures the model is trained on the entire dataset using stratified splits and saves the best checkpoints for each fold.
3.  **OOF Prediction**: To strictly adhere to the requirement of evaluating on the hold-out set defined in `./metadata/val.csv` without data leakage, we manually generate Out-Of-Fold (OOF) predictions. We recreate the stratified splits, load the best model for each fold, and predict on that fold's validation set. Crucially, we apply leak-free imputation for incidence angles by calculating the median solely from the training split of the current fold.
4.  **Validation**: We load the `./metadata/val.csv` file and retrieve the OOF predictions corresponding to these specific IDs. We then compute the Log Loss metric on this subset and print it as `Final Validation Metric`.
5.  **Failure Analysis**: We calculate the absolute error for each sample in the validation set. We then compute the Pearson correlation between this error magnitude and key features: incidence angle (handling NaNs), and the mean/standard deviation of Band 1 and Band 2.
6.  **Submission**: We check if the calculated validation metric is below the threshold (0.17174082291273365). If satisfied, we call `train_eval.make_submission()`, which averages predictions from all 5 folds on the test set and saves the result.
