Based on the comprehensive analysis of the experiment history and the derived lessons, I propose the **Capacity-Constrained Tri-Statistic Isomorphic CNN (CCTI-CNN)**.

This solution represents a structural synthesis designed to capture the complete physical signature of icebergs—**Peak Intensity**, **Shadow Depth**, and **Surface Texture**—while strictly managing the model's parameter budget to prevent overfitting. It explicitly resolves the conflict between **Lesson 163** (which mandates preserving feature width when adding statistics) and **Lesson 124** (which warns against exploding the classifier's capacity). By combining **Tri-Statistic Pooling (Max/Min/MAD)** with a **Constrained Classification Head**, this architecture extracts richer features without increasing the learnable parameter count, integrated into the robust **Plain CNN** backbone.

# Model
The architecture is a **Custom 4-Stage Attentive Convolutional Network** optimized for multi-statistic feature extraction and robust generalization.

*   **Backbone:** The network employs a **Plain CNN** structure (no residual connections) with 4 sequential blocks. We explicitly retain this over ResNets to enforce aggressive sequential downsampling (75x75 $\to$ ~4x4), which filters high-frequency speckle noise via convolution before it reaches the pooling layers (Cite solution_lesson_node_00046).
    *   **Block Structure:** `Conv2d` (bias=True) $\to$ `BatchNorm2d` $\to$ `LeakyReLU` $\to$ **Hybrid SE Module** $\to$ `MaxPool2d`.
    *   **Bias Retention:** We explicitly retain bias terms in convolutional layers to preserve initialization dynamics (Cite solution_lesson_node_00076).
    *   **Activation:** We use **`LeakyReLU`** (negative slope 0.1) throughout. This preserves negative values (e.g., radar shadows normalized by BatchNorm) that carry semantic meaning, which standard ReLU destroys (Cite solution_lesson_node_00091).
    *   **Width Strategy:** The channel dimensions are configured as **64 $\to$ 128 $\to$ 128 $\to$ 128**. We expand early to preserve texture (Cite solution_lesson_node_00050) but cap width to prevent overfitting (Cite solution_lesson_node_00026).
    *   **Attention:** **Hybrid SE** uses Global Average Pooling for the squeeze operation (low-pass filter) to be robust to noise (Cite solution_lesson_node_00104), with a reduction ratio of $r=16$ (Cite solution_lesson_node_00146).

*   **Structural Innovation 1 (Tri-Statistic Isomorphic Readout):**
    *   We extract features from **Stage 3** and **Stage 4** (Selective Hierarchical) (Cite solution_lesson_node_00035).
    *   **Decoupled Projections:** We use **separate** 1x1 Convolutional layers for Stage 3 (`Proj3`) and Stage 4 (`Proj4`) to learn depth-specific transformations (Cite solution_lesson_node_00144).
    *   **Width Preservation:** We project the 128 channels to **64 channels**. We explicitly **do not compress** this further (e.g., to 42), ensuring we maintain the spatial feature diversity required for robust texture analysis (Cite solution_lesson_node_00163).
    *   **Tri-Statistic Pooling:** On these 64-channel maps, we apply three global pooling operations:
        1.  **Global Max Pooling:** Captures bright backscatter peaks (Icebergs) (Cite solution_lesson_node_00007).
        2.  **Global Min Pooling:** Captures deep signal voids (Shadows), implemented as `Max(-x)` (Cite solution_lesson_node_00134).
        3.  **Global MAD Pooling:** Calculates the **Mean Absolute Deviation** ($\text{Avg}(|x - \text{Avg}(x)|)$). This captures **Texture/Roughness** (Ice vs. Water) robustly, avoiding the outlier sensitivity of Standard Deviation (Cite solution_lesson_node_00145).
    *   **Result:** A 384-dimensional feature vector ($64 \text{ ch} \times 3 \text{ stats} \times 2 \text{ stages}$).

*   **Feature Fusion (Raw Scale):** The 384-dim vector is concatenated with the scalar **incidence angle**. We explicitly **do not normalize** the angle, preserving its natural scale alignment with the raw radar signal (Cite solution_lesson_node_00057).

*   **Structural Innovation 2 (Capacity-Constrained Head):**
    *   **Problem:** Increasing input features from 256 to 385 would increase the parameter count of a standard (256-width) hidden layer from ~66k to ~99k, risking overfitting (Cite solution_lesson_node_00124).
    *   **Solution:** We constrain the hidden layer width to **128**.
    *   **Architecture:** `Linear(385 -> 128)` $\to$ `LeakyReLU` $\to$ `Dropout(0.5)` $\to$ `Linear(128 -> 1)` $\to$ `Output`.
    *   **Parameter Budget:** This results in $\approx 49,000$ parameters in the first dense layer, which is actually *more efficient* than the baseline (~66,000), despite the richer input representation. This effectively trades "combinatorial capacity" for "input information quality."
    *   **Non-Linearity:** We retain the non-linear activation to model the interaction between the angle and image features (Cite solution_lesson_node_00155).

*   **Initialization:** We strictly use **PyTorch Default Initialization** (Kaiming Uniform/Fan-In) (Cite solution_lesson_node_00078).

# Data
*   **Input Composition:** The input is a 3-channel tensor (75x75x3) comprising the **HH band**, the **HV band**, and a **synthetic average band** ((HH+HV)/2) (Cite solution_lesson_node_00005).
*   **Resolution:** The native **75x75** resolution is maintained (Cite solution_lesson_node_00009).
*   **Augmentation:** We use `torchvision.transforms` for RandomHorizontalFlip and RandomVerticalFlip (Cite solution_lesson_node_00013).
*   **Leak-Free Preprocessing:** Imputation of missing incidence angles is performed using the median calculated **only on the training fold indices** and applied to the validation fold. This corrects the data leakage identified in **Lesson 147**.

# Training
*   **Strategy:** The model is trained using **5-Fold Cross-Validation Ensembling** (Cite solution_lesson_node_00016).
*   **Optimizer:** We use **AdamW** with a **constant learning rate** (e.g., 1e-3). This decouples weight decay from the adaptive gradient updates, ensuring consistent regularization on the raw scalar input without the instability of schedulers (Cite solution_lesson_node_00019).
*   **Loss Function:** **`BCEWithLogitsLoss`** combined with **L2 Regularization (Weight Decay)** to ensure numerical stability and prevent overfitting to noise (Cite solution_lesson_node_00036).
*   **Duration:** We set a generous training budget (e.g., 75 epochs) with moderate patience (e.g., 12 epochs) to allow the regularized model to converge (Cite solution_lesson_node_00094).

# Evaluation
*   **Inference:** We explicitly **disable Test-Time Augmentation (TTA)**. Predictions are generated via a single forward pass on the original image, as TTA has been shown to degrade performance on this directional SAR data (Cite solution_lesson_node_00041).
*   **Ensembling:** The final submission probability for each ID is the simple average of the direct predictions from the 5 models trained in the Cross-Validation loop (Cite solution_lesson_node_00027).
