To establish a robust and highly efficient baseline, I propose a **Statistical Feature Aggregation approach using Gradient Boosting**. This method prioritizes computational speed and interpretability, leveraging the strong correlation observed between signal dispersion (e.g., standard deviation) and the target variable during the data analysis phase.

# Model
The core model will be a **LightGBM Regressor**, a gradient boosting framework that uses tree-based learning algorithms. It is chosen for its efficiency with large datasets and its native ability to handle potential irregularities in feature distributions.
*   **Architecture**: The "architecture" is a decision-tree ensemble. The input is not the raw 60,000-length time series, but a flattened vector of summary statistics representing the signal characteristics of each segment.
*   **Input Layer**: A tabular feature vector of size $N_{sensors} \times N_{stats}$ (e.g., $10 \times 10 = 100$ features).
*   **Inference Engine**: A boosted ensemble of decision trees optimized to minimize the L1 error (MAE).

# Data
The data processing pipeline focuses on reducing the high-dimensional time-series data into compact, informative descriptors while handling the significant missing data detected in sensors 2, 5, and 8.

1.  **Loading & Imputation**:
    *   Read each segment's CSV file.
    *   Address the missing values (NaNs) identified in the analysis (up to ~23% in some sensors) by filling them with the **column mean** of that specific segment. This ensures that statistics like standard deviation are not distorted by zero-filling artifacts.

2.  **Feature Engineering**:
    *   For each of the 10 sensor channels, compute a set of statistical descriptors. Based on the data analysis which showed `std` as the top correlated feature, we will focus on dispersion and shape metrics:
        *   **Dispersion**: Standard Deviation, Variance, Interquartile Range (IQR), Minimum, Maximum, Range (Max - Min).
        *   **Central Tendency**: Mean, Median.
        *   **Distribution Shape**: Skewness, Kurtosis (to capture the "tailedness" of the seismic activity).
        *   **Dynamics**: Mean of the absolute values of the first difference (representing signal "velocity" or abrupt changes).
    *   Concatenate these statistics into a single row per `segment_id`.

3.  **Normalization**:
    *   While tree-based models are generally robust to scale, standardizing the target variable or features is not strictly necessary, keeping the pipeline simple.

# Training
The training procedure is designed to prevent overfitting while maximizing the usage of the provided stratified metadata.

*   **Algorithm**: LightGBM Regressor.
*   **Objective Function**: Mean Absolute Error (MAE), aligning directly with the competition metric.
*   **Validation Strategy**: Use the pre-generated `metadata/train.csv` and `metadata/val.csv` splits. This ensures the validation set has a representative distribution of eruption times.
*   **Optimization**:
    *   Use **Early Stopping**: Train until the validation MAE stops improving for a set number of rounds (e.g., 50 rounds).
    *   Hyperparameters: Stick to default parameters initially, perhaps slightly lowering the `learning_rate` and increasing `n_estimators` for stability.

# Evaluation
1.  **Test Set Processing**: Iterate through `metadata/test.csv`. For each file path, load the data, apply the exact same imputation and feature engineering steps as the training set to generate a feature vector.
2.  **Prediction**: Pass the test feature vectors through the trained LightGBM model to predict `time_to_eruption`.
3.  **Submission**: Format the output as a CSV with `segment_id` and the predicted `time_to_eruption`.
