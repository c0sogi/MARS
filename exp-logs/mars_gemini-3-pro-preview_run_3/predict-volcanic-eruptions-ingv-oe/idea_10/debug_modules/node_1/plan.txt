The issue is that `library/config.py` contains a direct call to `run_pipeline()` at the global scope. When `runfile.py` imports `library.config` to access configuration constants, this function call triggers the execution of the entire training pipeline immediately. This blocks the intended execution of `runfile.py` and causes a timeout as it attempts to process the full dataset instead of the small debug subset.

To fix this, I will wrap the `run_pipeline()` call in `library/config.py` within an `if __name__ == "__main__":` block. This ensures the pipeline only runs when the script is executed directly, preventing unintended execution during imports.

library/config.py
<<<<<<< SEARCH
# Execute Pipeline
run_pipeline()
=======
# Execute Pipeline
if __name__ == "__main__":
    run_pipeline()
