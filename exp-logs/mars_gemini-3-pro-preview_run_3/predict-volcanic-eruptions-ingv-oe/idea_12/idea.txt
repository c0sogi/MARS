Based on the comprehensive analysis of previous experiments and the specific lessons derived, I propose the **Multi-Resolution Hybrid-Stream Stacking** strategy.

This approach synthesizes the high-performance components of the "Current Best" solution (Idea 4: Wavelets + Kinematics) with the critical corrections identified in subsequent failures (Idea 7: Smoothing, Idea 10: Peak Preservation). It resolves the conflict between "Robustness" and "Signal Intensity" by implementing a **Dual-Stream Feature Pipeline** that treats raw amplitude and kinematic evolution as distinct views, wrapped in a **Stacking Ensemble** to maximize generalization.

# Model
The predictive architecture will be a **Two-Level Stacking Ensemble**.
*   **Level 0 (Base Learners):** Three distinct Gradient Boosted Decision Tree (GBDT) implementations: **LightGBM**, **XGBoost**, and **CatBoost**.
    *   *Rationale:* GBDTs have proven to be the superior backbone for this dataset (Cite solution_lesson_node_00008). Using diverse implementations introduces algorithmic diversity (different split-finding and regularization strategies), reducing the variance observed in single-model solutions like Idea 4.
*   **Level 1 (Meta Learner):** A **Ridge Regression** model.
    *   *Rationale:* A linear meta-learner optimally combines the Out-of-Fold (OOF) predictions from the base learners to correct systematic biases without the overfitting risk of complex meta-models (Cite solution_lesson_node_00008).

# Data
The data processing pipeline is the core innovation. It implements a **Dual-Stream** paradigm to simultaneously capture signal intensity (Peaks) and signal dynamics (Kinematics) without cross-contamination of noise.

1.  **Preprocessing:**
    *   **Imputation:** Fill missing values with the segment-wise column mean to preserve DC offsets (Cite solution_lesson_node_00002).
    *   **Stream Splitting:** Create two parallel data streams:
        *   **Stream A (Raw):** The original imputed sensor data.
        *   **Stream B (Smoothed):** Apply a **Savitzky-Golay filter** with a **large window size (> 20)** to Stream A. This is mandatory to prevent noise amplification during derivative calculation (Cite solution_lesson_node_00006, solution_lesson_node_00023).

2.  **Feature Engineering (The Hybrid Paradigm):**
    *   **View 1: Raw Intensity (From Stream A):** Extract **Global Minimum**, **Global Maximum**, and **Peak-to-Peak Range**.
        *   *Rationale:* In seismic prediction, "outliers" are the signal. We explicitly retain raw extrema to capture the event severity, correcting the flaw in Idea 8/9 where robust statistics discarded these critical peaks (Cite solution_lesson_node_00031).
    *   **View 2: Robust Kinematics (From Stream B):** Compute **First (Velocity)** and **Second (Acceleration)** derivatives of the *smoothed* signal. Extract **Quantiles (1st, 5th, 95th, 99th)**, Mean, and Std.
        *   *Rationale:* Derivatives capture the rate of change (Cite solution_lesson_node_00021). Using Quantiles instead of Skewness/Kurtosis provides stable shape descriptors for these noisy derivatives (Cite solution_lesson_node_00026).
    *   **View 3: Multi-Resolution Texture (From Stream A):** Apply **Discrete Wavelet Transform (DWT)** (using `db4` wavelet) to decompose the signal. Extract energy and standard deviation from the approximation and detail coefficients.
        *   *Rationale:* This retains the texture-capturing success of Idea 4, which outperformed generic FFT statistics.
    *   **View 4: Structural Spectral Features (From Stream A):** Compute Power Spectral Density (PSD) and extract **Band Power** (Low/Mid/High) and **Spectral Centroid**.
        *   *Rationale:* This captures harmonic tremors better than generic FFT statistics (Cite solution_lesson_node_00007).
    *   **View 5: Flattened Temporal Windows (From Stream A):** Divide the signal into non-overlapping windows. Compute **RMS** and **Mean**.
        *   *Constraint:* **Flatten** these into explicit features (e.g., `w1_rms`, `w2_rms`) to preserve the temporal "arrow of time" (Cite solution_lesson_node_00010). Do not use Min/Max on windows (Cite solution_lesson_node_00023).

3.  **Feature Organization:**
    *   **Spatial Concatenation:** Concatenate the feature vectors of all 10 sensors into a single wide input. Do **not** aggregate features across sensors (Cite solution_lesson_node_00018).
    *   **No External Selection:** Feed the full feature set to the models. Do **not** use RFE (Cite solution_lesson_node_00017).

# Training
*   **Strategy:** Use **Stratified K-Fold Cross-Validation** (e.g., 5 folds) based on the provided metadata bins.
*   **Procedure:**
    1.  Train each Base Learner (LGBM, XGB, CatBoost) on the training folds, optimizing for **MAE**.
    2.  Generate "Out-of-Fold" (OOF) predictions for the training set.
    3.  Train the Meta Learner (Ridge) on the OOF predictions to predict the target `time_to_eruption`.
    4.  Retrain Base Learners on the full training set for final inference.
*   **Optimization:** Set a high `n_estimators` (e.g., 10,000) and use **Early Stopping** based on validation MAE (Cite solution_lesson_node_00002).

# Evaluation
1.  **Feature Extraction:** Process the test set using the full Dual-Stream pipeline (Imputation -> Smoothing -> Hybrid Feature Extraction -> Concatenation).
2.  **Base Inference:** Generate predictions from the retrained LightGBM, XGBoost, and CatBoost models.
3.  **Stacked Inference:** Feed the base predictions into the Ridge Meta-Learner to produce the final `time_to_eruption`.
4.  **Submission:** Format the output as `segment_id,time_to_eruption`.
