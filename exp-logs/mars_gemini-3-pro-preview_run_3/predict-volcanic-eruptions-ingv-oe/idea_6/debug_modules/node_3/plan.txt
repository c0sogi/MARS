The issue is that `library/data_processor.py` imports configuration variables (like `DEBUG`, `DEBUG_SAMPLE_SIZE`) directly from `library.config`. Since these are primitive types, they are copied by value at import time. When `runfile.py` subsequently modifies `config.DEBUG` to `True`, the `data_processor` module retains the old value (`False`), causing it to load the full dataset instead of the sample, leading to the assertion error. This is a classic "stale configuration" issue (Cite debug_lesson_2).

To fix this, I will update `library/data_processor.py` and `library/model_trainer.py` to import the `config` module itself rather than individual variables. This ensures that the code accesses the current state of the configuration variables at runtime.
