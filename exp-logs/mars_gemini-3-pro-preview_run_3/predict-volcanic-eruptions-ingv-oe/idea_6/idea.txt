Based on the extensive experimentation and the specific lessons derived from previous ideas, I propose the **Spatially-Coupled Kinematic Ensemble** strategy. This approach optimizes the feature engineering pipeline to prioritize physical interpretability and sensor geometry while leveraging the proven efficiency of Gradient Boosting.

# Model
The architecture will evolve from a single LightGBM model to a **Heterogeneous Weighted Ensemble** of **LightGBM** and **XGBoost** regressors.
*   **Rationale:** Previous experiments confirmed that Gradient Boosting on tabular features is the superior paradigm for this dataset (Cite solution_lesson_node_00008). However, relying on a single model type leaves performance on the table. By ensembling two distinct GBDT implementations (which handle split finding and regularization differently) trained on the same high-quality feature set, we can reduce prediction variance and improve generalization without the risk of including a non-convergent "weak" learner like a CNN (Cite solution_lesson_node_00008).
*   **Input Layer:** A dense tabular vector representing the concatenated features of all 10 sensors, augmented with explicit spatial interaction terms.

# Data
The data pipeline is designed to maximize signal extraction while rigorously preventing noise amplification and information loss.

1.  **Preprocessing & Imputation:**
    *   Load the raw sensor data.
    *   Impute missing values with the **segment-wise column mean** to preserve the DC offset (Cite solution_lesson_node_00002).
    *   **Signal Smoothing:** Apply a **Savitzky-Golay filter** to the raw waveforms. This is a mandatory step to enable the safe extraction of kinematic features, preventing the catastrophic noise amplification observed when using raw derivatives (Cite solution_lesson_node_00006).

2.  **Feature Engineering (Exploitation & Innovation):**
    *   **Per-Sensor Kinematics (Exploitation):** For each of the 10 sensors, calculate the first (velocity) and second (acceleration) derivatives of the *smoothed* signal. Compute **Higher-Order Moments** (Skewness, Kurtosis) and basic stats (Mean, Std) for these derivatives. This captures the "impulsiveness" and rate of change of the seismic activity, which are critical predictors (Cite solution_lesson_node_00021).
    *   **Explicit Windowing (Exploitation):** Divide the signal into non-overlapping windows. Compute statistics (Mean, Std, RMS) for each window and flatten them into explicit features (e.g., `s1_w1_std`, `s1_w2_std`) to preserve the temporal "arrow of time" (Cite solution_lesson_node_00010).
    *   **Structural Spectral Features (Exploitation):** Compute the Power Spectral Density (PSD) and extract **Band Power** (energy in specific frequency ranges) and **Spectral Centroid**. This preserves the physical "location" of energy better than generic FFT statistics (Cite solution_lesson_node_00007).
    *   **Spatial Interaction Features (Structural Innovation):** Instead of aggregating sensors (which destroys spatial information, Cite solution_lesson_node_00018), explicitly calculate **Pairwise Pearson Correlations** between sensor channels (e.g., Corr(S1, S2)). This creates a "fingerprint" of the synchronization across the volcanic array, allowing the model to distinguish between localized noise and generalized seismic events.

3.  **Feature Organization:**
    *   **Concatenation:** Concatenate all per-sensor and cross-sensor features into a single wide vector. Do **not** pool or average features across sensors (Cite solution_lesson_node_00018).
    *   **No External Selection:** Feed the full feature set to the models. Do **not** use aggressive wrapper methods like RFE, as GBDTs are capable of internal soft selection, and external pruning has been shown to discard valuable distributed signal (Cite solution_lesson_node_00017).

# Training
*   **Strategy:** Train both the LightGBM and XGBoost models using **Stratified K-Fold Cross-Validation** (based on the provided metadata bins).
*   **Objective:** Minimize **Mean Absolute Error (MAE)**.
*   **Optimization:**
    *   Set a high `n_estimators` (e.g., 10,000) for both models to ensure convergence (Cite solution_lesson_node_00002).
    *   Implement **Early Stopping** based on the validation set MAE to prevent overfitting.

# Evaluation
1.  **Inference:** For every segment in the test set, generate the full set of Kinematic, Windowed, Spectral, and Spatial features.
2.  **Prediction:** Pass the features through both trained models (LightGBM and XGBoost).
3.  **Ensembling:** Compute the simple arithmetic mean of the predictions from both models to generate the final `time_to_eruption`.
4.  **Submission:** Format the output as `segment_id,time_to_eruption`.
