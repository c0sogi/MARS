The following implementation demonstrates the usage of the provided library files to execute the machine learning pipeline for the volcano eruption prediction task.

### Implementation Strategy
1.  **Environment Setup**: Import necessary modules and the provided library components (`config`, `feature_engineering`, `data_manager`, `model_handler`, `workflow_orchestrator`).
2.  **Configuration Override (Monkey Patching)**: To ensure the demonstration runs quickly and adheres to the "Optimize for Speed" requirement, I will dynamically override the `get_lgbm_params` function in `library.model_handler`. This replaces the computationally expensive default hyperparameters (5000 estimators) with a lightweight configuration (10 estimators) suitable for a demo.
3.  **Feature Engineering Verification**:
    *   Directly test `process_segment` on a single metadata row to verify feature extraction logic.
    *   Validate that the output contains expected keys (e.g., sensor stats, target).
4.  **Data Management Verification**:
    *   Use `get_train_data` and `get_test_data` with a small `debug_size` (20 samples) to verify data loading and dimensionality.
    *   Assert that the returned DataFrames have the correct shapes and types.
5.  **Model Training Verification**:
    *   Perform a unit test of `train_fold_model` using the small data subset to ensure the LightGBM integration works correctly.
6.  **Full Workflow Execution**:
    *   Execute the end-to-end `generate_submission` pipeline via `workflow_orchestrator`.
    *   This triggers feature generation, cross-validation (training 5 folds), and prediction on the test set.
    *   Verify the final submission file is created and follows the required format.
