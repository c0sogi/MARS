### Implementation Strategy

1.  **Environment Setup**: Set random seeds for reproducibility and define paths for temporary working files.
2.  **Data Subset Creation**: To ensure the demonstration runs quickly (within the time limit) and optimizes for speed, we will create "mini" versions of the metadata files (Train, Validation, Test) containing only a small number of samples (e.g., 20 samples). These will be saved to the `./working` directory.
3.  **Library Monkey-Patching**: Since the provided library files have hardcoded paths and import specific variables, we will dynamically update (monkey-patch) the path variables within the `library.feature_engineering` module. This redirects the feature generation process to use our mini-metadata files and output to temporary Parquet files, allowing us to use the high-level `build_dataset` function without modifying the library code on disk.
4.  **Feature Engineering & Data Loading**: Call `library.data_processor.build_dataset(load_cached_data=False)`. This triggers the feature extraction pipeline on our data subset. We will assert that the resulting dataset shapes match our subset size.
5.  **Model Training**: Instantiate the `EruptionPredictor` from `library.model_trainer`. We will override the default LightGBM parameters to use a very small number of estimators (e.g., 10) and disable verbose logging. We will then train the model on the mini-dataset and verify the training process completes.
6.  **Prediction & Submission**: Use the trained model to predict on the test set and generate a submission file using `library.model_trainer.generate_submission`. We will verify the output file is created correctly.
7.  **Validation**: Throughout the script, `assert` statements will be used to verify data shapes, file existence, and prediction integrity.
