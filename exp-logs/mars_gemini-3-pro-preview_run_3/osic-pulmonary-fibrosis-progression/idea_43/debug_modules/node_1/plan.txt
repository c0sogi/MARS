The `KeyError: 'Weeks'` arises because the `merge` operation between `sub_df` (which has a generated `Weeks` column for target predictions) and `test_meta` (which has a `Weeks` column for the baseline measurement) causes a column name collision. Pandas resolves this by renaming them to `Weeks_x` and `Weeks_y`, removing the explicit `Weeks` column that `LungDataset` expects for sorting and feature engineering.

To fix this, I will rename the `Weeks` column in `test_meta` to `Baseline_Weeks` before the merge. This ensures the target `Weeks` column from `sub_df` is preserved in the final DataFrame, preventing the crash while keeping the baseline timing information available under a distinct name. This addresses the issue of implicit column renaming in redundant merges (Cite debug_lesson_6).
