The following code demonstrates the complete workflow for the Leaf Classification task using the provided library files.

### Implementation Strategy
1.  **Environment Setup**: We initialize the random seeds for reproducibility and create a temporary working directory (`./working/demo_run`) to store intermediate files and outputs without affecting the main working directories.
2.  **Data Subsetting**: To ensure the script runs quickly (under 1 hour) while maintaining logical validity, we create a small subset of the metadata. We select 3 specific species from the training set to ensure we have enough samples per class (approx. 8) to satisfy the requirements of Stratified K-Fold cross-validation (2 folds) and LDA.
3.  **Configuration Patching**: We dynamically override the `Config` class attributes to point to our new subset metadata files and the temporary working directory. This allows us to use the library functions as-is but directed at our demo data.
4.  **Component Verification**:
    *   **Image Processing**: We load a sample image and verify that `generate_rotated_views` produces the expected tensor shape (36 views).
    *   **Feature Extraction**: We instantiate the `FeatureExtractor` and run a small batch through the DINOv2 and ConvNeXt models to confirm the output feature dimensions (2560).
    *   **Manifold Densification**: We verify the logic of `compute_orthogonal_centroids` using dummy data.
5.  **Pipeline Execution**:
    *   **Training**: We call `train_and_evaluate`, which handles feature extraction (caching results), manifold densification (expanding the dataset), and training the `DualStreamLDA` model within a cross-validation loop.
    *   **Inference**: We call `generate_submission`, which processes the test set, applies Test-Time Aggregation (TTA) using the trained models, and generates the final CSV.
6.  **Final Validation**: We assert that the submission file exists and matches the expected format (rows for test IDs, columns for the selected species).
