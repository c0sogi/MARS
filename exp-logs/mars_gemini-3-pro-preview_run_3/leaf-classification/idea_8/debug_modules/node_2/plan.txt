The issue stems from an ordering mismatch between the image features and the tabular features for the training set. The `get_data_loaders` function currently hardcodes `shuffle=True` for the training `DataLoader`, causing image features to be extracted in a random order. However, `load_tabular_data` reads the CSV file sequentially. When `FeaturePipeline` attempts to merge these streams, it detects that the IDs do not match (`ValueError: ID mismatch`), as one stream is shuffled and the other is not.

To fix this, I will modify `get_data_loaders` in `library/data_loader.py` to accept a `shuffle_train` parameter (defaulting to `True` to preserve existing behavior elsewhere). Then, I will update `FeatureExtractor._get_loader` in `library/feature_extraction.py` to explicitly request `shuffle_train=False`. This ensures that feature extraction occurs in the deterministic order of the source CSV, aligning perfectly with the tabular data.
