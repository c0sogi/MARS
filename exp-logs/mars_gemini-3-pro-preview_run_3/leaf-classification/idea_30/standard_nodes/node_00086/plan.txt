The issue stems from **data leakage** caused by merging the training and validation datasets into a single combined dataset for cross-validation. This allowed the model to train on samples that were later used for the "hold-out" validation, resulting in an artificially low log loss. Additionally, the small number of samples per class in the isolated training set (sometimes as few as 5) makes `N_FOLDS=10` invalid for `StratifiedKFold`, which requires the number of splits to be less than or equal to the smallest class count (Cite debug_lesson_9).

To fix this:
1.  **Reduce Folds**: In `library/config.py`, reduce `N_FOLDS` from 10 to 5 to accommodate the small class sizes in the training data.
2.  **Separate Datasets**: In `library/data_processing.py`, modify `DatasetManager.load_data` to load `train.csv` and `val.csv` separately instead of concatenating them. This ensures the validation set remains strictly unseen during training.
3.  **Update Validation**: In `runfile.py`, update the validation logic to access the now-separate `val` data directly, removing the masking logic that was previously required for the combined dataset.
