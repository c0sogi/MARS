The issue is caused by an inconsistency in how the cache is generated and validated. Specifically, `get_raw_image_features` was truncating the data *before* saving it to the cache when `Config.DEBUG` was enabled. This resulted in a stale cache file containing only a subset of samples (e.g., 50). When the script was subsequently run with `Config.DEBUG=False`, it loaded the full tabular data (712 samples) but retrieved the truncated image features from the cache, leading to an `AssertionError: Train IDs mismatch`.

To fix this, I will modify `get_raw_image_features` in `library/feature_extractor.py` to:
1.  Validate the cache by comparing the number of cached IDs against the full metadata length. If they don't match (e.g., stale debug cache), the cache is ignored.
2.  Always extract and cache features for the **full** dataset, ensuring the cache is valid for future full runs.
3.  Apply the `Config.DEBUG` slicing only on the returned data, not on the cached data.

This ensures consistency between the tabular and image feature loaders regardless of the `DEBUG` flag's history.
