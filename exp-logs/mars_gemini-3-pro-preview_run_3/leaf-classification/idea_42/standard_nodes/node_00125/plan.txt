The issue is a data type mismatch in `runfile.py` when aligning model predictions to the global class list. The code incorrectly assumes `pipeline.classes_` contains string labels and attempts to map them to indices using `np.searchsorted` against the string array `classes`. However, since the models were trained on label-encoded integers (produced by `LabelEncoder` in `trainer.py`), `pipeline.classes_` already contains the integer indices corresponding to the global class list. Attempting to compare these integers with the strings in `classes` raises a `TypeError`.

The fix is to remove the `np.searchsorted` call and use `pipeline.classes_` directly as the column indices for the probability matrix, consistent with the logic in `trainer.py` and `inference.py`. This aligns with the strategy for handling missing classes in ensembles (Cite debug_lesson_7).
