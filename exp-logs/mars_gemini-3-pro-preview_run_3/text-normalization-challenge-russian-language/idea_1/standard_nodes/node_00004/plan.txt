The `OutOfMemoryError` is caused by the inefficient memory usage in the `Attention` mechanism, specifically the use of `hidden.unsqueeze(1).repeat(1, src_len, 1)` followed by `torch.cat`. This creates large intermediate tensors that scale quadratically with sequence length ($O(\text{Batch} \times \text{TargetLen} \times \text{SourceLen})$) and are stored for backpropagation.

To fix this, I will:
1.  **Refactor the Attention Mechanism** in `./library/model.py` to use a memory-efficient implementation. Instead of concatenating and projecting, I will decompose the linear projection into two separate layers (`attn_enc` and `attn_dec`) and use broadcasting to sum them. This avoids physically repeating the hidden state vector and creating the large concatenated tensor (Cite debug_lesson_1).
2.  **Reduce the Batch Size** in `./runfile.py` from 64 to 32. As noted in the lesson, addressing quadratic memory scaling often requires aggressive batch size reduction to fit the computational graph of long sequences (up to 300 steps) within GPU memory (Cite debug_lesson_1).
