The `RuntimeError: mat1 and mat2 shapes cannot be multiplied` occurs because the model initialization relies on static metadata (`self.backbone.feature_info`) to determine the input size for the final linear layer (`self.fc`). However, the actual feature maps produced by the backbone during the forward pass have a different total channel count (664) than what was statically predicted (720). This discrepancy is common when using specific `timm` models or configuration overrides.

To fix this, I will modify the `__init__` methods of both `AppleEfficientNet` and `AppleMaxViT` to perform a dummy forward pass with a sample tensor. This allows the code to empirically measure the exact shape of the feature maps and initialize the linear layer with the correct dimensions, as recommended in **Cite debug_lesson_6**.
