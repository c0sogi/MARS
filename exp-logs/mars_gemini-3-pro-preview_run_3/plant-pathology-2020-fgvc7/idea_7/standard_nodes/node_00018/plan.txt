The data leakage issue stems from the `prepare_folds` function in `library/data.py`, which incorrectly merges the hold-out validation dataset (`val.csv`) with the training dataset (`train.csv`) before creating cross-validation folds. This causes the models to train on the specific images intended for the final independent evaluation, resulting in an invalid perfect score. The fix is to modify `prepare_folds` to strictly use `Config.TRAIN_CSV` for generating the folds, ensuring the hold-out validation set remains completely unseen during the training phase.
