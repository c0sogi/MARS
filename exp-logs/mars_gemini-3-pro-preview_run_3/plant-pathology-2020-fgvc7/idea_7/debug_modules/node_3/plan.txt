The `AssertionError` in `runfile.py` occurs because the model checkpoints are never saved. This happens because the validation AUC (`val_auc`) consistently evaluates to `nan` (or `0.0` in the original fallback) during the demo run. In the debug mode with a very small sample size (`Config.DEBUG_SAMPLE_SIZE = 20`), the validation set often lacks positive examples for one or more classes. When this occurs, `sklearn.metrics.roc_auc_score(..., average='macro')` returns `nan` (a silent failure) instead of raising a `ValueError`. The existing code does not check for `nan`, so `val_auc` remains `nan`. Consequently, the comparison `if val_auc > best_auc:` (where `best_auc` is 0.0) fails, and no checkpoint is created.

To fix this, I will modify `library/utils.py` to explicitly check if the ROC AUC score is `nan`. If it is, I will raise a `ValueError` to trigger a fallback mechanism. This fallback will calculate the AUC for each column individually, ignoring classes that are not present in the current subset, and return the mean of the valid scores. This ensures a valid numeric score is returned, allowing the training loop to track the best model and save checkpoints.
