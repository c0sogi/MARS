The issue is that the `generate_cache` function in `library/data.py` keeps the write-mode memory maps (`eeg_mmap` and `spec_mmap`) open while attempting to create new read-mode memory maps for the same files. This results in double the virtual memory consumption (approx. 200GB+), causing the `OSError: [Errno 12] Cannot allocate memory`. As per **Cite debug_lesson_5**, while using memory mapping is correct for large datasets, one must properly manage the lifecycle of these mappings. The fix is to explicitly delete the write-mode objects and trigger garbage collection to release the resources before reloading the data in read-only mode.
