The error occurred because of a configuration mismatch between the training and inference phases. During training (`runfile.py`), the Reader model was instantiated with a hardcoded `num_highway_layers=1`, saving a checkpoint with only one highway layer. However, the inference pipeline (`inference_utils.py`) initializes the model using the default configuration `config.HIGHWAY_LAYERS`, which is set to `2` in `library/config.py`. Since the demo setup in `runfile.py` failed to override this default, the inference model expected two layers but tried to load weights for only one, causing a `RuntimeError`.

To fix this, I will update `runfile.py` to explicitly set `config.HIGHWAY_LAYERS = 1` in the demo environment setup and update the training instantiation to use this configuration value instead of a hardcoded integer. This ensures consistency across both phases (Cite debug_lesson_8).
