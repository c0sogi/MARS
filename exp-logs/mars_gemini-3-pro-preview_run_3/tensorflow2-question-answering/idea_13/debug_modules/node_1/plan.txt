The issue is that the `TextProcessor` splits document text on both container tags (like `<Ul>`, `<Table>`) and child tags (like `<Li>`, `<Tr>`), causing nested structures to be fragmented into multiple small segments (e.g., an empty `<Ul>` segment followed by `<Li>` segments). This violates the expectation in `runfile.py` that a list should be a single segment. The fix is to remove the child tags (`<Tr>`, `<Li>`, `<Dd>`, `<Dt>`) from the `split_tags` set in `library/text_utils.py`, ensuring that lists and tables are kept intact as single candidate paragraphs. This applies the lesson of maintaining a consistent Single Source of Truth for data processing rules (Cite debug_lesson_2).
