### Model
The proposed solution is a **Compare-Aggregate Ranker and Dilated Convolutional Reader**. This architecture focuses on computational efficiency by utilizing lightweight interaction mechanisms for ranking and parallelizable dilated convolutions for extraction, avoiding the sequential bottlenecks of RNNs and the quadratic complexity of Transformers.

1.  **Long Answer Ranker (Compare-Aggregate Network):**
    *   **Input:** Accepts the Question and a Candidate Long Answer (paragraph) as inputs.
    *   **Embedding:** Maps tokens to pre-trained static word embeddings (e.g., GloVe).
    *   **Question Encoding:** The Question embeddings are aggregated into a single dense vector using a **Max-Pooling** operation to capture the most salient keywords.
    *   **Comparison:** This Question Vector is compared against *every* token embedding in the Candidate Paragraph using an element-wise operation (e.g., Hadamard product or concatenation). This generates a sequence of "local relevance" vectors for the paragraph.
    *   **Aggregation:** The sequence of relevance vectors is summed (Sum-Pooling) to produce a single fixed-size representation of the pair.
    *   **Scoring:** This aggregated vector is passed through a small Feed-Forward Network (MLP) to output a relevance probability.

2.  **Short Answer Reader (Dilated ConvNet):**
    *   **Input:** Concatenates the Question and the Top-Ranked Candidate Paragraph.
    *   **Encoder:** The sequence is passed through a stack of **Dilated 1D-Convolutional** layers. Each layer increases the dilation rate exponentially (e.g., 1, 2, 4, 8). This allows the network to expand its receptive field to cover the entire paragraph and capture long-range dependencies without using pooling layers (which lose spatial resolution) or recurrent connections (which are slow).
    *   **Output:** The output of the final convolutional layer is fed into two independent 1x1 Convolutional layers (pointwise) to predict the logits for the `start` and `end` token indices.

### Data
*   **Preprocessing:** The raw `document_text` is parsed to identify top-level HTML tags (e.g., `<P>`, `<Table>`), splitting the document into discrete candidate paragraphs.
*   **Tokenization:** Text is tokenized by splitting on whitespace and mapped to indices in a vocabulary derived from the pre-trained embeddings.
*   **Ranker Dataset:** Training pairs are constructed. Positive pairs consist of the Question and the ground-truth paragraph. Negative pairs are selected by sampling paragraphs from the same document that do not contain the answer.
*   **Reader Dataset:** Only positive paragraphs containing a valid short answer are used. The start and end indices are adjusted to be relative to the beginning of the concatenated sequence.

### Training
*   **Strategy:** The Ranker and Reader are trained as independent models to minimize memory usage and allow for parallel training.
*   **Ranker Optimization:** Trained using **Binary Cross-Entropy Loss**. The model learns to classify whether a given Question-Paragraph pair is a match (1) or a non-match (0).
*   **Reader Optimization:** Trained using **Categorical Cross-Entropy Loss** for the start and end positions.
*   **Optimizer:** The Adam optimizer is used for both models.

### Evaluation
1.  **Candidate Generation:** The test document is segmented into candidate paragraphs.
2.  **Ranking:** The Compare-Aggregate Ranker processes the Question against all candidates to generate a relevance probability for each.
3.  **Selection:** The candidate with the highest probability is identified as the predicted Long Answer.
4.  **Extraction:** The Dilated ConvNet Reader processes the selected paragraph (concatenated with the question) to generate probability distributions for start and end indices.
5.  **Inference:** The valid span (`start <= end`) with the highest joint probability is selected. A global confidence score is computed; if it falls below a tuned threshold, the system predicts "Null", otherwise it outputs the Long Answer indices and Short Answer text.
