Based on the requirements and the provided model architectures, here is a proposal for a highly efficient baseline approach.

### Model
The proposed solution is a **Hierarchical Embed-and-Scan Network**, designed to decouple the problem into coarse-grained ranking (Long Answer) and fine-grained extraction (Short Answer) using computationally inexpensive components.

1.  **Long Answer Ranker (Siamese DAN):** To identify the correct paragraph, the model uses a **Deep Averaging Network (DAN)** in a Siamese configuration.
    *   **Input:** Accepts the Question and a Candidate Long Answer (paragraph) as separate inputs.
    *   **Embedding Layer:** Maps tokens to static, pre-trained word embeddings (e.g., GloVe) to avoid the computational cost of training embeddings from scratch.
    *   **Encoder:** Applies a simple **Average Pooling** operation over the sequence dimension of the embeddings, followed by a two-layer Feed-Forward Network (MLP) with ReLU activations. This compresses the text into a low-dimensional dense vector.
    *   **Scoring:** Calculates the dot product between the Question vector and the Candidate vector to produce a relevance score.

2.  **Short Answer Reader (Shallow CNN):** To extract the specific span within the chosen paragraph, the model uses a lightweight **1D-Convolutional Neural Network**.
    *   **Input:** Concatenates the Question and the Top-Ranked Long Answer candidate.
    *   **Encoder:** A stack of two 1D-Convolutional layers (kernel size 3 or 5) captures local n-gram context without the sequential dependency overhead of RNNs or the quadratic complexity of Self-Attention.
    *   **Output:** Two independent linear layers predict the logits for the `start` and `end` token indices of the short answer.

### Data
*   **Candidate Generation:** The raw `document_text` is parsed to split the article into discrete candidate blocks based on top-level HTML tags (e.g., `<P>`, `<Table>`, `<Ul>`). This transforms the long document into a manageable list of potential Long Answers.
*   **Tokenization:** Text is tokenized by splitting on whitespace and mapped to a fixed vocabulary index based on the pre-trained embeddings. Unknown words are mapped to a generic `<UNK>` token.
*   **Training Set Construction:**
    *   For the **Ranker**, datasets are created by pairing the ground-truth positive paragraph with a random sample of $k$ negative paragraphs from the same document.
    *   For the **Reader**, only the positive paragraphs containing short answers are used. The start/end indices are adjusted to be relative to the start of the paragraph.

### Training
*   **Strategy:** The Ranker and Reader modules are trained independently to maximize training speed and stability.
*   **Ranker Optimization:** Trained using **Margin Ranking Loss** (or Contrastive Loss). The objective is to ensure the similarity score of the positive candidate is higher than that of the negative candidates by a specified margin.
*   **Reader Optimization:** Trained using **Categorical Cross-Entropy Loss** for the start and end pointers.
*   **Optimizer:** The Adam optimizer is used for both modules with a standard learning rate decay.

### Evaluation
1.  **Preprocessing:** The test document is segmented into candidate blocks.
2.  **Ranking:** The DAN Ranker encodes the Question and all Candidates. It computes similarity scores for every candidate.
3.  **Long Answer Prediction:** The candidate with the highest similarity score is selected as the predicted Long Answer.
4.  **Extraction:** The selected candidate is passed to the CNN Reader, which predicts start and end probabilities.
5.  **Thresholding:** A confidence threshold is applied to the Ranker's top score. If the score is below the threshold, the model predicts "Null" (no answer). Otherwise, it outputs the predicted Long Answer indices and the Short Answer span derived from the Reader.
