The `AssertionError: Probabilities do not sum to 1.0` is caused by precision loss when saving the floating-point probability predictions to the CSV file using the default pandas formatting. When `runfile.py` reads these truncated values back, their sum deviates from 1.0 beyond the strict tolerance of `1e-5`. To fix this, I will update the `predict` function in `library/engine.py` (and the corresponding function in `library/modeling.py` for consistency) to explicitly specify `float_format='%.8f'` during the `to_csv` call. This ensures that sufficient precision is preserved in the output file to pass the verification check, addressing the I/O precision bottleneck (Cite debug_lesson_4).
