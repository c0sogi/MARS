The `RuntimeError: Trying to backward through the graph a second time` is caused by the default behavior of gradient checkpointing in PyTorch (via Hugging Face Transformers), which uses a "reentrant" implementation. In a Siamese network architecture where the same backbone model is called multiple times within a single forward pass (once for each branch), the reentrant checkpointing logic fails to correctly track the shared graph dependencies, leading to conflicts during backpropagation. To resolve this, we must explicitly configure the model to use the modern non-reentrant implementation by passing `gradient_checkpointing_kwargs={"use_reentrant": False}` Cite debug_lesson_7.
