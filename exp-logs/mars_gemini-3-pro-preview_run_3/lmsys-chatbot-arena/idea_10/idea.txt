This strategy addresses the "reasoning gap" by successfully scaling to a **Large** backbone (solving the convergence issues of Lesson 27 via improved training dynamics) and introduces a **Decoupled Contextual Pooling** structure to refine how the model utilizes the prompt.

# Model: Siamese DeBERTa-v3-Large with Decoupled Contextual Pooling

I propose upgrading the backbone to **`microsoft/deberta-v3-large`** within a Siamese architecture, enhanced by a **Decoupled Prompt-Response Pooling** mechanism.

*   **Backbone Architecture:** The solution will utilize **`microsoft/deberta-v3-large`**.
    *   **Rationale:** Previous experiments confirmed that pre-trained Transformers outperform LSTMs (Cite solution_lesson_node_00022). While the "Base" model was efficient, the "Large" model theoretically offers better reasoning capabilities required for subtle preference judgments. Lesson 27 noted that "Large" failed previously due to resource bottlenecks (underfitting/instability); I will address this via the training strategy (Gradient Accumulation) rather than downgrading the model.
*   **Siamese Input Structure:** The model will process two parallel branches sharing weights:
    1.  **Branch A:** `[CLS] Prompt [SEP] Response A [SEP]`
    2.  **Branch B:** `[CLS] Prompt [SEP] Response B [SEP]`
    *   **Rationale:** This retains the Siamese advantage of maximizing the context window for each response (512 tokens each), avoiding the aggressive truncation issues of Cross-Encoders (Cite solution_lesson_node_00023).
*   **Structural Innovation: Decoupled Multi-Layer Pooling:**
    *   I will evolve the "Response-Isolated Pooling" (Cite solution_lesson_node_00025) into a **Decoupled** dual-stream aggregation.
    *   **Stream 1 (Response):** For each branch, apply a binary mask to zero out `Prompt` tokens. Extract the hidden states from the **last 4 layers**, apply **Learned Attention Pooling** (Cite solution_lesson_node_00011) to each, and concatenate. This yields pure response vectors $R_A$ and $R_B$ (Cite solution_lesson_node_00029).
    *   **Stream 2 (Prompt):** Simultaneously, apply a binary mask to zero out `Response` tokens. Pool the `Prompt` tokens from the last 4 layers to generate a context vector $P$. (Since $P$ is identical in both branches, we average $P_A$ and $P_B$).
    *   **Rationale:** Previous best methods discarded the Prompt embedding to reduce noise in the difference vector. However, the *nature* of the prompt (e.g., "creative writing" vs. "math problem") dictates which features in the response are valuable. By re-introducing $P$ as a separate vector in the final stage, we allow the classifier to condition its judgment on the prompt type without diluting the comparative signal $|R_A - R_B|$.
*   **Hybrid Classification Head:** The final features will be a concatenation of:
    *   **Response Interaction:** $R_A, R_B, |R_A - R_B|, R_A \cdot R_B$
    *   **Context Modulation:** $P, P \cdot R_A, P \cdot R_B$
    *   **Explicit Scalars:** Log-transformed lengths of Prompt, Response A, and Response B (Cite solution_lesson_node_00004).

# Data: Full Dataset with Symmetric Augmentation

*   **Dataset:** Train on the **Full Training Set** (approx. 41k samples). Do not downsample; data volume is the primary driver of performance (Cite solution_lesson_node_00015).
*   **Symmetric Augmentation:** Double the dataset by creating a swapped copy $(B, A)$ with target $1-T$ for every pair $(A, B)$. This enforces permutation invariance and doubles the effective training signal (Cite solution_lesson_node_00029).
*   **Preprocessing:**
    *   **Tokenization:** Use the `deberta-v3-large` tokenizer.
    *   **Feature Consistency:** Compute scalar length features from the **tokenized sequences** to ensure alignment with the encoder (Cite solution_lesson_node_00005).
    *   **Sequence Length:** Set max length to **512 tokens per branch** (Total 1024 tokens of coverage). Truncate the Response if necessary, but always preserve the Prompt to ensure context is available (Cite solution_lesson_node_00013).

# Training: Gradient Accumulation for Large Batch Stability

*   **Strategy:** The primary failure of the previous "Large" model attempt (Lesson 27) was underfitting due to small batch sizes or insufficient epochs. I will solve this using **Gradient Accumulation**.
    *   **Mechanism:** Set the physical batch size to fit in GPU memory (e.g., 2 or 4) but accumulate gradients over multiple steps to achieve a **Target Effective Batch Size of 64**. This stabilizes the optimization landscape, allowing the Large model to converge reliably.
*   **Efficiency:** Enable **Gradient Checkpointing** to minimize activation memory, and use **Mixed Precision (FP16)** for throughput (Cite solution_lesson_node_00027).
*   **Optimizer:** AdamW with a conservative learning rate (e.g., 5e-6) and linear warmup.
*   **Loss Function:** Cross-Entropy Loss on soft targets.

# Evaluation: Robust Inference

*   **Test-Time Augmentation (TTA):** For every test instance, predict on both $(A, B)$ and $(B, A)$. Average the resulting probabilities (flipping the winner for the swapped pair) to produce the final prediction. This neutralizes any residual positional bias (Cite solution_lesson_node_00029).
*   **Pipeline:** Preprocess test data into Siamese pairs, extract scalar features, pass through the Decoupled Pooling model, and apply Softmax.
