Based on the accumulated lessons, I propose a **Hybrid Sequential-Visual Cascade** system. This solution structurally evolves the "Vectorized Sparse Propagation" baseline by integrating a multi-modal retrieval stage with a constrained ranking stage. This addresses the "Signal Destruction" observed in previous ranking attempts while maximizing the computational efficiency of sparse matrix operations.

### Model

The architecture consists of two tightly coupled stages designed to balance Recall and Precision:

1.  **Stage 1: Multi-Modal Vectorized Retrieval (High Recall)**
    *   **Backbone:** This stage utilizes **Vectorized Sparse Propagation** (Cite Lesson 5) to generate candidates. It represents the user's history as a sparse vector $U$ and propagates it through multiple sparse graph matrices.
    *   **User Representation:** We employ **Importance-Based Aggregation** (Cite Lesson 12). Instead of arbitrarily truncating history to the last $N$ chronological events, we aggregate all user transactions within the window, sum their time-decayed weights, and select the top components.
    *   **Sequential Graph ($T_{seq}$):** A **Time-Aware Sequential Transition Matrix** (Cite Lesson 2). We enforce **Strict Recency** (e.g., using only the last 10-12 weeks of data) (Cite Lesson 17) and explicitly **retain raw edge weights** (Cite Lesson 6) rather than normalizing them. This ensures that transitions backed by high transaction volumes (high confidence) naturally dominate the retrieval scores.
    *   **Visual Graph ($T_{vis}$):** To address the sparsity of behavioral data, we introduce a sparse K-Nearest Neighbors graph where edges represent the cosine similarity between item image embeddings.
    *   **Score Aggregation:** The retrieval score is computed as a linear combination of sparse matrix multiplications: $S = U \cdot T_{seq} + \lambda_{vis} (U \cdot T_{vis}) + \alpha U_{history}$. The repurchase weight $\alpha$ will be carefully tuned to prevent historical bias from overpowering new trends (Cite Lesson 11).
    *   **Output:** We extract the **Top-100 candidates** per user (Cite Lesson 15) to ensure the subsequent ranker has a sufficient pool of relevant items to sort, adhering to the Funnel Principle.

2.  **Stage 2: Feature-Constrained Re-Ranking (High Precision)**
    *   **Backbone:** A **LightGBM** model trained with a ranking objective (`lambdarank`).
    *   **Signal Preservation:** To prevent **Signal Destruction** (Cite Lesson 10), where a learned ranker overfits and discards valid heuristic signals, we explicitly feed the **Raw Retrieval Score** ($S_{total}$) and the **Retrieval Rank** from Stage 1 as primary features. This forces the ranker to use the strong sequential signal as a baseline and only re-order based on secondary features.
    *   **Context Features:** We augment the candidate vectors with User Demographics (Age), Global Item Popularity, and Temporal Recency (days since last interaction).

### Data

1.  **Visual Graph Construction:**
    *   Load all article images and pass them through a pre-trained CNN (e.g., `resnet18` or `efficientnet_b0` via `timm`) to generate dense embeddings.
    *   Compute the Top-20 nearest neighbors for each item based on Cosine Similarity.
    *   Store this as a sparse adjacency matrix $T_{vis}$.

2.  **Ranker Dataset Generation:**
    *   **Sliding Window Strategy:** To generate sufficient training data for the ranker, we will use a sliding window approach on the training set (e.g., using Week $N$ as the target and Weeks $N-10 \dots N-1$ as history).
    *   **Labeling:** For each user in the target week, Positive samples (1) are items actually purchased. Negative samples (0) are items retrieved by Stage 1 that were *not* purchased.

### Training

1.  **Retrieval (Deterministic):**
    *   Construct $T_{seq}$ using the time-decay formula on the filtered transaction log.
    *   Construct $T_{vis}$ using the pre-computed image embeddings.
    *   No gradient descent is required for this stage; it is a direct algebraic construction.

2.  **Ranking (Supervised):**
    *   Train the LightGBM model using the `lambdarank` objective (optimizing NDCG).
    *   Use Early Stopping based on a hold-out validation set (the final week of the sliding window) to prevent overfitting.

### Evaluation

1.  **Sparse Inference:**
    *   Construct the sparse user vectors $U$ for all test customers.
    *   Perform the sparse matrix operation: $S = U \cdot T_{seq} + \lambda_{vis} (U \cdot T_{vis}) + \alpha U_{history}$.
    *   **Optimization:** Use **Direct CSR Array Access** (Cite Lesson 16) to efficiently extract the indices of the Top-100 items. This avoids the computational trap of materializing dense score matrices (Cite Lesson 7).
2.  **Scoring & Submission:**
    *   Compute the feature vectors (Heuristic Score + Rank + Metadata) for these 100 candidates.
    *   Score them using the trained LightGBM model.
    *   Select the Top-12 items with the highest predicted scores for the final submission.
