Implementation Strategy:
1.  **Configuration Setup**: I will override the global configuration in `library.config` to use a temporary working directory (`./working/demo_execution`) and reduce computationally expensive hyperparameters (e.g., LightGBM estimators, history weeks) to ensure the script runs quickly.
2.  **Data Subsetting**: To demonstrate the pipeline within the time limit, I will load the full metadata files once, sample a small subset of customers (e.g., 2,000) and their corresponding transaction history, and filter the articles and validation data accordingly.
3.  **Monkey Patching**: I will dynamically replace the data loading functions in `library.data_loader` with wrapper functions that return these in-memory subsetted DataFrames. This ensures that all downstream components (Visual Encoder, Graph Builder, Ranker) operate on this consistent, small dataset without modifying the library files.
4.  **Pipeline Execution**: I will execute the pipeline stages sequentially:
    *   **Visual Encoder**: Generate embeddings for the subset of articles.
    *   **Graph Builder**: Construct the sequential, visual, and user history graphs.
    *   **Retrieval**: Verify candidate generation.
    *   **Feature Engineering**: Create training data for the ranker.
    *   **Ranker**: Train the LightGBM model and generate predictions.
5.  **Validation**: At each step, I will include assertions to verify shapes, data integrity, and file generation, ensuring the logic is correct.
