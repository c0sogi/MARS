Implementation strategy:
1.  **Environment Setup**: Import necessary libraries and the provided modules. Set random seeds for reproducibility.
2.  **Configuration Override**: To ensure the script runs quickly and within memory limits for this demonstration:
    *   Monkey-patch `library.data_utils.load_dataset` to return a small subset of the data (e.g., 200 customers and their associated transactions/articles). This preserves the temporal structure required for the sliding window logic while drastically reducing compute time.
    *   Modify `library.config.Config` parameters at runtime: reduce `RETRIEVAL_TOP_K`, `VISUAL_KNN_K`, `LGBM_PARAMS['n_estimators']`, and disable heavy logging.
    *   Redirect cache paths to a temporary `demo_working` directory to avoid conflicts with existing artifacts.
3.  **Execution Pipeline**:
    *   **ID Mapping**: Generate ID maps based on the sampled dataset. Verify consistency.
    *   **Visual Encoding**: Run the `ImageEmbedder` and `build_visual_graph` on the subset. Verify embedding shapes and graph sparsity.
    *   **Retrieval**: Initialize `DualGraphRetriever` and generate candidates for a sample of users. Verify that candidates are returned with correct columns.
    *   **Feature Engineering**: Initialize `RankerFeatureFactory`. Generate training and validation datasets using the sliding window approach on the sampled data. Verify feature matrix dimensions and label existence.
    *   **Ranking**: Initialize `LGBMRanker`. Train the model on the generated small datasets. Verify the model file is saved.
    *   **Inference**: Generate the inference dataset, run predictions, and produce a submission file. Verify the output format matches requirements.
4.  **Validation**: Insert `assert` statements after each major step to validate data shapes, types, and file existence.
