Based on the accumulated lessons, I propose a **Hybrid Cascade System** that integrates the highly efficient **Vectorized Sparse Propagation** heuristic (as a high-recall retriever) with a **Content-Aware Gradient Boosted Ranker** (as a high-precision filter). This structure specifically addresses the "Signal Destruction" observed in previous ranking attempts by explicitly feeding the heuristic's confidence scores into the ranker and expanding the retrieval window to prevent candidate starvation.

# Model

The architecture consists of two tightly coupled stages:

1.  **Stage 1: Vectorized Sparse Retrieval (High Recall)**
    *   **Backbone:** This stage utilizes the **Vectorized Sparse Propagation** architecture (Cite Lesson 5). It represents the user's history as a sparse vector $U$ and item transitions as a sparse matrix $T$.
    *   **Matrix Construction:** The transition matrix $T$ is built using **Time-Decayed Co-occurrences** (Cite Lesson 2), ensuring recent trends are prioritized. Crucially, we will **retain the raw magnitude of edge weights** and avoid row-normalization (Cite Lesson 6) to preserve confidence signals from high-volume transitions.
    *   **User Representation:** The user vector $U$ is constructed using **Importance-Based Aggregation** (Cite Lesson 12), summing time-decayed weights for all historical items and selecting the top components, rather than arbitrarily truncating to the last $N$ chronological events.
    *   **Output:** We compute the score vector $S = U \cdot T + \alpha \cdot U_{history}$ (where $\alpha$ is a tuned repurchase weight, Cite Lesson 11). From this, we extract the **Top-100 candidates** per user (Cite Lesson 15) to ensure the subsequent ranker has a sufficient pool of relevant items to sort.

2.  **Stage 2: Content-Aware Re-Ranking (High Precision)**
    *   **Backbone:** A **LightGBM** model trained with a ranking objective (`lambdarank`).
    *   **Input Features:** To prevent the "Fragility of Learned Rankers" (Cite Lesson 10), the model will consume:
        *   **Heuristic Signals:** The **raw score** and **rank** from Stage 1. This forces the ranker to respect the strong sequential signal found in the transition graph.
        *   **Visual Signals:** Using a pre-trained CNN (via `timm`), we will extract embeddings for all article images. We will compute the **Cosine Similarity** between the candidate item's embedding and the centroid of the user's recent purchase history. This captures "visual preference" dynamics missing from the ID-based graph.
        *   **Metadata:** User age, item product group, and colour group to capture demographic and categorical affinities.

# Data

1.  **Image Feature Extraction:**
    *   Use a lightweight pre-trained model (e.g., `resnet18` or `efficientnet_b0` from `timm`) to generate a dense embedding vector for every `article_id` with an associated image.
    *   Handle missing images by using a zero-vector or the average embedding of the item's `product_group_name`.

2.  **Ranker Dataset Construction:**
    *   **Time Split:** We will use a sliding window approach. The "Target Week" is the last week of the training data. The "Retrieval History" is all data prior to that week.
    *   **Candidate Generation:** Run the Stage 1 Retrieval model on the "Retrieval History" to generate top-100 candidates for all users active in the "Target Week".
    *   **Labeling:** Positive samples (1) are items actually purchased in the Target Week. Negative samples (0) are the retrieved items that were not purchased.
    *   **Feature Engineering:** Join these candidates with the User/Item metadata, the Visual Similarity scores, and the **Retrieval Score** from Stage 1.

# Training

1.  **Stage 1 (Retrieval):**
    *   This is a deterministic, counting-based process. No gradient-based training is required. The transition matrix $T$ is built once using the defined decay logic.

2.  **Stage 2 (Ranking):**
    *   **Objective:** Train LightGBM using `lambdarank` (optimizing NDCG) or `binary_logloss`.
    *   **Regularization:** Apply early stopping based on a hold-out validation set (a subset of the Target Week users) to prevent overfitting.

# Evaluation

1.  **Full-Data Inference:**
    *   Re-build the Stage 1 Transition Matrix $T$ using the **entire** training dataset (including the week used for Ranker training).
2.  **Sparse Candidate Extraction:**
    *   For each test user, compute the sparse score vector $S$.
    *   Extract the indices of the top 100 items using **Direct CSR Array Access** (Cite Lesson 16) to maximize throughput and avoid dense materialization bottlenecks (Cite Lesson 7).
3.  **Scoring & Submission:**
    *   Compute the feature vectors (Heuristic Score + Visual Sim + Metadata) for these 100 candidates.
    *   Score them using the trained LightGBM model.
    *   Select the top 12 items with the highest predicted scores for the final submission.
