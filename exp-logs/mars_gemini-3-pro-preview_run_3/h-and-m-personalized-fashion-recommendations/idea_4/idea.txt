Based on the accumulated lessons, I propose a **Multi-View Cascade System** that evolves the efficient **Vectorized Sparse Propagation** baseline into a robust two-stage architecture. This solution addresses the "Signal Destruction" and "Candidate Starvation" failures of previous ranking attempts by integrating Visual Content at the retrieval stage and using a calibrated, feature-rich ranker.

# Model

The architecture consists of two distinct stages designed to balance Recall (Retrieval) and Precision (Ranking).

### Stage 1: Multi-View Vectorized Retrieval (High Recall)
This stage generates a pool of high-quality candidates by propagating user history through multiple sparse graphs. It preserves the **Vectorized Sparse Propagation** backbone (Cite Lesson 5) but extends it to handle multi-modal signals.

*   **Behavioral View ($T_{trans}$):** A Time-Decayed Transition Matrix capturing sequential patterns ($A \to B$). We explicitly **retain raw edge weights** (Cite Lesson 6) and enforce **Strict Recency** (Cite Lesson 17) to capture fast-moving trends.
*   **Visual View ($T_{vis}$):** A Sparse K-Nearest Neighbors graph where edges represent the cosine similarity between item image embeddings. This addresses the sparsity of the behavioral graph by linking items that look similar, even if they haven't been bought together frequently.
*   **User Query ($U$):** The user's history is represented as a sparse vector constructed via **Importance-Based Aggregation** (Cite Lesson 12), summing time-decayed weights rather than truncating to the last $N$ items.
*   **Candidate Generation:** We compute the retrieval score $S = U \cdot T_{trans} + \lambda (U \cdot T_{vis}) + \alpha U_{history}$. We extract the **Top-100 candidates** (Cite Lesson 15) to ensure the subsequent ranker has a sufficient selection pool.

### Stage 2: Context-Aware Re-Ranking (High Precision)
A **LightGBM** model trained with a ranking objective (`lambdarank`) sorts the 100 candidates.
*   **Signal Preservation:** To prevent **Signal Destruction** (Cite Lesson 10), we feed the decomposed scores from Stage 1 (`transition_score`, `visual_score`, `repurchase_score`) as explicit features. This forces the ranker to respect the strong heuristic signals while learning to weight them dynamically (e.g., prioritizing Visuals for cold-start users).
*   **Context Features:** We augment the candidate vectors with User Demographics (Age), Global Item Popularity, and Temporal Recency (days since last interaction).

# Data

1.  **Visual Graph Construction:**
    *   Load all article images and pass them through a pre-trained CNN (e.g., `resnet18` via `timm`) to generate dense embeddings.
    *   Compute the Top-20 nearest neighbors for each item based on Cosine Similarity.
    *   Store this as a sparse adjacency matrix $T_{vis}$.

2.  **Ranker Dataset (Sliding Window):**
    *   Instead of a single validation split, we employ a **Sliding Window** strategy to generate training data. We will create multiple (History $\to$ Target) pairs: [Weeks 1-9 $\to$ Week 10], [Weeks 2-10 $\to$ Week 11].
    *   This increases the volume of training data, helping the LightGBM model generalize better than in previous attempts.

# Training

1.  **Retrieval (Deterministic):**
    *   Construct $T_{trans}$ using the time-decay formula on the transaction log.
    *   Construct $T_{vis}$ using the pre-computed image embeddings.
    *   No gradient descent is required for this stage.

2.  **Ranking (Supervised):**
    *   Train the LightGBM model using the `lambdarank` objective (optimizing NDCG).
    *   Use the generated Sliding Window dataset.
    *   Validate on the final week (Week 12) to tune hyperparameters and prevent overfitting.

# Evaluation

1.  **Sparse Inference:**
    *   Construct the sparse user vectors $U$ for all test customers.
    *   Perform the sparse matrix multiplication $S = U \cdot T_{trans} + \lambda (U \cdot T_{vis})$.
    *   Use **Direct CSR Array Access** (Cite Lesson 16) to efficiently extract the indices of the Top-100 items, avoiding dense matrix materialization (Cite Lesson 7).

2.  **Scoring & Submission:**
    *   Compute the feature vectors for these candidates.
    *   Score with the trained LightGBM model.
    *   Select the Top-12 items for the final submission.
