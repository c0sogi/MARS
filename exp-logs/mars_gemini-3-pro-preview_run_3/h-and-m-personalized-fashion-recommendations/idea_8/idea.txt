Based on the accumulated lessons, I propose a **Dual-View Vectorized Cascade with Sliding-Window Calibration**.

This solution structurally evolves the "Vectorized Sparse Propagation" baseline (Idea 1) into a two-stage system. It specifically addresses the "Fragility of Learned Rankers" (Lesson 10) by combining a multi-modal retrieval backbone with a ranking strategy trained on **Sliding Time Windows**. This ensures the ranker learns generalized weighting rules (e.g., "trust visual similarity when sequential signals are weak") rather than overfitting to specific item identities from a single week.

# Model

The architecture consists of two tightly coupled stages designed to balance Recall (Retrieval) and Precision (Ranking).

### Stage 1: Dual-View Vectorized Retrieval (High Recall)
This stage generates a pool of candidates by propagating user history through two distinct sparse graphs. It utilizes the **Vectorized Sparse Propagation** architecture (Cite Lesson 5) to capture collective intent.

1.  **Sequential Trend Graph ($T_{seq}$):** A **Time-Aware Transition Matrix** capturing directional patterns ($A \to B$).
    *   **Strict Recency:** We construct this graph using only the last 12 weeks of data (Cite Lesson 17) to prioritize immediate trends over long-term global bestsellers.
    *   **Raw Weights:** We explicitly **retain raw edge weights** (Cite Lesson 6) rather than normalizing them. This ensures transitions backed by high transaction volumes (high confidence) naturally dominate the retrieval scores.
2.  **Visual Content Graph ($T_{vis}$):** A sparse K-Nearest Neighbors graph where edges represent the cosine similarity between item image embeddings. This addresses the sparsity of behavioral data by linking items that look similar, providing coverage for cold-start items.
3.  **User Representation ($U$):** We employ **Importance-Based Aggregation** (Cite Lesson 12). Instead of arbitrarily truncating history to the last $N$ chronological events, we aggregate all user transactions within the window, sum their time-decayed weights, and select the top components.
4.  **Score Aggregation:** The retrieval score is computed as a linear combination:
    $$S = U \cdot T_{seq} + \lambda_{vis} (U \cdot T_{vis}) + \alpha U_{history}$$
    The repurchase weight $\alpha$ is kept low (~1.5) to prevent historical bias from overpowering new trends (Cite Lesson 11).
5.  **Output:** We extract the **Top-100 candidates** per user (Cite Lesson 15) to ensure the subsequent ranker has a sufficient pool of relevant items to sort.

### Stage 2: Signal-Preserving Calibration (High Precision)
A **LightGBM** model trained with a ranking objective (`lambdarank`) sorts the 100 candidates.
*   **Signal Preservation:** To prevent **Signal Destruction** (Cite Lesson 10), we explicitly feed the **Decomposed Raw Scores** ($S_{seq}$, $S_{vis}$, $S_{hist}$) and their **Ranks** from Stage 1 as primary features. This forces the ranker to use the strong sequential signal as a baseline and only re-order based on secondary contexts.
*   **Visual Consistency:** We compute the cosine distance between the candidate item's embedding and the **centroid of the user's recent purchase history**.
*   **Context Features:** User Age, Global Item Popularity, and Days Since Last Interaction.

# Data

1.  **Visual Graph Construction:**
    *   Pass all article images through a pre-trained CNN (e.g., `resnet18`) to generate dense embeddings.
    *   Compute the Top-20 nearest neighbors for each item via Cosine Similarity and store as a sparse matrix $T_{vis}$.

2.  **Ranker Dataset (Sliding Window Strategy):**
    *   To solve the overfitting problem observed in previous ideas, we employ a **Sliding Window** strategy for training data generation.
    *   We create multiple (History $\to$ Target) splits:
        *   Split A: Train on Weeks 1-10 $\to$ Target Week 11.
        *   Split B: Train on Weeks 2-11 $\to$ Target Week 12.
    *   **Labeling:** Positive (1) if purchased in the Target Week, Negative (0) if retrieved but not purchased.
    *   This increases the volume of training data and forces the model to learn temporal dynamics rather than memorizing static item popularity.

# Training

1.  **Retrieval (Deterministic):**
    *   Construct $T_{seq}$ and $T_{vis}$ using `scipy.sparse`. No gradient descent is required.

2.  **Ranking (Supervised):**
    *   Train the LightGBM model using the `lambdarank` objective (optimizing NDCG).
    *   Train on the combined dataset from the Sliding Windows (Splits A & B).
    *   Use a final hold-out set (e.g., a subset of Week 12 users) for Early Stopping.

# Evaluation

1.  **Sparse Inference:**
    *   Construct the sparse user vectors $U$ for all test customers.
    *   Perform the sparse matrix operation: $S = U \cdot T_{seq} + \lambda_{vis} (U \cdot T_{vis}) + \alpha U_{history}$.
    *   **Optimization:** Use **Direct CSR Array Access** (Cite Lesson 16) to efficiently extract the indices of the Top-100 items, strictly avoiding dense matrix materialization (Cite Lesson 7).

2.  **Scoring & Submission:**
    *   Compute the feature vectors for these 100 candidates.
    *   Score them using the trained LightGBM model.
    *   Select the Top-12 items with the highest predicted scores for the final submission.
