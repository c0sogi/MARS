The OOM error during student training with AWP is caused by the `distill_loader` (used for soft targets) defaulting to the larger `valid_batch_size` (8) because it uses the "test" split. In the student training loop, the model processes a labeled batch (size 4) and a distillation batch (size 8) simultaneously, resulting in an effective batch size of 12. Combined with the memory overhead of Adversarial Weight Perturbation (AWP), this exceeds the GPU's capacity.

To fix this, I will:
1.  Modify `get_dataloader` in `library/data.py` to accept an optional `batch_size` argument, allowing manual overrides.
2.  Update `runfile.py` to explicitly set the `distill_loader`'s batch size to `config.train_batch_size` (4).

This ensures the total effective batch size per step is reduced from 12 to 8 (4 labeled + 4 distilled), fitting within memory constraints. This applies **Cite debug_lesson_7** (Account for Auxiliary DataLoader Batch Sizes) and **Cite debug_lesson_5** (Reduce Micro-Batch Size to Accommodate AWP Memory Spikes).
