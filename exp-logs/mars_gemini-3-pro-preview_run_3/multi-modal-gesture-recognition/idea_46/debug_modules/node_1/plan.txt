The issue is that the cached datasets are stored as NumPy object arrays (to handle variable-length sequences), and when loaded using `np.load`, the individual arrays retain the `object` data type or are wrapped in a way that PyTorch's `torch.from_numpy` cannot handle. As noted in `debug_lesson_15`, deserialized object arrays must be explicitly cast to native numeric types before being passed to PyTorch. I will modify `library/data_loader.py` to iterate through the loaded features and labels and explicitly cast them to `np.float32` and `np.int64` respectively.
