The issue lies in `runfile.py` where the validation loop incorrectly calls `compute_levenshtein` (designed for a batch of sequences) on individual sequences (`pred_seq`, `target_seq`). When `pred_seq` is empty (e.g., due to model convergence issues predicting only background), `compute_levenshtein` treats the inputs as empty batches and returns 0.0, leading to a false perfect score. The fix is to import and use `levenshtein_distance` directly, which correctly computes the edit distance between two specific sequences.
