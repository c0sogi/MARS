# Proposed Solution: Dual-Stream Dynamic-Static Network with Bottleneck Refinement

To address the challenge of continuous multi-modal gesture recognition, I propose a **Dual-Stream Dynamic-Static Network with Bottleneck Refinement**. This architecture synthesizes the strong baseline performance of Recurrent Neural Networks (Cite solution_lesson_node_00002) with the specific feature engineering insights regarding motion derivatives (Cite solution_lesson_node_00005) and the structural necessity of information bottlenecks in multi-stage networks (Cite solution_lesson_node_00020).

### Model
The architecture consists of a **Dual-Stream Encoder** followed by a **Bottleneck Refinement Module**.

1.  **Dual-Stream Encoder (Stage 1):**
    *   Instead of a single monolithic input vector, the input is split into two semantically distinct streams to allow the model to learn specialized representations for "pose" and "motion."
    *   **Static Stream:** Takes **Normalized Skeleton Positions** and **Audio MFCCs** as input. It uses a **Bi-directional GRU** to capture the spatial configuration of the user and acoustic cues over time.
    *   **Dynamic Stream:** Takes **Skeleton Velocities** (1st derivative) and **Accelerations** (2nd derivative) as input. It uses a parallel **Bi-directional GRU** to explicitly model the dynamics, speed, and impulse of the gestures, leveraging the finding that explicit derivatives significantly boost performance (Cite solution_lesson_node_00005).
    *   **Fusion & Projection:** The hidden states from both streams are concatenated and passed through a dense layer with a Softmax activation to produce **Initial Class Probabilities** (21 classes) for each frame.

2.  **Bottleneck Refinement Module (Stage 2):**
    *   This module is a **Dilated Temporal Convolutional Network (TCN)**.
    *   **Strict Information Bottleneck:** Crucially, this stage takes **only** the 21-dimensional **Initial Class Probabilities** from Stage 1 as input. It does *not* receive the high-dimensional latent features. This design choice prevents the overfitting observed when dense features were forwarded (Cite solution_lesson_node_00020) and forces the TCN to focus solely on learning temporal consistency and error correction (e.g., smoothing jitter, filling gaps).

### Data
The data processing pipeline is calibrated to the temporal characteristics of the dataset.

1.  **Feature Engineering:**
    *   **Skeleton:** Compute 3D **Velocity** ($V_t = P_t - P_{t-1}$) and **Acceleration** ($A_t = V_t - V_{t-1}$) for all joints. Normalize positions relative to a root joint.
    *   **Audio:** Extract MFCCs and synchronize them to the video frame rate.
2.  **Windowing Strategy:**
    *   Generate training samples using a **Sliding Window of 64 frames** (approx. 3.2 seconds). This size is selected to match the average atomic duration of the gestures (~45 frames), ensuring the model learns complete gesture dynamics without being overwhelmed by background noise, as observed when using larger windows (Cite solution_lesson_node_00017).

### Training
The training strategy prioritizes stability and smoothness.

1.  **Loss Function:**
    *   **Weighted Cross-Entropy:** Applied to the outputs of both Stage 1 (Fusion) and Stage 2 (Refinement). A weight of **0.2** is assigned to the background class to counteract its dominance (Cite solution_lesson_node_00010).
    *   **Log-Space Smoothing Loss:** A Truncated Mean Squared Error (MSE) loss is applied to the log-probabilities of adjacent frames in the Stage 2 output. This explicitly penalizes high-frequency prediction changes ("jitter"), enforcing the temporal continuity required by the Levenshtein metric (Cite solution_lesson_node_00015).
2.  **Optimizer:** The model is trained end-to-end using the **Adam** optimizer.

### Evaluation
1.  **Inference:** Full test sequences (or stitched overlapping windows) are processed by the network.
2.  **Prediction:** The final predictions are derived from the output of the **Refinement Module (Stage 2)**.
3.  **Decoding:**
    *   Apply `argmax` to the refined probabilities to obtain frame-wise labels.
    *   Perform **Run-Length Encoding (RLE)** to collapse consecutive identical labels into single gesture instances.
    *   Remove the "background" class and any segments shorter than a minimal threshold (e.g., 5 frames) to generate the final ordered list of gesture IDs.
