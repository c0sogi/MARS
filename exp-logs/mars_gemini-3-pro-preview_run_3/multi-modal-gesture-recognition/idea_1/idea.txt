To address the task of multi-modal gesture recognition with a focus on simplicity, speed, and establishing a reliable baseline, I propose a **Frame-wise Bi-directional Recurrent Neural Network (RNN)**.

This approach differs fundamentally from the provided architectures: it avoids the manual feature engineering of Model 2, the probabilistic generative assumptions of Model 3 (HMM), the graph-based complexity of Model 4 (ST-GCN), and the convolutional/attention mechanisms of Model 5. Instead, it leverages the standard recurrent modeling capability of GRUs to learn temporal dependencies directly from low-level vector sequences.

### Model
The architecture is a lightweight **Bi-directional Gated Recurrent Unit (Bi-GRU) Network**.
*   **Input Layer:** A dense projection layer that maps the concatenated multi-modal feature vector (Skeleton + Audio) for a single frame into a hidden representation.
*   **Recurrent Layers:** Two stacked layers of Bi-directional GRUs. The bi-directional nature allows the model to capture context from both the past (onset of a gesture) and the future (completion of a gesture) for every frame, which is crucial for distinguishing gestures with similar starting motions.
*   **Classification Head:** A final fully connected layer followed by a Softmax activation. It outputs a probability distribution over **21 classes** (20 gesture categories + 1 "background/null" class) for every individual frame in the sequence.

### Data
The preprocessing pipeline focuses on creating efficient, low-dimensional feature streams and dense frame-wise labels.

1.  **Skeleton Normalization:**
    *   Extract the 3D `WorldPosition` coordinates for all joints from the `.mat` files.
    *   Perform **Root-Relative Normalization**: For each frame, subtract the coordinates of a central joint (e.g., `HipCenter` or `Spine`) from all other joints. This makes the features invariant to the user's global position in the room.
    *   Flatten the normalized coordinates into a single vector per frame (e.g., 20 joints $\times$ 3 dimensions = 60 features). Handle missing skeleton data by forward-filling valid values or zero-masking.

2.  **Audio Features:**
    *   Extract **MFCCs** (Mel-frequency cepstral coefficients) from the audio stream.
    *   Resample or interpolate the MFCC vectors to align perfectly with the video frame rate (e.g., 20 fps), ensuring a one-to-one correspondence between skeleton frames and audio features.

3.  **Label Generation:**
    *   Convert the sparse event-based annotations (Start Frame, End Frame, Label ID) into a **dense frame-wise label array**.
    *   Assign the specific Gesture ID (1-20) to all frames falling within a labeled segment.
    *   Assign the Background ID (0) to all frames outside these segments.

### Training
The training process treats the problem as a sequence labeling task.

*   **Loss Function:** Use **Weighted Cross-Entropy Loss**. Since "background" frames significantly outnumber gesture frames, apply a lower weight to class 0 or higher weights to classes 1-20 to prevent the model from biasing towards predicting "background" everywhere.
*   **Optimizer:** Use the **Adam** optimizer for fast convergence.
*   **Strategy:**
    *   Train on fixed-length sliding windows (e.g., 64 or 128 frames) sampled from the continuous training sessions to allow for efficient batching.
    *   Ensure windows overlap or are sampled such that the model learns transitions between background and gestures.

### Evaluation
Inference is performed on the continuous, unsegmented test sequences.

1.  **Forward Pass:** Feed the full sequence of preprocessed features (Skeleton + Audio) for a test session into the trained Bi-GRU to obtain frame-by-frame probability vectors.
2.  **Prediction:** Apply `argmax` to select the most likely class for each frame.
3.  **Post-Processing (Decoding):**
    *   **Smoothing:** Apply a median filter (e.g., kernel size 5 or 7) to the sequence of predicted labels to remove high-frequency noise (single-frame glitches).
    *   **deduplication:** Collapse consecutive identical labels into a single instance (e.g., `0, 0, 1, 1, 1, 0, 2, 2` $\rightarrow$ `0, 1, 0, 2`).
    *   **Filtering:** Remove the "background" class (0) and any gesture instances that are unrealistically short (e.g., lasting less than 5-10 frames).
    *   **Output:** The remaining ordered list of Gesture IDs forms the final prediction for the session.
