The implementation strategy is as follows:

1.  **Configuration & Setup**: Initialize the `Config` class. To ensure the process completes comfortably within the 2-hour limit while maintaining high performance, I will slightly adjust the number of epochs to 15. I will also ensure the output directory for the submission (`./submission`) exists.
2.  **Training**: Execute the training pipeline using `library.trainer.run_training`. This handles data loading (with caching), model initialization (ConvNeXt-Nano), and the training loop with Mixup and OneCycleLR. It saves the best model checkpoint based on validation LWLRAP.
3.  **Validation & Metrics**:
    *   Reload the best model from the checkpoint.
    *   Run inference on the full validation set in `eval` mode.
    *   Compute and print the `Final Validation Metric` (LWLRAP).
4.  **Failure Analysis**:
    *   Compute the loss (Binary Cross Entropy) for each validation sample to quantify "error magnitude".
    *   Extract metadata features from the validation CSV, specifically the number of labels per clip (`num_labels`).
    *   Calculate and print the Pearson correlation between the error magnitude and `num_labels` to identify if complexity correlates with failure.
5.  **Submission**:
    *   Compare the final metric against the threshold (0.7117108825122853).
    *   If the threshold is met, load the test data, generate predictions, and format them according to `sample_submission.csv`.
    *   Save the result to `./submission/submission.csv`.
