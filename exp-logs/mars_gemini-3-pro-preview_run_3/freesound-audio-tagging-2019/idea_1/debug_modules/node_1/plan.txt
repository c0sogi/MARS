The issue is in the `calculate_lwlrap` function within `library/engine.py`. The current implementation computes the average precision across *all* classes, including those that are not present in the ground truth (i.e., classes with zero support). Since these absent classes have a score of 0, including them in the mean calculation incorrectly lowers the overall LWLRAP score. The correct behavior for "label-weighted" average precision is to average only over the classes that actually appear in the dataset (or batch). I will fix this by using the existing `mask` (which identifies classes with non-zero counts) to filter the per-class scores before calculating the mean.
