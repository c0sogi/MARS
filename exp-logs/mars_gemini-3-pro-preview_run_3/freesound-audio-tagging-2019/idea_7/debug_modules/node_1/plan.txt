The issue is a variable name shadowing bug in `library/model.py`. The module `torch.nn.functional` is imported globally as `F`. However, inside the `DualStreamPooling.forward` method, the variable `F` is repurposed to store the frequency dimension size when unpacking `x.shape` (`B, C, F, T = x.shape`). This overwrites the reference to the functional module with an integer, causing the subsequent call `F.adaptive_max_pool2d` to raise an `AttributeError`. The fix is to rename the local variable for the frequency dimension (e.g., to `Freq`) to preserve the global reference to the module.
