Based on the comprehensive analysis of the "Lessons Learned," specifically the critical distinction between **Translational Differentials** for interactions (Cite solution_lesson_node_00080) and **Rotational Differentials** for impacts (Cite solution_lesson_node_00068), I propose the **Differential-Physics Dual-Stream GBDT with Visual Consensus**.

This solution structurally evolves the previous "Dual-Stream" architectures by formalizing a **Divergent Differential Paradigm**. Instead of applying a uniform feature engineering logic, we implement two strictly distinct mathematical pipelines: **Stream A** utilizes **Finite-Difference Translational Metrics** (to capture spatial convergence without sensor noise amplification) combined with **Visual Consensus**, while **Stream B** utilizes **Finite-Difference Rotational Metrics** (to capture inertial shock without spatial overfitting).

# Model

The architecture consists of two specialized **XGBoost** classifiers (Cite solution_lesson_node_00016) operating on physically disentangled feature spaces.

1.  **Stream A: The Interaction Model (Translational Convergence)**
    *   **Scope:** Predicts contact between two players (`player2 != 'G'`).
    *   **Philosophy:** **Translational Physics & Visual Certainty**. Interactions are defined by the rate at which two bodies occupy the same space.
    *   **Backbone:** A **Conditional Early-Fusion GBDT** (Cite solution_lesson_node_00036).
    *   **Feature Strategy:** Fuses **Finite-Difference Relational Scalars** (for robust proximity detection), **System Energy** (for collision intensity), and **Visual Consensus Pyramids** (for view disambiguation).

2.  **Stream B: The Impact Model (Rotational Inertia)**
    *   **Scope:** Predicts contact between a player and the ground (`player2 == 'G'`).
    *   **Philosophy:** **Rotational Physics & Strict Invariance**. Ground impacts are defined by the sudden loss of control and inertial shock relative to the body frame.
    *   **Backbone:** A **Uni-Modal Invariant GBDT**.
    *   **Feature Strategy:** Utilizes **Finite-Difference Ego-Dynamics** (Surge/Sway Jerk) derived from projected velocity. Explicitly rejects absolute coordinates and visual features (Cite solution_lesson_node_00075, solution_lesson_node_00034).

# Data

**Preprocessing:**
*   **Pipeline Integrity:** Implement **hash-based cache invalidation** derived from the full feature configuration (Cite solution_lesson_node_00004).
*   **Validation Mapping:** Explicitly map the `validation` mode to read from `train_player_tracking.csv` to ensure correct data loading (Cite solution_lesson_node_00054).

**Feature Engineering - Stream A (Interaction):**
1.  **Translational Differentials (The Correction):**
    *   Calculate **Closure Rate** using the **Finite Difference of Euclidean Distance**: $-(d_t - d_{t-1}) / \Delta t$.
    *   **Rationale:** This strictly replaces the "Vector Projection" method from Idea 23, which introduced sensor noise and degraded performance (Cite solution_lesson_node_00080).
    *   Include **Euclidean Distance** and **Relative Speed** (Scalar).
2.  **System Energy:** Flattened Exponential Pyramids ($t, t\pm1... t\pm15$) of **Absolute Speed** and **Scalar Acceleration** for both players (Cite solution_lesson_node_00075).
3.  **Visual Consensus Pyramids:**
    *   Calculate `Sideline_IoU` and `Endzone_IoU` at sparse lags ($t, t\pm4, t\pm8, t\pm15$).
    *   Compute **Consensus Metrics**: `Max_IoU`, `Min_IoU`, and `IoU_Diff` (`|Sideline - Endzone|`) to quantify visual uncertainty (Cite solution_lesson_node_00074).
    *   **Visual Looming:** Calculate the finite difference of `Max_IoU` ($\Delta \text{IoU} / \Delta t$) to capture the *rate* of visual convergence (Extension of Cite solution_lesson_node_00044).
    *   **Imputation:** Use **Left Join + Sentinel** (`-999`) (Cite solution_lesson_node_00036).

**Feature Engineering - Stream B (Impact):**
1.  **Rotational Differentials (The Innovation):**
    *   **Step 1:** Project Velocity ($v$) onto Orientation ($\hat{o}$) $\rightarrow$ $v_{surge}, v_{sway}$.
    *   **Step 2:** Differentiate $v_{surge/sway}$ $\rightarrow$ **Ego-Acceleration**.
    *   **Step 3:** Differentiate Ego-Acceleration $\rightarrow$ **Ego-Jerk**.
    *   **Rationale:** Differentiating the projected velocity captures rotational Coriolis terms that projecting the global acceleration misses (Cite solution_lesson_node_00068).
2.  **Invariant Baseline:** Include **Scalar Speed** and **Scalar Acceleration** (Cite solution_lesson_node_00055).
3.  **Strict Invariance:** Explicitly **exclude** `x`, `y`, `direction`, `orientation`, and all visual features (Cite solution_lesson_node_00075).

# Training

*   **Sampling:** Apply **Targeted Majority Undersampling**. Retain **100%** of the positive class and randomly subsample the negative class to a 10:1 ratio (Cite solution_lesson_node_00060).
*   **Algorithm:** Train both streams using **XGBoost** with the `gpu_hist` tree method (Cite solution_lesson_node_00016).
*   **Asymmetric Regularization:**
    *   **Stream A:** Standard depth (`max_depth=6`) to model the complex interaction between energy, geometry, and visual consensus.
    *   **Stream B:** **Shallow Depth** (`max_depth=6` to `8`) to prevent overfitting sensor noise, relying on the robust `Ego-Jerk` signal (Cite solution_lesson_node_00070).
*   **Objective:** Minimize **Binary Logistic Loss**.

# Evaluation

1.  **Inference:**
    *   Route test samples to Stream A or Stream B based on the `contact_id`.
    *   Stream A receives the "Translational + Visual Consensus" vector. Stream B receives the "Rotational + Invariant" vector.
2.  **Optimization:**
    *   **Thresholding:** Decouple the decision boundary from the probability. Perform a linear search on the Validation set to find the optimal probability threshold **independently for each stream** that maximizes the Matthews Correlation Coefficient (MCC) (Cite solution_lesson_node_00002, solution_lesson_node_00025).
    *   **Submission:** Apply these specific thresholds to the Test set predictions.
