The issue stems from incorrect operator precedence in the list comprehensions used to select feature columns in `library/feature_builder.py`. Specifically, the `and` operator binds tighter than `or`, causing the suffix check (`c.endswith("_p1")`) to apply only to the first condition (`"position" in c`), while subsequent conditions (e.g., `"speed" in c`) are evaluated independently. This results in columns from Player 2 being incorrectly included in Player 1's list (and vice versa), creating duplicate column names in the final feature set which causes the Parquet save operation to fail.

To fix this, I will wrap the multiple `or` conditions in parentheses to ensure they are evaluated as a single group against the suffix check. This ensures that a column is selected only if it *both* ends with the correct suffix *and* matches one of the feature keywords. This aligns with **Cite debug_lesson_10** regarding precise column selection to avoid schema collisions.
