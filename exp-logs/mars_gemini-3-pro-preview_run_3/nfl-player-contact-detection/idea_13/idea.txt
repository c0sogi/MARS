Based on the comprehensive analysis of the "Lessons Learned," specifically the proven superiority of **Gradient Boosted Trees** on flattened windows (Cite solution_lesson_node_00016), the critical need for **Asymmetric Modality Selection** (Cite solution_lesson_node_00034), and the specific failure of "Dense/Smoothed" visual features (Cite solution_lesson_node_00041), I propose the **Asymmetric Dual-Stream GBDT with Multi-Modal Exponential Temporal Pyramids**.

This solution structurally evolves the previous "Robust Asymmetric" approach (Idea 11) by applying the **Exponential Lag Strategy** (Cite solution_lesson_node_00042) to the **Visual Modality**. While previous successful iterations applied sparse lags only to tracking data, this solution extends that temporal logic to the helmet geometry, allowing the model to capture "Visual Trajectory" (e.g., looming) without the signal degradation caused by smoothing or dense sampling.

# Model

The architecture consists of two specialized **XGBoost** classifiers operating on distinct, physically-informed feature spaces.

1.  **Stream A: Interaction Model (Player-Player)**
    *   **Scope:** Predicts contact between two players (`player2 != 'G'`).
    *   **Architecture:** A **Conditional Early-Fusion GBDT**.
    *   **Structural Innovation:** The model ingests a **Multi-Modal Exponential Temporal Pyramid**. Instead of using only instantaneous visual geometry (IoU at $t=0$), it flattens visual features across exponentially spaced temporal lags (e.g., $t, t\pm4, t\pm8, t\pm15$). This allows the tree to learn non-linear temporal patterns in the visual domain (e.g., "IoU increasing from $t-8$ to $t$") without the noise amplification of explicit derivative calculation (Cite solution_lesson_node_00034) or the blurring effect of rolling averages (Cite solution_lesson_node_00041).

2.  **Stream B: Impact Model (Player-Ground)**
    *   **Scope:** Predicts contact between a player and the ground (`player2 == 'G'`).
    *   **Architecture:** A **Uni-Modal Kinematic GBDT**.
    *   **Constraint:** Explicitly **blocks** all visual features to prevent noise injection (Cite solution_lesson_node_00034).
    *   **Focus:** Relies on high-fidelity sensor kinematics to detect force transients (Jerk) and loss of control (Pose-Motion Alignment).

# Data

**Preprocessing:**
*   **Pipeline Integrity:** Implement **hash-based cache invalidation** derived from the full feature configuration to ensure data consistency (Cite solution_lesson_node_00004).
*   **Deterministic Ordering:** Use hardcoded whitelists to strictly define feature order (Cite solution_lesson_node_00008).

**Feature Engineering - Stream A (Tracking + Lagged Visuals):**
1.  **Primary Modality (Tracking):**
    *   **Exponential Temporal Pyramid:** Flatten features at sparse, exponentially spaced lags: $t, t\pm1, t\pm2, t\pm4, t\pm8, t\pm15$. This captures both instantaneous mechanics (Micro) and long-term trajectory context (Macro) efficiently (Cite solution_lesson_node_00042).
    *   **Interaction Features:** Relative Speed, Closure Rate (Cite solution_lesson_node_00006), and Cyclical Angle Encoding (Cite solution_lesson_node_00005).
2.  **Secondary Modality (Visual Geometry):**
    *   **Exponential Visual Lags:** Flatten **Sideline** and **Endzone** IoU and Centroid Distance at sparse lags: $t, t\pm4, t\pm8, t\pm15$. This provides the "Visual Context" required to distinguish incidental overlap from sustained collision courses (Cite solution_lesson_node_00041).
    *   **Robust Imputation:** Perform a **Left Join** of the Helmet data onto the Tracking data. Fill missing visual records (due to detection failures) with a sentinel value (e.g., -999) to prevent data loss (Cite solution_lesson_node_00036).

**Feature Engineering - Stream B (Tracking Only):**
1.  **Kinematics:** Flattened Exponential Pyramid ($t, t\pm1... t\pm15$) of Position, Velocity, and Acceleration.
2.  **Physics Derivatives:** Explicitly include **Jerk** (derivative of acceleration) and **Pose-Motion Alignment** (dot product of orientation and velocity) to detect tumbling and sudden stops (Cite solution_lesson_node_00027).
3.  **Exclusion:** Remove all visual features and "Player 2" relative features.

# Training

*   **Sampling:** Apply **Random Undersampling** with a 10:1 negative-to-positive ratio independently to each stream (Cite solution_lesson_node_00005).
*   **Algorithm:** Train both streams using **XGBoost** with the `gpu_hist` tree method. This backbone is selected for its superior performance on flattened tabular windows (Cite solution_lesson_node_00016) and native ability to handle sentinel values.
*   **Objective:** Minimize **Binary Logistic Loss**.
*   **Validation:** Use GroupShuffleSplit by `game_play`.

# Evaluation

1.  **Inference:**
    *   Route test samples to Stream A or Stream B based on the `contact_id`.
    *   Stream A receives the fused vector (Tracking + Lagged Visuals). Stream B receives the pure Tracking vector.
2.  **Optimization:**
    *   **Thresholding:** Decouple the decision boundary from the probability. Perform a linear search on the Validation set to find the optimal probability threshold **independently for each stream** that maximizes the Matthews Correlation Coefficient (MCC) (Cite solution_lesson_node_00002, solution_lesson_node_00025).
    *   **Submission:** Apply these specific thresholds to the Test set predictions.
