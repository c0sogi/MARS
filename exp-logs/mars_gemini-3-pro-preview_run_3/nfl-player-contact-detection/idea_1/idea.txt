To establish a highly efficient baseline for predicting player contact, I propose a **Time-Windowed Multi-Layer Perceptron (MLP)**. This approach prioritizes computational speed and architectural simplicity by relying exclusively on low-dimensional tracking data, ignoring the resource-intensive video data.

### Model
The architecture is a standard Feedforward Neural Network (MLP) designed to process a flattened vector of kinematic features over a small temporal window.
*   **Input Layer:** Accepts a flattened feature vector representing the state of the player pair over a window of $T$ timesteps (e.g., $t-2$ to $t+2$). This synthesizes the feature engineering approach of **Model 1** with the temporal context window of **Model 5**, but avoids the complexity of Recurrent or Graph layers.
*   **Hidden Layers:** Two or three dense (fully connected) layers with ReLU activation and Batch Normalization to allow for fast convergence.
*   **Output Layer:** A single neuron with a Sigmoid activation function to output the probability of contact.
*   **Ground Handling:** To handle "Ground" contacts (where Player 2 is 'G'), the model includes a binary flag feature (`is_ground`). When this flag is active, Player 2's tracking features are imputed as zeros, allowing the network to learn specific motion patterns (like sudden deceleration) associated with hitting the ground.

### Data
1.  **Preprocessing:**
    *   **Merge & Align:** Join the `train_labels.csv` with `train_player_tracking.csv` based on `game_play`, `step`, and `nfl_player_id`. Perform this twice to get features for both Player 1 and Player 2.
    *   **Feature Engineering:** Calculate relative features: Euclidean distance between P1 and P2, relative speed, and relative orientation. For Ground contacts, set distance and P2 features to 0.
    *   **Windowing:** For every target timestep $t$, concatenate the feature vectors from $[t-2, t-1, t, t+1, t+2]$ into a single 1D array. This captures the immediate trajectory and impact dynamics.
    *   **Normalization:** Apply standard scaling (mean 0, variance 1) to all continuous input features.

2.  **Sampling Strategy:**
    *   Given the extreme class imbalance (approx. 1:75), apply **Random Undersampling** to the majority class (No Contact) during training. Reduce the negative-to-positive ratio to approximately 10:1 or 5:1 to ensure the model learns the minority class effectively without processing millions of empty frames.

### Training
*   **Loss Function:** Use **Binary Cross-Entropy Loss**. To further address imbalance, apply a weighted loss where positive samples are weighted higher (inverse to their frequency in the sampled batch).
*   **Optimizer:** Use **Adam** or **AdamW** for efficient gradient descent with default learning rates.
*   **Validation:** Monitor the Matthews Correlation Coefficient (MCC) on the validation split (from metadata) to trigger Early Stopping if performance plateaus, preventing overfitting.

### Evaluation
1.  **Inference:** Process the test set using the same feature engineering and windowing pipeline. Do not undersample the test data.
2.  **Threshold Optimization:** Instead of a default 0.5 threshold, calculate the optimal probability threshold that maximizes the MCC score on the validation set.
3.  **Submission:** Apply this optimized threshold to the test predictions to generate the final binary `contact` labels and format them according to `sample_submission.csv`.
