The implementation strategy follows a structured pipeline designed for efficiency and reproducibility. 
1.  **Initialization**: We import the necessary components from the provided library files (`data_loader`, `model`, `utils`, `config`) and set the random seed to ensure consistent results.
2.  **Data Preparation**: The `NFLDataLoader` is used to load training and validation data. This class handles the complex feature engineering (flattened temporal windows), stream splitting (Player-Player vs. Player-Ground), and caching mechanisms to speed up subsequent runs.
3.  **Model Training**: We instantiate the `DualStreamXGB` model, which internally manages two separate XGBoost classifiers (one for each stream) utilizing GPU acceleration. The model is trained on the prepared streams with early stopping enabled to prevent overfitting and reduce runtime.
4.  **Optimization & Evaluation**: We optimize the probability thresholds for each stream independently on the validation set to maximize the Matthews Correlation Coefficient (MCC). The final validation MCC is then recalculated and printed in the required format.
5.  **Failure Analysis**: We perform a correlation analysis between the model's prediction errors on the validation set and the input features. This helps identify which kinematic variables (e.g., speed, distance) are most associated with incorrect predictions.
6.  **Submission**: Finally, the script checks if the validation MCC exceeds the specified benchmark (0.637875144942081). If successful, it loads the test data, generates predictions, and saves the `submission.csv` file.
