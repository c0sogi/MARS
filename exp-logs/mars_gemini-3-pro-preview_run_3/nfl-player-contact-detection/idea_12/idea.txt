Based on the comprehensive analysis of the "Lessons Learned," specifically the critical failures regarding data integrity in multi-modal pipelines (Cite solution_lesson_node_00036) and the distinct feature requirements for interaction versus ground impact (Cite solution_lesson_node_00034), I propose the **Dual-Stream GBDT with Multi-Resolution Visual Geometry and Robust Imputation**.

This solution structurally evolves the previous "Early-Fusion" attempts by introducing **Multi-Resolution Visual Features** to mitigate bounding box jitter and employing a **Robust Left-Join Topology** to prevent data loss.

### Model
The architecture consists of two specialized **XGBoost** classifiers (Cite solution_lesson_node_00016) that operate on asymmetric feature spaces tailored to the physics of the specific contact type (Cite solution_lesson_node_00025).

1.  **Stream A: Interaction Model (Player-Player)**
    *   **Scope:** Predicts contact between two players (`player2 != 'G'`).
    *   **Architecture:** A **Conditional Early-Fusion GBDT**.
    *   **Innovation:** Unlike previous iterations that used instantaneous visual features, this model utilizes **Multi-Resolution Visual Geometry**. It ingests both instantaneous Helmet IoU (Intersection over Union) and **Aggregated Visual Statistics** (e.g., Rolling Max IoU) over the temporal window. This allows the model to detect contact even if helmet detection "blinks" or jitters in a single frame, effectively smoothing the noisy visual signal (Extension of Cite solution_lesson_node_00031).

2.  **Stream B: Impact Model (Player-Ground)**
    *   **Scope:** Predicts contact between a player and the ground (`player2 == 'G'`).
    *   **Architecture:** A **Uni-Modal Kinematic GBDT**.
    *   **Constraint:** Explicitly **blocks** all visual features.
    *   **Rationale:** Ground impact is defined by force transients (Jerk) and loss of control. Visual bounding box derivatives introduce excessive noise (Cite solution_lesson_node_00034). This stream relies exclusively on high-fidelity sensor kinematics.

### Data
**Preprocessing:**
*   **Pipeline Integrity:** Implement **hash-based cache invalidation** derived from the full feature configuration to ensure that any logic changes automatically trigger data regeneration (Cite solution_lesson_node_00004).
*   **Deterministic Ordering:** Use hardcoded whitelists to strictly define feature order (Cite solution_lesson_node_00008).

**Feature Engineering - Stream A (Tracking + Robust Visuals):**
1.  **Primary Modality (Tracking):**
    *   **Multi-Resolution Windows:** Flattened Micro ($t \pm 4$) and Macro ($t \pm 15$) windows to capture both instantaneous mechanics and trajectory context (Cite solution_lesson_node_00031).
    *   **Interaction Features:** Relative Speed, Closure Rate (Cite solution_lesson_node_00006), and Cyclical Angle Encoding (Cite solution_lesson_node_00005).
2.  **Secondary Modality (Visual Geometry):**
    *   **View-Specific Flattening:** Flatten **Sideline** and **Endzone** features separately (e.g., `Sideline_IoU`, `Endzone_IoU`) to allow the tree to learn view reliability based on field position (Cite solution_lesson_node_00016).
    *   **Multi-Resolution Aggregation:** Calculate **Rolling Max** and **Rolling Mean** of the IoU and Centroid Distance over the Micro window ($t \pm 4$). This bridges gaps caused by imperfect helmet tracking.
    *   **Robust Imputation:** Perform a **Left Join** of the Helmet data onto the Tracking data. Fill any resulting `NaN` values (where helmet detection failed) with a distinct sentinel value (e.g., -999). This ensures the row count matches the tracking dataset exactly, preventing "silent data loss" (Cite solution_lesson_node_00036).

**Feature Engineering - Stream B (Tracking Only):**
1.  **Kinematics:** Flattened Micro/Macro windows of Position, Velocity, and Acceleration.
2.  **Physics Derivatives:** Explicitly include **Jerk** (derivative of acceleration) and **Pose-Motion Alignment** (dot product of orientation and velocity) to detect tumbling and sudden stops (Cite solution_lesson_node_00027).
3.  **Exclusion:** Remove all visual features and "Player 2" relative features to prevent noise injection.

### Training
*   **Sampling:** Apply **Random Undersampling** with a 10:1 negative-to-positive ratio independently to each stream. This balances training efficiency with sufficient negative exposure (Cite solution_lesson_node_00005).
*   **Algorithm:** Train both streams using **XGBoost** with the `gpu_hist` tree method. This backbone is selected for its superior performance on flattened tabular windows (Cite solution_lesson_node_00016) and native ability to handle missing/sentinel values.
*   **Objective:** Minimize **Binary Logistic Loss**.
*   **Validation:** Use GroupShuffleSplit by `game_play` to ensure no data leakage.

### Evaluation
1.  **Inference:**
    *   Route test samples to Stream A or Stream B based on the `contact_id`.
    *   Stream A receives the fused vector (with imputed missing visuals). Stream B receives the pure tracking vector.
2.  **Optimization:**
    *   **Thresholding:** Decouple the decision boundary from the probability. Perform a linear search on the Validation set to find the optimal probability threshold **independently for each stream** that maximizes the Matthews Correlation Coefficient (MCC) (Cite solution_lesson_node_00002, solution_lesson_node_00025).
    *   **Submission:** Apply these specific thresholds to the Test set predictions to generate the final binary labels.
