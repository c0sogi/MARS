Based on the progression of empirical findings—specifically the success of **Ego-Centric Projections** for ground impacts (Cite solution_lesson_node_00057), the necessity of **Explicit Relational Features** for interactions (Cite solution_lesson_node_00051), and the critical need to **Augment rather than Replace** raw data (Cite solution_lesson_node_00055)—I propose the **Biomechanical Dual-Stream GBDT with Hybrid Relational Projections**.

This solution structurally evolves the previous "Hybrid Coordinate" approach (Idea 17) by extending the biomechanical coordinate transformation logic to the **Interaction Stream (Stream A)**. While previous iterations applied ego-centric physics only to single-player ground impacts, this strategy introduces **Ego-Centric Relational Kinematics**, explicitly modeling the *angle of attack* (e.g., blindside vs. frontal) between players, which is a critical determinant of contact probability.

# Model

The architecture consists of two specialized **XGBoost** classifiers (Cite solution_lesson_node_00016) operating on asymmetric, physically-grounded feature spaces.

1.  **Stream A: Interaction Model (Player-Player)**
    *   **Scope:** Predicts contact between two players (`player2 != 'G'`).
    *   **Backbone:** A **Conditional Early-Fusion GBDT**.
    *   **Structural Innovation:** **Ego-Centric Relational Projection**.
    *   **Rationale:** Standard relational features (Relative Speed) capture *magnitude* but ignore *directionality* relative to the player's body. By projecting the **Relative Velocity Vector** ($V_{p2} - V_{p1}$) onto Player 1's orientation, the model can distinguish between **Relative Surge** (Closing speed along the spine/vision cone) and **Relative Sway** (Closing speed from the side/blindspot). This captures the biomechanics of evasion and impact (Cite solution_lesson_node_00057, solution_lesson_node_00051).

2.  **Stream B: Impact Model (Player-Ground)**
    *   **Scope:** Predicts contact between a player and the ground (`player2 == 'G'`).
    *   **Backbone:** A **Hybrid Kinematic GBDT**.
    *   **Input:** A concatenated vector of **Field-Centric Kinematics** (Anchor) and **Ego-Centric Self-Motion** (Augmentation).
    *   **Rationale:** Retains the "Hybrid" approach that successfully combined robust raw data with invariant physical signatures (e.g., Lateral Jerk) (Cite solution_lesson_node_00055).

# Data

**Preprocessing:**
*   **Pipeline Integrity:** Implement **hash-based cache invalidation** derived from the feature configuration (Cite solution_lesson_node_00004).
*   **Validation Logic:** Explicitly map the `validation` mode to read from `train_player_tracking.csv` to ensure correct data loading (Cite solution_lesson_node_00054).

**Feature Engineering - Stream A (Interaction):**
1.  **Field-Centric Relational (The Anchor):**
    *   **Exponential Temporal Pyramids:** Flatten features at sparse lags ($t, t\pm1, t\pm2, t\pm4, t\pm8, t\pm15$) (Cite solution_lesson_node_00042).
    *   Explicitly calculate Euclidean Distance and Scalar Relative Speed.
2.  **Ego-Centric Relational (The Innovation):**
    *   For every lag $\tau$, calculate the **Relative Velocity Vector**: $\vec{V}_{rel} = \vec{V}_{p2,\tau} - \vec{V}_{p1,\tau}$.
    *   Project $\vec{V}_{rel}$ onto Player 1's orientation unit vector ($\hat{o}$) and its orthogonal complement ($\hat{o}_{\perp}$).
    *   **Features:** **Relative Surge** ($\vec{V}_{rel} \cdot \hat{o}$) and **Relative Sway** ($\vec{V}_{rel} \cdot \hat{o}_{\perp}$).
3.  **Visual Geometry:**
    *   **Visual Temporal Pyramids:** Flatten Sideline and Endzone IoU/Distance at sparse lags ($t, t\pm4, t\pm8, t\pm15$) to capture looming trajectories (Cite solution_lesson_node_00044).
    *   **Robust Imputation:** Use **Left Join + Sentinel** (`-999`) to handle missing helmet detections without data loss (Cite solution_lesson_node_00036).

**Feature Engineering - Stream B (Impact):**
1.  **Field-Centric (The Anchor):** Flattened Exponential Pyramids of raw Position, Velocity, Acceleration, and Jerk.
2.  **Ego-Centric Self-Motion (The Augmentation):**
    *   Project Player 1's *own* Velocity, Acceleration, and Jerk vectors onto their orientation.
    *   **Features:** **Self-Surge** (Forward/Backward motion) and **Self-Sway** (Lateral motion).
    *   Explicitly include **Pose-Motion Alignment** (Cite solution_lesson_node_00027).
3.  **Exclusion:** Explicitly **block** all visual features (Cite solution_lesson_node_00034) and "Nearest Neighbor" context (Cite solution_lesson_node_00053).

# Training

*   **Algorithm:** Train both streams using **XGBoost** with the `gpu_hist` tree method (Cite solution_lesson_node_00016).
*   **Sampling:** Apply **Random Undersampling** with a 10:1 negative-to-positive ratio independently to each stream (Cite solution_lesson_node_00005).
*   **Regularization:** Do **not** apply aggressive depth constraints to Stream B. Allow the model sufficient capacity to learn the non-linear interactions between the Field-Centric and Ego-Centric features (Cite solution_lesson_node_00045).
*   **Objective:** Minimize **Binary Logistic Loss**.

# Evaluation

1.  **Inference:**
    *   Route test samples to Stream A or Stream B based on the `contact_id`.
    *   Stream A receives the Fused (Field-Relational + Ego-Relational + Visual) vector.
    *   Stream B receives the Hybrid (Field-Self + Ego-Self) vector.
2.  **Optimization:**
    *   **Thresholding:** Decouple the decision boundary from the probability. Perform a linear search on the Validation set to find the optimal probability threshold **independently for each stream** that maximizes the Matthews Correlation Coefficient (MCC) (Cite solution_lesson_node_00002, solution_lesson_node_00025).
    *   **Submission:** Apply these specific thresholds to the Test set predictions.
