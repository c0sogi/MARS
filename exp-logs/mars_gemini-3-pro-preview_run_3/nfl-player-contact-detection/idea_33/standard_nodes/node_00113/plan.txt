The implementation strategy involves the following steps:

1.  **Configuration Override**: To adhere to the time constraints and "fast baseline" requirement, we will dynamically modify the `Config` class attributes at runtime. We will reduce `n_estimators` for both XGBoost models to 100 and set the `UNDERSAMPLE_RATIO` to 1.0. This ensures the training process completes rapidly while still exercising the full pipeline.
2.  **Training Execution**: We will invoke `train_pipeline(load_cached_data=True)`. This function handles feature generation (utilizing caching where available), model training with the modified parameters, threshold optimization, and artifact saving.
3.  **Validation & Analysis**:
    *   We will explicitly load the validation dataset and the trained models/thresholds.
    *   We will generate predictions on the validation set to compute the final Matthews Correlation Coefficient (MCC).
    *   We will print the metric in the required format: `Final Validation Metric: <value>`.
    *   We will perform failure analysis by calculating the correlation between the absolute prediction error and the input features, printing the top contributors to model error.
4.  **Submission Logic**: We will check if the calculated validation MCC exceeds the threshold of 0.7008. If satisfied, we will execute `inference_pipeline(load_cached_data=True)` to generate the `submission.csv` file.
