Based on the comprehensive analysis of the "Lessons Learned," specifically the critical need for **Acausal (Future) Context** (Cite solution_lesson_node_00112), the superiority of **Dense Immediate Lags** for high-frequency events (Cite solution_lesson_node_00107), and the requirement for **Magnitude Alignment** in composite features (Cite solution_lesson_node_00105), I propose the **Bidirectional Hybrid-Context Dual-Stream GBDT with Scale-Aligned Consistency**.

This solution structurally evolves the previous architectures by correcting the "Causal-Only" and "Sparse-Lag" errors of Idea 32. It synthesizes the robust **Hybrid Context** paradigm (Cite solution_lesson_node_00091) with a **Dense Bidirectional Temporal Pyramid**, ensuring the model captures the full "Approach-Impact-Reaction" trajectory while maintaining physical consistency.

# Model

The architecture consists of two specialized **XGBoost** classifiers (Cite solution_lesson_node_00016) operating on physically disentangled feature spaces with asymmetric complexity constraints.

1.  **Stream A: The Interaction Model (Consistency & Energy)**
    *   **Scope:** Predicts contact between two players (`player2 != 'G'`).
    *   **Backbone:** A **Conditional Early-Fusion GBDT** (Cite solution_lesson_node_00036).
    *   **Structural Innovation:** **Scale-Aligned Cross-Modal Consistency**.
        *   Explicitly models the divergence between **Physical Closure Rate** (Tracking) and **Visual Looming Rate** (Video).
        *   **Correction:** Unlike Idea 32 (which used local Z-scores that destroyed magnitude info) or Idea 31 (which subtracted unscaled raw values), this model applies **Global Magnitude Matching**. It scales the `Closure_Rate` by a fixed heuristic factor (derived from global training statistics) to match the dynamic range of `IoU_Derivative` before subtraction. This preserves the absolute signal magnitude while enabling meaningful arithmetic combination (Cite solution_lesson_node_00105, solution_lesson_node_00107).
    *   **Feature Strategy:** Fuses **Relational Scalars**, **System Energy**, and **Visual Consensus** over a **Dense Bidirectional Window**.

2.  **Stream B: The Impact Model (Hybrid Context & Dynamics)**
    *   **Scope:** Predicts contact between a player and the ground (`player2 == 'G'`).
    *   **Backbone:** A **Uni-Modal Hybrid GBDT**.
    *   **Feature Strategy:** **Hybrid Context + Rotational Energy**.
        *   Combines **Field-Centric Anchors** (Raw Data) to capture environmental priors (Cite solution_lesson_node_00091) with **Finite-Difference Ego-Dynamics** (Invariant Physics) to capture the fall signature (Cite solution_lesson_node_00068).
        *   **Correction:** Utilizes a **Bidirectional Window** (Past + Future) to capture the "Reaction" phase (sudden stop/bounce) which is the strongest signal of impact (Cite solution_lesson_node_00112).

# Data

**Preprocessing:**
*   **Pipeline Integrity:**
    *   Implement **Configuration-Hashed Cache Invalidation** (Cite solution_lesson_node_00093).
    *   Enforce **Strict Schema Validation**; raise a `RuntimeError` if features are missing/zero-filled (Cite solution_lesson_node_00088).
    *   Explicitly map `validation` mode to `train_player_tracking.csv` (Cite solution_lesson_node_00054).

**Feature Engineering - Stream A (Interaction):**
1.  **Dense Bidirectional Pyramids:** Flatten features at lags $t \in \{0, \pm1, \pm2, \pm4, \pm8, \pm15\}$. The dense immediate lags ($\pm1, \pm2$) capture high-frequency contact mechanics, while sparse outer lags capture trajectory (Cite solution_lesson_node_00107, solution_lesson_node_00042).
2.  **Relational Primitives:** Calculate **Euclidean Distance** and **Closure Rate** (Finite Difference: $-\Delta d / \Delta t$) at each lag. Reject vector projections (Cite solution_lesson_node_00080).
3.  **Scale-Aligned Consistency:**
    *   Calculate `Raw_Closure_Rate` and `Visual_Looming_Rate` ($\Delta \text{Max\_IoU} / \Delta t$).
    *   Compute **Composite Feature**: `(Raw_Closure_Rate * Global_Scale_Factor) - Visual_Looming_Rate`.
    *   Include both the Composite Feature and the Raw components in the flattened vector.
4.  **Visual Consensus:** Flatten `Max_IoU`, `Min_IoU`, and `IoU_Diff` at sparse lags ($t, \pm4, \pm8, \pm15$) (Cite solution_lesson_node_00074).
5.  **System Energy:** Flattened pyramids of Absolute Speed and Scalar Acceleration (Cite solution_lesson_node_00075).

**Feature Engineering - Stream B (Impact):**
1.  **Hybrid Context:**
    *   **Field-Centric:** Flattened bidirectional pyramids of `x`, `y`, `speed`, `acceleration`, `direction`, `orientation` (Cite solution_lesson_node_00091).
    *   **Ego-Centric Dynamics:**
        *   Project Velocity $v$ onto Orientation $\hat{o}$ $\rightarrow$ $v_{surge}, v_{sway}$.
        *   Differentiate $v \rightarrow a \rightarrow j$ (Cite solution_lesson_node_00068).
        *   **Rotational Energy:** Calculate $E_{sway} = v_{sway}^2$ to distinguish cuts from tumbles.
    *   **Flattening:** Flatten these derived sequences over the full bidirectional window ($t \pm 15$) (Cite solution_lesson_node_00086, solution_lesson_node_00112).
2.  **Exclusion:** Block all visual features (Cite solution_lesson_node_00034).

# Training

*   **Sampling:** Apply **Targeted Majority Undersampling**. Retain **100%** of the positive class and randomly subsample the negative class to a 10:1 ratio (Cite solution_lesson_node_00060).
*   **Algorithm:** Train both streams using **XGBoost** with the `gpu_hist` tree method (Cite solution_lesson_node_00016).
*   **Asymmetric Regularization:**
    *   **Stream A:** **Standard Depth** (`max_depth=6`) to model complex cross-modal interactions.
    *   **Stream B:** **Shallow Depth** (`max_depth=6` to `8`) and **Conservative Learning Rate** (0.02). This prevents overfitting to sensor noise while capturing the robust Ego-Jerk signal (Cite solution_lesson_node_00070, solution_lesson_node_00045).
*   **Objective:** Minimize **Binary Logistic Loss**.

# Evaluation

1.  **Inference:**
    *   Route test samples to Stream A or Stream B based on the `contact_id`.
    *   Stream A receives the "Scale-Aligned Consistency + Energy" vector. Stream B receives the "Hybrid Context + Rotational Energy" vector.
2.  **Optimization:**
    *   **Thresholding:** Decouple the decision boundary from the probability. Perform a linear search on the Validation set to find the optimal probability threshold **independently for each stream** that maximizes the Matthews Correlation Coefficient (MCC) (Cite solution_lesson_node_00002, solution_lesson_node_00025).
    *   **Submission:** Apply these specific thresholds to the Test set predictions.
