Based on the progression of empirical findings—specifically the limitation of "Ego-Motion" features for ground impacts (Cite solution_lesson_node_00025), the failure of using cascaded model probabilities as proxies for physical context (Cite solution_lesson_node_00050), and the superiority of explicit relational features (Cite solution_lesson_node_00051)—I propose the **Context-Augmented Dual-Stream GBDT with Nearest-Neighbor Physics**.

This solution structurally evolves the "Stream B" (Player-Ground) architecture. Previous iterations treated Ground contact as an isolated "Single-Player" event, relying solely on the subject's internal kinematics (Jerk, Alignment). This ignores the physical reality that most ground impacts in football are caused by an external force (a tackle). This solution introduces a **Global Spatial Context** layer that explicitly engineers relational physics between the subject and their **Nearest Opponent**, providing the "Cause" (Tackle) to the "Effect" (Ground Contact) without relying on unreliable model cascades.

# Model

The architecture consists of two specialized **XGBoost** classifiers (Cite solution_lesson_node_00016) operating on physically distinct feature spaces.

1.  **Stream A: Interaction Model (Player-Player)**
    *   **Scope:** Predicts contact between two specific players defined in the `contact_id`.
    *   **Backbone:** The **Robust Asymmetric GBDT** established in previous successful iterations.
    *   **Input:** A fused vector of **Tracking Kinematics** and **Visual Geometry**.

2.  **Stream B: Context-Augmented Impact Model (Player-Ground)**
    *   **Scope:** Predicts contact between a player and the ground.
    *   **Structural Innovation:** Instead of a Uni-Modal Single-Player model, this is a **Relational Context Model**.
    *   **Input:**
        *   **Ego-Kinematics:** The subject player's motion derivatives (Jerk, Angular Velocity, Pose-Alignment) (Cite solution_lesson_node_00027).
        *   **Nearest-Neighbor Context:** Explicit relational features (Distance, Relative Speed, Relative Acceleration) calculated between the subject player and their **Nearest Opponent** on the field at time $t$.
    *   **Rationale:** This replaces the "Latent Probabilistic Context" of Idea 14 (which failed) with "Explicit Physical Context" (Cite solution_lesson_node_00050). It allows the tree to learn rules like: *"If P1 has high Jerk AND is within 0.5 yards of Nearest Opponent $\rightarrow$ Ground Contact (Tackle)."*

# Data

**Preprocessing:**
*   **Pipeline Integrity:** Maintain hash-based cache invalidation to ensure feature updates propagate (Cite solution_lesson_node_00004).
*   **Global Spatial Indexing (New Step):** Before generating features for specific `contact_id`s, process the entire `tracking` dataset frame-by-frame. For every player $P$ at step $t$, identify the opponent $O_{nearest}$ with the minimum Euclidean distance. Append $O_{nearest}$'s ID and attributes to $P$'s record.

**Feature Engineering - Stream A (Interaction):**
*   **Tracking:** Flattened **Exponential Temporal Pyramids** ($t, t\pm1, t\pm2, t\pm4, t\pm8, t\pm15$) to capture micro-mechanics and macro-trajectory (Cite solution_lesson_node_00042).
*   **Visuals:** Flattened **Sparse Visual Lags** ($t, t\pm4, t\pm8, t\pm15$) of Helmet IoU and Centroid Distance to capture visual looming trajectories (Cite solution_lesson_node_00044).
*   **Imputation:** Use **Left Join + Sentinel** (`-999`) for missing visual data to prevent data loss (Cite solution_lesson_node_00036).
*   **Explicit Physics:** Relative Speed, Closure Rate, and Cyclical Angle Encoding (Cite solution_lesson_node_00051, solution_lesson_node_00005).

**Feature Engineering - Stream B (Context-Augmented Impact):**
*   **Ego-Kinematics:** Flattened Exponential Pyramids of Position, Velocity, Acceleration. Explicitly include **Jerk** and **Pose-Motion Alignment** (Cite solution_lesson_node_00027).
*   **Context Features:** Using the pre-computed Spatial Index, calculate **Explicit Relational Features** (Distance, Relative Speed, Relative Orientation) between the subject and their Nearest Opponent. Flatten these over the temporal window.
*   **Exclusion:** Explicitly **exclude** all visual bounding box features, as they introduce noise for ground detection (Cite solution_lesson_node_00034).

# Training

*   **Algorithm:** Train both streams using **XGBoost** with the `gpu_hist` tree method for efficiency on flattened windows (Cite solution_lesson_node_00016).
*   **Sampling:** Apply **Random Undersampling** with a 10:1 negative-to-positive ratio independently to each stream (Cite solution_lesson_node_00005).
*   **Regularization:** Do **not** apply aggressive depth constraints to Stream B. Allow the model sufficient capacity to learn the non-linear interaction between "Ego-Jerk" and "Neighbor-Proximity" (Cite solution_lesson_node_00045).
*   **Objective:** Minimize **Binary Logistic Loss**.

# Evaluation

1.  **Inference:**
    *   Route test samples to Stream A or Stream B based on the `contact_id`.
    *   Stream A receives the fused Tracking+Visual vector. Stream B receives the Tracking+Neighbor vector.
2.  **Optimization:**
    *   **Thresholding:** Decouple the decision boundary from the probability. Perform a linear search on the Validation set to find the optimal probability threshold **independently for each stream** that maximizes the Matthews Correlation Coefficient (MCC) (Cite solution_lesson_node_00002, solution_lesson_node_00025).
    *   **Submission:** Apply these specific thresholds to the Test set predictions.
