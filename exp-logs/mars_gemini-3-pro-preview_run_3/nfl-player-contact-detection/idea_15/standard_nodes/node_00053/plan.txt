The implementation strategy follows the Context-Augmented Dual-Stream GBDT architecture.

1.  **Setup & Configuration**: We initialize the environment with a fixed seed and logger. We dynamically adjust the `Config` parameters (reducing `n_estimators` and `UNDERSAMPLE_RATIO`) to ensure the training completes quickly within the "Fast Baseline" constraints while maintaining model integrity.
2.  **Model Training**: We instantiate the `DualStreamModel`. This class orchestrates the feature generation (via `FeatureBuilder`) and training of two XGBoost models:
    *   **Stream A**: Handles Player-Player interactions using kinematic and visual features.
    *   **Stream B**: Handles Player-Ground impacts using ego-motion and the newly implemented Nearest-Neighbor Context features.
3.  **Threshold Optimization**: We invoke the model's optimization routine to find the best probability thresholds for each stream that maximize the MCC on the validation set.
4.  **Global Validation**: To compute the required `Final Validation Metric`, we manually trigger inference on the validation set for both streams. We combine the predictions (since the streams cover disjoint sets of contact IDs) and calculate the global Matthews Correlation Coefficient (MCC).
5.  **Failure Analysis**: We calculate the absolute error magnitude (`|y_true - y_prob|`) for the validation set and compute its correlation with input features. This identifies which features are most associated with prediction errors.
6.  **Submission**: We compare the final validation MCC against the specified threshold (`0.6938871601521127`). If the model performs sufficiently well, we generate the submission file using the `DualStreamModel`'s inference pipeline.
