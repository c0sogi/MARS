Based on the comprehensive analysis of the "Lessons Learned," specifically the conflicting requirements of **Interaction Detection** (which benefits from absolute energy context and relative geometry, Cite solution_lesson_node_00075, solution_lesson_node_00074) versus **Impact Detection** (which requires strict coordinate invariance and finite-difference dynamics, Cite solution_lesson_node_00075, solution_lesson_node_00068), I propose the **Biomechanical Invariance Dual-Stream GBDT**.

This solution structurally evolves the previous "Dual-Stream" architectures by formalizing a **Divergent Physics Paradigm**. Instead of attempting to find a "middle ground" feature set or architecture, we implement two strictly distinct modeling philosophies: **Stream A** acts as a "Collider Model" (Maximal Context, Energy-Aware) while **Stream B** acts as an "Accelerometer Model" (Minimal Context, Strictly Invariant).

# Model

The architecture consists of two specialized **XGBoost** classifiers with divergent feature spaces and complexity constraints.

1.  **Stream A: The Collider (Interaction Model)**
    *   **Scope:** Predicts contact between two players (`player2 != 'G'`).
    *   **Philosophy:** **Maximal Context & Energy Awareness**. Interactions are determined by the *convergence* of trajectories (Relational) and the *energy* of the system (Absolute).
    *   **Architecture:** A **Conditional Early-Fusion GBDT** (Cite solution_lesson_node_00036).
    *   **Feature Space:** Fuses **Absolute Kinematics** (to define collision energy), **Relational Scalars** (to define proximity), **Ego-Relational Projections** (to define angle of attack), and **Visual Pyramids** (to define looming).

2.  **Stream B: The Accelerometer (Impact Model)**
    *   **Scope:** Predicts contact between a player and the ground (`player2 == 'G'`).
    *   **Philosophy:** **Strict Biomechanical Invariance**. Ground impacts are intrinsic state changes defined by shock and loss of control. They are invariant to field position (`x`, `y`) and global heading.
    *   **Architecture:** A **Uni-Modal Invariant GBDT**.
    *   **Feature Space:** Strictly **Ego-Centric Finite-Difference Dynamics** (Surge/Sway Jerk). Explicitly **blocks** absolute coordinates and visual features to prevent overfitting to spatial noise (Cite solution_lesson_node_00075, solution_lesson_node_00034).

# Data

**Preprocessing:**
*   **Pipeline Integrity:** Implement **hash-based cache invalidation** derived from the full feature configuration (Cite solution_lesson_node_00004).
*   **Validation Mapping:** Explicitly map the `validation` mode to read from `train_player_tracking.csv` to ensure correct data loading (Cite solution_lesson_node_00054).

**Feature Engineering - Stream A (The Collider):**
1.  **Absolute Kinematics (Energy Context):** Flattened Exponential Pyramids ($t, t\pm1... t\pm15$) of **Speed** and **Scalar Acceleration**. This restores the "System Energy" signal lost in Idea 22 (Cite solution_lesson_node_00075).
2.  **Relational Scalars (Proximity):** Explicit **Euclidean Distance**, **Relative Speed** (scalar), and **Closure Rate** (derivative of distance). These are the robust primitives for spatial convergence (Cite solution_lesson_node_00062).
3.  **Ego-Relational Projections (Angle of Attack):** Project the Relative Velocity vector onto Player 1's orientation to get **Relative Surge** (closing from front/back) and **Relative Sway** (closing from side). This captures the biomechanics of the hit (Cite solution_lesson_node_00057).
4.  **Visual Pyramids & Consensus:**
    *   **Looming:** Flatten Sideline/Endzone IoU and Distance at sparse lags ($t, t\pm4, t\pm8, t\pm15$) (Cite solution_lesson_node_00044).
    *   **Consensus:** Explicitly calculate `IoU_Diff` (`|Sideline - Endzone|`) to quantify visual uncertainty (Cite solution_lesson_node_00074).
    *   **Imputation:** Use **Left Join + Sentinel** (`-999`) (Cite solution_lesson_node_00036).

**Feature Engineering - Stream B (The Accelerometer):**
1.  **Finite-Difference Ego-Dynamics:**
    *   **Step 1:** Project Velocity ($v$) onto Orientation ($\hat{o}$) $\rightarrow$ $v_{surge}, v_{sway}$.
    *   **Step 2:** Differentiate $v_{surge/sway}$ to get **Ego-Acceleration**.
    *   **Step 3:** Differentiate Ego-Acceleration to get **Ego-Jerk**.
    *   **Rationale:** This pipeline captures rotational dynamics (Coriolis terms) that projecting global acceleration misses (Cite solution_lesson_node_00068).
2.  **Strict Invariance:** Explicitly **exclude** `x`, `y`, `direction`, `orientation`, and all visual features. The model sees only the "Internal Forces" of the player body (Cite solution_lesson_node_00075).

# Training

*   **Sampling:** Apply **Targeted Majority Undersampling**. Retain **100%** of the positive class and randomly subsample the negative class to a 10:1 ratio (Cite solution_lesson_node_00060).
*   **Algorithm:** Train both streams using **XGBoost** with the `gpu_hist` tree method (Cite solution_lesson_node_00016).
*   **Asymmetric Regularization:**
    *   **Stream A:** Standard depth (`max_depth=6`) to model the complex interaction between 4+ feature groups.
    *   **Stream B:** **Shallow Depth** (`max_depth=6` to `8`) with **Explicit Physics**. By providing the robust `Ego-Jerk` signal, we avoid the need for deep trees that overfit sensor noise (Cite solution_lesson_node_00070).
*   **Objective:** Minimize **Binary Logistic Loss**.

# Evaluation

1.  **Inference:**
    *   Route test samples to Stream A or Stream B based on the `contact_id`.
    *   Stream A receives the "Maximal Context" vector. Stream B receives the "Strict Invariant" vector.
2.  **Optimization:**
    *   **Thresholding:** Decouple the decision boundary from the probability. Perform a linear search on the Validation set to find the optimal probability threshold **independently for each stream** that maximizes the Matthews Correlation Coefficient (MCC) (Cite solution_lesson_node_00002, solution_lesson_node_00025).
    *   **Submission:** Apply these specific thresholds to the Test set predictions.
