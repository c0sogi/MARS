The error `pandas.errors.MergeError: Passing 'suffixes' which cause duplicate columns` occurs because the `h_view` DataFrame (derived from `helmets_df`) retains metadata columns like `game_key`, `play_id`, and `video` that are not part of the join keys. When this DataFrame is merged iteratively for different players (P1, P2) and different views (Sideline, Endzone), these unhandled columns accumulate and cause naming collisions (e.g., `game_key_x` being generated when `game_key_x` already exists from a previous iteration).

To fix this, I will modify `library/features.py` to strictly project the `h_view` DataFrame to contain *only* the necessary join keys (`game_play`, `step`, `nfl_player_id`) and the feature columns (lagged visual features). This ensures that no extraneous metadata columns participate in the merge, preventing schema collisions. This solution directly applies "Debug Lesson 11: Strictly Project Columns Before Merging to Avoid Schema Collisions" (Cite debug_lesson_11).
