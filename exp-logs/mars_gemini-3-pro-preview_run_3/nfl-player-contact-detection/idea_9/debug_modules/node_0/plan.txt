Implementation Strategy:
1.  **Configuration & Patching**: To ensure the demonstration runs quickly (within seconds/minutes) and does not process the entire multi-gigabyte dataset, I will monkey-patch the `load_dataset` function used by the `FeatureEngineer`. This patched function will load only a small subset of the training and test data (first 5,000 rows of tracking/helmets) and ensure consistency between labels and tracking data.
2.  **Hyperparameter Optimization**: I will override the XGBoost parameters in the `config` module to use a minimal number of estimators (10) and a CPU-compatible tree method (though GPU is available, 'hist' is fast enough for small data) to speed up the training phase.
3.  **Pipeline Execution**:
    *   **Training**: I will execute `pipeline.run_training` with `debug=True`. This demonstrates the end-to-end flow: Feature Engineering -> Stream Splitting -> Model Training -> Threshold Optimization -> Model Saving.
    *   **Inference**: I will execute `pipeline.run_inference`. This demonstrates loading the saved models, generating features for the test set, and producing the submission file.
4.  **Validation**: After each major step, I will include assertions to verify that:
    *   Feature engineering produces dataframes with the expected shapes.
    *   Model artifacts (JSON files) are saved to the working directory.
    *   The submission file is generated and follows the required schema.
