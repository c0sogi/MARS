The issue is that the `datetime` column in the tracking data (which contains strings) is being merged into the feature set. When rows are missing (e.g., for "Ground" contacts), `NaN`s are introduced. The subsequent `fillna(0)` operation fills these `NaN`s with the integer `0`, creating a mixed-type column (strings and integers) in `datetime_p2`. PyArrow cannot serialize mixed-type columns to Parquet, resulting in the `ArrowTypeError`.

To fix this, I will modify `library/feature_engineering_tracking.py` to:
1.  Explicitly drop the `datetime` column from the tracking DataFrame after preprocessing, as it is not needed for the model and is the source of the specific error.
2.  Update the `fillna(0)` logic to apply only to numeric columns using `select_dtypes(include=[np.number])`. This ensures that other potential object columns (like `team` or `position`) remain as `NaN` (or their original type) rather than becoming mixed-type, preventing similar serialization errors.
