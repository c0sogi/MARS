The issue is caused by hardcoded `load_cached_data=True` arguments in the `create_features` methods of both `TrackingFeatureEngineer` and `HelmetFeatureEngineer`. Even when the pipeline is instructed to ignore cached data (e.g., `load_cached_data=False` in `runfile.py`), these hardcoded values force the `DataLoader` to load existing, potentially stale Parquet files instead of the freshly generated CSVs. This results in a mismatch between the metadata (which expects specific plays) and the tracking data (which is loaded from an obsolete cache missing those plays), causing the `ValueError`.

To fix this, I will update `library/feature_engineering_tracking.py` and `library/feature_engineering_helmets.py` to pass the `load_cached_data` argument received by `create_features` down to the data loader calls. This ensures that when the pipeline requests a fresh run, the raw data is reloaded from the source CSVs, effectively invalidating the stale cache. Cite debug_lesson_8.
