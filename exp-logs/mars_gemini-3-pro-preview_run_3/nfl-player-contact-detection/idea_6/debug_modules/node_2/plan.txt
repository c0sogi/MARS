The issue is caused by applying `fillna(0)` indiscriminately to all columns ending in `_p2` (and `_p1`) in `library/feature_engineering_tracking.py`. This includes the `datetime_p2` column, which is of string (object) type. Filling missing values with the integer `0` creates a mixed-type column (strings and integers), causing `pyarrow` to fail during Parquet serialization with an `ArrowTypeError`. The fix is to restrict the `fillna(0)` operation to only numeric columns, leaving string columns like `datetime` with `NaN` values, which `pyarrow` can handle correctly.
