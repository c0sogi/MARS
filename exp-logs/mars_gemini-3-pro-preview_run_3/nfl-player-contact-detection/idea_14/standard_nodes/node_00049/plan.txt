Implementation Strategy:
1.  **Configuration & Setup**: Import necessary modules from the provided library. Override specific `Config` parameters to ensure a "fast baseline" execution (reducing boosting rounds to 1000) and silence verbose logs. Set random seeds for reproducibility.
2.  **Workflow Initialization**: Instantiate the `WorkflowManager` to handle the pipeline orchestration.
3.  **Stream A (Interaction) Training**: Execute `train_interaction_stream` to train the Player-Player contact model. This yields the trained model, optimized threshold, OOF predictions for the training set (to be used as context), and validation predictions.
4.  **Stream B (Impact) Training**: Execute `train_impact_stream` using the OOF predictions from Stream A as input features. This trains the Player-Ground contact model and returns the model and optimized threshold.
5.  **Global Validation**: 
    *   Re-generate predictions for Stream B on the validation set (as the training method only returns the model).
    *   Combine Stream A and Stream B validation predictions.
    *   Compare against the ground truth from the validation metadata.
    *   Compute and print the `Final Validation Metric` (MCC).
6.  **Failure Analysis**:
    *   Calculate the absolute error between predictions and ground truth for both streams on the validation set.
    *   Compute correlations between these errors and the input features to identify failure modes.
    *   Print the top 5 correlated features for each stream.
7.  **Submission Logic**: Compare the calculated Final Validation Metric against the required threshold (0.6938871601521127). If the metric exceeds the threshold, execute `run_inference_cascade` to generate the `submission.csv` file for the test set.
