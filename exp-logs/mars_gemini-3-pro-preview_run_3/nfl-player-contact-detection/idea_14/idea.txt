Based on the comprehensive analysis of the "Lessons Learned," particularly the performance disparity between the strong Interaction Stream (MCC ~0.74) and the weaker Impact Stream (MCC ~0.50), I propose the **Sequential Cascade Dual-Stream GBDT with Cross-Modal Temporal Pyramids**.

This solution structurally evolves the "Asymmetric Modality-Selective" approach by introducing a **Sequential Dependency** between the streams. Instead of training them in isolation, we leverage the high-fidelity predictions of the Interaction Model (Stream A) as a contextual feature for the Impact Model (Stream B), explicitly modeling the physical causality that "collisions often lead to falls."

# Model

The architecture consists of two **XGBoost** classifiers arranged in a **Sequential Cascade**.

1.  **Stage 1: Interaction Model (Stream A)**
    *   **Scope:** Predicts contact between two players (`player2 != 'G'`).
    *   **Backbone:** A **Conditional Early-Fusion GBDT** (Cite solution_lesson_node_00036).
    *   **Feature Space:** Utilizes **Cross-Modal Exponential Temporal Pyramids**.
        *   **Tracking:** Sparse, exponentially spaced lags ($t, t\pm1, t\pm2, t\pm4, t\pm8, t\pm15$) to capture micro-mechanics and macro-trajectory (Cite solution_lesson_node_00042).
        *   **Visuals:** Sparse temporal lags ($t, t\pm4, t\pm8, t\pm15$) of Helmet IoU and Centroid Distance. This captures the **visual trajectory** (looming/convergence) rather than just static overlap (Cite solution_lesson_node_00044).
    *   **View-Awareness:** Flattens Sideline and Endzone features separately to allow the tree to weigh view reliability (Cite solution_lesson_node_00016).

2.  **Stage 2: Impact Model (Stream B)**
    *   **Scope:** Predicts contact between a player and the ground (`player2 == 'G'`).
    *   **Backbone:** A **Context-Aware Kinematic GBDT**.
    *   **Feature Space:**
        *   **Kinematics:** Pure sensor data (Position, Velocity, Acceleration, Jerk, Pose-Alignment) using Exponential Lags. Explicitly excludes noisy visual bounding box derivatives (Cite solution_lesson_node_00034).
        *   **Interaction Context (The Innovation):** A new feature, **`Max_Interaction_Prob`**, representing the maximum probability that the subject player is currently in contact with *any* other player (derived from Stage 1).
    *   **Rationale:** Ground impacts are often the downstream consequence of a tackle. By feeding the robust "Collision Signal" from Stage 1 into Stage 2, the Ground model gains critical context ("This player just got hit") that is otherwise invisible in pure single-player kinematics.

# Data

**Preprocessing:**
*   **Pipeline Integrity:** Implement **hash-based cache invalidation** derived from the full feature configuration (Cite solution_lesson_node_00004).
*   **Deterministic Ordering:** Use hardcoded whitelists to strictly define feature order (Cite solution_lesson_node_00008).

**Feature Engineering:**
1.  **Stream A (Interaction):**
    *   Construct **Exponential Temporal Pyramids** for both Tracking and Visual modalities.
    *   Apply **Robust Imputation** (Left Join + Sentinel `-999`) for missing visual data to prevent data loss (Cite solution_lesson_node_00036).
    *   Decompose angles into Sine/Cosine (Cite solution_lesson_node_00005).
2.  **Stream B (Impact):**
    *   Construct **Exponential Temporal Pyramids** for Tracking data only.
    *   **Cascade Feature Generation:** For every timestep $t$ and player $P$, calculate the `Rolling_Max` (over $t-10$ to $t$) of the Stream A probabilities for all pairs involving $P$. This scalar value serves as the "Interaction Prior."

# Training

**Procedure:**
1.  **Stage 1 Training (Interaction):**
    *   Train Stream A using **XGBoost** (`gpu_hist`) with **Random Undersampling** (10:1 ratio) (Cite solution_lesson_node_00005).
    *   Generate **Out-of-Fold (OOF)** predictions for the training set to prevent leakage when training Stage 2.
2.  **Stage 2 Training (Impact):**
    *   Construct the training set for Stream B, enriching it with the OOF `Max_Interaction_Prob` from Stage 1.
    *   Train Stream B using **XGBoost** (`gpu_hist`) with **Random Undersampling** (10:1 ratio).
    *   **Constraint:** Do *not* apply aggressive regularization (e.g., shallow depth) to Stream B, as it requires capacity to model complex kinematic non-linearities (Cite solution_lesson_node_00045).

**Loss Function:** Minimize **Binary Logistic Loss** for both streams.

# Evaluation

1.  **Inference Cascade:**
    *   **Step 1:** Generate predictions for all Player-Player pairs using the trained Stream A model.
    *   **Step 2:** For each player, compute the `Max_Interaction_Prob` feature from the Stream A predictions.
    *   **Step 3:** Generate predictions for all Player-Ground pairs using the trained Stream B model (fed with the feature from Step 2).
2.  **Threshold Optimization:**
    *   Decouple the decision boundary from the probability. Perform a linear search on the Validation set to find the optimal probability threshold **independently for each stream** that maximizes the Matthews Correlation Coefficient (MCC) (Cite solution_lesson_node_00002, solution_lesson_node_00025).
    *   Apply these specific thresholds to the Test set predictions.
