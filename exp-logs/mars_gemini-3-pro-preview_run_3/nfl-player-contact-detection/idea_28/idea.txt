Based on the comprehensive analysis of the "Lessons Learned," specifically the failure of "Strict Invariance" (stripping absolute coordinates) in Stream B (Cite solution_lesson_node_00091), the superiority of **Temporal Window Flattening** over instantaneous derivatives (Cite solution_lesson_node_00086), and the necessity of **Positional Differentials** for interactions (Cite solution_lesson_node_00080), I propose the **Hybrid-Context Dual-Stream GBDT with Temporal Physics Pyramids**.

This solution structurally evolves the previous architectures by correcting the "Over-Simplification" errors of Ideas 22-27. It rejects the hypothesis that models should be restricted to purely invariant or purely relative features. Instead, it implements a **Hybrid-Context Paradigm**:
*   **Stream A** combines **Relational Geometry** with **System Energy** (restoring absolute context).
*   **Stream B** combines **Ego-Centric Physics** with **Field-Centric Context** (restoring spatial priors).
*   Both streams utilize **Exponential Temporal Pyramids** to capture trajectory shapes rather than noisy instantaneous states.

# Model

The architecture consists of two specialized **XGBoost** classifiers (Cite solution_lesson_node_00016) operating on robust, physically grounded feature spaces.

1.  **Stream A: The Interaction Model (Geometry + Energy + Vision)**
    *   **Scope:** Predicts contact between two players (`player2 != 'G'`).
    *   **Backbone:** A **Conditional Early-Fusion GBDT** (Cite solution_lesson_node_00036).
    *   **Feature Strategy:**
        *   **Relational Scalars:** Uses **Euclidean Distance** and **Closure Rate** calculated via finite differences of distance. Explicitly rejects vector projections (Cite solution_lesson_node_00080).
        *   **System Energy:** Includes absolute **Speed** and **Acceleration** for both players. This restores the "Energy Context" (e.g., high-speed collision vs. low-speed bump) lost in previous invariant iterations (Cite solution_lesson_node_00075).
        *   **Visual Consensus:** Uses **Temporal Pyramids** of IoU metrics (Max/Min/Diff) to capture looming trajectories and gate perspective artifacts (Cite solution_lesson_node_00074, solution_lesson_node_00044).

2.  **Stream B: The Impact Model (Hybrid Context + Ego-Dynamics)**
    *   **Scope:** Predicts contact between a player and the ground (`player2 == 'G'`).
    *   **Backbone:** A **Uni-Modal Hybrid GBDT**.
    *   **Feature Strategy:**
        *   **Field-Centric Anchor:** Retains absolute `x`, `y`, `direction`, and `orientation`. This allows the model to leverage environmental priors (e.g., "falls are more likely near the sideline") which were fatal to remove (Cite solution_lesson_node_00091).
        *   **Ego-Centric Dynamics:** Projects velocity into **Surge** (Forward) and **Sway** (Lateral) components, then differentiates over time to derive **Ego-Acceleration** and **Ego-Jerk**. This captures the invariant physical signature of a fall (Cite solution_lesson_node_00068).
        *   **Temporal Flattening:** Instead of using just the current timestep's Jerk, it flattens the *entire window* of Surge/Sway values. This allows the tree to match the "shape" of the impact trajectory (Cite solution_lesson_node_00086).

# Data

**Preprocessing:**
*   **Pipeline Integrity:** Implement **hash-based cache invalidation** (Cite solution_lesson_node_00004).
*   **Strict Schema Validation:** Raise a `RuntimeError` if any expected feature column is missing or zero-filled at the end of the pipeline to prevent "silent defaults" (Cite solution_lesson_node_00088).
*   **Validation Mapping:** Explicitly map `validation` mode to `train_player_tracking.csv` (Cite solution_lesson_node_00054).

**Feature Engineering - Stream A (Interaction):**
1.  **Exponential Temporal Pyramids:** Flatten features at sparse lags ($t, t\pm1, t\pm2, t\pm4, t\pm8, t\pm15$) (Cite solution_lesson_node_00042).
2.  **Relational Primitives:** Calculate **Euclidean Distance** and **Closure Rate** ($-\Delta d / \Delta t$) at each lag (Cite solution_lesson_node_00080).
3.  **System Energy:** Flattened pyramids of Absolute Speed and Scalar Acceleration (Cite solution_lesson_node_00075).
4.  **Visual Consensus:** Flatten `Sideline_IoU`, `Endzone_IoU`, `Max_IoU`, `Min_IoU`, and `IoU_Diff` at sparse lags ($t, t\pm4, t\pm8, t\pm15$). Impute missing values with `-999` (Cite solution_lesson_node_00036).

**Feature Engineering - Stream B (Impact):**
1.  **Hybrid Coordinates:**
    *   **Context:** Flattened pyramids of `x`, `y`, `speed`, `acceleration` (scalar), `direction`, `orientation` (Cite solution_lesson_node_00091).
    *   **Physics:** For every timestep in the window:
        *   Project Velocity $v$ onto Orientation $\hat{o}$ $\rightarrow$ $v_{surge}, v_{sway}$.
        *   Differentiate $v_{surge/sway}$ $\rightarrow$ $a_{surge}, a_{sway}$.
        *   Differentiate $a_{surge/sway}$ $\rightarrow$ $j_{surge}, j_{sway}$ (Cite solution_lesson_node_00068).
    *   **Flattening:** Flatten these derived Ego-Centric sequences into the feature vector (Cite solution_lesson_node_00086).
2.  **Exclusion:** Explicitly block all visual features (Cite solution_lesson_node_00034).

# Training

*   **Sampling:** Apply **Targeted Majority Undersampling**. Retain **100%** of the positive class and randomly subsample the negative class to a 10:1 ratio (Cite solution_lesson_node_00060).
*   **Algorithm:** Train both streams using **XGBoost** with the `gpu_hist` tree method (Cite solution_lesson_node_00016).
*   **Regularization:**
    *   **Stream A:** Standard depth (`max_depth=6`) to model complex interactions.
    *   **Stream B:** **Shallow Depth** (`max_depth=6` to `8`). By providing the robust, flattened Ego-Centric trajectories and explicit Jerk, we avoid the need for deep trees, preventing overfitting to sensor noise (Cite solution_lesson_node_00070).
*   **Objective:** Minimize **Binary Logistic Loss**.

# Evaluation

1.  **Inference:**
    *   Route test samples to Stream A or Stream B based on the `contact_id`.
    *   Stream A receives the "Relational + Energy + Visual" vector. Stream B receives the "Hybrid Context + Ego-Physics" vector.
2.  **Optimization:**
    *   **Thresholding:** Decouple the decision boundary from the probability. Perform a linear search on the Validation set to find the optimal probability threshold **independently for each stream** that maximizes the Matthews Correlation Coefficient (MCC) (Cite solution_lesson_node_00002, solution_lesson_node_00025).
    *   **Submission:** Apply these specific thresholds to the Test set predictions.
