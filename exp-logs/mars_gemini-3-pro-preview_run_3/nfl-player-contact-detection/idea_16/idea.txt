Based on the progression of empirical findings—specifically the superiority of **Ego-Motion Kinematics** for ground impacts (Cite solution_lesson_node_00053), the necessity of **Explicit Relational Features** for interactions (Cite solution_lesson_node_00051), and the proven effectiveness of **Exponential Temporal Pyramids** (Cite solution_lesson_node_00042)—I propose the **Ego-Centric Dual-Stream GBDT with Multi-Modal Temporal Pyramids**.

This solution structurally evolves the previous "Dual-Stream" approaches by fundamentally transforming the feature space for the Impact Model (Stream B). Instead of relying on field-centric coordinates (which require the model to learn rotational invariance) or single scalar alignments (like "Pose-Motion Alignment"), this architecture projects the **entire kinematic temporal window** into the player's **Body-Centric Coordinate System**. This ensures that the GBDT learns physical signatures (e.g., "falling backward," "lateral impact") that are invariant to the player's position or direction on the field.

# Model

The architecture consists of two specialized **XGBoost** classifiers (Cite solution_lesson_node_00016) operating on physically distinct, coordinate-transformed feature spaces.

1.  **Stream A: Interaction Model (Player-Player)**
    *   **Scope:** Predicts contact between two players (`player2 != 'G'`).
    *   **Backbone:** A **Conditional Early-Fusion GBDT**.
    *   **Input:** A fused vector of **Field-Centric Relational Tracking** and **Visual Geometry**.
    *   **Rationale:** Interactions are defined by the spatial relationship between two entities. Explicit relational features (Distance, Relative Speed) and Visual Overlap (IoU) are the strongest signals (Cite solution_lesson_node_00051, solution_lesson_node_00034).

2.  **Stream B: Impact Model (Player-Ground)**
    *   **Scope:** Predicts contact between a player and the ground (`player2 == 'G'`).
    *   **Structural Innovation:** **Ego-Centric Kinematic Projection**.
    *   **Input:** **Body-Centric Kinematics**.
    *   **Mechanism:** Rather than using raw field coordinates ($x, y, v_x, v_y$), the model transforms all kinematic vectors in the temporal window into components relative to the player's orientation: **Surge** (longitudinal) and **Sway** (lateral).
    *   **Rationale:** Ground impacts are ego-motion events defined by loss of control and force transients. By projecting motion into the body frame, signatures like "sudden lateral deceleration" (getting tackled sideways) become consistent features regardless of whether the player is running North or East (Cite solution_lesson_node_00053).

# Data

**Preprocessing:**
*   **Pipeline Integrity:** Implement **hash-based cache invalidation** derived from the feature configuration (Cite solution_lesson_node_00004).
*   **Deterministic Ordering:** Use hardcoded whitelists to strictly define feature order (Cite solution_lesson_node_00008).

**Feature Engineering - Stream A (Interaction):**
1.  **Tracking (Field-Centric):**
    *   **Exponential Temporal Pyramids:** Flatten features at sparse lags ($t, t\pm1, t\pm2, t\pm4, t\pm8, t\pm15$) (Cite solution_lesson_node_00042).
    *   **Relational Features:** Explicitly calculate Euclidean Distance, Relative Speed, and Closure Rate at each lag (Cite solution_lesson_node_00051).
    *   **Cyclical Encoding:** Sine/Cosine for all angles (Cite solution_lesson_node_00005).
2.  **Visuals (Geometry):**
    *   **Visual Temporal Pyramids:** Flatten Sideline and Endzone IoU/Distance at sparse lags ($t, t\pm4, t\pm8, t\pm15$) to capture looming trajectories (Cite solution_lesson_node_00044).
    *   **Robust Imputation:** Use **Left Join + Sentinel** (`-999`) to handle missing helmet detections without data loss (Cite solution_lesson_node_00036).

**Feature Engineering - Stream B (Impact - The Innovation):**
1.  **Coordinate Transformation:** For every timestep $\tau$ in the exponential window ($t, t\pm1... t\pm15$):
    *   Calculate the relative angle $\phi = \text{Direction}_\tau - \text{Orientation}_{t=0}$.
    *   Project Velocity ($v$), Acceleration ($a$), and Jerk ($j$) into **Surge** and **Sway** components:
        *   $v_{surge} = v_\tau \cdot \cos(\phi)$
        *   $v_{sway} = v_\tau \cdot \sin(\phi)$
        *   (Repeat for $a$ and $j$).
2.  **Ego-Centric Features:** Flatten these transformed Surge/Sway vectors. This explicitly exposes "Forward Acceleration" vs "Lateral Acceleration" to the tree.
3.  **Exclusion:** Explicitly **block** all visual features (Cite solution_lesson_node_00034) and external context features (Cite solution_lesson_node_00053) to prevent noise injection.

# Training

*   **Sampling:** Apply **Random Undersampling** with a 10:1 negative-to-positive ratio independently to each stream (Cite solution_lesson_node_00005).
*   **Algorithm:** Train both streams using **XGBoost** with the `gpu_hist` tree method (Cite solution_lesson_node_00016).
*   **Regularization:** Do **not** apply aggressive depth constraints to Stream B. Allow the model sufficient capacity to learn the non-linear boundaries of the new Ego-Centric feature space (Cite solution_lesson_node_00045).
*   **Objective:** Minimize **Binary Logistic Loss**.

# Evaluation

1.  **Inference:**
    *   Route test samples to Stream A or Stream B based on the `contact_id`.
    *   Stream A receives the Field-Centric Relational + Visual vector. Stream B receives the Ego-Centric Kinematic vector.
2.  **Optimization:**
    *   **Thresholding:** Decouple the decision boundary from the probability. Perform a linear search on the Validation set to find the optimal probability threshold **independently for each stream** that maximizes the Matthews Correlation Coefficient (MCC) (Cite solution_lesson_node_00002, solution_lesson_node_00025).
    *   **Submission:** Apply these specific thresholds to the Test set predictions.
