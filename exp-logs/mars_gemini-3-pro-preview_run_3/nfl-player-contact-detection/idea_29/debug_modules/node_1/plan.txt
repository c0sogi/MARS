The issue stems from **schema pollution** caused by merging the helmet DataFrame (`view_h`) without first filtering out unnecessary metadata columns (like `game_key`, `play_id`, `video`). When `compute_view_iou` is called sequentially for "Sideline" and "Endzone" views, these unprojected auxiliary columns accumulate in the main DataFrame, creating duplicate columns with conflicting suffixes (e.g., `game_key_x`) that trigger a `pandas.errors.MergeError` during subsequent merges.

To fix this, I will strictly project the `view_h` DataFrame to include only the required join keys (`game_play`, `frame`, `nfl_player_id`) and the bounding box features (`left`, `width`, `top`, `height`) before performing any merges. This prevents metadata leakage and ensures schema consistency, applying the principle from **debug_lesson_11**.
