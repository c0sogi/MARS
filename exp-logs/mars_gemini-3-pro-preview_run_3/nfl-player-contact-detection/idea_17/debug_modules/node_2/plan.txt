The issue stems from the undersampling logic encountering a dataset with zero positive samples (common in small debug slices like Stream B). This causes `n_neg` to be calculated as 0, resulting in an empty training set. Subsequently, XGBoost attempts to estimate the `base_score` from this empty or single-class data, calculating it as 0.0, which is mathematically invalid for the logistic loss function (`log(0)` is undefined).

To fix this, I will:
1.  Modify `_undersample` in `library/model_trainer.py` to return the original dataframe if no positive samples are found, ensuring the model has data to train on (even if single-class). This aligns with handling single-class data slices robustly (Cite debug_lesson_5).
2.  Explicitly set `xgb_params["base_score"] = 0.5` in the `train` method. This overrides the automatic estimation, preventing the `XGBoostError` when the training data is homogeneous.
