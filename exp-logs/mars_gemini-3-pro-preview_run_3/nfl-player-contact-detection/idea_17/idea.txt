Based on the progression of empirical findings—specifically the failure of "Contextual" features for ground impacts (Cite solution_lesson_node_00053), the failure of "Replacing" raw data with projected features (Cite solution_lesson_node_00055), and the consistent superiority of **Asymmetric Modality Selection** (Cite solution_lesson_node_00034)—I propose the **Hybrid Coordinate Dual-Stream GBDT with Augmented Ego-Motion**.

This solution structurally evolves the "Stream B" (Player-Ground) architecture. Previous attempts failed by either relying on external context (Idea 15) or strictly replacing raw data with body-centric projections (Idea 16). This solution implements a **Hybrid Coordinate Strategy**: it presents the GBDT with *both* the stable Field-Centric kinematics (to anchor the model) and the derived Ego-Centric projections (to capture invariant physical signatures like "Lateral Jerk"), allowing the tree to learn the optimal synthesis of both frames.

# Model

The architecture consists of two specialized **XGBoost** classifiers (Cite solution_lesson_node_00016) operating on physically distinct feature spaces.

1.  **Stream A: Interaction Model (Player-Player)**
    *   **Scope:** Predicts contact between two players (`player2 != 'G'`).
    *   **Backbone:** The **Robust Asymmetric GBDT** established in previous successful iterations.
    *   **Input:** A fused vector of **Field-Centric Relational Tracking** and **Visual Geometry**.
    *   **Rationale:** Interactions are spatial relationships. Explicit relational features (Distance, Closure Rate) and Visual Overlap (IoU) are the strongest signals (Cite solution_lesson_node_00051, solution_lesson_node_00034).

2.  **Stream B: Hybrid Impact Model (Player-Ground)**
    *   **Scope:** Predicts contact between a player and the ground (`player2 == 'G'`).
    *   **Structural Innovation:** **Hybrid Coordinate Feature Space**.
    *   **Input:** A concatenated vector of **Field-Centric Kinematics** AND **Ego-Centric Projections**.
    *   **Rationale:**
        *   **Field-Centric (Raw):** Provides the robust, low-noise baseline (Speed, Scalar Acceleration) that prevented the collapse observed in Idea 16 (Cite solution_lesson_node_00055).
        *   **Ego-Centric (Augmented):** Projects motion into **Surge** (Forward/Backward) and **Sway** (Left/Right) components. This exposes invariant signatures (e.g., "Sudden Sway Deceleration" = Side Tackle) that are invisible in raw coordinates, without discarding the raw signal (Cite solution_lesson_node_00053).

# Data

**Preprocessing:**
*   **Pipeline Integrity:** Implement **hash-based cache invalidation** derived from the feature configuration (Cite solution_lesson_node_00004).
*   **Validation Logic:** Explicitly map the `validation` mode to read from `train_player_tracking.csv` to avoid the "Test Data" merge failure (Cite solution_lesson_node_00054).

**Feature Engineering - Stream A (Interaction):**
*   **Tracking:** Flattened **Exponential Temporal Pyramids** ($t, t\pm1, t\pm2, t\pm4, t\pm8, t\pm15$) to capture micro-mechanics and macro-trajectory (Cite solution_lesson_node_00042).
*   **Relational Features:** Explicitly calculate Euclidean Distance, Relative Speed, and Closure Rate at each lag (Cite solution_lesson_node_00051).
*   **Visuals:** Flattened **Sparse Visual Lags** ($t, t\pm4, t\pm8, t\pm15$) of Helmet IoU and Centroid Distance to capture looming trajectories (Cite solution_lesson_node_00044).
*   **Imputation:** Use **Left Join + Sentinel** (`-999`) for missing visual data to prevent data loss (Cite solution_lesson_node_00036).

**Feature Engineering - Stream B (Hybrid Impact):**
*   **Field-Centric (The Anchor):** Flattened Exponential Pyramids of raw Position, Velocity, Acceleration, and Jerk.
*   **Ego-Centric (The Augmentation):** For every timestep in the window, project Velocity, Acceleration, and Jerk into **Surge** and **Sway** components relative to the player's orientation. Flatten these as additional columns.
*   **Physics Derivatives:** Explicitly include **Pose-Motion Alignment** (Cite solution_lesson_node_00027).
*   **Exclusion:** Explicitly **exclude** all visual bounding box features (Cite solution_lesson_node_00034) and "Nearest Neighbor" context (Cite solution_lesson_node_00053).

# Training

*   **Algorithm:** Train both streams using **XGBoost** with the `gpu_hist` tree method (Cite solution_lesson_node_00016).
*   **Sampling:** Apply **Random Undersampling** with a 10:1 negative-to-positive ratio independently to each stream (Cite solution_lesson_node_00005).
*   **Regularization:** Do **not** apply aggressive depth constraints to Stream B. Allow the model sufficient capacity to learn the non-linear interactions between the Field-Centric and Ego-Centric features (Cite solution_lesson_node_00045).
*   **Objective:** Minimize **Binary Logistic Loss**.

# Evaluation

1.  **Inference:**
    *   Route test samples to Stream A or Stream B based on the `contact_id`.
    *   Stream A receives the Relational+Visual vector. Stream B receives the Hybrid Kinematic vector.
2.  **Optimization:**
    *   **Thresholding:** Decouple the decision boundary from the probability. Perform a linear search on the Validation set to find the optimal probability threshold **independently for each stream** that maximizes the Matthews Correlation Coefficient (MCC) (Cite solution_lesson_node_00002, solution_lesson_node_00025).
    *   **Submission:** Apply these specific thresholds to the Test set predictions.
