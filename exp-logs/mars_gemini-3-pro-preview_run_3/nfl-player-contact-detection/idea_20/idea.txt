Based on the progression of empirical findings—specifically the necessity of **Finite Difference Dynamics** for ego-motion (Cite solution_lesson_node_00068), the superiority of **Explicit Relational Scalars** for interactions (Cite solution_lesson_node_00062), and the critical need for **Asymmetric Regularization** (Cite solution_lesson_node_00045)—I propose the **Dual-Stream GBDT with Finite-Difference Ego-Dynamics and Relational Pyramids**.

This solution structurally evolves the previous "Physically-Disentangled" approach (Idea 19) by correcting the biomechanical feature engineering in the Impact Stream and optimizing the interaction features in the Interaction Stream. It replaces the flawed "Projection of Acceleration" logic with "Derivative of Projected Velocity" to correctly capture rotational forces during falls, and it reverts the Interaction Stream to robust scalar metrics.

# Model

The architecture consists of two specialized **XGBoost** classifiers (Cite solution_lesson_node_00016) operating on divergent, physics-optimized feature spaces with distinct complexity constraints.

1.  **Stream A: Interaction Model (Player-Player)**
    *   **Scope:** Predicts contact between two players (`player2 != 'G'`).
    *   **Backbone:** A **Conditional Early-Fusion GBDT**.
    *   **Feature Strategy:** **Relational Scalars + Visual Pyramids**.
    *   **Rationale:** Interactions are defined by spatial convergence. Explicit scalars (Closure Rate, Distance) outperform frame-dependent vector projections for this task (Cite solution_lesson_node_00062). Visual Temporal Pyramids provide the necessary "looming" signal (Cite solution_lesson_node_00044).

2.  **Stream B: Impact Model (Player-Ground)**
    *   **Scope:** Predicts contact between a player and the ground (`player2 == 'G'`).
    *   **Backbone:** A **Hybrid-Coordinate Kinematic GBDT**.
    *   **Feature Strategy:** **Raw Field-Centric Anchor + Finite-Difference Ego-Dynamics**.
    *   **Rationale:** Ground impacts are invariant to field position but highly correlated with body-relative forces. Crucially, we calculate ego-centric acceleration by differentiating the projected velocity, capturing rotational dynamics (Coriolis terms) that direct projection misses (Cite solution_lesson_node_00068).

# Data

**Preprocessing:**
*   **Pipeline Integrity:** Implement **hash-based cache invalidation** (Cite solution_lesson_node_00004) and **deterministic feature ordering** (Cite solution_lesson_node_00008).
*   **Validation Mapping:** Explicitly map the `validation` mode to read from `train_player_tracking.csv` (Cite solution_lesson_node_00054).

**Feature Engineering - Stream A (Interaction):**
1.  **Tracking (Relational Scalars):**
    *   **Exponential Temporal Pyramids:** Flatten features at sparse lags ($t, t\pm1, t\pm2, t\pm4, t\pm8, t\pm15$) (Cite solution_lesson_node_00042).
    *   **Explicit Scalars:** Calculate **Euclidean Distance**, **Relative Speed** (scalar), and **Closure Rate** (derivative of distance) at each lag. **Do not** project these into the body frame (Cite solution_lesson_node_00062).
    *   **Cyclical Encoding:** Sine/Cosine for all angles (Cite solution_lesson_node_00005).
2.  **Visuals (Temporal Pyramids):**
    *   Flatten Sideline and Endzone IoU/Distance at sparse lags ($t, t\pm4, t\pm8, t\pm15$) (Cite solution_lesson_node_00044).
    *   **Robust Imputation:** Use **Left Join + Sentinel** (`-999`) to handle missing helmet detections (Cite solution_lesson_node_00036).

**Feature Engineering - Stream B (Impact - The Innovation):**
1.  **Field-Centric Anchor (Raw):**
    *   Flattened Exponential Pyramids of raw Position, Velocity, and Acceleration. This provides the robust baseline (Cite solution_lesson_node_00055).
2.  **Finite-Difference Ego-Dynamics (New Logic):**
    *   For every timestep, project the **Velocity Vector** ($v_x, v_y$) onto the player's Orientation to get **Surge Velocity** ($v_{surge}$) and **Sway Velocity** ($v_{sway}$).
    *   Calculate **Ego-Acceleration** as the discrete time derivative of these projected velocities: $a_{surge} = \frac{v_{surge}(t) - v_{surge}(t-1)}{\Delta t}$.
    *   **Constraint:** Do *not* project the global acceleration vector directly, as this discards rotational information (Cite solution_lesson_node_00068).
3.  **Exclusion:** Explicitly **block** all visual features (Cite solution_lesson_node_00034) and relational context (Cite solution_lesson_node_00053).

# Training

*   **Sampling:** Apply **Targeted Majority Undersampling**. Retain **100%** of the positive class and randomly subsample the negative class to a 10:1 ratio (Cite solution_lesson_node_00060).
*   **Algorithm:** Train both streams using **XGBoost** with the `gpu_hist` tree method (Cite solution_lesson_node_00016).
*   **Asymmetric Regularization (Cite solution_lesson_node_00045):**
    *   **Stream A:** Use standard regularization (e.g., `max_depth=6`, `colsample_bytree=0.8`).
    *   **Stream B:** Use **Relaxed Regularization**. Increase `max_depth` to 10 or 12 and reduce `min_child_weight`. This allows the model to capture the complex, non-linear interactions between the Raw and Ego-centric features required to detect ground impacts.
*   **Objective:** Minimize **Binary Logistic Loss**.

# Evaluation

1.  **Inference:**
    *   Route test samples to Stream A or Stream B based on the `contact_id`.
    *   Stream A receives the Relational-Visual vector. Stream B receives the Hybrid-Coordinate Kinematic vector.
2.  **Optimization:**
    *   **Thresholding:** Decouple the decision boundary from the probability. Perform a linear search on the Validation set to find the optimal probability threshold **independently for each stream** that maximizes the Matthews Correlation Coefficient (MCC) (Cite solution_lesson_node_00002, solution_lesson_node_00025).
    *   **Submission:** Apply these specific thresholds to the Test set predictions.
