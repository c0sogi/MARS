# Optimized Strategy: Multi-Task Deberta-V3-Large with AWP and Multi-Sample Dropout

### Model
I propose a **Multi-Task Cross-Encoder Architecture** that structurally evolves the previous regression-only approach into a hybrid system.

1.  **Backbone:** We will persist with **`microsoft/deberta-v3-large`** as the shared encoder, leveraging its superior pre-trained representations (Cite solution_lesson_node_00001) and capacity (Cite solution_lesson_node_00011).
2.  **Cross-Encoder Design:** The input will remain a single concatenated sequence to maintain the critical token-level interactions between the context and phrases (Cite solution_lesson_node_00008).
3.  **Pooling:** We will utilize **Attention Pooling** to aggregate token embeddings into a sentence representation, preserving the ability to weight informative tokens dynamically (Cite solution_lesson_node_00011).
4.  **Structural Innovation (Multi-Task Heads & MSD):** Instead of a single output layer, the model will feature:
    *   **Multi-Sample Dropout (MSD):** We will replace the standard dropout layer with multiple parallel dropout masks. The output of the pooling layer will be passed through these distinct masks, and the results averaged. This technique accelerates convergence and acts as a robust ensemble-within-a-model.
    *   **Dual-Head Output:** We will attach two parallel heads to the MSD output:
        1.  **Regression Head:** A linear layer predicting the continuous similarity score (0.0 to 1.0).
        2.  **Classification Head:** A linear layer predicting the specific discrete score bucket (5 classes: 0, 0.25, 0.5, 0.75, 1.0).
    *   **Rationale:** The similarity scores are not arbitrary continuous values but represent distinct semantic categories (e.g., "Antonym" vs. "Synonym"). Adding the auxiliary classification task forces the model to respect these decision boundaries, regularizing the regression head to be more precise.

### Data
1.  **Input Formatting:** Inputs will be concatenated into the format: `[CLS] Context [SEP] Anchor [SEP] Target [SEP]` (Cite solution_lesson_node_00008).
2.  **Target Encoding:** We will prepare two target variables for each sample:
    *   **Float Target:** The original score (e.g., 0.75) for the regression task.
    *   **Integer Target:** A label index (e.g., 3 for 0.75) for the classification task.
3.  **Dynamic Padding:** Batches will be padded dynamically to the longest sequence to optimize A100 GPU throughput.

### Training
1.  **Loss Function:** The training objective will be a weighted sum of **Mean Squared Error (MSE)** for the regression head and **Cross-Entropy Loss** for the classification head (e.g., $L = L_{MSE} + \lambda L_{CE}$).
2.  **Adversarial Weight Perturbation (AWP):** We will integrate AWP into the training loop. After the initial forward/backward pass, we will perturb weights to maximize the combined loss, then minimize this "worst-case" loss. This ensures the model finds a flatter, more robust minimum (Cite solution_lesson_node_00012).
3.  **Optimization Strategy:**
    *   **Optimizer:** AdamW with weight decay.
    *   **Layer-wise Learning Rate Decay (LLRD):** We will apply a decay factor (e.g., 0.9) to learning rates, decreasing from the heads down to the input embeddings, to preserve the pre-trained backbone features (Cite solution_lesson_node_00011).

### Evaluation
1.  **Inference:** Test samples will be processed through the backbone and the **Regression Head** only. The classification head is used solely for representation shaping during training.
2.  **Post-Processing:** Predictions will be clipped to the [0, 1] range.
3.  **Submission:** The regression scores will be mapped to `id`s and saved.
