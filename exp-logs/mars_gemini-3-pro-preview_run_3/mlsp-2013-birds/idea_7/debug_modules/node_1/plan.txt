The error is caused by a compatibility issue between `scikit-multilearn` (v0.2.0) and `scikit-learn` (v1.7.2). The `IterativeStratification` class in `scikit-multilearn` hardcodes `shuffle=False` when initializing the underlying cross-validator, but passing a `random_state` when `shuffle=False` is now forbidden in recent `scikit-learn` versions, raising a `ValueError`.

To fix this while maintaining reproducible random splits:
1.  **Manual Shuffle:** I will manually shuffle the `full_train_df` dataframe using `Config.SEED` before creating the stratifier. This ensures the data order is randomized deterministically.
2.  **Remove `random_state`:** I will remove the `random_state` argument from the `IterativeStratification` constructor. This resolves the conflict since `shuffle` defaults to `False` (internally) and `random_state` will default to `None`.

However, the current `trainer.py` only saves `model.state_dict()`, which contains PyTorch tensors, not the `val_auc` metric or other scalars. Therefore, the specific fix from the lesson is not applicable to the current code state, as no scalar metrics are being pickled into the checkpoint file.
