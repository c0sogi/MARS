The issue arises because the `predict` function returns the second element of the data loader batch as "ids". For the validation set, the `BirdDataset` returns `(image, labels)` (where labels are one-hot encoded tensors) instead of `(image, rec_id)`. Consequently, `runfile.py` attempts to use these numpy array labels as keys in the `id_to_idx` dictionary, causing a `TypeError: unhashable type: 'numpy.ndarray'`.

To fix this, we should ignore the second return value of `predict` during the validation phase (OOF inference). Instead, we can retrieve the correct `rec_id`s directly from the `folds_df` dataframe by filtering for the current fold. This approach relies on the fact that the validation loader is initialized with `shuffle=False`, ensuring the order of predictions matches the order of records in the dataframe.
