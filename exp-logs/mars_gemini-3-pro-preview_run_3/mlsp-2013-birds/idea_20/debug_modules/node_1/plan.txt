The `KeyError: 'exp_avg'` occurs because the `SAM` optimizer shares its state dictionary (`self.state`) with the base optimizer (`AdamW`). In `first_step`, `SAM` stores the original parameter values (`old_p`) into `self.state`. Consequently, when `AdamW.step()` is called within `second_step`, it detects that `self.state` is not empty (it contains `old_p`) and skips its lazy initialization routine. This prevents `exp_avg` from being created, causing the crash when `AdamW` attempts to access it.

To fix this, I will modify `SAM` to store the temporary `old_p` values in a separate instance attribute (`self.param_storage`) instead of the shared `self.state`. This ensures `self.state` remains empty during the first step, allowing `AdamW` to correctly trigger its initialization logic. This approach resolves the crash without altering the optimization algorithm or breaking checkpoint compatibility.
