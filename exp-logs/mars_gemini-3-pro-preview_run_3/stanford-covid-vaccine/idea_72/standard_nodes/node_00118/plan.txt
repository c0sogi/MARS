### Implementation Strategy

1.  **Configuration Override**: To ensure a fast baseline execution within the time limit, I will override the default `Config` parameters in the main script, reducing `EPOCHS` to 15 and setting `BATCH_SIZE` to 32.
2.  **Setup & Data Loading**: I will initialize the environment using `set_seed` and `Config.setup_directories`. Data loaders for training, validation, and testing will be retrieved using `get_dataloaders` with caching enabled to speed up startup.
3.  **Model Training**: I will instantiate the `RNAModel` and move it to the GPU. The training loop will use `AdamW` optimizer and `CosineAnnealingLR` scheduler. I will implement a standard training loop that computes `MCRMSELoss`, evaluates on the validation set after each epoch, and saves the best model based on the validation score.
4.  **Validation & Metric**: After training, I will reload the best model weights and compute the final validation metric using `eval_fn`. This metric will be printed in the required format: `Final Validation Metric: <value>`.
5.  **Failure Analysis**: I will perform a detailed failure analysis by loading the validation metadata (`val.parquet`). I will calculate the Root Mean Squared Error (RMSE) for each sample individually on the scored columns (`reactivity`, `deg_Mg_pH10`, `deg_Mg_50C`). I will then merge these errors with metadata features (`signal_to_noise`, `SN_filter`, nucleotide content) and calculate/print the Pearson correlation coefficients to identify sources of error.
6.  **Conditional Submission**: Finally, I will check if the `Final Validation Metric` is strictly lower than the threshold `0.5884495377540588`. If the condition is met, I will generate predictions for the test set using `predict_fn` and save the formatted submission file to `./submission/submission.csv`.
