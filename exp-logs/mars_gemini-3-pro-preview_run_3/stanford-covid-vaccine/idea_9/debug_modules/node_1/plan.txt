The issue is that `runfile.py` defines cache file paths with a `.pt` extension (e.g., `train_cache.pt`), but `library/data.py` uses `np.save` to save the data. `np.save` automatically appends the `.npy` extension if it is not present, resulting in files named like `train_cache.pt.npy`. However, when `library/data.py` later attempts to load the cache, it checks for the existence of `train_cache.pt`. Since a file named `train_cache.pt` exists in the working directory (likely a leftover artifact or a zip-compressed file from a different process), `np.load` reads this file instead of the generated `.npy` file. Because the existing `train_cache.pt` is recognized as a zip archive (returning an `NpzFile` object) rather than a numpy array, `torch.tensor()` fails to convert it, causing the `ValueError`.

The fix is to update the cache file paths in `runfile.py` to use the `.npy` extension. This ensures that `np.save` writes to the intended filename (without appending an extra extension) and `np.load` reads the correct file.
