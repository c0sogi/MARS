The implementation strategy follows the requirements to create a fast baseline, perform rigorous validation and failure analysis, and conditionally generate a submission.

1.  **Setup & Configuration**: The script initializes the environment by setting the random seed for reproducibility and detecting the available device (GPU/CPU). The number of training epochs is overridden to 15 to ensure the execution completes well within the time limit while providing a meaningful baseline.
2.  **Data Loading**: It utilizes the provided `get_dataloaders` function to load training, validation, and test datasets. This function leverages the caching mechanism (`load_cached_data=True` implicitly) to speed up data preparation.
3.  **Training Loop**: The `DCASGBiGRU` model is initialized along with the `AdamW` optimizer, `CosineAnnealingLR` scheduler, and `MCRMSELoss`. The training loop runs for the specified epochs, performing training and validation steps. The model with the best validation MCRMSE is saved to `best_model.pth`.
4.  **Validation & Failure Analysis**:
    *   The best model is reloaded.
    *   Inference is run on the full validation set to compute the **Final Validation Metric** (MCRMSE on scored columns). This metric is printed with full precision.
    *   For failure analysis, the RMSE is calculated per sample. The validation metadata (`val.parquet`) is loaded to retrieve sample-level features (`signal_to_noise`, `SN_filter`, sequence content). Pearson correlations between the model's error and these features are computed and printed to identify sources of systematic error.
5.  **Submission**: The script checks if the final validation metric is strictly lower than `0.5978901386`. If the condition is met, it generates predictions for the test set, formats them according to the competition requirements using `format_submission`, and saves the result to `submission.csv`.
