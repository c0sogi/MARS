# Proposed Strategy: Dilated Residual BiGRU Network

This strategy synthesizes the superior inductive bias of Recurrent Neural Networks (RNNs) for this specific task with a robust, multi-scale feature extraction mechanism. It corrects the architectural over-complexity of Transformers and the data processing errors (filtering and embedding) that hindered previous attempts.

### Model

The architecture is a **Dilated Residual CRNN (Convolutional Recurrent Neural Network)**. It is designed to hierarchically extract structural motifs before modeling the global sequential degradation.

1.  **Input Representation:**
    *   The input is a sequence-preserved tensor of shape $(N, 107, 14)$. **Cite solution_lesson_node_00002**.
    *   **Feature Channels:** We will strictly use **One-Hot Encoding** for the nucleotide sequence (4 channels), secondary structure (3 channels), and predicted loop type (7 channels). We will **not** use learned embeddings, as they previously increased parameter count without improving performance in this low-data regime. **Cite solution_lesson_node_00009**.
    *   The secondary structure is treated as a local feature channel, avoiding the complexity and noise of explicit graph message passing. **Cite solution_lesson_node_00010**.

2.  **Feature Extractor (Dilated Residual CNN):**
    *   Instead of a single convolutional layer or a complex Transformer tokenizer, we employ a stack of **1D Residual Blocks** (e.g., 3-4 blocks).
    *   **Dilation Strategy:** The convolution layers within these blocks will use geometrically increasing dilation rates (e.g., 1, 2, 4, 8). This allows the model to exponentially expand its receptive field and capture multi-scale structural motifs (like hairpins or internal loops of varying sizes) while maintaining the sequence resolution and locality.
    *   **Residual Connections:** Skip connections are used to facilitate gradient flow and prevent signal degradation in the deeper feature extraction stage.

3.  **Sequential Backbone (BiGRU):**
    *   The output of the CNN stack is fed into a **Bidirectional GRU** (2-3 layers).
    *   We select the BiGRU over the Transformer/Conformer because its inductive bias for sequential processing has empirically outperformed attention mechanisms on this dataset, which consists of short sequences and limited training samples. **Cite solution_lesson_node_00017**.

4.  **Output Head:**
    *   A final Dense (Linear) layer projects the hidden states to the 5 target values for each position.

### Data

1.  **Full-Spectrum Training:**
    *   We will train on the **entire training dataset**, including samples with low signal-to-noise ratios (`SN_filter == 0`). While filtering data improves training loss, it creates a detrimental distribution shift relative to the public test set. Training on the full noisy distribution is necessary for robustness. **Cite solution_lesson_node_00015**.

2.  **Robust Pipeline:**
    *   We will implement **hash-based caching** for the preprocessed data (e.g., `train_data_{hash(config)}.npy`). This ensures that the switch back to full-dataset training and one-hot encoding is correctly propagated, preventing the stale cache failures observed previously. **Cite solution_lesson_node_00011**.

### Training

1.  **Objective:** We optimize the **MCRMSE** (Mean Columnwise Root Mean Squared Error) on all 5 target columns to stabilize the learning of shared representations.
2.  **Optimizer:** **AdamW** with a cosine annealing learning rate scheduler to ensure smooth convergence.
3.  **Regularization:** Dropout will be applied between the GRU layers and within the Residual blocks to mitigate overfitting.

### Evaluation

1.  **Internal Validation:** While the model predicts all 5 targets, our internal validation metric will explicitly calculate the MCRMSE on **only the 3 scored columns** (`reactivity`, `deg_Mg_pH10`, `deg_Mg_50C`) to accurately track performance against the competition metric. **Cite solution_lesson_node_00017**.
2.  **Inference:** The model processes the `test.json` sequences (converted to one-hot tensors) to produce a $(N, 107, 5)$ prediction tensor.
3.  **Submission:** We extract the first 68 positions (as defined by `seq_scored`) from the output and flatten them into the `id_seqpos` format required for the submission file.
