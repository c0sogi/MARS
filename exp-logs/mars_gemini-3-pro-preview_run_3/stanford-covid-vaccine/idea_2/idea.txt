Based on the lessons learned from the previous experiments, I propose a **Graph Neural Network (GNN) with Sequential Refinement**. This approach fundamentally shifts the modeling paradigm from treating RNA as a simple sequence (1D) to treating it as a structured graph (2D), leveraging the explicit secondary structure provided in the dataset.

# Model

The architecture is a **Hybrid GNN-BiLSTM** designed to capture both the spatial folding of the RNA and the sequential dependencies of the polymer chain.

1.  **Input Representation (Node Features):**
    *   Instead of using learned embeddings which increased complexity without gain, we will use **One-Hot Encoding** for the input features (Sequence, Predicted Loop Type, and Structure Character). This results in a compact feature vector (approx. 14 channels) for each of the 107 nucleotide positions. **Cite solution_lesson_node_00009**.
    *   The sequence dimension (107) will be preserved as the number of nodes in the graph. **Cite solution_lesson_node_00002**.

2.  **Graph Topology (Edges):**
    *   We construct a graph where each nucleotide is a node.
    *   **Backbone Edges:** Connect position $i$ to $i+1$ (and vice-versa) to represent the polymer chain.
    *   **Pairing Edges:** Connect position $i$ to $j$ (and vice-versa) if they are paired in the provided `structure` string (indicated by matching parentheses). This allows the model to directly propagate information between bases that are far apart in the sequence but close in 3D space.

3.  **Graph Layers (Spatial Encoder):**
    *   The node features are processed by a stack of **Graph Convolutional Layers** (e.g., GCN or GAT from `torch_geometric`). These layers allow nucleotides to exchange information with their spatial neighbors (paired bases) and sequential neighbors.

4.  **Sequential Refinement (Sequence Encoder):**
    *   The output node embeddings from the GNN are fed into a **Bidirectional LSTM (BiLSTM)**. While the GNN captures the folding stability, the BiLSTM is explicitly designed to model the sequential context and degradation patterns that propagate along the backbone, addressing the potential "oversmoothing" of pure GNNs.

5.  **Output Head:**
    *   A final Dense (Linear) layer projects the hidden state of each node to the 5 target values.

# Data

1.  **Graph Construction:**
    *   For each sample, a custom preprocessing step will parse the `structure` (dot-bracket) string to generate an **Edge Index** tensor (coordinate list format) representing the connectivity.
    *   The `structure` string will be parsed using a stack-based algorithm to identify matching parentheses indices $(i, j)$.

2.  **Feature Encoding:**
    *   Inputs will be strictly **One-Hot Encoded**. We will concatenate the one-hot vectors for `sequence` (4 dims), `predicted_loop_type` (7 dims), and `structure` (3 dims) to form the initial node features. **Cite solution_lesson_node_00009**.

3.  **Batching:**
    *   We will use `torch_geometric.loader.DataLoader` to batch multiple graphs together. This handles the variable connectivity (though node count is fixed at 107) efficiently.

# Training

*   **Loss Function:** We will continue to use **MCRMSE** (Mean Columnwise Root Mean Squared Error) as the objective function.
*   **Optimizer:** **AdamW** will be used to optimize the weights, with a standard learning rate (e.g., 1e-3).
*   **Regularization:** Dropout will be applied within the GNN and LSTM layers to prevent overfitting on the small dataset (2160 samples).
*   **Strategy:** We will train for a fixed number of epochs with Early Stopping based on the validation MCRMSE. The sequence dimension is never flattened during the forward pass. **Cite solution_lesson_node_00002**.

# Evaluation

*   **Inference:** For the test set (`test.json`), we will generate the graph topology (Edge Indices) and node features using the same preprocessing pipeline.
*   **Prediction:** The model will output a tensor of shape $(N, 107, 5)$.
*   **Formatting:** We will extract the first 68 positions (as defined by `seq_scored`) and flatten the result to match the `sample_submission.csv` format (`id_seqpos` rows).
