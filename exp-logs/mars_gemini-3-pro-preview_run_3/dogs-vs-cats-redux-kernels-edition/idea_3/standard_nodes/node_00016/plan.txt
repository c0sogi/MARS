The `CUDA out of memory` error is caused by three converging factors: (1) the GPU memory occupied by the first model (ResNet50) is not released before the second model (ConvNeXt) attempts to initialize, (2) the `BATCH_SIZE` of 128 is too aggressive for the available VRAM, and (3) the persistent runtime environment caches the `Config` module, meaning changes to the config file are ignored unless explicitly reloaded (Cite debug_lesson_1).

To fix this, I will:
1.  Reduce `BATCH_SIZE` to 64 in `library/config.py` to provide adequate memory headroom.
2.  In `runfile.py`, explicitly reload `library.config` to ensure the new batch size is recognized by the runtime.
3.  Add explicit memory cleanup (`del model`, `gc.collect()`, `torch.cuda.empty_cache()`) after each training and validation iteration to fully release VRAM between models.
4.  Update the `predict_ensemble` call to explicitly pass the new `BATCH_SIZE`, preventing the use of the stale default value baked into the function definition.
