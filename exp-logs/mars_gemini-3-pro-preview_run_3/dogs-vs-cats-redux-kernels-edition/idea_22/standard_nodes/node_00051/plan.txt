The issue is caused by data leakage in the `create_kfold_loaders` function within `library/dataset.py`. Currently, the function loads both the training metadata (`train.csv`) and the hold-out validation metadata (`val.csv`) and merges them into a single dataset before creating cross-validation folds. This means the models are trained on data that is later used for final evaluation in `runfile.py`, rendering the reported metric invalid. The fix is to modify `create_kfold_loaders` to load only the training metadata (`train.csv`), ensuring the validation set remains strictly isolated for the final hold-out evaluation.
