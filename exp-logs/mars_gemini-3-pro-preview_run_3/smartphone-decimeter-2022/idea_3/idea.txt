### Solution: Sequential Residual BiLSTM

This strategy evolves the previous point-wise regression approach into a sequence-to-sequence learning framework. It addresses the limitation of treating each timestamp independently by explicitly modeling the temporal correlations of GNSS errors (e.g., drift, multipath duration) and device dynamics.

#### **1. Model**
The architecture is a **Bidirectional Long Short-Term Memory (BiLSTM) Network** designed to smooth and correct the baseline trajectory.
*   **Backbone**: A multi-layer BiLSTM acts as the core sequence encoder. By processing the trajectory in both forward and backward directions, the model can utilize future context (available during post-processing/evaluation) to better estimate the true position at the current step, effectively learning to "smooth" the noisy baseline.
*   **Input**: A sequence of feature vectors $X = \{x_1, x_2, ..., x_T\}$ representing the entire trip (or long windows), where each $x_t$ contains the aggregated signal quality and IMU dynamics for that second.
*   **Correction Head**: A Time-Distributed Fully Connected (Dense) layer that maps the LSTM hidden states at each time step to a 2-dimensional correction vector $(\Delta Lat_t, \Delta Lon_t)$.
*   **Residual Connection**: The model explicitly implements the residual learning strategy. The final output is defined as:
    $$ \hat{P}_t = P_{WLS, t} + \text{Model}(X)_t $$
    where $P_{WLS, t}$ is the provided heuristic baseline position. This retains the robust physical prior while allowing the model to focus capacity on learning non-linear error biases. Cite solution_lesson_node_00007

#### **2. Data**
The preprocessing pipeline shifts from shuffling independent samples to constructing ordered time-series sequences.
*   **Sequence Construction**: Group the training data by `tripId` and sort by `UnixTimeMillis` to preserve temporal order.
*   **Feature Engineering (Aggregated)**: For each time step, generate the lightweight aggregated features identified as successful in previous iterations. This includes:
    *   **GNSS**: Mean/Std/Max of `Cn0DbHz`, number of visible satellites, and mean satellite elevation.
    *   **IMU**: Mean and Standard Deviation of the total accelerometer magnitude. High variance in IMU data serves as a strong predictor for dynamic conditions where GNSS errors often spike. Cite solution_lesson_node_00007
*   **Target Calculation**: Compute the additive residual targets for the sequence:
    $$ y_t = (\text{Lat}_{GT, t} - \text{Lat}_{WLS, t}, \ \text{Lon}_{GT, t} - \text{Lon}_{WLS, t}) $$
*   **Normalization**: Apply standard scaling (Z-score) to the input features. Since the sequence lengths vary (different trip durations), pad sequences to a fixed maximum length (e.g., 2048 steps) and generate corresponding masks to ignore padding during loss calculation.

#### **3. Training**
*   **Loss Function**: **Mean Absolute Error (MAE)**. We continue to use L1 loss because it minimizes the impact of extreme outliers (e.g., large jumps caused by signal reflections) which are common in the baseline WLS data. Cite solution_lesson_node_00007
*   **Optimizer**: **AdamW** with a learning rate scheduler (e.g., Cosine Annealing) to ensure stable convergence.
*   **Strategy**: Train on full trip sequences (or large sliding windows if memory is constrained). Use the padding masks to ensure the loss is only computed on valid time steps.

#### **4. Evaluation**
*   **Inference**: Preprocess the test set into sequences grouped by `tripId` and sorted by time. Feed the sequences into the trained BiLSTM to predict the correction sequence.
*   **Reconstruction**: Add the predicted corrections to the test `WlsPosition` (converted to Lat/Lon) to obtain the final trajectory.
*   **Post-Processing**: Since the model outputs a sequence, the predictions naturally enforce a degree of temporal smoothness, reducing the need for external Kalman smoothing.
