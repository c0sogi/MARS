Implementation Strategy:
1.  **Initialize and Setup**: Define input and output directories. Create the metadata directory if it doesn't exist.
2.  **Process Training Data**:
    *   Traverse the `input/train` directory to find all `ground_truth.csv` files.
    *   For each ground truth file, extract the `drive_id` and `phone_name` from the directory structure.
    *   Read the ground truth data (timestamps and coordinates).
    *   Construct relative file paths for the corresponding GNSS and IMU files.
    *   Aggregate all training trips into a single DataFrame.
3.  **Split Training/Validation**:
    *   Extract unique `drive_id`s from the training data.
    *   Shuffle the drive IDs with a fixed random seed (42).
    *   Split the drive IDs into 80% training and 20% validation sets to ensure no data leakage between trips from the same drive.
    *   Filter the aggregated training DataFrame into `train_metadata` and `val_metadata` based on the split drive IDs.
4.  **Process Test Data**:
    *   Read the `sample_submission.csv` file to identify the required prediction timestamps and trip IDs.
    *   Traverse the `input/test` directory to identify available test trips (drive and phone combinations).
    *   Map the `tripId` from the submission file to the actual directory structure to derive `drive_id` and `phone_name`.
    *   Add relative file paths for GNSS and IMU files to the test metadata.
5.  **Save Metadata**: Write the three DataFrames (`train`, `val`, `test`) to CSV files in the metadata directory.
6.  **Validation & Statistics**:
    *   Load the generated metadata files.
    *   Print summary statistics (sample counts, unique trips/drives).
    *   Perform a "broken link" check on a random sample of file paths to ensure they point to existing files.
    *   Verify that the training and validation sets are disjoint by `drive_id` to confirm the group split logic.
