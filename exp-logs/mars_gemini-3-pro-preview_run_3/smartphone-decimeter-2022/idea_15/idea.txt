Based on the accumulated lessons, I propose the **Multi-Hypothesis Newton-Boost** strategy.

This strategy represents a structural evolution of the "Geometry-Projected" approach (Idea 14). While Idea 14 successfully projected errors onto directional axes (Gradient), it still relied on the GBDT to implicitly approximate the inversion of the geometry matrix (Hessian) to find the position correction. Trees are notoriously inefficient at learning linear algebra operations like matrix inversion. This strategy explicitly solves the linearized GNSS observation equation using multiple weighting hypotheses (heuristics) and feeds these **explicit correction vectors** as high-value features to the model.

### 1. Model
The core architecture consists of an **Ensemble of LightGBM Regressors**.
*   **Backbone:** Independent LightGBM models trained on $K$ cross-validation folds.
*   **Targets:** The models predict the **ENU (East-North-Up) Residuals** in meters.
    *   $\Delta E = East_{GT} - East_{WLS}$
    *   $\Delta N = North_{GT} - North_{WLS}$
    *   This retains the **Residual Learning** paradigm, utilizing the robust WLS baseline as a center point and focusing the model on correcting non-linear biases (Cite solution_lesson_node_00007).

### 2. Data
The preprocessing pipeline moves beyond simple aggregation by embedding an **Explicit Physics Solver** into the feature engineering stage.

*   **Coordinate Transformation:** Convert Ground Truth and WLS positions to a local ENU frame.
*   **Physics-Based Feature Extraction:**
    For each timestamp, process the visible satellites:
    1.  **Residual Calculation:** Compute the pseudorange residual $r_i$ and Line-of-Sight unit vector $\vec{u}_i$ for each satellite (Cite solution_lesson_node_00040, solution_lesson_node_00043).
    2.  **Geometry Matrix Construction:** Form the design matrix $G$ (rows are $\vec{u}_i$) and the residual vector $\vec{r}$.
    3.  **Multi-Hypothesis Solver (Innovation):**
        Instead of a single aggregation, compute **Explicit Newton Steps** ($\Delta \vec{x} = (G^T W G)^{-1} G^T W \vec{r}$) under different weighting schemes ($W$):
        *   **Hypothesis A (Signal):** Weights proportional to signal strength ($Cn0DbHz$).
        *   **Hypothesis B (Elevation):** Weights proportional to $\sin(Elevation)$.
        *   **Hypothesis C (Quality):** Binary weights (masking out satellites with $Cn0 < 25$ dB).
        *   These resulting vectors $(\Delta E_A, \Delta N_A, \Delta E_B, \dots)$ represent "candidate corrections" derived from pure physics.
    4.  **Solution Quality Metrics:** For each hypothesis, calculate the **Post-Fit Chi-Square** (variance of residuals after applying the correction). This tells the GBDT how "trustworthy" each hypothesis is.
    5.  **Geometry Features:** Elements of the covariance matrix $(G^T W G)^{-1}$ (Dilution of Precision) (Cite solution_lesson_node_00043).
*   **Global Features:** IMU dynamics (Mean/Std of acceleration) to capture motion state.
*   **Constraint:** Strictly **Point-Wise** features only (no temporal windowing) to prevent trajectory memorization (Cite solution_lesson_node_00011).

### 3. Training
*   **Loss Function:** **Mean Absolute Error (MAE)**. This L1 loss is essential to minimize the influence of heavy-tailed outliers inherent in urban GNSS data (Cite solution_lesson_node_00007).
*   **Validation Strategy:** **GroupKFold** cross-validation grouped by `drive_id`. This ensures the model is evaluated on completely unseen drives, enforcing generalization.

### 4. Evaluation
The inference pipeline relies on robust ensemble aggregation, explicitly rejecting temporal smoothing to avoid the "smearing" of outliers observed in previous attempts.

1.  **Feature Generation:** Compute the Multi-Hypothesis Newton features for the test set.
2.  **Ensemble Prediction:** Generate predictions ($\Delta E, \Delta N$) from all $K$ fold models.
3.  **Robust Aggregation:** Compute the **Pixel-wise Median** of the predictions.
    *   This filters out stochastic prediction errors from individual models without propagating outliers across time (Cite solution_lesson_node_00014).
4.  **Reconstruction:** Convert the median ENU residuals back to Geodetic offsets and apply them to the WLS baseline to generate the final trajectory.
