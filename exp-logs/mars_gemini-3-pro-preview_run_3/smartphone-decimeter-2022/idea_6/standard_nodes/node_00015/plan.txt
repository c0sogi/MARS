Implementation Strategy:
1.  **Orchestration**: The script `runfile.py` will orchestrate the entire pipeline: Data Loading -> Model Training -> Validation & Smoothing -> Failure Analysis -> Submission.
2.  **Data Loading**: Utilize `library.data_factory.prepare_training_data` to load training and validation sets. This handles metadata parsing, raw file loading, and feature engineering (GNSS aggregation, IMU magnitude).
3.  **Model Training**: Use `library.quantile_regressor.QuantileLGBMWrapper` to train LightGBM models.
    *   Two models will be trained: one for East residuals and one for North residuals.
    *   Each model will be trained for three quantiles: 0.1, 0.5 (Median), and 0.9.
    *   The 0.5 quantile serves as the primary prediction, while the spread between 0.9 and 0.1 provides an uncertainty estimate.
4.  **Validation & Smoothing**:
    *   Predict residuals and uncertainties for the validation set.
    *   Group data by `tripId`.
    *   For each trip, convert WLS positions to a local ENU frame relative to the trip start.
    *   Construct "observed" positions by adding the predicted residuals to the WLS positions.
    *   Apply `library.adaptive_smoother.AdaptiveKalmanFilter`. This filter uses the predicted uncertainty to dynamically scale the measurement noise matrix, effectively gating outliers.
    *   Convert smoothed ENU positions back to WGS84 Geodetic coordinates.
    *   Calculate the competition metric using `library.metrics.competition_score`.
5.  **Failure Analysis**: Calculate correlations between the prediction error and input features/uncertainties to understand model behavior.
6.  **Submission**: If the validation score meets the threshold requirement, repeat the prediction and smoothing process on the test set (loaded via `prepare_test_data`) and generate the `submission.csv` file.
