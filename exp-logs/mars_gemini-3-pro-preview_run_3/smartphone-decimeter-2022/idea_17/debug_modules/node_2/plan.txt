The issue is that the `ResidualRegressor` training process drops any rows containing `NaN` values in the feature columns. The feature extraction logic merges IMU data onto GNSS data using an exact timestamp match (`utcTimeMillis`), which often fails due to sensor frequency differences, resulting in `NaN`s for all IMU features. Consequently, the entire training dataset is discarded, causing the cross-validation splitter to fail with `n_samples=0`.

To fix this, I will modify the `patched_process_drive` function in `runfile.py` to fill `NaN` values in the IMU columns with 0 immediately after the merge. This ensures that we retain the GNSS data rows (which are the primary source of information) even if IMU matching fails, thus preserving samples for cross-validation.
