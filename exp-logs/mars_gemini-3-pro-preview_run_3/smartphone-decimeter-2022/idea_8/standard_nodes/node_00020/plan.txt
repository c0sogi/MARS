The issue is that the training and validation datasets contain `NaN` values in the target columns (`target_E`, `target_N`). This happens because the targets are computed as residuals relative to a baseline Weighted Least Squares (WLS) position, which is sometimes missing or invalid in the raw GNSS data. While LightGBM can handle missing features, Scikit-Learn's metrics (like MAE used for validation scoring) cannot handle missing targets, causing the `ValueError: Input contains NaN`.

To fix this:
1.  **Sanitize Targets**: Modify `library/data_loader.py` to explicitly drop rows where the targets are `NaN` or `Infinite` for the `train` and `val` splits. This ensures we only train/validate on valid data points (Cite debug_lesson_2). We explicitly do *not* drop rows for the `test` split to preserve the required row cardinality for submission (Cite debug_lesson_4).
2.  **Invalidate Cache**: Modify `runfile.py` to delete the existing cached Parquet files (`train_features.parquet`, `val_features.parquet`) at the start of execution. This forces the pipeline to regenerate the datasets using the new cleaning logic instead of loading the stale, corrupt data (Cite debug_lesson_3).
