Based on the lessons learned, I propose the **Velocity-Initialized Physics-Gated Residual Boosting** strategy. This approach retains the high-performance LightGBM backbone for residual prediction (Cite solution_lesson_node_00010) but fundamentally restructures the post-processing stage to solve the catastrophic failures observed with standard smoothing (Cite solution_lesson_node_00014) and improper gating (Cite solution_lesson_node_00018).

### 1. Model: LightGBM for ENU Residuals
The core predictive model remains a **LightGBM Regressor**, chosen for its superior ability to map instantaneous sensor noise to error magnitudes without the overfitting risks of sequence models (Cite solution_lesson_node_00010).

*   **Architecture:** Two independent LightGBM models will be trained.
    *   **Model E:** Predicts the Easting error ($\Delta E$).
    *   **Model N:** Predicts the Northing error ($\Delta N$).
*   **Target Definition:** The model predicts the **residual vector** between the Ground Truth and the provided WLS Baseline in a local East-North-Up (ENU) Cartesian frame.
    *   Target = $P_{GT} - P_{WLS}$ (converted to meters).
    *   This leverages the robust physical prior of the WLS baseline while focusing the ML model solely on correcting non-linear biases like multipath and atmospheric delays (Cite solution_lesson_node_00007).

### 2. Data: Point-Wise Physics Features
The feature engineering pipeline strictly adheres to a **Point-Wise** paradigm to ensure generalization across disjoint drives (Cite solution_lesson_node_00011).

*   **Input Features:** For each timestamp, generate a single row of aggregated statistics:
    *   **GNSS Signal:** Mean, Max, and Standard Deviation of `Cn0DbHz`; Count of visible satellites; Mean `SvElevationDegrees`.
    *   **Signal Diversity:** Separate counts/stats for L1 vs. L5 signals (L5 is more robust to multipath).
    *   **IMU Dynamics:** Mean and Standard Deviation of total accelerometer magnitude.
*   **Constraint:** Explicitly **exclude** temporal windowing (lag/lead features) to prevent the model from memorizing the specific kinematic trajectories of training drives (Cite solution_lesson_node_00011).

### 3. Training: Robust L1 Optimization
*   **Loss Function:** **Mean Absolute Error (MAE)**. This L1 loss minimizes the impact of the heavy-tailed outliers inherent in urban GNSS data, preventing the model from skewing its predictions to accommodate rare, massive errors (Cite solution_lesson_node_00007).
*   **Validation:** **GroupKFold** cross-validation grouped by `drive_id`. This simulates the test environment by ensuring the model is evaluated on completely unseen routes.

### 4. Evaluation: Velocity-Initialized Kinematic Smoothing
The inference pipeline introduces a robust state estimation layer designed to fix the specific failure modes identified in previous smoothing attempts.

**Step 1: Base Prediction**
Generate the ML-corrected trajectory: $\hat{P}_{raw} = P_{WLS} + \text{Model}(Features)$.

**Step 2: Robust Kalman Smoothing**
Apply a Kalman Smoother to $\hat{P}_{raw}$ with the following critical structural changes:

1.  **Velocity Initialization (Fixing Lesson 00018):**
    *   Instead of initializing the state velocity to zero (which caused the filter to reject valid motion as outliers), explicitly calculate the initial velocity vector $\vec{v}_{init}$ using a **Robust Linear Regression (e.g., RANSAC)** on the first 5-10 seconds of the $\hat{P}_{raw}$ trajectory.
    *   Initialize the Kalman state as $[x_0, y_0, v_{x,init}, v_{y,init}]$.

2.  **Physics-Based Gating (Fixing Lesson 00014):**
    *   Implement an **Innovation Gate** to reject outliers before they smear into the trajectory.
    *   Calculate the **Innovation** (residual): $\vec{y} = z_t - H\hat{x}_{t|t-1}$.
    *   **Threshold Logic:** The gate threshold must be set based on maximum physical *acceleration*, not velocity (since velocity is modeled).
    *   If $||\vec{y}|| > \text{Threshold}$ (e.g., $10m$, corresponding to an unmodeled acceleration shock), **discard the measurement** for this step. The filter will perform a time-update only (coasting on the constant velocity model), effectively bridging the gap created by the multipath outlier.

This strategy combines the high accuracy of Gradient Boosting for signal correction with a physically robust state estimator that is immune to initialization failures and heavy-tailed outliers.
