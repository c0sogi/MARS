The issue is that the training data becomes empty after dropping rows with missing targets because the timestamp matching between GNSS data and Ground Truth (GT) fails. GNSS timestamps often have jitter and do not match the exact integer timestamps of the Ground Truth, causing a strict dictionary lookup to find zero matches. Additionally, missing altitude values in the Ground Truth can propagate NaNs.

To fix this, I will modify `library/feature_eng.py` to:
1.  Remove the exact-match dictionary lookup for Ground Truth.
2.  Implement a post-processing step using `pd.merge_asof` to align GNSS epochs with the nearest Ground Truth timestamps within a tolerance (e.g., 100ms).
3.  Fill missing altitude values in the Ground Truth with 0 to prevent NaN propagation (Cite debug_lesson_6).
4.  Compute the ENU targets (East, North, Up offsets) by iterating over the merged dataframe and applying the coordinate transformations using the aligned positions.
