Based on the task requirements and the provided dataset, here is a proposal for a highly efficient baseline approach.

### **Solution: Top-K Satellite Snapshot MLP**

This approach establishes a baseline by treating the positioning problem as a regression task on instantaneous satellite signal patterns. Unlike complex sequence models or graph networks, this model operates on independent time snapshots, making it extremely lightweight and fast to train. It leverages the provided Weighted Least Squares (WLS) baseline as a strong prior and learns to predict the **correction vector (residual)** needed to align the WLS estimate with the Ground Truth.

#### **1. Model**
The architecture is a simple **Multi-Layer Perceptron (MLP)** designed to map raw satellite signal configurations to position errors.
*   **Input Layer**: A fixed-size feature vector representing the state of the Global Navigation Satellite System (GNSS) constellation at a single timestamp.
*   **Hidden Layers**: A small stack of fully connected (dense) layers (e.g., 3 layers with 128, 64, and 32 units), using ReLU activation and Batch Normalization to stabilize training.
*   **Output Layer**: A linear projection to 3 units, representing the predicted ECEF (Earth-Centered, Earth-Fixed) coordinate corrections $(\Delta x, \Delta y, \Delta z)$.

#### **2. Data**
The preprocessing pipeline focuses on constructing a consistent feature representation from the variable number of satellites visible at any given moment.
*   **Coordinate Conversion**: Convert the Ground Truth `LatitudeDegrees`, `LongitudeDegrees`, and `AltitudeMeters` into ECEF coordinates $(x_{gt}, y_{gt}, z_{gt})$ to match the coordinate system of the provided `WlsPosition` columns.
*   **Satellite Ranking & Selection**: For each unique timestamp (`UnixTimeMillis`):
    1.  Group the raw GNSS measurements.
    2.  Sort the visible satellites by signal strength (`Cn0DbHz`) in descending order.
    3.  Select the **Top-K** satellites (e.g., $K=20$). If fewer than $K$ satellites are available, zero-pad the remaining slots.
*   **Feature Engineering**: Construct a flat feature vector by concatenating the raw features of the selected satellites. Key features per satellite include:
    *   `Cn0DbHz` (Signal strength)
    *   `SvElevationDegrees` (Satellite position relative to horizon)
    *   `SvAzimuthDegrees` (Satellite direction)
    *   `PseudorangeRateMetersPerSecond` (Doppler shift/velocity proxy)
*   **Target Generation**: Calculate the residual target for regression: 
    $$ \text{Target} = (x_{gt} - x_{wls}, \ y_{gt} - y_{wls}, \ z_{gt} - z_{wls}) $$
*   **Normalization**: Standardize input features (mean=0, std=1) to ensure efficient gradient descent.

#### **3. Training**
*   **Loss Function**: **Mean Absolute Error (MAE)**. This is preferred over Mean Squared Error (MSE) to reduce sensitivity to outliers, which are common in GNSS data due to signal multipath and urban canyon effects.
*   **Optimizer**: **Adam** optimizer with a standard learning rate (e.g., 1e-3).
*   **Strategy**: Train using standard mini-batch Stochastic Gradient Descent (SGD). Since the model treats every timestamp as an independent sample ("snapshot"), the data can be shuffled globally, breaking temporal correlations and preventing overfitting to specific trajectories.

#### **4. Evaluation**
*   **Inference**: For each timestamp in the test set, generate the Top-K satellite feature vector and pass it through the trained MLP to obtain the predicted residuals $(\hat{\Delta x}, \hat{\Delta y}, \hat{\Delta z})$.
*   **Reconstruction**: Add the predicted residuals to the baseline WLS position provided in `device_gnss.csv`:
    $$ \hat{P}_{ecef} = P_{wls} + \hat{\Delta P} $$
*   **Final Output**: Convert the corrected ECEF position $\hat{P}_{ecef}$ back to Geodetic coordinates (Latitude, Longitude) for the final submission.
