The issue is that the `tripId` column is missing from the loaded dataframe, causing a `KeyError` in the feature engineering step where data is grouped by `tripId`. This happens because the data loader (`_process_drive` and `_compute_dataset`) does not extract or propagate the `tripId` from the metadata into the loaded dataframe rows.

To fix this, I will modify `library/data_loader.py` to:
1.  Update `_process_drive` to accept an optional `trip_id` argument and add it as a column to the returned dataframe.
2.  Update `_compute_dataset` to include `tripId` in the list of columns extracted from metadata and pass it to `_process_drive`.

This ensures the `tripId` context identifier is preserved throughout the pipeline, addressing the root cause identified in **Debug Lesson ID: debug_lesson_5**.
