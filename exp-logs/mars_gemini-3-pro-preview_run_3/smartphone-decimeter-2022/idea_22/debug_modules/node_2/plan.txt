The issue is that the `device_gnss.csv` files use `utcTimeMillis` as the timestamp column, but the feature engineering and model training modules expect `UnixTimeMillis` (which is the standard in the ground truth files). The current data loader implementation merges datasets but then explicitly drops `UnixTimeMillis` to avoid duplication, leaving only `utcTimeMillis` (or neither if the merge logic is flawed). This causes a `KeyError` downstream when code attempts to group by `UnixTimeMillis`.

To fix this, I will modify `library/data_loader.py` to standardize the timestamp column name to `UnixTimeMillis` immediately after loading the GNSS data. I will then update the merge operations to join on this standardized column and remove the lines that drop it, ensuring the column persists throughout the pipeline.
