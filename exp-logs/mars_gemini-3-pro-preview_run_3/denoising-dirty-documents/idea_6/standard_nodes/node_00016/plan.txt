Implementation strategy:
1.  **Configuration Override**: To meet the "Fast Baseline" requirement and the time limit, I will override the default configuration values in `library.config` before training. Specifically, I will reduce `NUM_EPOCHS` to 5 and increase the patch extraction `STRIDE` to 20. This significantly reduces the dataset size and training time while maintaining the integrity of the pipeline.
2.  **Training**: I will execute the training pipeline using `library.train.train_model(load_cached_data=False)`. Setting `load_cached_data=False` ensures that the dataset is regenerated with the new, larger stride (fewer patches), rather than loading potentially massive cached files from previous runs.
3.  **Model Loading**: After training, I will explicitly load the "best" model weights saved during the training process (based on validation RMSE) to ensure the evaluation and submission steps use the optimal model state.
4.  **Validation & Metrics**: I will perform a dedicated validation pass using `library.train.validate` on the validation dataset. I will print the `Final Validation Metric` with full precision as required.
5.  **Failure Analysis**: I will iterate through the validation set to calculate the Pearson correlation between input pixel intensities and the model's absolute error magnitudes. This helps identify if the model struggles more with bright or dark areas.
6.  **Conditional Submission**: I will check if the calculated RMSE is strictly lower than the specified threshold (`0.011577641381826402`). If satisfied, I will generate the submission file using `library.predict.generate_predictions`.
7.  **Environment**: I will set random seeds for reproducibility and ensure the code runs on the available GPU.
