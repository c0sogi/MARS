The execution failed because `runfile.py` sets `Config.N_FOLDS = 1` to create a fast baseline, but this value is directly used as the `n_splits` argument for `StratifiedKFold`, which raises a `ValueError` because K-Fold cross-validation requires at least 2 splits. To fix this, I will decouple the number of cross-validation splits from the number of folds to execute. Specifically, I will modify `library/data.py` and `library/engine.py` to ensure `StratifiedKFold` receives a valid `n_splits` (defaulting to 5, the original configuration) even when `Config.N_FOLDS` is reduced to 1. This ensures the data is split correctly (e.g., 80/20 split) while still allowing the script to run only a single fold for speed. This addresses the configuration coupling issue (Cite debug_lesson_2).
